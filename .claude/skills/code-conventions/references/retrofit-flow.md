# code-conventions — retrofit 실행 절차 (규약 공용 역학)

`$ARGUMENTS` = `<규약 이름> [경로...]` — 규약 이름 = SKILL.md §규약 목록(목록에 없으면 거부). 경로 = 프로젝트 루트(cwd) 기준 상대(glob 미지원 — 디렉터리는 재귀 확장, 루트 밖 거부). 생략 = 프로젝트 전체(§1 범위 확정에서 규모 확인 후 분할 제안). 대상 = git 추적 소스만 · symlink 제외 · vendor·생성물 트리 기본 제외.

> 🔒 legend = 그 규약 파일. **『역할명』** = 전역 사전(`~/.claude/references/dictionary.md`) 정의 용어. **규약별 편집 원칙 · 전수 반환 항목 · 기계 확인 · 게이트 = 같은 폴더 `<규약>-retrofit.md`**(부재 = 그 규약 retrofit 거부). 이 문서는 규약 무관 공용 역학만 담는다.

## 정량 (정본)

| 항목 | 값 |
|---|---|
| 워커당 파일 | ≤ 10 |
| 워커 슬롯 | 🔒 **『코더(복잡)』 하한**(사용자 결정). 경량 슬롯 금지 — 삭제 판정을 조용히 스킵한다(같은 파일·같은 캐논·모델만 바꾼 A/B 3배치 연속 재현, 순감 1줄 vs 7줄). 증상이 정상 보고서라 반환물로는 안 드러난다 |
| 워커당 총 줄 수 | ≤ 1,500 — 워커 컨텍스트 절반 기준 실측(주석 편집 워크로드). 규약은 retrofit 파일에서 좁히기만 가능 |
| 1회 스윕 파일 | ≤ 50 — 초과 시 분할 제안(사용자 확인) |
| 초대형 파일 | 단독으로 총 줄 수 초과 = 구획 분담. 절단선 = 그 언어 테스트 구획(없으면 큰 논리 경계), 구획 범위 = **경계 앵커 텍스트(코드 토큰만 — 주석 앵커는 스윕 자신이 지울 수 있다)**, 같은 파일 구획 워커는 **순차**. 절단선 부재 = 사용자 에스컬레이션 |
| 재배정 | 미완 구간 재배정 ≤ 1회 — 재배정분도 커버 대조, 그래도 미완 = 사용자 에스컬레이션 |
| 게이트 하한 | 그 규약 retrofit 파일 지정대로, **최소 `/review` 1회**. 게이트 스킬 미가용 = 진행 불가(등가 임의 대체 금지) |

## 0. 준비

- **그 규약 파일 + retrofit 파일 둘 다 Read** + 필수 요소 충족 확인(retrofit 파일 부재·미충족 = 그 규약 retrofit 거부) · 바인딩 Read(부재면 "바인딩 부재 — 규약 기본값 진행" 명시, 조용한 생략 금지).
- 보호 패턴 합성(그 규약 §보호 항목 ∪ 바인딩 추가분 — 규칙 = 그 규약 §프로젝트 추가분) = 워커에 전달할 목록.
- **워킹트리 클린 확인** — 더러우면 중단·사용자 확인(diff 오염 방지).

## 1. 범위 확정

- 대상 목록 산출 → 상한 초과면 분할 제안(사용자 확인) → 묶음별 범위·워커 수 한 줄 명시.
- 기본 제외 경로가 명시 인자로 들어오면 조용한 no-op 금지 — 사용자 확인.

## 2. 워커 팬아웃

묶음별 병렬 스폰(슬롯 = §정량 표). **한 파일은 한 워커** — 구획을 나눴어도 순차로, 선행 완료 후 경계 앵커를 재확인하고 스폰한다(동시 write 인터리브 · 라인 드리프트). 같은 파일에 2인을 붙여 판정을 비교하려면 격리 사본을 쓴다.

지시서:

- **역할·범위** — 규약 파일과 바인딩을 Read하고 그대로만 정리. **담당 목록·구획 밖 편집 금지(배타 소유)** — 범위 밖 편집은 예산·커버 회계를 무너뜨린다.
- **편집 원칙** — 그 규약 retrofit 파일 그대로 전달(여기 재수록 금지 — 두 벌이 되면 갈린다). 규약 파일(기준·양식·보호)도 함께 간다 — 판정 기준이 거기 있다.
- **반환** — 파일별 판단 카운트 + 보존·보류 목록(근거 한 줄) + **커버 확인**(끝 도달 여부 + **마지막 처리 앵커(코드 토큰)** — 라인 번호 금지, 완료 참칭 금지) + 그 규약 전수 반환 항목 전량. verbose 덤프 금지.
- **금지** — 서브에이전트 스폰 · 커밋 · 규약/바인딩 수정.

🔒 **가동 중 스테이징은 파일 명시** — 디렉터리·글롭으로 add 하면 아직 도는 워커의 중간 상태가 딸려 커밋된다(실발생).

취합(메인): **커버 대조 먼저**(보고 앵커 vs 실제 말미 — 불일치 = 미완. 부분 스윕은 diff에 안 나타나 게이트가 못 잡는다) → 카운트 합산 → 판단 목록 검사(규약이 전수로 지정한 항목은 전수, 그 외 스팟체크). 재검 신호 둘: **가치물 유실 냄새**(근거 식별자·"우회"·불변식을 담은 항목의 삭제·이동 누락·근거가 사라진 압축) · **판단 목록이 비정상적으로 짧은 워커**(과잉 처리).

## 3. 기계 확인 + 게이트

그 규약 retrofit 파일이 지정한 방법대로 **메인이** 수행하고, 게이트는 정량 표 하한 위에서 — escalation-only(위험 발견 시 승격만, 하향 금지).

## 4. 완료 보고

카운트 + 게이트 결과(변경 = 미커밋 워킹트리, 커밋은 호출자 소관) + 피드백 한 줄(의무 — 발견분만 `feedback.md`).

## 가드레일

- **규약 편집 원칙 밖 코드 변경 금지** — 이름 변경·추출 등은 리팩터 후보로 반환한다(별도 `/implement` — 스윕에 섞으면 게이트 강도가 규모를 감당 못 한다).
- 🔒 **게이트 스킵 금지** — "가벼운 변경"을 이유로 §3 생략 불가(유용물 유실은 diff green으로 안 잡힌다).
- 🔒 **규약 교차 겸사겸사 금지** — 지정된 규약의 편집만 한다(게이트 강도가 그 규약 기준으로만 잡혀 있다). 발견분은 보고만. **단 그 규약 편집이 직접 stale화한 주석의 동갱신은 그 규약 편집의 일부다** — 알면서 거짓 주석을 남기는 것이 더 큰 위반이다.
