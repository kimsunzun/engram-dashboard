# comments — retrofit (기존 주석 정리)

> 판정 기준·마커 legend = `comments.md`(함께 Read). 공용 역학 = `retrofit-flow.md` — **이 문서만 읽고 워커 스폰 금지**(워커 슬롯 하한·커버 대조·게이트 하한이 그쪽에 있다). 이 문서는 **§기준을 그대로 두고 소급 작업에만 필요한 것을 더한다.**

## 편집 원칙

R1. **주석·공백만 바꾼다** — 코드 토큰 불변. 이름 변경·추출은 후보로 보고만. 주석 컨테이너가 코드 토큰인 자리(JSX `{/* */}` 등)는 내용이 전부 삭제 대상이면 컨테이너째 지운다 — 빈 껍데기 금지.
R2. **테스트 코드도 대상이다.** 단언을 바꿔 말한 주석은 지운다 — `assert` 메시지는 코드라 안 지워진다. **남기는 건 "이 값·픽스처가 무엇을 대표하나" 라벨뿐**이고, 그것도 이름·메시지가 이미 나르면 지운다(재진술은 메시지가 없어도 지운다).
R3. **앵커(§기준 7)는 토큰만 불가침** — 토큰이 남는 한 같은 주석의 나머지 문장은 일반 규칙을 따른다. 토큰이 지울 문장에만 실려 있으면 문장은 지우되 `// ADR-NNNN` 한 줄을 남긴다. **단 같은 토큰이 같은 사실과 함께 리포 어딘가 살아 있으면 안 남긴다**(범위 = 리포 전역) — 지시 대상 없는 맨 토큰은 쓰레기다. 어느 쪽도 아니면 **occurrence 0 은 위반**이고, 리포에서 해소 안 되는 앵커는 보존 + 보고한다. **원래부터 맨 토큰이던 한 줄도 같은 판정** — §기준 7 은 토큰을 보호하지 지시 대상 없는 토큰을 보호하지 않는다.
R4. 🔒 **한 사실은 한 집 — 반복은 지운다**(사용자 결정). 정본 하나만 남기고 나머지 자리의 복창은 **전부 지운다.** 정의 안이든(doc 블록 ↔ 본문) 정의를 넘든 같다.
  - **정본 = 그 사실이 정의되는 자리** — 그 타입·함수·모듈 자신. 선언과 정의가 갈렸으면 소비자가 계약을 찾으러 가는 쪽(C++ 헤더 · Rust 그 파일 `//!`).
  - **정본이 안 갈리는 때만 보고로 돌린다.** "찾은 사람이 자기 자리에서 읽어야 한다"는 보존 사유가 아니다 — 그건 정본을 찾아가게 만들 이유지 사본을 늘릴 이유가 아니다.
  - 자기 자리에서 §기준 1 에 걸리는 주석은 중복 여부와 무관하게 지운다.
R5. **섹션 구분선은 대상이 아니다** — 항해 표지지 주장이 아니다. 단 **구분선이 코드에 대한 주장을 달고 있으면 그 주장에는 일반 규칙이 걸린다**(구분선 자체는 남긴다) — 안 그러면 거짓이 된 주장을 규칙이 보호한다.
R6. **없던 주석을 새로 쓰지 않는다** — 빠진 계약·의도는 발견만 보고한다.
R7. **docstring 이 코드인 언어(Python 등)는 이 규칙으로 지우지 않는다** — 삭제가 곧 코드 변경이다.
R8. **마커는 대상이 아니다** — 내용만 본다. §기준 4 위반을 발견해도 마커는 그대로 둔다.

## 전수 반환 항목 (워커가 빠짐없이 보고 — 스팟체크 아님)

- **stale 후보** — 코드와 어긋난 주석. 정정안 + 무엇을 근거로 판정했는지(§기준 5). 어느 쪽이 옳은지 못 가리면 정정하지 말고 이 목록으로.
- **해소 불가 앵커** — 리포 전역에서 지시 대상을 못 찾은 앵커 토큰(R3).
- **리팩터 후보** — 이름이 동작을 못 담는 자리(R1 — 편집 금지, 목록만).
- **누락 계약 후보** — 있어야 할 계약·의도가 없는 자리(R6 — 새로 쓰지 않고 발견만).

## 기계 확인 (메인 수행 — 워커 자평으로 갈음 금지)

- **코드 토큰 불변** — 편집 전후에서 주석을 제거한 토큰 열이 동일한지 대조. 정규식 치환은 블록·JSX 주석에 오탐이 나므로 그 언어의 파서/AST 대조가 정본.
- **앵커 census** — 편집 전후 토큰 목록 대조. 파일 내 occurrence 0 이 된 토큰은 **R3 조건(같은 사실과 함께 리포 어딘가 생존)을 메인이 확인한다** — 확인되면 정상, 안 되면 위반. 범위는 R3 과 같은 리포 전역이다.
- **커버 대조** — 워커가 보고한 마지막 처리 앵커 vs 실제 파일 말미(retrofit-flow §2).

## 게이트

- **하한 = `/review doc` 1회** — 코드 토큰이 안 변하므로 `/qa` 는 하한이 아니다.
- **단 그 언어가 doc 주석을 파싱하면 빌드 확인 필수**(Rust `///` 위치·생성기 입력 등 — 주석만 고쳐도 컴파일·생성물이 깨진다). 생성물 트리로 doc 이 복사되는 스택은 생성물 diff 도 함께 본다.
