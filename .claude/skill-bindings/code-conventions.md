# code-conventions 바인딩 — engram-dashboard

## 바꾸는 규칙

- **「주변 코드의 관례를 따른다」** (§코딩 > 설계)
  - 대신:
    - 새로 쓰는 코드(새 함수·새 타입)는 §코딩을 기존 관례보다 앞세운다. §코딩이 정하지 않은 이름·패턴·스타일은 주변 관례를 따른다.
    - 기존 함수를 통째로 다시 쓰면 §코딩을 따르고, 일부만 고치면(기존 함수에 줄을 넣는 것 포함) 그 함수의 이름·패턴·스타일을 따르되, §코딩의 다른 규칙(에러·자원·외부 입력 등)은 크기와 무관하게 따른다. 기존 방식이 §코딩과 다르면 보고한다.
    - 구조(파일·모듈 배치, 타입 분할)는 과업이 바꾸라고 하지 않는 한 기존을 따른다.
  - 이유: 이 프로젝트는 기존 코드보다 공용 규약이 맞다(사용자 결정). 다만 한 함수 안에서 방식이 섞이면 읽기 어렵고, 구조까지 맞추면 과업 diff가 과업 밖 변경으로 부푼다.
- **「기존 주석은 지우지 않는다」** (§주석 > 기준)
  - 대신: 자기가 고치는 함수 안의 기존 주석을 적극적으로 §기준에 맞춘다. 남길 이유가 없는 주석·주석 처리된 코드·담당자 없는 TODO는 지운다. §보호 항목은 남긴다.
  - 이유: 추적 소스 전량을 이 기준으로 한 번 정리한 우리 프로젝트다. 남의 작업을 건드릴 걱정이 없고, 기준대로 유지하는 게 목표다(사용자 결정).
- **「코드를 바꾸면 그 변경 때문에 틀리게 된 주석을 고친다」** (§주석 > 기준)
  - 대신: 자기가 고치는 함수 안이면 원래부터 코드와 어긋나 있던 주석도 고친다 — 코드가 의도대로라고 가릴 수 있을 때만. 주석이 의도라면 주석은 두고 코드 결함으로 보고하고, 못 가리면 고치지 않고 보고한다.
  - 이유: 위 항목과 같다. 다만 코드가 버그이고 주석이 원래 의도라면 주석을 코드에 맞추는 순간 버그의 흔적이 사라진다.

## 코딩

### 설계

- **비자명한 기술 결함(동시성·타이밍·flaky·성능·메모리)을 추측이나 매직넘버·타이밍 상수 조정으로 맞추지 않는다** — 발동 조건과 절차는 `docs/reference/debugging-conventions.md`를 따른다. (ADR-0038)
- **외부 코드는 패턴만 빌린다.** 그대로 옮겨야 하면 옮기기 전에 출처와 라이선스를 보고한다.
- **서드파티 라이브러리는 아래 셋 중 하나라도 「예」면 목적 인터페이스 뒤에 두고, 셋 다 「아니오」면 그냥 쓴다** — ① 바깥(디스크 · 네트워크 · 프로세스 · OS · 외부 서비스)과 닿나 ② 바뀔 가능성이 큰가(RC · 관리자 적음 · 선택에 자신 없음) ③ 그 타입이 여러 곳 · 여러 crate 로 퍼지나. 감싸는 단위는 라이브러리가 아니라 목적이다 — 1:1 얇은 래퍼를 만들지 않는다. 언어 표준 · 기반(serde · tokio · React · Zustand) · 한 곳에서만 쓰는 순수 도우미는 감싸지 않는다. (`docs/tracking.md` T-61)

### 테스트

- **모듈은 외부 의존(Tauri·네트워크·실제 프로세스)을 seam으로 끊어 단독으로 도는 테스트를 갖춘다** — 새 모듈은 그 테스트와 함께 만든다. 외부 의존을 직접 불러 단독 실행을 막는 코드는 seam으로 끊는다. (ADR-0012)
- **테스트하기 어려운 구조를 만나면 테스트 가능하게 나누는 안을 검토해 보고한다** — 나눌지는 사용자가 정한다. (ADR-0012)

## 주석

### 기준

- **결정(ADR)을 모르고 고치면 그 결정이 깨지는 코드에는 ADR 앵커를 단다** — 새로 쓰거나 고치는 코드부터. 다음 세션은 `rg "ADR-"`로 코드에서 결정을 찾는다.

### 양식

- **코드로 읽히지 않는 파일 전체의 불변식·책임 경계(자동 vs 호출자 책임, 보장 vs best-effort)가 있으면 파일 머리 주석(Rust `//!`, TS는 파일 첫 `//` 주석)에 적는다** — 그 파일을 새로 만들거나 그 불변식을 바꿀 때. 선언마다의 계약은 규약대로 doc 주석에 쓴다.
- **ADR 앵커는 주석 첫머리에 `// ADR-NNNN`(4자리) 형태로 쓴다** — 뒤에 `: 이유`를 붙일 수 있다. `/engram-adr lint`의 고아 앵커 검사는 `//` 뒤에 공백만 두고 오는 `ADR-NNNN`만 잡는다.

### 보호 항목

- **앵커 형태** — 규약 기준에 더해 `ADR-NNNN`(dashboard `docs/decisions/`)과 `FIX <숫자>`(리뷰 지적 번호)를 앵커로 다룬다.
