# implement 바인딩 — engram-dashboard

## 작업 문서 폴더

- 주제 하나 = `docs/process/S<n>-<슬러그>/` 폴더 하나. `S<n>` 은 CLAUDE.md 「브랜치·커밋」이 정하는 그 주제의 번호다.
- 폴더 안 = `README.md` · `prd.md` · `trd.md`. 한 주제에 PRD · TRD 가 여럿이면 `prd-<부제>.md` · `trd-<부제>.md`.
- `README.md` = 무엇인지 한 문단 · 정본 ADR · tracking 번호 · 그 폴더의 TRD 파일 목록(파일마다 상태 한 줄). 단계별 상태는 상위 TRD 항목에 두고 README 에 다시 적지 않는다.
- `README.md` 가 없으면 다음 굳힘 커밋에서 만든다.

## PRD — 무엇 · 왜

절:
1. 무엇 · 왜
2. 범위 / 비목표
3. 요구사항 — 번호를 단다(`R1` …).
4. 수용 기준 — 실측(화면 · CLI)으로 확인할 문장. 번호를 단다(`AC1` …).
5. 미결 결정 — 사용자 결정 대상(선택지마다 트레이드오프 · 놓친 대안) · 메인 기본값.
6. 위험

## TRD — 어떻게

- 머리에 「상태」 줄 = 판 · 날짜 · 정본 ADR.
- 절은 그 과업에 필요한 것만 쓴다 — 범위와 PRD 관계 · 모듈 경계 · 자료 모양(wire · 영속) · 동시성 · 시험 계획 · 구현 단위 · 결정 · 위험 · 리뷰 기록.
- 시험 계획 = 무엇을 무엇으로 확인하나 — qa 바인딩 표의 행 · 로컬 레인 · GUI 장면을 짚는다.
- 구현 단위 = 파일이 겹치는 단위는 순차로 둔다. 단위 끝마다 빌드 · 시험이 초록이어야 한다.
- 「리뷰 기록」 절 = PRD+TRD 리뷰 통과 한 줄 — 날짜 · 강도 · 판정 · 리뷰한 판의 커밋. 리뷰 경과(라운드 · 지적 · 고친 것)는 적지 않는다.
- 상위 TRD(여러 단계를 묶는 TRD) = 단계마다 항목 하나. 단계 TRD 가 따로 있으면 그 항목은 상태 한 줄 + 링크이고, 단계 TRD 내용을 옮겨 적지 않는다.
- 굳힘 표기 = `Implemented` · 다시 리뷰 표기 = `Re-review needed`(TRD 는 영어다).
- 다음 단계로 넘기는 것은 받는 단계의 TRD(단계 TRD 파일이 있으면 그 파일, 없으면 상위 TRD 의 그 항목)에 한 번만 적는다 — 굳힘 커밋에서 메인이 쓰고, 커밋 번호는 적지 않는다.
- 받는 단계를 바꾸면 새로 받는 단계의 TRD(파일이 있으면 그 파일, 없으면 그 항목)에 적는다. 굳은 TRD 의 옛 언급은 기록으로 둔다.
- 항목에 넘겨받은 내용이 있는 단계가 나중에 단계 TRD 파일을 만들면, 그 내용을 파일로 옮기고 항목에는 상태 줄 + 링크만 남긴다.
- TRD 의 결정 중 ADR 로 남길 것은 PRD+TRD 리뷰 통과 뒤 코딩 전에 쓴다 — 코더가 새 주석의 앵커로 단다(code-conventions 바인딩).
- 코딩 중에 정한 결정 중 ADR 로 남길 것은 그 조각의 커밋 전에 쓴다.
- TRD 를 쓰면 채팅 요약을 보이고(HTML 은 요청할 때만) 「이대로 리뷰로 갈까요?」에 답을 받은 뒤 PRD+TRD 리뷰로 간다 — 자율 모드도 같다.

## 레퍼런스

- 자리 = `docs/reference/architecture.md`(전체 지도) + `docs/reference/structure/<주제>.md`(주제 하나 = 파일 하나).
- 주제 = 다른 코드가 기대는 경계 하나(크레이트 · 모듈 · 외부 계약). 단계가 새 경계를 처음 만들면 새 주제다.
- 크레이트 `lib.rs` 머리 주석도 지금 동작 문서다 — 틀리게 만든 변경과 같은 커밋에서 고친다.
- 독자 = AI 에이전트(코더 · 리뷰어)뿐이다. 사람을 위한 설명을 쓰지 않는다.
- 넣는 것 = 다른 코드나 사용자가 기대는 동작 · 계약 + 지금 구조(무엇인가 · 어떻게 쓰나 · 대략의 코드 배치 · 주요 타입).
- 빼는 것 = 날짜 · 경과 · 「왜」(ADR 을 링크한다) · 코드를 보면 아는 세부.
- 코드는 파일 이름 · 심볼 이름으로만 가리킨다. 줄 번호를 쓰지 않는다.
- 새 주제가 처음 착지할 때 그 코드와 같은 커밋에서 만든다.
- md 가 없는 기존 주제는 단계가 닿아도 만들지 않고 메모도 남기지 않는다 — 나중에 따로 지금 코드에서 쓴다.
- 설명 HTML = md 옆 `<주제>.html`. 구조 그림으로 보는 개관이고, md 에 없는 사실을 넣지 않는다.
- 설명 HTML 은 사용자가 요청할 때만 만든다. 만들 때마다 지금 md 에서 새로 그린다 — 옛 파일을 다시 쓰지 않는다.

## 사용자용 HTML — 요청할 때만

- PRD · TRD 의 한국어 HTML 은 사용자가 요청할 때만 만든다 — `/engram-explain` 으로 쓰고 자리는 explain 바인딩을 따른다. md(영어)가 정본이다.
- 만들 때마다 지금 md 에서 새로 그린다.
- PRD HTML = 무엇을 왜 만드나 · 화면에서 어떻게 보이나.
- TRD HTML = 위에서 아래로 — 전체 구조 → 프로세스 · 연결 관계 → 각 부분의 역할 → 세부.

## 결정 대장

- 코더 지시서 재료를 추릴 때 결정을 읽는 곳 = ADR(`docs/decisions/`) · PRD 「미결 결정」 · TRD 「결정」 · `docs/tracking.md`(보류 항목).
- 보류 기록 자리 = `docs/tracking.md` — 사용자가 「나중에」로 정한 안 고친 권장을 여기 적는다.
