# 턴 도중 입력 — TRD 7판 §10-4 사용자 답 (2026-09-26 세션)

PRD·TRD 반영 전 임시 기록. 반영 워커의 입력이다(사용자 인용 = PRD §6 · TRD §10-1/§10-5 근거).

## N11 — 빚진 후속 턴(빈 턴)이 실패하면 → (b) 붙든다 · 원칙으로 넓힘

- **답:** (b). 빈 턴을 다시 내지 않는다. 빚은 남고 다음 사용자 글의 턴이 갚는다. 우편은 그때까지 기다린다.
- **넓힌 원칙(사용자):** 진짜 오류(요청 한도·과부하·맥락 초과) 또는 요청 단계 실패로 이상하게 끝나면 **사용자 글이든 우편이든 자동으로 넣지 않는다.** 다시 흐르는 계기 = 사용자의 다음 입력 턴이 **성공으로 끝남**(그 턴도 실패하면 계속 붙든다). → **모든 오류 턴 뒤 우편**에 적용: PRD §3-9 「우편의 한가」·§3-10 에 한 줄씩(오늘 문구 = 오류 턴 뒤 목록이 비면 우편이 곧바로 든다 → 바뀐다).
- **사용자 인용:**
  - 「진짜 에러면 강제로 쑤셔넣으면 안되잖아」
  - 「어쨋든 본질은 가능하면 자동으로 되고, 거기에 유저게 우선한다는 얘기지」
  - 「어쨋든 모종의 이유로 이상하게 종료될때 채팅 입력이 성공하거나 어쨋든 재개 신호가 오면 뿌린다는거잖아」 → 확정 「ㅇㅇ」
- **거부한 대안:**
  - (a) 포기하고 우편을 곧바로 흘린다 — 원칙(진짜 오류 뒤 자동 투입 금지)과 어긋남. 관행 조사: codex 가 실패 뒤 대기 입력을 자동 제출하는 동작이 결함으로 신고됨(openai/codex#24443).
  - 한도 해제 신호(초기화 시각)로 자동 재개 — 「아냐 일단 복잡하게 하지말자」. 신호가 사용 한도 한 종류뿐 · 예고 시각이지 해제 알림이 아님 · PRD §3-10 「한도가 다시 풀려도 저절로 보내지 않는다」와 같은 방향.
- **근거 조사:** `docs/research/queued-input-after-failed-turn-2026-09-26.md`(미커밋 · TRD 에서 링크할 것 — 고아 금지)

## 백로그(이번 기능 밖)

- 우편 알림: 사용자와 대화 중이면 「우편 왔습니다 — 확인하세요」로 묻고 펼치고, 대화 중이 아니면 그냥 펼친다(사용자 구상 2026-09-26). 오류 뒤 우편이 이유 없이 멈춰 보이는 대가를 이것이 푼다.

## N12 — 수락 모름 codex 항목에 누른 ✕ → (a) 곧바로 닫는다

- **답:** (a). ✕ 순간 끝난 것(버림)으로 친다 — LLM 목록에서도 곧바로 빠지고 「취소 중」을 거치지 않는다 · 명부가 비면 우편이 흐르고 뒤에서 기다리던 글이 넘어간다 · 늦은 에코가 오면 대화 끝 말풍선 + 모델이 답한다(결말 기록이 버림 → 말풍선으로 뒤집히는 것을 받아들인다).
- **사용자 인용:** 「끝난걸로쳐. 유저가 x눌렀을때 우연찮게 들어가는건 그냥 그렇다 치겠지」
- **거부한 대안:** (b) 받음이나 에이전트 종료까지 「취소 중」 — 어느 창에도 안 보이는 항목이 우편을 상한 없이 막고(N8), 그 동안 한가할 때 친 글도 목록을 거친다(AC1 상실). TRD §10-5 에 이미 거부한 대안으로 적힌 행 유지. PRD AC13 · AC11 문자와의 어긋남은 이 답으로 예외를 적는다.

## N13 — 수락 모름 항목 뒤에 친 글 → (b) 평소대로 순서대로 넘긴다

- **답:** (b). 수락 모름 항목은 이미 codex 에 넘긴 글이므로, 뒤에 친 글은 그 뒤에 평소대로 넘어간다(넘기는 순서 = 친 순서 그대로). 수락 모름 항목은 회색으로 남고 ✕ 가 있으며 우편은 그것이 나갈 때까지 기다린다(N8 — 목록에 보이므로 막힌 이유가 화면에 있다). 늦은 에코면 그 말풍선이 그 사이 넘어간 글들의 말풍선 뒤에 설 수 있다 — 방어 갈래 안의 화면 위치 문제로 받아들인다(PRD §3-4 · AC2 에 예외 한 줄).
- **사용자 인용:** 「음? 뭔소리야 순서대로 들어가는거잖아. 앞지른다는게 뭔소리? 또 발생되지도 않는걸 가정함?」
  - 설명 표현 교정: 「앞지른다」는 목록 화면 기준 표현이었고 실제 넘기는 순서는 C → D → E 그대로다. 수락 모름 갈래 자체는 관측된 적 없는 방어 갈래다(codex 가 요청에 30 s 넘게 답하지 않음 · 턴 끝 확인 실패).
- **거부한 대안:** (a) 뒤 글을 그 항목 뒤에 붙든다 — 이미 넘긴 글의 결과를 모른다는 이유로 대화 전체가 사용자의 ✕ 까지 멈춘다.

## 툴팁 → 「목록에서 빼기」

- **답:** ✕ 툴팁 = 「목록에서 빼기」(모든 항목 · 두 백엔드 같은 문구). 경고 문구를 붙이지 않는다.
- **사용자 인용:** 「계속 몇번을 얘기하는데 x눌러도 없어졌는데 안으로 들어가서 표시하는건 어쩔수 없잖아.」 (앞서 2026-09-25 「x를 건드릴 이유가 있어? 그냥 x누르면 목록에서 기계적으로 빼는거잖아」)
- **거부한 대안:** 「취소 — 글은 버려짐」(넘긴 codex 항목엔 틀린 말) · 「목록에서 빼기 — 이미 넘어간 글은 대화에 나타날 수 있음」(늦은 말풍선은 어쩔 수 없는 일이라 경고할 것이 아니다).

## 적용 범위 메모(오케스트레이터)

- N11 의 넓힌 원칙(오류 뒤 자동 투입 금지 · 사용자 다음 턴 성공이 재개)은 **두 백엔드의 우편**에 건다 — 우편을 넣는 것은 우리 쪽이라 벤더 동작과 무관하다. claude 의 목록 항목은 PRD §3-10 대로 벤더를 따른다(그대로). claude 오류 턴 판정 = `result` 의 `is_error`·`error*` subtype(`backend/claude/mod.rs:806-819`).

## 설계 기조(사용자 2026-09-26) — TRD 전반에 적용

- 「일단 유저 채팅입력 관해서는 너무 깐깐하게 안해도 된다는거지」
- 「복잡한것보다 약간 양보하면서 단순한 방향으로 하되 나중에 문제되면 기능 추가하면 되지」
- 적용: 드문 방어 갈래(수락 모름 · 턴 끝 「기록만」 · 늦은 에코)는 상태·규칙을 늘리는 대신 단순한 보수적 동작(그대로 둠 + 경고 로그)을 고르고, 「나중에 더할 후보」로 적는다. 새 멈춤 상태가 덮는 기존 규칙은 지운다. 6차 리뷰에서 드문 갈래의 가장자리만 나오면 7차는 돌리지 않고 TRD 확정 → 측정 → 구현으로 간다.
- 순서(사용자): 처음엔 「TRD 나오면 최종적으로 얘기하고 구현 들어가자」였으나, 같은 날 뒤이어 위임으로 바뀌었다 — 「나 자러갈테니깐 쭉쭉 진행해. 충분히 얘기한것같으니 구현 너가 알아서하고 후에 최종 보고하는걸로」. → TRD 확정·구현은 오케스트레이터가 하고, 사용자는 최종 보고를 본다. master 병합 · `v*` 태그 push 는 남겨 둔다(오케스트레이터 판단 — 되돌리기 어려움).
