## Decided by user
- Components: instructions, skills, settings (+ workspace as component). Presets = component-based, "+" attach, multiple components per agent.
- Agent = empty shell; the SETTINGS component picks backend+model(+backend-specific options). One backend-choosing settings component per agent (2 → error). No settings → can't launch. Swapping settings to other backend → new conversation.
- Quick-create (pick folder → instance) kept as convenience = internally inline (unnamed) components; library (named) components shared. Inline → promote to library later. Existing agents migrate as inline. (user: "나중에 추가로 얘기")
- Conflict rule: same slot occupied by two components in same layer → ERROR (workspace, settings key, skill name). Instructions concatenate in attach order. Layer overrides (global<project<agent<run) are intended, not errors.
- Native discovery (each CLI's own ~/.claude, ~/.agents, project CLAUDE.md/AGENTS.md): keep as-is; duplicates = user mistake; no detection, NO docs/help note.
- Workspace: user-specified folder → use it; none → Engram creates internal folder.
- Codex terminal: user folder → presets NOT applied, warning; Engram-made folder → supported by materializing files (instructions = generated file, skills = directory junctions). Regenerate every launch (deterministic content, no timestamps). Instruction-file approach to be measured later (resume reread, TUI read timing, AGENTS.override.md if needed, terminal compaction).
- Size limits (codex AGENTS.md 32KiB project_doc_max_bytes, skills.max_context_tokens 2%/10k): auto-raise via per-launch -c every launch (computed from size, not stored); notify only when size changed (store last-notified size per agent); context-share warning.
- Component edits apply on next launch/resume (same as CLAUDE.md norm). No "pending" badge.
- Priming (Engram receive contract) = a component, default-active; user can disable with warning. Codex terminal + user folder: priming only, via current -c developer_instructions (exception). Known gap: may be dropped on compaction (terminal unmeasured).
- Dynamic injection (option a): Engram injects at start / resume / after compaction / preset change. claude: --append-system-prompt-file + --system-prompt-snapshot off (+ additionalDirectories in --settings for skill read; native skills via --add-dir). codex JSON: developerInstructions at start, extraRoots every process, additionalContext on resume, re-inject after compaction (value rev or inject_items; experimental API).
- Sharing/export: later, keep simple. Now: home/office via git — component library = user-registered source folders (multiple OK), scanned live (not copied); components referenced by source + relative path; per-PC bindings source→absolute path; secrets never in library.
