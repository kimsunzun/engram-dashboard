## 4. Decisions already made

- `StreamKey = Infallible` (A) — no resume path exists by type; never call `Peer::resume_stream`.
- `RouteState` is owned by the driver actor (`&mut`, no lock). The TRD's "fake re-takes the same lock inside the names
  call" test becomes: order test (frontend event then names) + no lock exists by type. Record as a TRD deviation.
- Generation filter (§3-3 rule ②) compares against the watermark the consumer saw in the same inbox (max seen
  `Connected` generation), NOT `Peer::generation()` — the atomic would drop in-order messages and the read-ahead the
  transport salvages before `Disconnected`.
- Rule ① = drop everything whose token is not the key's current token. Rule ③ = generation-less `ConnectFailed` /
  `Rejected` / `GaveUp` of the current token always pass (also for a peer that never connected).
- `HandleToken` minted by the shell through a private constructor in C.
- Credential slot keyed by `Address` (B).
- Error constants stay in `connection.rs` until U4 (C references them in place); `emit_broadcast` moves in C (convention:
  found duplicate → move to shared place, both use it).
- `is_live` pre-check separates `NOT_CONNECTED` from `UNSENT_ON_DISCONNECT`.
- Visibility: A uses `pub` items; C decides `pub` vs `pub(crate)` (+ `private_interfaces` lint once items take
  `&dyn DaemonEvents`, which is `pub(crate)`).
- ★User decision — version mismatch (4001 / local `VersionMismatch`)★: shown on the EXISTING connection-failure UI
  surface (connection state → `ConnectionNotice`, `src/components/layout/ConnectionNotice.tsx`, fed by
  `daemon-connection-state`) — NO new popup. The daemon side only logs; the shell logs it too (state + log line, peer
  text masked, never in the UI). Do not build popup copy.
- DECIDED 2026-11-05 (TRD revision 9 · ADR-0345 · ADR-0346): network failures retry without limit (no `GaveUp(BudgetExhausted)` in production), token refusal is terminal, the band carries 「다시 연결」 (try now); D14 ① retired;
  cold-start failure behaviour (`Registry::add` spends the budget where `connect()` failed at once — U3).
- Policy (§7, applied in U4; tests may use it now): reconnect 5 · request 30 s · backoff 500 ms ×2 cap 10 s + jitter ·
  connect/handshake 10 s · keepalive 20/50 s · write 5 s · outbound 512 · inbound 512 / 16 MiB.

## 5. Owned by C: reply order (§3-3 B2 · §8-1 R10)

A reply with `reply_tag` Some wakes its waiter inside the supervisor and never enters the inbox; an event the daemon sent
just before it may still sit in the inbox. C adds (a) a test that pins the order on `Registry<ShellWire>` +
`MemoryNetwork` (push event, then reply; the request resolves while the event is still unread) and (b) a caller survey:
every `send_command` / `send_command_with_origin` / `request_replay` caller and `forward_daemon_command` — does any rely
on a broadcast (e.g. `AgentListUpdated` after `Spawn`) having been emitted before the reply returns? Write findings into
the TRD landing note.

## 6. Risks

- Generation filter against the live atomic (see §4) — silent loss of in-order messages.
- Backpressure deadlock: pump → driver mpsc full → inbox full → supervisor stops reading → even direct-wake replies stall.
  The driver must never await `request()` inline (invariant 1 applies transitively). State it in the module doc.
- `AgentNamesSink` lock order: the real sink takes the layout lock (`layout/apply.rs:681-692`); never call ports while
  holding any routing lock; a re-add under the layout lock must not take one either.
- State emission must be edge-only: `ConnectFailed` arrives per attempt; emit `Reconnecting` once per drop, `Down` once.
- `Dropped{Outbound}` mixes real loss with intentional old-generation drops (`notify_in` after reconnect) → log only.
- `TransportEvent` non-exhaustive → wildcard arm logs; new variants are silently logged.
- Overlapping old/new supervisors of one key share a `KeySlot` → keep last-known endpoint per slot, benign.
- Until 3-3 the real daemon rejects with Error + close without code → 4001/4006 paths are proven in memory only.
- `ShellWire::encode` `expect` would abort the app (ADR-0292) if `AgentCommand` ever failed to serialize.
