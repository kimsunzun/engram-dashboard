## [IMPL] fix in the TRD
1. [A] Latch fast path race — `submitted` AtomicBool lets a 2nd concurrent submitter (mail flush vs user write_input on different threads) send before the 1st commit finishes → first turn leaves before persist (claude stdio/PTY, codex PTY). Set the fast-path flag only after commit returns (or when no commit can ever happen); otherwise take the mutex. Test: 2nd note during an in-flight commit must not return before commit completes.
2. [A] D2 incarnation binding — `handle_subscribe` reads `agent_epoch`/`agent_incarnation` then `subscribe_from` does a second `get_session` (connection_core.rs ~1747-1777, manager.rs ~2558-2568): ack flag/epoch may describe a different Arc than the replayed one (esp. around D4 swap). Have `AgentSession::subscribe_from` return epoch + `continues_conversation` in `SubscribeOutcome` (compute epoch match inside); build ack + ReplayComplete from it; drop the separate lookup. Test: respawn-during-subscribe.
3. [A] RichSlot reset window — `onReset` keeps `replayDone` true (RichSlot.tsx ~198) while clearing items/hasSent and (per TRD) the new flag → `showEmpty` true until next 'live' → a paint in between recreates the flicker. Clear `replayDone` in onReset; 'live' restores it with the new flag. Test: reset alone before 'live'.
4. [A] Latch default "none" → a spawn path that forgets to attach the latch silently loses ALL resumes. Make the latch mandatory in production assembly (`spawn_session` takes it; only test constructors pass an explicit no-op). Add a source-structure test (repo convention) that `spawn_agent_watching_link` passes `offer_sink()` to `open_spawn` and the same latch to the session. Reword Q4: "(a) leaves D1 end-to-end persistence verified only by GUI".
5. [A] claude offer timing — if the minted id is offered after publish (sessions insert), a parked-mail flush can note first → sends with id unknown → commit after. Offer the minted/stored id at latch creation (before `open_spawn`); pin with a test. Also state claude offer is keyed on the `assigns_session_id` axis (backend-neutral).
6. [A] Commit overwrites tracker id — commit uses overwrite verb `observe_session_id` (profile.rs ~709-722); if the ADR-0008 tracker persisted a new id Y before the first submit, commit rewinds to spawn value.
