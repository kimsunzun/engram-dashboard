## USER decision — added to (바) as a sub-question
- U1 (codex BLOCK) A contained non-poison panic leaves the latch clear; the boundary then logs synchronously (`base/src/logging/mod.rs:130` file-sink Mutex). If another thread stalls while holding that Mutex, the request never completes and no watchdog starts. Codex asks for "a separate deadline for every panic until its boundary commits an error response". The Claude reviewers classify contained non-poison as "not terminating by design". Main view (recommendation): NOT panic-specific — any log call on any request (no panic) blocks the same way on a stalled sink; a destructor stalling during unwind is a generic hang. A per-request hang deadline is a general hang watchdog = the time-limit device ADR-0288 deferred ("나중에 — 복원 시스템과 연관"). Recommend: keep out of this TRD, list as residual in §4-11 with that reasoning; option for the user = add a per-panic boundary deadline now (cost: a timer per caught panic + what to do on expiry — pull the latch? → turns a contained panic into a restart after N s).
