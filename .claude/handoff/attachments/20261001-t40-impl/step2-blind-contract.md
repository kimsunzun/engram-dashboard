# Contract for step ② under review (blind — what it must do, not why)

New file `crates/engram-dashboard-agent/src/backend/claude/leftover.rs` (not yet wired into production; step ③ will call `GateCell::interrupt`, `open_turn`, `deliver`, `close_turn`). It decides which leftover processes in OUR Windows Job to terminate after a user interrupt (Esc) of a claude agent that then stays hung, and terminates them. Platform pieces it uses (`ProcessGroup`, `Pinned`, `Births`, `RetiringSignal`) were reviewed earlier; `ProcessGroup::is_gone()` is new here.

## Must hold
1. **Never terminate a wrong process.** Only processes that (a) joined our Job after the interrupt line was written to claude's stdin (enforced by: pid ∉ W, a member-pid list taken right after the write, while candidate is held open from its join notification), (b) are held by a handle opened at their join notification (identity pinned; kill right requested then), (c) are not in the snapshot taken at the interrupt, (d) are alive at the pass, and (e) satisfy ALL rules: parent is a known, exited link; candidate is a copy of its parent (same image and same command line, or parent's command line is `-c "bash …"` hook form); every ancestor up to claude (the child of the root) is known, exited, and parent.create ≤ child.create on every link; the top T is `bash.exe -c "bash …"` (not containing `shell-snapshots`); claude spawned `taskkill.exe /PID <T> /T /F` with create ≥ T.create. Anything unknown → no kill.
2. **Timing:** a pass runs only if the turn has not ended N=3 s after the latest written interrupt line; up to 3 rounds; kills in a round confirmed within one shared 200 ms deadline; a refused commit (turn ended / new interrupt / new input / retiring) aborts the whole pass.
3. **Commit atomicity:** recheck (outside lock) → gate lock → `still_due`-style check → exactly one terminate call → release. Inside the gate lock: only field updates, monotonic clock reads, atomic reads, and that one terminate. Inside the record lock: only field/Vec/Arc operations (allocation allowed — pushing, Arc::new, cloning a Vec of Arcs). The two locks are never nested. Under either lock: no OS call, no log, no thread spawn, no handle close (no last drop of an Arc<Birth>/snapshot); under the GATE lock additionally no allocation/free.
4. **Opener exclusivity:** only one interrupt sets up an episode; all non-success exits of the opener undo its flag and stop its record (outside the lock).
5. **Listener thread:** starts before the job is attached to the port; attaches only if the thread started; per round never holds a strong Job reference while waiting; exits when the group is gone or retiring; on failure latches `port_failed`, stops recording, detaches; if detach fails, drains without recording. Pins happen outside the record lock; dedupe by (pid, create); cap 512.
6. **Panic-free by construction** (release builds abort on panic): no unwrap/expect/indexing on production paths; catch_unwind guards are only a debug safety net.
7. **No leak / wedge:** threads end with the incarnation; handles closed exactly once; nothing waits forever.
