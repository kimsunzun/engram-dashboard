## User decision (implement)
H1. **Failed `ensure` text when no daemon is live.** Old driver: `HandshakeError::NoLiveDaemon` → "daemon down — connect(명시 시작) 필요 (ADR-0021: ensure 는 respawn 안 함)". V2 today: the dialer's `NO_RECORD`/`UNUSABLE` (`link/dialer.rs` ~143-150) → `answer_first` maps every `Unreachable` to `HandshakeError::Connect` (`connection_v2.rs` ~878-881) → "daemon websocket 접속 실패: no daemon endpoint record — no live daemon" (or "…record is unusable: daemon.json names pid N which is not alive"). User decision (after a convention survey, `docs/research/client-without-daemon-message-2026-11-07.md`): **cause + a short question hint**, the Docker/kubectl/Tailscale shape — e.g. `no live daemon (no endpoint record) — is the daemon running?` and for the stale record `no live daemon (daemon.json names pid N which is not alive) — is the daemon running?`. English. Apply it where a never-connected handle's first failure is "no live daemon" (absent / unusable record) and that text reaches `connect`/`ensure` callers (frontend `daemon_ensure`, LLM surface). Decide whether this goes through `NoLiveDaemon` (new text) or a new variant — keep `HandshakeError` texts in one place (`link/errors.rs` or wherever texts live). Do not change the version-refusal text (pending decision for U5). Test: `ensure` with no record → exactly the new text; stale record → the stale variant.

## Chosen recommendations (implement)
R1. **`connect`/`ensure` resolve before the `connected` event and the state watch.** `on_routable` → `route_item` calls `answer_first` (~829) before `route()`/`apply()`, which sends `state_tx` and emits `Connected`. The old driver emitted first, then resolved; the frontend documents that order (`src/api/tauriTransport.ts` ~465-470). Restore it: answer the first callers after `apply(out)`. Test the order (event/state observed before the caller's `Ok`).
R2. **`connect()` throws away the endpoint `ensure` found** (`connection_v2.rs` ~382 `found.map(|_| ())`). Seed the new registration's last-known endpoint from it so the first dial does not re-read `daemon.json` (a sharing violation right after spawn gives `BUSY_UNKNOWN` → `daemon_connect` fails and `down` flashes). Use the existing endpoint-source / dialer seam; no transport API change. If seeding needs a transport change, report instead.
R3. **The replay-deadline sweep wakes the actor every second forever** (~701, ~723-726), even with no daemon. Arm it only while replay flights exist (the old tick ran only while connected). Keep it on the injected clock; existing deadline tests must still pass.
R4. **No test covers the real production assembly.** Add a `lib_unit` test of `on_link` with the real `WsDialer` (16 MiB) + `LocalEndpointSource` on a temp data dir with a written `daemon.json` + a transport `WsListener` acting as the daemon (handshake per `link/handshake.rs`), `SystemClock` or the real clock if feasible: connect → one round trip → drop the listener side → reconnect to a new port written to `daemon.json`. Keep it fast (seconds) and deterministic; if a piece cannot be driven without a production hook, say which.
