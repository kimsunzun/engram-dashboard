## Design corrections (main decides)
- D1 (codex, lens N1, arch N3) shell hook: store `MAIN_ESCALATED` (SeqCst) BEFORE `pull` (or one atomic state pulled-by-main / pulled-other). Waker: `app.exit` first, log after. §4-11: inherent variant (background thread pulls first, then main panics) cannot be ordered away.
- D2 (lens N2) B1′ PTY watcher catch path: publish failure reason (Release / under slot lock) BEFORE kill child + take master; pump reads (Acquire) after EOF. Else finalize-once (ADR-0005) shows Exited, reason lost.
- D3 (lens N3) testability seam (ADR-0012): pass `&Escalation`/Arc into containment helpers, `ConnectionCore`, accept loop, shell exit session; process global only at main/hook wiring. Observer slot injectable, or each registration state in its own integration-test binary. U1/U3/U6 tests otherwise flip each other via one-way globals.
- D4 (lens N4) `kill_agent` → `enter_exiting` → `DaemonStatusSink` → net `ConnRegistry .expect("conn registry poisoned")` (`ws.rs:212`) runs before `session.kill` → if that poison caused escalation, every kill thread panics, no 2-verb kill. Fix daemon-side: run the sink broadcast under `contain` (hook still escalates on poison) or shutdown path tolerates sink panic. net untouched.
- D5 (lens N6) stderr drain: after first caught panic, stop parsing → drain-and-discard (no panic storm).
- D6 (lens N7) `send_input` scope guard emits `Dropped` on unwind when the replay path is usable; otherwise residual.
- D7 (lens N8, M7 partial) `run()` locals drop during M6 unwind / `Err(101)` before `exit`: `AgentManager::drop` unbounded reaper join; `SessionTracker::drop` join + `.expect` (abort in Drop during unwind) → skip joins when `thread::panicking()` or pulled, or `mem::forget` manager on the escalation path. Correct M7 example (stuck kill thread hangs tail ③ via `thread::scope` `manager.rs:3122-3128` awaited `lib.rs:823`). Add `child.wait()` under child lock (`pty.rs:414`, `stdio.rs:396`) to the unbounded-wait list.
