## 실패한 접근 (반복 금지)

- **브리핑을 글 목록 + mermaid 로 만든 것** — 로컬 파일에서 mermaid 는 코드 글자로 보이고, 사용자는 글 벽을 안 읽는다. 브리핑 = **기존 브리핑에 이어서, 그림(SVG)으로, 글은 그림마다 2~3줄.** 확인하던 그림을 빠뜨리지 않는다.
- **브리핑을 아티팩트로만 준 것** — 계정이 바뀌면 못 연다. 정본 = 저장소 `briefing.html` 하나, 고칠 때마다 `cmd //c start "" "<경로>"` 로 열어 준다. 사본(v44 · trd 판)을 만들지 않는다 — 결정마다 그 파일을 고친다.
- **관행 확인 없이 이름을 추천한 것** — 「라이브러리만」 → 「에셋」 → 「커스터마이즈」로 흔들렸다. 이름 · 레이아웃 추천은 관행(조사 또는 「기억 기준」 명시) 먼저.
- **리뷰를 반복(PRD 4 · TRD 3)하면서 비용을 미리 말하지 않은 것** — 사용자가 토큰 낭비로 강하게 항의했다. 큰 작업(여러 회 리뷰 · 대형 위임) 전에 범위와 대략 비용을 먼저 말한다.
- 결정 메모 정리용 수집자에게 시간순 메모를 통째 맡기면 비싸다(PRD 작성자 실측) — 주제별 「현재 결정」 색인을 두면 싸진다(아직 안 만듦).

## 사용자 응대 — 반복 금지

- 채팅에 ASCII 상자 그림 금지 · 결론 먼저 · 하나씩 묻기 · 이미 정한 것 다시 묻지 않기 · 사용자 말 그대로.
- 큰 작업을 띄우기 전에 범위 · 비용을 한두 줄로 먼저 말한다. 사용자가 거부(도구 호출 반려)하면 멈추고 묻는다.
- 「안다」고 말할 땐 근거 수준(원문 확인 · 기억 · 미확인)을 붙인다. 과장(「거의 같은 묶음」)을 하지 않는다.
- 사용자가 Anthropic 의 의도(토큰 낭비 지시)를 의심했다 — 그런 지시는 없다고 사실대로 답했다. 같은 말이 나오면 방어하지 말고 낭비의 구체 원인과 다음 조치만 말한다.
