## 사용자 확인 거리 (하나씩 — 결정 메모 ROUND 8 · 9 · TRD §6-5 6–11)

1. **U1 — 휴지통 없는 드라이브 가려내기**: 항목마다 「휴지통 없음」을 확실히 알려 주는 신호가 없으면(9b 파일럿에서 잼) 그 드라이브의 `.trash` 는 Engram 에서 못 비운다 → (a) 받아들임(탐색기에서 손으로) / (b) 사람만 누르는 「그래도 영구 삭제」 확인.
2. **U2 — M59 범위 승인**: 너무 큼 · 모르는 실패도 지우지 않고 `.trash` 에 남김(G45 는 「열려 있음 · 권한」만 말했다).
3. **U3 — YAML 저장을 안전 검사가 거부할 때**: 실측상 앵커(`&`/`*`) 공유값을 고칠 때만(0.9%). 메인 추천 = (a) 거부 + 앵커 이름을 알림. (b) 주석 다 잃는 재작성은 데이터가 뒷받침 안 함.
4. **U4 — 흐름 목록(`[a, b]`) 안 순서 바꾸기에서 줄 끝 주석 사라짐 · 값 고칠 때 따옴표 사라짐**: 받아들임 / 흐름 목록 안 순서 바꾸기 거부.
5. **항목을 빼면 그 위 주석 줄이 남는다**(다음 항목 설명처럼 보임) — 같이 지울지.
6. **설정 YAML 엄격 읽기(`strict_booleans`)**: 따옴표 없는 `yes` 가 ⛔ 오류로 뜸(지금처럼 조용히 참이 아님).
7. **휴지통 비우기 확인 창 문구** — 초안 「Windows 휴지통으로 보냅니다 — 휴지통이 없는 드라이브면 바로 지웁니다」(U1 에 묶임).
8. **ADR 근거 약함 4건**(0312 「프리셋 폴더 따로 + 부품 라이브러리 여럿」 · 0315 「URI 꼴」 · 0320 「중앙 휴지통」 · 0325 `icu_casemap` 「무겁다」) + **미채번 서버 초안의 빈 근거 14칸**(C×2 · F×1 · I×3 · K×2 · L×2 · M×1 · N×2 · V×1) + AA×1 · 출처 충돌 의심(Y/Z 경고 범주 · V 쓰기 실패 경고 등 — 초안 파일 머리 목록). 클라이언트 초안(E · P · Q · S · T · X · AC · AA 일부)은 클라이언트 단계에서 채번.

## 실패한 접근 (반복 금지)

- ADR 채번 스크립트는 **로컬 폴더만** 본다 → 다른 가지가 선점한 번호와 겹친다. 채번 전 `git for-each-ref` 로 모든 가지의 `docs/decisions/` 최대 번호를 보고, 겹치면 그 파일을 잠깐 로컬에 놓고 돌린 뒤 지운다. ★**git 이 한글 파일명을 8진 이스케이프로 내므로 `-c core.quotepath=off` 필수**★(안 붙여 0310 으로 잘못 채번 → 되돌린 적 있음).
- 워커 지시서가 가리키는 파일은 **스폰 전에 만든다**(r7 지적 모음을 늦게 써 워커가 메모로 대신함).
- 긴 줄 문서 리뷰는 통째 diff 대신 압축 word-diff(스크래치 `wdiff.js` — `git diff --word-diff=porcelain` 후처리)를 준다(37만 → 10만 바이트).
- 폴더 목록이 참조 검사를 한다고 사용자에게 틀리게 설명했다가 정정함 — 설명 전에 TRD 해당 줄(§1-7 `library.list` · §1-3 「상태 — 가리키는 줄에만」)을 먼저 확인.
- Git Bash 의 `sed`/`node -e` 로 긴 한글 · 백슬래시 고치기 금지 → node 스크립트 파일로. 스크래치의 `g8apply.js`(검사된 정확 부분 문자열 교체 · dry run)가 TRD 일괄 수정에 잘 맞았다(이 세션 스크래치 — 다음 세션엔 없을 수 있음).
