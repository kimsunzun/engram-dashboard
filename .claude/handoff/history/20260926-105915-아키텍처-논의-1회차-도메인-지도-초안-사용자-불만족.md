# 핸드오프: 아키텍처 논의 1회차 — 도메인 지도 초안을 만들었으나 사용자 평가 「별로 · 이번 세션은 실패」

## 한 줄 상태 · 다음 첫 액션

**사용자는 transport 부착(3단 계획 ①) 전에 「전체 의존관계·모듈 쪼개기」 아키텍처를 먼저 논의하려 한다.** 이번 세션은 사람용 지도(HTML)와 AI용 원자료를 만들었지만, 사용자 평가는 「솔직히 별로인데 지시하기도 애매하네 … 이번 세션은 실패네」였다.

★**다음 첫 액션 = 사용자에게 한 가지만 묻는다. 코드 조사나 서브에이전트 스폰은 사용자가 방향을 준 뒤에만 한다.**★ 물을 것은 둘 중 하나다.
- 2장 도메인 관계 그림에서 무엇이 기대와 달랐는지(도메인 구분인가 · 관계 표현인가 · 그림 형태인가)
- 사용자가 머릿속에 둔 도메인·모듈 구도를 먼저 듣기

## 사용자가 원하는 것 (원문)

- 순서: 「일단 모듈 리팩토링을 해야되고 현재 transport 만 하나 만든 상태야. 근데 transport 붙이기전에 전체 의존관계및 모듈 쪼개기 같은 아키텍처 먼저 다 논의 한다음에 진행하려고.」
- 형태: 「탑다운으로 큰것부터 작은것까지 내려가면서 볼수 잇는게 필요할듯. 챕터? 같은걸로 나눠서. 일단은 큰그림 조감도만」
- 문서 두 벌: 「조사하면서 나오는 내용들은 너가 볼 용도로 알아서 정리되고(어차피 공짜니) 내가 볼 용도를 정제」 → 사람용 HTML과 AI용 md로 나누고 서로 링크하기로 합의. 관련 룰은 「나중에는 적립해야됨」.
- **통과한 모양(1장 첫 판):** 「적당히 정보를 선별해서 잘된것같음. 이미지 큰거 한장하고 단순하게 폴더구조 설명한게」
- 도메인 기준: 「데몬 기준으로 우편시스템, 에이전트 시스템, 로깅, 커맨드, 등등이 큰 카테고리 아님?」 · 「인증도 있고」 · 방법 = 「이 도메인으로 선을 긋고 연관관계를 따져서 한모듈에 도메인이 몰려있으면 분리하던가 합치던가」
- **거부된 것:** 「그냥 도메인이 어떤것들이 있고 어떤관계로 되는지 그림으로 보여주면 되는데 이건 내가 못볼 문서잖아」. 그 뒤 그림 두 장으로 줄였으나 결과는 「별로」였다.
- 다크 모드만(라이트는 필요하면 말하겠다고 함).
- 옛 `docs/reference/architecture-overview.md`: 「일단 건들지마. 나중에 정리하자」(보류).

## 확인된 사실 (다음 논의에 쓸 것 — 메인이 코드로 대조함)

- 셸→`net` 의존은 `AuthFrame` 하나다(`src-tauri/src/daemon_client/connection.rs:24`).
- 셸→`agent` 의존은 기호 셋이다: `COMMAND_SPECS` · `llm_creation_refusal` · `normalize_cwd`.
- discovery→`net` 의존도 `AuthFrame` 하나다.
- `bin/engram.rs`는 데몬 lib를 한 번도 참조하지 않는다.
- 데몬↔에이전트 CLI 주 통로는 **양방향**이고 형태가 셋이다(`TransportShape::{Pty, StdioNdjson, StdioBidiJson}`).
- 에이전트가 먼저 데몬을 부르는 입구는 둘(MCP · `engram` CLI → `/control/*`)이고, `control/ingress.rs`의 한 처리기로 모인다(ADR-0086).
- transport 소비자는 0이다. 셸→데몬 WebSocket 클라이언트는 이미 둘이다(셸 `daemon_client`, discovery의 정지 명령 전용). 요청과 응답을 짝짓는 구현은 셋이다(transport · codex 연결 · protocol 보조 함수).
- 옛 overview의 「세션 복원 / 활성화」 절은 ADR-0186이 정본으로 지정했다. 살아 있는 인용이 7곳이고, 그중 정본 인용은 `reference/structure/agent-backend.md:181`과 `agent/src/manager.rs:2370` 둘이다. 지우려면 이 절부터 옮겨야 한다.

## 검증 상태

- 사람용 HTML은 헤드리스 Edge로 찍어 확인했다. ★**마지막 수정(라벨 위치 · 표 정렬)은 다시 찍지 않았다.**★
- 태깅 줄 범위는 ±10~20줄 근사다. 의존 숫자는 import 수준의 결합 지표이지 호출 횟수가 아니다.
- 코드, 테스트, 빌드는 건드리지 않았다(문서뿐).

## 실패한 접근 / do-not

1. ★**load 직후 핸드오프의 「다음 액션」을 실행하지 말 것**★ — 이번에 브랜치를 따고 `/research` 수집자 넷을 띄웠다가 사용자가 막았다(「야 뭐확인하는거야? 아직 할거 얘기도 안했는데?」). handoff `feedback.md`에 적립해 두었다.
2. ★**도메인을 기능 기준과 기술 층 기준(연결 · 명령)으로 섞지 말 것**★ — 받은 요청을 기능에 넘기는 어댑터가 전부 「연결」에 모여 「연결이 허브」라는 착시가 생겼다.
3. ★**사람이 원하는 깊이를 확인하지 않은 채 무거운 수집을 돌리지 말 것**★ — 파일별 태깅과 import 집계에 수집자 7명, 약 100만 토큰을 썼다. 사람용에 모듈 막대 · 행렬 · 후보 목록을 넣었다가 「내가 못볼 문서」로 거부됐다.
4. 통신 방향을 대충 그리지 말 것 — 처음 그림이 데몬→CLI를 한 방향으로, MCP를 되돌아오는 길처럼 그려 사용자가 오해를 짚었다.
5. nmfc 플러그인 훅(HANDOFF-TRIGGER · WIKI-PRECONSULT)은 이 저장소와 무관하다(Origin UE5용). 핸드오프는 전역 `handoff` 스킬로 한다.

## 정지 조건

- 사용자 지시 없이 코드 조사를 하거나 서브에이전트를 띄우려 할 때 → 멈추고 묻는다.
- `architecture-overview.md`를 고치거나 지우려 할 때 → 사용자가 보류시켰다.
- transport 부착(①)에 착수하려 할 때 → 아키텍처 논의가 끝난 뒤다(사용자가 정한 순서).
- 새 스텝 번호를 올리려 할 때 → 사용자 결정이다(지금 S21).
