## ★이 세션에서 가장 중요한 것 — 사용자가 진짜 원하는 것★

마지막에 사용자가 화를 냈고, 사유가 명확하다. **질문은 「md 경로만 넣으면 첨부되나」였는데 내가 계속 주변 설명을 했다.** 사용자의 실제 목표는 이것이다:

> 「나중에 **수십 마크다운들** 붙여야 되서 그러는거잖아」

**즉 목표는 우편 지시서 한 장이 아니라 「문서 여러 장을 에이전트에게 다는 체계」다.** 그 축으로 답이 갈린다:

- **`developerInstructions` / `-c developer_instructions`** = **내용만**. 경로 불가(스키마 전수 확인). 수십 장에는 안 맞는다.
- ★**`AGENTS.md`**★ = codex 가 **디스크에서 스스로 읽는다**. 이게 「파일로 붙이는」 답이다.
  - `$CODEX_HOME/AGENTS.md` — **50KB 온전, 상한 미발견, 사용자 저장소 오염 없음**. 단 `CODEX_HOME` 을 우리가 소유해야 한다(인증·설정을 그쪽으로).
  - 프로젝트 `AGENTS.md`(루트→cwd 체인) — **여러 층 병합**되어 문서를 나눠 둘 수 있다. **32KiB 기본, 넘으면 조용히 잘린다.** 사용자 저장소에 파일이 생기는 오염 문제. **위치를 옮기는 인자는 없다**(`project_doc_fallback_filenames` 는 이름만 바꾼다).
  - `AGENTS.override.md` — 프로젝트 AGENTS 전체를 **대체**(전역본은 생존).

**첫 질문은 이것이어야 한다: 「우편 규약 한 장을 지금 닫을까, 아니면 수십 장 체계를 먼저 설계할까」.** 둘은 다른 결정이다.

## ★실측으로 확정된 것 — 다시 재지 말 것★

### 우편·배달

- **배달은 PTY 밀어넣기 한 경로**다(`service.rs:1691` → `messaging_host.rs:133` → `manager.rs:2580` → `session.rs:251`). **백엔드 분기 없음.** 당기는 경로는 없다.
- **터미널 모드엔 claude 도 codex 도 턴 신호가 0 이다.** 그런데 claude 는 이미 받고 있었다. **ADR-0116 결정 7** 이 「턴 신호 없음 → 게이트 없이 즉시 주입」을 정책으로 박아 두었고 거부한 대안에 「관측 못 하면 배달 못 한다」가 명시적으로 기각돼 있다.
- **보내는 데 501ms** — 500ms `SUBMIT_PACING`(본문 → sleep → `\r`)이 그대로 보인다. PTY 쪽 비용이고 claude 답장은 0.4ms.

### codex 승인 (전부 codex-cli 0.155.0)

- ★**`mcp_servers.<서버>.default_tools_approval_mode='approve'` 가 세 경로 전부에서 MCP 승인을 없앤다**★ — TUI · `codex exec` · app-server. **유효값 `auto|prompt|writes|approve` 중 `approve` 만** 걷는다(`auto` 는 안 걷힌다 — 이것 때문에 한때 「설정으로 못 끈다」로 오판했다).
- **붙이는 데는 승인이 없다. 부를 때 있다.** (훅은 정반대 — 붙이는 데 심사.)
- **「항상 허용」은 디스크에 안 남는다**(홈 전체 해시 비교 · 새 프로세스는 다시 묻는다). 지속 경로는 스폰 인자뿐.
- **`codex mcp add` 로 등록해도 똑같이 묻는다**(저장 모양이 주입본과 바이트 동일).
- **TUI 다이얼로그는 창 제목 `Action Required` 로 감지되지만 셸 승인도 같은 제목**이다.

### 훅 신뢰 (다음 덩어리 재료)

- ★**`hooks.state` 에 「출처:이벤트:순번」 키 + `trusted_hash` 를 심으면 심사 없이 훅이 실행된다**★(실측 2회, 마커 폴더 생성 확인). 범위는 **그 훅 하나**.
- ★**해시를 계산할 수 없다**★ — 후보 8종 실패. **codex 를 한 번 돌려 읽어 와야** 하고, 훅 명령이 바뀌면 **조용히 심사로 되돌아간다.** 그 동기화 부담이 별도 결정거리다.
- `projects."<경로>".trust_level` 은 실재하지만 **훅을 안 덮는다**(이미 `trusted` 인데도 심사가 떴다).

### ★지시서 주입 — 다음 액션의 재료★

**`ThreadStartParams` 전 필드**(스키마 전수, `codex app-server generate-json-schema --out <DIR>`): `approvalPolicy · approvalsReviewer · baseInstructions · config · cwd · developerInstructions · ephemeral · model · modelProvider · personality · sandbox · serviceName · serviceTier · sessionStartSource · threadSource`. **지시 관련은 둘뿐이고 둘 다 `string` — 경로를 받는 짝은 없다.**

| 슬롯 | 모드 | 덧붙임/대체 | 상한 |
|---|---|---|---|
| `thread/start` 의 **`developerInstructions`** | app-server | **덧붙임** | 미발견(8MB 수용) |
| **`-c developer_instructions='<한 줄>'`** | 터미널 | **덧붙임** | **약 7.9KB**(`cmd` 8,191자 한계) |
| `baseInstructions` · `instructions` · `model_instructions_file` | — | ★**기본 프롬프트 17,730자를 대체**★ | 쓰지 말 것 |
| `developer_instructions_file` · `instructions_file` · `experimental_instructions_file` | — | **unknown configuration field** | 없음 |

- ★**터미널에서 줄바꿈을 그대로 두면 조용히 사라진다**★ — `cmd.exe /c codex.cmd` 가 첫 LF 에서 명령줄을 자른다. **오류도 안 난다.** 해법 = 줄바꿈을 **`\`+`n` 두 글자**로 치환(TOML 리터럴은 이스케이프를 안 푸니 모델이 그 글자를 그대로 보는데 **읽는 데 문제없었다** — 5문항 정답), 또는 공백 하나로 치환.
- **codex.exe 를 직접 띄우면 여러 줄이 바이트 일치로 들어간다** — 변환이 필요한 건 순전히 `cmd` 껍데기 때문이다.
- ★**작은따옴표 리터럴이라 지시서에 `'` 가 하나라도 들어가면 인용이 깨진다**★. 지금 1,364B 에 `'`·`"`·`\`·`%` 가 **우연히 하나도 없어서** 안전하다. **영어 축약형(`don't`) 하나면 터진다 — 가드 필수.**
- **덧붙임 증명 방식**: 모델이 지시서만 답할 수 있는 5문항에 답했고(없으면 전부 「NONE」), 동시에 `base_instructions` 길이가 **17,730 그대로**였다(대체 슬롯을 쓰면 1,331 로 줄어든다).
- **MCP `initialize` 의 `instructions`** 도 모델에 도달한다(우리 데몬이 `mcp_server.rs:658` 에서 이미 한 줄 내보내는 중, 40KB 온전). ★**단 도착 자리가 「도구 탐색 안내문」 안이고, ADR-0211 이 「설명문에 심은 행동 규칙은 무시됐다」를 실측해 뒀다**★ — 행동 규약에는 약한 채널이다.
- **SessionStart 훅의 `additionalContext`** 도 도달한다(자기 `developer` 메시지). **단 신뢰 없이는 조용히 아무 일도 안 일어난다.**

## ★실 왕복 결과 — 배선은 끝, 규약이 없다★

**됐다(셋 다 실물 증거):** claude → codex 봉투 배달(codex 대화에 그대로 꽂히고 턴 시작) · codex → claude 답장(`eg_send`, **승인 프롬프트 0건**, 6.7ms) · 장부 닫힘.

★**그런데 첫 시도는 실패했다. 그게 진짜 결과다.**★ codex 는 요청 봉투를 읽고 **자기 채팅창에 답하고 끝냈다**(「Reykjavík PONG」). 도구를 안 불렀다. **본문에 「`eg_send` 로 답해라」라고 적어 주자** 그제야 도구를 검색해서 찾아 답장했다.

**즉 codex 는 `eg_send` 가 있는 건 알지만 「`type="request"` 봉투가 오면 그 도구로 답해야 한다」는 규약을 모른다.** claude 가 이걸 하는 이유는 지시서를 받기 때문이다.

**운영에서 이 상태의 증상** = 편지는 도착하고, codex 는 읽고, 자기 화면에 답하고, **발신자는 영원히 기다린다.** ADR-0209 가 막으려던 상태가 배선이 아니라 **무지로** 재현된다.

## do-not (이 세션에서 실제로 겪은 것만)

1. ★★**확인 없이 단정하지 말 것 — 이 세션에서 네 번 틀렸다**★★. ① 「우편 게이트가 claude 에게도 보인다」 ② 「터미널엔 턴 신호가 없어서 codex 우편을 못 연다」 ③ 「TUI 에선 승인 다이얼로그에 답할 길이 없다」 ④ 「json 도 경로를 못 받는다」(이건 나중에 맞는 것으로 판명됐지만 **말할 때는 측정 전이었다**). **넷 다 「기록에 적힌 문장」이나 「조사자의 추정」을 실측처럼 옮긴 것이다.** 사용자가 매번 되돌렸고 마지막엔 화를 냈다.
2. ★**사용자가 좁은 질문을 하면 좁게 답할 것**★ — 「md 경로만 넣으면 되나」에 주변 설명을 붙였다가 「하라는건 안하고 계속 이상한소리만해」를 들었다. **결론 한 줄 먼저, 나머지는 물으면.**
3. **Bash heredoc 에 한글 본문은 되지만 python `-c` 안의 한글 리터럴은 이스케이프가 꼬인다** — `\uXXXX` 로 쓰거나 파일로 빼서 `cat >>`.
4. **`git merge-base master <wip브랜치>` 반사로 쓰지 말 것** — 피처 브랜치에서 딴 WIP 는 `git merge-base HEAD <브랜치>` 가 실제 델타를 준다(이번에 43커밋 오독).
5. **워커에게 「citation 붙이기」로 범위를 주면 틀린 사실을 인용으로 굳힌다** — 실제로 셋이 틀렸다. 코드 실측물에 인용을 붙이는 일은 **검증이 딸려 오는 작업**이다.
6. **`--lib`·`--all-targets` 금지** · **루트 bare `cargo test` 금지** · 회귀에 `-- --test-threads=4` 유지 · **앱을 셸에서 직접 띄우지 말 것**.

## 미결 · 사용자 결정 대기

1. ★**수십 마크다운 체계를 먼저 설계할까, 우편 규약 한 장을 먼저 닫을까**★ (맨 위 절)
2. **실 `~/.codex` 에 남은 세션 기록 6개** — 지울까 둘까
3. **codex 에 지시서를 싣는 경계 변경** — 데몬이 내용을 읽게 되므로 ADR-0092 「코어는 내용을 안 읽는다」를 넘는다. **읽기 실패 시 fail-open/closed 도 새 결정**(claude 는 그 판단이 claude 쪽에 있었다)
4. **훅 신뢰 자동화** — 방법은 찾았고 해시 동기화 부담이 대가
5. **도움말 화면 보수** — 루트에 빠진 계열(창·탭·테마) · `agent spawn` 들여쓰기 결함 · 「대시보드 붙어 있을 때만」 단서
6. **claude 쪽 우편 가시성** — claude 가 `engram help` 를 쳐도 우편이 안 보인다(지시서가 도구를 직접 가리키게 바뀌어 타격은 줄었다)
7. **에스컬레이션 축에 게이트가 없다** — 행동 규칙을 걷으면서 pin 도 사라졌고 대체하려던 테스트가 중복이라 지웠다(ADR-0213 영향에 기록)
