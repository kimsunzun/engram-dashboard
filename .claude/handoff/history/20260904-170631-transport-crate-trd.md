## ★사용자가 정한 것 — 이번 세션 (2026-09-04)★

### 만드는 것

**새 crate `transport`** — 기존 `net` 은 이번 작업에서 안 뜯는다. 새로 세워 독립 검증한 뒤, 데몬·셸에 각각 **전용 폴더**를 두고 거기서 붙인다. 최종적으로 `transport` 가 네트워크 담당 자리를 가져간다. **이름은 사용자가 골랐다**("뭔가 직관적이다").

**범위 = engram 셋(데몬·셸·모바일)으로 좁힌다.** "너무 범용을 생각하지말고" — 좁히면 기본값을 확정할 수 있고, 그 셋이 이미 서버·클라·모바일이라 구조는 범용으로 나온다.

**crate 안:** 프레임 경계 · 요청/응답 상관(**태그 타입에 제네릭 — 이름을 모른다**) · 역할 구분(요청/응답/알림/스트림) · 스트림 살림(식별자·세대·순번·이어받기·중복 제거·**구멍 찾기**) · 연결 수립 · **불투명한 핸드셰이크 프레임(횟수는 몇 번이든)** · **양방향 keepalive** · **쓰기 시한** · **백오프+지터** · **상대 N개 레지스트리 + 상대마다 감독** · **출처 표식** · **세대 경계 노출** · 팬아웃 · 유계 큐.

**밖:** 패킷 구조체 정의 · 주소·인증 자료 · 정책 값(전부 기본값 있음) · 짝짓기 번호 꺼내는 함수(**이미 `protocol` 에 정본으로 있다**) · 큐 정책 선택.

**전송과 시간 둘 다 갈아끼울 수 있게** — 검증 하네스와 나중 TLS 가 여기 걸린다.

### 그 밖 확정

- ★**봉투는 소비자 소유**★ — 우리 wire 엔 봉투 struct 가 없고 종류 이름이 곧 JSON 키다. 코덱도 둘(제어 = JSON / 출력 = 29바이트 헤더 이진). 실측 근거는 ADR-0177.
- **느린 소비자 = 차면 끊는다**(현행 유지). 터미널 바이트는 중간을 버리면 화면이 깨진다. 단 **정책은 바깥이 고르게** 둔다.
- **유실 신호** = 참/거짓 대신 **「지금 유효한 가장 오래된 번호」**, 콘솔이 아니라 **위층 스트림**에. **순번 구멍 검사 + 그 지점부터 재요청**까지 묶는다.
- **검증** = 로직은 전부 **인메모리 + 시간 주입**, 실소켓은 소수(붙나 · 쓰기 시한이 실제로 잘라내나 · **버전 거절 왕복**). 포트는 0번 요청. CI 에서 돈다.
- **재연결** = **유계** + ★**외부 신호로 예산 되살리기**★(망 연결·앱 복귀 — 증권 앱 패턴을 사용자가 참조로 제시). crate 는 「지금 다시 해라」 입구만 갖고 무엇이 신호인지는 셸·폰이 정한다. **소진되면 큰 알림 + 재접속 버튼**(버튼은 새로 만들어야 한다).
- **버전 거절** = 재시도 무의미하므로 **즉시 포기 + 팝업**. 「거절」과 「못 붙음」을 구분해야 한다(지금은 안 한다).
- ★**A 확정 — 닫기 프레임에 오류 코드 + 문구 둘 다**★. 문구를 파싱해 분기하지 않는다. WS 닫기 코드 4000~4999 가 애플리케이션용으로 비어 있고, **코드를 닫기에 실으면 「오류 프레임보다 닫기가 먼저 도착」 경합이 사라진다**(닫기는 반드시 온다).

### 붙이는 순서 (사용자 로드맵)

**① crate 세우고 혼자 검증 → ② 셸 클라이언트를 그 위로 이사(= 「연결 정상화」) → ③ 명부를 N개로 → ④ 데몬 쪽도 같은 crate.**
★**②까지는 동작이 안 바뀌어야 한다**★ — 그래야 뭐가 깨졌는지 안다. 새 능력은 ③부터.

## ★남은 결정 넷 — 다음 세션의 본 과업★

**하나씩 묻는다. 아래는 목록일 뿐 한 번에 올리지 말 것.**

1. **B — 로그 창을 이번 범위에 넣나.** 지금 사라지는 것이 많다(실측): 재연결 중 거절 사유 → 디버그 로그만 · 명령 결말 폐기 → 경고 로그만 · 되감기 잘림 → 브라우저 콘솔만 · 출력 구간 소실 → 아무도 검사 안 함. **파일 로그는 있으나 앱 안에서 볼 수단이 없다.** 넣는다면 **transport 가 사건을 올리는 것까지가 이번 작업**이고 화면은 별도다.
2. **C — 로그 창 범위.** 연결 관련만? 에이전트 오류·명령 실패까지? 커지면 별도 설계다.
3. **D — 팝업 버튼.** 버전 거절이면 「데몬 재시작」이 실제 해결책인데 ★그건 지금 금지 경로다★(ADR-0158 결정 3 「데몬 자동 kill 금지」— 살아 있다). **사용자가 눌러 동의**하는 형태로 예외를 둘지. 그리고 「그만 꺼져라」 명령이 프로토콜에 **없다**(실측) — 강제 종료뿐이고, 그러면 에이전트가 함께 내려간다(세션 복원으로 이어받되 매끄럽지 않다).
4. **③ 요청 시한 기본값** — 종류별로 다르게 갈지 하나로 갈지. 에이전트 spawn 은 느리고 상태 조회는 빠르다. **명령 「결말」 경로엔 시한이 아예 없다**(코드 주석이 자인).
   **④ ②단계에서 새 동작을 같이 넣을지** — keepalive·쓰기 시한은 「없던 것 추가」라 동작을 바꾼다. ②에서 넣을지 ③으로 미룰지.

## 실측 — 이번 세션이 확인한 것

**셸 클라이언트(`src-tauri/src/daemon_client/`, connection.rs 1,674줄):**
- ★**`tauri` 의존 0줄**★ — 이사에서 제일 비싼 벽이 이미 서 있다.
- 파일 8개 중 **셋은 이미 순수**(`replay_flight` · `protocol_state` · 일부) — 그대로 옮길 수 있다.
- **재연결·백오프는 이미 있다** — 500ms→1s→2s→4s→8s, **최대 5회 후 영구 Down**. ★지터 없음★.
- ★**클라 쪽 keepalive 없음**★ — tungstenite 가 pong 자동응답만. 능동 probe 도 idle timeout 도 없다. 물리 끊김을 스스로 못 잡는다.
- **요청별 시한 없음.** 단 **끊길 때 pending 과 미전송 버퍼를 전부 Err 로 깨운다**(no-hang 확인 — 「명령 미전송(재전송 안전)」). 연결 없을 때 `send_command` 는 즉시 Err.
- **재구독은 항상 `after_seq: None`** — 통째로 다시 받는다(ADR-0046 의도).
- ★**버전 거절 사유를 클라가 실제로 파싱한다**★ — `HandshakeError::AuthRejected(message)` 로 타입까지 올라오고 **첫 연결 때는 화면까지 간다**. ★**재연결 중에는 `debug!` 로그로만 남기고 버린다**★ — 데몬 죽음과 구분 안 되고 5회 헛시도 후 조용히 Down.
- ★**「다시 연결」 버튼이 화면에 없다**★ — `ConnectionNotice.tsx` 의 버튼은 알림 닫기뿐. API 는 있으나 부르는 UI 가 없다 → 실질적으로 앱 재시작.
- **데몬 거절 종류는 여섯**(`ws.rs`): 토큰 · 버전 · 첫 프레임 아님 · 형식 이상 · 텍스트 아님 · 시간 초과. **전부 문자열 하나로 뭉쳐 나간다.**
- ★**버전 거절 처리에 테스트가 하나도 없다**★ — `AuthRejected`/`ClosedBeforeHello` 를 단언하는 테스트 0. 데몬 쪽 문구도 무검(`ws.rs` 주석이 자인).

**큐·배압(현행):**
- 연결당 송신 큐 `CONN_TX_CAP = 4608`, 차면 **그 프레임 버리고 연결 종료**.
- 되감기 링 = 2MB / `max_events = 4096`, 앞에서 evict. **생산자는 안 막힌다.**
- ★**4608 > 4096 — 거꾸로다**★. 끊기는 순간 밀려 있던 가장 오래된 것이 이미 링에서 밀려났을 수 있어 「끊고 다시 붙으면 복구된다」가 그 숫자에서 깨진다.
- ★**진행 중 소켓 write 는 close_signal 로 못 끊는다**★ — 그동안 keepalive 도 멈춘다(`ws.rs` 주석 자인). 「차면 끊는다」가 실제로는 「차면 멈춘다」가 된다.
- **순번 구멍 검사 없음**(`rg` 0줄). 단조 dedup 만 있다.

## 실패한 접근 / do-not

- ★**여러 항목을 한 번에 올리지 말 것**★ — 두 번 지적받았다. 목록은 한 줄씩, 펼치는 것과 묻는 것은 **하나만**.
- ★**「보통 첫 패킷 보내면 버전을 안다」로 설계하지 말 것**★ — 버전 번호는 **연결하는 순간** 이미 안다(인증 프레임에 실린다). 메인이 「그 시점이 없어졌다」고 잘못 말했다가 사용자가 잡았다.
- ★**「그냥 끊으면 사유가 간다」는 거짓**★ — RFC 6455 `1006` 은 **와이어로 못 보내는 예약값**이고 받는 쪽이 합성한다. WHATWG 는 DNS 실패와도 구분 못 하게 하라고 명시. **단 핸드셰이크 거절은 다르다** — 아직 안 밀려 있어 사유가 실제로 간다. **두 상황을 섞지 말 것.**
- ★**「제어를 따로 큐에 넣으면 항상 나간다」는 거짓**★ — HTTP/2 가 제어 프레임을 흐름 제어에서 면제하지만 RFC 9113 §5.2.2 가 「즉시 읽어야 한다」를 MUST 로 강제해 성립한다. 상대가 안 읽으면 커널 버퍼에서 막힌다. **업계 답은 「보장」이 아니라 「쓰기 시한 + 연결 폐기」.**
- ★**「타입 seam 과 수명을 겸한 라이브러리는 없다」는 반증됐다**★ — `bevy_simplenet`·`tonic` 이 실물. 못 찾은 것은 거기에 **N-피어 레지스트리까지** 갖춘 것뿐.
- ★**「의존 방향 강제」·「소비자 둘 이상」을 crate 사유로 쓰지 말 것**★ — 선행 조사와 ADR-0151 결정 4 가 둘 다 무너뜨렸다. 살아 있는 기준 = **「독립적으로 쓸 수 있는가」 + 무게**(ADR-0175 결정 6: 파일 하나짜리 lib 금지).
- **ADR H1 은 `# ADR-NNNN: 제목` 형식이어야 한다** — 접두를 빼면 인덱스가 「(제목 파싱 실패)」로 뜬다(이번에 실발생, 수습함).
- **조사 착수 전 `ls docs/research/` 를 먼저 볼 것** — 지난 세션이 안 해서 같은 주제를 두 번 돌렸다.

## 정지 조건

- ★**TRD 브리핑 없이 구현에 진입하려 할 때**★ → 멈춘다. 사용자가 "구조 TRD 확실하게 나한테 브리핑하고 구현해야되"를 명시했다.
- **남은 결정 넷 중 하나라도 미결인 채 코드에 손대려 할 때** → 멈춘다.
- **기존 `net` crate 를 수정하려 할 때** → 멈춘다. 새 crate 를 세워 독립 검증하는 것이 먼저다.
- **여러 결정을 한 번에 올리려 할 때** → 하나로 줄인다.
- **새 스텝 번호를 올리려 할 때** → 사용자 결정. 지금 S21.
