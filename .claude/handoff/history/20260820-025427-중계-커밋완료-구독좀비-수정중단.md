## ★진행 중인 것 — 구독 좀비(핵심)★

### 증상

데몬을 껐다 켜면 그 에이전트 슬롯이 **껍데기**가 된다. 트리는 초록불, 더블클릭도 되고, **입력도 실제로 나가는데**, 출력이 한 글자도 안 온다. 새 슬롯·새 창을 만들어도 같다. **앱을 껐다 켜야만 풀린다.**

### 원인 (production 로그로 확증 — 추론 아님)

셸(src-tauri)의 재생 단일비행 슬롯이 **거절당하면 영영 안 풀린다.**

```
17:32:17  request_replay 채번 agent_id=d26b6d03… gen=1 send_now=true
17:32:17  WARN 데몬 error 이벤트 request_id=None subscribe failed: agent d26b6d03… not found
17:32:28  WARN replay 무진행 만료 — 실패 마커 발행, 슬롯은 좀비로 유지
17:32:28  request_replay 채번 … gen=2 send_now=false
17:32:40  … send_now=false     ← 이후 전부. 더블클릭·새 슬롯 포함, 수 분간
```

- 재연결 시 **자동 재구독은 옳은 동작**이다(끊긴 사이 출력을 이어받아야 한다). 문제는 그 시점 새 데몬에 에이전트가 아직 없어 **거절**당하는 것.
- 그 거절이 셸에서 **조용히 버려졌다** — `emit_broadcast`에 `AgentEvent::Error` arm이 없었다. **이번 세션에 로그를 넣어 비로소 보이게 됐고, 그게 3세션 걸린 이유다.**
- 슬롯 해제 조건이 **완료 / 연결끊김** 둘뿐이고 **거절이 없다**. 만료돼도 일부러 안 푼다(뒤늦은 Ack 오귀속 방지 — `replay_flight.rs:216-220` 주석).
- ★**슬롯 키가 에이전트 단위**★ — 좀비 하나가 그 에이전트를 **모든 슬롯·모든 창에서** 봉쇄한다.
- `Subscribe`엔 `request_id`가 없고(`protocol_state.rs:370-379` 테스트가 단언) 거절 메시지에 agent_id가 **글자로만** 있어, **wire 변경 없이는 상관을 지을 수 없다** → 계약 추가가 불가피.

### 결정 (사용자 승인 2026-08-20)

**`AgentEvent::SubscribeFailed { agent_id, reason }` 추가 + `ReplayFlightSet::on_refused(agent)`.**
- 안전 근거: **거절된 Subscribe는 Ack도 Complete도 절대 안 온다** → 그 슬롯을 풀어도 오귀속 대상이 없다. 만료-해제 안(거부)과 갈리는 지점이 이것이다. **이 논거를 `replay_flight.rs:216-220` 옆에 코드로 박을 것**(지시서에 포함했다).
- 거부한 대안: ① 만료되면 풀기 — 주석이 금지한 오귀속을 되연다 ② 셸이 명부 미러를 들고 없으면 요청 보류 — 셸을 무상태 통과 라우터로 둔 ADR-0046을 뒤집는다.

### 남은 작업

1. `on_refused` 구현(슬롯 해제 + 그 세대 실패 마커 즉시 발행 + 합쳐진 `next_gen` 진행).
2. `connection.rs`에서 새 이벤트 수신 → `on_refused` 호출.
3. ts-rs 바인딩 재생성(생성물 게이트가 CI에서 diff한다).
4. 테스트: `on_refused` 뒤 같은 에이전트 `request_replay`가 `send_now: true`(현재 영원히 false). 되돌려 빨강 확인.
5. **실측**: 데몬 껐다 켜기 → 로그에 `send_now=true`가 다시 나오는지 + 화면에 출력이 오는지.

**빌드 주의**: 릴리즈 앱·데몬이 떠 있으면 `target/release/*.exe`가 잠겨 os error 5. 격리 `CARGO_TARGET_DIR`을 쓰거나 앱을 먼저 내린다.

## ★실패한 접근 / do-not★

1. ★**환경을 먼저 확인하지 않고 원인을 추정하지 말 것 — 이번 세션 최대 낭비**★. 「데몬 껐다 켜면 안 된다」를 두고 **트레이 종료 탓 → 백엔드 변경 탓 → 복원 실패 탓 → 어제 커밋 탓**으로 네 번 틀렸다. 진짜는 ⓐ 초기 관측이 **타 워크트리(`engram-dashboard`) 릴리스 고아 데몬**에 붙은 앱이었고 ⓑ 진짜 결함은 셸의 구독 좀비였다. **측정 전에 `Get-CimInstance`로 앱·데몬 exe 경로와 포트 소유자를 먼저 본다.**
2. ★**데이터 폴더가 빌드마다 다르다**★ — 디버그 = repo 루트 `.engram-data`, 릴리즈 = `target/release/data`. 엉뚱한 폴더를 읽고 「id가 하나도 안 겹친다」로 오진했다.
3. ★**1420(vite)을 남이 잡고 있으면 디버그 앱이 남의 화면을 로드한다**★ — 옛 버전 검증 때 실제로 걸렸다. 띄우기 전 포트 소유자의 **경로**를 확인한다.
4. **셸 백엔드는 이 입구로 못 만든다**(코드에 결정으로 박혀 있음 — `AgentCommand::Shell => None`). 그래서 실측용 에이전트는 claude로 뜬다. sid가 `null`이면 셸이라 그런 것 — claude 여부부터 본다.
5. **`agentlist.createTerminal`을 CDP eval로 부르면 영구 정지한다**(UI 응답 대기). 실측에선 `spawn_into` IPC를 직접 쓴다.
6. **코더가 「닫았다」고 하면 경로를 직접 걸어 확인한다** — 이번 세션 3회 연속 절반만 닫혀 있었다. 4회차에 **「자기 델타를 스스로 적대 검토하고 결과를 반환에 필수로 실어라」**를 넣었더니 즉시 자기 결함 3건을 잡았다(`implement` 스킬 feedback에 적립).
7. **리뷰어가 갈리면 「구성 가능한 반례를 낸 쪽」이 옳았다** — 부재 증명보다 구성 증명. 규약화는 리뷰 BLOCK으로 **보류**(아래).
8. **앱을 셸에서 직접 띄우지 말 것** · **남의 워크트리 프로세스를 죽이지 말 것** · 실측 전부터 떠 있던 것은 불가침.

## 밀린 사용자 결정

1. **구독 좀비 후속 2건**(코더가 찾아 큐에 넣음, 이번 범위 밖):
   - `lastDeliveredSeq`가 재연결 시 리셋되지 않는다 → **데몬 재시작하면 seq가 0부터라 새 프레임을 전부 중복으로 버린다.** 좀비를 고치면 이게 바로 드러난다. 해법 = 연결 세대를 구독 키에 넣기(코더가 이미 설계해 둠, 미적용).
   - `AgentEvent::Error`를 웹뷰로 라우팅할지(지금은 로그만). 오류에 소유자 칸이 없어 어느 뷰가 받을지 정할 수 없다 — 설계 필요.
2. **`slot.assignAgent`에 `layout.setSlotContent`가 필요한지** — 코드상 불필요(둘 다 슬롯 내용을 교체, 후자는 유니온 전체). 다만 **agent_id에 이름을 넘기면 거부 없이 슬롯만 빈다**(실재 검증 안 함 — ADR-0035 격리). 설명 문구는 이번에 박았다.
3. **스킬 개선 ②(리뷰어 대립 판정)** — 초안이 `/review doc`에서 **BLOCK**. 사유: 판정 기준이 반례의 *모양*만 보고 *타당성*을 안 본다 + 「부재 증명」 정의가 너무 넓어 거의 모든 대립이 예외로 빠진다. **되돌렸다.** 살리려면 「반례가 상대의 반박을 견디는가」를 채택 조건에 넣어야 한다. ①(코더 자체 검토)은 지적 반영해 **반영 완료**.
4. **`daemon.json` 접근 제한** — ADR-0160에 적은 「소켓 문은 에이전트에게 닫혀 있다」가 실은 거짓(파일 ACL 없음 + 에이전트가 권한 우회 모드). 결정은 안 바뀌지만 근거 문장이 약하다.
5. **중계 상한을 자격증명별로 걸까**(지금 전역 64) · **`INTERNAL`을 진짜 내부 결함과 구별할까** · **ADR-0130 재개 조건 ②**(이번 변경이 간선을 더 늘렸다 — `control` → `command_delivery`·`connection_core`·`log_capture`).
6. **스텝 4 제외 확정분** — 화면 연결 안 함(사용자 결정). ★귀결: 스텝 5(곁문 철거)에서 챗 5항목을 승격할 자리가 없어 **곁문 둘 중 하나는 못 지운다** — 착수 전 범위 재조정 필요.
