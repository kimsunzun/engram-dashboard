## 무엇이 결정됐나 (ADR-0134, 커밋 `d73eb0a`)

1. **릴리스 데이터 폴더 = 실행 폴더 하위 `engram-data/`** — `%APPDATA%`를 안 쓴다. 완전 포터블. **이 결정은 안 흔들렸다.**
2. 데이터는 하위 폴더 하나로 묶는다(exe 옆에 흩지 않음).
3. **단일 인스턴스 = 데이터 폴더 안의 고정 잠금 파일을 OS 잠금으로 보유.** ← **뒤집힌 조항**
4. 데이터 폴더를 못 쓰면 폴백 없이 명확히 실패한다.
5. 기존 `%APPDATA%` 데이터를 이전하지 않는다.
6. 디버그 동작 무변경(`.engram-data/`, `ENGRAM_DATA_DIR` override 유지).

### 결정 3이 왜 뒤집혔나 (이걸 모르면 되돌아간다)

원안은 "데이터 폴더 경로를 정규화 → 지문 → `Global\` named mutex 이름"이었고 **두 라운드 구현까지 갔다.** `/research medium` + 다른 family 적대 검증이 **문제 설정 자체를 반증**했다:

- **폴더를 식별할 필요가 없다.** 폴더 안 파일을 잠그면 경로 별칭 해석은 OS가 한다. 정규화·지문·소유 경로 비교가 전부 불필요.
- **선례가 전부 그 방식이다** — postgres(`postmaster.pid`)·leveldb(`LOCK`)·git(`index.lock`). 1차 수집이 이를 "경로 문자열 방식"으로 **오분류**했고 적대 검증이 적출했다.
- **named mutex는 컴퓨터 간 배제를 못 한다.** `Global\`은 한 컴퓨터의 세션 간 전역일 뿐이라, 두 PC가 같은 네트워크 공유 폴더를 쓰면 둘 다 뜬다. 파일 잠금은 파일 서버가 중재한다.
- **크래시 시 OS가 자동 해제**한다 — 낡은 항목 판정 로직이 필요 없어진다.

★**파일 잠금 = 파일에 뭘 적는 게 아니다.** 파일 내용은 신원이 아니고(적으면 복사본이 같은 신원을 주장한다), "그 파일을 열어 붙잡고 있다는 상태"가 잠금이다.★

## 실패한 접근 (do-not)

- **경로 문자열을 정규화해 잠금 이름을 만들지 말 것.** 위 「결정 3이 왜 뒤집혔나」가 근거. 되돌아가기 쉬운 자리다.
- **폴더 안에 고유 키 *값*을 적어 신원으로 쓰지 말 것.** 복사하면 두 설치가 같은 신원을 주장해 하나가 못 뜬다. 키 파일만 지워지면 산 데몬 옆에 두 번째가 뜬다.
- **`to_lowercase()`로 경로를 접지 말 것.** Windows도 폴더별 대소문자 구분이 가능해 서로 다른 두 폴더를 하나로 합친다.
- **진단을 위해 종료 코드 + 프로세스 관측을 다시 짓지 말 것.** 지어봤는데 **마지막 한 칸(화면 표시)이 없어 사용자 체감이 그대로**였다. 대안: 데몬을 띄우기 전에 **대시보드가 자기 데이터 폴더에 실제로 써보는 것** — 창이 있으니 바로 말할 수 있고 관측도 계약도 필요 없다.

## 미결 — 사용자 판단 필요

1. **잠금 파일 부재 시 진단** — 위 「대시보드 사전 점검」안을 채택할지. 채택하면 종료 코드·WMI 관측 배선은 전부 폐기.
2. **토큰 폴더 권한** — 데이터가 실행 폴더 밑으로 오면서 **접속 토큰이 폴더 권한을 물려받는다.** 공용 폴더에 풀면 같은 컴퓨터의 다른 계정이 읽는다. 데이터 폴더를 만들 때 소유자 전용 권한을 거는 게 싼 대응. **아직 미결.**
3. **복사한 배포판 두 벌** — 이미 한 번 실행한 폴더를 복사하면 연결키가 딸려가 복사본이 원본 데몬에 붙는다. **"UI가 어느 데몬에 붙을지 명시적으로 고른다"는 축(원격·모바일)과 함께 다루기로 보류**(사용자 판단 2026-08-13).
4. **런처 회귀** — `run-dashboard-release.bat`이 이름 대신 pid로 죽이게 바뀌면서, **연결키가 없는데 데몬만 살아 있는 상태를 복구 못 한다.** 옛 방식은 항상 복구했다. README가 "폴더 지우면 된다"고 안내해 이 상태를 유도한다.

## 이 작업 밖에 밀려 있는 것

- **에이전트 트리 ↔ 슬롯 동기화** — 원래 본론인데 하나도 착수 안 함. 후보: (A) 죽은 에이전트가 문 칸 비우기 — 이미 ADR-0017이 "좀비 칸 없음"으로 결정했는데 구현이 안 지킴, 논쟁 없는 결함 수정 · (B) 트리에서 지우면 프로세스도 끝나기(ADR-0122 미구현) · (C) 트리에 그릇(폴더) 노드 도입 — 깊이 1단 제약·휴지통 자리·순수 정리가 한꺼번에 풀림. **지휘 축(parent_id)이 메시징에서 전혀 안 쓰여 지금이 갈아타기 최저 비용** · (D) 휴지통 — C 필요 · (E) 트리에 "지금 화면 어디 떠 있나" 표시
- **휴지통에 든 에이전트가 이름을 점유하는지** — ADR-0122가 미해결로 남김
- **README 잘라내기 논쟁** — 실행 흐름 그림·crate 연결도·백엔드 미래 항목을 뺄지. 리뷰어 둘이 정면으로 갈렸고 일단 지키는 쪽으로 커밋됨
- **폐기된 ADR-0027을 가리키는 코드 앵커** — `src-tauri/src/tray/mod.rs:78`. 자동 시작 메뉴 건이라 어느 살아 있는 결정이 물려받는지 판단 필요
