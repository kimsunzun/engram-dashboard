## ★리뷰 2라운드 잔여 (다음 세션이 닫을 것)★

두 렌즈 모두 **FIX** 판정, 정면 대립 없음. 1라운드 BLOCK 4건 중 **2건 완전 폐쇄(중복 이름 감지·명부 주인별 키) · 2건 부분**이다.

**부분으로 남은 것 (핵심 — 「답장 정확히 하나」 계약이 아직 안 선다)**
1. **전달 콜백이 패닉하면 답장 0회** — `link.rs:54-56`이 `deliver`를 먼저 `take()`한 뒤 호출한다. 호출 중 패닉하면 `Drop`이 `None`을 보고 즉시 반환(`:62-64`). 「형태로 강제」의 유일한 구멍.
2. **명부 tombstone 무한 누적 — 회수 API가 없다** — `roster.rs:97-105`가 `available=false`만 찍고 지우지 않는다. `OwnerToken`이 연결마다 새 토큰(`envelope.rs:28-31`)이라 재연결 N회 = 같은 이름에 N개 영구 적체. `register`가 매번 전 슬롯을 훑어 비용도 오른다. **★메인 결정: 이름당 최신 흔적 하나만 유지★** — 「만료 없음」(ADR-0135) 취지는 「이름이 사라지지 않는다」이므로 중복 흔적 접기는 그 결정과 충돌하지 않는다.

**나머지 FIX**
3. **미지 오류 코드 왕복이 「retry 칸 부재」를 손상시킨다** — `error.rs:213-250`. retry 생략 입력이 `""`로 되살아나 중계 홉이 빈 문자열을 실어 나른다. 미지 **추가 필드**도 `RawError`가 버린다.
4. **`lint_spec`이 중첩 타입을 안 본다** — `spec.rs:169-180`이 최상위 `properties`만 훑어, 블록 선언 struct 안의 raw identifier·불량 `required`가 통과한다.
5. **`Option<Option<T>>`의 `required` 광고를 강제하는 것이 없다 + 매크로 문서가 자기모순** — `macros.rs:226`이 required에 싣지만 `#[serde(default)]`(`:176`)라 부재가 역직렬화를 통과한다. 반려는 손으로 쓴 핸들러 검사뿐(`commands.rs:460-464`). `macros.rs:49`("역직렬화가 반려")와 `:168`("핸들러가 반려")가 서로 반대로 적혀 있다.
6. **정수 스키마가 serde보다 넓다** — `1.0`이 스키마상 유효하나 serde는 거부(`macros.rs:122-134`).
7. **CI에 `cargo test -p engram-dashboard-command` 스텝이 없다** — TRD §6 Step 1 검증이 「신설」로 명시. 신규 crate만 CI 커버리지가 비었다.
8. **바인딩 sync 게이트가 미추적 신규 파일을 못 잡는다** — `git diff --exit-code`는 untracked를 안 본다. 명령을 더하면 `.ts`가 신규로 생겨 게이트가 초록으로 지난다. **이 저장소에 전례가 있다**(TRD §5의 `SlotContent.ts`).
9. **메시징 격리 게이트를 매니페스트 별칭으로 우회 가능** — `pkg = { package = "engram-dashboard-command" }` → `use pkg::…`면 정규식이 못 본다. ADR-0134가 「정규식이 유일한 벽」이라 적은 바로 그 지점.
10. **테스트 3건이 계약을 안 구속한다** — ① `route.rs:298`은 안쪽 그물(`table.rs:139`)을 지워도 바깥이 잡아 통과 ② `table.rs:271-283`의 「바이트 동일」은 같은 함수를 두 번 불러 비교하는 항진명제 ③ `command_declarations.rs:98`은 역직렬화를 한 번도 안 돌리고 하드코딩 목록만 비교.
11. **`CommandError`의 비공개 칸이 동등성 의미를 바꿨다** — `wire`(`error.rs:139`)가 `PartialEq`에 포함돼, 낮춰 읽은 미지 코드 오류와 `CommandError::of(Internal, …)`가 의미상 같은데 `!=`다. TRD §4-⑦의 평평한 3칸 struct에서 이탈.
12. **core의 생산 의존이 TRD가 계산한 대가보다 크다** — ADR-0134/TRD §5는 「워크스페이스 crate 0 → 1」로 못 박았는데 실제로는 `ts-rs`(생산 의존) + 전이 `inventory`가 데몬·셸 릴리즈 바이너리에 링크된다. **문서 정정 사안.**

**advisory(판정 미반영)** — `route`에 마감시각이 없다(Step 2 조립부 몫이면 그렇게 명시할 것) · `std::panic::set_hook`을 두 테스트가 같은 바이너리에서 경쟁적으로 갈아끼운다 · 생성물 `AgentMoveArgs.ts`가 `string | null | null` 중복 유니온 · `commands.rs:26-27`의 TODO가 `TODO(식별자):` 형식이 아니다.

## ★실패한 접근 / do-not★

1. **선언을 한 crate(`protocol`)에 모으지 말 것** — 폐기됐다(ADR-0134 거부 대안 A).
2. **명령 정의에 「주인」 칸을 만들지 말 것** — 정의 위치가 주인. 사용자가 두 번 철회시킨 제안.
3. **전역 자동등록 표에 핸들러를 박지 말 것** — T-1 하드 제약. `static`/링커 수집이 `Arc<dyn CommandHandler>`를 담으면 위반. 담아도 되는 건 `CommandSpec`까지.
4. **데몬이 빌드 목록을 컴파일에 넣지 말 것** — 명부는 런타임 등록으로만 찬다.
5. **봉투에 방향 필드를 넣지 말 것.**
6. **받은 자리(연결 태스크)에서 실행하지 말 것** — 복합 명령이 자기 답을 기다려 멈춘다.
7. **데몬이 인자를 뜯게 만들지 말 것.** 단 이름은 겉봉에 노출. **help 문자열도 절대 파싱하지 말 것**(불투명 유지 = ADR-0135 하드 제약).
8. **조사 보고서(`docs/research/unified-command-bus-survey-2026-08-12.md`)를 확정으로 읽지 말 것** — BLOCK 상태, 반증 6건. ADR 거부 근거로 인용 금지.
9. **blind 리뷰어가 「구판 보존이 과하다」고 하면 기각할 것** — TRD 개정 규약이 구판 보존을 **요구**한다(그 문서 헤더 `:5`).
10. **채팅에서 영어 용어·새 비유를 만들지 말 것.** 이번 세션에서도 「패닉/크래시」 설명이 길게 꼬였다. **C++ 예시가 가장 잘 통한다.**
11. **컨텍스트 사용량을 체감으로 단정하지 말 것** — 이번 세션에서 「절반 넘었다」고 했다가 실제 31%로 틀렸다. 측정 수단이 없으니 사용자에게 확인을 요청한다.
