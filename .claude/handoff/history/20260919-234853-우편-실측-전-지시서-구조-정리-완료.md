## 이번 세션에서 실측으로 뒤집힌 전제들 (전부 codex-cli 0.155.0)

> **정본 = `docs/research/codex-session-id-recovery-survey-2026-09-19.md` §10.** 수치를 여기 베끼지 않는다.

1. ★**훅 명령 문자열은 인자를 받는다**★ — 사용자 홈에 래퍼 스크립트를 설치해야 한다는 전제가 틀렸다. **설치물 0** 이 됐다.
2. ★**중복 `-c` 는 뒤가 이긴다**★ — 우리 override 가 사용자 passthrough **앞**에 있었고, `-c hooks.SessionStart=[]` 한 줄이면 **심사 프롬프트조차 안 뜬 채** 훅이 사라졌다. **확정 결함이었고 고쳤다.**
3. ★**`codex resume <id>` 는 id 를 유지한다**★ — 리뷰어가 우려한 두 꼬리(매 resume 충돌 경고 · 중간 대화 유실)가 실재하지 않는다. `source` 가 `startup`/`resume` 을 가른다.
4. ★**심사 프롬프트의 「끄기」는 영구 저장되지 않는다**★ — 직전 핸드오프가 1순위 위험으로 올려 둔 갈래가 닫혔다.
5. ★**`--dangerously-bypass-hook-trust` 는 탈락**★ — 전역이라 사용자 자신의 미심사 훅까지 실행된다.
6. ★**TUI ↔ app-server 모드 전환이 된다**★ — 양방향, 같은 스레드 id, 같은 기록 파일. **`developerInstructions` 는 기록에 저장돼 재개·모드전환에도 남는다.**
7. ★**MCP 도구 설명문은 붙는 순간 실린다 — 그러나 「실려 있음」이 「지켜짐」이 아니다**★. 설명문의 **행동 규칙은 무시됐고** 파일로 준 규칙은 지켜졌다. **그래서 「어떻게 부르나」=설명문, 「무엇을 해야 하나」=지시서**로 갈랐다. 제목/상세 분리는 **없다**.

## do-not (이번 세션에 실제로 겪은 것만)

1. ★**분리 실행(`run-detached.ps1`)이 배치 파일을 가리키면 `__EXIT=` 마커가 안 찍힌다**★ — `npm` 만이 아니라 **`.bat`/`.cmd` 전부**다. 마커를 기다리면 무한 대기로 읽힌다(**25분 낭비 실발생**). 도구 자체 요약으로 판정한다. 덤으로 **래퍼 안 cmd 문맥엔 `rg` 가 PATH 에 없다**.
2. **인라인 python/스크립트로 파일을 고치려 하면 권한 심사에 막힌다** — Edit 도구를 쓴다.
3. **Bash heredoc 에 한글 본문 금지** — Write 를 쓴다(커밋 메시지는 파일로 빼서 `-F`).
4. ★**「사용자 홈에 자동 실행되는 스크립트를 심는」 모양의 작업은 권한 심사가 막는다**★ — 우회하지 말 것. 이번엔 **그 전제 자체가 틀렸다**는 게 측정으로 드러나 문제가 사라졌다.
5. **`git checkout -- <file>` 금지** · **루트 bare `cargo test` 금지** · 워크스페이스 회귀에 `-- --test-threads=4` 유지 · **앱을 셸에서 직접 띄우지 말 것**.
6. **도움말 하위 이름에 없는 어휘를 지어내지 말 것** — 초안이 `check` 를 만들었고 사용자가 잡았다. **실제 명령 이름을 그대로 쓴다.**
7. ★**ADR 부분 폐기 조항 라벨을 틀리게 달지 말 것**★ — 「에스컬레이션 교육 위치」로 찍었다가 그 조항이 **안 죽은 것**이어서 고쳤다. 틀린 라벨은 없는 것보다 나쁘다.

## 보류한 것 — `wip/codex-mcp-attach` (로컬 전용)

codex 에 MCP 를 붙여 **우편 보내기**를 여는 작업이 통째로 들어 있다. **기술적으로는 성공했다** — 토큰이 argv 에도 디스크에도 안 남는 형태(`bearer_token_env_var`)로 실 codex 에 붙여 도구 둘 등록 + Bearer 헤더 전송까지 확인.

★**보류 사유 = 그대로 넣으면 「보내기만 열리고 받기는 닫힌」 상태가 된다**★. 그건 ADR-0133/0209 가 축을 쪼개며 **없애려던 바로 그 비대칭**이다. 원인은 ★**터미널 모드에 턴 신호가 아예 없다**★는 것 — `classify_turn` 이 터미널 바이트에 아무 신호도 안 낸다.

**그 브랜치 안에서 실측으로 확보한 것(값어치는 여기 있다):**
- `mcp_servers.engram={url='…',bearer_token_env_var='ENGRAM_TOKEN'}`
- ★**프라이밍(지시서)을 codex 에 실을 자리가 없다**★ — 경로를 받는 키는 codex **기본 프롬프트를 대체**해 버리고, 나머지 후보 키는 전부 unknown field

**그래서 다음 덩어리는 「codex json 모드 우편」이 싸다** — 거기는 턴 신호가 있어 **받기까지 같이 열리고**, 지시서도 RPC 로 넘어가 크기 제한이 없다.

## 미결 · 사용자 결정 대기

1. **우편을 어떻게 열 것인가** — ① 터미널 턴 신호를 먼저 세운다 ② **app-server(json) 모드에서만 연다**(권장) ③ 보내기만 먼저 연다(ADR-0209 결정 4 번복이라 새 ADR 필요)
2. **훅을 터미널 모드에만 등록하는 것**(ADR-0210 에 결정 대기로 남김) — ADR-0208 에서 사용자가 두 모드 공통 경로를 골랐는데 등록 축에서 분기가 되살아났다. 실측상 중복의 대가는 「이미 같은 값」 한 줄뿐이라 결함은 아니다
3. **LLM 이 터미널에 키를 쏘는 명령** — 권한 심사에 두 번 막혔다. 다만 측정 결과 **승인은 기기당 사실상 한 번**이라 값어치가 낮아졌다
4. **ADR-0126 결정 5 가 남긴 구멍** — 비-MCP 갈래에 에스컬레이션 교육이 0줄이다. **CLI 우편을 열 때 가장 먼저 닫을 자리**(ADR-0211 「영향」)
5. **`engram help` 의 우편 절이 MCP 에이전트에게 안 보인다** — 지시서가 「`engram help` 를 쳐라」라고 말하는 상대가 정작 우편 절을 못 본다. 읽기와 보내기를 가르면 풀린다(ADR-0211 「영향」에 ★로 적혀 있다)
