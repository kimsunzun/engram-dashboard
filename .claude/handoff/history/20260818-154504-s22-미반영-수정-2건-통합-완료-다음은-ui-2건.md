## 다음 세션이 할 일 — 미착수 2건

### (A) 에이전트 생성 메뉴 라벨 개명

`src/i18n/ko.ts:50-51`
- `createTerminal: '클로드 터미널 생성'` → **「클로드코드 터미널 생성」**
- `createJson: '클로드 JSON 생성'` → **「클로드코드 JSON 생성」**

**사용자 결정 2026-08-18:** 뜨는 것은 모델 "클로드"가 아니라 CLI 제품 "클로드 코드"다. 곧 codex 등 다른 백엔드가 옆에 붙으면 **제품 이름으로 갈라야 구분이 선다.**

**기각한 대안:**
- 「대화형 / 헤드리스」 — 공식 문서를 실조회해 확인한 결과 **안트로픽의 확정 제품 용어가 아니다.** 본문은 "non-interactive mode", 페이지 제목은 "Run Claude Code programmatically", 파일명은 `headless`로 셋이 갈린다. "interactive mode"는 `-p` 플래그 설명("Print response without interactive mode")에서 **부정으로만** 정의된다. 두 모드를 짝으로 명명하는 자리가 문서 어디에도 없다.
- 「TUI / JSON」 — JSON 모드는 PTY를 아예 안 연다(stdio 파이프). 따라서 "터미널"이 이미 정확히 한쪽만 가리켜 정확도 이득이 0이고 약어 비용만 는다.
- 「터미널 / 채팅」 — 화면 기준 명명. 사용자가 JSON 유지를 택했다.

**범위:** 한국어·영어 로케일. **ADR-0078 본문은 건드리지 않는다** — 그 ADR의 결정은 "렌더 모드는 생성 시 고정"이지 라벨 문자열이 아니다(ADR 덮어쓰기 금지).

**착수 시 물을 것:** 띄어쓰기 — 「클로드코드」 vs 「클로드 코드」.

## 실패한 접근 (do-not)

- **`git merge ... -F -` (heredoc)** — git merge의 `-F`는 `-`(stdin)를 안 받는다. `error: could not read file '-'`로 조용히 머지가 안 된다. 머지 메시지는 **파일로 써서** `-F <경로>`로 넘길 것(`git commit -F -`는 되므로 헷갈리기 쉽다).
- **워크트리에서 `git checkout master`** — master가 다른 워크트리에 체크아웃돼 있으면 git이 거부한다. 최신 master 코드가 필요하면 브랜치를 유지한 채 `git merge --ff-only origin/master`.
