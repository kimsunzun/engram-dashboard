## 이번 세션이 확정한 것 (사용자 결정 — 뒤집지 말 것)

1. ★**우편 화면은 항상 보인다**★ — `ENGRAM_MAIL` 환경변수 표식을 **주입·독해 양쪽 제거**하고 `MailSurface` 를 삭제한다. 외부에서 화면을 바꿀 수 없게 한다.
2. ★**CLI 메일의 내부 시스템은 전부 남긴다**★ — 동사 코드 · `mail_allowed` 파생 · 자격증명 강제 · 데몬 거절 경로. 나중에 비-MCP 백엔드가 실제로 생길 때 되살린다. **지금은 MCP 고정으로 쓴다.**
3. **help 본문은 MCP 도구 기준으로 쓴다** — CLI 동사 표기(`engram mail send --to X`)를 화면에서 뺀다.
4. **표면별 역할 분담** — 도구 설명(상주) = 호출에 필요한 인자 스펙만 · help 화면(온디맨드) = 가이드 전부 · 프라이밍(상주) = 다른 데서 못 배우는 것만.
5. **구획 표시 = 마크다운 제목**(`## <id>`). 옛 HTML 주석 꼴은 마크다운 뷰어가 감춰서 **파일을 고치는 사람에게 구획 경계가 안 보였다**(실발생).
6. **mail 페이지는 주제 4장 유지**(send·status·pending·recv) — 도구는 둘뿐이지만 배울 주제는 넷이고, `recv` 는 대응 도구가 없는 주제다.
7. **파일명** `engram-cli-help.md` → **`engram-help.md`** — 그 화면이 CLI 전용이 아니게 됐다.

## 코드 작업 (남은 전부, 순서대로)

1. **red 5건 재작성** — 전부 「내용이 바뀌었으니 단언도 바뀐다」. 느슨하게 고치지 말 것(그중 하나는 어휘 드리프트 가드다).
2. ★**우편 게이트 제거**★ — 변경 지도가 이미 확보돼 있다(아래 「조사 결과」). `ENGRAM_MAIL` 상수 3개·주입·독해 삭제, `MailSurface` 삭제, 렌더의 두 `if` 를 **지우되 항상 emit 하는 쪽으로**(빼는 게 아니다 — 방향이 반대다).
3. **구획 합치기 검토** — 게이트가 사라지면 `root.group.mail`·`agent.xref` 를 1줄짜리 구획으로 떼어 둘 이유가 없다. 17개를 줄일 수 있다(조립표·`required_section_ids` 함께).
4. **ADR** — 0133 결정 1·2 봉인(partial) · 0132 결정 3의 help 절반 · **0126 결정 1**(CLI/MCP 철자 분리를 못 박아 둔 결정 — 이번 변경이 정면으로 뒤집는다) · 0212 결정 1(표시 꼴 = 주석). ★대상이 여럿이니 `/adr supersede` 한 실행에 전부 넘길 것★
5. **문서 갱신** — `docs/reference/architecture-overview.md:363`(닿을 수 없는 화면을 정본으로 지목) · **`:365` 는 「codex = `uses_mail=false`」로 틀렸다**(실제 `true`. 닫히는 건 `accepts_mcp_config=true` 쪽) · `docs/research/command-discovery-survey-2026-09-20.md:10,40`(계열 둘 → 하나였다가 다시 둘) · ADR-0211 `:44`

### 조사 결과 (이미 확보 — 다시 조사하지 말 것)
`ENGRAM_MAIL`/`MailSurface` 제거의 전수 변경 지도를 조사 에이전트가 만들었다. 핵심만:
- 프로덕션 독자는 `MailSurface::from_env()` 하나, 기록자는 `backend/mod.rs:105-118` 하나
- `mail_allowed` 의 네 다리 중 **끊는 것은 endpoint 표식 하나**뿐. 자격증명·미들웨어 강제(`mcp_server.rs:711`·`:1156`)는 **손대지 않는다**
- `ControlEndpoint.mail_allowed` 가 **읽는 곳 0인 필드가 된다** — Rust 가 경고 안 한다. 남기되 주석을 달 것
- `required_section_ids()`(`engram.rs` 내) 가 17개를 요구하고 그중 13이 mail — **파일에서 구획을 지우면 화면 전체가 내장 사본으로 떨어진다**
- `HELP_EMBEDDED` 는 별도 사본이 아니라 **같은 파일의 `include_str!`**
- `scripts/` 에 `ENGRAM_MAIL` 없음(확인함)

## do-not

1. ★**`engram help` 가 「지금 무엇이 있는지」를 안다고 쓰지 말 것**★ — 그건 **손으로 쓴 파일**이고, 실제 카탈로그를 아는 것은 `engram commands` 다. 둘은 이미 어긋나 있다(조사 문서 기준 계열 둘 vs 실제 이름 22개). 이 세션이 프라이밍에 그렇게 썼다가 사용자에게 잡혔다.
2. ★**화면 본문에 마크다운 강조(별표)를 쓰지 말 것**★ — 터미널에 리터럴로 찍힌다.
3. ★**문단에 하드랩을 넣지 말 것**★ — 에디터 폭이 좁으면 이중으로 접혀 읽기 나빠진다. 줄을 끊는 것은 들여쓴 표·블록만(정렬이 걸려 있다).
4. ★**셸에서 친 `engram help` 를 「에이전트가 보는 화면」으로 착각하지 말 것**★ — 표식이 없으면 기본이 `Shown` 이라 사람 셸에서는 mail 이 보인다. 에이전트 조건은 `ENGRAM_MAIL=off` 다. 이 세션이 그 착각으로 사용자에게 잘못된 화면을 여러 번 보여 줬다.
5. **화면당 파일로 쪼개지 말 것**(사용자 결정) — 나중에 너무 잘게 갈린다. 한 파일 + 제목 분할로 간다.
6. **`agent spawn --cwd` 와 `agent new` 를 백엔드 선택 경로로 가르치지 말 것** — 그 둘은 백엔드를 못 고른다. 점형 `agent.new --backend` 여야 한다.

## 미결 · 사용자 답을 못 받은 것

1. ★**도구 설명을 영어로 되돌릴까**★ — 한글화가 토큰 기준 역효과일 수 있다(위 「크기 변화」). 물었으나 답 없음.
2. ★**`SendArgs` 필드 doc 1,234자(영문)가 schemars 를 타고 input schema 로 상주한다**★ — `@here`/`@all`·기한 하한·통지 대상이 **거기 한 번 더** 있다. 도구 설명만 줄여선 목표 미달이고, **지금 남은 최대 상주 덩어리**다. 손대지 않았다.
3. **`agent` 계열에 하위 페이지가 없다** — `engram help agent spawn` 이 안 된다. `mail` 만 하위 장을 갖는다. 코드 필요(`HelpTopic` 갈래 + 조립표 + `required_section_ids`).
4. **창·탭·분할, 테마가 계열이 아니다** — 루트 화면 목록에 줄로는 섰지만 `engram help window` 는 없다.
5. **`agent` 화면 정리안을 제시했으나 승인 못 받음** — `agent spawn --cwd`·`agent new` 를 빼고 함정 셋을 묶는 안. 마지막 턴에 올렸다.
6. **경로 정규화 코드화** · **재개 실패 폴백** · **릴리스 경로 push 게이트** · **`~/.codex` 잔여 정리** · **테스트 프로필 잔여**(`demo-*`·`t-*`·`v030-*`·`qa-*`) — 지난 핸드오프에서 그대로 밀렸다

## 절차 관측

- ★**이 세션은 사용자에게 「셸에서 친 화면」을 에이전트 화면인 양 반복해서 보여 줬다**★ — 게이트 존재를 알고 있었는데도. 화면을 보일 때는 **어느 조건으로 찍은 것인지 먼저 밝힐 것**.
