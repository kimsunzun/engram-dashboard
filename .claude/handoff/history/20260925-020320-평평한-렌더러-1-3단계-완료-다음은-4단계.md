## 코더·리뷰어 지시서 요령 (이번 세션 실측 — 다음 지시서에 넣을 것)
- **CRLF:** `cargo fmt`/`rustfmt` 가 CRLF 를 LF 로 뒤집고, **Git Bash `sed -i` 는 CR 을 전부 지운다**(2단계 실발생) → 「Edit 도구나 perl 로 편집, 편집 뒤 CR 수 == 줄 수 확인」.
- **lib_unit 필터는 `::tests` 까지** 쓴다(`layout::spatial::tests`) — 모듈 이름만 쓰면 ts-rs 내보내기 테스트까지 돌아 `src-tauri/bindings/` 를 다시 쓴다.
- **run-detached 에서 npx/npm 은 따로 부른다** — `a && npx …` 처럼 둘째 자리에 두면 `__EXIT` 마커가 사라진다. 대기 루프는 반복 상한을 두고 로그 경로는 리터럴로(3단계 셸 코더가 상한 없는 대기로 ~600초 매달림).
- **테스트 판별력:** 순서·원점 같은 성질을 고정하는 테스트는 「대안 순회(BFS·id 정렬·후위)와 어긋나는 픽스처」를 요구해야 한다(1단계에서 두 라운드를 여기 썼다). 코더에게 「요구 번호별 변이 1종이 빨개지는지」를 요구하면 수렴이 빠르다(3단계 프론트 코더가 변이 17~19종으로 자가 검증).
- **codex(blind) 리뷰어:** `~/.claude/skills/review/codex-call-spec.md` 대로 `codex:codex-rescue` 서브에이전트 · `--fresh` 로 열고 같은 사이클 재리뷰는 `--resume`(첫 줄에 「직전 턴에 한 일」 확인 문장). diff 파일을 스크래치패드에 떠서 넘긴다. 이번 세션에 codex 가 3단계의 실제 경합 셋을 잡았다 — doc-aware 가 놓친 것.
- 리뷰 대립(PASS vs FIX)은 자율 모드 규칙대로 무거운 쪽 채택 · 재수정 하드캡 3회.

## GUI QA 요령 (7·8단계에 필요)
- **프론트 view 캐시 읽기:** `window.__engram` 은 view 스토어를 열지 않는다. performance entries 에서 페이지가 실제로 로드한 모듈 URL 을 찾아 dev `import()` — ★다른 URL(쿼리 차이)을 import 하면 **별도의 빈 인스턴스**가 떠 「비었다」로 오판한다★. `windowCanvasReport.ts` 는 쿼리 없는 URL 이 실물이었다. (qa 스킬 `feedback.md` 에 적립함)
- **부팅 시점 콘솔 오류 포착:** `cdp.mjs` 로는 안 된다 — 같은 CDP 세션에서 `Page.addScriptToEvaluateOnNewDocument`(훅 설치) → `Page.reload`. 팝아웃 페이지엔 따로 걸어야 한다.
- **네이티브 창 리사이즈:** `Browser.setWindowBounds` 는 뷰포트만 바꾼다(`innerSize` 로 확인하면 창은 그대로). 실제 창을 바꾸려면 **컴파일 헬퍼**(작은 exe 로 `SetWindowPos`/`WM_SYSCOMMAND`)를 쓴다. ★PowerShell P/Invoke 스크립트 금지★ — 사내 보안 에이전트 경보 위험(앞 세션 기록), 훅이 명령 텍스트에 그 cmdlet 이름만 있어도 막는다. 7단계 TRD §5 GUI 항목(홀수 폭·배율 125% 이음매·글자 선명도·열 수)에 창 리사이즈가 필요하다.
- 렌더러 교체(7단계) QA 는 「자리 잡은 뒤 스크린샷」만으로 하지 말 것 — 프레임 단위로 칸 재생성 없음·첫 프레임 크기·소수 px 흐림을 본다(앞 세션 기록).
- 다른 워크트리 dev 앱이 떠 있으면 identifier 뮤텍스 공유로 이 워크트리 debug 앱이 즉시 죽는다 — 기동 전 점검.
