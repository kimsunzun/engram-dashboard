## ★다음 세션이 반드시 알아야 할 빈틈 2개★

**① 결정 3(`engram-send` 배선 존치)을 지키는 테스트가 0건이다.** control 테스트가 전부 `send_exe: None`으로 돌아(`control_send.rs:128`·`mcp_manager_lifecycle.rs:75`·`headless.rs:132`) MCP 가능 스폰이 실제로 CLI 경로를 싣는지 아무도 단언하지 않는다. **"A는 이제 engram-send를 안 가르친다"를 읽고 PATH·env 주입까지 지워도 전 테스트가 초록이다** — 그런데 그 배선은 사용자가 명시적으로 남기라 한 것이다. grants는 `build_grants_includes_cli_when_send_exe_present`가 pin하지만 **grants ≠ 배선.** 코드 변경이라 사용자 결정 후 착수.

**② 이 변경 방향은 측정된 적이 없다.** ADR-0099의 무회귀 10/10은 *both-teaching* 실측이지 *MCP-only 교육*이 아니다. 함께 볼 것: MCP 고장 시 에이전트가 **에스컬레이션 지시를 따르는지 · 그래도 셸에서 `engram-send`를 찾아 쓰는지 · 조용히 포기하는지.** 셋의 갈림이 **프라이밍 문장 하나에만** 걸려 있다(auto mode에서 grant는 NO-OP). 셸 우회나 조용한 포기가 관측되면 **결정 3(배선 존치)을 재론**한다.
