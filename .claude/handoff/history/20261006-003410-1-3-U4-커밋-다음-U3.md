## 실패한 접근 / do-not

1. **코더 지시서에 EOL 복원을 시키지 말 것** — `core.autocrlf=true` 라 작업본 줄끝은 커밋에 영향이 없다. U1 · U2 코더가 CRLF 복원에 도구 호출을 많이 썼다.
2. **스크래치 실행 스크립트 이름을 워커마다 따로** — 공용 `run.sh` 를 한 워커가 고쳐 써서 QA 워커가 남의 로그를 덮었다(U2). 지시서에 고유 접두(`u3-` 등)를 박는다.
3. **codex 리뷰가 「model at capacity」로 자주 죽는다**(U0 · U4 각 1회) — 같은 프롬프트로 1회 재실행하면 됐다(review flow §0-a).
4. **병렬 코더 분할은 파일 겹침 0 일 때만** — U1 은 코드(A) · 게이트 문서(B)로 갈라 성공(접점 = 심볼 경로를 메인이 먼저 고정).
5. cargo 를 터미널에서 직접 돌리지 말 것 — `scripts/run-detached.ps1`. 머신 메모리 부족 — cargo 하나씩.
6. load 직후 바로 실행하지 말 것 — 먼저 보고 · push 확인.
