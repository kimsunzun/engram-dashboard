## ★반드시 알아야 할 것 — 이 결함의 정체★

**제출은 "바이트"가 아니라 "수신자의 read 경계" 문제다.**

- 봉투 끝에 CR을 붙여 **한 번의 write**로 보내면 → 제출 안 됨
- 본문을 쓰고 CR을 **별도 write**로 보내되 **간격이 없으면** → 두 write가 PTY에서 한 덩이로 묶여 claude가 한 번의 read로 받고, CR을 붙여넣은 텍스트의 일부로 취급 → **제출 안 됨**
- 본문 → **간격** → CR → **제출됨** ✓ (실측 확인, 회신까지)

**★"지연 0ms로 된다"는 옛 관측은 측정 오류다★** — 제어 평면 명령을 두 번 따로 보낸 측정이라 왕복·태스크 전환으로 이미 간격이 벌어져 있었다. 그걸 0ms로 읽고 코더에게 "지연 넣지 마라"고 지시해 라운드 두 번을 낭비했다. **이 문장을 다시 뒤집지 말 것.**

## ★다음 작업 — 블로킹을 예약으로★

**문제:** 지금은 `AgentSession::submit_input_observed`가 `std::thread::sleep(500ms)`로 잔다. 배달 레인은 **전체에 하나이고 내부가 직렬**이라(`messaging_host.rs` 주석이 "레인 내부는 여전히 직렬"이라 명시), 터미널 수신자 하나 때문에 **지연이 필요 없는 JSON 수신자까지 뒤에서 대기**한다. 사용자 판정: "엔터 하나 치자고 배달 줄 전체를 세우는 건 시스템이 아니다."

**조사 근거(`/research` — 서버 구조 선례):**
- **Herdr**(Rust 상주 데몬, 우리와 같은 구조) — 본문은 논블로킹으로 즉시 쓰고 Enter는 **`send_bytes_after(enter, 300ms)`로 예약**한 뒤 핸들러가 즉시 리턴. pane별 채널이라 다른 에이전트를 막지 않는다. 단위 테스트가 "본문은 즉시 도착, Enter는 아직 없음"을 직접 단언한다. (소스 직접 확인)
- **값은 300ms** — Herdr·AWS Labs CAO 둘 다 300ms. 우리 0.5초보다 작다. **단 둘 다 그 값의 근거가 코드에 없다**(측정 주석 없음) — 그대로 쓰되 "근거 없는 정착값"임을 주석에 남길 것.
- **고정 지연 대신 준비 신호를 기다리는 완성된 서버 사례는 못 찾았다**(제안만 열린 이슈로 존재). 그래서 지금은 예약 + 고정 300ms가 현실적 최선이다.

**지시할 것:**
1. `submit_input_observed`의 블로킹 sleep 제거 → 본문 write 후 **즉시 리턴**, 제출 write는 300ms 뒤 예약 발행
2. 값은 `SUBMIT_PACING`을 300ms로 (상수는 이미 `backend/mod.rs`에 하나만 있다)
3. **같은 수신자에 대한 순서 보장**을 반드시 챙길 것 — `E1본문 → E2본문 → E1제출 → E2제출`로 엉키면 봉투 둘이 한 턴에 합쳐진다
4. 기존 seam(`with_submit_pacing`, `#[cfg(test)]`)과 뮤테이션 테스트 유지 — 대기가 사라지면 테스트가 깨져야 한다

## 실패한 접근 (do-not)

- **인코더에 CR을 붙이지 말 것** — 인코더는 바이트열 하나를 반환하는 계약이라 합치기가 되고, 합치면 위 read 경계 문제로 실패한다
- **셸을 "제출만 빼기"로 완화하지 말 것** — 사용자 결정은 **데몬에서 배달 대상 제외**다. 셸은 편지를 읽는 주체가 아니다
- **우편 자격을 항목마다 재조회하지 말 것** — TOCTOU · 비원자성(재시작 창의 파킹 메일 유실) · 세션당 락이 함께 되살아난다. 명단 스냅샷(`AgentInfo`)에 실어 보낸다
- **삭제 정리의 이름 축에 우편 자격 필터를 걸지 말 것** — 그 축은 "살아 있나"를 묻는다. 합치면 산 셸의 오픈 계약이 잘못 닫힌다(ADR-0118 결정 2가 금지한 결말). `live_id_for_name`이 그 축이다
- **제어 CLI(`engram.mjs`)의 `send`를 두 프레임으로 쪼개지 말 것** — 상대가 JSON이면 CR만 든 빈 턴이 하나 더 생긴다. 제출 판정은 코어 소유다

## 수용한 한계 (고치지 않기로 확정 — 재론 금지)

- **본문↔제출 사이에 사람 입력이 끼어들면 섞인 채 제출된다.** 동종 도구도 미해결
- **받는 쪽이 확인 프롬프트를 띄운 상태면 CR이 기본 선택지를 누를 수 있다.** 조사 결과 범용 해법 없음(있는 건 화면 스크래핑이고 새 창마다 깨진다). **확인 창을 켜고 쓰는 사용자가 생기면 재론** — 지금은 사용자가 끄고 쓴다(프로젝트 기본값이 아니다)
- 제출 write만 실패하면 재파킹으로 본문이 겹친다(로그로 두 경우 구분만)
- 힌트 큐와 현재 이름 큐를 다른 태스크가 동시에 드레인하면 봉투 둘이 한 턴에 합쳐질 수 있다
- 산 셸에 편지를 보내면 "그런 에이전트 없음"으로 응답한다(목록엔 running으로 뜬다)
- 트립와이어가 슬롯 번호를 건너뛰면 통과 · 테스트 픽스처 1곳이 실물과 반대값
