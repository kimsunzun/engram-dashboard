## ★사용자가 정한 방향 — 명제 다섯 (2026-09-03)★

원래 계획(셸 순수 층을 crate 로 빼기)을 **미루고** `net` 리팩터링을 먼저 하기로 했다. 사유는 사용자 발언 그대로 — **"이거 나중에 틀어지면 감당할 수 없어서"**.

1. **`net` = 데이터를 공간 너머로 전달하는 공용 기능.** 방향(서버/클라)은 **고르는 능력**이지 별도 층이 아니다.
2. **특화 기능은 옵션(feature).** 데몬 전용·클라 전용이 확실한 것만 그쪽에 두고 나머지는 켜고 끄는 것으로.
3. **클라가 다중 데몬에 접속할 수 있어야 한다.**
4. ★**작업 방식 = 별도 crate 신설 → 독립 검증 → 적당한 범위로 붙이며 테스트.**★ 기존 `net` 을 바로 뜯지 않는다. 본작업 금지.
5. **지금은 설계 대화 단계.** "바로 진행하지 말고 나하고 충분히 얘기한 다음에 하자."

이 명제가 **이미 배제하는 것 둘:** 재연결을 셸에 두는 것(공용 기능이므로 `net`) · 구독·재생을 `net` 에 넣는 것(앱 판정이므로 별도).

## ★정해야 할 것 여섯 — 1번이 나머지를 가른다★

`net` 리팩터링의 설계 갈림길. **굵은 설계라 사용자 선택 없이 확정 금지**(CLAUDE.md 개발 스텝).

1. ★**연결 N개를 누가 소유하나**★ — crate 가 풀을 소유 / 연결 핸들 N개를 소비자가 소유. **이것이 API 전체 모양을 정하고 2·3·4 의 선택지를 좁힌다.** ← 조사 대상
2. **default feature 에 뭐가 들어가나** — 공용/옵션 경계(명제 2의 실현)
3. **요청·응답 상관을 `net` 에 둘지** — 두면 `net` 이 `RequestId`(= `protocol`)를 알게 되고, 그건 그 crate 의 「에이전트 어휘 무지(예외 0)」 불변식에 닿는다. **기제 자체는 완전 범용**(`PendingMap<T>` 은 `T` 제네릭, 키만 `RequestId`)이라 `net` 쪽이 맞을 수 있다 — 미결
4. **전송을 WS 고정으로 둘지 trait 뒤로 둘지** — 모바일·원격이면 TLS 필요, 지금 `ws://` + host `127.0.0.1` 고정
5. **기존 `net` 과의 최종 관계** — 흡수 / 병존 / 개명
6. **독립 검증 하네스 모양** — loopback 실소켓 / 인메모리 / 둘 다

## 이 세션이 실측한 것 — `net` 현황

**어디 쓰이나(심볼 단위 실측):**
- **데몬 9파일** = 거의 전부. `ws::{handle_connection, ConnRegistry, KeepaliveConfig, ConnFrameSink}` · `frame_port::*`(7종) · `instance::acquire`
- **discovery 2파일** = `portfile::{read, is_stale, DaemonInfo, DAEMON_FILE}` + `auth::AuthFrame`
- ★**셸 2파일 = `auth::AuthFrame` 하나뿐**★ (`daemon_client/connection.rs:24` · `daemon_client/tests.rs:45`)

**`net` 에 클라이언트 절반이 아예 없다** — `connect` 도 재연결도 없고, 실물 전부가 `server` feature 뒤에 있다(`default = []`).

**왜 절반만 됐나(그 crate 헤더가 정본):** ① `net` 이 생긴 계기가 공유가 아니라 **순환 끊기**였다(`AuthFrame` 을 세 곳이 만들어야 하는데 `daemon` 안에 있으면 `discovery → daemon` 이 기존 `daemon → discovery` 와 순환) ② 셸 클라이언트가 `net` 보다 **먼저** 만들어졌고 그때 서버 코드는 `daemon` crate 안이라 셸이 쓰려면 `AgentManager` 전체가 딸려 왔다(ADR-0029 금지) ③ 후속 슬라이스 3 이 **ADR-0130 으로 보류**. 클라이언트를 다루는 슬라이스는 애초에 없었다.

**진짜 비대칭은 둘뿐이고 그것도 「방향」이 아니라 「능력」이다** — `accept` vs `connect` · 팬아웃(서버) vs 재연결(클라). ★keepalive 는 비대칭이 아니다★ — 지금 서버만 능동 Ping 을 보내는 건 `KeepaliveConfig` **설정 선택**이고, 원격·모바일 클라는 half-open 감지가 더 필요해 오히려 켜고 싶어진다.

**`connection.rs`(1,674줄 — 이 패키지 최대 파일) 분류 초안:**
| 지금 여기 | 가야 할 곳 |
|---|---|
| `connect` · 재연결 백오프 · 핸드셰이크 시퀀스 · 읽기 루프 · Ping 처리 | **`net`**(클라 절반) |
| 요청/응답 상관(`PendingMap`) | **미결 — 위 질문 3** |
| 화신 표식 가드 · 재생 single-flight | 앱 판정(옛 계획의 crate ②) |
| 프레임→창 라우팅 · 인바운드 명령 디스패치 · 웹뷰 Channel 전송 | 셸 |

## 미룬 것 — 셸 순수 층 crate 분할 (실측 완료, 착수 안 함)

`net` 을 먼저 하기로 해서 **미뤘다. 폐기가 아니다.** 실측이 이미 다 돼 있어 재조사 불필요:

- **조각 넷** = A 레이아웃(`types`+`spatial`+`tree`+`manager`+`apply`+`LayoutState`, 3,469줄·101테스트, **ts-rs 8종이 여기**) · B `output_router`(906줄·26테스트) · C 연결판정(`protocol_state`+`replay_flight`, 1,326줄·37테스트) · D `tray/core`(205줄·10테스트)
- ★**A 안에서는 못 자른다**★ — `types`⇄`spatial` 상호 참조. 한 crate 안 모듈 순환은 합법이지만 crate 를 넘으면 불법
- **비용 실측** = 가시성 넓힐 항목 **0개** · inherent impl 위반 **0건**(양방향) · 같이 끌려오는 파일 **1개**(`LayoutState`) · 후보 안 `tauri`/`tokio` 코드 참조 **0줄**(전부 주석)
- **D 는 셸에 남기기로 판단** — 순수한 건 우연이고 소비자 둘이 바로 옆이며 둘 다 `tauri` 를 문다
- ★**`net` 리팩터링이 C 의 경계를 움직인다**★ — 위 질문 3(요청/응답 상관)이 그 지점. 그래서 순서가 `net` → C 다
