# 핸드오프: 통합 command 버스 — TRD 개정 완료, 결정 1건 풀고 구현 진입

## 한 줄 상태 · 다음 첫 액션

**조사 → 적대 리뷰 → 설계 확정 → TRD 개정까지 끝났다. 코드는 여전히 0줄이다.**

**다음 첫 액션 = 아래 「막고 있는 결정」을 사용자에게 물어 닫는 것.** 그게 닫히면 `docs/process/S20-command-bus/trd.md` §6 마이그레이션 Step 1부터 구현 진입이 가능하다. **결정 전에 코드 들어가지 말 것** — 그 결정이 선언 형태와 등록 패킷 모양을 바꾼다.

## ★막고 있는 결정 1건 (개정이 새로 만든 구멍)★

**LLM이 셸·웹뷰 소유 명령의 "인자 모양"을 어디서 얻는가 — 지금 답이 없다.**

선언을 생산자 옆으로 흩은 결과 세 경로가 동시에 막혔다:
- 등록 패킷은 **이름만** 나른다(확정 구조)
- 웹뷰 선언은 TypeScript라 Rust 파생물에 안 들어온다
- `engram` CLI는 ADR-0081 가드상 UI 어휘를 컴파일에 못 넣는다

**구판(카탈로그를 한 곳에 모으는 안)에는 이 문제가 없었다.** 즉 이건 개정이 치른 대가이고, 방향 자체를 되돌릴 사유는 아니지만 **메우지 않으면 "LLM이 창·탭을 부른다"는 목표가 성립하지 않는다.**

후보 둘 (TRD §2-4·§3-7에 적혀 있다):
1. **등록 패킷에 스키마를 동봉** — 이름과 함께 인자 스키마를 올린다. 등록이 무거워지고 데몬이 스키마를 들고 있게 된다.
2. **`command.describe` 왕복** — 필요할 때 주인에게 물어본다. 데몬은 계속 이름만 안다. 왕복이 한 번 는다.

굵은 형태 결정이라 메인이 임의 확정하지 않았다.

## repo 상태

- 브랜치 `wt2`. **원격보다 15개 앞 — push 안 했다.** 12개는 master 당긴 merge(소스 0줄), `ff9e061`(서베이+TRD 초안), `5e5af9a`(TRD 개정).
- 워킹트리 clean. **소스 코드는 이번 세션에서 한 줄도 안 바뀌었다** — 따라서 빌드·테스트 게이트는 돌리지 않았고 돌릴 이유도 없었다.
- master 통합 미실시(덩어리 단위 규약).

## ★확정된 구조 (정본 = TRD. 여기는 요약)★

```
① 선언 + 본문 = 한 세트, 생산자 모듈 옆에
     core  agent.*  ·  daemon  mail.*  ·  src-tauri  window/tab/slot  ·  webview  theme/chat
② 도구 crate (신규) — 봉투 · 오류 · 선언 매크로만. 명령 0개. core 가 이것만 보면 되게
③ 조립은 실행 파일에서 — 이름·스키마는 자동 수집, 인스턴스는 주입 (전역 자동등록 금지)
④ 배달은 홉마다 같은 3단계 — 내 표 → 명부 → 오류. 2단 배달(데몬→셸→웹뷰)도 같은 규칙
```

- 봉투 `{ name, request_id, owner, proto_ver, args }` + 프레임 종류. **방향 필드 없음**(연결이 방향).
- 등록: 붙을 때 목록 1회 + 변경 시 델타 + 끊기면 tombstone(`available:false`로 존치).
- **데몬은 빌드 목록을 컴파일에 넣지 않는다.** 명부는 런타임 등록으로만 찬다.
- 인가는 **호출마다**. 오류는 `NoOwner`/`Unknown` 2종 구분.
- 새로 짓는 것: 도구 crate + **데몬→셸 인바운드**(실측 0건). 중계 구현이 이 작업에 포함된다(별도 선행 단계 아님 — TRD §6 Step 3).

## ★TRD 개정에서 드러난 것 4건 (구현 전에 봐야 함)★

1. **파생물 CI 게이트가 그대로 안 선다.** 바인딩 diff 게이트는 `protocol/bindings/` **하나만** 본다(`.github/workflows/ci.yml:124-131`). `src-tauri/bindings/`에 이미 8개가 있는데 아무도 안 보고, 워크스페이스 테스트는 그 패키지를 제외해서 CI에서 그 생성이 아예 안 돈다. **오늘 그 8개가 어떻게 갱신되는지 미확인** — 안 풀면 셸 명령의 TS 파생이 손으로 관리하는 생성물이 된다. Step 3 착수 전 실측할 것.
2. **메시징 격리 게이트 정규식이 신규 crate 이름을 안 잡는다**(`ci.yml:252`). 메시징엔 의존 상한 게이트가 없어 정규식이 유일한 벽이다 → **정규식 확장이 필수.**
3. **`core` 워크스페이스 의존이 0 → 1이 된다**(도구 crate). 이 수치를 지키는 게이트는 없어서 **조용히 바뀐다.** 게이트를 새로 세울지 판단할 것.
4. **`Unknown`과 `NoOwner` 구분에 원리적 한계가 남는다.** 데몬이 **한 번도 본 적 없는** 주인의 이름은 여전히 `Unknown`으로 나간다. 정확히 답하려면 데몬이 전량 목록을 알아야 하는데 그건 금지한 것이라, **정확성보다 결합 회피를 택했다**고 TRD §4-②에 명시돼 있다. tombstone 보존 기간은 미확정.

## ★실패한 접근 / do-not★

1. **선언을 한 crate(`protocol`)에 모으지 말 것** — 폐기됐다. TRD에 개정 도장과 함께 옛 문장이 남아 있으니 도장을 보고 판단할 것.
2. **명령 정의에 "주인" 칸을 만들지 말 것** — 정의 위치가 주인. 사용자가 두 번 철회시킨 제안이다.
3. **ADR-0081 「Opaque 결합 가드」에 폐기 도장을 찍지 말 것** — 필요 없어졌다(데몬이 UI 타입을 컴파일에 안 넣는다).
4. **전역 자동등록 표에 핸들러를 박지 말 것** — 테스트가 가짜 관리자를 못 꽂아 실제 프로세스가 딸려온다. TRD §7 규칙 T-1이 하드 제약이고 판정 기준까지 적혀 있다.
5. **데몬이 빌드 목록을 컴파일에 넣지 말 것** — 화면 이름을 정적으로 알게 되고, 앱이 꺼져 있어도 "있다"고 잘못 안다.
6. **봉투에 방향 필드를 넣지 말 것.**
7. **받은 자리(연결 태스크)에서 실행하지 말 것** — 복합 명령이 자기 자신을 기다려 멈춘다.
8. **데몬이 인자를 뜯게 만들지 말 것.** 단 **이름은 겉봉에 반드시 노출** — 명령 단위 권한·관측이 여기 달렸다.
9. **조사 보고서를 확정으로 읽지 말 것** — BLOCK, 반증 6건이 표로 남아 있다.
10. **채팅에서 영어 용어·새 비유를 만들지 말 것** — 이번 세션에서 사용자 이해가 40%까지 떨어져 재설명이 반복됐다. **C++ 예시가 가장 잘 통했다.** 코드 식별자를 그대로 쓰거나 역할로 말할 것.
