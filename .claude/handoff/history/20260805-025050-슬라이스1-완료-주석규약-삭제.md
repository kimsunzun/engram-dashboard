## ★왜 다음이 0-4 인가 (계획 변경 — 재조사 불필요)★

이월 근거였던 Cargo 순환은 **네트워크行이 데몬 crate 안에 있을 때만** 실재했다. 그때는 인증 타입이 `daemon` 에 놓이므로 `discovery → daemon` 이 필요해지고, 기존 `daemon → discovery`(경로 헬퍼)와 고리를 닫았다.

**지금은 아니다.** 네트워크行이 자기 crate 로 떨어져서 `discovery → net` 은 비순환이다 — net 의 정방향 워크스페이스 폐포가 `{core, protocol}` 이라 discovery 에 절대 닿지 않는다. **양 리뷰어가 `cargo tree` 로 독립 확인했다.** 즉 **슬라이스 1 의 완료가 곧 0-4 를 푸는 조건**이었다.

0-4 가 끝나면 ADR-0129 결정 1 의 "에이전트 어휘 타입 0" 불변식이 **완전 충족**된다(지금은 `ws.rs` 의 `AgentCommand::Auth`/`PROTOCOL_VERSION` 한 쌍만 의도적 미충족).

**검증 레시피(문서에 박혀 있다 — 그대로 실행 가능):**
```bash
cargo tree -p engram-dashboard-net -e normal --prefix none --target all --all-features \
  | rg "^engram-dashboard" | sort -u          # → net/core/protocol, discovery 없음
```
**★`cargo tree --invert` 를 쓰지 말 것★** — 조상을 나열할 뿐이라 순환이 실재하는 세계에서도 같은 출력이 나온다(unsound). 정방향 폐포를 봐야 한다.

- **슬롯에 배정 안 된 ad-hoc 에이전트는 수동 등록 채널로 출력 프레임을 못 받는다**(데몬 출력 구독이 레이아웃 주도 — ADR-0035/0046). 실측은 **실 슬롯 경로**(`spawn_into`)로 할 것. *결함 아님.*
