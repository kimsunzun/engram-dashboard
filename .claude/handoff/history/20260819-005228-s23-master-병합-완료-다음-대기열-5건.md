## ★대기열 — 전부 미착수, 사용자가 순서를 정한다★

### 1. 이력 없는 세션은 resume 대상에서 제외 + 트리에 실행 불가 표시 (방향 확정)

**증상(사용자 실측 2026-08-18):** 에이전트를 띄우고 **한 마디도 안 한 채** 종료 → 앱 재시작 시 그 슬롯에 `claude stream-json result reported failure (subtype=error_during_execution)`가 뜬다. 채팅 한 번 친 세션은 정상 복원된다.

**원인(설명, 코드 확증은 미실시):** 우리는 첫 spawn에서 세션 id를 우리가 정해 넘기고 복원 때 그 id로 `--resume`한다. claude는 **첫 메시지가 오가야** 그 세션의 대화 파일을 만든다 → 아이디만 있고 실체가 없어 복원이 실패한다. ADR-0082가 "복원 실패 시 새 대화로 조용히 갈아타지 않는다"로 막아둔 상태라 실패가 그대로 화면에 남는다.

**사용자 결정(2026-08-19):** 이력이 없는 세션은 **애초에 resume하지 않는다.** 더해서 **트리에 표시(예: X 아이콘)를 달아 실행 자체가 안 되게** 하는 방향.

**설계 시 정할 것:** ⓐ "이력 없음"을 무엇으로 판정하나(우리 기록이 비었는지 vs claude 대화 파일 부재) ⓑ 그 표시가 붙은 항목의 조작 가능 범위(삭제만? 새로 시작?) ⓒ ADR-0082의 해당 조항 부분 개정(그 금지는 *이력을 덮어쓸까 봐* 만든 것이라, 이력이 없다고 확인되면 근거가 성립하지 않는다).

### 2. Wait(대기) 표시 전반 정리

**증상:** 대기 표시가 떠 있는 상태에서 종료하면 **숫자가 계속 올라간다**(사용자 실측 2026-08-18). 사용자: "예전부터 버그가 많다 — 나중에 한 번 정리해야겠다."

**방향(사용자):** 개별 증상 대응 말고 **한 번에 정리.** 상태 전이(전송 직후 / 첫 응답 도착 / 턴 종료 / 에이전트 사망·연결 끊김)를 한 곳에서 정하는 형태가 후보다. 이번 세션에도 그 변수 주변에서 결함이 세 번 나왔다(실패 catch가 남의 전송 상태를 지움 · 빈 응답 조각에 표시가 꺼짐 · 종료 후에도 계속 돎).

### 3. 모델명 + effort 단계 보유·캐싱 (사전 조사 완료)

- claude 시작 라인에 **`model`은 있다**(`"claude-opus-5[1m]"` — CLI 별칭 + 컨텍스트창 접미사. `assistant.message.model`·`result.modelUsage`는 접미사 없는 값이라 **표기가 갈린다**). `claude_code_version`도 있다(사용자: 버전은 불필요).

## S23이 남긴 알려진 한계 (ADR-0149 §영향에 기록됨)

## ★이 세션이 낸 사고★

**사용자 프로필 2개(`Filter Library(1)`·`(2)`)가 사라졌다.** 내가 명시적으로 지운 id 목록엔 없었다. 두 프로필은 `auto_restore=true`였고, 실측하느라 **데몬을 여러 번 재기동**했다 — 매 기동마다 자동 복원되고 그 세션이 종료로 끝나면 종료 분류(ADR-0019)가 정리하는 경로가 가장 유력하다(**미확증**, 로그로 되짚지 않았다). 원인 규명을 원하면 데몬 로그가 출발점이다.

**교훈:** 사용자 데이터가 있는 데몬을 실측 목적으로 반복 재기동하지 말 것.

## 실패한 접근 (do-not)

- **`agent.spawnInto`로는 JSON 모드 에이전트를 못 만든다**(`outputFormat`을 안 받아 터미널로 뜬다). `forward_daemon_command`로 `CreateProfile{output_format:'StreamJson'}` → `SpawnProfile` → `__engramLayout.assignAgent(viewId, slotId, agentId)`.
- **`tab.close`의 인자 이름은 `view`다** — `viewId`로 넘기면 무시되고 **활성 탭이 닫힌다**(실발생).
- **`ListProfiles` 응답 키는 `ProfileList`** — `r.Profiles`로 읽으면 빈 배열이라 "명부가 비었다"로 오판한다(실발생).
- **CDP eval에서 상태 변경 직후 같은 호출로 DOM을 읽지 말 것** — React 커밋 전이라 오판한다. dispatch와 read를 별도 eval로 나눈다.
- **codex 리뷰어 출력이 비어 보여도 즉시 실패로 단정하지 말 것** — 늦게 쓰는 중일 수 있다(중복 실행으로 낭비 실발생). 완료 신호를 먼저 본다.
- **1420 포트를 wt2가 잡고 있으면 디버그 실측 금지** — 남의 화면을 측정한다. 이번 세션은 전부 릴리스 빌드로 실측했다(`npm run tauri build -- --no-bundle`, 약 5분).
