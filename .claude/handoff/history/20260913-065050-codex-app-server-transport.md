## 실측 대장 — ★저장소 어디에도 없는 사실들. 잃으면 다시 비싸다★

측정 대상 = 이 PC 의 **codex-cli 0.154.0**. ★TRD 의 실측은 0.153.4 라 버전이 어긋난다.★

**되살리는 법**
- 스키마 전량: `codex app-server generate-json-schema --out <dir>` → v2 타입 266 개. (`codex app-server generate-ts` 도 있다.)
- 재생성 명령은 `protocol.rs` 헤더에도 박아 뒀다.

**핸드셰이크 8문항(턴 미실행 = 모델 호출 0)**
1. **stdout 은 NDJSON 뿐** — 배너 없음, 비-JSON 줄 0(4회 런). 오류는 stderr. ★TRD §4-6 의 전제는 이 버전에서 미관측★.
2. `initialize` 응답 = `userAgent`·`codexHome`·`platformFamily`·`platformOs` 넷. **1회용** — 두 번째는 `-32600 Already initialized`.
3. **`initialized` 알림은 선택** — 보낸 런과 건너뛴 런의 `thread/start` 가 동일하게 성공.
4. initialize 직후 무단 도착 = `remoteControl/status/changed` 1건. `thread/start` 뒤엔 `thread/started` + `mcpServer/startupStatus/updated` 4건.
5. thread id = `result.thread.id`(UUIDv7), `result.thread.sessionId` 동일값.
6. 미지 메서드 → `-32600`, `data` 없음, **message 가 유효 메서드 160개를 나열하는 약 4KB 단일 라인**. 깨진 라인은 stderr 로그만 남기고 죽지 않는다.
7. **stdin 만 닫으면 41~51ms 에 스스로 exit 0** — kill 불요.
8. 데몬·소켓·lock 파일 안 남김. 단 `thread/start` 가 **MCP 손자 프로세스**를 띄운다(부모와 함께 죽는 것 실측).

**설계를 바꾼 셋(★전부 TRD 에 없다★)**
- ★**잘못된 봉투는 id 가 있어도 응답이 영영 안 온다**★ — `{"id":90}`(method 없음)은 stderr 한 줄 남기고 영구 무응답. **그래서 모든 아웃바운드 요청에 마감시한이 필수다.**
- ★**`id: null` 은 요청을 조용히 알림으로 강등시켜 버린다**★ — 오류도 stderr 도 없다.
- ★**thread id 를 알려주는 응답보다 그 thread 를 가리키는 알림이 먼저 올 수 있다**★(실측 0.2ms).
- 덤: `"jsonrpc":"2.0"` 을 붙여도 통과(무시). 응답에 스키마에 없는 필드가 8개 이상 붙는다 → **`deny_unknown_fields` 는 즉사**.

## do-not

1. ★**`turn/started` 로 턴을 식별하려 하지 말 것**★ — 우리가 발급한 식별자를 안 실어 **귀속이 불가능하다**. 그걸로 식별하려던 판이 리뷰 2라운드를 잡아먹었고, 지우면서 턴 기계가 24줄 줄었다. 근거 정본 = `TURN_COMPLETED` 상수 doc.
2. ★**접점을 박기 전에 그 접점이 지나는 기존 trait 계약을 읽을 것**★ — 메인이 「`decode` 는 한 줄을 받는다」로 박았는데 실제 계약은 임의 바이트 청크 + 꼬리 버퍼링이었다. 두 리뷰어가 독립으로 1번 결함으로 꼽았고 라운드 하나를 통째로 태웠다.
3. **주석에 코드가 성립시키지 않는 주장을 쓰지 말 것** — 이 작업에서만 3라운드를 먹었다(손으로 계산한 수 · 상대가 고르는 문자열에 대한 "보장" · 유계가 아닌데 유계라는 주석).
4. **테스트 건수를 커버리지로 읽지 말 것** — 통과하면서 아무것도 안 지키는 테스트가 5건 이상 나왔다. **가드마다 그것이 지키는 것을 지워 빨개지는지 확인**(뮤테이션)이 유일한 증명이다.
5. **선언 표가 초록이라고 그 축이 지켜진다고 믿지 말 것** — 실측으로 확인: app-server 표본 한 줄을 지우면 **세 트립와이어가 전부 초록**이었다. 지금은 `the_sample_list_covers_every_mode_of_every_backend` 가 그 목록 자체를 지킨다.
6. **코드 push 뒤 CI 가 끝나기 전에 후속 커밋을 밀지 말 것** — 앞 실행이 취소된다(이번에 발생).
7. **step-log 꼬리를 통째로 읽지 말 것** — `grep -o "S[0-9]\+" | tail` 로 충분. ★그리고 항목 형식은 헤딩이 아니라 **파일 끝 절의 불릿**이다★(`## S…` 계열은 2026-08-25 에 끝났다).

## 이 세션의 운영 관측

- **최대 단일 비용 = 통로의 리뷰↔수정 왕복**(코더 회당 38만~58만 토큰 × 3회). 봉투·번역기는 같은 라운드 수에 절반 이하였다 — 차이는 코드량이 아니라 **동시성**이다(매 수정이 새 인터리빙을 만들어 다음 라운드 findings 가 됐다).
- **조사·브리프가 값을 했다.** 프로토콜 압축(1150줄)과 통로 브리프(394줄) 둘을 합쳐도 코더 한 라운드보다 쌌고, 없었으면 코더가 스키마 266종과 TRD 1340줄을 직접 읽어야 했다.
- **리뷰어에게 「커밋 차단 / 빚」을 나눠 달라고 요구한 것이 캡 아래서 결정적이었다.** 마지막 라운드를 「코드 1곳 + 주석 3곳」으로 좁혀 끝냈다.
- 스킬 피드백 적립: `qa`(폴링 배치 · `npx` 는 `call` 필요 — 0바이트 로그 함정) · `review`(차단/빚 분리 · 뮤테이션 spot-check · 시간제 한도 처리) · `implement`(접점↔기존 계약 · 하드캡이 「수렴 중 새 표면」을 구분 못 함).
