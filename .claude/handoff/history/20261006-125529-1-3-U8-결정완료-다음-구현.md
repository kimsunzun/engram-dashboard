## 사용자 결정 (2026-10-06)
1. **U8 — OS 경계 게이트(「러프하게 · 범용적인 것만 막는다」 · 문자열 비교 수준이면 된다):**
   - `cfg` 게이트 ④(PCRE2 문법 정규식 · 명단 33)는 **지금 꼴로 닫는다** — 드문 꼴(`cfg_select!` · `cfg_aliases`/`cfg_if!` · 술어 앞 주석 · `cfg!{}`/`cfg![]` · 깊은 중첩)은 platform 헤더 ④ 「한계」에 적는다. 적대 리뷰의 드문 꼴 추적은 더 하지 않는다.
   - **의존 게이트 추가** — OS crate 목록을 손으로 적는다(관행 = cargo-deny 식 명시 목록): `windows` · `windows-sys` · `winapi` · `libc` · `nix` · `rustix` · `objc2` 계열 · `objc` · `cocoa` · `core-foundation` · `core-graphics` · `security-framework` · `mach2`. 검사 = `cargo tree --target all`(cargo-deny 아님 — 우리 멤버만 본다): 워크스페이스 멤버 중 **운영 의존(normal · build)** 으로 이것들을 직접 가질 수 있는 것은 `platform` 하나. dev 의존은 허용(agent 의 `windows` dev = examples/spike). ★켜기 전 실측: 지금 이미 위반이 있나(셸 · 데몬이 `libc` 직접 등) — 있으면 사용자에게.★
   - **`std::os` 텍스트 게이트 추가(B — 러프)** — platform 밖 운영 코드에 `std::os::windows` · `std::os::unix` 가 나오면 빨강. 시험 파일은 게이트 ④ 처럼 명단으로 허용. 별칭(`use std::os as x`)은 놓치는 것을 감수. clippy(A)는 하지 않는다 — `std::os` 금지에 쓴 피어가 0 이라 관행이 아니었다(메인이 처음에 과장했고 정정함).
   - **하지 않는 것** = 교차 타깃 `cargo check` · clippy · Dylint · cargo-deny — 메모만(macOS 이식 때 다시).
   - 사용자가 확인한 이해: std 의 일반 API(`std::fs` · `std::process`)는 OS 에 맞게 알아서 바뀌므로 경계 대상이 아니다. 막는 것은 `std::os` 하나.
2. **taskkill 창 숨김** — platform `process::kill_tree` 가 `taskkill.exe` 를 창 숨김 없이 띄워 콘솔이 번쩍일 수 있다 → `spawn::hide_console_window` 를 붙인다. 1-3 안에서 **U8 과 별도의 작은 커밋**. (참고: 트레이 「데몬 끄기」는 graceful `send_stop` 이라 taskkill 을 안 탄다 · taskkill 은 프론트 `daemonControl` 의 graceful 실패 fallback 뿐.)
3. **환경변수 이름 비교** — `CODEX_HOME`(codex `thread_lock` `child_lock_dir`) · `MAX_THINKING_TOKENS`(claude `build_spec`) 를 platform `env::env_key_eq` 로 바꾼다(Windows 결과 불변). `usage/gate.rs:69` `env_overrides_daemon` 은 의도된 보수 판정이라 **그대로**. 2 와 같은 작은 커밋.
4. 인증 모듈 분리 — 지금 결정 아님(transport TRD · 메모 후보 7 의 열린 질문).
