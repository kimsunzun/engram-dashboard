## 이 세션에 한 일

**결함 둘을 닫았다 — 같은 축의 원인과 그 부작용이다.**

1. **명령이 연결 경계를 넘던 것**(ADR-0195) — 소켓이 끊긴 동안 들어온 명령이 **다음 연결에서 실행되고 호출자는 성공했다고 듣던** 결함. 장치 둘 = **창구 게이트**(산 소켓이 없으면 송신단을 안 내준다 — ★저장된 송신단을 떨구지는 않는다. 그것이 유일한 강한 송신단이고 그 EOF 가 연결 task 의 유일한 즉시 종료 신호라, 비우면 재연결 루프가 죽는다★) + **소켓 세대 도장**(수신 루프가 불일치를 거절하며 대기자를 오류로 깨운다).
2. **그것이 만든 리사이즈 유실** — resize 는 fire-and-forget 이라 재연결 창에서 조용히 버려지고 다시 낼 자리가 없었다. `TerminalSlot` 에 **구독과 분리된 effect** 하나를 두어 connected 로의 전이마다 자기 치수를 다시 낸다. ★구독 트리거에 연결 상태를 섞지 않는다★(ADR-0164).

**사용자 질문이 2번을 열었다** — 「최초 접속 성공할 때 보내면 되는 거 아님?」. 맞았고, 최초 접속은 이미 그랬으며 빠진 건 재연결뿐이었다.

## 알려진 잔여 — 전부 기록만 했고 안 고쳤다

- ★**`reply_rx.await` 가 강한 송신단을 쥔다 — 진짜 hang 경로다**★(기존 결함, HEAD 와 바이트 동일). 데몬이 소켓을 열어 둔 채 응답을 안 하면 호출자가 매달리고 `close()` 가 task 를 수거 못 한다. **여덟 호출처 중 `forward_daemon_command` 만 30초 상한**(`commands/agent.rs:263`), 나머지 일곱은 무한. 고치는 법 둘 = 왕복에 마감시각 주기 · `main_loop` 에 취소 arm. 설명 정본 = `mod.rs` 의 `send_command` 「알려진 잔여」 블록.
- **구독 `.then` 경로의 resize 는 가시성 가드가 아예 없다** — 숨은 keep-alive 탭에서 마운트되면 `display:none` 컨테이너를 잰 값을 보낸다. 이제 다섯 발신자 중 유일하게 숨김 처리가 다르다.
- **같은 agentId 를 보는 슬롯 둘이면 어느 쪽이 PTY 에 남는지 미정**(별개의 비동기 왕복 — RO 발화에 이미 있던 중재).
- **글리프 metrics 가 0 인 슬롯은 직전 치수가 나가고 재시도가 없다.**
- **사용자 대면 오류 문구를 못 박는 단언이 없다** — 상수화는 집을 하나로 줄일 뿐 문구를 고정하지 않는다(실측: 상수를 바꿔도 초록).
- **T-35** — 별건 간헐 실패(`tests.rs:2232`). 이번 작업의 30+150회 반복에서 재현 안 됐으나 약 1/30 이라 약한 증거.
- **실측 중 관측(미규명, 별건):** 데몬 재기동 후 auto_restore 가 에이전트를 복원하지 않았다 · 실측용 claude 에이전트가 반복 조기 종료했다(PTY 40×10 에서 즉사).
