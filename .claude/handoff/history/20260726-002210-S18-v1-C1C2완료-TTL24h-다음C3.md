## C2 코드 계약 (C3가 알아야 할 것)
- `MessagingService.handle_single_send` = 판정 진입점(락 안 판정·락 밖 주입). busy면 파킹+도어벨(`FlushTrigger`), 큐 비어있지 않으면 직발송도 큐 합류(FIFO). `flush_for_agent(id)` = 현재 이름 큐 + `hinted_id` 매칭 큐 flush.
- `BusyTracker`(busy.rs): 양성 attach 게이트 `HashMap<(id,epoch),Instant>`, `BUSY_MAX_TURN=30min` fail-open(60s 스윕이 stale busy 청소+도어벨). tap = `subscribe_from` **live-only**(replay 부트스트랩 = 거부된 설계, 주석에 근거).
- ws.rs: `FlushMsg{Appear,Attach,Detach,Idle}` 단일 채널 → main 레인(생애주기)+flush 레인(주입) 분리, 둘 다 `FLUSH_JOIN_BELT` 5s로 셧다운(순서: shutdown_all 먼저 — kill이 블록 해제의 실보증).
- mailbox: `admission_seq`가 큐 순서축(복원 = `restore_ordered` merge), 만료 스캔 전량, cap=수용 전용, `PARK_TTL=24h`.
- 락 규율: messaging 락 → busy 락 단방향만. **락 보유 중 tracing 금지**(수집 후 락 밖 로깅). BusyGate는 락 보유 중 호출 안전 계약.

## do-not (재발 방지 — 이 세션 추가분)
- **blind 리뷰어 payload에 증분 스코프·의도적 미배선을 명시**(아니면 false BLOCK).
- **replay 부트스트랩으로 busy 상태 세우지 말 것**(resume transcript가 MessageDone 없이 끝나면 영구 false-busy — 이번 HIGH).
- 실험 bin 3종(roundtrip/priming/saturation)은 게이트 미적용(C1 동작) — 게이트 검증에 쓰지 말 것.
- src-tauri lib 테스트(`cargo test -p engram-dashboard --lib`)는 pre-existing DLL 로더 문제로 실행 불가(STATUS_ENTRYPOINT_NOT_FOUND) — 게이트 목록에 없음, 무시.
- 직전 세션 do-not 승계(stray kill·릴리즈 재빌드·전역 allowedMcpServers 불변·수신자 stream-json만).
