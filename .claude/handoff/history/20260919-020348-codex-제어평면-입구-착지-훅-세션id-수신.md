## 먼저 읽을 것

1. ★**이 세션의 가장 값진 산출은 코드가 아니라 아래 「측정값」 절이다**★ — 다시 재려면 측정 하나에 10~16분 + 워커 15만 토큰이다. **코드를 읽기 전에 그 절을 읽어라.**

3. **게이트 열화 둘을 안고 커밋했다** — 아래 「검증 상태」의 라벨 둘. 조용히 넘기지 말 것.
4. 사용자가 보고 길이를 반복해 지적했다 — **짧게, 결론 먼저.** 그리고 「막히는 것 아니면 묻지 말고 진행」이 반복 지시였다.

## ★측정값 — 다시 재면 비싼 것 (codex-cli 0.155.0 실측)★

★**전부 이 세션에 직접 돌려 확인한 것이다. 문서·웹이 아니다.**★ codex 벤더 문서는 hook 개념만 적고 기계적 계약(`trusted_hash`·`hooks.state`·저장 위치·무언 스킵·비대화형 부여)을 **한 줄도 안 적는다.**

### 훅 발화와 신뢰

- **훅을 실행 인자(`-c hooks.SessionStart=[…]`)로만 넘기면 파서는 받아들이지만 실행되지 않는다.** ★**완전 침묵으로 스킵된다**★ — 오류·프롬프트·로그 전부 없고 종료코드 0. `RUST_LOG=codex_hooks=trace` 까지 켜도 한 줄 안 남는다. **막는 것은 신뢰(trust)다.**
- `--dangerously-bypass-hook-trust` 를 붙이면 실행된다(2회 재현). ★**단 그 인자는 root/`exec` 에만 있고 `codex app-server` 는 받지 않는다**★ — 붙이면 `error: unexpected argument` 로 죽는다.
- **신뢰 영속 위치 = `$CODEX_HOME/config.toml`:**
  ```toml
  [hooks.state.'<sourcePath>:<event_snake>:<group_index>:<handler_index>']
  trusted_hash = "sha256:<hex>"
  ```
  ★**키는 훅 슬롯 단위다**★ — 훅 하나를 고치면 그 하나만 `modified` 가 되지만, **배열 순서를 바꾸거나 앞 항목을 지우면 뒤 슬롯의 키가 밀려 신뢰가 풀린다.**
- **신뢰 부여는 프로그램으로 된다(왕복 실측 확인):** app-server 로 `hooks/list` → 각 훅의 `key`·`currentHash`·`trustStatus` 수신 → `config/batchWrite` 로 `hooks.state` upsert(`mergeStrategy:"upsert"`, `reloadUserConfig:true`) → `untrusted` → `trusted`. **새 프로세스에서도 유지된다.** `-c` 로 주입한 훅도 같은 방식으로 신뢰가 붙는다.
- ★**해시를 직접 계산하지 말 것**★ — 재현은 가능하나(정규화 JSON 의 sha256) **선례(orca)가 codex 릴리스마다 깨져 그 자체 계산을 버리고 RPC 경로로 갈아탔다.** 우리는 그 시행착오를 건너뛴다.
- ★**신뢰 상태를 `-c` 로 주입하는 것은 실패했다**★ — 키에 콜론·백슬래시가 섞여서다. **파일로 넣어야 한다.**
- 심사 프롬프트는 **TUI 에만** 뜬다(`tui/src/startup_hooks_review.rs`). `exec`·`app-server` 는 묻지 않고 **무언 스킵**한다.
- `trustStatus` 어휘 = `trusted` / `untrusted` / `modified` / `managed`.

### 훅이 언제 뜨고 무엇을 주나

- **`codex exec`**: 세션 생성 직후, **사용자 프롬프트가 대화에 실리기 0.13초 전**에 뜬다(두 표본에서 간격 동일 → **훅을 동기로 기다린 뒤 프롬프트를 넣는 구조**).
- ★**`codex app-server` 도 뜬다**★ — 단 `thread/start` 가 아니라 **첫 `turn/start` 16ms 뒤**다. 스레드만 열고 턴을 안 돌리면 **안 뜬다.**
- ★★**app-server 에서 훅의 `session_id` == `thread/start` 응답의 `thread.id` (같은 값 실측)**★★ — 두 경로가 같은 칸에 같은 값을 쓴다. **통로 sink 가 언제나 먼저 도착한다.**
- `thread/resume` 뒤 첫 턴도 뜨고 `source` 가 `resume` 이다(신규는 `startup`).
- **app-server 는 `hook/started`·`hook/completed` 를 프로토콜로 내보낸다** → 외부 레코더 없이 발화·타이밍을 잴 수 있다. ★다음에 같은 부류를 잴 때는 `hooks/list` 를 먼저 불러라★ — `trustStatus`·`currentHash`·`key` 가 한 번에 나와 **무언 스킵과 미발화가 즉시 갈린다**(레코더 컨트롤보다 이것이 먼저다).
- **stdin 페이로드 = 정확히 7필드**(verbatim):
  `session_id` · `transcript_path` · `cwd` · `hook_event_name` · `model` · `permission_mode` · `source`
  467바이트, 개행 없음. ★**argv 는 비어 있다 — 전달은 stdin 단독**★. `.cmd` 직접 지정으로 뜬다(셸 래핑 불필요). 훅 프로세스 cwd = 세션 cwd.
- ★**codex 는 훅 프로세스에 자기 env 를 하나도 주입하지 않는다 — 순수 상속이다**★. 그래서 우리가 심은 `ENGRAM_TOKEN` 이 그대로 도달한다.
- ★**`CODEX_THREAD_ID` 는 0.155.0 에 존재하지 않는다**★(바이너리 전체 문자열 0건). **herdr 의 codex 훅이 그것으로 중첩을 가르는데, 그 가드를 베끼면 항상 미설정으로 읽힌다.**
- codex 훅 이벤트 어휘(herdr 설치 코드에서): `SessionStart` · `UserPromptSubmit` · `PreToolUse` · `Stop` · `PermissionRequest`. **herdr 도 지금은 `SessionStart` 하나만 쓴다**(나머지는 옛 항목을 지우는 코드만 남았다).

판별법 = `codex -c '<키>=<값>' --strict-config app-server --stdio < /dev/null` — ★가짜 키는 `unknown configuration field` 로 죽으므로 대조군이 성립한다★. (`doctor` 로는 검증이 안 된다 — 판별력 없음.)

- **`CODEX_HOME` 환경변수로 홈을 통째로 옮길 수 있다(실측)** — 그 프로세스에만 적용되고 사용자 본인 codex 는 원래 홈을 쓴다. ★**단 인증도 같이 옮겨간다**★(빈 홈에서 「자격증명 없음」). 스킬 위치가 홈 아래 `.codex/skills` 고정이므로 **스킬을 우리가 공급하려면 이 경로뿐이다.**

- ★**쿼터 안 쓰고 재는 법**★ — `CODEX_HOME` 을 빈 폴더로 돌리면 auth 가 없어 턴이 401 로 죽는데 **훅은 그 앞에서 발화한다.** 이 트릭으로 `turn/start` 까지 무료로 측정했다.

## 조사 결론 — 왜 훅인가 (피어 서베이 + 기법 분석)

- ★**위험한 것은 기법이 아니라 「못 찾았을 때 하나 고르는 tie-break」다**★ — `가장 최근 mtime`·`첫 매치` 류가 붙는 순간 그 기법은 **not-found 를 wrong-found 로 변환**하고, **그 변환은 전부 조용하다.** 새 대화가 「resumed」로 보고되는 최악 시나리오는 정확히 이 경로로만 생긴다.
- **오귀속이 구조적으로 불가능한 기법은 둘뿐이고 둘 다 추론이 아니라 전파다:** ① 감독자가 id 를 선발급해 주입(claude 방식 — codex 엔 그 플래그가 **없다**, 독립 2회 확인) ② **감독자가 상관 토큰을 env 로 주입하고 자식의 훅이 되돌려 보낸다**. W3C Trace Context 가 같은 답이다.
- **조용/시끄러움 순위(안전한 순):** `미지원 선언` > `id 선발급` > **`훅+상관토큰`** > `구조화 서버 모드` > `조회 서브커맨드` > `프로세스 introspection` > `출력 스크래핑` > ★`파일 감시(최신 고르기)` = 가장 위험·가장 조용★.
- **피어 셋:**
  - **herdr** — 17 에이전트 전부 훅/플러그인 확장점으로만. 파일 스캔·스크래핑 0줄. ★**그런데 신뢰를 전혀 다루지 않는다**★(`trusted_hash` 0건·bypass 0건·심사 문구 0건) → **codex 세션 id 를 사실상 못 받는다.** ★herdr 만 베꼈으면 우리도 같은 데서 막혔다★.
  - **orca** — app-server RPC 로 신뢰 부여(주 경로) + 자체 해시 폴백 + 심사 화면 스크래핑 안전망. 주석에 `Codex 0.129+ gates each hook on a trusted_hash`. ★**출처 검증 실패 시 resume 인자를 떼고 깨끗한 새 세션으로 띄운 뒤 사용자에게 고지한다**★ — 계정 교차 resume 사고를 겪고 넣었다. **우리가 원하는 정확한 행동 형태다.**
  - **octoally** — 유일하게 화면을 긁는다. **첫 매치 무조건 채택·검증 0.** 파일 탐색 폴백까지 달아 놨다(긁기만으로 부족했다는 자백).
  - 멀티플렉서(wezterm·zellij·tmux)는 **이 문제를 안 푼다** — 터미널을 복원하지 에이전트 세션을 복원하지 않는다.
- **RFC 9413**(IAB, Maintaining Robust Protocols)이 「모호한 입력을 추론된 의도로 처리하라」는 해석을 정면으로 거부한다 — 우리 상황에 가장 정확히 들어맞는 표준 문서.
- 정본 = 이 세션 조사 3갈래 + 측정 3회. ★**보고서 파일로 남기지 못했다 — 이 핸드오프가 유일한 기록이다.**★

## 사용자 결정 (이 세션)

1. ★**훅 보고를 두 모드 공용 경로로 받는다**★ — 「통일성이 중요하니 훅 시스템이 공용이면 공용으로 받아라」. **내가 「JSON 모드는 이미 튼튼한데 약한 길로 바꾸는 것」이라 반대 의견을 냈고 사용자가 재확인했다.** 그 대가 = 신뢰 부여가 **필수**가 되고(안 박히면 두 모드 다 이어받기를 잃는다), 「번호를 못 받은 세션」의 행동을 정의해야 한다(판정 술어 전환이 그 답).
2. **codex 에 딸려 열린 CLI 우편 인가를 되돌린다** — 「나중에 하는 거 아니냐」. 반쪽으로 열린 상태가 가장 나쁘다는 판단.
3. ★**우편은 MCP 가 정식이고 CLI 는 미러다**★ — **내가 거꾸로 알았고 사용자가 정정했다.** CLI 헤더가 `mail` 계열을 「MCP 툴 2종의 미러」로 적고, ADR-0132 의 「CLI 로만」은 `agent` 계열(제어)에만 해당한다. 기존 파생(`mail_allowed = !accepts_mcp_config`)이 이미 그 정책이었다 — **MCP 가 있으면 MCP, 없으면 CLI.**
   → **귀결: codex 우편의 정식 경로는 codex 에 MCP 를 붙이는 것이고, 그것은 별개 덩어리다.**
4. **프로필의 부모는 개념상이고 물리적으로 연결하지 않는다**(사용자 확정) — 그래서 **훅 계보 문제에 못 쓴다.**
5. **스폰 fail-closed·대화 없는 세션의 「이어받기 불가」 표시·전역 설정에 신뢰 한 줄**은 선택지가 없어 내가 정하고 보고만 했다.

## ★리뷰어가 안 고치고 넘긴 여덟 건 (2단계 지시서 재료)★

1. ★**`run()` → `run_hook` 배선을 재는 시험이 없다**★ — `every_hook_failure_path_exits_zero` 는 `run_hook` 을 직접 부르고 `run` 을 안 탄다. **훅 갈래를 `read_credentials` 뒤로 옮겨도 모든 시험이 초록이고, 그때 크레덴셜 부재가 stdout JSON + exit 1 로 샌다** — 이번에 고친 결함이 조용히 돌아오는 경로다.
2. **데몬의 실제 반려(`Conflict`·`NotEligible`·`Unreadable`)는 전부 HTTP 200** 이라 `(200..300)` 성공 판정에 걸려 `hook_note("daemon refused …")` 가 **한 번도 안 뜬다.** 2xx 게이트가 잡는 것은 전송층 오류뿐.
3. **판정의 셋째 항이 손으로 관리하는 열거다** — Fresh 반납 판정의 「그 칸을 채울 경로」를 `supports_control_channel || declares_link` 로 적었다. ★**셋째 보고 경로가 생기면 여기 더해야 하고, 안 더하면 그 백엔드만 2회차 화신부터 조용히 freeze 한다**★(증상 = 정상 재시작마다 거절 로그). 컴파일러가 못 잡는다. 진짜 축(「상대가 우리에게 id 를 말할 수 있나」)을 선언하는 칸이 없다.
4. **shell 의 `uses_mail` 미선언** — `reads_messages=false` 인데 기본값 true 라 이번에 세운 규율(「둘이 갈린 행은 사유가 그 백엔드 폴더에」)을 즉시 어긴다. 오늘 무해한 이유는 `supports_control_channel=false` 하나이고, **그건 이번에 고친 버그와 정확히 같은 모양(선언 없는 보내기 인가)이며 기본값이 fail-open 이다.**
5. **`ENGRAM_HOOK_DEBUG` 가 상속되면 은닉이 깨진다** — 서술은 고쳤지만 현상은 남는다. 데몬을 그 변수가 있는 셸에서 띄우면 에이전트가 훅 계열 이름을 stderr 에서 본다. 끊을지는 결정 사안(끊으면 배선 진단 수단이 0 — stdout·종료코드가 둘 다 봉인이라).
6. **상수 배치 근거가 사실이 아니다** — `types.rs` 의 두 상수를 코어에 둔 사유가 「생산자·소비자가 다른 crate」인데 소비자 전량이 daemon 이다. 실질 근거(최소 CLI bin 이 데몬 lib 의 axum·tokio 를 안 링크하려 한다)는 어디에도 없고, 결과적으로 **코어가 데몬 HTTP 라우트 경로를 선언한다**(ADR-0003 정신과 어긋남).
7. **`old_session_ids` 상한 없음 — 증가 경로가 하나 늘었다**(codex 터미널이 화신마다 한 개). 기존 미결(핸드오프 결정 5번)과 같은 뿌리.
8. 시험 동어반복(`assert_eq!(CONTROL_HOOK_ROUTE, "/control/hook")`) · 하네스가 `mail_allowed=true` 리터럴(운영 파생은 false) · 라우트 층 자격 순서 미검 · TOCTOU(근거 약함, 재현 시나리오 없음).
