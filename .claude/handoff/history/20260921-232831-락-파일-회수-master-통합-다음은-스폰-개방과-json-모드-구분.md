## do-not (이 세션에서 실제로 겪은 것만)

1. ★**게이트 초록을 「동작한다」로 읽지 말 것**★ — 래퍼 PID 결함이 **전 게이트 초록 아래** 살아 있었다. 원인은 둘: **배선을 재는 테스트가 0개**였고(지운 상태줄 테스트가 그 자리였다), 매처 픽스처가 홀더를 「자식 자신의 pid」로 심어 결함 아래서도 초록이었다. **새 규칙을 넣으면 변이 검증으로 그 규칙이 실제로 지켜지는지 확인할 것.**
2. ★**조사가 추천한 것을 우리 실측보다 앞세우지 말 것**★ — 이번 조사가 `tui.terminal_title` 을 최선으로 재추천했는데 **ADR-0216 이 32자 절단으로 이미 기각한 것**이었다.
3. ★**codex 는 틀린 resume 값을 실패로 돌려주지 않는다**★ — 세션 이름으로 재해석해 **종료코드 0** 으로 새 대화를 열고 턴을 과금한다. claude 는 정직하게 실패한다(정반대).
4. **락 파일은 「재개 가능?」 판정에 못 쓴다** — 내용 없는 락은 GC 되고 `exec` 세션은 락을 안 만든다. 그 판정은 **rollout 파일 존재**로 한다.
5. **codex 측정은 이미 신뢰된 폴더에서** — 새 폴더면 신뢰 모달에 막혀 아무 신호 없이 멈춘다.
6. **앱·빌드·테스트는 분리 실행** · `-- --test-threads=4` 유지 · 루트 bare `cargo test` 금지.

## 미결 · 사용자 결정 대기

1. ★**잔여 정리가 반만 됐다 — 삭제가 자동 모드 보호에 막혔다**★. **백업은 만들어 뒀다**(`~/.codex/config.toml.bak-20260921`). 남은 대상 셋: `config.toml` 의 **`c:\users`**(트리 전체가 신뢰됨)·**`c:\codex-trust-test`** 항목 · 빈 폴더 **`~/.codex/app-server-control`**(★남겨 두면 나중에 그 경로를 쓰는 app-server 가 「디렉터리가 내 것이 아니다」로 거절당한다★) · `C:\codex-trust-test` 폴더.
   - **`qa-codex-probe` 는 지우지 말 것** — 신뢰된 폴더라 codex 측정이 그것을 쓴다.
   - **`~/.codex/sessions/` 기록도 건드리지 말 것** — 그게 재개의 원천이다.
2. **재개 실패 폴백 — 설계까지 끝났고 구현만 남았다**(codex 쪽에만, claude 와 합치지 않는다). **판정 기준은 실측으로 확정**: 그 id 를 담은 **rollout 파일 존재**가 네 경우 모두 재개 가능 여부와 일치했고, codex 자신의 오류문이 `no rollout found for thread id` 라 같은 파일을 본다. **사용자 지정 형태 = 「실패했을 때만 확인한다」** — 평소엔 그냥 `resume` 로 띄우고, 실패하면 그때 파일을 보고 **없으면 새 세션 + 고지 · 있으면 새 세션으로 안 떨어뜨리고 알린다.** 선례 = orca 가 같은 형태(배너 고지까지).
3. **「우리 홀더 둘이면 모호」는 보류다** — 반론(둘 다 우리 것이면 채택이 옳다)이 섰고 코드·문서 양쪽에 「여기서 조용히 뒤집지 말 것」으로 박아 뒀다. 뒤집으려면 **핸들 상속 실재 측정**부터.
4. **문서 후속 다섯**(doc 리뷰가 후속으로 분류) — `agent-backend.md` 의 `mcp_server_override` 앵커가 실재하지 않는 심볼 · 출생순서 가드의 잔여 미기재 · 표식의 endpoint 조건 미기재 · `backend-capabilities.md:15` 의 손으로 센 열거 · **`qa.md:83` 의 `npm test` 원인 서술**(같은 `.cmd` 기전인데 다른 원인으로 적혀 있다 — `call npm test` 로 마커가 붙는지 재고 정리할 것).
5. **`scripts/run-detached.ps1` 이 `.cmd` 를 `call` 없이 부른다** — 문서만 고쳤고 스크립트는 그대로.
6. **도움말 화면 보수 · claude 쪽 우편 가시성 · 에스컬레이션 축 게이트 부재** — 계속 미착수.
7. **`subscribeOutput()` 에 실 슬롯이 아닌 viewId 를 주면 replay 경계가 영영 안 잡힌다**(QA 워커 관측 — `request_replay` 가 gen 1→11 로 무한 재시도). 설계인지 결함인지 미판정.

## 절차 관측 (적립한 것만)

- ★**"리뷰가 없었으면 조용히 실패하는 기능이 나갔다" 가 이 세션의 한 줄**★ — 두 계열이 **독립으로 같은 급소를 두 번** 짚었다(래퍼 PID · 테스트 부재).
- **codex 리뷰어는 기본 모델이 계정에서 거부돼 두 번 실패했다** — `--model gpt-5.6-luna` 를 명시해야 돈다. 규약의 「1회 재실행 후 대체」를 그대로 탔다.
- **자동 모드 보호가 `~/.codex` 삭제를 막는다** — 백업 생성은 통과, 삭제는 거부. 잔여 정리를 워커에 맡길 때 이 경계를 미리 알릴 것.
