## ★★다음 세션이 쓸 답 — 훅을 없애는 경로★★

**문제:** 터미널 모드 codex 는 자기 세션 id 를 스스로 정하고 안 알려준다. 그래서 `SessionStart` 훅으로 되받는데, codex 가 **훅 명령 문자열을 해싱해 사람 승인을 요구**한다. 우리 명령엔 **우리 exe 절대경로**가 들어가고 릴리스가 **태그 이름 폴더**(`engram-dashboard-v0.3.0/`)로 풀리므로 **릴리스마다 승인이 다시 뜨고, 그때까지 터미널 codex 가 아예 안 뜬다.**

### ★답 = `tui.status_line = ["thread-id"]`★ (실측 · codex-cli 0.155.1)

- **전체 36자 UUID** 가 화면에 찍힌다. **스폰 0.3초 뒤 · 턴 전 · rollout 파일이 생기기도 전**.
- **락 파일 이름과 전체 일치** 확인 — 진짜 재개용 id 다(4회 교차검증).
- 60칸으로 좁혀도 36자 온전.
- ★**설정값이라 명령 문자열이 없다 → 해시할 게 없다 → 신뢰 게이트가 안 걸린다.**★
- ★**`-c` 인자로 넘기면 디스크에 한 글자도 안 쓴다**★ — ADR-0210 의 「사용자 홈에 한 글자도 쓰지 않는다」를 **안 깬다.**

**대가 셋(전부 실측):** ① 화면 텍스트라 **모양으로 찾아야** 한다(구분자 없음) ② ★**딱 한 번만 나온다**★ — 주기 재출력 없음. 스폰 직후부터 읽고 있어야 한다(우리는 PTY 를 소유하니 해당 없음) ③ `thread-id` 를 **혼자 둔 상태로만** 쟀다 — 다른 항목과 같이 두거나 더 좁히면 줄바꿈으로 깨질 수 있다(미측정).

**★함정 — 잘못된 항목 이름은 오류가 아니라 조용히 무시된다★.** `thread-name` 은 그럴듯한데 **무효**다. 유효: `thread-id`(`session-id` 는 레거시 별칭) · `thread`/`thread-title`. **확인법 = `codex doctor -c 'tui.status_line=["thread-id"]' --json`** 이 파싱 결과를 돌려준다.

**터미널 제목(`tui.terminal_title`)은 쓰지 않는다** — 같은 항목을 넣을 수 있고 ★**깨끗한 OSC 이스케이프**(ESC ] 0 ; 값 BEL)로 와서 파싱은 더 쉽지만 **32자로 잘린다**(29자 + 말줄임, 뒤 7 hex 손실). 잘림은 **화면 너비와 무관하게 고정**이라, 29자 접두로 `$CODEX_HOME/thread-writer-locks/*.lock` 파일명을 찾아 전체 id 를 복원하는 우회는 가능하다 — 다만 메커니즘이 둘로 늘어난다.

### 버린 대안 둘 (둘 다 **된다**는 것은 실측 — 안 쓰기로 한 이유가 다르다)

- **orca 방식(훅 신뢰를 codex 자신의 RPC 로 부여)** — ★**끝까지 돈다**★: `hooks/list` 가 codex **자신의 `currentHash`** 를 돌려주고, 그 값을 `config/batchWrite` 로 `hooks.state."<키>".trusted_hash` 에 쓰면 `trustStatus` 가 `trusted` 로 바뀌고 **새 프로세스에서도 유지되며 훅이 깨끗이 발화한다**(대조군인 미신뢰 훅은 조용히 스킵됐다). **게이트 전무** — 인증·능력 플래그·확인 절차 아무것도 없고 `auth.json` 이 없는 홈에서도 됐다.
  ★**그런데 신뢰 키가 위치 기반이라 못 쓴다**★ — 키 = `<sourcePath>:<snake_case_event>:<groupIndex>:<handlerIndex>`. **우리 훅 위에 누가 훅을 하나 끼우면 두 가지가 동시에 일어난다**: 우리 훅은 자리가 밀려 `untrusted` 가 되어 **안 돌고**, ★**우리가 써 둔 해시가 그 사람의 심사도 안 거친 훅에 가서 `modified` 로 붙는다**★. 우리가 남을 승인해 준 꼴이 된다. 게다가 **사람이 한 적 없는 승인을 우리가 기록하는 것**이라는 성격도 그대로다.
- **herdr 방식(고정 경로 래퍼 스크립트)** — codex 홈에 스크립트를 깔고 **그 고정 경로**를 훅 명령으로 등록하고, 자기 exe 경로는 **환경변수**로 런타임에 넘긴다. codex 의 해시는 **훅 정의**를 덮지 **스크립트 내용**을 안 덮으므로 업그레이드해도 신뢰가 산다 — **평생 한 번 승인.** 안 쓰는 이유 = 사용자 홈에 파일을 깐다(ADR-0210 결정 1).

## ★실측으로 확정된 것 — 다시 재지 말 것★

**정본 = `docs/research/codex-instruction-injection-2026-09-20.md`**(방법·수치 전부). 아래는 그 문서에 **없는** 것만.

### 지시서 채널 (요약 — 상세는 위 조사 문서)

`model_instructions_file` = 경로를 받고 **시스템 프롬프트 칸**에 꽂히지만 **전체 대체**(기본 프롬프트 17,174자를 우리가 떠서 앞에 붙여야 한다 — 그 방법은 미측정). `developer_instructions` = 문자열이지만 **덧붙임**이고 codex 자기 블록보다 앞. ★**OpenAI 레퍼런스가 둘을 「동등」이라 적고 모델 규정 사다리에서도 둘 다 Developer 층**★ — 권한 이득이 0 이라 덧붙임을 골랐다(사용자 결정).

**실 지시서 1,331자 · 명령줄 전체 1,686/8,191** — 8KB 벽이 지금은 안 문다. 코드 주석의 「프라이밍은 8KB 넘는 마크다운」은 **틀린 수치**였고 이번에 고쳤다.

### 폴더 신뢰 (오늘 사용자가 직접 확인)

**폴더당 한 번이고 `config.toml` 에 영구 저장된다** — `[projects.'<경로>'] trust_level = "trusted"`. ★**상속 안 된다**★ — 부모가 신뢰돼 있어도 하위 폴더에서 다시 묻는다(실측). 우리 작업 폴더 대부분은 `i:\` 가 통째로 신뢰돼 있어 이미 뚫려 있다.

★**모달 문구가 중요하다**★ — "Trusting the directory allows **project-local config, hooks, and exec policies to load**" · "higher risk of **prompt injection**". 신뢰는 「여기서 일해도 된다」가 아니라 **그 폴더의 훅·실행 정책을 읽어 들이게 하는 것**이다.

### 릴리스 폴더 이름

CI 가 **조립 폴더 이름과 zip 이름에 태그를 박는다**(`.github/workflows/ci.yml` 의 릴리스 잡). 조립 폴더에 버전이 붙은 사유는 **co-location**(exe 3개 + `prompts/` 가 한 폴더에 떨어져야 한다 — ADR-0100)이고, **그 사유는 「폴더가 하나 있을 것」만 요구하지 버전을 요구하지 않는다.** 폴더 이름을 고정으로 바꾸면 훅 경로가 안 바뀐다(대가 = 여러 버전 나란히 두던 사람은 덮인다). **status_line 방식을 쓰면 이 축 자체가 무의미해진다.**

## do-not (이 세션에서 실제로 겪은 것만)

1. ★**스크래치 폴더 이름으로 `codexhome` 을 쓰지 말 것**★ — codex Claude Code 플러그인 companion 이 그 이름을 자기 `CODEX_HOME` 으로 쓰며 `config.toml` 을 덮어쓴다. 실제로 그 충돌로 프로브 한 턴이 실 `api.openai.com` 으로 나갔다(401, 페이로드 미전송).
2. **`cmd` 에서 `set RUST_LOG=debug && …` 금지** — 뒤에 **공백이 붙어** 필터가 거부하고 조용히 `warn` 으로 떨어진다. 따옴표로 감싼 형태를 쓴다.
3. **Bash heredoc 이 홑 역슬래시를 먹는다** — JS 정규식과 Windows 경로가 조용히 깨진다. Write 툴이나 python heredoc 을 쓴다. ★**긴 한국어 본문 + 작은따옴표가 섞인 heredoc 은 아예 깨진다**★(이 핸드오프를 쓸 때 실제로 터졌다 — Write 툴로 갈아탔다).
4. **codex 훅 설정의 이벤트 이름이 세 가지 표기로 갈린다** — config TOML 은 `SessionStart`(Pascal) · wire `eventName` 은 `sessionStart` · 신뢰 키 조각은 `session_start`. **config 에 camelCase 를 쓰면 빈 훅 목록이 오고 경고도 오류도 없다.**
5. **`config/batchWrite` 의 `keyPath` 안 따옴표 구간은 TOML basic string 이라 역슬래시를 두 번 써야 한다** — 안 그러면 ★`status:"ok"` 를 돌려주고 아무것도 안 한다★. 성공 응답을 성공 증거로 쓰지 말고 `hooks/list` 로 되읽을 것.
6. ★**모르는 `-c` 키는 거절이 아니라 조용히 무시된다**★ — 키 존재 확인은 **`--strict-config`** 를 붙여야 한다. 지난 세션의 「`*_instructions_file` 없음」 판정이 이것 때문에 방법이 달랐다.
7. **ADR 인용을 코드 주석에서 베끼지 말 것** — 「ADR-0092 가 경로만 허용한다」로 적었는데 그 ADR 엔 **오히려 「데몬이 읽어 넣음」**이라 적혀 있었다. **도장을 엉뚱한 ADR 에 찍었다**(실제로 좁히는 것은 **ADR-0099 결정 4**). 리뷰어가 잡았다.
8. **`rg -l | xargs sed` 은 Windows 경로에서 깨진다** — 역슬래시가 먹혀 경로가 붙어 버린다. 파일 목록을 손으로 쓰거나 슬래시로 변환할 것.
9. **`cargo test`에 `-- --test-threads=4` 유지 · `--lib`·`--all-targets` 금지 · 루트 bare `cargo test` 금지 · 앱을 셸에서 직접 띄우지 말 것.**
