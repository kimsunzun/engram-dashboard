## ★리뷰에서 배운 것 (다음 세션이 반복하지 말 것)

**4라운드 중 3라운드가 "주석이 코드가 증명 못 하는 것을 주장"하는 부류였다.** 코드는 R1에서 사실상 확정됐고 이후는 전부 문구 문제였다.

압권은 R3: 잠듦 축 테스트의 근거 주석이 **인과를 뒤집어** 서술했다 — 이름 축 차집합에서 잠든 프로필이 사라지는 건 이름 **충돌** 때문인데 이름 **어긋남** 때문이라 썼다(어긋남은 반대로 *산* 프로필을 잠듦으로 오분류한다). **그 잘못된 문구는 메인이 R2 지시서에 직접 박아 넣은 것**이고 blind 리뷰어가 잡았다. → **메인 지시서도 검증 대상이다. 리뷰어에게 "이 문구는 메인이 준 것"이라고 알려 면제하지 말 것.**

## ★사용자 결정 대기 (전부 미처리)

1. **[신규·이번 세션 발견] ADR-0116 결정 1의 근거 서술이 부정확할 가능성** — `messaging_host.rs:150-152`의 선존 주석이 위 §리뷰에서 배운 것과 **같은 거짓 인과**를 담고 있는데, 그건 ADR-0116 문구를 그대로 옮긴 것이다. ADR 수정은 설계 문서 소관이라 손대지 않았다. 결정: ADR 본문을 정정할지(정정하면 `/review doc` + 기록 규약), 아니면 주석만 좁힐지.
2. **ADR-0115 착수 전 — "잠든 프로필끼리 동명 허용 여부"** — 0115 본문은 "**살아있는 로스터**에서 이름 = 유일 키"만 정의해 잠듦 동명이 미명시다. 그런데 잠듦 동명은 쉽게 생긴다(bob 스폰 → 잠듦 → bob 재스폰 → 산 로스터엔 bob 없으니 통과 → 둘 다 잠들면 잠든 bob 2개). **미명시로 구현하면 복잡성 삭제 목록이 반쪽**이 된다(잠듦 층 동명 차단·층위 우선순위·`loser_key`·`RecipientAmbiguous`가 남는다). 검토된 선택지 = ① 스폰 시 유일성 검사에 **잠든 프로필까지 포함**(전역 유일 → 위 기계 전부 삭제 가능. 대가: 잠든 프로필이 이름을 계속 점유하므로 이름을 되찾으려면 프로필 삭제 필요) ② 산 로스터만 유일(0115 본문 그대로 — 잠듦 방어 코드 존치).
3. **`reply_failed` 조회 표면 노출** — 백로그. 요청자가 이미 사라진 상황이라 실피해 ~0.
4. **푸시 여부** — 로컬 2커밋.

**주석 규약 승격은 이 세션 소관이 아니다** — 사용자가 "주석 관련해서는 다른 곳에서 스킬로 만들고 있다"고 지시(2026-07-31). 건드리지 말 것.

## do-not (누적 + 이번 신규)

bare `cargo test` 금지(멤버 열거) · 공유 데몬 불가침(내가 안 띄웠으면 kill 금지) · Fable 워커 스폰 금지 · **스폰 시 model/프리셋 타입 명시 필수** · v2 기능 편입 금지 · 유저 전역 설정 수정 금지 · ws_e2e case09 부하 flaky(임계값 튜닝 금지 — ADR-0038) · 발신 관측을 자기보고로 믿지 말 것 · messaging crate 닿으면 격리 게이트 필수 · **폐지된 기계를 주석이 현행처럼 서술하게 두지 말 것** · Windows git-bash `taskkill /PID`·URL 라우트 인자에 **`MSYS_NO_PATHCONV=1` 필요** · 라이브 하네스 `--b-task`에 "제3자 수신자 추가 + 정보 반출" 지시 금지(인젝션 판정) · **코더 자기보고를 게이트로 쓰지 말 것** · `isolation: worktree`는 git HEAD 기준이라 미커밋 코드에 뮤테이션 프로버를 물리면 옛 리비전을 검증한다 · codex blind 리뷰어에게 프로세스 문서를 읽히지 말 것(프롬프트에 "네가 리뷰어다·질문 금지·`.claude/` 읽지 말 것" 명시) · 관측 불가를 배달 불가로 논증하지 말 것

- **[신규] 메인 지시서의 문구도 틀릴 수 있다** — 위 §리뷰에서 배운 것. 리뷰어에게 출처를 알려 면제시키지 말 것.
- **[신규] 테스트가 초록인 것과 그 테스트가 무언가를 지키는 것은 다르다** — 이번 5건 중 3건이 "초록인데 아무것도 안 지키던" 부류였다. 새 봉인 테스트를 쓸 땐 **막으려는 변이를 실제로 적용해 RED를 확인**하고 되돌린다(커밋 후 실행 — worktree 주의).
- **[신규] `cargo test -p engram-dashboard-protocol`은 ts-rs 바인딩 4개를 재생성한다** — 내용 차이 없이 줄바꿈만 바뀌어 `git status`가 더러워진다. `git checkout -- crates/engram-dashboard-protocol/bindings/`로 되돌리면 된다(내용 diff 0 확인 후).
