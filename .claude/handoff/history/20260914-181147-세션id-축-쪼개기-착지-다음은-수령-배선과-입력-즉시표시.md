> 같은 세션의 두 번째 save 다. 첫 판(`20260914-175303-…`)에 **ADR-0198 이 빠져 있었다** — 그 뒤에 박았다. 이 판이 최신이다.

## 먼저 읽을 것

1. ★**사용자가 보고 길이를 두 번 지적했다 — 짧게 쓴다.**★ 결론만, 물으면 그때 편다. 그리고 ★**코드에 있는 이름을 그대로 쓴다**★ — 한국어로 새 낱말을 지어 부르지 말 것(「통로」·「축」 같은 것을 지어 썼다가 지적받았다).
2. ★**`docs/reference/backend-capabilities.md` 가 새로 생겼다 — 기능을 붙이기 전에 그 표의 해당 줄을 먼저 채운다**★(사용자 지시). 벤더 사실을 그때그때 찾고 버리지 말고 거기 적립한다.
3. **1차는 끝났고 2차는 시작 안 했다.** 지금 상태로 resume 은 **아직 동작하지 않는다** — 그게 정상이다.

## 할 일 둘 — 순서는 사용자와 정하지 않았다

### A. resume 2차 (수령 배선)

codex thread id 를 프로필에 저장하는 배선. 오늘 `backend/codex/mod.rs` 가 sid sink 자리에 `None` 을 넘겨서 id 가 메모리에만 있다. 포트는 이미 뚫려 있다.

**함께 하는 것:** `observe_session_id` 에 화신 가드 추가(지금 없다 — codex 가 그 길로 들어오는 순간 죽은 화신이 산 화신 값을 덮을 수 있다. 공유 함수라 claude 회귀망도 함께 돌린다).

**그다음 3차:** `thread/resume` 실제 호출 + 거절 시 새 스레드 폴백. ★**`can_resume_stored_session(codex app-server)` 를 `false` → `is_app_server(command)` 로 뒤집는 것과 `capabilities().session.resume` 을 켜는 것이 그 커밋의 일이다 — 둘 중 하나만 먼저 켜지 말 것**★(먼저 켜면 복원이 새 thread 를 열고도 `Resumed` 로 보고한다). 그 조건은 코드 주석 세 곳에 적어 뒀다.

### B. ADR-0198 — codex 입력을 화면에 즉시 띄우기 (이번 세션에 결정만 박음, 구현 0)

**결정:** codex 도 입력을 보낼 때 화면용 합성 에코를 내고, 되울린 `userMessage` 항목과 **`clientUserMessageId` ↔ `clientId`** 로 합친다. claude 와 같은 모양이다.

- 그 필드는 codex 0.140.0 부터 있고 우리는 0.154.0 이다. ★**공개 문서에도, 우리가 손으로 적은 `backend/codex/protocol.rs` 에도 없다**★ — 그래서 「합칠 키가 없다」가 오래 사실처럼 통했다. **우리 타입에 필드를 더하는 것이 구현의 첫 걸음이다.**
- ★**큐 해제 판정(ADR-0193)은 건드리지 않는다**★ — 이 에코는 화면용이고 화면용으로만 쓴다. 이걸 「턴이 돈다」의 근거로 읽는 코드가 생기면 회귀다.
- ★**그 id 는 상관 키이지 멱등 키가 아니다**★ — 같은 id 로 두 번 보내면 모델에 두 번 갈 수 있는데 화면엔 한 줄로 합쳐진다. 재전송 판정에 쓰지 말 것.
- **되울린 항목은 두 번 온다**(`item/started`·`item/completed`) — 합치는 자리가 그 중복도 함께 흡수해야 한다.
- 표시 문구는 **우리 로컬 사본**을 남긴다(codex 가 내용을 정규화한다).

**A 와 B 는 파일이 겹친다**(`backend/codex/mod.rs` · `protocol.rs`). 병렬로 쪼개지 말 것 — 한 명에게 묶거나 순차로.

**그 뒤 순서(사용자 지정):** 우편 스위치 → json 프론트 첫 화면.

## 2차 착수 전에 알아야 할 사실 (조사로 확정)

정본은 `docs/reference/backend-capabilities.md` — 여기 요약만 둔다.

- **thread id 는 UUID 다.** codex 타입이 `uuid::Uuid` 를 감싸고 서버가 비-UUID 를 거부한다. **저장 칸 `Option<Uuid>` 를 문자열로 넓힐 필요 없다**(한때 넓혀야 하나 걱정했는데 해소).
- **`thread/resume`**: 모르는 id → 에러(조용히 새 대화 안 염) · cwd 달라도 이어짐 · 시간 만료 없음. ★단 `-32600` 은 「모르는 스레드」 전용 코드가 아니다 — 설정 오류도 같은 코드다★.
- **`thread/list` 가 있다** — 이미 대화가 오간 스레드는 목록에서 주워올 수 있다.
- ★**그런데 크래시 창은 그걸로 못 메운다**★ — **첫 사용자 메시지 전에는 rollout 자체가 없어** 목록에도 안 잡힌다(벤더 0.154.0 테스트가 단언). 적대 리뷰가 수집자 다수 의견을 뒤집은 항목이다. **해법 설계 없음** — 후보는 보내기 전에 우리 쪽에 먼저 적는 내구 기록.

## do-not

1. ★**사용자에게 갈림을 올리기 전에 이미 닫힌 결정인지 확인**★ — 결정은 ADR 만이 아니라 `docs/process/S21-codex-backend/trd-phase2a.md` §10 결정 대장에도 산다. ★**그 대장은 항목마다 「주인」을 적는다 — 주인이 「메인」이면 사용자에게 묻지 말고 내가 정한다**★(이번에 §10-16 이 그랬다).
2. ★**벤더 사실을 우리가 손으로 적은 타입으로 판단하지 말 것**★ — `protocol.rs` 는 우리 모델이지 벤더 스펙이 아니다. `codex app-server generate-json-schema` 로 **우리가 쓰는 버전의 스펙**을 뽑는다. **이 실수를 이번 세션에 실제로 했다**(ADR-0198 맥락 참조).
3. **파일이 안 겹쳐도 의미가 겹치면 병렬로 쪼개지 말 것.** 지시서에 계약 문장이 들어가면 병렬 금지 신호.
4. `interrupted` 를 실패로 분류하지 말 것(allowlist 로 잡는다) · `PROTOCOL_VERSION` 은 안 올린다(닫힌 결정).
5. **앱을 셸에서 직접 띄우지 말 것** · **루트 bare `cargo test` 금지** · 워크스페이스 회귀에 `-- --test-threads=4` 빼지 말 것.
6. **CI 가 build/test 게이트의 정본이다** — 로컬에서 같은 것을 선행 반복하지 않는다(사용자 결정). 게이트 성립 = CI 초록.

## 미룬 것 (이번 세션 밖)

- **1차 리뷰에서 나왔으나 범위 밖으로 남긴 것 셋:** `resume ||` 단락이 새 술어를 우회한다(`connection_core.rs`) · `upsert_preserving_hierarchy` 가 세션 필드를 스냅샷으로 덮는다(무게이트 쓰기 경로) · `mail_eligibility_samples()` 이름이 낡았다.
- **`backend_contract.rs` 의 모드별 칸** — 리뷰어 둘이 「걷어라 vs 두어라」로 갈렸고 메인이 **현행 유지**로 정했다. ★3차에서 codex 행이 실제로 갈리면 그때 재판정★ — 값을 하면 그 칸을 `Declared` 안으로 들이고 구조체 전체를 모드별로 바꾼다(예외 칸 하나로 계속 두지 않는다).
- **두 술어의 `command` 인자를 읽는 impl 이 아직 0개다** — 3차와 우편 스위치가 읽는다. 단순성 렌즈가 "시그니처는 지금 깔 값어치가 있다"로 판정했다(자유 함수는 원래도 command 를 받아서 실비용이 거의 0).
- **ADR lint error 8건이 전부 `missing-number`(0170·0177~0183)** — 그 번호들이 **master 에만 있고 이 브랜치엔 없어서** 난다. 결함이 아니고, master 를 브랜치로 되머지하면 사라진다.
- 트리·라벨에서 두 모드 구별 안 됨 · codex 슬롯 빈 화면 라벨이 「Claude Code」 · 버전 불일치 팝업 미구현.
- **Phase 2b 전체**(resume 수신 · 우편 · 승인 UI) · **Phase 3**(claude 스키마 전면 회수 · capability 프론트 독자 0).
