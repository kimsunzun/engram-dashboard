## 무엇을 고쳤나 (세 층)

### 층 1 — 거절당한 구독이 슬롯을 영영 붙잡는다

데몬이 재시작하면 명부가 비어 있어 재구독이 거절되는데, 그 거절이 셸에서 조용히 버려지고 재생 슬롯이 좀비로 남았다. 슬롯 키가 **에이전트 단위**라 그 에이전트가 **모든 창·모든 슬롯에서** 영구 두절됐다.

→ `AgentEvent::SubscribeFailed { agent_id, reason }` + `ReplayFlightSet::on_refused`로 해제. 안전 근거 = **거절된 구독엔 뒤따를 Ack/Complete가 없다**(코드로 확인 — `subscribe_from`의 유일한 `Err`가 구조적으로 `on_ready` 이전).

### 층 2 — 화신 신원(★설계 전환★)

에이전트마다 붙는 `epoch`이 **순서 카운터 + 디스크 저장**이었고, "이 프로세스에서 떠본 적 있나" 표식이 저장 제외라 **데몬 재시작 후 첫 spawn이 번호를 안 올렸다.** 복원된 에이전트가 옛 번호를 그대로 달고 나오고, 데몬보다 오래 사는 앱은 "같은 화신"으로 읽어 옛 진도를 유지 → 0부터 매겨진 새 출력을 전부 버렸다.

→ **화신마다 새로 뽑는 난수 `u32`, 저장 안 함, 비교는 같냐/다르냐.** 데몬이 새로 뜨면 구조적으로 달라진다. wire 폭·필드명은 그대로(폭 4바이트 = 프레임 헤더 `[tag1][id16][epoch4][seq8]`).

- ★**이름은 안 바꿨다**★ — `epoch`이라는 이름이 남아 있지만 의미는 "순서 없는 화신 표딱지"다. **기계적 rename은 별도 라운드로 예정**(동작 변경과 섞이면 리뷰 불가라 분리).
- 부산물: `had_session` 필드 제거, `agents.json`에서 `epoch` 제거(옛 파일은 읽고 무시).

### 층 3 — 구독을 언제 거나 + 화면을 언제 지우나

- **구독 트리거를 "소켓이 붙었다" → "그 에이전트가 명부에 있다"로 교체.** 명부에 없으면 요청 자체를 안 보낸다 → **거절이 구조적으로 안 난다.** 마운트·재연결이 같은 규칙을 탄다.
  - 세 갈래: 명부에 **있다** → 구독 / 명부에 **없다** → 대기(막+아이콘) / 명부를 **모른다** → 종전대로 쏜다(부팅·새로고침·명부 조회 실패가 여기).
- **화면 지우기를 요청 시점 → 재생 도착 시점으로.** 별도 콜백(`onReset`)이 재생 flush 직전에 부른다. **실패하면 안 부르므로 화면이 남는다.**
- **표시 통일:** 세 슬롯 모두 반투명 막 + 전원 아이콘 하나, **문구 없음**(사용자 결정 — 필요해지면 나중에 문구 추가).

## ★리뷰가 잡은 BLOCK과 그 해소★ (다음 세션이 되돌리지 말 것)

**BLOCK 사유:** 화면을 지우는 자리가 **두 군데**였다. 새로 만든 "재생 도착 때 지우기"보다 **기존 재마운트 경로가 항상 먼저 터졌다** — 슬롯 재구독 조건이 `[슬롯, 에이전트, 화신]`이었고 화신 값을 **프로필에서** 읽었는데, 층 2가 그 값을 저장에서 뺐다. 그래서 데몬 재시작 → 값이 0으로 → 슬롯 재마운트 → **재생 요청 전에 화면 삭제**. 데몬 보관분도 이미 없어 대화가 복구 불가. 게다가 그 재마운트가 구독을 갈아치워서 **새 리셋 경로가 production에서 한 번도 안 탔다**(테스트에서만 손으로 불러 초록).

**해소:** 재마운트 조건에서 화신 값을 뺐다(`[슬롯, 에이전트]`). 지우는 자리가 하나만 남는다. 대신 **명부 관찰이 이미 붙어 있는 뷰의 화신 변화도 처리**하게 했다(안 그러면 재spawn이 열린 슬롯에 안 닿는다).

**실측:** 옛 상태로 되돌리니 신규 테스트 4개 중 3개 빨강(`expected '' to be 'run-one output'` — 재연결 시 화면 소실). 복구 후 초록.

## ★실패한 접근 / do-not★

1. ★**무조건 초기화 안(폐기)**★ — "재연결이면 언제나 화면 지우고 진도 되돌리기". **사용자 기각.** 잠깐 끊겼다 붙는 경우까지 지워서 스크롤백이 데몬 보관분(2MB/4096조각)까지로 잘린다. **되살리지 말 것.**
2. ★**"사라진 적 있나" 추론 안(폐기)**★ — 명부에서 사라졌다 나타났는지를 클라이언트가 기억해 새 세션을 추정하던 것. **사용자 기각 — 데몬이 말해줘야 할 것을 클라이언트가 추측하는 모양.** 화신 신원이 그 자리를 대신한다.
3. **화신 신원을 프로세스 id로 하지 말 것** — PID는 재사용되고(재사용 = 신원 아님), 출력 번호를 매기는 주체(출력 코어)와 1:1이 아니며, 프로세스가 없는 구간(기동 중·정리 중)에도 신원이 필요하다.
4. **guid(16바이트)로 넓히지 말 것** — 프레임 헤더 29→41바이트. 조각이 잘게 오는 스트림이라 그대로 비용이다. 비교 상대가 직전 값 하나뿐이라 4바이트로 충분(충돌 40억분의 1).
5. **프로토콜 버전은 안 올린다**(사용자 결정). 리뷰가 "새 변종을 더했으니 올려야 한다"고 지적했으나 기각됐다. 재론 금지.
6. **설계 확정 전에 코더를 돌리지 말 것 — 이번 세션 최대 낭비.** 방향이 세 번 바뀌며(무조건 초기화 → 명부 기준 → 화신 신원) 앞 두 라운드 산출물이 상당 부분 버려졌다. 규약 순서(선택지 → 사용자 결정 → 설계 확정 → 구현)를 지켰으면 안 났을 비용이다.
7. **한 코더에게 리뷰 findings를 한 봉투로 넘기지 말 것** — 27분·35만 토큰·도구 129회가 나왔다. **"동작을 바꾸는 것"과 "정리"를 갈라** 별도 라운드로.
8. **`git checkout`/`restore`/`stash` 금지** — 워킹트리에 복구 불가능한 미커밋 작업이 있다. 한 라운드에서 실제로 파일을 날렸다가 백업으로 되살린 사고가 있었다.

## ★스킬 개선 — 적립 대기(사용자: 작업 끝나고 진행)★

세션이 끝나면 사라지므로 여기 남긴다. 반영처는 `implement`/`review` 스킬의 `feedback.md`.

1. **`implement` 지시서 골격에 컨텍스트 예산 항목이 없다.** 역할·목표·제약·주석·TDD·자기검토·반환형식·금지 여덟인데 컨텍스트가 빠져 있다. 그래서 코더가 34만 토큰까지 달려도 아무도 안 멈춘다. 이번에 "절반 넘으면 한 단위만 마무리하고 승계 요청" 한 줄을 손으로 넣었다.
2. **리뷰 findings를 심각도로 안 가르고 한 봉투로 넘기면 한 라운드가 비대해진다**(27분·35만 토큰·129 도구호출). "동작 변경"과 "정리"를 갈라 별도 라운드로.
3. **파일 소유로 잘라 병렬 스폰이 실제로 됐다** — Rust·프론트 동시, 슬롯은 계약이 겹쳐 순차. 겹치는 계약은 메인이 먼저 못박아 양쪽 지시서에 넣으면 병렬 가능.
4. **"fail-before 실측 보고" 요구가 시간의 상당분을 먹는다**(테스트를 2~3회 돌린다. 워크스페이스 회귀 1회가 2분). 값어치는 확인됐다(엉뚱한 이유로 통과하던 테스트를 잡아냈다) — 다만 **핵심 한두 개에만** 걸어야 한다.
5. **리뷰 강도 규칙이 위험 종류만 보고 델타 크기·비용은 안 본다.** deep(3인)을 정한 뒤 델타가 계속 커지는 동안 한 번도 재검토하지 않았다. 그리고 **리뷰어 결과를 메인이 압축하지 않고 사용자에게 거의 그대로 옮겼다** — 사용자가 "리뷰가 과도하다"고 지적한 실체가 이것.
6. **`handoff` 스킬 관측 2건은 이미 적립 완료**(`handoff/feedback.md`) — 훅 오분류 4회차, save 중 서브에이전트 착지로 문서가 즉시 거짓이 되는 것.

## 정지 조건
