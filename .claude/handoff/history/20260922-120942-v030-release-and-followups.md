## 1) 경로 정규화 — ★사용자 결정 완료, 조사부터★

**증상(사용자 실측):** `I:\Engram\...` 같은 역슬래시 경로나 따옴표로 감싼 경로를 `--cwd` 로 넘기면 **적은 그대로 저장**돼 존재하지 않는 폴더가 되고 첫 스폰이 실패한다.

**지금 상태 = 문서로 회피 중이다.** `prompts/agent-priming.md` 에 「슬래시로, 따옴표 없이」 한 줄이 들어가 있다. 사용자가 그것을 보고 「내부에서 컨버팅하면 되지 않냐」고 했고, **코드로 옮기는 것으로 결정됐다.** 코드가 고쳐지면 **그 프라이밍 줄은 지운다.**

**조사 시작점:**
- 이 저장소엔 이미 `dunce`(cwd canonicalize UNC 회피)가 의존성에 있다 — 즉 **정규화 기능이 없는 게 아니라 입구 하나가 그 단계를 건너뛴다.**
- cwd 입구 후보: CLI `engram agent new --cwd` · 명령버스 `agent.new` · 프론트 프로필 생성(`createClaudeProfile`/`createCodexProfile`) · `agent.spawnInto`
- ★**정규화를 입구마다 부르지 말 것**★ — 새 입구가 생기면 또 빠진다. **프로필에 저장되기 직전 한 층**으로 모은다.

★**기전은 아직 미확인이다**★ — 프라이밍을 쓴 워커가 「저장 경로 정규화 코드까지 추적하지 않았다」고 스스로 보고했다. 그리고 **메인이 CDP 로 겪은 같은 현상(`I:\...` → `I:Engram_Workspace...`)은 자바스크립트 이스케이프 문제였을 가능성이 크다** — 앱 결함의 증거로는 **사용자 보고가 사실상 유일**하니 거기서 출발한다.

## 2) 프라이밍 한글화 — ★초안 있음 · 사용자 지시 2건 미반영★

**초안 위치:** `.claude/handoff/attachments/20260922-agent-priming-ko-draft.md`(3,131바이트). 스크래치패드 원본은 사라지므로 **이것이 정본**이다.

**초안 실측:** 금지문자 5종(`'` `"` `%` `\` 제어문자) 전부 **0개** · UTF-16 **1,678단위**(영문판 2,601 → **줄었다**. 한도 8,191).

**사용자가 지시한 수정 2건(초안에 아직 안 들어감):**

- **① `engram help` 를 「시작 의례」가 아니라 「아래 명령들로 들어가는 입구」로 재배치.** 사용자 말: 「아래 명령들을 수행할 때 engram help 를 실행한다고 되어야지. 나중에는 카테고리가 될 거지만」. 합의된 문구:
  > 아래는 있는 줄 모르면 못 하는 것들이다. 이 중 하나가 필요해지면 `engram help` 부터 실행한다(Bash) — 지금 무엇이 있는지 거기서 보고, 옆에 적힌 명령으로 좁힌다.
  (기존 두 줄 「먼저 이것부터 실행한다」 + 「필요해지면 옆의 명령을 쓴다」를 이 한 줄로 합친다)
- **② 경로 줄은 1번 코드 수정 뒤 삭제 검토.**

★**적용 전 반드시 실측할 것 — 한글이 터미널 모드 명령줄을 온전히 지나는가**★. 터미널 모드는 프라이밍을 `-c developer_instructions='…'` 로 **Windows 명령줄에 실어** 보낸다. JSON 모드는 본문이라 안전하다. 이 저장소엔 한글·백슬래시가 명령줄 경유에서 깨진 전례가 기록돼 있다. 깨지면 갈림길 = JSON 은 한글 · 터미널은 영문으로 가르기(그러려면 프라이밍 seam 이 백엔드별 분기를 지원하게 손봐야 한다 — 아래 「seam 한계」).

★**금지문자 5종은 언어와 무관하게 절대 조건이다**★ — 하나만 들어가도 **문서 전체가 조용히 버려지고** 스폰은 정상으로 보인다. 신호는 데몬 로그 warn 한 줄뿐이고 **이 저장소에 그것을 잡는 게이트가 없다**(과거 사용자 결정으로 안 넣기로 함).

**seam 한계(백엔드별 프라이밍을 하려면):** trait 메서드가 인자를 하나도 안 받는다(`crates/engram-dashboard-daemon/src/control/priming.rs:228` `fn priming_file(&self) -> Option<PathBuf>`). 백엔드별로 가르려면 **trait 시그니처 + 구현 3개 + 호출부**를 함께 고쳐야 한다. 그 파일 헤더의 「구현만 갈아끼우면 된다」는 서술은 **오늘 기준 과하다.**

## 3) codex 회신 실측 — ★릴리즈에 미검증으로 나갔다★

**무엇을 재나:** 오케스트레이터가 claude·codex 를 띄우고 각자에게 퀴즈를 낸다. **claude 는 `eg_send` 로 회신했고 codex 는 채팅에 답하고 턴을 끝냈다**(사용자 실측). 프라이밍에 강제 문장을 박았으니 이제 codex 도 회신하는지 본다.

**전달은 문제가 아니다(실측 완료):** 프라이밍은 codex 두 모드 모두에 **온전히 닿는다.** 이번 라운드 로그에서 **프라이밍 미주입 경고 0건**도 확인했다. 원인은 문장이 약했던 것이고 ADR-0215 「영향」이 그 갭을 「claude 는 그 문장으로 올바르게 행동하지만 codex 도 그런지는 미검」으로 이미 자백해 뒀다 — 이번에 미검이 결론났다.

★**CLI 는 에이전트 밖에서 못 돈다**★ — `ENGRAM_TOKEN` 이 없으면 `NO_TOKEN` 으로 거절한다. 그래서 메인이 밖에서 우편을 못 보낸다. 재려면 에이전트를 하나 띄워 그 안에서 시키거나, 사용자가 직접 돌려야 한다.

## 4) resume 깜빡임 — ★두 번 시도 후 되돌렸다. 되살리지 말 것★

**증상:** rich 모드에서 **codex** 세션을 이어받으면 마스코트+제품명이 수백 ms 떴다가 대화로 바뀐다. claude 는 안 그런다.

**기전:** 빈 화면 판정의 `replayDone` 은 「우리 링을 다 보냈다」이지 「백엔드가 할 말을 다 했다」가 아니다. claude 이력은 자식 spawn **전에** 링에 seed 되지만(seed-before-publish), codex 는 그 문이 없어 `thread/resume` → `thread/items/list` 왕복 뒤에 온다. 그 사이 데몬은 빈 링을 다 보냈다고 `ReplayComplete` 를 즉시 낸다. ADR-0204 가 이미 알고 고른 대가다.

★**실패한 접근 둘 — 다시 시도하지 말 것**★:
1. **`backend_session_id != null` 을 반응형으로 읽기** → claude 는 Fresh 스폰에서 id 를 **즉시 발급**하므로 갓 만든 claude 가 안내 화면을 잃는다. codex 한정으로 좁혀도, **codex 는 스폰 몇 초 뒤 id 를 관측해 채우므로** 새 codex 도 잃는다(화면 실측: 새 codex splash=false · 새 claude splash=true).
2. **부착 시점 스냅샷(ref 래치)** → **경합에 진다.** 스폰 직후엔 프로필이 스토어에 없어 래치가 안 닫히고, 프로필이 도착할 때쯤엔 codex 가 이미 id 를 채워 놔 「이어받기」로 굳는다. 화면 실측에서 같은 자리에서 또 실패했다.

**정답 방향:** 프론트가 쥔 신호로는 「갓 띄운 것」과 「이어받는 것」을 못 가른다. **데몬이 아는 사실(이 스폰이 Resume 이었나 Fresh 였나)을 프론트에 알려 주는 것**이 맞다 — 와이어 신호 + ADR 이 붙는 별건.

**되돌린 커밋:** `32a76c9` → `bdcf086`(revert). 양쪽 다 master 에 있다.

## 5) 릴리즈 경로에 push 단위 게이트가 없다 ★다음 릴리즈에 또 물 자리★

이번에 릴리즈가 **두 번 실패**했다. 원인은 `src-tauri/build.rs` 가 `OUT_DIR` 의 `.lib`/`.a` 를 정확히 하나로 특정하는데, **release 프로필에는 후보가 둘**이었다 — `resource.lib` + `msvcrt.lib`(tauri-build 2.6.3 `static_vcruntime` 이 쓰는 82바이트 하드코딩 조각, `.drectve` 섹션만 있음).

**고쳤다**(`f9e4ec9`): 이름이 아니라 **리소스를 담았는지**로 거른다. ★판별자가 `.rsrc` 가 아닌 이유 = `resource.lib` 은 COFF 도 아카이브도 아니라 **Win32 `.res` 파일**이라 그 문자열이 한 번도 안 나온다★ — `.rsrc` 로 걸렀다면 진짜 리소스가 탈락해 「0개」 panic 으로 다시 멈췄을 것이다. `.res` 널 헤더 매직이 주경로, `.rsrc` 는 gnu 용 둘째 갈래.

★**그런데 이 경로는 `v*` 태그일 때만 돈다**(`ci.yml:898`)★ — 평시 push CI 는 debug 라 `STATIC_VCRUNTIME` 조건을 안 만든다. **즉 이번 수정에도 회귀 게이트가 없고, 같은 부류가 다음 릴리즈에서 또 태그 시점에야 드러난다.** 게이트를 세우는 것이 이번 라운드 후보다.

**gnu 타깃은 미검증** — 산출물이 없어 못 쟀다. 거기서 「0개」가 나오면 `.rsrc` 갈래를 넓힐 자리이지 내용 검사를 걷어낼 자리가 아니다(주석에 박아 뒀다).

## do-not (이 세션에서 실제로 겪은 것만)

1. ★**resume 깜빡임을 프론트 신호로 고치려 하지 말 것**★ — 두 접근이 화면 실측에서 각각 실패했다(위 4번에 상세).
2. ★**`call` 을 명령 체인에 쓰지 말 것**★ — `run-detached.ps1` 은 **첫 토큰만** 보고 `call` 을 붙인다. `npx tsc && npm test` 처럼 배치 명령 둘을 체인으로 넘기면 **뒤엣것이 맨몸으로 불려 마커가 사라진다**(실제로 밟았다). 배치 명령은 **하나씩 따로** 돌린다.
3. ★**`%` 가 든 명령은 래퍼에 넘기지 말 것**★ — `call` 유무와 무관하게 먹힌다. 이번 `call` 수정이 안 고친 축이다.
4. **`rg` 로 시작하는 게이트 줄은 감싸지 말 것** — 래퍼 안 cmd 문맥에 `rg` 가 PATH 에 없다(`__EXIT=9009`).
