## ★다음 세션이 반드시 알아야 할 것★

### 1. ADR 채번은 다른 브랜치를 못 본다 — 병합 전에 손으로 확인하라

`/adr new`는 **현재 브랜치 트리만** 스캔해 max+1을 준다. 이번에 그것 때문에 master가 이미 쓴 0140과 충돌했고, **파일명이 달라 git이 충돌로 잡지 않아** 하마터면 서로 다른 ADR-0140 둘이 공존할 뻔했다. 앵커 7개가 어느 쪽을 가리키는지 알 수 없게 된다.

**병합 전 확인 명령:** `git ls-tree --name-only master docs/decisions/` 로 master 쪽 최대 번호를 보고 내 번호와 겹치는지 본다. 겹치면 이쪽이 양보한다(먼저 병합된 쪽이 이긴다). 재채번 비용 = 파일 rename + H1 + 코드 앵커 전부 + 양방향 링크 + 상태줄 도장 + 인덱스 + step-log + tracking + 게이트 재실행.

**추적 목록 번호(T-NN)도 같은 문제가 있다.** 이번에 master의 T-27과 겹쳐 T-28~T-31로 밀었다.

### 2. 이 결함의 정체 — 쪼개는 기준이 실제 배달 대상이 아니다

호스트는 **도어벨에 실린 AgentId**로 배달을 분할한다. 그런데 실제 주입 대상은 **항목별로 `drain_queue` 안에서** 해석된다(`hinted_id` 우선 → 이름 유일 도달). 그래서 서로 다른 두 이름 큐가 한 세션으로 수렴할 수 있다 — 트리거는 **산 에이전트 개명 + 그 빈 이름을 다른 에이전트가 인계**. 겹치면 두 번째 본문이 첫 CR 앞에 닿아 봉투 둘이 한 턴으로 합쳐 제출된다.

**호스트 분할은 처리량용이고 정합성을 보장하지 않는다** — 그 진술은 `run_flush_lane`의 **함수 doc**에 있다(모듈 헤더가 아니다). 정합성은 커널의 `in_flight_targets` 축이 진다.

### 3. 우편함은 이름 키, 편지는 id 꼬리표 — 둘 다 필요하다

큐 키 = 수신자 **이름**(발신자가 아는 주소). 편지마다 **`hinted_id`**(보낼 당시 그 이름이 가리킨 세션). 배달 시 꼬리표 우선, 없거나 죽었으면 이름으로 재해석.

**id로 재키하자는 안은 사용자 결정으로 미뤘다(T-29). 폐기가 아니다.** 이름 키가 공짜로 해주는 두 구제를 명시 장치로 대체해야 한다: ① 아직 없는 상대에게 보낼 때 id가 없어 키를 만들 재료가 없다 ② 재시작로 id가 바뀔 때 옛 큐를 새 id로 이관해야 한다.

## ★실측 절차 (다음에 그대로 쓸 것)★

1. **파킹은 "없는 이름"으로 안 된다.** `absent_disposition`이 park하는 조건은 **그 이름의 저장된 프로필이 정확히 1개 + 산 세션 0**이다. 아무것도 없으면 `RECIPIENT_NOT_FOUND` 실패 행이다. 그래서 **프로필을 먼저 만들고(dormant) → 발송(park) → 스폰(도어벨)** 순서로 돌린다
2. 같은 cwd에 프로필 여럿이면 `RenameProfile`로 display_name을 박아야 한다 — 안 하면 동명 다수로 `RECIPIENT_AMBIGUOUS`
3. **앱이 띄운 데몬에는 `RUST_LOG`가 안 닿는다**(WMI spawn이라 부모 env 미상속) → 타이밍 증거가 안 남는다. 데몬을 직접 detach 기동하고 `-EnvVars 'RUST_LOG=debug','ENGRAM_DATA_DIR=<scratch>\data'`로 넘긴다(데이터 폴더 격리 = repo `.engram-data` 보호, 단일 인스턴스는 데이터 폴더 단위라 남의 데몬과 안 부딪힌다)
4. `engram.exe mail send`는 단독으로 못 쓴다(신원이 데몬 주입 토큰) — **JSON 에이전트 stdin에 지시해 자기 도구로 보내게 하는 것이 유일한 실경로**
5. StreamJson 수신자의 실제 턴 내용은 스냅샷 링에 안 들어간다(`GetSnapshot` → chunks 0) — 데몬측 `delivered` 영수증까지만 확인 가능

## 실패한 접근 (do-not)

- **제출 write를 예약(defer)하지 말 것** — 조사가 찾은 선례(Herdr·AWS Labs CAO, 300ms 예약)가 이 형태지만 두 가지가 깨진다: ① `submit_input_observed`의 Err 계약 → 무손실 재파킹이 성립 안 하고 미제출 봉투가 "배달됨"으로 정산된다 ② 같은 수신자 본문 병합을 **막지 못한다**(예약은 그걸 만드는 쪽이다). 근거 = ADR-0142 거부한 대안
- **`SUBMIT_PACING`을 낮추지 말 것** — 300ms는 상주 데몬형 선례값이고 근거가 코드에 없다. 우리 실측값 500ms이고 상수 doc이 "줄이면 재발"을 경고한다. **head-of-line이 사라져 줄일 동기 자체가 없다**
- **이름 축 in-flight 회계를 좁히거나 id로 갈아끼우지 말 것** — cap 분모가 거기 얹혀 있어 순서 보장과 유입 통제가 함께 깨진다. 대상 축은 **추가** 배제다
- **`gated`를 좁히려 하지 말 것** — 사유 우선순위 맨 끝 갈래라 그 자리에서 참이다. 미구현이 아니라 결정(ADR-0142 결정 3)
- **억제 완화를 되돌리지 말 것** — "남의 타깃 주입 실패 + 내 몫 게이트"에서 도어벨을 누르는 것은 수용된 동작이다. 넓은 억제로 되돌리면 남의 타깃 결말이 내 편지의 깨우기를 막는 결함이 함께 돌아온다(코드 주석에 명시)
- **`git merge -F -`는 안 된다**(표준입력 미지원) — 메시지를 파일로 써서 `-F <파일>`로 넘긴다. `git commit -F -`는 된다
