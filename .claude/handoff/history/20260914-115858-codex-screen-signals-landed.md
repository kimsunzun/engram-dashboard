## do-not

1. ★**사용자에게 갈림을 올리기 전에 그것이 이미 닫힌 결정인지 확인할 것**★ — 이 세션이 그러다 BLOCK 을 맞았다. 결정은 ADR 만이 아니라 **단계 문서의 결정 대장**(`docs/process/S21-codex-backend/trd-phase2a.md` §10-A)에도 산다. `implement` §0 컨텍스트 준비가 ADR 만 짚어서 샜다.
2. ★**파일이 안 겹쳐도 의미가 겹치면 병렬로 쪼개지 말 것**★ — 백엔드/프론트를 파일 무교차로 갈라 병렬로 돌렸는데, 한쪽이 「오류는 턴을 끝내지 않는다」로 바꾸자 다른 쪽의 「오류만 내고 끝내는」 경로가 즉시 깨져 BLOCK 이 났다. **지시서에 계약 문장이 들어가면 병렬 금지 신호다.**
3. ★**`interrupted` 를 실패로 분류하지 말 것**★ — claude 가 denylist 로 짰다가 사용자 Esc 중단을 오류로 둔갑시켜 되돌린 전례가 있다. 실패는 allowlist 로 잡는다.
4. ★**`PROTOCOL_VERSION` 은 안 올린다**★(사용자 결정 2026-09-14 — 확인이지 번복 아님, 새 ADR 없음). 양방향 분석은 `protocol/src/messages.rs` 의 그 변형 doc 에 있다.
5. **codex 자식에 `RUST_LOG=debug` 가 상속돼 데몬 로그를 덮는다** — `grep -vE "agent_stderr"` 를 먼저 물린다.
6. **앱을 셸에서 직접 띄우지 말 것** · **루트 bare `cargo test` 금지** · `-- --test-threads=4` 빼지 말 것.

## 구조 조사 결과 (이어서 이야기 중이던 주제)

- ★**펌프라는 타입이 없다**★ — 리더 루프가 각 통로의 `start()` 안에 **인라인으로 세 벌 복사**돼 있다. 「PTY용 클래스 / JSON용 클래스」가 아니다. 펌프 패닉→종료사유 규칙도 세 파일에 복제.
- **진짜 seam 다섯**: `AgentBackend` · `AgentTransport` · `OutputDecoder` · `InputEncoder` · `TurnClassifier`. 나머지(`OutputSink`·`StatusSink`·세션 id 출처 등)는 구현이 하나뿐이라 사실상 고정.
- ★**축이 둘이다**★ — 갈림 표(`backend_for`)는 **백엔드 축만** 보고, 모드(Terminal/StreamJson)는 각 백엔드 폴더 안 술어가 혼자 판정한다. **우편 스위치가 모드를 못 가르는 이유가 이것.**
- **얇은 곳**: 턴 분류자 두 구현이 match arm 까지 동일 · `GeminiBackend` **도달 불가**(명령 변형도 갈림 표 항목도 없다) · `TransportShape` 는 신고값일 뿐이고 **실물과 어긋나도 잡는 게이트가 없다** · `backend_for_encoder` 는 백엔드 이름 표의 두 번째 사본.
- ★**「새 백엔드 = 열 하나」는 폴더에만 참**★ — 실제로는 5개 crate·9개 파일. 그중 `AgentCommand` 변형은 **디스크 계약이라 하위호환이 깨진다**. 새 통로 모양이면 **네 번째 펌프 루프를 또 복사**하게 된다.

**문서↔코드 어긋남 둘(이번에 안 고침):** `agent-backend.md` 의 스폰 사슬 그림에 **codex 통로가 없다**(두 갈래로만) · 소유권 분할 인용이 **실제 필드보다 좁다**(세션 6칸·코어 3칸이 인용 밖).

## ★두 백엔드의 「내 말이 뜨는 시점」이 다르다★ (사용자 관측 2026-09-14)

| | 언제 뜨나 | 기제 |
|---|---|---|
| **claude json** | **즉시** | `write_input_observed` 가 `msg_uuid` 를 하나 뽑아 **stdin user 라인과 합성 에코 양쪽에 같은 값**으로 넘긴다. `send_input` 이 `Ok` 로 돌아온 직후 `core.emit`. 나중에 claude 가 그 uuid 를 replay 로 되울리면 프론트가 **합친다**(선입력 후 결합) |
| **codex** | **왕복 후** | 합성 에코를 선언하지 않는다(`input_encoder` 가 `None` — 테스트 `neither_mode_makes_a_synthetic_input_echo` 가 부활을 막는다). codex 가 되돌려준 `item/*#userMessage` 가 도착해야 뜬다 |

**왜 이 모양인가 — 결정 둘의 곱이다.** ADR-0193 이 codex 합성 에코를 **기각**했고(codex 가 자기 것을 되울리므로 이중 표시가 되는데 둘을 합칠 공통 키가 없다 — 우리 uuid vs codex 항목 id), 결정 대장 §10-A row 2 가 **되울린 항목을 「우리가 보낸 것」으로 표시**하라고 정했다. 둘 다 사용자 결정이고 이번 세션이 그대로 구현했다.

★**미결 — 아무도 적어 두지 않았던 것**★
- **「그래서 codex 는 내 말이 늦게 뜬다」가 어디에도 기록돼 있지 않다.** 사용자가 화면에서 먼저 알아챘다.
- **그 지연을 화면에서 다룰지**가 열린 항목이다 — TRD §10-17(「담겼지만 아직 안 나간 것」을 표시하나)이 그 자리이고 아직 안 닫혔다.
- ★**실제 지연이 얼마인지 안 쟀다.**★ codex 가 `userMessage` 항목을 턴 초반에 바로 되울리는지, 모델이 생각을 시작한 뒤에 주는지가 미측정이다. 전자면 체감이 작고 후자면 크다 — **재 보는 것이 이 항목의 첫 걸음**이다.
- 참고: 입력이 큐에 담기기만 하고 아직 안 나간 구간도 있다(codex 는 게이트된 입력 큐를 갖는다). 그 구간과 왕복 지연이 화면에서 구별되지 않는다.
