## 지금 할 일 — 3차 BLOCK 수정 (재수정 1회차)

### 핵심 결함 — 세 렌즈가 독립으로 같은 자리를 짚었다

**거절당한 이어받기가 「이어받음 성공」으로 보고되고 `last_failure` 까지 지운다.**

사슬(추적 검증됨):
- **왕복 실패 갈래가 stdin 을 안 닫는다** — `transport.rs` 의 그 분기는 `if *while_recording` 로 **기록 실패 갈래 전용**이다. 그래서 자식·리더·라이터가 살아남고 `closed` 가 안 선다.
- pump 가 `finish` 를 못 하니 **`ReapMsg` 가 발행되지 않는다.** reaper 가 그 메시지의 단일 소비자라 **수거 경로가 0** 이다.
- `early_activation_verdict` 는 3초간 `session.status()` 만 보는데 영영 `Running` 이다.
- 진단 갈래도 막혀 있다 — ★**`CodexBackend` 가 `resume_failure_kind` 를 override 하지 않아 기본값 `None`**★ 이고, 애초에 거절은 stdout 의 JSON-RPC error 라 stderr 버퍼(`diagnostic_tail`)에 안 담긴다.
- → `EarlyVerdict::Alive` → `note_activation_result(.., None)` 이 **실패 기록을 지우고** `RestoreOutcome::Resumed` 를 낸다.

**사용자가 보는 것:** 멀쩡한 Running 에이전트가 뜨는데 입력이 전부 거절되고, 아무도 안 거두며, 원인을 찾을 단서가 지워져 있다. **ADR-0082 가 막으려던 바로 그 결말**이고 릴리스에서 도달 가능하다.

**부팅 복원이 이걸 곱한다** — 이어받기 가능한 codex 프로필 **전부가 동시에** 그 상태로 서서 각각 자식 1 + Job Object 1 + 스레드 3 을 데몬 수명 내내 붙든다. (재시도는 `spawn_agent` 의 moot 가드가 막아 에이전트당 1건으로 묶인다.)

**고치는 법 — 같은 파일에 이미 답이 있다:** 왕복 실패 갈래도 stdin 을 닫는다(ADR-0199 가 기록 실패 갈래에 쓴 그 모양). 상대가 이미 죽었으면 no-op, 살아 있으면 EOF 라 양쪽 안전하다 — ★단 그 논증을 코드에 적을 것★. 그러면 기존 인과가 수거까지 처리하고 활성화 판정도 종점을 제대로 본다.

### 함께 고칠 것

- **`manager.rs` 가 이어받을 값을 명부가 아니라 호출자 스냅샷에서 읽는다** — 방금 도착한 새 thread id 를 무시하고 옛 id 로 이어받는다. ★**이 지점이 codex 를 claude 보다 넓게 뚫어 놓는다**★: claude 는 같은 자리에서 `ensure_session_id` 로 명부를 읽어 그 쓰기를 집어 든다. **최소 수정 = 그 한 줄을 명부 읽기로.**
- ★**2차에서 「무해」로 판정했던 지각 쓰기 논증에 구멍이 있었다**★ — `register_for_spawn` 이 `epoch_for_spawn` **보다 먼저** 돌고 화신 표식을 **보존**하므로, 그 사이 구간에선 표식이 아직 옛 화신 것이라 지각 쓰기가 **거절되지 않고 통과**한다. 코더와 메인이 둘 다 놓쳤고 동시성 렌즈가 호출 순서 두 줄로 잡았다.
- **거절 테스트가 깨진 구현 위에서 초록이다** — 가짜 서버가 일부러 살아 있고, 테스트가 **종점 도달을 단언하지 않은 채** `shutdown()` 을 부른다. 종점 단언을 넣을 것.
- ★**코더의 테스트 자신이 또 다른 결함 위를 지나간다**★ — 가짜가 `resumed-<uuid>` 를 돌려주는데 그건 UUID 가 아니라 **sink 가 조용히 버린다.** 런타임은 그 문자열로 턴을 보내고 디스크엔 옛 id 가 남는다. 그 갈림을 재게 할 것.
- **`resume:true` 우회** — 저장된 id 가 없는 codex 프로필에 그게 오면 **새 스레드를 열고 「이어받음」으로 보고**한다(app-server·터미널 양쪽). claude 는 같은 조합에서 시끄럽게 실패한다. 코드가 아니라 **그 술어가 codex 에 무엇을 뜻하는지**를 적는 쪽으로.
- **낡은 주석 셋** — 헤더의 「매니저가 거둘 때까지 상주한다」(거두는 것이 없다) · 존재하지 않는 회귀망을 가리키는 주석 · resume 의 `cwd` 사유가 `backend-capabilities.md` 의 실측 행과 어긋나게 범위가 잡혀 있다(실측은 「cwd 달라도 이어진다」이고, 진짜 미검은 「우리가 보낸 cwd 가 기록된 것을 덮나」다).
- **`excludeTurns` 가 무시되면 결말이 거절과 같다** — 긴 대화 응답 줄이 4MiB 를 넘어 버려지고 핸드셰이크가 시한까지 매달린다. 코더가 그 위험은 적었는데 **결말이 같다는 것**은 안 적었다.

## 화면 복원 — 미구현이고 갈림이 열려 있다 (사용자 관심 항목)

**지금 이어받기가 성공해도 화면은 빈 채로 시작한다.** codex 는 `resume_transcript_events` 를 구현하지 않고(우리가 읽는 것 없음), `excludeTurns: true` 라 상대가 주는 것도 없다.

**claude 와 구조가 반대다:** claude 는 `--resume` 로 띄우면 과거를 안 줘서 **우리가 `~/.claude/projects/<경로>/<uuid>.jsonl` 을 직접 읽는다.** codex 는 **응답에 `thread.turns` 로 담아 준다** — 원래는 읽을 필요가 없는 구조다.

**그런데 「주는 걸 그대로 받기」의 순진한 형태는 못 쓴다:** 응답이 **JSON 한 줄로 통째로** 오는데 긴 대화면 4MiB 상한을 넘어 그 줄이 버려지고, 결말이 위 교착과 같다. 게다가 상류가 전체 이력 수화를 **deprecated** 로 적어 두고 페이지 방식을 민다.

**후보 셋:**
1. **페이지 단위로 받기** — 상류가 미는 방향. 요청을 더 내고 응답을 번역하는 작업이 붙는다(`ThreadItem` 19 변형 중 우리가 판독한 건 일부).
2. ★**claude 처럼 rollout 파일을 우리가 읽기 — 사용자가 기울어 있는 쪽**★. 「유지보수 비용이 없으면 claude 와 맞추는 게 좋다」(사용자). **비용 확인이 안 됐다** — 관건은 **rollout 파일의 줄 모양이 우리 codex 디코더가 읽는 것과 같은지**다. 같으면 파일 찾기만 새로 짜면 되고, 다르면 번역기가 새 작업이다. ★파일명에 타임스탬프가 들어가 디렉터리를 훑어야 하고, `thread/revert` 가 같은 스레드에 다른 파일을 만들어서 **권위는 파일명이 아니라 `session_meta.id`**★.
3. 그대로 두기(빈 화면).

**착수 전에 1번 질문부터 답할 것:** rollout 줄 ≟ 디코더 입력.

## 미룬 것

- ★**로그에 개인정보**★ — `RUST_LOG=debug` 면 codex stderr 중계로 데몬 로그에 **사용자 이메일·계정 id 가 평문**으로 남는다. 이번 변경 탓 아님, 별건.

- **영속화 실패가 통로로 못 올라온다**(저장소가 IO 오류를 삼킨다) — 게이트 조건은 「기록 호출이 돌아왔다」.
- **`old_session_ids` 무한 증가** — claude 의 Fresh 경로도 같은 부류라 선재. 3차로 codex 가 재사용을 시작하면 증가 속도가 claude 와 같아진다.
- **서브에이전트 프리셋 개선 미착수** — 지금 프리셋은 model·effort 만 고정하고 본문이 비어 있다. **워커 규율**(서브에이전트 스폰 금지·커밋 금지·반환 형식·적대 자가점검·「중간에 멈춰도 빌드가 서게」)은 과업 무관하게 같으므로 **코더 전용 프리셋 본문에 넣을 값어치가 있다**. 프론트매터에 안 쓰는 칸도 많다(`skills` 자동 로드 · `disallowedTools` · `permissionMode` · `maxTurns`). ★`worker-senior` 가 사용자·프로젝트 양쪽에 거의 같은 내용으로 있고 어느 쪽이 이기는지 문서에 없다★ — 새로 만들면 이름을 달리 지어 그 모호함을 피할 것.

## 정지 조건
