## ★사용자 결정 4건 (이번 세션 — 다음 세션이 재론하지 말 것)★

1. **우편 채널 = capability로만.** MCP 되면 MCP, 안 되면 CLI. 스위칭·폴백 없음. **근거(사용자 발화):** 우편은 오가는 양이 많아 **토큰을 더 쓰더라도 속도가 빠른 MCP**를 택한다.
2. **잔여 위험은 감수한다.** 통제 수단은 **"가르치지 않는다"** 하나. 에이전트가 극히 낮은 확률로 우연히 바이너리를 찾아 호출하는 경우는 **그대로 둔다** — MCP 분기는 프로필이 넣은 크레덴셜·PATH를 **걷어내지도 경고하지도 않는다**. (그래서 ADR-0128 불변식이 "환경 전체"에서 **"데몬의 provisioning 행위"** 로 좁혀졌다.)
3. **제어 평면(스폰·추가·삭제 등)은 CLI + 열거 대신 발견.** 프라이밍에 기능 목록을 적지 않는다 — MCP는 툴 스키마가 스스로 드러나고 CLI는 help로 찾게 한다. 스케치 = **그룹 help**(`help agent` 식으로 묶어 MCP처럼 함수 사용법을 돌려받음). **★지금 깊게 설계하지 않는다★** — 에이전트 제어 시스템 챕터에서 어차피 다시 보고, 지금 복잡하게 얽으면 그때 추가가 더 힘들어진다.
4. **구조 변경 배제.** 타입 판별자·`ControlEndpoint` 모양 변경·fork 리팩터 전부 안 한다("처음부터 완벽할 필요 없다 — 기능 추가되면 또 리팩토링한다").

## ★미리 발견된 제약 — 제어 평면 할 때 반드시 볼 것★

**PATH는 파일 단위가 아니라 디렉토리 단위 권한이다.** `engram-send`는 데몬과 **같은 crate의 형제 바이너리**(`Cargo.toml` `[[bin]]`)라 같은 디렉토리에 나오고, 데몬은 자기 exe의 형제로 찾아 그 **부모 디렉토리를** 에이전트 PATH 맨 앞에 붙인다. → **제어 CLI도 형제로 두고 같은 방식으로 PATH를 붙이면 우편 CLI가 bare 이름으로 되살아난다.** ADR-0128에 적은 제약("제어 CLI가 우편 동사를 가지면 무너진다")**보다 강하다** — 우편 동사 없는 깨끗한 제어 CLI도 같은 디렉토리면 새어난다.

회피안 3개: ① 제어 CLI를 **다른 디렉토리**에 배치 ② bare 이름 포기하고 **절대경로 호출**(PATH 미주입 — `ENGRAM_SEND_EXE` 식 병행 배선이 이미 선례) ③ 한 바이너리 서브커맨드로 합치고 capability에 따라 우편 동사를 잠근다. (②가 가장 단순해 보인다.)

**또 하나:** 토큰·제어 URL은 **우편 전용이 아니라** 데몬 제어 평면 크레덴셜이다 — 제어 CLI도 정확히 같은 것이 필요하다. 그래서 "MCP 스폰 환경에 크레덴셜이 없어야 한다" 류의 불변식은 제어 CLI가 들어오면 성립 불가다(그게 위 결정 2의 배경).

## ★이 결정의 유일한 실효 통제 = 프라이밍★

배선 제거는 우연 발견의 표면을 줄이지만 **보장이 아니다**. 프라이밍 2파일이 상대 채널을 **이름조차 언급하지 않는 것**(실측: A파일 `send_message` 3회·`engram-send` **0회** / B파일 `engram-send` 7회·`send_message` **0회**)이 실효 통제이고, 그 배타성을 봉인한 단위테스트(`control/priming.rs:440`대 `production_priming_files_pin_taught_channels`)가 **ADR-0128의 실질 게이트**다. **그 테스트를 약화시키면 이 결정이 무력해진다.**

## 남은 작업

### 1. 실측 ⑤·⑧ — **지금 도구로는 못 돌린다(계측 코드 신규 필요)**

조사 결론(scout 실측): **메시징 경로 어디에도 경과 시간을 재는 코드가 없다.** `Instant::now()`가 나오는 곳은 전부 TTL·기한 비교용 시계 주입이다. 이름이 맞아 보이는 `saturation-pilot`은 **헛다리** — 거기서 "saturation"은 메일함이 아니라 **LLM 컨텍스트 포화**이고, 재는 시간도 실 LLM 턴 처리 시간이라 드레인 비용이 묻힌다.

**좋은 소식 = 무대는 다 있다.** 데몬 통합 테스트의 합성 수신자 seam(`crates/engram-dashboard-daemon/tests/control_send.rs`의 `obs_seam` — `insert_seam_recipient` / `insert_observed_seam_recipient`)이 **실 claude·실 PTY 없이** 진짜 발송 경로(`handle_send`)를 태운다. `@all` N명 팬아웃 정합성 테스트와 4스레드 동시 발송 soak가 이미 그걸로 돈다(정합성만 단언, 시간 미측정). 즉 **필요한 건 계측기뿐이고 결정론적으로 된다.**

**상수:** 메일함 cap **100**(메시지 레인, `messaging/src/mailbox.rs:114`) · 통지 레인 64 · 파킹 TTL 24h · 수신자 수 상한 **없음**.

- **⑤ 버스트 응답 지연** — 메일함을 0·1·10·50·99·100으로 채워두고 **발송 호출 자체의 경과 시간**을 잰다. 프로덕션 코드 무변경으로 가능. **spec이 임계값을 일부러 안 박았다** — 통과/실패가 아니라 수치가 산출물이다.
- **⑧ `@all` 수신자별 상호 지연** — **★에스컬레이션 항목★.** spec이 원하는 *"누가 누구를 얼마나 지연시키나"* 를 알려면 **드레인 루프 안에 수신자별 시각 훅**이 필요하고 그건 프로덕션 코드에 손대는 일 = "단순 최소" 지시와 충돌. **직전 세션 판단(사용자 미승인):** N을 늘리며 **전체 호출 시간만** 재는 대리 측정을 하고 *"수신자별 인과는 미측정"* 을 이유와 함께 남긴다. spec 자체가 이 항목에 *"'지연시키지 않는다'를 수용 기준으로 박지 말 것"* 이라 했으니 미측정이 거짓 단언보다 낫다. **프로덕션 훅을 넣을지는 사용자 판단.**

### 2. 데몬 lib 분리 — 사용자 지정 목표점

설계 합의·실측 수치는 **직전 인계 `20260803-175011-턴관측명단-코어승격-완주-다음은-우편실측3건.md` §데몬/에이전트 시스템 분리**에 있다(운영 빌드 11,729줄 분해, 합의된 3층 모양, 인증이 문제가 아닌 이유, ADR-0029와 충돌 아님). **그걸 먼저 읽을 것** — 여기 안 베낀다.

### 3. `--disallow-mcp` 존폐 — **사용자 결정 대기**

권한만 제거하는 노브라 실측으로 무효가 드러났고("두 채널 병존" 전제도 사라졌다), 코더 권고 = **플래그 + `ENGRAM_DISALLOW_MCP_SEND` env seam + 관련 테스트 3건을 함께 삭제**. 중간안 = env seam은 남기고 하네스 플래그만 제거. 임의 삭제 금지로 보류 중이다.

### 4. 문서 결함 1건 — 뿌리가 다른 슬라이스

`docs/reference/architecture-overview.md:344`가 *"존재하지 않는 이름도 파킹한다(ADR-0105)"* 라고 적었는데 **코드는 반대**(`없음` → `RECIPIENT_NOT_FOUND` 반려, `messaging/src/service.rs:23`)이고 ADR-0105는 애초에 **TTL 상향** 결정이라 그 주장을 한 적이 없다. 무효화 주체는 S18 발송 개편(ADR-0116 계열)이라 ADR-0127/0128과 무관. CLAUDE.md가 금지한 "맨 부재" 혼동(잠듦 ≠ 없음)을 그대로 저지르고 있다. standing 문서라 `/review doc` 경유 필요.

## 실패한 접근 (do-not)

- **★리뷰어를 공유 워킹트리에서 병렬로 돌리며 mutation을 허가하지 말 것 — 이번 세션 실발동★.** review 가드레일에 「공유 작업트리 변형 금지 — 격리 worktree에서」가 실발생 기록과 함께 박혀 있는데 어겼다. 두 리뷰어가 리뷰 중 대상 diff 해시가 4번 바뀌는 걸 감지해 동결 사본 기준으로 판정했다(다행). **교정 = mutation 렌즈는 `isolation: worktree`로 스폰.**

- **★내부 구현을 사용자 결정으로 올리지 말 것 — 이번 세션 실발동, 사용자가 두 번 지적★.** "타입 판별자 vs 테스트 추가" 같은 코드 구조 선택은 CLAUDE.md §사용자 협업 방식대로 **메인이 정하고 보고**하는 것이다. 결정 떠넘기기로 대화가 길어졌다. 사용자 결정 = **동작·정책·데이터 위치**만.
