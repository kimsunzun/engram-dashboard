### 메커니즘 요약 (상세 = ADR-0216)

codex 를 `-c tui.status_line=['thread-id']` 로 띄우면 **스폰 약 0.3초 뒤 · 턴 전**에 36자 thread id 가 TUI 상태줄에 찍힌다. 그 PTY 는 우리 것이므로 펌프가 읽은 슬라이스를 `emit` **직전**에 훑어 뽑는다. ★**설정값이라 해시할 명령 문자열이 없다 → 신뢰 승인 화면이 아예 안 뜬다**★ — 그게 이 교체의 목적이었다(훅은 우리 exe 절대경로를 해시해 릴리스마다 승인을 다시 요구했고, 누르기 전까지 터미널 codex 가 안 떴다).

**파싱 기준 = 모양 + 창.** 모양 = 8-4-4-12 소문자 16진수 + **양쪽 인접 검사**(37번째 16진수가 붙으면 거부). 창 = 스폰에 무장하고 ⓐ 회수 성공 ⓑ **PTY 첫 사용자 입력** ⓒ 1 MiB 예산 중 먼저 오는 것으로 닫힌다. 맞추기 전에 **ANSI 를 벗기고**(상태는 청크를 넘어 이어진다) **36바이트를 이어 붙인다**(읽기 단위가 4096 고정이라 id 가 쪼개진다).

★**ⓑ 를 떼면 안전 논거가 무너진다**★ — 이 채널도 결국 「첫 매치가 이긴다」이고, 그것이 무해한 것은 **창 안에 사용자·모델 내용이 구조적으로 없기 때문**이다. ADR-0216 「거부한 대안」의 재론 방어가 이 한 줄 위에 서 있다.

## do-not (이 세션에서 실제로 겪은 것만)

1. ★**빈 로그를 통과로 읽지 말 것**★ — `npx tsc --noEmit` 은 성공하면 아무것도 안 찍어서 **「안 돈 로그」와 「통과한 로그」가 둘 다 빈 파일**이다. 분리 실행 래퍼가 `.cmd` 를 `call` 없이 부르면 `__EXIT` 마커가 안 찍히는데, 그 조합이면 **false PASS 로 착지한다.** **`call` 을 붙이고 마커로 판정한다.** (`/qa` feedback 에 적립함 · 바인딩 수정은 미착수 = 미결 2)
2. ★**ADR 에 「측정했다」를 쓰기 전에 그 측정이 어디 있는지 확인할 것**★ — 이 세션에 **내가 쓴 주장 넷이 거짓**이었고 전부 리뷰가 잡았다: 「락을 하나도 안 잡는다」(값 쓰기는 전역 락 + 디스크 저장을 탄다) · 「후보 고르는 규칙이 없다」(첫 매치가 그 규칙이다) · 「재개 거동 미측정」(이미 실측돼 있었다 — 조사 §10-8) · 측정한 값과 싣는 값의 **따옴표가 달랐다**.
3. ★**폐기 범위를 「주제가 같으니 통째로」로 정하지 말 것**★ — ADR-0210 을 전체 폐기하려 했는데 그 결정 3·4 에 **우편·지시서가 이미 기대고 있었고** 확정 ADR 둘이 이름으로 가리키고 있었다. 리뷰가 잡았다.
4. **codex TUI 입력은 Enter 를 별도 write 로 보내야 제출된다** — 텍스트+`\r` 를 한 번에 쓰면 composer 에 남는다(2회 재현).
5. **합성 viewId 로 건 `subscribeOutput` 은 replay 가 안 온다** — 실 슬롯에 에이전트를 배정해야 DOM 모드가 성립한다.
6. **앱을 셸에서 직접 띄우지 말 것 · 빌드·테스트도 분리 실행** · `-- --test-threads=4` 유지 · `--lib`·`--all-targets` 금지 · 루트 bare `cargo test` 금지.

## 미결 · 사용자 결정 대기

1. ★**입력 없이 닫은 codex 프로필이 다시 안 켜진다**★ — 재개가 exit 1 로 죽고 명시적 fresh 요청도 같은 실패다(모드를 고르는 입구들이 **저장된 id 유무만** 본다). **사용자가 이미 알던 이슈이고 codex·claude 공통으로 「그냥 새 세션」 방향으로 고치기로 했다**(2026-09-21). ★**이번 변경이 만든 것은 아니나 더 자주 닿게 만들었다**★ — 훅은 첫 턴 **뒤**에 id 를 줘서 입력 없는 세션엔 id 가 아예 없었다.
2. **`/qa` 바인딩의 마커-불안정 예외 절 수정** — 지금 `npm test` 만 이름으로 적는데 **더 위험한 쪽(tsc)이 빠져 있다**. 적립만 했고 문서 수정은 미착수.
3. **실 `~/.codex` 의 세션 기록** — 지난 세션 6개 + 이번 실측분. 지울까 둘까(여전히 미답).
4. **`C:\codex-trust-test` 폴더**(지난 세션 잔여 — 삭제가 권한으로 거부됐다) · 실 `config.toml` 의 그 항목 한 줄.
5. **릴리스 조립 폴더에서 버전 빼기** — ★**이제 불필요하다**★. 그 축은 훅 승인 경로를 고정시키려던 것이었고 훅이 사라져 무의미해졌다.
6. **도움말 화면 보수** · **claude 쪽 우편 가시성** · **에스컬레이션 축 게이트 부재** — 직전 핸드오프에서 넘어온 미착수분, 그대로 남음.
7. **`prompts/` 의 초안 둘 미추적**(`REVIEW-ko.draft.md` · `agent-priming.ko.draft.md`) — 지난 세션 검토용. 커밋할지 버릴지 미정.

## 절차 관측 (적립한 것만)

- ★**이번 세션 최대 비용 = 코더 재작업 왕복**★(누적 약 38만 토큰·도구 32회 — 정식 1회 + 리뷰 반영 2회). **값은 했다** — 그 왕복이 없었으면 **기능을 존재하게 하는 단 한 줄에 테스트가 없는 채로** 착지했다(그 줄을 `None` 으로 바꿔도 795개가 전부 통과했다). 다음으로 비쌌던 것이 GUI 실측(약 22만·도구 113회)인데 그것도 값을 했다 — **벽돌 건은 실측이 아니면 안 나왔다.**
- ★**두 리뷰어가 독립으로 같은 자리를 셋 짚었다 — 그게 2인 적대의 값이다**★(무테스트 연결 지점 · 메모리 순서 · 이스케이프 누출). 그리고 **blind 가 구체 입력을 내는 데 특히 강했다** — `\x1b(B` 와 `ESC BEL` 두 케이스는 blind 만 실제 바이트열로 제시했고 둘 다 진짜였다.
- **ADR 을 먼저 박고 구현을 나중에 한 순서가 이득이었다** — 리뷰가 ADR 의 거짓 주장을 잡은 시점이 **구현 중**이라, 설계 정정이 코더에게 바로 흘러갔다(blocking 하나가 그렇게 잡혔다). 구현 뒤에 ADR 을 썼으면 그 정정이 코드에 안 닿았다.
