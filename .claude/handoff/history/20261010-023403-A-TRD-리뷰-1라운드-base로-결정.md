## 사용자 결정 · 의향 (이번 세션 · 2026-10-08~10)
- **작업 순서 = A → 패닉 정책 구현 → transport(3단계) → 셸 설계(플러그인 포함).** 「쭉쭉 진행」 — 메인이 갈림길을 정하고 보고(3단계 전까지). 세부 갈림길은 「성숙한 프로그램 관행대로 처리하면 될듯」 — 관행으로 메인이 정하고 보고.
- **A 범위**(사용자 「한번에 하는 게 좋아 보이는데 큰 부분 위주로」): ① 데이터 파일 넷(셸 설정 · 화면 상태 · 데몬 agents.json · presets.json)의 읽기 · 버전 판정 · 원자 쓰기 · 손상 사본 · 잠김 재시도를 한 벌 + 한 규칙으로 ② agent 손상 사본도 ADR-0274 규칙(고정 `.corrupt` 덮어쓰기 — 두 번째 손상 때 앞 사본이 사라지는 것 수락) ③ 데몬 mcp_config 평범한 쓰기 → 원자 쓰기 ④ 자식 프로세스 띄우기 세 벌 통일 ⑤ 셸 손 락 오염 복구 → base `sync` · saver 시계 → base `Clock`. 빼는 것 = daemon.json 읽기 · WS 재연결 · net 재시도(transport 3-3) · 락 패닉/복구 정책(패닉 정책 주제).
- **공용 자리 = base**(「나중에 쪼갤려면 base에서 쪼개야지」) — ADR-0269 지킬 것 6(serde 금지)만 개정.
- **패닉 정책 = ADR-0288 + ADR-0290**(ADR-0289 는 폐기): 요청 하나 · 에이전트 하나는 가두고, 공유 상태 패닉은 관행대로 기존 정상 종료 경로, 가두지 못한 패닉은 훅이 정상 종료를 당긴다(zellij 식), 크래시는 그냥 종료(Job 이 정리). 3 · 4 의 전용 장치(시간 제한 · 셸 사유 고지 · 복원 표시)는 나중(복원 시스템과 함께). unwind 범위(셸 포함 여부)는 구현 TRD 에서 사용자 결정. 구현은 A 뒤.
- **플러그인**(「그냥 한번 얘기한 거야 나중에」) — 메모 `docs/refactoring/architecture-discussion-2026-09-26.md` §9 에 적었다(채팅 스타일 풀 커스터마이징 · Engram Slot 추가 · 로컬 모델은 뺌). 셸 설계 때.
