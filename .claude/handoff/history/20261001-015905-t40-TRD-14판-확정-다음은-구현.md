## Final design (TRD 14판) in brief

- At the first Esc whose interrupt line is accepted: single opener takes one Job snapshot (pins pre-existing members: ppid, image, cmdline, creation time via handle) and starts recording births from Job NEW_PROCESS notifications (completion port; listener thread spawned BEFORE association; opened at once, handle pinned with TERMINATE, facts read, dedupe by (pid, create); exits ignored — user decision 6).
- At write-ack (writer thread, no locks): take one complete-or-error member list W. Candidates = recorded births alive at pass time with pid ∉ W (so they joined after the write). List failure → no pass.
- 3 s after the write, if the turn hasn't ended: kill C only if all hold: parent D is a known link and exited; hook copy (same image as D and cmdline == D's, or D's cmdline is the hook form); every link up to claude known, create-ordered (parent.create ≤ child.create — a TRD choice, NOT a user decision) and exited; chain top T is `bash.exe -c "bash …"` without `shell-snapshots`; claude spawned `taskkill /PID <T> /T /F` with create ≥ T.create. Up to 3 rounds (seq order, one shared 200 ms confirm deadline per round); a refused commit ends the pass. Anything unknown → no kill.
- Teardown: `AgentTransport::begin_retire()` (default no-op) called first in `kill_agent` and in `tear_down_failed_activation`; read-only `RetiringSignal` checked in `still_due` under the gate lock.
- Dependencies: `windows` features `Win32_System_IO`, `Wdk_System_Threading` (no new crate, Cargo.lock unchanged) — user informed; internal decision.
