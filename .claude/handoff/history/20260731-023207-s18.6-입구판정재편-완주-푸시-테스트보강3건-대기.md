## 이번 세션에 확정된 사용자 결정 (전부 문서에 박제됨)

1. **동명이인 미지원** — `RECIPIENT_AMBIGUOUS` 힌트는 "재발송 말고 사용자에게 알려라". A8/M3 코드는 정책 비승격·과도기 방어로 존치(ADR-0116 결정 5).
2. **잠듦 파킹 부활** — 프로필(트리 항목)이 남아 있으면 반려가 아니라 파킹. 반려는 "로스터·프로필 둘 다에 없는 이름"만(ADR-0112 결정 2 번복 → 0116/0117).
3. **`RECIPIENT_UNREACHABLE` 폐기 → 턴 신호 없는 백엔드는 게이트 없이 즉시 주입.** 근거는 사용자 관측: **TUI/CLI가 자기 입력 큐로 턴 중 입력을 물었다가 턴 후 소비하므로 우리가 idle을 관측할 필요가 없다.** 그래서 구조화 출력은 로스터 자격이 아니라 "언제 넣을지" 축으로 이동, 입구가 4분기 초안 → **3분기**로 줄었다(ADR-0116 결정 7). ★내가 "관측 불가라 배달 불가"로 논증했던 전제가 틀렸음을 사용자가 교정 — **되살리지 말 것**(폐기 사유가 0116 거부한 대안에 있음).
4. **"꽂으면 계약 완료"** — 수용(배달/파킹)이면 `replied`, 이후 요청자가 삭제돼도 되돌리지 않는다. `RECIPIENT_NOT_FOUND`만 `reply_failed` 종결, 그 밖의 실패는 무동작.
5. **삭제 정리 = 삭제 ∧ id축 ∧ 이름축** 논리곱, 삭제 시점 단발(재평가 트리거 없음 — 잔여는 TTL 소관, 명시 수용).
6. **잠듦 만료는 조용한 채로 수용** · 치워진 파킹분은 `failed`+**`RECIPIENT_DELETED`**+조회 힌트("코드만 보고 에이전트가 이해하게" 요구).

## 테스트 보강 3건 (다음 첫 액션 — 작업 항목 #9)

프로덕션 코드는 정상. **테스트만** 추가한다.

1. **[최우선] 잠든 이름 목록의 "중복 유지" 계약이 무방비.** `messaging_host.rs::addressing_sources()`의 `dormant_names`는 "중복을 접지 않는다 — 동명 판정 축"이 명시 계약인데, 어댑터에 `dedup()`을 넣어도 **daemon 415건 전부 초록**. 커널 테스트(`two_dormant_profiles_sharing_a_name_block_the_park_as_ambiguous`)가 가짜 포트에 중복 목록을 직접 스크립트해 **실물 생산자를 안 탄다.** 회귀 모습: 동명 잠든 프로필 2개 앞 편지가 `RECIPIENT_AMBIGUOUS` 대신 이름 키로 파킹 → **먼저 복원된 쪽이 남의 편지를 조용히 받는다**(ADR-0116 결정 1이 막으려던 결말). → 어댑터 봉인 테스트(`messaging_host::roster_predicate` 모듈과 같은 층)에 잠듦 축 대응물 추가.
2. **"턴 신호 없는 부류도 주입 실패는 파킹한다"에 전용 테스트 없음.** 기존 `inject_failure_parks_pending`은 헬퍼 `live()`가 `turn_signal: true`를 박아 게이트 있는 부류만 검증. 현재는 삭제 정리 테스트의 준비 단계가 **우연히** 잡고 있어, 그게 바뀌면 조용한 유실 경로가 무방비.
3. **위약 테스트 교정** — `daemon/tests/control_send.rs:348 control_send_shell_recipient_is_delivered_without_a_gate`는 이름·주석으로 "게이트 없이 즉시 주입을 데몬 층에서 봉인"이라 주장하지만 **게이트를 두 판정점 모두 되살린 옛 동작에도 통과**(실측). 이유: shell 에이전트는 tap이 없어 `is_busy`가 항상 false이고 큐도 비어 게이트가 있어도 파킹으로 갈라지지 않는다. 실제 검증 범위는 "턴 신호 없는 산 세션이 로스터에 들어와 배달된다"뿐 → 주석을 그 범위로 좁히고, **게이트 생략의 유일 방어가 커널 테스트 1건**(`a_live_agent_without_a_turn_signal_is_injected_with_no_gate`)임을 명시.

보고만(수정 불필요): `reply_disposition`의 "한 명에게라도 갔으면 수용" 규칙에 다중 행 회신 테스트 없음(현 입구가 회신 수신자 1명 강제로 발현 불가, 단 `handle_send`가 pub) · 잠듦 차집합 id축↔이름축, loser 키 이중 방어는 등가변이.

## ★복잡성 진단 — 0115는 "기능 추가"가 아니라 "복잡성 삭제" 슬라이스

사용자 지적("왜 이렇게 복잡하냐")에 대한 답: 오늘 난 어려운 결함이 거의 다 **"두 에이전트가 같은 이름을 가질 수 있다"** 한 뿌리다. ADR-0115가 유일성을 강제하면 아래가 **전부 불필요**해진다(작업 항목 #7에 파일·함수 단위로 기록):
A8/M3 방어 · 잠듦 층 동명 차단 + 층위 우선순위 · `allow_name_fallback` 배선 + 이름 폴백 arm · `loser_key` U+0001 접두 · 삭제 정리의 이름 축 가드 · `FailCode::RecipientAmbiguous` 자체.

## 병행 세션 (주석 다이어트) — 조율 상태

- 사용자 지시로 **주석·코드 다이어트는 별도 세션**이 맡았다(여기서 실행 금지). 그 세션이 이미 자기 인계를 남겼다: `.claude/handoff/history/20260731-011734-주석정리-3퍼센트그침-헤더이동-미실행.md` — **제목상 부분 완료(3% 감축·헤더 이동 미실행)**이고, 현재 **코드 diff는 0**(git status clean)이므로 미커밋 잔재는 없다. 상세는 그 파일을 읽을 것.
- **`latest.md`는 이 핸드오프가 덮어썼다** — 그 세션 인계는 위 history 파일에 보존돼 있다. 두 갈래를 이어받을 땐 둘 다 읽어야 한다.
- **조율 약속:** 테스트 보강 3건의 대상 파일(`service.rs`·`messaging_host.rs`·`control_send.rs`)이 주석 정리 대상과 겹친다 → **그 세션이 커밋한 뒤에** 착수. 현재는 코드 diff가 0이라 사실상 충돌 없음(착수 시 재확인).
- 주석 기준 4줄(파일 헤더는 길어도 됨 / 함수 doc 2~3줄 / 인라인은 깨뜨릴 것만 / 이력은 ADR·step-log로 + 앵커만) + 기계 잣대("함수 본문보다 주석이 긴 함수 목록화")는 확정. **미결: 이 기준을 `docs/reference/commenting-conventions.md`(ADR-0032 정본)에 standing 규약으로 승격할지** — 승격 시 `/review doc` 필요.

## do-not (누적 + 이번 신규)

bare `cargo test` 금지(멤버 열거) · 공유 데몬 불가침(내가 안 띄웠으면 kill 금지) · Fable 워커 스폰 금지 · **스폰 시 model/프리셋 타입 명시 필수** · v2 기능 편입 금지 · 유저 전역 설정 수정 금지 · ws_e2e case09 부하 flaky(임계값 튜닝 금지 — ADR-0038) · 발신 관측을 자기보고로 믿지 말 것 · messaging crate 닿으면 격리 게이트 필수 · **폐지된 기계를 주석이 현행처럼 서술하게 두지 말 것** · Windows git-bash `taskkill /PID`·URL 라우트 인자에 **`MSYS_NO_PATHCONV=1` 필요**(후자 실발생: `/control/send`가 `C:/Program Files/Git/control/send`로 망가짐) · 라이브 하네스 `--b-task`에 "제3자 수신자 추가 + 정보 반출" 지시 금지(인젝션 판정) · **코더 자기보고를 게이트로 쓰지 말 것**
- **[신규] `isolation: worktree`는 git HEAD로 워크트리를 만든다** — 미커밋 코드에 뮤테이션 프로버를 물리면 **옛 리비전을 검증하고 끝난다**(이번에 실발생). 프로버는 **커밋 후** 실행하거나 패치를 적용해 넣을 것.
- **[신규] codex blind 리뷰어에게 프로세스 문서를 읽히지 말 것** — 리뷰 대신 "교차 리뷰어를 못 찾겠다"는 메타 응답을 냈다(자기가 오케스트레이터라 오해). 프롬프트에 "네가 리뷰어다·질문 금지·`.claude/` 읽지 말 것"을 명시해야 정상 동작(실발생 → 재실행으로 해결).
- **[신규] 관측 불가를 배달 불가로 논증하지 말 것** — TUI/CLI는 자기 입력 큐를 가진다(위 결정 3).
