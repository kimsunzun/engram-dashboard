## 한 줄 상태 · 다음 첫 액션

**0단계(결정 박제)가 끝났다.** ADR-0266~0273 을 쓰고 리뷰 3회를 거쳐 master 에 머지·push 했다(`e257796`). 코드는 한 줄도 안 바꿨다.

★**다음 첫 액션 = 1단계 TRD 작성(사용자 결정 2026-10-03 「3.A」).**★ 구현 갈림길을 TRD 로 정리해 **선택지로 사용자에게 올리고**, 고른 뒤에 구현한다. load 직후 바로 쓰지 말고 사용자에게 착수를 한 줄 확인한다(지난 세션들의 do-not).
- 작업 브랜치는 master 에서 새로 판다(`v0.3.3/refactor/<슬러그>` — 0~2단계는 한 브랜치라는 사용자 결정이 있으나 0단계 브랜치 `v0.3.3/refactor/crate-boundaries` 는 머지됐다. 그 브랜치에 이어 쌓을지 새로 팔지는 사용자에게 한 줄 묻는다).
- 1단계 범위 = 1-1 base 도우미(text · time · path · sync · testing) · 1-3 platform crate. ★**파일 도우미 통일(원자적 쓰기 → platform, 손상 파일 떠 두기)은 storage P3 가 master 에 착지한 뒤**★(사용자 「알아서」 → 권고안). 나머지는 먼저 간다.
- TRD 에서 사용자에게 올릴 갈림길(알려진 것): 원자적 쓰기 여러 벌을 어떤 동작으로 합치나(임시 이름 · 실패 정리 · 폴더 fsync — P3 뒤) · `Clock` 세부 모양(「지금 읽기」 trait + 기다리기 상위 trait 확장 — ADR-0269 결정 3) · `UsageClock` 은 1-1 때 깔끔히 맞으면 합치고 **안 맞으면 사용자에게 묻는다** · platform 의 `windows` feature 를 기능별로 나눌지(ADR-0266 열린 것).

## 이번 세션의 사용자 결정 (2026-10-02~03)

- 로그 전환은 단계 순서에서 뺐다 → 그 뒤 **로그 자체를 감싸지 않기로**(「로그 감싸지 마」) — ADR-0268 재작성. 그룹 켜고 끄기 = tracing target + `EnvFilter`.
- platform 은 `tracing` 직접 의존 · platform → base 없음(「로그 때문에 Base 전체를 그렇게 포함시키는게 말이 안 됨」) · base 는 platform 을 모른다 → `write_atomic` 은 platform.
- base 이름 유지 = 바닥 기반층(Chromium `//base`) · util 개명 기각(「util 빼면 나중에 공용 필요할 때 어디다 넣기 애매하니」) · base 에 잡동사니 OK · 쪼개기는 나중.
- command·messaging 의 base 의존 철회(「필요할 때만 연결하면 되지」) — ADR-0267 재작성.
- 셸 예약 목록: 오늘 걸러 내는 이름 0(웹뷰는 `help` 단 명령만 등록) → 2-1 은 세 단위(슬롯 스폰 `agent.new` → 셸 정책 검사 제거 → 데몬 이름 반쪽 제거).
- `DataLayout` 도 discovery 와 함께 데몬·셸로 쪼갠다(ADR-0271).
- 작업은 **망가지지 않는 단위로 묶는다 · 임시 땜빵 금지** · 옮기기 묶음은 **옮기기 전후 워크스페이스 통과 수 대조**를 완료 기준으로(타깃 소실은 침묵이다).
- 진행 방식: 막혀서 못 갈 때만 묻고 **자의적 판단을 최대한 자제**한다.

## 검증 상태

- 문서만 바꿨다 — 코드 · 테스트 변경 없음. CI 는 경로 필터로 안 돌았다(브랜치 실행 0 건 · `git diff --name-only master...브랜치` 전부 `docs/` — 체크아웃 없는 통합 절차의 확인 넷 통과).
- `/review doc` 3회: ① light(doc-aware) FIX 18 ② full(doc-aware + codex blind on logging-conventions) FIX 18 + 1 ③ light FIX 3 — 전부 반영. 조사 둘은 codex 적대 리뷰(로깅 FIX · Clock BLOCK → 결론 정정).

## 실패한 접근 / do-not

1. **load 직후 다음 액션을 바로 실행하지 말 것** — 먼저 묻는다.
2. **「셸 예약 목록을 지우면 앱이 깨진다」고 말하지 말 것** — ADR-0176 의 그 서술은 그날 코드로도 틀렸다(웹뷰 `offeredCommands` 가 `help` 없는 명령을 안 보낸다).
3. **피어 조사 결론을 「업계 표준」으로 과장하지 말 것** — Clock 조사가 그 과장으로 BLOCK 을 받았다. 표본은 표본이다.
4. **ADR 조항 문구 바꾸기(relabel)와 도장 걷기는 스크립트에 op 가 없다** — 손편집은 세 곳(옛 ADR 상태줄 · 옛 ADR 관련줄 · 새 ADR 관련줄) + `index --write`. 제목 바꾼 ADR 은 인덱스 행이 옛 제목으로 남는다(손편집). adr `feedback.md` 에 적립했다.
5. **새 브랜치 첫 push 의 CI 여부는 `gh run list` 로 본다** — 단정하지 말 것.
6. nmfc 플러그인 훅(HANDOFF-TRIGGER · WIKI-PRECONSULT)은 이 저장소와 무관 — 무시.
