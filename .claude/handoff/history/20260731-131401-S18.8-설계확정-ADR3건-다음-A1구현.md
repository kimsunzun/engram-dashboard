## 확정된 결정 7건 (전부 ADR에 박제됨)

1. **이름은 트리에서 오직 하나** — 잠든 프로필 포함 **전역 유일**. 겹치면 자동 접미사 `bob(1)`. 잠든 프로필도 이름을 점유하고, 회수는 복원 또는 삭제뿐. (ADR-0120)
2. **편지 순서 보장** — 새 편지가 묵은 것을 앞지르지 않고 **오래된 순으로 함께** 나간다. 배치 도중 실패하면 거기서 멈추고 앞부분은 `delivered`, 나머지는 `pending` 유지. (ADR-0121)
3. **`@all` / `@here` 분리** — `@all` = 명부 전원(잠든 것 포함, 그쪽은 파킹) · `@here` = 산 전원. 현행이 `@here`에 해당하므로 "개명 + `@all` 신설". **둘 다 발신자 제외**(정본 = spec §4, ADR-0111 아님). (ADR-0121)
4. **장부는 `delivered` 유지** — 터미널 모드 별도 표기 안 함. 증거가 동일하기 때문. 모달 먹힘이 실측되면 재론. (ADR-0121)
5. **명부 단일 입구** — 프로필은 `AgentManager` 안으로 감추고(`manager.profiles()` 제거), "전체 에이전트 + 각자 살아있음/잠듦"을 주는 **통합 조회 하나**를 매니저가 제공. 우편·트리가 그것만 본다. (ADR-0119)
6. **에이전트 사실 계층의 거처 = 코어** — 턴 상태(ADR-0113)도 여기 얹는다. 0113이 열어둔 "코어/데몬" 갈림길 해소. (ADR-0119)
7. **프리셋은 안 건드림** — 아직 자리를 안 잡았다는 사용자 판단. 비대해지면 재검토(코드도 문서도 손대지 말 것).

**매니저 타입 분리는 실측으로 기각**(사용자가 판단 위임): `manager.rs` 1320줄 중 운영 순수 코드는 574줄이고 무거운 로직은 이미 형제 파일에 있다. 응집이 깨끗이 갈리는 선은 I/O 버킷 하나뿐인데(9개 메서드가 `sessions`만 접촉) 그걸 떼면 같은 락을 두 타입이 나눠 갖게 돼 락 감사성을 잃는다. 내부 완전 통합도 보류 — **한 클래스는 되지만 한 락은 안 된다**(프로필 맵이 락을 쥔 채 디스크에 저장하므로).

## 슬라이스 순서 · 테스트 방침

**A1**(백엔드 명부 통합 — **동작 불변**, `/qa standard`) → **A2**(명령 어휘를 에이전트로 + 프론트 단일 목록 — 화면 닿음이라 `/qa full` GUI 실측 필수) → **B**(턴 상태 코어 이사, ADR-0113) → **C**(우편 순서·`@all`/`@here`, ADR-0121).

**테스트 방침(확정):** 이동·재배선분엔 **새 테스트를 만들지 않는다** — 기존 회귀가 그대로 초록인 것이 "동작 불변"의 증거다. **새로 생기는 계약(이름 유일성 · 통합 조회)에만** 붙인다. 무거운 검증(뮤테이션·GUI)은 A2.

**A1 수용 기준:** 우편 입구와 트리가 같은 조회를 쓴다 · 바깥에서 프로필 타입을 직접 만지는 경로가 없다 · 이름 유일성이 한 곳에서 강제된다 · 기존 회귀가 **손대지 않고** 그대로 초록.

## ★A1 착수 전 반드시 알아야 할 것

**① 사문화 목록을 지금 지우면 안 된다.** ADR-0120이 6건을 제거 대상으로 지목하지만, **기존 `agents.json`이 이미 불변식을 깨고 있을 개연성이 높다** — canonical 이름은 표시명이 없으면 cwd basename에서 파생되므로 같은 폴더를 가리키는 프로필 둘은 개명 없이도 동명이다. **정규화가 끝난 뒤에만 제거한다.** 정규화 방식(로드 시 자동 접미사 vs 사용자 확인 후 개명)은 **사용자 결정 미결** — 사용자에게 보이는 이름이 바뀌므로 물어야 한다.

**② 사문화 목록 항목 3을 오독하지 말 것.** 죽는 건 `allow_name_fallback`의 **동명 가드**뿐이고 **이름 폴백 arm 자체는 운영 경로다**(잠든 수신자 계약은 실체 id가 없어 이름으로 닫는다). `ledger.rs` 주석이 "그 팔은 dead code 가 아니다"라고 이미 경고한다. 리뷰가 잡아준 것 — 그대로 뒀으면 조용히 깨졌다.

**③ 통합 조회는 원자적이지 않다.** ADR-0116이 "원자적 단일 뷰"를 락 순서 때문에 기각했고 경합 잔여분의 TTL 유계 수용은 그대로다. **"이제 통합됐으니 원자적으로 만들자"는 이미 기각된 방향.**

**④ 메시징 커널 격리는 불변**(ADR-0110) — 커널은 여전히 `AgentManager`를 모른다. 포트는 그대로고 데몬 어댑터(`messaging_host.rs`)가 얇아질 뿐이다.

## 검증 상태 (쌍으로)

- **돌린 것 — `/review doc full` 3라운드:** doc-aware(worker-senior) + cross-family. 1R **BLOCK**(3+9건) → 2R FIX(5건) → 3R FIX(1건), 전부 반영. `adr lint` clean(에러 0, advisory 5는 선존 레거시).
- **★cross-family를 blind가 아닌 사실검증 렌즈로 투입했다** — 대상이 전부 결정 문서라 blind가 성립 불가(근거를 주면 blind가 깨지는데 ADR이 곧 근거다). 그래서 "ADR이 코드에 대해 주장하는 것을 코드와 대조"시켰고, **거짓 근거 6건을 잡았다.** 이 편차는 결과 보고에 라벨했다.
- **안 된 것(정직):** ① **코드 검증은 전혀 안 했다** — 이번 세션은 문서만 바뀌었다. `cargo`/`npm` 게이트 미실행 ② 3라운드는 **단독 family**(doc-aware만) — 남은 변경이 링크·문구라 사실검증 재실행을 생략했다 ③ 손으로 고친 인덱스 3행은 **다음 `index --write` 때 되돌아간다**(아래 도구 결함).

## do-not (누적 + 이번 신규)

bare `cargo test` 금지(멤버 열거) · 공유 데몬 불가침 · Fable 워커 스폰 금지 · **스폰 시 model/프리셋 타입 명시 필수** · 유저 전역 설정 수정 금지 · ws_e2e case09 부하 flaky(임계값 튜닝 금지) · messaging crate 닿으면 격리 게이트 필수 · Windows git-bash에서 URL·경로 인자엔 **`MSYS_NO_PATHCONV=1`** · **코더 자기보고를 게이트로 쓰지 말 것** · `isolation: worktree`는 git HEAD 기준(미커밋 코드에 뮤테이션 프로버 금지) · codex 리뷰어에게 프로세스 문서를 읽히지 말 것 · **테스트가 초록인 것과 그 테스트가 무언가를 지키는 것은 다르다**(새 봉인 테스트는 막으려는 변이를 실제 적용해 RED 확인) · `cargo test -p engram-dashboard-protocol`은 ts-rs 바인딩에 줄바꿈 churn을 만든다

- **[신규] 리뷰어의 괄호 부연을 사실로 승격하기 전에 원문을 확인할 것.** 어제 "ADR-0116 문구가 부정확하다"를 미결로 들고 다녔는데 **그런 문구가 없었다.** 리뷰어의 한 줄 → 메인의 검증 없는 추측 → 사용자 보고 → ADR 조항 박제까지 갔다가 3라운드에서 걷어냈다.
- **[신규] 내가 쓴 ADR의 코드 주장도 반드시 대조시킬 것.** 이번에 6건이 거짓이었다. 결정은 사용자에게서 왔지만 **근거는 내가 지어낸 부분이 있었다.**
- **[신규] 인덱스의 다중 개정 표기를 신뢰하지 말 것** — 아래 도구 결함. **본문 상태줄**이 정본이다.
- **[신규] 병행 세션이 같은 트리에서 돈다** — 커밋 전 `git status`로 남의 변경을 스테이징하지 않았는지 확인.

## 도구 결함 (기록됨 — `~/.claude/skills/adr/feedback.md`)

**① 인덱스 합성이 개정 1건만 표시** — 단발 `.match()` + early return이라 손보존 분기에 도달조차 못 한다. 이번 `index --write`가 **ADR-0108의 0118 개정 표기를 조용히 삭제**했고(리뷰가 적출) 손으로 복구했다. 같은 원인의 **선재 오염 6행**: 0019·0066·0076·0094·0103·0107. `lint`는 인덱스를 안 봐서 못 잡는다. 0103은 상태줄 도장 자체가 없다.
