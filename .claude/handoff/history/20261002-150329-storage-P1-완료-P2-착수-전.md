## 확정된 사용자 결정 (정본 = `docs/research/storage-management-survey-2026-10-02.md` 「0. 결정」 · ADR-0264)
- 포터블 유지(릴리스 `<exe>\data\`, 개발 `<워크트리>\.engram-dev\`). 설치형/AppData 는 성숙 후 재론.
- 폴더 = 컴포넌트 먼저, 이름은 systemd·XDG 표준: `daemon\{state,run}` · `shell\{config,state}` · `webview\` · 바깥 `logs\`. 기준 = **config = 사람이 정한 선호(지우면 기본값) / state = 프로그램이 기록한 모습**(에이전트 목록·화면 배치 둘 다 state).
- **옛 데이터는 옮기지 않고 버린다**(아직 정립 전 — 사용자 결정). `ui-settings.json` 도 옮기지 않는다 → P2 `settings.json` 은 기본값부터.
- 설정 = `shell\config\settings.json`, 이름공간 키 + 범용 명령 넷(`settings.get/set/reset/schema`), 스키마 한 줄 등록. LLM 이 파일 직접 고치던 경로 폐지 → `prompts/engram-help.md` theme 구획·프라이밍 함께 수정.
- 화면 상태 = `shell\state\state.json`(Windows Terminal 관행 이름). 복원 = 항상 복원, 비정상 종료 뒤에만 묻기. 창별 테마는 state.json 의 그 창 항목. 테마는 이름 참조, 내장 셋은 CSS 유지(내장 JSON 통일은 나중).
- 기존 `presets.json` 은 옮기기만 — 새 프리셋 구조는 나중.
- 「업계 표준 우선」·「에이전트 앱이 아니라 일반 소프트웨어 관행」이 판단 기준.

## TRD 에 아직 안 들어간 결정 (P2/P3 착수 전 반영할 것)
1. **저장 범위 인벤토리**(조사 결과 — 25개 중 5개만 저장되던 것): 저장 = 팝아웃·탭·순서·활성 탭·탭 이름·분할 구조/방향/비율·슬롯 내용·포커스·창 위치/크기/최대화·**사용량 슬롯 claude/codex 체크박스**·테마(전체/창별)·챗 스타일 + **슬롯 보기 모드(터미널/챗 — `viewStore.renderModeOverride`, 프론트 메모리 → 셸 슬롯 값으로 옮겨 저장, P3 추가)**. 저장 안 함 = 도구 묶음·생각 줄·대기 목록 펼침, 스크롤 고정, 목록 선택, 입력 초안, 트레이 숨김.
2. `ui-settings.json` 은 이전하지 않는다(TRD §3-5 가 아직 「이전」을 적고 있으면 걷는다).
3. **P3 설계 쟁점(codex BLOCK)의 세션 기본값** = 크래시 스냅숏을 덮어쓰지 않고 최근 N(=3)개 돌려 보관(Firefox 방식). TRD §14-5 에 표시만 됨 — **P3 착수 전 설계 재작성 + 재리뷰 필수**.

## 실패한 접근 (do-not)
- **첫 부팅 이전(migration) 경로는 구현까지 했다가 걷었다** — 리뷰 3회 동안 대소문자 변형·FAT 이름 변경·링크·옛/새 바이너리 이중 잠금 같은 극단 사례가 끝없이 나왔다. 옛 데이터 처리 기능을 되살리지 말 것(ADR-0264 거부 대안). 걷기 전 패치 백업은 이전 세션 스크래치패드에만 있다(소실 가능 — 필요 없음).
- codex 리뷰어는 「두 잠금을 쥔 동안엔 불가능」 같은 설계 근거를 모르는 blind 슬롯이라 이론상 경합을 계속 낸다 — 재수정 상한(3회)에 닿으면 사용자에게 넘긴다.
