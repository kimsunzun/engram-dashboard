## ★이번 세션의 가장 큰 낭비 — 다음 세션이 반복하지 말 것★

**문서 파이프라인을 두 번 돌았다.** 메인이 선택지를 잘못 깔았다: 사용자가 "큐에 쌓고 한꺼번에 빼면 되지 않나"라 하자 **전부-큐(비동기 flush 레인)** 로 해석해 ADR-0124 + spec 6차 + `/review doc` 3라운드를 완주했는데, 그 뒤 사용자가 **"그 루틴에서 리턴되기 전에 큐에 있으면 다 보내고 리턴"**(= 동기 드레인)을 제시해 전부 폐기됐다.

**근본 원인:** 동기 드레인은 ADR-0124가 **「거부한 대안」에 이미 적어둔** 안이었고, 기각 사유("남의 백로그를 발신자가 치른다")가 **약했다.** 코드 착수 전이라 구현 손실은 0이지만 문서 사이클 1회분이 통째로 날아갔다.

**교훈(일반화):** 거부한 대안의 기각 사유가 약하면 **그게 정답일 수 있다.** ADR을 쓸 때 기각 사유의 강도를 스스로 채점하고, 약한 것은 사용자에게 선택지로 올릴 것. (같은 실패가 ADR-0121→0124에서도 있었다 — 0121이 정통 FIFO를 미검증 사유로 기각했고 0124가 그걸 뒤집었다. **두 번 연속이다.**)

## 확정된 계약 (정본 = ADR-0125 + spec 7차)

발송 = **큐 꼬리 적재 → 같은 호출에서 앞에서부터 드레인 → 리턴**. `port.inject` 호출 지점은 **파일 전체에 1곳**(`drain_queue`) — 동기 드레인과 비동기 flush는 같은 루틴의 두 계기다.

- **`delivered`** = 이번 호출의 드레인이 실제 주입 확인. **유일한 확정 정보.**
- **`pending`** = **"이번 호출이 배달을 확인하지 못했다"**(단일 정의). ㉮ 큐 잔류(턴 중·잠듦·주입 실패) / ㉯ 겹친 드레인에서 물러나 확인 불가 — **실제로는 배달됐을 수 있다.** "안 갔다"가 아니다.
- **`failed` 4종** = 적재 전 판정(이름 없음·동명 모호·보관함 초과·`REQUEST_CAPACITY`).
- **드레인 중복 진입 가드는 전제** — 제거하면 순서 역전(ADR-0125 §영향 하위 불변식).
