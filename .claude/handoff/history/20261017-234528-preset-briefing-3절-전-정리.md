- **정렬:** VS Code 관행 — 폴더 늘 위 · 종류 = 필터 순서(지침 · 스킬 · 설정 · 프리셋) · 같은 값 = 이름순 · 화살표는 누른 열에만 · 정렬 열 = 종류 · 이름(★ · 참조 열은 정렬 없음).
- **새로 고침:** 트리 우클릭 「새로 고침」(폴더 = 그 폴더+하위 · 루트 머리 = 전체) · F5 = 포커스 칸 기준(트리 = 선택 폴더, 없으면 전체 · 목록 = 지금 폴더, 하위 포함) · LLM = `library.refresh`.
- **단축키:** 각 OS 파일 관리자 기본값(PRD R50) · LLM 경로 없음 · 기존 키 표(`src/commands/keybindings.ts`)에 항목마다 win/mac 키 — 공용 OS 키맵 라이브러리는 없음(조사).

## 실패한 접근 (반복 금지)

- **관행 먼저 — 세션이 지은 말 · 배치를 결정처럼 말하지 않는다.** 이번에도 「3개 고름」 · 「항목을 고르면 여기 보입니다」 · 「안에 든 것 수」 · 「5개 + N개 더 보기」 를 지었다가 뒤집혔다. 사용자는 모르면 「관행 찾아봐」 한다 → 묻기 전에 조사(light)부터 · 근거 수준 표시.
- **질문을 잘못 읽지 말 것** — 「오른쪽 누를 때」 = 오른쪽 상세 칸(우클릭 아님)이었다 · 「고정 순서」 를 체크박스로 오해함. 애매하면 한 줄 확인.
- **설명을 복잡하게 하지 말 것** — 사용자가 「뭔소리야 · 되게 복잡하게 말한다」. 예시 하나로 짧게.
- 큰 일괄 편집(용어 전환 · 456k 토큰 · 98회)은 파일마다 커밋으로 쪼갰기에 살았다 — 같은 방식 유지. 워커가 한도로 죽은 적 1회(참조 묶음 반영) — 남은 diff 를 확인해 이어서 마무리.
- 브리핑 HTML: 글과 인라인 태그가 섞인 캡션은 안쪽 `<span>` 하나로 감싼다(또 깨진 곳 있었음) · 셸 인라인 `node -e` 금지 → 스크래치 스크립트 파일 + 못 찾으면 throw · 치환 규칙이 코드 칸을 넘지 않게.
