## 이 브랜치에서 할 것 (상세 = `docs/todo/terminal-cursor-ime-resize.md`)
- **① 초기 크기 가드** — `src/components/slot/TerminalSlot.tsx:304-305` 가 구독 직후 `fit()`+`resizePty` 를 가려짐 확인 없이 보낸다. 다른 세 경로는 건너뛴다: RO 콜백 `:99-101`(hidden 판정) · 비우기 콜백 `:285`(`offsetParent != null`) · 재연결 `:355`(`offsetParent === null`). WebGL 부착 `:211-213` 은 IO 가시성(`:224-227`)으로 거른다. 업계 규칙 = **잴 수 없는 크기는 보내지 않고 마지막 크기 유지**(보고서). 영향: 앱 시작 때 숨은 탭 터미널이 80×24(또는 잘못된 값)를 보내 → 탭 전환 때 한 번 다시 그림 · 같은 에이전트를 보이는 칸에서도 보고 있으면 그 칸이 깨진 채 남을 수 있음(추론 · 미재현).
  - `@xterm/addon-fit` 0.11.0 은 가려짐을 확인하지 않는다 — 부모 계산 너비 `auto` 면 NaN → `fit()` no-op, 0 이면 2×1(`node_modules/@xterm/addon-fit/src/FitAddon.ts:23-24,36,72-74,87-88`). 우리 컨테이너는 `width:100%`(`TerminalSlot.tsx:381`) — 가려진 조상 아래 실제 값은 **실측 안 했다**.
- **② 커서가 너무 두껍다** — 생성 옵션이 `fontFamily`·`fontSize`·`theme` 뿐(`TerminalSlot.tsx:78-82`)이라 xterm 기본 **블록 커서**. 후보 옵션: `cursorStyle`('block'|'underline'|'bar') · `cursorWidth`(bar 굵기 px) · `cursorBlink` · `cursorInactiveStyle`. 사용자 스크린숏 = 파란 블록이 한 칸을 꽉 채움.
  - ★사용자 설정으로 만들면 「LLM-우선 제어」(CLAUDE.md) 대상 — 새 UI 기능엔 LLM 호출 경로를 기존 표면에 얹는다. 기본값만 바꾸면 해당 없음.
- **③ 한글 조합 중 표시** — 사용자 스크린숏: 조합 중인 글자에서 블록 커서가 사라지고 글자 **위쪽에 작은 파란 선**이 뜬다. 원인 미조사. 조사 출발점: xterm.js 6 의 조합 표시(`.composition-view`·보조 textarea 위치) · 우리 CSS 가 xterm 보조 요소를 건드리는지(`src/index.css`) · 재현 = CDP `Input.imeSetComposition`(한글 조합 흉내)으로 스크린숏/DOM. 버전 = `@xterm/xterm ^6.0.0`.
