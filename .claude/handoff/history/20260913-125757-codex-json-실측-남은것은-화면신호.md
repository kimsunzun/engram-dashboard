# 핸드오프: codex JSON 은 실제로 대화한다 — 남은 것은 화면 신호 둘

## 먼저 읽을 것

1. ★**codex JSON 모드는 돈다. 「안 된다」로 읽지 말 것.**★ 턴을 두 번 왕복시켰고 맥락도 이어졌으며 답변이 챗 화면에 실제로 그려진다(아래 「실측으로 확인된 것」). **미완은 화면 신호 둘**이고 통로가 아니다 — 그걸 혼동하면 다 도는 통로를 다시 의심하며 시간을 쓴다.
2. ★**다음 첫 액션 = 턴 완료 번역**★ — 스피너가 안 멈추는 원인이고 번역기가 `turn/completed` 를 버리는 자리가 시작점이다.
3. ★**데몬은 이제 프로토콜이 갈려도 스스로 복구한다**(ADR-0196)★ — 직전 핸드오프가 요구했던 「실측 전 데몬 재빌드·수동 파일 삭제」 절차는 더 필요 없다.

## 실측으로 확인된 것 (이 경로는 처음 밟혔다)

- **핸드셰이크 완주** — `codex app-server 연결`(user_agent 전달) → `codex thread 개시`(cli 0.154.0).
- **턴 2회 왕복, 맥락 유지** — `2 더하기 3은?` → `5입니다.` · `그럼 그 답에 10을 곱하면?` → `50입니다.`
- **구조화 이벤트(tag 1)** — `TextDelta` 3개 + `Usage`(입력 17914 · 출력 7).
- **wire 되읽기** — 프로필에 `command.kind: "Codex"` · `command.output_format: "StreamJson"`.
- **답변이 DOM 에 그려진다** — 챗 슬롯은 캔버스가 아니라 진짜 DOM 이라 `innerText` 로 읽힌다. **DOM 모드 명령이 필요 없었다.**
- **kill → 명부 0** — `status_changed` 는 오지 않았고 그게 규약대로다(terminal 판정은 명부).
- **ADR-0196 이 실앱에서 통한다** — 프로토콜 4 + 죽은 pid 파일을 심고 두 번 확인(둘째는 실제로 데몬을 죽인 뒤 그 파일을 4 로 되돌린 프로덕션 모양). 연결 성공 후 새 데몬이 5 로 재기록.

## 화면에서 어설픈 것 = 미구현 (결함 아님)

- **질문이 안 보인다** — 번역기가 `item/*#userMessage` 를 버린다. 화면 전체 검색으로 0건. UI 에 사용자 메시지 행 종류는 **있다**(채울 것이 안 온다). claude json 은 이 자리를 합성 에코로 메운다(ADR-0044/0045).
- **`Wait Ns` 스피너가 안 멈춘다** — `turn/completed` 를 버린다. 66s·16s·20s 로 계속 세고 한 번 되감겼다(replay 요청과 시점이 겹쳤다 — 상관만 관측, 인과 미확인).
- **트리·라벨에서 두 모드 구별 안 됨** — 되읽기 칸은 있는데 그 값을 읽는 프론트 코드가 0줄.
- **우편 미노출** — `reads_messages` 가 두 모드 다 `false`.

### 검증 안 된 것
- ★**우리 `-32601` 거절을 codex 가 받아들이는지 미측정**★ — 이번 런에서 codex 가 미구현 *요청*을 한 번도 안 보냈다(로그 매치 0).
- **`q5_multiline_body_enters_whole` 빨강**(실 codex 계약 11개 중 1개 · `#[ignore]` · 터미널 모드 PTY). 우리 통로를 안 거친다. ★「원래 실패였나」는 여전히 미확인★. 재현 = `cargo test -p engram-dashboard-agent --test backend_contract -- --ignored --exact q5_multiline_body_enters_whole`
- **`SpawnByCwd` 갈래 회귀망 없음** — 되돌리면 codex by-cwd 가 조용히 app-server 가 되는데 전부 초록(`connection_core.rs:1024` 에 적어 뒀다).
- ★**마지막 코드 라운드는 적대 리뷰를 안 붙였다**★ — 주석·로그 문구·테스트 fake 위치만 바뀌어 메인이 델타를 직접 확인하고 넘겼다(step-log 에 라벨).
- **스피너 되감김의 인과** · **에이전트 kill 시 스피너가 풀리는지** 미측정.

## 다음 첫 액션 후보 (권장 순)

1. **턴 완료 번역** — 스피너를 푸는 유일한 길. 번역기가 `turn/completed` 를 「아는 이름인데 버린다」로 처리하는 자리.
2. **사용자 메시지 에코** — `userMessage` item 번역 또는 합성 에코(claude 선례 = ADR-0044/0045).
3. ★**데몬 정지 경로 결함**★ — `stopDaemon()` 이 `AgentCommand 파싱 실패: missing field 'force'` 로 거절된다. 클라·데몬 wire 드리프트이고 **살아 있는 경로**다. 가장 명확한 실결함.

## do-not

1. ★**데몬이 없을 때 앱은 스스로 못 띄운다**★ — `ensure` 는 attach-only(ADR-0021). 회복은 `window.__TAURI__.core.invoke('daemon_connect')` 하나뿐이고 명령 레지스트리에도 없다(`src/api/tauriTransport.ts:413`).
2. ★**입력을 보내기 전 출력 0건은 정상이다**★ — claude·codex 양쪽 다 그렇고 뷰 국면도 `buffering` 에 머문다. 결함으로 오진해 대조군·슬롯 배정까지 갔다(도구 12회 낭비).
3. **`RUST_LOG=debug` 는 codex 자식에 상속돼 데몬 로그를 덮는다** — 3960줄 중 우리 줄 24줄. `grep -vE "agent_stderr"` 를 먼저 물린다.
4. ★**`check_acceptable` 에 버전 방향 판정을 더하지 말 것**★ — 일부러 방향을 안 본다(ADR-0196 · 쌍둥이 테스트가 지킨다).
5. **게이트의 「사용자 결정」 항목을 리뷰어 어휘로 옮기지 말 것** — 눈에 보이는 동작이 어떻게 갈리나를 한 문장으로 먼저. 이 세션에 되묻기 2회를 만들었다.
6. **코드 push 뒤 CI 가 끝나기 전에 후속 커밋을 밀지 말 것.**
7. ★**ADR 채번 전 `git fetch`**★ — master 에 0177·0178·0180~0183 이 있고 **이 브랜치엔 없다**(lint 의 「빠진 번호」가 그것). 두 집합은 겹치지 않으니 머지 시 문제는 없다.

## 이 세션의 운영 관측

- ★**실측이 대상 기능이 아니라 환경을 먼저 찾았다**★ — codex 를 재려고 앱을 띄웠는데 데몬 기동 결함이 먼저 나왔다. 그게 오늘 최대 성과였다.
- **리뷰어 어휘를 직역해 올려 되묻기 2회** — 단위 번역이 오케스트레이터 몫인데 빠뜨렸다(`implement` feedback 적립).
- **CI 빨강 1회가 회귀가 아니었다** — 타이밍 테스트가 러너 부하로 30초 시한을 넘겼고 로컬 2.52초·재실행 초록으로 확정.
- **스킬 피드백 적립** — `qa` 4항목(데몬 부재 상태 · 「출력 0건」 오진 · RUST_LOG 상속 · 비용) · `implement` 1항목(게이트 결정 항목의 단위 번역).
