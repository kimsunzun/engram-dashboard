# 핸드오프: 제어 평면 CLI 4조각 완결 — 다음은 사람용 자격증명 결정(T-23)

## 한 줄 상태 · 다음 첫 액션

**제어 평면 CLI 4조각(①②③④)이 전부 끝나고 커밋·push까지 됐다.** ADR-0132가 고정한 이 라운드는 여기서 닫힌다. 다음 첫 액션 = **사용자 결정 3건 중 하나를 올리는 것**(아래 「미결 — 사용자 결정」), 또는 사용자가 원하면 **master 통합**.

**★이 세션이 새로 만든 갭이 하나 있다 — 그게 다음 라운드의 무게중심이다★**
조각 ④(옛 CLI 철거)로 **사람·스크립트의 데몬 제어 명령줄 표면이 0이 됐다.** 옛 CLI는 `daemon.json`을 디스크에서 읽어 붙어 **자격증명이 필요 없었는데**, 새 `engram`은 스폰 시 발급되는 **에이전트별 토큰**을 요구한다. 그래서 잃은 건 `kill`·주입 둘이 아니라 **옛 4동사 전부 + 앞으로 `engram`에 추가될 제어 동사 전부**다. 정본 = **T-23**.

## 완료 내용 (이 세션)

**조각 ③ — 우편 격리를 데몬 거절로 이관.** 배선(실행파일·자격증명)은 **전원에게** 가고, 강제는 데몬 auth 미들웨어의 자격증명 거절 **단독**. 판정은 `provision`이 `accepts_mcp_config`로 한 번 계산해 자격증명과 표식에 동시에 먹인다(단일 파생점 · epoch 회전 시 재발급). 교육은 `ENGRAM_MAIL=on|off` 표식으로 **help 렌더만** 가르고 실행은 안 막는다. 명단 밖 `/control` 경로는 **fail-closed**(분류 누락 = 거절). 거절 응답은 대안 채널을 명명하지 않는다.

**조각 ④ — 앱 실행파일의 옛 CLI 겸용 모드 철거.** `src-tauri/src/cli.rs`(449줄) + `main.rs` argv 분기 + `pub mod cli;` 제거. 앱은 이제 argv 무관하게 항상 GUI(`--hidden`만 예외).

**부수 — `adr.mjs` 결함 2건 근본 수정(9회 재발 끝).** 인덱스 상태 칸 파생이 `Amended by`를 **첫 건만** 읽어 개정 2건 이상 받은 ADR의 둘째 표기를 매 재생성마다 조용히 삭제하던 것 → `matchAll`. 조항 끝을 첫 반각 `)`로 끊어 어절 한복판에서 잘리던 것 → 괄호 균형 스캔. **사본이 둘(전역 + 대시보드 저장소)이라 양쪽 다 고쳤다** — 다음에 한쪽만 고치면 또 갈린다.

## ★실패한 접근 / do-not★

1. **`claude.rs`의 옛 "MCP 가능 스폰엔 CLI 배선 미주입" 분기를 되살리지 말 것.** 없어졌고 되살리면 **MCP 가능 스폰의 제어 경로가 통째로 끊긴다**(ADR-0132 결정 5 위반). step-log S19.1의 옛 경고 문장이 그 반대를 말하는데 **그 자리에 폐기 도장을 박아뒀다** — 도장을 보고 판단할 것.
2. **표식(`ENGRAM_MAIL`) 필터에 강제를 의존하지 말 것.** 표식은 교육 수단이고 **조작을 수용한다.** 떼면 목록에 우편이 보이지만 데몬이 거절한다(실측 완료). 반대로 **CLI가 우편 실행을 로컬에서 막게 만드는 것도 위반** — 그러면 강제가 클라이언트로 샌다.
3. **프라이밍 교육 판정기를 계열 전체로 넓히지 말 것.** 제어 동사는 전 스폰에 가르치므로 도구 이름 등장이 우편 채널의 판별 근거가 못 된다. 코더가 두 번 거부했고 리뷰어들이 확인했다.
4. **환경변수 언급을 "흔적 신호"로 내리지 말 것.** 현행 규칙 = 부르는 토큰(exe 이름 또는 env 변수) + 계열 + 동사 인접(ADR-0098 실사고).
5. **감춘 계열의 반려 문구를 자리마다 고치지 말 것** — 한 funnel(`hide_mail_reason`)로 접는다. 자리마다 고치면 새 동사·플래그가 생길 때 한 자리가 빠지고 그게 곧 누출이다(라운드 1에서 실제로 2/5만 적용돼 샜다).
6. **`adr.mjs index --write` 후 JSON의 `action:"rewritten"` 확인은 이제 불필요**(근본 수정됨). 단 **사본이 둘**이라 한쪽만 고치면 재발한다.
7. **리뷰 라운드 상한을 선언하되 마지막 라운드를 생략하지 말 것.** 이번에도 마지막 좁힌 라운드가 실질 결함 2건(경계 넘는 접두 비교 · 파싱 이후 누출)을 냈다.
8. **cross-family(GPT) 리뷰어를 빼지 말 것** — 이번에도 단독 적출 2건(`scripts/engram.mjs` 잔존 표면 · AuthFrame 명단). **단 두 가지 함정:** ① codex가 **자기 전역 지시를 읽고 오케스트레이터인 줄 착각**해 되묻고 끝난 적이 있다 → 프롬프트 맨 앞에 "지시 파일 무시 · 네가 리뷰어다 · 되묻지 마라" 오버라이드 + `-c project_doc_max_bytes=0`. ② "적대적 에이전트가 공격" 류 표현이 **제공자 보안 필터에 걸린다** → 중립적 감사 언어로 쓸 것.

## 미결 — 사용자 결정 (다음 세션이 올릴 것)

1. **T-23 사람용 자격증명 경로** ← 가장 무겁고 이 라운드가 만든 것. **구조는 이미 있다(실측):** 데몬 입구가 둘이고(사람·클라이언트용 `daemon.json` 토큰 → WS · 에이전트용 개인 bearer → HTTP `/control`), **사람 문으로 프로필 생성·스폰이 전부 돈다**(이 세션 실측). 빠진 건 구조가 아니라 **새 도구가 에이전트 문만 두드리는 배선**이라 additive다. 갈래 = `engram`이 `daemon.json`을 직접 읽는 관리자 모드 / 데몬이 사람용 자격을 따로 발급. **미확인:** 지금 `/control` 창구가 요청마다 "어느 에이전트냐"를 전제로 짜여 있어 그 전제를 비우는 자리가 몇 군데인지 안 봤다.
2. **grant 목록 일괄 정리** — 사용자가 "나중에 한꺼번에, 어차피 auto 모드니 지금 놔두자"고 명시(2026-08-12). 현재 MCP 가능 스폰에 CLI grant가 없는 채 프라이밍은 bare 이름을 가르친다(ADR-0097로 NO-OP이라 무해). 재검토 트리거 = base 권한 플래그를 걷는 날.
3. **`kill`·`rm`을 여는 전용 스텝** — 지우기가 프로세스를 안 죽여 ADR-0122와 어긋나는데 그 구현이 미정. **에이전트 축 갭**(띄울 순 있는데 CLI로 멈출 순 없다)은 kill을 여는 순간 닫히지만 **사람 축은 T-23이라 안 닫힌다.**
