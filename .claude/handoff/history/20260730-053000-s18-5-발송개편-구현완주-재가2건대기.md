## 재가 대기 (사용자 확인 필요 — 자율 진행 중 내가 잠정 채택한 것)
둘 다 `crates/engram-dashboard-messaging/src/service.rs` `push_recipient` 근처에 `// TODO(ratify)` 주석이 박혀 있다.
1. **A8 — 같은 수신자 키로 접힐 때 "해석된 토큰"이 이긴다.** 근거: 동명 모호 실패의 hint가 "exact agent id로 다시 보내라"고 안내하는데, 그 id를 같은 `to`에 함께 적으면(먼저 나온 모호 토큰이 흡수) 배달 0이 되던 문제. 지금은 해석 성공한 쪽을 보존(행 위치·표기는 먼저 나온 것 유지).
2. **M3 — 같은 이름의 서로 다른 실체를 함께 지목하면 뒤 토큰은 가시 실패 행(`RECIPIENT_AMBIGUOUS`).** 근거: 쌍둥이 둘을 exact-id로 지목하면 한 명이 **행도 없이 조용히 소멸**했다(spec §6 "수신자 1명당 1행" 위반). 조용한 소멸보다 보이는 실패가 낫다는 판단. 두 정책 모두 ADR-0115(스폰 이름 유일성)가 들어오면 모호 부류 자체가 소멸해 과도기 규칙이 된다.

## do-not (누적 + 신규)
bare `cargo test` 금지(멤버 열거) · 공유 데몬 불가침(내가 안 띄웠으면 kill 금지 — 이번엔 내가 띄운 것만 정리했고 종료 시 engram 프로세스 0) · Fable 워커 스폰 금지 · v2 기능 편입 금지 · 유저 전역 설정 수정 금지 · ws_e2e case09 부하 flaky(임계값 튜닝 금지) · 봉투/발신 관측을 자기보고로 믿지 말 것(census `delivered` 축이 정본) · "claude.ai MCP blocked by enterprise policy" 경고는 이 머신 상존 정책(오귀속 금지) · messaging crate 닿으면 격리 게이트 필수 · **[신규] 폐지된 기계를 주석이 현행처럼 서술하게 두지 말 것** — 이번 리뷰 최대 적출 부류였다(다음 세션이 그 근거로 수정을 되돌릴 명분을 얻는다) · **[신규] Windows git-bash에서 `taskkill /PID`는 경로 변환으로 깨진다 → `MSYS_NO_PATHCONV=1` 접두** · **[신규] 라이브 하네스 `--b-task`에 "제3자 수신자 추가 + 정보 반출" 형태 지시를 넣지 말 것** — 에이전트가 인젝션으로 판단해 거부하고 측정이 실패한다(실발생).
