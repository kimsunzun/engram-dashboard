## 검증 상태

### 돌린 것

- ★**A/B/C/D 4갈래 실측**★(같은 대상: `git diff 4e8a090~3 4e8a090 -- '*.rs'`, 988줄·5파일).

  **diff 를 건네는 것만으로는 거의 안 준다**(미캐시 84% 유지). **권고적 허용은 비용·품질 둘 다 최악.**

- 조사 3갈래 병렬 수집 + 메인 grounding.

## ★사용자 결정 대기 6건★ (직전 핸드오프에서 그대로 이월 — 근거는 모여 있다)

1. **리더 쪽 보류 — 버퍼 상한과 넘칠 때 처분.** 라이브 줄이 복원 이력보다 앞서는 것과 중간에 끼는 것은
   같은 구멍의 양면. 결정 = 상한 얼마 · 넘치면 (조용히 버림 / 화면에 오류 한 줄 / 연결 실패).
   ★중간에 끼면 프론트가 `seq <= lastSeq` 를 버려 그 뒤 이력이 화면에서 사라진다★.
2. **활성화 중 취소가 뒤에 줄 선다**(최대 ~11초). 리뷰어의 3번째 해법 유력 — **kill 프레임 하나만** 앞질러 처리.
   확인할 것 = 클라가 순서 뒤바뀐 응답을 견디나(`daemon_client_pending` 이 시사하나 미확인).
3. **프로필 락이 막혔을 때의 처분(ADR-0071 재론).** 지시했던 수정은 그 ADR 이 명시로 금지한 것이고,
   막히면 활성화 하나가 아니라 **명부 전체**가 멈춘다.
4. **멈춘 프로필이 낡은 실패 기록 때문에 「막힘」 글리프로 그려진다**(`statusGlyph.ts`).
5. **`old_session_ids` 무한 증가** — 상한 둘지.
6. **연결 미성립 실패에 전용 종류를 줄지** — 나중에 더해도 호환된다(리뷰어 확인).

## do-not (실제로 겪은 것만)

1. ★**codex 를 CLI 로 직접 쏘지 말 것**★ — 서브에이전트로 스폰한다(규약 §0). 직접 쏘면 하네스 밖이라
   뜬 것이 안 보이고 완료 알림도 없어 출력 파일을 폴링해야 한다.
2. ★**`--resume`(내부 `--last`)를 병렬 호출 뒤에 쓰지 말 것**★ — 조용히 엉뚱한 스레드를 문다(실측).
3. ★**`--json` 의 usage 를 그 턴 값으로 읽지 말 것**★ — **세션 누적값**이다. 요청별은
   `~/.codex/sessions/<날짜>/rollout-*-<UUID>.jsonl` 의 `info.last_token_usage`.
   이 오독이 「resume 이 더 비싸다」는 틀린 결론을 낳았다.
4. **codex 에 「되도록 열지 마라」 같은 권고적 제한을 주지 말 것** — 실측으로 기각(29회 열고 결함 1건,
   비용은 조인 것의 2.5배). **금지는 먹히고 권고는 안 먹힌다.**
5. **「로컬에 없다」를 「존재하지 않는다」로 굳히지 말 것** — 이 세션에서 실제로 그랬다. 스카우트에게
   네트워크 조회를 금지해 놓고 그 사실을 잊은 채 「플러그인은 없다」를 반복했다. **실재했다.**
6. **Bash heredoc 에 한글·따옴표 많은 본문을 넣지 말 것** — 두 번 깨졌다. Write/Edit 툴을 쓴다.
7. **`git checkout -- <file>` 를 작업 중 파일에 쓰지 말 것** · **통과 개수로 테스트 유실을 못 본다**
   (이름 목록 대조) · **앱을 셸에서 직접 띄우지 말 것** · **루트 bare `cargo test` 금지** ·
   워크스페이스 회귀에 `-- --test-threads=4` 유지.
