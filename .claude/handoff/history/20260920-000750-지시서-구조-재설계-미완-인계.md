## ★내가 틀린 것 — 여기서 시작한다★

### 지시서의 목적을 잘못 잡았다

내가 만든 것 = **우편 행동 규칙 모음**. 사용자가 말한 것 = ★**발견 장치**★.

> 「프라이밍은 engram에서 사용되는 거하고 engram help가 있고 **간략하게 help 목록**. 예를 들어 우편 / 에이전트 스폰. **그런 식으로 되어야 에이전트 스폰하고 싶을 때 이 문구가 발화돼서 help를 이용할 거 아냐**」

즉 지시서는 **「무엇이 가능한지」를 목록으로 보여 줘서, 필요가 생긴 순간 `engram help` 로 가게 만드는 것**이다. 계약서가 아니다. 지금 지시서를 읽은 에이전트는 **자기가 에이전트를 스폰할 수 있다는 걸 사실상 모른다**(한 문장에 묻혀 있다).

### 그리고 고쳐 주고도 또 틀렸다

사용자의 마지막 지적 셋, 전부 안 고쳐진 상태다:

1. ★**「미리 알아 둘 것」 절을 왜 아직 두느냐**★ — 빼라는 뜻인데 내가 계속 정당화했다.
2. ★**계열 목록에 빠진 게 많다**★ — 내가 **실제 명령 표면을 안 보고 셋(우편·에이전트·명령)을 적었다.** 확인하려다 사용자가 중단시켰다. **다음 세션은 실제 표면부터 세어 볼 것.**
3. ★**디테일을 빼고 훨씬 간추려라**★.

### 목록을 셀 때 쓸 실마리

`engram help` 루트가 오늘 내놓는 계열은 **`mail` · `agent` 둘 + `engram commands`**(데몬이 지금 돌릴 수 있는 명령 전부). 그런데 **명령 버스에 선언된 것과 프론트 레지스트리에 있는 것이 서로 다르다** — 백엔드 `declare_commands!` 쪽은 `agent.list`·`agent.spawn` 둘뿐인데 프론트에는 slot·tab·window·preset 계열이 잔뜩 있다. ★**어느 쪽이 에이전트에게 보이는 표면인지 확인하고 나서 목록을 적을 것.**★ 내가 그걸 안 하고 적어서 「빠졌다」는 지적을 받았다.

## ★구조 결함 — 지시서를 고쳐도 이것 없이는 안 닫힌다★

### 1. `engram help` 가 claude 에게 우편을 안 보여 준다

체인이 이렇다:

```
uses_mail && !accepts_mcp_config → mail_allowed → ENGRAM_MAIL 표식 → engram help 우편 절 노출
      (CLI 미러가 열렸나)                                            (우편을 알려야 하나)
```

**앞은 「CLI 로 보낼 수 있나」인데 뒤는 「우편이 있다고 알려야 하나」다.** 값 하나가 두 질문을 겸한다.

claude 는 **MCP 로 우편을 쓰므로 CLI 미러가 닫혀 있고**(설계상 맞다), 그래서 ★**지시서가 「`engram help` 쳐라」라고 하는데 정작 우편을 쓰는 claude 가 치면 우편이 안 나온다.**★

- 파생점 = `crates/engram-dashboard-daemon/src/control/mod.rs:184`
- 표식 주입 = `crates/engram-dashboard-agent/src/backend/mod.rs:109-115`
- 도움말 게이트 = `crates/engram-dashboard-daemon/src/bin/engram.rs` 의 `shows_mail()`
- ADR-0211 「영향」에 ★로 적어 두고 **고치지 않고 넘겼다.**

**고치는 방향** = 깃발을 둘로 가른다. 「우편이 있나(어느 경로로든)」가 도움말 노출을 정하고, 「CLI 동사를 쓸 수 있나」는 페이지 *안에서* 무엇을 보여 줄지만 정한다.

### 2. 우편 도움말이 CLI 표기로만 쓰여 있다

`engram help mail recv` 가 `engram mail send --to X --reply-to m-7f3k` 로 안내한다. **claude 는 그게 아니라 MCP 도구의 `reply_to` 를 쓴다.** 즉 보여 줘도 **틀린 것을 보여 준다.**

### 3. codex 는 지시서를 받을 수조차 없다

조건(`uses_mail && accepts_mcp_config`)에서 탈락하기도 하지만, 더 근본은 **실을 자리가 없다**는 것이다 — 경로를 받는 키는 codex 기본 프롬프트를 **대체**해 버리고 나머지 후보 키는 전부 거절(실측). **`developer_instructions` 로 내용을 인자에 직접 싣는 것이 답**이고 더하는 방식인 것까지 확인됐지만, **데몬은 경로를 주는데 codex 는 내용을 원해서** 누가 파일을 읽느냐가 갈린다(ADR-0092 가 「코어는 내용을 안 읽는다」로 박아 둔 경계).
