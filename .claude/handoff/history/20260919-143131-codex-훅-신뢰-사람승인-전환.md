## ★사용자 결정 (오늘)★

1. ★**신뢰를 자동으로 박지 않는다**★ — codex TUI 심사 프롬프트를 **사용자가 한 번 승인**한다. 성립 근거 = **심사 프롬프트는 TUI 에만 뜨고**(실측) 우리 터미널 모드가 바로 그 TUI 를 PTY 에 띄우므로 **프롬프트가 우리 화면에 실제로 뜬다**. 승인하면 codex 가 자기 `config.toml` 에 `trusted_hash` 를 직접 쓴다.
   - **버리는 것** = app-server 를 신뢰용으로 띄우는 부속 · 자체 해시 폴백 · `config.toml` 백업/롤백 · 장부·능력 캐시·쿨다운. **orca 가 그걸 다 만든 이유는 자동화를 하려 했기 때문**이고, 포기하면 전부 불필요하다.
   - **채택 근거** = orca 가 **자체 해시를 3번의 codex 릴리스에서 깨뜨린 뒤** RPC 로 갈아탔고, 그 RPC 조차 0.130 에서 깨진 이슈가 있다(TUI 승인마저 실패). **남의 사설 구현에 매달리는 코드를 안 갖는 게 장기적으로 싸다.** 사용자 개입은 사실상 평생 한 번.
2. ★**단 `hooks/list` 조회는 한다 — 쓰기만 안 한다**★. 그 호출은 `key`·`currentHash`·`trustStatus` 를 그대로 돌려주므로, 스폰 전에 한 번 물어 **`untrusted` → 「승인 필요」 · `modified` → 「훅이 바뀌어 재승인 필요」** 를 화면에 띄운다. ★**이 구조의 유일한 진짜 함정이 「조용한 실패」였고 이 조회가 그것을 없앤다.**★
3. **훅 명령 = 고정 래퍼 경로.** 제안 위치 `%USERPROFILE%\.engram\agent-hooks\codex-hook.cmd` — ★**사용자가 「다른 위치 원하면 말하라」에 답하지 않았다.** 착수 전에 한 줄 확인하거나, 이 위치로 가고 보고하라★(홈 밑에 우리 폴더를 만드는 것이 사용자가 체감하는 유일한 부분).
4. **참조 구현 목록 갱신 완료**(제거 2 · 추가 5 · 라이선스 정정 1 + 축 합의 둘). 정본 = `CLAUDE.md` 「참조 구현」.
5. **써볼 것 둘** = t3code(릴리즈 살아 있음) · vibe-kanban(★커밋은 살아 있는데 **마지막 릴리즈가 2026-04-24**★ — 설치본은 5개월 묵은 것). 둘 다 `I:\Engram_Workspace\opensource\` 에 클론했다.

## 2단계 — 5스텝 (순서 강제)

★**옛 4스텝에서 「신뢰 부여」가 빠지고 「상태 표시」가 들어왔다.**★

1. **고정 래퍼 설치 + 엔드포인트 파일 + `SessionStart` 하나 등록** — 래퍼는 **한 개의 스폰 가능한 토큰**이어야 한다(아래 근거). 휘발값(포트·토큰)은 엔드포인트 파일에 두고 훅이 **매번 다시 읽는다**.
2. ★**훅 CLI 의 stdin 순서 뒤집기**★ — 지금 `engram hook session-start` 는 stdin 을 먼저 읽는다. **Windows 에서 호출자가 stdin 을 닫지 않고 버리면 read-to-EOF 가 영원히 매달리고 훅 이벤트마다 창이 하나씩 남는다.** env 확인을 먼저.
3. **심사 화면을 「막힘」으로 인식해 띄우기 + `hooks/list` 조회 상태 배지** — 신뢰 부여 대신 들어온 것.
4. **판정 술어 둘을 쌍으로 전환** — `can_resume_stored_session` + `capabilities().session.resume`. ★반드시 쌍으로★(경고가 `crates/engram-dashboard-agent/src/backend/codex/mod.rs:169-171` 및 쌍 `:381-383` 에 박혀 있다).
5. **`codex resume <id>` 배선.**

## 진행 중이던 측정 (결과가 없으면 여기부터)

홈을 사본으로 떠서 `CODEX_HOME` 을 거기로 돌리고 재는 중이었다. ★**사용자의 실제 `C:\Users\kimsunzun\.codex` 는 절대 건드리지 않는다**★ — 사본이 필요한 이유는 `auth.json` 이 따라와야 턴이 돌기 때문이다(빈 홈은 401).

- **Q1 — 승인 직후 *그 세션*에서 훅이 도나, 다음 세션부터인가.** 다음 세션부터라면 **첫 대화는 이어받기 불가**이고 UI 가 그것을 말해야 한다.
- **Q2 — 취소/무시하면 다음에 또 뜨나.** 어휘가 `trusted`/`untrusted`/`modified`/`managed` 넷이고 **거부 전용 상태가 없어서** `untrusted` 로 남아 또 뜰 것으로 본다(추정, 미측정).
- ★**Q3 — 심사 화면의 「끄기」가 영구 저장되나**★. **이게 가장 무섭다** — 저장되면 훅이 영영 안 돌고 오류도 로그도 없다. 저장된다면 **무엇을 쓰고 `hooks/list` 에 무엇으로 보이는지**를 반드시 확보하라(감지해서 띄워야 한다).
- 덤으로 나오면 좋은 것: 프롬프트가 훅 단위인가 세션 단위인가 홈 단위인가 · **화면 문구 원문**(정규식으로 잡아야 한다).
- TUI 라 실 콘솔이 필요하다. 워크스페이스에 `portable-pty` 가 이미 있으니 스크래치에 작은 하네스를 만들어 몰면 된다. 훅은 **실행 인자 형태**로 등록해 파일을 안 쓴다.

## 피어에서 가져올 것 (전부 클론 코드로 확인 — 2026-09-19)

**orca** (`I:\Engram_Workspace\opensource\orca`)
- ★**훅 스크립트를 사용자 홈 아래 고정 경로에 두고 업그레이드 때 *내용만* 갈아 끼운다**★ — 신뢰 해시가 **명령 문자열**을 덮지 파일 바이트를 안 덮어서 업그레이드가 공짜다. 위치를 per-install 폴더로 두지 않은 이유도 적혀 있다(여러 인스턴스가 같은 항목을 써야 한다).
- ★**Windows 에서는 한 개의 스폰 가능한 토큰이어야 한다**★ — codex 가 훅을 `cmd.exe` 경유가 아니라 **argv[0] 로 직접 스폰**한다.
- **엔드포인트 파일 재읽기** — 포트·토큰을 파일에 두고 훅이 매 호출마다 다시 읽어, **데몬이 재시작해도 살아남은 PTY 가 계속 보고한다.** 우리 portfile 이 이미 그 모양이다.
- **페이로드는 stdin 으로 넘긴다**(명령줄 아님) — 수십 KB 도구 출력이 명령줄에 실리면 보안 에이전트 오탐을 부른다.
- **resume 을 못 믿으면 인자를 떼고 새 세션으로 띄운 뒤 전용 배너를 띄운다** — 「복원됨」 배너를 재사용하지 않는다(그건 옛 대화가 돌아왔다고 거짓말한다).
- **파일 폴백은 파일명이 *아는 id* 로 끝나는지로 정확 매칭**하고 홈 우선순위를 결정적으로 못 박는다. ★mtime 정렬이 없다★.

**herdr** (`…\herdr`) — **우리가 고른 그 형태의 실물이다**
- `SessionStart` **하나만** 등록하고 stdin 에서 `session_id` 를 꺼낸다. 신뢰는 자동화하지 않고 **심사 화면을 정규식으로 잡아 「막힘」**으로 띄운다.
- 스폰 때 `CODEX_THREAD_ID` 를 **지우고**, 훅은 그 변수가 설정돼 있고 값이 다르면 **보고를 포기**한다(중첩 방어). ★단 그 변수는 0.155.0 에 없다(실측) — 그래도 지우는 쪽은 해가 없다.★
- Windows 전송이 **자기 바이너리 CLI 재진입**이다(우리와 같은 모양).
- ★**베끼지 말 것 — 복원 실패가 전부 조용하다**★(에이전트를 안 살리고 옛 화면만 깔아 둔다. 로그도 토스트도 없다).

**t3code** (`…\t3code`) — **에이전트는 PTY 에 안 들어간다**(들어가는 건 로그인 셸뿐). 그래도 쓸 것:
- ★**rollout JSONL 의 첫 `session_meta` *내용*에서 id 를 읽어 그대로 resume 커서로 만든다**★ — **파일명은 타임스탬프가 섞여 id 로 되파싱이 안 된다**(Claude 는 파일명 자체가 id 라 정반대). **PTY 여부와 무관하게 도는 둘째 회수 경로다.**
- resume 커서를 **불투명 블롭 한 컬럼**으로 저장해 백엔드별 스키마를 안 만든다.
- `thread/resume` 실패 시 **`thread/start` 로 폴백**한다(행 대신).
- 훅에서 온 **일시적 id 가 durable id 를 덮지 못하게 가르는 판정**이 따로 있다 — 우리가 훅으로 id 를 받으면 같은 구분이 필요하다.

## do-not (실제로 겪은 것만)

1. ★**화면에서 세션 id 를 읽으려 하지 말 것**★ — 피어 넷 중 화면으로 id 를 얻는 곳이 **0곳**이다. codex 가 그걸 TUI 에 안 찍는다.
2. ★**「가장 최근 파일」 tie-break 금지**★ — 못 찾음을 잘못 찾음으로 바꾸고 조용하다. 파일 접근 자체가 아니라 **tie-break** 가 위험하다.
3. ★**훅 신뢰 해시를 직접 계산하지 말 것**★ — orca 가 3릴리스에서 깨진 뒤 버린 길이다.
4. ★**`--dangerously-bypass-hook-trust` 를 app-server 에 넘기지 말 것**★ — 인자 오류로 죽는다(root/`exec` 에만 있다). TUI 에서는 한동안 무시되기까지 했다(0.131~0.133).
5. **`codex doctor` 로 `-c` 키 유효성을 검증하지 말 것** — 판별력 0. 판별 경로는 `--strict-config` + `app-server --stdio < /dev/null`.
6. **코더 지시서에 「`assigns_session_id == false` 면 Fresh 에서 비운다」를 그대로 쓰지 말 것** — shell 이 걸려 ADR-0083 회귀가 깨진다.
7. **Bash heredoc 에 한글 본문 금지** — Write/Edit 를 쓴다.
8. **`git checkout -- <file>` 금지** · **루트 bare `cargo test` 금지** · 워크스페이스 회귀에 `-- --test-threads=4` 유지 · **앱을 셸에서 직접 띄우지 말 것**.
9. **step-log 에 `##` 헤딩 금지** — 파일 끝 최상위 불릿이 관례.
10. ★**앵커를 새 줄로 쌓으면 아래를 줄번호로 인용한 문서가 전부 밀린다**★ — 기존 앵커 줄에 `/` 로 이어 붙이면 0줄 움직인다(이번에 인용 6곳을 재유도했다).
11. **`npx tsc` 를 분리 실행 래퍼로 돌리면 종료 마커를 안 남긴다** — `node node_modules/typescript/bin/tsc --noEmit` 로 우회.
