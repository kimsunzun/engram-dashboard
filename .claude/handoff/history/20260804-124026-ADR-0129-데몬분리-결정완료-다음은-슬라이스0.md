## ★실행 계획 — 규모 조사 완료본(다시 조사하지 말 것)★

**측정:** `daemon/src/` 20,746줄 + `daemon/tests/` 8,134줄 = **28,880줄**(2026-08-04 `wc -l`).

### 핵심 발견 3개

1. **분량이 아니라 아키텍처 한 조각이 막고 있다.** `control/`(4,932)·`messaging_host.rs`(511)·`experiment/`(2,682)·test-harness bin 4개 — **`ws::`/`TcpStream`/`tungstenite` 참조 0건**(grep 확인). 결합은 **전부 `ws.rs` 한 파일**에 몰려 있다.
2. **`ws.rs`(1,899줄)는 사실상 두 파일이 붙어 있다.** ▸ **순수 네트워크 ~300줄**(`ConnRegistry`·`WsOutbound`·`OriginCheck`·`write_task`) ▸ **역사적 이유로 거기 사는 에이전트·메시징 어휘 ~694줄**(`DaemonStatusSink`·flush 기계 전체(`FlushMsg`/`IdleCoalescer`/`ChannelIdleNotifier`/`MessagingFlushSink`/`RosterDiff`)·flush worker·`WsOutputSink`/`WsOutboundSink`) ▸ **손봐야 할 ~310줄**(`handle_connection`·`send_error_and_close`·`read_task`).
   - **결정적 증거:** 4,009줄짜리 `tests/control_send.rs`가 `ws::`에 의존하는 **유일한 이유가 "그 타입들이 거기 있어서"** 다 — 진짜 대상은 `control::ingress::handle_send`·`MessagingService`·`messaging_host::*`. **파일 배치 문제지 결합이 아니다.**
3. **★진짜 설계 공백 1개 — ADR-0129가 명시하지 않았다★:** `handle_connection`/`read_task`(네트워크行)가 `ConnectionCore::dispatch`·`AgentManager::unsubscribe`를 **위로 호출**한다. 분리 후엔 순환이다(에이전트 시스템 → 네트워크는 정상, 반대는 불가). **네트워크 lib이 소유하는 포트 trait**이 필요하다 — ADR-0110의 idiom과 동일:
   ```rust
   trait ConnectionHandler: Send + Sync {
       fn on_connect(&self, conn_id: ConnId, sink: &dyn FrameSink);
       fn on_text(&self, conn_id: ConnId, text: String, sink: &dyn FrameSink) -> ControlFlow;
       fn on_disconnect(&self, conn_id: ConnId);
   }
   ```
   `FrameSink`는 `String`/`Vec<u8>`/close만 다룬다(= `WsOutbound`를 trait으로). 에이전트 시스템 lib이 `ConnectionCore`로 구현하고 **조립 바이너리가 꽂는다**. 이 한 수로 `read_task`/`handle_connection`/`send_error_and_close`에서 에이전트 타입 참조가 **전부** 사라진다. **다른 곳엔 trait이 필요 없다** — 에이전트 시스템이 네트워크의 평범한 타입(`ConnRegistry`·`ConnId`·`WsOutbound`)에 아래로 의존하는 건 순환이 아니다.

### 슬라이스 (순서 그대로)

- **★슬라이스 0 — crate를 안 옮기고 결합만 줄인다(최고 가치, 여기부터)★.** 4단계, **각각 독립 커밋·리뷰**:
  1. `ConnectionHandler`/`FrameSink` trait 쌍을 **현재 crate 안에** 도입하고 `handle_connection`/`read_task`/`send_error_and_close`를 그리로 태운다(~310줄). 게이트: `cargo test -p engram-dashboard-daemon` + `ws_e2e.rs` green(동작 보존).
  2. `ws.rs`의 에이전트·메시징 어휘 ~694줄을 `connection_core.rs`(또는 새 형제 모듈)로 **같은 crate 안에서** 이동. 성공 증거 = `tests/control_send.rs`의 import가 `ws::`에서 벗어난다.
  3. `connection_core.rs` 테스트 모듈의 `crate::ws::WsOutbound` 기반 mock(~28곳, 전부 `#[cfg(test)]`)을 `OutboundSink` trait 더블로 교체. **분리 전에 해야** 에이전트 시스템 테스트가 네트워크 lib에 dev-dependency를 지지 않는다.
  4. `AgentCommand::Auth`를 protocol에서 빼내 네트워크 소유 핸드셰이크 타입으로. (§인증 검증 참조)
  - **이걸 먼저 하면 나머지는 거의 `git mv` + `use` 경로 수정이다.** 안 하고 1·2를 바로 치면 이동 도중 순환에 걸려 멈출 곳이 없어진다 → 빅뱅 강제.
- **슬라이스 1 — 네트워크 lib 추출.** `instance.rs`(157, 완전 clean) · `portfile.rs`(191, 주의 — 아래 결정 대기) · `ws.rs`의 네트워크 ~300줄 + 슬라이스 0으로 탈결합된 3함수 + trait 정의.
- **슬라이스 2 — 에이전트 시스템 lib 추출.** `connection_core.rs` · `control/` · `messaging_host.rs` · `experiment/` · 슬라이스 0-2에서 옮겨온 것들. `test-harness` 기능은 **경계를 안 넘는다**(확인됨 — `ingress.rs`·`registry.rs`·`experiment/`·bin 4개에서만 쓰이고 `ws.rs`/`connection_core.rs`/`instance.rs`/`portfile.rs`엔 없다). 테스트 5,017줄(현 스위트의 61.7%)이 여기로.
- **슬라이스 3 — 조립 crate 박막화.** 남은 `lib.rs`(`run`·`build_manager*`·`run_accept_loop`·`start_test_server*`)·`main.rs`·`bin/*`. `ws_e2e.rs`(2,774)·`engram_send_cli.rs`(343)는 여기 남는다.

### 인증 검증 (ADR 주장 = 사실)

`AgentCommand::Auth` = `protocol/src/messages.rs:20-23`, 외부 태그 방식이라 wire = `{"Auth":{"token":"<64hex>","protocol_version":<u32>}}`. **프론트는 생성된 TS 타입을 안 쓰고 객체 리터럴을 직접 만든다**(`src/api/wsTransport.ts:270-274`) → **프론트 영향 0**. ts-rs 바인딩은 매 테스트 실행마다 덮어써지므로 golden-diff 실패 위험도 없다.

**한 가지 행동 차이(리뷰에 한 줄로 남길 것):** 지금은 첫 프레임이 Auth가 아니면 *"첫 frame이 Auth가 아님"* 이라는 구분된 에러가 난다(`ws.rs:972-976`). 단일 variant 타입으로 바꾸면 **파싱 자체가 실패**해 *"첫 frame 파싱 실패"* 분기로 떨어진다 — 결과(연결 종료)는 같고 메시지만 다르다. 회귀로 오인하지 말 것.

### `ConnectionCore` carrier-중립 주장 검증

파일 헤더의 *"TcpStream/tungstenite/코덱을 모른다"* 는 **문자 그대로 참**(프로덕션 구간 grep 0). 다만 `ConnRegistry`/`ConnId`를 직접 들고 있는데(`connection_core.rs:56,597,619,640`), 그건 **헤더가 스스로 밝힌 Stage-1 부채**이지 새 부식이 아니고, 방향이 아래쪽이라 **ADR-0129 불변식 위반도 아니다**. 부식은 `ConnectionCore`가 아니라 **한 파일 옆 `ws.rs`에서** 일어났다.

## ★사용자 결정 대기 (착수 전 필수 1건 + 누적 2건)★

1. **★격리 게이트 입도 — 슬라이스 1 전에 필요★.** ADR-0110식 **crate-level** 금지(`rg "engram_dashboard_(core|protocol|...)"` → 0)로 갈지, **type-level** 금지(에이전트 어휘 타입만)로 갈지.
   - **crate-level이면 `portfile.rs`가 오늘 기준 게이트를 통과 못 한다** — `pid_alive_with_start_time`(core)과 `DaemonInfo`(protocol)를 쓴다. 선이동 작업이 붙는다.
   - **type-level이면 통과한다.** 그리고 **선례가 이미 있다** — `discovery` crate가 같은 이유로 core에 full crate 의존을 지고 있다(`discovery/src/lib.rs:866`). 조사자 권고 = type-level(선례 정합·추가 작업 없음), 대가 = 기계적 보장이 약해짐.
2. **실측 ⑧ 프로덕션 훅** — 수신자별 인과를 재려면 드레인 루프에 시각 훅 필요(현재는 집계 대리 측정 + 미측정 명시).
3. **`--disallow-mcp` 존폐** — 권한만 제거하는 노브라 실측으로 무효 확인. 권고 = 플래그·env seam·테스트 3건 함께 삭제.

## 실패한 접근 (do-not)

- **★리뷰어를 공유 워킹트리에서 병렬로 돌리며 mutation 허가 금지 — 실발동★.** 격리 worktree(`isolation: "worktree"`)로. **그리고 worktree는 HEAD에서 생성돼 미커밋 변경을 안 가져간다** — `git diff > patch`로 만들어 넘기고 "적용 후 해시 검증"을 지시할 것(그렇게 하니 문제 소멸).
- **★내부 구현을 사용자 결정으로 올리지 말 것 — 실발동, 사용자 2회 지적★.** 코드 구조·자료구조·테스트 전략 = 메인이 정하고 **보고**. 사용자 결정 = **동작·정책·데이터 위치**만.
- **★설명이 계측 세부로 흐르면 사용자가 길을 잃는다 — 실발동 2회★**(*"무슨 테스트인지 이해가 안 감"*, *"그래서 뭘 해야 된다는거?"*). 결론 먼저, 세부는 물으면.
- **`/adr index --write`가 인덱스 행을 잘라먹는다 — 7회째.** 이번 손실 **6행**(0099·0108·0111·0112·0113·0116). `--write` 후 반드시 `git diff docs/decisions/README.md` 실측 → 수동 복구. 손편집 도장은 잘리는 게 아니라 **아예 안 나타나는** 변종도 있다.
- **`/adr supersede`는 `--old` 단일만.** 다중 부분폐기는 주 대상만 스크립트, 나머지는 손으로.
- **코더 자기보고를 게이트로 쓰지 말 것 — 이번 세션 3회 어긋남**(도장 유무 오보 · mutation 실패 개수 과소 · 지시서의 잘못된 해시를 코더가 지적해 정정).
- bare `cargo test` 금지(멤버별 `-p`) · Fable 워커 금지 · **Agent 스폰 시 model/프리셋 명시 필수** · messaging 닿으면 격리 게이트 필수 · git-bash 경로 인자엔 `MSYS_NO_PATHCONV=1` · ws_e2e case09 flaky(임계값 튜닝 금지 — ADR-0038)
- **`cargo build`가 `protocol/bindings/*.ts`를 더럽힌다**(줄바꿈만, `--numstat` 빈 출력). 커밋 전 `git checkout -- crates/engram-dashboard-protocol/bindings/`.

## 정지 조건

- **ADR 본문(결정 텍스트) 수정 = 사용자 승인.** (이번 세션에 spec §7 ⑤ + ADR-0125를 실측 반증 근거로 정정 — 사용자 승인 받음.)
- **리뷰 정면 대립·BLOCK·루프 상한 초과는 자율 모드라도 에스컬레이션.** 이번 세션 BLOCK 2회·대립 3회 발동, 전부 세 번째 렌즈(mutation 실증)나 사용자가 갈랐다.
- **코더 재수정 하드캡 5회** — ADR-0128 구현이 3, 계측 하네스가 2 소진(각 과업별).
- **프로덕션 코드에 test-only 훅 추가 = 사용자 결정**(실측 ⑧이 여기 걸린다).
- **`src-tauri` 교차 의존 주의** — `src-tauri/src/daemon_client/tests.rs:264`가 `engram_dashboard_daemon::start_test_server()`를 직접 부른다. **조립 crate 이름이 바뀌면 같은 PR에서 고쳐야 한다**(다른 crate라 놓치기 쉽다).
- `.gitattributes` 추가 임의 금지 · **Engram repo(`I:\Engram`)에서 `git add -A`/`commit -a` 금지**(중첩 repo가 gitlink로 딸려 온다).

## 미결 (착수를 막지 않음)

- **`bin/engram-send.rs`(1,528줄)는 직교** — `engram_dashboard_*` 의존 0, 서브프로세스 블랙박스 테스트. 어느 crate의 `[[bin]]`에 둘지만 정하면 된다(조립 crate가 자연스러움).
- **MCP 제어 평면(`control/mcp_server.rs`, axum, 자체 포트)은 네트워크 lib으로 안 간다** — ADR-0129가 "제어 평면"을 에이전트 시스템에 배정했다. 소켓을 다룬다고 착각하지 말 것.
