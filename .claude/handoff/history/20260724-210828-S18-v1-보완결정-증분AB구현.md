## 확정 결정 (이 세션 — 정본 ADR-0104 + spec §4·§5·§7·§8)
- **그룹 해석 = seam**(`GroupSource`): v1 소스 = 런타임 명단+`@all`. 폴더 = 미래 소스(데몬 소유화 시, 조직 방송 정본 예정). **하위 에이전트 계층 = 주소 단위 비채택**(오케스트레이터가 런타임 그룹 등록으로 대체).
- **wake 비채택(v1):** 잠든 수신자도 부재와 동일 파킹. wake-on-request = v2 후보. 사용자 확인: "파킹 구현부담 없으면 파킹으로"(부담 없음 — 파킹이 설계 중심).
- **주입 = idle 게이트 + 일괄 flush:** busy면 메일박스 대기(`pending` 공유), idle 진입/등장 시 전부 오래된 순 일괄. `delivered` = 실주입 시점만. busy/idle 관측 = capability(stream-json 턴 이벤트), 관측 불가 백엔드 = 즉시 주입 폴백. **배치 검증 = 수용 기준 중점 강화(사용자 지시).**

## 증분 C 착수 시 알아야 할 것 (코드 계약)
- `messaging/` 공개 API: `Mailbox{park,drain→DrainOutcome{deliverable,expired},sweep_expired}` · `Ledger{record,transition→Result(그래프 강제),open_request→OpenOutcome,close_on_reply(now)→ReplyOutcome{Closed,ClosedHistoryAnomaly,NoMatch,AlreadyClosed},due_timeouts}` · `Groups+GroupSource::resolve(group,live)`. 전부 순수(시계 주입) — **동시성 래핑은 C의 몫**(락 순서 = ADR-0006 준수).
- `wrap_message(sender,msg_id,body,format,&EnvelopeFields)` — 프로덕션 호출부(handle_send)는 현재 빈 fields. `wrap_notice` = `#[allow(dead_code)]` 대기.
- 장부 링버퍼 1024 = 코더 임의 상수 — **사용자 사후 비준 필요**(`Ledger::with_capacity` 오버라이드 가능).
- idle 관측: stream-json 턴 이벤트 기반 capability — 어느 이벤트로 busy/idle 판정할지는 C에서 설계(기존 관측 인프라 조사 먼저).

## do-not (재발 방지)
- **blind 리뷰어 payload에 증분 스코프를 정확히**: 1차 codex 리뷰가 "의도적 미배선"을 BLOCK 2건으로 오판 — 원인은 부정확한 완료 기준 전달. 수용 기준에 "deferred = by design, do not flag"를 명시하면 재발 없음.
- 직전 세션 do-not 승계: stray 프로세스 kill 후 재실측 · 소스 변경 후 릴리즈 재빌드(`launch\빌드.bat`) · bare `cargo test` 금지 · 에이전트 출력 검증 = 실 UI 슬롯 DOM · 유저 전역 `allowedMcpServers: []` 수정 금지(해법 = 스폰 `--settings` 주입) · 수신자는 stream-json만(TUI 수신 불가 by design).
