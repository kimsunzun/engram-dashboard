# LLM 명령 규칙

LLM 이 버스 · `engram` CLI 로 부르는 명령을 새로 만들거나 고칠 때 따르는 규칙. **목표 = 호출 수 최소 · 컨텍스트에 싣는 양 최소**(사용자 기준 「LLM 시나리오는 여러 번 거치지 않아야 실수가 적다」).

- **상태:** 초안(S27 · 2026-10-26). 「정함」은 사용자와 합의한 것, 「미정」은 아직 결정 전이다 — 미정을 정함처럼 따르지 않는다.
- **결정 기록:** ADR-0307(`docs/decisions/0307-llm-명령-규칙-명령은-한-호출-조회는-영역별로-바로-출력.md`)
- **근거 조사:** `docs/research/llm-command-design-query-vs-action-2026-10-26.md` · `docs/research/pane-positional-addressing-2026-10-26.md`
- **이 문서는 제자리 수정한다**(정설). 규칙을 바꾼 *이유*와 버린 대안은 ADR 로 남긴다.

## 1. 명령(쓰기) — 정함(세부 이름 · 인자 · 응답 문구는 메인이 LLM 이 잘 쓰는 쪽으로 정한다 — 사용자 위임 2026-10-26)

1. **시나리오 하나 = 명령 하나.** 흔한 요청이 한 호출로 끝나게 명령을 짠다. 여러 단계(찾기 → 바꾸기 → 자리 잡기)는 명령 안에서 한다 — 예: `agent.spawnInto` 는 띄우기와 칸 배치를 한 번에 한다.
2. **대상은 LLM 이 이미 아는 말로 받는다** — id 를 알아내려고 먼저 조회하게 만들지 않는다. 명령이 안에서 id 로 푼다(조회 단계가 없어지는 것이 아니라 셸 안으로 들어간다). 받는 말:
   - 에이전트 이름(자기가 띄웠거나 메시징 상대라 이미 안다) — **풀이는 데몬 명부의 해석기 하나(`resolve_in` 의미 — id 먼저 · 정확한 이름 · 중복은 CONFLICT · 없으면 NOT_FOUND)를 따른다.** 셸의 id→이름 캐시(`layout/manager.rs` 의 `agent_names` — 항목을 지우지 않는다)로 따로 풀지 않는다 — 해석기가 둘이면 판정이 갈린다(ADR-0132 · `crates/engram-dashboard-agent/src/commands.rs` 의 `resolve_in` 머리 주석).
   - 공간 낱말(모서리 · 지금 칸 기준 방향 — `slot.resolveSpatial` 의 낱말 · ADR-0068)
   - 화면 칸 번호 — **미정**(§3)
   - id(그대로 받는다 — 프로그램 소비자 · 이미 id 를 든 경우)
   **말의 종류마다 인자를 따로 둔다**(예: `--agent` · `--at` · `--id`). 한 인자에 여러 종류를 섞어 받으면 「2」 · 「left」 같은 이름의 에이전트가 번호 · 낱말과 부딪힌다.
3. **모호하거나 없으면 오류로 멈추고 고칠 단서를 준다.** 여럿이 맞으면 추측하지 않는다(tmux 와 같다). 오류에는 맞는 후보 몇 개를 싣는다 — 다음 호출 한 번에 고칠 수 있게.
4. **응답에는 바뀐 뒤의 상태를 짧게 싣는다.** 배치를 바꾼 명령은 그 결과의 배치(칸마다 안에 든 것)를 돌려준다 — LLM 이 결과를 추론하지 않아도 되고, 따로 조회할 일도 준다. 만드는 명령은 새 id 를 돌려준다. 응답의 모양(한 줄 꼴 · 텍스트/JSON)은 §4.
5. **묶음 실행 · 스크립트는 만들지 않는다**(필요해질 때). 같은 두세 호출이 실제로 반복되면 그 시나리오를 명령 하나로 만든다. 묶음(명령 목록을 차례로 · 실패하면 멈춤)은 그래도 모자랄 때 다시 꺼낸다. 변수 · 조건 · 반복이 드는 스크립트는 하지 않는다.

## 2. 조회(읽기) — 정함(4 의 자리만 미정)

1. **부를 말을 모를 때만 조회한다.** §1-2 의 말로 부를 수 있으면 조회 없이 명령으로 간다.
2. **영역마다 조회 하나 + 필터 인자.** 레이아웃 · 에이전트 · 설정(폰트 · 테마 …)처럼 영역별로 나누고, 「어느 부분만」 고르는 인자를 둔다(선례 = `settings.get` 의 키 접두). 찾을 말을 알면 그 인자로 좁힌 핀포인트 조회를 쓴다.
3. **결과는 컨텍스트에 바로 출력한다.** 파일로 내고 bash 로 찾게 하지 않는다 — 영역 하나의 결과는 작고(어림 = ADR-0307 「근거」 — 가정과 방법을 거기 적었다), 파일 + 검색은 호출을 늘린다. 찾을 말을 알면 핀포인트가 한 번에 끝내고, 모르면 어차피 전체를 읽어야 한다.
4. **크면 파일로 넘기는 공용 안전장치 하나 — 둘 자리는 미정.** 응답이 문턱을 넘으면 파일로 쓰고 경로 + 앞부분만 낸다(선례 = LangChain Deep Agents 의 20,000 토큰 문턱 · 경로 + 앞 10 줄). 자리 후보: ① `engram` CLI — 에이전트 경로의 응답이 다 지나지만, CLI 는 인증 + 배송만 한다는 사용자 결정(ADR-0285 결정 1)과 부딪힌다 ② 셸 처리기 · 데몬 — 내용을 쥐는 쪽이지만 영역마다 손댈 곳이 갈린다. 파일을 어디에 쓰나(데이터 위치)도 사용자 결정이다. 문턱 값은 구현 때 정한다. (구현 전 — 지금 CLI 는 몸통을 그대로 찍는다.)
5. **모든 영역을 한꺼번에 내는 조회는 만들지 않는다**(필요해질 때). 만들게 되면 그때가 4 의 파일 + 검색이 맞는 크기다.

## 3. 칸 번호 — 미정

- **좌표는 쓰지 않는다(정함).** 「x1 y2」 같은 열 · 행 좌표 — 분할 트리라 열마다 행이 달라 애매하고, 조사한 도구 중 쓰는 곳이 없었다(사용자 수락 2026-10-26).
- **번호 지목 자체가 미정이다.** 걸림 둘:
  - **창 번호를 버린 같은 까닭에 걸린다** — 창 인자는 번호를 받지 않는다(ADR-0302 결정 9 · 사용자 결정 2026-10-23: 2 를 닫고 새 2 가 생긴 뒤 늦게 온 `window.close("2")` 가 새 창을 닫는다). 칸 번호는 창 번호보다 더 자주 바뀐다.
  - **순번이 크기 조절로도 바뀐다** — 코드의 순번(`src-tauri/src/layout/spatial.rs` 의 `ordinal`)은 칸 중심점 높이를 그대로(허용오차 없이) 비교해 위→아래로 매기고 같을 때만 왼→오다. 그래서 칸 경계를 조금만 끌어도(`split.setRatio`) 순서가 바뀌고, 「같은 높이면 왼→오」는 거의 일어나지 않으며, 한 열의 칸들이 이어진 번호를 받는다는 보장도 없다(ADR-0068 결정 1 이 받아들인 한계). 0 부터 센다.
- 번호를 쓰게 되면 함께 정할 것: 번호의 범위(창 · 탭 하나 안) · 1 부터 보일지 · 높이 비교에 허용오차(줄 묶기)를 둘지 · 화면에 늘 보일지 필요할 때만 띄울지(tmux `display-panes` 는 키를 누를 때만) · 창 번호(제목 줄 표식 · ADR-0300)와 헷갈리지 않게 할 표기.
- **지금 연달아 작업할 때는 에이전트 이름을 쓴다** — 이름은 삽입 · 닫기 · 크기 조절로 안 바뀐다.

## 4. 출력 형식 — 미정(메인이 구현 때 정한다)

- 텍스트 · JSON · 그 밖의 압축 형식 중 보편 승자는 없다(모델 · 데이터마다 다르다). 명령 세부와 같이 메인이 LLM 이 잘 읽는 쪽으로 정하고 보고한다(사용자 위임 2026-10-26).
- 크기에는 영향이 크다 — ADR-0307 의 어림에서 id(UUID)를 실은 JSON 이 id 없는 텍스트의 열 배 남짓. LLM 은 이름으로 부르므로 id 를 늘 실을 필요는 없다.
- 제약(사실): 데몬은 UI 명령 몸통을 해석하지 않는다(ADR-0081 · ADR-0156) — 모양을 바꾸려면 셸 처리기에서 한다. CLI 는 지금 응답 몸통을 그대로 찍는다(실패 몸통의 교정 JSON 포함).

## 5. 새 명령을 낼 때 확인

- 흔한 요청이 몇 호출로 끝나나 — 2 이상이면 §1-1 · §1-2 로 줄일 수 있나.
- id 만 받는 인자가 남았나 · 말의 종류마다 인자가 따로인가(§1-2).
- 에이전트 이름을 데몬 해석기 의미로 푸나(§1-2).
- 모호 · 없음 오류에 후보가 실리나(§1-3).
- 응답이 다음 호출에 필요한 것(새 id · 바뀐 배치)을 싣나(§1-4).
- `prompts/engram-help.md` 에 사용법을 적었나 — LLM 이 읽는 사용 설명이 거기 있다.
