# UI string structure (i18n)

> Live reference doc — edit in place when the code moves. Anchors are file and symbol names only.
> Decisions and their reasons: ADR-0069 (`docs/decisions/0069-ui-문자열-중앙화-i18n-ready-strings-모듈-완전-i18n-보류.md`) · ADR-0349 (i18next behind `t()`) · ADR-0372 (English source, Korean selectable, live switch) · ADR-0373 (runtime design).

**Whole picture** = `docs/reference/architecture.md`

## What it is

Frontend UI text is looked up through one function, `t(key, params?)` in `src/i18n/index.ts`, against two deep-frozen tables: the English source `en` (`src/i18n/en.ts`) and the Korean translation `ko` (`src/i18n/ko.ts`), which must have the same keys and placeholder sets. A private i18next instance does the lookup in the current language; our own code fills `{word}` placeholders. Keys are `"<namespace>.<sub>"` strings whose type is derived from `en`, and `{word}` placeholders in a value make the matching `params` field required at compile time. The language is `en` or `ko`: a window boots in the language of `<html lang>` and switches live when the shell setting `ui.language` changes, re-rendering from the root without a remount. Every user-visible string is resolved where it is shown, so nothing keeps the old language after a switch. The Rust shell keeps its own small en/ko table for the text it draws (tray, refusal dialog, auto tab names, OS window titles) and follows the same setting. The daemon keeps one more, for the native approval dialogs it shows (`crates/engram-dashboard-daemon/src/link/peer/approvals/text.rs`; the "N more waiting" line in `src/ask_user.rs`); it never reads the shell's settings — the shell sends `AgentCommand::SetUiLanguage` on every connection and on each change.

## Modules

- `src/i18n/en.ts` — the source table (`en`, `as const`).
- `src/i18n/ko.ts` — the Korean table, checked against `en` by `ko satisfies Translation<typeof ko>`.
- `src/i18n/deepFreeze.ts` — freezes both tables at module load.
- `src/i18n/index.ts` — the only importer of i18next, and imports neither React nor Tauri: the private instance, `t`, `getLanguage` · `setLanguage` · `subscribeLanguage` · `isLang`, the key and placeholder types, the runtime matcher `WORD_PLACEHOLDER`, `lookup`, `interpolate`, and the test seam `__test__`.
- `src/i18n/react.ts` — `useLanguage()`, the React subscription to the language.
- `src/i18n/languageSetting.ts` — `installLanguageApplier`: subscribes to `ui.language` on `settingsClient` (`src/api/settingsClient.ts`), applies `en` / `ko` with `setLanguage`, then writes the window memory; `LANGUAGE_SETTING_KEY`.
- `src/i18n/langMemory.ts` — `rememberLanguage`: the per-window language memory `sessionStorage[LANG_KEY_PREFIX + window label]`; `LANG_KEY_PREFIX`.
- `src/i18n/intlLocale.ts` — `perLanguage(make)`: a value (an `Intl` formatter) made from the current language's locale on first use per language, then reused.
- `src/i18n/vitest.setup.ts` — a vitest `setupFiles` entry that switches every test file to `ko`.
- Tests next to them: `index.test.ts` · `index.node.test.ts` · `react.test.ts` (lookup, interpolation, miss rule, both tables' brace scan and token-set equality, language API, sync init via `moduleScopeTitle.fixture.ts`, loading without a `document`, the hook), `languageSetting.test.ts`, `langMemory.test.ts`, `intlLocale.test.ts`.

## Wiring and flow

- Boot: `index.ts` reads `<html lang>` once at module evaluation (absent or unknown → `en`) and initializes the instance synchronously, so `t()` works at module scope. The shell's init script (`src-tauri/src/webview_env.rs`) plants `<html lang>` per window: the window memory written by `rememberLanguage` when it is `en` or `ko`, else the effective `ui.language` at window creation.
- Live switch: `src/main.tsx` calls `installLanguageApplier()` next to `installChatStyleApplier()`, before `settingsClient.install()`. The settings client replays applied values on subscribe and pulls after listening, so a stale boot language corrects itself. `setLanguage` changes the instance language, updates `<html lang>` and notifies subscribers once.
- Re-render: `App` (`src/App.tsx`) calls `useLanguage()`, so a switch re-renders the tree under it; component state stays. The `memo` boundaries over `t()` text call `useLanguage()` too: `LayoutLeaf` and its inner `SlotBody` (`src/components/layout/LayoutLeaf.tsx`). React keys stay the same, so open menus and flyouts survive.
- Command titles: `Command.title` in `src/commands/registry.ts` is a function (`() => t('…')`), registered at module load by every `*Commands.ts` (imported by `src/commands/contributions.ts`); the helpers `registerSplit` (`slotCommands.ts`) and `registerWindowControl` (`tabCommands.ts`) take that function, `registerToggle` (`usageCommands.ts`) and `registerConnectionCommands` (`connectionCommands.ts`) build it. `list()` calls it, so `window.__engramCmd.list()` (`src/store/eventBus.ts`) returns titles in the current language. Native folder-picker titles (`dialog.*`) are resolved at click time inside `run` bodies.
- Slot menu: contributions in `src/commands/slotMenu.ts` reference commands by id; a submenu container has its own `id` and a `title` function. `buildSlotMenu` / `resolveRunnable` call the titles while building items; the open menu is rebuilt on each render under `SlotBody` (`LayoutLeaf.tsx`) and `src/components/slot/SlotContextMenu.tsx` draws `item.title`, measuring the menu and an open flyout again on a language change.
- Formatters: `src/components/layout/RestoreModal.tsx` (`formatSavedAt`) and `src/components/slot/usageFormat.ts` (`formatClock`, `formatResetAt`) take their `Intl.DateTimeFormat` from `perLanguage`.
- Shell: the setting `ui.language` is declared in `src-tauri/src/settings/registry.rs`; its change reaches the shell through `SettingsEvents::ui_language_changed` (`src-tauri/src/ui_language.rs`), which updates the layout language in `ViewManager`, re-announces affected tab names and window titles, and relabels the tray. The shell's texts, tab-name words included (`tab_word`), are in `src-tauri/src/ui_text.rs`; `src-tauri/src/layout/tab_name.rs` builds names from them; the refusal dialog is in `src-tauri/src/daemon_client/refusal.rs`. The shell also hands the setting to the daemon: `DaemonClient::set_ui_language` (called at startup and from `ui_language_changed`) keeps the value in the connection driver, which writes `AgentCommand::SetUiLanguage { language }` on every connection it opens and on the open one when it changes.
- Daemon: `ControlRegistry::ui_language` holds the last value (English until a shell sends one; an unknown word is English). The approval dialog reads it when it is about to show (`ask_user::LanguageSource`), so a change reaches the next dialog; an open dialog keeps its language (Task Dialog buttons cannot be relabelled). Every question is built in both languages when it is asked (`approvals/text.rs`, its Korean inside one `hangul-ok` block).

## Promises no single file shows

- No code keeps a `t()` result across renders or calls, and no translated text is a key, id, sort key, dismiss key or comparison baseline (ADR-0373). Today's untranslated stand-ins: container `id`s in `slotMenu.ts` (`itemKey`, resolved id `container:<id>`, React key, `data-slot-menu-container`, sort tie-break); row-menu `id`s in `AgentList.tsx` and `PresetPalette.tsx`; `RowError` in `AgentList.tsx` (key plus raw error, text made by `rowErrorText` at render); `BandCause` from `bandView` in `src/api/connectionBand.ts` (text made by `causeText` / `bandText`; `ConnectionNotice.tsx` keys its ✕ memory on the untranslated view).
- One deliberate exception: `draftStart` in `AgentList.tsx` and `PresetPalette.tsx` is the display name captured when a rename starts — it can be translated text (the `common.noPath` name) — and it is the rename's "unchanged" baseline by design, so a language switch or an outside rename during the edit does not count as an edit (the same rule as `TabBar`'s `seed`).
- A new `memo` component that renders `t()` text must call `useLanguage()`, or it keeps the old language until its props change.
- `basename` (`src/util/basename.ts`) returns the `common.noPath` text for a blank path in the current language; callers call it where the name is shown.
- The dropped-output placeholder is a marker: `PLACEHOLDER_ERROR_MESSAGE` in `src/api/wsFrame.ts` is byte-equal to the protocol's `placeholder.rs` constant, and `StructuredTextView.tsx` (`errorMessageText`) shows `chat.droppedOutput` for an error whose message equals it. Changing the text on one side alone shows the raw marker.
- `t()` checks and reads with one language (`current`): a key that is not exactly `ns.key`, or whose resource value in `current` is not a string, returns the key uninterpolated. Interpolation and nesting of i18next are skipped per call; params never reach i18next. A bare namespace key is caught by this check — with `returnObjects: false` i18next itself would return the key, not the object.
- `setLanguage` accepts only `en` | `ko` (else returns `false` and changes nothing) and does nothing for the current value. `installLanguageApplier` ignores any other setting value with a warning; `rememberLanguage` writes nothing outside the shell and only warns when `sessionStorage` is missing or throws.
- `LANG_KEY_PREFIX` must equal the prefix the shell's init script reads; a shell test pins the two by matching the one-line `export const LANG_KEY_PREFIX = …` in `langMemory.ts` as text.
- `slot.foreignContent` must equal the shell's `Foreign` tab-name word (`tab_word` in `src-tauri/src/ui_text.rs`) in each language; the Rust test `foreign_word_is_the_one_the_frontend_shows` (`src-tauri/src/layout/tab_name.rs`) reads the table files as source text, so it also pins their paths and the line form `foreignContent: '…'`.
- Tests run in Korean through `vitest.setup.ts`; a test that needs English sets it and restores Korean. Components outside `App` in a test do not re-render on a switch unless they or a wrapper call `useLanguage()`.
- Type grammar and runtime grammar must stay identical: `Placeholders` / `IsWord` (types) and `WORD_PLACEHOLDER` (runtime) are kept in sync by comment only; the brace scans over both tables in `index.test.ts` keep nested or unmatched braces out of values.
- `as const` in `en.ts` is required for placeholder inference; widening the table to `string` silently drops all param checking. The `ko` type gate misses a `ko` value widened to `string` when its `en` value has no token; the token-set test in `index.test.ts` covers that.
- Not guarded: that a user-visible string goes through `t()` at all, and that a new string is not stored. ADR-0069 and ADR-0373 make these review rules; no lint enforces them.
- LLM-facing text that follows the UI language until LLM text becomes English-only (ADR-0372 known exception): `__engramCmd.list()` titles, the `connection.status` reply `text`, `layout.rows` `tab_name`, `tab.list` `name`.

## Visible strings outside `t()`

- Shell-drawn text: see the Shell line under Wiring and flow.
- Backend brand names in `src/components/slot/richBranding.ts` are product names.
- Not UI strings and outside this system: logs and LLM-facing command text (`help.summary`, argument `description`). Thrown error causes (shell, daemon, crates) are English (ADR-0383, S38 TRD §3 D1); the frontend shows each inside its own translated head (`connectionBand.ts` `causeText`, `AgentList` `rowErrorText`, the chat error header), so in Korean mode the head is Korean and the cause stays English.
