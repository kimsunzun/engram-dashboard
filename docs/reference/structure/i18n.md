# UI string structure (i18n)

## What it is

Frontend UI text is looked up through one function, `t(key, params?)` in `src/i18n/index.ts`, against one statically imported, deep-frozen Korean table `ko` in `src/i18n/ko.ts`. There is one language, no locale state, no initialization step and no external library. Keys are `"<namespace>.<sub>"` strings whose type is derived from the table, and `{word}` placeholders in a value make the matching `params` field required at compile time. The Rust shell does not use this system: its visible strings are literals in Rust.

## Modules

- `src/i18n/ko.ts` — the table (`ko`, `as const`) and its type `KoTable`; `deepFreeze` locks it at module load.
- `src/i18n/index.ts` — `t`, the key type `StringKey`, the placeholder type extraction (`Placeholders` · `ParamsArg`), the runtime matcher `WORD_PLACEHOLDER`, `lookup`, `interpolate`, and the test seam `__test__`.
- `src/i18n/index.test.ts` — pins lookup, global interpolation, no rescan of substituted values, regex-special characters as literals, extra params ignored, a missing param keeps its `{token}`, a missing key returns the raw key uninterpolated, non-word braces are not placeholders, the malformed-brace scan over every `ko` value (`hasMalformedBrace`), and the freeze.

## Wiring and flow

- Callers import only `{ t }`. They are command modules under `src/commands/`, components under `src/components/`, and formatters such as `src/api/connectionBand.ts`, `src/components/agent/failureKinds.ts`, `src/components/slot/usageFormat.ts`. Find them: `rg "from '(\.\./)+i18n'" src`.
- Outside `src/commands/`, calls run at render or call time. Native folder-picker titles (`dialog.*` keys) are resolved at click time inside command `run` bodies (`agentCommands.ts`, `presetCommands.ts`, `slotContentCommands.ts`).
- Command titles are resolved **once, at module evaluation**. `src/App.tsx` imports `src/commands/contributions.ts`, which side-effect-imports every `*Commands.ts`; each calls `register({ title: t(...) })` at top level. The same happens through helpers that receive an already-resolved string: `registerSplit` (`slotCommands.ts`), `registerWindowControl` (`tabCommands.ts`), `registerToggle` (`usageCommands.ts`), and `registerConnectionCommands` (`connectionCommands.ts`, main window only). Submenu container titles are resolved the same way in `registerSlotMenu(...)` calls (`agentCommands.ts`, `slotContentCommands.ts`).
- The resolved string is stored as `Command.title` in `src/commands/registry.ts`. On screen it appears only in the slot right-click menu: `buildSlotMenu` / `resolveRunnable` (`src/commands/slotMenu.ts`) copy it into menu items and `src/components/slot/SlotContextMenu.tsx` renders `item.title`. It is also returned by `list()` and therefore by `window.__engramCmd.list()` (`src/store/eventBus.ts`). `src/commands/viewCommandBridge.ts` does not send titles to the shell.

## Promises no single file shows

- `t()` needs no initialization today: `ko` is a static import, so calling it at module load is safe. Any future backend must be ready before `contributions.ts` evaluates the command modules, or titles are captured wrong.
- Command and container titles are snapshots taken once per webview load. Nothing re-resolves them.
- A submenu container has no id: `itemKey` in `slotMenu.ts` uses `container:<title>`. Two containers with the same resolved title in one target replace each other on registration, and the title is the final sort tie-break.
- The type gate is the only key check. A key that bypasses it (a cast or a JS caller) is not rejected: `lookup` returns the raw key and `t` returns it uninterpolated, with no log.
- Type grammar and runtime grammar must stay identical: `Placeholders`/`IsWord` (types) and `WORD_PLACEHOLDER` (runtime) are kept in sync by comment only. Nested or unmatched braces in a value would split them; only the `ko` value scan in `index.test.ts` prevents that.
- `as const` in `ko.ts` is required for placeholder inference; widening the table to `string` silently drops all param checking.
- Not guarded: that a user-visible string goes through `t()` at all. ADR-0069 makes it a review rule; no lint or test enforces it.
- One shell string must equal a table value: `word(Word::Foreign)` in `src-tauri/src/layout/tab_name.rs` must equal `slot.foreignContent`. The Rust test `foreign_word_is_the_one_the_frontend_shows` checks it by reading `src/i18n/ko.ts` as source text with `include_str!`, so it also pins that file's path and the literal line form `foreignContent: '...'`.

## Visible strings outside `t()`

- Tray menu labels: `MenuAction::label` in `src-tauri/src/tray/core.rs`, used by `build_tray` (`src-tauri/src/tray/mod.rs`); the tray tooltip is set in `build_tray`.
- Native refusal dialog (title and body): `refusal_text` in `src-tauri/src/daemon_client/refusal.rs`, shown by `TauriRefusalBox`.
- Auto tab names and OS window titles: `word` / `Word` in `src-tauri/src/layout/tab_name.rs` (used by `effective_tab_name`, `slot_label`, `window_title`). The tab bar shows the shell-computed name. Whether a saved tab name is auto or named is the state file's `TabEntry.named` flag (`restored_name` in `src-tauri/src/state/convert.rs`), not its text. `is_word` only keeps a shell word from being seeded into the agent-name ledger on load (`agent_name_seed`, same file), so the word table is also that filter's list.
- Dropped-output placeholder text: `placeholder_message!` / `PLACEHOLDER_ERROR_MESSAGE` in `crates/engram-dashboard-protocol/src/placeholder.rs`, mirrored byte-for-byte as `PLACEHOLDER_ERROR_MESSAGE` in `src/api/wsFrame.ts`; the chat view renders it as an error row body.
- Frontend literals: `PATH_NAME_PLACEHOLDER` in `src/util/basename.ts`; in the chat view, the error row header in `StructuredTextView.tsx` (`RowHeader` in the `'error'` case), the tool row's `Error` badge, its `In` / `Out` captions and its `arguments` fallback in the same file, and the wait label in `src/components/slot/chat/WaitRow.tsx`.
- Fixed-locale formatters: `SAVED_AT` in `src/components/layout/RestoreModal.tsx` and `USAGE_LOCALE` / `CLOCK` in `src/components/slot/usageFormat.ts` are built once at module load with `ko-KR`. Backend brand names in `src/components/slot/richBranding.ts` are product names.
- Not UI strings and outside this system: logs, thrown error text, and LLM-facing command text (`help.summary`, argument `description`).

## Where to look

- Lookup and types: `src/i18n/index.ts` (`t`, `lookup`, `interpolate`, `StringKey`, `Placeholders`, `ParamsArg`).
- Table: `src/i18n/ko.ts` (`ko`, `KoTable`, `deepFreeze`).
- Title capture: `src/commands/contributions.ts`, each `*Commands.ts` top-level `register` call, `src/commands/registry.ts` (`register`, `list`).
- Menu rendering: `src/commands/slotMenu.ts` (`registerSlotMenu`, `itemKey`, `resolveRunnable`, `buildSlotMenu`), `src/components/slot/SlotContextMenu.tsx`.
- Shell strings: `src-tauri/src/tray/core.rs`, `src-tauri/src/daemon_client/refusal.rs`, `src-tauri/src/layout/tab_name.rs`.
