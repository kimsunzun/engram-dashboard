02백엔드 한눈에

백엔드가 갈리는 자리는 이 표 하나다

아래가 백엔드마다 다른 칸 전부다. 이 표 밖의 배관 — 통로·코어·데몬 팬아웃·프론트 — 은 백엔드 이름을 모른다.

백엔드전송 모양렌더세션 복원우편 수신LLM 창구상태
claude (터미널) Pty terminal (xterm) 무손실 --resume 받는다 열림 배선됨
claude (stream-json) StdioNdjson rich (챗) 무손실 --resume 받는다 열림 배선됨
codex Pty terminal (xterm) 없음 — 항상 Fresh 명단에서 제외 사람만 배선됨
gemini Pty (스텁) terminal (스텁) 없음 (보수적 스텁) 선언 안 함 — trait 기본 낱말 미등록 미배선
  • 각 칸은 백엔드 폴더 하나가 스스로 신고하고, 코어는 그 신고대로 배관을 잠근다 — 기능이 「빠진」 게 아니다. 그래서 새 백엔드는 파일이 아니라 열 하나가 늘고, 아래 척추는 한 줄도 안 바뀐다.
  • 미배선 = 폴더와 stub 은 서 있는데 명령 변형이 없어 dispatch 로 라우팅되지 않는다. 그래서 gemini 의 칸은 전부 stub 값(trait 기본·best-guess)이고 실측이 아니다.
  • 렌더 열은 강제값이 없을 때의 기본값이다 — 슬롯에 걸린 renderModeOverride 가 먼저다(「렌더 분기」).
  • LLM 창구 열은 결과만 적는다 — 「못 고른다」와 「골라도 정책이 닫는다」는 다른 축이고, 그 갈림은 「닫힌 문」이 가른다.
  • codex 의 상주 JSON-RPC(codex app-server)가 서면 그 행의 여러 칸이 한꺼번에 열린다 — 턴을 관측할 수 있게 되는 순간 세션 복원·턴 관측·구조화 챗이 같은 문으로 들어온다.

03중립 척추 · 두 제스처

만들기와 띄우기가 갈려 있다

에이전트를 만드는 것과 실제로 프로그램을 띄우는 것은 클릭 두 번으로 갈려 있다. 첫 클릭은 에이전트 목록 패널의 빈 곳을 우클릭해 폴더를 고른 뒤 명부에 「예약」 항목만 적어 둘 뿐이라, 이 시점에는 프로세스가 없다. 트리에 뜬 그 예약 노드를 더블클릭하거나 「활성화」를 눌러야 비로소 실제 CLI 가 뜬다.

우클릭 자리는 pane 배경이고 행 우클릭 메뉴가 아니다. 행을 우클릭하면 행 메뉴가 이겨서 상위 슬롯 메뉴가 아예 뜨지 않으므로(ADR-0064), 이 구분을 뭉개면 메뉴를 못 찾는다.

04중립 척추 · 스폰 사슬

CLI 한 줄이 슬롯에 닿기까지

05배선된 백엔드 · argv

실제로 띄우는 명령줄

claude cmd.exe /c claude [extra_args…] --session-id|--resume <sid> [--mcp-config <path>] [--allowedTools <패턴>…] codex cmd.exe /c codex --cd <고른 폴더> -s workspace-write -a on-request [extra_args…]
  • Windows 는 cmd.exe /c 를 한 겹 씌운다 — PATH 에 있는 그 이름이 실제 실행파일이 아니라 .cmd shim 이라서다(직접 띄우면 error 193 으로 죽는다). 실 경로를 찾아 부르지 않는 이유는 그 경로가 버전에 묶여 있고 CLI 가 스스로 업데이트해 옮기기 때문이다.
  • extra_args 자리가 백엔드마다 다르다 — 취향이 아니라 각 CLI 의 인자 문법에 딸린 결과다. claude 는 --allowedTools 가 variadic 이라 그 그룹을 맨 끝에 두고 extras 를 먼저 소진하며, codex 는 호출자가 우리 인자를 덮을 수 있게 extras 를 맨 마지막에 둔다.
  • claude 의 stream-json 갈래는 같은 줄에 -p --input-format stream-json --output-format stream-json --verbose 를 더한다 — 실행 파일과 세션·MCP·grant 인자는 터미널 갈래와 같다.
  • codex 는 우리가 발급한 sid 를 넘기지 않는다 — 「argv 에 절대 안 실린다」가 아니다. extra_args 는 그대로 통과하므로 호출자가 넣으면 실린다. 전용 테스트가 단언하는 것은 빈 extras 기준으로 sid 가 조립되지 않는다는 것이다.

06중립 척추 · 렌더 분기

override 가 먼저, 그다음 capability

슬롯에 무엇을 그릴지는 두 층으로 정해진다. 먼저 그 슬롯에 사람이나 LLM 이 걸어 둔 강제값(renderModeOverride)이 있는지 보고, 없을 때만 에이전트가 신고한 capability 한 칸으로 떨어진다. 그 칸이 「출력이 구조화되어 있나」다. 렌더러는 백엔드 이름을 한 번도 보지 않는다 — 그래서 새 백엔드가 들어와도 프론트는 안 바뀐다.

★ADR-0044 를 렌더 모드 우선순위의 근거로 인용하지 말 것★ — 그 ADR 은 JSON 모드 배선·StdioTransport 신설 결정이고 override 라는 낱말이 한 번도 안 나온다. 우선순위 정본은 ADR-0078 이다.

07중립 척추 · 닫힌 문

사람은 통과, LLM 은 정책이 닫는다

에이전트를 만드는 입구가 여럿이라, 「어느 백엔드를 만들 수 있나」를 입구마다 따로 적으면 반드시 어긋난다. 그래서 정책은 표 한 장이고 입구 셋이 그 표를 함께 본다. 표에 이름이 없는 백엔드는 열린 게 아니라 막힌 것이다(fail-closed). 문 하나는 낱말로 닫을 수 없다 — 프론트 레지스트리에 오른 항목은 사람 클릭과 LLM 호출이 같은 등록물이라, 낱말로 닫으면 사람 길까지 함께 닫힌다. 그래서 그 문만 호출자 축으로 갈랐다.

  • 오늘 닫혀 있는 것은 codex 의 LLM 창구다. codex 는 처음 보는 폴더에서 자기 신뢰 확인 모달을 띄우는데 사람이 아닌 호출자는 그 모달을 못 지난다 — 키를 넣어도 안 먹는다(실측 2026-09-07). 지금 열면 「만들 수는 있는데 쓸 수는 없는 에이전트」가 생긴다. 여는 시점 = Phase 2, codex 신뢰 확인 모달 처리가 정해질 때. 사람이 만드는 문은 그대로 열려 있다.
  • 「모르는 낱말」과 「아는데 이 표면이 안 만든다」는 다른 축이라 한 문구로 뭉치지 않는다 — 뭉치면 호출자가 있지도 않은 오탈자를 고치려 든다.
  • 코어 입구의 정책 팔은 오늘 발화하지 않는다 — 선언 어휘가 정책 표보다 좁아서 닫힌 낱말이 그 팔에 닿기 전에 역직렬화가 반려한다. ★그래도 지우지 말 것★ — 그 팔이 막는 편집은 「어휘를 넓히면서 정책 표는 안 넓히는 것」이고, 그 조합이 오는 날 유일한 런타임 방어가 된다.

08확장 축 · wire 계약

백엔드를 하나 늘리면 낱말이 네 곳에 선다

코어의 실행 명령 변형, 소켓으로 흐르는 wire 낱말, LLM 입구의 선언 어휘, 그리고 dispatch 배선이다. 넷 중 하나만 넓히면 나머지가 그 낱말을 모르는 채로 남는다 — gemini 가 「미배선」인 것이 그 상태다.

  • 변형 추가는 경성 파손이다 — 스폰 명령은 kind 태그로 갈리는 열거형이라 모르는 변형은 무시되지 않고 역직렬화 실패가 된다. 데몬이 셸 재빌드보다 오래 사는 것은 설계라서 「릴리스 상대가 없다」가 이 실패를 막아 주지 않는다. 그래서 PROTOCOL_VERSION 을 4 로 올렸다.
  • ★버전 인상의 값어치는 「분명한 거부」다★ — daemon.json 의 protocol_version 이 클라이언트와 다르면 판정이 살아있는 데몬을 spawn 으로 덮지 않고 DiscoveryError::VersionMismatch 로 실패한다. 그 판정이 보는 것은 같은지 다른지뿐이라 어느 쪽이 새것인지는 묻지 않는다. 안 올렸으면 두 빌드가 악수를 지나 서로 다른 낱말을 같은 것으로 읽었을 자리다.
  • 디스크는 통째로 파싱된다 — 모르는 kind 가 한 건이라도 있으면 그 한 건이 아니라 파싱 전체가 실패하고, 파일을 .corrupt 로 밀어낸 뒤 빈 명부로 부팅한다. 새 백엔드로 띄운 에이전트 하나가 나머지 전부를 데리고 사라진다. 이 하위호환은 개발 중이라 수용했고 재도입 트리거는 추적표에 걸려 있다(docs/tracking.md T-33).
  • backend 칸은 필수다 — 빈 칸을 데몬이 거절하고 어느 칸을 채우라는 문구까지 데몬이 낸다. 「안 적으면 claude」 같은 조용한 기본값을 두면 고르지 않은 것과 claude 를 고른 것이 구별되지 않는다.

09미검 · 부채

무엇이 미검인가

구조에 달린 한계

%VAR% 가 든 폴더 경로는 여전히 다른 폴더로 샌다 — cmd.exe 가 따옴표 안에서도 %NAME% 을 펴고, 알려진 해법이 일반적인 이스케이프가 아니라 미이식 상태다. 위 디스크 하위호환을 잡아 줄 미지 kind 회귀 테스트가 없다. 그리고 실 모델 턴이 측정되지 않았다 — 계약 시험대의 상시 레인은 선언표 대조뿐이고, 실 CLI 를 띄우는 레인은 #[ignore] 라 부를 때만 돈다.

굵은 결정 넷에 ADR 이 없다 — PROTOCOL_VERSION 4 인상 · wire enum 신설 · backend_session_id 하드 rename · 「사람만」 예외(humanOnly).
