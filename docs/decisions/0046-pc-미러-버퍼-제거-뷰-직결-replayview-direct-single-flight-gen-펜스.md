# ADR-0046: Remove the PC mirror buffer — view-direct replay + single-flight gen fence

- 상태: 확정 (2026-07-05, basis: medium research (grounding + Codex adversarial) + `/review trd deep` 3 rounds + user decision) · 부분 폐기 by ADR-0164 (the reconnect-trigger clause of decision 2)
- 관련: Supersedes ADR-0040 · Amends ADR-0037 (dedup/progress home clause: Rust alone → per-view in the webview) · Amends ADR-0007 (frontend epoch authority clause: SubscribeAck alone → src-tauri decide_epoch as first-pass filter + adopt the filtered frames/markers) · Amends ADR-0043 (deliverable gate mechanism: the mirror cursor gate is discarded → replaced by the view buffering phase + gen fence) · ADR-0029 (daemon data ownership) · ADR-0041/0042 (inherits BLOCK-1 and axis A) · TRD `docs/process/S16-view-direct-replay/view-direct-replay-trd.md`(rev4) · research 2026-07-05 · Amended by ADR-0164 (the reconnect-trigger clause of decision 2)

## 맥락
In the structure where the src-tauri relay hub mirrored the daemon ring (`AgentBufferStore`/`OutputViewStore`, ADR-0040) and fanned out with a per-view cursor, three sync bugs occurred in a row: lost reload replay (ca3f325), split/remount stall (23a8c47, a symptom fix via resync_output), and lost output when several slots share an agent (bug B — lastDeliveredSeq was per agentId). All three belong to one family: "the client mirrors a second copy of data the daemon already holds, then tries to keep the two in step". ADR-0040 justified keeping the mirror as "memory duplication is only ~2MB, so the gain is small", but it has been shown that the real cost was not memory but **sync complexity**. User decision (2026-07-05): on PC (loopback), remove the mirror and receive directly from the daemon; only mobile/remote cache (branching at the transport seam).

## 결정
1. **Remove the mirror entirely.** src-tauri = stateless router (reads only the frame header and passes the frame through to the Channel of each window in targets ∩ registered). `AgentBufferStore`/`OutputViewStore`/`BoundedSeqLog`/per-view cursor/`resync_output` are discarded.
2. **remount/reload/reconnect = replay the whole daemon ring again.** The wire keeps one subscription per agent, and every view mount re-emits `Subscribe{after_seq:None}` (daemon R1: Ack→replay→ReplayComplete FIFO unchanged). A view that is already live absorbs the duplicates with its per-view seq dedup.
3. **The only home of progress state = `lastDeliveredSeq` per webview view (slot).** No output progress (seq/cursor/buffer) in src-tauri — the only state allowed is request bookkeeping (epoch, single-flight).
4. **Replay boundary = in-Channel marker (tag=255) + single-flight gen fence.** src-tauri keeps one in-flight request per agent (lifetime sent→acked→completed, progress-based deadline, queue merging), maps Subscribe↔ReplayComplete 1:1, and stamps the gen. A view does a sort+dedup flush only on a successful marker whose gen is at least the gen that its own requestReplay returned. Detailed state machine = TRD rev4 §2.
5. **Gap policy: replay from the retention floor (current meaning kept).** Restoring beyond the floor is a non-goal — the source of truth for the conversation history is the claude session (`--session-id`/`--resume`, ADR-0008), which already preserves it, and when an agent restarts, claude re-emits the history and it accumulates again in the new epoch's ring.
6. **Mobile/remote caching = allowed only inside the transport implementation (a seat only).** The ProtocolClient interface is unchanged. **Caution: the consistency premise of the gen fence = every replay is full-from-oldest.** The moment partial resume by after_seq is introduced at the remote seam, this premise breaks, so the per-view marker correlation (exact gen match, etc.) must be strengthened first.

## 거부한 대안
- **Keep the mirror + refine the sync** — stacking one more layer on the structure that caused the three bugs (resync_output is the example). The answer to a sync bug is removing the sync, not refining it (explicit user do-not).
- **Per-view wire subscription (extend the protocol with a sub_id in the frame)** — the user-visible result is the same, but the knock-on rework across frame header, codec, daemon and both ends is large. The duplicate loopback transmission is absorbed for free by per-view dedup.
- **Single subscription + per-view one-shot catch-up merge** — the replay→live boundary merge is needed in every view, so the complexity of the current bug family remains (the user chose O1, 2026-07-05).
- **Daemon-side screen snapshot (the VS Code serialize approach)** — adds terminal-emulator-class functionality to the daemon = scope explosion. The substance of the truncated past (the conversation history) is already preserved by the claude session as the source of truth, so it would be a double investment (user decision).
- **Count-based coupling of the marker gen (stamp the last value / FIFO counting)** — broken by the review with evidence: the last value stamps a new gen onto someone else's Complete by mistake (premature flush loses data), and counting desyncs permanently on the failure path where Complete never arrives → endless re-requests. Replaced by the single-flight 1:1 mapping.
- **Absolute-time deadline** — false positives in a healthy-slow replay (debug build, contention) → a later Complete is mis-stamped onto the next gen. Replaced by a progress-based deadline (reset on every frame/Ack) + the acked gate.
- **Keeping a seq in src-tauri for after_seq resume (reconnect optimization)** — violates decision 3 (reintroduces progress state). The regression of a full replay on reconnect is accepted because PC loopback is local and reconnects are rare; remote is solved at the seam.

## 근거
- **Research (2026-07-05 medium, grounding + Codex adversarial review):** server (daemon) as the source of truth + a thin client is the industry norm (tmux/zellij/VS Code — in VS Code's three-tier structure of the same shape, the middle tier has only a 5ms batching send buffer and no mirror cache, confirmed in the source). A client cache is generally kept only for remote/offline reasons (wezterm mux prediction cache, Matrix mobile DB). But the final argument is not precedent but **our own cost comparison: mirror sync complexity (three bugs shown) > duplicate loopback transmission (~2MB cap)**.
- **`/review trd deep` 3 rounds (opus doc-aware ×3 + Codex blind):** confirmed in code by measurement that the daemon outbound is a single FIFO (text/binary in the same queue, ws.rs:519) and that resubscription is serialized (dispatch is serial + synchronous replay inside the lock). The BLOCKs of rounds 1–2 (uncorrelated marker → premature-flush loss, count-coupling desync) were resolved by the gen fence → single-flight, and the round-3 FIXes were applied (acked gate, progress deadline, no marker emitted on disconnect, the full-replay premise made explicit).

## 영향 / 불변식
- **Deleted:** the mirror part of `output_channel.rs`, `output_view_store.rs`, `output_view_buffer.rs`, `resync_output`, `ReplaySlots`/`DropSlots`, and the frontend `pendingBuffers`/`resubscribeAll`. The `ViewLayoutRenderer` duplicate workaround is removed (bug B resolved at the root).
- **BLOCK-1 applied everywhere (strengthens ADR-0041):** the frontend does not send wire Subscribe/Unsubscribe by any path (the old reconnect exception is deleted). The wire subscription is formed by request_replay alone, and cleaned up by the router's Unsubscribe alone. **But BLOCK-1 (the frontend must not send wire Subscribe) is limited to the src-tauri hub path (TauriTransport)** — the direct-daemon carrier (WsTransport, legacy/test only) has one connection = one subscription, so the storm premise does not exist, and it forms replay with its own wire Subscribe (not the production carrier, clientFactory.ts:24).
- **Daemon unchanged** — R1, frame format and codec stay as they are (preserves the single lossless stream per agent and viewer-agnosticism).
- **Reconnect = full replay (regression accepted)** — more bandwidth than the old tail-resume. The grounds for accepting it on PC are above. When a remote carrier is introduced, redesign at the seam.
- **mid-replay drop (daemon outbound saturation Error) = a limit equal to today's** — today's code does not consume it either. Promoting it to a failure marker after the daemon Error is attributed is backlog.
- Implementation gate: coder high · `/review code deep` · `/qa full` (cdp: including the bug B repro case). Put a `// ADR-0046` anchor in new code.
