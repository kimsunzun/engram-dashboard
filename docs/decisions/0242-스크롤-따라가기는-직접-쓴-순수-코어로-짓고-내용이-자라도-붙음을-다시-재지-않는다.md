# ADR-0242: 스크롤 따라가기는 직접 쓴 순수 코어로 짓고 내용이 자라도 붙음을 다시 재지 않는다

- 상태: 확정 (2026-09-27, 근거: 사용자 결정 U3 · U4 (TRD `docs/process/S21-chat-ux/trd.md` §1) + 메인 판정 ⑤ (TRD §11) + TRD 5판 리뷰 FIX 반영(TRD §12) · 구현 전 · 코드 무변경)
- 관련: TRD `docs/process/S21-chat-ux/trd.md`(§1 U3 · U4 · §2 · §4-5 · §7 FE-1.1 · FE-1.3 · §8-2 F1 · §9 F1 · §10 0242 · §11 ⑤) · 조사 `docs/research/chat-ux-four-features-2026-09-27.md`(§1 — 지금 코드 §1-1 · 피어 §1-2 · 선택지 §1-3) · ADR-0239(도구 묶음 펼침 — 결정 7 의 맞물림) · ADR-0053(ScrollArea seam) · ADR-0056(탭 keep-alive — 숨은 탭) · ADR-0012(시험대 — 코어 · 훅 seam) · ADR-0167(`help` 없는 창 명령) · step-log S21

## 맥락
오늘 두 슬롯(RichSlot · DomSlot)은 내용이 바뀔 때마다 **무조건** `scrollTop = scrollHeight` 를 쓴다(`src/components/slot/RichSlot.tsx:101` · `:288-291` · `src/components/slot/DomSlot.tsx:81` · `:180-185` · `:194-197`). 사용자가 위로 올려 읽는 중인지를 보지 않는다. 챗 화면 4건 중 스크롤 따라가기는 이것을 「바닥에 붙어 있을 때만 따라가고, 사용자가 위로 가면 놓는다」로 바꾼다.

풀기 어려운 자리는 **성장**이다 — 스트리밍으로 내용이 자라는 순간 붙음을 다시 재면 그 성장이 「위로 올렸다」로 읽힌다(조사 §1-3). 탭이 `display:none` 으로 숨을 때(ADR-0056 keep-alive) 재는 값이 무효가 되는 것도 같은 부류다.

## 결정
표기 — **[사용자]** = 사용자가 답한 결정 · **[메인]** = 오케스트레이터 판정 · **[고름]** = TRD 가 고른 내부 구현.

1. **공용 훅 하나 + DOM 없는 순수 코어를 직접 쓴다.** 두 슬롯의 무조건 효과를 지우고 `useScrollFollow(slotId)`(새 `src/components/slot/scrollFollow/useScrollFollow.ts`)를 쓴다. 판정은 순수 함수 `step(state, input) -> { state, scrollTo }`(새 `…/scrollFollow/followCore.ts` — DOM 0)가 한다. 입력 = `attach` · `scroll` · `resize` · `intentUp` · `pin` · `unpin`.
2. **붙음 플래그는 스크롤 이벤트와 위로 가는 입력으로만 바뀐다 — ★성장(`resize`)은 붙음을 다시 재지 않는다★.** 붙어 있으면 바닥(`max(0, height − client)`)으로 쓰고, 떨어져 있으면 `unseenGrowth = true` 만 적는다. 코어 규칙(TRD §2-2 의 표가 시험 표다):
   - **우리 쓰기는 절대 풀지 않는다** — `scroll` 의 위치가 우리가 예고한 값(`expectTop`)과 1px 안이면 기록만 옮긴다. 쓰기 예고는 실제로 움직일 때(`> 0.5px`)만 남긴다 — 이미 그 자리면 이벤트가 안 와 남은 예고가 뒤의 사용자 스크롤을 우리 것으로 오인할 수 있다.
   - **사용자 스크롤** — 붙어 있을 때는 바닥 거리가 문턱을 넘고 **위로 움직였을 때만** 푼다(문턱 안의 위 움직임은 내용 줄어듦의 클램프일 수 있다). 떨어져 있을 때 되붙기는 **아래로 움직여 문턱 안에 든** `scroll` 에서만이다 — ★위 의도 걸쇠★: 문턱 안의 작은 위 휠이 `intentUp` 으로 푼 뒤, 그 휠이 만든 `scroll`(위로 · 문턱 안)이 곧바로 되붙이지 않게 한다. 그 밖에 걸쇠를 푸는 길은 명시 `pin`(버튼 · 보냄 · 비우기 · 명령)뿐이다.
   - **위로 가는 입력**(`intentUp` — 휠 `deltaY < 0` · `PageUp` · `Home` · `ArrowUp`) — 스크롤할 것이 있으면 곧바로 푼다. 그래야 성장이 끌어내리지 않는다.
   - **얼음 · 풀림** — `client === 0`(숨은 탭)이면 얼고 `savedTop = expectTop ?? lastTop`(그 순간의 `top` 은 이미 무효일 수 있다). 얼어 있는 동안 스크롤·RO·`intentUp` 은 칸을 안 바꾸고 `pin`·`unpin` 은 붙음만 바꾼다. 풀릴 때 붙어 있으면 바닥으로, 떨어져 있으면 `savedTop` 으로 되살린다 — `display:none` 을 지나 `scrollTop` 이 보존되는지 모르므로 되살리기를 늘 건다(보존되면 무동작).
   - [고름] 문턱 `FOLLOW_THRESHOLD_PX = 48` — 피어 범위 40–64 의 가운데(t3code 40 · paseo 64).
3. **훅은 슬롯 코드에 기대지 않는다.** [고름]
   - `viewportRef` · `pin` · `unpin` 은 렌더마다 같은 함수다(코어 상태 · 노드를 ref 에 둔다). ★그래서 구독 효과 deps `[viewId, agentId]` 에 넣지 않는다★ — 넣으면 손잡이 정체성이 흔들릴 때 재구독 → replay 가 돈다.
   - 콜백 ref 라 뷰포트가 새 노드로 붙어도 옛 청취자·관찰자를 떼고 새 노드에 `attach` 를 먹인다.
   - ResizeObserver 둘 = 뷰포트 자신과 **뷰포트의 첫 자식 요소**(Radix 내용 래퍼). [고름] 내용 ref 를 StructuredTextView·`<pre>` 로 내려보내지 않는다 — 두 슬롯이 손대지 않고 같은 훅을 쓴다(대가 = Radix 내부 구조에 기댄다 · 영향).
   - 휠 · 키 청취자는 **뷰포트에만** 건다 — 전역 청취자를 걸지 않는다. 가장 가까운 `[data-radix-scroll-area-viewport]` 가 이 뷰포트가 아니면서 `scrollTop > 0` 이면 안쪽 스크롤러(ThoughtRow 의 자기 ScrollArea)가 먹는 입력이라 무시한다.
   - 관측 표면 = 뷰포트의 `data-scroll-follow="pinned" | "free"`(훅이 직접 적는다). 시험 seam = `useScrollFollow(slotId, { ResizeObserver? })`(ADR-0012).
   - 구독 초기화와 비우기(onReset)에서 `follow.pin()` — 비운 뒤 오는 이력이 바닥에 착지한다.
4. **「맨 아래로」 버튼 = 바닥이 아니면 늘** [사용자 U3] — 셰브론(lucide `ChevronDown`) · 개수 없음 · `!pinned` 이 150 ms 이어지면 보인다(t3code — 탭 전환 깜빡임 방지) · 누르면 즉시 `pin()`(부드러운 스크롤은 중간 이벤트를 만든다). 상수 `JUMP_BUTTON_MODE: 'whenFree' | 'whenUnseen' = 'whenFree'`.
5. **보내면 다시 바닥에 붙는다** [사용자 U4] — RichSlot `send` 에서 `if (REPIN_ON_SEND) follow.pin()`(상수 `REPIN_ON_SEND = true`).
6. **LLM 경로 = 명령 `slot.scrollToBottom { slotId }`**(새 `src/commands/scrollCommands.ts`) — ★`help` 없음★: 스크롤 위치는 창마다 따로 있는 프론트 상태다(`renderModeCommands.ts:8-20` · ADR-0167). 손잡이는 모듈 맵 `followRegistry.ts`(`Map<slotId, FollowHandle>` — 훅이 마운트 때 올리고 내릴 때 **자기 손잡이일 때만** 지운다 · StrictMode 이중 마운트) · 새 전역 핸들 없음. 손잡이가 없으면 throw · 돌려주는 값 `{ pinned: true }` · 숨은 탭이면 붙음만 세우고 쓰기는 보일 때 한다. 읽기 = DOM 속성 `data-scroll-follow`.
7. **사람이 마지막이 아닌 도구 묶음을 펼치면 따라가기를 푼다** [메인 ⑤ 수락 · t3code 선례] — `StructuredTextView` 의 `onGroupToggle(isLast)` 가 `follow.unpin()` 을 부른다. 마지막 묶음 토글은 붙음을 그대로 둔다. 푼 뒤는 결정 2 의 걸쇠가 지킨다.

## 거부한 대안
- **`use-stick-to-bottom` 라이브러리** — Radix 휠 불일치가 의심되고 전역 청취자를 건다(조사 §1-2).
- **CSS 만** — 「상태가 없다」(조사 §1-3). 비교는 조사 §1-2 · §1-3 에 있다.
- **가상화** — 「지금 필요 없다」(조사 §1-3).
- **성장마다 붙음을 다시 잰다** — 스트리밍 성장이 「위로 올렸다」로 읽힌다(조사 §1-3 · TRD §2-2 규칙 6).
- **버튼을 위로 올린 동안 새 내용이 왔을 때만 보인다**(`'whenUnseen'`) [사용자 U3 — 「바닥이 아니면 늘」을 골랐다] — 피어 전부가 추천안이다(조사 §1-2). 이 대안은 「읽다 멈춘 자리」에서 버튼이 안 떠 돌아갈 길을 못 찾는다. 상수 하나로 되돌릴 수 있다(코어의 `unseenGrowth` 를 버튼 조건에 건다).
- **보내도 스크롤을 그대로 둔다** [사용자 U4 — 「붙는다」를 골랐다] — 붙지 않으면 위를 읽다 보낸 글의 답이 화면 밖에서 흐른다. 붙는 쪽의 대가 = 읽던 자리를 잃는다(paseo 선례 = 붙는다).
- **내용 ref 를 StructuredTextView·`<pre>` 로 내려보낸다** [고름] — 두 슬롯 수정이 필요하다(TRD §2-3 · §9).
- **마지막이 아닌 묶음을 펼쳐도 붙음을 둔다**(지시 「RO 가 처리한다」 그대로) [메인 ⑤] — 붙은 채 위쪽 묶음을 펼치면 바닥으로 다시 내리면서 누른 머리가 화면 위로 밀려난다(Claude Code 가 2.1.83 에서 고친 「스크롤이 튄다」와 같은 부류 — 조사 §3-2).

## 영향 / 불변식
- **구독 effect deps 는 `[viewId, agentId]` 그대로**(CLAUDE.md 「통합 micro-rules」) — `follow`·`pin` 을 넣지 않는다(결정 3).
- **내용 노드 = Radix 첫 자식** — Radix 가 래퍼 구조를 바꾸면 성장을 못 본다(뷰포트 RO 는 계속 돈다). 증상 = 스트리밍이 바닥에 안 붙음 → 훅 시험이 첫 자식 부재를 경고로 남긴다(TRD §9).
- **제어 표면 하나** — 레지스트리 명령 · 모듈 맵 · DOM 표지. 새 전역 핸들 없음(CLAUDE.md 「LLM-우선 제어」).
- **알려진 한계(고치지 않는다 — TRD §2-6)** — DomSlot 머리 자르기(200 KB · `DomSlot.tsx:36` · `:142`)로 떨어져 읽는 동안 앞이 잘리면 본문이 위로 밀린다(표류). 글자를 끌어 선택하는 중 · 스크롤바를 문턱 안에서 끄는 중의 성장은 바닥으로 끌린다 — 거슬리면 `pointerdown` 을 의도 입력으로 더한다(후보).
- **기존 슬롯 시험은 회귀로 그대로 돈다** — 무조건 스크롤을 단언하는 시험이 없다(`rg scrollTop src --glob '*.test.*'` 의 슬롯 쪽 적중은 RO 가짜뿐).
- **도구 묶음 펼침 · 접힘 · 자동 접힘으로 높이가 바뀌면** 내용 RO 가 받는다 — 붙어 있으면 바닥으로 간다(ADR-0239).
