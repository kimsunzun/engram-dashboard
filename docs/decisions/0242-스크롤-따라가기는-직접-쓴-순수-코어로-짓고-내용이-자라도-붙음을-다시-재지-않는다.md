# ADR-0242: Scroll-follow is built on a hand-written pure core and does not re-measure the pinned state when content grows

- 상태: 확정 (2026-09-27, basis: user decisions U3 · U4 (TRD `docs/process/S21-chat-ux/trd.md` §1) + main decision ⑤ (TRD §11) + TRD 5th-edition review FIX applied (TRD §12) · before implementation · no code changed)
- 관련: TRD `docs/process/S21-chat-ux/trd.md`(§1 U3 · U4 · §2 · §4-5 · §7 FE-1.1 · FE-1.3 · §8-2 F1 · §9 F1 · §10 0242 · §11 ⑤) · research `docs/research/chat-ux-four-features-2026-09-27.md`(§1 — current code §1-1 · peers §1-2 · options §1-3) · ADR-0239(tool-group expansion — interlocks with decision 7) · ADR-0053(ScrollArea seam) · ADR-0056(tab keep-alive — hidden tabs) · ADR-0012(test bench — core · hook seam) · ADR-0167(window command without `help`) · step-log S21

## 맥락
Today the two slots (RichSlot · DomSlot) write `scrollTop = scrollHeight` **unconditionally** every time content changes (`src/components/slot/RichSlot.tsx:101` · `:288-291` · `src/components/slot/DomSlot.tsx:81` · `:180-185` · `:194-197`). They do not check whether the user has scrolled up to read. Of the four chat-screen items, scroll-follow changes this to 「바닥에 붙어 있을 때만 따라가고, 사용자가 위로 가면 놓는다」.

The hard part is **growth**: if the pinned state is re-measured at the moment streaming content grows, that growth reads as 「위로 올렸다」 (research §1-3). The measured values becoming invalid when a tab is hidden with `display:none` (ADR-0056 keep-alive) is the same kind of problem.

## 결정
Notation — **[사용자]** = a decision the user answered · **[메인]** = an orchestrator decision · **[고름]** = an internal implementation the TRD chose.

1. **Write one shared hook plus a pure core with no DOM.** Remove the unconditional effects of the two slots and write `useScrollFollow(slotId)` (new `src/components/slot/scrollFollow/useScrollFollow.ts`). The decision is made by the pure function `step(state, input) -> { state, scrollTo }` (new `…/scrollFollow/followCore.ts` — zero DOM). Inputs = `attach` · `scroll` · `resize` · `intentUp` · `pin` · `unpin`.
2. **The pinned flag changes only on scroll events and upward inputs — ★growth (`resize`) does not re-measure the pinned state★.** When pinned, write to the bottom (`max(0, height − client)`); when detached, only record `unseenGrowth = true`. Core rules (the table in TRD §2-2 is the test table):
   - **Our own writes never unpin** — if the position of a `scroll` is within 1px of the value we announced (`expectTop`), only move the record. A write is announced only when it actually moves (`> 0.5px`) — if it is already at that spot no event arrives, and the leftover announcement could mistake a later user scroll for ours.
   - **User scroll** — while pinned, unpin only when the distance from the bottom exceeds the threshold **and it moved up** (an upward move within the threshold may be the clamp from content shrinking). While detached, re-pinning happens only on a `scroll` that **moved down and entered the threshold** — ★upward-intent latch★: after a small upward wheel within the threshold unpins through `intentUp`, the `scroll` that wheel produces (upward · within the threshold) must not re-pin right away. The only other way to release the latch is an explicit `pin` (button · send · clear · command).
   - **Upward input** (`intentUp` — wheel `deltaY < 0` · `PageUp` · `Home` · `ArrowUp`) — unpin right away if there is something to scroll. That way growth does not drag the view down.
   - **Freeze · thaw** — when `client === 0` (hidden tab) it freezes and `savedTop = expectTop ?? lastTop` (the `top` at that moment may already be invalid). While frozen, scroll · RO · `intentUp` do not change the fields, and `pin` · `unpin` change only the pinned state. On thaw, if pinned it goes to the bottom, and if detached it is restored to `savedTop` — since it is unknown whether `scrollTop` is preserved across `display:none`, the restore is always attempted (a no-op if preserved).
   - [고름] Threshold `FOLLOW_THRESHOLD_PX = 48` — the middle of the peer range 40–64 (t3code 40 · paseo 64).
3. **The hook does not depend on slot code.** [고름]
   - `viewportRef` · `pin` · `unpin` are the same function on every render (the core state and node live in a ref). ★So they are not put in the subscription effect deps `[viewId, agentId]`★ — putting them in would resubscribe when the handle identity wobbles, and the replay would run.
   - Because it is a callback ref, even when the viewport attaches to a new node, the old listeners and observers are detached and `attach` is fed to the new node.
   - Two ResizeObservers = the viewport itself and **the first child element of the viewport** (the Radix content wrapper). [고름] The content ref is not passed down to StructuredTextView · `<pre>` — the two slots use the same hook without being touched (the cost = relying on Radix's internal structure · Impact).
   - Wheel · key listeners are attached **only to the viewport** — no global listener is attached. If the nearest `[data-radix-scroll-area-viewport]` is not this viewport and has `scrollTop > 0`, the input is consumed by an inner scroller (ThoughtRow's own ScrollArea), so it is ignored.
   - Observation surface = `data-scroll-follow="pinned" | "free"` on the viewport (the hook writes it directly). Test seam = `useScrollFollow(slotId, { ResizeObserver? })` (ADR-0012).
   - `follow.pin()` on subscription init and on clear (onReset) — history that arrives after the clear lands at the bottom.
4. **The 「맨 아래로」 button = always shown when not at the bottom** [사용자 U3] — chevron (lucide `ChevronDown`) · no count · shown once `!pinned` has lasted 150 ms (t3code — prevents flicker on tab switch) · ★but only when there is content to scroll (`scrollable` = `height − client > 0.5`) — if all content fits, that spot is already the bottom★ (an addendum that follows U3 as is · `/review code` finding 2026-09-28 · the pinning rule (decision 2) is unchanged) · pressing it calls `pin()` immediately (smooth scrolling produces intermediate events). Constant `JUMP_BUTTON_MODE: 'whenFree' | 'whenUnseen' = 'whenFree'`.
5. **Sending re-pins to the bottom** [사용자 U4] — in RichSlot `send`, `if (REPIN_ON_SEND) follow.pin()` (constant `REPIN_ON_SEND = true`).
6. **LLM path = command `slot.scrollToBottom { slotId }`** (new `src/commands/scrollCommands.ts`) — ★no `help`★: scroll position is frontend state that each window has separately (`renderModeCommands.ts:8-20` · ADR-0167). The handle is the module map `followRegistry.ts` (`Map<slotId, FollowHandle>` — the hook registers it on mount and, on unmount, removes it **only when it is its own handle** · StrictMode double mount) · no new global handle. Throws if there is no handle · the return value is `{ pinned: true }` · for a hidden tab it only sets the pinned state, and the write happens when it becomes visible. Reading = the DOM attribute `data-scroll-follow`.
7. **When a person expands a tool group that is not the last one, follow is released** [메인 ⑤ accepted · t3code precedent] — `StructuredTextView`'s `onGroupToggle(isLast)` calls `follow.unpin()`. Toggling the last group leaves the pinned state as is. After release, the latch of decision 2 guards it.

## 거부한 대안
- **The `use-stick-to-bottom` library** — a Radix wheel mismatch is suspected and it attaches a global listener (research §1-2).
- **CSS only** — 「상태가 없다」 (research §1-3). The comparison is in research §1-2 · §1-3.
- **Virtualization** — 「지금 필요 없다」 (research §1-3).
- **Re-measure the pinned state on every growth** — streaming growth reads as 「위로 올렸다」 (research §1-3 · TRD §2-2 rule 6).
- **Show the button only when new content arrived while scrolled up** (`'whenUnseen'`) [사용자 U3 — chose 「바닥이 아니면 늘」] — all peers use the recommended option (research §1-2). This alternative shows no button at 「읽다 멈춘 자리」, so the user cannot find the way back. It can be reverted with one constant (hang the core's `unseenGrowth` on the button condition).
- **Leave the scroll as is when sending** [사용자 U4 — chose 「붙는다」] — without pinning, the reply to a message sent while reading higher up flows off screen. The cost of the pinning side = losing the place being read (paseo precedent = pins).
- **Pass the content ref down to StructuredTextView · `<pre>`** [고름] — it requires modifying the two slots (TRD §2-3 · §9).
- **Keep the pinned state even when a group that is not the last is expanded** (the instruction 「RO 가 처리한다」 as is) [메인 ⑤] — expanding an upper group while pinned moves back down to the bottom and pushes the head that was clicked off the top of the screen (the same kind as the 「스크롤이 튄다」 that Claude Code fixed in 2.1.83 — research §3-2).

## 영향 / 불변식
- **The subscription effect deps stay `[viewId, agentId]`** (CLAUDE.md 「통합 micro-rules」) — do not put `follow`·`pin` in (decision 3).
- **Content node = the first child of Radix** — if Radix changes the wrapper structure, growth is not seen (the viewport RO keeps running). Symptom = streaming does not stick to the bottom → the hook test leaves a warning when the first child is absent (TRD §9).
- **One control surface** — registry command · module map · DOM marker. No new global handle (CLAUDE.md 「LLM-우선 제어」).
- **Known limitation (not fixed — TRD §2-6)** — when DomSlot's head truncation (200 KB · `DomSlot.tsx:36` · `:142`) cuts the front while reading detached, the body shifts up (drift). Growth while dragging to select text · while dragging the scrollbar within the threshold is pulled to the bottom — if it bothers, add `pointerdown` as an intent input (candidate).
- **Existing slot tests run unchanged as regression** — no test asserts the unconditional scroll (the slot-side hits of `rg scrollTop src --glob '*.test.*'` are only RO fakes).
- **When a tool-group expand · collapse · auto-collapse changes the height**, the content RO receives it — if pinned, it goes to the bottom (ADR-0239).
