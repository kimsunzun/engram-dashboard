## 맥락
The dashboard must attach a mode (RichSlot) that renders claude output as structured (JSON). Measurement shows `--output-format stream-json` and `--input-format stream-json` are **`-p` (print/headless) only** (stated explicitly in claude 2.1.170 `--help`: "only works with --print"). That is, today's PTY interactive claude cannot emit JSON, and what is needed is not "swap the terminal renderer for a JSON renderer" but **a separate path in which the way the process is launched itself differs**. The problem: how do we make this path coexist with the existing pipeline (OutputCore → codec → daemon → frontend)?

## 결정
The strategy "**mode = swapping the transport; the channel stays unrefined to the end (a dumb pipe)**".

1. **Add StdioTransport** — a new variant that implements the `AgentTransport` trait with a child process without a PTY (stdin/stdout pipes). Terminal mode stays with the existing `PtyTransport`. Only the transport is swapped in the same `AgentSession` assembly.
2. **Shared channel (zero changes)** — JSON output (NDJSON) is already serialized bytes, so the wire gives it no special treatment. `OutputCore` (subscribe · replay · seq · finalize) · the wire codec (`OutputChunk` = seq + bytes, the existing frame tag) · the daemon `WsOutputSink` · the frontend `transport.ts`/`protocolClient` are all reused as they are. Replay also works as is (parsing the whole byte history = conversation restore).
3. **Branching only at three points at the two ends** — ① assembly: the backend looks at the mode and builds the `CommandSpec` arguments (`-p --input-format stream-json --output-format stream-json --session-id <sid>`) + `AgentManager` chooses StdioTransport ② capability: the transport ⊕ backend composition declares output = structured (ADR-0030) ③ frontend: the slot looks at caps and branches xterm (TerminalSlot) vs RichSlot, and RichSlot goes bytes → lines → parsing.
4. **Multi-turn = a persistent process (Mechanism A)** — keep one `claude -p` process for the lifetime of the session, and inject user turns into stdin as `{"type":"user",...}` JSON lines. JSON wrapping lives only in `backend/claude.rs` (ADR-0004 claude knowledge isolation) — the frontend and the channel know only text/bytes.
5. **Use `--replay-user-messages`** — claude echoes the user turn back into the output stream → the frontend renders user + assistant from the output stream as the single source, without optimistic local state.
6. **MVP scope = text input/output only** — the backend does not peek into the JSON (state = only whether the process is alive or dead). The tool-permission approval UI · partial delta streaming · resume restore consistency · interrupt (stdio has no PTY Ctrl-C — method unconfirmed) come later.

## 거부한 대안
- **JSON output from PTY interactive (swap only the renderer)** — impossible. That `stream-json` is `-p`-only is confirmed by measurement (stated in claude `--help`). The starting point of this ADR.
- **Relaunch per turn (Mechanism B, `claude -p --resume <sid>` every turn)** — process startup cost every turn + no intervention while processing (injecting guidance). It has the advantage of reusing the existing controlled-sid/resume infrastructure (ADR-0008), but is unnatural for interactive UX. The unconfirmed point of A (the tool permission wire) is not stepped on because the MVP is a text chat only.
- **Add a typed structured variant to the wire (a new frame tag + extending OutputEvent/OutputChunk/codec/daemon/frontend)** — all 10 seams from backend spawn to frontend render would have to be touched, with zero MVP gain (interpreting the content is the frontend's job anyway). Reconsider at the point where the backend has to handle control events (permission requests, etc.) as types — even then, putting a line tap in the transport pump could keep the wire unchanged.

## 근거
- **Measurement spike (2026-07-02):** claude 2.1.170 `--help` — both `--output-format`/`--input-format` state "only works with --print". `--input-format stream-json` = multi-turn on a persistent process via stdin JSON lines (official headless docs: "without relaunching the claude binary"). The `--replay-user-messages` input-echo flag exists.
- **Backend seam mapping:** keeping the channel dumb shrinks the change to assembly (SEAM 1) · caps (SEAM 5) · renderer branching (SEAM 10) + the new StdioTransport — in contrast to the typed wire option (all of SEAM 1~10).
- **Lab verification:** the `src/lab/richslot/` parser (`parse.ts`) and 5 layouts already work with a measured fixture (stream-json capture) — proving the frontend can own parsing.
- User approval: "일단 이 배선으로 ㄱ" (the 2026-07-02 session).

## 영향 / 불변식
- **The channel stays unrefined (invariant)** — `OutputCore` · codec · daemon · frontend transport do not interpret the byte content even in JSON mode. JSON knowledge exists only on the producing side (claude), the wrapping side (`backend/claude.rs`), and the drawing side (the RichSlot parser). If violated (inserting JSON parsing into the channel), the swappable principle (ADR-0002) and seam isolation break. **(→ amended by ADR-0045: 'the channel stays unrefined' now applies only to the transport layer. OutputCore/buffer/codec/daemon carry the typed `OutputEvent` as a payload-generic, and parsing is owned by `backend/claude.rs` (the frontend RichSlot parser is removed). The swappable principle is kept through payload polymorphism.)**
- **Input wrapping = the backend alone** — if the `{"type":"user",...}` schema leaks outside `backend/claude.rs`, it violates ADR-0004.
- **StdioTransport caps** — honestly declare it cannot resize and is not terminal_bytes (it has no terminal concept). These caps are the only basis for the frontend renderer branching (ADR-0002).
- **MVP limits stated** — no interrupt support (kill only) and no permission approval (text chat only) are *intentionally unimplemented*. A follow-up task must not misread them as a "defect" and patch the channel — on extension, follow the path of a pump line tap + reconsidering a typed variant if needed. **(→ ADR-0045 executes this extension path: backend parsing + wiring the typed variant as a binary frame tag. "No patching the channel" remains valid limited to the transport layer — the backend does the refinement and the codec tag does the wire.)**
