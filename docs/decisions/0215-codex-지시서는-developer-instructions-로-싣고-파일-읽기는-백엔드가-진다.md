# ADR-0215: The codex instruction document is carried in developer_instructions, and the backend carries the file reading

- 상태: 확정 (2026-09-20, basis: `docs/research/codex-instruction-injection-2026-09-20.md` — the canonical source for method and figures, not copied here) · 부분 폐기 by ADR-0219 (the clause blocking codex on the LLM creation surface)
- 관련: ADR-0004(backend extension) · ADR-0210(do not fail the spawn) · ADR-0209 · ADR-0211(measured the same 8,191 wall first and is the decision that shrank the instruction document to this size) · ADR-0092(the original decision of the priming seam — this ADR does not violate it) · `crates/engram-dashboard-agent/src/backend/claude/mod.rs:238` · Amends ADR-0099 (codex carries content instead of a path) · Amended by ADR-0219 (the clause blocking codex on the LLM creation surface) · Amends ADR-0092 (the backend reads the priming content)

## 맥락

claude receives the instruction document through `--append-system-prompt-file <절대경로>` — the daemon passes **only the path** and does not read the content (ADR-0092). codex has no **appending** counterpart, so it could not receive the instruction document (`model_instructions_file`, which takes a path, exists but is a full replacement), and as a result the state ADR-0209 meant to prevent was reproduced **by ignorance, not by wiring**: codex read the request envelope and **answered in its own chat window and stopped** (measured — only when we wrote 「`eg_send` 로 답해라」 ("answer with eg_send") in the body did it call the tool). The sender waits forever.

The previous session **recorded no** to 「codex 에 경로로 지시서를 주는 수단이 있는가」 (is there a means of giving codex an instruction document by path), but that judgment was wrong — the rationale section below writes up how that happened.

## 결정

1. **The codex instruction document is carried in `developer_instructions`.** The value is a string (codex has no `developer_instructions_file` — ★it is rejected with `unknown configuration field` when `--strict-config` is attached. Without that flag it is silently ignored, so do not read silence as 「있다」 (it exists)★).
2. **The reader is the codex backend.** The daemon's priming provider keeps its current shape of emitting **only the path**, and `ControlEndpoint.priming_file` is left as it is. This is the place of ADR-0004, which gathers backend-specific knowledge in `backend/` alone, and claude's **argv and behavior are unchanged** — but since `open_spawn` was widened to take a `ControlEndpoint`, the claude-side signature also ends up taking one more argument (it is not that 「한 글자도 안 바뀐다」 ("not one character changes")).
3. **The carrier differs per mode.** app-server = the dedicated field `developerInstructions` of `thread/start`. Terminal = `-c developer_instructions='<한 줄>'`. The same value and the same meaning going to different slots is an existing pattern in this repository (the working folder splits the same way).
4. ★**Terminal mode checks before loading, and if it cannot load, it only leaves a warning and the spawn proceeds**★ — size (command-line limit of 8,191 characters) · single quote · newline · `%`. It inherits as it is ADR-0210 decision 4's 「어떤 갈래로도 스폰을 실패시키지 않는다」 ("do not fail the spawn on any branch").
5. **Read failure is fail-open.** If the priming file is missing or cannot be read, injection is skipped and it spawns. The instruction document is nice to have and the spawn is mandatory.
6. ★**Do not put contradictory text into two slots at the same time.**★ Use only one slot at a time.
7. ★**The app-server instruction document is taken only once, at `thread/start`**★ — if a different value is carried on resume or fork, it is **ignored with no error and no warning** and the first value is kept (fork inherits the parent's). **To swap the instruction document of a live agent, it is not a resume but a new thread.** So we do not carry this field on a resume request — not because it is absent (`ThreadResumeParams` and `ThreadForkParams` both have this field), but because **it has no effect**.

## 거부한 대안

- **Load it into the system prompt slot with `model_instructions_file`** — ★**Rejection = document comparison**★. It takes a path (measured: absolute path · 1MB lossless) and lands in the real `instructions` field, but it is a **full replacement**, so we would have to take codex's default prompt of 17,174 characters (tool usage · sandbox conventions · output format) and prepend it, and it **goes stale with every codex version.** There is no reason to pay that price — the OpenAI API reference writes the `instructions` parameter as **「`developer` 역할 텍스트 입력과 동등」** ("equivalent to a developer-role text input"), and in the model spec's authority ladder both are the **Developer** layer. **The authority gain is 0 and only the drift burden arises.** ★But this rejection is conditional★ — **once the size check of decision 4 actually starts emitting a skip warning in terminal mode**, this alternative comes back to life (because of the one property that it takes a path). The 8,191 budget is shared with the policy flags, the passthrough and the hook override, so the judgment is not the document size but **that warning**. Current headroom = 1,686/8,191.
- **`AGENTS.md` · `project_doc_fallback_filenames` absolute path** — ★**Rejection = measurement + documents**★. It is the only slot that takes a path and appends, but it lands in the **`user` role**, so its authority is **one grade lower**. In addition ① the default ceiling is 32,768 bytes (cut with no marker) ② if the workspace has an `AGENTS.md`, our fallback is **ignored with no signal** ③ if we win with `AGENTS.override.md`, then **the user's own `AGENTS.md` dies entirely** ④ the absolute-path usage is **not in the official documents** (the documents speak only of "file names"). ★Even so, this slot has one living use★ — **it is read once at session start and put into the record, so it persists even if written and deleted right away** (measured: after turn 1, with both modification and deletion, turn 2 kept the original). If a path to inject through a temporary file becomes necessary, use this property.
- **Have N markdown files each read with `$스킬이름` mentions** — ★**Rejection = measurement**★. It works (a 30,368-byte file goes in whole without truncation, and if several are called each accumulates as a separate block — **the only means where we need not merge them ourselves**). But ① it again lands in the **`user` role** ② **in terminal mode there is no means at all to add a root** (RPC only) ③ that RPC is **process-global**, so agents attached to one app-server **overwrite each other's instruction documents** (measured: thread 1 inherited thread 2's root on its next turn) ④ if the same skill is called repeatedly, it **keeps piling up** in the history ⑤ the document itself writes that RPC as 「예고 없이 바뀔 수 있다」 (may change without notice).
- **Put it in through the `additionalContext` of a `SessionStart` hook** — rejected. ★**Do not write it as 「훅은 신뢰 게이트라 못 쓴다」 ("a hook is a trust gate so it cannot be used") — ADR-0210 already registers the hook and obtains trust through the TUI review**★. The living rejection reasons are two: ① ADR-0210 decision 6 places hook registration in **terminal mode only**, so the app-server half is not covered ② trust arrives **only after the user approves once**, so the first spawn's instruction document is not guaranteed. The road of computing the hash ourselves was already rejected by ADR-0208·0210.
- **Split `CODEX_HOME` per agent and carry it in `config.toml` or a profile** — rejected = measurement. It does not go through the command line, so 500KB goes in whole, a single `-p <이름>` splits per agent, and concurrent runs do not mix with each other. But it would **write files into the user's codex home**, and if we avoid that with an isolated home, **credential copies** lie around as many as the number of agents. It breaks 「사용자 홈에 우리가 한 글자도 쓰지 않는다」 ("we write not one character into the user's home") (ADR-0210 decision 1).
- **Push the instruction document into the command line as prose and be done** — partially adopted. app-server is in fact this and has no command-line constraint (the previous session recorded accepting 8MB, and what this round measured directly is **502,530 characters** — the canonical source is the research document). **Only terminal** hits the 8,191-character wall, and needs the check of decision 4.

## 근거

- **Wire-capture measurement.** We set a fake model server (`127.0.0.1`) as codex's model provider, received **the full text of the request codex assembled**, and decided by sentinel. We did not call a real model and left no session record in the real `~/.codex` (963 entries unchanged before and after).
  - `developer_instructions` → `input[0].content[0]`, role `developer`, kind `generic.developer_instructions`, **ahead of codex's own blocks (skill list · permissions)**. `instructions` is **unchanged** at 17,174 characters = append confirmed.
  - `model_instructions_file` → `instructions` **full replacement** (1MB lossless). Same on the JSON path too, and ★**it is taken separately per thread**★ (no leak before or after, and a thread with it unset returns to the default prompt).
  - All four terminal traps measured — a newline cuts the command line **with no error**, and `%` is expanded as an environment variable even inside quotes.
- **Official documentation comparison** (`learn.chatgpt.com/docs` — `developers.openai.com/codex` has moved there). The `instructions` parameter = 「`developer` 역할 텍스트 입력과 동등」 · the model spec authority ladder Root > System > Developer > User > Guideline · ★**the System layer is 「OpenAI 만 넣을 수 있다」 ("only OpenAI can put things in")**★ — whatever we do, Developer is the ceiling. The role-token wrapping is **identical all the way down to user messages** and only the role name differs (the published Harmony format).
- ★**The previous session's 「경로를 받는 키가 없다」 ("there is no key that takes a path") was a misjudgment**★ — `experimental_instructions_file` was rejected not because the feature is absent but because it was **renamed to `model_instructions_file`**, and the documents still carry the migration guidance. In addition, **without `--strict-config`, an unknown `-c` key is silently ignored rather than rejected** — from now on, key-existence checks are done with that flag attached.

## 영향 / 불변식

- ★**What this decision narrows is ADR-0099 decision 4 alone**★ — 「스폰 시 둘 중 한 경로를 `--append-system-prompt-file` 로 전달」 ("at spawn, pass one of the two paths with --append-system-prompt-file") remains only for claude and codex carries content. ★**It does not violate ADR-0092**★ — that ADR is written as 「데몬이 읽어 넣음」 ("the daemon reads and puts it in") in the first place, so it points the same direction as this decision (claude's path passing is, if anything, farther from that sentence). Do not read the old description as 「ADR-0092 가 경로만 허용한다」 ("it allows only a path").
- ★**The boundary is not the process but the module**★ — the backend runs inside the daemon process, so **the daemon process now reads the instruction document bytes.** What must be kept is 「데몬의 프라이밍 제공자가 경로만 낸다」 ("the daemon's priming provider emits only the path") (`crates/engram-dashboard-daemon/src/control/priming.rs`), and do not change it into a content provider — if changed, the claude path is contaminated too.
- **The claude path is unchanged** — `--append-system-prompt-file` is as it was. Do not remove that argument from the forbidden-flag list in `backend/codex/mod.rs` (blocking claude-only arguments from leaking into codex).
- **Terminal injection is conditional — 「안 실렸다」 (was not loaded) is on the normal path.** So whether the instruction document was actually loaded in terminal mode can be known **only from the warning log**. A regression on this axis is caught by the argument assembly test.
- ★**The argument assembly test does not prove 「codex 가 규약대로 행동한다」 ("codex acts according to the convention")**★ — its only pass criterion is **whether codex replies with the tool when we send without writing 「`eg_send` 로 답해라」 in the envelope body**. The current instruction document does not put that convention directly into a sentence and substitutes the one line **「네 턴에 쓴 것은 주인에게만 가고 팀원에게 닿지 않는다」** ("what you write in your turn goes only to the owner and does not reach teammates") — claude behaves correctly on that sentence, but **whether codex does too is unverified.**
- ★**A real round trip passed the same day — this is the real pass criterion of this decision**★ (GUI measurement). Even though we did **not write** 「`eg_send` 로 답해라」 in the envelope body, codex **ran `engram help` first** (the instruction document's first line) and replied with `eg_send` (14 seconds · `delivered`). The injection itself was also confirmed with our eyes on the command line of a live `codex.exe`, and skip warnings were 0. **The statement just above, 「인자 조립 테스트가 증명하지 않는다」 (the argument assembly test does not prove it), is still true, and this measurement is what filled it in.**
- **What remains unverified:** the method of fetching codex's default prompt per version (needed when the first alternative above comes back to life) · **a turn run to completion in terminal-mode codex** (it stopped at its own hook review screen and we did not click approve) · **a single-quote watch test** (★we do not add it, by user decision★ — we go with the discipline of not using that character in the instruction document).

Both are intended, and the canonical source of the reasons and the time to open is `commands::LLM_BACKEND_POLICY` — this ADR does not change it.~~ ★**Now an LLM spawns codex too**★ — the policy table opened codex (ADR-0219), and the folder-trust-modal premise that propped up that rejection was overturned by measurement. ★**「넓히는 것은 디스크 호환 이주다」 (widening it is a disk-compatibility migration) was also false from that time**★ — the `AgentCommand::Codex` counterpart already existed and the human menu was already writing the same shape into `agents.json`. **The door a human makes through was open then and is open now.**
