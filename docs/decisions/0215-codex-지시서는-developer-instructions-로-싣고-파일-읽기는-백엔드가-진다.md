# ADR-0215: codex 지시서는 developer_instructions 로 싣고 파일 읽기는 백엔드가 진다

- 상태: 확정 (2026-09-20, 근거: `docs/research/codex-instruction-injection-2026-09-20.md` — 방법·수치 정본, 여기 베끼지 않는다)
- 관련: ADR-0004(백엔드 확장) · ADR-0210(스폰을 실패시키지 않는다) · ADR-0209 · ADR-0211(같은 8,191 벽을 먼저 실측했고 지시서를 이 크기로 줄인 결정) · ADR-0092(프라이밍 seam 의 최초 결정 — 이 ADR 이 어기지 않는다) · `crates/engram-dashboard-agent/src/backend/claude/mod.rs:238` · Amends ADR-0099 (codex 는 경로 대신 내용을 싣는다)

## 맥락

claude 는 지시서를 `--append-system-prompt-file <절대경로>` 로 받는다 — 데몬은 **경로만** 넘기고 내용을 읽지 않는다(ADR-0092). codex 에는 **덧붙이는** 짝이 없어 지시서를 못 받았고(경로를 받는 `model_instructions_file` 은 있으나 전체 대체다), 그 결과 ADR-0209 가 막으려던 상태가 **배선이 아니라 무지로** 재현됐다: codex 는 요청 봉투를 읽고 **자기 채팅창에 답하고 끝냈다**(실측 — 본문에 「`eg_send` 로 답해라」를 적어 주자 그제야 도구를 불렀다). 발신자는 영원히 기다린다.

「codex 에 경로로 지시서를 주는 수단이 있는가」는 직전 세션이 **없다고 기록**했으나 그 판정은 틀렸다 — 아래 근거 절이 그 경위를 적는다.

## 결정

1. **codex 지시서는 `developer_instructions` 로 싣는다.** 값은 문자열이다(codex 에 `developer_instructions_file` 은 없다 — ★`--strict-config` 를 붙였을 때 `unknown configuration field` 로 거절된다. 그 플래그 없이는 조용히 무시되므로 침묵을 「있다」로 읽지 말 것★).
2. **읽는 주체는 codex 백엔드다.** 데몬의 프라이밍 제공자는 **경로만** 내는 지금 모양을 유지하고, `ControlEndpoint.priming_file` 도 그대로 둔다. 백엔드 고유 지식은 `backend/` 한 곳에 모은다는 ADR-0004 의 자리이고, claude 의 **argv·동작은 불변**이다 — 다만 `open_spawn` 이 `ControlEndpoint` 를 받도록 넓어져 claude 쪽 서명도 인자 하나를 받아 버린다(「한 글자도 안 바뀐다」가 아니다).
3. **운반체는 모드마다 다르다.** app-server = `thread/start` 의 전용 필드 `developerInstructions`. 터미널 = `-c developer_instructions='<한 줄>'`. 같은 값·같은 의미가 다른 칸으로 가는 것은 이 저장소의 기존 패턴이다(작업 폴더도 그렇게 갈린다).
4. ★**터미널 모드는 싣기 전에 검사하고, 못 실으면 경고만 남기고 스폰은 진행한다**★ — 크기(명령줄 8,191자 한계) · 작은따옴표 · 줄바꿈 · `%`. ADR-0210 결정 4 의 「어떤 갈래로도 스폰을 실패시키지 않는다」를 그대로 승계한다.
5. **읽기 실패는 fail-open.** 프라이밍 파일이 없거나 못 읽으면 주입을 건너뛰고 스폰한다. 지시서는 있으면 좋은 것이고 스폰은 필수다.
6. ★**두 칸에 모순되는 글을 동시에 넣지 않는다.**★ 한 번에 한 칸만 쓴다.
7. ★**app-server 지시서는 `thread/start` 에서 한 번만 먹는다**★ — 재개·fork 에 다른 값을 실으면 **오류도 경고도 없이 무시**되고 처음 값이 유지된다(fork 는 부모 것을 물려받는다). **살아 있는 에이전트의 지시서를 갈아 끼우려면 재개가 아니라 새 스레드다.** 그래서 재개 요청에 이 필드를 싣지 않는다 — 없어서가 아니라(`ThreadResumeParams`·`ThreadForkParams` 둘 다 이 필드를 갖는다) **효과가 없어서**다.

## 거부한 대안

- **`model_instructions_file` 로 시스템 프롬프트 칸에 싣는다** — ★**기각 = 문서 대조**★. 경로를 받고(실측: 절대경로·1MB 무손실) 진짜 `instructions` 필드에 꽂히지만 **전체 대체**라, codex 기본 프롬프트 17,174자(도구 사용법·샌드박스 규약·출력 형식)를 우리가 떠서 앞에 붙여야 하고 **codex 버전마다 낡는다.** 그 대가를 치를 이유가 없다 — OpenAI API 레퍼런스가 `instructions` 파라미터를 **「`developer` 역할 텍스트 입력과 동등」**이라 적고, 모델 규정의 권한 사다리에서도 둘 다 **Developer** 층이다. **권한 이득이 0 인데 드리프트 부담만 생긴다.** ★단 이 기각은 조건부다★ — **터미널 모드에서 결정 4 의 크기 검사가 실제로 건너뛰기 경고를 내기 시작하면** 이 대안이 되살아난다(경로를 받는 성질 하나 때문에). 8,191 예산은 정책 플래그·passthrough·훅 override 와 나눠 쓰므로 판정은 문서 크기가 아니라 **그 경고**다. 현재 여유 = 1,686/8,191.
- **`AGENTS.md` · `project_doc_fallback_filenames` 절대경로** — ★**기각 = 실측 + 문서**★. 경로를 받고 덧붙는 유일한 칸이지만 착지가 **`user` 역할**이라 권한이 **한 등급 아래**다. 덧붙여 ① 기본 상한 32,768바이트(표식 없이 잘림) ② 워크스페이스에 `AGENTS.md` 가 있으면 우리 fallback 은 **아무 신호 없이 무시**된다 ③ `AGENTS.override.md` 로 이기면 이번엔 **사용자 자신의 `AGENTS.md` 가 통째로 죽는다** ④ 절대경로 사용법이 **공식 문서에 없다**(문서는 "파일명"만 말한다). ★그래도 이 칸에는 살아 있는 쓸모가 하나 있다★ — **세션 시작에 한 번만 읽고 기록에 넣으므로 쓰고 바로 지워도 남는다**(실측: 턴 1 뒤 수정·삭제 양쪽 모두 턴 2 가 원본을 유지). 임시 파일로 주입하는 길이 필요해지면 이 성질을 쓴다.
- **`$스킬이름` 멘션으로 마크다운 N 장을 각각 읽힌다** — ★**기각 = 실측**★. 동작은 한다(30,368바이트 파일이 잘림 없이 통째로 들어가고, 여러 개 부르면 각각 별도 블록으로 누적 — **우리가 합칠 필요가 없는 유일한 수단**). 그러나 ① 착지가 또 **`user` 역할** ② **터미널 모드엔 루트를 추가할 수단이 아예 없다**(RPC 전용) ③ 그 RPC 는 **프로세스 전역**이라 한 app-server 에 붙은 에이전트들이 **서로의 지시서를 덮어쓴다**(실측: 스레드1 이 다음 턴에 스레드2 의 루트를 물려받음) ④ 같은 스킬을 반복해 부르면 히스토리에 **계속 쌓인다** ⑤ 그 RPC 를 문서가 스스로 「예고 없이 바뀔 수 있다」고 적어 둔다.
- **`SessionStart` 훅의 `additionalContext` 로 넣는다** — 기각. ★**「훅은 신뢰 게이트라 못 쓴다」로 적지 말 것 — ADR-0210 이 이미 훅을 등록하고 TUI 심사로 신뢰를 얻는다**★. 살아 있는 기각 사유는 둘이다: ① ADR-0210 결정 6 이 훅 등록을 **터미널 모드에만** 두어 app-server 절반이 안 덮인다 ② 신뢰는 **사용자가 한 번 승인한 뒤에야** 오므로 첫 스폰의 지시서가 보장되지 않는다. 해시를 우리가 계산하는 길은 ADR-0208·0210 이 이미 기각했다.
- **`CODEX_HOME` 을 에이전트마다 갈라 `config.toml`·프로필에 싣는다** — 기각 = 실측. 명령줄을 안 타서 500KB 가 통째로 들어가고 `-p <이름>` 하나로 에이전트마다 갈리며 동시 실행도 서로 안 섞인다. 그러나 **사용자 codex 홈에 파일을 쓰게 되고**, 격리 홈으로 피하면 **자격증명 사본**이 에이전트 수만큼 눕는다. 「사용자 홈에 우리가 한 글자도 쓰지 않는다」(ADR-0210 결정 1)를 깬다.
- **지시서를 산문 그대로 명령줄에 밀어 넣고 끝낸다** — 부분 채택. app-server 는 실제로 이것이고 명령줄 제약이 없다(직전 세션이 8MB 수용을 기록했고, 이번 라운드가 직접 잰 것은 **502,530자**다 — 정본은 조사 문서). **터미널만** 8,191자 벽에 걸려 결정 4 의 검사가 필요하다.

## 근거

- **와이어 캡처 실측.** 가짜 모델 서버(`127.0.0.1`)를 codex 의 모델 제공자로 박아 **codex 가 조립한 요청 전문**을 받아 센티넬로 판정했다. 실 모델을 부르지 않았고 실 `~/.codex` 에 세션 기록을 남기지 않았다(전·후 963개 불변).
  - `developer_instructions` → `input[0].content[0]`, 역할 `developer`, 종류 `generic.developer_instructions`, **codex 자기 블록(스킬 목록·권한)보다 앞**. `instructions` 는 17,174자 **불변** = 덧붙임 확정.
  - `model_instructions_file` → `instructions` **전체 대체**(1MB 무손실). JSON 경로로도 같고 ★**스레드마다 따로 먹는다**★(전·후 누출 없음, 미설정 스레드는 기본 프롬프트 복귀).
  - 터미널 함정 넷 전부 실측 — 줄바꿈은 **오류 없이** 명령줄을 자르고, `%` 는 따옴표 안에서도 환경변수로 펴진다.
- **공식 문서 대조**(`learn.chatgpt.com/docs` — `developers.openai.com/codex` 는 이쪽으로 옮겨졌다). `instructions` 파라미터 = 「`developer` 역할 텍스트 입력과 동등」 · 모델 규정 권한 사다리 Root > System > Developer > User > Guideline · ★**System 층은 「OpenAI 만 넣을 수 있다」**★ — 우리가 무엇을 해도 Developer 가 천장이다. 역할 토큰 감싸기는 **user 메시지까지 전부 동일**하고 역할 이름만 다르다(공개된 Harmony 형식).
- ★**직전 세션의 「경로를 받는 키가 없다」는 오판이었다**★ — `experimental_instructions_file` 이 거절된 것은 기능 부재가 아니라 **`model_instructions_file` 로 개명**됐기 때문이고, 문서에 마이그레이션 안내가 그대로 있다. 더해 **`--strict-config` 없이는 모르는 `-c` 키가 거절이 아니라 조용히 무시된다** — 앞으로 키 존재 확인은 그 플래그를 붙여서 한다.

## 영향 / 불변식

- ★**이 결정이 좁히는 것은 ADR-0099 결정 4 하나다**★ — 「스폰 시 둘 중 한 경로를 `--append-system-prompt-file` 로 전달」이 claude 에만 남고 codex 는 내용을 싣는다. ★**ADR-0092 는 어기지 않는다**★ — 그 ADR 은 애초에 「데몬이 읽어 넣음」이라 적혀 있어 이 결정과 같은 방향이다(claude 의 경로 전달이 오히려 그 문장에서 멀다). 옛 서술을 「ADR-0092 가 경로만 허용한다」로 읽지 말 것.
- ★**경계는 프로세스가 아니라 모듈이다**★ — 백엔드는 데몬 프로세스 안에서 돌므로 **데몬 프로세스는 이제 지시서 바이트를 읽는다.** 지켜야 할 것은 「데몬의 프라이밍 제공자가 경로만 낸다」(`crates/engram-dashboard-daemon/src/control/priming.rs`)이고, 그것을 내용 제공자로 바꾸지 말 것 — 바꾸면 claude 경로까지 함께 오염된다.
- **claude 경로 불변** — `--append-system-prompt-file` 은 그대로다. `backend/codex/mod.rs` 의 금지 플래그 목록에서 그 인자를 빼지 말 것(claude 전용 인자의 codex 유입 차단).
- **터미널 주입은 조건부다 — 「안 실렸다」가 정상 경로에 있다.** 그래서 터미널 모드에서 지시서가 실제로 실렸는지는 **경고 로그로만** 알 수 있다. 이 축의 회귀는 인자 조립 테스트가 잡는다.
- ★**인자 조립 테스트는 「codex 가 규약대로 행동한다」를 증명하지 않는다**★ — 그 합격 판정은 **봉투 본문에 「`eg_send` 로 답해라」를 적지 않고 보냈을 때 codex 가 도구로 답장하는가** 하나뿐이다. 현재 지시서는 그 규약을 직접 문장으로 담지 않고 **「네 턴에 쓴 것은 주인에게만 가고 팀원에게 닿지 않는다」** 한 줄로 대신한다 — claude 는 그 문장으로 올바르게 행동하지만 **codex 도 그런지는 미검이다.**
- **미검으로 남은 것:** 실 왕복 1회 · GUI 실측 0 · codex 기본 프롬프트를 버전마다 떠 오는 방법(위 첫 대안이 되살아날 때 필요해진다).
