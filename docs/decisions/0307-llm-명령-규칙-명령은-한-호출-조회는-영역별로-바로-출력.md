# ADR-0307: LLM 명령 규칙 — 명령은 한 호출, 조회는 영역별로 바로 출력

- 상태: 확정 (2026-10-26, 근거: 사용자 대화 결정 · 조사 2 건)
- 관련: CLAUDE.md 「LLM-우선 제어」 · 정설 `docs/reference/llm-command-conventions.md` · 조사 `docs/research/llm-command-design-query-vs-action-2026-10-26.md` · `docs/research/pane-positional-addressing-2026-10-26.md` · step-log S27 · tracking T-65

## 맥락
LLM 이 버스 · `engram` CLI 로 부르는 명령을 늘리기 전(첫 소비자 = T-65 슬롯 도킹 LLM 명령)에 공용 규칙을 세운다. 사용자 기준 = 「LLM 시나리오는 여러 번 거치지 않아야 실수가 적다」 · 호출 수와 컨텍스트에 싣는 양을 둘 다 줄인다. 지금 레이아웃 명령은 불투명 id 로만 대상을 받아 흔한 요청이 조회 + 명령 2~3 호출이 된다(예: `slot.focus` 는 먼저 `slot.resolveSpatial` · `slot.assignAgent` 는 `agent.list` 와 칸 id 조회). 사용자가 함께 물었다 — 조회 결과를 컨텍스트에 다 싣나, 밖(파일)으로 내고 bash 로 찾게 하나.

## 결정
규칙의 정본은 `docs/reference/llm-command-conventions.md` 이고 이 ADR 은 그 *왜* 를 남긴다.

1. **명령(쓰기) = 시나리오 하나에 한 호출.** 여러 단계는 명령 안에서 한다.
2. **대상은 LLM 이 이미 아는 말로 받는다** — 에이전트 이름 · 화면 칸 번호 · 공간 낱말 · id. 명령이 안에서 id 로 푼다. 모호하거나 없으면 오류로 멈추고 후보를 싣는다.
3. **칸 번호 = 화면 위치 순**(위→아래, 같은 높이면 왼→오). 번호는 삽입 · 닫기로 밀리므로 LLM 이 연달아 작업할 땐 이름을 우선한다.
4. **배치를 바꾼 명령의 응답에 바뀐 뒤의 칸 번호 목록을 싣는다** — LLM 이 결과를 추론하지 않게(사용자: 「결과를 콜백해주는것도 좋겠지」).
5. **조회(읽기) = 영역마다 하나 + 필터 인자, 결과는 컨텍스트에 바로 출력.** 부를 말을 모를 때만 조회한다.
6. **크면 CLI 가 파일로 넘긴다 — 공용 안전장치 하나.** 응답이 문턱을 넘으면 `engram` CLI 가 파일로 쓰고 경로 + 앞부분만 낸다. 문턱 값은 구현 때 정한다.
7. **명령 세부(이름 · 인자 · 응답 문구)와 출력 형식(텍스트 · JSON)은 메인이 LLM 이 잘 쓰는 쪽으로 정하고 보고한다**(사용자 위임: 「이건 llm인 너가 잘 아니 잘 지시되는쪽으로 알아서 하면 될듯」).
8. **미정으로 남김** — 칸 번호를 화면에 늘 보일지 · 필요할 때만 띄울지(사람이 체감하는 UI 라 사용자 결정).

## 거부한 대안
- **열 · 행 좌표로 칸 지정(「x1 y2」 — 사용자 제안)** — 칸 배치가 격자가 아니라 분할 트리라 열마다 행 경계가 달라 「행 2」가 애매하다(코드 사실 — `src-tauri/src/layout/spatial.rs` 는 사각형 트리에서 위치를 파생한다). 조사한 도구(tmux · i3 · WezTerm · ace-window) 중 열 · 행 좌표로 지정하는 곳이 없었고, 그 자리를 순번 + 화면 표시로 메운다(tmux `display-panes` · ace-window 「top-down, left-to-right」 — 원문 확인). 기각 강도 = 조사 + 코드.
- **조회 결과를 늘 파일로 내고 bash(grep · 부분 읽기)로 찾게 하기** — 영역 하나의 결과가 작다(레이아웃 어림: 칸 160 개 극단도 텍스트 ≈ 760 토큰 · id 를 실은 JSON ≈ 9,200 토큰 — 글자 수 어림, 토크나이저 실측 아님). 다른 도구가 파일로 넘기는 문턱(LangChain Deep Agents 20,000 · Claude Code 25,000 토큰)에 한참 못 미친다. 파일 + 검색은 호출을 늘리고(조회 + 찾기 ≥ 2), 찾을 말을 알면 핀포인트 조회가 한 번에 끝내며, 모르면 어차피 전체를 읽어야 한다. 큰 경우는 결정 6 의 안전장치가 덮는다. 기각 강도 = 정량 어림.
- **묶음 실행(명령 목록 한 번에) · 스크립트 시스템 — 지금은 만들지 않음** — 시나리오마다 명령 하나로 흔한 요청이 한 호출로 끝나므로 쓸 곳이 아직 없다. 스크립트(변수 · 조건 · 반복)는 우리 규모에 과하다. 같은 두세 호출이 실제로 반복되면 그 시나리오를 명령 하나로 만들고, 그래도 모자랄 때 묶음을 다시 꺼낸다. 기각 강도 = 사용자 결정(「일단 1번만」) — 정량 근거는 없다.
- **모든 영역을 한꺼번에 내는 전체 출력 — 지금은 만들지 않음** — 영역별 조회로 충분하고 쓸 곳이 없다. 만들게 되면 그 크기가 결정 6 의 파일 + 검색이 맞는 경우다. 기각 강도 = 사용자 결정(「영역별로 잘 나누면 되겠네」).

## 근거
- 공급자 권고: 여러 단계를 한 도구로 묶기(`schedule_event`) · 자연어 이름이 암호 같은 id 보다 낫다 · 고칠 방법을 말하는 오류 · 페이지 · 필터 · 잘라내기 + 합리적 기본값 · 넓은 검색 한 번보다 작고 겨냥한 검색 여러 번 — [Anthropic, Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)(원문 확인).
- 이름 지목 · 모호하면 오류 = tmux 대상 해석(원문 확인). 이동 뒤 새 id 를 응답으로 돌려주는 피어 = herdr `pane move`(원문 확인).
- 크기 문턱형 파일 넘김 = LangChain Deep Agents(20,000 토큰 넘으면 경로 + 앞 10 줄 · 원문 확인) · Cursor(긴 출력을 파일로) · Claude Code(25,000 토큰 상한).
- 전체 상태를 늘 파일로 내는 선례(Playwright CLI)도 있다 — 우리 결과 크기에선 호출만 는다고 보아 따르지 않았다.
- 조사 상세 · 적대 리뷰(codex, 판정 FIX → 반영) = 관련 줄의 두 보고서.

## 영향 / 불변식
- 새 LLM 명령 · 조회는 `docs/reference/llm-command-conventions.md` §5 확인 목록을 지난다.
- **구현은 아직 없다** — 이름 · 칸 번호 지목, 응답의 번호 목록, CLI 파일 안전장치는 T-65 이후 구현 몫이다. 지금 코드는 id 만 받고 CLI 는 몸통을 그대로 찍는다.
- 데몬은 UI 명령 몸통을 해석하지 않는다(ADR-0081 · ADR-0156) — 응답 모양은 셸 처리기에서, 크기 안전장치는 CLI 에서 한다.
- 셸은 agent crate 를 의존하지 않으므로(ADR-0270) 에이전트 이름 풀기는 셸의 이름 캐시(지워지지 않아 낡은 이름이 남을 수 있다)나 데몬 왕복으로 해야 한다 — 구현 때 정한다.
