# ADR-0077: Manual activation also shares the fresh-fallback on an early resume exit — refines ADR-0076

- 상태: **폐기 (Superseded by ADR-0082)** — the fresh-fallback policy itself was reversed. The reason for this ADR's existence (manual activation also sharing the fresh-fallback on an early resume exit) is invalidated entirely — user decision: a resume failure is left as Failed (a corpse) with no automatic fresh replacement, with a cause log and LLM escalation. On top of that, this extension was the direct cause of a regression (a4aac1a) that destroyed a live agent when it was re-activated. ~~확정 (2026-07-13, basis: after a daemon cold boot, activating a profile with no conversation → claude dies instantly with "No conversation found with session ID <sid>", fresh-fallback did not fire (daemon-debug.log))~~
- 관련: Amends ADR-0076 (manual activation (activate_profile) also shares the same fresh-fallback as restore_one on an early resume exit) · ADR-0008 (session restore, sid control) · `agent/manager.rs::activate_profile`/`resume_with_fresh_fallback`/`restore_one`/`fallback_fresh` · `daemon/connection_core.rs::SpawnProfile` · step-log

## 맥락
User decision: **"If it was only spawned and never said a word, it is better to just start fresh."** That is, resume only a session that actually has a conversation to continue, and a session that cannot be continued (empty / no conversation / deleted / corrupted — claude exits immediately on `--resume <sid>` with "No conversation found with session ID ...") must not be killed but **started fresh with a new sid**.

Reproduced defect (daemon cold boot → activating a profile with no conversation): ADR-0076 fixed the activation mode derivation (`claude_session_id.is_some()` → Resume) and the new-sid issuance for Fresh, but **the logic "early resume exit → fresh-fallback" existed only in the boot restore path (`restore_one`/`fallback_fresh`) and not in the manual activation path (SpawnProfile → `manager.spawn_agent`).** `spawn_agent` only launches the process and does not detect an early exit. So when a session with no conversation was activated, the resume child died instantly → the reaper collected it → the agent simply died (fresh-fallback did not fire, confirmed from the log).

## 결정
- **Extract a shared fresh-fallback helper** — pull the discipline "try resume → detect an EARLY_EXIT_WINDOW early exit → `fallback_fresh`" out of `restore_one` into `resume_with_fresh_fallback(profile) -> RestoreOutcome`. `restore_one` (boot restore) keeps only the resumable gate and calls this helper (behavior unchanged).
- **Add a manual activation entry point** — `AgentManager::activate_profile(profile, mode) -> Result<AgentInfo, PtyError>`. In Resume mode it runs `resume_with_fresh_fallback`, applying the **same** early-exit→fresh-fallback discipline as boot restore, and translates the outcome (Resumed/FreshFallback → the AgentInfo of the live session, Failed → Err). Fresh mode delegates to `spawn_agent(Fresh)` as is (there is no conversation to resume, so early-exit detection is meaningless — existing behavior preserved).
- **Replace the handler wiring** — the daemon `SpawnProfile` handler calls `activate_profile` instead of `spawn_agent`. The mode derivation (ADR-0076 — resume-requested OR session-exists) is left as is, and only the execution part is replaced.

## 거부한 대안
- **Detect an empty session before spawn** — a way to look into claude's session store, decide beforehand whether there is "a conversation or none", and set the mode accordingly. It is fragile because it is coupled to claude's internal session file format and path (it breaks when the format changes), and it violates backend knowledge isolation (ADR-0004). The reactive way (fallback when the resume child exits early) depends only on the fact that claude itself reported "cannot resume", so it is robust, and it reuses the already verified ADR-0008 S9 infrastructure as is.
- **Detect the early exit inside `spawn_agent`** — `spawn_agent` is both the single authority point for sid issuance and the function that `fallback_fresh` itself calls in Fresh mode. If early-exit detection plus fallback is put there, (1) the fresh spawn of `fallback_fresh` would be detected again and fall back again, tangling the causality, and (2) every spawn would block for EARLY_EXIT_WINDOW (3s). So detection and fallback live only in the upper entry points (`activate_profile`/`restore_one`), and `spawn_agent` stays a pure spawn.
- **Put no fallback in manual activation at all (keep the current bug)** — a direct violation of the user decision (a session that cannot be resumed dies). The asymmetry where only boot restore survives and manual activation dies is the body of the reproduced bug.

## 근거
Instant death with "No conversation found with session ID <sid>" was reproduced when activating a profile with no conversation after a daemon cold boot (daemon-debug.log), and we confirmed from code and logs that the cause is "the fresh-fallback exists only in the restore path and not in the activation path". Because the two paths share the same helper (`resume_with_fresh_fallback`), the discipline is kept in one place and there is no divergence. The ADR-0019 reaper single-consumer, finalize-once, and epoch/kill invariants stay unchanged because the existing `fallback_fresh` is reused as is — the causality `remove_session` (drain the stale terminal via join_pump) → epoch++ → `spawn_agent(Fresh)` is the same as in restore.

## 영향 / 불변식
- **ADR-0076 is refined (not discarded)** — "activation=resume · Fresh=new sid (no reuse) · single sid-issuing point" remains valid. On top of that, this ADR adds "boot restore and manual activation **share** the fresh-fallback on an early resume exit".
- **Single source for the fresh-fallback discipline** — `resume_with_fresh_fallback` is the canonical one. Both `restore_one` and `activate_profile` call it — divergence by fixing only one side is forbidden (this very divergence was why manual activation died).
- **`spawn_agent` = pure spawn** — do not put early-exit detection or fallback here (keeps the single sid-issuing point and avoids the `fallback_fresh` re-entry tangle + the unconditional 3s block).
- **Outcome translation** — `activate_profile` Resume: Resumed/FreshFallback → the AgentInfo of the live session (re-queried via `agent_info_by_id` after a fallback), Failed → Err. Fresh → `spawn_agent(Fresh)` as is.
