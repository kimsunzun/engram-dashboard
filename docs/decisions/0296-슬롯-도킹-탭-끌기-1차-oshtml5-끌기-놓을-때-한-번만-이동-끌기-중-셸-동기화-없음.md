# ADR-0296: 슬롯 도킹 탭 끌기 1차 = OS(HTML5) 끌기 · 놓을 때 한 번만 이동 · 끌기 중 셸 동기화 없음

- 상태: 확정 (2026-10-20, 근거: 사용자 결정(VS Code 탭 끌기 화면을 보이며 「그냥 이런식으로 1차적으로 할까 덜어내고? 드래그 목표지점이 정해졌을때 이동되는걸로. 동기화 하려니깐 빡센거 아냐」 · 「ㅇㅇ 그렇게하자」) + 조사 `docs/research/slot-docking-drag-ownership-peers-2026-10-19.md`(피어 · 기법 · OS 끌기 Windows 모양 E 절)) · 부분 폐기 by ADR-0297 (끌기 도중 셸 호출 0 불변식의 범위) · 부분 폐기 by ADR-0299 (결정 5 중 예비 창 걷기)

## 맥락

ADR-0295 결정 1 로 데스크톱 Chrome 식 끌기(마우스 캡처 · 떼면 진짜 새 창 · Windows 창 이동 루프 · 놓기 전 다른 창에 붙기)를 TRD 6.3 U8 까지 구현했다. 실측에서 결함이 셸(Rust) ↔ 창마다 다른 웹뷰(React) 경계에서 반복됐다 — 재부착 때 모델 쓰기가 웹 알림보다 먼저 그려져 0 번 자리 한 프레임(원인 확정) · 탭이 다 사라짐(B1 · 웹이 폭 0 탭바를 보고 — 원인 미확정) · 붙었다 11 ms 만에 떨어짐(원인 미확정). 공통 뿌리는 끌기 하나를 두 프로세스가 나눠 판단하고 끌기 도중 IPC 로 상태 · 기하를 맞추는 것이다.

조사(`slot-docking-drag-ownership-peers-2026-10-19.md`)에서 — 렌더러와 모델 주인이 갈린 피어(Chromium 옛 WebUI 탭바 · Vivaldi)와 한 프로세스 피어(Firefox · Windows Terminal · VS Code) 모두 끌기 도중 모델을 쓰지 않고 놓을 때 한 번만 옮긴다 · 창 사이는 OS 끌어 놓기에 맡긴다 · 우리와 같은 분리 구조로 Chrome 식을 하는 곳은 Chromium Webium 하나인데 기본값 꺼진 실험 기능이다. Chrome 식 끌기 엔진은 손으로 만든 것만 시험 포함 약 1 만 줄(파일 줄 수 — platform 이동 루프 2,129 · 셸 세션 + 시험 3,717 · 실행기 · 예비 창 1,265 · 커서 밑 창 판정 817 · 끌기 명령 1,726 · 웹 끌기 훅 + 시험 1,907 · 기하 보고 270)이고, 이동 루프 · 훅은 OS 마다 다시 짜야 하며 Wayland 에서는 성립하지 않는다(Chrome 도 거기선 OS 끌기로 돌아간다 — `ShouldDragWindowUsingSystemDnD`).

## 결정

1. **탭 끌기 1차 = WebView2 의 HTML5(OS) 끌어 놓기, VS Code 꼴.** 끌기 그림 = 탭 이름 라벨.
2. **모델은 목표가 정해졌을 때(놓을 때) 한 번만 바뀐다.** 놓은 창의 웹뷰가 명령 하나(탭 · 대상 창 · 자리 또는 분할 자리)를 셸에 보내고, 셸은 LLM 명령과 같은 적용 경로(`layout::apply`)로 한 번 적용한다. **끌기 도중 셸 ↔ 웹 동기화는 없다** — 끌기 상태 · 탭바 기하를 셸로 보내지 않는다.
3. **미리보기(끼울 자리 · 도킹 띠)는 놓을 창의 웹뷰가 자기 dragover 로 자기 안에서 그린다.**
4. **어느 창에도 놓지 않으면 그 자리에 새 창** — 끌기가 끝난 직후 셸이 커서 위치를 읽는다.
   - 다른 앱이 받아도 새 창 · 우리 창 제목 표시줄 · 테두리 위 = 아무 일 없음(사용자 결정 2026-10-20 — PRD Q38 · Q39 · TRD §3-5).
5. **Chrome 식 끌기 엔진을 덜어낸다** — 창 이동 루프 · 훅 · 셸 끌기 세션 · 예비 창 · 커서 밑 창 판정 · 기하 보고. 무엇을 걷고 무엇을 남기는지는 TRD 가 정본이다 — 7판은 커서 밑 창 판정 중 platform `window::top_level_at` 을 걷지 않고 dragend 뒤 놓기 끝 판정에 남긴다(TRD §3-5 · §5-1).
6. ADR-0295 의 결정 3(칸 가장자리 10% 도킹 띠) · 결정 4(붙는 크기 = 원래 크기 · 칸 절반 상한)는 그대로 유효하다. 이 결정이 대신하는 것은 **결정 1 의 끌기 수단**(마우스 캡처 · 이동 루프 · 떼기/붙기 · 놓기 전 붙기 · Esc 되돌리기 등)과 **결정 2**(Chrome 방식이 안 되면 멈춤)뿐이다. 결정 1 의 활성 탭 모양(위 모서리 10 · 아래 휘어짐 12 · 구분선 규칙)은 그대로 유효하다 — ADR-0168 결정 5 부분 폐기의 근거다. 결정 1 의 끌기 밖 나머지(빈 탭바 = 창 끌기 영역 · 연달아 닫기 폭 고정)는 PRD 4.9 가 정본이다.

## 거부한 대안

- **Chrome 식 유지(ADR-0295 결정 1)** — 끌기 도중 셸 ↔ 웹뷰 동기화에서 결함이 반복됐다(위 맥락 — 하나는 원인 확정). 사용자: 「동기화 하려니깐 빡센거 아냐」. 손으로 만든 엔진이 약 1 만 줄(파일 줄 수 실측)이고 OS 마다 다시 짜야 한다.
- **Chrome 식 유지 + 경계만 재설계(Webium 꼴 — 탭바 안은 웹 · 창 단위는 셸 · 판 번호 스냅숏 · 붙기/떼기 여유 띠)** — 끌기 도중 동기화가 줄 뿐 남는다. 유일한 같은 구조 선례 Webium 은 기본값 꺼진 실험 기능이고(`chrome_features.cc` #1960 `FEATURE_DISABLED_BY_DEFAULT`) 2026-05~08 사이 크래시 수정이 여럿이며, 기하 보고에 판 번호가 없어 우리 B1 과 같은 구멍이 열려 있다(조사 · 소스 대조). 사용자가 OS 끌기 1 차를 골랐다.
- **끌기 출처를 Rust 네이티브 OLE 로 쥐어 Firefox 수준(화살표 커서 · Esc 와 창 밖 놓기 구분 · 되튐 애니메이션 없음)** — 1 차에서 하지 않는다: 다시 직접 만드는 길이다(사용자 「덜어내고」). WebView2 의 끌기 출처는 WebView2 브라우저 프로세스 안이라 셸이 훅할 수 없고(`drag_source_win.cc` #29-31), 앞서 본 네이티브 끌기 플러그인(crabnebula)은 메인 스레드를 막는 결함이 있었다(`slot-docking-drag-mechanism-2026-10-16.md` §1). 1 차 뒤 필요하면 다시 연다.

## 근거

- 피어 소스 대조(메인 grounding) — Chromium 옛 WebUI 탭바 `drag_manager.ts` #225-238(`finish()` 에서 `moveTab` 한 번) · Firefox `drag-and-drop.js`(모델 이동은 `handle_drop` 안에서만) · Windows Terminal `TerminalPage.cpp` #6050-6062 · Chromium Webium `tab_drag_session.cc` #354-357 · `tab_strip.ts` #247.
- HTML5 끌기 스파이크 실측(2026-10-16 · WebView2) — 셸 메인 스레드 안 막힘 · 대상 창 dragover 60/s · 좌표 정확 · dragend 모든 경우 발생 · 원본 창을 숨겨도 계속.
- OS 끌기 Windows 모양(조사 E 절) — 커서 옆 점선 상자 = OLE 기본 「이동」 커서 · Chromium 은 늘 기본 커서(`drag_source_win.cc` #29-31) · Firefox 만 사설 훅으로 화살표(`nsNativeDragSource.cpp` #95-114) · 사용자 관찰(2026-10-20): Visual Studio 에는 안 나오고 VS Code 에는 나온다.

## 영향 / 불변식

- **받아들인 대가(VS Code 수준):** 커서 옆 점선 상자 · 떼어진 탭은 진짜 창이 아니라 그림으로 따라옴(다른 앱 위에선 그림이 사라짐) · Esc 와 창 밖 놓기가 HTML 에선 같은 신호(`dragend` · `dropEffect "none"`) · 창 밖 놓기 때 Windows 의 되튐 애니메이션 · 끌기 도중 Windows 스냅 없음.
- **끌기 도중 셸 호출 0 이 불변식이다** — 셸은 놓기 명령 하나(+ 창 밖 놓기의 커서 읽기)만 받는다. 끌기 도중 기하 · 상태를 셸로 보내는 경로를 되살리면 이 결정의 이유(경계 동기화 결함)가 돌아온다.
- **LLM 경로:** 놓기 명령은 T-65 와 같은 적용 경로를 지난다(CLAUDE.md 「LLM-우선 제어」).
- **플랫폼:** HTML5 끌기는 웹 표준이라 OS 별 끌기 코드가 거의 없어진다. macOS(WKWebView) · WebKitGTK 의 창 사이 HTML5 끌기 동작은 미검 — 이식 때 잰다.
- PRD · TRD 는 이 결정으로 개정한다(Chrome 식 요구 · 단계 · 걷을 코드).
