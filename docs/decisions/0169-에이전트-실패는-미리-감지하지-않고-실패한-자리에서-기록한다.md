# ADR-0169: 에이전트 실패는 미리 감지하지 않고 실패한 자리에서 기록한다

- 상태: 확정 (2026-08-19, 근거: 사용자 결정 + 코드 조사 2026-08-19)
- 관련: ADR-0082(복원 실패 시 자동 fresh fallback 금지) · ADR-0008(sid 통제 · claude 파일은 best-effort) · ADR-0168(거처 기준 3층) · ADR-0170(표시 규칙) · ADR-0127(정리 지점을 늘리지 않는다)

## 맥락

에이전트를 띄우고 **한 마디도 주고받지 않은 채** 종료하면, 그 항목을 다시 열 때 실패한다. 우리가 대화 식별자를 먼저 발급해 넘기지만 claude는 **첫 교환이 있어야** 그 식별자의 대화 실물을 만든다 — 식별자만 있고 실물이 없어 이어 열기가 실패한다. ADR-0082가 자동 fresh fallback을 금지했으므로 그 실패는 화면에 그대로 남는다(의도된 동작).

문제는 **그 실패가 어디에도 기록되지 않는다**는 것이다. 종료 분류는 크래시·사용자 종료·복원 실패를 구분하지 않고 전부 같은 처분(자동 복원만 끄기)으로 수렴시키고, 실패 사유를 담을 필드는 예약만 되어 있고 연결돼 있지 않다. 그래서 화면도 제어 LLM도 "왜 안 열렸는지"를 알 수 없다. **ADR-0082가 요구한 "원인을 남겨 제어 LLM이 읽고 사용자에게 올린다"가 사실상 지켜지지 않고 있다.**

## 결정

1. **사전 판정을 하지 않는다.** 활성화 전에 "이 항목에 이력이 있나"를 미리 검사하지 않는다. 실패는 시도한 자리에서 관측하고 그때 기록한다.
2. **「마지막 실패」를 항목(프로필)에 붙인다.** 열거형이고, 디스크 직렬화에서 제외해 **데몬 수명 동안만** 산다(ADR-0168 3층). 별도 컨테이너에 모으지 않는다.
3. **지금 상태와 별개 축으로 둔다.** 기존 상태 열거형에 합치지 않는다.
4. **활성화가 성공하면 지운다.** 지우는 지점은 이 하나뿐이다. 낡은 쓰기는 화신(epoch) 검사로 거부하고, **아무것도 하지 않은 요청**(이미 돌고 있거나 이미 뜨는 중)은 기록도 지움도 하지 않는다 — 안 한 일에는 기록할 실패도 지울 근거도 없다.
5. **실패 종류마다 「다시 해볼 가치가 있나 · 화면 문구 · 권하는 행동」을 한 표에 모은다.** 화면 동작은 그 표에서 파생시킨다.
6. **이번 범위는 기록과 표시까지.** 클릭 동작 변경과 「새 대화로 시작」 버튼은 후속으로 미룬다.

## 거부한 대안

- **우리 관측을 영속 저장해 사전 판정한다** — 프로필에 그런 값이 없어 새로 만들어야 하는데, **이미 쌓인 항목은 도장이 없어 소급 판정이 불가능하다.** 기본값을 "이력 없음"으로 두면 멀쩡한 대화가 실행 불가로 잠기고, "있음"으로 두면 기능이 옛 항목에 안 걸린다.
- **claude가 만든 대화 파일을 읽어 사전 판정한다** — 소급은 되지만 ADR-0008이 **claude가 만드는 파일 위에 제품 기능을 짓는 것을 금지**한다(형식이 예고 없이 바뀔 수 있어 best-effort 등급 고정). 스크롤백 되살리기에 읽는 것과 기능을 잠그는 것은 등급이 다르다.
- **마지막 실패를 디스크에 영속한다** — 데몬을 내리면 그 세션들도 함께 죽으므로 옛 실패를 붙들 이유가 약하다. 프로필 파일 규격 변경과 하위 호환 처리가 따라붙는다(사용자 결정 2026-08-19).
- **별도 컨테이너에 모아 보관한다** — 상태가 주인과 떨어져 드리프트하고 정리 지점이 하나 더 생긴다. 같은 구조체에 **이미 디스크에서 빠지는 메모리 전용 필드 전례가 있어** 옆 표를 만들 이유가 없다.
- **기존 상태 열거형에 합친다** — "다시 떠서 도는 중인데 아직 첫 대화 전"이 표현되지 않는다. 그 조합이 없으면 화면이 「도는 중이 이긴다」를 적용할 근거도 사라진다.

## 근거

- **코드 조사(2026-08-19)** — 프로필에 대화 여부를 말해주는 저장값이 하나도 없다. 런타임 턴 관측표는 메모리 전용이고 재시작 시 소멸한다. 반면 프로필에는 이미 디스크 직렬화에서 빠지는 메모리 전용 필드가 존재해, 같은 방식이 검증된 패턴이다.
- **ADR-0082 §영향**이 "시체의 시각 표시는 사용자가 실물을 보고 추후 판단한다"로 이 결정을 명시적으로 열어두고 미뤄뒀다. 이 ADR과 ADR-0170이 그 미결을 닫는다.
- **사용자 결정(2026-08-19)** — 매번 감지하지 말 것 · 디스크에 저장하지 말 것 · 전송이 한 번 잘 되면 지울 것 · 종류별로 유동 처리하되 한 곳에 모을 것.

## 영향 / 불변식

- **지우는 지점은 「활성화 성공」 하나뿐이다.** 호출자를 늘리면 인과가 갈라진다 — ADR-0127이 턴 관측 정리 지점을 둘로 못박은 것과 같은 이유다.
- ★**「대화 왕복 성립」으로 되돌리지 말 것**★ — 초안의 기준이었고 구현 중에 폐기했다. 왕복은 **턴 종료 신호**로만 관측되는데 그 신호는 구조화 출력에서만 나오고, 반대로 실패 **분류**는 콘솔 바이트에서만 나온다. 두 반쪽이 출력 형식으로 갈려 서로 배타적이라 **터미널 에이전트의 기록은 영영 안 지워진다.** 게다가 턴 종료 신호는 화신 검사가 없고 논블록 계약이라, 거기서 프로필 잠금을 잡는 것 자체가 계약 위반이었다.
- **성공을 지움 근거로 삼는 것이 정직한 이유** — 이어 열기가 조기종료 창을 넘겼으면 이어받을 대화가 **실재했다**는 뜻이고, 새로 떴으면 이제 하나 생긴다. 그 뒤 한 마디도 없이 닫으면 **다음 활성화가 다시 실패해 다시 기록된다** — 그게 결정 1(미리 감지하지 않고 실패한 자리에서 기록한다)이다.
- **데몬 재기동 시 소멸한다.** 앱 창 재시작은 견딘다.
- **모르는 실패 종류는 막지 않는다(fail-open).** 분류가 "그 밖"으로 떨어지면 「다시 해볼 가치 있음」으로 취급한다 — 막았다가 멀쩡한 항목을 못 여는 손해가 헛시도 한 번보다 크다.
- 통신 규격에 이 값을 나르는 칸이 하나 추가된다(항목 단위).
