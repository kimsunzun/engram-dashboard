## 맥락

In the S18.5 send overhaul (ADR-0111/0112/0114) ratification Q&A (2026-07-30), the user re-examined the scope of the entry reject. Three issues:

1. **Rejecting even sleeping sessions went too far.** The core basis for discarding absent parking was "a typo or a dead name is silently parked and vanishes with no notice", but a sleeping (process closed, restorable) session is a **name that really exists in the profile list**, so it can be told apart from a typo — that basis does not apply to sleeping. The parking + TTL machinery is also identical to busy parking, so there is no new cost (the only difference is the flush trigger: the idle transition is automatic, restore is manual).
2. **Contract handling for a reply that did not arrive.** The old implementation closed the contract on the mere fact that a reply was sent, so the ledger claimed a message that never arrived as `replied`, and the provisional proposal of the review round (A1) left the contract open so a zombie contract remained — both are targets for rejection.
3. **Ratifying the namesake case (A8/M3).** Whether to promote to policy the "resolved token first" (A8) and "visible failure for duplicate entities" (M3) that the review round provisionally adopted.

## 결정

1. **A 3-branch entry + a capability sub-rule.** At the moment of sending, the recipient decision splits three ways: **roster (= every live session — structured output is not an eligibility condition)** = deliver / **sleeping (profile exists, restorable) = park** (`pending`, flush on reappearance — reusing the existing roster-diff machinery) / **none (a name that exists nowhere) = a failure row `RECIPIENT_NOT_FOUND`**. The principle in one line: **"If it is alive, send; if it can come alive later, wait; if it does not exist, fail loudly."** Within the delivery branch, **capability splits only "when to inject"** — if there is a turn signal, the idle gate (if busy, park); **if there is no turn signal, inject at once with no gate** (decision 7). The `@all` expansion uses the roster (= everyone alive right now, counterparts with no turn signal included). **Same-name blocking applies to the sleeping layer too** — if there are two or more sleeping profiles with the same name, do not park and give `RECIPIENT_AMBIGUOUS` (name-keyed parking would create a path where "whichever is restored first quietly receives", head-on in conflict with decision 5). For a same name that overlaps across layers, **the roster layer wins**.
2. **Reply contract — acceptance means complete, fail-close only when the name is missing, anything else is no action** (broken down and minimized by user decision 2026-07-30). If **accepted** (delivered|pending), close it as `replied` — **parking is acceptance too** ("꽂으면 계약 완료" — once you plug it in, the contract is complete). Even if the requester is then deleted and the parked reply is cleared away, **the contract stays `replied`** (no reversal — the contract axis is "did it answer", and the delivery axis records "did it arrive" exactly as `RECIPIENT_DELETED`, so both axes are true. Reversing an endpoint is a class the transition graph forbids). **Only `RECIPIENT_NOT_FOUND`** fail-closes the contract as `reply_failed` (removed from the open list, the deadline sweep, and the 512 count; history remains) — there is nowhere to go. **Any other failure** (`MAILBOX_FULL`, `RECIPIENT_AMBIGUOUS`) is **no action = the contract stays open** (a retry closes it by the normal path). On the reply path, `REQUEST_CAPACITY` and `RECIPIENT_DELETED` structurally cannot occur, so they are left out of the classification. The joining with the contract lifetime clause and the guard priority are in ADR-0118.
3. **Profile deletion = a bulk cleanup — the condition is "deleted ∧ that session is not in the roster (id axis) ∧ no live session carries that name (name axis)", a single shot at deletion time** (user decision 2026-07-30 + the name axis added by review R2 — the gate looks at one id but the cleanup sweeps by name key, so if a same-name live session exists, its letters would die for a false reason. The name-axis guard becomes unnecessary once ADR-0115 enforces uniqueness). The profile delete command does not kill a running session, so a state exists where "only the tree item was deleted but the process is alive" — that counterpart is a live recipient that can receive soon, so it is not a cleanup target. When the condition holds: ① terminate the items parked for that name as `failed` + **`RECIPIENT_DELETED`** (a ledger endpoint + a query hint — do not drop them silently) ② terminate as `reply_failed` the open contracts whose **requester** is that name (do not touch ones already `replied`, and keep contracts where the replier side was deleted — the deadline notice path survives). **No re-evaluation trigger is set** — it is explicitly accepted that the leftovers of a session that dies late after the deletion, and items parked after the decision was made, fall under the **TTL 24h `expired`** (a symmetric trigger and a tombstone are not adopted — rejected alternatives). The deletion UX (whether deleting from the tree is accompanied by a kill · a forced/quiet option) is outside this decision (the agent lifetime model — backlog).
4. **Add the failure code `RECIPIENT_DELETED` + legalize the `pending → failed` edge, limited.** Deletion cleanup is the only path that terminates an *already parked* record after the fact, so it cannot be expressed as "the recording time is the endpoint" → add `pending → failed` to the ledger transition graph **limited to this path** (`delivered → failed` stays illegal). The code name is self-explanatory, and **a hint is attached to the query row** so that the sending LLM knows the next action (resending is pointless → report to the user) from the code alone, and even more from the hint.
5. **Namesakes = unsupported (the A8/M3 ratification result).** Remove the "send again with the exact id" guidance from the `RECIPIENT_AMBIGUOUS` hint and replace it with **"재발송하지 말고 사용자에게 알려라" (do not resend, tell the user)**. The A8 (resolution first) and M3 (visible failure) code is **not promoted to policy, kept as a defense** (not written into the spec) — the root removal is done by ADR-0115 (spawn name uniqueness).
6. **The expiry of sleeping parking is accepted as quiet**(user decision 2026-07-30). Items parked for a sleeping name that is never restored are `expired` by the 24h TTL, and **there is no active notice to the sender** — keep one rule, the same as busy parking (do not make exceptions per parking reason). Improvement candidates (an expiry notice · a "not delivered" distinguishing wording in the request deadline notice) are backlog.
7. **A backend with no turn signal = inject at once with no gate** (user decision 2026-07-30 — **discarding and replacing** the `RECIPIENT_UNREACHABLE` reject provisionally adopted the same day). The basis is the user's observation: **that CLI has its own input queue**, so it holds input put in during a turn and consumes it after the turn ends → we have no reason to observe idle (that CLI itself is the gate). So instead of special-casing by mode name, handle it with **one capability rule**: turn signal present → idle gate / absent → inject at once (no waiting, no retry, "just send and never look back"). **The price, known and accepted**: if the injection moment is in a modal state (permission approval · menu · plan confirmation), the input can be eaten by that widget; if a person is typing on the same screen it gets mixed; and the submit handling of a multi-line envelope depends on the paste method — if a problem is actually observed, measure it with a spike then and narrow it (the spec §7 measurement item is reinstated).

## 거부한 대안

- **Keep rejecting sleeping recipients (ADR-0112 decision 2 — current)** — the original basis of instant typo feedback does not apply to names that really exist in the profile. Accumulating for a sleeping counterpart is the natural semantics of a mailbox, and the price (an indefinite wait) is the same machinery as busy parking (the same 24h TTL safety net), so no new cost.
- **Sleeping parking + wake as well** — out of scope this time. wake-on-request keeps its v2 candidate status (the decision in ADR-0112 not to adopt wake is valid — "instead of rejecting" just goes back to "instead of parking").
- **Always close the reply (the old implementation)** — a message that did not arrive is recorded as `replied` (the ledger lies) · the reply debt disappears · the deadline notice never fires.
- **Leave the contract open (the review's provisional A1)** — in preparation for a re-reply after a respawn, a zombie contract remains up to the cap pressure. Recording the failure as it is and clearing it away fits the user's stance ("이상한 것 제거" — remove weird things).
- **Promote A8/M3 to policy (write it into the spec)** — namesakes are themselves unsupported, so do not turn the id-rescue flow into a supported policy. Keep only the code defense (preventing silent row disappearance) and let 0115 make it a dead letter.
- **Close the contract on a transient-reason failure too** — the contract would close as a permanent failure because a live requester's mailbox was briefly full, and even if a retry is actually delivered the ledger stays "reply failed". Rejected by user decision (details = ADR-0118 decision 2). *(The current code is not this way — the S18.5 implementation is the provisional A1 proposal that leaves the contract open regardless of the failure reason, and closing unconditionally was the **old implementation** before that.)*
- **Reverse the contract from `replied` when the requester is deleted after parking was accepted** — reversing an endpoint state is a class the transition graph forbids (time rewriting · a wrongly fired close), and all it gains is a duplicate notation of a fact the delivery record already states. Rejected by "꽂으면 완료" (plug it in and it is complete) (user decision).
- **A symmetric trigger for deletion cleanup (re-fire on roster exit ∧ profile absence)** — it could reap at once the leftovers of a session that died late after deletion, but the TTL 24h already gives boundedness and there is no leak or contamination. Not adopted under "지금 필요한 최소만" (only the minimum needed now) (user policy 2026-07-30) — backlog.
- **Re-check a deletion tombstone at the parking insertion point** — it removes the leftovers of the decision↔insertion window, but adds new state and release rules, and those leftovers are also bounded by the TTL. Not adopted — backlog.
- **Reject a counterpart with no turn signal with a dedicated failure code (`RECIPIENT_UNREACHABLE`)** (provisionally adopted the same day → **discarded**) — the premise "we cannot observe it, so we cannot deliver" was wrong: that CLI's input queue plays the gate role, so delivery holds without observation. It is also a simplification that removes one code and one branch. The reason for recording the reason for discarding = to keep the next session from reverting to "it cannot be observed, so it must fail" (decision 7).
- **Park a counterpart with no turn signal like a sleeping one** — there is no trigger to wake it, so it becomes a silent 24h disappearance (the "quiet expiry" the user accepted is limited to the population that is *truly asleep*). Since inject at once was adopted, there is no reason to park to begin with. Rejected.
- **Merge the terminal mode into `RECIPIENT_NOT_FOUND`** (keep the 3rd-round behavior) — it is a lie that says a live counterpart "does not exist", and since delivery is now possible, the reject itself is unnecessary. Rejected.
- **Deletion cleanup trigger = `DeleteProfile` itself** — it would kill even the parked items and contracts of a live session whose profile alone was deleted, recording a counterpart that would be delivered normally as a failure (the opposite of the purpose of this amendment). Rejected by narrowing to "deleted ∧ not in the roster".
- **Reuse `expired` for deletion-cleanup parked items** — it is deletion, not a time expiry, so the reason would become false. Replaced by the new code `RECIPIENT_DELETED`.
- **Build an atomic single view of sessions and profiles at the entry** — the two sources have different owners (AgentManager · ProfileRegistry), so a unified lock would touch the lock-order convention (ADR-0006). **The race leftovers are bounded by the TTL 24h** (deletion cleanup **cannot** reap them — the single-shot nature of decision 3), so accepting that bound is the low-cost choice (the spec §5 race item).
- **Add an active notice to the sender when sleeping parking expires** — not adopted in this scope (decision 6). The judgment is that the cost of splitting the rule from busy parking and adding an exception is larger than the benefit now — add it if it becomes needed.

## 근거

- User decision (2026-07-30 ratification Q&A): "부재(비활성)시에는 쌓였다가 보내져야지" (when absent (inactive), it should pile up and be sent) → after the terminology cleanup, "잠들 때는 파킹, 죽었을/삭제 때만 실패" (park when asleep, fail only when dead/deleted) confirmed · "회신이 메일로 안 가니까 계약은 실패이고 목록에서 제거" (since the reply does not go out as mail, the contract is a failure and removed from the list) → split into two classes by the review findings (A = confirmed termination / B = stays open) · "동명이인은 지원하지 않는다고 얘기해 — 다시 보내지도 말고 사용자에게 전달" (say that namesakes are not supported — do not even resend, pass it to the user) · "실패코드로 해. 다만 그 코드만 보고 에이전트가 이해할 수 있게" (make it a failure code. But so that an agent can understand from the code alone) → a self-explanatory code name + a query hint · "그냥 이대로 하고 나중에 필요하면 추가" (just do it as is and add later if needed) (expiry notice) · the price objection ("비활성 파킹이 이미 있잖아" (inactive parking already exists)) confirmed that sleeping parking costs the same.
- Code check: the source for telling sleeping apart (ProfileRegistry · the `DeleteProfile` command) really exists · the reappearance flush machinery (roster diff Appear) really exists — it holds by extending wiring with no new machinery.
- **The `/review doc full` adversarial review found that the firing conditions and ledger vocabulary of decisions 2 and 3 were underspecified to the point of being unimplementable, and they were settled by 4 user ratification questions** (doc-aware = found violations of the contract axis and transition graph / blind = found leftover contradictory wording). The 3 big risks the review pointed out: a transient failure of a live requester permanently closing the contract · deleting the profile of a live session killing deliverable mail · quiet delivery to a sleeping same name (a new hole that the 3rd round did not have).

## 영향 / 불변식

- **Entry decision = 2 sources · 2 physical lookups.** The roster (1 session snapshot) + the profile list (1). The one-snapshot principle (ADR-0111 decision 2) is kept — taking the session snapshot twice brings the half-decision back. Whether output is structured is an attribute that comes attached to each snapshot item, so it is **not a separate lookup** (it does not split membership, it only splits timing — decision 7). The leftovers of the race between the two lookups are **accepted as TTL-bounded** (an atomic view and a tombstone are not adopted — rejected alternatives).
- **Profile-layer name derivation = the same rule as live sessions — the single source is `core/agent/name.rs::canonical_name_or_id_fallback`** (the very function `resolve_canonical_name` uses for live sessions. It has **two guards**: ignoring an empty override + degrading to the first 8 characters of the id on a placeholder — `resolve_display_name` does not have them, so using it splits the rule). **The cwd input must match too:** the live name is derived from the **session.cwd** that was `dunce::canonicalize`d at spawn, but `AgentProfile.cwd` can hold a raw value (`.`, `..`, symlinks, Windows case differences) → the profile cwd is **fed in after canonicalize** (on failure, a raw fallback + a comment). If they diverge, the parking key ≠ the live name after restore, so the letter never finds its owner and silently disappears by 24h expiry — the very failure this slice is meant to prevent.
- **Trap: the `AgentProfile.name` field is not the display name** (it is only the original string received at CreateProfile — the tree and the address scheme do not use it). Extracting the sleeping name from that field silently diverges.
- **A pre-existing comment mismatch (an item to confirm at implementation):** `profile.rs:157` claims "the profile cwd is canonicalized before storing", but `connection_core.rs:1114` hands that canonicalization to PresetRegistry — find out which of the two comments is true and fix one (this slice defends by feeding in after canonicalize).
- **The meaning of `RECIPIENT_NOT_FOUND` narrows** = "a name in neither the roster nor the profiles". Sleeping no longer gives this code, and a live session with no turn signal does not either (it gets delivered).
- **The roster predicate = state only** (`Running`, `Exiting`). The structured-output condition leaves the predicate and moves to the place that splits "when to inject". **This predicate was found undefended in the mutation measurement** (all tests stay green even with the state condition deleted) → a seal test at the real adapter level is a required deliverable of this slice.
- **Ledger transition graph amendment** — add one edge, `pending → failed` (limited to deletion cleanup). `delivered → failed` stays illegal. `reply_failed` is on the **contract axis**, so it is not a transition of the delivery state (`DeliveryStatus`) (the original request's delivery record stays at `delivered`).
- **The new seam attaches to `DeliveryPort`** (corrected by reconnaissance — the `ControlPlanePort` in the draft was a mistake): `ControlPlanePort` has only the two methods, envelope format and delivery observation, and its adapter (`ControlRegistry`) does not hold `AgentManager`. The side that owns the roster is `DeliveryPort` (its adapter `ManagerDeliveryPort` holds `Arc<AgentManager>`), so roster and sleeping-name lookups are also put there. **Renamed at implementation:** the old `live_reachable_agents` mismatched its predicate, so it became `live_agents`, and it carries whether each item has a turn signal. The messaging kernel's independence from workspace crates (ADR-0110) is unchanged — the real lookup is owned by the daemon adapter.
- **The @all expansion is based on the roster** — sleeping names are not included in a broadcast (a broadcast is "everyone present now"), and **a live session with no turn signal is included** (since it is a delivery target).
- **The structured condition must also be removed from the reappearance-flush candidate predicate** (found during implementation — a consequence of decision 7): a session with no turn signal can **also have parked items from an injection failure**, and if the appearance-flush candidates are left with the old structured filter, those parked items never get a flush trigger and quietly expire by the 24h TTL. But **the tap attach (turn observation) axis keeps the structured condition** — there is no reason to attach a tap to a counterpart with no turn events, and the discipline "gate set = tap set" lives there.
- The joining with the ADR-0108 contract lifetime clause, the guard priority, and the 512 count are canonical in **ADR-0118**.
- Sleeping-parked items are also subject to the same parking mailbox cap and 24h TTL sweep (no separate lane). **The logical claim "the reclaim criterion is an empty set" of ADR-0114 decision 1 is weakened** — the basis for boundedness moves from logic to "TTL 24h + mailbox cap" (discarding reclaim itself is kept, spec §5).
- **The "parking = only for busy and injection failure" item in the ADR-0111 impact section dies with this decision** (sleeping parking is the third reason — included in the range the 0117 stamp points to).
- **Code anchors and comments to update at implementation** (descriptions of the old semantics remain — a required deliverable of the slice):
  - `messaging/src/service.rs` — the module header's "sleeping sessions are rejected too" description · the entry branch comment · **the roster reachability comment (~320-323, the v1 description "unreachable → pull the parking decision forward to the roster stage")** · the `TODO(ratify)` markers in **8 places** (854 · 2572 · 2680 · 2685 · 2714 in the body + 7886 · 8885 · 9162 in tests — ratification is done, so leaving the "awaiting ratification" wording makes the next session read a decided policy as open).
  - **An existing test that must be flipped**: `service.rs:7886` `a_reply_that_reached_nobody_leaves_the_contract_open_and_the_timeout_still_fires` — it asserts that **in a confirmed-unreachable case the contract stays open**, but the ratified rule closes it as `reply_failed` in that case. Do not keep the old semantics on the strength of a green test.
  - The `mailbox.rs` header · `ledger.rs` (the transition graph comment and the description "no incoming edge" of `DeliveryStatus::Failed`) · the new anchors `// ADR-0116` and `// ADR-0118`.
