# ADR-0193: Each transport implementation decides 「지금 보낼 수 있나」 (“can we send now?”) for queue release from its own state

- 상태: 확정 (2026-09-10, basis: finding from a 2-person adversarial review + measured in code) · 부분 폐기 by ADR-0231 (the codex transport's handoff policy steer, the Idle order, and the stop after an error)
- 관련: Amends ADR-0190 (the clause 「턴이 도는가는 코어가 이미 안다」 in decision 4 (the part that narrowed the queue-release decision to the core alone)) · ADR-0127(the two points that clean up turn observation) · ADR-0189(the codex transport) · ADR-0191(the transport creation path) · `docs/process/S21-codex-backend/trd-phase2a.md` §4-10 · step-log S21 · Amended by ADR-0231 (the codex transport's handoff policy steer, the Idle order, and the stop after an error)

## 맥락

ADR-0190 decision 4 wrote: 「「턴이 도는가」는 **코어가 이미 안다.** 큐가 그 사실을 **읽는다**(`AgentManager::turns()`)」 (“"Is a turn running" is **already known to the core.** The queue **reads** that fact (AgentManager::turns())”). That wording narrowed the queue-release decision to a single core fact layer.

★**For codex, that fact layer is fail-open**★ — `BusyPolicy::is_busy` answers 「안 바쁨」 (“not busy”) at once when there is no fact for the turn in question (`crates/engram-dashboard-messaging/src/busy.rs:177-180`), and codex does not declare a synthetic input echo, so it takes the default `None` (`crates/engram-dashboard-agent/src/backend/mod.rs:209-211`). So **an unobserved window is real, from the moment we write the turn start until the first notification arrives**, and reading the core in that window returns 「한가함」 (“idle”).

If the queue trusts that answer as it is, it releases the next item at once and **two turn-start requests overlap.**

★**Decision 3 of the same ADR already said 「판정은 각 구현체 안에서 하되 축은 공용」 (“the decision is made inside each implementation, but the axis is shared”)**★ — decision 4 wrote that axis narrowed to a single core source, and that is the substance of the mismatch. So this ADR fixes decision 4 only, to bring the two clauses back into line.

## 결정

**Each transport implementation decides 「지금 보낼 수 있나」 (“can we send now?”) for queue release from its own state.** The axis is still shared (ADR-0190 decision 3 stands).

- **codex reads its own turn state machine** — because of the unobserved window above. It knows by itself the `turn/start` it sent and the end notification it received, so it can answer without going through the core.
- ★**claude json is the same — no exception is made**★. The first draft of this ADR wrote 「claude json 은 코어를 읽어도 된다 — 자기 합성 에코가 그 사실을 **동기적으로** 만들어 미관측 창이 없다」 (“claude json may read the core — its own synthetic echo makes that fact **synchronously**, so there is no unobserved window”), but **that ground is false**: the echo is emitted **after `send_input` has succeeded and returned** (`crates/engram-dashboard-agent/src/session.rs:165`·`:176` — the comment at that spot says 「`send_input` 성공 **후**」 (“after send_input succeeds”) explicitly). So claude json has a window too. It is narrow, not absent, and since `send_input` takes `&self`, concurrent calls are structurally possible (`crates/engram-dashboard-agent/src/transport/mod.rs:41-45`), so two callers can see the same 「한가함」 (“idle”) and start two turns. **The axis is not whether the decision reads the core, but whether the 「보낼 수 있나」 (“can we send?”) check and the 「진행 중으로 전이」 (“transition to in progress”) sit under one lock** — that atomicity can only be built inside the implementation, which is why the decision lives there. (Source of the finding = a round-3 blind review, 2026-09-10.)
- **Nothing is added to the core's turn fact layer.** The queue still **only reads**, and the points that clean up turn observation are still two (ADR-0127).

## 거부한 대안

- **Change the core fact layer for codex so the unobserved window disappears** — this increases the points that **write** turn observation. It touches the producer axis that pairs with the 「정리 = 두 지점뿐」 (“cleanup = two points only”) fixed by ADR-0127, and the causality splits. It is rejected on that invariant, not on a user preference.
- **Have codex declare a synthetic input echo to create the fact** — that echo is **for the screen** (it shows the user message at once in json mode — the `input_echo_event` comment states that purpose). It would repurpose a surface with a different purpose as input to the decision, and it overlaps with what codex echoes back as a `userMessage` item, so it **creates a new double-display and dedup problem** (measured = that backend does emit `userMessage` items). It is rejected on this measurement, not on taste.

## 근거

- **Two lines of measured evidence for the unobserved window** — `crates/engram-dashboard-messaging/src/busy.rs:177-180` (`return false` when there is no fact — fail-open) · `crates/engram-dashboard-agent/src/backend/mod.rs:209-211` (the `input_echo_event` default is `None`, and codex takes this default). The two multiply, and 「턴을 시작했는데 코어는 한가하다고 답한다」 (“we started a turn but the core answers that it is idle”) holds.
- **Consistency with ADR-0190's own decision 3** — that decision already set up 「판정은 각 구현체, 축은 공용」 (“the decision is made by each implementation, the axis is shared”). This ADR does not create a new axis; it brings decision 4 back to that axis.
- **A 2-person adversarial review pointed at the same mismatch in two places** — the finding that implementing decision 4 literally makes overlapping turn starts on codex.

## 영향 / 불변식

- **The rest of ADR-0190 stands** — do not drop input · only queue now and leave manipulation for later · PTY is out of scope. So this is a **partial amendment**, not a full discard.
- **No conflict with ADR-0127** — the queue only reads turn facts, and the two cleanup points stay as they are.
- ★**Open item that remains: whether the 「보낼 수 있나」 (“can we send?”) check and the 「진행 중으로 전이」 (“transition to in progress”) sit under the same lock**★ — `AgentTransport::send_input` takes `&self`, so concurrent calls are structurally possible (`crates/engram-dashboard-agent/src/transport/mod.rs:41-45`). This ADR fixes only **where** the decision lives, and the atomicity is decided at implementation time.
- **Trigger to reopen this decision** — if the core fact layer changes so that the unobserved window disappears (a separate decision), the per-implementation split becomes unnecessary.
