# ADR-0329: The backend tag of instructions and skills is attached to the preset entry — asset files are not touched

- 상태: 제안 (2026-10-31, basis: user decisions G29 (2026-10-30 「프리셋에 하는게 맞지 싶은데」) · G51 · G51-PURPOSE (2026-10-31 — order · purpose) + main M20 · M25 · M26 (reported) · research `docs/research/per-agent-instructions-practice-2026-10-30.md`)
- 관련: PRD R54 · P12 (dim the lines that are not loaded) · ADR-0327 (per-backend priming of 「기본」) · ADR-0337 (codex terminal notice) · TRD §1-2 · §1-3 1 · 5 · 6 · §7 32 · M24-4 (global order — reversed by G51)

## 맥락
For each agent, we needed a way to load claude-only and codex-only instructions and skills in addition to the common instructions (G29 — a new feature · a PRD-level addition). Where do we attach the tag? The purpose of the tag (G51-PURPOSE — user 「프리셋이 메인세션 프리셋인데 로컬모델이 구져서 제대로 안들으면 클로드랑 다르게 덧붙이는 느낌으로 해야되는거 아니면 각각 쓰거나」): it is a patch that adds lines the preset's common entries do not cover, for a backend that does not follow a preset well (e.g. a weaker model). If the content differs greatly per backend, write separate presets.

## 결정
1. An instruction or skill entry is a path string (= common) or `{path, backend: claude|codex}`. The tag is **in the preset** and not in the asset file.
2. `presets` and `settings` entries stay path strings as they are — for settings, the `claude:` and `codex:` fields inside the file already separate the backend.
3. Loading order = **per preset** — in expanded order, each preset's common entries → that preset's tag entries for that backend (G51 — e.g. if [A, B] are attached and A = [common a · codex a'] · B = [common b · codex b'], the order a codex agent receives = a → a' → b → b'). A preset contained inside is expanded before its own entries (D1 — unchanged). It adds and does not overwrite. The same path counts once, at its first position in the expanded order (M14 — unchanged).
4. The conflict check is done among the entries actually loaded for that agent.
5. The codex terminal still loads no instructions or skills, and also puts the codex tag lines into the notice (M20 · ADR-0337). The built-in 「기본」 can load different priming per backend through the tag.
6. Commands = an optional `backend` on `preset.add` + tag change `preset.setBackend {path, items, backend?}` (M26). The agent slot shows lines not loaded on that agent's backend dimmed (same as P12). The screen shape (three groups: common / claude-only / codex-only · changing the tag by dragging or right-click) is shown again in the client stage (M20).

## 거부한 대안
- **A tag in the front matter of the asset file** (rulesync shape — option (b) of the research) — it requires editing a received file · the same file cannot be used differently per preset · and the front matter must be stripped when loading (G29 · research 「우리에게」 table · the user chose (a)).
- **All common entries of the whole expansion → all entries of that backend (global order)** (M24-4 · M25 OVERRIDDEN — the shape the main session had decided · the old Decision 3 of this ADR's draft) — the user reversed it: 「공용 전용이 그렇게 쓰이는게 아니라 공용으로 안되는걸 덧붙이는 느김이라 aa bb 가 맞을듯?」 (G51 — a backend entry adds what that preset's common entries do not cover, so it stands right after them).
- **Dedicated first → common later** (the order Roo Code wrote in its docs — research conclusion 3) — the same user reason (G51).

## 근거
- Research (2026-10-30): 「공통 기본 + 에이전트별 예외」 is an existing shape (rulesync `targets` — both rules and skills) · no precedent was found for putting the mark on the bundle side · nearly all merging is concatenation, not overwriting.
- User decisions G29 · G51 · G51-PURPOSE.

## 영향 / 불변식
- We do not add a backend field to the asset file format — the property of not editing a received file is the reason for this decision.
- If the order rule (per preset · common, then that backend) changes, Decision 3 and the priming position of 「기본」 move together — since 「기본」 is expanded at the very front (TRD §1-3 1), that backend's tag priming is loaded right after the common priming of 「기본」 and before the user presets (under a global order, it would be after all common entries).
- The conflict check is independent of order — it counts among the loaded entries (Decision 4).
