# ADR-0329: 지침 · 스킬의 백엔드 꼬리표는 프리셋 항목에 단다 — 에셋 파일은 손대지 않는다

- 상태: 제안 (2026-10-31, 근거: 사용자 결정 G29(2026-10-30 「프리셋에 하는게 맞지 싶은데」) · G51 · G51-PURPOSE(2026-10-31 — 순서 · 쓰임) + 메인 M20 · M25 · M26(보고) · 조사 `docs/research/per-agent-instructions-practice-2026-10-30.md`)
- 관련: PRD R54 · P12(안 실리는 줄 흐림) · ADR-0327(「기본」 의 백엔드별 프라이밍) · S25 초안 K(미채번 — codex 터미널 알림) · TRD §1-2 · §1-3 1 · 5 · 6 · §7 32 · M24-4(전역 순서 — G51 이 뒤집음)

## 맥락
에이전트마다 공통 지침에 더해 claude · codex 전용 지침 · 스킬을 실을 길이 필요했다(G29 — 새 기능 · PRD 수준 추가). 꼬리표를 어디에 다느냐. 꼬리표의 쓰임(G51-PURPOSE — 사용자 「프리셋이 메인세션 프리셋인데 로컬모델이 구져서 제대로 안들으면 클로드랑 다르게 덧붙이는 느낌으로 해야되는거 아니면 각각 쓰거나」): 한 프리셋을 잘 따르지 못하는 백엔드(예 약한 모델)에 그 프리셋의 공통 항목이 못 덮는 줄을 덧붙이는 패치다. 백엔드마다 내용이 크게 다르면 프리셋을 따로 쓴다.

## 결정
1. 지침 · 스킬 항목은 경로 문자열(= 공통) 또는 `{path, backend: claude|codex}` 다. 꼬리표는 **프리셋에** 있고 에셋 파일에는 없다.
2. `presets` · `settings` 항목은 경로 문자열 그대로다 — 설정은 파일 안 `claude:` · `codex:` 칸이 이미 백엔드를 가른다.
3. 실리는 순서 = **프리셋마다** — 펼친 순서대로 각 프리셋의 공통 항목 → 그 프리셋의 그 백엔드 꼬리표 항목(G51 — 예 [A, B] 가 붙고 A = [공통 a · codex a'] · B = [공통 b · codex b'] 면 codex 에이전트가 받는 순서 = a → a' → b → b'). 안에 든 프리셋은 자기 항목보다 먼저 펼친다(D1 — 그대로). 덧붙임이지 덮어쓰기가 아니다. 같은 경로는 펼친 순서의 처음 자리 한 번이다(M14 — 그대로).
4. 충돌 검사는 그 에이전트에 실제로 실리는 항목끼리 한다.
5. codex 터미널은 여전히 지침 · 스킬을 싣지 않고 codex 꼬리표 줄도 알림에 넣는다(M20 · S25 초안 K(미채번)). 기본 제공 「기본」 은 꼬리표로 백엔드마다 다른 프라이밍을 실을 수 있다.
6. 명령 = `preset.add` 의 선택 `backend` + 꼬리표 바꾸기 `preset.setBackend {path, items, backend?}`(M26). 에이전트 슬롯은 그 에이전트 백엔드에 안 실리는 줄을 흐리게 보인다(P12 와 같음). 화면 꼴(공통 / claude만 / codex만 세 묶음 · 끌기나 우클릭으로 꼬리표 바꾸기)은 클라이언트 단계에서 다시 보인다(M20).

## 거부한 대안
- **에셋 파일 앞머리에 꼬리표**(rulesync 꼴 — 조사의 (나)) — 받은 파일을 고쳐야 하고 · 같은 파일을 프리셋마다 달리 못 쓰며 · 실을 때 앞머리를 벗겨야 한다(G29 · 조사 「우리에게」 표 · 사용자가 (가) 를 골랐다).
- **펼친 전체에서 공통 항목 전부 → 그 백엔드 항목 전부(전역 순서)**(M24-4 · M25 OVERRIDDEN — 메인 세션이 정했던 꼴 · 이 ADR 초안의 옛 결정 3) — 사용자가 뒤집었다: 「공용 전용이 그렇게 쓰이는게 아니라 공용으로 안되는걸 덧붙이는 느김이라 aa bb 가 맞을듯?」(G51 — 백엔드 항목은 그 프리셋의 공통 항목이 못 덮는 것을 덧붙이는 것이라 그 바로 뒤에 선다).
- **전용 먼저 → 공통 나중**(Roo Code 가 문서로 적은 순서 — 조사 결론 3) — 같은 사용자 이유(G51).

## 근거
- 조사(2026-10-30): 「공통 기본 + 에이전트별 예외」 는 있는 꼴이다(rulesync `targets` — 규칙 · 스킬 둘 다) · 묶음 쪽에 표시를 다는 선례는 못 찾았다 · 합치기는 거의 전부 덮어쓰기가 아니라 이어 붙이기다.
- 사용자 결정 G29 · G51 · G51-PURPOSE.

## 영향 / 불변식
- 에셋 파일 형식에 백엔드 칸을 더하지 않는다 — 받은 파일을 고치지 않는다는 성질이 이 결정의 이유다.
- 순서 규칙(프리셋마다 · 공통 다음 그 백엔드)을 바꾸면 결정 3 과 「기본」 의 프라이밍 자리가 함께 움직인다 — 「기본」 이 맨 앞에 펼쳐지므로(TRD §1-3 1) 그 백엔드 꼬리표 프라이밍은 「기본」 의 공통 프라이밍 바로 뒤 · 사용자 프리셋 앞에 실린다(전역 순서였다면 모든 공통 항목 뒤였다).
- 충돌 검사는 순서와 무관하다 — 실리는 항목끼리 센다(결정 4).
