# ADR-0297: 슬롯 도킹 탭 끌기 — 끄는 동안 아무것도 막지 않음 · 놓을 때 대상을 다시 찾아 있으면 붙이고 없으면 무동작

- 상태: 확정 (2026-10-20, 근거: 사용자 결정(「상관없어 그냥 예외 최대한 적게 넣으면 됨. 관행에 최대한 맞춰서」 · 「크리티컬한게 아니고 어차피 유저가 다시 하면 되는거라서」) + 조사 `docs/research/drag-external-events-practice-2026-10-20.md`)
- 관련: Amends ADR-0296 (끌기 도중 셸 호출 0 불변식의 범위) · TRD `docs/process/S21-slot-docking/trd.md`(7판 §2-2 · §2-4 · §3-3 · §4-3 · §4-7 · §8-4) · U3 코드 리뷰(2026-10-20 · FIX)

## 맥락
ADR-0296 은 「끌기 도중 셸 호출 0」을 불변식으로 두었고, TRD 7판은 그것을 끌기가 *일으키는* 호출 전부로 넓혀 터미널 `resizePty` 를 끄는 동안 미루게 했다(§4-7 · U3 조각 A). U3 코드 리뷰(2026-10-20)가 같은 틀 밖에서 새는 호출 둘을 더 잡았다 — 창이 막 뜬 직후의 창 틀 조회(`window_frame`) · 캔버스 크기 보고의 대기 타이머. 끌기와 무관한 호출이 생길 때마다 예외를 하나씩 더하는 구조다. 사용자 물음 — 「끌기 때문에 메인에 있는걸 멈추면 모든 예외사항들을 추가해야되서」. 같은 리뷰에서 놓을 때의 처리도 정했다 — 놓기는 미리보기 기준(놓은 순간 좌표로 다시 판정하지 않음 — 「유저는 미리보기로 판단하는거잖아」) · 같은 창 같은 자리 놓기는 셸에 아무것도 보내지 않음(「드래그 스타트 안보내는거면 엔드도 보내지마」).

## 결정
1. **끄는 동안 아무것도 막지 않고 미루지 않는다.** 끌기와 무관한 셸 호출(터미널 크기 맞춤 · 창 틀 조회 · 캔버스 크기 보고 · LLM 의 탭 · 창 조작 등)은 끄는 동안에도 평소대로 흐른다. ADR-0296 의 불변식은 **「끌기가 끄는 동안 자기 판정 · 상태를 셸과 맞추지 않는다 — 끌기 명령은 놓을 때(받은 창의 drop · 출처의 dragend) 보낸다」**로 좁힌다(옛 엔진의 경계 동기화 결함을 막는 몫은 그대로다).
2. **놓을 때 셸은 놓기가 가리킨 대상을 id 로 다시 찾는다** — 끄는 탭 · 대상 탭 · 대상 칸. 있으면 **지금 상태에 맞춰** 적용하고, 없으면 무동작이다. 예: 탭바 자리가 그사이 줄어든 목록 길이를 넘으면 끝 자리로 자른다 · 대상 칸이 그사이 나뉘었어도 그 칸이 남아 있으면 그 칸에 붙인다 · 끄는 탭 · 대상 칸이 사라졌으면 아무 일도 없다.
3. **놓을 때의 나머지**
   - **같이 정한 것(2026-10-20)** — 같은 창 같은 자리 놓기는 출처 dragend 도 보내지 않는다(셸 호출 0 회 — 「드래그 스타트 안보내는거면 엔드도 보내지마」).
   - **그대로인 것** — 놓기는 미리보기(마지막 판정)가 가리킨 대상으로 한다(사용자 재확인 「유저는 미리보기로 판단하는거잖아」) · 엔진이 접은 끌기는 셸 호출 0 회 · 끄는 동안 판정은 웹이 혼자 한다 · 취소 · 무시 뒤 출처의 원래 선택 되돌리기는 조건부 `switch_tab_if`(셸이 그 창 활성이 아직 끄는 탭일 때만 바꾼다 — 놓기 대조가 아니라 사용자 · LLM 이 그사이 고른 탭을 덮지 않는 장치다).

## 거부한 대안
- **미룸(TRD 7판 §4-7 · U3 조각 A)** — 끌기와 무관한 호출이 생길 때마다 예외를 더해야 한다. U3 리뷰가 그 틀 밖의 새 틈 둘(창 틀 조회 · 캔버스 보고)을 잡은 것이 실증이다. 관행에도 없다 — 끄는 동안 IPC · 저장을 막는 피어를 못 찾았고 미룸 선례는 끌기를 쥔 창 파괴 같은 국소 위험뿐이다(조사 결론 3). 사용자: 「모든 예외사항들을 추가해야되서」.
- **끄는 중 사건이 오면 끌기 취소** — 진행 중인 HTML5 끌기를 웹 코드가 취소할 길이 없고(Chromium 소스 — 조사 B) 셸(wry 창 호스팅)에도 지원되는 길이 없다(Esc 주입은 미검). 끌기를 도중에 끝내는 피어는 끄는 항목이나 그 탭바(컨테이너)가 바뀔 때만 끝낸다 — Chromium = 끄는 탭 제거 · 창 끌기 중 탭 추가(강제 완료) / Lumino = 그 탭바의 탭 추가 · 제거 · 방향 바뀜(중단). IPC · 창 크기 같은 무관한 사건으로 끝내는 피어는 없다(조사 결론 2). 사용자: 「관행에 최대한 맞춰서」.
- **엄격 거절(U1 셸 코드였던 것 — TabBar 탭 목록 대조 · `SeamAt` 판 번호 · 활성 · `expect_window`)** — 놓기가 본 상태와 조금이라도 다르면 거절한다. 관행의 주류(VS Code · dockview · FlexLayout · Zed · Lumino 도크 — id 로 다시 찾고 없으면 무동작(dockview 는 던짐))보다 예외가 많고, 결과가 조금 어긋나도 치명적이지 않다 — 사용자: 「크리티컬한게 아니고 어차피 유저가 다시 하면 되는거라서」.

## 근거
- 조사 `docs/research/drag-external-events-practice-2026-10-20.md`(medium · codex 적대 리뷰 반영) — 관행 주류 = 그냥 둠 + 놓을 때 id 로 다시 찾고 없으면 무동작(dockview 는 던짐).
- 우리 「끌기 도중 셸 호출 0」은 옛 Chrome식 엔진의 동기화 결함에서 물려받은 설계 선택이다(ADR-0296 맥락). HTML5 스파이크는 끄는 동안 invoke · emit 이 정상임을 쟀다(`docs/research/slot-docking-drag-mechanism-2026-10-16.md` — RDP · 22 회 · 작은 표본). Chromium 은 DoDragDrop 루프 안에서 일부러 작업을 돌린다.

## 영향 / 불변식
- 웹: U3 조각 A(`dock/dragActive.ts` · `TerminalSlot` 의 끌기 중 미루기)를 걷었다. 창 틀 · 캔버스 보고 미루기는 짓지 않는다. 끄는 동안 캔버스 크기가 바뀌면 받는 창이 다시 재고 마지막 점으로 다시 판정한다(미리보기가 새 크기를 따르게). 열린 미리보기 회차가 없을 때 온 drop 은 그 점에서 판정한다(유일한 폴백). `viewStore` 의 `CachedView.layoutRev` 는 걷었다(HEAD 그대로).
- wire: `DropTo` 에서 판정 때 상태 칸 `TabBar.expect` · `Seam.rev` · `Seam.active` 를 뺐다 — 짐 = `TabBar{index}` · `Seam{target, anchor, side, share}` · `NewWindow{…}`. `from` 은 남는다(결과 알림을 받는 창 · 다음 활성을 쓸 창 · 새 창 자리를 셀 출처 창 틀).
- 셸: 놓기는 `DockGuard::NONE` 이다 — `DockGuard.expect_window` · `TargetExpect::SeamAt` 를 걷었다. 놓기가 본 상태를 견주는 거절은 없다 — 대상 확인은 존재뿐이고(`TabNotFound` · `WindowNotFound` · `SlotNotFound` · `SlotNotInTab`) 기하 검사(`InvalidShare` · `ZeroArea`)는 그대로다. 탭바 자리는 지금 목록 끝으로 자른다. 끄는 탭이 그사이 다른 창으로 갔으면 우리 웹뷰에 놓은 놓기는 그 탭을 지금 창에서 빼 온다(웹뷰 밖 놓기 = 아래 받아들인 틈 · `initial` 은 그 탭이 `from` 에 있을 때만 다음 활성 — `DockMove.successor_window` · 아니면 셸 승계). 이음새 대상 탭이 옮겨졌으면 그 창에 붙이고 그 창에 포커스를 준다.
- 받아들인 틈: 끄는 중 LLM 이 끄는 탭을 다른 창으로 옮기거나 닫으면 출처 머리가 떼어져 그 끌기의 출처 dragend 가 오지 않는다 — 우리 웹뷰 밖 놓기는 무동작(새 창 없음)이다. 이 결정의 원칙(예외 최소)을 적용해 메인이 정했다(사용자 위임 2026-10-21 · TRD 7판 §9-2 · §9-5).
- 남은 군살: 판 번호 `layout_rev`(셸 · `ViewSnapshot` 칸)는 소비자 없이 남고, 옛 엔진 대조(`expect_source` · `TargetExpect::{Seam, Tabs}` · `DockError::{SourceChanged, TargetChanged}`)와 함께 TRD U6(모델 군살)이 걷는다.
- TRD 7판 §2-2 · §2-4 · §3-3 · §4-3 · §4-7 · §8-4 C7(「끄는 동안 셸 호출 전부 0」 → 「끄는 동안 끌기 명령 0」)을 이 결정에 맞췄다.
- **되살리지 말 것** — 끄는 동안 무관한 호출을 막는 미룸 · 놓기가 본 상태와 다르면 거절하는 대조. 둘 다 예외를 늘린다.
