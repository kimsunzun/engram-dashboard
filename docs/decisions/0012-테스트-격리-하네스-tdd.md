# ADR-0012: Test strategy — module isolation harness + TDD

- 상태: 확정 (accumulated over S3~S10, enforced in S12)
- 관련: CLAUDE.md 구현 실행 규약·빌드 명령 · `examples/{headless,transport_smoke,session_smoke}` · ADR-0003

## 맥락
Modules must be verifiable independently, so regressions are caught fast and a concurrency or lifetime bug can be isolated to the module where it occurred. LLM coding easily produces plausible but wrong code, so a net (tests) that automatically separates pass from fail must exist first.

## 결정
1. **Module isolation harness** — every module cuts its external dependencies (Tauri/network/real processes) at a seam so it can **run on its own**.
   - Core: `examples/headless` with a Noop/test sink (the whole manager, without a frontend).
   - transport/session: `examples/transport_smoke` · `session_smoke` (measured directly, without the manager).
   - Daemon modules: gathered so that an integration test + a harness bin run them in one go.
2. **TDD** — per feature, **write the tests first (or together)** and accumulate them. A single `cargo test` (workspace root) regression-checks every module.
3. **Code passing ≠ done** — QA must include build/test + GUI measurement (`scripts/cdp.mjs`) before the task counts as complete.

## 거부한 대안
- **Integration tests only (launch the whole app to verify)** — slow, and a failure cannot be isolated to a module. Concurrency bugs are hard to reproduce.
- **Leave tests until later** — regressions are not caught as they happen, and LLM hallucinated code passes and accumulates.

## 근거
The `OutputSink`/`StatusSink` seam (ADR-0003) already makes isolated execution of the core possible. examples/headless and the smoke examples really do verify the core/transport alone, without the frontend or manager (zero regressions confirmed in S3 and S10).

## 영향 / 불변식
- **A new module comes with an isolation harness** (`#[cfg(test)]` unit tests + an example/harness bin when needed).
- Code that calls an external dependency directly and so cannot be isolated violates this ADR — cut it at a seam.
