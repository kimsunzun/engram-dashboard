# ADR-0318: 서드파티는 목적 포트 · 부품 경계로 감싼다

- 상태: 제안 (2026-10-31, 근거: 조사 `docs/research/third-party-wrapping-criteria-survey-2026-10-14.md` · TRD §1-4 `store.rs` · §7 14)
- 관련: ADR-0311 · TRD §1-12 · ADR-0336

## 맥락
walkdir · serde-saphyr · 트리 · 표 · 끌기 · 쿼리 같은 서드파티를 어떻게 감싸나.

## 결정
1. 감싸는 단위는 목적이다 — walkdir · std::fs → 「라이브러리 저장소」 포트 하나(`LibraryStore`) · serde-saphyr → 형식 / 트리 · 목록 · 끌기 · 쿼리 → 우리 부품 한 곳씩.
2. 감싸지 않을 것 = 언어 표준 · 어디에나 쓰이는 기반(serde · tokio · React) · 한 곳에서만 쓰는 순수 도우미(조사 결론 3).

## 거부한 대안
- **라이브러리마다 1:1 래퍼** — 감싸는 단위는 라이브러리가 아니라 목적이다(Cockburn 헥사고날 — 조사 결론 2 · 확실) · 얇은 1:1 투과 래퍼는 아래 세부가 그대로 새서 이득이 없다(조사 결론 3 · 가능성 높음 — 통설).

## 근거
조사 결론 1~4(Fowler Gateway · Cockburn 헥사고날 · Spolsky · Rust API Guidelines C-STABLE).

## 영향 / 불변식
- crate 경계를 넘는 공개 API 에 남의 crate 타입을 내보내지 않는다(C-STABLE — 조사 결론 4).
- 무엇을 감싸는지(부품 고름)는 ADR-0336이고 이 결정은 감싸는 단위만 정한다.
- (클라이언트 몫 메모 — 2026-10-31 프론트 조사 · 잠정) 트리 react-arborist 는 자기 끌기(react-dnd)에 묶여 있고 「트리 · 목록 · 폴더 줄이 react-dnd 관리자 하나를 나눈다」 는 주장은 조사가 거뒀다 — 옮길 id 를 자기 트리 상태에서 가져오므로 목록 → 트리 · 트리 → 트리 이동엔 우리 쪽 놓기 어댑터가 필요하다(`docs/research/frontend-tree-dnd-virtualization-2026-10-31.md`). 「끌기 → 우리 부품 한 곳」 이 그 어댑터 자리다. 메모 113 의 `@dnd-kit/core` 는 arborist 를 못 몬다 — 클라이언트 단계에서 다시 정한다.
