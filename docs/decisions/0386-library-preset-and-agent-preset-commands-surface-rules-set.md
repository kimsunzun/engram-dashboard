# ADR-0386: Library, preset and agent-preset commands: surface rules set by step 10a

- 상태: 확정 (2026-11-19, 근거: S25 step-10a TRD draft 3 (deep review PASS at round 2) + user decisions 2026-11-19 (O1 to O4, root generation on `agent.new`, typed `previewFolder` rows))
- 관련: ADR-0155 (declaration next to the producer) · ADR-0307 (LLM command rules) · ADR-0311 (the daemon only wires) · ADR-0379 (refusal class to bus code) · ADR-0380 (profile-edit port cell) · ADR-0381 (`library-config-write-failed` is non-retaining) · ADR-0384 (9a answers mapped as they are) · ADR-0341 (folder entries, `preset.previewFolder`) · ADR-0358 (whole-file rewrite) · ADR-0367 (backend words are strings) · ADR-0377 (root generation) · ADR-0378 (`rev` and `base_rev`) · ADR-0360 decision 4 (5 s folder budget outside a launch) · ADR-0120 · ADR-0132 · ADR-0172 · ADR-0279 · ADR-0348 · ADR-0374 (launch skips missing items) · ADR-0385 (several roots) · step-10a TRD `docs/process/S25-preset-library/trd-library-commands.md` · Amends ADR-0383 (the priming leaves the user-held list) · Amends ADR-0321 (decision 4 create-verb exception) · Amends ADR-0379 (decision 5 internal refusals)

## 맥락
Step 10a declares every edition-1 library, preset and agent-preset command on the daemon command bus (9 `library.*`, 8 `preset.*`, 4 agent-preset verbs, `agent.setWorkspace`, `agent.duplicate`, and `agent.new` gaining `presets`), so the `engram` CLI, and through it the LLM, and later the screen call the same thing. The 9a bodies exist in asset-library (ADR-0384); `agent.setWorkspace` and `agent.duplicate` had no body in the manager yet. The TRD fixed how the bodies cross into the agent-owned vocabulary, how refusals become bus codes, how the two new manager bodies lock and write, and what the help and the priming teach. The rules below are the ones later work (10b edits, the screen step, T-112, step 21) must keep and that the code alone would not show as decisions.

## 결정
1. **One port, agent types, mapping in agent.** The declarations stay in the one agent `declare_commands!` block (`crates/engram-dashboard-agent/src/commands.rs`); the port trait `LibraryCommandHost`, the verb handlers and the refusal mapping live in a new agent module `library_commands.rs`; `make_table` takes the port as a third argument. The port takes parsed values (an `AgentId` resolved by `commands::resolve`, the `agent.spawn` resolver) and answers the declared ok types or an agent-defined port refusal (`{class, reason}` or `Store(StoreError)`). asset-library implements it in a new module `host.rs` (`impl LibraryCommandHost for LibraryService`): it parses spellings with its own helpers (`edit::lib_path`, `edit::parse_ref`, `AssetRef::parse`), calls the 9a body once, converts the answer to the declared rows and `LibraryRefusal` 1:1 into the port refusal, and never calls a second body or reads a file back. asset-library's `command` dependency stays test-only.
2. **Refusal mapping (one function in `library_commands.rs`, ADR-0379).** `Conflict` and `Unavailable` map to `CONFLICT`, `NotFound` to `NOT_FOUND`, `InvalidArgument` to `INVALID_ARGUMENT`, all non-retaining (including `library-config-write-failed`, ADR-0381); `Internal` (`profile-edit-unavailable`) to `INTERNAL`, retaining the id; `Store` through agent `store_command_error` with `store_error_reason(PROFILES_FILE, …)` and no args. `CommandError.args` = the `Reason`'s `{code, args, line?}` (the keys of one `args.reasons` row, agent `launch::put_reason`); the message is one English line naming the command and the code. A path argument that is not a library path (for `preset.get`, not an `AssetRef`) is refused by `host.rs` as `InvalidArgument` `item-path-invalid`. `library.list`'s bare `library-unavailable` gets class `Unavailable` in the host. 10a adds no refusal codes beyond the 9a bodies' except `profile-store-refused` `{why}` (a relink `stopped` carrying a store error) and the `agent.setWorkspace` codes of decision 6. Skips, a relink `stopped` and a refresh `errors[]` are answers, not refusals.
3. **Names are filled agent-side.** The port answers agents by id only. `agent.presets` and the agent-preset edits fill `name` from the `ResolvedAgent.name` the handler already has; `library.read` fills `agents_direct` and `agents_indirect` names from one `AgentCommandHost::roster` read and drops an id the roster no longer holds. No port answer is rebuilt after its change (ADR-0384).
4. **Typed rows.** Field names are snake_case; the agent argument is `target`. Rows are typed declarations: `ReasonRow` `{code, args, line?}`; `ProblemRow` (the `LaunchBlocked::to_args` row, with `kind: String` so its words equal the launch block's, e.g. `missing`); `ListRow`; `FolderRow`; `AgentFolderRow`; `PreviewSetRow` (the agent port's `FolderLoadSet` as rows; an `unsure` row is the `UnsureWhy` variant as a word plus `message?` and `line?`). `preset.previewFolder` answers typed rows, not free JSON. `LibraryKind` is a macro enum `Instruction`, `Skill`, `SkillFile`, `Settings`, `Preset`; `library.list` `kinds` matches a skill folder's `SKILL.md` row only by `SkillFile`, never by `Skill`, and the row is not left out. `Json` is used only for payloads whose keys depend on a code (`args`). Backend tags and `backend` arguments are strings checked by the registry (ADR-0367). `library.refresh` is `Read` and maps its report as is, a total failure being one `errors` row with no path. Every new declaration is `#[since(9)]`, `Ordinary`, inserted with `blocking_handler`.
5. **`agent.new {presets}`** judges the list under one library read lock with the same pure judgement `attach` uses (`agent_edit::attach` over a `CatalogLookup`, the profile outside the registry) and creates the profile with the accepted list in one registry write (`create_agent`); there is no profile-edit-port step after the create, so no `INTERNAL`-after-create path. The answer adds `skipped`. When a library preset is named and no first scan could be applied, the whole call is refused `CONFLICT` `library-unavailable` and nothing is created, the attach rule (user O3). It takes the optional `root_generation` like `agent.attachPreset`, compared inside the judgement's read lock; a stale one refuses the whole call `CONFLICT` `root-generation-stale`, nothing created (user 2026-11-19). Without `presets` there is no judgement and `root_generation` is not read. The read lock is released before `create_agent` takes the name-allocation gate.
6. **`agent.setWorkspace`** (manager body) runs in this order: (1) normalize the spelling and stat the folder through a new `LaunchKitSource` folder-stat method outside every lock (production = asset-library `BoundedIo` on the 5 s read budget, ADR-0360 decision 4; the Noop kits = std `fs`); missing, not a folder, unreadable or timed out answers `INVALID_ARGUMENT` `workspace-not-found` `{cwd, why}`, `why` naming the timeout or the unreadable folder; (2) pre-check without the reservation through the shared decision (`ProfileEditPort::workspace_lock` body in `manager/profile_edit.rs`) so a call that will be refused never holds the reservation; locked answers `CONFLICT` `workspace-locked` `{reason}` with `running`, `preparing`, `conversed` or `changing`; (3) take the agent's `SpawnReservation` as a working-folder holder (the reservation table becomes holder-aware: launch or working-folder change); (4) re-check under it, the shared decision counting only launch holders as `preparing`; (5) take the name-allocation gate and derive the current name; (6) one conditional registry method `ProfileRegistry::try_set_workspace` (`pub(crate)`, the `try_mutate_if` shape) that re-checks `backend_session_id`, answers `NOT_FOUND` for a deleted agent, writes `cwd` and pins `display_name` only when it is still `None`; a refusal writes and saves nothing of its own; (7) release and notify `RosterChanged`. No library lock is involved.
7. **A launch that loses the reservation to a working-folder change** answers through one new `PtyError` variant, listed in `refused_before_spawn`, at the three places a loss surfaces (`activate_profile_reporting`'s in-flight check, the reserve branch in `spawn_agent_watching_link`, the Fresh and Resume branches after it). On the bus it is `CONFLICT` with `RetryMode::AfterCondition` (the `LaunchRaced` precedent); the wire `Spawn` and `SpawnProfile` callers get its `AgentEvent::Error` text. It records no last failure (ADR-0172): `note_spawn_result` and `resume_no_fallback` each gain an arm that writes nothing for it, and `spawn_error_kind` names it explicitly. `restore_one` answers `RestoreOutcome::Failed` for it. A double start by two launches keeps today's answers.
8. **`agent.duplicate`** (manager body) is an LLM creation door: it consults `llm_creation_refusal` with the original's backend word (`launch::backend_word`), and a backend with no declared LLM policy (shell, gemini) is refused with `policy_refusal` (`INVALID_ARGUMENT`), the cost ADR-0279 accepts for `SpawnByCwd`. Under the name-allocation gate and one roster read it applies `check_roster_capacity` (ADR-0132) and the existing name rule (`assign_new_name` → `pick_suffix`: `bob` → `bob(1)` when no other `bob(n)` exists); `RosterFull` and an exhausted name space map through `create_error` to `CONFLICT`. A new `pub(crate)` `ProfileRegistry::try_insert_copy` reads the original and inserts the copy in one locked section (the `try_mutate_if` shape), so a copy queues with `rewrite_preset_paths` and `remove_preset_paths` and cannot slip past a relink; an original deleted meanwhile answers `NOT_FOUND` with nothing saved for this request. The copy is `AgentProfile::new(original.name, command, cwd, env, auto_restore = false)` plus `default_preset`, `presets`, the original's `parent_id` (a sibling, user O4) and the pinned name as `display_name`. Not carried (constructor values): backend session id and history, `epoch`, last failure, `failed_reason`, `restart_count`, `last_start_at`, `created_at`, `auto_restore`, the last-applied instructions hash, the notice fingerprint (ADR-0341 decision 5), `restart_policy`. It notifies `RosterChanged`; the answer is the new id, name and `sleeping`.
9. **Assemblies without a library** (the daemon test server and `saturation_pilot`) plug `NoLibrary` (daemon `control/commands.rs`, beside `NoUsageLimits`): every library command answers `CONFLICT` `library-unavailable`, except `library.refresh` (the report of a failed refresh) and the `agent.new` judgement (the attach rule with no catalog; a given `root_generation` is not compared). Production `run()` passes `wiring.library`; `roundtrip_smoke` plugs the profile-edit port before `make_daemon_table` and passes its real service.
10. **Help and priming.** Daemon `control/help.rs` gains the required topic `HelpTopic::Library`; `engram help` gains one `library` line; `help library` carries the commands by full name, the settings and preset file formats with a `description:` example and the one-line 「write a description」 rule, the folder entry form (ADR-0341), `root_generation` and `base_rev`, the whole-file-rewrite sentence (ADR-0358), how to read `args` on a refusal, the `workspace-not-found` timeout case, and 「check `agent.list` before calling `agent.new` or `agent.duplicate` again after a timeout or an unknown outcome」. `help library` says 「the library root」 without claiming there is only one. `help agent` gains `agent.new --presets`, `agent.setWorkspace`, `agent.duplicate` and a pointer to `help library`. The priming (`builtin/instructions/priming.md`) is translated to English in its existing structure and lines (user O2) and gains, in English, the `engram help library` line, the whole-file-rewrite sentence and the description rule (user O1). It therefore leaves ADR-0383's user-held list (user 2026-11-19; the held list names it by its old path `prompts/agent-priming.md`, renamed at step 17).
11. **Nothing promises that a missing item blocks a launch.** The help and the priming say a missing item shows as a problem row; ADR-0374 (T-112) makes a launch skip missing items with a notice, and texts written now must stay true after it.
12. **ADR-0321 decision 4's exception is out of date.** The create-verb gap it names (a create verb that registered before its activation loses to `setWorkspace`, answering `INTERNAL` with the id) is unreachable since ADR-0348: the one creation body reserves before `ensure_registered` adds the profile, so `setWorkspace` either cannot resolve the agent or meets the reservation. No branch or test is built for it.
13. **A `library.list` query matches items strictly below `folder`** — the folder asked for is never a result of its own search (user 2026-11-19, U1 review). A folder behind a link answers its one `path-through-link` row, which the filters do not apply to, and still answers the built-in row (`builtins`).
14. **Clearable library refusals carry `retry: after-condition`** (user 2026-11-19: 「llm이 알아서 수정해서 시도가 맞지」): `library-unavailable` · `library-write-failed` · `library-read-failed` · `library-root-unusable` · `library-config-write-failed` (agent `library_commands.rs` `RETRY_AFTER_CONDITION`). Refusals a retry of the same call cannot clear keep the class default — the argument codes, `name-exists`, `root-generation-stale`, `rev-mismatch`, `library-config-read-only`, `relink-kind-mismatch`, `profile-edit-unavailable`. The directive also reaches the LLM through the CLI as wording in the refusal message (the CLI error body carries no `retry`).
15. **The built-in in a world of roots is step 21's.** `library.read engram:/default` and `library.list` with no root keep refusing in 10a; step 21 makes the built-in an always-present read-only root (user 2026-11-19; parent TRD item 21).
16. **Folder spellings lose one quote layer before the port** (base `path::unquote`, backslashes kept) — `preset.previewFolder` `folder`, `preset.add` / `remove` / `check` / `save` `folders`, and `preset.reorder` `order` when the section is folders; library item spellings are passed as typed (U2 review). **`preset.previewFolder` answers `Internal` `folder-listing-unanswered {path}`** where the 9a body asserted that the bounded listing answers every asked path — no command may reach an abort (ADR-0292 · ADR-0293).

## 거부한 대안
- **`host.rs` returns `CommandError` directly** (TRD B1's alternative, using the `command` dependency the asset-library comment reserved for 10a) — puts bus codes in asset-library, the alternative ADR-0379 already rejected, and breaks the `LaunchKitSource` precedent where asset-library answers agent types and agent picks the code. Basis: code (`LaunchKitSource`), ADR-0379.
- **`agent.new` creates the agent bare, then attaches through the profile-edit port** (TRD B10's alternative, parent TRD §1-7) — a race at the port step leaves an `INTERNAL` answer with a created id; the port doc (`profile_edit.rs` `set_attachments`) already places `agent.new` outside the port, and judging first needs one registry write. Basis: code.
- **`agent.new --presets` with the library unavailable: create the agent and skip each library preset with `library-unavailable`** (TRD draft 1 §12 O3 (b)) — `agent.attachPreset` refuses the whole call in the same state, so the create door and the attach door answer alike, and nothing half-made is left to clean up. Basis: code (`agent_edit::attach`); offered to the user, who answered 「진행해」 to main's recommendation.
- **The duplicate at the top level of the agent tree** (TRD draft 1 §12 O4 (b)) — a duplicate lands beside the original in Windows Explorer and VS Code 「Duplicate」 and in this project's own `library.copy` paste rule (parent TRD §1-7). Basis: convention checked against those; offered to the user, who answered 「진행해」 to main's recommendation.
- **`preset.previewFolder` answering free JSON** (TRD draft 2 left it provisional) — the screen would get no schema or bindings for it. Basis: user decision 2026-11-19 (TRD B4).
- **`ProblemRow.kind` as a macro enum** — its words would be `Missing` rather than the launch block's `missing`, so one reader could not parse both. Basis: code (`LaunchBlocked::to_args`).
- **`library.refresh` declared `Write`** — a same-id retry would answer `ALREADY_APPLIED` with no report, while the command only changes the in-memory catalog and a rerun is harmless. Basis: code (`command_delivery::retains_the_id`).
- **`agent.setWorkspace` takes the reservation before checking the lock** — a call that will be refused would hold the reservation and could turn a concurrent start into a refused start. Basis: TRD review (risk lens).
- **`agent.setWorkspace` writes through `try_update_with`** — it goes through `try_mutate` → `commit_if_saved`, which always saves, so a `conversed` refusal would rewrite the file and a store error could replace the refusal. Basis: code (`profile.rs`).
- **`agent.duplicate` reads with `get` and inserts with `try_upsert`** — two locked sections, so a copy could slip past a relink's rewrite of the profiles. Basis: code (`profile.rs`).
- **Declare only `library.list {folder?}` now and add `query`, `kinds`, `builtins` with the screen step** (TRD B11's alternative) — the parent TRD already decided the shape; declaring it now avoids changing the declaration later. Basis: parent TRD (B1, Δa, G2).

## 영향 / 불변식
- Later library commands (10b `move`, `rename`, `copy`, `delete`, `trash`, `restore`, `emptyTrash`) join the same port and the same mapping function; asset-library never answers bus codes, and the port stays id-only.
- A new refusal code needs this ADR or ADR-0379 amended; a new answer must still be mapped as the 9a body built it (ADR-0384).
- Every launch entrance must take the holder-aware reservation and answer the new `PtyError` variant when the holder is a working-folder change; a new record site must skip it, or a moot launch records a last failure (ADR-0172).
- Every LLM creation door consults `llm_creation_refusal`; a new one that skips it opens a backend the policy closes.
- `agent.setWorkspace` and `agent.duplicate` write through their one conditional registry method each; replacing either with `try_update_with` or two locked sections breaks the refusal-writes-nothing rule or the queue with relink.
- The priming is bounded by the codex terminal command line (`CMD_LINE_LIMIT_UTF16` in agent `backend/codex/mod.rs`; asset-library `builtin.rs` `the_shipped_priming_fits_the_codex_terminal_command_line`); growing it past the bound blocks every codex terminal launch.
- `agent.new --presets` and `agent.duplicate` are not safe to retry with a new id after `OUTCOME_UNKNOWN` (a retry creates `name(1)` and the LLM has no delete verb); the help must keep telling it to check `agent.list` first.
- Several roots (ADR-0385, step 21) are not blocked: every path is a plain string checked by `LibPath` and `AssetRef` (a prefix is a parser extension), an omitted `folder` or `parent` means the current root, and `library.status`'s `root?` and `root_generation` read as 「the current root」; per-root values would be added fields.
