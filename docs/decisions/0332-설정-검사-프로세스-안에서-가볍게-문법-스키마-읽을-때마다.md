## 맥락
When and how much do we check a settings asset (claude raw-text JSON · codex `-c` lines)?

## 결정
1. Lightweight inside the process — syntax (YAML) + schema, every time Engram reads it.
2. A type or range error on a key the schema knows = blocks the run.
3. Unknown key = claude does not report · codex only ⚠ (does not block). If the schema we hold is older than the installed CLI, unknown keys are dimmed 「이 판 스키마로는 확인 못 함」 (P10-ADD).
4. Schema = one copy in the distribution + the daemon updates it in the background (cache = ADR-0323). If it fails, we use what we hold · there is no block because the schema is missing (P10).
5. What differs per backend (schema source · reading the version · raw text → JSON · unknown-key handling) is provided by the backend settings-check port (ADR-0334).

## 거부한 대안
- **A CLI check right before the run** (`claude --settings … doctor` · `codex debug models`) — user 「가볍게하는걸로하고 나중에 문제되면 차후에 고려하자」.
- **The 「모두 검사」 menu · `library.validate`** — refresh covers it (§7 23).
- **Re-reading when the editor gets focus** — user 「너무 복잡하게 할 필요는 없는것같아」.

## 근거
User decisions 2026-10-18 · P10 · measurement spike (2026-10-17).

## 영향 / 불변식
- The check does not make a run wait — fetching the schema is done in the background outside the lock (P10).
- Source mismatch to confirm: see the consequences of ADR-0331 (codex ⚠ and 「경고 범주 없음」).
- **When a new schema arrives, the re-check is also a `Catalog` change** — it takes a ticket and a change generation and also fixes the check results in the parse cache (ADR-0324 Decision 8 · M45 · M49). What remains (accepted): a read that answers between the first scan's swap-in and the re-check may show old-schema results — the next query is correct (M45 · TRD §1-11a scenario 8).
- Parts (2026-10-31 research): checker = `jsonschema` 0.60.2 (raised from 0.59.0 in the TRD) · fetching = `ureq` — ADR-0336. Both target schemas are draft-07, so the format validation policy is stated in code (research yaml-schema-https).
