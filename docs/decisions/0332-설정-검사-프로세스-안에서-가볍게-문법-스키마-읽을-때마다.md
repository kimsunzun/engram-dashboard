# ADR-0332: 설정 검사 = 프로세스 안에서 가볍게 — 문법 + 스키마, 읽을 때마다

- 상태: 제안 (2026-10-31, 근거: 사용자 결정 2026-10-18 · P10 · P10-ADD + 메인 M2 · M18 · M45 · M49 · TRD §7 23)
- 관련: ADR-0334 · ADR-0331 · ADR-0323 · ADR-0324 · ADR-0336 · TRD §1-4 `validate.rs` · 실측 `docs/research/settings-asset-validation-spike-2026-10-17.md` · 조사 `docs/research/yaml-schema-https-crates-2026-10-31.md`

## 맥락
설정 에셋(claude 원문 JSON · codex `-c` 줄)을 언제 · 얼마나 검사하나.

## 결정
1. 프로세스 안에서 가볍게 — 문법(YAML) + 스키마, Engram 이 읽을 때마다.
2. 스키마가 아는 키의 타입 · 범위 오류 = 실행을 막는다.
3. 모르는 키 = claude 는 알리지 않는다 · codex 는 ⚠ 만(막지 않음). 가진 스키마가 설치된 CLI 보다 낡았으면 모르는 키는 흐림 「이 판 스키마로는 확인 못 함」(P10-ADD).
4. 스키마 = 배포판 한 벌 + 데몬이 뒤에서 갱신(캐시 = ADR-0323). 실패하면 가진 것을 쓴다 · 스키마가 없어서 막는 일은 없다(P10).
5. 백엔드마다 다른 것(스키마 출처 · 판 읽기 · 원문 → JSON · 모르는 키 처리)은 backend 설정 검사 포트가 낸다(ADR-0334).

## 거부한 대안
- **실행 직전 CLI 검사**(`claude --settings … doctor` · `codex debug models`) — 사용자 「가볍게하는걸로하고 나중에 문제되면 차후에 고려하자」.
- **「모두 검사」 메뉴 · `library.validate`** — 새로 고침이 덮는다(§7 23).
- **편집기 포커스 때 다시 읽기** — 사용자 「너무 복잡하게 할 필요는 없는것같아」.

## 영향 / 불변식
- 검사는 실행을 기다리게 하지 않는다 — 스키마 받기는 락 밖 뒤에서 한다(P10).
- 원천 어긋남 확인: ADR-0331 영향 참조(codex ⚠ 와 「경고 범주 없음」).
- **새 스키마가 오면 다시 검사도 `Catalog` 변경이다** — 번호표 · 변경 세대를 지고 파싱 캐시의 검사 결과까지 고친다(ADR-0324 결정 8 · M45 · M49). 남는 것(받아들임): 첫 훑기의 바꿔 끼우기와 다시 검사 사이에 답한 읽기는 옛 스키마 결과를 보일 수 있다 — 다음 질의가 맞다(M45 · TRD §1-11a 시나리오 8).
- 부품(2026-10-31 조사): 검사기 = `jsonschema` 0.60.2(TRD 의 0.59.0 에서 올림) · 받기 = `ureq` — ADR-0336. 두 대상 스키마가 draft-07 이라 포맷 검증 정책을 코드에 밝힌다(조사 yaml-schema-https).
