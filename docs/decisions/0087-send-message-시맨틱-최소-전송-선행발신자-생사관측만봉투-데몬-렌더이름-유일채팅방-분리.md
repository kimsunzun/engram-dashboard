# ADR-0087: send_message semantics — minimal transmission first, sender liveness = observation only, the daemon renders the envelope, unique names, chat rooms separated

- 상태: 확정 (2026-07-19, basis: survey of 8 OSS projects + Orca real-source verification + the user's step-by-step approval + a 3-round adversarial review by 2 reviewers with both sides PASS + QA standard 9 gates)
- 관련: Amends ADR-0086 (the order of splitting step ladder ②③④ → the 2-min minimal transmission batch first + the SQLite mailbox deferred (resumed after the user learns)) · ADR-0086 (dual entrances, token authentication — the main body is valid) · ADR-0007 (epoch — the name is tied to AgentId) · ADR-0006 (lock discipline — the basis for rejecting the liveness gate) · ADR-0004 (backend knowledge isolation — where env is injected) · implementation commit `e05bd83` · Amended by ADR-0088 (reorganized the ladder order (format spike → delivery correctness verification first) + the envelope decision axis (forgery resistance → moved to escaping, format limited to readability and compliance))

## 맥락
Before starting step 2 (send_message), we expanded the design discussion. The issues: ① the layer by which agents "understand each other" (addresses, envelope, reply convention) was undesigned in ADR-0086 ② the user wants to decide on the SQLite mailbox after learning ③ splitting the steps finely delays measurement (utterance tests). On the basis of two OSS investigations (a web survey: mcp_agent_mail, Claude Code Agent Teams, Claude Swarm, AutoGen, CrewAI, A2A, OpenAI Agents SDK, LangGraph / Orca (stablyai, 21.4k★) verified in real source through commit-pinned permalinks), the user confirmed the following step by step.

## 결정

1. **Ladder reorganization (a partial amendment of 0086):** replace steps ②③④ (send tool / mailbox / delivery split) with a **"2-min minimal transmission" batch first** — intake (tool+Validator+ACK), immediate delivery (write_stdin), and even the CLI entrance in minimal form all at once (the ledger, idle gate, envelope finalization, name suffix, and groups are scoped out, with only the place reserved). The SQLite mailbox is **resumed after the user learns**. Implementation complete = `e05bd83`. Next = **the envelope format measurement spike** (XML tags vs an Orca-style banner, model ladder haiku→sonnet→(opus if sonnet performs poorly), acceptance baseline = sonnet — haiku is for detecting the lower bound).
2. **Sender liveness ≠ a delivery gate (observation only):** a message's validity is established by **authentication at authoring time** (token verification at the entrance), and even if the sender later dies or the epoch rotates, delivery is not blocked. The `is_identity_live` query is kept but only as a **record-keeping warn log** (room to reconsider when the product is refined — user instruction "기록용으로 남겨" ("leave it for the record")). Basis: "send the result and shut down" is a core pattern (isomorphic to Orca worker_done — the last-words message is the most important), and it is consistent with the future mailbox semantics (a ledger record = a commit, and the sender's later death is not an unsend).
3. **Envelope asymmetry — production is machine-enforced, consumption is model-friendly:** the agent only does typed sending (`{to, body}` tool call/CLI argument) and **the envelope is assembled by the daemon renderer** (zero typos + forgery can be blocked by escaping fake envelope tags inside the body). The envelope direction = **XML tags** (claude is trained on the native delimiter convention like the harness `<system-reminder>` + robust boundaries when several messages are batched) — **the final decision is by the spike measurement**. The reply line uses a **conditional tone** ("If a reply is needed: …" — always embed the mechanical method but do not imply an obligation to reply) to prevent a confirm-reply storm.
4. **Name rules:** address = the human-readable agent name (zero OSS projects in the survey adopted UUID addresses). **Uniqueness is enforced** among live agents (on a collision an automatic `-2`, `-3` suffix), **no reuse of suffix numbers while the daemon is running** (blocking misdelivery caused by remembering a dead name — for a dead name, a "no recipient" error is the right answer), and the name is **tied to AgentId and kept across epoch replacement**. (Unimplemented — the current minimal version has exact matching + an AMBIGUOUS error, and the suffix machinery is a follow-up.)
5. **Delivery policy = a daemon switch:** an idle gate (turn state based on StreamJson `MessageDone`) + **default = batch injection** (the backlog of envelopes in one go, isomorphic to Orca) / a **serial mode option** (switchable per agent) — left as a policy knob rather than architecture, to be decided by A/B on real traffic. (Unimplemented — the current minimal version pushes immediately.)
6. **Corrective error ACK:** a validation failure carries corrective information rather than a declaration (e.g. a hint with the list of live names on RECIPIENT_NOT_FOUND) — inducing self-correction within the same turn, partially resolved without a separate roster tool.
7. **Chat rooms = a system separate from mail (entirely later):** a shared append-only text is the room, with **a per-member read cursor** (the unread count derived like KakaoTalk), **trigger-based catch-up** instead of waking on every message (mention immediately / accumulate-silence / idle), and the user watching and taking part from a slot (remote participants later). Usage distinction: **mail = a one-off errand, room = a conversation expected to go back and forth** (including the human notion of "if mail is frustrating, switch to a messenger" — this decision criterion is also put into the agent convention). When starting, a separate PRD/investigation round (the discipline against runaway utterances is the key hard problem — no successful OSS exists).
8. **Broadcast/groups = later, place only:** an `@…` in `to` (a group family, all — the daemon interprets it and fans out per recipient, isomorphic to Orca group addresses) is reserved with a GROUPS_NOT_SUPPORTED error.
9. **(Not a decision — recorded as under consideration)** On multi-daemon expansion, MCP = the remote/inter-daemon candidate and CLI = the local-internal candidate — a policy assignment on top of the `ControlIngress` seam, so it can be decided later without an architecture change.

## 거부한 대안
- **The agent writes the envelope itself** — the production-side failure shown by the marker spike compliance of 66% (ADR-0086) (quotes, nonce misreported). Structure is read well but breaks in making → production is enforced by a typed schema.
- **Pull-style receiving (mcp_agent_mail-style fetch_inbox)** — the agent forgets to check or runs a polling loop (Orca even puts a no-polling statement in its preamble). Push (input injection) needs zero receiving cooperation.
- **UUID addresses** — a surface for LLM misrecording + zero OSS adoptions in the survey.
- **A sender-liveness rejection gate (SENDER_REVOKED)** — loses the last-words message. Complete blocking is impossible because it would be I/O while holding a lock (violates ADR-0006), and the reviewer conflict (Codex "residual race" vs deep "accept") was resolved by the user's reframing "liveness is not a gate".
- **A reply line in an imperative tone** — provokes a reply to every envelope, a confirm-reply storm (wasted turns).
- **Reusing name suffix numbers** — a dead name remaining in another agent's context is misdelivered to a new agent.
- **Fixing batch/serial now** — measurement on artificial scenarios is not representative, and the switch cost is 0, so defer to an A/B on real traffic.

## 근거
- **Two OSS convergences:** an envelope with "a built-in complete reply command" (Orca `[Reply: orca orchestration reply --id … --from …]` real source + mcp_agent_mail ack_required/frontmatter) converged independently — the highest-confidence pattern of the investigation. Address = name and exposing a one-line role description is also common to all OSS.
- **Orca real-source verification (commit-pinned):** the formatter (batch banner), the preamble (placing the rules right above the CLI example — "LLMs anchor on examples"), the messages schema (sequence/delivered_at/thread_id actually exist, `read` is a **boolean** — the read_at in the earlier investigation report is corrected as an error), group fan-out = a row per recipient.
- **Research process lesson (recorded separately):** the reason the web collector could not find Orca = the anchor (repo URL) was not passed + blind misapplied (a lookup-type task) — adopted the rule "for a verification-type investigation attach the anchors we hold, blind only for judgment collection". The honest UNVERIFIED report worked as designed.
- **Gates:** 3 rounds of adversarial review by 2 reviewers (deep=reviewer-deep + blind=Codex) → both sides PASS · QA standard 9 gates PASS (core 224 · daemon 164 · protocol 50 · discovery 44 · vitest 621 · isolation 0).

## 영향 / 불변식
- **Message validity = authentication at authoring time** — do not put back code that rejects by the sender's liveness at delivery time (the user-decision comment in `ingress.rs` is the anchor). Keep the observation log (warn).
- **Envelope rendering is a single point in the daemon** (the one function `wrap_message`) — a format change = a renderer fix + re-measuring utterances, not an agent migration. The agent contract is only `{to, body}`.
- **least-privilege, from = token-derived, token lifetime (AgentId, epoch)** — inherited as is from the ADR-0086 invariants.
- **`to` parsing is an extension point** — the `@` prefix is reserved (groups), name/ID dual acceptance (exact ID matching first — blocking hijacking where a name is someone else's UUID).
- For the unimplemented decisions (name suffix, idle gate, batch switch), this ADR is the canonical spec — do not reopen them at implementation.
