# ADR-0114: Send overhaul supplement — discard reclaim, notice cap 64, the whole-reject tier for @address errors, the same-name transitional rule

- 상태: 확정 (2026-07-29, basis: user decision — 4 forks found by the spec amendment /review doc full with 2 reviewers, each confirmed individually by Q&A) · 부분 폐기 by ADR-0309 (the basis for rejecting an id key, and decision 4) · **Basis weakened — the "logical empty set" premise of decision 1 (discard reclaim) was invalidated by ADR-0116 (revival of sleeping parking). The decision itself is kept, and the basis for boundedness moved to "TTL 24h + mailbox cap" (spec §5) — not discarded; read this line first when revisiting reintroducing reclaim.**
- 관련: Amends ADR-0107 (decision 2 pressure reclaim and decision 1 NOTICE_CAP 20) · Amends ADR-0108 (decision 2 the REQUEST_CAPACITY reject tier) · ADR-0111·0112(send overhaul proper — this ADR is a supplementary decision from that review round) · ADR-0115(the root fix for same names — spawn name uniqueness, a pair) · `docs/process/S18-messaging-v1/spec/messaging-v1-spec.md` §3·§4·§5·§6 · Amended by ADR-0309 (the basis for rejecting an id key, and decision 4)

## 맥락

When a `/review doc full` adversarial review with 2 reviewers (a doc-aware guardian + a cross-family blind reviewer) verified the amendment that reflected ADR-0111/0112 in the spec, it found 4 policy forks — all gaps that ADR-0111 did not settle, so each was closed individually by user decision.

## 결정

1. **Discard pressure reclaim.** Mailbox (message lane) full = that recipient's row fails immediately (`MAILBOX_FULL`), with no reclaim attempt. Basis: with binding discarded (ADR-0111 decision 6) + absent-reject (decision 1), the category of "leftovers confirmed undeliverable" disappeared, so the reclaim criterion became a logical empty set (found in review — by the worker's redefinition criterion, no reclaim target can exist). Cleaning up TTL-expired items has the 60-second periodic sweep as its only path.
2. **Multi-request timeout notice = keep one per contract + raise NOTICE_CAP 20 → 64.** No merge system is built (add it if the need is shown — the user). The rule of retiring the oldest notice on lane overflow is kept. The loss rule is the same as N single requests — it is not a path the overhaul newly created (review framing corrected: if the sender is idle, the notice is injected at once, so a backlog itself is rare).
3. **@address error = keep whole reject + make the tier separation explicit.** A missing name = runtime state → a recipient row failure (partial progress) / an @address error (a nonexistent address) = an address space error → whole reject (the sender fixes it and resends). A `GROUP_EMPTY` whole reject **only when the final recipient set is the empty set** — if in `["@all", 자기이름]` the only survivor is the sender, @all contributes 0 + one row delivered for the explicit pick (resolves the contradiction between the two clauses).
4. **Same-name transitional rule.** In the @all expansion, a same name (a duplicate live name) is made explicit as a `RECIPIENT_AMBIGUOUS` row failure (a stated exception to "to everyone"). The root fix = ADR-0115 (spawn name uniqueness) is going to eliminate this whole ambiguity class — until then this is the contract.

## 거부한 대안

- **Widen the reclaim criterion (reclaim TTL-expired items + roster-absent items)** — the cost of keeping a device whose threat has vanished, and TTL cleanup duplicates the 60-second sweep. The user: "회수 돌리지 마" (do not run reclaim).
- **Merge timeout notices per message** — needs a new merge system, and the frequency is low. The user: add it if needed.
- **Explicitly accept notice loss (keep cap 20)** — raising the constant is cheaper and shrinks the loss window itself.
- **Demote an @address error to a row failure** — "없는 게 있으면 안 되지, 고쳐서 다시 보내라" (there must not be something missing, fix it and send again) (the user). Absorbing an address error into partial success lets a typo pass through half succeeded.
- **Expand @all per entity (id) (bypassing same names)** — parking, ledger, and contracts are all name-keyed, so a parallel entity-key track needs a chain of redesigns — too costly (ADR-0115 is the cheaper root fix).

## 영향 / 불변식

- Remove the pressure reclaim branch of the mailbox (the ADR-0107 anchor points are the surgery target) · `NOTICE_CAP=64`.
- `REQUEST_CAPACITY` = a per-recipient row failure + no delivery to that recipient (a request whose contract could not be opened is not delivered — no delivering a request without tracking). The retirement policy of ADR-0108 (mark-and-sweep · the retirable condition) is unchanged.
- The `GROUP_EMPTY` decision point = based on the final set after resolution is done (not per element).
- The same-name row failure is transitional — expected to become a dead letter after ADR-0115 is implemented (whether to remove the code is decided then).
