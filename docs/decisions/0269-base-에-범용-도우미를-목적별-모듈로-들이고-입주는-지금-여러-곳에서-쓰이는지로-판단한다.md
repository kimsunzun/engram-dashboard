## 맥락

base has two residents — `logging` · `platform`. ADR-0175 fixed the residency conditions as three (in the impact): ① two or more consumers ② zero domain knowledge ③ no references to each other within this crate. The same place also fixed ★if a third resident appears, the first item of 「거부한 대안」 (logging · platform as separate independent crates) is reopened — that is the point of entering the `bevy_core` path★. The source of that warning is ADR-0151 — alternative E of 「거부한 대안」 (gathering domain-neutral code into a bottom crate whose name points only at its layer position — the precedent where Bevy's `bevy_core` sucked in time · names · task pools until it was dismantled and scattered by purpose) and the impact (「덩어리별로 따로 판정한다 — 셋을 뭉쳐 하나에 넣을 근거는 없고, 목적 이름을 가진 작은 crate 여러 개가 나올 수 있다」). ADR-0175 also rejected the name candidates `-common` · `-util` as 「잡동사니 이름」.

## 결정

1. **base is the place that takes generic code. Keep the name base, and inside it divide by modules with purpose names** (user 2026-10-02). Splitting into small purpose-specific crates is deferred — base sits at the bottom of the dependency graph and has few entanglements, so splitting later takes little effort (the user).
2. **Bring generic helper modules into base** (user 2026-09-26). The delivery method is **stateless public functions** (main session's proposal) — a call looks like `engram_dashboard_base::file::set_aside_corrupt(…)`. Function names are tentative.

   | Module | Functions (tentative) | What it absorbs |
   |---|---|---|
   | `file` | `set_aside_corrupt(path, stamp_ms) -> 새 경로` | the corrupt-copy list in 「영향」 below (★the atomic write `write_atomic` is out — it contains a Windows-only rename retry and goes to platform · ADR-0266 decision 8 · main session's judgment 2026-10-03★) |
   | `text` | `truncate_bytes(s, max)` (keep the front) · `keep_tail_bytes(s, max)` (keep the back) · `hex_lower(bytes)` (the two XML escape functions are on hold — right column) | the UTF-8 truncation · hex · XML in the table above (★XML escaping is not moved now — the consumer is messaging alone and messaging depends on base only when it needs it · ADR-0267★) |
   | `time` | `now_epoch_ms()` + a 「지금 읽기」 trait (decision 3) | agent's three copies · the `now` part of `Clock` (`UsageClock` is on hold — decision 3) |
   | `path` | `normalize_spelling(raw)` | agent `normalize_cwd` (→ the shell) |
   | `sync` | lock-poison recovery (decision 4) | 57 places (★the 3 places in command's harness `testing.rs` stay in place — ADR-0267★) |
   | `testing` (behind a feature flag) | `wait_until` · a fake `Clock` (decision 5) | the 9 test files |

3. **The user rule 「시간은 공용이면 무조건 합친다」 (2026-09-26) is applied as follows** (main session's judgment 2026-10-03 — basis = `docs/research/clock-seam-placement-2026-10-03.md`, cross-review BLOCK addressed · 4 is user decision 2026-10-03). This is the only exception to 「트레이트를 두지 않는다」.
   1. Put **one 「지금 읽기」 trait** (`now() -> Instant`) in base `time`. The test fake goes in base `testing` (behind a feature flag — decision 5).
   2. transport (async sleep) and discovery (blocking sleep), which need to wait, each define **their own trait that has the base trait as a supertrait**. One fake clock implements both with the same state — this is to keep the linkage where today's fakes push now forward by sleeping (the manual clock in transport `src/testing.rs` · discovery's test clock).
   3. The daemon `command_delivery`'s `Clock` (now alone) is replaced with base's.
   4. The daemon's `UsageClock` is **on hold** (user 2026-10-03) — if it fits cleanly during 1-1, merge it, and if not, ask the user then. What catches is the contract difference — 「그 시계가 만들어진 뒤 경과」 (it holds the origin) and signed epoch seconds, and the fake moves the two axes separately (`usage_service/clock.rs`).
   5. transport returns `std::time::Instant` and sleeps with tokio. `tokio::time::pause` does not stop std `Instant`, so **the clock domain is not changed** (tests use the manual clock).

   The detailed shape is decided at the start of 1-1. ★「지금 읽기만 합치는 것이 피어 표준이라서」 is not a basis★ — peers differ (zed · Materialize separate them, while `cruxi_clock` · `async_speed_limit` · quinn bundle reading and waiting into one trait). This shape is a design choice.
4. **Gather lock-poison recovery into the base `sync` module** (user 2026-09-26). Gathering it in one place makes possible a kind of control where poison, which is silently swallowed now, **leaves a warning log when it is recovered**. That warning calls `tracing::warn!` directly — base already depends on `tracing`, and logs are not wrapped (ADR-0268). So `sync` does not call base's `logging` module, and no cross-references between residents (residency condition ③) still holds.
5. **Put the test-wait helper in a module behind base's `testing` feature flag** (main session's judgment) — the fake `Clock` goes in the same place. It is not shipped in production builds and is turned on only in dev-dependencies. Things that know a domain, such as `wait_for_output` · `wait_for_text`, stay in place.
6. **Things to keep:**
   - **Do not bring heavy dependencies into base** — JSON serialization stays at the call site (base does not pull in serde) and `file` takes only bytes. hex is a direct loop (the `hex` crate is not used).
   - **No cross-references between residents (residency condition ③)** — the timestamp in a corrupt file's name is **received as an argument**, without `file` calling `time`.
   - **Errors are `std::io::Result`.**
   - **`file` is moved after settling several copies' behavior into one** — setting aside a corrupt copy is settled in work order 1-1 (impact below). Settling several copies of the atomic write into one goes to 1-3 after platform exists (ADR-0266 decision 8).
7. **The residency decision rule = 「기준을 미리 잡지 않고 지금 여러 군데 쓰는 걸로 판단」** (user 2026-09-26). If it has no domain knowledge and **is used or copied in several places now**, the main session judges and moves it to base — it reports rather than asking the user. This rule replaces ADR-0175 residency condition ① (two or more consumer crates). ② (zero domain knowledge · zero workspace dependencies) · ③ (no cross-references between residents) stay as they are.
8. **Steer the next session into following this rule** (user 2026-09-26 — 「나중」) — update the architecture description in CLAUDE.md (or another place) so that when a new generic helper appears, the main session moves it to base on its own.
9. **The meaning of the name base** (user 2026-10-03) — base is the **bottom foundation layer** that every crate stands on. It holds generic helpers and foundation infrastructure (including things with external dependencies, like the logging output configuration), and holds no domain knowledge and no workspace dependencies. Precedent = Chromium `//base` (files · strings · JSON · time + logging · processes · threads · task scheduling — the `base/` listing of `chromium/chromium`, checked 2026-10-03). The user: 「우리 프로젝트 규모에 util 빼면 나중에 공용 필요할 때 어디다 넣기 애매하니」.

## 거부한 대안

- **Split into small purpose-specific crates now (the 「덩어리별 판정」 of the ADR-0151 impact · the side that ADR-0175's reopen condition pointed at).** Rejected = user decision (2026-10-02) — 「Base 쪽에 잡동사니 넣어도 돼. 그러기 위한 base 인데」 · 「목적별 작은 crate는 나중에 base 쪼개는 걸 고려해도 될 듯 — base는 상위(바닥)에 있고 연관관계도 적을 테니 쪼개는 데 공수도 없을 테고」. That is, it does not block the dismantling that the `bevy_core` precedent warns about; it judges that the cost of that is small in this place. The device that currently supports 「연관관계도 적을」 is the gate on no cross-references between residents (residency condition ③) (code — the CI `rg` gate).
- **Keep residency condition ① (two or more consumer crates).** Rejected = user decision (decision 7 — 「기준을 미리 잡지 않고」). There is no other reason in the memo.
- **Put the helpers behind a trait.** Rejected = there is no implementation to swap in (main session's proposal). **Own assessment of the rejection basis: weak** (narrative). Exception = `Clock` (decision 3 — tests swap out time).
- **Merge all four `Clock` copies wholesale into one trait** (the side this decision's old decision-3 wording pointed at). Rejected = the four copies have different shapes (the 「맥락」 table above) · moving even the async sleep implementation into base would make base pull in tokio (not if only the trait signature is there — review correction) · `UsageClock`'s contract is different (origin-holding elapsed time + signed epoch seconds — code `usage_service/clock.rs`). Main session's judgment 2026-10-03 (decision 3).
- **Rename to `util`.** It is the most common name in the peer sample (zed `util` · Firecracker `utils` · TiKV `tikv_util` · nushell `nu-utils` — rust-analyzer `stdx` and Materialize `mz-ore` among the other names). Rejected = user decision (2026-10-03 · decision 9) + util usually means a collection of stateless helpers, which is narrower than today's base that holds foundation infrastructure (logging initialization · file sink) + the cost of renaming (the crate name · imports · CI gates · CLAUDE.md · many ADRs · old records get blurry — what happened in the `core` → `agent` rename, ADR-0175). ★ADR-0175 rejected `-common` · `-util` as 「잡동사니 이름」, and that reason no longer holds★ — the user has now approved base holding generic code (decisions 1 · 9). So this rejection stands on the reasons above.
- **Set up the test helpers as a separate dev-only crate.** Rejected = the generic helper is just one function using only std, so it is not worth it (main session's judgment — quantitative: one function).
- **Things not made residents (the 「안 된다」 verdicts of the candidate survey):**
  - **Truncation by character count (`clip` · `truncate`)** — on the agent side this is an intended private function that tests block from being called except through secret masking. Moving it into base would open that door (code — worker report, not re-confirmed by the main session).
  - **Finding the data folder (`default_data_dir`)** — it is Engram-specific knowledge (ADR-0134).
  - **Token generation (32 random bytes as hex)** — sharing is explicitly forbidden (ADR-0086). Only the encoding loop (`hex_lower`) is generic.
  - **`sha256_hex`** — it pulls in `sha2` (code — dependency).
  - **Reconnect backoff** — transport already has a richer policy (`transport/src/policy.rs`). It disappears if the shell absorbs it there when it attaches transport (code).
  - **`dunce::canonicalize`** — it is a one-line library call, so there is nothing to extract (code).
  - **Reading a non-empty environment variable · discovery `retry_if_vanished`** — the former has similar shapes in daemon 9 · agent 3 · protocol 1 · shell 1 places, but most are `ENGRAM_*` domain reads, so the share to extract is small (quantitative + narrative). The latter is a discovery-only policy — **own assessment of the rejection basis: weak** (narrative). ★**The latter (`retry_if_vanished` · `probe_write_in`) is looked at again by ADR-0271 in work order 2-2**★ — if discovery is split, the daemon-side `ensure_data_dir_writable` and the shell-side `check_data_dir_writable` use those two together (ADR-0271 impact 「열린 것」). That judgment follows decision 7's rule — if the split in 2-2 actually creates two copies, move it to base, and until then this exclusion stands.
