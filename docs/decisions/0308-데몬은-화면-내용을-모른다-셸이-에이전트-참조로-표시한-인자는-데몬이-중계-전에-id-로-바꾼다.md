# ADR-0308: 데몬은 화면 내용을 모른다 — 셸이 에이전트 참조로 표시한 인자는 데몬이 중계 전에 id 로 바꾼다

- 상태: 확정 (2026-10-27, 근거: 사용자 결정 2026-10-27 · 조사 `docs/research/agent-name-resolution-relay-vs-callback-2026-10-27.md`)
- 관련: Amends ADR-0081 (데몬 opaque 유지 조항의 인자 비파싱(에이전트 참조 인자 변환 허용)) · Amends ADR-0156 (결정 1과 근거의 데몬 파싱 금지 하드 제약(에이전트 참조 칸 예외)) · ADR-0035(레이아웃 권위 = 셸) · ADR-0132(이름 해석기 하나) · ADR-0270(셸은 agent crate 를 의존하지 않는다) · ADR-0307(LLM 명령 규칙) · TRD `docs/process/S28-llm-layout-commands/trd.md` · step-log S28

## 맥락
LLM 레이아웃 명령(T-65 · S28)이 에이전트 **이름**으로 칸 · 탭을 고르게 되면서(ADR-0307) 이름 → id 해석이 필요해졌다. 이름 명부는 데몬이 쥐고(ADR-0132 — 해석기는 데몬 한 곳), 화면 배치는 셸이 쥔다(ADR-0035). 처음 구현(S28 U3a · U3b — 미커밋)은 **셸이 명령을 처리하다 데몬에 되묻는** 꼴이었다(`agent.resolve` 왕복) — 데몬이 셸 명령 인자를 열지 않는다는 ADR-0081 · ADR-0156 의 문구를 지키려고. 그 되묻기에 딸린 시한 · 대기 슬롯 정리 · 옛 데몬 처리가 코드 리뷰마다 결함을 냈고(정리 방식만 세 차례 연속 미해소), 사용자가 「데몬이 이름을 id 로 바꿔 넘기면 되지 않나」를 물었다. 조사해 보니 그 두 ADR 의 문구는 수단이었고, 목적은 「데몬은 셸(화면)을 모른다」였다 — 사용자: 「결국에는 화면에 있는 내용을 모른다는 것만 있으면 되잖아」.

## 결정
1. **지키는 원칙 = 데몬은 화면 내용(창 · 탭 · 칸 배치와 그 뜻)을 모른다.** ADR-0081 · ADR-0156 의 「데몬 opaque 유지」는 이 원칙으로 읽는다.
2. **셸은 명령을 등록할 때 「에이전트 참조」 인자를 따로 표시한다** — help 문자열 안이 아니라 **등록 패킷의 별도 칸**(예: 에이전트 참조 인자 이름 목록)으로. help 는 계속 불투명 문자열이다(ADR-0156 의 그 부분은 그대로).
3. **데몬은 셸 명령을 중계하기 전에, 표시된 인자만 자기 명부의 해석기(`resolve_in` — ADR-0132)로 이름 → id 로 바꿔 넘긴다.** 데몬이 아는 것은 「이 칸은 내 에이전트를 가리킨다」뿐이고, 그것이 칸 지목인지 탭 지목인지는 모른다. 풀리지 않으면(없음 · 이름 겹침) 데몬이 중계하지 않고 그 오류(후보 포함 — ADR-0307 규칙)로 답한다.
4. **데몬이 화면 내용을 알아야 하는 변경은 사용자에게 먼저 묻는다**(사용자 결정 2026-10-27 — 「그걸 위해 뭘 할때는 나한테 물어봐야되는거지」). 이 ADR 이 허용하는 것은 데몬 자기 영역(에이전트)의 참조를 바꾸는 것까지다.
5. 세부(표시 칸의 꼴 · 오류 문구 · 명부 읽기를 막지 않는 스레드)는 S28 TRD 에서 정한다 — 메인 결정(사용자 위임).

## 거부한 대안
- **셸이 처리 중 데몬에 되묻기(S28 U3a · U3b 구현)** — 데몬 → 셸 → 데몬 순환 왕복이 생기고, 그 왕복의 시한 · 버려진 대기 슬롯 정리 · 옛 데몬(`agent.resolve` 모름) 처리 코드가 붙는다. 코드 리뷰에서 대기 슬롯 정리 방식이 세 번 연속 닫히지 않았고(크기 문턱의 제곱 비용 · 경계 아래에서 영영 안 치움 · 시간 주기로 바꾼 뒤 시험 정밀도 BLOCK), 셸 쪽에 이름 오류 문구 · 재시도 힌트 변환이 쌓였다. 외부 관례도 경계에서 한 번 풀고 id 만 내려보내는 쪽이 다수다(조사 보고서). 기각 강도 = 리뷰 실측 + 조사 + 사용자 결정.
- **셸의 id → 이름 캐시로 셸이 직접 풀기** — 캐시는 항목을 지우지 않아 죽은 에이전트 이름이 풀리고 중복 판정이 데몬과 갈린다 — ADR-0132(해석기 하나) 위반. 기각 강도 = 코드(`layout/manager.rs` 의 `agent_names`).
- **ADR-0081 · ADR-0156 문구를 그대로 두고 데몬을 계속 불투명하게** — 원칙(화면을 모른다)을 지키는 데 그 문구 전부가 필요하지 않고, 그 대가가 위 되묻기의 복잡도다. 기각 강도 = 사용자 결정.

## 근거
- 조사(light · 원문 확인 둘): Fowler 「smart endpoints and dumb pipes」 + 「Remote calls are more expensive … remote APIs need to be coarser-grained」 · Kubernetes 는 저장 전에 API 서버가 변형해 하위가 정규화된 객체를 받는다(변형 권고 = 멱등 · 부작용 피하기 · 의존 순환 피하기). 범용 표시만 보고 치환할 때 중계자 원칙과 충돌이 가장 적다.
- 코드 손익(조사 보고서 「우리 코드에서의 손익」): 중계 지점 하나(`command_delivery::deliver`) · 우회 경로 없음 · 8~10 파일 · 셸의 되묻기 · 시한 · 대기 슬롯 정리 코드가 빠진다.

## 영향 / 불변식
- **crate 의존은 그대로** — 표시는 데몬과 셸이 이미 함께 쓰는 명령 도구 crate(`command`)에 둔다. 데몬은 셸 코드를 의존하지 않고, 셸은 agent crate 를 의존하지 않는다(ADR-0270).
- **명부 읽기는 중계 경로를 막지 않게** — 잠든 프로필의 경로 정규화가 길게 걸릴 수 있다(`manager.rs` 문서) → 막는 작업 쪽에서 돈다.
- 이름 → id 시점은 셸의 적용 잠금 밖이고 id → 칸은 안이다 — 되묻기 때와 같은 성질(TOCTOU 는 셸 적용 잠금 안의 `locate` 가 지킨다).
- S28 의 미커밋 U3a · U3b 는 이 결정대로 S28 U3 에서 고쳐 썼다(되묻기 · 시한 · 대기 슬롯 정리 코드를 걷고 표시 칸 · 중계 전 변환으로).
