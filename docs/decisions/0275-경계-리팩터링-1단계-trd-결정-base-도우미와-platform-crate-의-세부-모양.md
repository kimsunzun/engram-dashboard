## 맥락

Stage 0 fixed the base general-purpose helpers (ADR-0269) and the platform crate (ADR-0266) and deferred the details to the start of stage 1 — ADR-0269 decision 2 「함수 이름은 가안」 · decision 3 「세부 모양은 1-1 착수 때」 · decision 3-4 「`UsageClock` 은 맞으면 합치고 안 맞으면 묻는다」 · ADR-0266 「열린 것」 (whether to split the `windows` features) and the `<platform>` slot for the crate name in the gate command.

The two stage-1 TRDs (1-1 base helpers · 1-3 platform crate) measured at `0ef6292` and found places that differ from the ADR's picture (TRD 1-1 §0 ② · TRD 1-3 §2-5):

- The 「지금 읽기」 clock seams are six, not four (+ agent `LeftoverClock` · `CaptureClock`).
- Attaching base to transport breaks transport's 「워크스페이스 의존 0」 gate (ADR-0177).
- UTF-8 boundary truncation is one std line in the pinned compiler (1.95.0) (`floor_char_boundary` · `ceil_char_boundary`).
- If the fake clock is placed in base `testing`, it has to implement `crate::time::Clock`, which hits the no-reference-to-occupants rule (gate ③).
- Lock-poison recovery is 117 sites (90 in production), and 116 of them already recover silently. The production build is `panic = "abort"`, so it never reaches that branch. Adding a warning would print while holding the guard, which would require removing the 「쥔 채 로그 금지」 locks, and that list grew with every review.
- The reason given for leaving out `sha256_hex`, 「`sha2` 를 끌고 온다」, is false — it is a hand-written std implementation.
- `windows.rs` holds `LEFTOVER_EXIT_CODE`, a domain constant of the claude leftover cleanup — moving it 「통째로」 collides with ADR-0266 decision 3 (domain knowledge stays behind).
- Moving things as the wording of ADR-0266 decision 6 「한 덩이로」 says would put a conduit concept (`RetiringSignal`), test-seam traits and trait objects into the platform public API.

The TRDs raised the forks to the user as choices — eleven in 1-1 (C1–C5 · T1 · T2 · S1 · S2 · N1 · P1) and three in 1-3 (D1–D3). ★**The user delegated the choosing (2026-10-04 「알아서 진행해」). Except for decisions 11 · 12 · 15, every decision below adopts the TRD recommendation as it is under that delegation — the reasons for the decisions and the rejections are the TRD's, not the user's own judgment**★ (TRD 1-1 §4 · TRD 1-3 §7 — both state that, after the delegation, they were checked against the recommendations character by character and are identical). Decisions 11–12 · 15 have a different source (the paragraph below · those items).

★**The items for user confirmation = D3 (decision 10) and decision 12.**★ Only decision 10 is D3. Decisions 11–12 are not D3 and were never raised as options — they are the 「공통 — 안과 무관해 묻지 않던 것」 at the end of TRD 1-3 §7, so they are outside the delegation and are the main session's judgment. Of those, decision 12 changes part of the shape of the 2026-09-29 user decision: ADR-0262 「[구현] 고른 것」's 「windows crate 와 io 만 · 통째로 옮길 수 있게」 (user decision 2026-09-29) stays in substance — `windows.rs` is a leaf that uses only the `windows` crate and io — and what changes is that one constant of the 「통째로」 (`LEFTOVER_EXIT_CODE`) goes out as an argument. D3 was decided under the delegation and decision 12 by the main session's judgment, so neither went through the user's own confirmation. → The user confirmed both on 2026-10-05 (「알아서 해 문제없으면」 — together with the six 「약함」 rejections above).

## 거부한 대안

Self-assessment rule = a rejection basis that does not rest on one of quantity · measurement · code is **weak**.

- **S2 (a) Warn on every recovery (keep the poison)** — the ADR-0269 decision 4 wording as it is. Rejected = the warning is printed while holding the guard, so the twelve 「쥔 채 로그 · IO · 밖 호출 금지」 locks (37 recovery sites) would have had to be removed, that list grew with every review (edition 1 two → round 1 +3 → round 2 +5 and, by the nesting rule, +1 → round 3 +1), and there is no gate that guards it · the production build is `panic = "abort"` (`Cargo.toml:34-35`), so the signal exists only in debug · test builds · 116 of 117 sites already recover silently (TRD 1-1 §2-4).
- **S2 (b) One warning per poisoning (`clear_poison`).** Rejected = there are seven places where a neighbor uses the same lock with `.expect` · `try_lock` (TRD 1-1 §2-4 table — e.g. the `.expect` in `shutdown()` of the PTY · stdio `child` is the ADR-0001 kill-causality path). If the poison is cleared, that neighbor's behavior depends on 「그 사이 복구가 돌았나」.
- **S2 (c) Once per site (macro) · (d) Once per process, the first time (static flag).** Rejected = it leaves the 「상태 없는 공개 함수」 of decision 2, and since it is a branch that adds a warning, the exclusion list above (37 sites) is still needed · (d) is invisible at the default level from the second poisoning on.
- **A helper that 「놓고 경고하고 다시 잡는」.** Rejected = it releases that lock itself, but under an outer lock held by the caller it still prints while holding it (e.g. codex `Announcer.order` → state lock — `backend/codex/transport.rs:1112-1115`).
- **C5 (a) Attach base to transport now · (c) attach only the clock and use std for truncation.** Rejected = it comes with an amendment changing transport gate ① (exactly 1 line · ADR-0177) to 2 lines, and `tracing` · `tracing-subscriber` · `regex` (and `windows` too if before 1-3) get loaded onto a reusable lib with zero consumers · stage 3 reopens the dependencies · gates anyway (the same line as ADR-0267) · (c) bears that same cost and gains only one clock.
- **T1 (a) base `text::truncate_bytes` · `keep_tail_bytes`.** Rejected = the body is one std line of the pinned compiler 1.95.0, so there is nothing to wrap (scratch compile measurement — 4 → 3 · 6 on `"가나다"` · the same reason ADR-0269 left out `dunce::canonicalize`) · keeping the tail has one copy, so it falls short of decision 7.
- **T2 (b) Leave `hex_lower` out of 1-1.** Rejected = the same three loops remain, and it conflicts with the decision 2 table.
- **C1 (b) Put no bound on `Clock`.** Rejected = a bound would have to be written at every use site and a `dyn Clock` without the bound could appear. The fact behind the chosen side = most existing seams (daemon · leftover · transport) are already `Send + Sync`, and what changes is one discovery test fake. **Self-assessment of the rejection basis: weak** (descriptive — the code fact shows that the chosen side's cost is small, not the harm of (b)).
- **C1 (c) Two reads (`now` + wall-clock ms).** Rejected = it amends decision 3-1 (「지금 읽기 하나」), yet the consumers in 1-1 do not use the wall clock.
- **C2 (b) Keep `LeftoverClock`.** Rejected = a seam at odds with the user rule 「시간은 공용이면 무조건 합친다」 (2026-09-26) remains · what changes is only the supertrait and the name (`mono_now` 22 sites).
- **C3 (b) Attach only a supertrait to `UsageClock` · (c) make `mono` an `Instant`.** Rejected = (b) is a hollow merge where nobody calls `now()` (usage is `.mono()` 11 · `.wall()` 13) · (c) is a contract change to ADR-0250 · the usage TRD and requires rewriting the `Duration::MAX` · `ZERO` end-value tests (`usage_service/book.rs`), which goes beyond the 1-1 scope.
- **C4 (b) Put the fake in `testing` and attach an exception to gate ③.** Rejected = the gate gets an exception and the regex gets longer. **Self-assessment of the rejection basis: weak** (descriptive — what the exception would let slip through was not measured).
- **C4 (c) Do not put the fake in base.** Rejected = it amends decisions 3-1 · 5, and daemon's `Mutex<Instant>` fake (`command_delivery.rs:2425`) remains.
- **S1 (b) Extension trait `m.lock_or_recover()`.** Rejected = one `use` line per file · a different name from std `lock` · it differs in grain from the ADR-0269 「거부한 대안」 (helpers behind a trait), so it needs an explanation. **Self-assessment of the rejection basis: weak** (descriptive — only the chosen side's precedent `usage/process.rs:636` is a code fact).
- **N1 feature name (a) `testing` · (c) `test-harness`.** Rejected = (a) diverges from the existing precedent (`test-support` in command · transport) · (c) is used by agent · daemon · messaging with a different meaning, 「운영 코드 안의 seam 을 연다」.
- **P1 (b) `normalize_typed_path` · (c) `tidy_typed_path`.** Rejected = they conflict with the tentative names already written in ADR-0269 decision 2 · ADR-0270 decision 5. **Self-assessment of the rejection basis: weak** (descriptive — name picking).
- **D3 A — move `windows.rs` + `process_group.rs` to platform whole, as the wording of decision 6 says.** The effort is the smallest. Rejected = the platform public API gets the conduit concept `RetiringSignal` (reading the conduit's retiring field — unrelated to the OS) · test-seam traits · trait objects (`Box<dyn Pinned>` · `Arc<dyn Births>`), and `ProcessGroup::detached` has to be opened as a `test-support` public constructor — against ADR-0266 decision 2 (decision = OS-dependent) · decision 5 (traits for fakes belong on the using side). A also has to build `GroupOwner` anew, so the wording 「새 손잡이를 따로 짓지 않는다」 had to be amended either way (TRD 1-3 §3-4 「왜 A 가 아닌가」).
- **Read `GroupOwner` as 「`JobObjectHandle` 의 겉만 바꾼 것」 and leave decision 6 unamended.** Rejected = the name · shape · inside (the `Arc` is moved inside) of a public type change.
- **Move `windows.rs` whole, constant and all.** Rejected = a domain value (`LEFTOVER_EXIT_CODE` — `windows.rs:53` · `terminate_raw` hard-codes it at `:405-406`) goes into platform, breaking ADR-0266 decision 3.
- **D1 (b) Per-function features (`process` · `group` · `file-holders` · `spawn` …) · default empty · (c) (a) for now, (b) when a condition is met.** Rejected = (b) adds `#[cfg(feature = …)]` inside platform · a CI feature-combination gate (in the shape of net 5a · 5b) · tests that split by feature, and what it gains is only the compile time of a stand-alone `-p` build (in a workspace build the features are unified and agent turns them all on — the same observation as ADR-0175 option C) · the 「PID 만 쓰는 소비자」 that would benefit, net · discovery, disappear in 3-3 · 2-2 · (c) leaves nothing to watch. **Self-assessment of the rejection basis: weak** — the compile cost was not measured (TRD 1-3 §9), and 3-3 (decision candidate 7), where net disappears, is not an ADR but a plan deferred to the transport TRD.
- **D2 `engram-dashboard-os` · `engram-dashboard-sys`.** Rejected = `-os` overlaps in meaning with `std::os` and could be read as a 「std 확장」 · `-sys` is a name ADR-0175 rejected (in Rust `-sys` is the convention for C FFI binding crates). **Self-assessment of the rejection basis: weak** (descriptive · convention — name picking).
- **Move the `fsutil.rs` branch to platform now.** Rejected = storage P3 changes the same file heavily (new `write_atomic_unless` · `copy_atomic` · `copy_aside` · `retry_denied` — compared against `origin/v0.3.3/feat/storage`) · if moved ahead of P3, the same file has to be reconciled again when P3 lands.
