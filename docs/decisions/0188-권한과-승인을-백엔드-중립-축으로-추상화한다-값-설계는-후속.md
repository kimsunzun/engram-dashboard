# ADR-0188: Abstract permissions and approvals into a backend-neutral axis — value design comes later

- 상태: 확정 (2026-09-09, basis: user decision + measurement of the value lists of both CLIs)
- 관련: Amends ADR-0097 (the part that fixed permission values in backend code) · ADR-0004 (backend knowledge isolation) · ADR-0002/0030 (capability output · ownership split) · ADR-0187 (app-server channel settled) · `.claude/handoff/attachments/codex-measurements-2026-09-09.md` §2 (measured value lists) · CLAUDE.md 「아키텍처 원칙」·「LLM-우선 제어」 · step-log S21

## 맥락

While attaching codex as the second backend, the question 「codex 를 읽기 전용으로 띄울까요」 (should we start codex read-only?) came up, and the user pointed out that **the question itself is a sign of a structural defect** — if permissions were abstracted, it would not be something to ask separately per backend. When we checked, that point was right.

- **The frontend has 0 lines of permission concept** — searching `src/` for permission · approval · sandbox gives no result. The axis is absent from the screen and from the LLM control surface.
- **`Capabilities` has no permission area** — it is in none of the five areas (input · output · control · session · model).
- **The two backends each hard-code strings in their own files, and their policies differ** — claude injects `--permission-mode bypassPermissions` **unconditionally** as the first two arguments to turn approvals off (`crates/engram-dashboard-agent/src/backend/claude/mod.rs:128-129`), and codex allows writing with `-s workspace-write -a on-request` and takes approval on request (`backend/codex/mod.rs:104-107`, constants `:46-51`). ★**Within one product the permission policy splits per backend, and the user has no way to see it.**★
- The reason it ended up that way is also left in the code — ADR-0097 adopted auto mode as the default on the ground 「승인 프롬프트를 띄울 사람이 없다(CLI 발신 0/38 실측)」 (there is no person to show an approval prompt to (CLI senders 0/38 measured)). It was turned off **because there was no screen to ask on**.
- ★**That ground now wobbles**★ — the app-server that ADR-0187 chose sends approval requests **to us** (11 kinds declared in the schema). codex is the first backend that demands a 「승인을 물어볼 화면」 (screen to ask approval on) from our UI.

## 결정

**Define permissions and approvals as a backend-neutral axis in our vocabulary, and have each backend move those values into its own arguments.**

- **Features that correspond are defined as our values.** The place to move them already exists — it is the place where `build_spec` produces `--permission-mode` for claude and `-s`/`-a` for codex today. The hard-coded literals change to **come from the value**.
- **Features without a counterpart stay backend-specific, but 「전용이다」 (it is specific) must show in the vocabulary.** Mixing them into free-string arguments as today leaves no way to tell common from specific — there must be a separate place that holds the specific settings, so that the screen and the LLM can know 「이건 이 백엔드만」 (this is only for this backend).
- ★**The matching decision is made by behavior, not by name**★ — even if value names are similar, if what they do differs, the moment they are bundled the screen makes a false report.
- **This ADR does not decide the value design (the number of axes · value names · what stays specific)** — it is a follow-up ADR. The reason is the last item of the 「근거」 section.

## 거부한 대안

- **Keep today's state (each backend fixes its own values)** — the frontend has 0 lines of permission concept and the two backends' policies **already differ from each other** (the measurement in 맥락 above). Every time a backend is added the combinations grow, and the user has no way to know from the screen what their agent can do. It touches both 「특정 모델·전송 방식에 코드를 묶지 않는다」 of CLAUDE.md 「아키텍처 원칙」 and 「LLM-우선 제어」.
- **Promote claude's vocabulary to the common vocabulary** — ★one axis of claude **cannot cover codex's sandbox axis** (measured)★. Among the 6 values of `--permission-mode` (`acceptEdits` · `auto` · `bypassPermissions` · `manual` · `dontAsk` · `plan`) there is none that decides the file-write and network scope of executed commands, and claude's version of that axis is scattered across separate flags (`--add-dir` · `--restricted`).
- **Promote codex's vocabulary to the common vocabulary** — there are three axes (`approvalPolicy` · `sandbox` · `permissions`) and ★`permissions` and `sandbox` are declared **mutually exclusive**★ (generated schema). There is no counterpart to move to on the claude side, and the set of named profile ids is not fixed by the protocol, so it is a runtime enumeration.
- **Match things with similar value names right now** — ★**there is no ground for matching (measured)**★. For codex's three sandbox values and claude's six values, **neither side's help text writes even one line of per-value meaning**. The only correspondence that stands on help-text wording is the one 「전부 무시」 (ignore everything) family (codex `--dangerously-bypass-approvals-and-sandbox` ↔ claude `--dangerously-skip-permissions` · `bypassPermissions`). Bundling without a ground makes the screen display something different from what is actually done.

All four rejections are caught by measurement, schema or code (no rejection rests on description alone).

## 근거

- The canonical source for the measured value lists = `.claude/handoff/attachments/codex-measurements-2026-09-09.md` §2. The **mismatch in the number of axes** (codex CLI = two axes that take values + one named profile / app-server = three, of which two are mutually exclusive / claude = one axis with 6 values) and **the absence of per-value meaning** are in that document.
- The values we inject today and their places are canonical in the `file:line` of 맥락 above. **Can they be overridden** — only appending after is possible, and ★whether the later value wins is unverified★ (our source already wrote that gap down — `claude/mod.rs:574`).
- ★**Why this ADR does not do the value design**★ — to lay out the axes we have to know **what claude's 6 values actually do**, and the help text does not say. Naming before confirming that would repeat at the vocabulary layer the failure for which this repository received BLOCK two rounds in a row (designing by layer names and checking the code afterward). We decide after measuring.

## 영향 / 불변식

- ★**claude's behavior changes**★ — the `bypassPermissions` injected unconditionally now becomes **value-derived**. ADR-0097's adoption of the default itself stays alive (that is why this is a partial amendment), and what changes is **that the value was fixed in code**. Its ground, 「물어볼 화면이 없다」 (there is no screen to ask on), dies at the point when the screen exists.
- **Axes may be added to `Capabilities`** — if so, it goes through the `PROTOCOL_VERSION` decision. ★Do not restate here the v4 reason that adding a `#[serde(default)]` field to an existing variant and adding a variant to a `#[serde(tag)]` enum are different axes★ (canonical source = `crates/engram-dashboard-protocol/src/lib.rs`).
- **Keep the ownership split** (ADR-0030) — permission is **what that program can do**, so it is an axis on the `BackendCaps` side. Do not wedge it into the `input`/`output`/`control` that the transport reports.
- **Keep the backend knowledge isolation** (ADR-0004) — the value→argument conversion happens only inside each `backend/<name>/`. If the shared layer knows words like `bypassPermissions` or `workspace-write`, that is a violation.
- **Build an LLM call path together with a new UI surface** (CLAUDE.md 「LLM-우선 제어」) — changing the permission mode goes on the command bus and does not add a new global handle. A human's key and the LLM use the same command.
- **What remains as follow-up** — ① confirm what claude's 6 values actually do ② decide the number of axes · value names · specific remainder (a new ADR) ③ ★**whether the mode can be changed in a live conversation**★ is unconfirmed (we did not look at whether app-server's 155 client request kinds have such a method, nor at the claude stream-json side). If it cannot be changed, 「모드 변경 = 다시 띄우기」 (mode change = start again) and the behavior the user feels changes.
