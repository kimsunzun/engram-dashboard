# ADR-0188: 권한과 승인을 백엔드 중립 축으로 추상화한다 — 값 설계는 후속

- 상태: 확정 (2026-09-09, 근거: 사용자 결정 + 양쪽 CLI 값 목록 실측)
- 관련: Amends ADR-0097 (권한 값을 백엔드 코드에 고정하던 부분) · ADR-0004(백엔드 지식 격리) · ADR-0002/0030(capability 산출·소유권 분할) · ADR-0187(app-server 통로 확정) · `.claude/handoff/attachments/codex-measurements-2026-09-09.md` §2(값 목록 실측) · CLAUDE.md 「아키텍처 원칙」·「LLM-우선 제어」 · step-log S21

## 맥락

codex 를 두 번째 백엔드로 붙이면서 「codex 를 읽기 전용으로 띄울까요」라는 질문이 나왔고, 사용자가 **그 질문 자체가 구조 결함의 신호**라고 지적했다 — 권한이 추상화돼 있으면 백엔드마다 따로 물을 일이 아니라는 것이다. 확인해 보니 그 지적이 맞았다.

- **프론트에 권한 개념이 0 줄이다** — `src/` 에서 permission·approval·sandbox 검색 결과가 없다. 화면에도, LLM 제어 표면에도 그 축이 없다.
- **`Capabilities` 에 권한 영역이 없다** — 다섯 영역(input·output·control·session·model) 어디에도 안 들어 있다.
- **두 백엔드가 각자 자기 파일에서 문자열로 박아 놓고 있고 정책이 서로 다르다** — claude 는 `--permission-mode bypassPermissions` 를 맨 앞 두 인자로 **무조건** 주입해 승인을 끄고(`crates/engram-dashboard-agent/src/backend/claude/mod.rs:128-129`), codex 는 `-s workspace-write -a on-request` 로 쓰기를 허용하고 요청 시 승인을 받는다(`backend/codex/mod.rs:104-107`, 상수 `:46-51`). ★**같은 제품 안에서 백엔드마다 권한 정책이 갈려 있고 사용자가 그것을 볼 방법이 없다.**★
- 그렇게 된 이유도 코드에 남아 있다 — ADR-0097 이 「승인 프롬프트를 띄울 사람이 없다(CLI 발신 0/38 실측)」를 근거로 auto mode 를 기본으로 채택했다. **물어볼 화면이 없어서 끈 것**이다.
- ★**그 근거가 이제 흔들린다**★ — ADR-0187 이 고른 app-server 는 승인 요청을 **우리에게** 보낸다(스키마 선언 11 종). codex 가 「승인을 물어볼 화면」을 우리 UI 에 요구하는 첫 백엔드다.

## 결정

**권한·승인을 백엔드 중립 축으로 우리 어휘에 정의하고, 각 백엔드가 그 값을 자기 인자로 옮긴다.**

- **대응되는 기능은 우리 값으로 정의한다.** 옮기는 자리는 이미 있다 — `build_spec` 이 오늘 claude 에 `--permission-mode`, codex 에 `-s`/`-a` 를 만들어 내는 그 자리다. 박혀 있는 리터럴이 **값에서 나오게** 바뀐다.
- **대응 없는 기능은 백엔드 전용으로 남기되, 「전용이다」가 어휘에 드러나게 한다.** 오늘처럼 자유 문자열 인자에 섞어 흘리면 공통인지 전용인지 구분이 안 보인다 — 전용 설정이 담기는 자리가 따로 있어야 화면과 LLM 이 「이건 이 백엔드만」을 알 수 있다.
- ★**매칭 판정은 이름이 아니라 동작으로 한다**★ — 값 이름이 비슷해도 하는 일이 다르면 묶는 순간 화면이 거짓 신고를 한다.
- **값 설계(축 개수 · 값 이름 · 무엇을 전용으로 남기나)는 이 ADR 이 정하지 않는다** — 후속 ADR 이다. 이유는 「근거」 절 마지막 항목.

## 거부한 대안

- **오늘 상태 유지(백엔드마다 값을 각자 고정)** — 프론트에 권한 개념이 0 줄이고 두 백엔드 정책이 **이미 서로 다르다**(위 맥락의 실측). 백엔드가 늘 때마다 조합이 늘고, 사용자는 자기 에이전트가 무엇을 할 수 있는지 화면에서 알 방법이 없다. CLAUDE.md 「아키텍처 원칙」의 「특정 모델·전송 방식에 코드를 묶지 않는다」와 「LLM-우선 제어」 양쪽에 걸린다.
- **claude 어휘를 공통 어휘로 승격** — ★claude 의 한 축이 codex 의 **샌드박스 축을 못 덮는다**(실측)★. `--permission-mode` 6 값(`acceptEdits`·`auto`·`bypassPermissions`·`manual`·`dontAsk`·`plan`) 중 실행되는 명령의 파일 쓰기·네트워크 범위를 정하는 값이 없고, claude 의 그 축은 별 플래그로 흩어져 있다(`--add-dir`·`--restricted`).
- **codex 어휘를 공통 어휘로 승격** — 축이 셋이고(`approvalPolicy`·`sandbox`·`permissions`) ★`permissions` 와 `sandbox` 가 **상호 배타**로 선언돼 있다★(생성 스키마). claude 쪽에 옮길 짝이 없고, 이름 프로필 id 집합은 프로토콜이 고정하지 않아 런타임 열거다.
- **값 이름이 비슷한 것끼리 지금 즉시 매칭** — ★**매칭 근거가 없다(실측)**★. codex 의 샌드박스 세 값과 claude 의 여섯 값은 **양쪽 도움말이 값별 의미를 한 줄도 적지 않는다**. 도움말 문구로 대응이 서는 것은 「전부 무시」 계열 하나뿐이다(codex `--dangerously-bypass-approvals-and-sandbox` ↔ claude `--dangerously-skip-permissions`·`bypassPermissions`). 근거 없이 묶으면 화면이 하는 일과 다른 것을 표시한다.

네 기각 모두 실측·스키마·코드에 걸린다(서술만인 기각 없음).

## 근거

- 값 목록 실측 정본 = `.claude/handoff/attachments/codex-measurements-2026-09-09.md` §2. **축 개수 불일치**(codex CLI = 값 받는 축 둘 + 이름 프로필 하나 / app-server = 셋, 그중 둘이 상호 배타 / claude = 한 축 6 값)와 **값별 의미 부재**가 그 문서에 있다.
- 오늘 우리가 넣는 값과 그 자리는 위 맥락의 `file:line` 이 정본이다. **덮어쓸 수 있나** — 뒤에 붙이는 것만 가능하고 ★뒤 값이 이기는지는 미검증★이다(우리 소스가 그 공백을 이미 적어 뒀다 — `claude/mod.rs:574`).
- ★**값 설계를 이 ADR 이 하지 않는 이유**★ — 축을 짜려면 claude 6 값이 **실제로 무엇을 하는지** 알아야 하는데 도움말에 없다. 그 확인 전에 이름을 정하면 이 저장소가 두 라운드 연속 BLOCK 을 받은 실패(층 이름으로 설계하고 코드를 나중에 대 보기)를 어휘 층에서 반복한다. 재고 나서 정한다.

## 영향 / 불변식

- ★**claude 동작이 바뀐다**★ — 지금 무조건 주입하는 `bypassPermissions` 가 **값 유래**가 된다. ADR-0097 의 기본값 채택 자체는 살아 있고(그래서 부분 개정이다), 바뀌는 것은 **그 값이 코드에 고정돼 있던 것**이다. 그 근거였던 「물어볼 화면이 없다」는 화면이 생기는 시점에 죽는다.
- **`Capabilities` 에 축이 늘 수 있다** — 그렇게 되면 `PROTOCOL_VERSION` 판정을 탄다. ★기존 변형에 `#[serde(default)]` 칸을 더하는 것과 `#[serde(tag)]` enum 에 변형을 더하는 것은 다른 축★이라는 v4 의 사유를 되풀지 말 것(정본 = `crates/engram-dashboard-protocol/src/lib.rs`).
- **소유권 분할을 지킨다**(ADR-0030) — 권한은 **그 프로그램이 무엇을 할 수 있나**라 `BackendCaps` 쪽 축이다. transport 가 신고하는 `input`/`output`/`control` 에 끼워 넣지 않는다.
- **백엔드 지식 격리를 지킨다**(ADR-0004) — 값→인자 변환은 각 `backend/<name>/` 안에서만 일어난다. 공용 층이 `bypassPermissions`·`workspace-write` 같은 낱말을 알면 위반이다.
- **새 UI 표면에는 LLM 호출 경로를 함께 만든다**(CLAUDE.md 「LLM-우선 제어」) — 권한 모드를 바꾸는 것은 명령 버스에 얹고 새 전역 핸들을 늘리지 않는다. 사람의 키와 LLM 이 같은 명령을 쓴다.
- **후속으로 남는 것** — ① claude 6 값의 실제 동작 확인 ② 축 개수·값 이름·전용 잔여 결정(새 ADR) ③ ★**살아 있는 대화에서 모드를 바꿀 수 있나**★가 미확인이다(app-server 의 클라 요청 155 종에 그런 메서드가 있는지 안 봤고, claude stream-json 쪽도 안 봤다). 못 바꾸면 「모드 변경 = 다시 띄우기」가 되어 사용자가 체감하는 동작이 달라진다.
