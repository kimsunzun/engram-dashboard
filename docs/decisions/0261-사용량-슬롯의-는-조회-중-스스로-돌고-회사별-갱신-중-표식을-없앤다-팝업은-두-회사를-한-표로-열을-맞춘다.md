# ADR-0261: 사용량 슬롯의 ⟳ 는 조회 중 스스로 돌고 회사별 갱신 중 표식을 없앤다 — 팝업은 두 회사를 한 표로 열을 맞춘다

- 상태: 확정 (2026-10-01, 근거: 사용자 결정(개정 19 실사용 피드백 — 원문 = `.claude/handoff/attachments/usage-slot-user-answers-2026-10-01.md`) + `/qa full` 관찰 1건(스크린숏 `.claude/handoff/attachments/usage-rev19-qa-2026-10-01/08-popup-codex-refreshing.png`) — ★피어 언급은 메인 기억이고 조사로 확인하지 않았다 · 적대 리뷰 전★)
- 관련: Amends ADR-0259 (결정 2의 조회 중 누름 처리) · ADR-0258(결정 3 — 조회가 진행 중이면 누름은 새 조회를 내지 않는다 · 시간 간격 없음 — 그대로) · ADR-0254(⟳ = 구독 강제 재전송 뒤 조회 요청 — 그대로) · ADR-0069(문구 = `t()`) · PRD `docs/process/S21-usage-limit-slot/prd.md` R5·R12·R27·D11 · TRD `docs/process/S21-usage-limit-slot/trd.md` §1-8 · §2 · §3 #102·#104·#106·#107·#108 · §6 #32·#33 · step-log S21 · Amends ADR-0258 (결정 3의 조회 중 누름 화면 응답)

## 맥락
개정 19(`603248d`)를 띄워 실사용하며 사용자가 피드백을 줬다(2026-10-01). 그때 화면은 이랬다.

- **조회 중 표시가 둘이었다.** 작은 표시는 회사 아이콘 옆에 도는 화살표 표식을 붙였다(`src/components/slot/UsageSlot.tsx` 의 `RefreshingMark` — 아이콘 묶음 `NameUnit` 안). 팝업은 회사 머리의 ⟳ 뒤에 「갱신 중」 글자를 붙였다(`data-usage-refreshing-text`). ⟳ 버튼 자체는 돌지 않았다.
- **그 표식이 자리를 차지했다.** 1·2단은 표식이 이름 칸(격자 첫 열)에 들어가 조회 중엔 격자 열이 약 17px 오른쪽으로 밀렸다(`/qa full` 관찰 — 스크린숏 `08-popup-codex-refreshing.png` · 단계는 그대로). 3단은 ⟳ 가 움직이지 않게 쉬는 줄 끝에 표식만 한 빈자리를 두고(`RefreshingMarkSpace`), 숨은 측정 사본은 표식을 늘 셌다 — 「조회 중 불이동」(`d88dfee` · TRD §3 #104 ③④ — 방법은 메인 결정). 그 결정이 지킨 것은 ⟳ 자리와 단계였고, 1·2단의 격자 열은 범위 밖이었다.
- **조회 중 누름은 화면 반응 없이 버려졌다** — 새 조회도 없고(ADR-0258 결정 3) 눈에 보이는 응답도 없었다(ADR-0259 결정 2 「누름을 버린다」 · `RefreshIconButton` 의 `busy` 갈래).
- **팝업은 창 줄마다 따로 놓였다** — 줄마다 flex 한 줄이고 이름 칸은 최소 폭만 있다(`PopupWindowRow`). 그래서 `gpt-reserve` 줄의 막대가 밀리고, `3%` 줄의 모래시계가 어긋나며, Fable 줄 위 간격이 더 넓었다(사용자 스크린숏 — 간격이 넓은 원인은 확인하지 않았다).

사용자 원문: 「툴팁모드에서 [팝업 스크린숏] 정렬 맞춤하고, 그리고 일반모드에서 버튼 눌러서 리프레시 돌리면 그냥 새로 리프레시 표시가 나오는게 아니고 버튼 자체가 리프레시 돌아가다 멈추면 좋을것 같은데?」

## 결정
1. **⟳ 버튼 자체가 돈다 — 회사별 「갱신 중」 표식은 없앤다.** 작은 표시 아이콘 옆의 회전 표식과 팝업 회사 머리의 「갱신 중」 글자를 둘 다 걷는다. 작은 표시의 전역 ⟳ 는 대상 회사 가운데 하나라도 조회 중이면 돈다 — 수동 ⟳ 든 자동 조회든 같다(조회 중 = 그 회사의 ⟳ 답 대기 또는 스냅숏 `in_flight` — 지금 「갱신 중」의 판정 그대로). 팝업의 회사별 ⟳ 는 그 회사가 조회 중이면 돈다. 사용자: 「일단 그게 깔끔할것같긴한데」 → 메인 추천 (가) → 「ㅇㅇ 그렇게 하면 될듯?」.
2. **최소 한 바퀴 돌고, 조회가 끝나면 돌던 바퀴를 마저 돈 뒤 멈춘다** — 갑자기 멈추지 않는다. 메인 제안을 사용자가 받아들였다(1 의 「ㅇㅇ 그렇게 하면 될듯?」).
3. **조회 중의 누름 = 새 조회 없이 회전만 처음부터 다시 시작한다.** 새 조회를 내지 않는 규칙은 ADR-0258 결정 3 그대로다 — 버리는 창은 누른 순간부터 그 조회 결과가 올 때까지이고 고정 간격은 없다. 회전 재시작은 눌렀다는 것을 눈으로 받는 표시일 뿐이다. 사용자: 「근데 다시 한번 연속으로 누르면 처음부터 돌리면 될듯?」 → 확인 질문 뒤 「ㅇㅇ 알았어. 이해함. 그대로 하면 될것같고」. **조회는 끝났고 바퀴를 마저 도는 중의 누름 = 보통 누름** — 새 조회를 내고 회전을 처음부터 다시 시작한다(메인 확인 질문의 「갈래 하나」를 사용자가 받아들였다). 보이는 거절 중 비활성(`aria-disabled`)은 그대로다. 이 결정은 ADR-0259 결정 2 의 「그 회사의 조회가 진행 중이면 누름을 버린다」를 화면 응답에 한해 고친다 — 작은 표시의 전역 ⟳ 에도 같은 응답이 걸린다(ADR-0258 결정 3 의 조회 규칙은 그대로).
4. **움직임 줄이기 설정과 e-ink 테마에서도 돈다** — 이 저장소의 회전 기호 규칙을 따른다(멈춘 회전은 「멈춤」과 구분되지 않는다 — 사용자 결정 2026-08-24·2026-09-24 · `src/components/agent/agentGlyph.css` · `src/components/ui/loading-panel.css` 주석). 지금 `RefreshingMark` 가 이미 이 규칙이다.
5. **팝업은 두 회사 칸 전체를 한 표로 열을 맞춘다(선택지 (나)).** 열 = 이름 | 막대 | %(오른쪽 끝 맞춤) | 리셋 시각(모래시계 + 시각 — ADR-0259 결정 3) | 남은 시간 「(… 뒤)」. 이름 열의 폭은 팝업 전체에서 가장 긴 이름(예 `gpt-reserve`)이다. 숫자는 고정폭(tabular-nums)이다. 줄 간격은 모두 같다. 오늘 리셋(날짜 없는 `15:20`) 줄은 시각 뒤에 빈칸이 생긴다 — 제시 때 알렸고 사용자가 골랐다. 사용자: 「ㅇㅇ 나로 해줘.」(메인 추천 (나)).

## 거부한 대안
★아래 사유의 출처를 항목마다 적는다 — 사용자 원문 · 제시 때의 근거(메인) · 코드·관측 중 하나다.★ 제시 때의 근거는 메인이 선택지를 올릴 때 적은 것이고, 사용자가 그 사유로 거부했다는 원문은 없다(ADR-0258·0259 와 같은 표기).
- **(나) 버튼도 돌고 회사별 표식도 남긴다** — 사용자 원문: 「일단 그게 깔끔할것같긴한데」((가) 쪽). 제시 때의 근거(메인): 회사별 진행은 팝업의 회사별 ⟳ 가 보여 주고, 실패는 「!」 배지가 남으며, 17px 밀림이 근본적으로 사라진다. 밀림은 관측이다(`/qa full` 스크린숏 `08`).
- **조회 중 재누름에 새 조회도 보낸다** — 제시 때의 근거(메인): ADR-0258 결정 3 을 뒤집고 429 위험이 있다(Claude 는 429 가 `Failed` 로 와 거절 중 차단이 걸리지 않는다 — TRD §6 #21). 사용자는 버리는 창의 길이를 물은 뒤(「조회중에 누름 버림은 어느정도 간격임?」 → 메인 답: 고정 간격 없음 — 그 조회 결과가 올 때까지) 회전만 다시 도는 쪽을 골랐다.
- **조회 중 재누름을 화면 반응 없이 버린다(바꾸기 전 동작 — ADR-0259 결정 2)** — 사용자 원문: 「다시 한번 연속으로 누르면 처음부터 돌리면 될듯?」.
- **(가) 팝업의 리셋 부분을 한 덩어리로 둔다(모래시계 시작점까지만 맞춤)** — 사용자는 메인 추천 (나)를 골랐다(「ㅇㅇ 나로 해줘.」). ★(가)를 거부한 사유는 사용자 원문이 아니라 메인 추천의 사유다★ — 남은 시간은 훑어볼 때 가장 많이 읽는 부분인데 (나)는 그 시작점이 한 줄로 맞아 표처럼 읽히고, (가)는 「(… 뒤)」 위치가 시각 길이에 따라 줄마다 어긋난다(제시 원문 = `.claude/handoff/attachments/usage-slot-user-answers-2026-10-01.md` 결정 2). 제시 때 알린 (나)의 대가 = 오늘 리셋 줄은 시각 뒤에 빈칸이 생긴다.
- **팝업 줄을 지금처럼 줄마다 따로 놓는다** — 사용자 원문: 「툴팁모드에서 [팝업 스크린숏] 정렬 맞춤하고」. 관측(사용자 스크린숏): `gpt-reserve` 줄의 막대가 밀리고 `3%` 줄의 모래시계가 어긋나며 Fable 줄 위 간격이 더 넓다.

## 영향 / 불변식
- **조회 중 누름은 여전히 새 조회를 내지 않는다(ADR-0258 결정 3)** — 회전 재시작을 「새 조회가 나갔다」로 읽고 그 자리에 조회를 붙이지 말 것(429 — TRD §6 #21). 구독 강제 재전송(ADR-0254)도 그 누름에선 나가지 않는다 — 지금과 같다.
- **회전의 꼬리는 「조회 중」이 아니다** — 조회가 끝나 바퀴를 마저 도는 동안의 누름은 보통 누름이다. 그래서 기계가 읽는 진행 상태(`aria-busy` 등)는 회전이 아니라 조회를 따른다(구현 세부 = TRD §3 #107).
- **회사별 「갱신 중」 표식을 되살리지 말 것** — 되살리면 1·2단 격자 열이 다시 밀리고, 3단 ⟳ 자리를 지키던 빈자리와 측정 사본의 상시 계산(TRD §3 #104 ③④)도 다시 필요해진다.
- **「조회 중 불이동」(`d88dfee` · TRD §3 #104)과의 관계** — 목적(조회가 ⟳ 자리와 단계를 바꾸지 않는다)은 그대로이고, 이제 1·2단 격자 열까지 덮는다(내용 안에 조회로 폭이 바뀌는 것이 없다). 수단 ③(3단 빈자리)·④(측정 사본이 표식을 늘 셈)는 지킬 표식이 없어 걷는다. 그 대가였던 ⑤(1·2단이 약 14px 일찍 다음 단계로 · 좁은 3단은 조회 중 숫자가 약 14px 일찍 잘림)도 함께 사라진다. ①(⟳ 는 내용 바로 옆)·②(단계 측정 폭 = 슬롯 폭 − ⟳ 자리 − 여백)는 그대로다.
- **LLM·cdp 가 읽는 회사별 진행 상태는 남긴다**(PRD R27 · CLAUDE.md 「LLM-우선 제어」) — 보이는 표식을 걷어도 ⟳ 의 `aria-busy` · 진행 중인 회사 이름을 단 데이터 속성 · 요약 버튼 접근성 이름의 회사별 「갱신 중」은 남는다(모양 = TRD §3 #107 — 메인 결정(구현)).
- **움직임 줄이기·e-ink 에서 회전을 끄지 말 것**(결정 4). 받아들인 위험(메인 관측): ⟳ 는 쉴 때와 돌 때 모양이 같다. 그래서 회전이 어떤 이유로 안 돌면 화면에서 진행 신호가 통째로 사라진다 — 회전 기호(`agentGlyph.css`)처럼 모양으로 남는 여유가 없다(TRD §6 #33).
- **받아들인 대가(메인 관측)** — 작은 표시만 보면 어느 회사가 조회 중인지 모른다. 팝업의 회사별 ⟳ · 요약 버튼 접근성 이름 · 데이터 속성이 그것을 진다(TRD §6 #32).
- **팝업 줄을 다시 줄마다 따로 놓지 말 것**(결정 5) — 이름 열은 팝업 전체에서 가장 긴 이름이다. 오늘 리셋 줄의 시각 뒤 빈칸은 받아들인 모양이다. 값이 없는 칸도 빈 칸으로 남겨 열이 밀리지 않게 한다(구현 세부 = TRD §3 #108).
