# ADR-0261: The usage slot's ⟳ spins by itself during a fetch and the per-vendor refreshing marker is removed — the popup aligns the columns of both vendors as one table

- 상태: 확정 (2026-10-01, basis: user decision (revision 19 real-use feedback — source text = `.claude/handoff/attachments/usage-slot-user-answers-2026-10-01.md`) + one `/qa full` observation (screenshot `.claude/handoff/attachments/usage-rev19-qa-2026-10-01/08-popup-codex-refreshing.png`) — ★the peer mentions are main's memory and were not confirmed by research · before adversarial review★)
- 관련: Amends ADR-0259 (Decision 2's on-screen response to a press during a fetch — no new fetch stays as is) · Amends ADR-0258 (only Decision 3's on-screen response to a press during a fetch — no new fetch and no time interval stay as is) · ADR-0254 (⟳ = force re-send of subscriptions, then fetch request — unchanged) · ADR-0069 (copy = `t()`) · PRD `docs/process/S21-usage-limit-slot/prd.md` R5·R12·R27·D11 · TRD `docs/process/S21-usage-limit-slot/trd.md` §1-8 · §2 · §3 #102·#104·#106·#107·#108 · §6 #32·#33 · step-log S21

## 맥락
The user ran revision 19 (`603248d`) in real use and gave feedback (2026-10-01). The screen then looked like this.

- **There were two fetching indicators.** The small display attached a spinning arrow marker beside the vendor icon (`RefreshingMark` in `src/components/slot/UsageSlot.tsx` — inside the icon group `NameUnit`). The popup attached the text 「갱신 중」 after the ⟳ at the vendor head (`data-usage-refreshing-text`). The ⟳ button itself did not spin.
- **That marker took up space.** In stages 1 and 2 the marker went into the name column (the first column of the grid), so during a fetch the grid columns shifted about 17px to the right (`/qa full` observation — screenshot `08-popup-codex-refreshing.png` · the stage stayed the same). In stage 3 a blank the size of the marker was left at the end of the idle row so that ⟳ would not move (`RefreshingMarkSpace`), and the hidden measurement copy always counted the marker — 「조회 중 불이동」 (`d88dfee` · TRD §3 #104 ③④ — the method is main's decision). What that decision protected was the ⟳ position and the stage, and the grid columns of stages 1 and 2 were out of its scope.
- **A press during a fetch was discarded with no on-screen reaction** — there was no new fetch (ADR-0258 Decision 3) and no visible response either (ADR-0259 Decision 2 「누름을 버린다」 · the `busy` branch of `RefreshIconButton`).
- **The popup was laid out separately for each window row** — each row is one flex line and the name column has only a minimum width (`PopupWindowRow`). So the bar of the `gpt-reserve` row was pushed, the hourglass of the `3%` row was misaligned, and the gap above the Fable row was wider (user screenshot — the cause of the wider gap was not confirmed).

User's words: 「툴팁모드에서 [팝업 스크린숏] 정렬 맞춤하고, 그리고 일반모드에서 버튼 눌러서 리프레시 돌리면 그냥 새로 리프레시 표시가 나오는게 아니고 버튼 자체가 리프레시 돌아가다 멈추면 좋을것 같은데?」

## 결정
1. **The ⟳ button itself spins — the per-vendor 「갱신 중」 marker is removed.** Remove both the spinning marker beside the icon on the small display and the 「갱신 중」 text at the popup vendor head. The small display's global ⟳ spins if any of the target vendors is fetching — the same for a manual ⟳ and an automatic fetch (fetching = that vendor's wait for a ⟳ reply or the snapshot `in_flight` — exactly the current decision for 「갱신 중」). The popup's per-vendor ⟳ spins if that vendor is fetching. User: 「일단 그게 깔끔할것같긴한데」 → main's recommendation (가) → 「ㅇㅇ 그렇게 하면 될듯?」.
2. **It spins at least one full turn, and when the fetch ends, it finishes the turn in progress and then stops** — it does not stop abruptly. The user accepted main's proposal (the 「ㅇㅇ 그렇게 하면 될듯?」 of 1).
3. **A press during a fetch = no new fetch, and only the spin restarts from the beginning.** The rule of not issuing a new fetch is as in ADR-0258 Decision 3 — the discard window runs from the moment of the press until that fetch's result arrives, and there is no fixed interval. The spin restart is only an indication that the press was received visually. User: 「근데 다시 한번 연속으로 누르면 처음부터 돌리면 될듯?」 → after a confirmation question 「ㅇㅇ 알았어. 이해함. 그대로 하면 될것같고」. **A press while the fetch is done and the turn is being finished = a normal press** — it issues a new fetch and restarts the spin from the beginning (the user accepted the 「갈래 하나」 of main's confirmation question). The disabled state (`aria-disabled`) during a visible rejection stays as is. This decision amends ADR-0259 Decision 2's 「그 회사의 조회가 진행 중이면 누름을 버린다」 for the on-screen response only — the same response applies to the small display's global ⟳ (the fetch rule of ADR-0258 Decision 3 stays as is).
4. **It spins also under the reduced-motion setting and the e-ink theme** — it follows this repository's rule for spinning glyphs (a stopped spin is indistinguishable from 「멈춤」 — user decision 2026-08-24·2026-09-24 · comments in `src/components/agent/agentGlyph.css` · `src/components/ui/loading-panel.css`). `RefreshingMark` already follows this rule now.
5. **The popup aligns the columns of the whole area of both vendors as one table (option (나)).** Columns = name | bar | %(right-aligned) | reset time (hourglass + time — ADR-0259 Decision 3) | remaining time 「(… 뒤)」. The width of the name column is the longest name in the whole popup (e.g. `gpt-reserve`). Numbers are fixed-width (tabular-nums). All row gaps are the same. A row that resets today (`15:20` with no date) gets a blank after the time — the user was told at presentation and chose it. User: 「ㅇㅇ 나로 해줘.」 (main's recommendation (나)).

## 근거
- **User decision (2026-10-01)** — source text = `.claude/handoff/attachments/usage-slot-user-answers-2026-10-01.md` (the feedback's source text · the questions and answers of Decisions 1 and 2 · the presentation mockup).
- **Observation** — `/qa full` (2026-10-01) screenshot `.claude/handoff/attachments/usage-rev19-qa-2026-10-01/08-popup-codex-refreshing.png`: when one vendor is fetching, the small display's grid columns shift about 17px to the right. The stage stays the same.
- **Peers (★main's memory — not confirmed by research★)** — GitHub Desktop's Fetch origin · the AWS console table refresh · Grafana refresh spin the icon of the pressed button. The basis of this decision is the user's choice, and it does not rest on the peers.
- **Code facts** — the current 「갱신 중」 decision is `pending` (waiting for the ⟳ reply) or the snapshot `in_flight` (`buildVendorView` in `UsageSlot.tsx`). An automatic fetch opened by the scheduler also reaches `in_flight` by broadcast at its start (TRD §1-4). So if the button spins on that value, it spins during an automatic fetch too. The spin is a `transform`, so it does not change position or width.

## 영향 / 불변식
- **A press during a fetch still does not issue a new fetch (ADR-0258 Decision 3)** — do not read the spin restart as 「새 조회가 나갔다」 and attach a fetch there (429 — TRD §6 #21). The force re-send of subscriptions (ADR-0254) also does not go out on that press — the same as now.
- **The tail of the spin is not 「조회 중」** — a press while the fetch is done and the turn is being finished is a normal press. So the progress state that machines read (`aria-busy` etc.) follows the fetch, not the spin (implementation details = TRD §3 #107).
- **Do not revive the per-vendor 「갱신 중」 marker** — if revived, the stage 1·2 grid columns shift again, and the blank that kept the stage 3 ⟳ position and the always-on calculation of the measurement copy (TRD §3 #104 ③④) become necessary again.
- **Relation to 「조회 중 불이동」 (`d88dfee` · TRD §3 #104)** — the purpose (a fetch does not change the ⟳ position and the stage) stays as is, and now it covers the stage 1·2 grid columns too (nothing in the content changes width because of a fetch). Means ③ (the stage 3 blank) and ④ (the measurement copy always counts the marker) are removed because there is no marker to protect. ⑤, which was their cost (stages 1 and 2 go to the next stage about 14px early · in a narrow stage 3 the number is cut off about 14px early during a fetch), also disappears with them. ① (⟳ right next to the content) and ② (stage measurement width = slot width − ⟳ position − margin) stay as is.
- **Keep the per-vendor progress state that the LLM and cdp read** (PRD R27 · CLAUDE.md 「LLM-우선 제어」) — even if the visible marker is removed, ⟳'s `aria-busy` · the data attribute carrying the name of the vendor in progress · the per-vendor 「갱신 중」 in the summary button's accessibility name remain (shape = TRD §3 #107 — main's decision (implementation)).
- **Do not turn off the spin under reduced motion and e-ink** (Decision 4). Accepted risk (main's observation): ⟳ looks the same at rest and while spinning. So if the spin does not run for some reason, the progress signal vanishes from the screen entirely — there is no margin left by shape as with a spinning glyph (`agentGlyph.css`) (TRD §6 #33).
- **Accepted cost (main's observation)** — looking at the small display alone, one cannot tell which vendor is fetching. The popup's per-vendor ⟳ · the summary button's accessibility name · the data attribute carry that (TRD §6 #32).
- **Do not lay out popup rows separately for each row again** (Decision 5) — the name column is the longest name in the whole popup. The blank after the time in a row that resets today is an accepted shape. A cell with no value is also left as an empty cell so the columns do not shift (implementation details = TRD §3 #108).
