# ADR-0162: Relay retry is resolved by a state query instead of a result store

- 상태: 확정 (2026-08-19, basis: code measurement + user decision)
- 관련: ADR-0161(the request number is issued by the caller — this decision closes its open branch) · ADR-0160(the relay is attached by widening the control route) · `src-tauri/src/layout/commands.rs`(15 registered commands) · `crates/engram-dashboard-daemon/src/bin/engram.rs`(the registry-based third surface) · step-log S20

## 맥락

ADR-0161 closed with one branch left open. The relay branch's duplicate prevention is **only 「진행 중 합치기」 (merging while in progress)** — the step that sets up seat retention (`SeatState::Retained`) exists only in the daemon's own command branch, and the relay erases the seat when the round trip ends. So **if the same number comes again after the round trip has ended, it is applied again** (two tabs · two slots).

The surface symptom is 「두 번 생긴다」 (it is made twice), but **the real cost is not that** — it is that when the caller receives `TIMEOUT` two states cannot be told apart: ① the owner did not receive it (operation not done) ② the owner did it but the answer was late (operation done). If retrying is dangerous the caller has to give up even in ①, and then **the option of retrying itself disappears.**

## 결정

**Do not build a result store. Settle it as no handling.** When the caller receives `TIMEOUT`, it **queries the state** to decide whether it was applied, and decides from that result whether to retry.

The chain that serves as the ground was confirmed by measurement (2026-08-19):

1. **Query commands are registered** — `tab.list` (the window's tab list + active tab + version) · `window.list` (all open windows) · `slot.resolveSpatial`. The shell's `declare_commands!` block declares these three as reads (`src-tauri/src/layout/commands.rs:114-123`·`:140-144`·`:227-235`).
2. **The control route does not filter reads** — the routing decision of `handle_call` is only 「내 표에 있나 / 명부에 주인이 있나」 (is it in my table / does the registry have an owner) and has no read/write axis (`control/catalog.rs:318-369`). The name-axis block is only for the mail family (`control/mcp_server.rs:214-217`) and no name qualifies today.
3. ★**The CLI vocabulary is not hand-coded**★ — if the first token has a dot, it **queries the registry and calls whatever is there** (`bin/engram.rs:686`·`:729-763`·`:1773-1826`). The hard-coded vocabulary is only the old `agent`·`mail` paths. That is, the query commands the shell registered **can be typed as they are today.**
4. **`TIMEOUT` really does reach the caller** — ADR-0161 decision 3 bound the deadline inequality (daemon deadline + sweep period + margin < client no-response limit) at compile time. Without it there would be no occasion to query (before that, a false transport error appeared).

That is, **instead of putting retry safety into the machinery, it moves it to the caller's observation.**

★**A more fundamental ground — the caller of this door is a subject that can judge**★ (user decision 2026-08-19). The one using this entrance is an agent, and 「시간 초과를 받았으면 상태를 확인하고 결정한다」 (if I got a timeout, I check the state and decide) is **a judgment an agent can make**. The behavior of sending twice without thinking sits in a **layer corrected by context and prompt**, and is not the kind the plumbing should block on its behalf. If the machinery takes over that judgment, it makes it so **the caller need not look at the state**, and the caller then stops looking even in other situations where a query is needed. This is the grain of CLAUDE.md 「LLM-우선 제어」 — the LLM is the controlling subject and the plumbing does not take over its judgment.

## 거부한 대안

- **Keep the completed result for a short time and return it for the same number** — the sturdiest, but ① retention lifetime and capacity must be newly settled ② **the behavior of the shared machinery changes, which affects the socket entrance too** (the two entrances use the same seat table — ADR-0160 invariant) ③ it amounts to stacking a **second duplicate-prevention axis** on top of the existing seat mechanism, which collides with ADR-0160's 「입구별로 다른 장치를 만들지 않는다」 (do not build a different mechanism per entrance). **Do not add machinery for a problem that a query resolves.**
- **The CLI sends the same number again on retry** (ADR-0161 decision 2 latter half) — it does not hold because the CLI has no retry loop (measured: `post_json` has 3 call sites, the only `loop` is the chunked decode). For the CLI a retry is re-running the process, and a new number is created. Newly exposing a surface that takes a number (a flag or environment variable) also **has no value now that a query is enough.**
- **Lengthen the deadline to reduce timeouts themselves** — it eases the symptom but does not remove the inability to decide. And the deadline is tied to the client limit, so there is little room to lengthen (ADR-0161 invariant).

## 근거

- The 4-step chain above was confirmed down to file:line by a subagent code survey (2026-08-19). ★**It is a static trace and was not actually typed in**★ — in particular item 3 (whether the registry-based CLI really gets the shell-registered query commands through) is **unmeasured**, and since it is a premise of this decision, it is left as a measurement item.
- User judgment (2026-08-19): 「실패하고 다시 보내기보다 현재 상태 확인하고 다시 보낼 것 같다」 (rather than fail and send again, I think it would check the current state and send again) — if the caller's behavior model is query first, there is no reason for the machinery to remember on its behalf.
- ★**The review that produced this decision was a single family**★ — the non-lead family's quota was exhausted. No cross-family cross-check.

## 영향 / 불변식

- **It closes the open branch of ADR-0161 decision 2.** That clause's latter half (resending the same number on retry) is **confirmed permanently unmet**, and both of the branches that were open (a CLI number surface / seat retention in the relay branch) are **not adopted**.
- **The relay branch's duplicate prevention is fixed as 「진행 중 합치기」 (merging while in progress)** — we pin here that this is a decision, not a defect. So that the next session does not read it as 「완료 후 재질의가 막힌다」 (a re-query after completion is blocked), the code comment must say so too (the `request_id` paragraph in `control/catalog.rs`).
- ★**The query path is the premise of this decision**★ — if a read command drops out of the registry, or the control route starts filtering reads, or the CLI's registry-based surface reverts to hard-coding, **the ground of this decision collapses.** A change touching any of those three must reopen this ADR.
- **Two conditions under which a result store becomes necessary** — ① an operation appears that a query cannot decide (a kind where doing the same operation twice leaves states indistinguishable) ② **a caller that cannot judge enters this door.** ② is the case where the premise of the 「더 근본적인 근거」 (more fundamental ground) above collapses — if a consumer appears that hits again without looking at the state, such as a script or an automatic retry layer, then the plumbing must bear it. Reopen if either holds.
