# ADR-0205: Do not build a reader-side hold queue that holds the live lines interleaving into history delivery

- 상태: 확정 (2026-09-17, basis: user decision + measured in code + recheck of the measured scope of ADR-0203)
- 관련: ADR-0203(receive the history by pages and load it as one chunk) · ADR-0204(the transport inserts the restore events) · ADR-0088(no silent loss — distinguish `Ok`/`Err`) · ADR-0202(do not erase activation evidence) · `crates/engram-dashboard-agent/src/output_core.rs::emit_batch_without_turn_observation` · `crates/engram-dashboard-agent/src/backend/codex/transport.rs` header 「알려진 한계」 · `docs/process/S21-codex-backend/trd-phase2a.md` §4-9·§4-10·10-A 21

## 맥락

「리더 쪽 보류 — 버퍼 상한과 넘칠 때 처분」 (“Reader-side hold — the buffer cap and the disposition on overflow”) remained open. The risk it was meant to close looks like this.

[`OutputCore::emit_batch_without_turn_observation`] issues and pushes the seqs of the whole history **inside one replay lock** (`crates/engram-dashboard-agent/src/output_core.rs:259`), and the fanout is done **after releasing** that lock (after `:273`). So the order inside the ring is closed but the delivery order is not — a single `emit` from the reader thread can interleave into the channel of a subscriber that is **already attached** as [chunk seq N] → [live seq N+k] → [chunk seq N+1].

And the frontend handles that by **discarding, not reordering** — the subscription callback drops it with `if (chunk.seq <= lastSeq.current) return` (`src/components/slot/RichSlot.tsx:155` · `TerminalSlot.tsx:253` · `DomSlot.tsx:126`). Symptom = **the restored conversation is quietly cut off on the screen. There is no error indication.**

This risk is already written in two places — the transport header's 「알려진 한계」 (`crates/engram-dashboard-agent/src/backend/codex/transport.rs:45-64`) and the comment at `output_core.rs:238-247`. **This ADR does not erase that risk** — it is a record of deciding **not to close** it.

## 결정

**We do not build a reader-side hold queue.** No bounded queue, no overflow disposition, no cap value. We close the open item as 「지금 하지 않는다」 (“not now”).

## 거부한 대안

The recorded options were three of 「지금 큐를 만든다」 (“build the queue now”), and they split on the overflow disposition. **Since we decided not to build the queue itself, all three are not adopted but deferred.**

- **(a) Drop the oldest quietly** — a family the TRD already rejected: 「조용히 버리는 갈래는 기각됐다 — 그것이 T-28 이 기록한 사고 부류다」 (“the branch that drops quietly was rejected — that is the family of incident T-28 recorded”) (`docs/process/S21-codex-backend/trd-phase2a.md:519`). It is not a subject for reconsideration.
- **(b) Count what was dropped and surface it on screen as one error line** — ★**if we resume, look here first**★. This repository **has a precedent** (the handshake-failure path already puts the **count** of lost input in the screen `detail` — `transport.rs:65-69`), and **there is not a single document that opposes it.**
- **(c) Reject, so the connection is not established** — there is no supporting document and two documents lean the other way. ① the posture of this repository that 「너무 오래 멈춘 것」 (“a thing that has stopped too long”) declares the observation debris and does not kill it (`trd-phase2a.md:1198`) ② the spot ADR-0202 left — the failure record is not erased, yet 「낡은 기록이 도는 에이전트 옆에 남을 때 그것이 낡았다고 알려 주는 표시는 없다」 (“when a stale record remains beside a running agent, there is no indication telling that it is stale”). This is a branch that turns a screen-order problem into an **activation failure**.

## 근거

It is a user decision, and five supports were confirmed in the session.

1. **Four of the six cannot come in that window.** The notifications the decoder translates into output events are six (`translate` at `decoder.rs:443-456` — `item/agentMessage/delta` · `item/started` · `item/completed` · `turn/completed` · `thread/tokenUsage/updated` · `error`. `deprecationNotice` emits no event). The first **four are turn output**, and the spot that opens a turn requires `Link::Ready`, so there is no turn before the gate opens.
2. **The other two are 「미측정」 (“unmeasured”), not 「0 건으로 측정됐다」 (“measured as 0 cases”).** The ones not tied to a turn are `thread/tokenUsage/updated` and `error`, and **one arriving in that window has never been observed.** ★But the measurement of ADR-0203 is explicitly limited to `item/*`★ — 「이력은 **전부 응답 안에** 있다 — resume 뒤 `item/*` 알림은 0건」 (“the history is **entirely within the response** — after resume there are 0 item/* notifications”) (`docs/decisions/0203-...md:35`). **So these two are not a measured 0 but something not measured.**
3. **A failure of our request does not come through this door.** `Inbound::Error { id }` is resolved by the wait table and returned to the writer (`transport.rs:2267`) — it is not emitted. That is, the 「보여 줘야 할 오류」 (“error that must be shown”) does not race with the history chunk.
4. **Even if it blows, no data is lost.** The ring keeps the history intact and in order (that is exactly what the one-lock chunk is for). A subscriber that **attaches later** receives it intact by replay, so reopening the view recovers the conversation. The damage is confined to **one moment of one already-attached view**.
5. **The prescription brings in a new defect of the same family.** A bounded queue must have a cap and must do something when it overflows, and every candidate disposition either ① drops quietly (the T-28 family the TRD rejected — `trd-phase2a.md:519`) or ② turns a screen-order problem into an **activation failure**.
6. **The cap value would be an invented number.** There is no measurement of how many items come in that window, and the TRD requires such numbers to **have their ground written in a comment** (`trd-phase2a.md:500` — 「그 값의 근거를 주석에 적는다 — 실측이 0 이라 지금 고르는 수는 지어낸 것이다」 (“write the ground for that value in a comment — the measurement is 0, so the number we pick now is invented”)).

## 영향 / 불변식

- **The risk stays open.** We **do not shorten or fix** the 「알려진 한계」 item in the `transport.rs` header and that comment in `output_core.rs` — both are still true. This ADR attaches to that spot only as an anchor and answers 「왜 아직 안 고쳤나」 (“why we have not fixed it yet”).
- **We carry on knowing that the containment is an observation of vendor behavior, not a structure.** codex updates itself and this protocol has no version field (another item in the same header). So that observation can change quietly.
- **Reopen triggers — if either one, reopen.**
  1. **A restored conversation is actually observed to be cut off.**
  2. **`error` or `thread/tokenUsage/updated` is measured arriving in the pre-gate window.**
  On resuming, look at **(b)** first (above, under 「거부한 대안」).
- **This decision does not change the lock discipline of `emit_batch_without_turn_observation`** — ADR-0006 (lock order)·ADR-0203 as they are. What is decided here is only one thing: 「생산자 쪽에 큐를 안 세운다」 (“we do not stand a queue on the producer side”).
