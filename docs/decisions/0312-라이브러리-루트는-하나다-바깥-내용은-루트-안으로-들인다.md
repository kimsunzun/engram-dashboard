# ADR-0312: 라이브러리 루트는 하나다 — 바깥 내용은 루트 안으로 들인다

- 상태: 제안 (2026-10-31, 근거: 사용자 결정 G36(2026-10-31 「ㅇㅇ 루트를 하나로」) · G37(「외부에 두지말고 engram 안으로」) · G37-NOTE(「라이브러리 폴더 바꾸기는 그대로 놔둬」) · G35(「최초 디폴트 등록해둬」) · G31 · G39 + 메인 M22 · M24-2(보고) · PRD R7)
- 관련: 옛 메모 127(2026-10-15 「그냥 한 개 폴더로 하자」 — 되살림) · G25 · G25-RESOLVED · G26 · G27 · G30 · M23 · M19/M21 의 여러 루트 부분(되돌림) · ADR-0315 · ADR-0320 · TRD `docs/process/S25-preset-library/trd.md` §1-1 · §1-2 `LibPath` · §1-4 「루트 · 기본 경로」 · §7 31 · 조사(배경) `docs/research/multi-root-asset-library-practice-2026-10-30.md` · `docs/research/cross-root-move-practice-2026-10-30.md`

## 맥락
메모 127(2026-10-15)은 라이브러리 폴더 하나로 정했다. 2026-10-29 사용자가 여러 루트를 요청했고(G25), 그 뒤 루트를 넘는 참조 허용(G25-RESOLVED) · 루트 이름 접두 `<이름>:/`(G26) · 루트 사이는 복사만(G27) · 루트 이름을 바꾸면 참조 고침(G30) · 참조된 루트 지우기에 `yes`(M23)가 줄줄이 붙었다. 2026-10-31 사용자가 하나로 되돌렸다.

## 결정
1. 라이브러리 루트는 하나다(R7 되살림). 프리셋도 그 안의 파일이다.
2. 루트 안이면 어디로든 옮기고 이름을 바꾼다(탐색기 규칙 — P5). 드라이브가 하나라 볼륨을 넘는 이동이 없다.
3. 바깥 내용(예 `~/.claude/skills`)은 제자리에서 쓰지 않는다 — 루트 안으로 복제 · 복사해 들인다(G37).
4. 나눠 줄 때 = 필요한 파일을 루트 기준 경로로 내보내 같은 경로로 들인다. 내보내기 · 들이기(의존 닫힘)는 S25 밖이다(G37 · T-73). S25 는 참조 걷기를 다시 쓰는 함수 하나로 둬 나중에 꽂히게 한다(G37). 일부만 손으로 옮기면 빈 참조는 「찾을 수 없음 · 다시 연결」(R19).
5. 첫 시작에 루트가 없으면 빈 `<배포판>\library` 를 만들어 루트로 적는다(개발 · 시험 = `DataLayout` 규칙 · `ENGRAM_DATA_DIR` 격리 — G35). 만들기에 실패하면 미설정 상태로 물러난다(M24-2). 「라이브러리 폴더 바꾸기」(R9)는 그대로다(G37-NOTE).
6. 나중에 루트를 늘리면 새 루트에만 이름 접두를 붙이고, 접두 없는 경로는 지금 루트를 뜻한다(G36).
7. 그대로 두는 것: 휴지통 `<루트>\.trash\`(G31 · ADR-0320) · 루트가 git 작업 트리면 `.git/info/exclude`(M22) · 기본 제공 `engram:/`.

## 거부한 대안
- **루트 여럿**(G25 · G25-RESOLVED · G26 · G27 · G30 · M23 — 2026-10-29~30) — 사용자가 되돌렸다(G36). 사용자 이유: 나눠 주기는 루트 기준 경로로 내보내고 같은 경로로 들이는 것으로 한다(언리얼 「Migrate」 · 유니티 「Export Package + dependencies」 꼴 — 메인 지식 · 조사 안 함). 원래 이유(메모 127): 여러 라이브러리의 문제(라이브러리를 넘는 프리셋 참조 · 루트를 넘는 순환)는 프리셋이 라이브러리 안에 살기 때문에 생긴다.
- **프리셋 폴더 따로 + 부품 라이브러리 여럿** — 보였으나 고르지 않았다(메모 127 · PRD R7 「루트를 넘는 참조 · 순환 문제」). (기각 근거: 약함)
- **바깥 폴더를 제자리에서 쓰기**(예 `~/.claude/skills`) — 사용자 「외부에 두지말고 engram 안으로」(G37).

## 영향 / 불변식
- `LibPath` 에 루트 접두가 없다 — `:` 를 받지 않아 `engram:/` 와 섞이지 않는다(TRD §1-2 · ADR-0315).
- 루트 관리 명령은 `library.status` + `setRoot` 둘이다(M21 의 addRoot · removeRoot · renameRoot 를 되돌림 — G36).
- 여러 루트를 다시 열 때는 결정 6 의 확장 길에서 출발하고, G25 갈래(루트를 넘는 참조 · 이름 바꾸면 참조 고침 · 복사만)는 다시 따진다.
- 참조 걷기 함수는 내보내기 · 들이기가 다시 쓸 수 있게 둔다(G37) — 그 기능이 올 때 따로 걷기를 짓지 않는다.
- 기본 루트 `<배포판>\library` 는 배포판 폴더 안이라 `scripts/build-release.ps1` 이 배포판을 다시 지을 때 함께 지워진다 — 의도다(`data\` 와 같음). 쓰는 라이브러리는 「라이브러리 폴더 바꾸기」(R9)로 배포판 밖에 둔다(G39 · 사용자 「빌드용이 뭔가 저장될 필요가 있음? 내가 사용할건 밖으로 뺄건데」). 스크립트는 바꾸지 않는다.
