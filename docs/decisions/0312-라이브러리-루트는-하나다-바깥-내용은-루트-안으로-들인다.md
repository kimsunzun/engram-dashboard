# ADR-0312: There is one library root — outside content is brought inside the root

## 맥락
Memo 127 (2026-10-15) settled on one library folder. On 2026-10-29 the user asked for multiple roots (G25), and then a chain followed: references allowed across roots (G25-RESOLVED) · a root-name prefix `<이름>:/` (G26) · copy only between roots (G27) · fixing references when a root is renamed (G30) · `yes` (M23) for deleting a referenced root. On 2026-10-31 the user reverted to one.

## 결정
1. There is one library root (R7 revived). Presets are also files inside it.
2. Within the root, anything can be moved and renamed anywhere (Explorer rules — P5). There is one drive, so there is no move across volumes.
3. Outside content (e.g. `~/.claude/skills`) is not used in place — it is duplicated or copied into the root and brought in (G37).
4. When handing out = export the needed files by root-relative path and bring them in at the same path. Export and import (dependency closure) are outside S25 (G37 · T-73). S25 keeps the reference walk as a single rewriting function so it can be plugged in later (G37). If only some files are moved by hand, empty references are 「찾을 수 없음 · 다시 연결」 (R19).
5. If there is no root at first start, create an empty `<배포판>\library` and record it as the root (development and test = the `DataLayout` rule · `ENGRAM_DATA_DIR` isolation — G35). If creation fails, fall back to the unset state (M24-2). 「라이브러리 폴더 바꾸기」 (R9) stays as it is (G37-NOTE).
6. If roots are added later, only the new root gets a name prefix, and a path without a prefix means the current root (G36).
7. Kept as is: the trash `<루트>\.trash\` (G31 · ADR-0320) · `.git/info/exclude` when the root is a git working tree (M22) · the built-in `engram:/`.

## 거부한 대안
- **Multiple roots** (G25 · G25-RESOLVED · G26 · G27 · G30 · M23 — 2026-10-29~30) — the user reverted it (G36). The user's reason: handing out is done by exporting by root-relative path and bringing in at the same path (the shape of Unreal 「Migrate」 · Unity 「Export Package + dependencies」 — main's knowledge, not researched). The original reason (memo 127): the problems of multiple libraries (preset references across libraries · cycles across roots) arise because presets live inside the library.
- **A separate preset folder + multiple parts libraries** — it was seen but not chosen (memo 127 · PRD R7 「루트를 넘는 참조 · 순환 문제」). (Basis for rejection: weak) Basis (main 2026-11-01 — reported · M98): it was not chosen, keeping the user's 2026-10-14 decision as is (when handing out, the folder is handed over, so presets must go with it → a preset is a file inside the library folder — memos 53 · 74) (memo 127). If the preset folder is separate, handing over one folder does not carry the presets with it.
- **Using an outside folder in place** (e.g. `~/.claude/skills`) — user 「외부에 두지말고 engram 안으로」 (G37).

## 영향 / 불변식
- `LibPath` has no root prefix — it does not accept `:`, so it does not mix with `engram:/` (TRD §1-2 · ADR-0315).
- There are two root management commands: `library.status` + `setRoot` (M21's addRoot · removeRoot · renameRoot reverted — G36).
- When multiple roots are reopened, start from the extension path in Decision 6, and re-examine the G25 branch (references across roots · fixing references on rename · copy only).
- Keep the reference-walk function reusable by export and import (G37) — when that feature comes, do not build a separate walk.
- The default root `<배포판>\library` is inside the distribution folder, so it is deleted together when `scripts/build-release.ps1` rebuilds the distribution — this is intended (same as `data\`). The library actually used is placed outside the distribution through 「라이브러리 폴더 바꾸기」 (R9) (G39 · user 「빌드용이 뭔가 저장될 필요가 있음? 내가 사용할건 밖으로 뺄건데」). The script is not changed.
