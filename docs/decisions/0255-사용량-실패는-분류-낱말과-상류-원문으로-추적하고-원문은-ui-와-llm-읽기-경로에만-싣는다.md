# ADR-0255: 사용량 실패는 분류 낱말과 상류 원문으로 추적하고 원문은 UI 와 LLM 읽기 경로에만 싣는다

- 상태: 확정 (2026-09-27, 근거: 사용자 결정 + TRD §7 #11)
- 관련: TRD §7 #11 · §7 #20(`Unavailable` 문구 중립화) · `base/src/logging/mod.rs`(마스커) · step-log S21

## 맥락
사용량 조회 실패를 사용자·LLM에게 어떻게 전달할지 정해야 했다 — 여러 출처의 오류 문구를 한 문자열로 섞을지, 분류하고 원문도 남길지.

## 결정
실패 추적은 **분류 낱말 + 상류 원문**이다. wire 는 비정상 상태마다 `UsageStateDetail{kind, code, upstream}`을 싣는다(agent 쪽 `ProbeFailure`·`UsageDetail`·`UpstreamText`). **원문은 UI와 LLM 읽기 경로(`usage.get` 행)에만 싣고 로그에는 보내지 않는다**(가림·200자 자름·가린 `Debug`, `ProbeError` 비밀 규칙 개정).

## 거부한 대안 (사용자)
- 분류 없이 여러 출처의 오류 문구를 한 문자열로 섞기 — 「오류 문구 원문이 있으면 보내야지 … 이상한거 다 섞어서 보내지 말고 타입은 보내야지」.

## 거부한 대안 (메인)
- 원문을 로그에도 남기기 — 로그는 공유될 수 있다.

## 거부한 대안 (내부 — §3)
- `kind`를 enum 으로 — 옛 셸 역직렬화가 깨진다(#68).
- 실패 변형마다 칸을 따로 두기(#70).

## 근거
사용자 결정 2026-09-27(「오류 문구 원문이 있으면 보내야지 … 유저가 최대한 추적할 수 있도록」) · TRD §7 #11.

## 영향 / 불변식
가림 규칙은 base 마스커가 아는 토큰 모양뿐이고(`base/src/logging/mod.rs:49`), 원문 칸은 **이름 붙은 칸 값만** 가린다. 무엇이 원문에 실리는지는 CLI 버전이 정하고 이 결정 자체는 정책 판단을 하지 않는다(PRD D3 와 같은 표지). 구현 커밋: `56776d6`, `c68b885`, `846a3e4`.
