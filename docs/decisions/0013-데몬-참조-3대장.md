# ADR-0013: The three daemon references — tmux / Zellij / Mosh

- 상태: 확정 (2026-06, selection of references for S12 daemonization preparation)
- 관련: CLAUDE.md 참조 구현 · `docs/process/S12-daemonization/` · clones: `I:\Engram_Workspace\references\`

## 맥락
When designing and implementing S12 daemonization (the server holds sessions, clients attach = the tmux model), we reference mature open source instead of writing from the ground up. There are many candidates (tmux/Zellij/Mosh/ttyd/gotty/wezterm/Screen/ET…), so we fix the priority of the first-class references.

## 결정
Fix the first-class references for daemon design at three (in reading order):
1. **tmux** — the textbook for the daemon model. Session lifetime separation · attach/detach · the control mode protocol.
2. **Zellij (Rust)** — implementation reference. Same stack, so patterns can be ported directly. Includes its own IPC · client-server · Windows I/O code.
3. **Mosh** — remote/reconnect robustness (SSP state-sync). Surviving disconnects and IP changes → preparation for the remote and mobile stages.

## 거부한 대안
- **ttyd / gotty** — PTY→WebSocket bridges. Useful for transport snippets, but shallow as a reference for the *daemon itself* (only as a secondary aid for transport).
- **wezterm mux** — already in operational use (the basis of Claude Orchestra). Not a subject for separate learning.
- **GNU Screen / Eternal Terminal / abduco·dtach** — overlap with tmux or are simpler. Little added value.

## 근거
The engram constraints = Rust + the tmux model + a remote/mobile future. tmux (the model), Zellij (the Rust implementation) and Mosh (remote robustness) cover each axis **without overlap**.

## 영향 / 불변식
- When designing anything daemon-related, consult these three first. **Borrowing = patterns, not copy-pasting code** (check licensing with legal if code is copied).
- If a reference is added or replaced, update this ADR.
