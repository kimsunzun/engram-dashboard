# ADR-0115: 에이전트 이름 유일성 — 스폰 시 동명 자동 접미사(후속 슬라이스)

- 상태: 확정 (2026-07-29, 근거: 사용자 결정 — 구현 시점 = 메시징 발송 개편(ADR-0111/0114) 완료 후 별도 슬라이스) · 부분 폐기 by ADR-0120 (유일성 검사 범위)
- 관련: ADR-0101(WYSIWYA 이름 주소 — "이름 = 유일 키" 전제를 이 ADR이 완성) · ADR-0111·0114(동명 모호가 만든 갈림길의 근본 해결) · ADR-0112(그룹 해석 — @all 동명 예외의 소멸 대상) · AgentManager 스폰 등록 지점(구현 시 `// ADR-0115` 앵커) · Amended by ADR-0120 (유일성 검사 범위)

## 맥락

메시징은 주소 지정·파킹 큐·장부·회신 계약이 전부 **이름 키**인데, 살아있는 동명 에이전트가 허용돼 모호 클래스가 존재한다: 직접 지목은 `RECIPIENT_AMBIGUOUS` 반려, @all 방송은 동명 이름 전원 미배달(ADR-0114 결정 4의 과도기 규칙). 리뷰가 @all×동명 충돌을 적출하자 사용자가 뿌리 제거를 결정했다 — 모호를 다루는 대신 모호가 생기지 않게.

## 결정

**스폰(신규 등록) 시 살아있는 로스터에 동명이 있으면 자동 접미사로 개명해 등록한다.** 표기 = `이름(1)`, `이름(2)` …. 번호는 그 이름에 대해 **관측된 최대 번호 + 1로 단조 증가**(번호 재사용 없음 — "bob(1)"이 죽어도 다음은 "bob(2)"). 구현 시점 = 메시징 발송 개편 완료 후 별도 슬라이스(사용자: "메일 끝나고 할 일").

## 거부한 대안

- **동명 스폰 거부(에러 반환)** — 같은 프로필로 워커 N마리 스폰 같은 정상 흐름을 막는다. 자동 접미사는 마찰 없이 같은 유일성을 얻는다.
- **실체(id) 병행 키 체계** — 메시징 전반(파킹·장부·계약)에 이중 키 재설계, 비용 과다(ADR-0114 거부 대안과 동일 판단).
- **현상 유지(모호를 행 실패로 명시만)** — 과도기로만 수용(ADR-0114 결정 4). 장기적으론 시스템이 에러 클래스 하나를 계속 짊어지는 것.
- **번호 재사용(빈 번호 채움)** — "bob(1)"이 죽었다 다른 개체로 부활하는 혼동. 단조 증가가 개체 연속성 오독을 차단.

## 근거

- 사용자 결정(2026-07-29): "스폰에서 같은 이름이면 (1)로 하던가 해서 동명이인 안 되게. 숫자는 가장 큰 것 있는 기준으로 계속 늘어나게. 메일 끝나고 할 일."
- 이름 유일이 성립하면: `RECIPIENT_AMBIGUOUS` 사문화 · @all 동명 예외(ADR-0114 결정 4) 소멸 · 이름 키 체계(파킹·장부·계약)가 추가 장치 없이 완전해짐.

## 영향 / 불변식

- **살아있는 로스터에서 이름 = 유일 키.** 죽은 이름의 재사용은 허용 — 파킹 이름 승계·재스폰 배달 연속성(같은 이름이 돌아오면 대기 편지를 받는다)은 유지된다.
- **epoch 교체는 개명 대상이 아니다** — restart/fresh fallback은 같은 AgentId의 맵 교체(ADR-0007)라 신규 등록이 아니다. 검사는 신규 등록에만 건다(과도기 겹침 창은 구현 때 확정).
- 접미사 카운터는 이름별 단조 증가 — 재사용 금지.
- 미검증(구현 때 확인): `(1)` 표기가 이름 문법·봉투 렌더·CLI 콤마 분해와 충돌하지 않는지.
