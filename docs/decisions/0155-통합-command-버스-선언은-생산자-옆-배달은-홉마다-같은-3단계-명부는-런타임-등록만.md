# ADR-0155: Unified command bus — declarations next to the producer, delivery in the same 3 steps at every hop, the registry filled by runtime registration only

- 상태: 확정 (2026-08-13, basis: design survey + adversarial review + user decision) · 부분 폐기 by ADR-0150 (owner token derivation)
- 관련: CLAUDE.md 「LLM-우선 제어」 · ADR-0022 (direction — status proposed) · ADR-0055 (frontend registry skeleton) · ADR-0081 (relay shape — an extension, not a reversal) · ADR-0012 (test isolation) · ADR-0003 (core isolation) · ADR-0129 (net isolation) · ADR-0035/0057 (layout authority) · ADR-0132 decision 7 · ADR-0156 (fills the discovery hole this decision left) · ADR-0154 (belatedly fills the targeting that the registry set up by this decision needs — not a reversal) · `docs/process/S20-command-bus/trd.md` · `docs/process/step-log.md:1667-1675` (user direction) · `:1649-1663` (S20.1·S20.2 record) · Amends ADR-0081 (replaces decisions 1 and 2) · Amends ADR-0022 (exhausts 3 unresolved forks) · Amended by ADR-0150 (owner token derivation)

## 맥락

The command vocabulary is split three ways and the parts do not know each other — 33 dot-separated ids on screen (`src/commands/`) · 2 groups and 8 verbs in the CLI (`crates/engram-dashboard-core/src/agent/types.rs:237`·`:246`·`:179`·`:212`) · 25 variants on the wire (`crates/engram-dashboard-protocol/src/messages.rs:25-214`). As a result **there is no unified path for an LLM to call windows, tabs and themes** (`docs/process/step-log.md:1673` ②).

The current wall is the hand-written match on 5 verbs in the daemon's agent door (HTTP `/control`) — `crates/engram-dashboard-daemon/src/control/agent.rs:222-239` (5-verb arms `:223-235`). A new verb exists only by editing this match.

**[Pointer correction 2026-08-16 — decision unchanged]** That hand-written match was **deleted in S20 Step 2 slice 3** — do not look for it by the line numbers above. That place is now a single adapter that builds the command name from `{verb}`, finds it in the table and calls it (`handle_agent` in `crates/engram-dashboard-daemon/src/control/agent.rs`). The wall this ADR aimed at has really disappeared, and the decision body is unchanged.

This decision is a concretization of ADR-0022 (a proposal that fixed only the direction) and stands on the frontend registry skeleton set up by ADR-0055. The design source of truth is `docs/process/S20-command-bus/trd.md`, and here only the **shape** that document settled is recorded.

## 결정

1. **Put the declaration and the body together as one set next to the producer module.** core = `agent.*` · daemon = `mail.*` · src-tauri = `window`/`tab`/`slot` · webview (TypeScript) = `theme`/`chat`. **No 「주인」 (owner) field is put in the declaration — where the declaration lives is the owner.**
2. **Create a tool crate `engram-dashboard-command`.** It holds only the envelope, errors, the declaration macro, the table and routing, with **zero workspace dependencies and zero commands.**
3. **Delivery is the same 3 steps at every hop** — is it in my table → is it in the registry → error. Two-stage delivery (daemon → shell → webview) follows the same rule, and **no special case is put in per hop.**
4. **Do not execute at the place of receipt (the connection task).** The inbound receiver returns at once and application runs outside it. It is a global rule that covers the shell, the daemon and the webview alike.
5. **No global auto-registration.** What auto-collection handles goes up to the name, the argument schema and the error set, and **the real handler is injected at assembly time with `make_table(deps)`.**
6. **The daemon does not put a build list into compilation** — the registry fills by runtime registration only. **No direction field is put in the envelope** (which connection it was written to is the direction), and **`name` is exposed on the outer cover** (per-command authorization and observation hang there. `args` is still opaque to the daemon).
   - ★**Amendment marker — the 「주인 토큰 산출」 (owner token derivation) of this registry was discarded by ADR-0150**★ Under this ADR the owner key was **derived from the connection id** (so a reconnect became a stranger), and now it is **an identifier the client makes by itself and sends in the first greeting** (only a connection that did not send the identifier keeps connection-id derivation — fail-open). A disconnected owner's registrations are **removed without a trace**. **This clause itself — runtime registration only — and all the rest of the decisions are valid** — the scope is authoritatively in the impact section of ADR-0150.

## 거부한 대안

- **A. Gather the declarations into the one crate `engram-dashboard-protocol`** — discarded by the user's remark 「생산자와 사용자가 명확히 분리돼야 한다」 (producer and user must be clearly separated) (`.claude/handoff/history/20260813-140452-command-bus-설계-방향-확정.md:53`). `protocol` is a **wire contract**, so it is not the home owner of the command vocabulary. As a side effect, for `core` to declare `agent.*` it would also see wire types — the tool crate (decision 2) blocks that inflow.
- **B. Put an `#[owner(...)]` field in the declaration** — the definition location is the owner, so it is **duplication** (`docs/process/step-log.md:1669`, user remark 2026-08-12). It is a proposal the user had withdrawn twice, and it revived because the premise (A's centralization) required it. What had to be fixed was not the field but the premise.
- **C. The daemon holds the full build list and checks it against the registry** — both are fatal. ㉠ **Coupling:** the daemon would statically know shell and screen names such as `tab.create` and `theme.set`, and the coupling A tried to avoid comes in through another door. ㉡ **False availability:** it answers "that command exists" even when the app is off. Only if the registry fills by runtime registration alone does 「지금 부를 수 있는가」 (can it be called now) become a fact. **The cost is a symmetric inaccuracy** — a name whose owner the daemon has **never once seen** goes out as `UNKNOWN_COMMAND` (the case where only the daemon is turned on and the app was never launched). That is, this decision did not remove the inaccuracy but avoided the coupling by **moving from false positive to false negative**, and since the side that created the prohibition is here, its cost is written here.
- **D. Embed the real handler in a global auto-registration table** — **tests lose the place to plug in a fake manager.** A unit test meant to assert `agent.spawn` alone drags in a real `AgentManager` and **launches a real process.** It is a direct violation of ADR-0012 「외부 의존을 seam으로 끊는다」 (cut external dependencies at a seam).
- **E. For webview commands put only the declaration in Rust and the body in TypeScript** (old edition, a C++-header-style split) — the sole basis of this option was 「화면 전용 명령은 Rust 모듈이 없어 목록에서 빠진다」 (screen-only commands have no Rust module and drop off the list) (the latter sentence of `docs/process/step-log.md:1669`), but **runtime registration (decision 6) filled that hole and made it unnecessary.**
- **F. Add a direction field to the envelope** — the same envelope would have two truths (the field value / the real connection), and the moment they diverge, routing splits.
- **G. 2-step routing (run it if it is in my table, otherwise send it)** — it has **the premise that there is only one place to send** baked in, so it breaks when there are two hops. The 3 steps are the same at every hop with no special case, so even when a new owner attaches, what grows is one registration, not delivery code.

## 근거

**Measured in code (2026-08-13).** `crates/engram-dashboard-core/Cargo.toml` and `crates/engram-dashboard-protocol/Cargo.toml` both have zero `path =` lines (zero workspace dependencies) · 33 frontend registered commands (31 `register(` hits in `src/commands/*Commands.ts` + `registerSplit` (`slotCommands.ts:35`) called twice at `:48-49`) · **zero daemon → shell inbound** (the `Message::Text` handling at `src-tauri/src/daemon_client/connection.rs:805` decodes only as `AgentEvent`) · zero `.rs` hits for the relay symbols (`RegisterRole`/`RelayUi`/`UiCommand`/`UiResult`).

**Status of the design survey — it is not a rejection basis for this ADR.** The precedent survey (`docs/research/unified-command-bus-survey-2026-08-12.md`) received a **BLOCK verdict** in the other-family adversarial review after six deep branches, and six rebuttals were corrected and applied. Because the report itself forbade using it as a rejection basis before its open items were closed, **the alternatives above were rejected not by the survey but by our own structure** — caller count (three or more places where discovery and merging would have to be duplicated) · hop uniformity · test isolation.

**In re-verifying 23 `file:line` items at the TRD revision, 7 drifts were found and fixed** (5 off-by-one cases that cited an attribute line as a function line, etc.). The pointers in this ADR are the values after that re-verification.

## 영향 / 불변식

- **The workspace dependencies of `core` go from 0 → 1** (one tool crate). **There is no CI gate today that keeps this number** — since it changes quietly, the fact that 「코어는 아무것도 안 본다」 (core sees nothing) is relaxed into 「코어는 도구 하나만 본다」 (core sees only one tool) is left here.
- **The new crate name must be added to the regex of the messaging-kernel isolation gate** (`.github/workflows/ci.yml:252`, currently `engram_dashboard_(core|daemon|protocol|discovery)`). Messaging has no dependency-ceiling gate like net's, so **the regex is the only wall**, and if it is left out the ADR-0110 invariant is left undefended.
- **The two net gates do not change** — the core symbol allowlist of exactly 2 lines (`ci.yml:276-293`) and the direct workspace dependencies of exactly 3 lines (`ci.yml:300-317`). One line of reason: **this design adds no concept to the network layer** (the ADR-0129 layer separation as it is).
- **The generated-output sync gate needs to be extended** — the only path `.github/workflows/ci.yml:124-131` watches is `crates/engram-dashboard-protocol/bindings/`, so nobody watches the new `core/bindings/` and the existing `src-tauri/bindings/`.
- **Hard constraint:** if `static`/`lazy_static`/linker collection holds an `Arc<dyn CommandHandler>`, it is a **violation**. What it may hold goes up to `CommandSpec` (name, schema, errors). Watcher = the `make_table` injection harness (asserts a handler with fake dependencies, without a process).
- **Moving a name to another crate is not additive** — since the declaration location is the owner, **moving house is an owner swap** and the registry is restructured. If it must move, **declare under the new name and deprecate the old name**.
- **★The stamps on the two old ADRs are labels, and the authoritative source for what dies and what lives is here.★** The status-line stamp is carried as is into the index table cell so it must be short, so the reasons are placed in this spot.
  - **ADR-0081 = only decisions 1 and 2 are replaced.** Live clauses: **preserving the single `request_id` round trip** · **the connection cleanup sweep and the lifetime bound of the routing table** · **dedup is committed only after application** · **keeping the daemon opaque** · **the UI vocabulary compile guard**. What was replaced is only `RegisterRole{UiApp}` of decision 1 and the 3-variant opaque relay envelope `RelayUi`/`UiCommand`/`UiResult` of decision 2, and that place is taken by the registration wire `RegisterCommands`/`UpdateCommands`/`ListCommands` + the owner-token registry and the unified command envelope. **Do not read all of 0081 as dead from the stamp alone.**
  - **ADR-0022 = the direction is valid.** This ADR and ADR-0156 stand on the decision of a single-source command registry, and what was exhausted is only the **three branches** that ADR left as 「미해결」 (unresolved) (registry location · LLM discovery path · backend mirror) — the body of that section is history, so do not read it as an open fork.
- **This decision creates the backend mirror that ADR-0055 「지금은 거부」 (rejected for now)** — the daemon registry is that mirror. Because 0055 itself **put a time limit on and deferred** it, through the decision 「레지스트리 위치 = 프론트 단독 … 백엔드 미러 = 후속」 (registry location = frontend alone … backend mirror = follow-up) and the rejected alternative 「백엔드 미러 레지스트리(**지금**)」 (backend mirror registry (**now**)), this is not a discard but **the realization of that follow-up**. So no discard stamp is put on 0055 — this repository has two precedents of not stamping a 「구체화」 (concretization) (0002↔0030 · 0022↔0055).
- **No discard stamp is needed** on the 「Opaque 결합 가드」 of ADR-0081. What the guard forbids is importing UI types, and what the daemon knows is only name strings, and even those it receives by runtime registration — the UI types that go into compilation are zero.
