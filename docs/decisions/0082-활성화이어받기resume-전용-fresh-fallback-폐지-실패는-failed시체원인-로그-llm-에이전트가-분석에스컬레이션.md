# ADR-0082: Activation = resume only — fresh-fallback discarded, failure is Failed (a corpse) + a cause log, the LLM agent analyzes and escalates

- 상태: 확정 (2026-07-14, basis: user measurement that re-activating an agent that was running normally → both terminal and JSON end up Failed + an empty slot, + the a4aac1a chain confirmed from code/git) · 부분 폐기 by ADR-0185 (the sid issuance clause among the surviving parent decisions) · 부분 폐기 by ADR-0201 (the means of finding out that a resume failed) · 부분 폐기 by ADR-0226 (a resume request without a handle in the first item of the decision, and the Fresh verb name in the consequences)
- 관련: Supersedes ADR-0077 · Amends ADR-0008 (the clause "early resume exit → fresh-fallback" discarded) · Amends ADR-0076 (the fallback_fresh-related invariants and the wording "fresh-fallback is valid" discarded) · `agent/manager.rs::activate_profile`/`resume_with_fresh_fallback`/`fallback_fresh` · `daemon/connection_core.rs::SpawnProfile` · CLAUDE.md §5(LLM-우선 제어) · step-log · Amended by ADR-0185 (the sid issuance clause among the surviving parent decisions) · Amended by ADR-0201 (the means of finding out that a resume failed) · Amended by ADR-0226 (a resume request without a handle in the first item of the decision, and the Fresh verb name in the consequences)

> ★**The "Failed" in the title is everyday language — it is not `AgentStatus::Failed`**★ (note 2026-08-25, decision unchanged). The decision below says "failure ends as a **terminal**" and pins that path down as "the resume child exits on its own (mostly exit code≠0)" — that maps to **`Exited{code}`**. `AgentStatus::Failed` is reserved for `TerminalReason::Error`, and **the only producers published to the StatusSink are the two pump panic sites** (`transport/pty.rs`, `transport/stdio.rs`). ★It is not true that "there are only two in the whole code"★ — inside `manager.rs::early_activation_verdict` there is one more local value `AgentStatus::Failed{message:"session gone"}`, and it happens to be inside the very resume path this section talks about. However, that value never reaches the sink and is used only in a log message and a `matches!` decision, so it does not go out to the screen or the frontend (measured 2026-08-25). Descriptions that read this title as the enum had spread to CLAUDE.md and the ADR index and were fixed together on the same day. **The title and the file name are history, so they are kept.**

## 맥락
The user reverses the **fresh-fallback** confirmed by ADR-0008/0076/0077 (when a resume fails or exits early, automatically start an empty new conversation with a new sid).

Two layers of problems surfaced.
1. **Regression (a4aac1a, ADR-0077):** when the fresh-fallback was extended to the manual activation path (`activate_profile` → `resume_with_fresh_fallback`), **re-activating an agent that is running normally (with a conversation)** made the "already running" Err returned by the double-spawn guard of `spawn_agent` be **mistaken for a "resume failure"** → `fallback_fresh` **killed the agent that was running fine** → epoch++ → replaced it with an empty fresh. Result: both terminal and JSON agents end up `Failed` + an empty-screen slot (user-measured screenshot).
2. **The policy itself:** even if only the re-activation regression were fixed locally, the fundamental behavior remains in which "on a resume failure the system destroys the conversation without the user knowing and replaces it with an empty new conversation". This (a) loses the conversation context, (b) hides the failure cause behind the automatic recovery and blocks diagnosis, and (c) conflicts with CLAUDE.md §5 (the LLM is the main operator — expose the cause so that the LLM decides).

## 결정
- **Activation (activate) = resume only.** Even if the session to resume has failed/exited early/been deleted/been corrupted, the system **does not create a new conversation (fresh) on its own.**
- **Failure ends as a terminal and the profile is preserved as a corpse.** Nothing is killed and nothing is newly created. The resume child exits on its own (mostly claude exiting with exit code≠0 on "No conversation found") and the reaper collects that session from the map, but **the profile is not deleted; it is lowered to `auto_restore=false` and preserved as a corpse** (it stays stopped until the user acts). **The visual display of the corpse (whether to show a separate "죽음" ("death") marker vs leave it as the current reserved node) will be decided later by the user after seeing the real thing — this ADR fixes only up to "do not kill, do not create anew, preserve the profile, cause log" and leaves the display method open.**
- **Leave the failure cause in the log** — record clearly in the log the reason claude exited (e.g. "No conversation found with session ID …") and the early-exit detection.
- **The control LLM agent analyzes that log and escalates to the user** (§5 — the LLM is the main operator, the human is auxiliary). Whether to recreate is decided **manually by the user** (delete the corpse + recreate).
- **Re-activating a live agent → kill nothing and leave it be** (only an already-running signal). Restores the harmless pre-a4aac1a behavior.
- **The first start of a truly new agent (Fresh) is kept** — the user explicitly starting a new profile that has nothing to resume is a normal creation, not a fallback (ADR-0076 "Fresh = new sid" remains valid). What is removed is only the fallback that **"automatically replaces a resume failure with fresh"**.

## 거부한 대안
- **Automatic fresh-fallback (ADR-0008/0076/0077 — discarded by this ADR)** — on a resume failure, automatically start fresh with a new sid. Rejected: (1) it replaces a live/existing conversation with an empty new conversation without the user knowing, losing the conversation context (2) the failure cause is buried behind the automatic recovery, making diagnosis impossible (3) a4aac1a extended it to manual activation and caused a regression that destroys a live agent. The user: **"Nothing must die. Even if the session blows up, do not create a new one. Rather than creating a new one, delete and recreate. Leave it as a corpse at least."**
- **Excluding only the double-spawn guard Err from the fresh-fallback (a local fix)** — blocks only the re-activation regression and keeps the fresh-fallback. Rejected: the fundamental policy of "handling a resume failure by an automatic overwrite" remains, so activating an empty/corrupted session is still replaced with fresh without the user knowing. The user decision is the **discarding of the fresh-fallback itself** (not a regression patch but a policy reversal).
- **Detect an empty session before spawn and handle it** — read the claude session store beforehand and decide "a conversation exists/does not". ADR-0077 already rejected it (coupling to claude's internal format, violating backend knowledge isolation ADR-0004). The reactive way (the early-exit signal of the resume child) is robust — but that signal is now translated not into a fresh-fallback but into **Failed + log + escalation**.

## 근거
- **User measurement (screenshot):** re-activating a terminal and a JSON agent that were running normally gives both Failed + an empty slot. The a4aac1a chain confirmed by code + git (guard Err → mistaken in `resume_with_fresh_fallback` → `fallback_fresh` kills the live agent → epoch++ → empty fresh). The entry is deterministic (guard Err → always fallback_fresh → always kills the live agent), and only whether the final result is Failed is nondeterministic, depending on whether the fresh survives.
- **The user's original plan (previous session):** "Activation is resume only, report the failure cause in the log, and have the agent analyze it and escalate to the user." This corrects that ADR-0076/0077 confirmed the fresh-fallback in conflict with this original plan.
- **§5 consistency:** the system does not hide or automatically recover from failure and exposes the cause in the log → the LLM (the brain) decides → escalation to the user. It is one body with the "hands/brain separation" mental model.

## 영향 / 불변식
- **The fresh-fallback path is removed/neutralized** — the "failure → respawn fresh with a new sid" of `resume_with_fresh_fallback` and `fallback_fresh` is taken out. A resume failure/early exit goes **straight to a terminal (mostly Exited code≠0)** (no automatic fresh respawn), and the profile is preserved as a corpse (reaper `KeepDisableAutoRestore`).
- **Re-activation guard** — when the `activate_profile`/`SpawnProfile` handler re-activates a session that is already running (`sessions.contains_key(id)`), it **leaves it as is with no kill/respawn** (an already-running signal). The double-spawn guard Err is not a destruction trigger.
- **The failure cause log = a control surface input** — leave the resume failure reason in the log so that the LLM agent reads it and escalates. Swallowing the cause (the old fresh-fallback) violates §5.
- **The new first start (Fresh) preserved** — an explicit new creation that issues a new sid with `new_session_id` remains valid (ADR-0076). This is not a fallback.
- **The surviving parent decisions** — ADR-0008 sid control (`--session-id`/`--resume` lossless restore), ADR-0076 activation=resume, Fresh=new sid, the single sid-issuing point (`spawn_agent`) remain valid. On top of them, this ADR takes out **only "automatic fresh replacement on failure"**.
- Anchors: `// ADR-0082` (manager.rs `activate_profile` and the resume failure handling, connection_core.rs the `SpawnProfile` re-activation guard).
- **Regression tests (mandatory):** ① re-activating an already running agent does not kill or respawn the original agent (epoch unchanged + spawn count unchanged) ② on a resume failure it stays as a terminal (profile corpse preserved, `auto_restore=false`) and no new conversation (fresh) is created (spawn exactly once).
- **Known edges and open items (the user's later decision):** ① the visual display of the corpse (a separate "죽음" ("death") marker vs the current reserved node) is undecided — the user decides after seeing the real thing. ② if claude exits early with exit code 0, the profile is deleted under the reaper's existing disposition policy and no corpse remains (the documented "No conversation found" is code 1 so it is preserved — the code-0 subcase is a remaining gap). ③ the cross-connection TOCTOU of the re-activation guard (double spawn on concurrent activation) is an existing race from HEAD — outside this ADR's scope, a follow-up task.
