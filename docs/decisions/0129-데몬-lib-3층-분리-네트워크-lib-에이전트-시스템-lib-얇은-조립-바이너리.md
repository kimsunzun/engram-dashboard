# ADR-0129: 데몬 lib 3층 분리 — 네트워크 lib · 에이전트 시스템 lib · 얇은 조립 바이너리

- 상태: 확정 (2026-08-04, 근거: 사용자 문제제기 + 운영 코드 전수 실측 + ADR-0020 경계 부식 이력)
- 관련: ADR-0020(Stage 1 — `ConnectionCore` carrier-중립 추출. 이 결정이 그 의도를 crate 경계로 승격) · ADR-0110(메시징 커널 crate 분리 — 같은 idiom: 컴파일러 강제 벽) · ADR-0029(에이전트 호스트 = 데몬 프로세스 — **부활 아님**, 아래 영향 절) · ADR-0028(이벤트버스 single-push) · ADR-0127(선행 슬라이스 — 부착 기계 철거로 분리 대상 −592줄) · `crates/engram-dashboard-daemon/src/ws.rs` · `connection_core.rs` · `control/` · `messaging_host.rs` · step-log S18.16

## 맥락

사용자 문제제기(2026-08-03): *"데몬은 프로토콜을 옮기기만 하는 중계기여야 하고 다른 시스템에서 재활용돼야 하는데, 언제부터인가 데몬 = 백엔드 전체가 됐다."*

실측이 이를 확인했다. 운영 빌드 **11,729줄**의 분해(실험·하네스 7,142줄은 이미 `test-harness` 기능 게이트 뒤라 제외):

| 프로세스 살림 | 조립 | WS 서버 | `ConnectionCore` | 제어 평면 | 메시징 접합 |
|---:|---:|---:|---:|---:|---:|
| 368 | 1,011 | 2,287 | 2,509 | 4,800 | 754 |

**네트워크 살림은 일부이고 나머지는 전부 에이전트 어휘다.** 그래서 "네트워크만 필요한 다른 시스템"이 이 crate를 재사용하려면 제어 평면·메시징까지 통째로 끌고 와야 한다.

## 결정

1. **데몬 lib = 네트워크만.** 소켓 수락 · Origin 허용목록 · 인증 핸드셰이크 · 연결 수명 · 연결당 단일 writer · 종료 신호 · 연결 레지스트리(팬아웃) · portfile · 단일 인스턴스. 위로 뚫린 구멍은 **하나뿐** — **불투명 프레임**을 받아 올리고, 이 연결로 내보낸다. **에이전트 어휘를 타입으로도 모른다.**
   > **note (2026-08-04 · 슬라이스 0-1 실측 · 사용자 승인):** 불투명 프레임 구멍은 **두 모양**을 갖는다 — **연결당**(`frame_port::FrameSink`)과 **전-연결 팬아웃**(`ConnRegistry::broadcast_text` 경로). 위 "하나뿐"은 *어휘 격리가 한 종류(불투명 프레임)로 끝난다*는 뜻이고, **표면이 하나라는 뜻이 아니다** — 원문이 "이 연결로 내보낸다"로 연결당 기준으로 쓰여 전-연결 팬아웃이 그 문장에 안 들어맞는다. 팬아웃도 포트여야 결정이 성립한다(연결당 경로만 포팅하면 미충족). 결정의 목표 모양·불변식은 불변이라 폐기(supersede) 아님 — 서술 보완이다. 팬아웃 포트는 상태 통지·메시징 flush sink가 `AgentManager` 조립 시점에 주입되고 레지스트리를 공유하므로 **결정 3(얇은 조립)에서 배선**된다.
2. **에이전트 시스템 lib.** `ConnectionCore`(프로토콜 디코드·디스패치) · `AgentManager` 호스팅 · 제어 평면(MCP·ingress·프라이밍) · 메시징 접합.
3. **실행 바이너리 = 얇은 조립.** 둘을 엮기만 한다.

## 거부한 대안

- **현상 유지(데몬 = 백엔드 전체)** — 사용자 문제제기 자체가 기각 사유다. 재사용이 불가능하고, 네트워크 계층만 필요한 소비자가 에이전트 어휘 전부를 의존으로 진다.
- **crate를 나누지 않고 모듈 규율·리뷰로 경계를 유지** — **역사가 이미 반증했다.** ADR-0020 Stage 1이 정확히 그 방식을 택해 `ws.rs`에서 `ConnectionCore`를 carrier-중립 모듈로 뽑았고, 그 파일 헤더는 **지금도** "TcpStream/tungstenite/코덱을 모른다"고 선언한다. 그런데 그 사이 제어 평면과 메시징 접합이 같은 crate로 흘러들었다. 작업마다 코더 세션이 갈리는 이 코드베이스에서 **문서·리뷰로만 지킨 경계는 세션 교체를 못 견딘다** — ADR-0110이 메시징 커널에서 도달한 것과 같은 결론이고, 그때와 같은 처방(**컴파일러가 강제하는 벽**)을 쓴다.
- **2층(데몬 lib + 나머지 전부)** — 조립 책임을 어느 한쪽 lib이 떠안게 되고, 그 lib이 다시 "전부를 아는 자리"가 된다. 지금 문제를 이름만 바꿔 옮기는 셈이다. **얇은 조립 바이너리를 따로 두어야** 두 lib이 서로를 모르는 상태로 남는다.

## 근거

- **경계 의도가 이미 코드에 있다.** ADR-0020 Stage 1의 `ConnectionCore`는 carrier-중립으로 설계돼 있고 그 선언이 파일 헤더에 살아 있다. 이 결정은 새 설계를 발명하는 게 아니라 **이미 있는 경계를 crate로 승격**하는 것이다 — 그래서 설계 리스크가 낮다.
- **인증은 걸림돌이 아니다.** 지금 `AgentCommand::Auth`로 에이전트 명령 목록에 끼어 있을 뿐이고, 데몬 소유 핸드셰이크 타입으로 옮기면 된다. **wire JSON 모양만 유지하면 프론트는 무변경**이다(타입이 어느 crate에 사는지는 프론트가 모른다). 그래서 "데몬 lib이 프로토콜 crate에 의존하지 않는다"가 사실상 공짜로 성립한다.
   > **note (2026-08-05 · 슬라이스 1 실측 · 사용자 승인):** 이 항목의 마지막 문장 — *그래서 "데몬 lib이 프로토콜 crate에 의존하지 않는다"가 사실상 공짜로 성립한다.* — 은 **지금 거짓이다**(원문은 고치지 않고 여기서 정정한다). 네트워크 lib(`engram-dashboard-net`)의 `protocol` 의존은 **영구**다: `crates/engram-dashboard-net/src/portfile.rs` 가 daemon.json 의 공유 구조체 `DaemonInfo` 를 protocol 에서 re-export 하고, 그 구조체는 데몬이 write·클라이언트가 read 하는 두 프로세스 계약이라 어느 한쪽 crate 안으로 옮길 수 없다. **0-4 이월분과 구분할 것** — `ws.rs` 의 `AgentCommand::Auth`/`PROTOCOL_VERSION` 간선은 0-4(인증 타입 이사)가 끝나면 사라지지만 `portfile`↔`DaemonInfo` 간선은 그 뒤에도 남는다. 즉 "프로토콜 무의존" 은 이 결정의 부수 이득이 아니었다. 목표 모양·불변식은 불변이라 폐기(supersede) 아님 — 사실 정정이다.
- **선행 슬라이스가 대상을 줄여 뒀다.** ADR-0127로 턴 관측 부착 기계가 철거되며 `ws.rs`가 −592줄 됐다 — 분리 대상이 그만큼 작아진 뒤에 착수한다.

## 영향 / 불변식

- **불변식:** 데몬 lib에 **에이전트 어휘 타입이 등장하면 이 결정 위반**이다. 격리 게이트는 메시징 커널(ADR-0110)과 같은 형태로 건다 — 금지 import grep 0줄. 컴파일러가 먼저 잡고, grep이 주석·테스트 헬퍼 이름으로 새는 경로를 잡는다.
   > **note (2026-08-05 · 슬라이스 1 실측 · 사용자 승인):** 위 "금지 import grep 0줄" 은 실제로 건 게이트와 다르다 — 슬라이스 1 은 **다중 게이트**를 걸었고 그중 하나는 기대값이 0이 아닌 **allowlist** 다. *왜:* 이 결정의 불변식은 crate 단위가 아니라 **타입 단위**(에이전트 *어휘*)다. `portfile` 은 정당하게 `protocol::DaemonInfo` 와 core 의 프로세스 liveness 헬퍼 둘(`agent::platform::pid_alive_with_start_time`·`current_process_start_time`)을 필요로 하는데 셋 다 에이전트 어휘가 아니다 — 같은 이유로 `discovery` crate 가 이미 `core` 에 의존한다(선례). 그래서 core 간선은 금지가 아니라 **심볼 allowlist** 로 묶었다. *실제 게이트 3종(정본 = `crates/engram-dashboard-net/src/lib.rs` 헤더):* ① `src/` 에 daemon·messaging·discovery 이름 참조 0줄 ② `src/` 의 core 참조를 위 심볼 둘로 고정하는 allowlist ③ **해석된 의존 그래프**에서 이 crate 의 워크스페이스 의존을 protocol·core 로 고정(`cargo tree` 기반 — 매니페스트 텍스트가 아니라 패키지 identity 를 보므로 table 형·들여쓰기·rename 우회에 견딘다). *★알려진 공백(리뷰 2인 공동 적출 — 이번 슬라이스에서 닫지 않았다)★:* **`protocol` 심볼 사용을 묶는 게이트가 없다.** 그래서 허용된 protocol 간선을 타고 에이전트 어휘가 늘어나도 어느 게이트도 울리지 않는다. 0-4 가 인증 타입을 옮기고 나면 그 간선에 남는 정당한 용도는 `DaemonInfo` 하나이므로 allowlist 게이트를 하나 더 거는 것이 자연스러운 후속이지만, 게이트 추가는 범위 확장이라 별 결정으로 미룬다 — 이 note 가 그 근거 기록이다. 아울러 코드 두 곳(`net/Cargo.toml`·`net/src/lib.rs`)이 "격리는 crate 단위가 아니라 타입 단위" 를 이 ADR 에 귀속시키는데 그 귀속은 이 note 로 정당해진다. 목표 모양·불변식은 불변이라 폐기(supersede) 아님 — 게이트 구현 서술 보완이다.
   > **note (2026-08-05 · 0-4 완료 + feature 경계 실측 · 사용자 승인):** 바로 위 note 의 두 문장이 0-4(커밋 `818cc0c`)로 거짓이 됐다 — 원문은 고치지 않고 여기서 정정한다. ① *"실제 게이트 3종"* — 0-4 가 **게이트 4**(`rg "(A)gentCommand|(P)ROTOCOL_VERSION" crates/engram-dashboard-net/src/` → **0줄**)를 더했다. 개수를 새 숫자로 갈아 끼우지 않는다(새 숫자는 같은 속도로 다시 썩는다 — step-log S18.22) — **게이트 목록의 정본은 `crates/engram-dashboard-net/src/lib.rs` 헤더**이고, 위 note 의 "3종" 은 그 포인터로만 읽을 것. ② *"허용된 protocol 간선을 타고 에이전트 어휘가 늘어나도 어느 게이트도 울리지 않는다"* — 이제 **부분만 참**이다. 게이트 4 가 `AgentCommand`·`PROTOCOL_VERSION` **그 두 이름에는** 운다(부분 문자열까지 — 의도, 근거는 lib.rs 헤더). 그 밖의 `protocol::` 심볼을 묶는 **일반 allowlist 는 여전히 없고**, 위 note 가 기록한 유예는 그 나머지 전부에 대해 그대로 살아 있다. ★경계를 흐리지 말 것★ — 게이트 4 를 일반 allowlist 로 키우는 것은 별 결정이다(0-4 범위 밖). ③ **긴장을 숨기지 않는다:** 위 note 는 "게이트 추가는 범위 확장이라 별 결정으로 미룬다" 고 적었는데 0-4 가 좁은 것을 하나 걸었다. 그 게이트가 무는 범위는 **0-4 가 제거한 두 이름**뿐 — 이 작업항목 자신의 회귀 가드지 유예된 일반 allowlist 가 아니다. 아울러 `lib.rs` 헤더가 `ADR-0129 Note A` 로 가리키는 알려진 공백 = 위 note 의 ★알려진 공백★ 절이다(라벨 자체는 이 ADR 에 없다).
   >
   > **0-4 완료 — 결정 1 의 "에이전트 어휘를 타입으로도 모른다" 가 이제 성립한다.** 핸드셰이크 프레임의 모양은 `crates/engram-dashboard-net/src/auth.rs` 가 소유하고, 기대 프로토콜 버전은 import 가 아니라 `ws::handle_connection` 이 **값으로 주입**받는다. **wire 바이트는 움직이지 않았다** — 옛 타입과 새 타입을 한 바이너리에 링크해 직렬화 출력을 대조(차이 0)했고, 프론트가 손조립하는 JSON 의 실제 바이트가 동일하며 진짜 데몬에 인증을 통과함을 실측했다(상세 = 커밋 `818cc0c`). ★§근거 의 2026-08-05 note 와 충돌하지 않는다★: 사라진 것은 `ws.rs` 의 어휘 간선이고, `portfile` ↔ `DaemonInfo` 의 `net → protocol` 간선은 그 note 가 적은 대로 **영구**다.

   > **`auth` 모듈이 Cargo feature 경계 뒤로 갔다(사용자 결정 2026-08-05).** `engram-dashboard-net` 에 `server` feature(기본 OFF, `default = []`)를 두어 서버 살림과 async 런타임을 그 뒤로 넣고 `auth` 는 게이트하지 않는다 — 무엇이 그 뒤에 들어갔는지의 정본은 `crates/engram-dashboard-net/Cargo.toml` 의 `[features]` 주석이다(여기서 다시 세지 말 것). `discovery` 와 `src-tauri` 는 플래그 없이 그대로 의존을 선언하고(빈 기본값이라 `auth` 만 받는다), **`daemon`** 이 `features = ["server"]` 로 명시 옵트인한다. *왜 기본을 비웠나:* `server` 가 기본 ON 이면 흔히 쓰는 의존 선언 형태(`{ path = … }`)가 async 런타임을 조용히 끌고 들어오고 소비자마다 옵트아웃을 기억해야 하는데 — 그게 지금 고치는 결함이 생긴 경위 그대로다. 빈 기본값에서는 서버 행이 필요한 소비자가 잊으면 컴파일 에러로 드러난다 — 조용한 회귀 대신 시끄러운 실패다. *왜 필요했나:* 인증 타입이 `net` 으로 오면서 `discovery` 가 **WS 서버 crate 를 의존**하게 됐고 async 런타임이 그 해석 트리로 딸려 들어와, "동기라 async 런타임을 안 들인다" 는 `discovery` 의 명시된 설계 성질이 조용히 거짓이 됐다. *실측:* `cargo tree -p engram-dashboard-discovery -e normal --prefix none --target all` 의 normal 폐포가 **122 → 110** 이 되고, 같은 명령을 `rg -i "^(tokio|mio|tokio-tungstenite|futures-util) "` 로 거르면 **0줄**이다(게이트 명령의 정본 = `crates/engram-dashboard-discovery/Cargo.toml` 주석. 비공허 확인 = `--features engram-dashboard-net/server` 를 붙이면 그 넷이 그대로 돌아온다). ★이득의 범위를 넘겨 읽지 말 것★: Cargo 의 feature 합집합은 **호출 1회 단위**라 워크스페이스 통짜 빌드는 데몬이 `server` 를 켜므로 여전히 그 조합으로 빌드된다 — 얻는 것은 `discovery` **단독** 빌드/소비가 가벼워지는 것과 위 설계 성질이 참으로 유지되는 것이다. `src-tauri` 도 같이 껐지만 **그쪽 트리는 줄지 않는다**(async 런타임을 자기 몫으로 이미 선언) — 의도 표시지 측정된 이득이 아니다. *기록된 대안과의 관계(관찰이지 번복 아님):* step-log S18.20 이 기각한 **작은 전용 핸드셰이크 crate** 의 대가 중 하나가 영구 워크스페이스 멤버 추가였는데, feature 경계는 그 대가 없이 비슷한 분리에 닿는다 — 기각 결정 자체는 그대로다. *게이트 3 은 영향 없음:* `--all-features` 로 읽으므로 optional 로 바뀐 간선이 그대로 드러나고 기대값은 **정확히 3줄** 그대로다(재실측 완료). 목표 모양·불변식은 불변이라 폐기(supersede) 아님 — 사실 정정 + 경계 기록이다.
- **프론트·wire 계약 무변경이 전제다.** 인증 타입 이사는 **wire JSON 모양 보존 조건에서만** 공짜다. 변경이 필요해지는 순간 멈추고 재론한다 — 프론트를 건드리는 순간 이 결정의 비용 계산이 달라진다.
