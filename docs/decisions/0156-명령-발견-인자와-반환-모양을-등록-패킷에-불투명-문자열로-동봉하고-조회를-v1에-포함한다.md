# ADR-0156: Command discovery — bundle the argument and return shapes into the registration packet as an opaque string, and include lookup in v1

- 상태: 확정 (2026-08-13, basis: user decision 2026-08-13) · 부분 폐기 by ADR-0150 (keeping a trace of a disconnected name) · 부분 폐기 by ADR-0169 (the two chat reads cited as the basis for tearing down the side doors) · 부분 폐기 by ADR-0308 (decision 1 and the hard constraint in the basis forbidding the daemon from parsing (exception: the agent reference field))
- 관련: CLAUDE.md 「LLM-우선 제어」 · ADR-0155 (the decision that created the hole this decision fills) · ADR-0081 (keep the daemon opaque · UI vocabulary compile guard) · `docs/process/S20-command-bus/trd.md` §2-4·§3-7·§4-②·§8 · `.claude/handoff/history/20260813-142447-command-bus-trd-개정-완료.md:9-24`·`:87` · Amended by ADR-0150 (keeping a trace of a disconnected name) · Amended by ADR-0169 (the two chat reads cited as the basis for tearing down the side doors) · Amended by ADR-0308 (decision 1 and the hard constraint in the basis forbidding the daemon from parsing (exception: the agent reference field))

## 맥락

As a result of ADR-0155 scattering declarations next to producers, **the path for an LLM to get the 「인자 모양」 (argument shape) of shell- and webview-owned commands disappeared.** Three paths were blocked at the same time.

- The registration packet carries **only names** → the daemon registry has no schema.
- Webview commands are TypeScript declarations, so they are **not in the Rust derivatives at all.**
- The `engram` CLI **cannot put UI vocabulary into compilation** under the ADR-0081 guard.

This is a problem the old edition (the option of gathering declarations in one crate) did not have, and it is **the price the revision paid.** It is not a reason to reverse the direction, but if it is not filled, the goal 「LLM이 창·탭을 부른다」 (the LLM calls windows and tabs) (CLAUDE.md 「LLM-우선 제어」) does not hold.

## 결정

1. **The registration packet carries `help` along with the name.** `help` = **one opaque string slot** holding the argument and return shapes. **The daemon only stores and relays it and does no parsing, validation or branching.** The macro fills Rust declarations automatically, and TypeScript declarations get one hand-written line.
2. **Include value reading (lookup) in the v1 command list** — it overturns the default of TRD §8 assumption B. `help` tells 「무슨 키를 넣나」 (what key to put in) but **does not tell 「지금 값이 뭔가」 (what the value is now).** Without lookup the LLM would have to close a tab without even knowing which tabs exist, so control would be half.
3. **Put no expiry on the name of a disconnected owner** — leave it as a tombstone while the daemon lives, and overwrite it with last-wins on re-registration.
   - ★**Amendment marker — this clause was discarded by ADR-0150**★ Now **when the connection drops, that owner's registrations are removed without a trace.** Because the premise that had justified leaving traces, 「재등록 시 last-wins로 덮인다」 (it is overwritten by last-wins on re-registration), did not hold (the owner key was derived from the connection id, so a reconnect was not overwriting but **piling up**). **Decisions 1 and 2 and the hard constraint below are valid** — the scope is authoritatively in the impact section of ADR-0150.

## 거부한 대안

- **A. A `command.describe` round trip — ask the owner when needed.** ㉠ **The discovery path itself becomes able to fail** — failure modes of a new command, two-stage delivery, timeout and owner absence arise in the discovery layer, and then the LLM cannot even get `help`. ㉡ **The cost structure is bad** — registration is once at attach + deltas, but lookup is every time. ㉢ **If the app is off there is no one to ask, so only the name comes out.** With bundling it answers even 「있던 명령, 지금 못 부름, 모양은 이것」 (a command that existed, cannot be called now, the shape is this). ★Strength of the rejection basis = **weak** (descriptive, not quantitative or measured)★ — so the main agent did not settle it and put the two options up as choices, and **the user chose bundling (2026-08-13).**
- **B. Exclude value reading from v1** (the default of TRD §8 assumption B) — it was a default set up on the single principle of **reversibility**: 「나중에 넣는 건 안 깨지고 뺐다 넣는 건 계약 파괴」 (adding later does not break, taking out and putting back is a contract break). **Overturned by user decision:** without knowing the current state one cannot control.
- **C. Put a time expiry (TTL) on the trace** — **a different error goes out depending on timing** for the same question, so the distinction between 「그런 명령 없음」 (`UNKNOWN_COMMAND`) and 「주인 없음」 (`OWNER_UNAVAILABLE`) collapses. That distinction decides whether the caller retries, so it must not waver.
- **D. Statically embed `help` in the CLI** — under the ADR-0081 guard **UI vocabulary cannot be put into compilation.**

## 근거

**User decision (2026-08-13 conversation).** It is the answer received by putting two candidates (bundling / `command.describe` round trip) up as choices, and including lookup is an explicit reversal of assumption B.

**Measured in code.** The frontend `Command` interface **has no argument information** (`src/commands/registry.ts:11-27` — only `id`·`title`·`category`·`keybinding`·`when`·`run`), and `list()` for discovery also gives only `id`/`title`/`category`/`keybinding` (`registry.ts:67-74`). That is, today's discovery surface ends at the name layer.

**A cost common to both options — not a fork.** TypeScript types are erased at runtime, so **whichever option is chosen, a runtime string must be written by hand for each declaration.** This cost is not the reason A was rejected.

**The real cost of excluding lookup (not an estimate).** The 4 reads in `src-tauri/src/commands/layout.rs` — `get_view` (`:497`)·`list_tabs` (`:508`)·`list_windows` (`:520`)·`resolve_spatial` (`:530`) — could not have become commands in v1, and `get` (`src/store/eventBus.ts:119`) and `defaults` (`:123`) of `window.__engramChat` would have remained and kept us from erasing that side door wholesale.

## 영향 / 불변식

- ★**Keeping the daemon opaque = hard constraint**★ — **if daemon code parses, validates or branches on `help`, it is a violation.** It is blocked **by form** by fixing the data type to a string. The moment it is opened, 「데몬은 클라이언트 셸을 모른다」 (the daemon does not know the client shell) is left as form only (the same axis as 「데몬 opaque 유지」 of ADR-0081).
- **The 「데몬 opaque 유지」 clause of ADR-0081 is valid — no discard stamp.** The daemon comes to **hold the help string** but **does no parsing, validation or branching, so type coupling is 0.** What that clause forbids is the daemon knowing UI meaning, and what the daemon has here is only opaque bytes it carries whole. (It is the same conclusion as the ruling ADR-0155 gave on the 「가드」 clause of the same ADR, and it is stated here because 0156 alone staying silent would be asymmetric.)
- **The registration wire shape changes** — from a name list to a `{name, help}` list. `help` is also attached to the daemon registry entry (`CommandListEntry`).
- **The frontend registry surface widens by one slot (additive)** — for the frontend to carry help, the `Command` interface in `src/commands/registry.ts` (`:11-27`) needs a `help` field, and the return of `list()` for discovery (`:67-74`) needs that field, **attached in an add-only way.** **Neither exists today.** The place where TRD Step 4 wrote 「`registry.ts`는 손대지 않는다」 (do not touch it) becomes, by this decision, **「새 표면은 안 만들되 기존 표면을 한 칸 넓힌다」 (do not make a new surface but widen the existing surface by one slot)** — since it extends the existing registry rather than adding a new global handle, it does not conflict with 「기존 표면에 얹는다」 (build on the existing surface) of CLAUDE.md 「LLM-우선 제어」.
- **The migration scope widens** — TRD §6 Step 3 handles **all 16 layout commands, rather than only the 12 writes**, and in Step 5 **both side doors can be torn down wholesale** (before, `__engramChat` was a read so only half was erased).
- **A reading is idempotent, so one dedup (duplicate prevention) exemption rule is attached** (the current contract is that all commands are dedup targets).
- **What we accept:** a hand-written `help` is not guarded by the compiler, so **it quietly goes stale when the handler changes.** The Rust side is derived automatically so it does not go stale, and **only the 33 frontend ones bear this risk.** If staleness becomes a real problem, promote it to a runtime schema.
- **The remaining limit in principle:** a name whose owner the daemon has **never once seen** still goes out as `UNKNOWN_COMMAND` (the case where only the daemon is turned on and the app was never launched). To answer exactly the daemon would have to know the full list, which is **what ADR-0155 forbade**, so this is **a place where avoiding coupling was chosen over exactness**.
