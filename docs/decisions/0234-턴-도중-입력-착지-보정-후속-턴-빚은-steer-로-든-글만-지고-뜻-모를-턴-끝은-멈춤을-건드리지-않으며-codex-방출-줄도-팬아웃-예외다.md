## 맥락
ADR-0231 was written before the code (its 「영향」 — 「착지 전 — 코드 없음」). The implementation (P0–P8) landed differently from the TRD 8th edition description in several places, and TRD 9th edition §10-6 indexes those differences row by row with the decider — the 「8판 서술」 column of that table is written so that it becomes the rejected alternatives of a new ADR.

Most of those rows are the implementation shape at the TRD layer and stay in the TRD. Here we move only **what changes a decision sentence of ADR-0231 · ADR-0006, or what a later session that read only that sentence would reopen**. The persistence moment of the codex JSON session id (a user decision of the same landing) is handled by ADR-0233.

## 결정
The notation follows the ADR-0231 legend — **[User]** = a decision the user answered · **[Delegated]** = a decision the user entrusted (TRD §10-1 23) and review decisions — 「오케스트레이터」·「리뷰」 in TRD §10-6 · **[Picked]** = an internal implementation the implementation picked itself — 「구현」·「계획」 in TRD §10-6.

1. ★**The follow-up turn debt is owed only by text carried in by `turn/steer`**★ (narrows ADR-0231 decision 7) [Delegated — orchestrator 2026-09-26]. Debt = after the receipt (echo) of text handed to an open turn by steer, that turn ended in `completed` without the turn's sampling start (the `item/started` of an output item) (`State::unanswered` → `follow_up_owed`). Text that `turn/start` carried (Direct · the `Held` head · text resent after a rejection) owes no debt — the turn that request opened samples its own input first, and 「기록만」 (M10) is a phenomenon of steer. The separation is the item-stage slot `Stage::InFlight.steered`, which becomes true only when a steer is sent out. The sentence of ADR-0231 decision 7 (「기록만 되고 답을 못 받으면」) · the three exceptions · the time of settling (the moment it is issued — a mail turn does not settle it) · not issuing again if the debt-paying turn ends abnormally are unchanged.
2. ★**A codex turn end of unknown meaning (`TurnClose::Unknown`) neither sets nor clears the stop after error, and carries no debt**★ (added to the 「계기가 아니다」 list of ADR-0231 decision 8) [Delegated — P2 review]. If the status of `turn/completed` is missing or an unknown value (including `inProgress`), the item disposition is the same as `completed` (a list item without an echo is acceptance-unknown · if a steer awaiting a response exists, it settles), and the stop stays as it is · no debt · it is not counted in the warning counter (`unpaid`) either. Reason: the kernel classifier folds the same line into 「그 밖의 끝」 (`TurnEndKind::Other`) and leaves `last_end_failed` as it is (`turn.rs`) — if only the path cleared it, the stops of the two layers would diverge. So the ends of decision 8 that 「세우지도 풀지도 않는」 = a cut-off end · a steer failure · an end of unknown meaning.
3. **Claude receivability is opened only by a recognizable lifecycle line** (widens ADR-0231 decision 10 「옛 벤더 버전 = 오늘 동작」 to vendor surfaces we do not know) [Delegated — P3 review]. It is `Available` only when a `command_lifecycle` line has both a non-empty `command_uuid` and a known status word (`is_recognisable_lifecycle` — the canonical status-word list = the constant next to it). A line that matches only the type does not open it — if left as is, an init without `msg_lifecycle_v1` in its capability list would send it to `Unavailable` and fall to today's path.
4. **The codex operating default hand-over = `AtEarliestBoundary` · the answer span is also held** (the landing result of ADR-0231 decision 2) [Picked — in the landing order decision 2 set]. M15 green (tool-end reaction sum 2275 µs < window minimum 6 ms · answer end 221 µs < 9.4 ms) · M16 green → `HAND_OVER_POLICY = AtEarliestBoundary` · `ANSWER_SEGMENT_HOLDS = true` (both are constants of the codex backend — not a user setting surface). `Immediate` stays as a variant and is plugged in only through the seam that builds the path (`with_hand_over`) — a test measures the divergence of the two policies, and it is the value for spans where measurement is red (as in 「거부한 대안」 of ADR-0231: 「`Immediate` 는 착지 첫 걸음과 측정이 빨간 구간의 값으로만 남는다」). A path built without the seam is also the operating policy — the test bench measures the operating value.
   - ★**Revisit trigger = the vendor narrows the window (remeasurement red).**★ What to do then is not newly decided here — ADR-0231 decision 2 · PRD R8 stand as they are: if only the answer-end window narrows, `ANSWER_SEGMENT_HOLDS = false` (only the answer span goes at once — not a question for the user, per that constant's doc) · if the tool-end window narrows, ask the user before the code (「붙들기 대 다른 길」). ★The old sentence in the `HAND_OVER_POLICY` doc, 「벤더가 그 창을 좁히면 `Immediate` 로 되돌린다」, was a delegation description that skips that question, so it disagreed with these two sentences★ — the implementation plan's 「M15 빨강 → 묻지 않고 `Immediate`」 was written into TRD §10-6 with the same disagreement, and it did not stand because M15 is green. That comment was fixed into a revisit condition together with this decision (see 「이 결정과 함께 맞춘 표면」 below).
   - **Holding becomes the default, and the 「codex 남은 항목」 of decision 8 become common** — text held before a turn that ended in error does not go out until the user types the next text. The P8 review raised this as a defect and closed it as by design (TRD §10-1 9 — user decision Q8: after a turn that ended in error, codex does not send on its own, even when the limit is lifted).
5. ★**Fan out while holding the codex emit line (`Announcer.order`) — the second exception to ADR-0006 「lock 미보유 send」**★ (ADR-0231 decision 9 · amends ADR-0006) [Picked — implementation]. Two parties emit codex list items and synthetic bubbles (`send_turn` on the input thread · the writer's floor decision `settle_floor` — once per incarnation). Emitting has to be outside the state lock (ADR-0006), so `announce` lines the two up with `order`, and the party holding the line emits **all** pre-emit items in arrival order — so `OutputSink::send` runs inside `order`. The reader and `withdraw` do not take `order` (they dispose only of items that finished emitting, and only attach a death mark to pre-emit items). The codex path has no session input lock (`input_order`) — that belongs to the claude (`SessionClassified`) path, and in codex `order` does the same lining up.
   - **All lock orders that landed**: session (claude) = `input_order → replay → 명부` · `replay → 대기 목록 표` (both leaves under replay — write to the table after releasing the registry guard, `OutputCore::record_list_event`) — as in the sentence of ADR-0231 decision 9. Codex = `order → 상태` (short — released before emit) · `order → replay → 명부` · `replay → 대기 목록 표` · the old order inside the path `상태 → 대기표` (ADR-0006 · path file header) as is. **There are two fan-out exceptions** — inside the session `input_order` (ADR-0231 decision 9) · inside the codex `order` (this decision). Both rely on the non-blocking contract of `OutputSink::send`.
6. **The core holds the queued-input registry — the session goes through the core** (fixes 「소유권 분할의 session += 대기 입력 명부·입력 자물쇠」 in the 「영향」 of ADR-0231) [Picked — implementation]. The core receives the registry `Arc` (`QueuedInputs`) and the queue list table `Arc` (`InputsPendingTable` — `AgentManager` owns one table itself) through `with_queued(QueuedWiring)`, and the session's registry accessor (`AgentSession::queued_inputs`) hands out that `Arc` of the core. What remains on the session side is the input lock (`input_order`).
7. **The landing state of ADR-0231** — landed: P0–P8, end of code push = P2 `3014247` · P8 `37ecc5e` (CI green). The 「착지 전 — 코드 없음(2026-09-26)」 in the 「영향」 of that ADR is a description from the time of writing.

## 거부한 대안
- **A debt decision for all handed-over text** (the letter of TRD 8th edition §5-5 「답 없는 항목」 · settlement 3 · §5-9) [Delegated] — it also catches text carried by `turn/start`, so if that turn ends with no output item after the echo, an empty `turn/start` goes out in operation and the model repeats the earlier answer (the M9 control — when nothing is left unanswered, opening an empty turn makes it repeat the previous answer).
- **Separate steer by turn id** [Picked] — text carried by `turn/start` also records a turn id once the response arrives, so it cannot be separated (the `Stage::InFlight` doc) → item slot `steered`.
- **Read an unknown status as `completed`** (first landing) [Delegated — P2 review] — it could clear the path's stop and even stand a debt, but the kernel folds the same end into 「그 밖」 and holds `last_end_failed` → the stops of the two layers diverge.
- **`Available` on seeing the first `command_lifecycle` line** (TRD 8th edition §5-4 · §7-1) [Delegated — P3 review] — it is an internal surface, so if the vendor changes the key or status words, the registry rows left open never close (no cap — ADR-0231 decision 7 · N8).
- **Codex emit inside the state lock** [Picked] — ADR-0006 (no external calls while holding the state lock).
- **Two emitters each emit outside the lock without an emit line** [Picked] — in the gap where both release the lock, each overtakes the other's emit and the list gets out of step with the order typed (the `Announcer` doc).
- **Plug the registry `Arc` separately into the session and the core** (TRD 8th edition §5-3 「명부는 세션 소유 · 코어는 관찰자」) [Picked] — if plugged separately in two places, the registry the session reads and the registry the core feeds can diverge, and that mismatch shows up only as an empty list, with no compile error or error (the `AgentSession::queued_inputs` doc).

- **Code anchors** — `is_recognisable_lifecycle` · `HAND_OVER_POLICY` · `State::unanswered` · `TurnClose` · `Announcer` · `announce` also carry `// ADR-0234`. - **Surfaces aligned together with this decision**: the trait doc of `OutputSink::send` (two exceptions) · the `HAND_OVER_POLICY` doc and the `HandOverPolicy::Immediate` doc (the revert sentence → a revisit condition, decision 4) · the lock-order, fan-out-exception and ownership-split lines of CLAUDE.md 「핵심 불변식」. **Left as is**: the head comment of `OutputCore::record_list_event` writes the lock order as the single line `replay → 명부 → 대기 목록 표` (not a wrong order — the code writes to the table after releasing the registry guard, so the two are never held overlapping).
