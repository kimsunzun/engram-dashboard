# ADR-0141: 빈 슬롯 어포던스 = 중앙 + 아이콘 단독 (슬롯 id 텍스트 제거, 클릭 = 우클릭과 동일 메뉴)

- 상태: 확정 (2026-08-17, 근거: 사용자 결정) · 부분 폐기 by ADR-0143 (클릭 대상과 아이콘 상호작용성)
- 관련: ADR-0065(빈 슬롯 메뉴 구성) · ADR-0064(슬롯 메뉴 단일 기여 API) · ADR-0063(슬롯 콘텐츠 배치 제어표면) · `src/components/layout/ViewLayoutRenderer.tsx` · Amended by ADR-0143 (클릭 대상과 아이콘 상호작용성)

## 맥락

빈 슬롯이 화면 중앙에 두 줄 텍스트를 띄웠다 — `Slot 93d98776`(슬롯 UUID 앞 8자)과 `— empty —`. 사용자 제보(2026-08-17): 그 텍스트가 무엇인지 읽어서 알 수 없고("Slot 넘버링?"), 빈 슬롯을 채우는 경로가 화면에 드러나지 않는다. 실제 채움 경로는 우클릭 → `새 콘텐츠 ▶` 하나뿐이었고 좌클릭은 포커스만 옮겼다 — 즉 빈 슬롯을 보고도 다음 동작을 화면이 말해주지 않았다.

슬롯 id 앞 8자는 사람이 쓸 일이 없다. 그 값을 실제로 쓰는 소비자(LLM·자동 호출자)는 레이아웃 스냅샷에서 전체 id를 받으므로 화면 텍스트에 의존하지 않는다.

## 결정

1. **빈 슬롯 = 중앙 `+` 아이콘 단독.** 두 줄 텍스트를 지우고 i18n 키 `common.viewEmpty`도 함께 삭제한다.
2. **프레임 없는 아이콘.** 테두리·배경 있는 버튼 상자가 아니라 아이콘만 뜬다.
3. **클릭 = 우클릭과 같은 메뉴, 같은 좌표.** 기존 `setContextMenu({x, y})` 상태와 기존 `SlotContextMenu` 마운트를 그대로 쓴다 — 두 번째 메뉴도, 두 번째 조립 경로도 만들지 않는다.
4. **우클릭 경로는 그대로 유지**된다(`+`는 추가 진입점이고 대체가 아니다).
5. **아이콘 클릭은 컨테이너의 포커스 이동 핸들러까지 버블링된다** — 클릭 한 번으로 슬롯 포커스와 메뉴 오픈이 함께 일어난다.
6. **아이콘은 탭 포커스 순회에서 제외한다**(사용자 결정 2026-08-17). 이 메뉴는 키보드로 조작되지 않으므로, 순회에 넣으면 Tab→Enter로 열고 마우스 없이는 닫지도 실행하지도 못하는 막다른 상태에 닿는다.

## 거부한 대안

- **테두리·배경 있는 진짜 버튼** — 사용자가 "진짜 버튼이 아니고 이미지가 가운데 뜨는 것"이라고 명시했다(2026-08-17).
- **`+` 전용 축약 메뉴(콘텐츠 채움만) 또는 클릭 즉시 기본 콘텐츠 삽입** — 사용자가 "우클릭 메뉴같이 동일하게 메뉴 나와도 된다"고 동일 메뉴를 허용했다(2026-08-17). 게다가 축약 메뉴는 ADR-0064의 단일 기여 API 밖에 두 번째 메뉴 조립 경로를 세운다 — 항목 구성이 두 곳으로 갈리면 메뉴에 항목을 더할 때마다 한쪽을 빠뜨린다.
- **슬롯 id 텍스트 유지 + 아이콘 병기** — 그 텍스트를 치우자는 것이 요청의 출발점이었다(2026-08-17). 사람이 그 값으로 하는 일이 없고, 값이 필요한 소비자는 레이아웃 스냅샷에서 전체 id를 받는다.
- **아이콘을 탭 순회에 넣고 메뉴에 키보드 조작(Esc 닫기·방향키 이동·Enter 실행)을 추가** — 키보드 접근성으로는 가장 나은 안이고 우클릭 경로의 기존 결함까지 함께 메운다. 그러나 사용자가 순회 제외를 골랐다(2026-08-17). 메뉴 컴포넌트는 이 결정의 범위 밖이고, 키보드 조작 부재는 이 어포던스가 만든 문제가 아니라 우클릭 경로에 원래 있던 결함이다 — 여기 끼워 고치면 결함의 소유가 흐려진다.
- **아이콘을 탭 순회에 넣고 Esc 닫기만 추가** — 막다른 상태만 봉합하는 최소안. 같은 사용자 결정으로 기각됐다. 열리기만 하고 실행이 안 되는 메뉴는 순회에 있을 이유가 약하다.

## 근거

- **사용자 결정(2026-08-17)** — 아이콘 형태·클릭 시 동일 메뉴·텍스트 제거 셋 다 사용자가 지정했다.
- **제어 표면을 늘리지 않는다는 코드 근거** — `+`는 새 command를 만들지 않고 registry의 기존 command(`slot.fill.*`·`slot.split.*`·`slot.close`)로만 이어진다. CLAUDE.md 「LLM-우선 제어」가 요구하는 "새 UI 기능엔 LLM 호출 경로를 함께 만들고 기존 표면에 얹는다"를 새 전역 핸들 0으로 충족한다.

## 영향 / 불변식

- **메뉴 오픈 경로는 하나다** — `setContextMenu`. `+`와 우클릭이 같은 상태를 흔든다. 세 번째 경로를 늘리면 메뉴 위치·닫힘 처리가 갈라진다.
- **빈 슬롯의 시각 정보는 `+` 하나뿐이다** — 슬롯 id는 화면에서 사라졌다. 슬롯을 텍스트로 찾던 디버깅·GUI 실측은 레이아웃 스냅샷이나 접근성 이름을 쓴다.
- **아이콘의 접근성 이름은 자기 키를 갖는다** — ADR-0065의 서브메뉴 컨테이너 라벨(`slot.newContent`)을 재사용하지 않는다. 재사용하면 그 서브메뉴 라벨을 고치는 편집이 이 버튼 이름까지 조용히 바꾸고, 그 이름으로 요소를 찾는 테스트가 엉뚱한 것을 잡는다.
- **아이콘은 탭 순회 밖에 있다 — 이 부재는 의도다.** 되살리려면 메뉴에 키보드 조작(최소 Esc 닫기)을 먼저 넣어야 한다. 순서를 뒤집으면 마우스 없이 못 빠져나오는 메뉴로 들어가는 문이 넓어진다.
- **단 그 문이 닫힌 것은 아니다 — 순회 제외는 흔한 경로만 막는다.** 탭 순서에서 빠져도 요소는 접근성 트리에 남아, 스크린리더 사용자는 여전히 이 버튼에 도달해 활성화할 수 있고 그러면 닫지도 실행하지도 못하는 메뉴를 만난다. 남은 이 경로까지 없애려면 위의 해제 조건(메뉴에 최소 Esc 닫기)을 먼저 충족해야 하며, 그때 순회 제외도 함께 거둔다 — 둘은 한 묶음이다.
- **메뉴는 앵커에서 넘치면 밀지 않고 뒤집는다.** 앵커(여는 지점)가 메뉴 사각형 안으로 들어가면 커서 밑에 항목이 놓이고, `+`는 좌클릭 오프너라 이어지는 더블클릭이 그 항목을 실행한다 — 닫기가 걸리면 슬롯이 사라진다. 뒤집어도 안 들어가는 퇴화 케이스(메뉴가 뷰포트보다 큼)에서만 밀기로 떨어진다. 이 규칙은 우클릭 경로에도 함께 적용된다 — 오프너별로 위치 규칙을 가르지 않는다.
- **좌표 없는 클릭도 메뉴를 아이콘 자리에 연다** — 탭 순회에서 뺐어도 코드·보조기술이 부르는 클릭은 남고, 그 클릭은 좌표가 `0,0`으로 온다. 좌표를 그대로 믿으면 메뉴가 뷰포트 좌상단에 열리므로, 좌표가 없는 클릭인지를 보고 아이콘 위치로 대체한다. **판별은 좌표가 0인지가 아니라 클릭 횟수가 0인지로 한다** — 좌표로 보면 뷰포트 좌상단을 실제로 누른 경우와 구별되지 않는다.
