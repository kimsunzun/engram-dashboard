# ADR-0173: The failure indicator swaps the symbol in the tree, and the slot layers onto the existing exit screen

- 상태: 확정 (2026-08-19, basis: user decision + code investigation 2026-08-19) · 부분 폐기 by ADR-0165 (slot clause (screen shows only an icon, the reason only on tree hover))
- 관련: ADR-0172 (what is recorded) · ADR-0149 (slot's 3 states) · ADR-0082 §영향 (the place where the corpse's visual display was deferred) · Amended by ADR-0165 (slot clause (screen shows only an icon, the reason only on tree hover))

## 맥락

ADR-0172 decided to attach 「마지막 실패」 (last failure) to the entry. What remains is where on the screen and how to show it. There are two places — the **tree row** is immediately visible when scanning the list but is narrow, so it can hold nothing but a symbol and a color, and the **slot screen** is wide enough for a sentence but is visible only when you are looking at that slot.

This is exactly the place ADR-0082 left open with "the visual display of the corpse is for the user to judge later after seeing the real thing".

## 결정

- **Tree** — if there is a last failure and the entry is not running, **swap the status symbol for a prohibition mark and use the warning color**. Do not add one more symbol. The reason is shown as **one line on mouse hover**.
- **If it is running, running wins** — even while holding a last failure, it is not shown.
- **Slot — terminal screens only.** No new state is created; **one reason line is layered onto the existing 「종료됨」 screen.** If the last failure is empty, it looks exactly as it does now.
- ★**No reason line on the chat screen — it is not an omission**★. The exit indicator there is just a power symbol, and it stays as is. Two reasons: ① we do not layer our wording on top of the conversation (ADR-0146) ② in structured mode diagnostics flow through a separate path, so **cause classification itself does not hold** — with no classification there is no wording to write. (User decision 2026-08-19.)
- **No button this time.** 「새 대화로 시작」 is a follow-up (ADR-0172 decision 6).

## 거부한 대안

- **Place one more symbol side by side** — the row is narrow, so it becomes harder to tell which is the status and which is the failure. Moreover, the failure indicator appears only for 「안 떠 있는 항목」 (an entry that is not running), so the original symbol has no information to carry there, and swapping loses nothing.
- **Gray it out to show not runnable (user proposal)** — in the tree, **dim gray italic is already the expression for "a reserved entry not yet launched"**, so failure and reserved would be indistinguishable. Gray is the conventional expression for "inactive", but in this tree that spot already has an owner, and a failure should rather stand out.
- **Create a fourth state screen in the slot** — a resume failure actually has a process that comes up briefly and dies, so it **already falls to the 「종료됨」 screen.** Creating a new state would make two screens share the same situation, and which one appears would depend on timing.

## 근거

- **Code investigation (2026-08-19)** — a reserved entry is drawn in a dim color + italic. The status symbol is a single point that takes one status string and decides the symbol and color, so the swap change ends in one place.
- **ADR-0149** defined the slot's 3 states (connecting / exited / deleted), and a resume failure already corresponds to 「종료됨」 among them.
- **User decision (2026-08-19)** — keep it simple with an icon · buttons and click blocking later.

## 영향 / 불변식

- **The tree keeps one symbol per entry.** Even if axes grow, the symbol is swapped, not added.
- **The slot keeps three states** (ADR-0149) — a failure is not a new state but additional information on the existing exit screen.
- **Screen wording is drawn from the failure-kind table** (ADR-0172 decision 5). Do not hard-code strings in components — doing so means fixing two places when kinds grow.
