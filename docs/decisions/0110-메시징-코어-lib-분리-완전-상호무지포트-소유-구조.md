# ADR-0110: 메시징 코어 lib 분리 — 완전 상호무지·포트 소유 구조

- 상태: 확정 (2026-07-28, 근거: 사용자 결정 + worker-scout 2기 전수 실측) · 부분 폐기 by ADR-0127 (결정 3의 TapHost 포트와 결정 4 분류 거처)
- 관련: ADR-0012(모듈 격리) · ADR-0004(백엔드 지식 격리) · ADR-0002(capability) · ADR-0104(busy 게이트) · step-log S18 2026-07-28 · CLAUDE.md §핵심 불변식(core tauri import 0 — 같은 계열의 컴파일러 벽) · Amended by ADR-0127 (결정 3의 TapHost 포트와 결정 4 분류 거처)

## 맥락
메시징(v1)은 데몬 crate 안의 모듈(`src/messaging/`)로 존재하고, 데몬 내부와의 경계는 규약(리뷰·load-bearing 주석)으로만 유지된다. 이 프로젝트는 코드를 매번 다른 코더 서브에이전트가 짜는 구조라, 규약만으로는 세션이 갈릴 때마다 경계가 부식될 위험이 있다 — 사용자 우려: "앞으로 짜는 것에서 이런 시스템을 고려해야 하는데 고려하지 않을 것 같다." 방향 언명: **"약속이 아니라 구조로 구조를 만들어야지."** 한편 채팅시스템 도입 구상(메시징과 형제 시스템)과 독립 메일 서비스 분리 구상(백로그, MCP Agent Mail 참조 건)이 있어, 메시징 커널이 두 번째 소비자를 맞을 전망이 구체적이다.

## 결정
1. **메시징 코어를 워크스페이스 6번째 lib crate로 분리한다.** 시점 = S18 인수 실측 잔여 완료 후 독립 슬라이스(TRD-lite → 코더/리뷰/QA). 인수 실측이 검증하는 경로를 이사 중에 흔들지 않기 위해 순서를 고정한다: 학습 모드 → 인수 실측 → 분리 슬라이스.
2. **완전 상호무지(core 무의존):** 새 lib은 core를 포함한 어떤 워크스페이스 crate에도 의존하지 않는다(외부 의존 = uuid·tracing뿐). 참여자 id는 lib 자체 별칭(uuid 기반), 주입 결과도 lib 자체 타입으로 정의한다.
3. **포트 소유 구조:** 접합점의 **계약(trait)은 lib이 소유**(DeliveryPort·BusyGate·TapHost·IdleNotifier·FlushTrigger + 신원/관측 포트), **실물 어댑터는 호스트(데몬)가 소유**한다(ManagerDeliveryPort·ManagerTapHost·registry 어댑터 — 전부 데몬으로 이사). 데몬이 유일한 조립·배선실이다.
4. **busy 턴 관측의 백엔드 지식 분리:** 출력 이벤트 → 턴 신호(진행/종료) 분류는 claude stream-json 백엔드 지식이므로 데몬 어댑터로 이동하고, lib은 신호 어휘(진행/종료 수신구)만 정의한다(ADR-0004와 같은 결). busy 불변식(positive-knowledge-only·유령 busy 차단·pump 콜백 규율·락 순서)은 무변경으로 lib에 남는다.
5. **봉투 계층 이사:** ControlIngress 안에 살던 봉투 계층(wrap_message·EnvelopeFields·EnvelopeFormat·Entrance·new_msg_id·DeliveryObservation)은 lib으로 이사한다 — messaging↔control 모듈 순환의 해소이며, 채팅이 공유할 커널 부품을 첫날부터 올바른 자리에 놓는다.
6. **입구(MCP 서버·engram-send·ws)·조립(lib.rs)은 데몬 잔류.** 채팅시스템은 이 lib의 형제 소비자로 설계한다(단일 시스템 통합 아님).

## 거부한 대안
- **rg 격리 게이트만 걸고 모듈 유지(현상 유지)** — 사후 검사이자 약속이라 코더 서브에이전트 세션 갈이마다 샐 수 있다. crate 경계는 컴파일러가 강제하는 벽으로, 미래 세션이 "고려"하지 않아도 물리적으로 못 뚫는다. 사용자 기각("약속이 아니라 구조로").
- **AgentId 낱말만 공유하는 부분 무지** — 실측 결과 AgentId가 `uuid::Uuid` 단순 별칭이라 완전 무지의 추가 비용이 사실상 0(데몬 호출부 무수정 컴파일). 비용 차이가 없는데 벽에 구멍을 남길 이유가 없다.
- **즉시 분리(인수 실측 전)** — 인수 실측이 검증하는 경로를 이사 중에 흔든다. 실측으로 현 경로를 못박은 직후가 가장 안전한 이사 시점.
- **채팅까지 단일 메시징 시스템으로 통합** — 메일 = 이산 편지 + 의무 의미론(회신빚 장부·기한·파킹), 채팅 = 방/스트림 의미론(이력·참여자·팬아웃)으로 불변식이 다르다. 공유는 커널 부품(봉투·Groups·신원)으로, 정책 계층은 형제로.
- **운영 어댑터를 lib에 두기** — lib이 AgentManager를 알게 돼 완전 무지가 깨지고, 미래 독립 메일 서비스(AgentManager 없는 호스트)의 그림이 훼손된다. 어댑터는 호스트 소유.

## 근거
worker-scout 2기 전수 실측(2026-07-28):
- `AgentId` = `uuid::Uuid` 타입 별칭(newtype 아님) → 데몬↔lib 경계 호출 ~66곳이 무수정 컴파일, 경계 번역 비용 사실상 0.
- `AgentManager` 접점 = 어댑터 2곳(ManagerDeliveryPort·ManagerTapHost) + 편의 생성자뿐. `AgentStatus`는 어댑터 내부 1곳(어댑터 이사와 함께 lib에서 소멸). `WriteOutcome`은 DeliveryPort 시그니처 → lib 자체 4필드 타입 + 어댑터 1곳 복사.
- ControlRegistry 접점 = 2메서드(봉투 포맷 조회·배달 관측 기록) → 소형 포트.
- 사이드이펙트 축 전부 0 실측: serde/영속화 0(전부 in-memory), async/tokio 0(순수 동기), 플랫폼 cfg 0, src-tauri/프론트/protocol 참조 0, 문서의 경로 포인터 0.
- 규모: 메시징 6파일 16,733줄(운영 6.6k/테스트 10.1k) 이사 + 봉투 계층 ~240줄. 로직 변경은 3곳 국소(busy 탭 신호 좁히기·어댑터 이사·봉투 이사), 나머지 기계적. 워크스페이스 내부 crate라 공개 lib과 달리 API 동결 압력이 없다(한 커밋 양쪽 수정).
- 부수 이득: `cargo test -p <메시징 lib>` 단독 격리 하네스(ADR-0012 정합), 채팅시스템이 첫날부터 소비자 관점으로 설계됨.

## 영향 / 불변식
- **격리 게이트(분리 후):** 메시징 lib에서 워크스페이스 crate import 0(컴파일러 강제) — 특히 `AgentManager` import 0. 위반 시도는 컴파일 에러 = 포트를 파거나 사용자에게 묻는 강제 멈춤이 설계 의도다.
- 워크스페이스 멤버 +1 → 멤버 열거 명령 갱신 필요(README.md·CLAUDE.md·`.claude/skill-bindings/qa.md`·docs/testing-strategy.md). `test-harness` feature는 lib이 자체 선언(현 core 전달형에서 독립).
- busy 불변식(positive-knowledge-only = 모르면 idle·유령 busy 차단·콜백 규율·BUSY_MAX_TURN sweep)은 이 분리로 **변경되지 않는다** — 바뀌는 건 신호 입구의 겉면뿐. 이 불변식을 lib 밖(어댑터)에서 재구현하지 말 것(포트는 얇게, 정책은 lib에).
- 호스트가 꽂아야 하는 필수 접합부 = 배달 실물(DeliveryPort)·로스터 급식(attach/forget/flush)·도어벨 배관(flush 워커)·스위프 타이머·입구. 턴 관측·봉투 포맷은 선택(fail-open 폴백). 푸시 배달은 프로세스 소유권 필요 — 없는 호스트는 pull 강등(외부 서비스 구상 시 재론).
