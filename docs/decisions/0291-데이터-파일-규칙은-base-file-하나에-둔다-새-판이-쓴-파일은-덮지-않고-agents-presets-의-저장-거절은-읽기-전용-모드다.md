## 맥락

- **There are four copies doing the same job, and their behavior differs.** For the four versioned JSON data files — the shell settings `shell\config\settings.json` · the screen state `shell\state\state.json` · the daemon `daemon\state\agents.json` · `presets.json` — the read rules (BOM · size cap · version gate · corruption decision), atomic write and corrupt copy were split across the shell `src-tauri/src/fsutil.rs` · `settings/store.rs` · `state/codec.rs` and agent `persistence/mod.rs` · `persistence/presets.rs`. Missing version · newer edition · BOM · cap · the name and timing of the corrupt copy · temp name · locked-file retry differ per file (TRD §2-1 · §2-2 — tree `78ed761` measured).
- **Known defect.** When agent load meets a `schema_version` that differs from its own edition, it starts with an empty list, and the first change's save overwrites that file without a copy (`persistence/mod.rs:115-122` · `profile.rs:377-396`). If that file is of a newer edition, the newer edition's registry disappears. A read IO failure takes the same road (empty list → overwrite).
- **The last production OS branch outside platform.** The shell `fsutil.rs`'s locked-file decision `cfg!(windows)` (`:320`) remained as the time-limited exception of ADR-0275 decision 15.
- **Save failures are invisible.** `ProfileStore::save` · `PresetStore::save` is `()` and a failure only leaves a log inside the implementation — since `mutate` applies to the map first, even when the save fails the in-memory change stays as if it succeeded and disappears on restart (`profile.rs:304-309` · `:387-407`).
- This scope takes over the deferred items D1 · D2 · D3 of TRD 1-1 (corrupt copy · shell sweep-up · atomic write) and TRD 1-3 §5-1 U-W (unifying atomic write). Two extras came along in the same scope — the three copies of agent child launch (for stdio · pty, if putting into the group fails, the launched child lives outside the group) and the shell hand-lock poison recovery · the state recorder's own clock.

### Home

1. **Gather the rules of the four data files into one implementation — a new base tenant `file`** (user — 「Base에 넣어야지. 나중에 쪼갤려면 base에서 쪼개야지.」). Reading · version decision · atomic write · copy · corrupt copy · temp sweep · the 「덮어도 되나」 decision all stand in `file`, and the shell · agent · daemon call the same functions (1a · 1b). File names · locations · schemas · version key names (`$version` · `version` · `schema_version` — unchanged now, so existing files keep being read) are held by each owner. The names `file` knows are only two forms — temp `<이름>.tmp<pid>.<번호>` · copy `<이름>.corrupt`. The new-crate plan of the 2nd edition was withdrawn (rejected alternative A).
2. **The three that differ by OS — the locked-file decision `is_busy` · retry `retry_busy` · folder sync `sync_dir` — are platform `fs`** (user 1d · 1f · 5 — the shape of `sync_dir` and `OsHooks` is main-session judgment (delegation) · R10). Since base cannot call platform (admission condition ②), the IO functions of `file` take retry and folder sync as **an argument `OsHooks` passed by the caller**. The production values are constants per crate — one each for shell · daemon · two for agent (the load-read share — R14 of decision 4). So the shell `fsutil.rs`'s `cfg!(windows)` is withdrawn and the production OS branches outside platform become 0 — **this closes the time-limited exception of ADR-0275 decision 15**. ★`OsHooks` stays an fn pointer for the production constants, and a test fake that holds state is passed only through a private closure seam inside base (D15 · provisional)★.
   - **Two consumers outside the data files.** The token file of the daemon `control/mcp_config.rs` changes from a plain `fs::write` to the unified atomic write (`write_atomic`) (user 1e) — the session settings fragment of the same lifetime and the same shape moves with it (main-session judgment (delegation)). ★The token is also briefly carried in the temp file — same folder · same ACL · deleted on failure★. ★The current `create_dir_all` is withdrawn only after R11 is in `write_atomic` (U3) — withdrawing it earlier makes the first agent spawn fail in a new data root★. ### Read · write rules (canon = the R1~R17 table in TRD §3-5)

4. **R1~R15 = main-session judgment (delegation)** — the main session adopted them on the basis of convention or the shell rules fixed now (2026-10-10 · R2 · R7 · R8 were re-confirmed separately by the main session — TRD §8-1 2 · 4). In brief:
   - **R1** no version = edition 1 · **R3** an earlier edition is read only when a reader for that edition exists, otherwise it is corrupt (today all four are `current = 1` · `version` is raised only together with an earlier-edition reader) · **R4** the version value must be an integer value only (`1` · `1.0`) · **R5** one leading BOM is ignored and not written.
   - ★**R2 a file written by a newer edition (`found > current`) is neither read, overwritten, nor copied aside, for all four files**★ — memory is the default · an empty list and writes to that file are refused (settings = re-read at every write, so it unlocks when the file changes · state = no saving during that run · agents · presets = read-only during that run — decision 6). **This reverses TRD S21-storage §6-5 · §12 R3 (copy aside and overwrite the newer edition `state.json` · no downgrade support), and removes the newer edition from the 「모르는 `$version` · `version` = 통째로 못 쓸 파일」 of ADR-0265 decision 4 · ADR-0274.** The known defect above is closed by this. The screen state gets a new state value `newer` (the `state_file` of the bus `restore.status`) and a notice.
   - **R6** cap = read cap = write cap — original text over it is not written (settings 64 KiB · state 4 MiB unchanged · agents.json 16 MiB · presets.json 4 MiB new).
   - **R7** corrupt = not JSON · not an object · over the cap · not UTF-8 · wrong version shape · an earlier edition without a reader · ★failure of the owner's shape check — the shape check lives in `Spec` and is called by `parse`, so at load · re-decision just before save · state recorder re-decision, the definition of corrupt is the same everywhere (D1 · provisional)★. **A read IO failure is not corrupt but a save refusal** (so agent's 「읽기 실패 → 빈 목록 → 덮음」 also closes with it).
   - **R8** write decision = Missing · writable → write · corrupt → copy aside and write · newer edition · read failure → refuse. ★While the load was Missing · corrupt and this run has not yet written even once (`Claim::NotYet`), if a file worth keeping is sitting there, copy it aside before overwriting — the copy name stays the fixed `.corrupt` of ADR-0274 (D14 · provisional)★. If the copy aside fails, settings · agents · presets fail that write (the original stays) and only state goes ahead (ADR-0274 「영향」 cost 2 · state = the user decision D8 of TRD S21-storage unchanged).
   - **R9** corrupt copy = ADR-0274 unchanged (fixed `<이름>.corrupt` · copy · overwrite · right before the first write) is used for agents · presets too (user 1c — the user accepted that a second corruption overwrites the first copy). For agent it changes from 「적재 때 `.corrupt-<ms>` 로 이동 · 누적」 to 「첫 저장 직전 복사」.
   - **R10** atomic write = temp in the same folder → write and `sync_all` → rename → parent folder sync (platform `sync_dir` — POSIX = folder `sync_all` · Windows = explicit no-op · result ignored) · on failure · skip, delete the temp. **R11** the folder is created by the writer when it writes (inside `write_atomic` · `copy_atomic`) and load · decision creates nothing — the state recorder and the copy aside also recreate a folder deleted while running.
   - **R12** temp name = `<이름>.tmp<pid>.<번호>` · leftover temps are swept by the file's owner at startup (another live pid's is left) · the old fixed names `agents.json.tmp` · `presets.json.tmp` are deleted directly by the store at the same place (the `sweep_temps` API stays) · agent's `write_lock` is withdrawn and the state the store newly holds (load refusal · ★last re-decision refusal (D6 · provisional)★ · ★`Claim` (D14 · provisional)★ · log display) is put in one leaf lock 「저장소 상태 칸」 — lock order = `래치 → expected 칸 → profiles|presets → 저장소 상태 칸`.
   - **R13** locked-file decision = `PermissionDenied` + Windows raw 32 · 33. **R14** retry = first attempt + N times · fixed interval · no sleep after the last · an error that is not locked goes immediately · the budget is passed by the caller — data files 5 × 20 ms (a constant of base `file`) · ★only the load reads of agents · presets use first attempt + 19 times × 50 ms (about 1 second per file — a lock remaining there makes that file read-only for the whole run, D7 · provisional)★ · temp folder delete 19 × 10 ms. **R15** refusal log = error once at the moment of entering the refusal state · debug while the same cause continues · once a write succeeds, from the start again.
5. **R16 re-decision just before save · no cross-process lock** (main-session decision). The write policy is not decided and held at load time; at every write, just before it, the current file is re-read and decided by R8 (including shape · `Claim`). No cross-process lock (file lock · lock file) is placed — there is one process that writes each file in a data folder: under `daemon\` the daemon (it holds the single-instance guard before creating the registry) · under `shell\` the shell. ★The shell-side ground mainly rests on the single-instance plugin (its mutex is per **bundle identifier**, not per data folder — a build with a different identifier already has a different data folder) and the shell run lock `state/lock.rs` is auxiliary (C1 · finishing touch of review round 3 · provisional)★. ★**Editing from outside while running is not supported** — if a person or a sync tool changes the four files while the daemon · app is up, the next save overwrites them (the last writer wins · same as now · to fix, turn it off and fix). What the re-decision catches is only the case where that edit produced a newer edition · an unreadable file · corruption (C1 · provisional)★.
6. **R17 the save refusal of agents · presets = read-only mode** (main-session decision).
   - If the load decision is a refusal (newer edition · read failure — including a lock remaining after the load-read budget), it is **read-only for the whole run**. The in-memory registry is empty, and a change with a caller returns an error before it is applied. ★It is released only by restarting the daemon (main-session confirmation · provisional)★ — the re-decision looks only at 「지금 파일이 쓸 만한가」 and does not know 「메모리가 그 파일에서 왔나」, so if it were released by the re-decision alone because the file became readable later, an empty registry would overwrite the real registry.
   - The store state is carried on the bus registry `agent.list`. ★There are three values — writable · read-only (load refusal) · this write refused (provisional name `refusing` — loaded fine, but the re-decision of the last save refused) — and the cause (D6 · provisional · wording at implementation)★. It is not carried on the screen registry. ★Landing (U5b-2b · provisional): field `store { agents, presets }` · state `Writable` | `ReadOnly` | `Refusing` · cause `Newer` | `Unreadable` · `file_version` · agent `catalog_version` 6 → 7★
   - **A change with a caller** (bus · WS · the launch path those two call) = apply to a copy → save → commit only on `Ok`. ★On `Err`, whether a refusal or a write IO failure (disk full · lock budget exceeded), leave memory as it is and return an error (main-session decision 「예」 of TRD §8-3 · provisional)★. Entry names = `try_*` of the registry · manager (U5b-1 · provisional).
   - ★**2026-10-11 amendment (user decision) — that error is split by where the refusal came from.**★ A refusal at load (`StoreError::ReadOnly` — read-only for the whole run) = `CONFLICT` 「다시 해도 같다 — 파일을 고치거나 바꾸고 데몬을 다시 띄운다」 · of the refusals of the re-decision just before write (new variant `StoreError::Refused` — split off from `ReadOnly` in the U5b-2 review), unreadable = `CONFLICT` 「대개 잠깐 쥔 잠김 — 조금 뒤 다시」 · newer edition = `CONFLICT` 「그 파일이 있는 동안은 다시 해도 같다」 · write IO failure = `INTERNAL`. An unreadable shell setting (`settings.set` · `settings.reset`) is also `CONFLICT` by the same rule (shell `catalog_version` 16 → 17). Since the daemon relay lowers the retry field of every answer it relays to `never` (`command_delivery::send_reply` · ADR-0159), the wording and help carry this distinction to the caller. The place of the mapping = `store_command_error` · `store_error_reason` of `agent/src/commands.rs` (shared by bus and WS).
7. ★**An internal change without a caller is applied to memory under any `Err` of save (write IO failure · refusal of the re-decision just before save) and sets dirty — the next successful save carries it** (D2 → E1 · provisional)★. Targets = recording the session id of the first-submit latch · the session id tracking of the claude file watcher · the reaper's lowering of `auto_restore` · raising `auto_restore` after launch · the launch path of boot restore (decision 8). Today's self-healing (even when the save fails memory stays and the next save aligns the disk) is left as it is at the internal entries. The disk is guarded by the re-decision of every write — the dirty registry is carried only by the first successful save after the refusal lifts. On a load refusal (read-only) the registry is empty and the internal changes have no target.
   - dirty sits next to the registry map (inside the same profiles · presets lock) — 「메모리가 디스크보다 앞섰다」 is a fact only the registry knows and the places that set and clear it are all inside that lock, so there is no new lock · no new edge. Even if a change with a caller returns as `Err`, the pending dirty changes are not erased.
   - **dirty left at shutdown is lost** — no final save is added to the shutdown path (same as now · finishing touch of review round 3 · provisional). ★While dirty, `mutate_if` that answered with 「변경 없음」 is also saved (adopted provisionally — TRD §8-2 10)★.
   - ★Landing (U5b-1a · main-session decision · provisional — awaiting user confirmation)★: the internal entry = the existing registry verbs put in a dirty-aware form, and the entry with a caller = `try_*`. ★presets has no dirty★ — there is no internal preset change, so the preset registry keeps only `try_*` (above 「같은 profiles · presets 락」 · departs from the TRD's 「presets 같은 꼴」).
   - Resulting invariant = 「메모리 명부 = 마지막으로 성공한 디스크 + (dirty 면) 그 뒤의 내부 변경」.
8. ★**Boot restore counts as an internal change, and the shared function that it and manual wake-up both reach (`spawn_agent_watching_link`) takes one policy argument (provisional name `Entry` — with a caller · internal) to tell them apart — no per-entry copy (a launch function dedicated to restore) is made** (E1 · E3 · provisional)★. 9. ★**Side effects after a change run only on `Ok`** (D3 · provisional)★ — registry broadcast · bus `roster_changed` · the messaging-delete cleanup hook of WS `DeleteProfile` (ADR-0116 decision 3 — if a profile that was not deleted is cleaned up, the messaging of a live profile breaks). ★However, the notices that ADR-0172 requires even on activation **failure** (the notice after the activation of bus wake-up · create-and-launch) and the broadcast after WS activation are outside this rule — because 「마지막 실패」 flows only through the registry (E2 · provisional)★.
10. ★**The three changes of the launch path (registry registration · incarnation marker · making the old handle history) are not bundled as 「셋 다 아니면 전무」** (D8 · provisional)★. The incarnation marker (`epoch_for_spawn`) is not meaningfully carried to disk (skipped on read · written as a `0` placeholder), so it does not take `mutate` and only takes the lock to change the marker — no save (the `set_last_failure` form). 11. ★**The increase of work inside the lock is accepted** (D4 · provisional)★ — one save does, inside the profiles · presets lock, additionally re-reading that file · parsing · shape check · copy aside if corrupt · the locked-file retry of each step. Usually = one more read of a small file · **worst = about 0.4 seconds of sleep for the locked-file retry alone** (4 loops of 5 × 20 ms) + IO + two parses up to the cap. During that, registry lookups (the critical path of mail dispatch) stand still. Decision and write must be inside the same lock so two saves do not overlap; the worst case lasts only while that file is locked, and saves run only on lifetime events.

## 거부한 대안

Only what is written in the TRD (§3-1 · §3-5 · §3-7 · §3-9 · §8-1) and the review collection attachments is carried over as rejection grounds.

- **A — a new crate `engram-dashboard-datafile` (the decision of the 2nd edition)** — user decision (「Base에 넣어야지. 나중에 쪼갤려면 base에서 쪼개야지.」). It would have been doing first, at this place, the 「목적별 작은 crate 로 쪼개기」 that ADR-0269 decision 1 had put off. The costs the 2nd edition counted (workspace members 11 → 12 · four registration gates · +2 regression result lines) also disappear.
- **B — split between the existing two** (atomic write · copy · copy aside · temp · sweep go to platform `fs` · reading · decision go to base `file`) — ADR-0266 decision 2 (platform's admission criterion = whether it depends on the OS): those mechanisms are OS-independent, and the one locked-file decision line inside them that is the OS's share has already fallen to platform through `is_busy`. ★The two reasons the 3rd edition also included (「`.corrupt` 이름은 도메인 지식이다」 · 「부르는 쪽이 두 crate 를 각자 잇는다」) were removed because they conflict with the ground for choosing base (D12 · provisional)★.
- **C — everything in platform + allow `serde_json`** — platform's third-party rule (only `windows` · `tracing` — the header of that crate 「의존」) breaks and JSON policy enters the OS layer.
- **D′ — pass only the decision function (`is_busy`), and the retry loop and budget are held by base `file`** — platform `retry_busy` remains the share of scratch · net so there would be two loops, and it breaks 1d (「잠깐 쥐어졌다」 retry = one platform policy).
- **The two reasons by which the 2nd edition rejected the current shape (the caller passes the retry) — re-examined and withdrawn.** ① 「base 에 어차피 `serde_json` 이 든다」 = the user amended ADR-0269 decision 6 「지킬 것」, and the three that call base as a production dependency (shell · agent · daemon) already pull in `serde_json`, so new packages are 0 for `Cargo.lock`. ② 「부를 때마다 platform 재시도를 들고 오는 이음매는 의존을 피하려고만 생긴다」 = the seam ends with one constant per crate, the same shape already exists (shell `sweep_temps` takes platform's PID liveness decision as an argument — `state/boot.rs:105-110`) and that seam is itself the test seam (ADR-0012). The remaining cost = since passing a retry that does nothing as the production `OsHooks` still compiles, each crate gets one 「재시도가 잠김 오류를 실제로 다시 한다」 test.
- **Also copy aside and overwrite a newer edition (the state · settings rule before R2)** — convention = an old edition does not overwrite a file written by a newer edition (SQLite opens a DB whose header write version is larger than its own as read-only · Firefox: an old edition does not open a profile written by a newer edition). The state's crash copy already does so (TRD S21-storage N6). ★Rejection ground weak — the convention citations were not checked against the original text (cited from memory · unverified — TRD §8-2 3)★.
- **Aligning to one budget (R14)** — the grounds differ from each other: data files = the current shell rule (ADR-0265 decision 4) · temp folder delete = the 200 ms measured budget of scratch · net open = 「5번 시도 · 최악 400 ms(클라이언트 5 s 폴링 안)」 · load read = a value set backward from the shell's 5-second deadline for finding the daemon.
- **Holding a write decision decided at load time (2nd edition)** — two things leak: ① even if the file changes to a newer edition while running, it is overwritten ② if a value decided as 「떠 두고 쓴다」 because of corruption is held, after the first save our healthy file is copied aside as `.corrupt` on every save and erases the real corrupt copy (review round 1 codex).
- **A cross-process lock (file lock · lock file)** — it overlaps with the single-writer guards of decision 5 (the daemon single-instance guard · the shell single-instance plugin).
- **Remember file identity (file id · modified time · size) or a content fingerprint at load · write time, compare just before save, and if different refuse that save or reload** (C1 · provisional) — main-session decision: as by convention, no detection mechanism is placed (an app-owned state file does not support edits from outside while running and the last writer wins — Firefox `prefs.js` · Chrome `Preferences`). It is the same as the current behavior so not a regression, and the reload branch needs the same consistency design (registry · screen · live sessions) as 「실행 중 다시 적재」 below. ★Rejection ground weak — the convention citations are cited from memory · unverified and the rest is a statement★.
- **Save refusal = log only · the memory change as if it succeeded · it disappears on restart (2nd edition · current behavior)** — a change the caller (a person · the LLM) believed 「바꿨다」 disappears on restart (`ProfileStore::save` is `()` — `profile.rs:304-309`). The shape is the same as SQLite returning an error for a write to a DB it opened read-only (cited from memory · unverified).
- **Ask first, then apply (check only that it can be written, then apply to the map → save)** — a write failure between the check and the save (disk full · rename lock budget exceeded) makes 「메모리만 바뀜」 again.
- **Reload while running to release read-only** — the registry changes while running, so consistency with the screen · live sessions would have to be designed separately (the road of releasing by re-decision alone falls into the trap of decision 6). ★Rejection ground weak — a statement only★.
- **Make internal changes all-or-nothing too (3rd edition)** — the premise at the head of the first-submit latch (「포트는 반환이 없어 결과가 래치에 돌아오지 않고, 같은 입력이면 답도 같으므로 재시도할 것이 없다」 — `session_id_latch.rs:14-16`) breaks, and one transient failure loses the session id · `auto_restore` for good (review round 2 D2).
- **For internal changes too, if the re-decision just before save refuses, do not apply, and boot restore then `Failed` (4th edition)** — one short read lock in the re-decision would discard the reaper's `auto_restore=false` (`reaper.rs:135`), so the in-memory `true` would be carried by the next save and the dead agent would revive as a target of the next boot restore (the crash loop that the 「올림 → 펌프 → reaper 내림」 order of `manager.rs:2003-2010` meant to prevent). The latch's session id is also discarded (ADR-0226) and boot restore fails. Not writing our registry on top of a newer-edition file is already guarded by the re-decision of every write (review round 3 E1).
- **A launch function dedicated to boot restore (per-entry copy)** — boot restore deliberately uses the same verb as manual wake-up. A copy would revive the 「입구마다 판정이 갈려 하나가 뒤처진다」 that ADR-0082 · ADR-0201 · ADR-0202 blocked (review round 3 E3).
- **(g) Switch to launching suspended (platform `spawn::prepare_tree_root` · `TreeRoot` — the precedent of the usage query)** — before putting in, no grandchild can exist, so it would close even the gap on the success path, but portable-pty (the pty link) has no way to launch suspended and it changes the success path of stdio · codex, which goes beyond the scope of 2g (the guard rule).
- **(g) The guard kills the child tree as a whole with `taskkill /T` (platform `process::kill_tree`) (the original plan of decision 13)** (★main-session decision (delegation) 2026-10-10 · provisional — awaiting user confirmation★) — `taskkill` ties the tree only by the parent number (WMI `ParentProcessId`) and does not look at the start time. Processes that still carry the number of a dead parent are common on this PC (U7 reviewer measurement 2026-10-10), so under the `cmd.exe` that received that number again it could kill even another party's tree (e.g. `explorer.exe`).
- **(g) Scan and kill descendants with a number snapshot** (take an identity list with platform `process::subtree`, re-read the start time of each descendant and kill by that handle — the U7 first-round amendment) (★main-session decision (delegation) 2026-10-10 · provisional — awaiting user confirmation★) — if a number on the list ends after the snapshot and before the re-read and is handed to another process, or an intermediate descendant's number is handed over before it is expanded, it aims at someone else (two reviews of the U7 second round). Descendants started after putting in are ended by the group without numbers, so what this means covers in addition is only the descendants started before putting in.
- **Also make the base `writable` `retry_if_vanished` of 1d a platform policy** — it is not a locked-file retry but doing it once more on `NotFound` (a race where someone else deletes the folder during a check — `writable.rs:86-97`). There is no OS rule, so it does not fit the platform charter (whether it depends on the OS), and ADR-0282 put that place in base — putting it in would bring OS-independent code into platform.
