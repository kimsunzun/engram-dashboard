## 맥락

- **There are four copies doing the same job, and their behavior differs.** The four versioned JSON data files — shell settings `shell\config\settings.json` · screen state `shell\state\state.json` · daemon `daemon\state\agents.json` · `presets.json` — had their read rules (BOM · size cap · version gate · corruption decision) · atomic write · corrupt copy scattered across the shell `src-tauri/src/fsutil.rs` · `settings/store.rs` · `state/codec.rs` and agent `persistence/mod.rs` · `persistence/presets.rs`. The handling of a missing version · a newer edition · BOM · cap · the name and timing of the corrupt copy · the temp name · locked retry differs per file (TRD §2-1 · §2-2 — measured on tree `78ed761`).
- **A known defect.** When agent load meets a `schema_version` different from its own edition, it starts with an empty list, and the save of the first change overwrites that file without a copy (`persistence/mod.rs:115-122` · `profile.rs:377-396`). If that file is a newer edition, the newer edition's registry is lost. A read IO failure takes the same path (empty list → overwrite).
- **The last production OS branch outside platform.** The locked-detection `cfg!(windows)`(`:320`) in the shell `fsutil.rs` remained as the time-limited exception of ADR-0275 decision 15.
- **A failed save is invisible.** `ProfileStore::save` · `PresetStore::save` return `()` and a failure only leaves a log inside the implementation — since `mutate` applies to the map first, even if the save fails the memory change remains as if it succeeded and vanishes on restart (`profile.rs:304-309` · `:387-407`).
- This scope inherits TRD 1-1's deferred items D1 · D2 · D3 (corrupt copy · shell sweep · atomic write) and TRD 1-3 §5-1 U-W (atomic write unification). Two extras are in the same scope — agent child spawn in three variants (in stdio · pty, if putting into the group fails, the spawned child lives outside the group) and the shell's hand-written lock-poison recovery · the state writer's own clock.

### Home

1. **Gather the rules of the four data files into one implementation — a new base resident `file`**(user — 「Base에 넣어야지. 나중에 쪼갤려면 base에서 쪼개야지.」). Reading · version decision · atomic write · copy · corrupt copy · temp sweep · the 「덮어도 되나」 decision all stand in `file`, and the shell · agent · daemon call the same functions (1a · 1b). File names · locations · schemas · version key names (`$version` · `version` · `schema_version` — unchanged, so existing files keep being read) are held by each owner. `file` knows only two name shapes — temp `<이름>.tmp<pid>.<번호>` · copy `<이름>.corrupt`. The 2nd edition's new-crate proposal was withdrawn (rejected alternative A).
2. **The three that vary by OS — the locked check `is_busy` · retry `retry_busy` · directory sync `sync_dir` — are platform `fs`**(user 1d · 1f · 5 — the shape of `sync_dir` and `OsHooks` is main's judgment (delegated) · R10). base cannot call platform (residency condition ②), so the IO functions of `file` take retry and directory sync as an **argument `OsHooks` passed by the caller**. The production values are constants per crate — one each for shell · daemon, two for agent (the load-read part — R14 of decision 4). So the `cfg!(windows)` in the shell `fsutil.rs` is removed and the production OS branches outside platform become 0 — **this closes the time-limited exception of ADR-0275 decision 15**. ★`OsHooks` stays as plain fn pointers for the production constants, and a stateful test fake is passed only through a private closure seam inside base (D15 · provisional)★.
   - **Two consumers outside the data files.** The token file of the daemon `control/mcp_config.rs` changes from a plain `fs::write` to the unified atomic write (`write_atomic`) (user 1e) — the session-settings fragment of the same lifetime · same shape moves along (main's judgment (delegated)). ★The token is briefly carried in the temp file too — same folder · same ACL · deleted on failure★. ★The current `create_dir_all` is removed only after R11 enters `write_atomic` (U3) — removing it first makes the first agent spawn fail on a new data root★. The other consumer of 1d, agent `usage/scratch.rs`, does not go through base and calls platform `retry_busy` directly, and ★errors other than locked are no longer retried — the U6 pilot first measures the actual failure code (TRD §8-2 1)★.

### Read · write rules (canonical = the R1~R17 table of TRD §3-5)

4. **R1~R15 = main's judgment (delegated)** — main adopted them on the basis of practice or the shell rules fixed now (2026-10-10 · R2 · R7 · R8 were re-confirmed separately by main — TRD §8-1 2 · 4). Gist:
   - **R1** no version = edition 1 · **R3** an earlier edition is read only when a reader for that edition exists, otherwise it is corrupt (all four have `current = 1` now · `version` is raised only together with an earlier-edition reader) · **R4** the version value is only a number whose value is an integer (`1` · `1.0`) · **R5** a single leading BOM is ignored and not written.
   - ★**R2 a file written by a newer edition (`found > current`) is neither read, overwritten, nor copied aside for any of the four files**★ — memory is the default · an empty list, and writing to that file is refused (settings = re-read on every write so it clears when the file changes · state = no saving during that run · agents · presets = read-only during that run — decision 6). **This reverses TRD S21-storage §6-5 · §12 R3 (a newer-edition `state.json` is copied aside and overwritten · downgrade not supported) and removes the newer edition from 「모르는 `$version` · `version` = 통째로 못 쓸 파일」 in ADR-0265 decision 4 · ADR-0274.** The known defect above is closed by this. The screen state gets a new state value `newer` (`state_file` of bus `restore.status`) and a notice.
   - **R6** cap = read cap = write cap — raw text over it is not written (settings 64 KiB · state 4 MiB unchanged · agents.json 16 MiB · presets.json 4 MiB new).
   - **R7** corrupt = not JSON · not an object · over the cap · not UTF-8 · wrong version shape · an earlier edition with no reader · ★owner shape check failure — the shape check lives in `Spec` and `parse` calls it, so load · re-decision just before save · state-writer re-decision all share the same definition of corrupt (D1 · provisional)★. **A read IO failure is not corruption but a save refusal** (so agent's 「읽기 실패 → 빈 목록 → 덮음」 is closed too).
   - **R8** write decision = Missing · writable → write · corrupt → copy aside and write · newer edition · read failure → refuse. ★If the load was Missing · corrupt and, while this run has not yet written even once (`Claim::NotYet`), a usable file has appeared, it is copied aside before being overwritten — the copy name is ADR-0274's fixed `.corrupt` as is (D14 · provisional)★. If the copy-aside fails, settings · agents · presets fail that write (original untouched) and only state proceeds (ADR-0274 「영향」 cost 2 · state = the user decision D8 of TRD S21-storage as is).
   - **R9** corrupt copy = ADR-0274 as is (fixed `<이름>.corrupt` · copy · overwrite · right before the first write) also used for agents · presets (user 1c — accepted that a second corruption overwrites the first copy). agent changes from 「적재 때 `.corrupt-<ms>` 로 이동 · 누적」 to 「첫 저장 직전 복사」.
   - **R10** atomic write = temp in the same folder → fill and `sync_all` → rename → parent folder sync (platform `sync_dir` — POSIX = folder `sync_all` · Windows = explicit no-op · result ignored) · if it fails or is skipped, the temp is deleted. **R11** the writer creates the folder when writing (inside `write_atomic` · `copy_atomic`) and load · decision create nothing — the state writer and copy-aside also recreate a folder that was deleted during the run.
   - **R12** temp name = `<이름>.tmp<pid>.<번호>` · leftover temps are swept by the file's owner at startup (a live other pid is left alone) · the old fixed names `agents.json.tmp` · `presets.json.tmp` are deleted directly by the store in the same place (the `sweep_temps` API unchanged) · agent's `write_lock` is withdrawn and the state the store newly holds (load refusal · ★last re-decision refusal (D6 · provisional)★ · ★`Claim` (D14 · provisional)★ · log marker) is put in one leaf lock, 「저장소 상태 칸」 — lock order = `래치 → expected 칸 → profiles|presets → 저장소 상태 칸`.
   - **R13** locked decision = `PermissionDenied` + Windows raw 32 · 33. **R14** retry = first attempt + N times · fixed interval · no sleep after the last · errors other than locked go straight through · the budget is passed by the caller — data files 5 × 20 ms (a constant of base `file`) · ★only the load reads of agents · presets use first attempt + 19 times × 50 ms (about 1 second per file — a lock remaining there makes it read-only for that whole run, hence D7 · provisional)★ · temp folder deletion 19 × 10 ms. **R15** refusal log = one error when entering the refusal state · debug while the same cause continues · starts over once a write succeeds.
5. **R16 re-decision just before save · no inter-process lock** (main decision). The write policy is not decided at load time and held; on every write, the file as it is now is re-read just before and decided by R8 (including shape · `Claim`). No inter-process lock (file lock · lock file) is placed — each file of a data folder has one writing process: under `daemon\` the daemon (it takes the single-instance guard before creating the registry) · under `shell\` the shell. ★The main basis on the shell side is the single-instance plugin (its mutex is per **bundle identifier**, not per data folder — builds with a different identifier have different data folders from the start), and the shell run lock `state/lock.rs` is auxiliary (C1 · review round 3 touch-ups · provisional)★. ★**Outside editing while running is not supported** — if a person or a sync tool changes the four files while the daemon · app is up, the next save overwrites it (the last writer wins · same as now · to fix it, shut down and edit). What the re-decision catches is only the case where that edit produced a newer edition · an unreadable file · corruption (C1 · provisional)★.
6. **R17 a refused save of agents · presets = read-only mode** (main decision).
   - If the load decision is a refusal (newer edition · read failure — including a lock remaining after the load-read budget), **it is read-only for that whole run**. The in-memory registry is empty, and a change with a caller returns an error before being applied. ★Cleared only by restarting the daemon (main confirmation · provisional)★ — the re-decision only looks at 「지금 파일이 쓸 만한가」 and does not know 「메모리가 그 파일에서 왔나」, so if it were cleared by re-decision alone after the file became readable, an empty registry would overwrite the real registry.
   - The store state is carried in the bus registry `agent.list`. ★There are three values — writable · read-only (load refusal) · this write refused (draft `refusing` — loaded fine but the re-decision of the last save refuses) — and the reason (D6 · provisional · the words are fixed in implementation)★. It is not carried in the screen registry. ★Landing (U5b-2b · provisional): field `store { agents, presets }` · state `Writable` | `ReadOnly` | `Refusing` · reason `Newer` | `Unreadable` · `file_version` · agent `catalog_version` 6 → 7★
   - **A change with a caller** (bus · WS · the spawn path they call) = apply to a copy → save → commit only on `Ok`. ★On `Err`, whether a refusal or a write IO failure (disk full · lock budget exceeded), memory is left as is and the error is returned (the main decision 「예」 of TRD §8-3 · provisional)★. Entry names = the registry · manager's `try_*` (U5b-1 · provisional).
   - ★**2026-10-11 amendment (user decision) — that error splits by where the refusal occurred.**★ A refusal at load (`StoreError::ReadOnly` — read-only for this whole run) = `CONFLICT` 「다시 해도 같다 — 파일을 고치거나 바꾸고 데몬을 다시 띄운다」 · of the refusals of the re-decision just before write (the new variant `StoreError::Refused` — split from `ReadOnly` in the U5b-2 review), unreadable = `CONFLICT` 「대개 잠깐 쥔 잠김 — 조금 뒤 다시」 · newer edition = `CONFLICT` 「그 파일이 있는 동안은 다시 해도 같다」 · write IO failure = `INTERNAL`. Unreadable for the shell settings (`settings.set` · `settings.reset`) is also `CONFLICT` by the same rule (shell `catalog_version` 16 → 17). Because the daemon relay lowers the retry field of every relayed reply to `never` (`command_delivery::send_reply` · ADR-0159), this distinction is carried to the caller by the text and the help. The mapping lives in `store_command_error` · `store_error_reason` of `agent/src/commands.rs` (shared by bus · WS).
7. ★**An internal change with no caller is applied to memory and marks dirty on any `Err` of the save (write IO failure · refusal of the re-decision just before save) — the next successful save carries it**(D2 → E1 · provisional)★. Targets = the session-id record of the first-submit latch · the session-id tracking of the claude file watcher · the reaper's lowering of `auto_restore` · raising `auto_restore` after spawn · the spawn path of boot restore (decision 8). Today's self-healing (even if a save fails memory remains and the next save aligns the disk) is left as is at the internal entry. The disk is guarded by the re-decision on every write — the dirty registry is carried only by the first successful save after the refusal is lifted. If the load is refused (read-only) the registry is empty and the internal change has no target.
   - dirty is kept beside the registry map (inside the same profiles · presets lock) — 「메모리가 디스크보다 앞섰다」 is a fact only the registry knows and the places that set and clear it are all inside that lock, so there is no new lock · new edge. Even if a change with a caller returns with `Err`, the pending dirty change is not erased.
   - **dirty left at shutdown is lost** — no final save is added to the shutdown path (same as the current behavior · review round 3 touch-ups · provisional). ★While dirty, even a `mutate_if` that answered 「변경 없음」 saves (adopted provisionally — TRD §8-2 10)★.
   - ★Landing (U5b-1a · main decision · provisional — awaiting user confirmation)★: the internal entry = the existing registry verbs made dirty-aware and the entry with a caller = `try_*`. ★presets has no dirty★ — there is no internal preset change, so the preset registry has only `try_*` (it deviates from 「같은 profiles · presets 락」 above and 「presets 같은 꼴」 of the TRD).
   - Resulting invariant = 「메모리 명부 = 마지막으로 성공한 디스크 + (dirty 면) 그 뒤의 내부 변경」.
8. ★**Boot restore is treated as an internal change, and the shared function that boot restore and manual wake-up both reach (`spawn_agent_watching_link`) carries one policy argument (draft `Entry` — has a caller · internal) to tell them apart — no per-entry copy (a restore-only spawn function) is made**(E1 · E3 · provisional)★. If the save on that path at boot is refused · fails, it is still applied to memory + dirty and spawning continues. The production daemon today does not call boot auto-restore (default OFF) — the rule is set for when that function is called again and is guarded by tests. ★Landing (U5b-1b · provisional): the name `Entry` (`Caller` · `Internal`) as is · private to the manager module★ · ★Remaining — if the late reap of an old session overlaps a failed caller activation, `auto_restore=true` is left on a dead agent (harmless now since boot auto-restore is OFF · `docs/tracking.md` T-57)★.
9. ★**Side effects after a change run only on `Ok`**(D3 · provisional)★ — registry broadcast · bus `roster_changed` · the messaging deletion cleanup hook of WS `DeleteProfile` (ADR-0116 decision 3 — cleaning up a profile that was not deleted breaks the messaging of a live profile). ★But the notifications ADR-0172 requires even on activation **failure** (bus wake-up · the post-activation notification of create-and-start) and the WS post-activation broadcast are outside this rule — because 「마지막 실패」 flows only through the registry (E2 · provisional)★.
10. ★**The three changes of the spawn path (registry registration · incarnation marker · moving the old handle into history) are not bundled as 「셋 다 아니면 전무」**(D8 · provisional)★. The incarnation marker (`epoch_for_spawn`) is not meaningfully carried to disk (read skipped · write `0` placeholder), so it does not go through `mutate` and only takes the lock to advance the marker — no save (the `set_last_failure` shape). If moving the old handle into history fails after registration succeeds, the registration is not rolled back — it is 「명부에 오른 채 안 뜬 에이전트」 and the same end shape as after a process-open failure today. ★The partial success of create-and-start (`create_and_start`) is the current contract as is — registration is not rolled back (rewinding is the second deletion path) and the error text carries the recovery path. No new device is added (review round 4 · provisional)★.
11. ★**The growth of in-lock work is accepted**(D4 · provisional)★ — one save, inside the profiles · presets lock, additionally does re-reading that file · parsing · shape check · copy-aside if corrupt · the locked retry of each step. Usual = one more small file read · **worst = about 0.4 s of sleep from locked retries alone** (4 loops of 5 × 20 ms) + IO + two parses up to the cap. During that, registry lookups (the critical path of mail dispatch) stall. The decision and the write must be inside the same lock so that two saves do not overlap, the worst case is only while that file is locked, and saves run only on lifetime events.
12. ★**The state writer also re-decides before every save**(D5 · E5 · provisional)★ — two operations, reading state.json and copy-aside, are added to the writer's file seam (`StateFiles`) · a newer-edition refusal waits until the next screen change, like the snapshot the codec refused (it does not re-read every period) · only a read-failure refusal is re-decided after the debounce · even if copy-aside fails that write is done (R8 — state is the user decision D8 of TRD S21-storage as is).

## 거부한 대안

The rejection grounds carry over only what is written in the TRD (§3-1 · §3-5 · §3-7 · §3-9 · §8-1) and the review roll-up attachments.

- **A — a new crate `engram-dashboard-datafile` (the decision of the 2nd edition)** — user decision (「Base에 넣어야지. 나중에 쪼갤려면 base에서 쪼개야지.」). It would have been doing first, on this occasion, the 「목적별 작은 crate 로 쪼개기」 that ADR-0269 decision 1 deferred. The costs the 2nd edition counted (workspace members 11 → 12 · four registration gates · +2 regression result lines) also disappear.
- **B — split between the two existing crates** (atomic write · copy · copy-aside · temp · sweep in platform `fs` · read · decision in base `file`) — ADR-0266 decision 2 (platform's residency criterion = OS dependence): those devices are OS-independent, and the OS part inside them, the one-line locked decision, has already fallen to platform as `is_busy`. ★The two reasons the 3rd edition also included (「`.corrupt` 이름은 도메인 지식이다」 · 「부르는 쪽이 두 crate 를 각자 잇는다」) were dropped because they conflict with the grounds for choosing base (D12 · provisional)★.
- **C — everything in platform + allow `serde_json`** — the third-party rule of platform (only `windows` · `tracing` — 「의존」 in that crate's header) breaks and JSON policy enters the OS layer.
- **D′ — pass only the decision function (`is_busy`) and let base `file` hold the retry loop and budget** — platform `retry_busy` stays for scratch · net, so there would be two loops, and it violates 1d (「잠깐 쥐어졌다」 retry = one platform policy).
- **The two reasons by which the 2nd edition rejected the current shape (the caller passes the retry) — looked at again and withdrawn.** ① 「base 에 어차피 `serde_json` 이 든다」 = the user amended ADR-0269 decision 6 「지킬 것」, and the three that call base as a production dependency (shell · agent · daemon) already pull `serde_json`, so new packages in `Cargo.lock` are 0. ② 「부를 때마다 platform 재시도를 들고 오는 이음매는 의존을 피하려고만 생긴다」 = the seam ends as one constant per crate, the same shape already exists (the shell `sweep_temps` takes platform's PID liveness decision as an argument — `state/boot.rs:105-110`), and that seam is as is the test seam (ADR-0012). The remaining cost = since passing a do-nothing retry in the production `OsHooks` still compiles, each crate gets one test 「재시도가 잠김 오류를 실제로 다시 한다」.
- **Copy aside and overwrite even for a newer edition (the state · settings rule before R2)** — practice = a file written by a newer edition is not overwritten by an older edition (SQLite opens a DB whose header write version is larger than its own read-only · Firefox does not let an older edition open a profile written by a newer one). The state's crash copy already works that way (TRD S21-storage N6). ★Rejection basis weak — the practice citations were not checked against originals (quoted from memory · unverified — TRD §8-2 3)★.
- **Aligning to a single budget (R14)** — the grounds differ from each other: data files = the current shell rule (ADR-0265 decision 4) · temp folder deletion = scratch's 200 ms measured budget · net open = 「5번 시도 · 최악 400 ms(클라이언트 5 s 폴링 안)」 · load read = a value worked back from the shell's 5-second deadline for finding the daemon.
- **Holding the write decision made at load (2nd edition)** — two things leak: ① even if the file changes to a newer edition while running, it is overwritten ② if the held value says 「떠 두고 쓴다」 because of corruption, then after the first save our healthy file is copied to `.corrupt` on every save and erases the real corrupt copy (review round 1 codex).
- **Inter-process lock (file lock · lock file)** — a device that overlaps the single-writer guard of decision 5 (the daemon single-instance guard · the shell single-instance plugin).
- **Remember file identity (file id · mtime · size) or a content fingerprint at load · write time and compare just before save, refusing that save or reloading if different** (C1 · provisional) — main decision: by practice, no detection device is placed (an app-owned state file does not support outside editing while running and the last writer wins — Firefox `prefs.js` · Chrome `Preferences`). It is the same as now, so not a regression, and the reload branch needs the same consistency design (registry · screen · live sessions) as 「실행 중 다시 적재」 below. ★Rejection basis weak — the practice citations are quoted from memory · unverified and the rest is a statement★.
- **Save refusal = log only · the memory change as if succeeded · lost on restart (2nd edition · current behavior)** — a change the caller (person · LLM) believed 「바꿨다」 vanishes on restart (`ProfileStore::save` is `()` — `profile.rs:304-309`). The shape is the same as SQLite returning an error for a write to a DB opened read-only (quoted from memory · unverified).
- **Ask first, then apply (check only that it can be written, apply to the map, then save)** — a write failure between the check and the save (disk full · rename lock budget exceeded) again produces 「메모리만 바뀜」.
- **Reload while running to lift read-only** — the registry changes during the run, so consistency with the screen · live sessions has to be designed separately (the way of lifting by re-decision alone falls into the trap of decision 6). ★Rejection basis weak — a statement only★.
- **Internal changes also all-or-nothing (3rd edition)** — the premise at the head of the first-submit latch (「포트는 반환이 없어 결과가 래치에 돌아오지 않고, 같은 입력이면 답도 같으므로 재시도할 것이 없다」 — `session_id_latch.rs:14-16`) breaks, and one transient failure loses the session id · `auto_restore` forever (review round 2 D2).
- **If the re-decision just before save refuses, an internal change is not applied either, and boot restore then becomes `Failed` (4th edition)** — one short read lock in the re-decision drops the reaper's `auto_restore=false` (`reaper.rs:135`), the memory `true` is carried on the next save, and a dead agent revives as a target of the next boot restore (the crash loop that the 「올림 → 펌프 → reaper 내림」 order of `manager.rs:2003-2010` was meant to prevent). The latch's session id is also dropped (ADR-0226) and boot restore fails. Not writing our registry over a newer-edition file is already guarded by the re-decision on every write (review round 3 E1).
- **A boot-restore-only spawn function (per-entry copy)** — boot restore deliberately uses the same verb as manual wake-up. A copy revives what ADR-0082 · ADR-0201 · ADR-0202 prevented, 「입구마다 판정이 갈려 하나가 뒤처진다」 (review round 3 E3).
- **(g) Switch to spawn-suspended (platform `spawn::prepare_tree_root` · `TreeRoot` — the precedent of the usage query)** — before putting in, no grandchild can be born, so it even closes the gap of the success path, but portable-pty (the pty link) has no way to spawn suspended and it changes the success path of stdio · codex, so it exceeds the scope of 2g (the guard rule).
- **(g) Have the guard kill the whole child tree with `taskkill /T` (platform `process::kill_tree`) (the original proposal of decision 13)**(★main decision (delegated) 2026-10-10 · provisional — awaiting user confirmation★) — `taskkill` builds the tree only from the parent number (WMI `ParentProcessId`) and does not look at start time. Processes that still carry a dead parent's number are common on this PC (measured by the U7 reviewer 2026-10-10), so under a `cmd.exe` that received that number again, someone else's tree (e.g. `explorer.exe`) could also be killed.
- **(g) Scan descendants by a number snapshot and kill them** (take an identity list with platform `process::subtree`, re-read each descendant's start time, and kill by that handle — the U7 first amendment proposal)(★main decision (delegated) 2026-10-10 · provisional — awaiting user confirmation★) — if a number on the list ends and passes to another process between the snapshot and the re-read, or the number of an intermediate descendant passes before expansion, it aims at someone else (two U7 second-round reviews). Descendants born after putting in are ended by the group without numbers, so what this means additionally covers is only the descendants born before putting in.
- **Make 1d's base `writable` `retry_if_vanished` a platform policy too** — it is not a locked retry but one more try on `NotFound` (a race where someone deletes the folder in the middle of the check — `writable.rs:86-97`). It has no OS rule so it does not fit the platform charter (OS dependence), and ADR-0282 set that place as base — putting it in would put OS-independent code in platform.
