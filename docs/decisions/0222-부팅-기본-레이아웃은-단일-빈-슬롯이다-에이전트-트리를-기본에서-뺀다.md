# ADR-0222: 부팅 기본 레이아웃은 단일 빈 슬롯이다 (에이전트 트리를 기본에서 뺀다)

- 상태: 확정 (2026-09-23, 근거: 사용자 결정)
- 관련: Amends ADR-0063 (결정 2 부팅 기본 레이아웃) · Amends ADR-0140 (결정 5 부팅 기본 레이아웃 배치) · ADR-0035(레이아웃 권위 = src-tauri) · `src-tauri/src/layout/manager.rs`(`ViewManager::new`)

## 맥락

ADR-0063 결정 2는 고정 사이드패널을 슬롯으로 옮기면서 main 창 첫 뷰를 `Split[AgentList(좌) · Empty(우)]`로 만들었다. ADR-0140 결정 5가 그 배치를 방향 어휘만 바꿔 유지했다. 그래서 클라이언트를 띄울 때마다 에이전트 트리가 붙어 나온다. 레이아웃은 디스크에 저장되지 않아 매 기동이 이 기본값에서 시작한다.

사용자가 이것을 결함으로 보고했다(2026-09-23): "디폴트가 아무것도 없는거여야 되는데 에이전트 트리가 최초에 항상 붙어있더라고".

## 결정

1. **main 창 첫 뷰도 다른 모든 새 뷰와 같은 단일 Empty 슬롯으로 시작한다.** 새 탭·새 창·마지막 탭을 닫은 뒤의 대체 탭이 이미 그렇다. 부팅만 예외이던 것을 없앤다.
2. **에이전트 트리는 필요할 때 슬롯에 배치한다.** 빈 슬롯 우클릭 메뉴(새 콘텐츠 → 에이전트 트리)나 `layout.setSlotContent`(`{type:'agent_list'}`)로 배치한다. ADR-0063 결정 1의 제네릭 배치 경로를 그대로 쓰며, 새 표면을 만들지 않는다.
3. ADR-0063 결정 1·4와 ADR-0140의 나머지 결정은 그대로 유효하다. ADR-0063 결정 3(고정 사이드패널 제거)도 유효하되, 그 안의 "AgentList는 부팅 레이아웃의 슬롯으로만 존재(2)" 구절은 "슬롯 콘텐츠로만 존재"로 읽는다 — 부팅 배치 부분은 결정 2와 함께 폐기다. ADR-0140 「영향」의 "ADR-0063 decision 2 재해석" 항목도 같은 이유로 결정 5와 함께 낡았다.

## 거부한 대안

- **ADR-0063 결정 2 유지(부팅 기본 = AgentList·Empty 분할)**: 사용자가 기본 레이아웃은 비어 있어야 한다고 결정했다. 기각 근거는 사용자 선호 하나이고 정량·실측 근거는 없다(**약함**). 재론할 때는 사용자에게 다시 묻는다.

## 근거

- 사용자 결정(2026-09-23, 위 인용).
- 코드 사실: 기본 레이아웃을 만드는 곳은 `ViewManager::new` 한 곳뿐이다. 다른 뷰 생성 경로는 이미 단일 슬롯이다 — 새 탭·새 창·대체 탭은 Empty, 팝아웃 대상 뷰는 옮겨 온 콘텐츠를 담은 단일 슬롯(조사 2026-09-23).

## 영향 / 불변식

- **부팅 기본 레이아웃 = 단일 Empty 슬롯.** 기본 모양을 단언하던 테스트가 새 기본을 단언한다. "부팅 기본은 Split"을 전제로 하던 테스트는 필요한 Split을 스스로 만든다.
- **첫 기동에 에이전트 트리가 없다.** 트리를 쓰려면 위 결정 2의 경로로 배치한다. 숨은 `/tree` 전용 창(`tauri.conf.json`의 agent-tree)은 이 결정과 무관하다.
- 부팅 포커스는 그 단일 Empty 슬롯이다.
