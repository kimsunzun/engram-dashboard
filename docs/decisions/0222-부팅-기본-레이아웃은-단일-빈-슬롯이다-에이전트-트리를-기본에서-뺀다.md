# ADR-0222: The boot default layout is a single empty slot (the agent tree is removed from the default)

- 상태: 확정 (2026-09-23, basis: user decision)
- 관련: Amends ADR-0063 (decision 2 boot default layout) · Amends ADR-0140 (decision 5 boot default layout placement) · ADR-0035 (layout authority = src-tauri) · `src-tauri/src/layout/manager.rs`(`ViewManager::new`)

> Note 2026-10-04 (decision unchanged): 「맥락」's 「레이아웃은 디스크에 저장되지 않아 매 기동이 이 기본값에서 시작한다」 (the layout is not saved to disk, so every launch starts from this default) is no longer a fact — since storage management P3b3 (`f9db35a`), the layout is persisted in `shell\state\state.json` and a boot after a normal exit restores it. This default layout is used **only when there is no state to restore** (first boot · an unusable file · after an abnormal exit, etc. — TRD `docs/process/S21-storage/trd.md` §6-5 · §11-4).

## 맥락

ADR-0063 decision 2 moved the fixed side panel into a slot and made the first view of the main window `Split[AgentList(좌) · Empty(우)]`. ADR-0140 decision 5 kept that placement, changing only the direction vocabulary. So the agent tree comes attached every time the client is launched. The layout is not saved to disk, so every launch starts from this default.

The user reported this as a defect (2026-09-23): "디폴트가 아무것도 없는거여야 되는데 에이전트 트리가 최초에 항상 붙어있더라고" (the default should be nothing at all, but the agent tree is always attached at the very start).

## 결정

1. **The first view of the main window also starts as a single Empty slot, the same as every other new view.** A new tab, a new window, and the replacement tab after the last tab is closed already do so. Boot being the only exception is removed.
2. **The agent tree is placed in a slot when needed.** It is placed through the empty-slot right-click menu (새 콘텐츠 → 에이전트 트리) or `layout.setSlotContent` (`{type:'agent_list'}`). It uses the generic placement path of ADR-0063 decision 1 as is, and creates no new surface.
3. ADR-0063 decisions 1 and 4 and the rest of ADR-0140's decisions remain valid. ADR-0063 decision 3 (removing the fixed side panel) is also valid, but the phrase in it, "AgentList exists only as a slot of the boot layout (2)", is read as "exists only as slot content" — the boot placement part is discarded together with decision 2. The item "ADR-0063 decision 2 reinterpretation" in ADR-0140's 「영향」 has also gone stale together with decision 5, for the same reason.

## 거부한 대안

- **Keep ADR-0063 decision 2 (boot default = AgentList·Empty split)**: the user decided that the default layout should be empty. The rejection basis is a single user preference, with no quantitative or measured basis (**weak**). When reopening, ask the user again.

## 근거

- User decision (2026-09-23, the quotation above).
- Code fact: the only place that builds the default layout is `ViewManager::new`. The other view-creation paths are already a single slot — a new tab, a new window and a replacement tab are Empty, and a pop-out target view is a single slot holding the moved content (survey 2026-09-23).

## 영향 / 불변식

- **Boot default layout = a single Empty slot.** The tests that asserted the default shape assert the new default. Tests that assumed "the boot default is Split" create the Split they need themselves.
- **There is no agent tree on first launch.** To use the tree, place it through the path of decision 2 above. The hidden `/tree`-only window (agent-tree in `tauri.conf.json`) is unrelated to this decision.
- The boot focus is that single Empty slot.
