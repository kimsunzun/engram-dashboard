## 맥락

- **3단계 = net 을 걷고 셸 · 데몬을 transport 에 붙인다.** 경계 리팩터링 작업 순서 3(메모 §10 「3. transport」)이고 단계는 3-1 protocol 정리 → 3-2 셸 부착 → 3-3 데몬 부착 + net 삭제다. transport 는 독립 crate 로 서서 단독 검증까지 끝났지만 소비자가 0 이다(ADR-0177 결정 1). 같은 일(핸드셰이크 · keepalive · 재연결 · 짝 맞추기)이 셸의 손짠 WS 클라(`daemon_client/connection.rs` · 동기 정지 클라 `stop.rs`)와 데몬의 net 서버 행(`net/src/ws.rs`)으로 세 벌이다. net 은 데몬 전용 서버 행 · 셸도 쓰는 인증 프레임 · 데몬 살림(단일 인스턴스 · daemon.json)을 섞고, protocol 은 command 의 구조체를 품는다(ADR-0272 가 걷기로 하고 착수를 이 단계로 미뤘다).
- **지금 내보내는 동작은 셸 하나 + 로컬 데몬 하나(1:1)이고, 다중 데몬은 바로 다음 단계다.** 사용자 지시(2026-10-12)는 셸 하나가 데몬 여럿에 붙고 데몬끼리 말하는 구조를 세우되 원격 적용 · 시험은 나중 트랙으로 두었고, 보안은 층을 나눠 암호화 · 상대 인증은 나중에 Link 층에서 빌리고 인가 · 페어링 · Origin · 자원 상한은 우리 몫으로 했다(TRD 머리 「결정 출처」).
- **붙이기 전에 transport 에서 결함 다섯을 찾았다**(TRD §3-0 — 정적 판독). 어느 것도 어댑터로 못 메운다 — 유실 · 순서가 crate 안에서 이미 정해진다.
  1. 받는 줄 유실 — 감독이 메시지 · 사건을 공유 줄 하나에 `try_send` 하고 차면 세기만 한다(`peer.rs:1224-1256`).
  2. 생애 사건도 같은 손실형 줄을 탄다.
  3. 재연결 창의 낡은 명령 — `ReconnectNow` 가 그 순간의 큐만 비우고 dial 해 그 창에 들어온 명령이 다음 세대에 쓰인다(`machine.rs:281-292` — ADR-0195 위반).
  4. 닫기 전 비우기가 없다 — `Peer::close` 가 제어 줄로 가 먼저 들리고 정리가 큐를 거절해, 앞서 넣은 정지 Ack · Error 가 사라진다(`peer.rs:282` · `:1177`).
  5. 핸드셰이크 거절이 늘 `GaveUp` 이다(`machine.rs:361-368`) — 다시 해 볼 거절과 끝난 거절을 못 가른다.
- TRD 는 다섯 판(리뷰 네 차례 · 매번 전원 FIX)을 거쳐 사용자 결정 목록 D1~D26 을 권고안이 첫째인 모양으로 올렸다(TRD §8-3). 2026-10-31 에 master 를 흡수해 다시 대조했고 어느 결정의 선택지 · 권고도 바뀌지 않았다(D18 ① 의 대가 한 줄만 늘었다 — 결정 24).

## 결정

표기: 각 결정 끝 괄호 = 정한 주체(**사용자** · **사용자 위임 — 메인 판단** · **권고안 채택 — 사용자 위임**). 세부 명세(가안 이름 · 상수 · 시험)의 정본은 TRD 5판이다. 아래 「가안」 값은 착지 때 메인이 정해 보고하는 내부 상수다.

### 단계

1. **D19 ① — transport 보강을 새 단계 3-0 에 전부 넣는다.** 상대별 무손실 수신단 · 생애 사건 · 세대 도장 · 보냄 칸 · 닫기 전 비우기 · 거절 분류 · Debug 가림 · 받는 쪽 seam · ws 수락 강화를 소비자가 0 인 지금 한 번에 고친다. 3-0 은 3-1 과 나란히 간다. (사용자)

### 구조

2. **D1 ① — 받는 쪽 seam = `Listener` trait + `Registry::attach`.** `Registry::new` 시그니처는 그대로다. 받은 상대는 Handshaking 에서 시작하고, Live 가 아닌 모든 끝(거절 · 핸드셰이크 시한 · 통로 손실 · Live 뒤 손실)에서 `Closed{generation, cause}` 를 내고 명부에서 스스로 내린다 — 다시 걸지 않고 세대 표에 들지 않는다. 수락 루프 · 상한 · 속도 정책은 소비자(데몬) 몫이다. (권고안 채택 — 사용자 위임)
3. **D2 ① — 관계마다 Wire · Registry · Listener 를 따로 둔다.** 셸↔데몬 = 지금 어휘의 `ShellWire` / `DaemonWire`. 다른 관계(데몬↔데몬)의 어휘가 드는 날 그 관계는 자기 Wire · Registry · Listener 를 갖는다 — 이번엔 짓지 않는다(결정 6). (권고안 채택 — 사용자 위임)
4. **D3 ① — 영속 데몬 신원 `DaemonId` + `Hello` 의 덧붙임 칸.** 데몬 상태 폴더에 처음 한 번 UUID v4 를 만들어 두고(자리는 데몬 `DataLayout` 이 소유) `Hello{.., daemon_id: Option<String>}`(`#[serde(default)]` · `PROTOCOL_VERSION` 그대로 · TS 바인딩 한 칸)로 알린다. 파일이 깨지거나 지워져 새 신원을 만들면 경고 로그를 크게 남긴다. `PeerId` 는 이름표로 남고 신원은 나중에 키에 묶는다(신원 ≠ 키). ★`DaemonId` 는 주장된 · 검증 안 된 id 라 그것을 키로 한 영속 신뢰(허용 목록 등)를 만들지 않는다 — 페어링으로 키에 묶기 전까지★. 셸 핸드셰이크의 기대 id 대조는 둘 다 있고 다를 때만 거절이며, 로컬 기대는 3단계 내내 `None` 이다(인메모리 시험으로만 선다). (권고안 채택 — 사용자 위임)
5. **D4 ① — 셸 다중 데몬은 어댑터 깊이까지 실물로 세운다.** 셸 어댑터가 `Registry` 하나에 상대 N 을 담고 윗층(`router` · `layout` · 명령)은 주 데몬 `primary()` 하나만 본다. 데몬마다 큐 · 재연결이 따로이고, 사건 · 출력 길찾기 상태는 `(DaemonKey, AgentId)` 로 키를 잡아 보낸 데몬의 목록에 없는 `AgentId` 의 사건 · 출력은 버린다. 주 데몬이 아닌 데몬의 `CommandRequest` 는 적용하지 않고 거절 답을 보낸다. 가짜 데몬 둘 시험이 이것을 잰다(3-2 U6). (사용자 위임 — 메인 판단)
   - 까닭: 다중 데몬 단계가 곧바로 이어진다. 이 깊이 — 연결 N 개를 섞지 않고 따로 둔다(데몬별 큐 · 재연결 · `DaemonId` · `(데몬, 에이전트)` 키 사건 · 주 데몬만 화면과 명령 · 가짜 데몬 둘 시험) — 는 다음 PRD 가 등록 · 화면 · 원격 · 오케스트레이션을 어떻게 답하든 필요하므로 모양을 잘못 짤 위험이 낮다.
6. **D5 ③ — 데몬↔데몬은 이번에 짓지 않고 다중 데몬 단계로 넘긴다.** `PeerWire` 뼈대 · protocol `peer` 어휘(`PeerAuth` · `Identify` · `Ping`) · 데몬 `link/peer.rs` · 둘째 Listener 를 3-3 U7 에서 뺀다. 남는 seam = 관계별 Wire · Registry(결정 3) · `DaemonId`(결정 4) · transport 의 상대 N 명부(ADR-0179 결정 3). (사용자 위임 — 메인 판단 · TRD 권고 ① 에서 바뀜)
   - 까닭: 데몬↔데몬 오케스트레이션의 모양은 다가오는 다중 데몬 PRD 가 정한다. 그 전에 `PeerWire` 뼈대를 세우면 모양이 틀릴 위험이 있다. transport 는 이미 상대 N 이라 데몬↔데몬을 나중에 붙여도 transport 를 다시 고칠 일이 없다.
   - ★사실 기록★: 사용자 지시 2026-10-12(TRD 머리 「결정 출처」 ①)는 「데몬끼리 서로 말하는 구조를 지금 3단계에서 세운다」였다. 2026-10-31 위임이 그 지시를 덮는지는 이 ADR 이 판정하지 않는다.

### 보안

7. **D26 ② + D22 ② — 같은 PC 의 다른 OS 사용자는 3단계 위협 모형 밖이다.** 3-3 U2 는 데이터 폴더 ACL 을 `icacls` 로 재어 기록만 한다. 데이터 폴더 소유자 · ACL 검사 없음 · 셸 daemon.json 읽기의 소유자 검사 없음(TRD §5 28) · 수락 칸 채우기 로컬 DoS(R11 — 「다시 연결」 버튼이 없는 동안 `GaveUp` 으로 굳는다)를 알려진 한계로 `docs/tracking.md` 와 사용자 문서(「다른 사용자가 쓸 수 있는 폴더에 풀지 말 것」)에 적는다. ADR-0135 의 열기 방식은 그대로다. 결정 14(D23) · 결정 15(D25)는 이 결정과 무관하게 든다. (사용자)
   - 사용자 까닭: 다음 단계인 다중 데몬(다른 PC 의 데몬에 붙기)은 보안 설계를 어차피 다시 해야 한다 — TLS · 원격 인증 · 기기 신원 · 권한 · 토큰 자리. 같은 PC 의 다른 사용자 파일 권한 문제는 그 재설계에 속하고, 지금 하면 같은 자리를 두 번 고친다.
   - TRD 까닭: 이 구멍은 지금 net · daemon.json 에도 똑같이 있고 3단계가 넓히지 않는다 · 막는 일(platform 보안 모듈 + 발견 · 시작 자리)은 연결 기계와 독립이라 따로 세워도 비용이 같다 · 포트 가로채기의 주 경로는 결정 15 가 위협 모형과 무관하게 닫는다.
8. **D6 ②′ — 인가는 「누구냐」만 지금: `admit` + `Principal` 보관.** `admit(attempt, &LinkInfo) -> Result<Principal, Refusal>` 이 attach 의 핸드셰이크 값 안에 `Principal`(지금 `LocalClient` · 나중 `PeerDaemon` · `Paired`)을 동기로 적고, 어댑터가 Live 때 ConnId 옆 표로 옮긴다 — 없으면 거부 · 닫기. 명령별 `allow` 는 짓지 않고 정책이 꽂힐 자리를 이름으로 박는다: 명령 입구 넷(ⓐ `connection_core` dispatch ⓑ `call_daemon_command`(ADR-0157 검문) ⓒ `/control/send` ⓓ `/control/messages`) + MCP 도구(`/mcp`) + 읽기 전용 둘(`/control/commands` · `/control/help`). (권고안 채택 — 사용자 위임)
9. **D7 ① — 인증 판정은 데몬 안 한 모듈(`link/auth.rs` — 판정 trait + 토큰 · 상수시간 비교 · 버전)이고 인증 프레임 `AuthFrame` 은 protocol 로 간다.** 3단계 끝 상태(TRD §0 ①)대로 net 의 나머지도 갈라 놓고 net crate 를 지운다 — 연결 기계 = transport · 데몬 전용 서버 행(읽기 task · 연결별 줄 · dispatch · bypass · 팬아웃) = 데몬 `link/server.rs` · 단일 인스턴스 · daemon.json = 데몬. ADR-0129 결정 1 의 「네트워크 lib」은 이렇게 흩어지고, 그 결정의 「에이전트 어휘를 타입으로도 모른다」는 데몬 `link/` 모듈의 끝자락 어휘 게이트 ① ② 가 잇는다. (권고안 채택 — 사용자 위임)
10. **D8 ① — Origin · Host 검사는 transport ws 수락 설정에 산다.** `AcceptPolicy` 는 필수이고 `Default` 가 없다 · 무검사 `WsListener::accept` 를 지운다 · 허용 정책은 이름이 위험을 말한다(가안 `AcceptPolicy::permissive_unsafe()` · `test-support` 뒤) · `transport::ws::split_link` 를 `pub(crate)` 로 내린다 · 값은 데몬이 준다. (권고안 채택 — 사용자 위임)
11. **D9 ① — 새 방어를 지금 넣는다:** 업그레이드 시한(TCP 수락부터 · 가안 1 s — 그 뒤 인증 시한 1 s 가 업그레이드 끝부터 이어 잰다) · 수락 분리 · 연결 수 상한 셋(업그레이드 대기 · 인증 대기 · 전체 — 상대 수명에 묶인 RAII 가드 · 넘치면 새것을 닫는다) · 양방향 메시지 상한 16 MiB · Host 검사(DNS 리바인딩) · `ws://` Listener 의 loopback 단언 · 수락 정책 필수 · 거절 보고(`AcceptRefusal` · 갈래별 시간 창 묶음 로그 · 토큰 없음). 인증 실패 속도 제한 · TLS 는 미룬다. (권고안 채택 — 사용자 위임)
12. **D20 ① — 인증 실패를 둘로 가른다.** 토큰 불일치 = `Retryable`(재연결 예산을 쓰고 접속 정보를 다시 푼다 — 지금 셸 동작) · 버전 불일치 = `Terminal`(예산 안 씀 · 즉시 팝업). 종류는 **닫기 코드**로 나른다 — 4001 = `Terminal` · 새 칸(가안 4006) = `Retryable` · 모르는 거절 코드 = `Retryable` · 맨 닫기 = 「못 붙음」. 팝업 문안은 닫기 코드별 고정 로컬 문구이고 상대가 준 글은 세부 · 로그로만 간다. 로컬 버전 불일치는 dial 전에 daemon.json 대조가 거르므로 접속 정보의 `VersionMismatch` → Dialer 거절 종류(가안 `DialFailure::Refused`) → `GaveUp(Rejected)` 로 같은 `Terminal` 이 된다(기제는 메인 판단). 그래서 ADR-0180 결정 5 의 「붙었다가 거절 = 예산 안 쓰고 첫 거절에서 즉시 팝업」은 버전 불일치로 좁혀진다. 상대 문구는 믿지 않는다(`DecodeFailed.reason` = 분류 문자열 · `Rejected.reason` 길이 상한 · 제어 문자 제거). (권고안 채택 — 사용자 위임)
13. **D21 ① — 릴리스 빌드는 Origin 이 달린 업그레이드를 전부 거부하고 dev 빌드만 허용 목록을 쓴다.** 운영 클라는 Origin 을 안 보낸다(가능성 높음 · 미실측 — 3-3 U5 의 `/qa full` 이 받은 업그레이드의 Origin 유무를 로그로 잰다). (권고안 채택 — 사용자 위임)
14. **D23 ① — `DaemonInfoDto` 에서 토큰을 뺀다**(3-2 U4 · 그 DTO 를 돌려주는 `discover_daemon` · `daemon_start` · `read_daemon_info` 셋 전부). 막는 것 = 토큰이 WebView 밖(다른 프로세스 · 직접 소켓)으로 나가거나 남는 것 · 못 막는 것 = WebView 발 제어(`forward_daemon_command` · `csp: null`). 운영이 아닌 직결 경로 `wsTransport.ts` 는 Auth 를 못 하게 된다(그 시험의 처분 포함). (권고안 채택 — 사용자 위임)
15. **D25 ① — 옛 주소 폴백을 공유 위반으로 좁힌다.** daemon.json 을 남이 공유를 막고 잠깐 쥐었을 때(platform `fs::is_sharing_violation`)만 마지막으로 안 주소로 건다. 없음 · 빈 · 깨짐 · 죽은 pid · 접근 거부 · 그 밖 I/O 오류 = 실패 한 번(예산) · dial 없음 · 다음 시도에 다시 읽기. 버전 다름 = `Terminal`(결정 12). 그래서 접속 정보 인터페이스의 `current()` 는 `Option` 이 아니라 갈래를 돌려준다(가안 `Live · Busy · Absent · Unusable · VersionMismatch`). (권고안 채택 — 사용자 위임)

### 스트림 · 큐

16. **D10 ① — transport 의 스트림 층을 두 소비자가 쓰지 않는다.** `ShellWire` · `DaemonWire` 의 `stream_mark` = `None` 이고 `resume_stream` 을 부르지 않는다. replay→live · gen 펜스 · 화신 표식 · seq 연속은 지금처럼 데몬 · 셸 `replay_flight` · 프론트가 진다. ADR-0177 결정 3 의 스트림 살림과 결정 9 의 유실 신호 · 구멍 재요청은 crate 에 남되 셸↔데몬 관계에서는 놀린다. (권고안 채택 — 사용자 위임)
17. **D11 ②′ + D24 ② — 받는 줄 = 상대별 무손실 수신단 + 배압이고, 포화 처분은 transport 에 넣지 않는다.** ADR-0177 결정 3 의 「유계 큐와 배압 신호」를 받는 쪽으로 넓히고 공유 줄 유실을 없앤다. (사용자)
    - transport: 상대마다 무손실 수신단을 돌려준다(훅 없음). 차면 그 상대의 소켓 읽기만 선다(TCP 배압). 바이트 예산은 셈 하나다 — `read_link` 가 앞잡이 줄에 넣을 때 더하고 소비자가 수신단에서 꺼낼 때 뺀다 · 「더하기 전 물높이」 판정 · 연결당 transport 층 상한 = B + M(가안 B = 16 MiB · M = 한 메시지 상한 16 MiB) · 개수 상한은 작은 프레임 홍수용으로 남는다(가안 셸 512 · 데몬 받은 상대 16). 사건 · 메시지는 상대별 한 줄에 도착 순서대로 탄다(감독의 상대별 순서 칸). 끝 원인은 읽기 끝 · 쓰기 끝을 가른다(가안 `ReadFailed` · `WriteFailed`).
    - 데몬: `link/server.rs` 가 연결마다 net 의 `read_task` 를 그대로 옮겨 소켓 대신 그 상대의 수신단을 읽는다 — 연결별 줄 · 바이트 예산 · 포화 처분 · `dispatch_task` · `bypass_task` · `finish_bypass_lane` 을 상수까지 코드째 옮긴다(우선 줄 참 = 기다림 유지 · ADR-0206 처분 무변경). 연결 수명은 끝 원인으로 가른다 — 읽기 끝 = 남은 것 비움(새 상한 가안 30 s 뒤 abort) · 쓰기 끝 = abort(net 그대로) · 데몬이 먼저 끝낼 때(`StopDaemon` 의 `ConnFlow::Close` · `Unanswered`) = 어댑터가 `close_after_flush(code)`.
    - 셸(D24 ②): 데몬마다 수신단 소비자 task 를 두고 Channel 로 넘기기만 한다. 합친 보기가 필요하면 셸 어댑터가 select 로 합친다(transport 표면 무변경). 생애 사건은 그 키의 지금 손잡이 · 주 데몬 것만 적용하고 `replay_flight` 를 `DaemonKey` 마다 둔다.
18. **D12 ① — 끊김 오류에 「보냈나」 칸을 둔다**(`RequestError::Disconnected{sent}` · 3-0 U2). 셸이 지금 가르는 두 글(결과 모름 · 안 나갔다)을 유지한다. 같은 단위가 세대 도장(부르는 쪽이 잡은 세대 — `notify_in` · `request_in` · 결정 1)을 함께 넣는다. (권고안 채택 — 사용자 위임)
19. **D13 ① — 팬아웃 포화 = 그 연결을 끊는다**(조용한 유실을 끊김 + 전량 replay 로 바꾼다). ADR-0177 결정 6 과 같은 선택이다. (권고안 채택 — 사용자 위임)

### 정책 값

20. **D14 ① — 재연결 횟수는 3-2 에서 5 를 주입하고, 「다시 연결」 버튼이 착지하는 날 3 으로 내린다.** ADR-0180 결정 4 의 「기본 = 3회」는 그 버튼이 있을 때의 값이다(같은 ADR 결정 7 이 3 을 떠받친다). 결정 12 로 토큰 거절도 이 예산을 쓴다. (권고안 채택 — 사용자 위임)
21. **D15 ① — 요청 시한은 30 s 를 공용으로 주입하고, spawn 실소요를 3-2 QA 에서 재 기록한 뒤 8 s 는 따로 다시 정한다.** `forward_daemon_command` 의 `REPLY_TIMEOUT`(30 s)를 걷고 나머지 핸들러는 없던 상한을 얻는다. ADR-0181 결정 1 의 「명령 무관 공용 하나」는 그대로이고 기본값 8 s 만 미룬다. (권고안 채택 — 사용자 위임)
22. **D16 ① — 데몬이 받은 상대의 나가는 큐는 4608(링 4096 + 512)을 유지한다** — transport 기본 512 를 덮어 주입한다. ADR-0177 근거의 「큐 상한이 되감기 링보다 크면 안 되는 이유」 문단을 이 결정이 고친다(거부한 대안 결정 22). (권고안 채택 — 사용자 위임)

### protocol (3-1)

23. **D17 ① — `OwnerToken` 은 protocol 사본이다**(newtype · 안쪽 문자열 그대로 직렬화 = 같은 바이트). 셸 · 데몬 끝자락이 command 타입과 옮겨 담는다. ADR-0272 영향이 이 TRD 에 남긴 열린 항목을 닫는다. (권고안 채택 — 사용자 위임)
24. **D18 ① — 원문 칸(`Box<RawValue>`)의 TS 는 `#[ts(type = ..)]` 덮어쓰기를 유지한다** — 생성 바인딩 바이트가 안 바뀐다. ADR-0272 영향의 「TS 바인딩에서 명령 칸 넷이 JSON 이 된다」를 대신한다. 대가: 손으로 쓴 TS 문자열이 drift 위험으로 남는다. ★master 흡수 재확인이 더한 대가(A3)★ — 그 drift 지킴이 `command_decl_hand_written_ts_matches_rust_shape`(`crates/engram-dashboard-protocol/src/messages.rs:1794`)는 protocol 안에서 `CommandDecl` · `AgentCommand` 를 만들므로 3-1 U5 가 protocol → command 간선을 걷으면 거기서 컴파일되지 않는다 → 데몬 또는 셸 시험으로 옮긴다. (권고안 채택 — 사용자 위임)

## 영향 / 불변식

- **받는 줄 불변식 다섯**(3-0 U1 이 transport lib 헤더에 박는다 — TRD §3-0 ①):
  1. 수신단 소비자는 `request()` 를 await 하지 않는다 — 배압으로 그 상대의 읽기가 서면 답장이 못 들어와 교착이다(요청은 따로 띄운 task 에서).
  2. 배압으로 붙든 동안 그 상대의 침묵 판정은 멈춘다 — 막힌 것은 우리 쪽이다. 자리가 나면 `last_rx` 를 그때로 둔다.
  3. 사건 · 메시지는 상대별 한 줄에 도착 순서대로 탄다.
  4. 데몬 쓰기 시한 대 셸 배압(R7)과 그 거울(셸도 쓰기 시한 5 s 를 새로 얻는다)은 실소켓 시험으로 잰다(3-2 U4) — 인메모리는 TCP 버퍼를 흉내 못 낸다.
  5. 모든 수신단은 끝(`Closed` · `None`)까지 비운다 — 끝을 `Peer::state()` watch 만으로 보지 않는다. 거꾸로 소비자가 수신단을 놓으면 감독은 곧바로 닫는다(대기 루프마다 `Sender::closed()` 갈래).
- **단계 계획:** 3-0 ∥ 3-1 → 3-2 → 3-3. 3-0 과 3-1 은 소스가 안 겹쳐 나란히 가되, 둘 다 고치는 게이트 줄(`ci.yml` · qa 바인딩)의 커밋은 3-1 U2 → 3-0 U7 → 3-1 U5 로 한 줄에 선다. 3-2 U2 는 3-0 U1~U5 뒤, 3-3 U4 는 3-0 전부 뒤다. 어느 커밋에서 멈춰도 빌드 · 회귀 · 게이트가 초록이어야 하고, 게이트 사본을 바꾸는 단위는 그 커밋에서 `/review doc` 을 거친다.

- **고치지 않고 확인만 하는 옛 결정:** ADR-0179 결정 3 은 결정 2 가 그대로 지킨다 · ADR-0206 의 처분과 우선 레인 대기는 결정 17 에서 그대로다(받는 자리만 소켓 → 수신단) · ADR-0157 은 결정 8 이 입구에 이름만 박는다 · ADR-0135 의 열기 방식은 결정 7 이라 그대로다 · ADR-0195 의 결정은 그대로이고 그 지킴이가 transport 세대 도장으로 간다 · ADR-0271 결정 5 는 3-2 U5 가 이행한다(일방 발사 그대로 — `stop.rs:13-15` 사용자 결정) · ADR-0177 결정 6 은 결정 19 와 같은 선택이다. ★TRD §6-5 가 개정 후보로 든 ADR-0036(재연결 · pending 소유 자리) · ADR-0130(대상 소멸)에는 이 ADR 이 도장을 박지 않았다★ — ADR-0036 의 「셸 Rust 가 연결을 소유한다」와 ADR-0130 의 「데몬은 한 crate 로 둔다」가 이 결정들과 어긋나지 않는다고 판단했다. 도장이 필요하다고 보면 `/adr link` 로 잇는다.
