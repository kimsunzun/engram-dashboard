# ADR-0338: 프리셋 편집 칸 = 초안 + [저장] — 저장은 목록을 통째로 덮고 마지막 저장이 이긴다 · LLM 버스 연산은 바로 적용

## 맥락
프리셋 편집(붙이기 · 빼기 · 순서 · 꼬리표)을 누가 어떻게 적용하나 — 화면 칸이 여럿일 수 있고 LLM · 손 고침도 같은 파일을 바꾼다. 옛 결정은 바로 적용이었다(메모 41 「no per-slot draft/save button (immediate apply)」 · 메모 83 「+ 담기」 팝오버 바로 적용 · 이 ADR 초안의 옛 판). 사용자가 2026-10-31 초안 + 저장으로 뒤집고(G52) 저장이 부딪힐 때를 메모장 규칙으로 정했다(G53). 검사 · 저장 검사 · 다시 연결과의 관계는 사용자가 관행에 맡긴 몫이라(G53) 메인이 정했다(M75–M85 — 재리뷰 r9) · 초안의 자리 · 닫기는 메인이 정했던 셸 메모리 꼴(M82)을 사용자가 따로 된 초안 파일로 바꿨다(G54 · G54-ADD).

## 결정
*초안*
1. 화면 편집 칸은 초안을 고친다 — 「+ 담기」 팝오버 체크도 초안에 든다 · 저장 안 한 상태는 표시한다 · [저장] 으로 데몬에 보낸다(G52).
2. **초안의 자리 = 셸 쪽 따로 된 초안 파일**(사용자 G54 — VS Code 핫 엑싯 꼴 · 메인 M82 의 셸 메모리 초안과 M77 의 「재시작 · 크래시에 잃음」 을 대체) — Engram 데이터 폴더의 셸 쪽(예 `shell\state\drafts\` — 파일 이름 · 꼴 = 클라이언트 단계)에 쓰고 라이브러리 폴더에는 두지 않는다 · 데몬 · 버스엔 초안이 없다(G52). 초안 파일의 열쇠 = **(라이브러리 번호 · 프리셋 경로) 짝** + `daemon_id` · 라이브러리 루트(M89-REVISED · M92 — S25 초안 P(미채번) 가 개인 데이터를 데몬 id 로 가르는 것과 같은 꼴 · 이름 · 치우기(지워짐 · 이름 바뀜 · 옮겨짐 — M91)는 클라이언트 단계에서 다시 본다) — Library n 에서 A 를 B 로 바꿔도(LLM · 묻지 않음) A 의 초안 파일은 남고 그 번호에서 A 로 돌아오면 ● 와 함께 되살린다 · 같은 프리셋을 연 두 슬롯 = 초안 둘 · 마지막 저장이 이긴다(G53). 그 번호를 다시 열면(재시작 뒤 · 크래시 뒤엔 복원을 받아들였을 때) 보기 상태가 마지막에 보이던 프리셋을 그 짝의 초안 · ● 와 함께 보인다 · 초안은 크래시 복원 답과 따로다 — 거절해도 지우지 않고 그 열쇠를 열 때 나타난다(M94) · 데몬 · 루트가 지금 라이브러리와 다르면 그 위에 되살리지 않고 남긴다 · 되살린 초안의 [저장] 은 지금 루트 세대(`library.status` — 세대는 메모리 값 · M14)를 보낸다(M92) · 같은 창이 받은 삭제 답은 그 초안 파일을 지우고 이름 바꾸기 · 옮기기 답은 다시 단다(결정 8 — M91) · 초안은 시작한 원본 판(`rev` — `preset.get` · M21)을 적어 두고, 되살릴 때 어긋나면 「원본이 그 사이 바뀜」 표시만 하고 그대로 붙인다([저장] 은 마지막 저장이 이긴다 — G53 · M96) · 유령 막기는 같은 창의 삭제까지다 — LLM · 다른 창 · 바깥이 지우고 다시 만든 것엔 그 표시와 함께 붙는다 · 일반 보장은 파일마다 안정된 정체가 있어야 한다(G38 · T-74 + ADR-0325 개정 — 지금 아님 · M96) · [저장] 이 성공해 저장 안 됨 표시가 지워지거나(초안이 아직 r — 결정 7) 「저장 안 함」 · [되돌리기](결정 10)를 고르면 지운다 · r 을 보낸 뒤 더 고쳤으면 초안 파일은 남아 그 뒤 고침을 지닌다(M88). 탭 옮기기 · 붙이기 · 떼기(사람 끌기 · 버스 `tab.move` · `tab.dock` · `tab.detach`)와 LLM 의 닫기 · 고르기 바꾸기는 초안을 지킨다 — 파일에 있으니 문 · `CONFLICT` 가 없다(G54). 되살린 초안의 원본이 그사이 바뀌었으면 [저장] 은 마지막 저장이 이긴다(G53 · 세부 = 클라이언트 단계). 초안 읽기 · 쓰기 = invoke 전용 셸 명령이고 셸 명령 표에 올리지 않는다(표는 22 그대로 · 버스엔 초안이 없다 — G52) · 셸에 내용은 불투명하고 꼴은 프런트가 정한다 · 셸 → agent 의존 없음은 그대로다(M93 · ADR-0270).
3. **초안 검사 = 데몬 읽기 `preset.check {path, instructions, skills, settings, presets}`** — 준 목록을 그 프리셋 자리에 넣어 실행과 같은 해석 함수로 돌리고 `preset.get` 과 같은 충돌 · 문제 꼴을 낸다 · 쓰지 않는다 · 클라이언트는 해석을 다시 짜지 않는다(M80 · TRD §1-3 「같은 함수」). 편집 칸 자기 검사(충돌 줄 · 문제 목록 · 팝오버 「이미 추가됨」 · 순환 흐림)는 초안 위에서 바로 · 라이브러리 전체 상태(트리 ⛔ · 실행 막힘 · 다른 칸)는 저장된 파일만 따른다(M75 — 편집기가 저장 안 한 버퍼에 진단을 보이는 꼴).

*저장*
4. **저장 = 버스 명령 `preset.save {path, instructions, skills, settings, presets, baseRev?}`** — 프리셋의 네 목록을 초안의 것으로 통째로 바꾼다 · 초안 연산을 합치지 않는다 · 화면은 `baseRev` 를 보내지 않는다 — 그사이 디스크가 바뀌었어도(다른 칸 · LLM · 손 고침) 덮는다 = **마지막 저장이 이긴다**(메모장 규칙 — G53). `baseRev` 는 선택이다 — LLM · CLI 가 읽은 뒤 주면 어긋날 때 `CONFLICT` · help 는 LLM 에게 `baseRev` 를 주거나 `add` · `remove` · `reorder` 를 쓰라고 이끈다(M84).
5. **저장 검사 = 전부 아니면 무** — 순환 · 틀린 종류 · `presets` · `settings` 항목의 꼬리표 · 꼴이 틀린 `AssetRef`(`LibPath` 나 `engram:/`) · 목록 안 겹친 항목이 하나라도 있으면 저장 전체를 거절한다 — 안정 코드 + 어긋난 항목 인자 · 아무것도 쓰지 않는다(M78 · M78-REVISED · M85). **없는 경로는 어긋남이 아니다** — 「찾을 수 없음」 줄은 정당한 내용이다(M78-REVISED). 보통은 편집 칸이 초안에서 이미 보이므로(결정 3) 어긋난 것이 저장까지 오지 않는다.
6. 쓰기 = 디스크의 지금 파일에서 그 목록으로 가는 고침을 계산해 `yaml-edit` 로 쓴다 — 주석 · 모양은 ADR-0333 대로(G53 — 메인 내부) · 쓰기 문이 거절하면 저장도 같은 코드로 거절된다(ADR-0333 결정 4). 그사이 그 프리셋이 옮겨지거나 이름이 바뀌거나 지워졌으면 `NOT_FOUND` — 옛 경로에 파일을 다시 만들지 않는다(부모 · 대상이 있는지 먼저 본다 · `write_atomic` 이 되살리지 않는다 — M76-REVISED-2 · M65).
7. **저장 상태 기계**(M81): 초안은 제 판 번호를 지닌다 · [저장] 은 판 r 을 보낸다 · 성공하면 초안이 아직 r 일 때만 저장 안 됨 표시를 지운다(그 뒤 편집은 저장 안 됨으로 남는다) · 거절(저장 검사 · 쓰기 문 · 루트 세대 · `NOT_FOUND` 등)이면 초안을 지키고 까닭을 보인다 · 성공해도 초안이 r 이 아니면 초안 파일은 남는다(M88 — 결정 2) · 「저장」 을 부른 닫기 · 바꾸기는 저장이 성공하고 **초안이 아직 보낸 판 r 일 때만** 이어 가고, 아니면(그사이 다시 연결 답 등이 초안을 고침) 그 자리에 남아 다시 묻는다(M81-AMEND · 프런트 시험에 그 끼어듦을 넣는다).

*다른 조작과의 관계*
8. **다시 연결 · 옮기기 · 이름 바꾸기와 초안**(M76 · M76-REVISED · M76-REVISED-2): [다시 연결] 은 바로 적용하는 라이브러리 전체 명령(`library.relink` — ADR-0330)으로 남는다. 그 명령과 `library.move` · `library.rename` 을 낸 **같은 창**이 받은 답의 옛 → 새 대응을 그 창의 열린 초안 줄에도 적용한다(초안 파일 포함 — 그 창이 연 초안 · 클라이언트 몫 — 그래야 뒤의 [저장] 이 그 고침을 되돌리지 않는다). 그 답이 열린 초안의 프리셋 자체를 옮기거나 이름을 바꿨으면 초안을 새 경로로 다시 단다 — 저장 대상 · 초안 파일 열쇠를 바꾸고 옛 초안 파일은 지운다 · 보기 상태의 선택도 같은 대응을 따른다(M91). 다른 창의 초안 · 어느 창도 열지 않은 초안 파일(예 LLM 이 탭을 닫은 뒤 — M88) · LLM 이 낸 명령은 초안에 들지 않는다 — 그런 초안을 나중에 저장하면 옛 경로를 되써 그 줄이 다시 「찾을 수 없음」 이 된다(다시 연결로 고친다 · G53 아래 받아들임). 새 방송을 만들지 않는다(「감시 · 방송 없음」 그대로).
9. LLM 의 `preset.add` · `remove` · `reorder` · `setBackend` 는 바로 적용하는 버스 · CLI 명령으로 남는다(버스엔 초안이 없다 — G52). 데몬이 「최신 파일 읽기 → 연산 → 원자적 쓰기」 로 적용 · 판 확인은 `reorder` 만(`baseRev` = 안정 내용 해시 — M21) · `add` · `remove` 는 낡은 판에도 경로로 멱등(M24-8). 명령 하나가 곧 저장 하나다 · 되돌리기 기록은 없다 — 잘못된 에이전트 편집은 다시 고친다(라이브러리가 git 저장소면 git 으로 · G54-ADD).
10. **닫기 · 바꾸기**(메인 — 관행 · G53 · 사용자 G54 · G54-ADD): 사람이 저장 안 된 그 탭 ✕ · 슬롯 닫기 · 그런 탭이 든 팝아웃 창의 앱 안 제목 줄 ✕(= 그 탭들을 닫는 것 — M87 을 M90 이 이것으로 좁힘) · 가운데 칸에서 다른 프리셋 고르기를 하면 「변경 내용을 저장할까요?」 [저장] [저장 안 함] [취소] 를 묻는다(저장 규칙 = 결정 7). 묻는 자리 = 초안을 쥔 웹뷰가 사람의 손짓 처리기 안에서 명령을 부르기 **전** — 셸 명령 · 레지스트리 · 버스 명령과 OS `CloseRequested` 는 묻지 않는다(팝아웃 닫기는 취소할 수 없다는 전제 — S21-slot-docking Q12 · `/qa` prevent_close 검사 — 를 지킨다). 그래서 팝아웃을 Alt+F4 · 작업 표시줄로 닫으면 묻지 않고 초안 파일이 남는다(LLM 이 닫을 때와 같다 · M90). 이 목록이 전부다 — 슬롯 메뉴 「새 콘텐츠」 · 끌어 놓아 `setSlotContent` · `slot.assignAgent` · `libraryView.reveal` · 폴더 이동 · 프리셋 아닌 항목 고르기는 일부러 묻지 않고 초안을 지킨다(M95). 대시보드 끝내기(트레이 「완전 종료」)는 묻지 않는다 — 초안 파일이 남아 다음 시작에 ● 로 되살린다 · main 창 ✕ 는 숨기기라 탭을 닫지 않고 묻지도 않는다(G54 · M87 · M95 · ADR-0026 · ADR-0229 — 관행: VS Code 는 저장 안 한 편집기가 든 마지막이 아닌 창을 닫을 때 묻고, 핫 엑싯은 앱 끝내기만 덮는다). 버스 · LLM 의 닫기 · 고르기 바꾸기는 묻지도 거절하지도 않는다 — 초안은 파일에 남는다(G54 — 옛 M82 의 `CONFLICT` · `--yes` 문과 OS 닫기 · 앱 끝내기 물음을 걷음). **[되돌리기]** = 초안 파일을 버리고 원본을 다시 읽어 ● 를 지운다(VS Code 「Revert File」 꼴 — G54-ADD · 자리(단추 · 메뉴 · 단축키) = 클라이언트 단계).
11. 에이전트 슬롯의 프리셋 붙이기 · 떼기 · 순서는 초안 없이 바로 적용한다(메인 — 관행 · 사용자 위임 G53) — 검증 뒤 프로필 편집 포트로 간다(M18) · 에이전트 `baseRev` = `default_preset` + `presets` 순서의 안정 해시(M25).

*화면*
12. 화면 꼴(표시 · [저장] · [되돌리기] 자리 · 모달)과 초안 파일(이름 · 꼴 · 되살리기 세부)은 클라이언트 단계에서 정한다(§5-4 · M77 · G54 · G54-ADD). 서버 단계 몫 = `preset.save` · `preset.check` · 버스 연산(데몬엔 초안이 없다 — G52).

## 거부한 대안
- **바로 적용 — 칸마다의 초안 · 저장 단추 없음**(메모 41 · 메모 83 「+ 담기」 팝오버 바로 적용 · 이 ADR 초안의 옛 결정 1) — 사용자가 뒤집었다: 「다 수정하고 저장 눌러야되는거 아님? 물론 저장안된건 마킹되있는게 맞고??」(G52).
- **저장 때 초안 연산을 지금 파일에 합치기 · 화면 저장에 「파일이 바뀌었습니다」 묻기(판 확인)** — 사용자 「A가 보는대상하고 B가 보는대상이 다르잖아. 노트패드 룰로 해야될듯? … 그냥 마지막으로 덮으면 되는거 아님?」(G53). LLM · CLI 의 선택 `baseRev` 는 이것과 다르다 — 주는 쪽이 고른다(M84).
- **저장 검사의 부분 적용**(맞는 줄만 쓰기 — `preset.add` 의 Δ7 · G41 꼴) — 저장은 통째 바꾸기라 사용자 초안의 줄을 말없이 버린다(M78).
- **없는 경로도 저장 거절** — 「찾을 수 없음」 줄은 정당한 내용이다(삭제는 되살리기 · 다시 연결까지 그 줄을 남긴다 — P3 · M4) · 막으면 그런 프리셋을 저장할 수 없다(M78-REVISED).
- **클라이언트가 해석을 다시 짜 초안을 검사** — 화면과 실행이 다른 규칙으로 갈린다(M80 · TRD §1-3 「같은 함수」).
- **초안을 셸 메모리에만 두기**(라이브러리 번호마다 `LibraryViewState` 곁 · `state.json` 에 쓰지 않음 — 메인 M82 · M77 · 이 ADR 초안의 옛 결정 2 · 10) — 재시작 · 크래시에 초안을 잃고, 버스 · LLM 의 닫기 · 고르기 바꾸기마다 `CONFLICT` · `--yes` 문이 들어야 했다(재리뷰 r10 NF1–NF5). 사용자가 따로 된 초안 파일을 골랐다 — 「ㅇㅇ ㅇㅋㅇㅋ … 클리쪽이라서 나중에 펼치면 되고」(G54 · VS Code 핫 엑싯 꼴).
- **초안을 원본의 OS 파일 정체에 묶기**(M91 의 첫 꼴 — 되살릴 때 정체가 어긋나면 붙이지 않고 고아로) — 원자적 쓰기가 저장마다 정체를 바꾸고(그러면 [저장] 뒤 고친 초안이 다시 켤 때 붙지 않는다) · ADR-0325 결정 5 가 정체를 훑기 변경 표시로만 한정하며 · 클라이언트는 그 값을 읽을 데가 없다(메인 2026-10-31 M96 — 재리뷰 r12).
- **번호만 열쇠로 하는 초안 파일**(Library1–4 — 번호별 보기 상태와 같은 꼴 · 메인 M89 의 첫 꼴) — 그 번호에서 LLM 이 프리셋을 바꾸면(묻지 않는다 — 결정 10) 앞 프리셋의 초안을 덮는다(메인 2026-10-31 M89-REVISED).
- **프리셋마다 초안 하나**(VS Code 의 공유 버퍼 꼴 — 같은 프리셋을 연 칸들이 한 초안을 함께 본다) — 웹뷰 사이 실시간 동기가 든다 · 단순함을 골랐다(메인 2026-10-31 M89 · M89-REVISED — 두 초안의 마지막 저장이 이김은 이미 받아들였다 · G53).
- **초안을 그 슬롯 웹뷰의 클라이언트 상태에만 두기**(TRD 첫 반영 꼴 · 재리뷰 r10 뒤 갈래 B) — 탭이 다른 창으로 옮겨지거나 LLM 이 닫기 · 바꾸기를 하면 초안을 잃는다(G54 가 따로 된 초안 파일로 정했다).
- **다른 창 초안 · LLM 이 낸 다시 연결까지 초안에 반영** — 방송이 없어 닿지 않는다 · 「감시 · 방송 없음」 을 지키고 G53 아래 받아들였다(M76-REVISED).
- (물음 사라짐) 옛 「전부 판 확인」 갈래 — 그 물음을 부른 낡은 화면의 「빼기」(PRD 리뷰 #23 뒤 절반)는 화면이 `add` · `remove` 를 보내지 않게 되어(결정 1 · 4) 없어졌다. 버스(LLM) 연산엔 결정 9 의 멱등 규칙이 그대로다(M24-8).

## 영향 / 불변식
- 화면 저장은 목록 넷만 보낸다 — 파일 바이트를 보내는 길이 없다 · 목록 밖 칸(`description` 등)은 저장이 건드리지 않는다.
- 마지막 저장이 이긴다 — 칸을 연 뒤 LLM · 다른 칸 · 손으로 바꾼 목록은 화면 저장이 덮는다 · 같은 창 밖에서 낸 다시 연결 · 옮기기 · 이름 바꾸기도 그런 초안의 저장이 되쓴다(받아들임 — G53 · M76-REVISED).
- 저장 안 한 초안은 셸 쪽 초안 파일로 재시작 · 크래시를 넘는다(G54 · 크래시 복원 답과 따로 — M94) · 대시보드 끝내기(트레이 「완전 종료」) · 팝아웃 OS 닫기는 묻지 않는다(M90 · M95). 초안을 라이브러리 폴더 · 데몬 · 버스에 두는 변경은 G52 · G54 를, 화면 저장에 판 확인을 더하는 변경은 G53 을 다시 연다.
- LLM 은 사람의 초안을 보거나 저장하거나 버릴 수 없다 — 알려진 갭(G52 · M93 · TRD §1-7 · §1-10 에 적음). CLAUDE.md 「LLM-우선 제어」 남은 갭에 그 줄을 더하는 것은 §5 15a 에서 사용자 확인을 받는다(CLAUDE.md 고침).
- 초안 검사는 실행과 같은 해석 함수 하나다(결정 3) — 클라이언트에 해석을 두면 M80 을 다시 연다.
- 프런트 시험 = 저장 상태 기계(M81 · M81-AMEND — 저장 중 초안을 고친 끼어듦 포함). 클라이언트 단계 메모(지금 바꾸지 않음): 겹친 저장 — 저장 답은 가장 최근에 보낸 판의 것일 때만 적용한다(M86) · 팝오버 흐림의 가정 답 · 후보마다 부분 추가(재리뷰 r9 N5) · 순서가 뒤바뀐 `preset.check` 답을 가르는 초안 판 표시(N6) · 초안 파일과 열린 초안 경로 고침 · 순서를 다시 본다(재리뷰 r10 NF3 · NF5 — G54) · 재리뷰 r11 N1 · N5 · N6 · N7 — 초안 파일 쓰기와 탭 옮기기 · 내림의 겨룸(보장은 마지막 쓰기까지) · 잃은 저장 답(파일과 같은 초안에 ●) · 다른 번호 밑 숨은 초안 · 쌓임 · 초안 파일 원자적 쓰기 = `base::file` 로 하되 상태 쓸기 밖 · 이름은 초안 저장소 소유(ADR-0264) · §5 12a · 13 의 작업 이름 · 재리뷰 r12 R2 · R3 · R4 — 다른 창 · LLM 의 이름 바꾸기로 남겨진 열린 초안(저장 `NOT_FOUND` → 다른 이름으로 저장 · 셸 자기 창 전부에 대응 나눠 주기를 본다) · 문은 메뉴 · 손짓 처리기만 감싸고 레지스트리 명령은 감싸지 않는다(뒤의 단축키 · 팔레트는 그 문을 거치거나 묻지 않음 · 팝아웃 제목 줄 ✕ 의 여러 저장 안 된 탭) · 이미 있는 열쇠로 다시 달기 · 다시 달기와 고르기의 차례 · 열쇠 안 루트 문자열 정규화.
- 주석 · 모양을 지키며 고쳐 쓰는 편집기 = ADR-0333 · 판 해시의 부품(SHA-256 · 원시 바이트 · 정규 인코딩) = ADR-0336 · 편집 · 저장이 `Catalog` 에 드는 차례(번호표 · 변경 세대) = ADR-0324.
