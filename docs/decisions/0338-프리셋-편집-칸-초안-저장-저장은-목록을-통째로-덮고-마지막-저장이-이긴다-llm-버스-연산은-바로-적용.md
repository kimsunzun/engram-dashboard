## 맥락
Who applies a preset edit (attach · detach · reorder · tags), and how? There may be several screen areas, and the LLM and hand edits change the same file too. The old decision was to apply immediately (memo 41 「no per-slot draft/save button (immediate apply)」 · memo 83 「+ 담기」 popover applies immediately · the old edition of this ADR draft). The user reversed this on 2026-10-31 to draft + save (G52) and set what happens when saves collide to the notepad rule (G53). The relation to checking · save checking · relink was left by the user to convention (G53), so the main session decided it (M75–M85 — re-review r9) · for the place and closing of the draft, the user replaced the shell-memory form the main session had decided (M82) with a separate draft file (G54 · G54-ADD).

## 결정
*Draft*
1. A screen edit area edits a draft — the 「+ 담기」 popover check also goes into the draft · an unsaved state is shown · [저장] sends it to the daemon (G52).
2. **The place of the draft = a separate draft file on the shell side** (user G54 — VS Code hot exit form · it replaces the main M82's shell-memory draft and M77's 「재시작 · 크래시에 잃음」) — written on the shell side of the Engram data folder (e.g. `shell\state\drafts\` — file name · form = client stage) and not placed in the library folder · there is no draft in the daemon · bus (G52). The key of a draft file = **a (library number · preset path) pair** + `daemon_id` · the library root (M89-REVISED · M92 — the same form as S25 draft P (unnumbered) separating personal data by daemon id · names · cleanup (deleted · renamed · moved — M91) are looked at again at the client stage) — even if Library n changes A to B (by the LLM · no asking), A's draft file remains, and if it returns to A at that number it is revived with ● · two slots that opened the same preset = two drafts · the last save wins (G53). When that number is opened again (after restart · after a crash when the restore was accepted), the view state shows the preset last shown with that pair's draft · ● · the draft is separate from the crash-restore answer — even if it is declined it is not deleted and appears when that key is opened (M94) · if the daemon · root differs from the current library, it is not revived on top of it and is left · the [저장] of a revived draft sends the current root generation (`library.status` — the generation is an in-memory value · M14) (M92) · a delete answer received by the same window deletes that draft file, and a rename · move answer re-attaches it (decision 8 — M91) · the draft writes down the original edition it started from (`rev` — `preset.get` · M21), and when revived, if it does not match, it only shows a 「원본이 그 사이 바뀜」 mark and attaches as is ([저장] is last save wins — G53 · M96) · ghost prevention goes only as far as a delete in the same window — what the LLM · another window · the outside deleted and recreated is attached together with that mark · a general guarantee needs a stable identity per file (G38 · T-74 + the ADR-0325 amendment — not now · M96) · it is deleted when [저장] succeeds and the unsaved mark is cleared (the draft is still r — decision 7) or when 「저장 안 함」 · [되돌리기] (decision 10) is chosen · if more edits were made after r was sent, the draft file remains and holds the edits after that (M88). Moving a tab · attaching · detaching (human drag · bus `tab.move` · `tab.dock` · `tab.detach`) and the LLM's close · change-of-selection keep the draft — it is in a file, so there is no gate · `CONFLICT` (G54). If the original of a revived draft changed in the meantime, [저장] is last save wins (G53 · details = client stage). Draft reading · writing is an invoke-only shell command and is not put in the shell command table (the table stays 22 · there is no draft on the bus — G52) · to the shell the content is opaque and the form is decided by the frontend · no shell → agent dependency stays as is (M93 · ADR-0270).
3. **Draft check = the daemon read `preset.check {path, instructions, skills, settings, presets}`** — put the given list into that preset's place, run it with the same resolution function as launch, and produce the same conflict · problem form as `preset.get` · it does not write · the client does not rebuild the resolution (M80 · TRD §1-3 「같은 함수」). The edit area's own check (conflict lines · problem list · popover 「이미 추가됨」 · cycle dimming) is directly on the draft · the whole-library state (tree ⛔ · launch blocked · other areas) follows only the saved file (M75 — the form where an editor shows diagnostics on an unsaved buffer).

*Save*
4. **Save = bus command `preset.save {path, instructions, skills, settings, presets, baseRev?}`** — replaces the four lists of the preset with those of the draft as a whole · it does not merge draft operations · the screen does not send `baseRev` — even if the disk changed in the meantime (another area · LLM · hand edit), it overwrites = **the last save wins** (the notepad rule — G53). `baseRev` is optional — if the LLM · CLI gives it after reading, `CONFLICT` on a mismatch · help guides the LLM to give `baseRev` or to use `add` · `remove` · `reorder` (M84).
5. **Save check = all or nothing** — if even one item has a cycle · a wrong kind · `presets` · `settings` item's tags · a malformed `AssetRef` (`LibPath` or `engram:/`) · an overlapping item in the list, the whole save is refused — a stable code + the mismatched item as an argument · nothing is written (M78 · M78-REVISED · M85). **A path that does not exist is not a mismatch** — a 「찾을 수 없음」 line is legitimate content (M78-REVISED). Usually the edit area already shows it on the draft (decision 3), so a mismatch does not reach the save.
6. Writing = compute the edit from the current file on disk to that list and write it with `yaml-edit` — comments · shape as in ADR-0333 (G53 — main internal) · if the write gate refuses, the save is refused with the same code (ADR-0333 decision 4). If that preset was moved, renamed or deleted in the meantime, `NOT_FOUND` — the file is not recreated at the old path (it first checks that the parent · target exist · `write_atomic` does not revive it — M76-REVISED-2 · M65).
7. **Save state machine** (M81): the draft carries its own edition number · [저장] sends edition r · on success it clears the unsaved mark only if the draft is still r (edits after that stay unsaved) · on refusal (save check · write gate · root generation · `NOT_FOUND` etc.) it keeps the draft and shows the reason · even on success, if the draft is not r the draft file remains (M88 — decision 2) · a close · change that called 「저장」 continues only if the save succeeded and **the draft is still the sent edition r**, otherwise (the relink answer etc. edited the draft in the meantime) it stays in place and asks again (M81-AMEND · that interleaving is put into the frontend test).

*Relation to other operations*
8. **Relink · move · rename and the draft** (M76 · M76-REVISED · M76-REVISED-2): [다시 연결] (relink) stays a whole-library command that applies immediately (`library.relink` — ADR-0330). The old → new mapping of the answer received by the **same window** that issued that command and `library.move` · `library.rename` is also applied to the open draft lines of that window (including the draft file — the draft that window opened · the client's share — so that a later [저장] does not revert that edit). If that answer moved or renamed the preset of the open draft itself, the draft is re-attached to the new path — the save target · the draft-file key is changed and the old draft file is deleted · the view-state selection also follows the same mapping (M91). Drafts of other windows · draft files that no window has open (e.g. after the LLM closed the tab — M88) · commands issued by the LLM do not go into the draft — if such a draft is saved later it writes back the old path and that line becomes 「찾을 수 없음」 again (fix it with relink · accepted under G53). No new broadcast is made (「감시 · 방송 없음」 as is).
9. The LLM's `preset.add` · `remove` · `reorder` · `setBackend` stay bus · CLI commands that apply immediately (there is no draft on the bus — G52). The daemon applies with 「최신 파일 읽기 → 연산 → 원자적 쓰기」 · edition checking only with `reorder` (`baseRev` = stable content hash — M21) · `add` · `remove` are idempotent by path even on an old edition (M24-8). One command is one save · there is no revert record — a wrong agent edit is fixed again (by git if the library is a git repository · G54-ADD).
10. **Close · change** (main — convention · G53 · user G54 · G54-ADD): when a person does the ✕ of that unsaved tab · closing the slot · the in-app title bar ✕ of a popout window holding such a tab (= closing those tabs — M90 narrowed M87 to this) · choosing another preset in the center area, it asks 「변경 내용을 저장할까요?」 [저장] [저장 안 함] (don't save) [취소] (cancel) (save rule = decision 7). The place it asks = **before** the webview holding the draft calls the command inside the person's gesture handler — shell commands · the registry · bus commands and the OS `CloseRequested` do not ask (this keeps the premise that closing a popout cannot be cancelled — S21-slot-docking Q12 · `/qa` prevent_close check). So closing a popout with Alt+F4 · the taskbar does not ask and the draft file remains (the same as when the LLM closes · M90). This list is all — slot menu 「새 콘텐츠」 · drag and drop `setSlotContent` · `slot.assignAgent` · `libraryView.reveal` · folder move · choosing a non-preset item deliberately do not ask and keep the draft (M95). Quitting the dashboard (tray 「완전 종료」) does not ask — the draft file remains and is revived with ● at the next start · the main window ✕ is hiding so it does not close tabs and does not ask (G54 · M87 · M95 · ADR-0026 · ADR-0229 — convention: VS Code asks when closing a non-last window that holds an editor with unsaved edits, and hot exit covers only quitting the app). The bus · LLM's close · change-of-selection neither asks nor refuses — the draft remains in the file (G54 — withdraws the `CONFLICT` · `--yes` gate of the old M82 and the OS close · app quit questions). **[되돌리기]** = discard the draft file and re-read the original to clear ● (VS Code 「Revert File」 form — G54-ADD · place (button · menu · shortcut) = client stage).
11. Attaching · detaching · reordering a preset in an agent slot applies immediately without a draft (main — convention · user delegation G53) — it goes to the profile edit port after validation (M18) · agent `baseRev` = `default_preset` + a stable hash of the `presets` order (M25).

*Screen*
12. The screen form (the indicator · the place of [저장] · [되돌리기] · the modal) and the draft file (name · form · revive details) are decided at the client stage (§5-4 · M77 · G54 · G54-ADD). The server stage's share = `preset.save` · `preset.check` · bus operations (the daemon has no draft — G52).

## 거부한 대안
- **Apply immediately — no per-area draft · no save button** (memo 41 · memo 83 「+ 담기」 popover applies immediately · the old decision 1 of this ADR draft) — the user reversed it: 「다 수정하고 저장 눌러야되는거 아님? 물론 저장안된건 마킹되있는게 맞고??」 (G52).
- **At save, merge the draft operations into the current file · ask 「파일이 바뀌었습니다」 on a screen save (edition check)** — user 「A가 보는대상하고 B가 보는대상이 다르잖아. 노트패드 룰로 해야될듯? … 그냥 마지막으로 덮으면 되는거 아님?」 (G53). The LLM · CLI's optional `baseRev` is different from this — the giver chooses (M84).
- **Partial application of the save check** (write only the lines that fit — `preset.add`'s Δ7 · the G41 form) — a save is a whole replacement, so it silently drops lines of the user's draft (M78).
- **Refuse a save for a path that does not exist too** — a 「찾을 수 없음」 line is legitimate content (a delete leaves that line until restore · relink — P3 · M4) · blocking it would make such a preset impossible to save (M78-REVISED).
- **The client rebuilds the resolution and checks the draft** — the screen and the launch would split into different rules (M80 · TRD §1-3 「같은 함수」).
- **Keep the draft only in shell memory** (for each library number beside `LibraryViewState` · not written to `state.json` — main M82 · M77 · the old decisions 2 · 10 of this ADR draft) — the draft is lost on restart · crash, and for every close · change-of-selection by the bus · LLM the `CONFLICT` · `--yes` gate had to be added (re-review r10 NF1–NF5). The user chose a separate draft file — 「ㅇㅇ ㅇㅋㅇㅋ … 클리쪽이라서 나중에 펼치면 되고」 (G54 · VS Code hot exit form).
- **Tie the draft to the original's OS file identity** (the first form of M91 — if the identity does not match when reviving, it is not attached and becomes an orphan) — atomic write changes the identity on every save (then a draft edited after [저장] does not attach when reopened) · ADR-0325 decision 5 limits the identity to the scan change marker only · and the client has nowhere to read that value (main 2026-10-31 M96 — re-review r12).
- **A draft file keyed by number only** (Library1–4 — the same form as the per-number view state · the first form of main M89) — if the LLM changes the preset at that number (no asking — decision 10) it overwrites the draft of the previous preset (main 2026-10-31 M89-REVISED).
- **One draft per preset** (VS Code's shared buffer form — areas that opened the same preset see one draft together) — it needs real-time sync between webviews · simplicity was chosen (main 2026-10-31 M89 · M89-REVISED — that the last save of two drafts wins was already accepted · G53).
- **Keep the draft only in the client state of that slot's webview** (the TRD's first-applied form · branch B after re-review r10) — if the tab is moved to another window or the LLM closes · changes it, the draft is lost (G54 decided a separate draft file).
- **Reflect even other windows' drafts · a relink issued by the LLM in the draft** — there is no broadcast so it does not reach · 「감시 · 방송 없음」 is kept and it was accepted under G53 (M76-REVISED).
- (question gone) the old 「전부 판 확인」 branch — the 「빼기」 of the stale screen that raised that question (the half after PRD review #23) is gone because the screen no longer sends `add` · `remove` (decisions 1 · 4). For bus (LLM) operations the idempotence rule of decision 9 stays as is (M24-8).

## 영향 / 불변식
- A screen save sends only the four lists — there is no path that sends file bytes · fields outside the lists (`description` etc.) are not touched by a save.
- The last save wins — lists changed by the LLM · another area · by hand after the area was opened are overwritten by the screen save · a relink · move · rename issued outside the same window is also written back by the save of such a draft (accepted — G53 · M76-REVISED).
- An unsaved draft survives restart · crash through the shell-side draft file (G54 · separate from the crash-restore answer — M94) · quitting the dashboard (tray 「완전 종료」) · the OS close of a popout do not ask (M90 · M95). A change that puts the draft in the library folder · daemon · bus reopens G52 · G54, and a change that adds an edition check to the screen save reopens G53.
- The LLM cannot see, save or discard a person's draft — a known gap (G52 · M93 · written in TRD §1-7 · §1-10). Adding that line to the remaining gaps of CLAUDE.md 「LLM-우선 제어」 gets user confirmation at §5 15a (CLAUDE.md edit).
- Draft check is one resolution function, the same as launch (decision 3) — placing resolution in the client reopens M80.
- Frontend test = the save state machine (M81 · M81-AMEND — including the interleaving where the draft is edited during a save). Client-stage notes (not changed now): overlapping saves — a save answer is applied only when it belongs to the most recently sent edition (M86) · the assumed answer of popover dimming · partial add per candidate (re-review r9 N5) · the draft edition mark that tells apart reordered `preset.check` answers (N6) · fixing the draft file and the open draft path · looking at the order again (re-review r10 NF3 · NF5 — G54) · re-review r11 N1 · N5 · N6 · N7 — the contest between draft file writing and tab move · lowering (the guarantee goes up to the last write) · a lost save answer (● on the same draft as the file) · hidden drafts under another number · accumulation · draft file atomic write = done with `base::file` but outside the state sweep · the name is owned by the draft store (ADR-0264) · the task names of §5 12a · 13 · re-review r12 R2 · R3 · R4 — an open draft left behind by another window's · the LLM's rename (save `NOT_FOUND` → save as another name · look at handing out the mapping to all of the shell's own windows) · the gate wraps only the menu · gesture handler and not registry commands (later shortcuts · palette go through that gate or do not ask · the several unsaved tabs of a popout title bar ✕) · re-attaching with an existing key · the order of re-attaching and choosing · normalizing the root string inside the key.
- The editor that rewrites while keeping comments · shape = ADR-0333 · the components of the edition hash (SHA-256 · raw bytes · canonical encoding) = ADR-0336 · the turn at which edits · saves enter `Catalog` (ticket · change generation) = ADR-0324.
