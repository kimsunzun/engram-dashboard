# ADR-0139: The launcher kills only its own distribution's daemon — image-name kill is abolished

- 상태: 확정 (2026-08-16, grounds: measured — in-progress work destroyed during development)
- 관련: ADR-0137(running dev and release together became the normal state) · ADR-0134/0135(connection key file = pid source) · ADR-0029(agents are children of the daemon) · `run-dashboard-release.bat` · `run-dashboard-clean.bat` · step-log S21

## 맥락

Both launchers kill a stale daemon so that the new build gets used, and the means was `taskkill /IM engram-dashboard-daemon.exe /F` — **it kills every daemon on this machine.**

Agents are **children of the daemon** (ADR-0029), so running the release launcher once during development **destroyed the agent work that was in progress** (measured, not an assumption). When ADR-0137 made running dev and release together the **normal behavior**, this blast radius grew larger.

## 결정

1. **Each launcher reads the pid from its own distribution's connection key file and kills only that pid.** Release = `target\release\data\daemon.json` · dev = repo-root `.engram-data\daemon.json`.
2. **Before killing, it checks two things together** — whether the image name is `engram-dashboard-daemon.exe` **and** whether the executable path is **this distribution's**.
3. **Cases where it kills nothing and states the reason:** connection key missing or unreadable · pid missing/0/not a number · dead pid · different image name · path cannot be verified (including permission denied — "could not verify" is not a pass).
4. **After killing, it checks again.** If the process is still alive it does not move on to build or launch and **aborts** — it does not trust the exit code of `taskkill`.

## 거부한 대안

- **Kill by image name (the previous behavior)** — it is the defect itself. Grounds for rejection = measured (destroyed another distribution's in-progress agents).
- **Fix only the release launcher** — the dev launcher had **the very same line**. Fixing only one side within a single change is self-contradictory in itself, and since ADR-0137 made dev↔release concurrent running the normal state, the side left alone causes the same accident. Grounds for rejection = code (identical line) + the consequence of ADR-0137.
- **Trust the pid alone** — pids get reused. **Killing someone else's process is worse than the stale daemon problem we are fixing.** Grounds for rejection = logic (asymmetry of harm).

## 근거

- Because of the structure where agents are children of the daemon (ADR-0029), killing the wrong daemon kills **all the work under it** — so in this one place, "kill less and state the reason" is better than "kill for certain."
- The reason a re-check after killing is needed: on a silent failure (permission denied · elevated daemon), **the stale daemon keeps holding the lock** and the newly built binary starts by seeing that daemon — exactly the state this step was meant to prevent.

## 영향 / 불변식

- **★Do not go back to `taskkill /IM`★** — both scripts carry a comment anchor.
- **★Residual TOCTOU (accepted)★:** the pid can be reassigned between the check and the kill. It is inherent in the structure and is stated in the script comments.
- **`/FO CSV` is load-bearing** — the default `tasklist` table truncates the image column to 25 characters (`engram-dashboard-daemon.e`), so the full-name comparison **never matches even once and every kill is skipped.**
- **The connection key path is handed to PowerShell through an environment variable and is not interpolated into a quoted string** — a checkout path containing an apostrophe (`C:\O'Brien\Engram`) breaks the string, and a crafted path can inject PowerShell.
- **The `[int]` cast is a guard, not decoration** — the returned value is expanded below **without quotes**, so a non-numeric `pid` becomes shell text injection. A missing field becomes `[int]$null = 0` and **hits the same check** as a literal 0.
- **Do not "point the CLI at the release daemon" with `ENGRAM_DATA_DIR`** — in ADR-0134 that variable is **also the single-instance scope**, so setting it makes the next daemon claim a different folder (a second daemon with its own registry quietly appears).
- **★Not verified★:** the kill path of `run-dashboard-clean.bat` **has never been executed** — only the release launcher side was sample-checked. It is registered as a tracked item.
