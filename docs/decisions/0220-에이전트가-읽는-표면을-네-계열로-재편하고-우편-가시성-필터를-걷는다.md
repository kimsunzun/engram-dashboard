# ADR-0220: 에이전트가 읽는 표면을 네 계열로 재편하고 우편 가시성 필터를 걷는다

- 상태: 확정 (2026-09-23, 근거: 사용자 결정)
- 관련: Amends ADR-0126 (CLI 와 MCP 철자 분리) · Amends ADR-0132 (그룹 help 발견 경로) · Amends ADR-0133 (우편 가시성 필터) · Amends ADR-0211 (지시서 포인터와 mail 하위 쪼개기) · Amends ADR-0212 (파일명과 구획 표시 꼴) · Amends ADR-0213 (지시서의 engram help mail 금지)

## 맥락

에이전트가 계약을 배우는 표면이 셋이었다 — 프라이밍(상주) · MCP 도구 설명(상주) · `engram help` 화면(온디맨드). 셋이 **같은 계약을 여러 벌 싣고 있었고**, 줄이려 해도 어느 쪽을 줄여야 하는지가 정해져 있지 않았다.

그 위에 셋이 겹쳤다.

1. **help 기계장치가 컸다.** 본문이 구획 17개로 쪼개져 고정 조립표가 화면마다 이어 붙였고, 그 조립·검증만을 위한 코드가 `engram.rs` 약 280줄(전체의 4.7%)과 테스트 16개였다. mail 만 하위 4장을 가졌고 그 id 는 동사 토큰에서 파생돼, 코드에 하위 주제를 더하면 파일에도 구획 둘을 함께 더해야 로드가 됐다.
2. **화면이 조건부라 사람과 에이전트가 다른 것을 봤다.** 우편이 목록에 보일지를 스폰 때 심는 `ENGRAM_MAIL` 표식이 갈랐다(ADR-0133 결정 1). 표식이 없으면 기본이 「보임」이라 **사람이 셸에서 친 화면에는 우편이 있고 에이전트 화면에는 없었다.** 이 세션이 그 착각으로 사용자에게 틀린 화면을 여러 번 보여 줬다.
3. **창·탭·분할·테마를 배울 자리가 없었다.** 루트 목록에 한 줄로만 서 있었고 자기 화면이 없어서, 에이전트는 17개 레이아웃 명령의 인자를 `engram commands` 로 하나씩 캐물어야 했다.

## 결정

1. **화면은 다섯 장이고 파일 구획과 일대일이다** — `root`(목차) · `mail` · `agent` · `window` · `theme`. 렌더는 조립이 아니라 **구획 하나 고르기**다. mail 하위 페이지와 그 파생 id 는 없앤다.
2. **프라이밍은 네 계열을 각자 명령으로 직접 지목한다**(`engram help mail` 등 네 줄). ★맨손 `engram help` 를 치라는 안내는 어느 표면에도 두지 않는다★ — 어느 장을 볼지 모른 채 목차부터 부르는 왕복을 없앤다. 목차 화면 자체는 남긴다(프라이밍을 못 본 사람이 셸에서 치는 자리).
3. **표면별 분담을 못 박는다.** MCP 도구는 **인자 설명만** 지고 그 정본은 입력 스키마의 칸별 설명이다. 그 밖의 계약(응답 행 읽는 법 · 봉투 · 함정)은 help 화면이 전부 진다. 프라이밍은 포인터와 다른 데서 못 배우는 것만 진다.
4. **우편 화면은 항상 보인다.** `ENGRAM_MAIL` 표식을 주입·독해 양쪽에서 걷고 `MailSurface` 를 삭제한다. ★강제는 손대지 않는다★ — `mail_allowed` 파생 · 자격증명 · 데몬 거절은 그대로다. 표식은 교육 축이었지 강제가 아니었다.
5. **CLI 우편 동사는 코드로 남기되 어느 화면에서도 가르치지 않는다.** 나중에 비-MCP 백엔드가 실제로 생기면 되살린다.

## 거부한 대안

- **에이전트가 help 파일을 직접 읽게 한다(`cat`/grep)** — ★경로를 알려줄 수단이 없다★. 설치본의 help 파일은 실행파일 옆 `prompts/` 에 있고 그 절대경로는 사용자가 어디에 풀었는지에 달려 고정값이 없다. 프라이밍 본문에 경로를 치환해 넣는 기계장치가 **0이고**(실측), codex 터미널 주입 경로는 백슬래시를 거절해 Windows 절대경로를 **아예 못 싣는다**. claude 는 본문이 아니라 파일 경로를 넘기는 방식이라 치환하려면 읽어서 다시 쓰는 단계가 새로 생긴다. `engram help <계열>` 은 PATH 의 바이너리 하나라 그 문제가 애초에 없다.
- **help 본문을 프라이밍처럼 상주로 밀어 넣는다** — 온디맨드 8.7KB 가 상주가 되어 이 라운드의 목적과 정면으로 어긋난다. 게다가 ★오늘 그대로는 불가능하다★ — 본문에 큰따옴표가 20개 있고 codex 터미널 주입 가드가 `"` 를 거절한다(실측).
- **주제별 하위 페이지를 유지한다**(`mail send`/`status`/`pending`/`recv`) — 화면당 크기는 작아지지만 그 조립을 떠받치는 기계장치가 약 280줄과 테스트 16개다. 값이 그 대가에 못 미친다.
- **목차 화면을 없애고 프라이밍이 대신한다** — 프라이밍을 못 본 사람이 셸에서 칠 자리가 남는다. 목차를 파일 구획으로 유지한다.
- **표식을 남긴다** — 사람 화면과 에이전트 화면이 계속 갈려 같은 착각이 반복된다. 감출 대상도 사라졌다 — 화면이 이제 MCP 도구만 가르치고 CLI 동사는 한 줄도 안 적는다.
- **표식 코드를 지우지 않고 주석으로 남긴다** — 주석 안의 코드는 컴파일러가 안 봐서 주변이 리팩터될 때 조용히 썩고, 되살릴 때 그대로 못 쓴다. 되살릴 근거는 git 이력과 이 ADR 이 진다.

## 근거

- **기계장치 실측** — `engram.rs` 5,959 → 5,682줄(−277). 재편 뒤 `--bin engram` 122건 · `--test engram_cli` 41건 전부 초록.
- **상주분 실측** — 도구 설명 둘이 합쳐 대략 820자 → 220자. 걷어낸 다섯 줄은 입력 스키마의 칸별 설명과 1:1 중복이었고, 스키마 쪽이 더 자세하다(`@here`/`@all` · 기한 하한 · 회신 배타).
- **주입 가드 실측** — codex 터미널 경로가 `'` `"` `%` `\` 를 거절한다. 위 두 대안을 막은 근거가 이것이다.
- **화면에 적은 명령이 전부 실재함을 카탈로그와 대조했다** — `tab.next`·`slot.empty` 둘은 프론트 버스가 등록해 소스 grep 으로는 안 보이지만 런타임에는 있다.
- **화면이 존재하지 않는 인자를 가르치고 있었다** — 초안이 `agent new --backend` 를 적었는데 하이픈 꼴은 `--cwd`·`--name` 만 받는다. agent 장을 점형으로 통일해 해소했고, 이것이 「한 파일 안에 두 호출 꼴이 섞이면 안 된다」의 실발생 근거다.

## 영향 / 불변식

- ★**구획은 다섯이고 화면과 일대일이다**★ — 하나라도 빠지면 파일이 통째로 거부되고 내장 사본이 나간다(반쪽 화면 금지 — ADR-0212 결정 4 그대로). 새 계열을 늘리면 코드의 `HelpTopic`·`required_section_ids` 와 파일 구획을 함께 늘린다.
- ★**인자 계약의 집은 입력 스키마의 칸별 설명 하나다**★ — 도구 설명문에 인자를 다시 적으면 그때부터 두 벌이 되고, 갈리는 날 어느 쪽이 참인지 알 수 없다. 고정 = `crates/engram-dashboard-daemon/src/control/mcp_server.rs` 의 `the_send_message_entry_teaches_its_own_call`.
- ★**「`pending` 으로 상대 상태를 단정하지 말고 조회하라」(ADR-0211 결정 2)의 집이 help 화면으로 옮겼다**★ — 계약은 유효하고 표면만 옮겼다. 고정 = `crates/engram-dashboard-daemon/src/bin/engram.rs` 의 `the_mail_screen_teaches_the_reply_contract`. 두 자리 다 비면 그 금지를 가르치는 표면이 하나도 안 남는다.
- ★**프라이밍이 가리키는 네 명령이 실제로 파싱되고 렌더되는가**★ — 고정 = 같은 파일의 `the_priming_pointer_names_a_help_entry_that_actually_renders`. 끊기면 에이전트는 **아무 오류도 없이** 표면을 영영 못 찾는다(양쪽 다 자기 파일 안에서는 멀쩡하다).
- **우편 강제는 이 결정이 건드리지 않는다** — `mail_allowed` 파생(`control/mod.rs`)과 데몬 거절(`mcp_server.rs`)은 그대로다. ADR-0133 의 나머지 결정(거절 응답이 대안 채널을 알리지 않는다)도 그대로 산다.
- ★**`ControlEndpoint.mail_allowed` 는 프로덕션 독자 0인 채로 남는다**★ — Rust 가 경고하지 않으므로 죽은 필드처럼 보이지만, 비-MCP 백엔드가 생기면 그 축이 다시 산다. 지우면 다음 설계가 그 경계를 없는 셈 치고 짠다. 자격증명 쪽 `TokenBinding.mail_allowed` 는 **별개 필드**이고 거절 미들웨어가 계속 읽는다.
- ★**ADR-0213 이 금하던 줄을 이번에 되살렸다**★ — 그 ADR 은 「지시서가 `engram help mail` 을 가리키면 그 줄은 자기 독자에게 **항상 실패한다**」를 못 박았다. 근거는 주입 조건(`wants_priming = uses_mail && accepts_mcp_config`)과 노출 조건(`mail_allowed = uses_mail && !accepts_mcp_config`)이 배타라 지시서를 받은 에이전트는 예외 없이 표식 off 라는 것이었다. **결정 4 가 그 전제를 죽였다** — 표식이 없으면 화면은 조건 없이 뜬다. 그래서 그 조항에 부분 폐기 도장을 박았다. ★표식을 되살리려는 편집은 이 줄부터 다시 읽을 것★ — 되살리는 순간 프라이밍의 네 줄이 다시 거짓이 된다.
- ★**에이전트 대면 표면의 언어(한국어 전환)는 이 ADR 이 결정하지 않는다**★ — 프라이밍과 도구 설명 둘이 한국어가 됐지만 **입력 스키마의 칸 설명은 영어 그대로**라 한 도구 안에서 언어가 갈려 있다. 한글은 글자 수를 줄이지만 토큰으로는 되레 비쌀 수 있고(≈1자/토큰 대 ≈4자/토큰) 아직 토크나이저로 재지 않았다. **사용자가 「나중에 영어로」로 미뤘다** — 그때 별도 ADR 로 박는다. 지금 상태를 결정으로 읽지 말 것.
