## 맥락

The step-21 TRD settled them (§3, §7, §8) and passed a deep review on 2026-11-21. The user took every recommended option (UD2–UD9) and replaced UD1 with ADR-0398. This ADR records what step-21 coding and step 9b anchor on.

## 결정
**Data and names**
1. **No migration (UD1, ADR-0398).** `library.json` is schema 2 only: `{"schema_version": 2, "mounts": [{"name", "path"}]}`, `path` = `"default"` or an absolute normalized folder, list order = the order shown; the built-in mount is not stored; no mount id (T-72 decides one). Schema 1 has no reader, so the base data-file rules treat it as corrupt. Paths already written are not rewritten: a root-relative path names an unregistered mount and reads absent; an attached `engram:/…` is an unparsed spelling and blocks that agent's launch until detached.
2. **Mount names (UD2 a)** = the rules of one `LibPath` segment (ADR-0362: Unicode allowed; no `/ \ :` or control character, not `.` or `..`, not ending in `.` or a space, no Windows device name), plus: no leading `.`; `engram` reserved, case-insensitive on every OS; unique by platform `path_key`; at most 64 characters. A name need not equal anything on disk. Mount lookup and `AssetRef::parse` compare names by `path_key`; `engram` is matched case-insensitively on every OS.
3. **First start (UD4 a)** — a missing `library.json` registers the default place `<dist>\library` (created) as one mount named `library` with `path` `"default"`.

**The virtual root**
4. `library.list` without `folder` and `library.folders` list the mounts, each with its last known `state` / `state_why` (no fresh stat; `library.status` stats). With no user mount the root still reads (only `engram`), never `library-unavailable`. `library.read` of a one-segment path answers `not-found`. A first segment naming no mount reads absent, never as a path under some default mount.
5. **Nothing is created at the top.** `library.newFolder` without `parent`, `library.newFile` without `folder`, and any write (in 9b also a move, rename or delete) whose target has one segment refuse `INVALID_ARGUMENT` `virtual-root-read-only`. A mount's top changes only through the mount commands; Engram never deletes a mount's real folder.
6. **Whole-tree reads answer partially.** `library.list {query}` without `folder` and `library.folders` answer from every usable mount and name each unusable one (`unavailable: [{mount, state, why}]`). A read whose range is inside one unusable mount refuses `library-unavailable` with `mount`.

**Mount commands and lifecycle**
7. **Commands (UD3 a).** `library.status` answers every mount (`mounts: [{name, path, default, builtin, state, state_why}]`; `root`, `root_setting`, `state`, `state_why` leave the top level). Four writes, each answering the status after the change: `library.addMount {name, path, create?}`, `library.removeMount {mount}`, `library.renameMount {mount, to, yes?, root_generation?}`, `library.relocateMount {mount, path, create?}`. `library.setRoot` is removed. New refusal codes: `mount-name-invalid`, `mount-name-taken`, `mount-overlaps {with}`, `mount-read-only`, `mount-unusable {mount, state}`, `mount-rename-unconfirmed {plan, root_generation}`, `mount-not-found`, `virtual-root-read-only`.
8. **Which folders (UD6 a).** Any absolute folder may be a mount (a git clone anywhere, a share, `~/.claude/skills`), refused only for overlap. A mounted outside folder is used in place, and Engram writes into it (preset edits, its `.trash`, its `.git/info/exclude`). A mount folder may itself be a link (junction or symbolic link); links inside a mount are still never followed (ADR-0365).
9. **Add.** `name` is required; no name is derived from the folder. The path is absolute and normalized, created first with `create`, and must stat as a folder through `BoundedIo`. Then, under a `Root` ticket, the new mount is walked and its range applied; other mounts' items stay. The answer counts `already_pointing {presets, agents}`.
10. **Overlap.** Add and relocate refuse `mount-overlaps {with}` when the folder is the same as a mount, inside one or containing one, or overlaps the data root (except the default place), the launch folder or the built-in folder (`LibraryValues` gains `data_root`). Overlap compares the canonical final paths (`BoundedIo` `canonical`, links and junctions resolved) of both sides and their ancestors by `path_key`, and also `file_identity` when the volume gives one. Relocate is judged against every other mount. **At load and at each boot** the saved mounts are checked again, in the background boot-scan job beside the bounded stat, not before the daemon answers (ADR-0382 decision 1); a mount overlapping an earlier one in the list stays registered but is not walked, its state `unreadable` with `why` naming the other mount, until the user relocates or removes it.
11. **Remove (UD8 a)** drops the registration only — no file is touched, ever — and asks no confirmation. Its range leaves the catalog; references to it become absent (ADR-0387); running agents are unaffected. The answer counts `now_absent {presets, agents}`; adding the mount back restores every reference.
12. **Rename (UD7 a).**
    - Refused `mount-unusable {mount, state}` when the mount itself is absent or unreadable.
    - Refused before any file is written when the plan touches an agent and the profile store is `ReadOnly` (ADR-0291), passing the store's refusal through (ADR-0379); `library-config-read-only` is checked first. A `Refusing` store is not refused here.
    - The plan is built only after every mount's first scan was applied. It lists the files to rewrite per mount, which mounts are git working trees, the mounts it could not read (their references stay broken, fixed by hand — ADR-0396 decision 3), the agents it would change, that files are rewritten whole (ADR-0358), and the references already pointing at `to`.
    - When any file would be rewritten: without `yes` nothing is applied and the answer is `CONFLICT` `mount-rename-unconfirmed {plan, root_generation}`; `yes` must carry that `root_generation` — without it the call refuses with the plan, a stale one refuses `root-generation-stale` with a fresh plan.
    - It then runs the **rename primitive**: one `Root`-ticket operation that, in one write-lock hold, rewrites references by a leading-names mapping in the preset files of every readable mount → raises the generation (root generation and change number) → rewrites agent attachments → re-keys the catalog range → renames the registration; the save follows the hold. A read or write failure stops the walk before the agents and the registration (ADR-0335 relink rule): written files point at `to`, the old name stays registered, and the same call finishes it. A stop at the agents step comes after the raise, so the answer carries the new `root_generation` for the finishing call. A case-only rename is allowed. The answer carries `fixed`, `written`, `skipped`, `stopped` and `already_pointing`.
13. **Relocate** re-points a mount at another folder under the same name; references do not change; same overlap rules as add (excluding the mount itself); the mount is re-walked.
14. **Repeat after a failed save** (ADR-0381 decision 3, `RETRY_AFTER_CONDITION_TAIL`). A mount change is published before `library.json` is saved; after `library-config-write-failed` (`config: unsaved`) the caller repeats the same call, and a call whose effect is already live answers success and saves again. The service keeps the mount list last saved:
    - `addMount` with the same name and folder live → success + save;
    - `removeMount` of a name not registered while `unsaved` and the last saved list still names it → success, 「not registered — saved only」; otherwise `mount-not-found`;
    - `renameMount X→Y` with `X` not registered, `Y` live, `unsaved`, and the last saved list naming `X` — judged before any generation comparison: no file still holds `X/…` → save without comparing; files still do → the plan with the current `root_generation`, and the `yes` call carrying it walks, then saves. Otherwise a rename of an unregistered `X` is `mount-not-found`;
    - `relocateMount` to the folder already live → success + save.
15. **Read-only config** refuses every mount command `library-config-read-only` before anything.

**Concurrency and scans**
16. **One library lock and one generation for the whole tree**; every mount change raises it, so an edit carrying an older `root_generation` is refused `root-generation-stale` whichever mount it touches. A mount change is a `Root` ticket: add and relocate walk the one mount and apply it under the write lock after dropping that mount's range; remove drops the range; rename is the primitive (decision 12), which cannot call `change_at` because a `Change` never enters behind a held `Root` ticket. Every mount command and the first start take the mount-change mutex (formerly the root-change mutex).
17. **Bounded stat before any walk ticket.** Every scan (boot, refresh, add, relocate) stats each mount it would walk through `BoundedIo` (share probe included) before drawing its ticket; a mount absent, unreadable or not answering is not walked and takes that state (ADR-0387). The first-scan answer is kept per mount; readers still wait at the first-scan entrance for the whole first scan. A mount not walked at boot is walked again by the next reader whose range touches it, or by a `refresh` of it, after a fresh stat.
18. **`agent.new {presets}` re-checks the change number inside the registry's locked insert.** The judgement notes `Numbers.change` (not the root generation); inside the registry's `try_mutate` section the current change number is compared. Equal → insert. Different → nothing is inserted, the mismatch is returned out of `create_agent` (registry lock and name-allocation gate released), and `verb_new` judges again under the library read lock and retries until they match, or answers that judgement's refusal. A re-judgement keeps the request's paths as given (an `old/…` path a rename moved away lands in `skipped` as `not-found`). No new refusal code. The library read lock is still released before `create_agent` (ADR-0386 decision 5). Lock order: the number read inside the registry lock takes only the gate's turn mutex (`Gate::numbers`), a leaf; the second judgement takes the library lock only after the registry lock is released. Every change that rewrites agents (the rename primitive, 9b's move) raises the change number before its agents pass.

**Launch, reads and the built-in**
19. **Per-mount root state.** `RootState::of` runs per mount. A mount not registered, or registered and absent → its items are `Missing`; a launch skips them with one `library-unavailable-skipped` per mount, args gaining `mount`. A mount that exists but cannot be read, did not answer, whose share is unreachable, or that overlaps another → ④ `LibraryUnavailable` with `mount`; a launch reaching it is refused with no folder IO and no command-line check. At the read entrances one ④ row stands for each unusable mount; other mounts expand normally. Built-ins never block. `agent.attachPreset` and `agent.new {presets}` keep the whole-call refusal per mount (`library-unavailable` with `mount`) when a named library preset's mount has no applied first scan.
20. **The built-in is the reserved read-only mount `engram` (UD5 B)**, always present, a view over `builtin.rs` (read once; joined by `file_of`, not scanned). Spellings `engram/default`, `engram/priming`, `engram/settings/default`; `AssetRef::parse` maps a first segment `engram` (case-insensitive) to `BuiltIn` and refuses any other name under it; `engram:/…` is refused `item-path-invalid` with a `why` naming the new spelling. `list engram` answers `default`, `priming` and the virtual folder `settings`; `library.read engram/default` answers the real file as `absolute`. Writes refuse `mount-read-only`; it is never renamed, removed or relocated and has no `.trash`. `library.list` loses its `builtins` flag and field. Kept: an unusable built-in is an empty stand-in with `builtin-unavailable` (ADR-0361), and `preset.get engram/default` keeps that notice; the `default_preset` bool.
21. **No read-only flag per user mount now (UD9 a).**
22. `PresetSection` words in `preset.reorder --section` become lowercase (`presets`, `instructions`, `skills`, `settings`, `folders`), a host-checked `String`; another word refuses `INVALID_ARGUMENT`.

**Trash, git exclude and the rules 9b inherits**
23. **Trash per mount.** Delete = rename into `<mount folder>\.trash\<bundle>\<MountPath>`; a bundle keeps the mount-relative path, so a mount rename does not break restore; restore returns into the same mount. Emptying covers every mount's `.trash` (9b decides the per-mount argument). A removed mount's `.trash` stays on disk, unreachable from Engram. Accepted: a bundle restored after a mount rename comes back with its `old/…` references (the rename walk skips `.trash`) — fixed by hand.
24. **Git exclude per mount.** Walk up from the mount folder through its parents for a `.git` entry — a folder, or a file (worktree or submodule) whose `gitdir:` leads to the common dir; write `info/exclude` in the common dir. For a mount in a subfolder of the repository the line is anchored: `/<mount path from the repository top>/.trash/`, with gitignore metacharacters escaped (`* ? [ # !`, a trailing space).
25. **Moves across mounts (step 9b builds them):**
    1. Refused when the target is inside the source (canonical path and identity, as overlap).
    2. On one volume: a no-replace rename (a new platform function; std `fs::rename` replaces); a taken name is a conflict.
    3. On different volumes: copy, only to names that did not exist; told apart by trying the rename and treating `ErrorKind::CrossesDevices` as 「copy」.
    4. Every entry of the source is copied (dot entries and files of no library kind included) except a mount top's own `.trash`; a link anywhere inside the source refuses the cross-volume move, naming the links, nothing moved. If anything could not be copied the original stays and the answer lists what was not copied.
    5. Before the original goes to trash: re-list the source and compare it entry by entry with the copy, and re-check the generation (a target mount removed or relocated meanwhile); a change stops the step and keeps both, answering the finished copy's path.
    6. Then the original goes into its own mount's `.trash` as one bundle. On any failure the original stays; a partial copy is never removed by name — it goes into the target mount's `.trash`.
    7. Overwriting move: copy to a new temporary name in the target, then the target's existing entry goes to the target mount's `.trash`, then a same-volume no-replace rename puts the copy in place; if that last rename fails, the entry is restored to its name and the copy's temporary name reported. A failed copy leaves the target's entry in place.
    8. The move and its reference fix are one hold (write lock), as the rename primitive: on one volume the rename, the catalog update and the reference walk; across volumes the source comparison, the original's trash step and the reference walk.
    - Copies keep Unix mode bits and never overwrite (base `copy_atomic` / `LibraryStore::copy` is not used), and go to a base temp-name shape first, then a same-volume no-replace rename (ADR-0335 decision 3). A copy across mounts = steps 3–4, no reference fix. Mount tops are never moved, renamed or deleted. 9b keeps the single generation and the ticket rules, and raises `Numbers.change` (not the root generation) inside the move's hold before its agents rewrite.

## 거부한 대안
- **Migrate the single root and the paths already written** (UD1 as first drafted: a schema-1 reader, rewriting attachments and preset files) — the review found five must-level defects inside that rewrite, for data only developers hold. 사용자 직접 기각 (ADR-0398).
- **UD2 b — ASCII lowercase identifiers `[a-z0-9-_]`** — avoids the case question across OSes, but the user's own examples are Korean (`업무/…`, `스킬/리뷰/review`). 약함 — 사용자 직접 기각.
- **Derive the mount name from the folder** — a derived name could be empty (`D:\`), start with `.`, be reserved, be too long or be a device name. Basis: decision 2's rules refuse each of these names.
- **UD3 b — keep `setRoot` as 「relocate the first mount」** — two commands would change a mount's folder. 약함 — 사용자 직접 기각.
- **UD3 c — one `library.setMounts {mounts}` whole-list write** — a rename hidden in a list diff cannot carry the plan or `yes`. 약함 — 사용자 직접 기각.
- **UD4 b — register nothing at first start** — against the user's earlier 「최초 디폴트 등록해둬」 (G35, ADR-0312 decision 5). 약함 — 사용자 직접 기각.
- **UD4 c — also ship a sample mount** — none exists yet. 약함 — 사용자 직접 기각.
- **UD5 A — keep `engram:/` and special-case `list` / `read`** — two reference forms everywhere, against ADR-0396 decision 2's one form. 약함 — 사용자 직접 기각.
- **UD6 b — only folders under one parent** — contradicts ADR-0396 decision 1's own example (a git clone anywhere). 약함 — 사용자 직접 기각.
- **UD7 b — rename runs and only warns** — it rewrites files in other git repositories, whole (TRD R4); the plan is the only guard. 약함 — 사용자 직접 기각.
- **UD8 b — `yes` to remove a referenced mount** — remove touches no file and adding the mount back restores every reference; no confirmation precedent was found. 약함 — 사용자 직접 기각.
- **UD9 b — a read-only flag per user mount now** — no precedent found. 약함 — 사용자 직접 기각.

## 영향 / 불변식
- `mounts.rs` is the only converter between `LibPath` (virtual, `<mount>/…` — catalog, references, wire, resolver) and `MountPath` (relative to one mount — the only path type the store takes and returns); the store stays mount-unaware, so a missed prefix or strip does not compile. The catalog is keyed by the virtual path.
- Every PC must register a shared mount under the same name (ADR-0396 「영향」); on a case-sensitive OS user mount names must match case exactly (`engram` excepted — TRD R7).
- Accepted risks (TRD §11): a mount change makes edits queued in every mount stale (R2); a mount that stats but walks slowly holds the one ticket line, and a rename on a slow share holds the write lock (R3); a rename rewrites files in other git repositories whole, uncommitted changes included (R4); overlap detection can be escaped where neither canonical paths nor identities agree (SMB without file ids, one share under several host spellings — R5); mounting a folder a backend also reads natively can load a skill twice and shows Engram's `.trash` there (R6); development data from before mounts is not carried (R8).
- Any new path that rewrites agent attachments must raise `Numbers.change` before its agents pass, or an `agent.new` judged before it can store an `old/…` path.
- `catalog_version` stays 9 (unreleased generation).
- Not decided here: a mount identity and per-PC data keyed by it (T-72), export / import (T-73), screens (steps 11–13), 9b's per-mount emptying argument.
