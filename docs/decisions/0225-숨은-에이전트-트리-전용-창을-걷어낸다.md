# ADR-0225: Remove the hidden agent-tree-only window

- 상태: 확정 (2026-09-24, basis: user decision + implementation `ab332a1` (2026-10-08 · `/review code full` PASS (one re-fix — a comment) · `/review doc light` FIX 9 applied → re-check PASS · `/qa full` PASS (measured in the GUI) — numbers · items = step-log) · the implementation settled the points this decision left open by main-session judgment — see 「구현 기록」 below)
- 관련: Amends ADR-0063 (the clause in decision 3 that keeps the tree-only window) · ADR-0057 (popout window = created at runtime) · ADR-0223 (split id — popout defect fix) · `src-tauri/tauri.conf.json` (the `agent-tree` window declaration) · `src/pages/TreePage.tsx` · `src/App.tsx` (the `/tree` route) · ADR-0283 (2026-10-08 — the shell creates static windows in setup, and that added code for the tree window · list = 「함께 바꿀 곳」 below)

## 맥락

`src-tauri/tauri.conf.json` statically declares an `agent-tree` window (`index.html#/tree`, `visible: false`), so a hidden copy of it starts along with the app every time.

- **Origin:** in the screen-skeleton phase (2026-06-08, `f2b38c4`), when the agent tree was a fixed sidebar of the main window, this window was hidden in advance as the destination of the 「트리를 별도 창으로 떼어 내기」 feature (detaching the tree into its own window).
- **After that:** ADR-0063 (2026-07-10) moved the tree into a slot and removed the sidebar, but decision 3 left the clause 「`/tree` 전용 창(TreePage)은 유지(별도 창)」 (keep the tree-only window (TreePage) as a separate window).
- **Now:** no code makes that window visible — the tray and the window-show code call only `main` (by search · likely, 2026-09-24). Yet one hidden window's worth of resources (a WebView2 renderer + the whole app code + subscriptions) runs every time, and exception handling for this window is scattered through the code (excluded from destination candidates · fallback to the main view · the declared-window list, and so on). **How to find it = `rg -n "agent-tree|#/tree|TreePage|TREE_WINDOW_ID|WindowKind::Tree|KindTag::Tree|TreeAttrs|StaticWindow::Tree" src src-tauri prompts`** (2026-10-08 — storage management widened the names and the help path) — ★`data-testid="agent-tree"` (`AgentList.tsx` and its test) is a tree DOM marker, not the window, so it is not removed★. ★**Hits that remain after the implementation (`ab332a1`) are intended leftovers — do not read them as unfinished work**★: the `data-testid` above · the removed-label test in `tests/layout_commands.rs` and its comment · the old-tree-entry regression test in `state/codec.rs` · the vocabulary generation 15 history in `layout/commands.rs`.
- **Replacement path:** to see the tree in a separate window, pop out the tree slot (ADR-0057 — ADR-0223 fixed the defect in that path). ★**It is not the same shape — the target of 「열기」 differs**★: the old `/tree` window opened into **main's active tab** through the `#/tree` → main fallback (the window-label resolution in `src/store/viewStore.ts`), while a popped-out tree opens into **its own window's tab** — the only slot in that tab is the tree, so until it is split, a message appears saying there is no empty slot (`selectOpenTarget.ts` · `AgentList.tsx`). Since nobody ever showed that window, no reachable behavior is lost, but 「따로 된 창의 트리로 main 에 열기」 (opening into main from a tree in a separate window) exists on no path after this decision.

## 결정

1. **Remove the `agent-tree` static window declaration, the `/tree` route, and `TreePage`.** Also clean up the exception handling that exists only for this window and the tests that assert it.
2. The way to see the tree in a separate window is **tree-slot popout** alone. No new surface is created.
3. Before implementing, re-check 「정말 아무도 띄우지 않는가」 (does nobody really show it?) — including whether the general-purpose commands that show a window by name (`window.*` · the LLM bus) can accept this label.

## 거부한 대안

- **Leave it as is** — user decision: "안쓰면 걷어내고" (2026-09-24). There is no reason to keep paying for one hidden window and its exception handling.
- **Build a new way to make it visible (tray menu · command)** — tree-slot popout already gives a way to see the tree in a separate window (see 맥락 for the 「열기」 target difference). Reviving that window would make a second surface doing the same job (CLAUDE.md 「LLM-우선 제어」 — no second surface).

## 근거

- User decision (2026-09-24).
- Code facts (2026-09-24 investigation + re-check in the doc review — certain): the only calls that make a window visible target `main` (`src-tauri/src/tray/actions.rs` · `src-tauri/src/lib.rs`), the frontend has no `.show()` or label-lookup calls, and the LLM `window.*` verbs are only create · close · list (create takes no label, and close answers `WindowNotFound` for this window, which is outside the model). `agent-tree` is mentioned only as a hidden-window exception.

## Implementation record (2026-10-08 — `ab332a1`)

- **Landing:** decisions 1–3 hold as written. ★The re-check in decision 3 found one new acceptor★ — the window theme commands (`window.getTheme`/`setTheme`) were accepting this label (「근거」 listed only create · close · list). What matches 「근거」 is the conclusion — there was no path anywhere that could make that window visible. The 「창 테마 명령의 계약」 item below removed that acceptance. The three items below (two hidden-window-only rules · the tree entry in the old `state.json` · the contract of the window theme commands) settle points this decision left open as implementation judgment — all three are **main-session judgment 2026-10-08 (not exposed to the user)** and are not user decisions. Gates · numbers = this round's entry in the step-log.
- **Removed the two hidden-window-only rules (implementation judgment on the second item of 「영향」).** One is the filter that dropped windows hidden by the config from the last-resort step of command destination picking (`hidden_window_labels` in `view_commands`); the other is the `focused(false)` branch in `build_static` that created windows hidden by the config without focus. The branch that creates main without focus on a `--hidden` boot stays. Reason for not keeping them as a general rule = a rule with no subject has nothing to test. ★**If a hidden static window is brought back, decide these two again**★ — left as is, that window could become a command destination as the first survivor in alphabetical order (answering success while applying to a window nobody sees), and on a visible boot it would take the foreground (the focus measurement in ADR-0283 「근거」). Even when filtering, do not exclude main on a `--hidden` boot (the `repick` comment).
- **A `kind:"tree"` window in an old `state.json` = the existing skipping of unknown window kinds.** That one window is skipped with a one-line warning (`WindowSkipped` · 「모르는 창 종류」) and the other windows are restored. The next save drops that entry. No recognizer dedicated to the old value was added — this follows the existing storage-management policy that the user is only the author and so old values are not handled (user decision U1 — TRD `docs/process/S21-storage/trd.md` §14-7). One codec test measures this behavior.
- **Contract of the window theme commands — `agent-tree` is now an unknown window.** It answers with the same error as any other unknown label (`CONFLICT`). Because the declaration changed, the vocabulary generation `CATALOG_VERSION` in the shell command table was raised from 14 to 15 (the convention is that it is raised by hand when a declaration changes — `crates/engram-dashboard-command/src/macros.rs`). The clause 「또는 트리 창 agent-tree」 in the help file was also removed.
- **Known limit ① of ADR-0283 (a dead registration left when only the tree window fails silently) no longer has a subject** — marked in that ADR's 「영향」. The discovery ensure serialization lock stays, per the last item of 「영향」, and only the rationale comment was fixed.
- **Code anchors:** no load-bearing place is left to attach a new anchor for this decision (it removes things). In the same round two more ADR-0283 anchors were added (the exit path on main creation failure in `lib.rs` · the default-folder fallback in `webview_env.rs`) — how to find them = `rg "ADR-0283"`.
