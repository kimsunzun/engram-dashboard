# ADR-0225: 숨은 에이전트 트리 전용 창을 걷어낸다

- 상태: 확정 (2026-09-24, 근거: 사용자 결정) · **구현 전**(다음 세션)
- 관련: Amends ADR-0063 (결정 3의 tree 전용 창 유지 구절) · ADR-0057(팝아웃 창 = 런타임 생성) · ADR-0223(분할 id — 팝아웃 결함 수정) · `src-tauri/tauri.conf.json`(`agent-tree` 창 선언) · `src/pages/TreePage.tsx` · `src/App.tsx`(`/tree` 라우트)

## 맥락

`src-tauri/tauri.conf.json` 에 `agent-tree` 창(`index.html#/tree`, `visible: false`)이 정적으로 선언돼 있어, 앱을 켤 때마다 숨은 채로 함께 뜬다.

- **유래:** 2026-06-08 화면 뼈대 단계(`f2b38c4`)에서 에이전트 트리가 main 창의 고정 사이드바였을 때, 「트리를 별도 창으로 떼어 내기」 기능의 목적지로 미리 숨겨 둔 창이다.
- **그 뒤:** ADR-0063(2026-07-10)이 트리를 슬롯으로 옮기며 사이드바를 걷었지만, 결정 3이 「`/tree` 전용 창(TreePage)은 유지(별도 창)」라고 남겼다.
- **지금:** 그 창을 보이게 하는 코드가 없다 — 트레이와 창 표시 코드는 `main` 만 부른다(검색 기준 · 가능성 높음, 2026-09-24). 반면 보이지 않는 창 한 벌(WebView2 렌더러 + 앱 전체 코드 + 구독)이 매번 돌고, 코드 곳곳에 이 창을 위한 예외 처리가 있다(`agent-tree` 언급 22 곳 — 목적지 후보 제외 · main 뷰 폴백 · 설정 창 목록 등).
- **대체 경로:** 트리를 따로 된 창으로 보려면 트리 슬롯을 팝아웃하면 된다(ADR-0057 — 그 경로의 결함은 ADR-0223 이 고쳤다).

## 결정

1. **`agent-tree` 정적 창 선언, `/tree` 라우트, `TreePage` 를 걷어낸다.** 이 창만을 위한 예외 처리와 그것을 단언하는 테스트도 정리한다.
2. 트리를 별도 창으로 보는 길은 **트리 슬롯 팝아웃** 하나로 둔다. 새 표면을 만들지 않는다.
3. 구현 전에 「정말 아무도 띄우지 않는가」를 다시 확인한다 — 창을 이름으로 띄우는 범용 명령(`window.*`·LLM 버스)이 이 label 을 받을 수 있는지 포함.

## 거부한 대안

- **그대로 둔다** — 사용자 결정: "안쓰면 걷어내고"(2026-09-24). 보이지 않는 창 한 벌과 예외 처리 비용을 계속 치를 이유가 없다.
- **보이게 하는 길(트레이 메뉴·명령)을 새로 만든다** — 트리 슬롯 팝아웃이 같은 모양을 이미 준다. 같은 일을 하는 두 번째 표면이 된다(CLAUDE.md 「LLM-우선 제어」 — 두 번째 표면 금지).

## 근거

- 사용자 결정(2026-09-24).
- 코드 사실(2026-09-24 조사): 창을 보이게 하는 호출은 `main` 대상뿐이고(`src-tauri/src/tray/actions.rs`·`src-tauri/src/lib.rs`), `agent-tree` 는 숨김 예외로만 언급된다(`src-tauri/src/view_commands.rs`·`src/store/viewStore.ts`·`src-tauri/src/ui_settings.rs`).

## 영향 / 불변식

- 정적 창은 `main` 하나가 된다 — CLAUDE.md 「창 구성」의 「정적 창 2개」 서술을 함께 고친다.
- 「설정이 숨긴 창은 목적지에서 뺀다」 같은 규칙은 대상이 사라지므로 걷거나 일반 규칙으로만 남긴다(구현 판단 — 숨은 창이 다시 생길 여지를 막을지는 그때 정한다).
- 창 label 목록을 단언하는 테스트·설정 검증(`ui_settings.rs` 의 선언 창 목록)이 바뀐다.
