# ADR-0225: 숨은 에이전트 트리 전용 창을 걷어낸다

- 상태: 확정 (2026-09-24, 근거: 사용자 결정 + 구현 `ab332a1`(2026-10-08 · `/review code full` PASS(재수정 1회 — 주석) · `/review doc light` FIX 9 반영 → 재확인 PASS · `/qa full` PASS(GUI 실측) — 수치 · 항목 = step-log) · 구현이 이 결정이 열어 둔 자리를 메인 세션 판단으로 정했다 — 아래 「구현 기록」)
- 관련: Amends ADR-0063 (결정 3의 tree 전용 창 유지 구절) · ADR-0057(팝아웃 창 = 런타임 생성) · ADR-0223(분할 id — 팝아웃 결함 수정) · `src-tauri/tauri.conf.json`(`agent-tree` 창 선언) · `src/pages/TreePage.tsx` · `src/App.tsx`(`/tree` 라우트) · ADR-0283(2026-10-08 — 정적 창을 셸이 setup 에서 만들며 트리 창 몫 코드를 더했다 · 목록 = 아래 「함께 바꿀 곳」)

## 맥락

`src-tauri/tauri.conf.json` 에 `agent-tree` 창(`index.html#/tree`, `visible: false`)이 정적으로 선언돼 있어, 앱을 켤 때마다 숨은 채로 함께 뜬다.

- **유래:** 2026-06-08 화면 뼈대 단계(`f2b38c4`)에서 에이전트 트리가 main 창의 고정 사이드바였을 때, 「트리를 별도 창으로 떼어 내기」 기능의 목적지로 미리 숨겨 둔 창이다.
- **그 뒤:** ADR-0063(2026-07-10)이 트리를 슬롯으로 옮기며 사이드바를 걷었지만, 결정 3이 「`/tree` 전용 창(TreePage)은 유지(별도 창)」라고 남겼다.
- **지금:** 그 창을 보이게 하는 코드가 없다 — 트레이와 창 표시 코드는 `main` 만 부른다(검색 기준 · 가능성 높음, 2026-09-24). 반면 보이지 않는 창 한 벌(WebView2 렌더러 + 앱 전체 코드 + 구독)이 매번 돌고, 코드 곳곳에 이 창을 위한 예외 처리가 있다(목적지 후보 제외 · main 뷰 폴백 · 선언 창 목록 등). **찾는 법 = `rg -n "agent-tree|#/tree|TreePage|TREE_WINDOW_ID|WindowKind::Tree|KindTag::Tree|TreeAttrs|StaticWindow::Tree" src src-tauri prompts`**(2026-10-08 — 저장 관리가 더한 이름과 도움말 경로를 넓혔다) — ★`data-testid="agent-tree"`(`AgentList.tsx` 와 그 테스트)는 창이 아니라 트리 DOM 표지라 걷지 않는다★. ★**구현(`ab332a1`) 뒤에도 남는 적중은 의도된 잔재다 — 못다 한 일로 읽지 말 것**★: 위 `data-testid` · `tests/layout_commands.rs` 의 걷은 label 시험과 그 주석 · `state/codec.rs` 의 옛 트리 항목 회귀 시험 · `layout/commands.rs` 의 어휘 세대 15 이력.
- **대체 경로:** 트리를 따로 된 창으로 보려면 트리 슬롯을 팝아웃하면 된다(ADR-0057 — 그 경로의 결함은 ADR-0223 이 고쳤다). ★**같은 모양은 아니다 — 「열기」의 대상이 다르다**★: 옛 `/tree` 창은 `#/tree` → main 폴백으로 **main 의 활성 탭**에 열었고(`src/store/viewStore.ts` 의 창 label 해석), 팝아웃한 트리는 **자기 창 탭**에 연다 — 그 탭의 유일한 칸이 트리라 분할하기 전까지는 빈 칸이 없다는 안내가 뜬다(`selectOpenTarget.ts`·`AgentList.tsx`). 그 창을 아무도 띄우지 않았으므로 도달 가능한 동작은 잃지 않지만, 「따로 된 창의 트리로 main 에 열기」는 이 결정 뒤 어느 경로에도 없다.

## 결정

1. **`agent-tree` 정적 창 선언, `/tree` 라우트, `TreePage` 를 걷어낸다.** 이 창만을 위한 예외 처리와 그것을 단언하는 테스트도 정리한다.
2. 트리를 별도 창으로 보는 길은 **트리 슬롯 팝아웃** 하나로 둔다. 새 표면을 만들지 않는다.
3. 구현 전에 「정말 아무도 띄우지 않는가」를 다시 확인한다 — 창을 이름으로 띄우는 범용 명령(`window.*`·LLM 버스)이 이 label 을 받을 수 있는지 포함.

## 거부한 대안

- **그대로 둔다** — 사용자 결정: "안쓰면 걷어내고"(2026-09-24). 보이지 않는 창 한 벌과 예외 처리 비용을 계속 치를 이유가 없다.
- **보이게 하는 길(트레이 메뉴·명령)을 새로 만든다** — 트리를 따로 된 창으로 보는 길은 트리 슬롯 팝아웃이 이미 준다(「열기」 대상 차이는 맥락 참조). 그 창을 살리면 같은 일을 하는 두 번째 표면이 된다(CLAUDE.md 「LLM-우선 제어」 — 두 번째 표면 금지).

## 근거

- 사용자 결정(2026-09-24).
- 코드 사실(2026-09-24 조사 + 문서 리뷰 재확인 — 확실): 창을 보이게 하는 호출은 `main` 대상뿐이고(`src-tauri/src/tray/actions.rs`·`src-tauri/src/lib.rs`), 프론트엔 `.show()`·label 조회 호출이 없으며, LLM `window.*` 동사는 create·close·list 뿐이다(create 는 label 을 안 받고, close 는 모델 밖인 이 창에 `WindowNotFound`). `agent-tree` 는 숨김 예외로만 언급된다.

## 구현 기록 (2026-10-08 — `ab332a1`)

- **착지:** 결정 1–3 그대로다. ★결정 3 의 재확인은 새 수락자 하나를 찾았다★ — 창 테마 명령(`window.getTheme`/`setTheme`)이 이 label 을 받고 있었다(「근거」는 create · close · list 만 들었다). 「근거」와 같은 것은 결론 쪽이다 — 그 창을 보이게 할 길은 어디에도 없었다. 그 수락은 아래 「창 테마 명령의 계약」 항목이 걷었다. 아래 세 항목(숨은 창 전용 규칙 둘 · 옛 `state.json` 의 트리 항목 · 창 테마 명령의 계약)은 이 결정이 구현 판단으로 열어 둔 자리를 정한 것이다 — 셋 다 **메인 세션 판단 2026-10-08 (사용자 비노출)** 이고 사용자 결정이 아니다. 게이트 · 수치 = step-log 의 이 라운드 항목.
- **숨은 창 전용 규칙 둘을 걷었다(「영향」 둘째 항의 구현 판단).** 명령 목적지 고르기의 마지막 수단에서 설정이 숨긴 창을 빼던 거르기(`view_commands` 의 `hidden_window_labels`)와, 설정이 숨긴 창을 포커스 없이 만들던 `build_static` 의 `focused(false)` 갈래다. `--hidden` 부팅의 main 을 포커스 없이 만드는 갈래는 남는다. 일반 규칙으로 남기지 않은 사유 = 대상이 없는 규칙은 시험할 것이 없다. ★**숨은 정적 창을 다시 들이면 이 둘을 다시 정한다**★ — 그대로 두면 그 창이 사전순 첫 생존자로 명령 목적지가 될 수 있고(성공을 답하며 아무도 안 보는 창에 적용), 보이는 부팅에서 전경을 가져간다(ADR-0283 「근거」의 포커스 실측). 거르더라도 `--hidden` 부팅의 main 은 빼지 않는다(`repick` 주석).
- **옛 `state.json` 의 `kind:"tree"` 창 = 기존의 모르는 창 종류 건너뛰기.** 그 창 하나를 경고 한 줄(`WindowSkipped` · 「모르는 창 종류」)과 함께 건너뛰고 나머지 창은 복원한다. 다음 저장이 그 항목을 떨군다. 옛 값 전용 인식기는 두지 않았다 — 사용자가 본인뿐이라 옛 값을 다루지 않는다는 저장 관리의 기존 정책(사용자 결정 U1 — TRD `docs/process/S21-storage/trd.md` §14-7)과 같은 쪽이다. 이 동작은 코덱 시험 하나가 잰다.
- **창 테마 명령의 계약 — `agent-tree` 는 이제 모르는 창이다.** 다른 모르는 label 과 같은 오류(`CONFLICT`)로 답한다. 선언이 바뀌었으므로 셸 명령 표의 어휘 세대 `CATALOG_VERSION` 을 14 → 15 로 올렸다(선언이 바뀌면 손으로 올린다는 규약 — `crates/engram-dashboard-command/src/macros.rs`). 도움말의 「또는 트리 창 agent-tree」 구절도 걷었다.
- **ADR-0283 의 알려진 한계 ①(트리 창만 조용히 실패한 죽은 등록)은 대상이 없어졌다** — 그 ADR 「영향」에 표시했다. discovery ensure 직렬화 락은 「영향」 마지막 항대로 남기고 근거 주석만 고쳤다.
- **코드 앵커:** 이 결정의 앵커를 새로 달 load-bearing 자리는 남지 않았다(걷은 쪽이라). 같은 라운드에 ADR-0283 앵커를 둘 더했다(`lib.rs` 의 main 생성 실패 종료 경로 · `webview_env.rs` 의 기본 폴더 물러남) — 찾는 법 = `rg "ADR-0283"`.
