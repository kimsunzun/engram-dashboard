# ADR-0278: OS 경계 게이트는 러프한 텍스트 검사와 의존 그래프 검사로 한다 — 린트 도구는 들이지 않는다

- 상태: 확정 (2026-10-06, 근거: 사용자 결정 2026-10-06 (U8 게이트 처리 — 「러프하게 · 범용적인 것만 막는다 · 문자열 비교 수준이면 된다」) + 관행 조사 `docs/research/os-boundary-enforcement-2026-10-06.md`(정정 2건 반영) + 착지 `c0ba4fa`)
- 관련: ADR-0266(불변식 「운영 OS 분기는 platform crate 안에만」 — 게이트 꼴을 메인 판단으로 남겼고 이 ADR 이 그 밖쪽 벽의 꼴을 정한다 · 개정하지 않는다) · ADR-0275(결정 15 의 시한부 예외 `src-tauri/src/fsutil.rs`) · ADR-0230(플랫폼 중립 — 개발 · CI 가 Windows 뿐인 현황) · `crates/engram-dashboard-platform/src/lib.rs` 헤더 게이트 ④ ⑤ ⑥ · 「하지 않는 것」 · `.github/workflows/ci.yml` 의 `platform gate 4` · `platform gate 5` · `platform gate 6` · `.claude/skill-bindings/qa.md` standard 4f · 4g · 4h · CLAUDE.md 「플랫폼 중립」 · TRD 1-3 §4-4 · step-log S21(1-3)

## 맥락

ADR-0266 이 「운영 OS 분기는 platform crate 안에만」을 불변식으로 세우고 게이트 꼴은 메인 판단으로 남겼다. 그 ADR 「영향」이 적은 게이트는 의존 상한 ① · `use tauri` 0 ② 둘이고, 둘 다 platform **안쪽**을 지킨다 — platform 밖에서 새는 OS 분기는 보지 않는다.

작업 순서 1-3 의 U8 이 그 밖쪽 벽으로 게이트 ④(platform 밖에서 OS `cfg` 술어를 쓰는 `.rs` 파일 목록 = 고정 명단)를 세웠다 — PCRE2 문법 정규식 하나 · 명단 33 · 결함 주입 44가지 통과. 그런데 `/review doc` 에서 codex 가 매 라운드 더 드문 Rust 꼴을 새로 짚어 FIX 를 냈다:

- 라운드 1: 중첩 · 여러 줄 `cfg`
- 라운드 2: 문자열 속 `[` `;` · 술어 밖 OS 낱말
- 라운드 3: `target_os /* c */ =` · 술어 안 raw 문자열
- 라운드 4(최종 확인): `cfg /* c */ (windows)` · `cfg!{windows}` · `cfg![windows]` · 19겹 중첩이 PCRE2 한도(실패로 떨어져 무음 통과는 아님)

재수정 3회 하드캡을 넘어 에스컬레이션했고 U8 은 미커밋으로 보류됐다. 이어 돌린 관행 조사는 OS 경계를 지키는 층이 셋(위치 · 의존 · 이식성)이고 서로 대신하지 않으며, 그때 의존 층과 이식성 층이 없었다고 정리했다(그 보고서 결론 4).

## 결정

1. **원칙 = 러프하게 · 범용적인 것만 막는다 · 문자열 비교 수준이면 된다**(사용자 2026-10-06). 게이트는 흔한 꼴을 막는 것이지 보증이 아니다 — 못 무는 꼴은 한계로 적고 쫓지 않는다. 적대 리뷰의 드문 꼴 추적은 더 하지 않는다.
2. **OS 경계 게이트는 셋이고 CI 에서 돌며 `/qa` 바인딩이 같은 것을 돌린다.**
   - **④ OS `cfg` 위치** — platform 밖에서 OS `cfg` 술어를 쓰는 `.rs` 파일 목록이 고정 명단과 정확히 같아야 한다(양방향 판정). matcher = PCRE2 문법 정규식 하나(`rg -P -U -l`). **지금 꼴로 닫는다.** 드문 꼴(`cfg_select!` · `cfg_aliases` · `cfg` 와 `(` 사이 주석 · `cfg!{…}` · `cfg![…]` · 깊은 중첩)은 platform 헤더 ④ 「한계」에 적는다. `cfg_if!` 는 안의 `#[cfg(…)]` 철자로 문다(실측 — 조사 정정 2026-10-06).
   - **⑤ OS crate 의존** — 워크스페이스 멤버 중 OS crate 를 **운영 의존**(normal · build — 대상 OS 무관)으로 **직접** 가진 것은 platform 하나여야 한다. OS crate 목록은 손으로 적는다(cargo-deny 식 명시 목록): `windows` · `windows-sys` · `winapi` · `libc` · `nix` · `rustix` · `objc2` 계열 · `objc` · `cocoa` · `core-foundation` · `core-graphics` · `security-framework` · `mach2`. 검사 = `cargo tree --workspace --no-dedupe … --target all`(cargo-deny 아님 — 우리 멤버만 본다). dev 의존은 허용한다(agent 의 `windows` dev = `examples/spike*.rs`).
   - **⑥ `std::os` 경로** — platform 밖 운영 코드에 `std::os::windows` · `std::os::unix` 가 나오면 빨강. 판정은 ④ 와 같은 방식의 파일 명단 대조(명단은 따로 — `platform gate 6` heredoc)이고 시험 파일은 명단으로 허용한다. matcher 는 `//` 주석 밖을 보는 텍스트 정규식(rg 기본 엔진)이다. 별칭(`use std::os as x`)은 놓치는 것을 감수한다.
3. **std 의 일반 API(`std::fs` · `std::process` 따위)는 대상이 아니다** — OS 에 맞게 알아서 바뀐다. 표준 라이브러리 쪽에서 막는 것은 `std::os` 하나다(사용자가 확인한 이해 2026-10-06).
4. **들이지 않는 것 = clippy `disallowed-*` · Dylint · cargo-deny · 교차 타깃 `cargo check`** — 메모만 남기고 macOS 이식 때 다시 본다(사용자 2026-10-06). ④~⑥ 은 이것들을 대신하지 않는다.

## 거부한 대안

- **게이트 ④ 의 정규식을 드문 꼴까지 계속 넓힌다** — 라운드마다 새 꼴을 FIX 하는 것, 그리고 U8 보류 때 메인이 추천한 「술어 앞 주석 · 다른 묶음 기호만 한 번 더 고치고 적대 라운드를 닫는다」를 포함한다. 기각 = 사용자 결정(러프하게) + 수렴하지 않았다: 적대 리뷰 4라운드가 매번 더 드문 꼴을 새로 짚었고 재수정 하드캡에 닿았다(「맥락」 — 리뷰 기록). 조사 범위 안에서 찾은 최고 선례인 rustc tidy `pal` 도 문자열 스캐너이고, `cfg_attr` · 앞선 doc 주석 뒤의 `cfg` 를 놓치는 것을 알고도 필수 게이트로 돈다(소스 대조 — 가능성 높음 · 빈틈은 코드 읽기). 비교한 항목에서는 게이트 ④ 가 그보다 넓게 문다(U8 결함 주입 44건). 조사 적합도 표의 비용 = 라운드당 코더 수십만 토큰.
- **정규식 대신 Rust 구문 분석 도구(syn 등)로 `cfg` 위치를 잰다**(U8 보류 때 선택지 c — 핸드오프 `20261006-073603` 「정지 조건」). 기각 = 범위가 크다 + 사용자가 지금 꼴로 닫기를 골랐다. **기각 근거 자평: 약함**(서술 — 비용을 재지 않았다). 사용자 확인 2026-10-06 — 약함 표시대로 확정.
- **clippy `disallowed-methods` / `disallowed-types` 로 `std::os` 를 막는다.** 기각 = 조사한 피어 중 이 도구로 `std::os` 경로를 막는 곳이 0 이라 관행이 아니다(조사 정정 2026-10-06 — deno 가 막는 것은 파일 시스템 함수 · `std::env::var` 이고 `std::os` 가 아니다). CI 에 clippy 가 없어(실측 — `ci.yml` 0건) 들이려면 CI 신설 · 기존 경고 정리가 따라온다. Windows 호스트에서는 `std::os::unix` 경로가 해석되지 않아 `allow-invalid = true` 가 필요하다(가능성 높음). clippy 는 `#[cfg]` 속성의 위치를 막지 못하므로(가능성 높음 — 그런 lint 를 못 찾았고 반증 없음) ④ 를 대신하지도 못한다. ★메인이 처음에 이것을 「`std::os` 금지 관행」으로 과장해 전했다가 정정했다★ — 이 대안을 다시 꺼낼 때 그 과장을 근거로 쓰지 말 것.
- **Dylint 커스텀 lint 로 `cfg` 위치 · `std::os` 경로를 컴파일러 수준에서 막는다.** 기각 = nightly 고정 · `rustc_private` · 드라이버 버전 고정 · 타깃별 실행 — 지키려는 경계에 비해 유지비가 크다(조사 「거부 후보」). **기각 근거 자평: 약함**(도구 요건은 문서 사실이지만 「유지비가 크다」는 우리 저장소에서 잰 것이 아니다). 사용자 확인 2026-10-06 — 약함 표시대로 확정.
- **cargo-deny `[bans]` `wrappers` 로 OS crate 의 직접 의존자를 제한한다.** 기각 = 규칙의 뜻이 「그래프 전체에서 명단만」이다(cargo-deny 문서 원문 — 확실). 그래서 tokio · mio 같은 서드파티가 `windows-sys` 를 직접 쓰면 그들도 명단에 올라야 하고 의존성 업데이트마다 흔들린다(가능성 높음 — 문서 의미에서 도출). 우리 목적은 「워크스페이스 안에서 platform 만」이라 우리 멤버만 보는 `cargo tree` 검사가 소음 없이 맞는다 — ⑤ 는 rename 을 단 대상 조건 의존과 build 의존을 결함 주입으로 잡았다(실측). CI 에 cargo-deny 도 없다(실측 — `ci.yml` 0건).
- **교차 타깃 `cargo check`(Linux · macOS 타깃)를 지금 세운다.** 미룬다 = 사용자 결정(macOS 이식 때 다시). 이 수단은 다른 층(이식성)이다 — 거짓 갈래의 `cfg` 는 그 타깃 컴파일에서 아예 빠지므로 위치를 강제하지 못하고(Rust Reference — conditional compilation), 조건 없이 쓴 OS 전용 코드와 다른 OS 에서 안 서는 코드를 잡는다. 비용은 실측 전이다 — build script 가 C 코드를 빌드하거나 네이티브 라이브러리를 찾으면 실패할 수 있고, 셸 패키지는 Linux 에서 webkit 계열을 요구해 처음부터 빼야 하며, CI 시간은 모른다. ★조사는 이 수단을 적합(○ — 별도 단위 · 실측 먼저)으로 매겼다★. **기각 근거 자평: 약함**(미룸의 근거가 사용자 판단뿐이고 비용을 재지 않았다). 사용자 확인 2026-10-06 — 약함 표시대로 확정. 지금 남은 큰 구멍이 이 축이다 — CI 가 Windows 뿐이라 조건 없이 쓴 OS 전용 코드가 통과한다(platform 헤더 「하지 않는 것」).

## 영향 / 불변식

- **정본 배치:** 정규식 · 판정 함수 · 명단은 `ci.yml` 의 `platform gate 4` · `5` · `6` 스텝 하나씩에만 둔다. `/qa` 바인딩 standard 4f · 4g · 4h 블록이 그것을 읽어 돈다(4f 는 대상 범위 · 짝 · 대조를 따로 되풀어 적는다 — 스텝을 고치면 함께 맞춘다). 짝 · 범위 · 한계 · 명단 고치는 법의 정본 = `crates/engram-dashboard-platform/src/lib.rs` 헤더 ④ ⑤ ⑥. 여기 베끼지 않는다.
- **세 게이트 모두 보증이 아니다** — 한계의 정본은 그 헤더다. 요지: ④ · ⑥ 은 명단 밖의 새 파일만 잡는다(명단에 든 파일 안에 더한 운영 분기 · 쓰임은 리뷰 몫) · ④ 는 `cfg` 없이 런타임에 OS 를 가르는 자리를 못 본다 · ⑤ 는 직접 의존만 보고 목록 밖 OS crate(`-sys` 형제 · `windows-core` 따위)나 OS API 를 감싼 서드파티를 못 본다 · ⑥ 은 별칭 · 묶음 `use` 와 다른 OS 모듈(`std::os::linux` · `std::os::fd` 따위)을 못 본다.
- **짝을 지우지 말 것** — 세 게이트 모두 platform 안쪽에서 1 이상을 요구한다. 정규식이나 `cargo tree` 출력 꼴이 망가지면 판정이 「위반 0」으로 눈먼다.
- **리뷰 문턱:** 이 게이트들을 건드리는 리뷰에서 드문 Rust 꼴 추적 라운드를 다시 열지 않는다(사용자 결정 — 러프하게). 리뷰 지시서에 「실제로 쓸 법한 꼴만 FIX」 문턱을 1라운드부터 박는다.
- **되열 조건:**
  - macOS 이식에 착수하면 교차 타깃 `cargo check` · clippy · Dylint · cargo-deny 를 다시 본다(사용자).
  - ⑤ 목록 밖의 OS crate 가 들어오면 그때 목록을 넓힐지 정한다(헤더 ⑤ 「한계」).
  - `cfg_select!` · `cfg_aliases` 가 저장소에 들어오면 ④ 가 못 본다 — 결정 시점 0건(실측 2026-10-06 — `rg "cfg_if!|cfg_select!|cfg_aliases"` 0)(지금 돌리면 platform 헤더 ④ 「한계」의 자기인용 두 줄이 걸린다 — 코드 쓰임 0).
