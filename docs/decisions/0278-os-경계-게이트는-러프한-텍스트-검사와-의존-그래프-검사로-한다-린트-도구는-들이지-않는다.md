# ADR-0278: The OS-boundary gates are a rough text check and a dependency-graph check — no lint tool is brought in

- 상태: 확정 (2026-10-06, basis: user decision 2026-10-06 (U8 gate handling — 「러프하게 · 범용적인 것만 막는다 · 문자열 비교 수준이면 된다」) + practice research `docs/research/os-boundary-enforcement-2026-10-06.md` (2 corrections applied) + landing `c0ba4fa`)
- 관련: ADR-0266 (the invariant 「운영 OS 분기는 platform crate 안에만」 — it left the gate shape to the main session's judgment and this ADR fixes the shape of the outer wall · it does not amend) · ADR-0275 (the time-limited exception `src-tauri/src/fsutil.rs` of decision 15) · ADR-0230 (platform neutrality — the current state where development · CI are Windows only) · `crates/engram-dashboard-platform/src/lib.rs` header gates ④ ⑤ ⑥ · 「하지 않는 것」 · `platform gate 4` · `platform gate 5` · `platform gate 6` in `.github/workflows/ci.yml` · `.claude/skill-bindings/qa.md` standard 4f · 4g · 4h · CLAUDE.md 「플랫폼 중립」 · TRD 1-3 §4-4 · step-log S21 (1-3)

## 맥락

ADR-0266 set up 「운영 OS 분기는 platform crate 안에만」 as an invariant and left the gate shape to the main session's judgment. The gates its 「영향」 lists are two, the dependency ceiling ① and `use tauri` 0 ②, and both guard the **inside** of platform — they do not see an OS branch leaking outside platform.

U8 of work order 1-3 set up gate ④ as that outer wall (the list of `.rs` files outside platform that use an OS `cfg` predicate = a fixed roster) — one PCRE2-syntax regex · roster of 33 · passed 44 kinds of fault injection. But in `/review doc`, codex pointed out a rarer Rust shape every round and issued a FIX:

- Round 1: nested · multi-line `cfg`
- Round 2: `[` `;` inside a string · an OS word outside the predicate
- Round 3: `target_os /* c */ =` · a raw string inside the predicate
- Round 4 (final check): `cfg /* c */ (windows)` · `cfg!{windows}` · `cfg![windows]` · 19-level nesting hits the PCRE2 limit (it falls to a failure, so it is not a silent pass)

It exceeded the hard cap of 3 re-fixes and was escalated, and U8 was put on hold uncommitted. The practice research run next summarized that there are three layers that guard the OS boundary (location · dependency · portability), that they do not substitute for one another, and that at that time the dependency layer and the portability layer did not exist (conclusion 4 of that report).

## 결정

1. **Principle = block rough · general things only · string-comparison level is enough** (user 2026-10-06). A gate blocks common shapes; it is not a guarantee — shapes it cannot catch are written down as limits and not chased. No more tracking of rare shapes in adversarial review.
2. **There are three OS-boundary gates, they run in CI, and the `/qa` binding runs the same ones.**
   - **④ OS `cfg` location** — the list of `.rs` files outside platform that use an OS `cfg` predicate must be exactly equal to the fixed roster (a two-way decision). Matcher = one PCRE2-syntax regex (`rg -P -U -l`). **Closed in its current shape.** Rare shapes (`cfg_select!` · `cfg_aliases` · a comment between `cfg` and `(` · `cfg!{…}` · `cfg![…]` · deep nesting) are written in the platform header ④ 「한계」. `cfg_if!` is caught by the spelling of the `#[cfg(…)]` inside it (measured — research correction 2026-10-06).
   - **⑤ OS crate dependency** — among the workspace members, the one that has an OS crate as a **runtime dependency** (normal · build — regardless of target OS) **directly** must be platform alone. The OS crate list is written by hand (an explicit list, cargo-deny style): `windows` · `windows-sys` · `winapi` · `libc` · `nix` · `rustix` · the `objc2` family · `objc` · `cocoa` · `core-foundation` · `core-graphics` · `security-framework` · `mach2`. The check = `cargo tree --workspace --no-dedupe … --target all` (not cargo-deny — it looks only at our members). Dev dependencies are allowed (agent's `windows` dev = `examples/spike*.rs`).
   - **⑥ `std::os` paths** — if `std::os::windows` · `std::os::unix` appears in production code outside platform, it is red. The decision is a file-roster comparison in the same way as ④ (the roster is separate — the `platform gate 6` heredoc) and test files are allowed by the roster. The matcher is a text regex that looks outside `//` comments (rg default engine). Missing aliases (`use std::os as x`) is accepted.
3. **std's general APIs (`std::fs` · `std::process` and the like) are not targets** — they change to fit the OS by themselves. What is blocked on the standard-library side is `std::os` alone (an understanding the user confirmed 2026-10-06).
4. **Not brought in = clippy `disallowed-*` · Dylint · cargo-deny · cross-target `cargo check`** — only a memo is left, to be looked at again at the macOS port (user 2026-10-06). ④–⑥ do not substitute for these.

## 거부한 대안

- **Keep widening the regex of gate ④ to rarer shapes** — this includes FIXing a new shape every round, and what the main session recommended when U8 was put on hold, 「술어 앞 주석 · 다른 묶음 기호만 한 번 더 고치고 적대 라운드를 닫는다」. Rejected = the user decision (rough) + it did not converge: 4 rounds of adversarial review each pointed out a still rarer shape and hit the re-fix hard cap (「맥락」 — review record). rustc tidy `pal`, the best precedent found within the research scope, is also a string scanner, and runs as a mandatory gate while knowing it misses `cfg_attr` · a `cfg` after a preceding doc comment (source cross-check — likely · the gaps are from reading the code). On the items compared, gate ④ catches wider than that (U8 fault injection 44 cases). The cost in the research fit table = several hundred thousand coder tokens per round.
- **Measure the `cfg` location with a Rust parsing tool (syn etc.) instead of a regex** (option c when U8 was put on hold — handoff `20261006-073603` 「정지 조건」). Rejected = the scope is large + the user chose to close it in its current shape. **Self-assessment of the rejection basis: weak** (descriptive — the cost was not measured). User confirmation 2026-10-06 — confirmed as marked weak.
- **Block `std::os` with clippy `disallowed-methods` / `disallowed-types`.** Rejected = among the peers researched, none blocks the `std::os` path with this tool, so it is not a practice (research correction 2026-10-06 — what deno blocks is file-system functions · `std::env::var`, not `std::os`). There is no clippy in CI (measured — 0 in `ci.yml`), so bringing it in would require setting up CI · cleaning up existing warnings. On a Windows host the `std::os::unix` path does not resolve, so `allow-invalid = true` is needed (likely). clippy cannot block the location of a `#[cfg]` attribute (likely — no such lint was found and there is no counter-evidence), so it cannot substitute for ④ either. ★The main session first overstated this as a 「`std::os` 금지 관행」 and then corrected it★ — do not use that overstatement as a basis when this alternative is raised again.
- **Block the `cfg` location · `std::os` path at the compiler level with a Dylint custom lint.** Rejected = nightly pinning · `rustc_private` · driver version pinning · per-target execution — the maintenance cost is large relative to the boundary it protects (research 「거부 후보」). **Self-assessment of the rejection basis: weak** (the tool requirements are documented facts, but 「유지비가 크다」 was not measured in our repository). User confirmation 2026-10-06 — confirmed as marked weak.
- **Restrict the direct dependents of OS crates with cargo-deny `[bans]` `wrappers`.** Rejected = the rule means 「그래프 전체에서 명단만」 (the cargo-deny docs, verbatim — certain). So if a third party such as tokio · mio uses `windows-sys` directly, they also have to be on the roster and it shakes with every dependency update (likely — derived from the meaning in the docs). Our purpose is 「워크스페이스 안에서 platform 만」, so a `cargo tree` check that looks only at our members fits without noise — ⑤ caught a target-conditional dependency with a rename and a build dependency by fault injection (measured). There is no cargo-deny in CI either (measured — 0 in `ci.yml`).
- **Set up cross-target `cargo check` (Linux · macOS targets) now.** Deferred = user decision (look again at the macOS port). This measure is a different layer (portability) — `cfg` on the false branch drops out of that target's compilation entirely, so it cannot enforce location (Rust Reference — conditional compilation), and what it catches is OS-specific code written without a condition and code that does not stand on other OSes. The cost is not measured yet — it can fail if a build script builds C code or looks for a native library, the shell package requires the webkit family on Linux and so has to be excluded from the start, and the CI time is unknown. ★The research rated this measure as fitting (○ — a separate unit · measure first)★. **Self-assessment of the rejection basis: weak** (the basis for deferring is only the user's judgment and the cost was not measured). User confirmation 2026-10-06 — confirmed as marked weak. The big hole left now is this axis — CI is Windows only, so OS-specific code written without a condition passes (platform header 「하지 않는 것」).

## 영향 / 불변식

- **Canonical placement:** the regex · decision function · roster live only in one step each of `platform gate 4` · `5` · `6` in `ci.yml`. The `/qa` binding standard 4f · 4g · 4h blocks read and run them (4f restates the target scope · pairing · comparison separately — fix them together when the step is fixed). The canonical source for pairing · scope · limits · how to fix the roster = `crates/engram-dashboard-platform/src/lib.rs` header ④ ⑤ ⑥. It is not copied here.
- **None of the three gates is a guarantee** — the canonical source for the limits is that header. Summary: ④ · ⑥ catch only new files outside the roster (a production branch · usage added inside a file on the roster is review's share) · ④ does not see a place that tells OSes apart at runtime without `cfg` · ⑤ sees only direct dependencies and does not see OS crates outside the list (`-sys` siblings · `windows-core` and the like) or third parties that wrap OS APIs · ⑥ does not see aliases · grouped `use` and other OS modules (`std::os::linux` · `std::os::fd` and the like).
- **Do not delete the pairing** — all three gates require 1 or more inside platform. If the regex or the shape of the `cargo tree` output breaks, the decision goes blind and reports 「위반 0」.
- **Review threshold:** in a review that touches these gates, do not reopen a round of tracking rare Rust shapes (user decision — rough). Put the threshold 「실제로 쓸 법한 꼴만 FIX」 in the review brief from round 1.
- **Reopening conditions:**
  - When the macOS port starts, look again at cross-target `cargo check` · clippy · Dylint · cargo-deny (the user).
  - If an OS crate outside the ⑤ list comes in, decide then whether to widen the list (header ⑤ 「한계」).
  - If `cfg_select!` · `cfg_aliases` enter the repository, ④ cannot see them — 0 at the time of the decision (measured 2026-10-06 — `rg "cfg_if!|cfg_select!|cfg_aliases"` 0) (if run now, the two self-quotation lines in the platform header ④ 「한계」 are hit — code usage 0).
