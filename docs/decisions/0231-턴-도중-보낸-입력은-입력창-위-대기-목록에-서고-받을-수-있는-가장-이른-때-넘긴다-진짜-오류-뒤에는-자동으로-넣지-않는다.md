# ADR-0231: 턴 도중 보낸 입력은 입력창 위 대기 목록에 서고 받을 수 있는 가장 이른 때 넘긴다 · 진짜 오류 뒤에는 자동으로 넣지 않는다

- 상태: 확정 (2026-09-26, 근거: 사용자 결정 PRD §2·§3·§9 와 TRD §10-1 + Phase 0·0b 실측 + TRD 8판 리뷰 7차 light PASS)
- 관련: Amends ADR-0044 (입력 시점 합성 에코는 한가할 때만) · Amends ADR-0045 (렌더 모델에 대기 목록 추가와 uuid dedup 범위 좁힘) · Amends ADR-0190 (턴 도중 사용자 입력은 가장 이른 경계까지만 붙든다 · Idle 사용자 우선 · halted · 재론 트리거 ② 발동) · Amends ADR-0198 (합성 에코는 한가할 때만 · 영향의 하이드레이션 순서 미결을 닫음(대기 → 이력 뒤 전달) · 보낸 자리 정식 말풍선 원안 거부) · Amends ADR-0193 (codex 통로의 넘기기 정책 steer와 Idle 순서와 오류 뒤 멈춤) · Amends ADR-0006 (입력 자물쇠 락 순서 줄과 그 안 팬아웃 예외 · replay → 대기 목록 표(잎)) · Amends ADR-0226 (D5 로딩 종료 조건을 전달된 입력의 말풍선으로 · 연결 중 거둔 첫 입력의 id 영속을 쓰레기 부류에 더함) · Amends ADR-0127 (턴 오류 신호와 last_end_failed 칸 추가) · Amends ADR-0110 (바쁨 판정 사실에 inputs_pending과 last_end_failed 추가) · Amends ADR-0104 (결정 3 idle 게이트의 한가에 사용자 목록 빔과 오류 뒤 멈춤 아님을 더함(상한 없음)) · PRD `docs/process/S21-codex-backend/prd-mid-turn-input-queue.md` · TRD `docs/process/S21-codex-backend/trd-mid-turn-input-queue.md`(§5 · §8 · §10) · `docs/research/mid-turn-input-display-2026-09-25.md` · `docs/research/mid-turn-phase0-measurements-2026-09-25.md` · `docs/research/mid-turn-phase0b-measurements-2026-09-26.md` · `docs/research/queued-input-after-failed-turn-2026-09-26.md` · 관련 ADR-0192 · ADR-0113 · ADR-0004 · step-log S21

## 맥락
구조화 채팅(JSON) 슬롯에서 에이전트가 턴을 도는 도중에 보낸 사용자 글을 어디에 보이고 언제 넘기나를 정해야 했다(PRD §1).

- **오늘 claude** — 글은 곧바로 stdin 으로 가고 에이전트도 도구 경계에서 읽는데, 화면은 **보낸 자리**에 정식 말풍선을 박는다. 앞 답의 나머지가 그 아래로 이어져 대화 순서가 에이전트가 읽은 순서와 어긋나 보이고, 보낸 뒤 거둘 길이 없다.
- **오늘 codex** — 턴 도중 글은 **턴이 끝날 때까지** 모델에게도 화면에도 가지 않는다(ADR-0190 의 큐). 한가할 때 보낸 글도 되울림이 올 때에야 뜬다. ADR-0198 은 「보낸 즉시 보낸 자리에 정식 말풍선」으로 정해 두고 구현하지 않았다.
- **공통** — 「보냈지만 에이전트가 아직 안 받은 글」이라는 상태가 화면 어디에도 없다.

조사(`docs/research/mid-turn-input-display-2026-09-25.md`)는 턴 도중 보내기를 막지 않는 것이 관행이고, 대기분은 대화 밖에 따로 보이며, 정식 말풍선의 자리는 보낸 때가 아니라 **전달 때**라는 것을 보였다(가능성 높음). 경위는 PRD 1–6판 → TRD 1–8판 → 리뷰(8판 7차 light PASS)이고, 그 사이 사용자가 Q1–Q9 · N1–N13 에 답했다(TRD §10-1 · PRD §9). ★결정 하나가 실측으로 뒤집혔다★ — 사용자는 처음 「두 백엔드 공통으로 받자마자 넘긴다」를 골랐으나(「클로드든 코덱스든 우리가 받고 바로 전달하자. 일단 공용화하고 나중에 세분화」), Phase 0 실측에서 codex 는 도구 **끝**까지 붙들어도 같은 경계에 들었다(M7 10/10 · claude 는 0/10). 사용자는 그 실측을 알고 원칙 「받을 수 있는 가장 이른 때 전달」을 세웠다 — 이것은 나중 일이 아니라 이 기능의 일부다(TRD §10-2).

## 결정
정본 문구는 PRD §2·§3(무엇)과 TRD §5·§8(어떻게)이다. 여기는 결정의 뼈대만 적는다. **범위 = JSON 모드의 사용자 입력만** — 터미널(PTY) 모드는 입력 바이트까지 오늘 그대로(사용자: 「터미널 모드는 그런거 필요없잖아」) · 에이전트 간 우편은 목록에 오르지 않는다.

1. **표시 = 입력창 위 대기 목록 · 정식 말풍선은 전달 자리(대화 끝).** 대기분은 대화 밖 상태이고, 에이전트가 받는 순간 대화 끝의 평범한 말풍선으로 옮긴다. 입력 시점 합성 에코는 **한가할 때만** 낸다(ADR-0044 · ADR-0198 개정). 하이드레이션 순서 = 대기 → 이력 뒤 전달 — ADR-0198 「영향」의 미결을 닫는다(TRD §8). 목록 머리줄은 없다. 접힌 목록 = 가장 오래된 3개 · 「외 N개」를 누르면 펼침 · 툴팁 전문(개수·모양은 나중 조정).
2. **전달 = 받을 수 있는 가장 이른 때.** claude 는 받자마자 stdin. codex 는 backend 안의 교체 가능한 넘기기 정책 `HandOverPolicy` 가 가장 이른 경계까지 붙든다 — 측정이 「늦지 않다」를 세운 구간(도구 구간 · M16 녹이면 답 구간)만 붙들고, 구간 판정이 모호하면 곧바로 넘긴다(디코더의 도구 호출 어휘만 도구로 센다). 진행 중 턴이면 넘기기 = `turn/steer`. 착지 = `Immediate` 뼈대(✕ 와 `withdraw` 포함) → 측정(M15 반응 지연 = 두 다리 + 리더 밀림 · M16) → `AtEarliestBoundary`. M15 가 빨가면 코드(붙듦 정책) 전에 멈추고 묻는다 · M16 이 빨가면 답 구간만 곧바로 넘기고 멈추지 않는다(PRD R8). (ADR-0190 · ADR-0193 개정 · 착지 순서는 TRD 가 정한 것 — 고름)
3. **✕ = 목록의 모든 항목에 늘 — 두 백엔드 · 어느 구간에서든 · 「목록에서 뺀다」.** 거둘 수 있으면 글도 거둔다(claude = 벤더 취소 요청 · codex 붙든 항목 = 통로 동사 `withdraw`, 벤더 호출 없음) · 이미 넘긴 codex 항목은 목록에서만 빼고 늦게 받히면 말풍선이 선다. 이 두 백엔드 체감 갈림은 ADR-0192 「못 맞추면 보고」로 적는다(PRD R3). 취소는 등록된 명령 하나(`CancelQueuedInput`)이고 LLM 도 목록의 어느 항목이든 같은 명령으로 부른다 · 목록 조회 = `ListQueuedInputs`. 툴팁 = 「목록에서 빼기」.
4. **✕ 는 모든 창에서 곧바로 감춘다.** 취소 대기는 어느 창에도 그리지 않고 LLM 목록(`cancelling`)에만 보인다.
5. **결말은 수명주기로.** claude 취소 응답 `false`·오류는 `cancelled` 의 원인 귀속에만 쓰고 「전달됨」으로 읽지 않는다 · 응답 `true` 는 벤더가 뺐다는 답이라 곧바로 취소됨 · 취소 요청이 실패해도 항목을 되돌리지 않는다.
6. **거둔 글·못 보낸 글은 버린다 — 입력창 복귀 없음 · 알림 없음.** 한가할 때 그린 말풍선이 거절되면(`Dropped{Rejected}`) 알림 없이 지운다 · 받음 뒤 거절도 같다. 처리 전에 끊기·에이전트 종료를 만난 한가 말풍선은 남긴다(N9 — 사용자: 「그냥 별도로 뭐 해야되는게 있음? resume 하면 어차피 갱신될텐데」).
7. **사용자 입력이 우편보다 먼저.** 우편의 한가 = 도는 턴 없음 ∧ 사용자 목록 빔. 커널 바쁨 판정 = `in_turn ∨ inputs_pending ∨ last_end_failed`(`BusyPolicy` · 사실은 `TurnFact` — ADR-0110 개정). `inputs_pending` 의 출처는 턴 관측 표와 별개의 대기 목록 표이고 명부가 비는 순간 flush 초인종을 울린다. **fail-open 상한이 없다** — ADR-0113 「안 가는 것 > 늦게 가는 것」 · 30 분 상한 = ADR-0127 결정 4 의 의도된 예외(사용자 결정 N8 · 게이트는 ADR-0104 결정 3). **후속 턴 빚** = codex 사용자 글이 기록만 되고 답을 못 받으면 빈 `turn/start` 후속 턴 하나로 답하게 하는 빚이다(PRD §3-1 · AC6 · 예외 셋 — 오류 턴 뒤 · 늦은 에코 · 오류 뒤 멈춤). codex Idle 에서 턴을 여는 순서 = 사용자 `Held` → 후속 턴 빚(빈 `turn/start`) → 우편 · 우편 턴은 빚을 풀지 않는다.
8. **오류 뒤 멈춤**(사용자 결정 N11 (b) 을 넓힌 원칙). 이상하게 끝난 턴(codex `turn/completed(failed)` · `turn/start` 다섯 출구 · claude 오류 `result` — 턴 종류 무관) 뒤에는 사용자의 다음 입력 턴이 성공으로 끝날 때까지 아무것도 저절로 넣지 않는다(빈 턴 · 우편 · codex 남은 항목). 자리: 우편 = 두 백엔드 모두 턴 관측 표의 `last_end_failed`(각 분류기가 오류 끝에서 세운다 — ADR-0127 개정) + 커널 `BusyPolicy` · codex 가 스스로 여는 턴 = 통로 칸 `halted`. 끊긴 끝과 steer 실패는 계기가 아니다(세우지도 풀지도 않는다 — 두 백엔드). claude 목록 항목은 벤더대로. LLM 목록 응답에 `stopped_after_error` 를 싣는다. 막는 자리는 TRD 가 골랐다(고름 — 6차 리뷰가 codex 우편의 문을 통로에서 커널 사실로 옮겼다). **우편 멈춤은 모든 벤더 버전에 건다 — 위임 판정(6차 리뷰 R1)이지 사용자 답이 아니다**(하한 밑 옛 codex 는 통로가 오늘 동작이라 `halted` 만 없다).
9. **보관 = 데몬의 에이전트 세션 층.** 대기 입력 상태 = 링 사건 한 줄기(`StructuredEvent::QueuedInput`)이고 명부와 누산기가 같은 환원 규칙(원인 귀속 · 묘비 · 되살림)을 쓴다. 입력 경로·적는 순서(TRD §5-0) · 락 순서 `input_order → replay → queued_inputs` · `replay → 대기 목록 표`(잎) 와 그 자물쇠 안 팬아웃 예외(`OutputSink::send` 논블록 계약에 기댄다 — ADR-0006 개정) · 턴 신호는 claude `Delivered`(벤더 `started`) 하나. codex 턴 끝 = 턴마다 한 번의 정산(응답만 모은다 · 턴 끝 탐침 없음 · 시한 하나). 수락 여부를 끝내 모르는 codex 항목은 받음 · ✕ · 에이전트 종료 중 하나가 올 때까지 목록에 둔다(N10) · 그 뒤에 친 글은 친 순서대로 넘긴다(N13 (b)) · 그 항목의 ✕ 는 곧바로 버림으로 닫는다(N12 (a)). 라이브 배달 순서는 클라이언트 seq 연속과 sink 자리채움으로 맞춘다 — 코어 「lock 미보유 send」 불변식은 그대로(N5 (a)). ADR-0226 D5 의 로딩 종료 조건 = 「전달된 입력의 말풍선」이고, codex 연결 중 ✕ 는 ADR-0226 「이 결정이 새로 만드는 쓰레기」 부류(대화 없는 id 영속)에 새 입구 하나를 더한다(TRD §5-8 끝줄 · ADR-0226 개정).
10. **옛 벤더 버전 = 오늘 동작**(N1 (a) — 우편 멈춤만 예외, 위 8). 통로 동사 `withdraw` · `send_turn`. **`PROTOCOL_VERSION` 5 → 6**(N4 승인 — 새 `AgentCommand` 변형이 구데몬에서 `Error{request_id: None}` 로 답해진다) · 명령 카탈로그 `catalog_version` 4 → 5.

## 거부한 대안
표기: **[사용자]** = 사용자가 답한 결정(사용자 발화 원문 = [사용자] 태그 뒤의 「…」) · **[위임]** = 사용자가 맡긴 판정·리뷰 판정 · **[고름]** = TRD 가 스스로 고른 내부 구현 · **[조사]** = 조사 보고서의 판단. 전체 표와 판 표시는 TRD §10-5 · PRD §6 이 정본이다.

**표시·전달**
- **보낸 자리에 정식 말풍선 고정**(오늘 claude · ADR-0198 원안 · 조사의 B) [사용자] — 턴 도중이면 앞 답의 나머지가 그 아래로 이어져 순서가 섞인다.
- **대화 맨 아래 회색 대기 행**(조사 보고서 추천안 A) [사용자] — 「터미널이 가장 자연스럽다」.
- **목록 위 머리줄**(「준비되면 전달」 · 「도구 호출이 끝나면 전달」 · 둘째 문구 · 그것을 읽던 대기 사유 칸 `QueueReason` 과 도구 끝 사건) [사용자 Q4 · N2] — 「한 줄 낭비」.
- **턴이 끝날 때까지 붙든다**(오늘 codex) [사용자] — 「당연히 도구호출 끝나면 바로 푸쉬」.
- **codex 도 받자마자 넘긴다**(두 백엔드 공통 즉시 전달 — 한때 결정: 「클로드든 코덱스든 우리가 받고 바로 전달하자. 일단 공용화하고 나중에 세분화」) [사용자] — 원칙 「받을 수 있는 가장 이른 때 전달」로 바뀌었다. codex 는 도구 끝까지 붙들어도 같은 경계에 든다(M7 10/10). 사용자: 이것은 나중 일이 아니라 이 기능의 일부다. `Immediate` 는 착지 첫 걸음과 측정이 빨간 구간의 값으로만 남는다.
- **claude 를 붙들었다가 도구 완료를 보고 넘긴다**(S1) [사용자 · M7] — 한 걸음 늦다: 에이전트가 도구 끝에서 자기 대기함을 먼저 스냅숏해 그 뒤 글은 다음 도구 끝에야 읽힌다(사용자 확인 · claude 0/10). ★claude 에만 기각 — codex 에는 채택★(M7 10/10).
- **훅으로 당겨오기**(S4) [사용자] — 「훅마다 매번 뭔가 실행하면 안 된다」 · 넣는 글이 사용자 턴이 아니라 모델 맥락 · codex 훅 신뢰는 ADR-0216 이 걷은 길.
- **codex 를 도구 시작에 넘긴다**(S5 · 1판 권고) [사용자] — 도구가 끝날 때까지 붙들어도 전달 시점이 같고 ✕ 창이 더 길다. 옛 사유 「공용화가 먼저, 세분화는 나중」은 원칙이 대신했다.
- **대기분을 이어 붙여 한 번에** [사용자 · 조사 §5] — 메시지는 따로 남는다(PRD §3-8) · 항목별 id 가 뭉개져 항목별 받음·✕·말풍선이 서지 않는다 · 백엔드마다 편법이 필요하다.
- **codex 를 턴 안 모든 구간에서 경계까지 붙든다**(경계 직후 · 턴 시작 포함) [고름] — 붙들면 다가오는 대기분 확인을 놓칠 수 있다 → 측정이 세운 구간만 · 모호하면 곧바로.
- **codex 도구 구간에 출력·되울림 아닌 항목을 전부 도구로 센다**(모르는 변형 포함 · 7판 초안) [고름] — 방향이 거꾸로다: 도구로 세는 것은 붙드는 쪽이라 늦는다 → 디코더의 도구 호출 어휘(6 종)만.
- **codex `thread/queue/*`** [고름] — 실험 API · 스레드가 한가할 때 배출이라 도구 경계 전달이 안 된다.
- **한 `turn/start` 에 여러 항목** [고름] — 한 `userMessage`·한 `clientId` 로 뭉쳐 메시지가 따로 남지 않는다.
- **턴 끝에 남은 여럿을 머리 하나만 새 턴에** [사용자 Q9] — 그 동안 친 글이 FIFO 뒤에 서 도는 턴에 못 든다(PRD AC4) → 한 다음 턴에 함께, 각자 따로.
- **Idle 에서 쥔 것 전체(사용자 · 우편)를 도착 순으로** [사용자 N6] — 사용자 입력이 우편보다 먼저다(우편이 늦어지는 것을 사용자가 받아들였다).

**✕ · 결말**
- **구간별 ✕**(넘긴 뒤·경계 열림에선 숨긴다 · 칸 `cancellable` · 한때 결정) [사용자 2026-09-25] — 「x를 건드릴 이유가 있어? 그냥 x누르면 목록에서 기계적으로 빼는거잖아. 구지 비활성 필요 있냐고」 · 넘긴 항목이 늦게 받혀 말풍선으로 서는 것엔 「상관없어」. 칸 · 재방출 · `CONFLICT` 가 통째로 빠진다.
- **✕ 누른 창만 곧바로 감추고 다른 창은 「취소 중」** · **누른 창에서도 결말까지 남긴다** [사용자 Q7 · Q7 후속] — 「x 누르면 바로 빠지는 거잖아. 다른 창도 바로 빠져야 되는 거 아니?」.
- **✕ 없는 항목이 있을 때 안내 한 줄** [사용자 Q7] — 두지 않는다(회색 항목만).
- **✕ 툴팁 「취소 — 글은 버려짐」 · 「목록에서 빼기 — 이미 넘어간 글은 대화에 나타날 수 있음」** [사용자] — 「계속 몇번을 얘기하는데 x눌러도 없어졌는데 안으로 들어가서 표시하는건 어쩔수 없잖아.」 → 「목록에서 빼기」.
- **거둔 글·못 보낸 글을 입력창으로 되돌리기**(1판 Q2 권고) [사용자] — 「일단 그냥 다 버리고 나중에 생각하자」(미룸).
- **버림·실패 알림**(대화 안 한 줄 · 목록 자리 · 토스트 · 전문) [사용자 Q1] — 지금은 없다(미룸).
- **한가할 때 보낸 글이 거절돼도 말풍선을 남긴다** · **받음 뒤 거절은 남긴다**(7판 초안) [사용자 Q1 ④] — 「거절하면 우리쪽 채팅도 지워져야」. 뒤 안의 전제(「받음 전에만 거절된다」)는 벤더 수명주기로 틀렸다(`refused` 는 `started` 뒤에도 온다).
- **claude `cancelled:false` 를 「전달됨」으로 읽기** [고름 · M3] — 경계 위에서는 `false` 뒤 `started`, 예약 취소도 `false`.
- **취소 대기 항목의 `cancelled` 를 무조건 「취소됨」으로**(3판) [고름] — 실패한 턴이 대기분을 닫아도 `cancelled` 가 온다 → 우리 취소 응답과 대조해 원인을 가른다.
- **`CancelAnswered{true}` 뒤에도 수명주기 `cancelled` 를 기다린다** [고름] — 그 줄이 안 오면 모든 창에서 빠진 항목이 우편을 상한 없이 막는다 → 곧바로 취소됨.
- **취소 요청 자체가 실패하면 `Queued` 로 되돌린다** [고름 · 사용자 원칙] — 빠진 항목이 다시 그려진다(「x 누르면 바로 빠지는 거잖아」) · 결말은 수명주기가 낸다.
- **넘긴 뒤 ✕ 한 codex 항목이 거절·부재로 돌아오면 다시 보낸다** [고름] — 사용자가 거두라고 한 글이다.
- **넘긴 codex 항목의 ✕ 에 전용 사건·명령 결과** [고름] — 어휘가 는다 → `CancelRequested` + `CancelAnswered{removed:false}` · 판명되면 `Dropped{Withdrawn}`.
- **claude 오류 턴을 우리 쪽에서 맞춘다**(`DropCause::TurnFailed` · 우리가 취소 요청 · 다음 턴으로 밀기 · 표식) [사용자 Q8] — 「억지로 구현하지 마」.

**수락 여부를 모르는 codex 항목**
- **버리고(`Dropped{Unknown}`) 늦은 에코면 되살린다**(7판 잠정 · 오케스트레이터 권고) [사용자 N10] — 「갑자기 목록이 사라져서 이상할것같은데 응답이 없으면 유저가 뭘 할 수있다고 스택에서 빼? 목록에서 뺀다는건 이유가 있어야되는거아냐」 → 받음 · ✕ · 에이전트 종료까지 목록에 둔다.
- **그 항목의 ✕ 뒤 받음·종료까지 「취소 중」**(N12 (b)) [사용자] — 「끝난걸로쳐. 유저가 x눌렀을때 우연찮게 들어가는건 그냥 그렇다 치겠지」.
- **그 항목 뒤에 친 글을 그 항목 뒤에 붙든다**(N13 (a)) [사용자] — 「음? 뭔소리야 순서대로 들어가는거잖아. 앞지른다는게 뭔소리? 또 발생되지도 않는걸 가정함?」.
- **통로가 그 id 를 T 뒤 턴까지만 기억** · **통로는 우편 턴을 연다(커널만 막는다)** · **곧바로 후속 턴 빚** · **`Held` 로 되돌려 다시 보내기** · **수락 모름을 링 사건으로** [고름] — 목록과 통로의 답이 갈리거나(PRD §3-9) · 받혔는지 몰라 빚이 서지 않거나 · 이중 전달이거나 · 어휘·환원기·wire 가 함께 는다(읽는 쪽은 LLM 하나 → 조회 순간 표지 `unconfirmed`).
- **LLM 목록 `state` 를 둘(`queued`·`cancelling`)로** [고름] — 우편이 왜 기다리는지 LLM 이 못 읽는다(CLAUDE.md 「LLM-우선 제어」) → `unconfirmed` 를 지금 싣는다.
- **턴 끝 탐침**(`thread/items/list` 로 `clientId` 있음·없음 가르기 · 2–7판) [고름 · 벤더 소스 · M10] — 받힌 steer 의 에코는 `turn/completed` 앞에 온다(벤더 소스 0.156.1 · M10 적중 3건 모두 4.5–4.8 ms 앞) → 가를 것이 없는데 칸·규칙만 는다. 탐침에 딸린 논쟁(응답 전 항목 탐침 · 한 장 「없음」 · `turnId` 좁히기 · 쪽마다 시한 · 수락 모름 `turn/start` 탐침 · M10 빨강 시 조용히 걷기)은 함께 닫혔다.

**우편 · 오류 뒤 멈춤**
- **`inputs_pending` 에 30 분 상한(fail-open)** [사용자 N8] — 「일단 사용자 글이 막히면 우편도 막혀야 되는거 아냐? 상한이 필요한거? 애초에 글이 막히는것 자체가 이상한건데?」 — ADR-0113 「안 가는 것 > 늦게 가는 것」 · 30 분 상한 = ADR-0127 결정 4 의 의도된 예외.
- **오류로 끝난 턴 뒤 codex 대기분을 저절로 보낸다**(한도가 풀린 뒤 포함) [사용자 Q8] — 사용자는 세션을 건드리지 않길 원한다 → 다음 사용자 글과 한 턴에, 남은 것이 먼저.
- **빚진 빈 턴이 실패하면 포기하고 우편을 곧바로 흘린다**(N11 (a)) [사용자] — 「진짜 에러면 강제로 쑤셔넣으면 안되잖아」 · 「어쨋든 모종의 이유로 이상하게 종료될때 채팅 입력이 성공하거나 어쨋든 재개 신호가 오면 뿌린다는거잖아」 → 「ㅇㅇ」. 관행: codex 가 실패 뒤 대기 입력을 자동 제출하는 동작이 결함으로 신고됐다(openai/codex#24443 — `docs/research/queued-input-after-failed-turn-2026-09-26.md`).
- **한도 해제 신호(초기화 시각)로 저절로 푼다** [사용자 N11] — 「아냐 일단 복잡하게 하지말자」 · 신호가 사용 한도 한 종류뿐이고 예고 시각이다.
- **codex 우편의 멈춤을 통로(`halted`)에만 둔다**(8판 리뷰 6차 전) [위임 — 6차 리뷰] — 원장은 `delivered` 인데 통로가 상한 없이 쥐어 종료·재기동에 잃고 공유 입력 상한(`INPUT_QUEUE_LIMIT = 32`)을 막을 수 있으며 ADR-0104 「`delivered` = 실제 주입 시점」을 선언 없이 깬다 → 두 백엔드 한 사실(`last_end_failed`).
- **claude 의 끊긴 결과는 멈춤을 푼다**(두 백엔드 비대칭) [위임 — 6차 리뷰] — 풀림은 사용자의 다음 입력 턴 성공이고 ADR-0192 는 맞추는 것이 기본이다 → 끊긴 끝은 두 백엔드 모두 그대로.
- **우편 멈춤을 대기 목록 표의 칸으로** · **커널이 턴 결말을 받아 멈춤을 쥔다** · **세션이 멈춤 동안 우편 쓰기를 거절** [고름] — 둘째 쓰는 쪽과 초인종이 늘거나 · `StatusSink` 동사가 늘어 커널이 사실 계층을 겸하거나(ADR-0110 「포트는 얇게」) · 거절된 우편을 깨울 사건이 없다.
- **후속 턴 빚을 커널 `inputs_pending` 에 더한다** · **우편 턴도 빚을 푼다(7판 초안 Idle 순서)** [고름] — 대기 목록 표에 둘째 쓰는 쪽이 생기거나 · 모델이 우편에 답하고 사용자 글은 답을 못 받는다(PRD §3-9).
- **빚을 새 턴 id 가 설 때 · `completed` 로 끝날 때 · `Delivered` 뒤 열린 턴이 푼다** [고름] — 다섯 출구에서 빚이 남아 빈 `turn/start` 가 쉬지 않고 돌거나 · 칸만 는다 → 사용자·빈 `turn/start` 를 내는 순간 푼다.
- **오류 뒤 기다림을 도착 사건으로 푼다** · **실패 턴의 빚을 세대 비교로 가른다** [고름] — ✕ 로 빠진 글 때문에 남은 항목이 저절로 나가거나 · 멈춤이 덮는 옛 규칙이다 → 매 Idle 상태 판정.
- **벤더 늦은 에코를 보통 `emit` 으로** [고름] — 턴 표가 다시 「턴 중」이 되어 우편이 30 분 fail-open 까지 막힌다(ADR-0127).

**보관 · 순서 · wire**
- **WS/net 층 보관 · 프론트(창별) 보관** [사용자 확정 · 고름] — 연결·창마다 권위가 갈리고 재접속에 사라진다 · net 은 에이전트를 모른다(ADR-0129).
- **라이브 배달 순서를 코어에서 맞춘다**(emit 이 subscribers → replay 순으로 락을 쥐고 한 구간에 · N5 (b)) [사용자 N5] — 코어 불변식(ADR-0006 「lock 미보유 send」)을 바꾸지 않는 쪽을 확인했다 → 클라이언트 seq 연속 + sink 자리채움.
- **하한 미달 codex 에서 「`turn/start` 를 쓴 순간 = 받음」**(1판 고름) · **옛 버전에 목록은 두되 ✕ 없이** [사용자 N1] — 「알아서 업데이트」 — 옛 버전은 오늘 동작.
- **이어받는 claude 화신의 첫 입력은 늘 목록에**(N7 (b)) [사용자] — 「그냥 내가 채팅 치다가 오면 병합 잘 되는거잖아. 이번에 순서 삐뚤어져도 맞추는거 추가하잖아.」 · 「애초에 코덱스쪽에서 리스트를 먼저 보내주겠지 시작하자마자」.
- **접힌 채로 두기 · 가장 최근 3개 · 전문 안 보이기** [사용자 Q3] — 「외 N개」 펼침 · 가장 오래된 3개 · 툴팁 전문.
- **`PROTOCOL_VERSION` 유지** [고름 · 사용자 승인 N4] — 새 명령이 구데몬에서 `Error{request_id: None}` 로 답해져 신셸이 마감까지 매달린다(v3 선례).
- **내용 비교로 말풍선 짝짓기** · **턴 중 보내기 막기** [조사 §5] — ADR-0198 이 이미 기각(두 백엔드 모두 항목 id 가 있다) · 관행과 반대이고 claude 경로엔 퇴행.
- **그 밖의 내부 구현 대안**(발췌 — 전수·사유는 TRD §10-5) [고름] — `Structured` 탈출구로 싣기 · SubscribeAck 에 목록 싣기 · Queued 갈래에서 턴 표에 진행 적기 · 분류 전용 벤더 턴 신호 · 받음 불가 전이를 입력 자물쇠 안으로 · 인코더 태그·백엔드 이름으로 세션 분기(ADR-0004) · `input_id` 없으면 「가장 최근」 · 입력 자물쇠 없이 · 이력 기반 환원 규칙 · drain 턴 틈 오분류 받아들이기 · 대기 목록 표 「비었다」를 replay 락 안에서 · claude 분류가 명부를 직접 읽기 · 재부착 대조를 종결 id 뺀 합집합으로 · 재부착 답을 화신 표식으로만 거르기 · 구멍 뒤 시한 건너뛰기(ADR-0038) · flush 가 구멍을 건너뛰기 · flush 시작점을 버퍼 최소 seq 로 추정 · sink 폐기를 `SinkError` 로 · 셸 중계가 나쁜 프레임을 조용히 버리기 · 모르는 tag 도 연결 끊기 · poisoned 락에 끊기·한 자리만 되찾기 · `turn/started` 로 턴 id 잡기 · steer 대기표에 시한 없이 · `Accepted`·`Expired` 가르기 · Direct 글을 `pending` 밖에 · 종료 합성을 id 마다 낱개 · M15 를 두 다리 합으로 · 뼈대에 측정 전용 붙듦 스위치 · 로딩 게이트를 화면 단계에 · 생산자를 화면보다 먼저 · `Delivered` 에 본문 칸 · 재부착 스냅숏에 받음 행 싣기. 각 사유는 TRD §10-5 해당 행.

## 영향 / 불변식
- **착지 상태**: 착지 전 — 코드 없음(2026-09-26). 구현 = TRD §9 순서.
- **개정 조항**(각 ADR 에 도장 · 구체 문구 = TRD §8): ADR-0044 · 0045 · 0190 · 0193 · 0198 · 0006 · 0226 · 0127 · 0110 · 0104. **관련(개정 아님)**: ADR-0127/0113(새 이벤트 중 턴 신호는 claude `Delivered` 하나 · 통로 합성 말풍선은 관측 없이) · ADR-0004(중간 입력 정책·받음 가능 여부는 backend 가 신고 · `HandOverPolicy` 는 codex backend 안) · ADR-0192(✕ 의 두 백엔드 체감 갈림을 「못 맞추면 보고」로 적는다) · ADR-0204 · ADR-0216 · ADR-0129 · ADR-0082 · ADR-0079.
- **CLAUDE.md 핵심 불변식에 더할 줄**(TRD §8 문구): 소유권 분할의 session += 대기 입력 명부·입력 자물쇠 · 락 순서 `input_order → replay → queued_inputs`(잎) · `replay → 대기 목록 표`(잎) — 출력 펌프는 `input_order` 를 잡지 않는다 · 대기 입력 상태 = 링 사건 한 줄기 · 턴 관측 정리 줄에 `last_end_failed`(쓰는 쪽 = 분류기 하나 · 정리 = 같은 두 지점) · replay→live 에 sink·셸 중계는 seq 를 건너뛰지 않는다 · 프론트 seq dedup → seq 연속.
- **어기면 깨지는 것**: 턴 관측 표에 셋째 쓰는 쪽을 들이면 ADR-0127 인과가 갈라진다 · `OutputSink::send` 가 막히면 입력 자물쇠 안 팬아웃이 그 화신을 세운다(그 계약을 trait doc 에 명시) · sink 가 seq 를 건너뛰면 클라이언트 연속 규칙이 그 뷰를 상한까지 멈춘다 · `inputs_pending`·`last_end_failed` 에 상한을 붙이면 사용자 결정 N8·N11 을 뒤집는다.
- **wire**: `PROTOCOL_VERSION` 5 → 6 · `StructuredEvent::QueuedInput` · `AgentCommand::{CancelQueuedInput, ListQueuedInputs}`(응답에 `as_of_seq` · 화신 표식 · 행 `state` = `queued`·`unconfirmed`·`cancelling` · `stopped_after_error`) · 명령 카탈로그 `catalog_version` 4 → 5. 오류 뒤 멈춤은 wire 어휘를 늘리지 않는다.
- **받아들인 대가**: 오류 뒤 멈춤 동안 목록이 빈 채 우편이 화면에 까닭 없이 멈춘다(상한 없음 · 우편 알림은 백로그) · 수락 모름 항목의 늦은 에코는 뒤 글들의 말풍선 뒤에 설 수 있다(PRD AC2 예외) · ✕ 한 글이 우연히 들어가 말풍선으로 설 수 있다.
- **나중에 더할 후보 — 거부가 아니라 미룸**(설계 기조 · TRD §10-5 끝): ① **턴 끝 뒤 늦은 에코의 빚**(받힌 글에 답할 빈 턴을 한 번 연다 — 지금은 말풍선 + 경고 로그뿐, 다음 사용자 턴이 이력에서 본다) ② **✕ 뒤 숨은 기록**(✕ 로 닫은 수락 모름 항목의 id 를 쥐어 늦은 에코에 빚을 세운다 — ①이 없으면 쥘 까닭이 없다) ③ **턴 끝 탐침**(경고 계수가 「성공 응답인데 에코 없음」을 실제로 세면 되살린다). 공통 까닭 = 단순함 기조 + M9 대조군(답 못 받은 것이 없는데 빈 턴을 열면 모델이 직전 답을 되풀이한다). PRD §7 의 미룬 것(턴 끊기 조작 — 바로 다음 기능 · 입력창 되돌리기 · 버림 알림 · Esc · 우편 알림 · 한도 해제 자동 재개 · Send now · 데몬 재기동 뒤 목록 보존)도 이 결정 밖이다.
