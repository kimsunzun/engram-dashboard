## 맥락
In a structured chat (JSON) slot, we had to decide where to show the user text sent while the agent is running a turn, and when to hand it over (PRD §1).

- **Claude today** — the text goes straight to stdin and the agent also reads it at a tool boundary, but the screen puts a formal bubble at the **sent position**. The rest of the earlier answer continues below it, so the conversation order looks out of step with the order the agent read, and there is no way to take the text back after sending.
- **Codex today** — mid-turn text reaches neither the model nor the screen **until the turn ends** (the queue of ADR-0190). Even text sent while idle shows up only when the echo arrives. ADR-0198 decided on 「보낸 즉시 보낸 자리에 정식 말풍선」 and did not implement it.
- **Common** — the state 「보냈지만 에이전트가 아직 안 받은 글」 exists nowhere on the screen.

The research (`docs/research/mid-turn-input-display-2026-09-25.md`) showed that not blocking sending mid-turn is the practice, that queued items are shown separately outside the conversation, and that the place of the formal bubble is not the time of sending but the **time of delivery** (likely). The history is PRD editions 1–6 → TRD editions 1–8 → review (8th edition, round 7 light PASS), and in between the user answered Q1–Q9 · N1–N13 (TRD §10-1 · PRD §9). ★One decision was overturned by measurement★ — the user first chose 「두 백엔드 공통으로 받자마자 넘긴다」 (「클로드든 코덱스든 우리가 받고 바로 전달하자. 일단 공용화하고 나중에 세분화」), but in the Phase 0 measurements codex fell on the same boundary even when held until the **end** of the tool (M7 10/10 · claude 0/10). Knowing that measurement, the user set the principle 「받을 수 있는 가장 이른 때 전달」 — this is not later work but part of this feature (TRD §10-2).

## 결정
The canonical wording is PRD §2·§3 (what) and TRD §5·§8 (how). Here only the skeleton of the decisions is written. **Scope = user input in JSON mode only** — terminal (PTY) mode stays as today down to the input bytes (user: 「터미널 모드는 그런거 필요없잖아」) · agent-to-agent mail does not go on the list.

1. **Display = the queue list above the input box · the formal bubble is at the delivery position (the end of the conversation).** Queued items are state outside the conversation, and the moment the agent receives one it moves to an ordinary bubble at the end of the conversation. The synthetic echo at input time is issued **only when idle** (amends ADR-0044 · ADR-0198). Hydration order = queue → delivered after history — this closes the open item in the 「영향」 of ADR-0198 (TRD §8). There is no list header line. The collapsed list = the oldest 3 · pressing 「외 N개」 expands it · tooltip shows the full text (counts and shape to be adjusted later).
2. **Hand-over = the earliest moment it can be received.** Claude: stdin as soon as received. Codex: a swappable hand-over policy `HandOverPolicy` inside the backend holds the item until the earliest boundary — it holds only in the spans where measurement established 「늦지 않다」 (the tool span · the answer span once M16 is green), and when the span decision is ambiguous it hands over immediately (only the decoder's tool-call vocabulary counts as tool). If a turn is in progress, the hand-over = `turn/steer`. Landing = the `Immediate` skeleton (including ✕ and `withdraw`) → measurement (M15 reaction latency = two legs + reader lag · M16) → `AtEarliestBoundary`. If M15 is red, stop and ask before the code (the holding policy) · if M16 is red, hand over immediately only in the answer span and do not stop (PRD R8). (amends ADR-0190 · ADR-0193 · the landing order was set by the TRD — picked)
3. **✕ = always on every item of the list — both backends · in any span · 「목록에서 뺀다」.** If the text can be taken back, it is taken back too (claude = vendor cancel request · a codex held item = the path verb `withdraw`, no vendor call) · for a codex item already handed over, it is removed from the list only, and if it is accepted late a bubble stands. This felt difference between the two backends is recorded under ADR-0192 「못 맞추면 보고」 (PRD R3). Cancel is one registered command (`CancelQueuedInput`), and the LLM also calls the same command for any item on the list · list query = `ListQueuedInputs`. Tooltip = 「목록에서 빼기」.
4. **✕ hides at once in every window.** A cancel-pending item is drawn in no window and is visible only in the LLM list (`cancelling`).
5. **The outcome comes from the lifecycle.** A claude cancel response of `false` or an error is used only for the cause attribution of `cancelled` and is not read as 「전달됨」 · a response of `true` is the vendor's answer that it removed the item, so it is cancelled at once · even if the cancel request fails, the item is not put back.
6. **Text taken back or not sent is discarded — no return to the input box · no notification.** If a bubble drawn while idle is rejected (`Dropped{Rejected}`), it is erased without notification · a rejection after receipt is the same. An idle bubble that meets a disconnect or agent exit before being processed is kept (N9 — user: 「그냥 별도로 뭐 해야되는게 있음? resume 하면 어차피 갱신될텐데」).
7. **User input goes before mail.** Idle for mail = no turn running ∧ user list empty. The kernel busy decision = `in_turn ∨ inputs_pending ∨ last_end_failed` (`BusyPolicy` · the fact is `TurnFact` — amends ADR-0110). The source of `inputs_pending` is the queue list table, separate from the turn observation table, and the flush doorbell rings the moment the registry empties. **There is no fail-open cap** — ADR-0113 「안 가는 것 > 늦게 가는 것」 · the 30-minute cap = the intended exception of ADR-0127 decision 4 (user decision N8 · the gate is ADR-0104 decision 3). **Follow-up turn debt** = if codex user text is only recorded and gets no answer, the debt of making one empty `turn/start` follow-up turn answer it (PRD §3-1 · AC6 · three exceptions — after an error turn · late echo · stop after error). The order for opening a turn at codex Idle = user `Held` → follow-up turn debt (empty `turn/start`) → mail · a mail turn does not settle the debt.
8. **Stop after error** (a principle widened from user decision N11 (b)). After a turn that ended abnormally (codex `turn/completed(failed)` · the five exits of `turn/start` · claude error `result` — regardless of turn kind), nothing is fed in on its own until the user's next input turn ends in success (an empty turn · mail · the remaining codex items). Places: mail = for both backends, `last_end_failed` in the turn observation table (each classifier sets it at an error end — amends ADR-0127) + the kernel `BusyPolicy` · a turn codex opens by itself = the path slot `halted`. A cut-off end and a steer failure are not triggers (they neither set nor clear it — both backends). Claude list items follow the vendor. `stopped_after_error` is carried in the LLM list response. The place that blocks was chosen by the TRD (picked — review round 6 moved the gate for codex mail from the path to a kernel fact). **The mail stop is applied to every vendor version — it is a delegated decision (review round 6 R1), not a user answer** (an old codex below the floor has today's behavior in the path, so it only lacks `halted`).
9. **Storage = the daemon's agent session layer.** Queued-input state = one ring event stream (`StructuredEvent::QueuedInput`), and the registry and the accumulator use the same reduction rules (cause attribution · tombstone · revival). The input path and write order (TRD §5-0) · lock order `input_order → replay → queued_inputs` · `replay → 대기 목록 표` (leaf) and the fan-out exception inside that lock (relying on the non-blocking contract of `OutputSink::send` — amends ADR-0006) · the turn signal is claude `Delivered` (vendor `started`) alone. The codex turn end = one settlement per turn (collects only responses · no turn-end probe · one deadline). A codex item whose acceptance is never learned stays on the list until one of receipt · ✕ · agent exit arrives (N10) · text typed after it is handed over in the order typed (N13 (b)) · ✕ on that item closes at once as a discard (N12 (a)). Live delivery order is kept by client seq continuity and sink slot filling — the core 「lock 미보유 send」 invariant is unchanged (N5 (a)). The loading end condition of ADR-0226 D5 = 「전달된 입력의 말풍선」, and ✕ during codex connecting adds one new entrance to the ADR-0226 class 「이 결정이 새로 만드는 쓰레기」 (id persistence without a conversation) (last line of TRD §5-8 · amends ADR-0226).
10. **Old vendor versions = today's behavior** (N1 (a) — only the mail stop is an exception, see 8 above). Path verbs `withdraw` · `send_turn`. **`PROTOCOL_VERSION` 5 → 6** (N4 approved — a new `AgentCommand` variant is answered by an old daemon with `Error{request_id: None}`) · command catalog `catalog_version` 4 → 5.

- **At turn end, put only the head of several leftovers into a new turn** [User Q9] — text typed in the meantime stands behind them in FIFO and cannot enter the running turn (PRD AC4) → all together in the next turn, each separately.
