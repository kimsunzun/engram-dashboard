- 상태: 확정 (2026-10-02, basis: user decision 2026-09-26 (`docs/refactoring/architecture-discussion-2026-09-26.md` decision candidate 1) + the interface shape · the 「프로세스 그룹」 handle · the gate form are the main session's judgment (delegated by the user) + user decision 2026-10-02 (do not pull in base for logging — 「거부한 대안」 second item) + user decision 2026-10-03 (platform's direct dependency on `tracing` — decision 9) + the home of atomic writes is the main session's judgment 2026-10-03 (decision 8) + current-state measurement master `a226f63` · re-measurement `d5ac725`) · 부분 폐기 by ADR-0275 (the time-limited exception in decision 6, the open items, and the impact invariant) · 부분 폐기 by ADR-0291 (decision 8's home of atomic writes, the reason for the second item, and the copy list)
- 관련: Amends ADR-0175 (decision 1's home for the PID helper, decision 2's home for the Job Object wrapper, and the platform side of the first item of 거부한 대안) · Amends ADR-0218 (the home of the platform query in decision 11) · Amends ADR-0230 (narrows decision 1's OS-branch places to a single crate) · ADR-0262 (the `ProcessGroup` neutral handle · the `platform/windows.rs` leaf — what gets moved wholesale) · ADR-0151 (crate decision criteria) · ADR-0175 decision 6 (lib weight) · ADR-0004 (isolating backend knowledge) · ADR-0001 (kill causality) · ADR-0269 (answers its reopen condition for base's third resident · atomic writes leave base `file` and come here — decision 8) · ADR-0268 (each crate calls `tracing` directly for logs — decision 9) · `src-tauri/src/fsutil.rs` (`write_atomic`) · `crates/engram-dashboard-base/src/platform.rs` · `crates/engram-dashboard-agent/src/platform/` · `crates/engram-dashboard-discovery/src/lib.rs` (`wmi_spawn` · `wmi_create_raw`) · `docs/refactoring/architecture-discussion-2026-09-26.md` §1 · step-log S21 · Amends ADR-0265 (the atomic-write function's home in decision 4) · Amended by ADR-0275 (the time-limited exception in decision 6, the open items, and the impact invariant) · Amended by ADR-0291 (decision 8's home of atomic writes, the reason for the second item, and the copy list)

## 맥락

Code that varies by OS is scattered across several crates (measured at master `a226f63`, excluding test-only branches).

| What | Where it is now |
|---|---|
| Windows API wrappers — PID liveness · creation time · child PIDs · Job Object · finding the process that has a file open · process tree · launching outside the terminal tree via WMI | `base/src/platform.rs` · `agent/src/platform/` · `discovery/src/lib.rs` (`wmi_spawn` · `wmi_create_raw`) |
| OS rules — appending `.exe` · the default shell · the home directory · wrapping a CLI in `cmd.exe /c` · case-insensitive `PATH` | `discovery/src/lib.rs` (the daemon executable name) · `daemon/src/lib.rs` (the CLI executable name) · `agent/src/manager.rs` (`default_shell`) · `agent/src/backend/claude/mod.rs` · `agent/src/backend/mod.rs` (`console_command` · PATH merging) |
| Branches leaked to the caller — carrying the Job Object handle around under `#[cfg(windows)]` | `agent/src/transport/pty.rs` · `agent/src/transport/stdio.rs` · `agent/src/backend/codex/transport.rs` |

The PTY itself is already hidden by `portable-pty`.

This layout is the result of an old criterion. ADR-0175 moved the PID helper down into base and left the Job Object wrapper behind because 「소비자가 `agent` 안뿐이라」 (decision 2). ADR-0218 put `file_holders` · `process_tree` in agent because 「소비자가 하나뿐이라 입주 조건 ①을 못 채운다」 (decision 11). The idea of splitting platform out into an independent crate was rejected by ADR-0175 by user decision (first item of 거부한 대안 — *"기능 추가할 때마다 모듈 만들 순 없다. 과해지면 그때 분리하자."*). All three used the **number of consumers** as the criterion.

The user (2026-09-26): 「인터페이스 호출로 하고 플랫폼적인 건 다 감추고」 · 「어차피 플랫폼 전용 기능은 의존 0」 · 「애초에 초반부터 잡고 갔어야 됐어」.

## 결정

1. **Gather the OS-varying code into one independent crate with zero workspace dependencies** (user 2026-09-26). Callers call only the interface, and OS branches (`#[cfg]`) exist only inside that crate. Places already tied to OS code are all moved over as well — the three rows of the 「맥락」 table above and the re-measured items in 「근거」 below.
2. **Decision criterion = whether it depends on the OS.** This replaces the number of consumers (ADR-0175 decision 2 · ADR-0218 decision 11).
3. **Domain knowledge stays.** For example: for the claude config folder, only 「홈 디렉터리 찾기」 moves, and the knowledge of the `.claude` path stays in the backend (CLAUDE.md 「백엔드 확장」). The lock directory location and the knowledge that 「파일 이름 = 스레드 id」 stay in `backend/codex` as they are (that half of ADR-0218 decision 11 is kept). Branches that run tests only on Windows stay on the test side.
4. **`logging` stays in base as it is. base's role = a leaf used everywhere** (user 2026-09-26). By this decision, the only thing that leaves base is the PID helper (the `platform` module).
5. **Interface shape (main session's judgment — delegated by the user):** functions + handle types, compile-time branching. Where a test fake is needed, **the using side** defines a small trait (discovery's injection seam is the precedent).
6. **The 「프로세스 그룹」 handle = ADR-0262's `ProcessGroup` and the Job Object wrapper moved together as one unit** (main session's judgment). No new handle is built separately. The Job handles that pty · stdio · the codex transport carry around under `#[cfg(windows)]` go behind this handle. Basis = those two files are already written to be moved that way — the layout that keeps `platform/windows.rs` as a leaf and has `process_group.rs` do the conversion to neutral types is the user's decision (2026-09-29 「windows crate 와 io 만 · 통째로 옮길 수 있게」) (ADR-0262 「[구현] 고른 것」).
   - ★**Even after the move, ownership stays the same — the Job's strong owner stays with the transport**★ (ADR-0262 impact 「소유권」 · CLAUDE.md 「핵심 불변식」 ownership split). What goes out through this handle is only the weak handle (`Weak<JobObjectHandle>` — `platform/process_group.rs:118-119`) · the read-only `RetiringSignal` · and a port that is attached once. What moves is the type's home, not the owner of the strong reference. Kill causality (ADR-0001 — `transport.shutdown()` ends the Job) does not change.
7. **No implementation for another OS arises from this separation.** The gaps merely appear gathered in one place. The placeholder for PID decision outside Windows (a PID is alive as long as it is not 0) is also carried over as it is.
8. **Atomic file writing (`write_atomic`) goes to platform** (main session's judgment 2026-10-03). The shell's `write_atomic` in `src-tauri/src/fsutil.rs` contains a Windows-only branch (`cfg!(windows)` · `raw_os_error` 32/33 — `fsutil.rs:107`) that retries when the rename fails with a sharing violation or lock violation. base does not depend on platform (ADR-0175 residency condition ② — zero workspace dependencies stays as is) — so this function is placed here, not in base `file` (ADR-0269).
   - **Settling the behavior of several copies into one also comes to this stage (work order 1-3)** — ADR-0269 had put it in 1-1. They are merged after platform exists. Current copies = the shell's `src-tauri/src/fsutil.rs` (called by `settings/store.rs` · `ui_settings.rs`) · daemon `usage_service/reject_store.rs` · agent `persistence/mod.rs` · `persistence/presets.rs` (re-measured `d5ac725` — the ADR-0269 「영향」 list). Once merged, ADR-0265 decision 4's 「`write_atomic` 은 셸 공용 `fsutil.rs`」 becomes stale.
   - **Setting aside a corrupt copy (`set_aside_corrupt`) stays in base `file`** — it is a single rename with no OS branch (ADR-0269).
9. **platform may depend directly on the third-party `tracing` (facade)** (user 2026-10-03). Zero dependencies on workspace crates stays as is — gate ① below counts only crates with the `engram-dashboard` prefix. So the `Drop` warning of `RmSession` (the `impl Drop for RmSession` in `crates/engram-dashboard-agent/src/platform/file_holders.rs` — 「`Drop` 이라 돌려보낼 곳이 없으므로 남기는 것은 로그뿐」) moves over as `tracing::warn!` unchanged. There is no platform → base edge (ADR-0268 — logs are not wrapped).

## 거부한 대안

- **Decide the home by the number of consumers (current — ADR-0175 decision 2 · ADR-0218 decision 11).** Rejected = user decision (「애초에 초반부터 잡고 갔어야 됐어」 · 「플랫폼적인 건 다 감추고」). The current state is that OS code is split across several crates and `#[cfg(windows)]` handles leak into callers (the 「맥락」 table above — code). ★The ground ADR-0175 gave when it rejected the opposite side of this alternative (an independent platform crate) was also a user judgment (that ADR's own assessment: weak)★ — this decision reverses a user judgment on the same axis.
- **platform depends on base in order to print logs.** Rejected = user decision (2026-10-02 — 「로그 때문에 Base 전체를 그렇게 포함시키는게 말이 안 됨」). Logs are printed through one facade (`tracing`) (decision 9 · ADR-0268).
- **platform prints no logs — failures as result values, cleanup as an explicit `end() -> Result` + a silent `Drop`** (the form of the lowest handle layer such as Rust API Guidelines C-DTOR-FAIL · std · wezterm `filedescriptor` — `docs/research/low-level-crate-logging-2026-10-02.md` branch A). Rejected = user decision (2026-10-03 — 「로그 감싸지 마」 opened a direct facade dependency, so decision 9 stood) + the cost of that form: for a function with several exits after a session is opened, like `holders_of` (`return Err` twice · one early `return Ok` inside the loop · the `Err` of convergence failure at the end — four), `end()` has to be called on every path for a failure to be visible (code — `holders_of` in `file_holders.rs`). OS wrappers one layer up (portable-pty · alacritty · cargo `FileLock`) print through the facade (same report §1 · §3).
- **Pick the OS through a trait object (runtime branching).** Rejected = the OS does not change while running, so runtime branching gains nothing (main session's judgment). **Own assessment of the rejection basis: weak** (narrative).

## 근거

Research behind it = `docs/research/low-level-crate-logging-2026-10-02.md` (the peer practice of low-level crates depending directly on a facade · a third-party facade does not break zero workspace dependencies — that report's 「우리 제약과의 적합도」 branch C).
- **Current-state measurement (master `a226f63`)** — the 「맥락」 table. The shell (`src-tauri/src`) had no OS branch at that point.
- ★**Re-measurement (2026-10-02 · `d5ac725`) — wider than the table above**★ (after `rg -l 'cfg!?\(windows\)|cfg\(not\(windows\)\)' crates src-tauri/src`, production branches and test branches were told apart by the start line of each file's `#[cfg(test)]`):

  - **Test branches only — stay per decision 3:** agent `usage/scratch.rs` · `backend/claude/leftover.rs` · `backend/claude/usage_probe.rs` · `backend/codex/mod.rs` · `session.rs` · daemon `messaging_host.rs` · net `src/portfile.rs` · base `logging/mod.rs` (each file's branches are all under that file's `#[cfg(test)]`).

## 영향 / 불변식

- **Invariant: `#[cfg(windows)]` · `cfg!(windows)` exist only inside the platform crate** (excluding test-only branches — test-harness bins · `examples/` are the same, 「근거」 re-measurement). ADR-0230 decision 1 (「맡은 함수 · 모듈 하나 안에서만」) narrows to this one crate. The precedent `console_command` in CLAUDE.md 「플랫폼 중립」 also goes to this crate.
- **Gates (main session's judgment) — two of the same form as base:** ① dependency ceiling `cargo tree -p <platform> --depth 1 --prefix none -e normal,dev,build --target all --all-features | rg "^engram-dashboard" | sort -u` → exactly 1 line (itself — third-party crates (`windows` · the `tracing` facade) are not counted · decision 9) ② `rg "^\s*use tauri" crates/<platform>/src/` → 0 lines (check first that the path exists — the core-isolation gate item in CLAUDE.md 「빌드·검증 명령」). A new crate registers the gates in three places (`ci.yml` · CLAUDE.md 「빌드·검증 명령」 · `.claude/skill-bindings/qa.md`) and must keep the name prefix `engram-dashboard-` for the ceiling gate to see it (ADR-0175 impact · ADR-0151 「개명 함정」). Tests that launch real child processes (`child_pids` etc.) come along, so that crate's test command takes `-- --test-threads=4` (CLAUDE.md 「병렬은 테스트 바이너리마다 걸린다」).
- **Gates that change:** net's base-symbol allowlist (exactly 2 lines — the two PID helpers) switches over to the platform crate · `platform` drops out of the base-resident cross-reference gate (`rg "(crate|super)::(logging|platform)"`) · the `windows` crate feature list (CLAUDE.md 「의존성」) moves over per crate.
- ★**Kill causality (ADR-0001) passes through the Job Object** — the step that moves that wrapper is full QA (work order 1-3).
- **Group the work into units that do not break** (user 2026-10-02 — 「망가지지 않는 단위로 잘 그룹지어서 작업하라」). Within 1-3, cut at each unit with build and regression green.
- **The platform side of the first item of ADR-0175 「거부한 대안」 is reversed by this decision** (platform is an independent crate) — the logging side stays in base per decision 4. ADR-0269 answers that item's reopen condition (「base 에 세 번째 입주자」).
- **Fix the base · agent items of CLAUDE.md 「백엔드 모듈 맵」** — the agent item's 「남은 `platform`은 Job Object 래퍼 하나뿐」 is already stale (now four — the Job Object wrapper · `process_group` · `file_holders` · `process_tree`).
- **Open item — decide at the start of 1-3:** whether to split the `windows` crate features into per-capability cargo features (`net` needs only PID decision but the Job Object · Restart Manager bindings get pulled in too).
- **Code anchor = `// ADR-0266`** — the platform crate header · the 「프로세스 그룹」 handle.
