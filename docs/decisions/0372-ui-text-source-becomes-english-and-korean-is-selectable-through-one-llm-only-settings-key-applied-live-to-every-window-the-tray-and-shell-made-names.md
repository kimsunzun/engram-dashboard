# ADR-0372: UI text source becomes English and Korean is selectable through one LLM-only settings key, applied live to every window, the tray and shell-made names

- 상태: 확정 (2026-11-17, 근거: user decisions 2026-11-08 「화면 원본 언어도 영어로 하고 한국어 보이는걸 나중에」 and 2026-11-17 「디폴트 영어 선택 한국으로」 · 「언어를 고르는 설정이 있긴한데 llm 명령으로만 일단 하자고」)
- 관련: Amends ADR-0349 (ko.ts as the source, Korean only, Rust strings excluded, interpolation options, call sites unchanged, init before titles) · ADR-0069 (UI strings centralized) · ADR-0055 (LLM controls everything through the existing surfaces) · `docs/process/S35-i18next-backend/prd.md` · `docs/reference/structure/i18n.md` · Amends ADR-0301 (decision 2 merging the shell word table into the web i18n)

## 맥락
ADR-0349 put i18next behind `t()` with `ko.ts` as the only, typed source, Korean only, and left the Rust shell's visible strings out. The user then set the app's base language: the UI is English by default, Korean is available on request, and internal text (logs, errors, LLM-facing text) becomes English-only in a separate topic. There is no settings screen; settings are changed through the LLM settings commands (`settings.get` / `settings.set` / `settings.reset` / `settings.schema`). User-visible text also comes from the shell: tray labels, the native refusal dialog, auto tab names and OS window titles (`src-tauri/src/layout/tab_name.rs`).

## 결정
- `en.ts` is the typed source of keys and placeholders. `ko.ts` stays, with exactly the same keys and placeholder sets, enforced at compile time. A label meant to stay English in Korean mode keeps its English text in `ko.ts` (status labels such as `Wait`, user 2026-11-17).
- One settings key selects the UI language: values `en` | `ko`, default `en`. It is read and changed only through the existing LLM settings commands; no new command and no UI control for now.
- A change applies immediately, with no restart: the React UI in every window, the slot right-click menu, the tray menu, the refusal dialog (when shown), auto tab names and OS window titles. Component state is kept.
- The Rust shell's visible strings are in scope and follow the same key, in both languages. The shell keeps its own small en/ko table (it does not read the frontend tables), which replaces ADR-0301 decision 2's plan to merge the shell word table into the web i18n.
- Unchanged from ADR-0349: i18next is the lookup backend behind `t()`; the public `t()` signature stays; only `src/i18n/` imports i18next.

## 거부한 대안
- **Apply on restart (VS Code's display-language model)** — fewer places to touch, but the user rejected a restart for a language switch (「보통은 로컬적용될때 재부팅하는경우는 없는데」). The live-switch cost was counted: about 52 module-load title captures in 10 command files, one `memo` component with `t()` text, and Tauri 2.11 has `MenuItem::set_text` / `TrayIcon::set_menu` for the tray. (약함 — 사용자 직접 기각)
- **A settings screen with a language picker** — deferred by the user (「llm 명령으로만 일단 하자고」); the key works the same when a screen is added later. (약함 — 사용자 직접 기각)
- **Korean source with English as the translation** — the user chose English as the source (「화면 원본 언어도 영어로」). (약함 — 사용자 직접 기각)
- **English only, `ko.ts` deleted and regenerated by an LLM later** — the user wants Korean selectable now (「디폴트 영어 선택 한국으로」), which needs the table. (약함 — 사용자 직접 기각)

## 근거
- User decisions quoted above.
- Facts from the current code (S35 fact collection, HEAD 36320580): settings keys are declared in `src-tauri/src/settings/registry.rs` with a `Choice` kind (precedent `theme.default`, applied live per window); the frontend `settingsClient` receives `settings:changed` in every window; the tray is built once in `build_tray` and Tauri 2.11.3 offers runtime `set_text` / `set_menu`; the refusal dialog can only appear after the settings store is loaded; auto tab names are written to the state file and matched back by `tab_name::is_word`.
- Convention for chat labels (Roo Code, Open WebUI, LibreChat `ko` locale files): structural labels are translated, agent tool names stay raw identifiers.

## 영향 / 불변식
- A new UI string is added to `en.ts` and `ko.ts` together; a key only in `ko.ts` (e.g. from a branch made before this change) fails the type check.
- No code keeps a translated string across a language change: titles and labels are resolved when shown, and stored state holds keys or raw values, not translated text.
- State files must not depend on the UI language: an auto tab name saved in either language, or in today's Korean, is still recognized as auto.
- Logs, thrown error text and LLM-facing text are not UI strings and do not follow this key. Known exceptions until the topic that makes LLM-facing text English-only: `window.__engramCmd.list()` titles, the `connection.status` reply text and `layout.rows` `tab_name` follow the UI language.
- The settings key's name and values are an LLM-facing contract once shipped.
