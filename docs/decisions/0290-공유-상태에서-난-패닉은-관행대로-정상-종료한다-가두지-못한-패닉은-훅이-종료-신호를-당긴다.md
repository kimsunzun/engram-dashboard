# ADR-0290: A panic from shared state exits normally, as is the practice — for a panic that was not confined, the hook pulls the exit signal

- 상태: 확정 (2026-10-10, basis: decision 1 = user decision 2026-10-10 「관행대로 종료하자」 · decision 2 = main's judgment (user delegation 「성숙한 프로그램 관행대로 처리하면 될듯」 2026-10-10)) · 부분 폐기 by ADR-0292 (the return to normal exit in decision 1, and decision 2)
- 관련: Supersedes ADR-0289 · ADR-0288 (revives decision 3) · research `docs/research/panic-policy-peers-2026-10-08.md` · `docs/research/stop-writes-after-internal-error-2026-10-10.md` · Amends ADR-0288 (the return of decision 3 voids the partial discard by ADR-0289) · Amended by ADR-0292 (the return to normal exit in decision 1, and decision 2)

## 맥락

ADR-0289 changed ADR-0288 decision 3 (shared-state panic = normal exit) to 「데몬을 살려 두고 강한 경고 · 경고 중 저장 멈춤」. After that the user asked 「성숙한 곳의 기본 정책이 뭐냐」, and main's answer = **confine the units that can be confined (a request · tab · extension that shares no state with others), exit or restart the whole thing cleanly when shared state may be broken, and instead make restart cheap** (zellij · Zed · Alacritty exit · zellij session resurrection · VS Code terminal restore — `docs/research/panic-policy-peers-2026-10-08.md` · PostgreSQL full restart · crash-only design — `docs/research/stop-writes-after-internal-error-2026-10-10.md`). That herdr · atuin · helix are alive on a non-main thread panic is not by design but because they do nothing (herdr likely · atuin · helix uncertain). By that standard ADR-0289 departs from the practice and ADR-0288 decision 3 is the practice.

## 결정

1. **Discard ADR-0289 entirely and revive ADR-0288 decision 3** — a panic that occurs while changing shared state takes the existing normal exit path. The strong warning · stopping saves during the warning are not done (the process ends, so stopping saves is not needed either).
2. **For a panic that was not confined, the panic hook pulls the normal exit signal** (main's judgment) — in an unwind build, a panic that the entrances of tiers 1 · 2 (ADR-0288) did not confine ends only that thread · task quietly and the daemon keeps running. That is the 「조용히 살리기」 the user rejected (ADR-0289 second rejected alternative) and is not in the practice either. So when the hook detects 「지금 가두는 중이 아닌 패닉」 (a panic that is not currently being confined), it pulls the normal exit — the shape where a zellij server, on a panic in any thread, sends an error to the server loop, notifies the attached clients, and then ends (`zellij-server/src/lib.rs:1596-1607` — research report). The marker that says 「가두는 중」 is set by the entrances of tiers 1 · 2, and its shape is decided by the TRD.

The rest of ADR-0288 (decisions 1 · 2 · 4 · the unwind premise · the items passed to the TRD · not building the dedicated mechanisms of 3 · 4 · the deferred mechanisms) stays as it is.

## 거부한 대안

- **Keep alive with a strong warning · stop saves during the warning (ADR-0289)** — the user heard the default policy of mature projects and decided on exit, as is the practice. (Main's explanation: stopping saves also had no direct precedent at the app layer — `docs/research/stop-writes-after-internal-error-2026-10-10.md`.)
- **Leave a panic that was not confined as it is (leave it to the default unwind behavior)** — the function that thread was in charge of stops with no indication while the daemon runs. User: 「조용히 살리는 건 좀 그렇고」 (ADR-0289 second rejected alternative). (Main's judgment — that rejection by the user, which came out of the shared-state context, was widened and applied to every panic that was not confined.)

## 근거

- Conclusions 2 · 4 of the research report and the placement of herdr · atuin · helix that the document review brought back (`docs/research/panic-policy-peers-2026-10-08.md`).
- The detection means = the daemon panic hook (`crates/engram-dashboard-daemon/src/lib.rs:133`) — for a panic on any thread, it is called on that thread before unwinding.

## 영향 / 불변식

- **The three lines of ADR-0288 「영향」 tied to decision 3 are valid again** (the ones ADR-0289 had made stale) — the normal exit path must run to the end even on a poisoned shared lock (now `sessions.read().expect(…)` in `shutdown_all` — `crates/engram-dashboard-agent/src/manager.rs:2943` cannot tolerate it · the lock poisoning policy closes it in the TRD) · a normal exit takes the next boot restore as it does now (ADR-0019) · T-52 is looked at together.
- **The exit signal the hook pulls does not take locks** — the hook runs on the panicking thread before unwinding. Taking again a lock that thread holds is a deadlock. The signal is pulled with a lock-free marker (an atomic value · a send on the already existing exit watch, etc. — the TRD chooses). ★The existing hook's `tracing::error!` already takes the log file Mutex★ — there is a documented window where, if it panics while holding that lock, the hook waits on itself (`crates/engram-dashboard-base/src/logging/mod.rs:110-115` 「알려진 미수정」). When adding the exit signal to the hook, this hole is looked at together.
- **Places where the process ends immediately even under unwind** = a panic in the main future and the connection accept loop inside it · a `Drop` panic during unwinding · a panic crossing an `extern "system"` callback (the last two abort — ADR-0288 decision 4). For a shared-state panic it is the exiting side anyway, so it does not conflict with this decision, but it does not go through the normal exit — the TRD looks at whether to put the entrances of tiers 1 · 2 outside that place. A panic propagated through `std::thread::scope` · `join().expect` does not end the process right away and panics again on the parent thread — decision 2 catches that re-panic.
- **The existing confinement places must set the 「가두는 중」 marker first** — the hook of decision 2 pulls exit on a panic without the marker, so if the hook comes in before the marker, a panic of the pump (B-2) · reaper that was already being confined becomes a daemon exit. The connection task (`crates/engram-dashboard-daemon/src/lib.rs:394` — no catch now) is also the 「연결 하나」 entrance of ADR-0288 decision 1, so it needs the same marker. How to find them = `rg -n catch_unwind crates src-tauri/src` (examples as of 2026-10-10: `transport/pty.rs:299` · `transport/stdio.rs:305` · `backend/codex/transport.rs:2461,4078` · `reaper.rs:205` · `transport/input_queue.rs:288` · `backend/claude/leftover.rs:722` · daemon `lib.rs:728` · `usage_service/mod.rs:726` · `control/registry.rs:333`).
- **The second rejected alternative of ADR-0288 (keep alive with a strong warning) is rejected again** — the valid reason is this ADR's (the default policy of mature projects · the user's 「관행대로 종료하자」), not the premise 「다수가 종료한다」 written in ADR-0288 (that premise was main's wrong report — ADR-0289 맥락).
