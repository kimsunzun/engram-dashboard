# ADR-0149: Split a slot's agent absence into three states

- 상태: 확정 (2026-08-18, grounds: user decision + code measurement) · 부분 폐기 by ADR-0280 (① absorbing spawn-wait into decision (A) ② the wording of decision (C), a slot whose profile was erased ③ in the last item of the grounds, the judgment that a dead indicator must not flash right after a reserved node is activated, only for a reserved slot with no memory ④ in the known limits of 영향, the display of a renderer with no memory ⑤ the reason of the rejected alternative 「삭제도 흐림으로 통일」, only for a reserved slot with no memory)
- 관련: Amends ADR-0148 (single decision of agent absence) · ADR-0019(termination classification · corpse retention) · ADR-0018(reserved node = frontend composition) · ADR-0163(meaning and comparison rule of the incarnation marker) · ADR-0164(reattach trigger · subscription deps) · `src/components/layout/ViewLayoutRenderer.tsx` · `src/components/slot/RichSlot.tsx` · ADR-0280(2026-10-06 — the leaf (`LayoutLeaf`) draws the shared veil as a fourth: only for cells that have no slot component, so the factual statement 「흐림·심볼은 세 슬롯이 한 벌로 그린다」 in 「영향」 merely grew and this is not an amendment of this ADR) · Amended by ADR-0280 (① absorbing spawn-wait into decision (A) ② the wording of decision (C), a slot whose profile was erased ③ in the last item of the grounds, the judgment that a dead indicator must not flash right after a reserved node is activated, only for a reserved slot with no memory ④ in the known limits of 영향, the display of a renderer with no memory ⑤ the reason of the rejected alternative 「삭제도 흐림으로 통일」, only for a reserved slot with no memory)

## 맥락

After ADR-0148 was implemented and the user measured it, **no dimming was applied when an agent was terminated.** The cause was confirmed by investigation:

- The slot renderer's gate looks at **the `agents` list only** (`ViewLayoutRenderer.tsx:52-68`). When the agent disappears from there, it takes the slot component down entirely and draws the 「에이전트 연결 중…」 placeholder.
- The actual outcome of termination: the reaper collects the session out of the map and **removes it completely from the broadcast `agents`**, but **preserves the profile as a corpse** (`reaper.rs:44-89`, ADR-0019). So the tree remains as a reserved item while only the slot loses its view.
- The absence decision of `RichSlot` has an `agent != null` guard, so it becomes **false once the agent is fully collected** — the overlay did not appear and the input box also stayed active.
- ★And it cannot be undone★: on termination the daemon's replay ring is released together with the session (owned in `output_core.rs:30-44` → dropped at `reaper.rs:56,65`). **If the view comes down, that conversation is lost permanently** and cannot be revived even by resubscription (`error` after the ladder's 3 attempts). That is, the essence of this problem is not the wording but **whether the view is kept**.

And one placeholder was covering **three situations of different natures** — one that has not yet received the registry / one that was terminated / one that was deleted. The user: 「에이전트 연결 중…」 is ambiguous.

## 결정

Differentiate ADR-0148 decision 1 (the single decision that treats death and disconnection alike) **into three states**.

The decision axis is **"does this slot remember mounting that agent while it was alive"** (not whether a profile exists — the grounds are in the last item of 「근거」 below).

1. **(A) No memory** → 「에이전트 연결 중…」. No registry received (boot · reconnect) and **spawn wait** (right after a reserved node is activated) are absorbed together here. It is actually on its way, so that wording is right.
2. **(B) Memory + agent absent** → **keep rendering the slot component to keep the screen content**, with dimming + symbol (ADR-0148 decisions 2 and 3 as they are), and input is blocked. Termination lands here.
3. **(C) No profile either** → **「연결된 에이전트가 없습니다」**. There is neither content to freeze nor a target to point to. **But "there is no profile" is trusted only when the profile list was actually received** — making this decision during an interval where the list reception failed would unmount a live conversation and lose it permanently (pulled out by review).
4. **Disconnection stays handled the same as (B)** — ADR-0148 decision 1's "treat death and disconnection alike" remains valid in this scope. What was differentiated is the case beneath it, "the target does not exist at all."
5. **The memory holds only the render mode.** It does not hold the **incarnation marker** — ADR-0164 decision 8 removed it from both the subscription deps and the slot props, so there is no consumer to remember it for (`ViewLayoutRenderer.tsx` does not pass that value down to the slot). ★It is not "because the profile already holds it"★ — the memory record of the commit that implemented this ADR actually held that value (added after a review BLOCK), and the frontend does not read the marker from the profile either (the only source = the authoritative registry — `observeRoster` of `protocolClient`). The memory is recorded only at a committed mount, and is cleared when that slot leaves (B).

## 거부한 대안

- **Just change the wording** (「연결 중」 → another expression) — the real problem is that the conversation of a terminated slot disappears. The daemon history is released together, so the moment the view comes down it cannot be recovered.
- **Unify deletion into dimming too** — dimming in a state with no content to freeze has zero information. Dimming an empty screen is misread as "something was there and it died."
- **Erase the profile too on termination and unify into (C)** — it breaks ADR-0019's corpse retention (resumability · reason tracing). The path of reviving it from the tree as a reserved item also disappears.
- **Treat it as absence without distinguishing (A)** — right after boot, 「연결된 에이전트가 없습니다」 flashes briefly and then gets filled. It is a defect of the same family as the restore flicker (ADR-0145).
- **Promote the overlay to the slot wrapper (layout) to cover terminal mode as well** — consistency is better, but it duplicates RichSlot's existing decision and is a refactor beyond this scope. **This rejection remains valid** — instead of lifting it to the wrapper, each slot computes the decision from its own data and only the place that draws was gathered into a shared component (「영향」 below).

## 근거

- **User measurement and decision (2026-08-18)** — "종료됐을 때는 흐릿하게, 삭제됐을 때는 연결된 에이전트가 없다는 문구" (gloss: dimmed when terminated, the wording that there is no connected agent when deleted). The wording was also approved by the user.
- **Code measurement** — we confirmed in code, each separately, that termination leaves the profile (`reaper.rs` `decide()` → `KeepDisableAutoRestore`), that the store holds `agents` and `profiles` separately so **no backend change is needed to tell (B)/(C) apart**, and that a signal to detect (A) **does not exist** (`agents: []` cannot tell not-yet-received from truly empty — `connectionState` looks only at the transport layer).
- **Precedent** — the tree already composes reserved nodes as `profiles ∖ agents` (ADR-0018, `mergeTreeNodes.ts`). Only the slot renderer was not using that decision.
- **Why the decision axis was moved from "profile exists" to "mount memory" (review round 2)** — with profile existence alone, **right after a reserved node is activated** (the interval where the profile exists but the agent does not yet) is misclassified as absence and a dead indicator flashes. Conversely, with memory as the axis that interval is naturally absorbed into 「연결 중」, and it also matches the real condition "is there content to freeze" (content exists only while the component is mounted).

## 영향 / 불변식

- **The slot renderer does not decide absence from `agents` alone** — it looks at `profiles` and "whether the registry was received" together. If any one of the three is missing, the three states get smeared together again.
- **The slot component is not unmounted in (B)** — unmount = permanent loss of that conversation (the daemon history is already gone). Do not put a conditional unmount here for performance or cleanup purposes.
- **The absence decision rule is in one place** — the tree and the slot use the same union rule. If implemented separately in two places, drift occurs where only one side gets fixed.
- **The (A) detection flag is raised once at the first registry reception and does not come down** — it is kept across the reconnect resync too (if it came down, the (C) wording would flash on every reconnect).
- **Dimming and symbol are drawn by the three slots as one set** — terminal · DOM · rich use the same veil component (`SlotUnavailableVeil`). Each slot computes the absence condition from its own data, and the place that draws the result is that single one — if the look diverges, it is not that the convention has slipped but that the shared component was bypassed (the source of truth for look and grounds = that file's header). Input blocking also applies in all three modes.
- **★A renderer with no memory shows a terminated slot as 「연결 중」 — a known limit★** — the memory lives in that renderer instance, so an instance that has never seen that agent alive (after an app restart · after a tab is pulled out into a separate window · a reserved id assigned without activation) cannot know (B). In that case the display is the same as the old behavior. **To fix it, the conversation state would have to be lifted out of the slot component, and that is a separate matter.**
- **Splitting a slot makes the preserved conversation disappear — an accepted limit** — the conversation lives in the slot component state and a split unmounts that component. If only the memory is lifted out, an empty screen with only dimming is shown and even a resubscription to the dead agent is attempted, which is **worse than now** (this ADR already rejected that state).
