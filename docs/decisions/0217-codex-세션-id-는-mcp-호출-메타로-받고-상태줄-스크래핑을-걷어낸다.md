# ADR-0217: The codex session id is received through the MCP call meta, and the status-line scraping is removed

- 상태: 확정 (2026-09-21, basis: three measurement rounds — see 「근거」 below) · 부분 폐기 by ADR-0218 (recovery channel replaced with the lock-file holder PID) · 부분 폐기 by ADR-0226 (decision 7 value policy)
- 관련: CLAUDE.md 「백엔드 확장」 · ADR-0185 (codex does not issue an id) · ADR-0208 (hook recovery) · ADR-0203 (vendor storage formats are not read) · ADR-0210 (no files on the user's machine) · ADR-0214 (MCP mail) · ADR-0213 (`eg_` prefix) · ADR-0207 (profile writes) · ADR-0004 (isolating backend knowledge) · `crates/engram-dashboard-agent/src/backend/codex/mod.rs:711` · `crates/engram-dashboard-daemon/src/control/mcp_server.rs:437` · `crates/engram-dashboard-daemon/src/control/registry.rs:24` · `crates/engram-dashboard-agent/src/profile.rs:709` · step-log S21 · Amends ADR-0216 (status-line recovery channel and scanner replaced) · Amended by ADR-0218 (recovery channel replaced with the lock-file holder PID) · Amended by ADR-0226 (decision 7 value policy)

## 맥락

codex issues its own thread id by itself (ADR-0185), and terminal mode has no channel through which it could tell us that value (ADR-0208 맥락). ADR-0216 chose the **TUI status line** (`-c tui.status_line=['thread-id']`) as that channel, and the recovery itself does actually work.

★**The price differed from the premise on which it was approved**★ — the user approved it understanding it as 「정보가 한 번 뜨고 사라진다」 (the information shows up once and disappears), but the status line is **a resident single line redrawn on every frame**. Recovery is needed once per incarnation, yet for that one time a line of the screen is given up for the whole session. The user confirmed this mismatch of premise and decided to choose the channel again (user decision 2026-09-21).

★**The recovery timing may be late**★ (user's point 2026-09-21) — the id is needed **only for the very first incarnation**. After that, the incarnations get the id guaranteed because we pass `resume <id>` as an argument. So the constraint 「스폰 0.3초 안에 잡아야 한다」 (it must be caught within 0.3 seconds of spawn) never existed in the first place, and receiving it after the first turn is fine. This relaxation is what makes the channel below possible.

## 결정

1. **Recovery source of record = the `_meta` of the `tools/call` that our MCP server receives.** When codex calls an `eg_*` tool, the thread id comes along in that request — `_meta.threadId` and `_meta.x-codex-turn-metadata.{session_id, thread_id, turn_id, model, codex_version}`. ★**There is no pairing — we receive.**★
2. **Identity comes from the per-agent bearer token that already exists.** We use as is the `BoundIdentity { agent_id, epoch }` (`control/registry.rs:24`) in the request extensions. ★**It carries the epoch too**★ — which is stronger than the way the only profile sid write path in the daemon today (the `SessionTracker` callback) passes the epoch as `None`.
3. **Remove the status-line channel.** Remove the spawn argument `STATUS_LINE_OVERRIDE` (`codex/mod.rs:833-841`) · remove the whole scanner `backend/codex/thread_id.rs` and its only operational call site (`codex/mod.rs:1026`). **The PTY pre-input observer seam** (`transport/pty.rs:351-356` · `transport/mod.rs:61`) had this scanner as its only consumer, so it is removed together.
4. **Plant a complementary marker — this time only the planting.** Put `CODEX_INTERNAL_ORIGINATOR_OVERRIDE=<에이전트별 고유 문자열>` in the spawn env. That value is left as is in the `originator` field of the session record, so that later, when looking for the row, ownership can be decided by **exact string match**. ★**The reading side is not built in this round**★ — it is a follow-up, and even when reading, we do not scrape files but ask the app-server (the path ADR-0203 allowed).
5. **The env injection condition is only when a control endpoint exists** — the same condition as the existing `inject_cli_entrance`. It is not loaded unconditionally: we do not break 「엔드포인트 없으면 env 도 없다」 (no endpoint means no env), which `without_an_endpoint_nothing_is_injected` (`codex/mod.rs:1548`) guards.
6. **As the write path, publish one public verb in the agent crate.** Today there is **no** way from the MCP handler (daemon) to reach the profile — `AgentManager` holds `profiles` as private and has no write-delegating method. The new verb **must ride, as is, the epoch guard** of `ProfileRegistry::observe_session_id` (`profile.rs:709`) (we do not build a new bypass).
7. **The value policy keeps overwriting** (inherits ADR-0216 decision 7). The same value is a no-op, and a different value pushes the old value into `old_session_ids` and records. Even if the same id arrives again every turn, nothing changes.
8. **Recovery runs only for a fresh incarnation.** A resume incarnation has nothing to receive, because we pass the id as an argument. This does not contradict the existing `fresh_spawn_release_session_id` (`manager.rs:467`).
9. **If it cannot be received, it is left unreceived — no fallback is built** (inherits ADR-0203·0216). ★**Known gap**★: a session that never calls a tool does not get an id and is not resumed. That gap is closed later by the reading path of decision 4.

## 거부한 대안

- ★**Leave the status line as it is (ADR-0216 as it stands)**★ — that it works is measured, and it is not a defect either. **Rejected = user decision**: the approval premise (「한 번 뜨고 사라진다」, shows up once and disappears) differed from the facts, and for the price of one recovery, a resident line is too much.
- **Change the status-line item to `thread`** — the item description is `Current thread title, or thread identifier when unnamed` and codex auto-generates a title after the first turn, so **after the first turn the 36-character hex is replaced by the title** (binary measured). ★Rejected = the line itself remains★ — the user's complaint was not the hex but the residency, so it does not serve the purpose.
- **Receive it through `tui.terminal_title`** (it does not show in the chat body and comes cleanly by OSC) — ★**Rejected = measurement**★: **it is truncated to 32 characters** (29 characters + an ellipsis, the last 7 hex lost), and the truncation is fixed regardless of the screen width. ADR-0216 had already rejected this by measurement, and this survey **recommended it again as the best** — the survey left the truncation unconfirmed, and our measurement wins. **If it comes up again, look at this line first.**
- **Turn it off at runtime with the `/statusline` slash command** — it exists (binary strings confirmed). ★Rejected = it **persists** the selection into `~/.codex/config.toml`★ (there is even a save-failure string) + it is an interactive multi-select picker, so it is fragile to drive by script. It runs into ADR-0210 decision 1 (do not write on the user's machine).
- ★**Lock file + time window**★ (`~/.codex/thread-writer-locks/<id>.lock` appears immediately at startup and the id is a UUIDv7, so the creation time is stamped into the name) — **rejected = measurement**. The spawn→id-creation delay over 4 runs = **0.735 · 0.879 · 0.907 · 1.891 seconds**, but ★**there is no upper bound**★: in a separate round a **21-second** case was observed, and it did not come up again in 4 reproduction attempts, so the cause is unidentified. A 2-second window has zero candidates in that case (not received), and a 25-second window has two candidates if the user launches even one codex of their own within those 25 seconds (rejected) — **there is no width that satisfies both ends together.** Collision measurement = **90 ms** between the id creations of two launched 411 ms apart.
  - Side fact (does not reverse the rejection): **codex sweeps away locks whose owner is dead when it starts** (observed 2 times — we did not delete them). Candidates do not pile up, but the window problem stays.
- **Find it before the first turn from the app-server list** — ★rejected = measurement★. A plain TUI **does not attach** to the app-server: with 4 TUIs alive, `thread/loaded/list` was an empty array, and by `netstat` the only one holding a socket was the one launched with `--remote`. Besides, the npm install cannot even start the managed daemon (`codex app-server daemon start` → no standalone install). A thread **before** the first turn is not in the on-disk list either.
- **Resume without an id using `codex resume --last`** — by measurement **it was per-cwd after all**: even when a more recent session was in another folder, it picked the one of that folder, and it is steered by `-C` (the `--all` description is 「disables cwd filtering」, which confirms that the default is the cwd filter). ★Rejected = **it collides if we have two agents in the same cwd, and it also collides when the user launches their own codex in that folder**★ — there are two hard keys, so there is no reason to leave a guessing path.
- **Revive the hook (herdr's fixed-path wrapper)** — it has a precedent, and since the approval hash covers the hook definition and not the script content, **one approval for life** holds. Rejected = **cost and line**: the amount to revive is about 1,900 lines (what `535cdba` deleted), and laying a file in the user's home runs into ADR-0210 decision 1. The MCP channel gives the same value more cheaply.
- **The orca way (grant hook trust by RPC)** — inherits ADR-0216's rejection: the trust key is position-based, so it ends up with us approving someone else's hook on their behalf.
- **Decide by the lock file's owning PID** — the lock is kept open by the owning process, so an OS-level PID↔thread binding actually exists (that `cat` fails as busy confirmed even that it is held). ★**Left unverified**★ — the path to see which PID holds it (Restart Manager) was blocked by the policy of this environment. To revive it, that check has to be done first.

## 근거

- ★**This ADR is the measurement source of record**★ — the numbers below are measurements from three worker rounds on 2026-09-21 and were not promoted to a survey document. Method: in the already-trusted `I:\Engram_Workspace\qa-codex-probe`, we launched codex on its own console, attached a minimal stdio MCP server that only prints logs, and received the JSON-RPC in full. codex-cli **0.155.1**.
- **Probe A (channel) — confirmed.** `initialize` has no id (only `clientInfo`, no `_meta`) and not a single `CODEX_*` reaches the MCP server environment (scrubbed). The place where it is carried is **the `_meta` of `tools/call`**. The id received is identical to the rollout's `session_id`, belongs to the process we launched (PID 38052), and was **the same shape in both the TUI and `exec`**.
- **Probe B (marker) — confirmed.** We planted 3 arbitrary strings in `CODEX_INTERNAL_ORIGINATOR_OVERRIDE` and all were read back as is from the record's `originator`. No allowlist rejection was observed.
- **Probe C (record row) — confirmed.** After the first turn the row carries `session_id · cwd · originator · cli_version · source · thread_source · model_provider · git`. ★**There is no PID anywhere in the row.**★ **Before** the first turn, even if a thread id exists, there is no rollout file.
- **Probe D (PID) — none.** The rollout JSONL has no pid, hostname, or command line.
- **Code measured (exploration round).** The env is already passed to the child — `build_spec` takes `env` (`codex/mod.rs:718`) and it is applied at `transport/pty.rs:168`. **No new wiring is needed.** `_meta` is discarded now, but rmcp 2.2.0 already lifts it up as `RequestContext.meta`. There is no daemon→profile write path (decision 6 opens it).
- **Gate.** MCP tool calls ride the approval policy — with `-a never` they are rejected (measured). Our spawn is `-a on-request`, so it does not apply. **A per-server auto-approve setting does not exist** — with `--strict-config`, `auto_approve` · `trust` · `trusted` · `approval_policy` · `tool_approval` were all rejected as unknown fields, and under `mcp_servers.<name>` only `enabled_tools` and `startup_timeout_sec` are accepted.
- ★**Three unverified**★ — ① **whether the same `_meta` comes in a normal TUI that a human approved by hand** was not measured (the measurement ran with `--approve-for-me`, and that flag creates **one more sibling thread for auto-review** in the same cwd). ② We do not know whether the `originator` value affects vendor telemetry or billing attribution. ③ `CODEX_INTERNAL_ORIGINATOR_OVERRIDE` is an **undocumented internal variable**, so if upstream removes it, it silently stops taking effect — the failure mode is 「못 받음」 (not received).

## 영향 / 불변식

- **The recovery channel of ADR-0216 dies** — the status-line argument, the scanner, and the arming window (first input / budget / recovery success) go out together. The **overwriting policy (decision 7) and the fresh give-back of that ADR are alive** and are inherited by this decision.
- ★**The invariant 「창 안에 사용자·모델 내용이 구조적으로 없다」 (the window structurally contains no user or model content) becomes unnecessary**★ — since the screen is not read, the first-match tie-break itself disappears. The three conditions ADR-0216 set up to guard that window (the ban on keeping it armed, etc.) retire together.
- **New invariant: the write carries the epoch.** The MCP path passes `BoundIdentity.epoch` as is to the incarnation guard of `observe_session_id` — it does not bypass with `None`. If it bypassed, a dead incarnation's report would overwrite a live profile.
- **New invariant: the env is loaded only together with the control endpoint** (decision 5). If violated, `without_an_endpoint_nothing_is_injected` breaks, and our marker leaks into a spawn with no endpoint.
- **The comment assumption at `manager.rs:455-458` is reversed** — it says 「codex 가 이 칸을 채우는 경로는 제어 평면이 아니라 PTY 상태줄」 (the path by which codex fills this slot is the PTY status line, not the control plane). That place is fixed to match this decision.
- **ADR-0203 is not reversed** — this round does **not read** the vendor store (decision 4 only plants). Even when it is read later, it must be an app-server query, not a file.
- **Regression net** — the status-line scanner tests (the `thread_id.rs` unit group · the through-PTY end-to-end in `codex/mod.rs` · the pre-input observer wiring in `transport/pty.rs`) go out together with what is deleted. **The tests of the MCP `_meta` parsing and the new write verb must fill that place instead** — it is not left as a net decrease.
