# ADR-0016: Agent lifetime model — sid instances, saved = kept alive · deleted = turned off, restart defaults to Always, simple guard

- 상태: 확정 (2026-06-16, basis: the user's conceptual correction + `/consult` cross-validation job `20260616-001941`) · 부분 폐기 by ADR-0019 (the runtime interpretation of restart=Always) — **However, the "runtime auto-restart" interpretation of restart_policy=Always is discarded (Superseded in part by ADR-0019). There is no runtime auto-restart (a crash = back to reserved, manual re-run). Boot restore, the guard counter and Failed persistence remain valid (to be reviewed later).**
- 관련: ADR-0015(daemon lifetime) · ADR-0008(session restore sid) · `agent/profile.rs` · `agent/manager.rs` · `docs/process/S12-daemonization/lifecycle-policy-prd.md` · Amended by ADR-0019 (the runtime interpretation of restart=Always)
- Scope: the lifetime of claude agents held by the persist daemon (boot restore · runtime restart · crash guard). **This stage = fixing the model + variables; implementing the behavior is TODO.**

## 맥락
We must decide when a claude agent is revived, when it is killed, and when we give up on it. In the earlier chat the concepts were misjudged several times (separating the profile from the instance, assuming a pause state, resetting on stable uptime, etc.), corrections piled up, and consult cross-validation refined them.

## 결정
1. **An agent = a sid-based instance, persisted.** spawn creates an instance by sid and that itself is saved. **A saved record exists = the intent to keep it alive.** Reviving = re-spawn with `--resume` using the saved sid. **Deletion is the only "do not keep alive" switch** (removing the saved record).
2. **There is no pause/manual-stop state.** claude is **either alive or dead**, nothing else — if it is not in use, leave it idle, and that is the pause. We do not create a separate state like "turn off briefly" or "manual stop". To turn it off, delete it.
3. **The restart_policy default = `Always`.** If it dies, revive it (except Failed and deleted). Since there is no concept of killing to stop briefly (§2), delete it to stop it. ⚠️ **This "runtime auto-restart" interpretation is discarded by ADR-0019** — at runtime a crash = back to reserved (waiting) + manual re-run (no auto-restart), and "if it dies, revive it" is valid only in the **boot restore** context.
4. **The crash guard = a simple per-agent counter.** Add +1 to `consecutive_failures` on every restart attempt, and stop at Failed once it exceeds the limit (`restart_max`, e.g. 5). **Only a manual restart resets it** — no automatic reset, no stable-uptime reset, no sliding window. Since there is no automatic reset, even a runaway loop that "lives 35 seconds and dies" simply stops after 5 times. **Manual restart = an explicit spawn request from the user/LLM** (a UI button or command).
5. **Failed = the saved record kept + automatic wake-up suspended.** It is kept across a cold boot (excluded from automatic restore) until a manual wake-up. **It is not data deletion.** The existing `auto_restore` field is **redefined as "automatic wake-up on/off"** — true normally, false when the guard blocks it (= suspended), true again on a manual wake-up. (No separate intent/observation variables are needed — §1)
6. **Boot restore = revive every saved non-suspended instance** (once on a daemon cold boot, independent of the UI). "UI opens → restore everything automatically" is forbidden (ADR-0015 detachable viewer). An **explicit user request** (waking a specific agent, securing the daemon) is fine, though.
7. **The daemon runaway guard = app-side, with the limit `daemon_respawn_max` (e.g. 3) < the agent's (5).** One daemon restart = restoring everything, so it gives up sooner. **Manual daemon restart = launching the UI (an ensure-daemon request)**, and launching the UI also resets the guard.
8. **Global tuning values = a new `daemon-config.json`** (restart_max, daemon_respawn_max, etc.). Rename `last_restore` → `last_start_at` (for records and debugging, not used in reset decisions). The guard counter and Failed are **persisted** (agents.json).

## 거부한 대안
- **A pause/manual-stop state** — claude is alive-or-dead and idle is the pause, so it is unnecessary.
- **restart default Never** — conflicts with the product direction of "always alive" (the user chose Always). (consult recommended Never for migration safety, but the user overrode it.)
- **A stable-uptime reset (counter to 0 after surviving T seconds) · a sliding window** — over-defense. With manual-reset-only, a runaway stops on its own. For claude workloads (a normal prompt takes 1–2 minutes), stable_secs=30s is actually dangerous (a 35-second loop resets every time and never stops — pointed out by Gemini in the consult).
- **A global guard counter** — one broken agent would stop healthy agents too. It has to be per-agent.
- **was_running observation tracking / splitting auto_restore into "intent vs observation"** — unnecessary in the sid-instance model (saved = kept alive, deleted = off). This split was considered at first, but discarded after the conceptual correction.
- **UI open = restore trigger** — an anti-pattern (the daemon = the brain becomes dependent on the viewer; 0 of the 6 systems in the consult adopted it). Only explicit user requests are allowed.
- **Daemon idle auto-exit** — persist-until-kill (ADR-0015).

## 근거
- The user's conceptual correction: agent = sid instance, saved record = the instance itself, reviving = re-spawn, deletion = removing the saved record, no pause (alive/dead).
- Consult cross-validation (GPT · Gemini · Claude opus blind + judge): agreement on separating intent from observation · Failed persistence · the daemon guard × agent guard counters being volatile · daemon-config.json · exit-kind (excluding Killed from restart). The trap in E (guard reset) was singled out quantitatively by Gemini alone.

## 영향 / 불변식
- **Turning off = deletion only.** A kill is not a brief stop (with Always it comes back). If you will not use it for a while, leave it idle.
- **Failed and the guard counter are persisted** — if a daemon reboot wiped the counter to 0, an infinite loop (daemon restart → restore → instant death → …) would bypass the guard. That is why they are saved in agents.json.
- **A manual kill/shutdown does not restart even with Always** — otherwise it would be an agent that cannot be turned off (an exit-kind to distinguish `Killed` is needed, in the behavior stage).
- **The runtime death-observation hook** (the restart trigger path) does not exist in the code → a separate decision: **proposed ADR-0017 = a `done_rx` supervisor** (reusing the existing completion channel, leaving ADR-0001/0005 undamaged). Awaiting approval.
