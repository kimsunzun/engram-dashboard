# ADR-0153: Threat model of the command-registry identifier — inside the authentication boundary, trust on string knowledge alone

- 상태: 확정 (2026-08-17, basis: user decision + measured authentication-boundary code)
- 관련: ADR-0150 (trace discarded · identifier written by the client) · `crates/engram-dashboard-net/src/auth.rs:28-31` · `crates/engram-dashboard-daemon/src/command_roster.rs:65-70` · `docs/research/client-identity-survey-2026-08-17.md` · step-log S20.8

## 맥락
Just as we were about to start slice B (replacing the registry owner key from a connection-derived value with a **client-made identifier**), the preliminary research blocked it. The reason was not that there were no candidates but that **there was no requirement** — nowhere in constraints C1 to C8 is "a returning client must be distinguished from an impostor" written, so it cannot be derived which of takeover, refusal, authentication binding, or coexistence is needed (issue 1 of the research report).

The precedents also split into two lines. One line allows takeover on string knowledge alone (MQTT ClientID · Kafka `transactional.id`), and the other requires a **second factor** before re-takeover (SMB2 Durable Handle v2 = authenticated OS user + a GUID from open time). Choosing in this fork without a threat model would be a choice without a basis.

## 결정
1. **Impersonation is outside the current threat model.** The registry identifier is trusted by knowing that string alone, and proof of ownership is not required.
2. The boundary that grounds that trust **already stands in code.** After connecting, the daemon accepts only one token authentication frame as the first frame within 1 second (`auth.rs:28-31`), and registration and update are reached only after it. So only a process that holds the daemon token can touch the registry, and **inside that boundary we trust.**
3. The reappearance of the same string is **handled as a takeover** (the unconditional-takeover line).
4. If it becomes necessary, proof can be added later. This decision does not close that door, but adding it needs a new ADR that amends this one.

## 거부한 대안
- **Decide-then-block (SMB2 Durable Handle v2 line)** — Before re-takeover it filters out an impostor with a second factor (authenticated user identity + a GUID from open time). Reason discarded: the second factor exists for **blocking impersonation alone**, so if decision 1 puts impersonation out of scope, only cost remains. In addition, if this line is put in by half (only 「남이 쥐고 있으면 거절」, reject if someone else holds it), a shell that reconnects within the half-open window (up to 50 seconds) is **blocked by its own corpse.**
- **Self-certifying identity (libp2p Peer ID line)** — The client makes a key pair, derives the identity from the public key, and proves ownership on connect. Reason discarded: the purpose of this method is to solve 「문자열 지식만으로는 못 믿는다」 (string knowledge alone cannot be trusted), so it runs head-on against decision 1. And since the token authentication boundary already stands, it would buy the same protection twice.
- **Server-issued resume token (WAMP · Socket.IO · ZooKeeper line)** — The daemon issues the identifier and returns it to the client. Reason discarded: ADR-0150 has already decided the identifier is **written by the client**, and this method conflicts with that wording. Also, what this line solves is the opposite-direction problem (making the server recognize the client again). ★Strength of the rejection basis = **weak** (descriptive)★ — apart from the wording conflict with ADR-0150 and the directionality description, there is no quantitative, measured, or code basis.

## 근거
- **Source of the requirement = user decision (2026-08-17).** The research blocked on 「요구가 문서에 없다」 (the requirement is not in the documents), and the user filled that gap with 「요구를 두지 않는다」 (we set no requirement). So this ADR is not a product of comparing candidates but **a statement of the requirement in writing.**
- **Code basis:** the authentication frame is for the first frame only with a 1-second timeout, and the token is a 256-bit hex in the daemon's config file (`auth.rs:28-31`). Because the paths that touch the registry are reached only after it, 「인증 안 된 아무나」 (any unauthenticated party) cannot reach the registration surface in the first place.
- **The candidate space shrank from five to three.** Of the five methods the research raised, 「인증 후 늦은 결속(XMPP 리소스 바인딩 계열)」 (late binding after authentication, the XMPP resource-binding line) **already holds** because of the structure above — authentication is the first frame, so registration is by definition after authentication. It was not rejected; it dropped out of the candidates because there is nothing separate to do, and 「자기증명 신원」 (self-certifying identity) is rejected because it runs head-on against decision 1 (rejected alternatives). What remains is only the three lines of **unconditional takeover · decide-then-block · server-issued token**, and of these unconditional takeover was chosen (decision 3).
- The Kafka static membership source does not address 「산 소유자가 있을 때 새 클라를 어떻게 하는가」 (what to do with a new client when a live owner exists), so it is used as a basis for neither side (research second-edition correction).

## 영향 / 불변식
- **What we accept (stated explicitly):** after the old connection is decided dead, **any process that knows that string takes that name.** What this decision gains is **exclusivity**, not identity. But that 「아무 프로세스」 (any process) is limited to those that already hold the daemon token.
- **Token distribution scope = registry manipulation scope.** Because the trust boundary is the daemon token, a change that widens the range that can read the token reopens this ADR.
- **Slice B validates only the shape at the entrance** — up to length and character set, and does not put in proof or authentication binding.
- **No half implementation:** since the reappearance of the same string = takeover allowed, do not build an implementation that puts in only 「남이 쥐고 있으면 거절」 and so blocks a reconnect in the half-open window.
- A change that adds proof reverses decision 1 of this ADR, so **amend it with a new ADR** (do not edit this file).
