# ADR-0093: S17 reply round-trip experiment harness — sending-guidance case matrix (C0~C3)

- 상태: 확정 (2026-07-20, basis: user decision — bird's-eye view approval + a request to compare the sending paths)
- 관련: ADR-0092(receive contract · priming) · ADR-0091(happy-path ladder) · ADR-0086(dual entrance · token-derived from) · ADR-0088(write-boundary observation) · `crates/engram-dashboard-daemon/src/bin/roundtrip_smoke.rs` · `prompts/experiments/agent-priming-send-{both,mcp,cli}.md` · step-log S17

## 맥락
The baseline (ADR-0092) established that a primed agent accepts a natural A→B message without treating it as an injection. The next step is the B→A **reply round trip** and proving "how B learns how to send". Sending is already wired through the dual entrance (MCP `send_message` / `engram-send` CLI, ADR-0086), but **no real agent has ever called the sending half on its own** (the baseline smoke had the daemon call `handle_send` directly as a fake sender). The current priming (`prompts/agent-priming.md`) states only receiving and leaves sending as just "possible · details later". This is a slice on top of the happy-path-first ladder (ADR-0091).

## 결정
1. **Round-trip slice shape = seed→B, B replies to a real A.** Spawn both A and B as real primed agents, the daemon injects an "A-sent" natural message into B (reusing the baseline path), B replies to A through its own sending path, and A receives and processes it. Building on the baseline, only the two unverified pieces (a real agent actually using the sending half · A naturally accepting the reply) are newly verified — deterministic.
2. **"The path by which B learns how to send" is decided after an empirical comparison through a C0~C3 matrix, not by adopting a single one.** C0 = no priming (only MCP tool auto-discovery) · C1 = receive + send (both MCP and CLI taught) · C2 = send via MCP only · C3 = send via CLI only. Decision axis = acceptance > tokens; B's natural choice (MCP vs CLI) is observed through `DeliveryObservation.entrance`.
3. **Leading hypothesis (unconfirmed) = priming covers both the sending and receiving directions consistently** — but whether tool auto-discovery alone is enough is also checked in parallel (hence C0).
4. **Add a "no-form / natural-prose body" candidate to the follow-up format spike.** The daemon wraps the envelope (`[message from <sender> id:<id>] <body>`, ingress.rs `wrap_message`), so the sender may submit just a raw body — hypothesis: less form → less error in the agent's output.

## 거부한 대안
- **Fully autonomous (A decides to send first)** — whether A sends or not depends on prompt luck, so the test is non-deterministic. Too much for the first happy-path slice → later.
- **A stub A (an empty shell that only records what it receives)** — the cheapest, but it cannot see the core of the round trip, "A naturally accepting the reply", so it is meaningless.
- **Testing a single sending path only** — only one of the dual entrances (ADR-0086) is seen, so coverage is lost. Both must work.
- **Fixing a sending section into the priming body (agent-priming.md) now** — the wording is due to change in the format spike, so avoid fixing it early. Experiment variants stay as isolated drafts in `prompts/experiments/`.

## 근거
The user's decision (bird's-eye view approval + a request to "compare cases for both MCP and CLI and decide the best", 2026-07-20). The baseline confound lesson (ADR-0090→0092): do not dig into failure modes without a success mode — stand up the round-trip happy path first. A real agent's sending and A's acceptance can only be confirmed by measurement, so running the matrix backs the decision (the run is a follow-up).

## 영향 / 불변식
- Run C0~C3 as parameters through `roundtrip_smoke.rs` (a test-harness bin, gated by required-features — excluded from production builds). The **final decision on the best sending configuration and on whether to make priming bidirectional is deferred until after the matrix is measured**.
- Harness invariants: after the baseline, only a from=B · to=A record counts as a reply (prevents pre-seed false positives) · both A and B must be alive for a valid negative (A dead = setup failure) · priming that requires the CLI while engram-send is absent = SETUP-SKIP (not a normal negative) · the sender identity is token-derived (ADR-0086, not a body string) · observation goes through the write-boundary sink (ADR-0088).
- The priming experiment variants (`agent-priming-send-{both,mcp,cli}.md`) are **not production** — clean them up when the format spike fixes the wording.
