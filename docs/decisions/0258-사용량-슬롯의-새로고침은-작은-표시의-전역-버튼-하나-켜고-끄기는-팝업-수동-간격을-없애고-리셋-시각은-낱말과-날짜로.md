## 맥락
PRD R12 put the manual ⟳ in three places — the small display · the popup · the slot right-click menu — and R8 put the per-company toggle only in the right-click menu, making the popup view-only (R7). D11 made a ⟳ within 30 seconds after a company's last query answer with the held value. The small display wrote the reset time as the glyph ↻ and a weekday (weekly window).

Those 「세 곳」 and the menu ⟳ first appear in the 2026-09-26~27 interview summary (`docs/research/usage-limit-display-ui-survey-2026-09-26.md:13-22`), and the user's original words are not preserved. The handoff of the same day recorded only the menu toggle, and there was no ⟳. The user stated on 2026-09-29 that they had never requested the small-display and menu refresh in that form, and chose the layout below. ★This section is the source of truth for this provenance record★ — PRD R12 · TRD §3 #102 ① point here.

## 결정
1. **Manual ⟳ = one global button on the small display (always shown).** On the right of the grid · at all three width steps · it refreshes the companies that are turned on together · hide it when both companies are off. The popup's per-company ⟳ is removed. The slot right-click menu has no usage item at all (neither ⟳ refresh nor ☑ show Claude/Codex) — only the general slot menu remains. The commands `usageSlot.refresh` · `usageSlot.toggleClaude` · `usageSlot.toggleCodex` remain as the LLM path (CLAUDE.md 「LLM-우선 제어」) — only the menu items are removed.
2. **Toggling is one line at the very bottom of the popup, 「슬롯에 표시: ☑ Claude ☑ Codex」** (wraps when companies are added). The popup detail shows only the companies that are turned on — a company that is off is not subscribed, so there is no value to show (the user: 「끄면 사용량도 안보내고 좋네」). When both companies are off, the small display's hint changes from 「우클릭해서 표시할 항목 고르기」 to 「클릭해서 표시할 항목 고르기」, and the popup shows only the toggle line. So the popup is no longer view-only (amends PRD R7). (Implementation detail — main decision 2026-09-30: the toggle sends only its own field, as an absolute value, to the webview Tauri command `set_usage_slot` and takes the shell's in-lock per-field merge — a full replacement is out because rapid consecutive clicks · concurrent LLM writes overwrite each other. TRD §3 #102 ⑤.) **Relation to ADR-0063 (user decision 2026-09-30 — option A):** this webview IPC conflicts with ADR-0063's invariant 「슬롯 콘텐츠 변경은 `set_slot_content` 단일 경로」 and its rejected alternative 「variant별 전용 command」, and the user accepted that exception. That rejected alternative (command explosion) is not reopened in general — a per-field partial merge cannot be carried in a complete `SlotContent` (the serde default fills a missing `show_*` with true), the bus verb `layout.setSlotContent` is still one generic command and already routes usage to the same `apply::set_usage_slot`. The new IPC only lets the human path reach that same merge (ADR-0081 decision 3 — humans and the LLM use the same apply function). The rejected option B is in the 「거부한 대안」 section.
3. **Remove the 30-second interval of the manual ⟳** (the 30-second clause of PRD D11 · TRD §3 #38 · the daemon constant `REFRESH_MIN_SPACING`). Two things remain — while a query is in progress, a press does not issue a new query until the result arrives (the small-display ⟳ ignores the press entirely if any target is in progress, and separately the daemon joins it, per company, to the in-progress query — TRD §3 #102 ②-2) · no query during a rejection (429) (R24 · D22 unchanged). The user: 「다른데도 쿨타임 없으면 그대로 하자. 막히면 그네들이 알아서 적게 누르겠지」.
4. **The small display's reset time uses a word instead of the glyph ↻** — 「리셋 00:58」 · in English 「resets 00:58」 (Korean is shorter · the same word as the popup's existing 「리셋 …」 · it does not overlap the glyph of the global ⟳ button). If the reset is on a day other than today, show not a weekday but a **date**, in the order date → time — 「리셋 10/1 01:48」 · 「resets Oct 1 01:48」. (Implementation note: the current code builds the date from a numeric month and day — an English month name needs a locale formatter when the en table is added. There is no en table yet, only `ko.ts`.)

## 거부한 대안
★**The reasons attached to the toggle B · C · the bare 「☑ 표시」 · the reset-notation items below are the trade-offs at the time of presentation — the user chose A · date.**★ Those reasons were written by the main agent when it put up the options, and no original words survive saying the user rejected them for those reasons (`.claude/handoff/attachments/usage-slot-main-notes-2026-09-29.md` 「USER DECISIONS — session 2」). The weekday trap (the same weekday next week) is also noted by the research document as 「메인 추론, 피어 근거 아님」. Reasons that trace back to a user decision are written separately in their place.
- **Toggle B — a 「☑ 슬롯에 표시」 on each company head** — the same word repeats as many times as there are companies, and a company that is off also takes a line, so it gets long as companies are added.
- **Toggle C — a switch per company + a hover explanation** — the meaning cannot be read before hovering.
- **A bare 「☑ 표시」** — it is ambiguous whether it is shown in this popup or in the slot.
- **Reset notation — a clock icon** · **time only** (「00:58」 reads as a remaining time) · **weekday 「수 01:48」** (「리셋 수」 reads as a count, and it is ambiguous if the reset is on the same weekday next week — the latter is the main agent's inference) · **a 「(수)」 · 「수요일」 variant** · **a countdown** (an earlier decision to keep the remaining time only in the popup — that was the user decision of 2026-09-29).
- **Keeping the 30-second interval · shortening it to 10 seconds (Usage4Claude precedent)** — the user chose no interval (the quote in decision 3 above).
- **B — widening `set_slot_content` to partial fields** (instead of the ADR-0063 exception) — the user's reason = it costs more to implement (user decision 2026-09-30 — option A · record = `.claude/handoff/history/20260930-033545-사용량-슬롯-⟳·토글-재배치-커밋-문서리뷰·팝업문서·todo이관-대기.md:20` 「B(set_slot_content 확장)는 구현이 더 들어 기각」). The breakdown of that 「더」 (touch every `setSlotContent` call site and run one more review round) is a trade-off the main agent wrote when it put up the options — not the user's original words.
- **A client-side pending-selection workaround** (keep the full replacement while the webview holds the pressed value) — if the order of reflection is swapped or part of it fails, it still leaks (code review round 2 — TRD §3 #102 ⑤).

## 근거
- Manual-refresh peers (`docs/research/usage-manual-refresh-peers-2026-09-29.md`) — a global refresh is typical (only CodexBar was confirmed to also have a per-company button). Blocking a re-press during a query exists in all four places confirmed from source (Orca · CodexBar · Paseo service · CodexMeter), two more are likely and one is uncertain (Usage4Claude only has the 10-second debounce in its README). A time cooldown is rare.
- Reset-time notation peers (`docs/research/usage-reset-time-format-peers-2026-09-29.md`) — a date is the most common, and both vendor tools use a date (Codex CLI = certain · Claude Code = likely — based on output pasted into an issue).

## 영향 / 불변식
- **Accepted risk:** mashing can trigger a Claude 429, and that rejection can last about an hour — source = the query survey `docs/research/claude-usage-query-method-survey-2026-09-27.md` §0-3 · verification table, which cites the design document in the ClaudeBar repository (`docs/providers/claude/design.md:61-62`) (not confirmed by the vendor · that observation called the private usage URL B directly, and whether A shares the same limit is, in §0-4 of the same survey, 「가능성 높음 — 버킷 미확인」). ★**The only brake on the Claude side is the in-progress lock**★ — CLI 2.1.280 returns a 429 as `rate_limits: null`, so it looks like `Failed` and does not reach `Rejected`, so the block during rejection does not engage (TRD §6 #21). Even then, values come in through conversation.
- With the 「간격」 row gone from the daemon decision table, a `refresh` after a query has finished always issues a new query (if in progress, it joins · if rejected, `Rejected`).
- The spec of the small-display ⟳'s press decision (choosing targets · partial rejection · ignoring while in progress) = TRD §3 #102 ②-2.
- The usage slot is no longer a consumer of the `checked` · `enabled(ctx)` fields that ADR-0252 added. The ctx `usageRefreshable` and LayoutLeaf's usage-store subscription were removed in `910c214` — the `checked`/`enabled` fields and the rule 「조립처가 ctx 로 싣는다」 remain, and no state is carried now. **Open:** this change leaves the shared base (those fields) untouched (main decision 2026-09-29) — whether to remove it when there is no consumer is deferred.
- Toggle writes are a per-field atomic merge (`set_usage_slot`) — do not go back to a write that fully replaces from the webview copy (consecutive clicks overwrite each other). Deferred follow-up: the in-window `layout.setSlotContent` path still fills a missing field from the webview copy (`mergeUsageShows`).
- ★**Pressing the same field again before the echo = keep current behavior (user decision 2026-09-30)**★ — meaning: the checkbox draws the slot content the shell gave as is and does no optimistic update (ADR-0035). So a re-click before the echo sends the same absolute value (`!current[field]`), computed from the still-old value, once more, and the slot content does not change (the second click is effectively ignored). ★Do not 「고치지」 it with an optimistic toggle or a flip inside the shell★ — the app-wide handling is decided in the follow-up topic T-36 (`docs/tracking.md` · state of affairs · precedents = `docs/research/pre-echo-reinput-2026-09-30.md`).
- The popup's absolute reset time is also date + time without a weekday if it is on a day other than today (the same rule as decision 4).
