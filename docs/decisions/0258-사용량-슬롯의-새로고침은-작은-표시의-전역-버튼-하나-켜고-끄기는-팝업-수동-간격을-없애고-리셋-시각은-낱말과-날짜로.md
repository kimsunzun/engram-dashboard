## 맥락
PRD R12 는 수동 ⟳ 를 작은 표시 · 팝업 · 슬롯 우클릭 메뉴 세 곳에 두었고, R8 은 회사별 켜고 끄기를 우클릭 메뉴에만 두어 팝업을 보기 전용으로 했다(R7). D11 은 회사별로 직전 조회 뒤 30초 안의 ⟳ 를 들고 있는 값으로 답하게 했다. 작은 표시는 리셋 시각을 글리프 ↻ 와 요일(주간 창)로 적었다.

그 「세 곳」과 메뉴 ⟳ 는 2026-09-26~27 인터뷰 요약(`docs/research/usage-limit-display-ui-survey-2026-09-26.md:13-22`)에서 처음 나오며 사용자 원문은 남아 있지 않다. 같은 날 인계는 메뉴 토글만 적었고 ⟳ 는 없었다. 사용자는 2026-09-29 작은 표시·메뉴 새로고침을 그렇게 요청한 적이 없다고 밝혔고, 아래 배치를 골랐다. ★이 출처 기록의 정본이 이 절이다★ — PRD R12 · TRD §3 #102 ① 은 여기를 가리킨다.

## 결정
1. **수동 ⟳ = 작은 표시(상시)의 전역 버튼 하나.** 격자 오른쪽 · 세 폭 단계 모두 · 켠 회사를 함께 새로 고친다 · 두 회사 다 끄면 숨긴다. 팝업의 회사별 ⟳ 는 없앤다. 슬롯 우클릭 메뉴엔 사용량 항목이 하나도 없다(⟳ 새로고침 · ☑ Claude/Codex 표시 모두) — 범용 슬롯 메뉴만 남는다. 명령 `usageSlot.refresh`·`usageSlot.toggleClaude`·`usageSlot.toggleCodex` 는 LLM 경로로 남는다(CLAUDE.md 「LLM-우선 제어」) — 빠지는 것은 메뉴 항목뿐이다.
2. **켜고 끄기는 팝업 맨 아래 한 줄 「슬롯에 표시: ☑ Claude ☑ Codex」**(회사가 늘면 줄바꿈). 팝업 상세는 켠 회사만 보인다 — 끈 회사는 구독하지 않아 보일 값이 없다(사용자: 「끄면 사용량도 안보내고 좋네」). 두 회사 다 끄면 작은 표시의 안내가 「우클릭해서 표시할 항목 고르기」에서 「클릭해서 표시할 항목 고르기」로 바뀌고, 팝업엔 켜고 끄기 줄만 보인다. 그래서 팝업은 더는 보기 전용이 아니다(PRD R7 개정). (구현 세부 — 메인 결정 2026-09-30: 토글은 자기 칸만 절댓값으로 웹뷰 Tauri 커맨드 `set_usage_slot` 에 보내 셸의 락 안 칸별 병합을 탄다 — 전량 교체는 빠른 연속 클릭·동시 LLM 쓰기가 서로를 덮어서다. TRD §3 #102 ⑤.) **ADR-0063 과의 관계(사용자 결정 2026-09-30 — 선택지 A):** 이 웹뷰 IPC 는 ADR-0063 의 불변식 「슬롯 콘텐츠 변경은 `set_slot_content` 단일 경로」와 그 거부 대안 「variant별 전용 command」에 어긋나고, 사용자가 그 예외를 받아들였다. 그 거부 대안(command 폭발)이 일반적으로 다시 열리는 것은 아니다 — 칸별 부분 병합은 완전한 `SlotContent` 에 실을 수 없고(serde 기본값이 빠진 `show_*` 를 true 로 채운다), 버스 동사 `layout.setSlotContent` 는 여전히 제네릭 명령 하나이며 이미 사용량을 같은 `apply::set_usage_slot` 으로 보낸다. 새 IPC 는 사람 경로가 그 같은 병합에 닿게 할 뿐이다(ADR-0081 결정 3 — 사람·LLM 이 같은 적용 함수). 거부한 선택지 B 는 「거부한 대안」 절에 둔다.
3. **수동 ⟳ 의 30초 간격을 없앤다**(PRD D11 의 30초 조항 · TRD §3 #38 · 데몬 상수 `REFRESH_MIN_SPACING`). 남는 것은 둘 — 조회가 진행 중이면 결과가 올 때까지 누름은 새 조회를 내지 않는다(작은 표시 ⟳ 는 대상 중 하나라도 진행 중이면 누름을 통째로 무시하고, 데몬은 그와 별도로 회사별로 진행 중 조회에 합류시킨다 — TRD §3 #102 ②-2) · 거절(429) 중엔 조회하지 않는다(R24 · D22 그대로). 사용자: 「다른데도 쿨타임 없으면 그대로 하자. 막히면 그네들이 알아서 적게 누르겠지」.
4. **작은 표시의 리셋 시각은 글리프 ↻ 대신 낱말** — 「리셋 00:58」 · 영어 「resets 00:58」(한국어가 더 짧다 · 팝업의 기존 「리셋 …」 과 같은 낱말 · 전역 ⟳ 버튼과 글리프가 겹치지 않는다). 리셋이 오늘이 아닌 날이면 요일이 아니라 **날짜**를 날짜 → 시각 순으로 — 「리셋 10/1 01:48」 · 「resets Oct 1 01:48」. (구현 주: 지금 코드는 날짜를 숫자 월·일로 짠다 — 영어 월 이름은 en 표를 더할 때 로캘 포맷터가 필요하다. en 표는 아직 없고 `ko.ts` 뿐이다.)

## 거부한 대안
★**아래 켜고 끄기 B·C · 맨 「☑ 표시」 · 리셋 표기 항목에 붙은 사유는 제시 때의 트레이드오프다 — 사용자는 A·날짜를 골랐다.**★ 그 사유는 메인이 선택지를 올릴 때 적은 것이고, 사용자가 그 사유로 거부했다는 원문은 남아 있지 않다(`.claude/handoff/attachments/usage-slot-main-notes-2026-09-29.md` 「USER DECISIONS — session 2」). 요일의 함정(다음 주 같은 요일)은 조사 문서도 「메인 추론, 피어 근거 아님」으로 적는다. 사용자 결정으로 거슬러 가는 사유는 그 자리에 따로 적었다.
- **켜고 끄기 B — 회사 머리마다 「☑ 슬롯에 표시」** — 같은 낱말이 회사 수만큼 되풀이되고, 끈 회사도 줄을 차지해 회사가 늘면 길어진다.
- **켜고 끄기 C — 회사마다 스위치 + hover 설명** — hover 하기 전엔 뜻을 못 읽는다.
- **맨 「☑ 표시」** — 이 팝업에 보이는 것인지 슬롯에 보이는 것인지 모호하다.
- **리셋 표기 — 시계 아이콘** · **시각만**(「00:58」 은 남은 시간으로 읽힌다) · **요일 「수 01:48」**(「리셋 수」 가 횟수로 읽히고, 다음 주 같은 요일의 리셋이면 모호하다 — 뒤쪽은 메인 추론) · **「(수)」·「수요일」 변형** · **카운트다운**(남은 시간은 팝업에만 두기로 한 앞선 결정 — 이것은 사용자 결정 2026-09-29 다).
- **30초 간격 유지 · 10초로 단축(Usage4Claude 선례)** — 사용자가 간격 없음을 골랐다(위 결정 3 의 인용).
- **B — `set_slot_content` 를 부분 칸으로 넓히기**(ADR-0063 예외 대신) — 사용자 사유 = 구현이 더 든다(사용자 결정 2026-09-30 — 선택지 A · 기록 = `.claude/handoff/history/20260930-033545-사용량-슬롯-⟳·토글-재배치-커밋-문서리뷰·팝업문서·todo이관-대기.md:20` 「B(set_slot_content 확장)는 구현이 더 들어 기각」). 그 「더」의 내역(모든 `setSlotContent` 호출부를 건드리고 리뷰를 한 바퀴 더 돈다)은 메인이 선택지를 올릴 때 적은 트레이드오프다 — 사용자 원문이 아니다.
- **클라이언트 대기 선택(pending-selection) 우회**(전량 교체를 유지한 채 웹뷰가 눌린 값을 쥐고 있기) — 반영 순서가 뒤바뀌거나 일부가 실패하면 여전히 샌다(코드 리뷰 2차 — TRD §3 #102 ⑤).

## 영향 / 불변식
- **받아들인 위험:** 연타로 Claude 429 를 부를 수 있고, 그 거절이 한 시간쯤 갈 수 있다 — 출처 = ClaudeBar 저장소의 설계 문서(`docs/providers/claude/design.md:61-62`)를 인용한 조회 서베이 `docs/research/claude-usage-query-method-survey-2026-09-27.md` §0-3 · 검증 표(벤더 미확인 · 그 관측은 비공개 사용량 주소 B 를 직접 부른 것이고, A 가 같은 제한을 공유하는지는 같은 서베이 §0-4 의 「가능성 높음 — 버킷 미확인」). ★**Claude 쪽의 브레이크는 진행 중 잠금 하나뿐이다**★ — CLI 2.1.280 은 429 를 `rate_limits: null` 로 돌려줘 `Failed` 로 보이고 `Rejected` 에 닿지 않으므로 거절 중 차단이 걸리지 않는다(TRD §6 #21). 그동안에도 값은 대화로 들어온다.
- 데몬 판정 표에서 「간격」 행이 사라져, 조회가 끝난 뒤의 `refresh` 는 늘 새 조회를 낸다(진행 중이면 합류 · 거절 중이면 `Rejected`).
- 작은 표시 ⟳ 의 누름 판정(대상 고르기 · 일부 거절 · 진행 중 무시)의 명세 = TRD §3 #102 ②-2.
- 사용량 슬롯은 ADR-0252 가 더한 `checked`·`enabled(ctx)` 칸의 소비자가 아니게 된다. ctx `usageRefreshable` · LayoutLeaf 의 사용량 스토어 구독은 `910c214` 에서 걷었다 — `checked`/`enabled` 칸과 「조립처가 ctx 로 싣는다」 규칙은 남고 지금 싣는 상태는 없다. **미결:** 이번 변경은 공용 기반(그 칸)을 건드리지 않고 남긴다(메인 결정 2026-09-29) — 소비자가 없으면 걷을지는 뒤로 미룬다.
- 켜고 끄기 쓰기는 칸별 원자 병합(`set_usage_slot`)이다 — 웹뷰 사본으로 전량 교체하는 쓰기로 되돌리지 말 것(연속 클릭이 서로를 덮는다). 미룬 후속: 창 안 `layout.setSlotContent` 경로는 빠진 칸을 아직 웹뷰 사본에서 채운다(`mergeUsageShows`).
- ★**같은 칸을 반영(echo) 전에 다시 누르는 것 = 현행 유지(사용자 결정 2026-09-30)**★ — 뜻: 체크박스는 셸이 준 슬롯 내용을 그대로 그리고 낙관적 갱신을 하지 않는다(ADR-0035). 그래서 반영 전의 재클릭은 아직 옛 값에서 계산한 같은 절댓값(`!current[field]`)을 한 번 더 보내고, 슬롯 내용은 바뀌지 않는다(두 번째 클릭이 사실상 무시된다). ★낙관적 토글이나 셸 안 뒤집기(flip)로 「고치지」 말 것★ — 앱 전체 처리는 후속 주제 T-36(`docs/tracking.md` · 실태·선례 = `docs/research/pre-echo-reinput-2026-09-30.md`)에서 정한다.
- 팝업의 절대 리셋 시각도 오늘이 아닌 날이면 요일 없이 날짜 + 시각이다(결정 4 와 같은 규칙).
