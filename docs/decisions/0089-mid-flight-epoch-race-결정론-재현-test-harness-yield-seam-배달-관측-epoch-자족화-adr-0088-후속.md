# ADR-0089: Deterministic reproduction of the mid-flight epoch race — a test-harness yield seam + making the delivery observation self-sufficient in epoch (an ADR-0088 follow-up)

- 상태: 확정 (2026-07-20, basis: user approval (a batch start of the 3 S17 stage 1 follow-up decisions) + /review code deep 3 lenses (doc-aware, concurrency, cross-family Codex) 2 rounds PASS + /qa full PASS)
- 관련: ADR-0088 (delivery correctness verification — this decision is the announced follow-up of its Stage 1) · ADR-0086 §F5 (the epoch race is design-accepted — this decision does not change that acceptance and only makes the *observation* deterministic) · ADR-0006 (lock discipline — the hook firing and drop locations follow this discipline) · ADR-0012 (isolation harness)

## 맥락
Oracle 5 of ADR-0088 Stage 1 (epoch rotation delivery) honestly left two gaps: ① the **true mid-flight epoch race** (resolve sees epoch 0, and right after that a restart makes it epoch 1, and then the write arrives) cannot be **reproduced deterministically** because production has no yield point where an outside party can interpose between resolve and write in `handle_send` — only sequential replacement was verified. ② `DeliveryObservation` does not carry the receiver epoch, so "exactly which incarnation received it" **cannot be asserted from the record alone** (only indirectly confirmed by comparing the capture buffers). The user approved starting this follow-up (2026-07-19~20).

## 결정
1. **A test-hookable yield seam in `handle_send`** — put a `mid_send_hook` (RwLock\<Option\<Arc\<dyn Fn()\>\>\>) gated by `#[cfg(feature = "test-harness")]` on `ControlRegistry`, and `handle_send` fires it **right before** the `write_stdin_observed` call (the last point of the resolve↔write gap). The firing is a call outside the lock after cloning the Arc (ADR-0006), and the setter drops the old hook after releasing the lock. It is not compiled at all in production builds.
2. **A daemon `test-harness` feature + a self-dev-dependency** — the daemon references itself in `[dev-dependencies]` together with the feature, so `cargo test -p engram-dashboard-daemon` turns on the hook without a flag. It was demonstrated with cargo tree that the feature is not unified into the production graph (normal edges). **One operational caution documented:** `cargo build --release --all-targets` unifies the dev-feature, so do not build the release binary in that form (Cargo.toml comment).
3. **Making the delivery observation self-sufficient in epoch** — `WriteOutcome` gets `epoch: u32` (the by-construction value of the session incarnation that executed the write), and `DeliveryObservation` gets `to_epoch: Option<u32>` (success = `Some(outcome.epoch)` = the **landing epoch**, failure = `None` = "no completed write → no incarnation to prove" — not a claim that zero bytes moved). Do not put an epoch condition into `is_delivered()` (it is an observation axis, not a validity gate).

## 거부한 대안
- **Keep it nondeterministic (verify only sequential replacement)** — the position that since the race is design-accepted (F5), an indirect observation is enough. Rejected: scheduler-dependent reproduction cannot catch a regression, and the gap that the oracle 5 docstring left ("this test does not claim the race is safe") becomes permanent. Deterministic coverage had been announced as a follow-up and the user chose to start it.
- **epoch pinning (pinning delivery to the epoch at resolve time)** — rejected: a direction ADR-0086 §F5 explicitly rejected — mail is addressed to the logical agent, so pinning would cause loss during a restart. This decision does not change the delivery semantics by even 1 bit (the seam is observation-only).
- **Recording the resolve-time snapshot epoch in to_epoch** — rejected: the purpose of the race observation is "which incarnation it actually landed on", so carrying the resolve snapshot destroys the record's self-sufficiency (regressing to an indirect comparison). The `self.epoch` of the landing session is the only correct source (the same Arc as the write).
- **Requiring a `--features` flag to run tests (instead of the self-dev-dep)** — rejected: a bare `cargo test -p engram-dashboard-daemon` call would silently run as a build without the hook, a case where the new oracle always fails or silently skips. The self-dev-dep turns the feature on only in the dev graph without a flag.
- **Wrapping the hook in catch_unwind** — rejected (observation only recorded): unlike the observer (which exists in production), the hook is test-only and not compiled in production, so panic propagation is a normal test failure signal. Wrapping it would instead bury the failure.

## 근거
- The new oracle `stage1_lifecycle_mid_flight_epoch_race_lands_on_new_incarnation_deterministic`: resolve=epoch 0 → the hook replaces it with an epoch 1 session of the same AgentId → the write lands → 1 record · `is_delivered` · `to_epoch==Some(1)` · bytes only in the epoch-1 buffer. TDD discriminating power demonstrated: disabling the hook firing fails with `to_epoch=Some(0)` (the same assertion also catches a resolve-time wiring regression).
- Review: doc-aware + concurrency lens + cross-family (Codex) 2 rounds — the fire point is lock-free (zero locks held at firing) · guard-lifetime correct · no feature inflow into the production graph (cargo tree normal edges empty) · feature-off byte-identical demonstrated. All 5 Codex R1 FIX items (documenting –all-targets · dropping the old hook inside the lock · an overclaiming failure comment · the missing to_epoch None assertion · the test hook Arc cycle) were applied, then R2 PASS.
- QA full: all-member regression + isolation + frontend + GUI measurement (a spawn→output→kill smoke, with the new binary) PASS.

## 영향 / 불변식
- **The seam is observation-only — delivery semantics unchanged.** With the feature OFF, `handle_send` behaves identically to before the change (the only production code movement is the drop location of the old hook in the setter, limited to test-harness builds). An attempt to put epoch pinning on top of this seam violates F5.
- **`to_epoch` is the landing epoch — reverting to the resolve snapshot regresses the self-sufficiency.** The only epoch source of a success record is the `self.epoch` of the session that executed the write.
- **Do not build the release binary with `--all-targets`** (dev-feature unification — the daemon Cargo.toml comment is the anchor).
- Code anchors: `crates/engram-dashboard-daemon/src/control/{ingress.rs(fire 지점·to_epoch),registry.rs(mid_send_hook)}` · `crates/engram-dashboard-core/src/agent/{types.rs(WriteOutcome.epoch),session.rs(write_input_observed)}` — each adjacent to a `// ADR-0088` anchor (this ADR is the *why* of that follow-up decision).
