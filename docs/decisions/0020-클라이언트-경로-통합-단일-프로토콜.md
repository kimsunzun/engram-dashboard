# ADR-0020: Client/backend path unification — a single protocol + a transport-neutral dispatch core

- 상태: 확정 (2026-06-17, basis: `/consult` 3-way cross-validation job `20260617-021239-consult-client-unification` + the judge's decision)
- 관련: ADR-0011(agentClient control surface) · ADR-0002/0003(OutputSink seam) · ADR-0001(kill 2 verbs) · ADR-0005(finalize once) · ADR-0006(lock order) · `crates/engram-dashboard-daemon/src/ws.rs` · `crates/engram-dashboard-protocol/messages.rs` · `src-tauri/src/commands/` · `src/api/{agentClient,embeddedClient,daemonClient}.ts` · Amended by ADR-0037 (decision 3: where the protocol semantics live — JS ProtocolClient → Rust (DaemonClient/protocol_state))
- Scope: unify the local (embedded) / remote (daemon) **dual paths** into a single protocol + a single dispatch core and swap only the transport. This ADR = decisions + boundaries; the implementation steps are in the TRD (`docs/process/S12-daemonization/client-unification-trd.md`).

## 맥락

The frontend has 1 `AgentClient` interface + 2 implementations (`EmbeddedClient` = Tauri invoke/Channel, `DaemonClient` = WS + protocol). The backend likewise has two entry points wrapping the same `AgentManager` (`src-tauri/commands/*.rs` thin wrappers, `daemon/ws.rs` dispatch). The protocol (`AgentCommand`/`AgentEvent`) is already designed to correspond 1:1 with every AgentClient method, but **embedded bypasses this protocol** (calling Tauri invoke directly) and only the daemon uses it. The result: every new feature needs wiring on both sides, twice (2x upkeep). The core (AgentManager) and everything below it are already shared as one copy.

Key observation (consult B = pointed out by claude): of the 10 arguments of `dispatch(cmd, conn_tx, manager, registry, multiview, ...)`, the only pure business one is `manager`, and the dispatch body already responds only through the `conn_tx` (WsOutbound mpsc) · `reply()` abstractions, so it **does not touch TcpStream/tungstenite/the frame codec directly**. That is, the transport cut line is already almost drawn.

## 결정

**Unify. Make only the carrier (transport) swappable, and share the protocol + dispatch as a single copy.**

1. **(Decision 1) Message-level extraction.** handshake/auth/Origin/frame codec/keepalive stay in the WS adapter; behind them, extract a **transport-neutral ConnectionCore** (dispatch + per-conn session state) that takes `AgentCommand 입력 + Outbound(AgentEvent/binary) sink 출력` (AgentCommand in, Outbound (AgentEvent/binary) sink out). For future carriers (gRPC/mobile), the input and output are fixed as a trait (`OutboundSink`) (§0 low risk + long term → over-engineering allowed).
2. **(Decision 2) The embedded carrier = one generic `agent_command(AgentCommand)` invoke + a Channel (AgentEvent/output receive).** Serialization happens anyway across the WebView2 IPC boundary → merging 20 invokes into 1 (the number of serializations is the same or lower). **Output encoding is per carrier**: InProc = base64 Channel (the existing PtyEvent kept), WS = binary frame. `OutputSink` goes only as far as "frame to the sink", and the encoding is owned by the sink implementation (consistent with ADR-0003).
3. **(Decision 2 supplement — singled out by GPT alone, required)** **Serialize concurrent embedded invoke racing.** In Tauri commands each invoke is spawned as an independent async task, so when they **arrive in parallel the command order is nondeterministic** (WS is naturally serial because of the single read_task). The embedded adapter also **serializes commands with a per-connection inbound mpsc + a single command loop** to guarantee semantic equivalence with WS.
4. **(Decision 3) Generalize the frontend `ProtocolClient` on top of a `Transport` trait.** request_id matching · seq dedup · the epoch guard · reconnection are protocol semantics independent of the carrier → gather them in one place. `WsTransport` (with reconnection) / `InProcTransport` (invoke + Channel, always connected → reconnection/dedup converge naturally to no-ops). For consistency, invoke is also unified as ack-only (request_id matching lives in the one place, ProtocolClient).
5. **lease/viewport/registry — no bypass.** Embedded also takes the same ConnectionCore path, and with a single client they are naturally neutralized: one conn_id → `check_input` is always Allow, one viewport → smallest = its own size. No `if embedded { skip }` branch (it would interleave when embedded and remote attach at the same time in the future). `ConnRegistry` (status fanout) stays as an internal detail of the WS adapter, and status broadcast goes through a `StatusSink` that the carrier implements (already TauriStatusSink vs DaemonStatusSink).
6. **Crate location.** ConnectionCore depends on both protocol and core → **it cannot go in the core crate** (the core's zero tauri/protocol imports isolation, ADR §4 maintained). Put it in the daemon crate (or a newly created `connection-core` crate). The Tauri adapter (src-tauri) calls it.

## 거부한 대안

- **(Decision 1b) byte-stream generic** — generalize `handle_connection` as `S: AsyncRead+AsyncWrite`, and locally reuse the whole WS stack through `tokio::io::duplex`. **Rejected:** it permanently burdens the local path with WS handshake/frame masking/Origin/token comparison/keepalive + the debugging call stack gets longer through tungstenite + a headless unit test would have to set up duplex + handshake. An anti-pattern that turns local into a "fake WebSocket". (The need to regression-test the WS protocol locally is already covered by the in-proc server of `ws_e2e.rs`.)
- **(Decision 2b) duplex stream carrier** — rejected for the same reason as decision 1b.
- **(Decision 3b) Write a new thin EmbeddedClient** — after unification embedded also needs AgentCommand serialization + Channel decoding + (defensive) dedup, so it is no longer thin and would reimplement a subset of the DaemonClient logic → "two copies of wiring" revived in another form. A head-on conflict with the goal of the refactor.
- **Auto-generating the two copies with codegen** — it automates only the symptom (two copies of wiring) and does not create a single dispatch. It does not achieve §5 (single entry point), leaves room for subtle behavior differences between the two paths (R1~R3), and adds macro debugging cost. Unsuited to the 10-year/swappability principle.
- **always-loopback-daemon (discard embedded, local also over WS loopback)** — the simplest with one client copy, but it always occupies a TCP port (firewall/conflict surface), the local hot path permanently pays WS framing + masking + loopback TCP (extending the cost of decision 1b to the whole app), and adds boot handshake latency. consult A (gemini) elevated it to "seriously considered", but this contradicts its own basis for decision 1a. Rejected (see ttyd/zellij prior art if revisited in the future).
- **request_id via the invoke return (a Tauri-only hybrid)** — it simplifies embedded, but request_id matching would split per carrier and break the single ProtocolClient of decision 3(a) (two copies revived). Rejected, but recorded as an escape hatch if there is an embedded performance problem.

## 근거

- consult 3-way blind (GPT · Gemini · Claude-opus) + judge: **all three agreed on 1a/2a/3a.** The judge's top trust = Claude (precise on code facts and ADR invariants, zero factual errors), required merge = GPT (singled out the decision 3 racing alone), reference only = Gemini (a seq-loss factual error — seq is a single-pump invariant of OutputCore, so the carrier cannot change it; overestimated always-loopback).
- The code has already reached the cut line (dispatch is unaware of the carrier) → 1a is minimum change, maximum effect. Confidence: decisions 1 and 2 **certain**, decision 3 **likely** (the difficulty of decomposing the 580-line DaemonClient is the variable).

## 영향 / 불변식 (regression risks — must not break during the refactor)

- **R1 Ack→replay→ReplayComplete FIFO** (while holding the subscribers lock, on_ready sends the Ack before the replay binary, ADR-0006/C4). Assert the order [Ack,Binary,ReplayComplete] with an OutboundSink mock (both carriers).
- **R2 seq dedup/high-water** (based on `lastDeliveredSeq`, replay_from does not touch the baseline = the lesson of the existing bug B). Unit test at the ProtocolClient (transport mock).
- **R3 epoch guard/Resume** (if resubscribe epoch=null, FromOldest duplicates = the existing bug A). **Baseline coverage confirmed**: `ws_e2e.rs` case06/case10 + the frontend vitest reconnection regression.
- **R4 finalize once / terminal split of duties** (terminal = the pump alone, the frontend decides from agent-list-updated, ADR-0005). Once with a headless StatusSink mock.
- **R5 kill 2 verbs** (ADR-0001) — the Kill arm delegates to the manager so the core is unchanged, safe.
- **R6 close_signal** (WS queue saturation out-of-band) — **WS-specific, stays in the adapter** (do not extract). OutboundSink only returns SinkError, and the adapter interprets it per carrier.
- **R7 zero tauri imports in the core, isolation** (ADR §4) — ConnectionCore goes in the daemon/new crate. Keep `rg "use tauri" crates/engram-dashboard-core/src/` → 0 lines.
- **Test order:** fix the phase4 green baseline → pure move (zero functional change, rerun WS at every step) → add the Tauri adapter → WS/embedded conformance (equivalence) tests → real WebView2 measurement with cdp.mjs. Unit tests are updated/accumulated at every stage (user instruction).
