# ADR-0300: 창 번호는 살아 있는 창이 안 쓰는 가장 작은 수다 — 레이아웃 모델이 쥐고 OS 창이 없어질 때 풀며 영속 id 와 함께 저장한다

- 상태: 확정 (2026-10-26, 근거: 사용자 결정 2026-10-17(R1 — 비어 있는 가장 작은 번호 재사용 · R2 — label 은 단조 그대로) · 2026-10-23(Q3 — 모든 창 번호 · 메인 = 늘 1 · 번호 표식 자리 · 제목 꼴 / Q8 — 영속 id 와 함께 저장 / 리뷰 1차 지적 ① — 복원 중 잠깐 겹침 수락) + 메인 결정 M1 · M2 · M3 · M24(TRD §12-3) + PRD 기본값(메인 제안 — D2 의 복원 쪽 · D3 고치기 규칙 · D13 · R29) + 구현 U1 `4cefce48` · U2 `f27de03c` · U8a `982e07a8`(번호 표식))
- 관련: PRD `docs/process/S21-window-chrome/prd.md`(0.5판 — R1 · R2 · R3 · R24 · R29 · D1 · D2 · D3 · D13 · W7 · W12 · AC1 · AC20 · AC25 · AC31 · AC38) · TRD `docs/process/S26-window-chrome/trd.md`(0.3판 — §2-4 불변식 1 · §3-3 · §3-4 · §4-1 · §5-6 · §5-7 · §7-3 · §12-3) · 조사 `docs/research/window-identity-display-2026-10-23.md`(Q3) · ADR-0299(예열 창 — 번호를 쥐지 않는다) · ADR-0301(OS 제목을 입히는 법) · ADR-0302(창 인자는 번호를 받지 않는다) · ADR-0303(번호 표식이 서는 제목 줄) · ADR-0305(첫 화면 전 실패 — D13 예외가 바뀐 까닭) · `src-tauri/src/layout/numbering.rs` · `src-tauri/src/layout/manager.rs` · `src-tauri/src/state/codec.rs` · step-log S26 · 트래킹 T-66

## 맥락

팝아웃 창 제목이 「Engram — slot-popup-11」이었다 — 창 label 은 단조 카운터라 창을 닫아도 번호가 돌아오지 않는데 그것이 사람에게 보였다(PRD §1 · 코드). 메인과 팝아웃도 겉보기로 같았다(사용자 2026-10-20 「똑같으니깐 뭐가 메인인지 모르겠네」 — 트래킹 T-66 「창 구분」). OS 제목 표시줄을 걷으면(ADR-0303) 창 안에 창을 가를 것이 없어지고, Windows 11 작업 표시줄은 기본으로 단추 글자를 숨긴다(PRD Q3).

사람은 「2번 창」으로 말하고 싶고, LLM 은 다시 쓰이지 않는 id 로 창을 가리켜야 한다(Q9 — ADR-0302). 그래서 사람에게 보이는 작은 번호를 label 과 따로 두고, 그 번호의 수명 · 주인 · 저장을 정해야 했다.

## 결정

1. **새 창의 번호 = 살아 있는 창들이 쓰지 않는 가장 작은 번호**(사용자 결정 2026-10-17 — R1). 1 · 2 · 3 에서 2 를 닫으면 다음 새 창 = 2. **모든 창이 번호를 갖고 메인은 늘 1 이다**(사용자 결정 2026-10-23 — Q3 · D1). **살아 있는 창의 번호는 바뀌지 않는다** — 앞 번호 창이 닫혀도 당겨 매기지 않고 재시작을 넘어서도 같다(D2 · 사용자 결정 2026-10-23 — Q8). 내부 label 은 지금처럼 단조이고 번호와 따로다(사용자 결정 2026-10-17 — R2).
   - 「살아 있는 창」 = 모델에 있는 창(숨은 · 최소화한 창 포함) **+ 모델에서 빠졌지만 OS 창이 아직 없어지지 않은 닫히는 창**(D13 · PRD R1 — 기본값 메인 제안).
   - 숨은 예열 창은 모델 밖이라 번호를 쥐지 않는다 — 맡아 모델에 드는 순간 받고, 되물리면 번호 없이 돌아간다(PRD R1 · D13 — 기본값 메인 제안 · ADR-0299). 열기 실패 · 넣기 거절로 거둔 창은 번호를 잡은 적이 없다.
2. **번호의 주인 = 레이아웃 모델**(메인 결정 M1) — `ViewManager` 의 창 항목 칸 `WindowTabs.number` · 닫히는 창 표 `closing` · 순수 셈 모듈 `layout/numbering.rs`(`smallest_free` · `resolve_saved`). 번호는 창 항목을 넣는 그 락 안에서 받으므로 동시에 만든 둘이 같은 번호를 받지 않는다. 넣고 빼는 길은 사설 메서드 둘(`insert_window_entry` · `retire_window_entry(label, Os::{Alive, Gone})`)만 지난다(TRD §2-4 불변식 1).
3. **번호는 OS 창이 실제로 없어질 때(`Destroyed`) 풀린다**(D13 — 메인 결정 M2 가 남겼다). 모델에서 빼는 길(`window.close` · 닫기 요청 · 마지막 탭 닫기 · 0탭 자가닫힘)은 그때까지 번호를 `closing` 에 쥔다.
   - **OS 창이 이미 없는 창**(부팅 복원 팝아웃을 못 열었거나 · 사본 수락 뒤 바꾸기 전에 사라진 창)은 `closing` 을 거치지 않고 곧바로 푼다 — `drop_window_gone`(메인 결정 M24 · PRD D13 예외 — 기본값 메인 제안 2026-10-24).
   - `Destroyed` 정리가 넷(`LayoutState` · 라우터 · 채널 명부 · 데몬 클라이언트) 중 하나라도 없어 돌지 못하면 `LayoutState` 하나로 `release_window_number` 를 불러 푼다(TRD §4-1 · U2 리뷰).
   - `Destroyed` 가 끝내 안 오면 그 번호는 실행 끝까지 잡힌다 — 받아들인다(W7).
4. **번호를 영속 id 와 함께 화면 상태에 저장하고 부팅 · 크래시 사본 수락 때 되살린다**(사용자 결정 2026-10-23 — Q8). `shell\state\state.json` 의 창 항목에 선택 칸 `number`(쓰기는 늘 값 · `STATE_VERSION` 은 1 그대로). 읽기는 너그럽다 — 정수 `1..=999` 만 쓰고(상한 = 메인 결정 M3) 그 밖의 값은 없음 + 경고이며, ★창을 건너뛰지 않는다★. 고치기 규칙(D3 — 기본값 메인 제안): 메인 = 늘 1(저장값을 보지 않는다) · 팝아웃이 적은 1 = 없음 · 같은 번호를 둘 이상 적었으면 저장 순서 앞 창만 · **이미 쥔 창이 지킨다**(복원 창이 비켜선다) · 바른 번호를 먼저 다 세운 뒤 없음인 창이 저장 순서대로 비어 있는 가장 작은 번호를 받는다. 사본 수락(`adopt_restored`)은 옛 팝아웃(닫히는 중 포함)의 번호를 다 풀고 사본 번호를 세운다. 탭 이름 · 「정한 이름인가」 · 영속 id · 번호는 한 스냅숏에 든다(R29 — 기본값 메인 제안).
5. **보이는 곳**(사용자 결정 2026-10-23 — Q3): 제목 줄의 탭줄 **오른쪽 끝 · 창 단추 바로 왼쪽** 번호 표식(번호만 · 늘 · 창이 하나여도 「1」 · 탭이 먼저 줄고 표식은 그대로 · 끌 자리 — ADR-0303) + OS 제목 「<탭 이름> - Engram:<n>」(입히는 법 = ADR-0301) + `window.list` 의 `details[].number`(ADR-0302). 번호가 두 · 세 자리가 되면 표식이 그만큼 넓어지고 번호를 자르지 않는다(R24 · AC38 — 기본값 메인 제안).
6. **복원 · 사본 수락 도중 같은 번호가 잠깐 두 창에 보이는 것은 받아들인다**(사용자 결정 2026-10-23 — 「어차피 잠깐 보이는거니 노상관」 · W12). 사본 수락의 차례(사본 창을 보인 뒤 옛 창을 거둔다)는 바꾸지 않는다. 막는 것은 닫히는 창이 없어진 뒤 남는 겹침뿐이다(D3 · AC31).

## 거부한 대안

- **번호를 저장하지 않고 부팅마다 메인부터 저장 순서대로 다시 매기기**(PRD Q8 ② · 0.1판 D3) — 1 · 3 으로 끄면 1 · 2 로 켜져 「3번 창」이 2 가 된다. 기각 = 사용자 결정 2026-10-23(Q8 ①).
- **모델에서 빠질 때 번호를 풀고 닫히는 창을 먼저 숨기기**(PRD D13 의 거부한 갈래) — 숨기기 호출이 돌아온 것은 화면에서 사라졌다는 OS 확정이 아니어서 실패 · 늦음을 따로 다뤄야 하고, 닫는 길(닫기 요청 · `window.close` 의 직접 파괴 · 사본 수락의 거두기)마다 숨기기를 끼워야 한다. 숨기기 없이 「모델에서 빠질 때」 푼 PRD 0.2판은 같은 번호 둘이 보였다(PRD 2차 리뷰 BLOCK). 기각 강도 = 리뷰(BLOCK) + 서술.
- **D13(닫히는 창 번호 쥐기)을 걷기** — PRD 는 TRD 가 비싸다고 보면 새 사용자 결정 없이 걷어도 된다고 맡겼다(사용자가 받아들인 잠깐 겹침 전반에 든다). 걷으면 보통 닫기 뒤 새 창이 닫히는 창과 같은 번호를 잠깐 보이고 AC20 ② 를 걷어야 한다. 남기는 값은 모델 안 표 하나 + 넣고 빼는 사설 메서드 둘 + `Destroyed` 정리의 한 줄이다(메인 결정 M2 · TRD §4-1). 기각 강도 = 서술(비용 셈).
- **예열 창이 지어질 때 미리 번호를 쥐기**(PRD D13 의 다른 갈래) — 그 번호가 맡을 때까지 막히고, 그사이 앞 번호가 비어도 예열 창은 쥔 번호로 나와(메인 · 2 · 예열 창 3 에서 2 를 닫고 새 창을 열면 3) 「살아 있는 창이 쓰지 않는 가장 작은 번호」(사용자 결정 2026-10-17)와 어긋난다 — 맡을 때 다시 매기면 이 결정과 같아진다. 기각 강도 = 사용자 결정 규칙과의 충돌.
- **복원이 기다려 번호가 `Destroyed` 뒤에만 비게 하기**(PRD 리뷰 1차 지적 ① 이 낸 규칙) — 사용자가 잠깐 겹침을 받아들였다(「어차피 잠깐 보이는거니 노상관」). 명령은 번호가 아니라 영속 id 로 창을 가리켜 겹침의 영향이 없다(Q9). 기각 = 사용자 결정 2026-10-23.
- **OS 창이 이미 없는 창도 보통 닫기(`close_window` → `closing`)로 빼기**(TRD 0.1판) — 그 창의 `Destroyed` 는 이미 지나갔거나 오지 않아 번호가 실행 끝까지 잡힌다(TRD 리뷰 Claude ⑥). 기각 강도 = 코드.
- **번호를 보이는 다른 자리**(PRD Q3 의 갈래 · 옛 메인 제안) — ① 창이 둘 이상일 때만 탭바 왼쪽 끝 표식 + 제목 끝 번호: 창 수가 1 ↔ 2 로 바뀔 때 탭이 쓸 폭이 흔들린다 · ② 표식을 늘: 채택한 꼴이 이 「늘」을 따르되 자리는 왼쪽이 아니라 오른쪽이다(대가 = 창이 하나여도 「1」 — 받아들임) · ③ OS 제목에만(메인 = 번호 없음 · 0.1판 권장): 창 안에서 안 보인다 · ④ 안 보임(`window.list` 만): 사람이 「2번 창」이라 말할 근거가 없다 · 옛 메인 제안(탭이 없을 때만 「Engram N」): 메인은 빈 탭을 늘 하나 남기고 팝아웃은 탭이 0 이 되면 닫혀 번호가 사실상 안 보인다. 기각 = 사용자 결정 2026-10-23(Q3).
- **메인만 따로 꾸미는 표식(색 · 배지)** — 주 창을 색 · 배지로 꾸미는 피어를 못 찾았고 주 창이 있는 앱은 기능 · 수명으로 가른다(조사 식별 결론 5 · PRD R24 — 기본값 메인 제안). 메인 구분은 번호 1 + 메인 ✕ 의 뜻(ADR-0303)이 채운다. 기각 강도 = 조사(피어 부재).

## 영향 / 불변식

- **번호 셈은 `ViewManager` 메서드 안에서만 한다**(TRD §2-4 불변식 1) — `windows` 칸을 직접 `insert` · `remove` 하는 새 코드를 쓰지 않는다(그 칸이 `pub` 인 것은 시험 · 영속 변환의 읽기 때문). 어기면 `closing` 과 살아 있는 번호 집합이 갈라져 같은 번호가 둘에게 가거나 번호가 샌다.
- `closing` 은 영속하지 않는다. `window.list` 는 닫히는 창을 싣지 않으므로 그 잠깐 `window.list` 에 없는 번호가 비어 있지 않을 수 있다(1 · 2 · 3 에서 닫히는 2 가 아직 있으면 새 창 = 4) — 도움말이 말한다(D13 의 대가).
- 번호는 사람과의 대화용이다 — 명령의 창 인자로 받지 않는다(ADR-0302 · Q9).
- 옛 빌드로 내리면 번호 칸이 사라져 다음 이 판 부팅에서 메인부터 저장 순서대로 다시 매겨진다 — 받아들임(저장 TRD §12 R3 · TRD §3-3).
- 첫 화면 시한에 먼저 보인 새 창은 번호 표식이 아직 없을 수 있다(ADR-0305).
- 앵커 — `layout/numbering.rs` · `ViewManager` 의 넣기 · 빼기 사설 메서드 · `release_closing` · `drop_window_gone` · 저장 번호 너그러운 읽기에 `// ADR-0300` 을 단다.
