# ADR-0105: 파킹 TTL 1h→24h 상향 — 인메모리 단계, 시계 기반 단일 규칙 유지

- 상태: 확정 (2026-07-25, 근거: /research light 선례 조사 + 사용자 결정 — 아래 근거 절)
- 관련: Amends ADR-0103 (파킹 TTL 1h → 24h — 인메모리 단계 한정) · ADR-0104(idle 게이트 — busy 대기가 TTL을 공유하게 되면서 재검토 촉발) · spec §5 정책 상수

## 맥락

C2(idle 게이트, ADR-0104)로 "살아있지만 턴 진행 중"인 수신자의 메시지도 파킹 TTL을 공유하게 되면서, 1시간 넘는 장기 턴 중 도착한 메시지가 만료될 수 있다는 리뷰 지적(2026-07-25 C2 deep 리뷰 info 항목)이 나왔다. 기존 1h는 정밀 근거 없는 균형값(오타 청소·메모리 위생·뒷북 방지)이었다. 사용자 지시로 유사 시스템 만료 정책 선례를 /research light로 조사한 뒤 결정.

## 결정

**파킹 TTL = 24h**(`PARK_TTL` 상수 1개 변경). **만료 면제 규칙 없음** — 시계 기반 단일 규칙 유지(부재든 busy 대기든 동일). cap 100/수신자·notice cap 예외·만료 시 장부 `expired` 기록(조용한 유실 금지)은 전부 불변. **영속화(디스크) 단계가 오면 재설계 전제**(사용자 명시 — 이 값은 인메모리 단계 한정).

## 거부한 대안

- **1h 유지 + 살아있는 수신자 스윕 면제(liveness-aware TTL)** — 조사한 6개 시스템(RabbitMQ·SQS·Kafka·Postfix·ejabberd·LLM 프레임워크) 어디에도 선례가 없는 자체 설계가 됨(RabbitMQ는 consumer가 접속 중이어도 TTL 만료분을 절대 배달 안 함을 문서 명시). 규칙 2중화(시계+생존) 대비 실익이 24h 상향으로 대부분 흡수됨.
- **1h 현행 유지** — 장기 턴·잠든 동료·스폰 전 선지시가 만료될 위험. 업계 기본값(SQS 4일·Kafka 7일·Postfix 5일) 대비 이례적으로 짧음.
- **무만료(RabbitMQ 기본과 동형)** — 오타 수신자 메시지가 데몬 재시작까지 잔존해 `messages` 조회를 오염. 24h면 선지시·장기 턴을 다 덮으면서 청소도 됨.

## 근거

- 선례 조사(/research light, 2026-07-25, grounding 통과 — 수치 4건 메인 교차확인). 시스템별:

| 시스템 | 보관 기본값 | 생존 면제 | 만료 시 |
|---|---|---|---|
| RabbitMQ(AMQP) | 무만료(TTL 기본 없음) | 없음(접속 consumer에도 만료분 미배달 — 문서 명시) | DLX 사유 기록, 발신자 비통지 |
| AWS SQS | 4일(최대 14일) | 없음(visibility timeout과 retention은 별개 축) | 조용한 삭제 |
| Kafka | 7일(log.retention.hours=168) | 없음 | 조용한 세그먼트 삭제 |
| Postfix(이메일) | 5일(maximal_queue_lifetime) | 없음 | **발신자 반송 통지** |
| ejabberd(mod_offline) | 시간 만료 미확인(개수 상한만 확인) | 미확인 | 미확인 |
| LLM 프레임워크(AutoGen 등) | 미발견(기권 — 공식 repo 미조사) | — | — |

  요지: liveness-aware 면제 선례 전무(전부 시계 기반) · 만료 처리의 업계 절충 = DLX식 "사유 기록·비통지"(우리 장부 `expired`와 동형) · 1h는 선례 대비 짧은 축, 일 단위가 관행.
- 인메모리 단계라 긴 TTL의 비용 ~0: cap 100이 메모리를 이미 유계화, 데몬 재시작 시 전부 소멸. 뒷북 배달(하루 전 메시지)은 수신 LLM의 판별 몫.
- 사용자 결정(2026-07-25): "어차피 나중에 저장구조 들어가면 변경해야 됨. 24시간으로."

## 영향 / 불변식

- `PARK_TTL`(mailbox.rs) = 24h — **적용은 C2 커밋과 함께**(상수 + 기존 "왜 1h" 주석 3곳 갱신 + `// ADR-0105` 앵커 동반 필수; 이 ADR 커밋 시점에 코드가 아직 1h면 코드가 후행 중인 것). 경계 의미(`>=` = 정확히 TTL 도달 시 만료)·만료 장부 기록·cap admission-only는 ADR-0103/0104 결정 그대로.
- v2 후보 메모: 만료 시 발신자 notice(이메일 반송 선례 — 우리 시스템 성격이 서신에 가장 가까움) — 영속화 재설계 때 함께 재론.
