# ADR-0179: 데몬은 클라이언트 여럿을 받고 클라는 데몬 여럿에 붙는다

- 상태: 확정 (2026-09-04, 근거: 사용자 요구 2026-09-04 + ADR-0036 원문 대조(정적 판독) + ADR-0134/0135 의 폴더별 데몬 공존 실측 2026-08-16)
- 관련: **Amends ADR-0036 (데몬이 보는 연결 수)** · ADR-0177 결정 3(전송 방향 대칭 — 이 결정을 구현 가능하게 만드는 전제) · ADR-0129(net 분리) · ADR-0035(레이아웃 권위 = src-tauri — 살아남는 조항의 권위 짝) · ADR-0029(daemon-only·앱 = 데몬 클라이언트) · ADR-0134/0135(단일 인스턴스 스코프 = 데이터 폴더 — 폴더가 다른 데몬은 이미 공존) · `docs/research/client-identity-survey-2026-08-17.md`(**결론 없이 남아 있다**) · `docs/tracking.md` T-15(★결정이 아니라 보류 메모★) · step-log S21

## 맥락

사용자 요구(2026-09-04)는 **양방향**이다 — **클라가 데몬 여럿에 붙어야 하고, 데몬도 PC·모바일 등 클라 여럿을 받아야 한다.** 한쪽만 여는 형태가 아니다.

ADR-0036 은 **셸이 데몬과 단일 WS 연결을 쥐고 창들에 fan-out** 하는 것으로 확정돼 있고, 그 「영향 / 불변식」 중 한 줄이 「**데몬은 클라 수를 모르고 1 연결만 본다**」다.

★**한 클라가 데몬 N대에 붙는 것만으로는 ADR-0036 이 안 깨진다**★ — 데몬 A 입장에서는 여전히 연결 하나이기 때문이다. 늘어나는 것은 **상대 데몬의 수**이지 한 데몬과의 연결 수가 아니다. **깨지는 것은 반대 방향, 「데몬이 클라 여럿을 받는다」 쪽이다.** 두 요구를 뭉뚱그리면 ADR-0036 을 필요 이상으로 죽이게 되므로 이 구분이 이 결정의 축이다.

**데몬 쪽 다중 인스턴스는 이미 열려 있다** — ADR-0134 가 단일 인스턴스 스코프를 데이터 폴더 기준으로 바꾸고 ADR-0135 가 잠금·주소를 `<데이터 폴더>/daemon.json` 한 파일로 통합하면서, **폴더가 다른 데몬은 이미 공존한다**(실측 2026-08-16, dev·release 동시 기동). 즉 이 ADR 이 새로 여는 축은 인스턴스 수가 아니라 ★**한 데몬이 보는 연결 수**★ 하나다.

## 결정

1. **데몬은 클라이언트 연결 여럿을 동시에 받는다.** ★ADR-0036 의 「데몬은 클라 수를 모르고 1 연결만 본다」를 **이 조항에 한해** 대체한다★ — 그 결정을 통째로 폐기하지 않는다.
2. **클라는 데몬 여럿에 동시에 붙는다.** 붙는 주체는 ★**창이 아니라 셸**★이다 — ADR-0036 의 「창↔데몬 직결 금지」가 그대로 유지되므로, **N개 연결을 쥐는 것도 셸 하나**다. 창이 자기 데몬을 고르는 형태가 아니다.
3. **전송 계층은 방향 대칭으로 짠다** — 「N개에 붙는다」와 「N개를 받는다」가 **같은 레지스트리·같은 감독 구조**다(ADR-0177 결정 3의 「상대 N개 레지스트리 + 상대마다 감독」). 그래서 **모바일이 데몬에 붙는 경로가 별도 구현이 아니라 같은 코드**다.

### ★ADR-0036 에서 죽는 것 / 사는 것★

| 원문(ADR-0036) | 자리 | 판정 |
|---|---|---|
| 「**데몬은 클라 수를 모르고 1 연결만 본다**」 | 영향 / 불변식 「데몬 불변」 | ★**죽는다**★ — 이 개정이 대체하는 유일한 조항 |
| 「**단일 choke point:** 모든 트래픽(레이아웃·에이전트 I/O)이 src-tauri를 지난다.」 | 영향 / 불변식 | **그대로 산다** — 이 개정이 건드리지 않는다 |
| 「**창↔데몬 직결 금지**」 / 「창은 src-tauri하고만 IPC(레이아웃 + 에이전트 둘 다) — 데몬 직결 0」 | 영향 / 불변식 · 결정 | **그대로 산다** |
| 「src-tauri가 … 자기가 소유한 레이아웃 라우팅 테이블(ADR-0035)로 각 창에 출력을 fan-out한다」 | 결정 | **그대로 산다** — 셸→창 fan-out 구조는 무변경 |

- **「src-tauri가 데몬과 단일 WS 연결을 쥐고」도 죽지 않는다** — 그 문장이 말하는 것은 **한 데몬과 연결 하나**이고, 결정 2 가 늘리는 것은 **상대 데몬의 수**다. 셸↔데몬 A 사이는 여전히 연결 하나다.
- ★**같은 줄 뒤에 붙은 「데몬 코어/프로토콜 변경 없음(에이전트만)」은 이 개정이 판정하지 않는다**★ — 아래 「영향」 넷이 전부 미결이라 무엇이 바뀌는지 셀 수 없다. **「그대로 유효」로도 「함께 죽었다」로도 읽지 말 것.**
- ★**ADR-0036 이 기각한 「창마다 데몬 WS 직결(현행)」은 여전히 거부 상태다 — 이 개정이 그것을 되살리지 않는다. 재론 금지.**★ 기각 사유(N창 = N 인증/재연결/discover 중복 + 출력 N중복 전송 + 셸이 이미 가진 라우팅 테이블을 각 창이 재유도)는 연결 수가 늘어도 그대로다.

## 거부한 대안

- **창마다 데몬 직결** — ADR-0036 이 이미 기각했고 이 개정도 되살리지 않는다(N창 = N 인증·재연결 중복 + 출력 N중복). ★**재론 금지**★.
- **데몬을 여전히 단수 전제로 두고 클라 쪽만 N 으로 늘리기** — 사용자 요구가 **양방향**이라 성립하지 않는다. 모바일이 붙는 순간 데몬이 연결을 여럿 보게 된다.
- **ADR-0036 을 전체 폐기** — 살아 있는 조항 셋(단일 choke point · 창 직결 금지 · 셸 fan-out)을 함께 죽이므로 **부분 개정**으로 처리했다. **기각 근거 = 원문 대조(실측 — 위 대조표).**

## 근거

- **축이 다르므로 부분 개정이 정확하다** — ADR-0036 의 불변식 중 둘(단일 choke point · 창 직결 금지)은 **클라이언트 내부 토폴로지**에 관한 것이고, 죽는 하나만 **데몬이 보는 연결 수**에 관한 것이다. 앞 둘은 창이 몇이든·데몬이 몇이든 그대로 성립한다.
- **데몬 다중 인스턴스는 이미 결정돼 있다** — ADR-0134/0135 가 단일 인스턴스 스코프를 데이터 폴더 기준으로 바꾼 뒤 **폴더가 다른 데몬은 이미 공존한다**(실측 2026-08-16). ★단 `docs/tracking.md` T-15 는 **결정이 아니라 보류 메모**다★ — 그 항목을 근거로 인용할 때 결정으로 읽지 말 것(그 문서가 스스로 "결정 아님"이라 적어 두었다).
- **구현 가능성의 전제 = ADR-0177 결정 3** — 전송을 방향 대칭으로(상대 N개 레지스트리 + 상대마다 감독) 짜기로 한 그 결정이 이 결정을 구현 가능하게 만든다. 그것 없이는 연결이 하나라는 전제가 `src-tauri/src/daemon_client/connection.rs` 의 상태 모양에 박힌 채로 남는다(ADR-0177 맥락).

## 영향 / 불변식

데몬이 클라 여럿을 받게 되면 아래 넷이 살아난다. ★**이 ADR 은 그중 어느 것도 결정하지 않는다 — 전부 미결로 남긴다.**★

1. **데몬 쪽 팬아웃** — 에이전트 하나의 출력을 클라 여럿에게. 지금은 하나에게만 보내면 됐다. **이 ADR 이 결정하지 않는다.**
2. **입력 충돌** — 폰과 PC 가 같은 에이전트에 동시 입력하면? 입력 권한(lease) 개념이 이미 있으니 그것을 **다중 클라 기준으로 다시 봐야 한다**. **이 ADR 이 결정하지 않는다.**
3. **클라별 되감기** — 폰이 늦게 붙으면 폰만 자기 지점부터. 지금 replay 는 **클라가 하나인 전제**로 서 있다. **이 ADR 이 결정하지 않는다.**
4. ★**클라이언트 신원**★ — 현행 토큰은 **데이터 폴더를 읽을 수 있으면 누구나 읽는 공유 비밀**이라 클라를 구분하지 못한다. 위 2·3 이 성립하려면 구분이 필요하다. **그리고 이것은 원격 인증(페어링)과 같은 문제라 함께 푼다.** 조사는 `docs/research/client-identity-survey-2026-08-17.md` 가 **결론 없이 남아 있고**, 그 문서가 스스로 「**위협 모형 없이는 인수·거부·인증 결속·공존 중 무엇이 필요한지가 도출되지 않는다** … 이 조사만으로 방식을 고르면 근거 없는 선택이 된다」고 적어 두었다. **이 ADR 이 결정하지 않는다.**

- ★**살아 있는 셋을 이 개정의 그림자로 건드리지 말 것**★ — 단일 choke point · 창↔데몬 직결 금지 · 셸의 창 fan-out. 다중 연결을 구현하면서 창을 직접 붙이면 ADR-0036 의 기각 사유가 그대로 재발한다.
- **미검** — 데몬 쪽 팬아웃·입력 권한·클라별 되감기가 **현재 코드에서 얼마나 단수 전제에 묶여 있는지 이 세션은 세지 않았다.** 판정은 **정적 판독뿐**이고 코드를 한 줄도 고치지 않았다.
