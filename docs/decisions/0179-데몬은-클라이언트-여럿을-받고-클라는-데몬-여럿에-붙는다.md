# ADR-0179: The daemon accepts several clients and a client attaches to several daemons

- 상태: 확정 (2026-09-04, basis: user requirement 2026-09-04 + comparison against the ADR-0036 original (static reading) + measurement of per-folder daemon coexistence from ADR-0134/0135, 2026-08-16)
- 관련: **Amends ADR-0036 (the number of connections the daemon sees)** · ADR-0177 decision 3 (transport direction symmetry — the premise that makes this decision implementable) · ADR-0129 (net split) · ADR-0035 (layout authority = src-tauri — the authority pair of the surviving clause) · ADR-0029 (daemon-only · the app = a daemon client) · ADR-0134/0135 (single-instance scope = data folder — daemons in different folders already coexist) · `docs/research/client-identity-survey-2026-08-17.md` (**left without a conclusion**) · `docs/tracking.md` T-15 (★a deferral memo, not a decision★) · step-log S21

## 맥락

The user requirement (2026-09-04) is **bidirectional** — **a client must attach to several daemons, and a daemon must also accept several clients (PC, mobile, and so on).** It is not a form that opens only one side.

ADR-0036 is fixed as **the shell holding a single WS connection to the daemon and fanning out to the windows**, and one line of its 「영향 / 불변식」 is 「**데몬은 클라 수를 모르고 1 연결만 본다**」 (the daemon does not know the number of clients and sees only 1 connection).

★**A client attaching to N daemons alone does not break ADR-0036**★ — because from daemon A's point of view it is still one connection. What grows is **the number of peer daemons**, not the number of connections with a single daemon. **What breaks is the opposite direction, the 「데몬이 클라 여럿을 받는다」 (the daemon accepts several clients) side.** Lumping the two requirements together would kill ADR-0036 more than necessary, so this distinction is the axis of this decision.

**Multiple instances on the daemon side are already open** — ADR-0134 changed the single-instance scope to be based on the data folder, and ADR-0135 merged the lock and address into one file, `<데이터 폴더>/daemon.json`, so **daemons in different folders already coexist** (measured 2026-08-16, dev and release started at the same time). That is, the one axis this ADR newly opens is not the number of instances but ★**the number of connections one daemon sees**★.

## 결정

1. **The daemon accepts several client connections at the same time.** ★It replaces ADR-0036's 「데몬은 클라 수를 모르고 1 연결만 본다」 **only for this clause**★ — that decision is not discarded as a whole.
2. **A client attaches to several daemons at the same time.** The one that attaches is ★**the shell, not the window**★ — ADR-0036's 「창↔데몬 직결 금지」 (no direct window↔daemon link) stays as it is, so **the one that holds the N connections is also the single shell.** It is not a form where a window chooses its own daemon.
3. **The transport layer is built direction-symmetric** — 「N개에 붙는다」 (attach to N) and 「N개를 받는다」 (accept N) are **the same registry and the same supervision structure** (ADR-0177 decision 3's 「상대 N개 레지스트리 + 상대마다 감독」 (a registry of N peers + supervision per peer)). So **the path by which mobile attaches to the daemon is the same code, not a separate implementation.**

### ★What dies / what lives from ADR-0036★

| Original (ADR-0036) | Location | Verdict |
|---|---|---|
| 「**데몬은 클라 수를 모르고 1 연결만 본다**」 | 영향 / 불변식 「데몬 불변」 | ★**dies**★ — the only clause this amendment replaces |
| 「**단일 choke point:** 모든 트래픽(레이아웃·에이전트 I/O)이 src-tauri를 지난다.」 | 영향 / 불변식 | **lives as is** — this amendment does not touch it |
| 「**창↔데몬 직결 금지**」 / 「창은 src-tauri하고만 IPC(레이아웃 + 에이전트 둘 다) — 데몬 직결 0」 | 영향 / 불변식 · 결정 | **lives as is** |
| 「src-tauri가 … 자기가 소유한 레이아웃 라우팅 테이블(ADR-0035)로 각 창에 출력을 fan-out한다」 | 결정 | **lives as is** — the shell→window fan-out structure is unchanged |

- **「src-tauri가 데몬과 단일 WS 연결을 쥐고」 (src-tauri holds a single WS connection to the daemon) does not die either** — what that sentence speaks of is **one connection with one daemon**, and what decision 2 increases is **the number of peer daemons**. Between the shell and daemon A it is still one connection.
- ★**This amendment does not decide 「데몬 코어/프로토콜 변경 없음(에이전트만)」 (no daemon core/protocol change (agents only)), which is attached after the same line**★ — the four items under 「영향」 below are all undecided, so what changes cannot be counted. **Do not read it as either 「그대로 유효」 (still valid as is) or 「함께 죽었다」 (died with it).**
- ★**The 「창마다 데몬 WS 직결(현행)」 (each window connects directly to the daemon WS (current)) that ADR-0036 rejected is still rejected — this amendment does not revive it. Do not reopen.**★ The reasons for rejection (N windows = N duplicated authentication/reconnect/discover + output sent N times + each window re-deriving the routing table the shell already has) stay as they are even when the number of connections grows.

## 거부한 대안

- **Each window connects directly to the daemon** — ADR-0036 already rejected it and this amendment does not revive it either (N windows = N duplicated authentication and reconnect + output duplicated N times). ★**Do not reopen**★.
- **Keeping the daemon on a singular premise and growing only the client side to N** — it does not hold, because the user requirement is **bidirectional**. The moment mobile attaches, the daemon sees several connections.
- **Discarding ADR-0036 entirely** — it would also kill three living clauses (single choke point · no direct window link · shell fan-out), so it was handled as a **partial amendment**. **Basis for rejection = comparison against the original (measured — the table above).**

## 근거

- **A partial amendment is exact because the axes differ** — two of ADR-0036's invariants (single choke point · no direct window link) are about the **client's internal topology**, and only the one that dies is about **the number of connections the daemon sees**. The first two hold no matter how many windows or daemons there are.
- **Multiple daemon instances are already decided** — after ADR-0134/0135 changed the single-instance scope to be based on the data folder, **daemons in different folders already coexist** (measured 2026-08-16). ★But `docs/tracking.md` T-15 is **a deferral memo, not a decision**★ — when citing that item as a basis, do not read it as a decision (that document itself says "결정 아님" (not a decision)).
- **The premise for implementability = ADR-0177 decision 3** — the decision to build the transport direction-symmetric (a registry of N peers + supervision per peer) makes this decision implementable. Without it, the assumption that there is one connection stays baked into the state shape of `src-tauri/src/daemon_client/connection.rs` (ADR-0177 맥락).

## 영향 / 불변식

Once the daemon accepts several clients, the four below come alive. ★**This ADR decides none of them — all are left undecided.**★

1. **Daemon-side fan-out** — one agent's output to several clients. Until now it only had to be sent to one. **This ADR does not decide it.**
2. **Input conflicts** — what if a phone and a PC input to the same agent at the same time? The notion of an input permission (lease) already exists, so it **must be looked at again on a multi-client basis**. **This ADR does not decide it.**
3. **Per-client rewind** — if the phone attaches late, only the phone goes from its own point. The current replay stands on the **premise of a single client**. **This ADR does not decide it.**
4. ★**Client identity**★ — the current token is a **shared secret that anyone who can read the data folder can read**, so it cannot tell clients apart. For 2 and 3 above to hold, the distinction is needed. **And this is the same problem as remote authentication (pairing), so it is solved together.** For the investigation, `docs/research/client-identity-survey-2026-08-17.md` is **left without a conclusion**, and that document itself writes 「**위협 모형 없이는 인수·거부·인증 결속·공존 중 무엇이 필요한지가 도출되지 않는다** … 이 조사만으로 방식을 고르면 근거 없는 선택이 된다」 (without a threat model it cannot be derived which of takeover, rejection, authentication binding and coexistence is needed … choosing a method from this survey alone would be an unfounded choice). **This ADR does not decide it.**

- ★**Do not touch the three living ones as a shadow of this amendment**★ — the single choke point · no direct window↔daemon link · the shell's window fan-out. If windows are attached directly while implementing multiple connections, ADR-0036's reasons for rejection recur as they are.
- **Unchecked** — this session did not count **how tightly the daemon-side fan-out, input permission and per-client rewind are tied to the singular premise in the current code.** The decision is **static reading only** and not a single line of code was changed.
