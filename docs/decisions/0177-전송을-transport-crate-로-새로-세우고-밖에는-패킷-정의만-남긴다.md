# ADR-0177: Build transport as a new crate and leave only packet definitions outside

- 상태: 확정 (2026-09-04, basis: user decision + `docs/research/reusable-transport-crate-boundary-2026-09-03.md` (adversarial review BLOCK → fixes applied, **re-decision not run**) + this session's slow-consumer / loss-signal investigation (**report not written**) + static-reading measurement) · 부분 폐기 by ADR-0272 (decision 4: canonical location of the pairing-number function) · 부분 폐기 by ADR-0310 (decision 3: stream lifecycle management and the receiving queue; decision 9: the queue-cap paragraph of the loss signal and rationale)
- 관련: CLAUDE.md 「백엔드 모듈 맵」 net entry · 「네트워크 행 격리 게이트」 · ADR-0129(net split — the premise this decision stands on) · ADR-0036(transport relay unification — **needs amendment, this ADR does not do it**) · ADR-0158(version mismatch notice — **needs reversal, this ADR does not do it**) · ADR-0130(`frame_port` feature membership on hold) · ADR-0151(crate decision criteria) · ADR-0175 decision 6(lib weight) · ADR-0155(command crate) · ADR-0046(replay single-flight) · ADR-0163/0164(incarnation marker) · `src-tauri/src/daemon_client/connection.rs` · `crates/engram-dashboard-net/src/ws.rs` · step-log S21 · Amended by ADR-0272 (decision 4: canonical location of the pairing-number function) · Amended by ADR-0310 (decision 3: stream lifecycle management and the receiving queue; decision 9: the queue-cap paragraph of the loss signal and rationale)

## 맥락

`engram-dashboard-net` is, **despite its name, only the daemon's server layer**. It is `default = []` and all of its content sits behind the `server` feature, with no `connect` and no reconnection. The only symbol the shell actually uses from that crate is `auth::AuthFrame` (measured). ★**`net` came into being not for sharing but to break a cycle**★ — the header of that crate's `src/lib.rs` is canonical, and so 「재사용 가능한 전송 계층」 **does not exist** in this repository yet.

All client socket driving is lumped into one shell file, `src-tauri/src/daemon_client/connection.rs` (1,674 lines — the largest file in this package, measured). Connect · reconnect backoff · handshake · read loop · Ping handling · request/response correlation · incarnation-marker guard · replay single-flight · frame→window routing are all in one place. ★**So there is no place to put 「클라가 데몬 여러 대에 붙는다」**★ — the assumption that there is one connection is built into the state shape of the whole file.

User requirements (2026-09-03~04):

- **Direction (server/client) is not a separate layer; it is a capability you choose.**
- What comes from outside is **only the packet definitions**, and the rest must handle the networking by itself.
- **The client must connect to multiple daemons**, and **the daemon must also accept multiple clients** such as PC and mobile.
- Way of working = **create a separate crate → verify it independently → attach it in a suitable scope and test** (적당한 범위로 붙이며 테스트).

## 결정

1. **The new crate's name = `transport`** (user decision 2026-09-04 — *"it feels intuitive"*). ★**We do not tear apart the existing `net` in this work**★ — we build the new one, **verify it independently**, and then attach it in a dedicated folder for each of the daemon and the shell. In the end `transport` takes over the networking role.
2. **Narrow the scope to the three engram components (daemon · shell · mobile)** (user decision — *"don't think too generic"*). If we aim at any project whatsoever, **we cannot decide and everything becomes an option.** Narrowing to three lets us **fix the defaults** — those three are already server, client and mobile, so the structure comes out generic anyway.
3. **What goes inside the crate**:
   - Frame boundary · request/response correlation (★**generic over the tag type (태그 타입에 제네릭) — the crate does not know its name**★) · role distinction (request/response/notification/stream)
   - Stream lifecycle management = identifier · generation · sequence number · resume · dedup · **gap detection**
   - Connection establishment · **opaque handshake frames** (any number of rounds) · **bidirectional keepalive** · **write deadline** · **backoff + jitter reconnection**
   - **A registry of N peers + a supervisor per peer** · **origin marker** on inbound · **exposing the generation boundary**
   - Fan-out · bounded queue and backpressure signal
4. **What stays outside (the consumer)**: **packet struct definitions** · addresses and auth material · policy values (the crate has defaults for all of them) · **the function that extracts the pairing number** (not new — the canonical one already exists as `command_request_id` · `event_reply_request_id` in `protocol`) · the choice of policy when the queue is full · version and capability negotiation.
5. ★**The consumer owns the envelope**★ — the crate does not fix the `{tag, kind, payload}` envelope. The reasons are all **measured**: our wire has no envelope struct and **the kind name is itself the JSON object key** (`{"CreatePreset":{…}}`), the correlation key is inside the payload and **its position differs per variant**, many variants have no key at all, four of them sit one level inside and **the outer one and the inner one mean different things**. On top of that there are two codecs — control = JSON (WS Text) · output hot path = `[tag:1][agent_id:16][epoch:4][seq:8]` fixed-header binary (WS Binary).
6. **Slow consumer = when the queue fills, drop that connection** (current behavior kept). But ★**the policy is not nailed down inside the crate; the outside chooses it**★.
7. **Build it so that both transport and time can be swapped.** The verification harness (decision 8) requires this, and later TLS and other transports hook in here.
8. **Verification harness** = all logic runs **fully in memory with injected time** (backoff · keepalive · write deadline are verified **without actually waiting**). Only a few real sockets are used — ① does the WS adapter actually connect ② **does the write deadline actually cut when the peer does not read**. ★The latter cannot be measured in memory because it needs a kernel buffer to measure★. Ports are requested as 0. **It runs as is in CI.**
9. **Loss signal**: truncation is given not as true/false but as ★**「지금 유효한 가장 오래된 번호」**★. And it is carried up not on the console but in **the stream the upper layer reads**. In addition, we put in a **sequence-gap check**, and on a gap we **re-request from that point** (그 지점부터 재요청) — we do not stop at detection only.

## 거부한 대안

- **Creating a folder inside `net` to put it in** (the user proposed it first → withdrew) — rejected for four reasons. ① There is almost nothing real to gather as 「우리 규칙」 — the packet contents are `protocol`, addresses and tokens are discovery and portfile, and policy is not code but **values**. ② For `net` the invariant is **ignorance of agent vocabulary**, and the CI isolation gate guards it — putting it in turns the gate red. ③ That crate's identity is pinned in the docs as 「데몬의 **서버** 행」, so putting in the client half and a multi-connection registry **makes that sentence false.** ④ ★**「일단 폴더로 두고 나중에 crate 로 승격」 is a line of reasoning this repository has already been bitten by**★ — the previous session recommended it and withdrew it after the user's remark (*"it won't be kept in the team, so will it ever get promoted later"*).
- **A form where the crate owns the envelope** (investigated candidate A) — the measurement in decision 5 above is itself the reason for rejection. Adopting it would **change the wire bytes** and run into the 「wire JSON 모양 보존」 premise of ADR-0129. **Basis of rejection = measured** (golden test + codec source).
- **A form that carries only a byte pipe** (investigated candidate C) — leaves serialization and correlation entirely to the upper layer. Vocabulary-isolation friction is 0 but it is **the furthest from the user's requirement** — it becomes 「바이트만 나른다」 instead of 「패킷만 주면 된다」. The amount that can be stripped out of `connection.rs` is also the smallest.
- **A thin sans-IO core + I/O layer, splitting the crate in two** (investigated candidate B) — it satisfies the reuse condition best of the three. But ★**it risks running into ADR-0175 decision 6 (no single-file libs · matching lib weight)**★, and **that weight cannot be measured before the design is drawn.** It also points in a different direction from decision 2, which narrowed the scope to the three engram components. **Basis of rejection = weak (not measured).**
- **Absorbing the existing `net` in one go** — nine daemon files would have to be replaced at once. It is the opposite of 「적당한 범위로 붙이며 테스트」, and it is the place ADR-0036 pinned down as 「전송층 재배치는 **동시성-치명**」.
- **Keeping the name `net`** — it has the advantage that few places need touching, because gates and docs hang on that name. But the user chose `transport` for **intuitiveness** (2026-09-04). Cleaning up docs and gates is done **when attaching**.
- **Dropping per message for the slow consumer** (drop oldest / drop newest) — the way the MQTT family does it, but ★**it cannot be used on terminal bytes**★: dropping the middle breaks UTF-8 and throws the ANSI parser state off, so **the screen keeps being drawn corrupted.** Dropping the connection at least lets it reattach and sync from the start.
- **A design that guarantees control delivery** (a control-only queue / a control-only socket) — ★**on a single socket the guarantee is impossible (investigation conclusion)**★. HTTP/2 exempts control frames from flow control, but that holds only because RFC 9113 §5.2.2 **enforces 「양 끝은 받은 즉시 읽어야 한다, 안 읽으면 교착」 as a MUST** — if the peer does not read the socket, even an exempted frame is blocked in the kernel send buffer. A control-only **socket** is a real pattern (PostgreSQL opens a **new connection** to cancel a running query), but it doubles the connections and complicates auth and lifetime. Because transport is placed behind a trait (decision 7), it stays open for later.
- **The assumption that simply dropping a congested connection conveys the reason** — ★**false**★. RFC 6455 §7.4.1 pins `1006` as a **reserved value that cannot be sent on the wire**, and §7.1.5 defines it as a **value the receiving side synthesizes locally**. WHATWG **explicitly says to make DNS failure, routing failure, TLS failure and abrupt termination indistinguishable** (security). All the client gets is `1006` · an empty reason · `wasClean=false`. **In return, the spec allows dropping that way itself** — §7.1.7 「상대가 Close frame 을 받아 처리할 가능성이 낮다고 판단되면 생략해도 된다」.

## 근거

- **The shape of request/response correlation** — **all** five camps surveyed put the correlation id in the **protocol/session layer**, and the transport only carries frames. A placement where the transport **learns** the id was not found in the survey scope. `TagStore` of `tokio-tower` expresses it with a **single bound** on the associated type `type Tag: Eq` (checked against the original). So 「태그 타입에 제네릭」 in decision 3 is a **form that does not conflict** with the vocabulary isolation of ADR-0129 (at the type level).
- **Why a write deadline is needed** — the current code ★**already has a real defect**★: an in-progress socket write in `crates/engram-dashboard-net/src/ws.rs` cannot be cut by close_signal, and keepalive stops along with it in the meantime (**that file's comment admits it**). So even with the 「차면 끊는다」 policy, it does not actually get cut. The industry catches this with a write deadline across the board (NATS 10s · nginx 60s · gRPC keepalive timeout 20s).
- **Why the queue cap must not be larger than the rewind ring** — the current state is the other way round (`CONN_TX_CAP = 4608` > replay `max_events = 4096`). ★**At the moment the queue fills and the connection is dropped, the oldest backed-up item may already have been pushed out of the ring**★ — 「끊고 다시 붙으면 복구된다」 **already breaks at that number.** (Surfaced by adversarial review — **computed from the numbers only**, runtime reproduction not checked.)
- **A physical disconnect is known only by asking for yourself** — normal exit and process death send a signal, but **a cut line has no way to send a signal**, so it stays quiet with the socket looking fine. OS keepalive defaults to 2 hours and is useless, so we do it at the app level. The current code sends active Pings **from the daemon side only** — enough locally, but for remote and mobile **the client side** needs it too.
- **Why loss must not be silent** — two investigation conclusions. ① Put the signal **inside the stream the consumer already reads** — a side channel is the same as nonexistent if nobody listens, and the NATS docs list it as their own pitfall. ② **「어디서부터 다시 받나」 is more useful than 「얼마나 잃었나」** — every system that supports recovery gives a boundary value. The current code has **no** sequence-gap check **at all** (`rg` measured 0 lines) and the truncation mark appears **only as a console warning**.
- **State of the investigation** — canonical = `docs/research/reusable-transport-crate-boundary-2026-09-03.md` (adversarial review applied, **decision BLOCK → fixes applied, re-decision not run**). ★**This session's slow-consumer / loss-signal investigation was not left as a report document**★ — it is the source of the two items above, and for now this ADR is its only record.

## 영향 / 불변식

- ★**ADR-0036 needs amendment**★ — its invariant 「데몬은 클라 수를 모르고 1 연결만 본다」 **breaks the moment the daemon accepts multiple PC and mobile clients.** The single choke point (the shell is the only path) and the ban on a direct window↔daemon connection stay as they are. **This ADR does not make that amendment — it must be recorded as a separate decision.**
- ★**ADR-0158 needs reversal**★ — instead of **deciding a version mismatch by capability advertisement at connect time**, the user flipped it to **tell the user by receiving a version error when a request is made** (2026-09-04). Then the handshake looks at only 「토큰 통과/거절」 and the crate becomes simpler. **Cost = the UI cannot gray out a button in advance; you find out by pressing it.** **This ADR does not make that reversal — it must be recorded as a separate decision.**
- **If the crate name drops the `engram-dashboard` prefix, the CI dependency-cap gate silently stops looking at that crate** (because it identifies members by **name prefix**). When attaching `transport`, **fix the gate regex in the same commit.**
- **The open feature-membership question of `frame_port` (ADR-0130 reservation) comes alive** — if the new crate tries to reference that contract, it **gets caught immediately.** The `Cargo.toml` comment recorded it as 「재개 시 **착수 전에** 결정할 것 — 공개 API 변경이라 나중에 하면 비싸다」.
- **The port file and single instance are not moved to `transport`** — they are not transport but **daemon lifecycle management**, and discovery already uses them.
- **Deferred (outside the scope of this decision)**: remote auth and pairing (★**it is the same problem as multi-client identity, so we solve them together**★ — the current token is a **shared secret** that anyone who can read the folder can read, so it cannot tell clients apart) · remote address discovery · TLS · multi-client input permission · per-client rewind · **screen state synchronization** (the root fix that lets a lagging client catch up in one go without being dropped — the daemon would have to interpret ANSI and hold a screen grid, so it is a big job).
- **Not verified**: every decision in this ADR rests on **static reading + investigation** and **not one line of code was changed.** ★We did **not check** whether on reconnect the shell actually resumes (whether it fills in and sends `after_seq`) vs receives the whole buffer again★ — **whether the 「그 지점부터 재요청」 of decision 9 is new or existing is decided there.**
