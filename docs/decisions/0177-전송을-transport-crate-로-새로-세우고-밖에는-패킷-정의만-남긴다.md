# ADR-0177: 전송을 transport crate 로 새로 세우고 밖에는 패킷 정의만 남긴다

- 상태: 확정 (2026-09-04, 근거: 사용자 결정 + `docs/research/reusable-transport-crate-boundary-2026-09-03.md`(적대 리뷰 BLOCK → 수정 반영, **재판정 미실행**) + 이 세션의 느린-소비자/유실-신호 조사(**보고서 미작성**) + 정적 판독 실측)
- 관련: CLAUDE.md 「백엔드 모듈 맵」 net 항목 · 「네트워크 행 격리 게이트」 · ADR-0129(net 분리 — 이 결정이 딛는 전제) · ADR-0036(전송 중계 통일 — **개정 필요, 이 ADR 이 하지 않는다**) · ADR-0158(버전 불일치 고지 — **번복 필요, 이 ADR 이 하지 않는다**) · ADR-0130(`frame_port` feature 소속 보류) · ADR-0151(crate 판정 기준) · ADR-0175 결정 6(lib 무게) · ADR-0155(command crate) · ADR-0046(재생 single-flight) · ADR-0163/0164(화신 표식) · `src-tauri/src/daemon_client/connection.rs` · `crates/engram-dashboard-net/src/ws.rs` · step-log S21

## 맥락

`engram-dashboard-net` 은 **이름과 달리 데몬의 서버 행뿐**이다. `default = []` 이고 실물 전부가 `server` feature 뒤에 있으며 `connect` 도 재연결도 없다. 셸이 그 crate 에서 실제로 쓰는 심볼은 `auth::AuthFrame` 하나뿐이다(실측). ★**`net` 이 생긴 계기는 공유가 아니라 순환 끊기였다**★ — 그 crate `src/lib.rs` 헤더가 정본이고, 그래서 「재사용 가능한 전송 계층」은 이 저장소에 아직 **없다**.

클라이언트 소켓 구동은 전부 셸의 `src-tauri/src/daemon_client/connection.rs` 한 파일에 뭉쳐 있다(1,674줄 — 이 패키지 최대 파일, 실측). connect · 재연결 백오프 · 핸드셰이크 · 읽기 루프 · Ping 처리 · 요청/응답 상관 · 화신 표식 가드 · 재생 single-flight · 프레임→창 라우팅이 한 자리에 있다. ★**그래서 「클라가 데몬 여러 대에 붙는다」를 얹을 자리가 없다**★ — 연결이 하나라는 전제가 파일 전체의 상태 모양에 박혀 있다.

사용자 요구(2026-09-03~04):

- **방향(서버/클라)은 별도 층이 아니라 고르는 능력이다.**
- 밖에서 주는 것은 **패킷 정의**뿐이고, 나머지는 알아서 네트워킹이 되어야 한다.
- **클라가 다중 데몬에 접속**해야 하고, **데몬도 PC·모바일 등 다중 클라를 받아야** 한다.
- 작업 방식 = **별도 crate 신설 → 독립 검증 → 적당한 범위로 붙이며 테스트.**

## 결정

1. **새 crate 이름 = `transport`**(사용자 결정 2026-09-04 — *"뭔가 직관적이다"*). ★**기존 `net` 을 이번 작업에서 뜯지 않는다**★ — 새로 세워 **독립 검증**한 뒤, 데몬·셸에 각각 전용 폴더를 두고 거기서 붙인다. 최종적으로 `transport` 가 네트워크 담당 자리를 가져간다.
2. **범위를 engram 셋(데몬·셸·모바일)으로 좁힌다**(사용자 결정 — *"너무 범용을 생각하지말고"*). 아무 프로젝트나 겨냥하면 **결정을 못 내리고 전부 옵션이 된다.** 셋으로 좁혀 **기본값을 확정**한다 — 그 셋이 이미 서버·클라·모바일이라 구조는 어차피 범용으로 나온다.
3. **crate 안에 드는 것**:
   - 프레임 경계 · 요청/응답 상관(★**태그 타입에 제네릭 — crate 는 그 이름을 모른다**★) · 역할 구분(요청/응답/알림/스트림)
   - 스트림 살림 = 식별자 · 세대 · 순번 · 이어받기 · 중복 제거 · **구멍 찾기**
   - 연결 수립 · **불투명한 핸드셰이크 프레임**(횟수는 몇 번이든) · **양방향 keepalive** · **쓰기 시한** · **백오프+지터 재연결**
   - **상대 N개 레지스트리 + 상대마다 감독** · 인바운드에 **출처 표식** · **세대 경계 노출**
   - 팬아웃 · 유계 큐와 배압 신호
4. **밖(소비자)에 남는 것**: **패킷 구조체 정의** · 주소·인증 자료 · 정책 값(전부 crate 기본값이 있다) · **짝짓기 번호를 꺼내는 함수**(신규가 아니다 — `protocol` 에 `command_request_id`·`event_reply_request_id` 로 이미 정본이 있다) · 큐가 찼을 때의 정책 선택 · 버전·능력 협상.
5. ★**봉투는 소비자가 소유한다**★ — crate 가 `{tag, kind, payload}` 봉투를 정하지 않는다. 사유는 전부 **실측**이다: 우리 wire 엔 봉투 struct 가 없고 **종류 이름이 곧 JSON 객체 키**이며(`{"CreatePreset":{…}}`), 상관 키가 payload 안에 있고 **variant 마다 위치가 다르며**, 키가 아예 없는 variant 가 다수고, 넷은 한 겹 안쪽에 있는데 **밖의 것과 안의 것은 뜻이 다르다**. 게다가 코덱이 둘이다 — control = JSON(WS Text) · 출력 hot path = `[tag:1][agent_id:16][epoch:4][seq:8]` 고정헤더 binary(WS Binary).
6. **느린 소비자 = 큐가 차면 그 연결을 끊는다**(현행 유지). 단 ★**정책을 crate 안에 못 박지 않고 바깥이 고르게 둔다**★.
7. **전송과 시간을 둘 다 갈아끼울 수 있게 짠다.** 검증 하네스(결정 8)가 이것을 요구하고, 나중의 TLS·다른 전송이 여기 걸린다.
8. **검증 하네스** = 로직은 **전부 인메모리 + 시간 주입**(백오프·keepalive·쓰기 시한을 **실제로 기다리지 않고** 검증한다). 실소켓은 소수만 둔다 — ① WS 어댑터가 실제로 붙나 ② **상대가 안 읽을 때 쓰기 시한이 실제로 잘라내나**. ★후자는 커널 버퍼가 있어야 재므로 인메모리로 못 잰다★. 포트는 0번을 요청한다. **CI 에서 그대로 돈다.**
9. **유실 신호**: 잘림을 참/거짓이 아니라 ★**「지금 유효한 가장 오래된 번호」**★로 준다. 그리고 콘솔이 아니라 **위층이 읽는 스트림**에 실어 올린다. 더해 **순번 구멍 검사**를 넣어, 구멍이면 **그 지점부터 재요청**한다 — 검출만 하고 끝내지 않는다.

## 거부한 대안

- **`net` 안에 폴더 하나 파서 넣기**(사용자가 먼저 제안 → 철회) — 넷으로 기각. ① 모아 둘 「우리 규칙」이 실제로 거의 없다 — 패킷 내용물은 `protocol`, 주소·토큰은 discovery·portfile, 정책은 코드가 아니라 **값**이다. ② `net` 은 **에이전트 어휘 무지**가 불변식이고 CI 격리 게이트가 그것을 지킨다 — 넣으면 게이트가 빨개진다. ③ 그 crate 정체성이 문서에 「데몬의 **서버** 행」으로 못박혀 있어, 클라 절반과 다중 연결 명부를 넣으면 **그 문장이 거짓이 된다.** ④ ★**「일단 폴더로 두고 나중에 crate 로 승격」은 이 저장소가 이미 물린 논리다**★ — 직전 세션이 그것을 추천했다가 사용자 지적(*"팀에서 안 지켜질 텐데 나중에 승격이 되겠나"*)으로 철회했다.
- **crate 가 봉투를 소유하는 형태**(조사 후보 A) — 위 결정 5 의 실측이 그대로 기각 사유다. 채택하면 **wire 바이트가 바뀌고** ADR-0129 의 「wire JSON 모양 보존」 전제에 걸린다. **기각 근거 = 실측**(golden 테스트 + 코덱 소스).
- **바이트 파이프만 나르는 형태**(조사 후보 C) — 직렬화·상관을 전부 위층에 남긴다. 어휘 격리 마찰은 0 이지만 **사용자 요구에서 가장 멀다** — 「패킷만 주면 된다」가 아니라 「바이트만 나른다」가 된다. `connection.rs` 에서 걷어낼 수 있는 양도 가장 적다.
- **얇은 sans-IO 코어 + I/O 층으로 crate 를 둘로 쪼개기**(조사 후보 B) — 재사용 조건은 셋 중 가장 잘 만족한다. 그러나 ★**ADR-0175 결정 6(파일 하나짜리 lib 금지 · lib 무게 맞추기)에 걸릴 위험**★이 있고, **그 무게는 설계를 그려 보기 전에는 못 잰다.** 범위를 engram 셋으로 좁히기로 한 결정 2 와도 방향이 다르다. **기각 근거 = 약함(실측 아님).**
- **기존 `net` 을 한 번에 흡수** — 데몬 9개 파일을 동시에 갈아야 한다. 「적당한 범위로 붙이며 테스트」와 정반대이고, ADR-0036 이 「전송층 재배치는 **동시성-치명**」이라 못박은 자리다.
- **이름을 `net` 으로 유지** — 게이트·문서가 그 이름에 걸려 있어 손댈 데가 적다는 이점은 있다. 그러나 사용자가 **직관성**을 이유로 `transport` 를 골랐다(2026-09-04). 문서·게이트 정리는 **붙일 때** 한다.
- **느린 소비자에게 메시지 단위로 떨구기**(drop oldest / drop newest) — MQTT 계열이 쓰는 방식이지만 ★**터미널 바이트에는 못 쓴다**★: 중간을 버리면 UTF-8 이 깨지고 ANSI 파서 상태가 어긋나 **화면이 망가진 채로 계속 그려진다.** 끊으면 최소한 다시 붙어 처음부터 맞춘다.
- **제어 전달을 보장하는 설계**(제어 전용 큐 / 제어 전용 소켓) — ★**단일 소켓 위에서는 보장이 불가능하다(조사 결론)**★. HTTP/2 는 제어 프레임을 흐름 제어에서 면제하지만, RFC 9113 §5.2.2 가 「양 끝은 받은 즉시 읽어야 한다, 안 읽으면 교착」을 **MUST 로 강제**해서 성립하는 것이다 — 상대가 소켓을 안 읽으면 면제받은 프레임도 커널 send buffer 에 막힌다. 제어 전용 **소켓**은 실재하는 패턴이지만(PostgreSQL 이 실행 중 질의 취소에 **새 연결**을 연다) 연결이 두 배가 되고 인증·수명이 복잡해진다. 전송을 trait 뒤에 두었으므로(결정 7) 나중에 열려 있다.
- **혼잡한 연결을 그냥 끊으면 사유가 전달된다는 가정** — ★**거짓이다**★. RFC 6455 §7.4.1 이 `1006` 을 **와이어로 보낼 수 없는 예약값**으로 못박고, §7.1.5 가 그것을 **수신 측이 로컬에서 합성하는 값**으로 정의한다. WHATWG 는 DNS 실패·라우팅 실패·TLS 실패·급작 종료를 **구분하지 못하게 하라고 명시**한다(보안). 클라이언트가 얻는 것은 `1006` · 빈 사유 · `wasClean=false` 뿐이다. **대신 그렇게 끊는 것 자체는 규격이 허용한다** — §7.1.7 「상대가 Close frame 을 받아 처리할 가능성이 낮다고 판단되면 생략해도 된다」.

## 근거

- **요청/응답 상관의 형태** — 조사한 다섯 진영이 **전부** 상관 id 를 **프로토콜/세션 계층**에 두고 transport 는 프레임만 나른다. transport 가 id 를 **배우는** 배치는 조사 범위에서 못 찾았다. `tokio-tower` 의 `TagStore` 는 연관 타입 `type Tag: Eq` **하나뿐인 바운드**로 그것을 표현한다(원문 대조). 그래서 결정 3 의 「태그 타입에 제네릭」은 ADR-0129 의 어휘 격리(타입 단위)와 **충돌하지 않는 형태**다.
- **쓰기 시한이 필요한 이유** — 현행 코드에 ★**이미 실물 결함**★이 있다: `crates/engram-dashboard-net/src/ws.rs` 의 진행 중 소켓 write 는 close_signal 로 못 끊고, 그 동안 keepalive 도 함께 멈춘다(**그 파일 주석이 자인**). 즉 「차면 끊는다」 정책이 있어도 실제로는 안 끊긴다. 업계는 전부 write deadline 으로 이것을 잡는다(NATS 10s · nginx 60s · gRPC keepalive timeout 20s).
- **큐 상한이 되감기 링보다 크면 안 되는 이유** — 현행이 거꾸로다(`CONN_TX_CAP = 4608` > replay `max_events = 4096`). ★**큐가 꽉 차서 끊기는 순간, 밀려 있던 가장 오래된 것이 이미 링에서 밀려났을 수 있다**★ — 「끊고 다시 붙으면 복구된다」가 **그 숫자에서 이미 깨진다.** (적대 리뷰 적출 — **숫자만으로 계산됨**, 런타임 재현 미검.)
- **물리 끊김은 스스로 물어봐야 안다** — 정상 종료·프로세스 사망은 신호가 오지만 **회선 절단은 신호가 올 길이 없어** 소켓이 멀쩡해 보이는 채로 조용하다. OS keepalive 는 기본이 2시간이라 무용지물이므로 앱 레벨로 한다. 현행은 **데몬 쪽만** 능동 Ping 을 보낸다 — 로컬에선 충분했으나 원격·모바일이면 **클라 쪽도** 필요하다.
- **유실이 조용하면 안 되는 이유** — 조사 결론 둘. ① 신호는 **소비자가 이미 읽는 스트림 안에** 넣는다 — 옆 채널은 안 들으면 없는 것과 같고, NATS 문서가 그것을 자기 함정으로 적었다. ② **「얼마나 잃었나」보다 「어디서부터 다시 받나」가 유용하다** — 복구를 지원하는 시스템은 전부 경계값을 준다. 현행은 순번 구멍 검사가 **아예 없고**(`rg` 실측 0줄) 잘림 표시가 **콘솔 경고로만** 난다.
- **조사의 상태** — 정본 = `docs/research/reusable-transport-crate-boundary-2026-09-03.md`(적대 리뷰 반영, **판정 BLOCK → 수정 반영, 재판정 미실행**). ★**이 세션의 느린-소비자/유실-신호 조사는 보고서 문서로 남기지 않았다**★ — 위 두 항목의 출처가 그것이고, 지금은 이 ADR 이 그 유일한 기록이다.

## 영향 / 불변식

- ★**ADR-0036 개정이 필요하다**★ — 그 결정의 불변식 「데몬은 클라 수를 모르고 1 연결만 본다」가 **데몬이 PC·모바일 다중 클라를 받는 순간 깨진다.** 단일 choke point(셸이 유일 통로)와 창↔데몬 직결 금지는 그대로 유지된다. **이 ADR 은 그 개정을 하지 않는다 — 별도 결정으로 박아야 한다.**
- ★**ADR-0158 번복이 필요하다**★ — 버전 불일치를 **붙을 때 능력 광고로 판정**하는 대신, **요청했을 때 버전 오류를 받아 알리는** 쪽으로 사용자가 뒤집었다(2026-09-04). 그러면 핸드셰이크가 「토큰 통과/거절」만 보게 되어 crate 가 단순해진다. **대가 = UI 가 버튼을 미리 흐리게 못 하고 눌러 봐야 안다.** **이 ADR 은 그 번복을 하지 않는다 — 별도 결정으로 박아야 한다.**
- **crate 이름이 `engram-dashboard` 접두를 벗으면 CI 의존 상한 게이트가 그 crate 를 조용히 안 본다**(멤버를 **이름 접두**로 식별하기 때문). `transport` 를 붙일 때 **게이트 정규식을 같은 커밋에서 고친다.**
- **`frame_port` 의 feature 소속 미결(ADR-0130 유보)이 살아난다** — 새 crate 가 그 계약을 참조하려 하면 **즉시 걸린다.** 그 `Cargo.toml` 주석이 「재개 시 **착수 전에** 결정할 것 — 공개 API 변경이라 나중에 하면 비싸다」로 적어 두었다.
- **포트 파일·단일 인스턴스는 `transport` 로 옮기지 않는다** — 전송이 아니라 **데몬 살림**이고, discovery 가 이미 쓴다.
- **미룬 것(이 결정의 범위 밖)**: 원격 인증·페어링(★**다중 클라 신원과 같은 문제라 함께 푼다**★ — 현행 토큰은 폴더를 읽을 수 있으면 누구나 읽는 **공유 비밀**이라 클라를 구분하지 못한다) · 원격 주소 발견 · TLS · 다중 클라 입력 권한 · 클라별 되감기 · **화면 상태 동기화**(뒤처진 클라를 끊지 않고 한 번에 따라잡게 하는 근본 해결 — 데몬이 ANSI 를 해석해 화면 격자를 들어야 해서 큰 작업이다).
- **검증 안 된 것**: 이 ADR 의 판정은 전부 **정적 판독 + 조사**이고 **코드를 한 줄도 안 고쳤다.** ★재연결 시 셸이 실제로 이어받는지(`after_seq` 를 채워 보내는지) vs 버퍼를 통째로 다시 받는지는 **확인하지 않았다**★ — 결정 9 의 「그 지점부터 재요청」이 **신규인지 기존인지가 거기서 갈린다.**
