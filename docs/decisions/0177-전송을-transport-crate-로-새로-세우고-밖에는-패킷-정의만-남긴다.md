# ADR-0177: Build transport fresh as a transport crate and leave only packet definitions outside it

- 상태: 확정 (2026-09-04, basis: user decision + `docs/research/reusable-transport-crate-boundary-2026-09-03.md` (adversarial review BLOCK → fixes applied, **re-decision not run**) + this session's slow-consumer / loss-signal investigation (**no report written**) + static-reading measurements) · 부분 폐기 by ADR-0272 (decision 4's canonical location of the pairing-number function)
- 관련: CLAUDE.md 「백엔드 모듈 맵」 net entry · 「네트워크 행 격리 게이트」 · ADR-0129 (net split — the premise this decision stands on) · ADR-0036 (transport relay unification — **needs amending, this ADR does not do it**) · ADR-0158 (version-mismatch notice — **needs reversing, this ADR does not do it**) · ADR-0130 (`frame_port` feature membership deferred) · ADR-0151 (crate decision criteria) · ADR-0175 decision 6 (lib weight) · ADR-0155 (command crate) · ADR-0046 (replay single-flight) · ADR-0163/0164 (incarnation marker) · `src-tauri/src/daemon_client/connection.rs` · `crates/engram-dashboard-net/src/ws.rs` · step-log S21 · Amended by ADR-0272 (decision 4's canonical location of the pairing-number function)

## 맥락

Despite its name, `engram-dashboard-net` is **only the daemon's server side**. It has `default = []`, all of its real contents sit behind the `server` feature, and it has neither `connect` nor reconnection. The only symbol the shell actually uses from that crate is `auth::AuthFrame` (measured). ★**`net` came about to break a cycle, not to share code**★ — the header of that crate's `src/lib.rs` is the canonical source — so the 「재사용 가능한 전송 계층」 (reusable transport layer) does **not** exist in this repository yet.

All client-socket driving is lumped into one file of the shell, `src-tauri/src/daemon_client/connection.rs` (1,674 lines — the largest file in this package, measured). Connect · reconnect backoff · handshake · read loop · Ping handling · request/response correlation · incarnation-marker guard · replay single-flight · frame→window routing all sit in one place. ★**So there is no place to put 「클라가 데몬 여러 대에 붙는다」 (a client attaches to several daemons)**★ — the assumption that there is one connection is baked into the state shape of the whole file.

User requirements (2026-09-03~04):

- **Direction (server/client) is not a separate layer but a capability you choose.**
- What comes from outside is **only the packet definitions**; the rest must do its own networking.
- **A client must connect to multiple daemons**, and **a daemon must accept multiple clients (PC, mobile, and so on)**.
- Way of working = **create a separate crate → verify it independently → attach it in a suitable scope and test.**

## 결정

1. **The new crate is named `transport`** (user decision 2026-09-04 — *"뭔가 직관적이다"* (it feels intuitive somehow)). ★**The existing `net` is not torn apart in this work**★ — build the new one fresh and **verify it independently**, then give the daemon and the shell each a dedicated folder and attach it there. In the end `transport` takes over the network-handling slot.
2. **Narrow the scope to the three engram parts (daemon, shell, mobile)** (user decision — *"너무 범용을 생각하지말고"* (don't think too general-purpose)). Aiming at any project whatsoever means **we cannot decide, and everything becomes an option.** Narrowing to three lets us **fix the defaults** — those three are already server, client and mobile, so the structure comes out general-purpose anyway.
3. **What goes inside the crate**:
   - Frame boundaries · request/response correlation (★**generic over the tag type — the crate does not know its name**★) · role distinction (request/response/notification/stream)
   - Keeping streams alive = identifier · generation · sequence number · resume · duplicate removal · **gap finding**
   - Connection establishment · **opaque handshake frames** (any number of them) · **bidirectional keepalive** · **write deadline** · **backoff+jitter reconnection**
   - **A registry of N peers + supervision per peer** · an **origin marker** on inbound traffic · **generation boundary exposure**
   - Fan-out · bounded queue and backpressure signal
4. **What stays outside (with the consumer)**: **the packet struct definitions** · address and authentication material · policy values (the crate has defaults for all of them) · **the function that extracts the pairing number** (not new — the canonical ones already exist in `protocol` as `command_request_id` and `event_reply_request_id`) · the choice of policy when the queue is full · version and capability negotiation.
5. ★**The envelope is owned by the consumer**★ — the crate does not fix a `{tag, kind, payload}` envelope. The reasons are all **measured**: our wire has no envelope struct and **the kind name is itself the JSON object key** (`{"CreatePreset":{…}}`), the correlation key is inside the payload and **its position differs per variant**, many variants have no key at all, four of them have it one layer further in, and **the outer one and the inner one mean different things**. On top of that there are two codecs — control = JSON (WS Text) · output hot path = fixed-header binary `[tag:1][agent_id:16][epoch:4][seq:8]` (WS Binary).
6. **Slow consumer = when the queue is full, that connection is cut** (current behavior kept). But ★**the policy is not nailed down inside the crate; the outside chooses it**★.
7. **Build it so that both the transport and the clock can be swapped.** The verification harness (decision 8) requires this, and later TLS or other transports hook in here.
8. **Verification harness** = the logic is **all in-memory + time injection** (backoff, keepalive and write deadline are verified **without actually waiting**). Only a few real sockets are used — ① does the WS adapter actually connect ② **when the peer does not read, does the write deadline actually cut it off**. ★The latter needs a kernel buffer to measure, so in-memory cannot measure it★. Ports are requested as port 0. **It runs as-is in CI.**
9. **Loss signal**: truncation is given not as true/false but as ★**「지금 유효한 가장 오래된 번호」** (the oldest number that is valid now)★. And it rides up in **a stream the upper layer reads**, not on the console. In addition, **a sequence-gap check** is added, and on a gap **it re-requests from that point** — it does not stop at detection.

## 거부한 대안

- **Creating a folder inside `net` and putting the code there** (the user proposed it first → withdrew) — rejected on four grounds. ① There is actually almost no 「우리 규칙」 (our rules) to gather — packet contents are in `protocol`, addresses and tokens in discovery and portfile, and policy is a **value**, not code. ② `net` has **ignorance of the agent vocabulary** as an invariant, and the CI isolation gate guards it — adding this turns the gate red. ③ That crate's identity is nailed down in the docs as 「데몬의 **서버** 행」 (the daemon's **server** side), so adding the client half and a multi-connection registry makes **that sentence false.** ④ ★**「일단 폴더로 두고 나중에 crate 로 승격」 (keep it as a folder for now and promote it to a crate later) is a line of reasoning this repository has already been bitten by**★ — the previous session recommended it and withdrew it after the user's objection (*"팀에서 안 지켜질 텐데 나중에 승격이 되겠나"* (the team won't keep to it, so will it ever get promoted later?)).
- **A form where the crate owns the envelope** (research candidate A) — the measurements in decision 5 above are themselves the reason for rejection. Adopting it would **change the wire bytes** and collide with ADR-0129's premise 「wire JSON 모양 보존」 (preserve the wire JSON shape). **Basis for rejection = measured** (golden tests + codec source).
- **A form that only carries a byte pipe** (research candidate C) — leaves all serialization and correlation to the upper layer. Friction with vocabulary isolation is zero, but it is **the furthest from the user's requirement** — it becomes 「바이트만 나른다」 (only carries bytes) instead of 「패킷만 주면 된다」 (just hand over the packets). The amount that can be taken out of `connection.rs` is also the smallest.
- **Splitting the crate in two, a thin sans-IO core + an I/O layer** (research candidate B) — it satisfies the reuse condition best of the three. But ★**there is a risk of running into ADR-0175 decision 6 (no single-file libs · match the lib weight)**★, and **that weight cannot be measured before the design is drawn.** The direction also differs from decision 2, which narrowed the scope to the three engram parts. **Basis for rejection = weak (not measured).**
- **Absorbing the existing `net` in one go** — nine daemon files would have to be swapped at the same time. It is the exact opposite of 「적당한 범위로 붙이며 테스트」 (attach in a suitable scope and test), and it is the spot ADR-0036 nailed down as 「전송층 재배치는 **동시성-치명**」 (relocating the transport layer is **concurrency-critical**).
- **Keeping the name `net`** — it has the advantage that gates and docs hang on that name, so there is less to touch. But the user chose `transport` for **intuitiveness** (2026-09-04). The cleanup of docs and gates is done **when attaching**.
- **Dropping messages one at a time for a slow consumer** (drop oldest / drop newest) — the MQTT family does this, but ★**it cannot be used for terminal bytes**★: dropping the middle breaks UTF-8 and throws the ANSI parser state off, so **the screen keeps being drawn in a broken state.** Cutting at least reconnects and realigns from the start.
- **A design that guarantees control delivery** (a control-only queue / a control-only socket) — ★**on a single socket the guarantee is impossible (investigation conclusion)**★. HTTP/2 exempts control frames from flow control, but that holds only because RFC 9113 §5.2.2 **enforces as a MUST** that 「양 끝은 받은 즉시 읽어야 한다, 안 읽으면 교착」 (both ends must read immediately on receipt, otherwise deadlock) — if the peer does not read the socket, even exempted frames are blocked in the kernel send buffer. A control-only **socket** is a real pattern (PostgreSQL opens a **new connection** to cancel a running query), but it doubles the connections and complicates authentication and lifetime. Since the transport is placed behind a trait (decision 7), it stays open for later.
- **The assumption that simply cutting a congested connection delivers the reason** — ★**false**★. RFC 6455 §7.4.1 nails `1006` down as a **reserved value that cannot be sent on the wire**, and §7.1.5 defines it as a **value the receiving side synthesizes locally**. WHATWG **explicitly requires that DNS failure, routing failure, TLS failure and abrupt termination be made indistinguishable** (security). All a client gets is `1006` · an empty reason · `wasClean=false`. **On the other hand, cutting that way is itself allowed by the spec** — §7.1.7 「상대가 Close frame 을 받아 처리할 가능성이 낮다고 판단되면 생략해도 된다」 (if it is judged unlikely that the peer will receive and process the Close frame, it may be omitted).

## 근거

- **The shape of request/response correlation** — **all** five camps surveyed put the correlation id in the **protocol/session layer**, and the transport only carries frames. A placement where the transport **learns** the id was not found within the survey scope. `tokio-tower`'s `TagStore` expresses it with **a single bound**, the associated type `type Tag: Eq` (checked against the original). So decision 3's 「태그 타입에 제네릭」 (generic over the tag type) is a form that **does not conflict** with ADR-0129's vocabulary isolation (type-level).
- **Why a write deadline is needed** — the current code ★**already has a real defect**★: in `crates/engram-dashboard-net/src/ws.rs`, a socket write in progress cannot be cut by close_signal, and keepalive stops along with it for that time (**the comment in that file admits it**). That is, even with a 「차면 끊는다」 (cut when full) policy, in practice it does not get cut. The whole industry handles this with a write deadline (NATS 10s · nginx 60s · gRPC keepalive timeout 20s).
- **Why the queue cap must not be larger than the rewind ring** — the current code has it backwards (`CONN_TX_CAP = 4608` > replay `max_events = 4096`). ★**At the moment the queue fills and the connection is cut, the oldest backed-up item may already have been pushed out of the ring**★ — 「끊고 다시 붙으면 복구된다」 (cut and reattach and it recovers) **is already broken at those numbers.** (Found in the adversarial review — **computed from the numbers alone**, runtime reproduction unchecked.)
- **A physical disconnect can be detected only by actively probing** — a normal exit or a process death sends a signal, but **a cut line has no way to send one**, so it stays quiet with the socket looking fine. OS keepalive defaults to 2 hours and is useless, so it is done at the app level. The current code sends an active Ping from **the daemon side only** — enough locally, but for remote or mobile **the client side** needs it too.
- **Why loss must not be silent** — two investigation conclusions. ① The signal goes **inside the stream the consumer already reads** — a side channel might as well not exist if nobody listens, and the NATS docs list it as one of their own pitfalls. ② **「어디서부터 다시 받나」 (from where to receive again) is more useful than 「얼마나 잃었나」 (how much was lost)** — every system that supports recovery gives a boundary value. The current code has **no** sequence-gap check **at all** (`rg` measured 0 lines) and truncation shows **only as a console warning**.
- **State of the investigation** — canonical = `docs/research/reusable-transport-crate-boundary-2026-09-03.md` (adversarial review applied, **decision BLOCK → fixes applied, re-decision not run**). ★**This session's slow-consumer / loss-signal investigation was not left as a report document**★ — it is the source of the two items above, and for now this ADR is its only record.

## 영향 / 불변식

- ★**An ADR-0036 amendment is needed**★ — its invariant 「데몬은 클라 수를 모르고 1 연결만 본다」 (the daemon does not know the number of clients and sees only 1 connection) **breaks the moment the daemon accepts multiple PC and mobile clients.** The single choke point (the shell is the only path) and the ban on direct window↔daemon links stay as they are. **This ADR does not make that amendment — it must be recorded as a separate decision.**
- ★**An ADR-0158 reversal is needed**★ — instead of **deciding a version mismatch by capability advertisement at connect time**, the user flipped it to **receiving a version error on request and reporting it** (2026-09-04). Then the handshake sees only 「토큰 통과/거절」 (token pass/reject), and the crate becomes simpler. **Cost = the UI cannot grey out a button in advance and you only find out by pressing it.** **This ADR does not make that reversal — it must be recorded as a separate decision.**
- **If the crate name drops the `engram-dashboard` prefix, the CI dependency-ceiling gate silently stops looking at that crate** (because it identifies members by **name prefix**). When attaching `transport`, **fix the gate regex in the same commit.**
- **The undecided feature membership of `frame_port` (ADR-0130 reserve) comes alive** — if the new crate tries to reference that contract, **it is caught immediately.** The comment in its `Cargo.toml` says 「재개 시 **착수 전에** 결정할 것 — 공개 API 변경이라 나중에 하면 비싸다」 (decide it **before starting** on resumption — it is a public API change, so doing it later is expensive).
- **The port file and single instance are not moved to `transport`** — they are not transport but **daemon lifecycle management**, and discovery already uses them.
- **Deferred (outside this decision's scope)**: remote authentication and pairing (★**the same problem as multi-client identity, so solved together**★ — the current token is a **shared secret** that anyone who can read the folder can read, so it cannot tell clients apart) · remote address discovery · TLS · multi-client input permissions · per-client rewind · **screen-state sync** (the fundamental fix that lets a lagging client catch up in one go without being cut — the daemon would have to interpret ANSI and hold a screen grid, so it is a big job).
- **Not verified**: every decision in this ADR is **static reading + investigation** and **not a single line of code was changed.** ★Whether the shell actually resumes on reconnect (whether it fills in and sends `after_seq`) vs receives the whole buffer again was **not checked**★ — whether decision 9's 「그 지점부터 재요청」 (re-request from that point) is **new or existing** turns on that.
