# ADR-0160: Agent command relay is attached by widening the control route

- 상태: 확정 (2026-08-19, basis: code measurement + user decision) · 부분 폐기 by ADR-0161 (who issues the request number)
- 관련: ADR-0129(net isolation) · ADR-0155(command crate) · ADR-0157(wiring check — open item to be reopened) · `crates/engram-dashboard-daemon/src/control/catalog.rs:194-209` · `crates/engram-dashboard-daemon/src/command_delivery.rs` · step-log S20 · Amended by ADR-0161 (who issues the request number)

## 맥락

Of the 20 commands in the command registry, the 15 whose owner is the dashboard cannot be called by an agent. An agent comes in through the control route (`/control/call`), but its handler looks up only the daemon's own `CommandTable`, and if the command is not there it returns `UNSUPPORTED` via `not_mine()` (`control/catalog.rs:194-209`·`:264-281`, `control/commands.rs:73-90`). A registry lookup finds out who the owner is, but **there is no act of handing the call over.**

The machinery for handing over already exists and runs every day — the seat and pairing (`CommandDeliveries`, `command_delivery.rs:296-306`), the 10-second deadline (`:362`) and the expiry sweeper on a 1-second cycle (`:404-437`), and holding the seat that prevents re-execution (`SeatState::Retained`, `:211`). But the only production caller of `deliver` is **the socket dispatcher alone** (`connection_core.rs:1271`). That is, it is not blocked; the path from the control route to that machinery has not been built.

## 결정

1. **The relay widens the control route and attaches it to the existing delivery machinery.** The agent stays with the door and key it uses now.
2. **The daemon issues `request_id`**, ties that seat to the request, and when the answer comes returns it as the response. The control route is one connection per request, so the caller does not send a number along.
3. **The wire contract (the envelope) is not touched in this scope.** The envelope already has `request_id`, so the default behavior needs no contract change.

## 거부한 대안

- **Join the agent to the socket door (WS)** — that door only does a constant-time comparison of the daemon's single token (`engram-dashboard-net/src/ws.rs:264`, token generation `daemon/src/lib.rs:64-67`, written to `daemon.json` at `:696-703`), so it **has no concept of identity at all.** Giving the agent that token opens `WriteStdin` (`connection_core.rs:779` — arbitrary bytes into another agent's stdin), `Kill` (`:758`), `StopDaemon` (`:876`), and `RegisterCommands` (`:1172` — hijacking a dashboard-owned name) all at once. To build an identity scheme on that door we would have to cross the net crate's isolation boundary (ADR-0129) as its spec allows, and on top of the current structure with no sender check (the `Command` arm unconditionally spawns `deliver`, `connection_core.rs:1264-1277`) we would have to newly create a guest tier. By contrast the control door has identity **already arriving** — `ControlRegistry::validate()` returns `(AgentId, epoch)` + `mail_allowed` (`control/registry.rs:156-163`, issuance `control/mod.rs:140-229`).
- **Add a caller-identity slot to the envelope now** — it is not needed to open the 15 (the answer is delivered by a ticket number and does not use identity). Moreover how to extend the contract is an open item (the clash between ADR-0157 and the bus frame path — pending decision ②), so that has to be settled first. **It is a deferral, not a permanent rejection** — add it when the dashboard needs to know "who issued this command". The material is already in hand then (the `validate()` return value above).
- **The caller writes its own id into the envelope and sends it** — it is a self-declared identity and cannot be used. This judgment is already embedded in the code: the `CommandEnvelope.owner` comment says "do not read this as identity" (`engram-dashboard-command/src/envelope.rs:68-70`), and `route()` overwrites that value with the registry lookup result (`route.rs:144-149`).

## 근거

- The file:line references above were measured by a subagent code survey on 2026-08-19 (control route transport and authentication, an exhaustive list of `deliver` callers, the WS authentication check function, the locations of seat, deadline and duplicate prevention).
- This is not building new delivery machinery but **connecting a second entrance**. That machinery was converged through 5 review rounds on 2026-08-18, so there is no reason to build a second copy, and this decision does not build a copy.
- User decision (2026-08-19) — after seeing the list of privilege jumps from joining the socket, the user chose extending the control route.

## 영향 / 불변식

- **`deliver` gets two production callers.** The two entrances use the **same** seat, deadline and duplicate prevention — building a different mechanism per entrance splits causality.
- **The control route response can be delayed up to the deadline** (currently 10 seconds by default). A caller written on the assumption of an immediate answer loses that assumption.
- **Do not put the agent token on the socket door.** The net crate's isolation gate (ADR-0129) and the symbol allowlist stay as they are.
- **No envelope change** — the generated-output sync gate (`protocol/bindings/`·`core/bindings/`) is unaffected. The moment the envelope is touched this clause breaks, so a new decision is needed then.
- **Write the regression net anew.** An integration test that runs `deliver` end to end exists on **neither path** (the socket e2e suite has no command-bus frames, and the `deliver` tests are all inline unit tests with a fake peer). This decision opens a new entrance, so the integration coverage of that entrance is built together with it.
