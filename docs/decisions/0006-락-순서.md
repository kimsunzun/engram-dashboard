# ADR-0006: Lock ordering discipline (sessions → internals)

- 상태: 확정 (S1 LLD §10, caught in the dr26 review) · 부분 폐기 by ADR-0231 (the input-lock lock-order line and the fan-out exception inside it · replay → pending-list table (leaf)) · 부분 폐기 by ADR-0234 (the fan-out exception in the codex emit line that holds order)
- 관련: CLAUDE.md 핵심 불변식 · `manager.rs::get_session` · `output_core.rs::emit` · Amended by ADR-0231 (the input-lock lock-order line and the fan-out exception inside it · replay → pending-list table (leaf)) · Amended by ADR-0234 (the fan-out exception in the codex emit line that holds order)

## 맥락
If the `sessions` map lock and a session's internal locks (core/status) are held at the same time, the lock order conflicts with other paths and deadlocks.

## 결정
- **The sessions RwLock is lookup-only** — clone the `Arc<AgentSession>` and **release the lock immediately**; only then acquire the internal locks (core/transport).
- **No external calls while holding the status lock** — `finish`/`enter_exiting` release the status lock first, then emit status_changed.
- **The send in emit** — clone the subscribers, then send without holding the lock.

## 거부한 대안
- **Nested lock holding** (touching internals while holding the sessions lock) — if the order differs per path, it deadlocks. The most common concurrency trap.

## 근거
The dr26 (fable) LLD review caught the transition race and the nested-lock risk as real defects. A one-way lock order removes the possibility of deadlock.

## 영향 / 불변식
- Every manager method follows the `get_session` pattern (Arc clone + immediate release).
- New code that touches session internals while holding the sessions lock violates this ADR.
