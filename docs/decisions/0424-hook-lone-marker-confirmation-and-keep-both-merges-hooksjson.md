# ADR-0424: Hook lone-marker confirmation and keep-both merges: hooks.json asks like SKILL.md, a referenced marker is never numbered, one code per call, the detach filter judges where the pairs put a folder

- 상태: 확정 (2026-11-26, 근거: user decision 2026-11-26 on tracking T-125 (「어쨋든 이대로 진행하던지」) · main decisions during step-22 P4 coding and review (ADR-0420 decision 14, TRD O4) · P4 code review (lead PASS, risk axis FIX, cross-family Codex FIX) on `3211b40d..7788c880` · fix rounds 1–3 re-reviewed (lead PASS, risk PASS, Codex PASS after round 3) · QA PASS 2026-11-26)
- 관련: Amends ADR-0420 (decisions 1 and 14 lone-marker scope) · Amends ADR-0415 (decisions 2 and 3 merge leaves) · Amends ADR-0339 (decision 2 lone marker shapes) · ADR-0374 (a missing item is skipped with a notice) · ADR-0409 (decision 2 the plan digest) · ADR-0425 (same unit: read-only leftovers) · TRD `docs/process/S25-preset-library/trd-hook-components.md` §2.1, §6 P4 and §9.3 O4 · tracking T-125

## 맥락
ADR-0420 decision 14 extended ADR-0339's lone-marker confirmation to a hook's `hooks.json`: renaming it or moving it out of a referenced hook folder asks, with its own code `hook-unconfirmed`; without the ask the hook vanishes and its references are only skipped with a notice at launch (ADR-0374). Decision 1 of the same ADR still said the lone-marker mechanism stays skill-only, and the TRD (§2.1) left the generalization to P4. P4 made the machinery in `ops.rs` marker-generic.

Three more gaps sat beside it. ADR-0415 left open (tracking T-125) that a keep-both merge of a referenced skill into a same-name folder renames its `SKILL.md` to `SKILL (2).md` and removes the emptied source folder without asking. The P4 risk review found that a referenced hook merged into a same-name folder that holds a `SKILL.md` loses its hook the same way: its `hooks.json` becomes an ordinary file of a skill and nothing asks (must M1). It also found that ADR-0415 decision 2's post-step filter looked at a planned leave's old path and counted only exact pairs, so a planned leave that an earlier item of the same call let move whole had its references dropped instead of re-pointed (must M2, a fault from U3).

## 결정
1. **A referenced hook folder losing its `hooks.json` asks like a skill losing its `SKILL.md`** (main, ADR-0420 decision 14, TRD O4). A `hooks.json` renamed away, moved out of its hook folder (its own subfolder included), or taken by a merge while the folder keeps an entry is refused `hook-unconfirmed` with the same `yes` / `detachRefs` / plan digest as `SKILL.md` (ADR-0339 M110, ADR-0409 decision 2), planned from no-follow listings and stats at the call and again in the hold. The skill machinery is marker-generic: one private `Marker { Skill, Hook }` drives the lone-marker target, the merge-leave plan, the merge guard and the post-step check. ADR-0420 decision 1's "ADR-0339's lone-marker mechanism stays skill-only" no longer holds; its folder precedence (a folder with both markers is a skill) stands.
2. **A keep-both merge never numbers a referenced marker unasked** (user 2026-11-26, T-125).
   - A keep-both merge that would rename a referenced skill's `SKILL.md` (or a referenced hook's `hooks.json`) to a numbered name asks with the same refusal, even when nothing else stays behind. Confirmed, the marker takes the numbered name, the source folder goes, and detach applies.
   - So does a referenced hook merged into a same-name folder that holds a `SKILL.md`, under any `onConflict`: its `hooks.json` would become an ordinary file of a skill (risk M1).
   - The merge keeps an unconfirmed marker in place (the folder then stays) whenever the hold's plan did not name that leave: an entry stayed behind, a keep-both name, or a hook landing beside a `SKILL.md`. A marker that would stay anyway answers its own reason, as in ADR-0415 decision 3.
   - An unconfirmed marker is placed without keep-both numbering: a name taken after the check gives a conflict, and the marker stays in place, left with its own code.
3. **One code per call; the `left` reason is the marker's own** (main). A call refused for lone markers answers `hook-unconfirmed` only when every referenced folder among them is a hook, otherwise `skill-unconfirmed`. This holds at the call, in the hold and for the fresh plan after the hold. The code is not in the digest, and the plan, digest and `forms` do not depend on it. A merge's `left` row names the marker's own code: a `hooks.json` kept in a call refused `skill-unconfirmed` is left `hook-unconfirmed`.
4. **The post-step detach filter judges a planned-leave folder where the move's pairs put it** (main, risk M2; fixes ADR-0415 decision 2). A planned leave is detached only when the folder, mapped through every pair of the call in order, is no item of the marker's kind after the disk step. A folder merged away whole maps to the destination's item, and one an earlier item of the call let move whole by its own rename is the same item at its new path: both keep their references, which follow the pairs. A keep-both or entry-stays leave has no pair for the folder and its old path is no item, so it still counts as gone.
5. **Open, held for the user.**
   - Deleting a lone `hooks.json` also asks (`delete-unconfirmed`; detach drops the hook folder's lines; agents are never changed for a lone marker), as deleting a lone `SKILL.md` does under ADR-0339 decision 2. This follows from the generic lone-marker target and goes beyond decision 14 (rename, move-out, merge). It is committed with the ask; the user decides whether it stays.
   - A `SKILL.md` arriving in a referenced hook folder (a lone `SKILL.md` moved in, or a skill merged into a same-name hook folder) turns it into a skill without asking. Decision 14 covers only a marker leaving.

## 거부한 대안
- **Keep the lone-marker mechanism skill-only (ADR-0420 decision 1 as written)** — renaming or moving a referenced hook's `hooks.json` makes the hook vanish, and its references are only skipped with a notice at launch, easy to miss. Evidence: 코드 (ADR-0374 skip path; TRD O4).
- **Number the marker under keep-both without asking (the U3 behaviour)** — `SKILL.md` becomes `SKILL (2).md`, the source folder goes, and references read not found. Evidence: 사용자 직접 기각 (T-125, 「어쨋든 이대로 진행하던지」).
- **Leave the hook merged beside a `SKILL.md` as an accepted gap (a tracking item)** — exactly the "moved out of a referenced hook folder" case decision 14 exists for, and the same class as T-125 (the marker moves but does not become the destination's). Evidence: 리뷰 + 코드 (risk M1; test `a_merged_hook_folder_takes_its_references_where_its_hooks_json_made_a_hook_and_asks_where_it_would_not`).
- **Place an unconfirmed marker with keep-both numbering** — a marker name made by another process between the stat and the no-replace rename gives the marker a numbered name unasked. Evidence: 리뷰 + 코드 (risk R2; test `a_keep_both_merge_never_numbers_an_unconfirmed_skill_md_whose_name_was_taken_after_the_check`).
- **Judge a planned leave at its old path with exact pairs only (the U3 filter)** — a planned leave whose folder an earlier item let move whole has no exact pair and no item at its old path, so its references are dropped although the skill is intact at its new path: the outcome ADR-0415's own rejected alternative describes. Evidence: 리뷰 + 코드 (risk M2 two-item trace; test `a_planned_leave_whose_folder_an_earlier_item_let_move_whole_keeps_its_references`).
- **A code per marker, or a separate refusal per marker kind, in one call** — one `Conflict` per call carries one plan, digest and `forms`; the per-marker detail lives in the `left` rows. Evidence: 약함 (judgement; the lead review checked only that the plan JSON and `forms` do not depend on the code).

## 영향 / 불변식
- **Nothing unasked leaves a referenced marker folder** — a merge moves the marker last and keeps it whenever the hold's plan did not name that leave; it is never numbered past the check. A change that lets a marker move or take a numbered name without a planned leave breaks this ADR, ADR-0415 decision 3 and ADR-0339 M110.
- **The detach filter is independent of how the folder moved** (exact pair, prefix pair or removal): it maps the folder through the pairs before it looks at the catalog.
- **ADR-0420 decision 1** — code that treats a marker folder as one item now includes the lone-marker mechanism; the folder precedence rule stands.
- **ADR-0415** — decision 2's ask now covers keep-both names and a hook merged beside a `SKILL.md`, and its filter judges where the pairs put the folder; decision 3's guard keeps the marker in those cases too, never numbered; its 영향 open item (the keep-both merge, T-125) is closed by decision 2 here.
- **ADR-0339 decision 2** — the lone-marker shapes (rename, move-out and, pending decision 5, delete) cover a hook's `hooks.json` as well as a skill's `SKILL.md`; `detachRefs` applies to them in the same way.
- **LLM surface (step-22 P5)** — `prompts/engram-help.md` (the confirmation paragraph, skill-only today), agent `commands.rs` `library.move` / `library.rename` docs, `library_commands.rs` and the generated bindings still name only `SKILL.md` and `skill-unconfirmed`; until P5 an LLM receiving `hook-unconfirmed` has only `forms` to go on.
- **Docs** — `docs/reference/structure/asset-library.md` (move and delete paragraphs) and the `ops.rs` header follow this decision (main's).
- **Not covered** — a marker matched by exact name after an on-disk case-only rename with no rescan (risk R6, pre-existing); decision 5's open items.
