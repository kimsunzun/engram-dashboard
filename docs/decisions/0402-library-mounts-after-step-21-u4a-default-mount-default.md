# ADR-0402: Library mounts after step-21 U4a: default mount default_library, overlap only between mounts, judge before create, load-time overlap judgement on the first caller's budget

- 상태: 확정 (2026-11-22, 근거: user 2026-11-22 「그냥 디폴트 라이브러리로해.」 (name) · 「그냥 전부 허용해. 예외처리 시팔 계속 추가할래?」 (no reserved folders, after being told the launch folder is swept at every daemon start) · 「순서 바꿔.」 (judge before create) · 「껏다 키면 되는거 아님?」 (holds lift on restart) · 「그대로 두는게 좋을것같아」 (no special repeat after a failed first-start save) · 「ㅇㅇ 그렇게 고쳐.」 (a starved scan records nothing) · user 2026-11-21 「이건 그냥 구현 간단한걸로해.」 (one invalid mount entry keeps the whole list corrupt) · step-21 U4a code review deep, rounds 1–4)
- 관련: Amends ADR-0400 (decisions 3, 9, 10 and 13 first mount name, create order, overlap and the load-time check) · ADR-0291 (data-file rules, unchanged) · ADR-0312 (decision 5, as ADR-0400 changed it) · ADR-0360 (IO budgets) · ADR-0375 · ADR-0382 (decisions 1 and 4, as ADR-0400 changed them) · ADR-0398 (no migration) · step-21 TRD `docs/process/S25-preset-library/trd-library-mounts.md`

## 맥락
Coding and reviewing step-21 unit U4a (the mount commands other than rename) changed four rules ADR-0400 set. The default mount's name `library` was the product word for the whole library, and the user read 「remove `library`」 as deleting the library. The overlap rule against the data, launch and built-in folders added exceptions the user did not want. Creating the folder before the overlap judgement left an empty folder behind a refusal. The load-time overlap check, placed only in the boot job, let a reader or a launch walk an overlapping mount before it ran (review round 1); moving it onto request paths then had to keep each caller inside its own IO budget (round 2) and not record healthy mounts as unreadable when the check ate a scan's budget (round 3).

## 결정
1. **The default mount and its folder are `default_library`** (amends ADR-0400 decision 3). A missing `library.json` registers the default place `<dist>\default_library` / `<data>\default_library` (created) as one mount named `default_library` with `path` `"default"`. Not shipped, so nothing is carried from `library` (ADR-0398): an existing development entry `{library, "default"}` now resolves to the new folder and reads missing until fixed by hand.
2. **Overlap is judged only between mounts** (amends ADR-0400 decision 10). Add and relocate refuse `mount-overlaps {path, with: "mount", mount}` when the folder is the same as another mount, inside one or containing one — never because of the data folder, the launch folder or the built-in folder. `LibraryValues.data_root` is gone. Accepted: a mount at or inside the launch folder loses its contents to the boot sweep (`sweep_launch_dir`) and on agent release; a mount holding the built-in folder shows those files a second time.
3. **Judge before create** (amends ADR-0400 decisions 9 and 13). With `create`, add and relocate run the overlap judgement first and create the folder only after it passed; a refused judgement leaves nothing on disk. A folder that does not exist yet is judged by its nearest ancestor whose canonical path the OS gives, with the names below it appended by spelling; an OS refusal moves up one level; an ask that gives no answer refuses (fail closed). A later create, stat or walk failure can still leave a created folder (ADR-0379 decision 4).
4. **The load-time overlap judgement runs once per run, at whichever comes first** — the boot job, a reader's scan, a read entrance, a launch, `library.status` or a mount command — never before the daemon answers and never in the first start (amends ADR-0400 decision 10; ADR-0382 decision 1 holds). Others wait for it. It costs no caller more than its own budget (ADR-0360): the caller that runs it spends at most what is left of its own required budget (at most one limit), a caller that finds it running waits at most that much, and either is charged the time (`LaunchIo::charge_required`). A caller whose budget runs out first takes no mount as `Ok` (`not checked` for that one answer), and a mount command refuses `library-unavailable` (repeat the call).
5. **A scan starved by the judgement records nothing.** A scan waits for the judgement on its own budget and stats the mounts on a fresh one; if the judgement is still running when that wait ends, no mount is stated: none is recorded, walked, or counted toward raising the first scan, and the next scan stats them. A mount's own timeout is still recorded unreadable. Cost: up to one extra budget once per run for the first whole scan.
6. **Holds lift only by relocate, remove or a restart.** A mount held at load for overlapping an earlier one stays held for the run even after the earlier mount is removed (ADR-0400 decision 10's 「until the user relocates or removes it」, plus a restart re-judges).
7. **Unchanged, decided again:** a `library.json` with one invalid mount entry is corrupt as a whole (ADR-0291), and a repeated `removeMount` after a failed first-start save gets no special rule (it answers `mount-not-found`; the next start, still without a file, registers `default_library` again).

## 거부한 대안
- **Keep the name `library`** — it is the product's word for the whole library; the user misread its removal as deleting the library. 사용자 직접 기각.
- **`default`, `user` or `local` as the name** — `default` already names the `library.json` path value and the built-in `engram/default`; the user chose `default_library` over `user` / `local`. 약함 — 사용자 직접 기각.
- **Keep the reserved-folder refusal (data, launch, built-in)** — exceptions for folders the user registered on purpose (CLAUDE.md 「최소한만 막기」). 사용자 직접 기각.
- **Refuse only the launch folder (swept at every daemon start)** — presented with the sweep evidence (`launch.rs` `sweep_launch_dir`); the user declined another exception. 사용자 직접 기각.
- **Re-judge the reserved folders at load** — superseded by alternative 3's rejection. 사용자 직접 기각.
- **Create before judging (ADR-0379 decision 4 order)** — a refusal leaves an empty folder. 사용자 직접 기각.
- **Judge only in the boot job (ADR-0400 decision 10 as written)** — a reader, a launch or a failed job spawn could walk or read an overlapping mount first. Basis: code review round 1 (Codex must, against `lib.rs` `start_boot_scan`).
- **Judge under a mutex held across IO, on its own budget** (round-1 fix) — the first `library.status` with a dead share took about two budgets (~10 s), past the transport `request_timeout` of 8 s. Basis: code (`transport/src/policy.rs`), review round 2.
- **Record the starved `not checked`** — healthy mounts showed unavailable after startup until a refresh. Basis: review round 3; user approved the fix.
- **Lift a hold when the earlier mount is removed** — needs a re-judgement on every remove; a restart lifts it. 사용자 직접 기각.
- **Treat a missing `library.json` as naming the default mount for a repeated removal** — a special case for two consecutive save failures; the mount coming back after a restart is harmless. 사용자 직접 기각.

## 영향 / 불변식
- `mounts.rs` `FIRST_MOUNT` = `default_library`; daemon `data_dir.rs` default place folder `default_library`. Tests that need a generic mount use `MountName::library()` (test-only), not the first-start name.
- `mounts::overlap` takes no reserved places; `mount-overlaps` args are `{path, with: "mount", mount}`.
- `LibraryService::judge_at_load` is the one load-time judgement; every mount stat goes through `stat_held` (`stat_mount_list`, `scan_stats`) and every mount command through `take_mount_change(io)`; `first_start` uses the raw mount-change mutex and never judges.
- `scan_stats` runs the judgement on its own read budget and stats the mounts on a second, fresh one; when the judgement is still running at the end of its wait, every mount is "not stated" and `scan_until_applied` / `Gate::observe` record nothing for it. A scan's stats must never share a budget with the judgement — that would bring back healthy mounts recorded unreadable.
- Step 21 U4b (rename) must go through `take_mount_change(io)` and move or release a hold on the renamed mount.
