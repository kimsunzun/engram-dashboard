# ADR-0229: 메인 창을 닫으면 모든 창을 트레이로 숨기고 트레이 아이콘은 모든 창을 되살린다

- 상태: 확정 (2026-09-24, 근거: 사용자 결정 + `/research` medium(최소화 연동) · light(트레이 닫기) 조사)
- 관련: Amends ADR-0026 (X 와 보이기 숨기기가 다루는 대상 창 범위만) · ADR-0057(팝아웃 창) · ADR-0225(숨은 `agent-tree` 창 걷기 — 대상에서 뺀다) · 조사 `docs/research/multi-window-minimize-survey-2026-09-24.md` · `src-tauri/src/tray/actions.rs`(보이기·숨기기) · `src-tauri/src/lib.rs`(창 이벤트)

## 맥락
사용자 제기(2026-09-24): 「최소화했다가 아이콘을 누르면 복원되는데, 창을 여러 개로 분리했을 때는 메인 창만 적용된다.」

코드 사실(읽기 확인):
- 트레이 아이콘 좌클릭(`src-tauri/src/tray/mod.rs:111-120`)·단일 인스턴스 재실행(`src-tauri/src/lib.rs:36-37`)·보이기 명령(`show_main_ui` — `src-tauri/src/commands/tray.rs:10`)이 모두 같은 함수(`show_main_ui`)를 부르고, 그 함수는 **메인 창 하나만** `show → unminimize → set_focus` 한다. 숨기기 명령(`hide_main_ui` — `commands/tray.rs:16`)도 메인만 숨긴다.
- 메인 X 는 `prevent_close` + 메인 **하나만** 숨긴다(ADR-0026 「X = hide」) — 공용 숨기기 함수를 거치지 않고 창을 직접 숨긴다(`lib.rs:180-184`).
- ★트레이 메뉴엔 「UI 보이기·숨기기」 항목이 **없다**★ — 좌클릭이 대신한다(`src-tauri/src/tray/core.rs:7-8`, `tray/mod.rs:66`). 이를 메뉴 항목처럼 적은 옛 주석(`commands/tray.rs:8,14` · `tray/actions.rs:63`)과 ADR-0026 본문(:14)은 낡았다.
- 팝아웃 창은 독립 최상위 창이라 작업표시줄 항목을 따로 갖고, 메인을 트레이로 보내도 화면에 남는다. 따로 최소화한 팝아웃은 작업표시줄에서 하나씩 되살려야 한다.

## 결정
1. **최소화는 창마다 각자다** — 창 사이 최소화 연동을 두지 않는다(지금과 같다).
2. **메인 X(트레이로 숨김)는 모든 UI 창을 숨긴다.** 숨기기 명령(`hide_main_ui`)도 같은 동작이다. 팝아웃 창의 X 는 지금처럼 그 창을 닫는다.
3. **트레이 아이콘은 언제 누르든 모든 UI 창을 화면으로 되살린다** — 숨은 창은 보이고, 최소화된 창은 펼치고, **다른 앱 창 뒤에 있던 팝아웃도 앞으로 올린다**. 포커스는 메인이 받아 맨 위에 오고 팝아웃은 그 바로 아래다. (「앞으로 올린다」는 사용자 원문 「전부다 화면에 나오도록」을 구현하며 메인이 해석해 보고한 것 — 처음 구현은 이미 보이는 팝아웃을 올리지 않았다.) 같은 복원 함수를 쓰는 입구(단일 인스턴스 재실행·보이기 명령)도 같은 동작이다. **따로 최소화해 둔 팝아웃도 펼친다** — 사용자 확인(2026-09-24): 메인이 「언제 누르든 모든 창을 펼친다(따로 최소화해 둔 팝아웃 포함), 포커스는 메인」으로 읽어 되물었고 사용자가 「ㅇㅇ 그렇게 진행하자」로 답했다. 사용자 원문 = 「오른쪽하단 아이콘을 더블클릭하면 전부다 화면에 나오도록」. **클릭 방식은 바꾸지 않는다** — 트레이는 좌클릭 한 번에 반응한다(`tray/mod.rs:111-120`). 더블클릭하면 같은 복원이 두 번 불릴 뿐이다.
4. **대상 창 = 메인 + 팝아웃 창.** 숨은 정적 창 `agent-tree` 는 뺀다 — 늘 숨어 있어야 하는 창이고 ADR-0225 가 걷어낼 예정이다.

## 거부한 대안
- **A. 팝아웃을 메인의 소유 창으로(Win32 owner — Tauri `parent`)** — 메인 최소화·복원을 OS 가 묶어 주지만, 팝아웃이 포커스와 무관하게 늘 메인 위에 뜬다. 사용자: 「비주얼 스튜디오도 포커싱된게 앞으로 오는데 저방식으로하면 포커싱 상관없이 … 오히려 이상한데?」 (Visual Studio 도 떼어 낸 **문서** 창은 기본값에서 독립이다 — 소유는 도구 창 쪽이다.) 또 소유 관계**만으로는** 주인을 **숨길** 때 소유 창이 숨지 않는다(MSDN — X 를 풀려면 `ShowOwnedPopups` 를 따로 불러야 한다). 기각 근거 = 사용자 판단(포커스 무관 순서 고정) + 문서.
- **B. 독립 창 + 최소화 동기화(메인 최소화를 감지해 팝아웃도 따라 최소화)** — 사용자: 「최소화는 그냥 각각 알아서 하는거지만 x누를때가 다르면 될것같음」. 기각 근거 = 사용자 판단.
- **C. 현행 유지** — 사용자가 문제 삼은 현상(복원은 메인만 · 메인을 트레이로 보내도 팝아웃이 남음)이 그대로다.
- **D. 설정으로 고르게(Visual Studio 식)** — 사용자가 고르지 않았다(사유 미기재).
- **트레이 복원은 X 가 숨긴 창만 되살린다(따로 최소화한 팝아웃은 그대로)** — 조사의 적대 리뷰가 짚은 쪽이고 hermes-agent 선례도 「숨은 창」만 다룬다. 기각 근거 = 사용자 결정(위 결정 3 의 확인 문답) — 사용자가 처음 문제 삼은 「최소화한 팝아웃을 작업표시줄에서 하나씩 되살려야 한다」도 트레이 한 번으로 풀린다.
- **메인 X 가 팝아웃을 숨기지 않고 닫는다(파괴)** — 검토하지 않았다(사용자 안은 처음부터 숨김이었다).

## 근거
- 조사 `docs/research/multi-window-minimize-survey-2026-09-24.md` — 트레이로 닫을 때 팝아웃을 남기는 앱이 확인된 둘(OBS·Telegram)이지만, OBS 에선 사용자가 「프로젝터 창도 OBS 와 같이 트레이로」를 요청하고 있다(답 없음). 트레이 클릭이 숨은 창 전부를 되살리는 선례가 하나 있다(hermes-agent). 「그렇게 했더니 문제가 났다」는 근거는 찾지 못했다.
- ADR-0026 의 「X = 트레이로 숨김」은 앱을 트레이로 보낸다는 뜻인데 팝아웃이 화면·작업표시줄에 남아 그 뜻과 어긋나 있었다 — 이 결정이 그 어긋남을 없앤다.

## 영향 / 불변식
- **보이기·숨기기 경로를 하나로 맞춘다** — 트레이 좌클릭·명령 둘·재실행·메인 X·부팅 `--hidden` 이 모두 같은 두 함수(`src-tauri/src/tray/actions.rs`)를 타게 한다. 오늘은 메인 X 만 창을 직접 숨기므로 **공용 숨기기 함수로 다시 잇는다.** 입구마다 따로 창을 다루게 만들면 입구별로 동작이 갈린다.
- **부팅 `--hidden` 도 공용 숨기기 함수를 탄다** — 부팅 때는 팝아웃이 없어(레이아웃은 디스크 영속이 없다 — `lib.rs:78-80`) 결과는 메인만 숨기는 것과 같다.
- **명령 이름은 그대로 둔다** — `show_main_ui`·`hide_main_ui` 는 이제 모든 UI 창을 다루지만 이름을 바꾸면 명령 표면이 바뀐다. 동작은 문서 주석이 적는다.
- **보이기 순서** — 팝아웃을 먼저 보이고 메인을 마지막에 `show → unminimize → set_focus` 한다. 메인 쪽 순서는 Windows 포커스 강탈 회피 때문에 load-bearing 이다(ADR-0026).
- **LLM 경로** — 기존 보이기·숨기기 명령이 그대로 새 동작을 탄다. 새 표면은 없다(「LLM-우선 제어」).
- **`agent-tree` 제외** — ADR-0225 가 그 창을 걷으면 이 조건은 할 일이 없어진다.
- **알려진 동작(결함 아님)** — UI 가 트레이에 숨어 있는 동안 새 팝아웃이 생기면(예: LLM 의 `slot.popout`) 그 창만 화면에 뜨고 나머지는 숨은 채로 있다. 새 창 생성은 이 결정의 숨김 상태를 모른다.
