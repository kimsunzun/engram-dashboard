# ADR-0229: Closing the main window hides all windows to the tray, and the tray icon revives all windows

- 상태: 확정 (2026-09-24, basis: user decision + `/research` medium (minimize linkage) · light (tray close) investigations)
- 관련: Amends ADR-0026 (only the range of target windows handled by X and show/hide) · ADR-0057 (popout window) · ADR-0225 (removing the hidden `agent-tree` window — excluded from the targets) · research `docs/research/multi-window-minimize-survey-2026-09-24.md` · `src-tauri/src/tray/actions.rs` (show/hide) · `src-tauri/src/lib.rs` (window events)

> ★**The statement in 「영향 / 불변식」, 「부팅 때는 팝아웃이 없어(레이아웃은 디스크 영속이 없다) 결과는 메인만 숨기는 것과 같다」, is no longer true**★ (note 2026-10-04, decision unchanged). Since storage management P3b3 (`f9db35a`), a boot after a normal exit restores even popout windows (`shell\state\state.json` — TRD `docs/process/S21-storage/trd.md` §6). The restored popouts are opened inside the user setup, and the `--hidden` hiding goes through the same shared hide function (`hide_main_ui`) at the end of that setup, so **restored popouts are hidden together, and are shown together when shown from the tray** (user decision F13 — no `--hidden`-specific logic · TRD §6-5 ⑨). This decision's invariant 「보이기 · 숨기기 경로는 하나」 produces that result as is.

> **Popouts redrawn by runtime restore (accepting the crash copy) also follow main's visibility — through the same tray path** (note 2026-10-05, decision unchanged). Since storage management P3c1 (`064b61c`), when 「복원」 is answered after an abnormal exit, popout windows are created hidden and shown only if main is visible — if main is hidden (tray hide · the LLM's answer after a `--hidden` boot), they are left hidden and the tray 「보이기」 (`show_main_ui`) reveals them together (TRD `docs/process/S21-storage/trd.md` §6-7 ④ · session judgment (delegated by the user) 2026-10-04 · user confirmation 2026-10-05). That show/hide is the window port's `set_shown` (`src-tauri/src/state/placement.rs`) calling the same turn-taking function as the tray, `for_each_ui_window` (`src-tauri/src/tray/actions.rs` — down to the usage attention-notification turn), for that one window, so it is **not a second path for show/hide**. Therefore the 「알려진 동작」 below (while hidden, a new popout is the only window that appears on screen) does not apply to a restored popout.

## 맥락
User raised (2026-09-24): 「최소화했다가 아이콘을 누르면 복원되는데, 창을 여러 개로 분리했을 때는 메인 창만 적용된다.」

Code facts (confirmed by reading):
- The tray icon left click (`src-tauri/src/tray/mod.rs:111-120`) · re-launching the single instance (`src-tauri/src/lib.rs:36-37`) · the show command (`show_main_ui` — `src-tauri/src/commands/tray.rs:10`) all call the same function (`show_main_ui`), and that function does `show → unminimize → set_focus` on **the main window only**. The hide command (`hide_main_ui` — `commands/tray.rs:16`) also hides only main.
- Main's X does `prevent_close` + hides **only** main (ADR-0026 「X = hide」) — it hides the window directly without going through the shared hide function (`lib.rs:180-184`).
- ★The tray menu has **no** 「UI 보이기·숨기기」 item★ — the left click stands in for it (`src-tauri/src/tray/core.rs:7-8`, `tray/mod.rs:66`). The old comments that write it like a menu item (`commands/tray.rs:8,14` · `tray/actions.rs:63`) and the body of ADR-0026 (:14) are stale.
- A popout window is an independent top-level window, so it has its own taskbar entry and stays on screen even when main is sent to the tray. A popout minimized separately has to be revived one by one from the taskbar.

## 결정
1. **Minimizing is per window** — no minimize linkage between windows is added (same as now).
2. **Main's X (hide to the tray) hides all UI windows.** The hide command (`hide_main_ui`) behaves the same way. A popout window's X closes that window, as now.
3. **The tray icon revives all UI windows to the screen whenever it is clicked** — hidden windows are shown, minimized windows are expanded, and **popouts that were behind other apps' windows are also raised to the front**. Main receives focus and is on top, and the popouts are right below it. (「앞으로 올린다」 (raise to the front) is main's interpretation, reported when implementing the user's original words 「전부다 화면에 나오도록」 — the first implementation did not raise popouts that were already visible.) The entrances that use the same revive function (re-launching the single instance · the show command) behave the same way. **Popouts minimized separately are also expanded** — user confirmation (2026-09-24): main read it as 「언제 누르든 모든 창을 펼친다(따로 최소화해 둔 팝아웃 포함), 포커스는 메인」 and asked back, and the user answered 「ㅇㅇ 그렇게 진행하자」. The user's original words = 「오른쪽하단 아이콘을 더블클릭하면 전부다 화면에 나오도록」. **The click method is not changed** — the tray reacts to a single left click (`tray/mod.rs:111-120`). A double click just calls the same revive twice.
4. **Target windows = main + popout windows.** The hidden static window `agent-tree` is excluded — it is a window that must always stay hidden, and ADR-0225 will remove it.

## 거부한 대안
- **A. Make the popout a window owned by main (Win32 owner — Tauri `parent`)** — the OS ties main's minimize and restore together, but the popout always floats above main regardless of focus. User: 「비주얼 스튜디오도 포커싱된게 앞으로 오는데 저방식으로하면 포커싱 상관없이 … 오히려 이상한데?」 (In Visual Studio too, a detached **document** window is independent by default — ownership is on the tool-window side.) Also, ownership **alone** does not hide the owned windows when the owner is **hidden** (MSDN — to release the X, `ShowOwnedPopups` has to be called separately). Rejection basis = user judgment (fixed order regardless of focus) + documentation.
- **B. Independent windows + minimize synchronization (detect main's minimize and minimize the popouts along with it)** — user: 「최소화는 그냥 각각 알아서 하는거지만 x누를때가 다르면 될것같음」. Rejection basis = user judgment.
- **C. Keep the current behavior** — the phenomenon the user complained about (restore is main only · popouts remain when main is sent to the tray) stays as is.
- **D. Let a setting choose (Visual Studio style)** — the user did not choose it (reason not recorded).
- **Tray restore revives only the windows that X hid (popouts minimized separately stay as they are)** — this is the side the investigation's adversarial review pointed out, and the hermes-agent precedent also handles only 「숨은 창」 (hidden windows). Rejection basis = user decision (the confirmation exchange in decision 3 above) — what the user first complained about, 「최소화한 팝아웃을 작업표시줄에서 하나씩 되살려야 한다」 (a minimized popout has to be revived one by one from the taskbar), is also solved by a single tray click.
- **Main's X closes the popouts (destroys them) instead of hiding them** — not examined (the user's proposal was hiding from the start).

## 근거
- Research `docs/research/multi-window-minimize-survey-2026-09-24.md` — two apps confirmed that leave popouts behind when closing to the tray (OBS · Telegram), but in OBS the user is requesting 「프로젝터 창도 OBS 와 같이 트레이로」 (no answer). There is one precedent where a tray click revives all hidden windows (hermes-agent). No evidence of the kind 「그렇게 했더니 문제가 났다」 was found.
- ADR-0026's 「X = 트레이로 숨김」 means sending the app to the tray, but popouts stayed on screen and in the taskbar, which conflicted with that meaning — this decision removes that conflict.

## 영향 / 불변식
- **Make show/hide a single path** — the tray left click · the two commands · re-launch · main's X · the boot `--hidden` all go through the same two functions (`src-tauri/src/tray/actions.rs`). Today only main's X hides the window directly, so it is **reconnected to the shared hide function.** If each entrance is made to handle windows on its own, behavior diverges per entrance.
- **The boot `--hidden` also goes through the shared hide function** — at boot there are no popouts (the layout has no disk persistence — `lib.rs:78-80`), so the result is the same as hiding only main.
- **Command names are left as they are** — `show_main_ui` and `hide_main_ui` now handle all UI windows, but renaming them would change the command surface. The behavior is written in the doc comment.
- **Show order** — show the popouts first and do `show → unminimize → set_focus` on main last. The order on the main side is load-bearing because of avoiding the Windows focus-stealing rule (ADR-0026).
- **LLM path** — the existing show/hide commands take the new behavior as they are. There is no new surface (「LLM-우선 제어」).
- **`agent-tree` exclusion** — once ADR-0225 removes that window, this condition has nothing to do.
- **Known behavior (not a defect)** — if a new popout is created while the UI is hidden in the tray (for example the LLM's `slot.popout`), only that window appears on screen and the rest stay hidden. Creating a new window does not know the hidden state from this decision.
