# ADR-0136: Drop the app prefix from the release data folder name

- 상태: 확정 (2026-08-14, user's point — the prefix repeats its own parent) · 부분 폐기 by ADR-0264 (decision 3 gains the run-folder rule and the agents.json copy pattern · decision 2 reversed — the development root name is `.engram-dev` (the old `.engram-data` is not moved))
- 관련: Amends ADR-0134 (release data folder name) · ADR-0100(release packaging portable folder) · `crates/engram-dashboard-discovery/src/lib.rs`(`RELEASE_DATA_DIR`) · Amended by ADR-0264 (decision 3 gains the run-folder rule and the agents.json copy pattern · decision 2 reversed — the development root name is `.engram-dev`(the old `.engram-data` is not moved))

## 맥락

ADR-0134 decision 1 set the release data folder to `<실행 폴더>/engram-data/`. The name was **taken over unchanged from the debug-side name (`.engram-data`)** without separate deliberation, and the decision record has no discussion of the name.

The user pointed out that the folder lives permanently **inside** a distribution folder the user has already named, and never leaves it. Yet it re-describes its own parent by its own name. In addition, **its sibling `prompts/` in the same folder has no prefix.** Prefixing only one is a habit, not a rule, and to make it a rule the prefix would have to go on all the others.

## 결정

1. **Release data folder = `<실행 폴더>/data/`.** The app prefix is dropped.
2. **The debug-side `.engram-data` stays as it is.** The repository root holds many other folders, so the prefix really does distinguish, and the leading dot does the hiding. **The asymmetry between the two names is intended** — do not try to make them symmetric.
3. **`.gitignore` blocks by the names of the files that hold secrets, not by the folder name** — `**/data/daemon.json` · `**/data/agents.json`.

## 거부한 대안

- **Keep `engram-data/`** — it repeats the parent and is out of line with its sibling. Grounds for rejection = logic + user judgment.
- **A `data/` rule in `.gitignore`** — it is a rule that looks only at the name, so it **swallows every unrelated `data` folder in the repository.** Confirmed by measurement: `src/data/agents.ts` · `src/data/config.json` · `packages/data/index.ts` would all become ignored. Grounds for rejection = measured (`git check-ignore`).
- **Drop the `.gitignore` rule altogether (the existing `target/` and `release/` cover it, so it is unnecessary)** — disproved by measurement. The two assembly output locations are already covered, but **two paths are not covered**: a distribution zip unpacked at an arbitrary location inside the repository, and `build-release.ps1 -OutDir` pointed elsewhere (`launch/빌드.bat` already uses that flag). Grounds for rejection = measured (`git check-ignore`, checked path by path).
- **A rule pinned by path (`/release/data/` and the like)** — the real assembly outputs are only `release/` and `launch/release/`, and they are **already ignored wholesale**, so this is pure duplication. Grounds for rejection = measured.
- **Also ignore `presets.json`** — it holds no credentials, and a `presets.json` under `data/` is the most plausible false-positive candidate going forward. Grounds for rejection = logic (what must be blocked is secrets, not data in general).

## 근거

- User's point (2026-08-14): "engram 폴더 내에 데이터 폴더가 고정인데 접두어가 의미 있나. 붙인다는 건 다른 모든 것에도 붙여야 한다는 거잖아." (gloss: the data folder inside the engram folder is fixed, so does the prefix mean anything? attaching it means attaching it to everything else too.)
- **Now is the cheapest time** — no release has shipped under this name, so there is zero data to migrate (same grounds as ADR-0134 decision 5).
- The objection main first raised (`.gitignore` leans on the name) **was overstated** — that file only takes effect inside this repository, and the assembly outputs are already ignored. If an end user unpacks into their own repository, our rule is irrelevant to begin with. But, as the rejected alternatives above say, **dropping the rule altogether was also disproved by measurement**, so option 3 was chosen: block by file, not by name.

## 영향 / 불변식

- **Only the folder name in ADR-0134 decision 1 changes.** The location (under the run folder) · grouping under a subfolder (decision 2) · no migration (decision 5) · debug unchanged (decision 6) all stay alive.
- **The `.gitignore` sentence in ADR-0134 §영향 is stale** — "the `engram-data/` rule in `.gitignore` covers it as well" is now a rule that blocks two files by name.
- **The `RELEASE_DATA_DIR` constant carries a "do not revive" comment** — it stops attempts to put the prefix back or to make it symmetric with the debug name. The code is this decision's discovery surface.
- **The secret file names are now the key to the ignore rule** — if the `daemon.json` or `agents.json` file name changes, `.gitignore` must be changed with it. Coupling has increased over the earlier state (a single folder-name line), and in exchange the false positives are gone.
