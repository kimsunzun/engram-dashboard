# ADR-0281: When the daemon refuses the shell's command registration, the shell shows an OS error box — the split is the origin type at the reply boundary

- 상태: 확정 (2026-10-07, basis: landing = 2-1 U3 (`/review code full` 4 rounds — codex + Claude final PASS · `/qa full` PASS (including GUI measurement)) + user decision 2026-10-02 (show a box · no LLM notice — ADR-0270 decision 4) · 2026-10-07 (「강하게 경고 표시」 → error kind) + the other details are main's decisions under the user's delegation (2026-10-06 「알아서 해 … 단계 착수」) + `/review trd full` round 3 PASS (TRD 2-1 §2-4 D4)) · 부분 폐기 by ADR-0292 (the abort description of the dialog panic)
- 관련: ADR-0270 decision 4 (this ADR fills in 「구현 때 고른다」 — not an amendment) · ADR-0279 (the policy wall of the same 2-1) · ADR-0006 (call outside the lock) · ADR-0012 (seam · standalone harness) · `src-tauri/src/daemon_client/protocol_state.rs`(`CommandFailure` · `classify_reply`) · `src-tauri/src/daemon_client/connection.rs`(filling the waiting slot · registration outcome task) · `src-tauri/src/daemon_client/mod.rs`(`send_command_with_origin`) · `src-tauri/src/daemon_client/refusal.rs` · `src-tauri/src/commands/view_bus.rs` · `docs/process/S21-crate-boundaries/trd-2-1-shell-agent-cut.md` §2-4 · §3-4 · §5-2 · step-log S21 · Amended by ADR-0292 (the abort description of the dialog panic)

## 맥락

Every time the shell attaches to the daemon, it registers its own commands (window · tab · slot) and the webview commands **in one packet**, and when the webview commands change it sends a delta. The daemon refuses **the whole packet** with `CONFLICT` if a name overlaps its own, or with `INVALID_ARGUMENT` if a name or description length or a count limit is exceeded — when registration is refused, that shell has zero commands until the next reconnect, so the LLM cannot touch windows, tabs or slots. Today that refusal is left only as one warn log line.

Because 2-1 (ADR-0270) removed the agent crate from the shell, it also removed the shell's filtering of reserved names (the daemon name list lived in the agent), so the wall against name collisions is the daemon's registration refusal alone. ADR-0270 decision 4 decided 「거절을 셸이 OS 메시지 박스로 띄운다 · LLM 통지는 두지 않는다 · 방법은 구현 때 고른다」. This ADR is that method.

What had to be solved: the shell's waiting slot (`CommandReply` = `oneshot::Sender<Result<AgentEvent, String>>`) **folded the daemon's `Error` reply and shell-local failures (not connected · disconnected · lost reply, etc.) into the same `Err(String)`.** A disconnect is common at every daemon restart and every wake from sleep, so if the two cannot be told apart, the box pops up at every ordinary reconnect.

## 결정

1. **Trigger = every case where the daemon answered a registration or delta with `Error`** — regardless of the code (`CONFLICT` · `INVALID_ARGUMENT` · ★an unknown · new code★). That reply means 「적용되지 않았다」 and the outcome is the same. **Only shell-local failures are excluded.**
2. ★**The split is the origin type left at the reply boundary — the string is not read.**★ The daemon's paired reply is put into the waiting slot as is, without folding, at the one place that fills it (`connection.rs`) (`Error` also goes in as `Ok(AgentEvent::Error{..})`) — so only shell-local failures remain in the slot's `Err`. `classify_reply` splits the slot result into `CommandFailure { Daemon { message }, Local(String) }`, and the sibling `send_command_with_origin` returns that type. The existing `send_command` folds it with `to_string`, so **the text that existing callers receive is byte-for-byte the same**.
3. **Two sites** — the registration outcome task (`RefusalSite::Register`) · the webview delta (`RefusalSite::Update`, `view_bus.rs`). `Daemon` → warn + box · `Local` → warn only. The warn labels are left as they are now, but **only the `Daemon` arm at the delta site gets its own label** — the old label 「다음 재연결의 전량 등록이 해소한다」 stays on the local-failure side (there the reconnect sends the list again, and if it is still refused the registration site reports it with a warn and a box — the label is optimistic but it is not silently buried). If the daemon refused, the shell is still holding the refused name, so the next full registration may be refused as well (code review 2026-10-07). The label at the registration site (the pre-existing defect where even a disconnect is printed as 「거절」 — TRD §8 O4) stays as it is.
4. **The box = the Rust API of tauri-plugin-dialog · kind `MessageDialogKind::Error` · `show` (non-blocking)** — `blocking_show` is not used. No capability is added (the Rust API does not go through IPC). No OS `cfg` enters the shell (the OS differences are inside the plugin). The text puts the result (the LLM cannot use that command) and the remedy (fix the command declaration that caused it, then rebuild) first, and carries the daemon's original text — no per-code texts. The delta box also states 「원인을 고치지 않은 채 재연결하면 이 셸의 명령 등록 전체가 거절될 수 있다」 — the shell is still holding the refused name, so if the declaration is unchanged, that name is carried again in the next full registration. The reason for 「될 수 있다」 = the declaration may change before the reconnect, and a refusal that arises only in a delta (another owner's name · a list overlap) does not arise again in a full registration (code review 2026-10-07, both reviewers).
5. **A new narrow port `RefusalNotice`** — a sibling port that does not widen `DaemonEvents`. Production adapter `TauriRefusalBox` · test doubles (`RecordingRefusals` · `NoRefusalNotice`).
6. **Repeat suppression — key = (site, daemon text) · lifetime = the shell process.** The decision is inside the lock, the port call after the lock is released (ADR-0006). The warn is printed every time. ★**The delta site shows the box after releasing the bridge's ordering door (`outbound` — a tokio `Mutex`)**★ — the delta send (`push_delta`) runs inside that door, so it gets the daemon text back (`Option<String>`) and calls the box after `report_and_push` has returned. Do not move the box back inside that closure.
7. **The LLM is not told** (ADR-0270 decision 4 as is — the cause stays in the log).

## 거부한 대안

- **Split by string code (read the `CONFLICT:` · `INVALID_ARGUMENT:` prefix).** Rejected = code — adding a code is a permitted extension (the `ErrorCode` doc in `crates/engram-dashboard-command/src/error.rs` 「코드 추가는 additive」). If an unknown code arrives, the box silently dies. TRD review C1 removed it.
- **Narrow the trigger to `CONFLICT`.** Rejected = code — an `INVALID_ARGUMENT` refusal (name 128 B · description 4096 B · 512 per owner · 4096 in total — `roster.rs`) has the same outcome (zero registered · the delta not applied). TRD §8 O3.
- **Change the slot's `Err` to a new type (`LocalFailure`) so that the compiler enforces 「슬롯 `Err` = 로컬뿐」.** Rejected = code (the range it spreads to) — it spreads to seven local send sites · `register_pending` · two test files (`daemon_client/tests.rs` · `tests/daemon_client_pending.rs`). The minimal change was chosen, and its cost is guarded by placement (the first item of 「영향」 below · the real-socket test catches it).
- **Widen `DaemonEvents` to carry the box.** Rejected = code — the doc of that port (`daemon_client/events.rs`) forbids widening (a port that cuts off only emit).
- **`blocking_show`.** Rejected = code — the plugin source writes 「main thread 에서 쓰지 말 것」 (tauri-plugin-dialog 2.7.1 `lib.rs:351-358`), and the connection task stalls.
- **Suppress once per connection.** Rejected = code — a refusal is deterministic for the same build · same name (at every reconnect the same packet is refused with the same text), so 「연결마다」 cannot stop the very repetition where windows pile up when reconnects are frequent. The daemon text carries the cause (overlapping name · oversized size · limit value), so a different incident is a different key and shows anew.
- **The warning (`Warning`) kind.** Rejected = user decision 2026-10-07 (「개발 단계에서만 일어나는 일이라 강하게 경고 표시」).

## 근거

- **Source of the decision** — show a box · no LLM notice = the user (2026-10-02, ADR-0270 decision 4 — 「빵 하고 뜨면서 클라에서 뜨면 유저도 알지」). The error kind = the user (2026-10-07). The rest (trigger range · origin type · port · suppression key) are main's decisions under the user's delegation and went through `/review trd full` round 3 PASS.
- **Plugin measurement (source reading)** — the locked version tauri-plugin-dialog 2.7.1. `show` brings up the window with `run_on_main_thread` and the waiting is carried by a separately spawned thread (`desktop.rs:215-245`). `dialog:allow-message` is the permission of the JS IPC command `message`, so the Rust API does not need it (`permissions/autogenerated/commands/message.toml`).
- **Verification status (2026-10-07 · 2-1 U3)** — tests: origin classification (including an unknown code · text without a prefix) · suppression (site · text · re-entry outside the lock) · real-socket round trip, four branches at the registration site (`CONFLICT` · `INVALID_ARGUMENT` · unknown code → once · disconnect before the reply → zero) · byte comparison of the `send_command` text and the `Daemon` assertion of `send_command_with_origin`. If each of these is deliberately introduced — folding `Error` into `Err` at the slot · a box on the local arm · turning suppression off · a misclassification in the sibling — the test goes red (mutation check). Workspace regression = result line 61 · 3997 passed · zero failed · 31 ignored. GUI measurement (release build · caused on purpose by changing the webview report through CDP — TRD §5-2): delta `CONFLICT` · registration `CONFLICT` · the same registration repeated = 「눌러 둠」 without a box · `INVALID_ARGUMENT` (name 206 B) delta · registration · local failure = warn only · recovery — all as expected. The box = title 「Engram — 명령 등록 거절」 · red X (error kind) · the body was read with UI Automation.
- ★**Confirmed limit — if the app is not the foreground window, the box does not come to the front**★ (GUI measurement 2026-10-07): in both the state hidden to the tray and the state where the window is visible but not foreground, the box window is created but cannot take focus and was hidden behind other apps' windows. Presumed to be the Windows foreground lock — **likely** (the desktop z-order kept changing during the measurement, so it is not certain). When the app was the foreground window, the box took focus. ★**User decision 2026-10-07 — leave it as is**★ (it happens rarely, and only in the development stage). The proposals raised alongside = adding a taskbar icon flash · pulling the main window to the front (may be blocked by the same foreground lock, so the effect is uncertain) — neither was chosen.

## 영향 / 불변식

- ★**There is one place that puts the daemon reply into the waiting slot, and it puts `Error` in as `Ok` too — do not fold `Error` into `Err`.**★ If it is folded, a daemon refusal is classified as `Local` and the box silently dies (it still compiles). The real-socket round-trip test (registration site — `CONFLICT` · `INVALID_ARGUMENT` · unknown code · disconnect before the reply) catches this regression.
- **The text of existing `send_command` callers is byte-for-byte the same** — `Display` of `CommandFailure` = the original text. The test measures it by byte comparison.
- **Order dependence** — if a change that reverses the slot filling lands before the classification in `send_command`, a daemon refusal goes to the caller as `Ok(Error)` and `expect_ack`-style callers pass it as success (TRD §3-4).
- **Do not remove the dialog plugin** — `dialog()` panics when there is no plugin state, and release has `panic = "abort"`. If the plugin is removed together with the folder-picking feature, the refusal box becomes an app exit (the registration comment in `src-tauri/src/lib.rs`).
- **The box decision is also counted in the info log** (shown · 눌러 둠 + site) — the GUI measurement counts that log.
- **The cost of suppression** — from the second occurrence of the same incident on, only a warn is left. Since the key is recorded before the box, if the plugin fails to bring up the window (the failure is swallowed), that key will not show again in this process.
- **Code anchor = `// ADR-0281`** — the slot filling · `classify_reply` · `send_command_with_origin` · `refusal.rs`.
- **Out of scope** — retry after a registration refusal · LLM notice · the shell filtering the causing name in advance (ADR-0270 removed it).
