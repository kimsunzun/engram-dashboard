# ADR-0339: 덮어쓰기 = 삭제 + 이름 바꾸기 (참조는 자리를 따름 · 한 목록 안 같은 경로는 처음 자리만) · 삭제는 참조 처리를 고른다 (사람 = 모달 · LLM = 인자, 기본 남기기)

## 맥락
S25 4단계 P3 코드 리뷰가 경로 바꿔 쓰기 뒤 한 에이전트 목록 안 같은 경로 중복(`[b, b]`)을 짚었다 — engram 안 [덮어쓰기] 이동(옛 파일 → `.trash` · ADR-0335 결정 4)과 다시 연결(ADR-0330)이 만든다. 덮어써진 옛 파일에만 붙어 있던 에이전트가 새 내용을 조용히 받는 문제도 함께 논의했다. 사용자 질문 「우리 데이터를 파일에 못 넣으면서 링크되는 성숙한 시스템 없음?」 → 조사 `docs/research/external-file-reference-tracking-2026-11-01.md`. 삭제 쪽은 사용자가 참조를 날리는 길도 원해 ADR-0335 결정 5 를 대체하고(거부한 대안 F), 참조 고침이 있는 조작 목록(ADR-0335 결정 1)과 프로필 편집 포트가 받는 것(결정 6)을 넓힌다.

## 결정
1. **덮어쓰며 이동 = 옛 파일 삭제(`.trash`) + 이름 바꾸기.** 참조는 고르지 않고 자리를 따라 그 자리에 들어온 새 파일을 가리킨다 — 대체다(사용자 「대체하는거라서 링크는 무조건 달아야되는거잖아」 — G58). 덮어써진 옛 파일에만 붙어 있던 에이전트도 새 내용을 받는다. 덮어쓰기에는 참조 선택지를 두지 않는다. 종류가 다른 파일로 덮어써도 참조는 자리를 따르고, 종류가 안 맞으면 그 줄은 「틀린 종류」(TRD M78)로 보인다(메인 2026-11-01 — M107 · 받아들임).
   - **중복 정리** — 경로 바꿔 쓰기 뒤 한 목록 안 같은 경로(`same_path` — ADR-0325)는 처음 자리 하나만 남긴다. 따로 된 개념이 아니라 삭제 + 이름 바꾸기의 뒷정리다(사용자 「중복접기라는 단어의 개념은 아니라는거지. 그냥 삭제잖아」 — G58).
   - 범위(메인 2026-11-01 — M102 · M103) = **모든 경로 바꿔 쓰기**(덮어쓰기 이동 · 이동 · 이름 바꾸기 · 다시 연결 — ADR-0330)가 건드린 목록 전부 — 에이전트 붙임 · 프리셋 파일의 목록 · 그 명령을 낸 창의 저장 안 된 편집 초안 줄(ADR-0338 결정 8 의 대응표 적용 뒤). 까닭 = 프리셋 목록에 중복이 남으면 「목록 안 같은 항목 중복 = 어긋남」(TRD M78 · M85)을 어긴다 — 다음 저장이 거절된다.
2. **삭제는 참조 처리를 고른다**(ADR-0335 결정 5 「삭제는 참조를 고치지 않는다」 를 대체 — G59).
   - 사람 — 참조가 있으면 늘 확인 모달 [취소] [참조도 빼고 이동] [휴지통으로 이동](G60).
   - LLM — 참조가 있는데 `--yes` 가 없으면 지금처럼 `CONFLICT` 로 거절하고 참조를 돌려준다(PRD R48 그대로). 참조 빼기는 선택 인자 하나로 고른다(`--detach-refs` — 이름은 자리표시 · 최종 이름은 TRD 에서 `docs/reference/llm-command-conventions.md` 를 따라 정한다) · 빼면 기본 = 남기기(사용자 「기본값을 남기기 … 그 기본값이란게 LLM한테의 기본값이지? 사람은 무조건 물어봐야되니」 — G60). 그 `CONFLICT` 답은 참조와 함께 다음 두 꼴(`--yes` = 남기기 · `--yes --detach-refs` = 참조도 빼기)을 싣는다 — LLM 이 꼴을 추측하지 않게(메인 2026-11-01 — M99 · 사용자가 맡긴 기준 「llm이 명령을 쏠때 햇깔리지 않고 잘 유지하는것 기준」).
   - 인자 검문(메인 2026-11-01 — M108 · 같은 기준) — `--yes` 없이 `--detach-refs` 만 주면 `--yes` 가 없는 것과 같다(`CONFLICT` + 두 꼴). 아래 셋(삭제 · `SKILL.md` 이름 바꾸기 · `SKILL.md` 밖으로 옮기기) 밖의 조작에 `--detach-refs` 를 주면 `INVALID_ARGUMENT` 로 거절한다(말없이 무시하지 않는다 · 그 셋인지는 참조가 있는지가 아니라 조작의 꼴로 가른다).
   - **`detachRefs` 의 조작 꼴**(메인 2026-11-01 — M110 · 같은 기준) — 그 인자는 한 조작 안의 항목마다, 셋 중 하나의 꼴인 항목에만 걸린다: 항목 삭제 · 스킬 폴더의 `SKILL.md` 이름 바꾸기 · `SKILL.md` 가 그 스킬 폴더 바로 아래를 떠나는 옮기기(같은 스킬 폴더의 하위 폴더로 옮겨도 든다 — 그 폴더 바로 아래에 `SKILL.md` 가 없어지므로 · PRD R12). 꼴이 맞는 항목에서 참조는 실제로 뺄 줄이 있는지만 가른다(참조가 없으면 아무 줄도 빠지지 않고 거절도 아니다). 같은 여러 경로 조작의 다른 항목은 영향받지 않고, `INVALID_ARGUMENT` 는 그 조작에 그런 꼴의 항목이 하나도 없을 때만이다.
   - 남기기 = 지금 규칙 그대로 — 참조는 원래 경로에 남아 「찾을 수 없음」 이고 원래 자리로 되살리면 저절로 풀린다.
   - 참조도 빼기 = 그 항목을 가리키는 줄을 프리셋 · 에이전트 목록에서 뺀다 · 참조를 뺀 삭제는 되살려도 다시 붙지 않는다.
   - **뺄 경로**(메인 2026-11-01 — M105) = 그 조작이 지운 경로 전부 — 항목 자체와, 폴더면 그 안 모든 자손 · `SKILL.md` 경우(아래)면 그 스킬 폴더. 계획 때 참조된 것만 떠 둔 목록이 아니라 실행 때 센다(ADR-0335 결정 6 과 같은 까닭 — 그 사이 붙은 줄을 놓치지 않게). 같은 조작으로 `.trash` 에 간 프리셋은 줄 빼기 대상이 아니다. 에이전트는 프리셋만 붙이므로(`AgentProfile.presets` · `default_preset`) 에이전트 빼기(`remove_preset_paths`)에는 그중 프리셋 파일 경로만 넘긴다.
   - **같은 창 초안**(메인 2026-11-01 — M103) — 참조를 뺀 조작의 답은 뺀 경로를 싣고, 그 명령을 낸 창의 저장 안 된 편집 초안에서도 그 경로의 줄을 뺀다(초안의 다른 편집은 그대로 · ADR-0338 결정 8 의 대응표 적용과 같은 몫 — 뒤의 [저장] 이 뺀 줄을 되살리지 않게).
   - **도중에 끊기면**(메인 2026-11-01 — M104) — `.trash` 로 옮기기(또는 아래 이름 바꾸기 · 옮기기)가 끝난 뒤 끊기면 아직 못 뺀 줄은 남기기와 같다 — 「찾을 수 없음」 으로 남고, 원래 자리로 되돌리면 다시 붙으며, × 로 빼거나 원래 자리로 되돌린 뒤 참조 빼기로 다시 하면 된다(ADR-0335 결정 2 의 진행 기록 없음 그대로).
   - `SKILL.md` 하나만 지워도 그 스킬은 없어진다 — 그 스킬 폴더를 가리키는 참조도 같은 고르기를 따른다(참조도 빼기 = 그 폴더를 가리키는 줄을 뺀다 · 사용자 「skill.md가 없으면 스킬 자체가없어지는거잖아. 그럼 참조를 빼야되는거 아님? 그 참조는 에이전트가 스킬을 인식한다는 기준으로 해야지」 — G62). 참조가 담는 것은 폴더 경로이고 스킬이 있는지는 `SKILL.md` 로 가린다(스킬 인식 규칙 그대로 — PRD R12).
   - 참조된 스킬의 `SKILL.md` 이름 바꾸기도 그 스킬을 없애므로 같은 고르기다(사용자 「이것도 링크옵션으로 되야하지 않음? 사실 이런경우 자체가 이상하긴한데」 — G63) — 사람 = 확인 모달 [취소] [참조도 빼고 바꾸기] [이름 바꾸기](참조를 남기면 「찾을 수 없음」) · LLM · CLI = 같은 `--yes` + 선택 `--detach-refs`(자리표시) · 기본 남기기 · `CONFLICT` 답에 두 꼴. 순서 = 이름 바꾸기 먼저 → 프리셋 파일의 그 스킬 줄 빼기. 에이전트는 스킬을 붙이지 않으므로 그 프리셋을 거쳐서만 달라지고, 스킬 폴더 경로로 `remove_preset_paths` 를 부르지 않는다(맞는 붙임이 없다). 위 `SKILL.md` 지우기와 아래 옮기기도 같다.
   - 참조된 스킬의 `SKILL.md` 를 그 스킬 폴더 밖으로 옮기기(끌어 옮기기 · 잘라내 붙이기)도 그 스킬을 없애므로 같은 고르기다(메인 2026-11-01 — M106 · 위 G62 · G63 의 원칙에서) — 사람 = 확인 모달 [취소] [참조도 빼고 옮기기] [옮기기] · LLM · CLI = `library.move` 의 `--yes` + 선택 `--detach-refs` · 기본 남기기 · `CONFLICT` 답에 두 꼴. 순서 = 옮기기 먼저 → 프리셋 파일(에이전트 단계 없음 — 위와 같다). 스킬 폴더 자체의 이름 바꾸기 · 옮기기는 보통 이동이다 — 참조를 고친다(넷째 경우가 아니다).
3. **가리키는 방식(메커니즘)은 경로 그대로**(ADR-0315) — 덮어쓰기 정책은 메커니즘이 정해 주지 않는다.

## 거부한 대안
- **(C) 덮어써진 옛 파일의 붙임을 `.trash` 안 경로로 바꿔 써 앱 안 되살리기 때 따라오게** — 규칙 다섯(동시 대응 · 되살리기 이름 부딪힘 · 부분 실패 되돌리기 · 비우기 · 실행 처리)이 더 필요하고 engram 과 같은 선례를 못 찾았다(DEVONthink 가 휴지통 항목 참조를 비울 때까지 남긴다고 조사가 적었으나 데이터베이스 구조이고 메인 미대조다 — 조사). 사용자가 덮어쓰기 = 대체로 정리했다.
- **(B) 덮어써진 것의 붙임을 무조건 떼기** — 대체의 뜻과 어긋난다(사용자).
- **(D) OS 파일 신원(file ID · object ID)으로 가리키기 — 덮어쓰기 정책을 고치는 수단으로서** — 메커니즘은 덮어쓰기 정책을 정해 주지 않는다. 임시 파일에 쓰고 바꿔 넣는 저장에서 file ID 가 바뀔 수 있다(`ReplaceFile` 결과 file ID = replacement 의 것 — Microsoft Learn · 원문 대조) · 같은 함수가 object ID 는 원래 파일 것을 지킨다(원문 대조) · object ID 는 NTFS 한정이다. 바깥 이동 뒤 되찾기의 후보로는 tracking T-74 에 남는다.
- **(E) 옆 파일 ID(Unity `.meta` · Godot `.uid`) — 덮어쓰기 정책을 고치는 수단으로서** — 라이브러리 폴더에 engram 전용 파일을 더 두지 않는다(사용자 「메타파일은 하지말고」 — G61). 곁 근거 — 바깥에서 옮길 때 옆 파일을 함께 옮겨야 한다(Godot 원문 대조 — 이동만 · 조사). 이 거부로 옆 파일은 T-74(바깥 이동 뒤 되찾기)의 후보에서도 빠진다. 파일 안 id(파일 안에 engram 이 써 넣는 고정 id)도 같은 자리에서 뺀다 — 파일에 engram 데이터를 넣지 않는다(메인 2026-11-01 — M109 · 사용자 2026-11-01 질문 「우리만의 데이터를 삽입 못하면서」 의 전제에서).
- **(F) 삭제에 선택지 없이 늘 남기기**(옛 ADR-0335 결정 5) — 사용자가 날리기도 원했다(「삭제는 옵션이 있어야되지 않음? 기존 링크를 남기단지 날리던지」 — G59).

## 영향 / 불변식
- P3 의 경로 바꿔 쓰기(profile 명부 `try_rewrite_preset_paths`)에 「한 목록 안 같은 경로는 처음 자리만」 이 더해진다 · 프리셋 파일의 경로 바꿔 쓰기(파일 조작 단계) · 다시 연결 · 같은 창 초안의 줄 바꿈도 같은 규칙이다(메인 2026-11-01 — M102 · M103).
- 삭제 명령 · 이름 바꾸기 명령 · 이동 명령(참조된 스킬의 `SKILL.md` 를 스킬이 아니게 만들 때 — 파일 조작 단계)에 참조 빼기 인자(자리표시 `--detach-refs`)와 모달 단추가 더해진다 · `--yes` 없는 `CONFLICT` 답에 두 꼴이 실린다 · 참조를 뺀 조작의 답은 뺀 경로를 싣는다.
- ADR-0335 의 바뀐 자리(ADR-0335 본문은 고치지 않는다 — 이 ADR 이 개정 범위를 진다): 결정 5 를 대체한다 · 결정 1(참조 고침이 있는 조작 = 이동 · 이름 바꾸기 · 다시 연결)에 참조를 뺀 삭제 · 참조를 뺀 `SKILL.md` 이름 바꾸기 · 밖으로 옮기기가 더해진다(같은 참조 고침 길로 줄을 뺀다) · 결정 6(포트에는 옛 → 새 대응표만)에 빼기 동사 `remove_preset_paths(paths)` 가 더해진다 · 영향 「공통 뼈대(계획 → 실행 → 참조 고침)는 이동 · 이름 바꾸기 · 다시 연결만 쓴다」 에 같은 셋이 더해진다 · 거부한 대안 「파일마다 고정 정체(사이드카 `.meta` · 파일 안 id · NTFS 파일 id)를 다시 연결 후보로」 가 좁혀진다 — 사이드카와 파일 안 id 는 후보가 아니고(G61 · M109) NTFS 파일 id 는 object ID · 해시로 바뀐다(tracking T-74).
- 참조 빼기의 순서 = `.trash` 로 옮기기(또는 이름 바꾸기 · 옮기기) 먼저 → 프리셋 파일 → 에이전트(ADR-0335 결정 1 의 뼈대 그대로 · 메인 2026-11-01 — M100).
- 에이전트 쪽 참조 빼기 = 프로필 편집 포트의 명부 전체 빼기 동사(`remove_preset_paths(paths)` — 이름 자리표시 · 메인 2026-11-01 — M101). 준 경로 중 하나와 `same_path` 로 같은 붙임을 모든 에이전트에서 명부 락 한 번 아래 빼고, 바뀐 에이전트를 id 순으로 돌려준다. 에이전트 목록을 받지 않는다 — `rewrite_preset_paths` 와 같은 까닭(복제와의 경합 — ADR-0335 결정 6). 4 단계에서 포트와 함께 더한다. 부르는 곳은 참조를 뺀 삭제가 지운 프리셋 파일뿐이다 — 에이전트는 프리셋만 붙이므로 `SKILL.md` 경우(지우기 · 이름 바꾸기 · 옮기기)에는 부르지 않는다.
- 라이브러리 폴더에 옆 파일(`.meta` · `.uid` 꼴)을 두지 않고(G61) 파일 안에 engram id 를 써 넣지도 않는다(M109) — 바깥 이동 뒤 되찾기의 후보(OS 파일 신원(object ID) · 해시 등)는 tracking T-74 에 남는다 — 덮어쓰기 정책이 아니라 그 몫이다.
- 덮어쓰기 확인 대화상자에도 참조 안내를 띄울지는 파일 조작 단계에서 확인한다(미정).
