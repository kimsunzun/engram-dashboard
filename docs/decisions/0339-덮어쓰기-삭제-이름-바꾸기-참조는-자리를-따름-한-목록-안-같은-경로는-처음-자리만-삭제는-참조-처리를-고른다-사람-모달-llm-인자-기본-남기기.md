# ADR-0339: 덮어쓰기 = 삭제 + 이름 바꾸기 (참조는 자리를 따름 · 한 목록 안 같은 경로는 처음 자리만) · 삭제는 참조 처리를 고른다 (사람 = 모달 · LLM = 인자, 기본 남기기)

- 상태: 제안 (2026-11-01, 근거: 사용자 결정 2026-11-01(「대체하는거라서 링크는 무조건 달아야되는거잖아」 · 「중복접기라는 단어의 개념은 아니라는거지. 그냥 삭제잖아」 · 「삭제는 옵션이 있어야되지 않음? 기존 링크를 남기단지 날리던지」 · 「기본값을 남기기 … 그 기본값이란게 LLM한테의 기본값이지? 사람은 무조건 물어봐야되니」) · 조사 `docs/research/external-file-reference-tracking-2026-11-01.md`)
- 관련: Amends ADR-0335 (결정 5 대체) · ADR-0335 결정 4 · ADR-0315 · ADR-0325(`same_path`) · ADR-0320 · ADR-0330 · PRD R17 · R18 · TRD §1-4 흐름 ④

## 맥락
S25 4단계 P3 코드 리뷰가 경로 바꿔 쓰기 뒤 한 에이전트 목록 안 같은 경로 중복(`[b, b]`)을 짚었다 — engram 안 [덮어쓰기] 이동(옛 파일 → `.trash` · ADR-0335 결정 4)과 다시 연결(ADR-0330)이 만든다. 덮어써진 옛 파일에만 붙어 있던 에이전트가 새 내용을 조용히 받는 문제도 함께 논의했다. 사용자 질문 「우리 데이터를 파일에 못 넣으면서 링크되는 성숙한 시스템 없음?」 → 조사 `docs/research/external-file-reference-tracking-2026-11-01.md`. 삭제 쪽은 사용자가 참조를 날리는 길도 원해 ADR-0335 결정 5 를 대체한다(거부한 대안 F).

## 결정
1. **덮어쓰며 이동 = 옛 파일 삭제(`.trash`) + 이름 바꾸기.** 참조는 고르지 않고 자리를 따라 그 자리에 들어온 새 파일을 가리킨다 — 대체다(사용자 「대체하는거라서 링크는 무조건 달아야되는거잖아」). 덮어써진 옛 파일에만 붙어 있던 에이전트도 새 내용을 받는다. 경로 바꿔 쓰기 뒤 한 목록 안 같은 경로(`same_path` — ADR-0325)는 처음 자리 하나만 남긴다 — 따로 된 개념이 아니라 삭제 + 이름 바꾸기의 뒷정리다(사용자 「중복접기라는 단어의 개념은 아니라는거지. 그냥 삭제잖아」). 덮어쓰기에는 참조 선택지를 두지 않는다.
2. **삭제는 참조 처리를 고른다**(ADR-0335 결정 5 「삭제는 참조를 고치지 않는다」 를 대체).
   - 사람 — 참조가 있으면 늘 확인 모달 [취소] [참조도 빼고 이동] [휴지통으로 이동].
   - LLM — 삭제 명령의 인자로 고른다 · 빼면 기본 = 남기기(사용자 「기본값을 남기기 … 그 기본값이란게 LLM한테의 기본값이지? 사람은 무조건 물어봐야되니」).
   - 남기기 = 지금 규칙 그대로 — 참조는 원래 경로에 남아 「찾을 수 없음」 이고 원래 자리로 되살리면 저절로 풀린다.
   - 참조도 빼기 = 그 항목을 가리키는 줄을 프리셋 · 에이전트 목록에서 뺀다 · 참조를 뺀 삭제는 되살려도 다시 붙지 않는다.
3. **가리키는 방식(메커니즘)은 경로 그대로**(ADR-0315) — 덮어쓰기 정책은 메커니즘이 정해 주지 않는다.

## 거부한 대안
- **(C) 덮어써진 옛 파일의 붙임을 `.trash` 안 경로로 바꿔 써 앱 안 되살리기 때 따라오게** — 규칙 다섯(동시 대응 · 되살리기 이름 부딪힘 · 부분 실패 되돌리기 · 비우기 · 실행 처리)이 더 필요하고 engram 과 같은 선례를 못 찾았다(DEVONthink 가 휴지통 항목 참조를 비울 때까지 남기나 데이터베이스 구조다 — 조사). 사용자가 덮어쓰기 = 대체로 정리했다.
- **(B) 덮어써진 것의 붙임을 무조건 떼기** — 대체의 뜻과 어긋난다(사용자).
- **(D) OS 파일 신원(file ID · object ID)으로 가리키기** — 메커니즘은 덮어쓰기 정책을 정해 주지 않는다. 임시 파일에 쓰고 바꿔 넣는 저장에서 file ID 가 바뀐다(`ReplaceFile` 결과 file ID = replacement 의 것 — Microsoft Learn · 원문 대조) · object ID 는 NTFS 한정이다.
- **(E) 옆 파일 ID(Unity `.meta` · Godot `.uid`)** — 라이브러리에 파일이 두 배가 되고 바깥 이동 · 복사 때 고아 · 중복 ID 가 생긴다. (기각 근거: 약함) 근거: 「고아」 는 Godot 원문 대조 · Unity 는 메인 미대조(조사) · 「중복 ID」 는 조사에 출처가 없다.
- **(F) 삭제에 선택지 없이 늘 남기기**(옛 ADR-0335 결정 5) — 사용자가 날리기도 원했다(「삭제는 옵션이 있어야되지 않음? 기존 링크를 남기단지 날리던지」).

## 영향 / 불변식
- P3 의 경로 바꿔 쓰기(profile 명부 `try_rewrite_preset_paths`)에 「한 목록 안 같은 경로는 처음 자리만」 이 더해진다.
- 삭제 명령(파일 조작 단계)에 참조 빼기 인자와 모달 단추가 더해진다.
- 참조 빼기는 기존 프로필 편집 포트(`set_attachments`)와 프리셋 파일 고침으로 한다 — 포트 변경은 그 단계에서 확인한다(미검).
- 덮어쓰기 확인 대화상자에도 참조 안내를 띄울지는 파일 조작 단계에서 확인한다(미정).
