# ADR-0236: We accept control using other daemon modules — we give up its leaf property and take up the control-plane split in a later refactor

- 상태: 확정 (2026-09-27, basis: user decision 2026-09-27 + measured master `control/` edges 2026-09-27)
- 관련: Amends ADR-0130 (resumption condition 2 and the reopen trigger) · Amends ADR-0151 (positive evidence that control is a leaf) · ADR-0129(the application-layer split target shape, on hold — this decision does not bring it up either) · ADR-0154(command delivery) · ADR-0155(command bus tool) · ADR-0231(input-lease refusal text) · step-log S21

## 맥락
ADR-0130 decided not to split the daemon crate any further and set resumption condition ② as 「`control/` 에서 다른 최상위 데몬 모듈로 나가는 production 간선이 생긴다」 (a production edge appears going out of control/ to another top-level daemon module). The 「ADR-0130 재론 트리거」 in the `/qa` binding was the alert for it (not a gate but 「멈추고 사용자에게 물어라」). The ADR-0151 impact section put one more meaning on top of that — `control/` being a leaf with zero outgoing edges is the **positive evidence** that the control plane alone can be split off, and once trigger ② breaks, that evidence is gone.

On 2026-09-27 the `/qa standard` run on this branch (`v0.3.2/feat/json-midturn-queue`) reported, from the trigger, `control/agent.rs` · `control/commands.rs` → `connection_core::INPUT_LOCKED_REFUSAL` (a share meant to use the input-lease refusal text with the same characters as the WS entrance — ADR-0231). We assumed that removing that one edge would bring the leaf back and moved the constant into `control/`, but even after the move the trigger still produced a production match. On checking, `control/` **had already not been a leaf since S20 (2026-08-19~20).** This was not the first time the trigger fired either — on 2026-08-23 a todo item wrote 「재론할 시점인지 판단이 필요하다」 (a judgment is needed on whether it is time to reopen) (the source is the judgment-deferral record under 「근거」 below), and after that it stayed as a 「상시 매치」 (permanent match) in the QA side observation (step-log S21) and in the qa skill feedback. Only the judgment was never made, and the bodies of ADR-0130, ADR-0151 and the `/qa` binding stayed premised on the leaf. This ADR closes that deferred judgment.

## 결정
1. **We accept `control/` using other top-level daemon modules in production** — we do not restore the leaf property. Right now the targets are `command_delivery` and `connection_core`, and we also leave in place the refusal-text edge this branch added (the fix that moved the constant was reverted before commit).
2. **ADR-0130 resumption condition ② was observed, but we do not reopen** — we do not bring up the target shape of ADR-0129 now. Splitting off the control plane is considered at that point, when we do the refactor that splits the daemon [user] — 「그냥 놔두고 control 자체를 때는건 나중에 리팩토링할때 고려해야되는데 현재는 단계가 아님 내려놓아」. Resumption condition ③ (a production cycle) also already holds — `connection_core` → `control/` (since `7c47947` on 2026-07-21) and `control/` → `connection_core` (`sanitize_for_log` — since `9df137f`) call each other. It is the same bundle of edges, so this decision covers it too [main — the same bundle as the edges the user accepted · reported to the user].
3. **We remove reopen trigger ②** — a consequence of decision 1. If the trigger stays while control/ is not a leaf, every QA fires on the same match and the alert loses its meaning. In the same change we remove that block of the `/qa` binding and the places that counted it as the local share (the binding 「CI 미커버」 · the CLAUDE.md 「CI」 section · `docs/testing-strategy.md`).

## 거부한 대안
- **Move only the refusal-text constant into `control/`** (coder landing 2026-09-27 — `cargo check -p engram-dashboard-daemon --all-targets` · `cargo fmt --check` green · reverted before commit) [user — 「내려놓아」] — even after the move the trigger still produced a production match (code measurement): the S20 edges (3 kinds of `command_delivery` · `sanitize_for_log`) remain, so the leaf does not come back. We gain nothing and are left with only a wrong comment saying 「여기 둬야 잎이 유지된다」 (it must sit here to keep the leaf).
- **Remove the S20 edges too and restore the leaf** (a refactor that moves or inverts even the command-delivery connection and the log-cleanup function) [user — **a postponement, not a rejection**] — see the quote in decision 2 above. The `command_delivery` edge is a feature path — the route by which an agent calls a dashboard-owned command (`tab.create` etc.) through the control entrance rides on it (`9df137f`). **Reopen condition** = starting a refactor that deals with the control-plane split (to be decided together with reopen items ①–③ in the ADR-0151 impact section).

## 영향 / 불변식
- **ADR-0130 resumption condition ① stays as it is** (ADR-0151 already replaced its decision criterion). **③ was observed for this bundle and decision 2 covers it** — the condition itself is alive, so if another cycle appears it is still a subject for reopening, and there is still no one-shot command.
- **The 「`control/` 이 잎이라는 긍정 증거」 (positive evidence that control/ is a leaf) in the ADR-0151 impact section has not been true since 2026-08-19.** What holds the deferral is still the user's judgment (ADR-0151 decision 5 + decision 2 of this ADR), and 「`control/` 이 쓰는 데몬 모듈 간선을 끊는 공수」 (the effort of cutting the daemon-module edges that control/ uses) is added to reopen items ①–③.
- **How to measure the edges when reopening** = the re-check command of ADR-0130 §근거 ③. The sentence in that section, 「살아 도는 사본(`/qa` 바인딩)과 명령줄이 같아야 한다」 (the command line must match the live copy, the /qa binding), has no target left because that copy is removed. ★Because of `-U` and `[^;]*`, that command also bites doc comments spanning several lines★ (measured on this branch's tree 2026-09-27 — `control/catalog.rs:150-160` · `control/mcp_server.rs:1051-1065` are comments but matched) — when using it again, read it with the `#[cfg(test)]` split and with comment lines filtered out. Also, when retyped as is in a shell, the substitution breaks and it has come out as **0 lines, reading like a pass** (the deleted todo item under 「근거」 above) — check first that the command actually ran, before whether it matched.
- Code behavior is unchanged — two comments that gave the old reason (the `RosterBroadcast` port doc in `control/agent.rs` · the `RosterFanout` doc in `connection_core.rs`) were corrected to point to this ADR. We do not add a `// ADR-` anchor line.
