# ADR-0014: Orchestration reference candidates (to consider at design time)

- 상태: **제안** (2026-06, recording candidates — the actual adoption is decided when orchestration design starts)
- 관련: complements ADR-0013(the three daemon references) · CLAUDE.md 참조 구현 · roadmap "message system / auto-restart"
- **Deep survey (2026-07-12):** `docs/research/orchestration-survey-2026-07-12.md` — surveys these candidates layer by layer + maps them to existing engram assets + three option sets + a Codex adversarial review. When design starts (TRD), the user decides among those options → update this ADR to confirmed, or write a follow-up ADR.

## 맥락
engram will be extended with a layer for **coordinating multiple agents (supervision · restart · message passing)** on top of the terminal daemon (ADR-0013). That design is a "decide once, lives long" decision, so before building from the ground up we record proven prior examples as candidates. The engram constraints = Rust + independent-process (PTY) agents + supervision + messaging.

## Candidates (by layer)

**A. Supervision and fault-tolerance patterns (the engram core — death detection/restart)**
- **Erlang/OTP supervision tree (let it crash)** — a supervisor watches workers and restarts them on a crash, with process isolation. Isomorphic to the engram supervision model. *The number-one concept.*
- **Ractor (Rust)** — a Rust implementation of OTP-style actors + supervision. Same stack, so it can be ported. (Alternative: Actix)

**B. Durable orchestration (not losing state)**
- **Temporal** — the standard for durable execution (persistent state · retries · heartbeat).
- **Restate / Inngest** — lighter alternatives (journaled replay / event step retries).

**C. Agent orchestration frameworks (coordination logic — for borrowing patterns, Python-centered)**
- **LangGraph** — graph + checkpoints + rollback + HITL. The most adopted at present.
- **Microsoft Agent Framework** — the successor to AutoGen/AG2 (1.0 GA 2026-04). Event-driven · GroupChat.

**D. Inter-agent communication protocols**
- **A2A (Agent2Agent, Google)** — a standard message protocol between agents. Reference it when the "message system" roadmap item comes up.

## Rejected/deferred alternatives
- Ray (distributed actor parallelism) · Akka (JVM actors) · Google ADK · OpenAI Agents SDK · CrewAI — honorable mentions. Too heavy for engram's scale (local, few agents) or a stack mismatch. Revisit if needed.

## 근거
engram is *terminal/process agents + supervision*, so **A (Erlang/OTP·Ractor) is the most directly relevant**. B is state persistence, C is coordination logic (borrow patterns, not port), D is the communication standard. LangGraph and similar are Python-centered, so they are not targets for code porting.
