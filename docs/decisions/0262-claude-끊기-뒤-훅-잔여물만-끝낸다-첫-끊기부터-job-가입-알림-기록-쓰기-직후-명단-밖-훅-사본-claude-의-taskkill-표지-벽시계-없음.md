## 맥락
**The symptom, cause and adopted plan are as in ADR-0257** — when claude is interrupted during a hook, the hook child that Git Bash forked survives and holds the hook output pipe for about 300 seconds, and the dashboard ★ends only the leftovers inside our Job after the interrupt and keeps claude alive★. This ADR changes **the means of choosing what to end**.

**Why decide again.** ADR-0257's choosing compared the kernel creation time with the system time written at Esc (the clock method · TRD revision 5 · implemented through stage 1 `9fa9215` · stages 2 and 3 exist only in the backup ref `refs/backup/t40-clock-design-20260930`). The user removed that comparison — 「근데 생성된 절대시간말고 상대시간은 모름?」 (2026-09-30). The measurements after that (TRD §3-0) rebuilt the shape of the choosing.
- **MSYS parent spike (09-30)** — in 5 of 7 cases, the Windows parent of a `sleep` launched by a live, running Git Bash was an already-ended fork. 「부모가 죽었다」 alone cannot separate the leftovers.
- **Provenance spike (09-30)** — among 4322 records opened right at each Job join notification and with the facts read, 0 could not be opened and 0 were outside the Job. In 5/30 hangs + 2/4 of the background repeats, the owner was always a copy of the hook-script bash, and all ancestors up to claude had ended. The hook launcher (`…\Git\bin\bash.exe -c "bash …"`) and the Bash tool launcher were separated by command line 291 to 6 with 0 ambiguous, and at interrupt claude launched `taskkill /PID <실행기> /T /F` for every hook launcher (it did not launch one for the Bash tool launcher). In p3bg the owner had live forks under it, so ending once did not solve it.

## 결정
**One-line gist** — after a claude interrupt, end only the leftovers that, among the births recorded through Job join notifications from the first interrupt, were not in the member list right after the interrupt line was written, for which the whole known chain up to claude has ended, that are hook copies, and whose top is the hook launcher that claude taskkilled — the wall clock is not used (Decisions 1 · 3 · 4 below).

Notation — **[user]** = user decision (source text = TRD §1) · **[TRD]** = internal implementation chosen by TRD revision 14 (can be reversed · the design source of truth = TRD) · **[impl]** = internal implementation chosen by the orchestrator during implementation.

1. **Birth after the interrupt = Job join notification [user Decisions 5 · 6 · 7 · 11]** — 「Esc 뒤에 태어났나」 is not separated by time. From the first interrupt until the sweep ends, the thread listening to processes arriving by Job join notification opens each one right away, reads its facts (parent PID · creation time · executable · command line) once, and holds the handle (birth record · sequence number `seq` · limit 512). Ended notifications are not processed. The record lasts only during the episode, and notifications outside it are drained and discarded. What disappeared is not removed — it is not taking one snapshot and comparing.
   - User: 「알림이 오면 그냥 그거 핸들 보관한다음에 그것들만 이터 돌면 되겠네」 (5) · 「생성된것만 기록하고 빠지는건 처리 안하고 그냥 날리면 되는거지」 (6) · 「어쨋든 esc 할때만 수집하는게 맞아. … 그 안에서는 구현 심플한 쪽으로 하면 될듯」 (7) · 「아니 내가 원래 얘기했던게 3초동안 오는거 기록하고 삭제되는건 빼지 말라고 했는데 한번 캡쳐하고 다음번에 비교하라고 해서 그렇게 진행한건데?」 (11).
   - **The port is attached once per incarnation, at the first episode [TRD]** — create the port → start the listening thread → attach the Job only if that succeeded (the order is enforced by the OS piece's API — the one to drain it is already up). A real OS failure hardens, and that incarnation's later episodes have no sweep.
2. **Ancestors before the interrupt = the snapshot at the first Esc [TRD]** — only the one interrupt that opens a new episode (the opener) turns recording on outside the gate lock (**before** the snapshot), takes the member list once, confirms membership with the same handle for each member, and reads and holds the facts. If the list fails · exceeds 256 · has no root · the root has more than two children · or the port fails, that episode has no sweep. The line goes out through **two sections** (gate lock ① → prepare outside → ②), and if the turn closed in between, the line is not given · if there was new input · the record number · the turn changed, only the line is given without an episode. Later interrupts of the same episode are appended.
3. **Write list W [TRD]** — right after the interrupt line is written to stdin, the writer takes one snapshot of the member-number list W with no lock. **Candidates are only births whose number is not in W** — one that joined before the write and was alive at sweep time was alive when W was taken too (an ended process does not come back to life · the list is used only when complete), so it is in W. So it does not depend on when notifications accumulate. N seconds are counted from the moment of writing. A write that could not take W cannot become the first write (if a later interrupt of the same episode is written together with W, that becomes the first write).
4. **Choosing — only those that satisfy all four [user Decisions 9 · 10 · 11 + TRD]** — for the candidate C (number ∉ W · held with termination rights · not in the snapshot · alive). A **known link** = a held member of the snapshot or a birth of the same record — links are connected **only between held handles**.
   1. **Parent** — C's parent is a known link and has ended (Decision 11). If the parent is alive, it is not touched (Decision 4 as is).
   2. **Hook copy** — C and its parent have the same executable and ⓘ the command line is the same (a fork copy) or ⓘⓘ the parent is a hook shell (`-c "bash …"` · not `shell-snapshots`) (Decision 10). Exec'd programs (`sleep` · `cat` · servers · build children) are excluded.
   3. **Ancestors** — every link from the parent up to claude (the link whose parent is the root) is known and ended, and ★for every link parent creation ≤ child creation★ (Decisions 9 · 11 · the creation-order check is [TRD] — it filters out a wrong parent slipping in through number reuse and only reduces candidates). 16 steps · a cycle · reaching the root first is a broken chain.
   4. **Hook chain** — the top T (the link directly under claude) is a hook launcher, and in this record there is a birth whose parent is claude, which is `taskkill.exe`, whose command line is exactly `/PID <T> /T /F`, and whose creation is at or after T's creation (Decision 10 · taskkill ≥ T is [TRD]). If claude changes its interrupt method, everything is missed (the safe side).
   - User: 「어쨋든 부모 쭉 타고올라가서 살아있으면 제외한다는거잖아. 딱히 로직 부담도없겠네 상위부모 탐색만 하면되니」 (9) · 「어차피 5분 멈추는것보다는 훨씬 좋은거잖아 이것들이.」 (10).
5. **Sweep [TRD]** — if the episode has no turn end N = 3 seconds (monotonic time) after the write, the worker thread runs a sweep. One sweep = **at most 3 passes** · each pass copies the record → chooses → ends in ascending `seq` (the earlier-born ancestor first) → confirms what that pass ended within **one 200 ms confirmation deadline** → chooses again. What was ended shows up in the next pass as an ended link, and the copies it was keeping become candidates (the 2 passes of p3bg). The waiting at sweep time is at most 0.6 seconds.
6. **Termination confirmation [TRD — the shape of ADR-0257 as is]** — re-confirm the root and the marker outside, re-check 「표식 없음 · 같은 세대 · 쓰임 · 정리 중 · 쓰임 + N ≤ 지금」 inside the gate lock, then one `TerminateProcess` with the birth record's handle (exit code `0x7440`). If rejected (turn end · new interrupt · new input · marker), the remaining candidates and the next pass are discarded and the whole sweep stops.
7. **Retirement start [TRD]** — `AgentTransport::begin_retire(&self)` (default no-op — the pty and codex channels are unchanged). `StdioTransport` raises its own `retiring` cell, and the first line of `shutdown()` raises it too. The manager calls session → channel at the first line of `kill_agent` (before the permission revocation · `Exiting` · `session.kill`) and at `tear_down_failed_activation` (the first line after the incarnation-marker check). The backend reads it through the read-only `RetiringSignal` the channel hands out (only `is_set()`) — the manager does not know the backend's gate.
8. **Locks — two new leaves [TRD]** — the gate lock `GateCell.state` and the recorder lock `Recorder.inner`. **They are not held overlapped.**
   - While holding the gate lock, do not do logging · thread start · emit · sleep · another lock · allocation and release · member list query · pinning and closing handles · any other OS call. The only exceptions are ⓐ reading monotonic time ⓑ exactly one `TerminateProcess` call in the termination confirmation (atomic reads are allowed).
   - The recorder lock does only fields · `Vec` push · `Arc` clone · take-out (allocation allowed), and does no OS call · handle close · log · another lock. It tolerates poison.
   - The write confirmation (writer) · the listening thread · `begin_retire` are called with no lock (the first line of `kill_agent` has already released the registry lock) — no edge with existing locks. Source of truth = the end of TRD §3-3 (CLAUDE.md's 「핵심 불변식」 lock-order line carries it).
9. **No notice · replacement · off switch [user Decisions 1 · 2 · 3 — ADR-0257 as is]** — the screen looks the same as a normal interrupt and only the tracing log remains.
10. **Implementation fixes only what reproduces [user 2026-10-01]** — 「일단 재현 가능한것만 구현하자. 좀 현실적인 사항으로 단순화」 · 「현실적으로 가능한것 위주로 단순화 하자」. The theoretical paths raised by the implementation review (stages 2 and 3 codex) are not blocked by code and are left as the 「알려진 한계」 K1–K9 below. TRD §5's real-process test 13 (`#[ignore]` MSYS repeat · pipe) was also not built because of this decision.

**OS pieces [TRD]** — in `platform/windows.rs`: the member list (stage 1 as is) · `pin_member` (confirm membership with the same handle · facts once · choose termination rights) · `watch_births(start)` · `unwatch_births` · `BirthPort::next`. The neutral handle `ProcessGroup` (weak Job handle + `RetiringSignal`) wraps them · on other OSes = empty member list · no pinning · port `Unsupported`. ★Two new `windows` features = `Win32_System_IO` (completion port — the public means to receive join notifications) · `Wdk_System_Threading` (`NtQueryInformationProcess` — parent and command line by handle)★ — user confirmed (TRD §10) · no new crate · `Cargo.lock` unchanged.

**[impl] What was chosen** — 「무리가 사라졌나」 (`ProcessGroup::is_gone()` — no side effects) is checked by the listening thread every pass (there is a path where the reaper collects a naturally ended session without `shutdown()` so the marker is never raised) · if pinning with termination rights is rejected, pin again without rights as **link-only** (it cannot be a candidate but connects the chain) · the panic logs of the callee · the listening thread · the worker are error (logging convention — this ADR corrects the warn in TRD §3-8) · `windows.rs` is kept as a leaf (it holds its own facts and event types, and the conversion to neutral types is in `process_group.rs` — the 2026-09-29 user decision 「windows crate 와 io 만 · 통째로 옮길 수 있게」 is kept). ★The release profile is `panic = "abort"`, so the `catch_unwind` guard works only in debug and tests — the callee · the listening thread · the worker are written from the start to have no panic (no `unwrap` · no indexing · tolerate a poisoned lock)★.

**Revisions (two-way links are in the 관련 line):**
- **ADR-0238 Decision 2** — the return of the interrupt line function changes from `Option<Vec<u8>>` to `Option<InterruptOut { bytes, on_written }>`. `on_written` = what the writer calls **after** it writes that line (write success · after `mark_written` · with no lock) — the input queue carries it optionally per chunk (`push_with` · `pop` gives the pair) and discards it when closed. The channel still knows neither the meaning of the bytes nor the meaning of the callee.
- **ADR-0238 Decision 3** — the turn-open gate `TurnGate { open: AtomicBool }` becomes `GateCell` (gate lock `Mutex<GateState>` — open · episode · generation · opener · worker). The decoder holds it as the slot `GateSlot` (`Arc<OnceLock<Arc<GateCell>>>`) — the gate is built after the channel is opened and the decoder is made before that. The open/close rules and the rejection contract are as is, and a live `started` (new input) discards that turn's interrupt episode (opens it if it was closed). ★If the turn closes between the two sections, the line is not given — that Esc is rejected with CONFLICT★ (it only narrowed Decision 7's residual race a little and did not close it).
- **ADR-0238 Decision 5** — the cleanup record at that place becomes the episode (first · last write time · snapshot · record number · W · pass). ★The interruption classification is still done by `terminal_reason` and does not read this record★.
- **ADR-0238 「영향」 lock-order line (`:66`)** — 「새 락 간선 없음」 → two new leaves (gate · record) · not held overlapped · the write confirmation takes the member list outside the lock on the writer thread and holds only the gate lock briefly · no edge with existing locks (Decision 8 above).
- **ADR-0244 Decision 2** — takes over ADR-0257's revision: the backend **does not reject** a repeated interrupt (the blocking place is still the frontend) but **appends** it to the same episode.

## 거부한 대안
**Closed by user decision:**
- **Wall clock — comparing the kernel creation time with the system time written at Esc (the clock method · TRD revision 5 · ADR-0257 implementation gist)** — Decision 5 「근데 생성된 절대시간말고 상대시간은 모름?」 · 「알림이 오면 그냥 그거 핸들 보관한다음에 그것들만 이터 돌면 되겠네」. The clock method held reading two clock values · an anchor · jumping backward · future-creation correction and a protected set · a wrapper shape · reading the process table twice (ADR-0257 「구현 요지」). That part of stage 1 (`9fa9215`) was removed by this implementation's stage 1, and stages 2 and 3 exist only in the backup ref.
- **Taking one snapshot and comparing (TRD revisions 7–10 — compare the first Esc's list with the list at sweep time and treat new numbers as births after the interrupt)** — Decision 11 「… 한번 캡쳐하고 다음번에 비교하라고 해서 그렇게 진행한건데?」. It loses the facts of intermediate links that were born after the interrupt and ended before the sweep — the shortest intermediate link measured lived 250 ms (D of p3t3 · TRD §3-2).
- **Also receiving ended notifications and removing them from the record** — Decision 6 「구지 처리하지 않아도 되는건 처리하지 않아도됨. 종료 이벤트까지 받아서 매번 빼고 그러면 번잡하잖아」.
- **Attaching the port at spawn and listening always · collecting between Escs too** — Decision 7 「어쨋든 esc 할때만 수집하는게 맞아」.
- **Parent death alone · only when the dead parent existed since before Esc (Decision 8) · one grandparent layer** — in the MSYS parent spike, even the child of a live Git Bash was a fork whose parent had ended (5 of 7) → Decision 9 widened it to ancestors up to claude and Decision 11 replaced Decision 8 (all links known · ended).
- **Blocking the theoretical paths of the implementation review with code** — Decision 10 of 2026-10-01. Each path and its realism judgment is in the 「알려진 한계」 K1–K9.

**Closed by TRD [TRD — can be reversed]:**
- **The writing side records the candidate boundary (`next_seq`) at write confirmation (revision 12)** — notifications that piled up in the port queue first but have not been taken out mix in behind the boundary.
- **Drawing the boundary by posting a marker packet to the same port (revision 13)** — there is no documentation that 「가입하는 자리에서 쌓인다」, so it cannot be a basis for safety → replaced by the write list W.
- **Starting the listening thread after attaching the Job (through revision 13)** — if startup fails and detaching fails too, a kernel queue that nobody drains is left.
- **Setting up an episode with a stale snapshot (revision 12)** — it is not set up, and only the line is returned.
- **Recording only the PID at notification** — a PID that is not opened and held is guaranteed neither to be alive nor not to be reused (MS Learn · TRD §3-5) → open and hold right away.
- **Ending everything at once with no confirmation after ending** — in p3bg the owner had live forks, and those forks become 「끝난 부모의 사본」 only **after** the owner ends (measured · 2 passes).
- **Hook-copy check on every link** — the shell → launcher link has different executables (`usr\bin` versus `bin`) so a third shape would be needed, and rules 2 and 4 already tie the chain to the hook tree (nothing gained).
- **Separating hooks and the Bash tool by environment variables (`CLAUDE_PROJECT_DIR` · `AI_AGENT`)** — reading the PEB is needed. **Connecting by stream events** — events have no PID (TRD §3-0).
- **The manager raises the backend's gate directly** — a violation of backend extension (ADR-0004) → neutral `begin_retire` + a channel cell + a read-only marker.
- The remaining alternatives inside the TRD (a table at sweep time · Toolhelp parent · ending even if the chain is broken · `pid_alive` · re-taking at every Esc · not taking inside the gate lock · cumulative join count · comparing only the executable · an episode age cap · revision 6's clearing by several threads) are in TRD §9 and the revision history (`git log -- docs/process/S21-chat-ux/trd-t40.md`) — not moved here.

## 영향 / 불변식
- **Scope** — only the claude JSON (stream-json) path · works only on Windows. codex · terminal mode (`begin_retire` default no-op) · frontend · wire types · bus · protocol · daemon · shell · the `open_spawn` signature are unchanged. ★`base` unchanged★ — `ProcessStart` · `process_start` · `process_parent_table` that ADR-0257 stage 1 added are no longer called by T-40, but they remain as the bodies of the existing public functions (`child_pids` · `process_creation_time`), and their anchor is still `// ADR-0257`.
- **Ownership** — Job · `shutdown` · the `retiring` cell = transport. Outward only the weak handle · the read-only `RetiringSignal` · a once-attached port go out. The backend (`backend/claude/leftover.rs`) holds the snapshot and births during an episode and ends them one by one. ★Kill causality (ADR-0001) unchanged — `begin_retire` only raises one cell★ (CLAUDE.md 「핵심 불변식」 ownership · kill causality line).
- **Closed failures · sweep order** — no marker → the snapshot is `Taken` and the record is alive → the held root is alive → the passes → before each termination re-check the root and marker → confirmation. ### Known limits
**Misses (about 300 seconds as today · TRD §8 ③ ④ ⑱ ㉓):** a lost join notification · a birth at the moment of attaching the port · a short intermediate link ending before it is opened · the clock jumping backward between two creations · record overflow (512) · the parent or an ancestor is alive · the chain is not known · hook wrapping · the taskkill method changes · the command line cannot be read · pending input's `started` discards the hung turn's episode (G1b not run) · port failure · write-list failure · the ended confirmation exceeds 200 ms · fork generations beyond 3 passes · an owner born between the write and W (G1 — 6–26 µs versus 320–504 ms) · an owner that reused a number of W · a launcher between cmd and claude (all misses) · a hang from the residual race (ADR-0238 Decision 7).

**What the implementation review left — recorded without code by Decision 10:**
- **K1** The ancestor walk treats every child of the root as claude (codex stage 2 A#1) — unrealistic: the root `cmd /c` launches only claude (and conhost), and if the root has more than two children at Esc, the snapshot is `Failed(shape)`.
- **K2** If detaching the port fails at retirement, or `next` errors again while only draining and discarding, the listening thread ends (codex stage 2 A#2) — a detach failure has never been observed, and on retirement the Job ends soon.
- **K3** An Esc that arrives interleaved during opening has no write confirmation on its line → the sweep may run less than 3 seconds after that line was written (codex stage 2 B#1) — the window = two Escs must land within the opener's preparation time (ms), and ending still has to satisfy all four rules.
- **K4** The same creation tick (parent creation = child creation) passes the creation-order check — the check is 「부모 ≤ 자식」 (the same side as 「같은 눈금 포함」 in ADR-0257 Decision 9). This line corrects the 「엄격히 늦게」 wording of TRD §3-7 · §8 ⑰ⓑ.
- **K5** An episode with no W (list failure · an unwritten line) holds the handles of the snapshot and record until the turn end — if the turn is hung, about 300 seconds · bounded to one episode per incarnation.
- **K6** If the listening thread that only drained and discarded ends, or the retirement detach fails, the port is closed while still attached to the Job (debug log).
- **K7** Two guards lean on the release `panic = "abort"` — the `OnceLock` of port acquisition · the guard after the worker receives the end (Exit).
- **K8** The episode-open log undercounts the echoed notifications · facts are copied three times per birth · the random transition test does not exercise termination confirmation or panics.
- **K9** At every appended Esc, section ① raises the last interrupt time **before** the line is written → if an Esc that is not written repeats, the sweep may keep being pushed back (codex stage 3 FIX) — unrealistic: the chat screen ignores Esc during 「중단하는 중…」 (ADR-0244 · FE-1.4). It only delays and does not end anything wrong.
