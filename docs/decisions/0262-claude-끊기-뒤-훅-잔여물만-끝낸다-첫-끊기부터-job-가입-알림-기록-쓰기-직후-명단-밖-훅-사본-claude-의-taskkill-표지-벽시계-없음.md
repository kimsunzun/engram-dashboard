## 맥락
**증상 · 원인 · 채택안은 ADR-0257 그대로다** — claude 훅 도중 끊기에 Git Bash 가 fork 한 훅 자식이 살아남아 훅 출력 파이프를 약 300 초 쥐고, 대시보드는 ★우리 Job 안의 끊기 뒤 잔여물만 끝내고 claude 는 살린다★. 이 ADR 은 **무엇을 끝낼지 고르는 수단**을 바꾼다.

**왜 다시 정하나.** ADR-0257 의 고르기는 커널 생성 시각을 Esc 때 적은 시스템 시각과 비교했다(시계 방식 · TRD 5판 · 1단계 `9fa9215` 까지 구현 · 2·3단계는 백업 ref `refs/backup/t40-clock-design-20260930` 에만 있다). 사용자가 그 비교를 걷었다 — 「근데 생성된 절대시간말고 상대시간은 모름?」(2026-09-30). 그 뒤의 측정(TRD §3-0)이 고르기의 모양을 다시 세웠다.
- **MSYS 부모 스파이크(09-30)** — 살아 도는 Git Bash 가 띄운 `sleep` 의 Windows 부모가 7 가지 중 5 가지에서 이미 끝난 fork 였다. 「부모가 죽었다」 하나로는 잔여물을 가르지 못한다.
- **출처 스파이크(09-30)** — Job 가입 알림마다 곧바로 열어 사실을 읽은 기록 4322 개에서 못 연 것 0 · 열었는데 Job 밖 0. 멈춤 5/30 + 백그라운드 반복 중 2/4 에서 주인은 늘 훅 스크립트 bash 의 사본이었고 claude 까지 조상이 모두 끝나 있었다. 훅 실행기(`…\Git\bin\bash.exe -c "bash …"`)와 Bash 도구 실행기는 명령줄로 291 대 6 · 모호 0 으로 갈렸고, claude 는 끊기 때 훅 실행기마다 `taskkill /PID <실행기> /T /F` 를 띄웠다(Bash 도구 실행기에는 띄우지 않았다). p3bg 에서는 주인이 산 fork 를 거느려 한 번 끝내기로는 안 풀렸다.

## 결정
**한 줄 요지** — claude 끊기 뒤 잔여물은 첫 끊기부터 Job 가입 알림으로 기록한 탄생 중 줄이 쓰인 직후 멤버 명단에 없던 것으로서 claude 까지 알려진 사슬이 모두 끝났고 훅 사본이며 꼭대기가 claude 가 taskkill 한 훅 실행기인 것만 끝낸다 — 벽시계는 쓰지 않는다(아래 결정 1 · 3 · 4).

표기 — **[사용자]** = 사용자 결정(원문 = TRD §1) · **[TRD]** = TRD 14판이 고른 내부 구현(뒤집을 수 있다 · 설계 정본 = TRD) · **[구현]** = 구현 중 오케스트레이터가 고른 내부 구현.

1. **끊기 뒤 탄생 = Job 가입 알림 [사용자 결정 5 · 6 · 7 · 11]** — 「Esc 뒤에 태어났나」를 시각으로 가르지 않는다. 첫 끊기부터 판이 끝날 때까지 Job 가입 알림으로 온 프로세스를 듣는 스레드가 곧바로 열어 사실(부모 PID · 생성 시각 · 실행 파일 · 명령줄)을 한 번 읽고 핸들을 붙든다(탄생 기록 · 순번 `seq` · 상한 512). 끝남 알림은 처리하지 않는다. 기록은 에피소드 동안만이고 그 밖의 알림은 꺼내 버린다. 사라진 것을 빼지 않는다 — 한 번 찍어 비교하는 것이 아니다.
   - 사용자: 「알림이 오면 그냥 그거 핸들 보관한다음에 그것들만 이터 돌면 되겠네」(5) · 「생성된것만 기록하고 빠지는건 처리 안하고 그냥 날리면 되는거지」(6) · 「어쨋든 esc 할때만 수집하는게 맞아. … 그 안에서는 구현 심플한 쪽으로 하면 될듯」(7) · 「아니 내가 원래 얘기했던게 3초동안 오는거 기록하고 삭제되는건 빼지 말라고 했는데 한번 캡쳐하고 다음번에 비교하라고 해서 그렇게 진행한건데?」(11).
   - **포트는 화신마다 한 번, 첫 에피소드에서 붙인다 [TRD]** — 포트를 만들고 → 듣는 스레드를 띄우고 → 그것이 성공일 때만 Job 을 붙인다(순서를 OS 조각의 API 가 강제한다 — 꺼내 줄 이가 먼저 떠 있다). 진짜 OS 실패는 굳어 그 화신의 이후 에피소드는 판이 없다.
2. **끊기 전 조상 = 첫 Esc 의 스냅숏 [TRD]** — 새 에피소드를 여는 끊기 하나(여는 이)만 문 자물쇠 밖에서 기록을 켜고(스냅숏 **앞**) 멤버 명단을 한 번 찍어 멤버마다 같은 핸들로 소속을 확인하고 사실을 읽어 붙든다. 명단 실패 · 256 초과 · 뿌리 없음 · 뿌리 자식이 둘 초과 · 포트 실패면 그 에피소드는 판이 없다. 줄은 **두 구간**(문 자물쇠 ① → 밖에서 준비 → ②)을 거쳐 나가고, 그 사이 턴이 닫혔으면 줄을 주지 않는다 · 새 입력 · 기록 번호 · 차례가 바뀌었으면 에피소드 없이 줄만 준다. 같은 에피소드의 뒤 끊기는 이어 적는다.
3. **쓰기 명단 W [TRD]** — 끊기 줄이 stdin 에 쓰인 직후 라이터가 아무 락 없이 멤버 번호 명단 W 를 한 번 찍는다. **후보는 번호가 W 에 없는 탄생뿐이다** — 쓰기 전에 가입해 판 때 산 것은 W 를 찍을 때도 살아 있었으므로(끝난 프로세스는 되살지 않는다 · 명단은 완전할 때만 쓴다) W 에 든다. 그래서 알림이 언제 쌓이는지에 기대지 않는다. N 초는 쓰인 순간부터 센다. W 를 못 찍은 쓰기는 첫 쓰임이 되지 못한다(같은 에피소드의 뒤 끊기가 W 와 함께 쓰이면 그것이 첫 쓰임이 된다).
4. **고르기 — 넷을 모두 채운 것만 [사용자 결정 9 · 10 · 11 + TRD]** — 후보 C(번호 ∉ W · 끝내기 권한으로 붙듦 · 스냅숏에 없음 · 산 것)에 대해. **알려진 고리** = 스냅숏의 붙든 멤버 또는 같은 기록의 탄생 — 고리는 **붙든 핸들 사이에서만** 잇는다.
   1. **부모** — C 의 부모가 알려진 고리이고 끝났다(결정 11). 부모가 살아 있으면 건드리지 않는다(결정 4 그대로).
   2. **훅 사본** — C 와 부모의 실행 파일이 같고 ⓘ 명령줄이 같거나(fork 사본) ⓘⓘ 부모가 훅 껍데기(`-c "bash …"` · `shell-snapshots` 아님)다(결정 10). exec 된 프로그램(`sleep` · `cat` · 서버 · 빌드 자식)은 빠진다.
   3. **조상** — 부모에서 claude(부모가 뿌리인 고리)까지 모든 고리가 알려졌고 끝났으며 ★고리마다 부모 생성 ≤ 자식 생성★이다(결정 9 · 11 · 생성 순서 검사는 [TRD] — 번호 재사용으로 엉뚱한 부모가 끼는 것을 거르고 후보를 줄이기만 한다). 16 걸음 · 순환 · 뿌리에 먼저 닿음은 끊긴 사슬이다.
   4. **훅 사슬** — 꼭대기 T(claude 바로 아래 고리)가 훅 실행기이고, 이 기록에 부모가 claude 이고 `taskkill.exe` 이며 명령줄이 정확히 `/PID <T> /T /F` 인 탄생이 있고 그 생성이 T 의 생성 이상이다(결정 10 · taskkill ≥ T 는 [TRD]). claude 가 끊기 방식을 바꾸면 모두 놓친다(안전 쪽).
   - 사용자: 「어쨋든 부모 쭉 타고올라가서 살아있으면 제외한다는거잖아. 딱히 로직 부담도없겠네 상위부모 탐색만 하면되니」(9) · 「어차피 5분 멈추는것보다는 훨씬 좋은거잖아 이것들이.」(10).
5. **판 [TRD]** — 쓰인 지 N = 3 초(단조 시각)에 그 에피소드의 턴 끝이 없으면 일꾼 스레드가 판을 돈다. 한 판 = **차례 많아야 3** · 차례마다 기록 복사 → 고르기 → `seq` 오름차순(먼저 태어난 조상부터)으로 끝내기 → 그 차례가 끝낸 것을 **확인 마감 200 ms 하나** 안에서 확인 → 다시 고른다. 끝낸 것은 다음 차례에서 끝난 고리로 보여 그것이 거느리던 사본이 후보가 된다(p3bg 의 2 차례). 판 시간의 기다림은 많아야 0.6 초다.
6. **끝내기 확정 [TRD — ADR-0257 의 모양 그대로]** — 밖에서 뿌리 · 표식을 재확인하고, 문 자물쇠 안에서 「표식 없음 · 같은 세대 · 쓰임 · 정리 중 · 쓰임 + N ≤ 지금」을 다시 본 뒤 탄생 기록의 핸들로 `TerminateProcess` 하나(종료 코드 `0x7440`). 거절되면(턴 끝 · 새 끊기 · 새 입력 · 표식) 남은 후보와 다음 차례를 버리고 판 전체를 멈춘다.
7. **물러남 시작 [TRD]** — `AgentTransport::begin_retire(&self)`(기본 무동작 — pty · codex 통로는 그대로). `StdioTransport` 가 자기 `retiring` 칸을 세우고 `shutdown()` 첫 줄도 세운다. manager 는 `kill_agent` 의 첫 줄(권한 회수 · `Exiting` · `session.kill` 보다 먼저)과 `tear_down_failed_activation`(화신 표식 대조 뒤 첫 줄)에서 세션 → 통로로 부른다. backend 는 통로가 내준 읽기 전용 `RetiringSignal`(`is_set()` 만)로 읽는다 — manager 는 backend 의 문을 모른다.
8. **자물쇠 — 새 잎 둘 [TRD]** — 문 자물쇠 `GateCell.state` 와 기록 자물쇠 `Recorder.inner`. **겹쳐 잡지 않는다.**
   - 문 자물쇠는 쥔 채 로그 · 스레드 기동 · emit · 잠 · 다른 자물쇠 · 할당과 해제 · 명단 조회 · 붙들기와 핸들 닫기 · 그 밖의 OS 호출을 하지 않는다. 예외는 ⓐ 단조 시각 읽기 ⓑ 끝내기 확정의 `TerminateProcess` 호출 정확히 하나뿐이다(원자 읽기는 허용).
   - 기록 자물쇠는 필드 · `Vec` 넣기 · `Arc` 복제 · 꺼내기(할당 허용)만 하고 OS 호출 · 핸들 닫기 · 로그 · 다른 자물쇠는 하지 않는다. 독을 견딘다.
   - 쓰기 확인(라이터) · 듣는 스레드 · `begin_retire` 는 아무 락 없이 부른다(`kill_agent` 의 첫 줄은 명부 락을 이미 놓았다) — 기존 락과 간선이 없다. 정본 = TRD §3-3 끝(CLAUDE.md 「핵심 불변식」 락 순서 줄이 옮긴다).
9. **고지 · 대체 · 끄기 없음 [사용자 결정 1 · 2 · 3 — ADR-0257 그대로]** — 화면은 평소 끊김과 같고 tracing 로그만 남는다.
10. **구현은 재현되는 것만 고친다 [사용자 2026-10-01]** — 「일단 재현 가능한것만 구현하자. 좀 현실적인 사항으로 단순화」 · 「현실적으로 가능한것 위주로 단순화 하자」. 구현 리뷰(2 · 3단계 codex)가 낸 이론 경로는 코드로 막지 않고 아래 「알려진 한계」 K1–K9 로 둔다. TRD §5 의 실프로세스 시험 13(`#[ignore]` MSYS 반복 · 파이프)도 이 결정으로 짓지 않았다.

**OS 조각 [TRD]** — `platform/windows.rs` 에 명단(1단계 그대로) · `pin_member`(같은 핸들로 소속 확인 · 사실 한 번 · 끝내기 권한 선택) · `watch_births(start)` · `unwatch_births` · `BirthPort::next`. 중립 손잡이 `ProcessGroup`(약한 Job 손잡이 + `RetiringSignal`)이 그것을 감싼다 · 다른 OS = 명단 빈 것 · 붙들기 없음 · 포트 `Unsupported`. ★새 `windows` feature 둘 = `Win32_System_IO`(완료 포트 — 가입 알림을 받는 공개 수단) · `Wdk_System_Threading`(`NtQueryInformationProcess` — 핸들로 부모 · 명령줄)★ — 사용자 확인(TRD §10) · 새 crate 없음 · `Cargo.lock` 무변경.

**[구현] 고른 것** — 「무리가 사라졌나」(`ProcessGroup::is_gone()` — 부작용 없음)를 듣는 스레드가 매 차례 본다(reaper 가 자연히 끝난 세션을 `shutdown()` 없이 거둬 표식이 서지 않는 길이 있다) · 끝내기 권한 붙들기가 거절되면 권한 없이 다시 붙들어 **고리 전용**(후보는 못 되고 사슬은 잇는다) · 부를 것 · 듣는 스레드 · 일꾼의 패닉 로그는 error(로깅 규약 — TRD §3-8 의 warn 을 이 ADR 이 바로잡는다) · `windows.rs` 는 잎으로 둔다(자기 사실 · 사건 타입을 갖고 중립 타입으로의 변환은 `process_group.rs` — 2026-09-29 사용자 결정 「windows crate 와 io 만 · 통째로 옮길 수 있게」 유지). ★릴리스 프로필이 `panic = "abort"` 라 `catch_unwind` 막이는 디버그 · 시험에서만 일한다 — 부를 것 · 듣는 스레드 · 일꾼은 만들 때부터 패닉이 없게 짠다(`unwrap` · 색인 없음 · 독 걸린 자물쇠를 견딤)★.

**ADR-0257 과의 관계(줄 번호 = 그 ADR 본문 · TRD §9):**

**개정(양방향 링크는 관련줄):**
- **ADR-0238 결정 2** — 끊기 줄 함수의 반환이 `Option<Vec<u8>>` 에서 `Option<InterruptOut { bytes, on_written }>` 로 바뀐다. `on_written` = 라이터가 그 줄을 쓴 **뒤**(쓰기 성공 · `mark_written` 뒤 · 아무 락 없이) 부르는 것 — 입력 큐가 덩이마다 선택적으로 싣고(`push_with` · `pop` 이 쌍을 준다) 닫히면 버린다. 통로는 여전히 바이트의 뜻도 부를 것의 뜻도 모른다.
- **ADR-0238 결정 3** — 턴 열림 문 `TurnGate { open: AtomicBool }` 가 `GateCell`(문 자물쇠 `Mutex<GateState>` — 열림 · 에피소드 · 세대 · 여는 이 · 일꾼)로 바뀐다. decoder 는 그것을 자리 `GateSlot`(`Arc<OnceLock<Arc<GateCell>>>`)로 쥔다 — 문은 통로를 연 뒤에 서고 decoder 는 그 전에 만들어진다. 여닫기 규칙과 거절 계약은 그대로고, 라이브 `started`(새 입력)가 그 턴의 끊기 에피소드를 버린다(닫혀 있었으면 연다). ★두 구간 사이에 그 턴이 닫히면 줄을 주지 않는다 — 그 Esc 는 CONFLICT 로 거절된다★(결정 7 의 잔여 경합을 조금 좁혔을 뿐 닫지 못한다).
- **ADR-0238 결정 5** — 그 자리의 정리용 기록이 에피소드(첫 · 마지막 쓰임 시각 · 스냅숏 · 기록 번호 · W · 차례)가 된다. ★끊김 분류는 여전히 `terminal_reason` 이 하고 이 기록을 읽지 않는다★.
- **ADR-0238 「영향」 락 순서 줄(`:66`)** — 「새 락 간선 없음」 → 새 잎 둘(문 · 기록) · 겹쳐 잡지 않는다 · 쓰기 확인은 라이터 스레드에서 명단을 락 밖에서 찍고 문 자물쇠만 잠깐 잡는다 · 기존 락과 간선 없음(위 결정 8).
- **ADR-0244 결정 2** — ADR-0257 의 개정을 이어받는다: backend 는 되풀이 끊기를 **거절하지 않지만**(막는 자리는 여전히 프론트다) 같은 에피소드에 **이어 적는다**.

- **닫힌 실패 · 판의 순서** — 표식 없음 → 스냅숏 `Taken` 이고 기록이 산다 → 붙든 뿌리가 산다 → 차례들 → 끝내기 전마다 뿌리 · 표식 재확인 → 확정. 하나라도 서지 않으면 아무것도 끝내지 않고 warn(사유 `reason`). ★실패 방향은 늘 놓침(오늘처럼 약 300 초)이다★.
- **남는 오살 틈(TRD §8 ⑰)** — ⓐ 창 = 「첫 쓰임의 W, 마지막으로 쓰인 끊기 + N + 차례들」 사이의 가입 가운데 훅 사본 · 사슬 전멸 · 꼭대기 = 훅 실행기 · claude 의 taskkill 이 그 꼭대기를 가리키는 것 — 곧 **claude 가 taskkill 한 훅 나무의 스크립트 · 서브셸이 살아남은 것**이고 끝내는 것이 끊기의 뜻과 맞는다. Bash 도구 사슬 · exec 된 프로그램 · 산 작업 아래의 것은 빠진다. ⓑ 사슬 이어 붙이기 — 부모 번호 재사용과 **그 두 생성 사이의 시계 뒤로 뛰기** 또는 재사용한 새 주인이 자식과 같은 생성 눈금(K4)이 겹치고 엉뚱한 사슬이 규칙을 다 채울 때(추론 · 무시할 만하다).
- **안전을 떠받치는 추론(TRD §8 ㉒ ⓐ–ⓓ — 틀리면 엉뚱한 것을 끝낼 수 있다)** — claude 의 직계 자식 중 훅이 아닌 것이 `-c "bash …"` 를 쓰지 않는다(taskkill 표지가 둘째 벽) · 뿌리 자식 = conhost + claude · 위 ⓑ 의 겹침이 없다(시계 뒤로 뛰기만이 아니라 같은 눈금 재사용도 잔여다 — K4) · claude 내부 모양(훅 · Bash 도구 감싸기 · taskkill 방식 · MSYS 명령줄 복사 — 2.1.284 · 문서 없음 · 판이 바뀌면 출처 스파이크를 다시 돌린다).
- **upstream 이 고치면(#85250) 이 경로는 잠든다** — 턴 끝이 N 안에 오므로 판이 돌지 않는다.
- **T-40 과 무관한 관측(T-41)** — 새 에이전트의 첫 턴에서 `UserPromptSubmit` 훅 도중의 Esc 는 아무 일도 안 한다 — 문이 첫 `started` · 진행 줄에서야 열린다(ADR-0238 결정 3 · G1 중 1 회 관측). 이 결정이 만든 것이 아니다.
- **코드 앵커 `// ADR-0262`** — 찾는 법 = `rg "ADR-0262" crates`. `// ADR-0257` 은 `base` 의 1단계 함수와 N = 3 초 상수 `INTERRUPT_LEFTOVER_GRACE`(ADR-0257 결정 4 의 N — 이 ADR 앵커와 나란히)에만 남는다.

### 알려진 한계
**놓침(오늘처럼 약 300 초 · TRD §8 ③ ④ ⑱ ㉓):** 가입 알림 유실 · 포트를 붙이는 순간의 탄생 · 짧은 중간 고리를 열기 전에 끝남 · 시계가 두 생성 사이에 뒤로 뜀 · 기록 넘침(512) · 부모 · 조상이 산다 · 사슬이 알려지지 않음 · 훅 감싸기 · taskkill 방식이 바뀜 · 명령줄을 못 읽음 · 대기 입력의 `started` 가 멈춘 턴의 에피소드를 버림(G1b 미실행) · 포트 실패 · 쓰기 명단 실패 · 끝남 확인이 200 ms 를 넘음 · 3 차례를 넘는 fork 세대 · 쓰기와 W 사이에 태어난 주인(G1 — 6–26 µs 대 320–504 ms) · W 의 번호를 재사용한 주인 · cmd 와 claude 사이의 런처(모두 놓침) · 잔여 경합(ADR-0238 결정 7)의 멈춤.

**구현 리뷰가 남긴 것 — 결정 10 으로 코드 없이 기록:**
- **K1** 조상 걷기는 뿌리의 자식을 모두 claude 로 본다(codex 2단계 A#1) — 비현실: 뿌리 `cmd /c` 는 claude(와 conhost)만 띄우고, Esc 때 뿌리 자식이 둘을 넘으면 스냅숏이 `Failed(shape)` 다.
- **K2** 물러남에서 포트 떼기가 실패하거나, 꺼내 버리기만 하는 중에 `next` 가 다시 오류면 듣는 스레드가 끝난다(codex 2단계 A#2) — 떼기 실패는 관측된 적이 없고, 물러남이면 Job 이 곧 끝난다.
- **K3** 여는 중에 엇갈려 온 Esc 의 줄에는 쓰기 확인이 없다 → 판이 그 줄이 쓰인 지 3 초가 안 되어 돌 수 있다(codex 2단계 B#1) — 창 = 여는 이의 준비 시간(ms) 안에 Esc 둘이 들어야 하고, 끝내기는 여전히 규칙 넷을 다 채워야 한다.
- **K4** 같은 생성 눈금(부모 생성 = 자식 생성)은 생성 순서 검사를 통과한다 — 검사는 「부모 ≤ 자식」이다(ADR-0257 결정 9 의 「같은 눈금 포함」과 같은 쪽). TRD §3-7 · §8 ⑰ⓑ 의 「엄격히 늦게」 서술은 이 줄이 바로잡는다.
- **K5** W 가 없는 에피소드(명단 실패 · 쓰이지 않은 줄)는 스냅숏 · 기록의 핸들을 턴 끝까지 쥔다 — 멈춘 턴이면 약 300 초 · 화신당 한 에피소드로 묶인다.
- **K6** 꺼내 버리기만 하던 듣는 스레드가 끝나거나 물러남의 떼기가 실패하면 포트가 Job 에 붙은 채 닫힌다(debug 로그).
- **K7** 막이 둘이 릴리스의 `panic = "abort"` 에 기댄다 — 포트 확보의 `OnceLock` · 일꾼이 끝(Exit)을 받은 뒤의 가드.
- **K8** 에피소드 열림 로그가 되알림 수를 적게 센다 · 탄생마다 사실을 세 번 복사한다 · 무작위 전이 시험은 끝내기 확정과 패닉을 돌리지 않는다.
- **K9** 이어 적는 Esc 마다 구간 ① 이 줄이 쓰이기 **전에** 마지막 끊기 시각을 올린다 → 쓰이지 않는 Esc 가 되풀이되면 판이 계속 밀릴 수 있다(codex 3단계 FIX) — 비현실: 채팅 화면은 「중단하는 중…」 동안 Esc 를 무시한다(ADR-0244 · FE-1.4). 늦출 뿐 엉뚱한 것을 끝내지 않는다.
