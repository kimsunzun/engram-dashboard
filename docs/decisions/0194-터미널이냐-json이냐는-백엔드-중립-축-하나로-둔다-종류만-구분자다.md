# ADR-0194: 터미널이냐 JSON이냐는 백엔드 중립 축 하나로 둔다 — 종류만 구분자다

- 상태: 확정 (2026-09-11, 근거: 사용자 결정)
- 관련: ADR-0044(입력 인코딩·출력 정제 — 이 축을 처음 만든 결정) · ADR-0192(백엔드 기본값은 claude 와 동일) · ADR-0188(권한을 중립 축으로 — 같은 형태의 선례) · ADR-0191(통로 생성) · ADR-0004(백엔드 지식 격리) · `docs/process/S21-codex-backend/trd-phase2a.md` §10-7 ① · step-log S21

## 맥락

codex 가 통로를 둘 갖게 되면서(터미널 대화 화면 · app-server) 「이 에이전트를 어느 쪽으로 띄우나」를 담을 자리가 필요해졌고, 그것을 어떻게 표현할지가 Phase 2a 의 마지막 열린 항목이었다(§10-7 ①).

★**그런데 그 축은 이미 있고, 이미 공용으로 쓰이고 있으며, 이름만 한 백엔드를 달고 있다.**★ 실물:

- `crates/engram-dashboard-agent/src/profile.rs:29-37` — `ClaudeOutputFormat { Terminal, StreamJson }`. **값이 이미 중립**이고, 그 타입 주석이 스스로 「claude 출력 포맷 — **프로세스 기동 방식(= transport)과 프론트 렌더러를 함께 가른다**(ADR-0044)」라고 적는다. 즉 출력 포맷이 아니라 **모드 축**이다.
- ★`crates/engram-dashboard-agent/src/backend/gemini/mod.rs:135`·`:179` — **gemini 백엔드가 이미 그 타입을 빌려 쓴다**★(`crate::profile::ClaudeOutputFormat::Terminal`). 세 번째 백엔드가 남의 이름을 단 타입을 가져다 쓰는 상태가 이미 실재한다.
- `crates/engram-dashboard-agent/bindings/AgentNewArgs.ts:17` — **밖으로 나가는 이름은 이미 중립이다**(`output_format?: AgentOutputFormat`). Rust 타입 이름만 뒤처져 있다.

## 결정

**터미널이냐 JSON이냐는 백엔드 중립 축 하나로 둔다.**

- **밖으로 드러나는 것은 둘뿐이다 — ① 에이전트 종류(Claude · Codex …) ② 이 모드 축.** 그 밖의 것은 백엔드마다 다른 이름·다른 모양으로 노출하지 않는다(사용자 결정).
- **Rust 타입 이름을 중립으로 바꾼다** — 이미 중립인 wire 이름(`AgentOutputFormat`)과 맞춘다. ★claude 쪽도 함께 고친다(사용자 결정) — 한쪽만 두면 「남의 이름을 빌려 쓰는」 오늘 상태가 남는다.★
- **codex 에 그 필드를 더한다.** `#[serde(default)]` 로 기본값 = 터미널.
- ★**디스크 계약은 안 바뀐다**★ — 저장되는 필드 이름(`output_format`)과 값(`Terminal`·`StreamJson`)을 그대로 둔다. 그래서 **마이그레이션이 없다**: 옛 claude 프로필은 그대로 읽히고, 옛 codex 프로필은 필드가 없으니 기본값(터미널)으로 흡수된다. 그 흡수 선례가 `crates/engram-dashboard-agent/src/profile.rs:47-52` 의 주석에 이미 적혀 있다(사용자 결정 2026-09-07 — 「칸을 더할 땐 `#[serde(default)]` 를 달면 옛 프로필이 그대로 흡수된다」).
- **모드가 무엇을 고르는지는 각 백엔드 안에서 갈린다** — 같은 「JSON」이 claude 에서는 헤드리스 NDJSON 스트림이고 codex 에서는 app-server 다. 그 차이는 `backend/<name>/` 안에 남고 축은 공용이다(ADR-0004 · ADR-0191 의 통로 생성 경로가 이 값을 읽는다).

## 거부한 대안

- **백엔드마다 자기 이름의 타입을 둔다**(오늘 상태 + codex 용으로 하나 더) — ★그 상태가 이미 새고 있다★: gemini 가 claude 이름 타입을 빌려 쓴다(위 `file:line`). 백엔드가 늘 때마다 같은 축이 다른 이름으로 늘거나 남의 이름을 빌린다.
- **모드를 `extra_args` 자유 인자 문자열에 섞는다** — 새 필드가 없어 변경은 가장 작지만, **그 문자열이 모드 선택인지 사용자가 덧붙인 인자인지 코드가 구분하지 못한다.** ADR-0188 이 권한 축에서 이미 같은 이유로 기각한 모양이다(「자유 문자열 인자에 섞어 흘리면 공통인지 전용인지 구분이 안 보인다」).
- **터미널 codex 와 JSON codex 를 별개 에이전트 종류로 나눈다** — 선언 표 검사는 자동으로 갈리지만 사용자 눈에 종류가 늘어 보이고, 「종류는 도구, 모드는 축」이라는 이 결정의 축이 무너진다.

## 근거

- 위 세 `file:line` 이 전부다 — 축이 이미 공용이고, 값이 이미 중립이고, 바깥 이름이 이미 중립이다. 이 ADR 은 **없던 추상화를 만드는 것이 아니라 이름이 뒤처진 것을 따라잡는다.**
- ADR-0192(백엔드 기본값은 claude 와 동일하게 맞춘다)의 직접 적용 — claude 가 필드로 하니 codex 도 필드로 한다.

## 영향 / 불변식

- **마이그레이션 없음**(위 결정의 디스크 계약 조항). 저장 파일 버전도 안 올린다.
- **`AgentCommand` 는 `#[serde(tag = "kind")]`** 라 종류가 이미 구분자다(`crates/engram-dashboard-agent/src/profile.rs:44-46`) — 이 결정은 그 구분자 **바깥**을 정리한다.
- ★**선언 표 트립와이어를 같은 변경에서 고쳐야 한다**★ — 그 표는 `AgentCommand::Codex { .. }` **변형 하나에 튜플 하나**를 대므로(`crates/engram-dashboard-agent/src/backend/mod.rs:779`, 단언 `:800-802`), 모드를 필드로 나르면 **둘째 모드가 그 검사를 안 탄다.** 안 고치면 검사가 초록인 채 아무것도 안 잰다.
- **gemini 의 차용이 정리된다** — 이름이 중립이 되면 그 백엔드가 남의 이름을 부르지 않게 된다.
- **재론 트리거** — ① 「터미널이냐 JSON이냐」로 안 갈리는 제3 의 모드가 생기면(예: 원격 전송) 이 축의 값 집합을 다시 연다 ② ADR-0188 의 권한 값 설계가 나오면 그것과 이 축이 같은 선언 묶음에 앉을지 결정한다.
