# ADR-0249: 사용량 능동 조회는 짧게 뜨는 전용 프로세스를 분리 스레드에서 돌리고 Job 종료로 죽인다

- 상태: 확정 (2026-09-27, 근거: TRD §7 #5)
- 관련: TRD §7 #5 · `crates/engram-dashboard-agent`(Job Object 래퍼) · step-log S21

## 맥락
사용량 능동 조회를 어디서 실행할지 정해야 했다 — 이미 떠 있는 에이전트 프로세스에 조회를 얹을지, 대화 통로에 RPC 표면을 하나 더 낼지, 아니면 조회 전용 프로세스를 따로 띄울지.

## 결정
능동 조회는 **짧게 뜨는 전용 프로세스**를 **분리 스레드**에서 돌리고, **Job 종료**로 죽인다.

## 거부한 대안
- **떠 있는 에이전트 프로세스에 보내기(D7)** — 대화 컨텍스트에 사용량 조회를 얹게 된다.
- **대화 통로에 일반 RPC 표면 추가**(`transport/mod.rs:51-90`) — 통로의 계약 범위를 사용량 조회까지 넓힌다.
- **명시 shutdown 단계** — 크래시를 못 덮는다. Job 종료(Job Object)는 프로세스가 어떻게 죽든 자식까지 함께 걷는다.

## 근거
TRD §7 #5.

## 영향 / 불변식
기존 Job Object 래퍼(`agent` crate, Windows `Win32_System_JobObjects`)를 재사용 — 조회 프로세스가 새는 경로를 만들지 않는다. 구현 커밋: `7aad8f7`, `56776d6`.
