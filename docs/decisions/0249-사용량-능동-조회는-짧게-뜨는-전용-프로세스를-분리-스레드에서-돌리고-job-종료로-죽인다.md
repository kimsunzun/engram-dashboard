# ADR-0249: Usage active query runs a short-lived dedicated process on a separate thread and kills it by Job termination

- 상태: 확정 (2026-09-27, basis: TRD §7 #5)
- 관련: TRD §7 #5 · `crates/engram-dashboard-agent`(Job Object wrapper) · step-log S21

## 맥락
We had to decide where to run the usage active query — put the query on an agent process that is already running, add one more RPC surface to the conversation channel, or start a dedicated query process separately.

## 결정
The active query runs a **short-lived dedicated process** on a **separate thread** and kills it by **Job termination**.

## 거부한 대안
- **Send it to the running agent process (D7)** — it would put the usage query on the conversation context.
- **Add a general RPC surface to the conversation channel** (`transport/mod.rs:51-90`) — it widens the channel's contract scope to the usage query.
- **An explicit shutdown step** — it cannot cover a crash. Job termination (Job Object) collects the children together however the process dies.

## 근거
TRD §7 #5.

## 영향 / 불변식
Reuse the existing Job Object wrapper (`agent` crate, Windows `Win32_System_JobObjects`) — do not create a path by which the query process leaks. Implementation commits: `7aad8f7`, `56776d6`.
