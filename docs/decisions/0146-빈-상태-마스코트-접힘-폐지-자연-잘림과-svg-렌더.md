# ADR-0146: 빈 상태 마스코트 접힘 폐지, 자연 잘림과 SVG 렌더

- 상태: 확정 (2026-08-18, 근거: 사용자 결정 + 화면 실측)
- 관련: Amends ADR-0145 (마스코트 임계 높이 접힘) · `src/components/slot/RichSlot.tsx` · `src/components/slot/ClaudeMascot.tsx`

## 맥락

ADR-0145 결정 7은 슬롯 높이가 임계 미만이면 마스코트를 통째로 숨기게 했다. 구현 후 화면에서 보니 **슬롯을 줄이는 도중 마스코트가 툭 사라진다.** 사용자 제보(2026-08-18): 공간이 줄면 점점 가려지다 안 보이는 것이 자연스럽고 그게 기본 동작 아니냐 — 맞다. 임계값 자체도 격자 크기가 바뀔 때마다 다시 계산해야 하는 부채였다(240 → 300px으로 한 번 밀렸다).

같은 실측 라운드에서 마스코트 도형·색·문구도 사용자 확인을 거쳐 바뀌었고, 렌더 방식도 DOM 격자에서 SVG로 옮겼다(빈 상태 하나에 DOM 노드 442개가 들어갔다).

## 결정

1. **임계 높이 접힘을 폐지한다(ADR-0145 결정 7 대체).** 높이 관측 장치·임계 상수·접힘 분기·그 debounce를 전부 제거하고, 공간이 줄면 마스코트가 **잘려 나가게** 둔다.
2. **잘리는 쪽은 마스코트뿐이다.** 문구와 입력창은 축소·잘림 대상에서 제외한다. 슬롯이 입력창보다 작아지는 극단 구간은 그대로 짜부되게 둔다 — 사용자 결정: 그 구간은 신경 쓰지 않는다.
3. **마스코트는 SVG로 그린다(ADR-0145 결정 4의 "격자 요소" 구체화).** 도트 데이터는 문자열 배열 그대로 두고, 가로로 이어진 칸을 하나의 사각형으로 병합해 그린다. 병합 계산은 모듈 로드 시 1회.
4. **색은 빨강이 아니라 원본 마스코트의 테라코타 계열(ADR-0145 결정 3 수정).** 참조는 공식 스티커의 Clawd 도형이다.
5. **빈 상태 문구는 「메시지를 입력하세요」.** 「오늘 어떤 도움을 드릴까요?」는 claude.ai 문구를 그대로 옮긴 인상이라 사용자가 거부했다.
6. **작업 디렉터리(cwd) 줄은 넣지 않는다.** 한 번 넣었다가 사용자 결정으로 제거했다 — 이 앱의 에이전트 정체성은 폴더 경로 기준이 아니다.

## 거부한 대안

- **접힘을 유지하되 부드럽게(페이드·축소 애니메이션)** — 사용자가 원한 것은 연출이 아니라 "기본 동작대로"였다. 애니메이션은 ADR-0145 결정 6(스냅)과도 어긋난다.
- **임계값만 다시 잡기** — 격자 크기가 바뀔 때마다 재계산해야 하는 부채가 그대로 남는다. 실제로 이 작업 중에만 두 번 밀렸다.
- **폭 기준 접힘 추가** — 마스코트가 커지면서 좁은 슬롯에서 좌우가 잘리는 것이 관측됐다. 세로와 같은 이유로 넣지 않는다(잘리는 것이 정상 동작이다).
- **DOM 격자 유지** — 빈 상태 하나에 노드 442개. 슬롯 여러 개에 동시에 뜨면 그만큼 곱해진다. SVG 전환 후 37개.
- **PNG 자산으로 전환** — ADR-0145에서 이미 기각(테마·배율). 이번에도 재론하지 않는다.

## 근거

- **사용자 결정(2026-08-18)** — 접힘 폐지·문구·경로 줄 제거·마스코트 형태 전부 화면을 보고 사용자가 지정했다. 렌더 방식(SVG)은 사용자가 메인에 위임했다.
- **화면 실측** — 릴리스 빌드를 띄워 CDP로 확인했다. 접힘 폐지 전 동작(임계 통과 시 마스코트만 사라짐)까지 실제로 재현해 본 뒤 폐지했다.

## 영향 / 불변식

- **높이를 재는 코드가 이 컴포넌트에 다시 들어오면 이 결정 위반이다.** 접힘·축소·반응형 분기를 넣지 말고 CSS 흐름에 맡긴다.
- **문구·입력창은 잘림 대상이 아니다** — 마스코트 칸만 축소·잘림을 흡수한다. 이 구조가 깨지면 좁은 슬롯에서 입력창이 먹힌다.
- **도트 데이터는 한 곳 상수로 유지한다** — 형태 조정이 한 줄 수정이어야 한다는 성질은 SVG 전환 후에도 유효하다.
- **마스코트는 장식이다** — 의미를 나르지 않으므로 접근성 트리에서 숨긴다. 여기에 상호작용을 붙이지 않는다.
