## 맥락

P3c2 (`7b742fb`) introduced the state-file notice (`StateFileNotice` — a closable notice line shown in main when boot could not read `state.json` properly · user decision 2026-10-05). Its on-screen shape was a session judgment (user delegation), and because it was the same flow block as the connection banner (`ConnectionNotice`), when it appeared it pushed down the layout below it.

The basis of that shape is ADR-0180. That ADR splits notifications into a banner (「알린다」) and a popup (「네가 눌러야 한다」), and decides 「알림이 덮는 것」 only by popup eligibility (decision 2 — a state that is never recovered unless the user acts) (first item of 「영향 / 불변식」 — otherwise it is a banner). The reason the connection banner does not overlay is that the old edition of that banner was an overlay and ate TabBar clicks (`ConnectionNotice.tsx:10` — the edition before `9318b5c`). ★Changing that banner from an overlay to a flow block (2026-08-14 · `485f84c` — the commit that introduced that file) was not a user decision but a session change (user's remark 2026-10-06)★.

P3c2 also left one open item (TRD §14-15) — for guard ii (the crash copy that should have been set aside could not be, so that run saves no screen state at all), no notice remained after it was answered. What stated that fact was only the `durable:false` while asking and the refusal warning of the modal.

## 결정

1. **The state-file notice overlays the layout and does not push it** (user decision 2026-10-06). The user: 「우리는 레이아웃을 고정시키고 그 고정된 상황에서 작업하는건데 팝업이 나오면 밀림」.
2. **It may cover the TabBar — close it with ✕** (user decision 2026-10-06). The user: 「탭바 가려도 되지않음? 어차피 x눌르면 없어지는거잖아」. ★(2026-10-26 mark) Since the OS frame was removed, the banner overlays below the title bar (tab bar · drag area · window buttons) and does not cover the title bar — ADR-0306 (user decision 2026-10-26)★
3. **If there are several notices they stack, and past a certain height they scroll** (user decision 2026-10-06). The user: 「일정 이상 나오면 스크롤」. ★That height (1/3 of the window height — `33vh`) is a session judgment★ — it is not a value the user chose.
4. **Guard ii also shows the same kind of notice** (2026-10-06). The session raised it as 「새 결정이라기보다 10-05 결정을 이 경우에도 적용할지의 문제 — 따로 말씀이 없으면 그렇게 보고 같은 안내 띠를 띄우는 쪽으로 진행」 and the user answered 「그래 띠로 하던가」. ★The implementation that realizes that notice is a session judgment (`125d190` — neither a user decision nor a review result)★: add to `restore.status` an always-present field `saves` (whether this run saves screen state), and the notice condition = `saves:false` and `state_file:'ok'` — it remains after being answered. The LLM reads the same fact through `saves` (TRD §6-7 command).
5. **Scope = the state-file notice in the main window only.** The connection banner (`ConnectionNotice` — main · popout · tree window) stays in the flow and pushes the layout, as in ADR-0180. ★Whether the connection banner should overlay too was not decided★ — it reverses ADR-0180, so it was raised to the user and the answer is awaited. ★(revision mark 2026-10-06) The same day the user decided that the connection banner overlays too — ADR-0277 (main · popout · tree window)★.

## 거부한 대안

- **Flow block (a banner that pushes the layout — the shape of P3c2 · the same place as the connection banner)** — the user: 「우리는 레이아웃을 고정시키고 그 고정된 상황에서 작업하는건데 팝업이 나오면 밀림」.

## 영향 / 불변식

- ★**One exception arose in ADR-0180's wall (「알림이 덮는 것」 is decided only by popup eligibility) — the state-file notice**★. Every other new notification stays as in ADR-0180 — if it is not popup-eligible it is a banner and goes in the flow. Moving one to the overlay side needs a separate decision. ★(revision mark 2026-10-06) The connection banner was moved by that decision — ADR-0277★. ★(2026-10-08 mark) Now all non-popup notifications (banners) stack in the overlay layer — no separate decision is needed when putting a new banner on (user decision 2026-10-08 · ADR-0287 decision 1)★.
- **The position of the overlay layer is held by the wrapping `div`** — the Root of Radix ScrollArea sets an inline `position: relative`, which a class cannot override. If a position class is given to the Root, the inline value wins and it cannot overlay (a defect the code review caught — TRD §6-5 ③ guard item).
- **Do not make the layer's height larger than the notice lines** — laying a transparent curtain of full height would eat clicks even outside the lines (the very incident ADR-0180 wanted to prevent). ★This invariant is a session judgment that came out of the implementation — it is not a user decision★ (the open item 「줄 바깥 빈 영역」 below). ★(2026-10-08 mark) It is now a user decision — ADR-0287 decision 2 (layer height = only as much as the drawn notice lines · T-50 closed). The cap value (1/3 of the window height) is still a session judgment★.
- **Stacking order of the layer** = z 40 — above the dividers · the cell curtain (z-20) · below the restore modal (z-50) · menus (1000 and above). The layer is inside the wrapper that is locked (`inert`) while asking, so during that time the notice's ✕ is blocked too.
- ★**Not verified**★: stacking · scrolling (the only notice inside the overlay layer now is the state-file notice, so stacking is not used in practice — scrolling is only a structural test in vitest and was not measured with the GUI) · in the dark theme the shadow of the overlay layer is barely visible (an observation — not fixed). ★(revision mark 2026-10-06) Stacking was measured in main by the GUI QA of ADR-0277 (connection banner + state-file notice) · scrolling is still not measured with the GUI★.
- ★**Open (not a decision)**★:
  - Whether the connection banner (main · popout · tree window) should overlay too — awaiting the user's answer. If it is decided to overlay, it reverses ADR-0180, so it is a new ADR. → ★Closed (2026-10-06) — it overlays · ADR-0277★.
  - 「줄 바깥 빈 영역」 — the user postponed it to talk about next. For now the layer is only as tall as the notice line and a click outside the line goes to what is below (H3). ★(2026-10-06 mark) After the storage system is finished it is raised to the user again (user decision 2026-10-06 · `docs/tracking.md` T-50)★. ★(2026-10-08 mark) Closed — the user confirmed the current behavior (overlaying only the lines) (user decision 2026-10-08 · ADR-0287 decision 2 · T-50 closed)★.
