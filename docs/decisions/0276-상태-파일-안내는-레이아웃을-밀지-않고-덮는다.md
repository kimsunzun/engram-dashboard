# ADR-0276: 상태 파일 안내는 레이아웃을 밀지 않고 덮는다

- 상태: 확정 (2026-10-06, 근거: 사용자 결정 2026-10-06 + 구현 `125d190` 코드 리뷰(`/review code full` · 2 family)·GUI QA H1–H6(스크래치 데이터 폴더)·CI run 37351977245)
- 관련: Amends ADR-0180 (알림이 덮는 것을 팝업 자격으로만 가르는 불변식 중 상태 파일 안내) · TRD `docs/process/S21-storage/trd.md` §6-5 ③ 가드 항목 · §6-7 명령 · §14-15 · §14-16 · `src/components/layout/AppLayout.tsx`(덮는 층) · `src/components/layout/StateFileNotice.tsx` · `src/components/layout/ConnectionNotice.tsx:10`(연결 띠의 「덮지 않는다」 — 그대로) · step-log S21

## 맥락

P3c2(`7b742fb`)가 상태 파일 안내(`StateFileNotice` — 부팅이 `state.json` 을 제대로 못 읽었을 때 main 에 띄우는 닫을 수 있는 안내 줄 · 사용자 결정 2026-10-05)를 들였다. 그 화면 모양은 세션 판단(사용자 위임)이었고, 연결 띠(`ConnectionNotice`)와 같은 흐름 블록이라 뜨면 그 아래 레이아웃을 밀어냈다.

그 모양의 근거는 ADR-0180 이다. 그 ADR 은 알림을 띠(「알린다」)와 팝업(「네가 눌러야 한다」)으로 가르고, 「알림이 덮는 것」은 팝업 자격(결정 2 — 사용자가 행동하지 않으면 영영 복구되지 않는 상태)으로만 가른다(「영향 / 불변식」 첫 항목 — 아니면 띠다). 연결 띠가 덮지 않는 까닭은 그 띠의 옛 판이 오버레이라 TabBar 클릭을 먹었기 때문이다(`ConnectionNotice.tsx:10`). ★그 띠를 오버레이에서 흐름 블록으로 바꾼 것(2026-08-14 · `485f84c` — 그 파일을 들인 커밋)은 사용자 결정이 아니라 세션 변경이었다(사용자 지적 2026-10-06)★.

또 P3c2 는 열린 것 하나를 남겼다(TRD §14-15) — 가드 ⅱ(떠야 할 크래시 사본을 못 떠 그 실행이 화면 상태를 하나도 저장하지 않는다)는 답한 뒤 남는 안내가 없었다. 그 사실을 말하는 것은 묻는 동안의 `durable:false` 와 모달의 거절 경고뿐이었다.

## 결정

1. **상태 파일 안내는 레이아웃을 밀지 않고 그 위에 덮는다**(사용자 결정 2026-10-06). 사용자: 「우리는 레이아웃을 고정시키고 그 고정된 상황에서 작업하는건데 팝업이 나오면 밀림」.
2. **TabBar 를 가려도 된다 — ✕ 로 닫는다**(사용자 결정 2026-10-06). 사용자: 「탭바 가려도 되지않음? 어차피 x눌르면 없어지는거잖아」.
3. **안내가 여럿이면 쌓고, 일정 높이를 넘으면 스크롤한다**(사용자 결정 2026-10-06). 사용자: 「일정 이상 나오면 스크롤」. ★그 높이(창 높이의 1/3 — `33vh`)는 세션 판단이다★ — 사용자가 고른 값이 아니다.
4. **가드 ⅱ 도 같은 종류의 안내를 띄운다**(2026-10-06). 세션이 「새 결정이라기보다 10-05 결정을 이 경우에도 적용할지의 문제 — 따로 말씀이 없으면 그렇게 보고 같은 안내 띠를 띄우는 쪽으로 진행」으로 올렸고 사용자가 「그래 띠로 하던가」로 답했다. ★그 안내를 실현하는 구현은 세션 판단이다(`125d190` — 사용자 결정도 리뷰 결과도 아니다)★: `restore.status` 에 늘 값인 칸 `saves`(이 실행이 화면 상태를 저장하나)를 더하고, 안내 조건 = `saves:false` 이고 `state_file:'ok'` — 답한 뒤에도 남는다. LLM 은 같은 사실을 `saves` 로 읽는다(TRD §6-7 명령).
5. **범위 = main 창의 상태 파일 안내뿐이다.** 연결 띠(`ConnectionNotice` — main · 팝아웃 · 트리 창)는 ADR-0180 대로 흐름에 남아 레이아웃을 민다. ★연결 띠도 덮을지는 정하지 않았다★ — ADR-0180 을 뒤집는 일이라 사용자에게 올렸고 답을 기다린다.

## 거부한 대안

- **흐름 블록(레이아웃을 미는 띠 — P3c2 의 모양 · 연결 띠와 같은 자리)** — 사용자: 「우리는 레이아웃을 고정시키고 그 고정된 상황에서 작업하는건데 팝업이 나오면 밀림」.

## 영향 / 불변식

- ★**ADR-0180 의 벽(「알림이 덮는 것」은 팝업 자격으로만 가른다)에 예외가 하나 생겼다 — 상태 파일 안내다**★. 그 밖의 새 알림은 ADR-0180 그대로다 — 팝업 자격이 아니면 띠이고 흐름에 둔다. 덮는 쪽으로 옮기려면 결정이 따로 필요하다.
- **덮는 층의 자리는 감싼 `div` 가 잡는다** — Radix ScrollArea 의 Root 는 인라인 `position: relative` 를 박아 클래스로 못 덮는다. Root 에 위치 클래스를 주면 인라인 값이 이겨 덮지 못한다(코드 리뷰가 잡은 결함 — TRD §6-5 ③ 가드 항목).
- **층의 높이를 안내 줄보다 크게 만들지 않는다** — 전체 높이의 투명 막을 깔면 줄 밖의 클릭까지 먹는다(ADR-0180 이 막으려던 그 사건). ★이 불변식은 구현에서 나온 세션 판단이다 — 사용자 결정이 아니다★(아래 열린 것 「줄 바깥 빈 영역」).
- **층의 겹침 차례** = z 40 — 분할선 · 칸 막(z-20) 위 · 복원 모달(z-50) · 메뉴(1000 이상) 아래. 층은 묻는 동안 잠기는(`inert`) 감싸개 안이라 그동안 안내의 ✕ 도 막힌다.
- ★**검증 안 된 것**★: 쌓임 · 스크롤(지금 덮는 층 안의 안내는 상태 파일 안내 하나라 쌓임이 실사용되지 않는다 — 스크롤은 vitest 의 구조 시험뿐이고 GUI 로 재지 않았다) · 다크 테마에서 덮는 층의 그림자가 거의 안 보인다(관찰 — 고치지 않았다).
- ★**열린 것(결정 아님)**★:
  - 연결 띠(main · 팝아웃 · 트리 창)도 덮을지 — 사용자 답 대기. 덮기로 하면 ADR-0180 을 뒤집으므로 새 ADR 이다.
  - 「줄 바깥 빈 영역」 — 사용자가 다음에 얘기하자고 미뤘다. 지금은 층이 안내 줄 높이만큼만이고 줄 밖의 클릭은 그 아래로 간다(H3).
