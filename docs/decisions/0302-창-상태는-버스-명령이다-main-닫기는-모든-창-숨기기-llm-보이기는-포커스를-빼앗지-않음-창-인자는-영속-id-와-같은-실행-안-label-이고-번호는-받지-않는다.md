# ADR-0302: Window state is a bus command — closing main hides all windows · the LLM's show does not steal focus · the window argument is a persistent id or a same-run label, and numbers are not accepted

- 상태: 확정 (2026-10-26, basis: user decision 2026-10-23 (Q7 — main ✕ = hide all windows · Q9 · D11 — numbers are not accepted as a window argument · review round 1 finding ② — a 0-tab self-close is re-checked by the shell at the moment of closing) + main-agent decisions M7 · M8 · M12 · M13 · M14 · M22 · M23 · M25 · M29 · M30 · M31 · M34 (TRD §12-3) + PRD defaults (main agent's proposal — R17 · R18 · D12 · W10) + implementation U5 · U6 `bbd34258` · U7a `07f35609` · `e329eb21` · U7b `24782701` · windows outside the model = U8b review 2 · 3 `056e6a63` · `49b64836`)
- 관련: PRD `docs/process/S21-window-chrome/prd.md` (version 0.5 — R6 · R10 · R17 · R18 · R23 · D6 · D11 · D12 · W7 · W9 · W10 · AC8 · AC9 · AC10 · AC24 · AC26 · AC28 · AC32) · TRD `docs/process/S26-window-chrome/trd.md` (version 0.3 — §2-3 · §2-4 invariants 3 · 5 · §4-5 · §5-2 · §5-4 · §5-5 · §6 · §9 · §10-4 · §15) · ADR-0026 · ADR-0229 (closing main = hide all windows · there is one hide path) · ADR-0299 decision 5 (raise z only, without stealing focus · no Alt synthesis) · ADR-0081 · ADR-0155 (humans and the LLM share the same application service · the command table is declared) · ADR-0167 (the old popout label restarts counting from 1 on every run) · ADR-0300 (window number) · ADR-0303 (window buttons) · `src-tauri/src/layout/window_ctl.rs` · `src-tauri/src/layout/window_arg.rs` · `src-tauri/src/commands/window_ctl.rs` · `src-tauri/src/tray/actions.rs` · CLAUDE.md 「LLM-우선 제어」 · step-log S26 · Amends ADR-0167 (the popout label form in its rationale, the counter 「앱을 띄울 때마다 1 부터 다시 세는」)

## 맥락

The LLM had no way to show a window or bring it to the front — showing and hiding existed only as the tray and its invokes (`show_main_ui` · `hide_main_ui`), there was no command to bring a single window to the front, and `window.close` rejected main (PRD §1 · R17). Once we draw the window buttons ourselves (ADR-0303), this gap shows up as is between humans and the LLM.

The argument that names a window was a problem too. The visible number is reused (ADR-0300), and the popout label restarts counting from 1 on every run (ADR-0167 rationale · `PopupCounter`), so a command arriving late after a restart could land on a different window (PRD D12 · second-round review BLOCK).

The OS-side facts were also tied in — tao's maximize · minimize · restore reveal a hidden window (comment on `state::placement::DeferredMaximize`), and for a new window or a restored window the first-paint gate (`first_paint`) owns showing it (ADR-0299 decision 3).

## 결정

1. **All window-state changes are bus commands, and a human's button calls that command** (R17 — principle · main-agent decision M7). New commands `window.minimize` · `window.maximize` · `window.unmaximize` · `window.raise` · `window.hideAll` · `window.showAll` · the widened `window.close` (`if_empty`) · `window.list` gains `details` (persistent id · label · number · main · visible · minimized · maximized · foreground window — the old `windows` field stays as is · R18). The service = `layout/window_ctl.rs` (zero Tauri) · port `WindowControl` · one human-path invoke `window_control` (it lands on the same service — ADR-0081 two shells). The 「원래 크기」 (restore size) command is not named `window.restore` (main-agent decision — it gets confused with the bus `restore.*`). There are no move · size · snap commands — a known gap.
2. **The web does not call the Tauri window API's minimize · maximize · close · show · raise** (TRD §2-4 invariant 3 · R17) — the gate = a vitest test `src/__tests__/noWindowControl.test.ts` that checks the receiver type through the TypeScript compiler API (main-agent decision M25) · the popout capability's `core:window:allow-close` is removed, so permissions block it too (TRD §9).
3. **`window.close(main)` = hide all windows** (user decision 2026-10-23 — Q7 · ADR-0229's one path `tray::actions::hide_main_ui`) — reply `HiddenAll` (it replaces the old `CONFLICT`). A popout = `apply::close_window` (reply `Closed`) → the OS window is destroyed → the number is released on `Destroyed` (ADR-0300). The button · Alt+F4 · the bus · closing the last tab · a 0-tab self-close all converge on one outcome (R23). The premise that a popout close request is not reverted (W7) is kept — the title-bar button does not issue an OS close request and goes through the bus.
4. **0-tab self-close = `window.close { window: <영속 id>, if_empty: true }`** (user decision 2026-10-23 — the shell re-checks at the moment of closing · main-agent decision M13) — before the common resolver, and under one lock: if an entry for that id is in the model, `Kept` · if it is not there and is in `closing`, close that label · if it is in neither, `Kept`. 「0 탭」 (0 tabs) = there is no entry in the model (a popout entry is excluded from operations that bring tabs to 0). The number rejection, however, comes before it.
5. **The LLM's show · raise does not steal focus** (main-agent decision M22 · PRD W10 default · ADR-0299 decision 5) — it uses the existing `first_paint::raise_and_show` sequence: ⓐ platform `place_window(…, ZOrder::Top, show: false, activate: false)` raises only z to the very top while the window stays hidden ⓑ Tauri `show()` · `unminimize()` (the tao visible and minimized flags stay correct), then applies the recorded desire ⓒ `set_focus()` only when the foreground is currently our process · no Alt synthesis · the reply's `focused` is the plain fact. It shares one path with the tray show, `tray::actions::show_main_ui(app, Activation)` — `TrayClick` = a tray icon click · the single-instance second-launch callback (a human's hand) · `NoSteal` = bus `window.showAll` · `window.raise` on a hidden window · invoke `show_main_ui` (the LLM · cdp surface — main-agent decision M31).
6. **Rules for invisible windows** (main-agent decisions M23 · M30 · TRD §5-2 table) — `minimize` on a window waiting for first paint or a hidden window = `CONFLICT` · `maximize` / `unmaximize` record the desired state (`DeferredMaximize` — applied when the window becomes visible · reply `deferred: true`) and, if the window is already that size, only withdraw the desire · `raise` on a window waiting for first paint = no-op (`pending: true`). **The LLM's show (`NoSteal`) skips windows waiting for first paint, while a tray click, as now, withdraws the wait and shows** (invariant 5). Every show branch applies a deferred maximize.
7. **One window-state action = one main-thread job** (main-agent decision M29) — reading state (`is_held` · visible · maximized · minimized) → the pure decision `window_ctl::plan` → recording and withdrawing the desire · the OS call all happen in one `app.run_on_main_thread` job, and the caller waits for the reply (`mpsc::channel` + `recv_timeout`). The bus verbs and `window.list` are plugged in with `offloaded_handler`, and the invoke `window_control` is async · `show_all` · `hide_all` have the same shape. It is not called while holding the layout lock.
8. **The foreground-window decision = platform `window::is_foreground`** (main-agent decision M12) — on Windows, Tauri `is_focused` is not used.
9. **Window argument = persistent id · same-run label alias · numbers rejected** (user decision 2026-10-23 — Q9 · D11 / label alias · run marker = PRD D12 default · form = main-agent decision M8). One resolver, `layout/window_arg.rs`, is shared by the bus and invoke shells: `main` · a persistent id (the same spelling first) · a label in the model → that window · digits only = `INVALID_ARGUMENT` (the help tells the caller to look up that number's `window_id` in the `details` of `window.list`) · anything else (a label from an earlier run · a closed window) = `CONFLICT`. Popout label = `slot-popup-<실행 표식 8 hex>-<n>` (monotonic within a run · the glob `slot-popup-*` still matches · the 2⁻³² probability that the marker equals an earlier run's is accepted). This form replaces the label that ADR-0167's rationale describes as 「앱을 띄울 때마다 1 부터 다시 세는」 (`slot-popup-1`…) — that ADR's decision is not touched (an amendment link was added in U10 2026-10-26).
10. **The reply from the three places that create a window = `{ window, window_id, number }`** (main-agent decision M14 · R6) — the invoke · the bus (`window.create` · `slot.popout`) · the web registry return the same three.
11. **Window buttons for a window outside the model** (main-agent decision M34 · 2026-10-26 · U8b review 2) — if the window argument is not in the model, its spelling is the label of an open popout OS window, and it is not a window in the warm-window pool: minimize · maximize · restore size = go straight to that window (the same `plan` · the same deferred-maximize table · only the model marker is not recorded) · close = **before withdrawing, place the tombstone (`ViewManager::mark_closed`) inside the layout lock first**, then withdraw the OS window (reply `Closed` · if it entered the model in the meantime, close it as a model window) · raise = still 「창 없음」 (no such window) (`CONFLICT`) · wire shape unchanged. main is always in the model, so it does not fall into this branch.

## 거부한 대안

- **Just accept numbers as a window argument** (PRD Q9 ③ · version 0.1 D11 「둘 다 받는다」 (accept both)) — after 2 is closed and a new 2 is created, a `window.close("2")` that arrives late closes the new window. Rejected = user decision 2026-10-23 (the user confirmed the reason and chose).
- **Accept a number but also accept the list version that `window.list` returned, and answer `CONFLICT` if it changed** (PRD Q9 ②) — fields grow and the LLM has to carry the version around. Rejected = user decision 2026-10-23.
- **Window argument = persistent id only (labels rejected)** (PRD D12 ①) — the simplest, but every call of a command that takes a window argument (`tab.*` · `window.close` · `window.getTheme` / `setTheme` · `slot.popout`, etc.) changes. Rejection strength = descriptive (scope of change).
- **Store the label counter in the state file so it is monotonic across runs** (PRD D12 ②) — if the app is shut down while the save is late or has failed, counting restarts from a value smaller than a label the earlier run handed out. Rejection strength = descriptive.
- **Labels only, as now** (PRD D12 ③) — after a restart a late command reaches a different window (PRD second-round review BLOCK). Rejection strength = review.
- **main ✕ = hide main only** (PRD Q7 ②) — it reverses ADR-0229 「숨기기 경로는 하나다」 (there is one hide path) (it would need a new ADR) and it creates a state where only popouts are visible without main. Rejected = user decision 2026-10-23.
- **Do the show that does not steal focus with raw Win32 `place_window(show: true, activate: true)`** (TRD version 0.2) — tao's visible flag stays false, so the next tray hide does nothing (comment on `first_paint::raise_and_show` ⓑ · head of `commands::spare` · TRD version 0.3 re-review ①). Rejection strength = code.
- **Do restore with raw Win32 `restore_no_activate` (`SW_SHOWNOACTIVATE`)** (TRD version 0.2) — the same flag problem arises. Use Tauri `unminimize()` (tao = `SW_RESTORE`). Rejection strength = code.
- **Taking the foreground when another app is in front (a workaround such as Alt synthesis)** — it contradicts ADR-0299 decision 5 (user decision 2026-10-21 「포커스 뺏지말고, 순서만 위로올려」). Rejected = user decision (ADR-0299).
- **Decide the foreground window with Tauri `is_focused` on Windows** (TRD review Claude ④) — wry hands focus to the webview on every `WM_SETFOCUS` of the window, so while the webview holds keyboard focus that value is false (code comment `state::placement::foreground_is_ours` · source reading · not verified in the GUI). Rejection strength = code (source reading).
- **Read `is_held` on the bus thread and record the deferral on the main thread** (TRD version 0.2) — if the first-paint show (on the main thread) passes in that gap, the deferral is left alone, and `state::placement::record` stops recording positions and pushing `window:frame` while a deferral stands (TRD version 0.3 re-review ②). Rejection strength = code.
- **Send `if_empty` to the common window-argument resolver** (TRD review codex ②) — the window on that path is usually already gone from the model, so the resolver would answer `NotFound` (= `CONFLICT`). Rejection strength = code.
- **Have the web call the Tauri window close directly for the 0-tab self-close** (as of now — the 0-tab effect in `WindowLayout.tsx`) — it does not take the shell close path (model · number · tray cleanup) (PRD W9), and it closes even if a tab enters in the gap between when the web saw it and when the shell closes (user decision 2026-10-23 — re-check at the moment of closing). Rejection strength = user decision + descriptive.
- **The AC10 gate as a one-line rg** (TRD version 0.1) — it is bypassed by line breaks and aliases (`const w = getCurrentWindow(); w.close()`) (TRD review Claude ⑦). Rejection strength = review.
- **Answer commands for a window outside the model with 「창 없음」 (no such window), as now** (behavior before U8b) — a command sent by the window button on the boot-failure screen (a stale popout that is not in the model · a warm window taken in whose role query failed) vanished silently (the web uses `fireAndForget`). Because the OS frame is stripped from these windows, even that screen needs a place to move and close the window (TRD §7-12 · ADR-0306 decision 2). Rejection strength = code.
- **Leave the tombstone for closing a window outside the model to `Destroyed`** (U8b review codex · 2026-10-26) — destruction queues on the event loop, so a window move or slot-detach confirmation in that gap attaches with this label and the `Destroyed` cleanup erases it along with the tabs that moved in. If the tombstone is placed first, that confirmation is rejected as `WindowClosed` and the tab stays at its source. Rejection strength = review (code).
- **The 「원래 크기」 command name `window.restore`** — it gets confused with the bus's `restore.*` (crash copy) (main-agent decision · TRD §6-1). Rejection strength = descriptive (weak — choosing a name).

## 영향 / 불변식

- **Invariant 3** — if the web calls a Tauri window-state API, the `noWindowControl` test turns red. A new window button · menu also goes registry command → invoke `window_control`.
- **Invariant 5** — only the first-paint gate and a human's tray show reveal a window waiting for first paint. Window-state commands and the LLM's show skip that window.
- `WindowControl` is called outside the layout lock, and the real implementation runs one action as one main-thread job — if split in two, the first-paint show interleaves and the deferral is left alone.
- `focused: false` is a normal reply — if another app is in front, the window is only raised to the top (intended). Whether the activation of `SW_RESTORE` synthesizes Alt has not been read in the tao path (likely not — QA measures it as AC9).
- The remaining gap for a window outside the model (accepted · M34): on that screen, pulling window facts ends with one `console.error` line after a bounded retry, and the maximize button's appearance does not follow the OS state.
- Known gap: there are no LLM commands for window move · size · snap (added to the remaining gaps in CLAUDE.md 「LLM-우선 제어」).
- Anchors — put `// ADR-0302` on `layout/window_ctl.rs` (`plan` · `close_if_empty` · `close_unmodeled`) · `layout/window_arg.rs` · `commands/window_ctl.rs` (the main-thread job) · the `Activation` branch of `tray::actions::show_main_ui` · platform `window::is_foreground` (decision 8) · `PopupCounter::next_label` in `commands/popout.rs` (the label form is built by `popup_label`).
