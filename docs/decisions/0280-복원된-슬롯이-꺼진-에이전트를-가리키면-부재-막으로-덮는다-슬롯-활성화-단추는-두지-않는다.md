# ADR-0280: When a restored slot points at an agent that is off, cover it with the absence veil — no slot activation button

- 상태: 확정 (2026-10-06, basis: user decision 2026-10-06 + implementation `e904161` code review (`/review code full` · 2 families · 5 rounds) · `/qa full` GUI (scratch data folder) · CI green (run 37429747731) · addendum the same day, 2026-10-06: decision 7 (closed the open item))
- 관련: Amends ADR-0149 (① the spawn-wait absorption of decision (A) ② the text of decision (C), for the slot whose profile was deleted ③ the judgment in the last item of the rationale that a dead indication must not flash right after a reserved node is activated, only for a reserved slot with no memory ④ the indication of the memoryless renderer among the known limits of the impact ⑤ the reason of the rejected alternative 「삭제도 흐림으로 통일」, only for a reserved slot with no memory) · ADR-0148(dimming + symbol · no text) · ADR-0165(shared veil — the leaf also draws that veil · not an amendment · back-link in that ADR's 관련 line · reason = 「영향」) · ADR-0059(empty / occupied decision) · ADR-0060(unknown slot content — requirement when persistence is introduced) · ADR-0168(focus ring strength 40% — why the ring is translucent) · TRD `docs/process/S21-storage/trd.md` §6-8 · §6-2 · §12 R10 · §14-18 · `docs/research/storage-management-survey-2026-10-02.md:19`(the source of 「대상 없음」 — user decision 2026-10-02) · `src/components/layout/LayoutLeaf.tsx`(decision · the leaf's veil · focus ring) · `src/components/slot/SlotUnavailableVeil.tsx`(shared veil — four drawing sides) · `src/components/agent/selectOpenTarget.ts`(unknown-content slot = occupied) · `src/store/viewStore.ts`(`foreign_slots` → cache) · step-log S21

## 맥락

When storage management (TRD S21-storage) restores a layout, a slot keeps its placement and `agent_id` as they were. But after a tray exit the daemon does not start agents automatically, so right after a restore an agent slot often points **at an agent that has a profile and is not running (`reserved`), with no memory of having mounted that agent** (TRD §6-8). When there is no memory, ADR-0149 sends the slot to (A) 「에이전트 연결 중…」 and accepted that limit as 「기억 없는 렌더러는 종료된 슬롯을 「연결 중」으로 표시한다」 — after a restore that 「연결 중」 never ends. TRD §6-8 puts four decisions in the spec that blocks this (F16 「무기한 「연결 중」 금지」 — fixed as spec by review · TRD §10), and for the one of them 「프로필 있음 · 실행 중 아님 · 기억 없음」 it planned a **「정지됨」 text + a 「활성화」 button** (the same `agentClient.spawnProfile` as tree activation).

Code review R1–R3 of the P3c3 implementation (`e904161`) produced, because of that button, a new defect across surfaces every round in keeping the activation state of the tree and the slot in step — duplicate activation by tree and slot (R1) · a shared activation door that is released before a refresh · a rejection marker left in the tree (R2) · a slot failure not visible in the tree · a menu that opens during activation · clearing the error (R3). After R3 the user changed the scope (decision 1).

The same TRD step also had the job of showing unknown slot content (a slot kind saved by a newer version — ADR-0060) in the frontend: the shell reported that slot as `ViewSnapshot.foreign_slots`, but the frontend dropped that field and saw an empty slot (TRD §9-2 「P3b 가 넘긴 것」).

## 결정

1. **A slot that points at an agent that is off (has a profile · not running (`reserved`) · no memory) looks the same as disconnected · dead — it is covered with the shared absence veil (dimming + a power-off icon · no text · no button). No activation button is put on the slot** (user decision 2026-10-06). Two user statements: ① 「기존에 종료된 에이전트 활성은 아직 기능이 없는거고 그냥 구현 안해도됨. 나중에 전체 resume 관련해서 따로 구현할거임」 ② 「에이전트 활성 시키면 똑같이 복원되겠지」. In fact, activating from the tree makes the slot attach to the normal screen by itself (「근거」 QA).
   - ★Session interpretation (not a user statement)★: the 「종료된 에이전트 활성」 of ① was read in this context as meaning both **the operation of turning on an off agent from the slot (slot-side activation)** and **full resume** — tree activation already works, and as in ②, it revives the slot. The scope of what was deferred (T-49) is this interpretation.
   - Examples: right after a layout restore (the common case) · pop-out · when the slot id changes and it is mounted again · A → B → A reassignment (reassignment drops the memory) · assigning a reserved id without activating it (the third case among the known limits in ADR-0149 「영향」).
   - ★This reverses, for this case only, the reason ADR-0149 rejected 「삭제도 흐림으로 통일」 (if an empty screen with nothing to pin is dimmed, it is misread as 「무언가 있었는데 죽었다」)★ — the empty cell of an off agent is now covered with dimming. A deleted agent (decision 3) still gets the text.
2. **「에이전트 연결 중…」 is used only before both the registry and the profile list have been received** — once the lists arrive, it always moves on to another decision. The 「스폰 대기도 연결 중」 of ADR-0149 (A) is replaced. The source of this line is TRD §6-8 (F16), and the user decision of this ADR is decision 1, which changed what is drawn in that place.
   - **As a result — the slot of a freshly created or freshly activated agent may briefly show the absence veil until that agent gets onto the registry.** ★Accepting this was a session judgment — not a user decision★: it carries on the acceptance of TRD §12 R10 (「수용 · [미검] 체감」 — at planning time it was written as 「정지됨」 flashing by). The last item of ADR-0149 「근거」 moved the decision axis to memory precisely to avoid this flash (a dead indication flashes right after a reserved node is activated) — this ADR replaces the judgment 「그 스침을 피해야 한다」 only for a reserved slot with no memory. The axis itself that splits whether to keep the view by memory is unchanged.
3. **A slot whose profile was deleted (after the list is received) shows the text 「대상 없음」.** This text comes from the record of the user decisions of storage management — `docs/research/storage-management-survey-2026-10-02.md:19` (「0. 결정 (2026-10-02 사용자 결정 · 대화)」: a slot with no target agent keeps its placement and is restored in a 「대상 없음」 waiting state). TRD §6-8 attached it to the 「프로필 없음」 decision, and it replaces the 「연결된 에이전트가 없습니다」 of ADR-0149 (C) (remove i18n `agent.noneConnected` and add `agent.noTarget`). **That cell keeps using the original agent-slot menu — including 「비우기」** (user decision 2026-10-06). In that cell you can, after emptying it with 「비우기」, place content · overwrite it directly with 「에이전트 모니터링」 · or close it.
4. **No 「비우기」 is put on an unknown-content slot** (user decision 2026-10-06). The user: overwriting with new content or closing the slot is enough. The placeholder of that cell ~~「이 버전이 모르는 내용」~~ (original text = `8f1a00a` · now a single icon — decision 7) belongs to TRD §6-2 and the menu is the empty-slot menu. Counting that cell as occupied (auto placement · tree 「열기」 does not pick that focused cell — the same answer as Rust `ViewManager::slot_is_free`) is the spec of TRD §6-2 (ADR-0059 · ADR-0060).
5. **The focus ring color does not change with the slot state — the ring is drawn over every veil** (user decision 2026-10-06). The residue the user accepted: the ring is translucent (accent color mixed at 40% — ADR-0168), so the visible color follows the background. A terminal slot has a fixed dark background, so in the light and e-ink themes the ring of a live terminal slot and the ring of a veil-covered slot look different (the dark theme is the same — QA pixel measurement). The user: leave it as is, and I will ask for a fix if it looks odd.
6. ★**The implementation below is a session judgment — it is not what the user chose**★ (`e904161`):
   - **The veil of decision 1 is drawn by the leaf (`LayoutLeaf`) — only when no slot component is shown.** That cell has no content to cover, so it covers nothing. It is the same component (`SlotUnavailableVeil`) as the veil inside the three slots (terminal · DOM · rich), and the two do not overlap in one cell (the head of that file).
   - **Focus ring** = z 10 → 20 · the last child of `[data-slot-border]` — drawn above both the leaf's veil and the veil inside a slot.
   - **Unknown-content slot** = `applyLayoutUpdated` puts `ViewSnapshot.foreign_slots` into the cache (`CachedView.foreignSlots`), and `selectOpenTarget` sees that slot as occupied and does not return that focused slot.
   - ~~**The one-line hint of the unknown-content slot** (`slot.foreignContentHint` — 「더 새 버전에서 저장한 내용입니다 — 다른 내용을 놓으면 사라집니다」) is the coder's and session's choice — TRD §6-2 wrote only the placeholder. Relation to ADR-0165 decision 5 (do not spell out state · cause as screen text): the latter part is not an agent state but a warning of slot-content loss (if other content is placed in that cell, the original disappears). ★But the former part says why that content is there (a newer version saved it) — the user has not decided whether to count that as the 「원인 문구」 of that policy (the open item in 「영향」 below)★.~~ → **Removed — decision 7.**
   - **The icon implementation of decision 7 (addendum after `8f1a00a`)** = lucide `FileQuestionMark` · in the same style as the power-off icon of the absence veil (`size-10 text-muted`), centered · the wrapping element gets `role="img"` · `aria-label` (name) · `title` (hover tooltip) · the automation marker `data-slot-foreign`. The choice of the icon · its size · the hover tooltip · the automation marker are session judgments (the name text is decision 7 — a user decision).
7. **The placeholder of an unknown-content slot is a single icon — no version distinction · no hint line · no veil** (user decision 2026-10-06 · addendum after `8f1a00a`). There is no on-screen text, no distinguishing of 「더 새 판이 저장했다」, no one-line hint, and since it is not an off agent, no veil (dimming) is laid on it. The meaning stays in the name · hover tooltip · automation marker — the name text 「알 수 없는 내용」 was approved by the user (the session recommended 「알 수 없는 내용」 and the user said 「ㅇㅇ … 통일 해도된다고 생각」 — after that, the user asked for an icon). The user: 「구지 새버전이라고 구분하지 않았으면 좋겠는데. 이게 되게 크리티컬한것도 아니고 그냥 쿨하게 없애버려도 되는 정보잖아」 — and asked for an icon like the power-off icon. This closes the open item in 「영향」 (whether the former part of the hint line counts as a 「원인 문구」 of ADR-0165 decision 5). Implementation = the last item of decision 6 (session judgment).

## 거부한 대안

- **The 「정지됨」 text + 「활성화」 button of TRD §6-8** (and the shared tree-and-slot activation door built for that button during review rounds) — the user's reason is the two statements of decision 1 (the reading of that scope = the session interpretation of decision 1). Added as fact: once that button was implemented, the activation state of the tree and the slot had to be kept in step, and new defects across surfaces continued through 3 review rounds (「맥락」 above).
- **Using the empty-slot menu as is for 「대상 없음」** (the intermediate implementation did) — the 「비우기」 that was originally on that slot disappeared. The user had the original agent-slot menu kept (decision 3).
- **Adding 「비우기」 to the unknown-content slot** — the user: overwriting with new content or closing is enough (decision 4).
- **An opaque fixed-color ring** (a proposal that removes even the translucency residue) — not done now. The user said to leave it and ask if it looks odd (decision 5).
- **A version-distinguishing text · one-line hint on the unknown-content slot** (the look of `e904161` — placeholder text + hint line) — the user: 「구지 새버전이라고 구분하지 않았으면 좋겠는데. 이게 되게 크리티컬한것도 아니고 그냥 쿨하게 없애버려도 되는 정보잖아」 (decision 7).

## 영향 / 불변식

- **What stays the same from ADR-0149** — (B) memory present + absent → keep the view · decision 4 (a disconnect is handled the same as (B)) · decision 5 (memory is one render mode) · the decision of (C) (「프로필이 없다」 is believed only after the list is received) · the rejection of the proposal to lift the overlay to the slot wrapper · the 「영향」 outside items ①–⑤ of the 관련 line above. What this ADR changed is only the five items of the 관련 line.
- **The leaf's veil is drawn only when no slot component is shown** — so the rejection in ADR-0149 of 「오버레이를 슬롯 래퍼(layout)로 승격」 remains valid: the leaf covers nothing. If the leaf drew a veil while showing a slot, the duplicated decision that rejection meant to prevent would arise.
- **The veil is one component** — the shared veil of ADR-0165 is now drawn by four sides, the three slots and the leaf. If the look diverges, the shared component has been bypassed (ADR-0149 「영향」 · the head of `SlotUnavailableVeil.tsx`). ★The number of drawing sides is a statement of fact, not a decision★ — the leaf draws as the fourth only in a cell that has no slot component, so in this respect neither ADR-0149 (「흐림·심볼은 세 슬롯이 한 벌로 그린다」 in 「영향」) nor ADR-0165 is amended. Both only get a link to this ADR from the 관련 line. The premise of ADR-0165 「영향」 (the drawing sides compute the same condition, so the same picture appears at the same time) also still stands — the leaf's condition differs from the condition of the three slots, but the leaf draws only in a cell that has no slot component, so there is no place in one cell where the two conditions could diverge.
- **If 「연결 중」 remains after the list has arrived, it is a regression** (decision 2 · F16) — after a restore, the slot of an off agent is trapped again in a 「연결 중」 that never ends.
- **The occupied decision for an unknown-content slot gives the same answer in the frontend and in Rust** — if only one side is changed, auto placement or tree 「열기」 overwrites the original text of the newer version (TRD §6-2).
- **The focus ring is the last child of `[data-slot-border]`** — if a veil is inserted after it or a veil is raised above the ring, the ring color follows the slot state again (decision 5).
- **Slot-side activation and full resume were deferred as a separate feature** (user decision 2026-10-06 — raised to the user again after the storage system is finished · `docs/tracking.md` T-49 · the scope is the session interpretation of decision 1). Do not bring the activation button back on the slot before that feature arrives — the tree-and-slot state-sync defects come back with it (「거부한 대안」).
- ~~★**Open item (not a decision)**★: whether the former part of the one-line hint of the unknown-content slot (「더 새 버전에서 저장한 내용입니다」) counts as a 「원인 문구」 of ADR-0165 decision 5 (decision 6).~~ → **Closed — decision 7 (user decision 2026-10-06).** Do not bring a version distinction or cause text back on that cell.
- ★**Not verified**★: the look of the ring in the light and e-ink themes (residue accepted — decision 5) · the order of moving from 「연결 중」 to 「대상 없음」 was observed only once (7 ms). Bonus observation: the slot context menu does not close with Escape (since before this change · not fixed).
