# ADR-0165: The slot-absence display is unified into one terminated icon and the veil is shared by the three slots

- 상태: 확정 (2026-08-20, basis: user decision (provisional) + code measurement) — the direction is a provisional decision approved as 「일단 이렇게」 (for now, like this) (decision 6)
- 관련: Amends ADR-0148 (scope of the no-wording clause: chat veil → shared by the three slots + removal of the terminal and DOM status wording) · ADR-0149(splitting absence into three states · wrapper promotion rejected) · ADR-0019(termination classification) · ADR-0226(pins the veil's pointer pass-through as a user decision (2026-09-24) · the takeover loading lifts once the veil is up — that ADR's 「구현 중 정정」) · `src/components/slot/SlotUnavailableVeil.tsx` · `src/components/slot/RichSlot.tsx` · `src/components/slot/TerminalSlot.tsx` · `src/components/slot/DomSlot.tsx` · ADR-0280(2026-10-06 — the leaf (`LayoutLeaf`) draws this veil as a fourth: a reserved slot with no memory · only on a cell that has no slot component, so it does not overlap the three slots in one cell · this is not an amendment of this ADR) · Amends ADR-0173 (the slot clause (the screen shows only an icon, the reason only on tree hover))

## 맥락

ADR-0148 decision 4 settled 「설명 문구를 넣지 않는다」 (do not put in explanatory wording), but its **scope was the chat veil** — the same clause narrowed its own scope by stating "leave the input box's existing disabled handling and wording as is". The terminal and DOM slots' own wording was outside that scope and survived.

As a result **the same fact was reported on three surfaces in three looks and three wordings** (code measurement — the state just before commit `db8197a`):

- Terminal: a central overlay covering the whole slot (`rgba(0,0,0,0.6)` · 13px) with `Failed: <메시지>` or `종료됨` (terminated).
- DOM: a small badge at the top right (11px) with the same two wordings.
- Chat: the wording-free veil that ADR-0148 set.

On 2026-08-20 the user directed the course: **unify into one terminated icon**. The implementation went into commit `db8197a` the same day, and this ADR is **a record pinned belatedly on 2026-08-21** (it was not left at the time of the decision). At that point the user also stated the reason — it is the ownership split in 「근거」 below, and the core of this ADR is not the *shape* of the icon but **where the failure cause lives**.

## 결정

1. **The log owns the failure cause, and the screen shows only a terminated icon.** This ownership split is the body of the decision. The absence display consists only of a translucent cover (`absolute inset-0` · `bg-background/70`) and a single lucide `PowerOff` icon, and has **zero text nodes** (`SlotUnavailableVeil.tsx:28-42`).
2. **Widen ADR-0148 decision 4's 「문구 없음」 (no wording) from the chat veil to all three slots.** Remove the status wording the terminal and DOM had (`종료됨` · `Failed: <메시지>`) and its i18n key (`agent.terminatedOverlay`).
3. **The veil is one shared component.** `src/components/slot/SlotUnavailableVeil.tsx` — the three slots draw it as one set. **The source of truth for the look and the ground is that file's header**, and that header already records the wording removal as a 2026-08-20 user decision.
4. **The condition is computed by the slot and the drawing is done by the shared component.** The overlay is not promoted to a layout wrapper — the proposal that ADR-0149 rejected stays rejected. The three slots each compute the same condition and pass it to this component (`RichSlot.tsx:114` · `TerminalSlot.tsx:63` · `DomSlot.tsx:104`, usage sites `RichSlot.tsx:379` · `TerminalSlot.tsx:380` · `DomSlot.tsx:215`).
5. **This is a policy, not a slot-local rule — 「다른 부분도 그렇게 해」 (the user, 2026-08-21).** (Do it that way in the other parts too.) Do not lay out state or cause as on-screen wording. **The current scope of application is the three slots**, and ★surfaces built from now on also follow this policy★. **Do not write a list of other surfaces here** — listing surfaces that have not been checked would itself become a false scope. The convention is to read this decision and apply it when building a new surface.
6. **The chat input box's own disabled wording stays.** The latter half of ADR-0148 decision 4 remains valid — the placeholder at `RichSlot.tsx:356-362` and `src/i18n/ko.ts:63` (`agent.terminatedPlaceholder`) are not deleted. What this decision widened is the **veil**, not the input box.
7. **★This direction is a provisional approval — not a closed position.★** In the user's words as is, 「일단은 그렇게 가자고 하긴 했음」 (we did say let's go that way for now). The reason the status is left as `확정` is **that it is implemented and running now**, and it is not meant to block reopening. It is not a convention violation if a next session reopens this direction — but when reverting, decision 2's unification of the three slots and decision 5's policy must be looked at together.

## 거부한 대안

- **Keep each surface's own wording** — the user directed unifying into one terminated icon, and the reason is the ownership split (**user-provided ground**): the cause stays in the log and the screen shows only the icon. The fact backing the rejection is also confirmed in code (**code measurement**): the same state came out on three surfaces in different wordings and different looks (the three items in 「맥락」 above).
- **Promote the overlay to a slot wrapper (layout) and cover from one place** — **source = the body of ADR-0149 「거부한 대안」** (not a user statement). There it was rejected as "duplicating RichSlot's existing decision and a refactor beyond scope", and this decision keeps that rejection while gathering **only the drawing place** into a shared component.

## 근거

- **User decision — the ownership split (directed 2026-08-20, reason confirmed 2026-08-21).** The user's words: 「실패 원인은 보통은 로그로 남기고 화면은 종료 아이콘으로만 해. 다른 부분도 그렇게 해. 나중에 릴리즈에서도 디버깅 화면을 따로 만들어도 되니까.」 (Usually leave the failure cause in the log and make the screen only a terminated icon. Do the other parts that way too. Because later, even in a release, we can build a separate debugging screen.) ★That is, the icon unification is not a matter of taste but **settles the place where cause information deliberately does not go**★ — the log owns the cause, and the screen does not speak for it. If it becomes needed, the answer is a **separate debugging screen**, and the user stated explicitly that it **may exist in release builds too**.
- **Provisionality (the user).** In the same place the user said 「일단은 그렇게 가자고 하긴 했음」. The direction has its grounds, but **it is not promoted to a closed conclusion**.
- **Code measurement (confirmed while writing this ADR — not a user statement).** ① The veil has zero text nodes ② the three slots compute and pass **the same ternary** (`agentGone || !connected || subscriptionDown`) ③ the wording before removal had two branches, `Failed: <메시지>` or `종료됨` (`TerminalSlot`·`DomSlot` just before `db8197a`) ④ input blocking remains in all three modes.
- ★Do not add reasons outside the three branches above to this place★ — filling in a ground that does not exist silently promotes a provisional approval into a closed decision.

## 영향 / 불변식

- **★The absence of the failure reason on the slot screen is intentional — bringing it back is the violation.★** Previously the reason was printed in the slot as `Failed: <메시지>`. One icon cannot tell terminated, disconnected and failed apart (not giving that distinction is the intent of ADR-0148 decision 1), and **the cause string belongs to the log under decision 1's ownership split**. Putting the cause string back on the slot surface is not an improvement but a breach of this decision.
- **If a need arises to see the cause with the eyes, the answer is a separate debugging screen** — not slot wording. It is the direction the user approved and **may exist in release builds too**. ★This ADR does not design that screen here★ — all this ADR pins is "if it becomes needed, we go in that direction".
- **The decision is per slot, the drawing is in one place.** The three slots compute the condition and pass it to the shared component, and the overlay was **not promoted to a layout wrapper** (ADR-0149 rejection kept). If the look splits, it is not that the convention was breached but that **the shared component was bypassed**.
- **That the condition is the same ternary in the three slots is the premise of this unification** (code measurement — `RichSlot.tsx:114` · `TerminalSlot.tsx:63` · `DomSlot.tsx:104`). If only one slot changes the condition, the same picture appears at different times.
- **Input blocking is kept in all three modes, separately from the drawing.** The veil is `pointer-events-none`, so the drawing alone cannot block operation — chat has the send guard and `disabled` (`RichSlot.tsx:234`·`:363`), the terminal has the `onData` guard (`TerminalSlot.tsx:364`), and DOM has no input to begin with (a read-only observer). **Do not delete these guards together when touching the veil.**
- **New surfaces are born under this policy** (decision 5). If a surface is newly built that lays out state or cause as on-screen wording, it was built without knowing this decision. That the current scope of application is the three slots is **not a scope limit but a list of the places touched so far**.
- **When bringing the wording back, do not fix just one slot.** What decision 2 widened is the *scope*, so putting wording back into only one slot breaks the unification and returns to the state before this ADR (three surfaces, three wordings). Reopening is done with a new decision that handles the three slots and the policy together.
