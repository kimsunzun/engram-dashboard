# ADR-0122: Deleting a tree entry = ending the agent's life — no orphaned live sessions; agents undergoing safe shutdown are blocked entirely

- 상태: 확정 (2026-07-31, basis: user decision — "트리에서 뺐는데 왜 세션이 따로 생존해 있는거야")
- 관련: ADR-0101 (name fallback — this decision removes the *occurrence condition* of the basename↔id fork) · ADR-0116 decision 3 (delete cleanup hook — stays) · ADR-0119 (single registry entry point) · ADR-0120 (names globally unique — this decision removes the root cause of the hole on the delete side) · `crates/engram-dashboard-daemon/src/connection_core.rs` (DeleteProfile arm) · `crates/engram-dashboard-core/src/agent/name.rs::canonical_name_or_id_fallback` · step-log S18.9

## 맥락

The A1 (single registry entry point) review pulled out a uniqueness hole. The name-uniqueness check hangs on three points — create, spawn, rename — but **profile deletion was in effect a fourth rename point**. The display-name override is stored in the profile, so deleting the profile makes the override vanish and the canonical name is demoted to `basename(cwd)`, and that demotion goes through no check at all. If an agent renamed to `alpha` is deleted **while alive**, its name collides with another live agent in the same folder, so letters addressed to that name are rejected and it drops out of all-recipient sends — the state ADR-0120 meant to remove is restored by one ordinary command. The doc-aware reviewer and the cross-family reviewer found **the same defect independently**.

Adding a fourth check point is blocked: even if we try to stop the demotion with an automatic suffix, **the profile in which to store the suffix has just vanished.** There is nowhere to pin the name.

So we raised the problem one level — why does a live agent without a profile exist at all. Currently deletion and shutdown are deliberately separated (DeleteProfile arm comment: "실행 중 세션은 별도 Kill" — a running session is killed separately). The user's decision was that the separation itself is wrong.

## 결정

**1. The agent tree is the screen that shows all agents.** There must be no live agent that is not in the tree — that would be a state where an agent the user does not know about is running.

**2. Removing from the tree = ending the agent's life.** There is no state where the entry is deleted but the session survives on its own. That is, "a live agent without a profile" becomes an unreachable state.

**3. If it is running, it is not torn out immediately — it can go through the safe shutdown path and be removed after a grace period.** A safe shutdown option can be set per agent.

**4. An agent in safe shutdown is blocked entirely = treated as dead** (user: "안전종료는 다 차단이야 그냥 죽었다고 생각하면 됨"). It is not alive as an address — the grace period does not create a new intermediate state that complicates the delivery decision. We do not add a fourth to the existing three states (alive / asleep / absent), and one in its grace period is on the **absent** side from the delivery point of view.

**5. Implementation timing = the follow-up management system structure slice** (user: "이건 나중에 생각해"). What the user pointed to be designed together in that slice: **a path that deletes an agent along with its folder**, and **the option of putting an agent into an unsearchable store ("trash")**.

**6. Until then A1 does not touch the delete path.** It adds no fourth check point and does not change the DeleteProfile behavior. The hole above is **recorded as a known exception** and closed together when the slice of decision 5 removes the root cause.

## 거부한 대안

- **Keep the current behavior (deletion and shutdown separate)** — rejected by the user's decision: "트리에 없는데 산 세션이 남으면 내가 원하지 않는 에이전트가 돌아가는데 이건 잘못된 거지." The loss of observability is the root problem, and the name collision is its symptom.
- **Change the name fallback from `basename(cwd)` to the unique id** — a direction the user proposed first (“폴더 이름이 아니라 고유 세션 id가 되야 되는 거 아님?”), and it does close the collision *structurally* (it does not block it with a check; it gives a name that cannot overlap). But `name.rs` has already recorded that fork — the frontend tree draws even a live session whose profile is gone as `basename(AgentInfo.cwd)`, so if only the backend falls to id, **the name seen on screen and the actual delivery address split** (the screen shows `proj`, but letters go only to `a3f8c1d2` → if the user gives instructions by looking at the screen, they fail). To match them the frontend must change too, which spreads to A2 and above. **Decision 2 removes that state itself, so this option becomes unnecessary** — the path that would take the fallback disappears. The fallback code stays as a defense (the edge where cwd is empty).
- **A temporary guard in A1 (reject deletion if a live session exists)** — the main agent recommended it, but the user put it on hold ("이건 나중에 생각해"). The hole would close now, but A1 would no longer be a "behavior unchanged" slice, and we would have to flip the assertions of the tests that sealed the current flow. Since the root cause is due to disappear under decision 5, we do not build a transitional device twice.
- **Introduce the grace state as a new fourth agent state** — it adds one more branch to the delivery decision (3 outcomes: delivered · parked · rejected). Decision 4 folds it into "treated as dead" and prevents the state axis from growing.

## 근거

- User decision (2026-07-31): "에이전트 트리는 에이전트 전체를 보여주는 내용임. 그럼 트리에서 안 보이는 세션이 살아있으면 내가 원하지 않는 에이전트가 돌아가는데 이건 잘못된 거지. 반대로 트리에서 뺐는데 왜 세션이 따로 생존해 있는 거야?" · "실행 중이면 바로 빼는 게 아니라 특정 에이전트는 안전종료옵션으로 둔다거나 해서 바로 빼지 않고 딜레이 후에 뺄 수도 있음." · "안전종료는 다 차단이야 그냥 죽었다고 생각하면 됨." · "해당 에이전트가 폴더째로 삭제되야 될 수도 있음 … 정 뭐하면 나중에 휴지통이라고 따로 에이전트 넣어두는 곳(탐색 안 되는 곳) 만들어둘 수도 있음."
- **The hole was confirmed in code** (two reviewers found it independently): the delete arm comment itself already recognized "the profile vanishes, so the override disappears and it is demoted to basename" (which is why the delete cleanup hook extracts the name *before deletion*), and that recognition was not connected to uniqueness.
- **The current separation was explicit design** (not conjecture): the DeleteProfile arm comment "실행 중 세션은 별도 Kill" (a running session is killed separately) + the existence of a test that sealed the live-session delete flow. That is, this ADR **reverses an explicit design**, not an accidental behavior.

## 영향 / 불변식

- **"A live agent without a profile" is an unreachable state** — after the slice of decision 5. Do not write new code that presupposes this state.
- **The basename↔id priority debate of `canonical_name_or_id_fallback` is not up for reopening** — because its occurrence condition disappears. The fallback itself stays as a defense for the empty-cwd edge, and a proposal to change the priority to "id first" creates tree≠routing **unless the frontend tree display is changed along with it** (ADR-0101).
- **The grace period does not grow the state axis** — the agent 3-state / message 3-outcome system stays (CLAUDE.md fixed terms).
- **The delete cleanup hook (ADR-0116 decision 3) stays** — even when deletion means shutdown, it is still necessary to close the parked items and open contracts addressed to that name. The hook also keeps deciding the gate **by profile id** (deciding by name would spin idle because of the demotion — that basis remains valid after decision 2).
- **★Known exception (time-limited)★** — under decision 6, at the A1 point a same-name live agent caused by deletion can still be created. Reproduction path: rename → spawn a second one in the same cwd → delete the first while it is alive. The result is rejection of letters that name it directly + omission from all-recipient sends. **The slice of decision 5 bears the responsibility of closing this exception** — before that, do not read "uniqueness is guaranteed globally" as unconditionally true.
- Unverified (to confirm at implementation): the grace length of safe shutdown · whether it can be cancelled · how the tree shows an entry during grace, the filesystem safeguards of folder-wide deletion, whether a trash item occupies a name (if it does, it comes into the scope of ADR-0120 uniqueness — this is the open item of the decision 5 slice).
