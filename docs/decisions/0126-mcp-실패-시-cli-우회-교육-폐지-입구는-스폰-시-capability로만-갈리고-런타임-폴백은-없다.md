# ADR-0126: Abolish teaching a CLI workaround when MCP fails — the entry is split only by capability at spawn, and there is no runtime fallback

- 상태: 확정 (2026-08-02, basis: user decision + findings of `/review doc full` round 2 — see the basis below) · 부분 폐기 by ADR-0128 (decision 3, keep the wiring) · 부분 폐기 by ADR-0211 (priming B dependency clause) · 부분 폐기 by ADR-0213 (removal of the priming escalation pin) · 부분 폐기 by ADR-0220 (separating the CLI and MCP spellings)
- 관련: Amends ADR-0099 (abolishing the engram-send fallback teaching and making the channel-consistency invariant one-directional) · ADR-0086 (dual entry · single wrap) · ADR-0125 (synchronous drain — a contract that raised the cost of duplicate sends) · `prompts/agent-priming.md` · `crates/engram-dashboard-daemon/src/control/priming.rs` · Amended by ADR-0128 (decision 3, keep the wiring) · Amended by ADR-0211 (priming B dependency clause) · Amended by ADR-0213 (removal of the priming escalation pin) · Amended by ADR-0220 (separating the CLI and MCP spellings)

## 맥락

ADR-0099 set priming A (for MCP-capable) as **"send_message primary + engram-send fallback"**, and the document spelled that fallback out like this:

> **Fallback:** if any attempt to reach a teammate **fails or errors for any reason**, don't stop there — run in your shell: `engram-send …`

During the priming revision to reflect slice C (ADR-0125), in `/review doc full` round 2 the doc-aware reviewer pulled out a defect in this sentence: its trigger condition is "fails or errors for any reason", so it **swallows even `pending`, which is a normal response.** `pending` is not a failure but "this call could not confirm delivery", yet if the agent reads it as a failure the fallback rule fires and re-sends the same letter through the CLI. **Under ADR-0125's synchronous drain, both are accepted normally and loaded into the queue and there is no duplicate-removal device, so the recipient receives the same letter twice.**

The wording could have been narrowed to block this, but the user pointed out a more fundamental problem: **the CLI was never a "workaround for when MCP is broken" in the first place.** The entry is already split at spawn time by backend capability (ADR-0099 decisions 2 and 3) — a backend that cannot use MCP receives priming B and does not even see the word `send_message`. So the only situation in which priming A's fallback can fire is, logically, **"MCP is attached but failed at runtime"**, and then working around it silently means **the breakage is never observed.**

## 결정

1. **Remove the CLI workaround teaching from priming A.** `prompts/agent-priming.md` teaches only `send_message` — remove entirely `engram-send`, the CLI flag notation, `--body-stdin` and all other descriptions attached to that path.
2. **Teach escalation instead (one body with the removal — do not separate).** If `send_message` is missing or keeps failing, the agent **does not work around it but reports to the principal that "the messaging channel is broken"**. If the fallback is removed and the place is left empty, two malfunctions remain: ㉮ by decision 3 `engram-send` stays on the PATH as it is, so an agent that rummages in the shell **finds and uses on its own a path that was not taught** (exactly the silent workaround this decision means to block) ㉯ or it silently drops the letter, so **the principal never learns of the breakage.** That is, "do not work around it" alone does not complete the decision — "what to do instead" must be in the same document.
3. **The physical wiring is not touched.** Even for MCP-capable spawns the `engram-send` PATH and env injection stay as they are (ADR-0099 decision 2 survives). Reason = to leave room to connect with the command family later (user decision).
4. **Revise the channel-consistency invariant to be one-directional.** ADR-0099's *"the set of laid channels **=** the set of channels the priming teaches"* no longer holds as an equality. What the measured evidence (the 6/7 no-send freeze) supports is only the one direction **"when a channel that was not laid was taught"**, so the invariant is restated as **taught channels ⊆ laid channels**. The state decision 3 creates (laid but not taught) falls inside this.
5. **There is no fallback to remove from priming B — but decision 2 applies to it too.** `prompts/agent-priming-cli.md` is the single surface for non-MCP backends and has no workaround teaching to begin with, so it is not a target of decision 1. But **the failure mode of silently dropping the letter when the only entry is broken is the same on both sides**, so the escalation teaching goes into both files in the same sentence (the surface difference = the tool name only).

## 거부한 대안

- **Only narrow the fallback sentence's trigger condition (state that `pending` and `failed` rows do not apply)** — it blocks duplicate sends but **keeps teaching the wrong mental model.** As long as we keep telling the agent "if MCP breaks, go another way", the breakage keeps being silently worked around. The user's rejection: "MCP 연결 없으면 연결을 해결해야지."
- **Keep ADR-0099 as is (keep the fallback)** — the reason ADR-0099 gave when rejecting hard single-channel was **the determinism axis only** ("auto mode is a transitional regime so airtight has no practical benefit · both-teaching no-regression 10/10 measured → soft is enough"). **The cost of hiding observability — if you work around a broken MCP the breakage is not seen — is an axis that ADR did not examine.** A new argument has appeared, so that reason for rejection no longer supports the decision.
- **Complete hard single-channel (remove even the physical injection of engram-send — the plan ADR-0099 had already rejected)** — if it is neither taught nor laid, consistency is restored as an equality, but the user rejected it: the wiring is left for use in connecting with the command family later. That is why decision 4's one-directional invariant became necessary, and decision 2's escalation teaching became the only device that prevents misuse of that remaining wiring.

## 근거

- **User decision (2026-08-02, conversation session).** The stated basis: the agent is connected 1:1 with the daemon and **already knows** whether it can use MCP — if it cannot, the connection is what should be fixed, not a matter of teaching the agent a workaround.
- **How it was found = `/review doc full` round 2 (doc-aware slot).** It traced that the priming's fallback sentence + the `pending` correction wording cut off in round 1 for length combine to make a duplicate-send path. That is, this ADR is a case where a document review drew out a design defect in reverse.
- **The missing axis in ADR-0099's reason for rejection** (rejected alternative 2 above). It matches the lesson left by the handoff document, *"if the reason for rejecting a rejected alternative is weak, that may be the right answer"* (the third real case after ADR-0121→0124 and 0124→0125).
- **The direction of the freeze measurement.** ADR-0099's `지시-도구 불일치 freeze` (instruction–tool mismatch freeze) (MCP exposed + CLI-only instruction = about 6/7 no-send) is a measurement of the case where **a channel that was not laid was taught** — the conclusion of that sentence also says only one direction, *"a channel that was not laid must be deleted from the prompt entirely"*.
- **Measured backing for making it one-directional (a reviewer's finding — the first item of ADR-0099 context).** *"The only real enforcement is physical provisioning (a channel that was not laid cannot be used), and **the choice among laid ones is decided by the priming** (measured: even if MCP is visible, with CLI priming the CLI is used)."* That is, **a channel that is laid but not taught is simply not used** is ADR-0099's own observation. Decision 4's inclusion relation comes from this sentence.
- **★But that measurement is the mirror direction (stated honestly).** The above observation is *untaught MCP + CLI priming* and this configuration is *untaught CLI + MCP priming*. The mechanism is surface-neutral and the affordance slope is more favorable on this side (a taught channel shows up in the tool list, while an untaught channel requires shell exploration), but **"engram-send laid on the PATH + MCP-only priming" has never been measured by anyone.** This decision is recorded as *inferred* from that sentence, not observed.

## 영향 / 불변식

- **Channel-consistency invariant (revised) — taught channels ⊆ laid channels.** Teaching a channel that was not laid brings back the send freeze (ADR-0099 measurement). Not teaching a laid channel is allowed, and decision 3 creates that state on purpose. When adding a new backend or channel, check this inclusion relation.
- **Priming A single surface is invariant** — if `engram-send` or CLI flags come back into `prompts/agent-priming.md`, that is a regression of this decision. Check: `rg "engram-send|--to |--body|--request|--reply-by|--reply-to" prompts/agent-priming.md` → 0 lines.
- **grants are invariant** — the grants of an MCP-capable spawn stay `[Mcp, Cli]` (ADR-0099 decision 2). It is a NO-OP now because of auto mode, but when a future shared constraint layer is attached, "whether to keep emitting the grant for a channel that is not taught" will be decided again at that point.
- **★Unverified — the biggest blank of this decision★:** the send reliability of the direction that **reduced** the taught channels has not been measured. ADR-0099's 10/10 no-regression measurement is of *both-teaching*, not of *MCP-only teaching*. The measuring means is `roundtrip_smoke` (`--bin roundtrip-smoke`).
- **★Unobserved — whether the escalation instruction actually takes effect★:** decision 2 puts "report to the principal" into the priming, but in a situation where MCP is really broken, whether the agent **follows that instruction · still finds and uses `engram-send` in the shell · or silently gives up** has not been observed. Since decision 3 leaves the wiring, the split among these three hangs on a single priming sentence (ADR-0099: in auto mode the grant is a NO-OP so there is no enforcement other than physical provisioning). **If a shell workaround or silent giving-up is observed, it is a sign that strengthening the priming wording is not enough**, and then decision 3 (keeping the wiring) is reopened.
