# ADR-0126: MCP 실패 시 CLI 우회 교육 폐지 — 입구는 스폰 시 capability로만 갈리고 런타임 폴백은 없다

- 상태: 확정 (2026-08-02, 근거: 사용자 결정 + `/review doc full` 2라운드 적출 — 아래 근거) · 부분 폐기 by ADR-0128 (결정 3 배선 존치)
- 관련: Amends ADR-0099 (engram-send 폴백 교육 폐지와 채널 정합 불변식 단방향화) · ADR-0086(듀얼 입구·단일 wrap) · ADR-0125(동기 드레인 — 중복 발송의 대가를 키운 계약) · `prompts/agent-priming.md` · `crates/engram-dashboard-daemon/src/control/priming.rs` · Amended by ADR-0128 (결정 3 배선 존치)

## 맥락

ADR-0099는 프라이밍 A(MCP-capable용)를 **"send_message 주력 + engram-send 폴백"**으로 정했고, 그 폴백을 문서가 이렇게 풀어 썼다:

> **Fallback:** if any attempt to reach a teammate **fails or errors for any reason**, don't stop there — run in your shell: `engram-send …`

슬라이스 C(ADR-0125) 반영을 위한 프라이밍 개정 중 `/review doc full` 2라운드에서 doc-aware 리뷰어가 이 문장의 결함을 적출했다: 발동 조건이 "어떤 이유로든 실패·오류"라 **정상 응답인 `pending`까지 삼킨다.** `pending`은 실패가 아니라 "이번 호출이 배달을 확인하지 못했다"인데, 에이전트가 이를 실패로 읽으면 폴백 규칙이 발동해 같은 편지를 CLI로 재발송한다. **ADR-0125의 동기 드레인 하에서는 두 통 다 정상 접수돼 큐에 적재되고 중복 제거 장치가 없으므로, 수신자가 같은 편지를 두 번 받는다.**

문구를 좁혀 막을 수도 있었으나, 사용자가 더 근본적인 문제를 지적했다: **애초에 CLI는 "MCP가 고장났을 때의 우회로"가 아니다.** 입구는 스폰 시점에 백엔드 capability로 이미 갈린다(ADR-0099 결정 2·3) — MCP 불가 백엔드는 프라이밍 B를 받고 `send_message`라는 단어조차 보지 못한다. 따라서 프라이밍 A의 폴백이 발동할 수 있는 상황은 논리적으로 **"MCP가 붙어 있는데 런타임에 실패했을 때" 하나뿐**이고, 그때 조용히 우회하면 **고장이 관측되지 않는다.**

## 결정

1. **프라이밍 A에서 CLI 우회 교육을 제거한다.** `prompts/agent-priming.md`는 `send_message`만 가르친다 — `engram-send`·CLI 플래그 표기·`--body-stdin` 등 그 경로에 딸린 서술을 전부 걷어낸다.
2. **대신 에스컬레이션을 가르친다(제거와 한 몸 — 분리 금지).** `send_message`가 없거나 계속 실패하면 에이전트는 **우회하지 말고 principal에게 "메시징 채널이 고장났다"고 보고**한다. 폴백을 빼고 자리를 비워 두면 두 가지 오작동이 남는다: ㉮ 결정 3으로 `engram-send`가 PATH에 그대로 남으므로, 셸을 뒤진 에이전트가 **가르치지 않은 경로를 스스로 찾아 쓴다**(이 결정이 막으려는 바로 그 조용한 우회) ㉯ 아니면 편지를 조용히 버려 **principal이 고장을 영영 모른다**. 즉 "우회하지 마라"만으로는 결정이 완결되지 않는다 — "대신 무엇을 하라"가 같은 문서에 있어야 한다.
3. **물리 배선은 건드리지 않는다.** MCP 가능 스폰에도 `engram-send` PATH·env 주입은 그대로 유지한다(ADR-0099 결정 2 생존). 사유 = 나중에 커맨드 계열과 연결할 여지를 남긴다(사용자 결정).
4. **채널 정합 불변식을 단방향으로 개정한다.** ADR-0099의 *"깐 채널 집합 **=** 프라이밍이 가르치는 채널 집합"*은 등호로 성립하지 않게 됐다. 실측 근거(6/7 미발신 freeze)가 뒷받침하는 것은 **"안 깐 채널을 가르쳤을 때"** 한 방향뿐이므로, 불변식을 **가르치는 채널 ⊆ 깐 채널**로 고쳐 박는다. 결정 3이 만드는 상태(깔았지만 안 가르침)가 이 안에 들어온다.
5. **프라이밍 B에는 걷어낼 폴백이 없다 — 단 결정 2는 같이 적용한다.** `prompts/agent-priming-cli.md`는 비-MCP 백엔드용 단일 표면이라 애초에 우회 교육이 없으므로 결정 1의 대상이 아니다. 그러나 **유일한 입구가 고장났을 때 편지를 조용히 버리는 실패 모드는 양쪽이 동일**하므로 에스컬레이션 교육은 두 파일에 같은 문장으로 넣는다(표면 차이 = 툴 이름뿐).

## 거부한 대안

- **폴백 문장의 발동 조건만 좁히기(`pending`·`failed` 행은 해당 없음을 명시)** — 중복 발송은 막지만 **틀린 멘탈모델을 그대로 가르친다.** 에이전트에게 "MCP가 깨지면 다른 길로 가라"고 계속 말하는 한, 고장은 계속 조용히 우회된다. 사용자 기각: "MCP 연결 없으면 연결을 해결해야지."
- **ADR-0099 현상 유지(폴백 존치)** — ADR-0099이 hard 단일채널을 기각할 때 든 사유는 **결정성(determinism) 축뿐**이었다("auto mode가 임시 체제라 airtight의 실익이 없다 · both-teaching 무회귀 10/10 실측 → soft로 충분"). **관측성 은폐 비용 — 고장난 MCP를 우회하면 고장이 안 보인다 — 은 그 ADR이 검토하지 않은 축이다.** 새 논거가 등장했으므로 기각 사유가 더 이상 결정을 지탱하지 못한다.
- **hard 단일채널 완성(engram-send 물리 주입까지 제거 — ADR-0099이 이미 기각했던 그 안)** — 가르치지도 깔지도 않으면 정합이 등호로 복원되지만, 사용자가 기각: 나중에 커맨드 계열과 연결할 용도로 배선을 남긴다. 그래서 결정 4의 단방향 불변식이 필요해졌고, 결정 2의 에스컬레이션 교육이 그 잔존 배선의 오용을 막는 유일한 장치가 됐다.

## 근거

- **사용자 결정(2026-08-02, 대화 세션).** 근거 진술: 에이전트는 데몬과 1:1로 연결돼 있어 자기가 MCP를 쓸 수 있는지 **이미 안다** — 못 쓰면 연결을 고칠 일이지 에이전트에게 우회로를 가르칠 일이 아니다.
- **발견 경위 = `/review doc full` 2라운드(doc-aware 슬롯).** 프라이밍의 폴백 문장 + 1라운드에서 분량 사유로 잘려나간 `pending` 보정 문구가 결합해 중복 발송 경로가 성립함을 추적했다. 즉 이 ADR은 문서 리뷰가 설계 결함을 역으로 끌어낸 사례다.
- **ADR-0099 기각 사유의 축 누락**(위 거부한 대안 2번). 인계 문서가 남긴 교훈 *"거부한 대안의 기각 사유가 약하면 그게 정답일 수 있다"*(ADR-0121→0124, 0124→0125에 이어 세 번째 실사례)에 해당한다.
- **freeze 실측의 방향성.** ADR-0099의 `지시-도구 불일치 freeze`(MCP 노출 + CLI-only 지시 = 약 6/7 미발신)는 **안 깐 채널을 가르친** 경우의 실측이다 — 그 문장의 결론도 *"안 깐 채널은 프롬프트에서 완전히 삭제해야 한다"*로 한 방향만 말한다.
- **단방향화의 실측 뒷받침(리뷰어 적출 — ADR-0099 맥락 첫 항목).** *"유일한 실질 강제력은 물리 provisioning(안 깐 채널은 못 쓴다)이고, **깐 것들 사이의 선택은 프라이밍이 결정**한다(실측: MCP가 보여도 CLI 프라이밍이면 CLI 사용)."* 즉 **깔렸지만 안 가르친 채널은 그냥 안 쓰인다**는 것이 ADR-0099 자신의 관측이다. 결정 4의 포함관계는 이 문장에서 나온다.
- **★단 그 실측은 거울 방향이다(정직 명시).** 위 관측은 *안 가르친 MCP + CLI 프라이밍*이고 이번 구성은 *안 가르친 CLI + MCP 프라이밍*이다. 기제는 표면 중립이고 affordance 기울기는 이쪽이 더 유리하지만(가르친 채널은 툴 목록에 뜨고, 안 가르친 채널은 셸 탐색이 필요하다), **"PATH에 깔린 engram-send + MCP-only 프라이밍"은 아무도 측정한 적이 없다.** 이 결정은 관측이 아니라 그 문장에서 *추론*한 것으로 기록한다.

## 영향 / 불변식

- **채널 정합 불변식(개정) — 가르치는 채널 ⊆ 깐 채널.** 안 깐 채널을 가르치면 발신 freeze가 재발한다(ADR-0099 실측). 깐 채널을 안 가르치는 것은 허용되며 결정 3이 그 상태를 의도적으로 만든다. 새 백엔드·새 채널 추가 시 이 포함관계를 확인할 것.
- **프라이밍 A 단일 표면 불변** — `prompts/agent-priming.md`에 `engram-send`·CLI 플래그가 다시 들어오면 이 결정의 회귀다. 검사: `rg "engram-send|--to |--body|--request|--reply-by|--reply-to" prompts/agent-priming.md` → 0줄.
- **grants는 불변** — MCP 가능 스폰의 grants는 `[Mcp, Cli]` 그대로다(ADR-0099 결정 2). 지금은 auto mode라 NO-OP지만, 미래 공용 제약 레이어가 붙을 때 "가르치지 않는 채널의 grant를 계속 방출할 것인가"를 그 시점에 재결정한다.
- **★미검증 — 이 결정의 가장 큰 빈칸★:** 가르치는 채널을 **줄인** 방향의 발신 신뢰성은 실측되지 않았다. ADR-0099의 10/10 무회귀 실측은 *both-teaching*의 것이지 *MCP-only 교육*의 것이 아니다. 실측 수단은 `roundtrip_smoke`(`--bin roundtrip-smoke`)다.
- **★미관측 — 에스컬레이션 지시가 실제로 먹히는가★:** 결정 2가 "principal에게 보고하라"를 프라이밍에 넣지만, MCP가 실제로 고장난 상황에서 에이전트가 **그 지시를 따르는지 · 그래도 셸에서 `engram-send`를 찾아 쓰는지 · 아니면 조용히 포기하는지**는 관측된 바 없다. 결정 3이 배선을 남겨 둔 이상 이 셋의 갈림은 프라이밍 문장 하나에만 걸려 있다(ADR-0099: auto mode에서 grant는 NO-OP이라 물리 provisioning 외의 강제력이 없다). **셸 우회나 조용한 포기가 관측되면 프라이밍 문구 강화로는 부족하다는 신호**이고, 그때 결정 3(배선 존치)을 재론한다.
