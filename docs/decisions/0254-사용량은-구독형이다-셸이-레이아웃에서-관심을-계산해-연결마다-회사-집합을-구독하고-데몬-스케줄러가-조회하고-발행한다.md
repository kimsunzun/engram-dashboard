# ADR-0254: Usage is subscription-based — the shell computes interest from the layout and subscribes a company set per connection, and the daemon scheduler queries and emits

- 상태: 확정 (2026-09-27, basis: user decision, TRD §7 #10 — reversed #2 the same day)
- 관련: TRD §7 #2(discarded draft — pull type) · §7 #10 · §6 #25(the cross-check gap and the ⟳ remedy) · §6 #28(minimized = visible) · ADR-0046(resubscribe deps lesson) · step-log S21

## 맥락
We had to decide whether the usage query timing is set by client polling or scheduled by the daemon on a subscription basis. At first it was set as "request (pull) type — daemon cache + refresh when stale" (§7 #2, discarded in the TRD record), but the user reversed it the same day.

## 결정
Usage is **subscription-based**. The shell computes **interest from its own layout** (the companies turned on by usage slots in the active tab of a visible window) and **subscribes a company set per connection**, and the **daemon scheduler** counts the cooldown · reset and queries and emits. When a subscription is added, the first snapshot is sent to that connection. Each broadcast also carries that connection's `subscribed` set so the shell cross-checks (if they differ, it is sent back and fixed on the spot). ⟳ = forced re-send of the subscription followed by a query request (re-sending the subscription and refreshing are one action).

## 거부한 대안 (user)
- **Frontend 60-second poll + decide at request time** — the daemon holds the cooldown, but if the client alone holds the trigger, the polling and delay remain as they are.
- **Re-sending everything every 30 seconds** — 「사이드 이슈 때문에 30초마다 매번 보내는 걸 추가한다고?」 — unnecessary traffic.

## 거부한 대안 (internal — §3, paths where an ordering hole appeared in every re-review)
- The webview computes interest and reports it to the shell + ordering rules such as seq/`load_gen`/`StaleGen` reissue — it becomes a second copy of a layout the shell already has, repeating the same lesson as ADR-0046.
- A paired subscribe/unsubscribe message — a lost unsubscribe = the query goes on.
- Sending the first snapshot while holding the lock · a tokio task scheduler · an all-connection broadcast · the shell emitting without filtering · each caller re-reading and sending the set · forgetting `revision` on a connection-state transition alone · reporting hidden through `visibilitychange` · building the JSON anew for each connection · computing interest from the layout notification.
- A handoff where a new window sends the daemon a read-only wire request for the value instead of using the shell cache — condition to revisit: move it if the cache rules grow beyond the present four.

## 근거

## 영향 / 불변식
A minimized window counts as a **visible window** (the query goes on, and only a tray hide removes interest — user decision, §6 #28). A connection with no subscription at all is left with a gap that has no cross-check trigger, and **⟳ is the remedy** (§6 #25 — a gap that remains even after ⟳ is filled by another company's event · a layout change · a new socket).
