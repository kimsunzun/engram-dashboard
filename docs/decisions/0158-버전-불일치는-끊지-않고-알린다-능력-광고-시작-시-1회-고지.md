# ADR-0158: A version mismatch is announced, not cut off — capability advertisement + a one-time notice at startup

- 상태: **폐기 (Superseded by ADR-0178)** — the decision moved from **capability advertisement at attach time** to the **daemon handshake**, and ★**it flipped to cutting off on mismatch**★. So this ADR's top-level clause 「끊지 않는다」 (do not cut off), decision 2 (the `AgentEvent::Hello` advance advertisement + 「광고에 없는 명령은 보내지 않는다」 (do not send a command that is not in the advertisement)), and decision 4 (a one-time banner at startup — its place moves to a 「연결 거절 팝업」 (connection-refused popup)) **die**. ★But decision 1 (the `PROTOCOL_VERSION` bump criterion = envelope grammar breakage) and decision 3 (no automatic daemon kill) live on, and ADR-0178 carries them over unchanged★ — in fact decision 1 is the ground for that reversal (the version is bumped only when the grammar breaks, so a mismatch = the two sides cannot understand each other). The contrast between the clauses that die and the clauses that live is in ADR-0178 「영향 / 불변식」, which is the source of truth. ~~확정 (2026-08-14, basis: user decision + `/research medium` (peer survey in 3 strands + cross-family adversarial review))~~
- 관련: `crates/engram-dashboard-protocol/src/lib.rs`(`PROTOCOL_VERSION` and its bump history) · `AgentEvent::Hello`(the place where the daemon advertises its full capabilities) · `crates/engram-dashboard-discovery`(the daemon is refused on a version mismatch) · ADR-0157(layering of unknown slots) · TRD S20 §4-① · step-log S20.3

## 맥락

The daemon **exists to survive the app being closed** — it holds the live agent sessions. Deployment is unpacking an archive, so the install has no step that kills the daemon. So **a combination where only the app is new and the daemon is old happens as a normal case.** It is unrelated to the frontend and shell shipping together as one deliverable — the cause of the split is not the deployment unit but the **lifetime of the daemon**.

`PROTOCOL_VERSION` is a single integer and the check is **an equality comparison**. On a mismatch the client rejects that daemon and does not start a new daemon on top of it either, so until the user kills it by hand the app cannot attach and the agents it was holding are stuck. At the 1→2 bump an endless 「재연결 중」 (reconnecting) with no visible reason actually occurred, and the 「불일치 시 팝업 가이드」 (popup guide on mismatch) in the original design is still unimplemented.

S20 Step 2 added 3 commands to the protocol, which reopened this question. The old daemon **cannot even decode** that envelope, and the error it returns carries no correlation marker, so the sender waits forever. The earlier v3 bump had exactly the same cause, so **by convention we should bump.**

## 결정

**Do not cut off. Even on a mismatch, keep it working as is, and announce once at startup.**

1. **Do not bump `PROTOCOL_VERSION`.** Keep the constant, but narrow the bump criterion to **「실행에 크게 지장 있을 때」** (when execution is seriously impaired) (a change that breaks the envelope grammar itself). Adding a command is not at that level.
2. **Look at the peer's capabilities before sending.** The daemon advertises its own capabilities first, with `AgentEvent::Hello` right after the connection, so **there is no moment at all when a new app sends something unknown to an old daemon.** If it is not in the advertisement, that command is not sent.
3. **Do not kill the daemon automatically.** It must not be killed without knowing what is running (user decision).
4. **Notice = once at app startup, announce only.** If it is closed, leave a small state trace so it can be expanded again later. **Do not add an action (replace) button.** A modal only when the app cannot attach at all.
5. **Lay down together the two things that are needed regardless of version** — a deadline on every request, and a correlation marker on errors. These two prevent **different failures** from version negotiation.

## 거부한 대안

- **Bump the version by convention** — the extent of the damage flips. If we do not bump, 「그 명령을 실제로 쓴 사람의 요청 하나」 (the one request of a person who actually used that command) fails, but if we bump, **every user who upgrades** cannot attach to the app as long as the daemon is alive and all agents are stuck. The survey found that **automatic kill+restart is used only 「잃을 게 없을 때」 (when there is nothing to lose)** (as with a build cache, which can be recomputed), and those that hold sessions either do not replace automatically or changed the architecture altogether.
- **Bump but guide with a modal** — the notification guideline is against it. A modal is for 「지금 하려는 일이 막혔다」 (the thing you are trying to do right now is blocked), and the vendor guideline's explicit branch is to send a state that arose automatically, without the user asking, to a band (banner). Also the cost of over-notification is measured — the warning-ignore rate is high, and in the end users turn off that app's notifications altogether.
- **Silently disable only the feature, with no notice** — the user can never resolve 「왜 이게 안 되지」 (why doesn't this work). The GUI precedents surveyed all show something as well.
- **Remove the version concept** — it is still needed for changes that truly break the envelope grammar. It is narrowing, not removing.

## 근거

- **It was confirmed by measurement that there is no need to ask the old daemon.** `AgentEvent::Hello` carries 「데몬 전체 능력」 (the daemon's full capabilities) (the comment states so explicitly) and arrives in the daemon→client direction right after the connection. And this protocol crate has **not one declaration that rejects an unknown slot.** So the old daemon says only what it knows, and the new app reads an absent item as absent. The hole the adversarial review pointed out — 「능력 협상은 이미 설치된 옛 상대에게 물어볼 길이 없으면 성립하지 않는다」 (capability negotiation does not hold if there is no way to ask the old peer that is already installed) — is **already closed in our structure.**
- **Industry practice has moved away from 「버전 숫자 하나로 전부 끊기」 (cut everything off on a single version number).** There are cases that give each message type its own version range so that adding one does not affect the rest, cases that layer version and capability as separate tiers, and cases where the documentation openly recommends 「버전 숫자로 비교하지 말고 기능이 있는지 물어라」 (do not compare by version number; ask whether the feature exists).
- **「무한 대기」 (waiting forever) cannot be seen as only a version problem** — the adversarial review's point. A deadline only cuts the wait, and a correlation marker is attached only when the peer could open the envelope. To be precise, **the version mismatch exposed two defects that were already there**, which is why we lay down all three (capability check · deadline · correlation).
- **The notice timing follows the scope of impact** — if a specific action is blocked, notify at that spot; **if the condition stays in effect, notify at the app level in advance**. An old daemon is a condition that persists the whole time it is attached.

## 영향 / 불변식

- **Do not send a command that is not in the advertisement.** If this discipline breaks, an unknown envelope goes to the old peer, and without a deadline that request stops forever.
- **The capability-advertisement slot must not break when absent** — the old daemon not sending it is the normal path. Making it a required slot collapses this decision.
- **Limit a `PROTOCOL_VERSION` bump to 「봉투 문법이 깨질 때」** (when the envelope grammar breaks). Do not bump it for adding commands or fields.
- **Do not build a path that kills the daemon automatically.**
- **The notification surface does not add a new global handle; it rides on the existing control surface** (CLAUDE.md 「LLM-우선 제어」). The LLM must be able to read the same information — what is shown to a person and what automation reads must come from the same source, which is the standard practice confirmed in the survey.
- **Banked as a long-term direction (not in this scope):** run generations side by side and keep the old daemon alive until its own sessions end (the formal technique of the proxy-server family). It is the only way to solve 「데몬을 죽이면 안 된다」 (the daemon must not be killed) by structure.
