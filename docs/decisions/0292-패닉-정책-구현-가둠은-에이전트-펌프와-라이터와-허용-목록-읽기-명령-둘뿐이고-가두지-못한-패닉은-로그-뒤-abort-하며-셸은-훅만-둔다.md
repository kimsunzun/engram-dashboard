# ADR-0292: Panic policy implementation — confinement covers only the agent pumps, the writer, and two allow-listed read commands; a panic that was not confined is logged and then aborts; the shell gets only the hook

- 상태: 확정 (2026-10-12, basis: user decision 2026-10-11~12 · TRD `docs/process/S21-panic-policy/trd.md` edition 11 §3 · research `docs/research/panic-practice-peers-2026-10-12.md`) · 부분 폐기 by ADR-0293 (the command-side allow list of decision 2)
- 관련: Amends ADR-0288 (the confinement scope of decisions 1 and 2, and decision 3) · Amends ADR-0290 (the return to normal exit in decision 1, and decision 2) · ADR-0159 (a bus command panic = `INTERNAL`) · ADR-0262 (claude leftover cleaner K7 — a guard that relies on abort) · ADR-0199 (the channel does not shut itself off) · ADR-0005 (finalize once) · ADR-0001 (kill causality) · Amended by ADR-0293 (the command-side allow list of decision 2) · Amends ADR-0199 (the abort premise of the release-unreachable basis) · Amends ADR-0226 (the abort premise of the latch catch_unwind basis) · Amends ADR-0233 (the pump-Failed description of a reader-port panic) · Amends ADR-0262 (the abort premise of K7 and the implementation's catch_unwind guard) · Amends ADR-0275 (the abort premise of the context and the S2 basis) · Amends ADR-0281 (the abort description of a dialog panic) · Amends ADR-0142 (the abort premise of the accepted residue)

## 맥락

ADR-0288 decided 「요청 하나 · 에이전트 하나의 패닉은 그것만 실패시키고 공유 상태에서 나면 정상 종료한다」, and ADR-0290 decided 「가두지 못한 패닉은 훅이 정상 종료 신호를 당긴다」. The TRD for implementing them went through 10 editions, but nearly all the holes that 9 review rounds found came from the 「패닉 뒤 정상 종료 꼬리」 (the watcher thread · waiting for the reason · waking the shell · re-checking the Exit callback), and the user stopped it with 「케이스별로 복잡하게 하는 느낌」. Next, with the proposals (options (가) · (나)) that 「요청 전부를 가두려면 공유 락 오염 규칙이 필요하다」 on the table, the user asked 「우리가 너무 민감하지 않나」, and the research answered that 「가두지 못한 패닉 = 끝」 is a common shape and that the confinement scope is usually narrowed to units that do not change state.

## 결정

1. **A panic that was not confined = log the reason and `std::process::abort`.** No normal-exit tail · watcher thread · lock poisoning policy is put in (the same result as today's release abort). — This changes the 「정상 종료 경로를 탄다」 of ADR-0288 decision 3 · ADR-0290 decision 1, and its decision 2 (the 「ADR-0289 전체 폐기」 of ADR-0290 decision 1 stands).
2. **What is confined is only units that do not change state or that belong only to that agent** (rust-analyzer style · it narrows the scope of ADR-0288 decisions 1 · 2):
   - Agent side — the three output pumps (PTY · stdio · codex reader) and the input writer. A confined panic = that agent `Failed` · input rejected.
   - Command side — an **explicit allow list** of two, `agent.list` · `agent.listQueuedInputs`. A confined panic = an `INTERNAL` reply (ADR-0159). The condition for putting a command on the list = its body has no effect (if it has an effect, the folding of a panic must be `OUTCOME_UNKNOWN`, so the folding is decided again first).
   - Everything else (requests that change state · activation · control HTTP · MCP tools · `usage.get` · the shell · background threads) is not confined → decision 1.
3. **Even inside confinement, a call that changes agent shared state turns the marker off** (a panic inside it = decision 1) — recording the codex first-turn session id · usage observation · the writer's `on_written` · the claude decoder's door operation (ADR-0262 K7 relies on abort). The marker scope is limited to inside the `catch_unwind` closure, and `finish` runs outside the marker.
4. **The shell installs only the hook** (no confinement · a shell panic = decision 1).
5. **The notice of a confined panic is the current surface as it is** (`Failed` · input rejected · `INTERNAL`) — the details are in the log. The hook logs regardless of the marker, and the log's self-deadlock is closed with a thread-local marker on the log side.
6. **After a confined pump panic the CLI ends through the existing cleanup path** (`finish` → reaper → session release → group owner drop → `KILL_ON_JOB_CLOSE`). For each pump kind, a real-process test checks that the CLI tree disappears within the deadline, and if it fails, go to rejected alternative 4 below.
7. **The release unwind switch is the very last line** (delete `panic = "abort"` in `Cargo.toml`) — the earlier units do nothing under abort, so the rollback = that one line.

## 거부한 대안

- **Run a panic that was not confined through the normal-exit tail (the original of ADR-0288 decision 3 · ADR-0290 decision 2)** — user 「복잡하게 할 필요없음」 (2026-10-11~12). Basis = nearly all the holes in the 9 review rounds of TRD edition 10 came from that tail (`.claude/handoff/attachments/panic-trd-review-r2~r9-2026-10-11.md`).
- **Confine every request and put in a shared-lock rule (option (가) B of TRD edition 11 draft `bedda3f3` = exit immediately on meeting poisoning in a shared lock · option (나) E = turn the marker off in a multi-step shared-change section — then main's proposal 「공유 락을 쥔 동안 표시를 끈다」)** — user decision ② (2026-10-12). Basis = research conclusions 2 · 4: most of the sample confines only units that do not change state (rust-analyzer leaves state-changing handling 「isn't guarded by `catch_unwind`」), and no precedent was found for the mechanism of 「공유 락을 쥔 동안 표시 끄기」. Narrowing removes the lock poisoning policy · the multi-step section mechanism entirely.
- **Decide command confinement by an `effect == Read` predicate** — `usage.get` is `Read`, yet it launches a usage query and sets an in-progress slot (`agent/src/commands.rs:334-337` · daemon `usage_service` `book.rs:279-282` · `mod.rs:420-423`). If confined, that slot would stay in progress forever and that vendor would never be refreshed again (common to both reviewers of review round 1). A predicate would also silently confine a `Read` command that appears in the future.
- **Explicitly shut down the CLI on a confined pump panic (option B)** — user decision A (2026-10-12). Basis = killing the child handle ends only the root `cmd /c` (ADR-0262 K1), and there is no API for the pump to call to end the group, so platform `GroupRef::terminate` would have to be newly brought in and an exception made to ADR-0199 (the channel does not shut itself off). The existing cleanup path is the road taken every time on a normal exit, and the other holders that hold the session briefly take ≤ about 100 ms (doc-aware check of review round 1). If the test of decision 6 fails, go to this option.
- **Ending with our own `TerminateProcess(101)`** — platform helpers · hook injection places increase and the release exit code changes. abort is std only and the same as today. **`process::exit`** — `ExitProcess` ends the other threads first and may then stall at the DLL detach notification (the order in the MS docs · not measured — weak).
- **Add a notice with a strip notice (N2b)** — it needs a new screen mechanism. The user chose the current surface + log with 「그냥 내부에서 대되 로그는 남겨지는건 맞지?」.
- **Also confine shell bus commands (S2)** — a shell-side poisoning policy would be needed separately. Together with the narrowing in decision 2, S1 (hook only) was chosen.

## 영향 / 불변식

- **Invariant — marker scope ⊆ the `catch_unwind` closure.** If the marker covers `finish`, a panic inside it passes through the hook and only the pump thread dies, with no finalize · reap · Job close → a zombie that looks `Running` + a live CLI (the quiet stall that ADR-0005 · ADR-0290 rejected).
- **Invariant — a command outside the allow list is not confined.** Adding a command to the list is done together with confirming 「본문 효과 없음」 and re-checking the panic folding (TRD §4-2 B1).
- If a new call is added inside confinement that changes agent shared state or touches a mechanism that relies on abort (ADR-0262 K7), it is wrapped with the marker turned off (decision 3).
- **The marker is thread-local** — it does not follow threads · tasks · blocking calls that the confined code launches (those are outside the marker = immediate exit), and no async marker was put in (all the confinement places are synchronous). To confine an async place, a task-local marker is separately needed (materialize `CATCHING_UNWIND_ASYNC` — research conclusion 3 · TRD §4-3).
- **Places that this decision made stale in 0288 · 0290** (a status stamp covers only the decision, so they are written here) — in ADR-0288 「영향」, 「3 의 경로는 오염된 공유 락에서도 끝까지 가야 한다」 · 「2 는 펌프 밖이 열린 문제다(쓰기 · 출력 해석기 · 래치 …)」 (→ closed by decisions 2 · 3: only the pumps · the writer, the latch path turns the marker off) · in ADR-0290 「영향」, 「연결 태스크(`lib.rs:394`)도 … 같은 표시가 필요하다」 (→ the connection task · reaper are not confined) · 「정상 종료 경로는 오염된 공유 락에서도 끝까지 가야 한다」 (→ a panic does not take that path).
- **What remains in the seven ADRs that laid 「배포판 = `panic = "abort"`」 as their basis (0142 · 0199 · 0226 · 0233 · 0262 · 0275 · 0281 — linked 2026-10-12)** — the premise changes from 「배포판 프로필이 abort」 (the release profile is abort) to 「표시 밖 패닉은 훅이 되감기 전에 abort」 (a panic outside the marker is aborted by the hook before unwinding) (regardless of daemon · shell · build kind). All the conclusions stand: the `catch_unwind` guards of 0199 · 0262 and the unwinding (Drop) branch of 0142 are outside the marker so they are not reached in production and run **only in test builds without the hook** (the description 「debug 에서 관측된다」 has become false) · the basis on which 0226 puts no `catch_unwind` on the latch stands as 「래치를 부르는 자리가 전부 표시 밖」 · the 「dialog 패닉 = 셸 종료」 of 0281 holds in debug as well · the first-turn port panic on the reader thread in 0233 is not a pump `Failed` but a **daemon exit** (that call turns the marker off — decision 3) · the 0275 context's 「운영 빌드는 락 오염 복구 갈래에 닿지 않는다」 is false if a confined pump panics while holding that agent's lock (the `finish` outside the marker that follows takes that lock back — path inference · not measured) — the decision (reclaim without a warning) stands on the remaining reasons of S2 and decision 1 (no lock poisoning policy).
- `panic = "abort"` disappears from the `Cargo.toml` release profile — the rollback is that one line. After the hook goes in, the debug daemon ends even on panics that tokio used to isolate (a TRD U3 item to confirm).
- `docs/process/S20-command-bus/trd.md` §4 ⑨ 「릴리즈 `panic = "abort"` 유지」 is replaced by this decision — the convention 「명령 핸들러는 값으로 실패한다」 stands.
