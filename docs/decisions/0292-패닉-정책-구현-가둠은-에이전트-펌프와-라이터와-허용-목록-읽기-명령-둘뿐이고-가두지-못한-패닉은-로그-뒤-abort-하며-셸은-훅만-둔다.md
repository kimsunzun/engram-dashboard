# ADR-0292: 패닉 정책 구현 — 가둠은 에이전트 펌프와 라이터와 허용 목록 읽기 명령 둘뿐이고 가두지 못한 패닉은 로그 뒤 abort 하며 셸은 훅만 둔다

- 상태: 확정 (2026-10-12, 근거: 사용자 결정 2026-10-11~12 · TRD `docs/process/S21-panic-policy/trd.md` 11판 §3 · 조사 `docs/research/panic-practice-peers-2026-10-12.md`) · 부분 폐기 by ADR-0293 (결정 2의 명령 쪽 허용 목록)
- 관련: Amends ADR-0288 (결정 1과 2의 가둠 범위 및 결정 3) · Amends ADR-0290 (결정 1의 정상 종료 복귀와 결정 2) · ADR-0159(버스 명령 패닉 = `INTERNAL`) · ADR-0262(claude 잔여물 정리기 K7 — abort 에 기댄 막) · ADR-0199(통로는 스스로 끄지 않는다) · ADR-0005(finalize 1회) · ADR-0001(kill 인과) · Amended by ADR-0293 (결정 2의 명령 쪽 허용 목록)

## 맥락

ADR-0288 은 「요청 하나 · 에이전트 하나의 패닉은 그것만 실패시키고 공유 상태에서 나면 정상 종료한다」를, ADR-0290 은 「가두지 못한 패닉은 훅이 정상 종료 신호를 당긴다」를 정했다. 그 구현 TRD 는 10판까지 갔지만, 리뷰 9 라운드가 판 구멍이 거의 전부 「패닉 뒤 정상 종료 꼬리」(감시 스레드 · 사유 대기 · 셸 깨우기 · Exit 콜백 재확인)에서 나왔고 사용자가 「케이스별로 복잡하게 하는 느낌」으로 멈췄다. 이어 「요청 전부를 가두려면 공유 락 오염 규칙이 필요하다」는 안((가) · (나))을 두고 사용자가 「우리가 너무 민감하지 않나」를 물었고, 조사가 「가두지 못한 패닉 = 끝」은 흔한 모양이고 가두는 범위는 대개 상태를 안 바꾸는 단위로 좁다고 답했다.

## 결정

1. **가두지 못한 패닉 = 사유를 로그하고 `std::process::abort`.** 정상 종료 꼬리 · 감시 스레드 · 락 오염 정책은 두지 않는다(오늘 배포판 abort 와 같은 결과). — ADR-0288 결정 3 · ADR-0290 결정 1 의 「정상 종료 경로를 탄다」 · 결정 2 를 바꾼다(ADR-0290 결정 1 의 「ADR-0289 전체 폐기」는 산다).
2. **가두는 것은 상태를 안 바꾸거나 그 에이전트에만 딸린 단위뿐이다**(rust-analyzer 식 · ADR-0288 결정 1 · 2 의 범위를 좁힌다):
   - 에이전트 쪽 — 출력 펌프 셋(PTY · stdio · codex 리더)과 입력 라이터. 가둔 패닉 = 그 에이전트 `Failed` · 입력 거절.
   - 명령 쪽 — **명시 허용 목록** `agent.list` · `agent.listQueuedInputs` 둘. 가둔 패닉 = `INTERNAL` 답(ADR-0159). 목록에 넣는 조건 = 본문에 효과가 없을 것(효과가 있으면 패닉의 접기가 `OUTCOME_UNKNOWN` 이어야 하므로 접기부터 다시 정한다).
   - 그 밖 전부(상태를 바꾸는 요청 · 활성화 · 제어 HTTP · MCP 도구 · `usage.get` · 셸 · 배경 스레드)는 가두지 않는다 → 결정 1.
3. **가둠 안에서도 에이전트 공유 상태를 바꾸는 호출은 표시를 끈다**(그 안의 패닉 = 결정 1) — codex 첫 턴 세션 id 기록 · 사용량 관측 · 라이터의 `on_written` · claude decoder 의 문 조작(ADR-0262 K7 이 abort 에 기댄다). 표시 범위는 `catch_unwind` 클로저 안으로 한정하고 `finish` 는 표시 밖에서 돈다.
4. **셸은 훅만 설치한다**(가둠 없음 · 셸 패닉 = 결정 1).
5. **가둔 패닉의 고지는 지금 표면 그대로**(`Failed` · 입력 거절 · `INTERNAL`) — 자세한 것은 로그. 훅은 표시와 무관하게 로그하고, 로그 자기교착은 로그 쪽 스레드 지역 표지로 닫는다.
6. **가둔 펌프 패닉 뒤 CLI 는 기존 정리 경로로 끝난다**(`finish` → reaper → 세션 해제 → 무리 주인 drop → `KILL_ON_JOB_CLOSE`). 펌프 종류마다 실프로세스 시험으로 CLI 트리가 시한 안에 사라지는지 확인하고, 실패하면 아래 거부한 대안 4 로 간다.
7. **배포판 unwind 전환은 마지막 한 줄**(`Cargo.toml` `panic = "abort"` 삭제) — 앞 단위는 abort 아래 무동작이라 되돌림 = 그 한 줄.

## 거부한 대안

- **가두지 못한 패닉에 정상 종료 꼬리를 태운다(ADR-0288 결정 3 · ADR-0290 결정 2 원안)** — 사용자 「복잡하게 할 필요없음」(2026-10-11~12). 근거 = TRD 10판 리뷰 9 라운드의 구멍이 거의 전부 그 꼬리에서 나왔다(`.claude/handoff/attachments/panic-trd-review-r2~r9-2026-10-11.md`).
- **요청 전부를 가두고 공유 락 규칙을 둔다(TRD 11판 초안 `bedda3f3` 의 (가) B = 공유 락에서 오염을 만나면 즉시 종료 · (나) E = 여러 걸음 공유 변경 구간은 표시를 끈다 — 그 뒤 메인 제안 「공유 락을 쥔 동안 표시를 끈다」)** — 사용자 결정 ②(2026-10-12). 근거 = 조사 결론 2 · 4: 표본 대부분은 상태를 안 바꾸는 단위만 가두고(rust-analyzer 는 상태를 바꾸는 처리를 「isn't guarded by `catch_unwind`」로 둔다), 「공유 락을 쥔 동안 표시 끄기」 메커니즘은 선례를 못 찾았다. 좁히면 락 오염 정책 · 여러 걸음 구간 장치가 통째로 빠진다.
- **명령 가둠을 `effect == Read` 술어로 정한다** — `usage.get` 이 `Read` 인데 사용량 조회를 띄우고 진행 중 칸을 세운다(`agent/src/commands.rs:334-337` · daemon `usage_service` `book.rs:279-282` · `mod.rs:420-423`). 가두면 그 칸이 영원히 진행 중으로 남아 그 벤더가 다시 갱신되지 않는다(리뷰 1 라운드 두 리뷰어 공통). 술어는 앞으로 생길 `Read` 명령도 말없이 가둔다.
- **가둔 펌프 패닉에서 CLI 를 명시적으로 끈다(B안)** — 사용자 결정 A(2026-10-12). 근거 = 자식 손잡이 kill 은 뿌리 `cmd /c` 만 끄고(ADR-0262 K1) 무리 종료는 펌프가 부를 API 가 없어 platform `GroupRef::terminate` 를 새로 들이고 ADR-0199(통로는 스스로 끄지 않는다)에 예외를 내야 한다. 기존 정리 경로는 정상 종료 때 매번 타는 길이고, 세션을 잠깐 쥐는 다른 보유자는 ≤ 약 100 ms 다(리뷰 1 라운드 doc-aware 확인). 결정 6 의 시험이 실패하면 이 안으로 간다.
- **끝내기를 자기 `TerminateProcess(101)` 로** — platform 도우미 · 훅 주입 자리가 늘고 배포판 종료 코드가 바뀐다. abort 는 std 뿐이고 오늘과 같다. **`process::exit`** — `ExitProcess` 가 다른 스레드를 먼저 끝낸 뒤 DLL 분리 알림에서 멎을 수 있다(MS 문서 순서 · 실측 아님 — 약함).
- **띠 알림으로 고지를 더한다(N2b)** — 새 화면 장치가 든다. 사용자 「그냥 내부에서 대되 로그는 남겨지는건 맞지?」로 지금 표면 + 로그를 골랐다.
- **셸 버스 명령도 가둔다(S2)** — 셸 쪽 오염 정책이 따로 필요하다. 결정 2 의 좁힘과 함께 S1(훅만)로 정했다.

## 영향 / 불변식

- **불변식 — 표시 범위 ⊆ `catch_unwind` 클로저.** 표시가 `finish` 를 덮으면 그 안의 패닉이 훅을 통과해 펌프 스레드만 죽고 finalize · reap · Job 닫기가 없다 → `Running` 으로 보이는 좀비 + 산 CLI(ADR-0005 · ADR-0290 이 거부한 조용한 멈춤).
- **불변식 — 허용 목록 밖 명령은 가두지 않는다.** 목록에 명령을 더하는 것은 「본문 효과 없음」 확인과 패닉 접기 재검을 함께 한다(TRD §4-2 B1).
- 가둠 안에서 에이전트 공유 상태를 바꾸거나 abort 에 기댄 장치(ADR-0262 K7)를 건드리는 새 호출을 더하면 표시 끔으로 감싼다(결정 3).
- **표시는 스레드 지역이다** — 가둔 코드가 띄운 스레드 · 태스크 · blocking 으로 따라가지 않고(그쪽은 표시 밖 = 즉시 종료), 비동기 표시는 두지 않았다(가두는 자리가 전부 동기). async 자리를 가두려면 태스크 지역 표시가 따로 필요하다(materialize `CATCHING_UNWIND_ASYNC` — 조사 결론 3 · TRD §4-3).
- **0288 · 0290 에서 이 결정이 낡게 만든 자리**(상태 도장은 결정만 덮으므로 여기 적는다) — ADR-0288 「영향」의 「3 의 경로는 오염된 공유 락에서도 끝까지 가야 한다」 · 「2 는 펌프 밖이 열린 문제다(쓰기 · 출력 해석기 · 래치 …)」(→ 결정 2 · 3 으로 닫힘: 펌프 · 라이터만, 래치 경로는 표시 끔) · ADR-0290 「영향」의 「연결 태스크(`lib.rs:394`)도 … 같은 표시가 필요하다」(→ 연결 태스크 · reaper 는 가두지 않는다) · 「정상 종료 경로는 오염된 공유 락에서도 끝까지 가야 한다」(→ 패닉은 그 경로를 안 탄다).
- `Cargo.toml` 배포판 프로필에서 `panic = "abort"` 가 사라진다 — 되돌림은 그 한 줄. 훅이 들어간 뒤 debug 데몬은 tokio 가 격리하던 패닉에도 끝난다(TRD U3 확인 거리).
- `docs/process/S20-command-bus/trd.md` §4 ⑨ 「릴리즈 `panic = "abort"` 유지」는 이 결정으로 대체된다 — 「명령 핸들러는 값으로 실패한다」 규약은 산다.
- 구현 단위 · 시험 · 감사 거리 · 표시 원시의 정본 = TRD 11판 §5 · §6 · §4-6 · §4-3.
