# ADR-0164: The re-attach trigger is the authoritative registry, not the socket — do not put the incarnation token in the subscription deps

- 상태: 확정 (2026-08-20 user decision, basis: code measurement + 1 `/review code` BLOCK)
- 관련: Amends ADR-0046 (the reconnect-trigger clause of decision 2) · ADR-0163(meaning and comparison rule of the incarnation token) · `src/api/protocolClient.ts:9-19`(header, source of truth) · `protocolClient.ts:165-181`(socket transition handler) · `protocolClient.ts:526-536`(canAttach) · `protocolClient.ts:546-571`(detach) · `protocolClient.ts:589-613`(observeRoster) · `protocolClient.ts:794-804`(mount path) · `src/components/slot/TerminalSlot.tsx:270-289`(clearing on replay arrival) · `TerminalSlot.tsx:315-320`(deps) · CLAUDE.md 「핵심 불변식」·「통합 micro-rules」

## 맥락

ADR-0046 decision 2 was "remount/reload/**reconnect** = the daemon re-replays the whole ring". Of these, the **reconnect** half hung its trigger on the **socket transition** — when the connection comes up as `connected`, every view that was attached issues `Subscribe` again.

That premise breaks on a daemon restart. **The restarted daemon's registry is empty.** The fact that the socket is up and the fact that the agent exists are different facts, but since the trigger hangs on the former, it fires `Subscribe` for everything at agents that are not even alive and **all of them are rejected** — the retry ladder is exhausted and the slot freezes in `error`. It is not accidental timing but a structural rejection storm.

## 결정

1. **When the connection drops, the view only settles down to `detached`.** It leaves the screen, progress cursor and incarnation token as they are and issues no request (`protocolClient.ts:546-571`). Only the pipe has gone; the user's intent that "this slot views this agent" is unchanged. What is discarded is only the incomplete replay fragments of the dropped generation and the **registry** — the registry known now is that of the daemon that just dropped, so using it as a fact of a live daemon would read a vanished agent as alive.
2. **The only trigger for issuing a request again = the observation that the agent is in the authoritative registry** (`observeRoster`, `protocolClient.ts:589-613`). The socket state handler **intentionally has no** reviving branch (`protocolClient.ts:168-173`).
3. ★**Both the door that comes in and the door that is pulled from converge on that one place**★ — the broadcast (`AgentListUpdated`) and the query (`getAgents`). After a reconnect the first registry comes by query (`eventBus.resyncAfterReconnect`), so if that side is omitted the main recovery path never attaches.
4. **"Is it the same session" is not inferred** — it is decided **by comparing** the incarnation token the registry reported with the one the view was holding (`protocolClient.ts:606`). Ordering is not looked at (ADR-0163 decision 2). If a registry entry has no token, **it is not asserted to be the same incarnation** — that assertion is the original defect (a new incarnation arriving from 0 while the cursor is kept would drop out entirely in dedup and the slot would stay empty forever). The cost of rotating wrongly is one unnecessary full replay, and since the clearing and the redrawing are in the same tick it does not even show on screen — **we choose a loud re-replay over a silent permanent stall.**
5. **If it is not in the registry, a view that was attached is also brought down** (`protocolClient.ts:580-583`). If not, a slot viewing a reaped agent keeps being reported to `getViewOutputState` as `live`, so the screen is frozen while automation and the LLM read it as alive (that surface is the contract of CLAUDE.md 「LLM-우선 제어」).
6. **An unknown registry (`roster === null`) is not absence — send** (`canAttach`, `protocolClient.ts:526-536`). Boot, a webview reload and a failed query all fall here. Sending wrongly costs at worst one rejection, and that is already absorbed. **Mount also uses this same one rule as re-attach** (`protocolClient.ts:794-804`) — with two rules the same question gets two answers.
7. **The screen clearing that follows an incarnation rotation is moved from the request (resubscribe) moment to the replay arrival moment.** Right after the router calls the `onReset` callback, in the same tick it delivers the full replay of the other incarnation and discards the progress cursor (`TerminalSlot.tsx:270-289`). This callback **must be passed by all three slots (Terminal · Dom · Rich)** — if not passed, only the cursor goes back to 0 while the screen still holds the previous incarnation's content, so the whole replay is drawn on top of it and no error is left anywhere. **The one reset at mount (StrictMode duplicate prevention, `TerminalSlot.tsx:243`) stays as it is** — the two are different jobs, so do not merge them into one.
8. ★**Do not put the incarnation token in the subscription deps.**★ The actual deps = `[viewId, agentId]` (`TerminalSlot.tsx:320`). `viewId` is in because it is the **subscription key** (ADR-0046).

## 거부한 대안

- **Make the socket transition the trigger (ADR-0046's original)** — the rejection storm in the 맥락 above. It fires `Subscribe` for everything at the restarted daemon's empty registry, all are rejected, the ladder is exhausted and the slot freezes in `error`. The socket state is "is there a pipe" and the registry is "is there that agent", and the cause is using the former fact in place of the latter.
- ★**Include the incarnation token in the subscription effect deps**★ — **`/review` raised a BLOCK.** Every time the value wobbles (a re-spawn · a daemon restart) the subscription is swapped wholesale, and the mount reset that swap runs executes **before the replay even arrives** and the screen is wiped. The daemon ring is already gone too, so the scrollback cannot be recovered. In addition, that swap **loses the incarnation token itself**, so the rotation decision (`observeRoster`) can no longer stand — it is a proposal that breaks what it set out to fix (`TerminalSlot.tsx:315-318` is the source-of-truth description of this rejection).
- **Decide the rotation on the frame side** — the frame path simply drops a token mismatch (not mine = drop), so it cannot be the place that *recognizes* a rotation. The only place that recognizes a re-spawn of an attached view is the registry observation (`protocolClient.ts:585-587`). If this branch is removed, a live slot cannot draw a single byte after a re-spawn.
- **Treat an unknown registry as absence (conservative block)** — at the cost of one failed query, the output is blocked entirely, and even on a normal boot the first paint is delayed by one registry round trip (the opposite side of decision 6).
- **Fix the resize regression in 「대가」 below by restoring the deps** — that regression is real, but reverting returns straight to the BLOCK proposal above. It was fixed by attaching the dimension resend as a separate signal.

## 근거

- **User decision 2026-08-20.** Both moving the trigger to the registry and deciding "is it the same session" only by token comparison are this decision.
- **1 `/review code` BLOCK** — the proposal to include the token in the deps. The ground is the rejection item above as is (reset before replay → unrecoverable + token loss → rotation decision collapses).
- **Code measurement (2026-08-21).** Header source of truth `protocolClient.ts:9-19` · the socket handler's intentionally empty branch `:168-173` · `canAttach` `:526-536` · detach `:546-571` · `observeRoster` `:589-613` · mount `:794-804` · clearing on replay arrival `TerminalSlot.tsx:270-289` · deps `TerminalSlot.tsx:320`.

## 영향 / 불변식

- **The single point of the attach trigger = `observeRoster`.** Do not read the socket state handler's empty branch (`protocolClient.ts:168-173`) as "missing handling" and fill it in — that is the entrance of the rejection storm.
- **Both doors must be open** — the broadcast and the query. If only one is left, the reconnect recovery path dies.
- **The rotation decision is by the registry alone.** The frame path only drops a mismatch. A dropped frame is not lost — the attach claims the full replay again.
- **deps = `[viewId, agentId]`.** The incarnation token is forbidden (decision 8). All three slots pass the `onReset` callback (decision 7).
- **The remount and reload half of ADR-0046 decision 2 remains valid** — only the **reconnect** half was replaced. The form of a full re-replay itself also remains (what changed is *when it is claimed*).
- **★If the dimension resend on re-attach is removed, the regression below returns★** (`TerminalSlot.tsx:279-288`). It is skipped while hidden and the visibility effect emits the same propagation when it shows again — because `fit()` on a collapsed container yields the minimum dimensions.

### The cost — a regression that actually occurred

Taking the token out of the deps **cut the only path that re-propagated the terminal dimensions on re-attach** (in the old structure the subscription effect re-running doubled as that propagation). The restored PTY stands at the daemon spawn default **80×24** while this slot's xterm stays at the dimensions it had been stretched to (**measured 137×25**). The claude TUI (Ink) computes "erase N rows upward" from the size it believes, so even one row off leaves one line of a stale copy on every update — the symptom the user saw was **text printed twice**.

The fix was **not** restoring the deps but resending the dimensions after `fit()` on the re-attach signal (`TerminalSlot.tsx:279-288`). It fills one more empty hole of the same family as the single propagation right after mount (ADR-0036 carry-forward, `TerminalSlot.tsx:297-305`).
