# ADR-0017: Session/slot structure — slot = one session of one mode (when it ends, the slot ends), "death" = per-backend Run end + reason

- 상태: 확정 (2026-06-16, user decision — the consult (B) recommendation overridden by the domain intuition (A)) · 부분 폐기 by ADR-0245 (decision 5, the interrupt(Ctrl-C) part: PTY does not support interruption)
- Basis: `/consult` job `20260616-011502-consult-death-abstraction` (GPT · Gemini · Claude + judge, OSS survey) · ADR-0016(agent lifetime model) · ADR-0002/0004(backend abstraction) · ADR-0001(kill 2 verbs)
- Replaces: the (B) recommendation part of `docs/process/S12-daemonization/session-death-structure-options.md`
- 관련: ADR-0001(kill 2 verbs — the kill · interrupt separation that decision 5 points to) · Amended by ADR-0245 (decision 5, the interrupt(Ctrl-C) part: PTY does not support interruption)

## 맥락
"Agent death" must be defined independently of the backend, and consult recommended the **(B) model that persists the slot with Slot≠Run≠Transport** (tmux remain-on-exit/respawn-pane style). But that model causes confusion: "swapping the backend inside a slot (claude→codex) · zombie (frozen) slots · dead pane vs live terminal". The user's domain intuition is the simpler **(A)**: a slot is one session of one kind, and when that session ends, the slot ends.

## 결정
1. **A slot = one session of one mode (terminal/claude/codex/api).** When that session ends, **the slot ends too** (the current behavior is kept). **We do not swap the mode/backend inside a slot** (no in-place claude→codex switch). If a different mode is needed, use a **new slot.**
2. **No zombie/frozen slots** — do not leave an ended slot stopped in place (reject the tmux remain-on-exit-style (B)). Keeping the shell alive with `cmd /k` is also rejected (raw-mode contamination · no EOF · Job conflict).
3. **Restore = reviving (a new session), regardless of backend.** An agent that has a session (`needs_session=true`: claude/codex) uses `--resume` with the sid, anything else is fresh. Restore brings it back up "as the same kind". (The user's requirement "restore terminals and codex too" = restore works for every kind = satisfied. It is unrelated to swapping the backend inside a slot.)
4. **The terminal (shell) is not a save/restore target.** `needs_session=false` → there is no session (sid) or conversation to pick up. Reviving it would only give an empty new shell, so it is meaningless → **excluded from persist/auto_restore.** Only claude/codex, which have sessions, are saved and restored.
5. **"Death" is defined per backend + classified by reason (the part salvaged from consult):** Run end + reason (Completed/Failed/Signaled/KilledByUser/Interrupted/StartupFailed/...). For the API, stream-end = Completed (≠ death). **KilledByUser/Interrupt are not targets of auto-restart or (future) respawn** (what a human turned off does not come back). Keep kill (process/Job level) and interrupt (Ctrl-C) separate (ADR-0001).

## 거부한 대안
- **(B) A Slot≠Run persist container** (tmux remain-on-exit/respawn-pane, GNU screen zombie, Zellij command pane, VS Code relaunch): it has the flexibility of respawning in the same place and swapping modes, but causes domain confusion (zombie slots · in-place backend swaps · mistaking a dead pane for a live terminal). **It was the consult recommendation but was rejected on the user's domain intuition** — avoiding confusion > tmux-style flexibility. (The "promote the Rust Slot lifetime" implementation that Gemini pointed out only makes sense if (B) is chosen, so it is shelved along with it.)
- **Keeping the shell alive with cmd /k** — TUI raw-mode contamination · no PTY EOF (a child watcher would be needed) · the JobObject catches the shell too. Rejected.
- **Terminal persist/restore** — there is no session state to pick up, so it is meaningless.

## 근거
Of the agreements in the consult cross-validation (three kinds + judge), **"per-backend death definition + exit-reason classification + excluding KilledByUser + API stream ≠ death"** was adopted (needed for backend independence). But the core structural choice (the slot persist container (B) vs slot = session (A)) puts the **user's domain intuition** ahead of OSS precedent — claude is the slot, ending = the slot ending fits the user's mental model and causes no confusion.

## 영향 / 불변식
- **Slot lifetime = session lifetime** (they end together). The current behavior is kept → the ADR-0001 (kill 2 verbs) and ADR-0005 (finalize once) invariants are **unchanged.**
- **Terminal/shell slots are excluded from agents.json persist and auto_restore** (`needs_session=false` is not a restore target). Saving and restoring are limited to `needs_session=true` (claude/codex).
- **Do not create a path for swapping the backend inside a slot** — the mode is fixed when the slot is created.
- Consistent with ADR-0016: the "sid instance" of ADR-0016 is this ADR's "one session", and "saved = kept alive" is made concrete as **limited to agents that have a session** (terminals excluded).
- "Death" is still observed by PTY EOF (current, ADR-0016 §the runtime death-observation hook TODO) — since we do not take (B), no child watcher is needed.
