# ADR-0088: Delivery correctness verification first — instrumentation first, forgery defense = the escaping body, format limited to readability/compliance (an ADR-0087 ladder amendment)

- 상태: 확정 (2026-07-19, basis: /research (OSS and literature survey in 3 branches + grounding) + two Codex cross-family adversarial reviews (test suite BLOCK, plan BLOCK, 20+ findings) + the user's step-by-step approval)
- 관련: Amends ADR-0087 (reorganized the ladder order (format spike → delivery correctness verification first) + the envelope decision axis (forgery resistance → moved to escaping, format limited to readability and compliance)) · ADR-0086 (dual entrances, immediate push relay — the main body is valid) · ADR-0006 (lock discipline — the basis for immediate push) · ADR-0012 (module isolation harness — the spike harness rides this grain) · Amended by ADR-0091 (ladder order + step 4 split (the saturation moved behind the format-acceptance part; escaping deferred))

## 맥락
After step 2-min (the minimal transmission of dual entrances) was complete, ADR-0087 named the **envelope format measurement spike** (XML vs an Orca-style banner, sonnet baseline) as next. To design the test suite for that spike we ran /research (3 branches: entrance comparison / envelope format / behavior cases), and when its output was put through adversarial review by Codex (a non-lead family) twice, **both came back BLOCK**. The key points:

1. **The order is wrong.** The current delivery is **immediate push** (`write_stdin` = 1 write = 1 complete user turn), and the **idle gate, batching, and queue are unimplemented** (ADR-0087 ladder ③④ still only reserve a place). So **nobody has verified** whether loss, truncation, duplication, or timing errors occur when a message is inserted while the receiving agent is doing something. If a decision on "which envelope reads well" is made while the soundness of this pipe is unproven, the results cannot be interpreted.
2. **An observability gap.** With only the relay log + the assistant transcript, "the agent missed the message" cannot be told apart as a *transmission failure* or the *model ignoring it* — without instrumentation at the write boundary every delivery decision is ambiguous.
3. **Measuring forgery defense by the envelope grammar is an illusion.** Whatever the envelope grammar (XML/banner), it is breached if the sending agent **imitates that grammar in the body text** (ChatInject: disguising role/system tags inside the body raises ASR 3x over a naive injection). The real defense lever is not the grammar but **the daemon neutralizing (escaping) envelope-boundary-lookalike strings in the body**.

These three points change the step ladder order of ADR-0087 and the decision axis of the envelope spike — the remaining decisions (sender liveness = observation only, envelope asymmetry, name rules, chat room separation, and so on) remain valid, so this is a **partial amendment**.

## 결정

1. **Ladder reorganization (a partial amendment of 0087) — insert delivery correctness verification before the format spike.** Between the existing ③ (format spike) and ④ (delivery refinement = idle gate, batching), put **"delivery correctness verification" in as a preceding step**. Only **after** measuring with instrumentation + a harness whether messages are delivered without loss, duplication, truncation, or timing errors under immediate push and no idle gate, and whether there is any malfunction at context saturation, do we go to the format spike. This verification result is itself the measured basis for the need for an idle gate (the old ④) (admitting that ③↔④ were tangled and correcting the order).
2. **Increments in b slices (user decision).** Do not build everything at once: **(0) instrumentation → (1) delivery correctness core** (state matrix: during text/tool-argument generation · during tool execution · waiting on permission/result · the receiver itself sending · self-send + an exact-once burst of 2/10/100 messages + lifetime races kill/restart + PTY boundary 64KiB±1 · multibyte) **→ (2) a context saturation reduced factorial design** (length × filler kind × envelope position × delayed use × before/after compaction, decision = sustained processing). This first round must pass before moving on to (3) the entrance comparison + (4) the format spike. This is so as not to waste expensive format runs (50+) if the pipe is unsound.
3. **Forgery defense = escaping (not the envelope grammar).** The choice of envelope grammar does not create forgery resistance — the real defense is neutralizing envelope-boundary-lookalike strings in `wrap_message` before wrapping the body. Measure the escaping **together in the format spike as the defense body** (per-format escaping rules + a breakout corpus: closing tags, delimiters, bidi, zero-width, homoglyph sender names), but **limit the decision axis of the format contest itself to "readability and compliance"**. Do not claim forgery resistance as a format advantage.
4. **Instrumentation first (a precondition of observability).** Since no delivery decision holds without instrumentation at the write boundary, implement the `write_stdin` boundary instrumentation (write start/completion · byte count/error + msg_id correlation) **first, as a precondition of every delivery test**. Before classifying a "miss", the daemon leaves evidence of whether the transmission completed.
5. **Basic harness requirements — reproducibility, safety, statistical pre-registration.** The spike harness has (a) reproducibility pins (the resolved model ID, CLI commit, daemon commit, settings, and system prompt fixed), (b) a safety sandbox (an isolated workspace · no secrets · network blocked · minimal-privilege tools · hard caps on spawns/messages — mandatory because the `$()`, backtick, and propagation cases of 1i can actually execute/propagate commands), (c) statistical pre-registration (cell allocation · minimum effect · confidence interval · repeated-failure threshold · holdout).

## 거부한 대안
- **Format spike first (what we were going to do, the ADR-0087 original plan)** — Codex BLOCK: a format decision made while the soundness of the immediate-push pipe is unproven cannot be interpreted. If delivery is truncated or mixed up, the format runs would have to be redesigned entirely and the expensive real spawns are wasted.
- **Forgery defense by envelope grammar (deciding spoofing resistance by F1/F2 superiority)** — the body can imitate the envelope grammar (the measured ASR increase in ChatInject), so the grammar is not a defense lever. Defense holds only through escaping (placement, encoding).
- **Implementing the full rig at once (option a)** — building every stage (entrance, format, injection resistance all) in one go while the pipe is unverified carries a large rework risk depending on the first-round results. The minimum (option c) keeps only half the intent of the restructuring (verify first) and cannot cover the delivery core. → the middle b slices.
- **Immediate ack = a delivery success decision** — Codex: an immediate receipt indication does not prove sustained processing. The decision is made by delayed retrieval (recalling sender/id/body in a later turn) · delayed reply correctness · completion of the original task · surviving compaction.
- **Relay log order = the oracle of delivery order** — invalid, since the relay log order may precede the actual PTY acceptance order. Give a daemon admission sequence as the oracle and capture confirmation of the receiving input.

## 근거
- **Research grounding (confirmed/likely):** long-context instability (arXiv 2512.02445 — beyond ~100K tokens, injection handling degrades, unstable refusals) · ChatInject (arXiv 2509.22830 — in-body chat-template disguise ASR 15.13%→52.33%) · Anthropic's recommendation (place untrusted content in a tool_result + JSON encoding). The Orca formatter and the mcp_agent_mail reply structure were directly verified in primary sources (pinned commits).
- **Adversarial review (BLOCK×2):** the review of the test-suite research output caught 3 misattributions (the self-correction 85% figure = an unrelated paper / "OSS convergence of 2" = mcp_agent_mail replies through a separate tool, and the built-in command is Orca alone / the Spotlighting compression figure = that of datamarking). The plan review caught an ordering error, an observability gap, confounding, and a safety gap. Reviewer = Codex (GPT family, effort high, codex exec in the background).
- **Research process correction:** the wording "OSS convergence of 2" in the ADR-0087 basis section corresponds to misattribution ② above — independent convergence on a built-in reply command does not hold and it is an Orca-alone precedent (this ADR records that fact as a correction; the 0087 decision itself is unaffected because the spike fixes the envelope).

## 영향 / 불변식
- **No format decision while delivery soundness is unproven** — the envelope format spike (the old step 3) is gated by passing delivery correctness verification (the new preceding step). If a later session reverses the order and tries to measure the format first, this ADR is the anchor.
- **Forgery defense lives in the `wrap_message` escaping** — an envelope grammar change is a readability and compliance experiment, not a change of forgery defense. Removing the escaping or replacing it with grammar as the defense is forbidden.
- **Instrumentation is the precondition of delivery tests** — do not classify a "miss" without write boundary instrumentation.
- **The harness safety requirements are mandatory** — do not run the injection/shell expansion cases (1i, propagation) on real agents without an isolated workspace, network block, and spawn caps.
- **The immediate push relay (ADR-0086), sender liveness = observation only (ADR-0087), envelope asymmetry, name rules, and chat room separation = remain valid as they are** — this amendment does not touch them (the partial amendment scope = only the two clauses, the ladder order + the envelope decision axis).
