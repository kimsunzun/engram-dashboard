# ADR-0387: A launch skips what is absent and blocks on what exists but cannot be read, for every preset item, folder entry and the library root

- 상태: 확정 (2026-11-20, 근거: user decisions 2026-11-20 during the T-112 TRD review — 「ㅇㅇ 막아.」 (an unreadable folder entry keeps blocking), 「ㅇㅇ 같은 기준으로해.」 (after main's table: absent → skip, exists but unreadable or broken → block, the library root included), 「ㅇㅇ 별도로 구분해. 너무 디테일하게 원인을 쓰지는 말고.」 (the unreadable folder row is its own class, short text); main's decisions recorded in the TRD §11 b, reviewed deep PASS) · 부분 폐기 by ADR-0400 (decision 2 library root)
- 관련: Amends ADR-0374 (decision 2 unusable root) · Amends ADR-0341 (decision 6 unreadable folder row) · Amends ADR-0361 (decision 1 launch scope of block 4) · Amends ADR-0363 (decision 3 missing half) · TRD `docs/process/S25-preset-library/trd-launch-skip-missing.md` · tracking T-112 · ADR-0215 (codex `developer_instructions` replaces the config value) · ADR-0357 / ADR-0364 (notice wording) · ADR-0386 d14 (clearable refusals) · Amended by ADR-0400 (decision 2 library root)

## 맥락
ADR-0374 made a launch skip missing items and an unusable library root instead of refusing. Its decision 4 left "exists but cannot be read" out, and ADR-0361 counts a root whose stat errors or does not answer as "unusable", so ADR-0374 decision 2 would have skipped every library item when the root is on a share that is down, while ADR-0363 decision 3 kept an unreadable folder entry blocking. The TRD draft therefore treated the two "storage not reachable" cases oppositely. The user asked for one rule. Main also measured (rustc 1.95, Windows 11) that `std::fs::metadata` answers `ErrorKind::NotFound`, raw OS error 3, for an unreachable UNC path (`\\nohost\share\x`, `\\localhost\noshare\x`) and for an absent drive letter — so "absent" cannot be read from the error kind alone on a network path.

## 결정
1. **One rule for every preset item (instruction, skill, settings, preset), every folder entry itself and the library root: absent → skipped with a notice; exists but cannot be read, did not answer in time, or is broken → the launch is refused.** Contents below a folder entry keep ADR-0363: skipped and named in a notice.
2. **Library root.** Only an unset root, a missing root and a root path that is a file skip every library item (one `library-unavailable-skipped` notice; built-ins still resolve). A root that is set but cannot be read or does not answer refuses the launch with today's ④ row as the whole answer. A configured root that is missing when the first scan fails is still absent (the root is stat'ed when the first scan failed).
3. **An unreadable folder entry is its own row.** It is a ② broken row with the code `folder-unreadable` `{path, why}`, not a `folder-not-found` row. The row's text is short and fixed by code; the cause stays in `args` for the log and an LLM caller. A launch never refuses on a `Missing` row. Edit answers (`preset.add`, `preset.previewFolder`) follow the same split.
4. **A network share that does not answer is not absent.** On `NotFound` for a UNC path or a drive letter mapped to a network location, the share root is stat'ed in the same bounded required phase; if it does not stat as a folder the item is unreadable (`share not reachable`) and blocks. A local drive letter that is not present stays absent (an unplugged disk is skipped). `agent.setWorkspace` treats `share not reachable` as clearable, like a timeout.
5. **`library.status` gains the word `unreadable`** beside `missing`, so status shows the same split as the launch.
6. **A link probe that fails is broken, not absent** (`library-read-failed`); a path under a file (`NotADirectory`) counts as absent. A file below a folder entry that cannot be read for a reason other than a timeout joins that folder's `folder-listing-skipped` notice.
7. **Telling the agent.** The skipped items are appended to the merged instructions as a launch note (names, else a count, else nothing — the note can never turn a skip into a refusal). A backend whose instructions replace the user's own (codex) gets no note when Engram has no instruction text of its own (`trim()`-empty); the reply notice and the log still name the skip. Skip notices in the reply are once per agent (ADR-0341 decision 5); the log line is every launch.

## 거부한 대안
- **Skip everything, unreadable included, and only notify** — a share that is slow or down would drop that folder's rules or the whole library on every launch, silently except for a notice. Offered to the user as option B and rejected (사용자 직접 기각).
- **Keep the draft's mix: unreadable folder entry blocks, unreadable library root skips** — two rules for the same "storage not reachable" case. Rejected by the user (「같은 기준으로해」, 사용자 직접 기각).
- **Keep the unreadable folder entry as a `folder-not-found` row with a `why`** (smaller change) — the screen would say "not found" for a folder that exists, and the split would have to read folder statuses instead of the row kind. Rejected by the user (「별도로 구분해」, 사용자 직접 기각).
- **Read "absent" from `ErrorKind::NotFound` alone** — measured: Windows answers `NotFound` (raw 3) for an unreachable UNC path, so a down share would be skipped.
- **Probe the share inside each worker's stat** — the worker gets only a path, no required/advisory need and no per-launch store (code: `run_op` → `FolderOps::stat`), so the probe could neither be shared per launch nor skipped for advisory asks.
- **Give a codex agent a note-only instruction text** — `-c developer_instructions` and the JSON `developerInstructions` replace the user's own config value (ADR-0215), so one skipped item would drop the user's instructions for that launch.
- **Repeat the skip notices on every launch** — the user rejected repeating notices earlier (「알면서 쓰는사람도 있을텐데 그 메세지 실행하면서 계속 보면 안되잖아」, 사용자 직접 기각); a changed skip set still shows again.

## 근거
- The user's decisions (상태 line), each given after main's plain-words table of what is skipped and what blocks.
- Convention (light check in the TRD §8): git skips a missing `include.path` file silently and stops on one it cannot read; OpenSSH skips an `Include` that matches no file; codex refuses to start when its `model_instructions_file` cannot be read. What Claude Code does with a missing `@import` was not confirmed.
- Main's measurement of `NotFound` on unreachable UNC paths (맥락).
- TRD reviewed deep (lead, risk-axis lens, Codex), five rounds, PASS.

## 영향 / 불변식
- The launch split is by row kind: `Missing` rows (and the absent-root ④ row at the read entrances) are skipped; every other row blocks. Code: asset-library `resolve.rs` (`Resolution` split, `RootState` absent/unreadable, `folder-unreadable`), `lib.rs` (`root_state`, typed `stat_root`, `status`, `mark_links`), `agent_edit.rs` (`RootSeen` follows the same root rule as `agent.presets`, ADR-0384), `folder.rs` (`BoundedIo::stat_all` share probe), `edit.rs` (folder refusals, `mark_row_link`), `launch.rs` (`launch_check`, `prepare_in`, `Stamp`), platform `fs::share_root`, agent `launch.rs` codes, `commands.rs` `workspace_refusal`, backend `instructions_append`.
- Accepted risks: a skipped settings file can drop a permission limit (ADR-0374); a local-drive path that reaches a share through a directory link is not probed; a resumed codex JSON thread keeps instructions whose file was deleted when Engram then has no instruction text; what a disconnected mapped drive letter answers is unconfirmed (QA live check).
- ADR-0361 「영향」 bullet 2 (no folder IO or command-line judgment for a ④ resolution) still holds for the unreadable-root refusal; the absent-root path runs the normal launch.
