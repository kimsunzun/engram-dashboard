# ADR-0230: Platform neutrality — split OS differences only inside the one function that owns them, and do not tie the regression net to one OS

- 상태: 확정 (2026-09-24, basis: user decision) · 부분 폐기 by ADR-0266 (narrowed the place for OS branching in decision 1 to a single crate)
- 관련: CLAUDE.md 「플랫폼 중립」 (the body of this decision's principle) · CLAUDE.md 「0. 판단 기준」 (the existing criterion applied) · ADR-0131 (CI windows single runner — the known gap in 「영향」 below) · `crates/engram-dashboard-agent/src/backend/mod.rs:44` (`console_command` — precedent for the shape to keep) · 「남은 것」 ⑥ of the step-log entry 「S21 — 첫 대화 뒤에만 세션 id 를 영속하는 이어받기」 · Amended by ADR-0266 (narrowed the place for OS branching in decision 1 to a single crate)

## 맥락

Releases are Windows only for now — the release zip is built only by the `windows-latest` runner with `scripts/build-release.ps1` (`.github/workflows/ci.yml:897`). macOS is for later, and we are not porting now.

What has to be solved is not the port itself but **what has to be changed at that time**. The user's original words: 「지금 당장 맥으로 한다는건 아니고 그것을 위한 구조를 미리미리 갖춰야지」. Here 「구조」 means two things — ① work that varies by OS is confined inside the function or module that owns it, and the caller does not know the OS ② the regression net stands independent of the OS.

## 결정

1. **Work that varies by OS is split with `#[cfg]` only inside the one function or module that owns it, and the rest of the code calls only that function.** Do not scatter `cfg!(windows)` across callers.
2. **Do not tie the regression net to one OS either.** If a test file is blocked wholesale with `#![cfg(windows)]`, on other OSes that regression net becomes silence instead of a failure.
3. The body of the principle lives in CLAUDE.md 「플랫폼 중립」.

## 거부한 대안

- **Move everything at once when we do the Mac later** — user rejection: moving then becomes a whole refactoring (「안그러면 나중에 전체 리팩토링을 하니깐」, 2026-09-24). ★Strength of the rejection basis = **weak** (narrative)★ — the range over which OS branching has spread (the 37 files in 「영향」 below) is measured, but the cost of moving everything at once was not itself measured. It is a principle the user set directly.

## 근거

- **User decision (2026-09-24)** — original words: 「지금 당장 맥으로 한다는건 아니고 그것을 위한 구조를 미리미리 갖춰야지 안그러면 나중에 전체 리팩토링을 하니깐.」
- **Application of an existing criterion** — CLAUDE.md 「0. 판단 기준」: low risk + long term (boundaries · seams · types — things that are expensive to change later) are laid down thoroughly now. The boundary that confines OS differences is that kind.

## 영향 / 불변식

- **The shape to keep (precedent)** — `console_command` (`crates/engram-dashboard-agent/src/backend/mod.rs:44`): Windows = `cmd.exe /c <program>`, elsewhere = run as is. The two backends that assemble the spawn (`crates/engram-dashboard-agent/src/backend/claude/mod.rs:310` · `crates/engram-dashboard-agent/src/backend/codex/mod.rs:971`) do not branch on the OS and call only this function.
- **An example of what should be gathered — the `.exe` in executable names.** At least four places each split the same OS difference, 「실행파일 이름에 `.exe` 를 붙이나」, with their own `cfg!(windows)` — `crates/engram-dashboard-daemon/src/lib.rs:96` (app) · `crates/engram-dashboard-daemon/src/lib.rs:146` (CLI) · `crates/engram-dashboard-discovery/src/lib.rs:981` (daemon) · `crates/engram-dashboard-daemon/src/bin/roundtrip_smoke.rs:903` (CLI).
- **Current state (measured 2026-09-24)** — 37 files under `crates` and `src-tauri` contain `cfg(windows)` or `cfg!(windows)` (`rg -l 'cfg!?\(windows\)' crates src-tauri`. Every file that contains `cfg(not(windows))` also contains `cfg(windows)`, so it is already in this count). ★This number is not a violation count but a count of places to look at★ — it includes cases confined inside one function like the precedent.
- **Known gap ① — six test files blocked wholesale.** On other OSes this regression net silently drops out of compilation.
  - `crates/engram-dashboard-agent/tests/activation.rs:6`
  - `crates/engram-dashboard-agent/tests/canonical_name_wiring.rs:22`
  - `crates/engram-dashboard-agent/tests/stdio_physical_pipe.rs:14`
  - `crates/engram-dashboard-agent/tests/stdio_smoke.rs:8`
  - `crates/engram-dashboard-agent/tests/submit_delivery_boundary.rs:13`
  - `crates/engram-dashboard-discovery/tests/stop_smoke.rs:14`
  - ★Test modules blocked to Windows **inside** a file are the same silence★ — for example: `crates/engram-dashboard-agent/src/transport/pty.rs:682` · `:757` · `crates/engram-dashboard-agent/src/backend/codex/mod.rs:3421` · `crates/engram-dashboard-net/src/instance.rs:333` (`#[cfg(all(test, windows))]` — ★but this one has a non-Windows counterpart (`non_windows_tests`) at `:319`, so it is not silence but a shape where each OS measures its own behavior — an example of the form the principle wants★) · `crates/engram-dashboard-daemon/tests/ws_e2e.rs:2282` (`#[cfg(windows)] mod real_process`). How to find them = `rg -n -U '#\[cfg\(all\(test, windows\)\)\]|#\[cfg\(windows\)\]\s*\n\s*mod \w+ \{' -g '!**/examples/**' crates src-tauri` (measured 2026-09-24 = the five places above — it is a multi-line match, so `ws_e2e.rs` prints on two lines and the output is six lines). ★It is not a complete list★ — `#[cfg(windows)]` attached to a single test function (for example `crates/engram-dashboard-base/src/platform.rs:242`) is the same kind and is in several files, but this search does not catch it.
- **Known gap ② — dev tools and CI are Windows only.** The run scripts (five `.bat` and three `.ps1` in `scripts/`) · GUI measurement (`scripts/cdp.mjs` — WebView2 CDP) · the three CI verification jobs (backend · gates · frontend) and the release build run only on `windows-latest` (`.github/workflows/ci.yml:55` · `:378` · `:851` · `:900` — the basis for the single runner = ADR-0131).
- **This ADR does not change code.** It does not decide when to close the two gaps (step-log 「남은 것」 ⑥).
