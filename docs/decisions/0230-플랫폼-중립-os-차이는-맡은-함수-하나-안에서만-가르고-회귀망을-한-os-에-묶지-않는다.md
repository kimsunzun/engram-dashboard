# ADR-0230: 플랫폼 중립 — OS 차이는 맡은 함수 하나 안에서만 가르고 회귀망을 한 OS 에 묶지 않는다

- 상태: 확정 (2026-09-24, 근거: 사용자 결정)
- 관련: CLAUDE.md 「플랫폼 중립」(이 결정의 원칙 본문) · CLAUDE.md 「0. 판단 기준」(적용하는 기존 기준) · ADR-0131(CI windows 단일 러너 — 아래 「영향」의 알려진 갭) · `crates/engram-dashboard-agent/src/backend/mod.rs:44`(`console_command` — 지킬 모양의 선례) · step-log 「S21 — 첫 대화 뒤에만 세션 id 를 영속하는 이어받기」 항목의 「남은 것」 ⑥

## 맥락

배포는 지금 Windows 하나다 — 배포판 zip 은 `windows-latest` 러너가 `scripts/build-release.ps1` 로만 만든다(`.github/workflows/ci.yml:897`). macOS 는 나중 일이고, 지금 이식하는 것이 아니다.

풀어야 할 것은 이식 자체가 아니라 **그때 무엇을 고쳐야 하느냐**다. 사용자 원문: 「지금 당장 맥으로 한다는건 아니고 그것을 위한 구조를 미리미리 갖춰야지」. 여기서 「구조」는 두 가지를 뜻한다 — ① OS 마다 달라지는 일이 그 일을 맡은 함수·모듈 안에 갇혀 있고 부르는 쪽은 OS 를 모른다 ② 회귀망이 OS 와 무관하게 선다.

## 결정

1. **OS 마다 달라지는 일은 그 일을 맡은 함수·모듈 하나 안에서만 `#[cfg]` 로 가르고, 나머지 코드는 그 함수만 부른다.** 부르는 쪽에 `cfg!(windows)` 를 흩뿌리지 않는다.
2. **회귀망도 한 OS 에 묶지 않는다.** 시험 파일을 통째로 `#![cfg(windows)]` 로 막으면 다른 OS 에서는 그 회귀망이 실패가 아니라 침묵이 된다.
3. 원칙 본문은 CLAUDE.md 「플랫폼 중립」이 갖는다.

## 거부한 대안

- **나중에 맥을 할 때 한꺼번에 옮긴다** — 사용자 기각: 그때 가서 옮기면 전체 리팩토링이 된다(「안그러면 나중에 전체 리팩토링을 하니깐」, 2026-09-24). ★기각 근거의 강도 = **약함**(서술)★ — OS 분기가 퍼진 범위(아래 「영향」의 37파일)는 실측이지만, 한꺼번에 옮기는 비용 자체는 재지 않았다. 사용자가 직접 정한 원칙이다.

## 근거

- **사용자 결정(2026-09-24)** — 원문: 「지금 당장 맥으로 한다는건 아니고 그것을 위한 구조를 미리미리 갖춰야지 안그러면 나중에 전체 리팩토링을 하니깐.」
- **기존 기준의 적용** — CLAUDE.md 「0. 판단 기준」: 저위험 + 장기(경계·seam·타입 — 나중에 바꾸면 비싼 것)는 지금 충분히 깐다. OS 차이를 가두는 경계가 그 부류다.

## 영향 / 불변식

- **지킬 모양(선례)** — `console_command`(`crates/engram-dashboard-agent/src/backend/mod.rs:44`): Windows = `cmd.exe /c <program>`, 그 밖 = 그대로 실행. 스폰을 조립하는 두 백엔드(`crates/engram-dashboard-agent/src/backend/claude/mod.rs:310` · `crates/engram-dashboard-agent/src/backend/codex/mod.rs:971`)는 OS 를 가르지 않고 이 함수만 부른다.
- **모으려는 것의 실례 — 실행파일 이름의 `.exe`.** 「실행파일 이름에 `.exe` 를 붙이나」라는 같은 OS 차이를 적어도 네 자리가 각자 `cfg!(windows)` 로 가른다 — `crates/engram-dashboard-daemon/src/lib.rs:96`(앱) · `crates/engram-dashboard-daemon/src/lib.rs:146`(CLI) · `crates/engram-dashboard-discovery/src/lib.rs:981`(데몬) · `crates/engram-dashboard-daemon/src/bin/roundtrip_smoke.rs:903`(CLI).
- **현황(실측 2026-09-24)** — `crates`·`src-tauri` 아래 `cfg(windows)` 나 `cfg!(windows)` 를 담은 파일이 37개다(`rg -l 'cfg!?\(windows\)' crates src-tauri`. `cfg(not(windows))` 를 담은 파일은 전부 `cfg(windows)` 도 담고 있어 이 수에 이미 들어 있다). ★이 수는 위반 수가 아니라 살펴볼 자리의 수다★ — 선례처럼 한 함수 안에 갇힌 것도 들어 있다.
- **알려진 갭 ① — 통째로 막힌 시험 파일 여섯.** 다른 OS 에서는 이 회귀망이 조용히 컴파일에서 빠진다.
  - `crates/engram-dashboard-agent/tests/activation.rs:6`
  - `crates/engram-dashboard-agent/tests/canonical_name_wiring.rs:22`
  - `crates/engram-dashboard-agent/tests/stdio_physical_pipe.rs:14`
  - `crates/engram-dashboard-agent/tests/stdio_smoke.rs:8`
  - `crates/engram-dashboard-agent/tests/submit_delivery_boundary.rs:13`
  - `crates/engram-dashboard-discovery/tests/stop_smoke.rs:14`
  - ★파일 **안에서** Windows 로 막힌 시험 모듈도 같은 침묵이다★ — 예: `crates/engram-dashboard-agent/src/transport/pty.rs:682` · `:757` · `crates/engram-dashboard-agent/src/backend/codex/mod.rs:3421` · `crates/engram-dashboard-net/src/instance.rs:333`(`#[cfg(all(test, windows))]` — ★단 이쪽은 `:319` 에 비-Windows 짝(`non_windows_tests`)이 있어 침묵이 아니라 OS 마다 제 동작을 재는 모양이다 — 원칙이 바라는 형태의 예★) · `crates/engram-dashboard-daemon/tests/ws_e2e.rs:2282`(`#[cfg(windows)] mod real_process`). 찾는 법 = `rg -n -U '#\[cfg\(all\(test, windows\)\)\]|#\[cfg\(windows\)\]\s*\n\s*mod \w+ \{' -g '!**/examples/**' crates src-tauri`(실측 2026-09-24 = 위 다섯 자리 — 여러 줄 매치라 `ws_e2e.rs` 는 두 줄로 찍혀 출력은 여섯 줄). ★명단이 아니다★ — 시험 함수 하나에 붙은 `#[cfg(windows)]`(예: `crates/engram-dashboard-base/src/platform.rs:242`)도 같은 부류이고 여러 파일에 있지만 이 찾는 법에는 안 걸린다.
- **알려진 갭 ② — 개발 도구와 CI 가 Windows 전용.** 실행 스크립트(`scripts/` 의 `.bat` 다섯 · `.ps1` 셋) · GUI 실측(`scripts/cdp.mjs` — WebView2 CDP) · CI 검증 잡 셋(backend · gates · frontend)과 릴리즈 빌드가 `windows-latest` 에서만 돈다(`.github/workflows/ci.yml:55` · `:378` · `:851` · `:900` — 러너 단일화의 근거 = ADR-0131).
- **이 ADR 은 코드를 바꾸지 않는다.** 두 갭을 언제 메울지는 정하지 않았다(step-log 「남은 것」 ⑥).
