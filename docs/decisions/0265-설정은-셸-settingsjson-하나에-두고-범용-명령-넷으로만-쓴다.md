# ADR-0265: 설정은 셸 settings.json 하나에 두고 범용 명령 넷으로만 쓴다

- 상태: 확정 (2026-10-02, 근거: 사용자 결정 2026-10-02 (`docs/research/storage-management-survey-2026-10-02.md` 「0. 결정」) + 사용자 결정 U1 · U2 (TRD §14-7) + TRD `docs/process/S21-storage/trd.md` §3-5 · §5 · §11-3 + P2a 구현 코드 리뷰(마무리 중)) · 부분 폐기 by ADR-0274 (결정 4 의 떠 두기 규칙)
- 관련: Amends ADR-0166 (결정 1과 3과 5와 7과 8과 9) · Amends ADR-0167 (결정 1과 3과 6과 7과 8) · Amends ADR-0051 (권위 프론트 전용과 영속 localStorage 조항) · Amends ADR-0169 (결정 1의 ui.refresh 경로와 받아들인 대가와 chatStyleStore 불변식) · ADR-0264(데이터 배치 — `shell\config\` 는 취향) · ADR-0081 결정 3(두 껍데기, 서비스 하나) · ADR-0102(웹뷰 첫 invoke 전 manage) · ADR-0035(프론트 전용 예외 목록) · TRD `docs/process/S21-storage/trd.md` · 조사 `docs/research/storage-management-survey-2026-10-02.md` · `src-tauri/src/settings/` · step-log S21 · Amended by ADR-0274 (결정 4 의 떠 두기 규칙)

## 맥락

설정 파일은 셸의 `ui-settings.json` 하나다 — `{"theme":…, "windows":{label:…}}`, 자리는 루트 평면(TRD §3-5). 그 파일은 밖의 에이전트가 직접 고치고 셸은 `ui.refresh` 로 다시 읽기만 한다(ADR-0166 결정 3). 챗 스타일은 프론트가 권위를 쥐고 localStorage 에 영속한다(ADR-0051). ADR-0169 가 버스 이전 곁문을 걷은 뒤로 릴리스 빌드에서는 챗 스타일을 바꿀 길이 없다(그 ADR 「받아들인 대가」).

ADR-0167 은 앱 쪽 쓰기가 늘면 밖의 편집자와 앱이 한 파일을 다투게 된다고 적고 갈림길 둘(파일을 쪼갠다 · 쓰기를 한 곳으로)을 열어 뒀다. 저장 관리 작업(ADR-0264 · TRD S21-storage)이 취향을 담을 자리 `shell\config\` 를 세우면서 그 갈림길에 답할 때가 됐다.

사용자 결정(2026-10-02, 조사 「0. 결정」): 설정 = `shell\config\settings.json` — 사람·LLM 이 정하는 값, 기본값에서 바꾼 것만. 키는 이름공간. 접근은 범용 명령 넷뿐이고 설정 추가는 스키마 한 줄 등록이다. LLM 이 `ui-settings.json` 을 직접 고치던 경로를 폐지한다. 저장 계층 한 곳만 파일을 안다. 챗 스타일을 localStorage 에서 여기로. 화면에서 바꾼 테마도 저장한다 — 전체 기본 = `settings.json` · 창별 = `state.json` 의 그 창 항목.

## 결정

1. **자리 = `shell\config\settings.json` 하나**(`DataLayout::shell_config_dir` — ADR-0264). 기본값에서 바꾼 것만 적는다. 파일 = 평평한 점 키 객체 + 예약 키 — `{"$version":1, "theme.default":"light"}`.
2. **설정 하나 = 스키마 표 한 줄**(`src-tauri/src/settings/registry.rs` 의 정적 표 — 키 · 종류 · 기본값 · 설명). **기본값의 정본은 이 표다.** 키 = 소문자 이름공간 + 점(`theme.*` · `chat.style.*`)이고 마지막 마디는 기존 철자다. 초기 키는 12개 — `theme.default`(선택지 `dark` · `light` · `e-ink`, 기본 `dark`) + `chat.style.*` 11개(결정 9). `CssLength` 는 범위를 단위마다 따로 선언한다 — `px` 는 필수, `rem` 은 그 키가 받을 때만(`em` 은 `rem` 과 같은 범위). 선언 안 된 단위는 `INVALID_ARGUMENT` 다.
3. **wire 계약 — 값은 언제나 정규 문자열 하나.** get · set 답 · 알림이 싣는 값은 정규형이다.

   | 종류 | 받는 입력 | 정규형 | 파일에 적는 JSON |
   |---|---|---|---|
   | `Choice` | 선택지 낱말, 대소문자 무시 | 표의 철자 그대로(`e-ink`) | 문자열 |
   | `CssLength` | 앞뒤 공백 허용 · 수 + 그 키가 선언한 단위(대소문자 무시) · 그 단위의 범위 안 | 최단 십진 + 소문자 단위(`15px` · `0.9rem` · `-1rem`), `+` 없음 | 문자열 |
   | `CssNumber` | 단위 없는 수 | 최단 십진(`1.45`) | 문자열 |

   오류는 셋이다 — 모르는 키 = `NOT_FOUND` · 형식·범위 위반 = `INVALID_ARGUMENT`(기대 형식을 문구에) · 디스크 쓰기 실패 = `INTERNAL`(메모리 · `rev` 불변 · 알림 없음). **쓸지는 디스크로, `changed` 는 유효 값으로 가른다** — 유효 값이 지금과 같으면 `changed:false` · `rev` 그대로 · 알림 없음이되, 파일이 목표와 다르면(밖에서 고친 값 · 접힌 못 쓸 값 · 정규형이 아닌 철자) 파일만 바로잡아 쓴다. 유효 값이 바뀌는데 파일이 이미 목표대로면 쓰지 않고 `changed:true` · 알림만 낸다. 파일을 못 읽으면(읽기 IO 실패 · 통째로 못 쓰는 파일) 유효 값이 바뀔 때만 쓴다(읽기 IO 실패면 그 쓰기는 `INTERNAL`). 기본값과 같은 값을 받으면 파일에서 그 키를 지운다. `reset` 도 같은 가름이다. 한 호출 = 한 파일 — 장래 두 파일에 걸치는 `reset` 은 `INVALID_ARGUMENT` 로 거절한다.
4. **파일을 아는 것은 저장 계층 하나**(`settings/store.rs`). 경로 갈래 함수는 지금 두지 않는다. 쓰기 = 쓰기 직렬화 락(`io`) 아래 **읽고-고치고-쓰기**(매번 파일을 다시 읽어 받은 키만 바꾼다)이고 원자적이다(임시 파일 → `sync_all` → rename · rename 이 접근 거부 · 공유 위반 · 잠금 위반이면 20 ms 간격으로 5번까지 다시 · `write_atomic` 은 셸 공용 `fsutil.rs`). 쓸 원문이 64 KiB 를 넘으면 쓰지 않고 `INTERNAL`. **파일이 없거나 통째로 못 쓰면 새 파일을 메모리의 유효 덮어쓰기 전부에서 다시 짓는다** — 그래서 실행 중 파일을 지워도 초기화가 아니고(다음에 파일을 쓰는 호출이 보이는 값 그대로 되살린다), 멀쩡한 파일에서 손으로 지운 키는 되살리지 않는다(그 편집이 다음 부팅에 이긴다 — 세션 기본값, TRD §10 F20). 항목별 관용 — 모르는 키는 무시하되 파일에 그대로 남긴다 · 아는 키의 못 쓸 값은 기본값으로 접고 warn(파일은 덮일 때까지 그대로) · 읽는 양 상한 64 KiB · 앞머리 UTF-8 BOM 무시 · `$version` 은 수 1(`1.0` 도 1). **통째로 못 쓰는 파일은 적재 때 건드리지 않고**(메모리는 기본값) **첫 쓰기가 원본을 `settings.json.corrupt-<ms>` 로 떠 둔 뒤 그 자리를 원자적으로 갈아끼운다** — 이름이 겹치면 `-<n>` 을 덧붙이고 앞선 사본을 덮지 않는다 · 사본은 `sync_all` 까지 한 뒤 갈아끼우므로 파일이 없는 순간이 없다 · 떠 두기가 실패하면 그 쓰기는 `INTERNAL` 이고 원본은 그대로다. 1 MiB 넘는 원본은 떠 두지 않고(error 뒤 갈아끼운다 · 상한은 뜨는 도중에도 지킨다) 이 프로세스가 직전에 떠 둔 사본이 그 자리에 남아 있고 지금 원본과 바이트가 같으면(길이 · 수정 시각은 먼저 거르는 값일 뿐) 다시 떠 두지 않는다(세션 기본값 — TRD §10 F21). ADR-0166 결정 9 「`.corrupt` 없음」을 뒤집는다.
5. **명령 넷 + Tauri 껍데기, 서비스 하나.** 셸 명령 표의 한 블록(`layout/commands.rs`)에 더하고 `catalog_version` 을 10 으로 올린다.

   | 명령 | effect | 인자 → 답 |
   |---|---|---|
   | `settings.get` | Read | `{key?}` → `{rev, items:[{key, value, is_default}]}` |
   | `settings.set` | Write | `{key, value}` → `{rev, key, value, changed}` |
   | `settings.reset` | Write | `{key}` → `{rev, reset:[key…]}` |
   | `settings.schema` | Read | `{key?}` → `{items:[{key, kind, default, choices, min, max, description}]}` |

   `key` = 정확한 키 또는 점으로 끝나는 접두. `reset` 은 키가 필수다(전체 초기화 없음). 사람 경로도 같은 서비스다 — `#[tauri::command] settings_get/set/reset/schema` 껍데기(ADR-0081 결정 3)이고 프론트는 이것을 쓴다. 서비스는 Tauri 빌더 전에 **읽기 전용으로** 적재해 manage 하고(웹뷰 첫 invoke 전에 존재 — ADR-0102) 쓰기는 `setup` 에서 켠다.
6. **변경 알림 = 커밋 뒤 `settings:changed {rev, items}`.** 상태 락을 놓은 뒤 알림 순서 락(`announce`) 아래서 모든 웹뷰에 보낸다 — 알림 순서 = `rev` 순서. `rev` 는 유효 값이 바뀐 쓰기마다 오르는 단조 번호다. 구독 먼저 → `settings_get` 당기기. 받는 쪽은 항목마다 그 키에 마지막으로 적용한 `rev` 보다 클 때만 적용한다(처음 보는 키는 그대로 · `settings_get` 답도 항목마다 답의 `rev` 로) — 답을 통째로 버리지 않는다. 챗 스타일의 권위는 셸로 옮긴다 — `chatStyleStore` 는 `chat.style.*` 를 CSS 변수에 붙이는 **적용자**가 되고(`CSS_VAR_BY_KEY` 화이트리스트는 프론트 소유) 쓰기는 `settings_set` 이다. localStorage 읽기·쓰기와 개발 손잡이 `window.__engram.chatStyle` 은 걷는다. ADR-0035 의 프론트 전용 예외 목록(`docs/reference/architecture-overview.md:578`)에서 `chatStyleStore` 를 뺀다.
7. **테마 — 전역은 설정, 창별은 상태.** 유효 테마(창 W) = W 의 창 테마 ?? `theme.default`. 셸이 계산하고 기존 창별 배달(`get_ui_settings` 당기기 + `ui:settings-updated` 밀기)을 그대로 쓴다. `theme.default` 쓰기와 창별 쓰기는 각자 저장을 끝낸 뒤 같은 함수 `push_effective_themes()` 를 부르고, 그 함수가 모든 창의 유효 값을 새로 계산해 민다 — 마지막 밀기 = 마지막 읽기라 두 쓰기가 엇갈려도 낡은 조합이 화면에 남지 않는다. **바꾼 테마가 저장된다** — 전역 = `settings.set theme.default <값>` · 창별 = 셸 명령 `window.setTheme {window, theme}`(`theme:null` = 덮어쓰기 해제) · 조회 `window.getTheme {window}` → `{theme, effective}`. 창별 값은 그 창의 모델 항목에 들어가 **창과 같이 죽는다** — 부팅 쓸기가 필요 없어진다. 창별 테마가 명령 넷 밖의 다섯째 길인 이유 = 그 값은 설정이 아니라 상태이고, 상태 파일은 기계가 통째로 다시 쓰므로 손 편집 경로가 될 수 없다. 오늘 화면에는 테마를 바꾸는 UI 가 없다(ADR-0167 결정 5). 창별 부분(`window.setTheme`/`getTheme` · 쓸기 폐지)은 L3(P3d)에서 착지한다 — 그때까지 ADR-0167 결정 3·6·7 은 코드에 살아 있다.
8. **옛 값은 다루지 않는다(U1).** `settings.json` 은 기본값에서 시작하고 `ui-settings.json` 에서 채우지 않는다. 셸은 그 파일의 `theme` 를 있든 없든 못 쓸 값이든 무시한다 — 지금은 못 쓸 `theme` 하나가 파일 전체를 거부해 창별 칸까지 함께 버려지므로 파서가 `theme` 를 보지 않는다. 그 파일은 L2 동안 창별 칸의 집으로 살아 있고, P3d 부터 셸은 그것을 읽지도 쓰지도 않는다. 남은 파일은 따로 다루지 않는다. 챗 스타일의 localStorage 값도 가져오지 않는다. 이전 코드는 없다.
9. **`chat.style.*` 는 임시 이름공간이다(U2).** 지금 11키(`railRowPt` · `plainRowPt` · `userPy` · `userPx` · `userMy` · `railGutter` · `railLineOffset` · `railDotTop` · `fontSize` · `lineHeight` · `waitStripH`)와 기본값을 그대로 옮긴다. `lineHeight` 만 `CssNumber` 이고 `railLineOffset` 은 음수를 허용한다. 챗 영역은 나중에 쪼개 다시 짜고 챗 배치는 결국 플러그인으로 자유롭게 짜게 되므로 이 키들은 갈려 나간다 — 키 이름 · 묶음 · 범위 다듬기는 하지 않는다. `theme.css` 의 `--chat-*` fallback(첫 페인트용)은 남긴다.

## 거부한 대안

- **값마다 명령.** ADR-0169 가 이미 거부했다 — 사유는 그 ADR 「거부한 대안」 첫 항목.
- **파일 직접 편집 + `ui.refresh`.** 밖의 편집자와 앱이 한 파일을 다툰다. ADR-0167 이 남긴 갈림길(파일을 쪼갠다 · 쓰기를 한 곳으로) 중 「쓰기를 한 곳으로」를 고른다. 직접 고치던 경로의 폐지는 사용자 결정이다(조사 「0. 결정」).
- **localStorage.** 사용자 결정(조사 「0. 결정」 — 「챗 스타일을 localStorage 에서 여기로」). 근거: (기록 없음).
- **데몬 소유.** 표시 설정은 셸이고, 데몬은 에이전트를 띄울 때 들어가는 정의만 가진다 — 사용자 결정(조사 「0. 결정」).
- **설정과 상태를 한 파일에.** 사람이 고치는 설정과 기계가 쓰는 상태를 목적별로 가르는 것이 피어의 공통이다(조사 §2-1 — VS Code · Windows Terminal · JetBrains · Zed · herdr). orca 는 한 파일에 담았다가 자주 바뀌는 데이터 때문에 보조 파일을 따로 떼야 했다(조사 §4). 사용자 결정도 둘을 다른 파일로 갈랐다(`settings.json` · `state.json`).
- **선언 매크로에 임의 JSON 을 더해 값을 싣는다(F1).** 선언 매크로의 타입 알파벳에 임의 JSON 이 없다(`command/src/macros.rs:37-47`) — 그래서 값은 정규 문자열 하나로 싣는다(결정 3).
- **빈 경로 갈래를 미리 깐다.** 지금은 키가 전부 한 파일로 간다. 다른 파일이 필요해지면 그 첫 키와 함께 저장 계층 안에서만 가르므로 호출부는 고치지 않는다.
- **옛 값 가져오기**(`ui-settings.json` · 챗 스타일 localStorage). 사용자 결정 U1 — 배포본(v0.1.0–v0.3.2)은 있으나 사용자가 본인뿐이라 지킬 사용자 데이터가 없다(사용자 판단 2026-10-02).
- **챗 스타일 키 재설계.** 사용자 결정 U2 — 챗 영역 재작성과 플러그인 배치로 갈려 나갈 임시 이름공간이다.

## 근거

- **사용자 결정 2026-10-02 (조사 「0. 결정」)** — 자리 · 바꾼 것만 · 이름공간 키 · 범용 명령 넷 · 스키마 한 줄 등록 · 직접 편집 경로 폐지 · 저장 계층 한 곳 · 챗 스타일 이전 · 화면에서 바꾼 테마도 저장(전역 = 설정 · 창별 = 상태).
- **U1 (사용자 판단 2026-10-02)** — 처음엔 「애초에 기존데이터라는게 따로없어. 아직 릴리즈 출시하지 않아서. 그냥 배제하고 작업하면 될듯」이었고, 재리뷰가 「출시 전」 전제를 바로잡자(GitHub 릴리스 v0.1.0–v0.3.2 공개 · v0.3.2 = 2026-09-27) 「본인뿐임. 챙길필요없어」로 답했다. 옛 값 처리를 계획에서 모두 뺀다(TRD §14-7).
- **U2 (사용자 결정 2026-10-02)** — 「기존것만 잘 옮겨 깊게하지는 말고」 · 「가볍게 구현해 현재 있는것만」(TRD §14-7).
- **피어 조사** — 설정과 상태의 목적별 분리(조사 §2-1).
- **코드** — 값을 문자열 하나로 싣는 이유는 선언 매크로의 타입 알파벳이다(`command/src/macros.rs:37-47`).
- **리뷰** — TRD 리뷰 반영 대응표 = TRD §14. ★§14-7 반영분(U1 · U2 포함)은 TRD 재리뷰를 따로 거치지 않았다★. 자리 · 키 수 · 오류 어휘 · 쓰기 방식 · `.corrupt-<ms>` · 서비스 적재 · 알림 · `catalog_version` 은 P2a 구현 코드 리뷰(deep)에서 확인한 사실이고, 그 리뷰의 지적으로 바뀐 사양(결정 3 · 4 · 6)은 TRD §14-8 에 있다.
- **이 ADR 이 기대는 GUI 실측은 없다** — 위 사실은 소스 읽기와 코드 리뷰에서 왔다.

## 영향 / 불변식

- **설정을 쓰는 길은 명령 넷과 같은 서비스를 부르는 Tauri 껍데기뿐이다.** 파일 직접 편집 + `ui.refresh` 를 설정 경로로 되살리지 않는다. 새 설정은 스키마 표에 한 줄을 더한다 — 값마다 명령을 만들지 않는다.
- **파일 이름 · 위치는 `settings/store.rs` 만 안다.** 다른 파일이 필요해지면 그 모듈 안에서만 가른다.
- **쓰기는 읽고-고치고-쓰기라 모르는 키를 지우지 않는다** — 앱 밖에서 고친 다른 키는 실행 중엔 반영되지 않고 다음 부팅에 읽힌다.
- **못 읽는 파일은 원본을 남긴 뒤에만 덮는다** — 적재는 건드리지 않고, 첫 쓰기가 `.corrupt-<ms>` 로 떠 둔 뒤 갈아끼운다(1 MiB 넘는 원본은 떠 두지 않고 error 를 남긴다 · 상한은 뜨는 도중에도 지킨다 — TRD §10 F21).
- **알림은 커밋 뒤 · 쓰기 락과 상태 락 밖 · 알림 순서 락 안(`rev` 순서)이다 — 알림 포트는 막히지 말고 설정을 쓰지 말 것(교착).** 디스크 쓰기가 실패하면(`INTERNAL`) 메모리도 `rev` 도 알림도 바뀌지 않는다.
- **테마 밀기는 `push_effective_themes()` 한 자리에서만 계산한다.** 그 함수의 테마 관문 락이 가장 바깥이다 — 쥔 채 설정 상태 락(`state`)을 짧게 읽고 놓고 → `ViewManager` · 트리 칸 락을 짧게 읽고 놓고 → 창마다 emit. 설정 쓰기는 설정의 모든 락을 놓은 뒤에 밀기를 부른다.
- **셸이 떠 있어야 닿는다**(오늘 `ui.refresh` 와 같은 성질).
- **U2 의 대가** — 대조 시험이 없으므로 (a) `theme.css` fallback 이 표의 기본값과 같은지 (b) 표의 11키가 프론트 `CSS_VAR_BY_KEY` 와 같은지를 아무것도 확인하지 않는다. 키 집합이 어긋나면 `settings.set chat.style.X` 가 `changed:true` 로 답하는데 화면에는 아무 변화가 없다.
- **`chat.style.*` 를 걷는 챗 재작성이 파일 정리까지 맡는다** — 표에서 뺀 키는 모르는 키라 저장 계층이 남기고, 모르는 키의 `reset` 은 `NOT_FOUND` 라 명령으로 지울 수 없다.
- **ADR-0169 「받아들인 대가」(릴리스 빌드에서 챗 스타일을 바꿀 길이 없다)가 해소된다** — 챗 스타일은 `settings.set` 으로 바뀐다.
- **코드 앵커 = `// ADR-0265`** — 설정 저장 계층 · 스키마 표 · 명령 블록.
