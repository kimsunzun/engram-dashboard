# ADR-0118: Linked to reply-contract fail-closing — amending the contract lifetime clause (proper ADR-0116)

- 상태: 확정 (2026-07-30, basis: user decision — the same ratification Q&A session as ADR-0116, step-log 2026-07-30)
- 관련: Amends ADR-0108 (decision 1 the contract close condition) · **ADR-0116(the 3-branch entry and contract fail-close proper — read them as a pair)** · ADR-0108(decisions 2, 3, 4 all survive — in particular the decision 4 guard invariant)

## 맥락

ADR-0108 decision 1 nailed down that "a contract is open **until a reply arrives** and purge applies **only to contracts closed by a reply**" (deadline exceeded ≠ closed). Decisions 2 and 3 of ADR-0116 add **two paths that close a contract without a reply** (a reply confirmed unable to reach · the requester's profile deleted), so the scope of that clause changes. So that a session that reads only 0108 does not read "it never closes except by a reply" as a valid invariant, it is stamped under a separate number (the same precedent as the 0111↔0112 and 0116↔0117 pairs — the proper prose is in ADR-0116).

The place where 0108 was breached for 6 rounds was exactly "who touches an unsettled contract, and when", so how the new close path joins with that guard is also fixed here.

## 결정

1. **Add `reply_failed` to the contract close reasons.** The "open until a reply" of ADR-0108 decision 1 survives as the **default**, but in two cases the contract is **fail-closed without a reply**: ① the reply send fails with **`RECIPIENT_NOT_FOUND`** (the requester's name exists nowhere) ② the requester profile deletion cleanup (ADR-0116 decision 3 — but a contract already `replied` is not reversed). **A deadline exceeded (timeout) is still not a close reason** — the core of 0108 decision 1 (notice ≠ closed) is unchanged.
2. **Other reply failures do not close it** (user decision 2026-07-30). If a reply fails with `MAILBOX_FULL` or `RECIPIENT_AMBIGUOUS`, the contract **stays open** — if a retry succeeds, it closes normally as `replied`. **It is not a new zombie class**: when its deadline notice fires, this contract also gains the retirement eligibility of 0108 decision 2 (the notified ones), and a contract with no deadline is retirable from the start, so it does not occupy the cap permanently.
3. **Guard first (respecting the ADR-0108 decision 4 invariant).** `reply_failed` and deletion cleanup **do not touch contracts marked provisional (`provisional`) or pending retirement (`pending_retirement`)** — the lifetime of an unsettled item is owned by its guard, so they apply only after settlement (a failed reply that arrives in between is no action).
4. **A `reply_failed` contract drops out of the open cap 512 count** (the `occupied_slots` single predicate is kept). Keeping zombie contracts from eating the cap is the purpose of ADR-0116 decision 2.

## 거부한 대안

- **Discard ADR-0108 in full** — decisions 2 (cap retirement policy), 3 (mark-and-sweep), and 4 (guard invariant) are entirely valid regardless of this amendment, and 3 and 4 were obtained through 6 rounds of findings, so the cost of a wrong discard is large. Rejected.
- **Bury it in the proper ADR-0116 and skip the stamp on 0108** — a session that reads only 0108 reads "no close except by a reply" as a valid invariant (violating the no one-way link). Rejected.
- **Treat `reply_failed` as a retirable contract too (mark it retired instead of removing it)** — retirement is a separate axis split by "is there a promise left to tell the sender", and a fail-close is already a settled outcome, so there is no reason to put it into the retirement candidate calculation. Dropping out of the count is enough.
- **Close on a transient reason too** — the contract would close as a permanent failure because a live requester's mailbox was briefly full, and even if a retry is actually delivered the ledger stays "reply failed" (the opposite direction of the ledger lying). Rejected by user decision. *(The current code is not this way — the S18.5 implementation is keep-open regardless of reason (the provisional A1 proposal), and closing unconditionally is the old implementation before that. What this slice does is narrow "open unconditionally" to "close if the name is missing".)*

## 근거

- User decision (2026-07-30): "A(도달 불가 확정)는 실패 종결이 맞고 B(일시 사유)는 그대로 두기" (A (confirmed unreachable) is right as a fail-close, and leave B (transient reason) as is) — so that a retry closes the contract by the normal path.
- The failure class that ADR-0108 decision 4 tried to block (removing an innocent contract · contaminating a provisional contract) can be reproduced as is in the new close path, so the guard priority is made explicit (decision 3).

## 영향 / 불변식

- **Contract close reasons = reply accepted (`replied`) | confirmed-unreachable failure (`reply_failed`) | requester deleted (`reply_failed`).** A deadline exceeded or a TTL expiry is not a close reason.
- Decisions 2, 3, 4 of ADR-0108 and their code anchors (`ledger.rs` occupies_slot · cap retirement oldest · purge exemption · due_timeouts skip · `service.rs` ReservationGuard) all survive — the new close path must also pass the same predicate and guard.
- The implementation contract details (vocabulary · transitions · query exposure) are canonical in spec §3 item 7-④ · §5 deletion cleanup · §6 vocabulary.
