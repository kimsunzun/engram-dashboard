## 맥락
Today the claude JSON transport (`StdioTransport`) does not know interrupt — `interrupt()` returns `Unsupported` (`transport/stdio.rs:371-376`) and the capability `control.interrupt` is false. As it stands, the Esc of ADR-0237 does nothing in a claude slot. The default backend is claude, so most of the felt value is empty.

The user decided to build it this time [사용자 U1 2026-09-27] — 「claude 쪽 기능 확인해서 적용」 (spike first — design as is).

Three things had to be solved.
- **The route by which the line reaches the transport** — the instruction was 「`cancel_async_message` 가 닿는 길을 따라 하라」 (follow the route cancel_async_message takes). That route is the session doing `send_input` of `MidTurnPolicy::SessionClassified { cancel_line }` (`types.rs:215`) inside the input lock (`session.rs:563-580`).
- **Interrupt when there is no turn** — codex refuses an interrupt when there is no turn (`backend/codex/transport.rs:4045-4061` — `Unsupported("… 중단할 턴이 없다")`). claude must follow the same bus contract (ADR-0237 decision 2 mapping = CONFLICT).
- **The `result` of an interrupted turn** — the current translator (`claude/mod.rs:944-970`) emits `Error(RESULT_FAILURE_DETAIL…)` when `is_error || subtype.starts_with("error")`. The `result` of an interrupted turn can arrive as `is_error: true` with `terminal_reason` = `aborted_streaming` | `aborted_tools` (SDK `types.py` · SDK issue #429 — main cross-check). Left as it is, one Esc draws an error row and sets the stop after an error (`last_end_failed`), which stops the mail — the opposite of the intent.

**Consistency with ADR-0044 decision 6 · 「통로에 땜질하지 말 것」** [메인 — the orchestrator's consistency judgment]. ADR-0044 postponed interrupt as a follow-up (decision 6 — 「stdio엔 PTY Ctrl-C 없음」) and wrote 「interrupt 미지원(kill만)은 의도된 미구현 — 통로에 땜질하지 말 것」 (0044 「영향 / 불변식」). What that rule blocked was faking an interrupt inside the transport (for example, emulating a PTY Ctrl-C). In this ADR it is the claude backend that builds the control line, and the vendor knowledge stays in the backend (ADR-0004). When the transport receives a request, it only writes the one line of unknown meaning that the backend gave it — the same shape as the `structured` injection it already does today. The capability `control.interrupt` comes from the transport caps (TRD §3-4 · §11 ①).

## 결정
Notation — **[사용자]** = a decision the user answered · **[메인]** = an orchestrator decision (TRD §11) · **[고름]** = an internal implementation the TRD picked.

1. **Control line = `{"type":"control_request","request_id":"interrupt:<uuid v4>","request":{"subtype":"interrupt"}}\n`** — the shape is from the official Agent SDK (research §2-1). It is serialized as a typed struct like `cancel_line` (`claude/mod.rs:698-724`). ★We do not carry an optional capability like `cancel_queued`★ — the meaning is the same as codex: **only the running turn stops, and the queued input already received goes to the next turn** (ADR-0235 decision 4 — `Interrupted` does not set the stop · decision 5 — the remaining text goes in the next single turn). Whether that is the meaning of `still_queued` in the CLI response is confirmed by spike S3.
2. **The route by which the line reaches the transport = transport injection** [메인 ① accepted] — the same shape as the `structured` injection (`stdio.rs:52-56`).
   ```rust
   pub type InterruptLine = Arc<dyn Fn() -> Option<Vec<u8>> + Send + Sync>; // None = 「지금은 끊을 턴이 없다」
   impl StdioTransport { pub fn with_interrupt(mut self, line: InterruptLine) -> Self { … } }
   ```
   - `interrupt()`: if there is an injection and the function returns `Some(b)`, it puts the bytes in the input queue · if `None`, `Unsupported("끊을 턴이 없다")` · if there is no injection, today's `Unsupported`.
   - Capability `control.interrupt = self.interrupt.is_some()` — it means 「끊을 수 있는 통로」 (a transport that can interrupt), not 「지금 턴이 있다」 (there is a turn now).
   - The transport does not know the meaning of these bytes (it stays a dumb pipe). The claude knowledge — the line shape and the decision of whether a turn is open — lives only in `backend/claude` (「백엔드 확장」 · ADR-0004). `open_spawn` (`claude/mod.rs:424-433`) unpacks the tuple that `open` returned and plugs it in.
   - The line goes into the input queue (`stdio.rs:46-47` — a single writer thread) and is serialized **as a whole** with the user lines (no line mixing). It does not take the input lock (`input_order`).
   - The response `control_response` (`request_id` prefix `interrupt:`) is **not translated** — `cancel_response_event` (`:1215-1235`) looks only at the `cancel:` prefix, so it is already `None`. A response arriving does not mean the turn stopped (S4).
3. **Turn-open gate** [메인 ③ resolved] — an incarnation-shared value inside `backend/claude`, `turn_gate: Arc<TurnGate>` (`struct TurnGate { open: AtomicBool }`). The same shape as the `DeliveryAck` sharing (`open_spawn` makes one and gives the same `Arc` to the decoder and to the interrupt-line function). The wire type, the session and the transport do not know this value — it is not put in `types.rs`.
   - **The side that sets it = the live decoder** — when one live line emits even one turn-progress signal event (`classify_turn` `:538-545` → `Progress` — the user echo `Structured{user}` · an `assistant` block · a streamed `TextDelta` · the `Delivered` of `command_lifecycle` `started`), `open = true`. **At `result`, `open = false`** (after today's translation). Resumption (`LineSource::Transcript`) is not touched. [고름] We take the definition of 「턴 중」 from the same single classifier as turn observation — the two definitions do not diverge.
   - **The side that reads it = the interrupt-line function** — if `open`, `Some(줄)`, otherwise `None` → the transport `Unsupported` → bus CONFLICT · WS `Interrupt` is an error response (`connection_core.rs:1222-1230`). An Esc before the turn opens is an honestly refused no-op — the user presses again.
   - ★If S4 shows 「되울림이 `system/init` 보다 먼저 오고 그 틈의 끊기는 무시된다」, we delay the point where the gate opens to **the first progress line after that turn's `system/init`**★ (same value · same refusal — only the opening line changes · not a reason to stop). That correction costs one more bit (「마지막 `result` 뒤 init 을 봤나」) · S4 records whether `system/init` comes every turn (TRD §12 round-1 low 1).
4. **An interrupted turn's `result` → `OutputEvent::TurnEnd { turn_id: None, outcome: TurnOutcome::Interrupted }`** [메인 ② accepted] — it emits neither `Error` nor `MessageDone`. `Usage` is emitted before it, as today.
   - Decision `interrupted(result)` (confirmed by spike S2) = `subtype == "interrupted"` (not an error even today — `:951-956`, kept) **or** `terminal_reason ∈ {"aborted_streaming","aborted_tools"}`.
   - The turn classifier (`classify_turn` `:553-557`) already writes `Interrupted → Ended(Other)` → the turn ends · it neither sets nor clears the stop after an error (ADR-0234). The accumulator (`structuredAccumulator.ts:213-220`) draws the `outcome: 'interrupted'` row and the divider — the same shape as a codex interrupt · frontend and wire type unchanged.
   - It is not a migration — **only the interrupt branch** goes to `TurnEnd`. Today `subtype:"interrupted"` closes with `MessageDone` (the divider only), and after this change the interrupt row is attached (still not an error). `types.rs:70` (「`MessageDone` 을 이것으로 이주시키지 않는다 — claude 는 그대로 `MessageDone` 을 쓴다」) and `claude/mod.rs:551` (「이 decoder 는 `TurnEnd` 를 내지 않는다」) collide with this change, so we fix the two comments together — the same doc also says 「어느 쪽을 내는지는 각 decoder 가 정한다」.
5. **The 「우리가 끊기를 보냈다」 marker is kept only as a reserve** [메인 ④] — we build `TurnGate.interrupt_sent` **only** when neither of the two fields (`subtype` · `terminal_reason`) can tell an interrupt apart in S2. The interrupt-line function sets it **only when the gate is open** (only when it returns a line), and the translator reads and clears it at **that turn's `result`** (the same place that closes the gate) — so an interrupt call made while idle cannot set the marker and does not mask the next turn's real error. If the spike separates it with one of the two fields, this field is not built.
6. **The queued input runs in the next turn** — an interrupt does not cancel queued input (decision 1 · `cancel_queued` not used).
7. **We document the residual race as a vendor limit — it narrows but does not close it.** If that turn's `result` comes out between reading the gate and putting the line in the queue, or before the line reaches the CLI, and **the CLI opens the next turn on its own** (the queued B · a turn the mail carried), that line interrupts **the next turn**. The frontend `streaming` turns off late, at the turn-end event, so a late Esc · bus call falls in this gap. The claude `control_request` has no turn id (codex `turn/interrupt` carries a `turn_id`), so it **cannot be closed by the vendor protocol**. Symptom = B closes as a once-interrupted turn (interrupt row · not an error · the stop unchanged — the mail does not stop). Spike S7 measures the size.
8. **If the spike (B2) fails its exit condition, the claude part stops and goes back to the user.** The canonical source for the method, runs S1–S8 and pass conditions = TRD §3-5 (results = a new report `docs/research/claude-interrupt-spike-2026-09-2x.md` + fixture `backend/claude/fixtures/interrupt_s1.jsonl`). The bus command (ADR-0237) goes ahead regardless of the spike (TRD §7 B3 ⓐ).

## 거부한 대안
- **The session input-lock route** (`MidTurnPolicy::SessionClassified { cancel_line }` — the `cancel_async_message` route the instruction told us to follow) [메인 ① — TRD §11] — ① The capability `control.interrupt` comes from the **transport's caps** (`session.rs:656-657` → `stdio.rs:425-455`) ② an interrupt is not tied to an input id, so there is no order for the input lock to guard. Reviewer check: transport injection keeps the ADR-0004 isolation · no new lock edge · the input-lease check is already covered.
- **Close an interrupted turn with `MessageDone` as today** [메인 ② — TRD §11] — when an interrupted `result` arrives with `is_error: true`, the current translator emits `Error`, draws an error row and sets the stop after an error (context). The gain of `TurnEnd{Interrupted}` = the same interrupt display as codex · the stop after an error unchanged. Reviewer check: turn observation `Ended(Other)` · `last_end_failed` unchanged · the doorbell rings · the accumulator already draws the outcome row · the queued-input golden is unaffected.
- **A queue that holds an interrupt until the turn opens** (it delays the interrupt until we see init) [메인 ③ — TRD §11] — delaying needs new shared state between the translator and the transport. The turn-open gate does that job instead — an Esc before the turn opens is `Unsupported` (a no-op · an honest answer) and the user presses again.
- **Cancel the queued input together with the interrupt** (carry `cancel_queued`) — we keep the meaning the same as codex: only the running turn stops and the queued input already received goes to the next turn (ADR-0235 decisions 4 · 5). If the CLI discards the queued input while interrupting, B vanishes from the list without a bubble — ADR-0235 decision 2 「글은 늘 보인다」 and the claude lifecycle translation table (`claude/mod.rs:1164-1181` — the `cancelled` → `Dropped{Unknown}` tombstone) break (TRD §3-5).
- **Add an argument to `StdioTransport::open`** [고름] — there are 9 `StdioTransport::open(` call sites including tests (`rg "StdioTransport::open\(" crates`). With a builder, the existing assertions (`stdio.rs:507` · `session.rs:1249` — a transport without injection is `Unsupported` · `false`) stay true as they are.

  - 「오류 뒤 멈춤」 `last_end_failed` (ADR-0231 N11 · ADR-0234) — S2. If an interrupt is read as a failure, one Esc stops the mail.
  - The reduction rule 「대기 입력 상태 = 링 사건 한 줄기」 · the claude lifecycle translation table · ADR-0235 decision 2 — S3.
  - ADR-0226 first-submit latch — not relied on (claude counts before sending · an interrupt does not touch the latch).
- **Lock order (ADR-0006)** — the interrupt line rides only the input queue · it does not take the input lock · no new lock edge.
- **The cost of the ④ reserve marker (only if built)** — a real error **of the same turn** that overlaps with an interrupt is folded into an interrupt. If it hits the residual race (decision 7), the marker is spent on the previous turn's `result`, and the next turn that the line interrupted can be read as an error (the stop after an error stands on that turn).
- **Before the turn opens · right after the turn end** — the front is a no-op refused with CONFLICT (press again) · the back is the residual race of decision 7.
- **The truncated `assistant` line right before an interrupt** — after ADR-0240, the truncated completed body of a streamed block is discarded (the user already saw as much as was streamed) and an un-streamed block goes out as the truncated body as it is. The interrupt row shows the end.
- **Capability display** — when `control.interrupt` of claude JSON becomes true, the tree `canInterrupt` (`mergeTreeNodes.ts:94`) also becomes true — it has no consumer today.
- **Two existing tests we intentionally rewrite — do not read them as a regression**: `result_interrupted_subtype_emits_only_done_no_error` (`claude/mod.rs:3390`) · `result_interrupted_subtype_with_is_error_false_emits_only_done` (`:3402`). The real error regression net = the existing `result_error_handbuilt.jsonl` is still `Error` + `MessageDone`.
