# ADR-0268: 로그는 base 의 입구로만 찍고 로그 라이브러리는 base 만 의존한다

- 상태: 확정 (2026-10-02, 근거: 사용자 결정 2026-09-26 (방향 — `docs/refactoring/architecture-discussion-2026-09-26.md` 결정 후보 3) + 사용자 결정 2026-10-02 (입구 모양 · 가리기는 찍는 곳에 · 사이드 작업) + 로그 현황 실측 master `a226f63` · 스팬 실측 `d5ac725`)
- 관련: ADR-0138(릴리스 로그 파일 동기 쓰기 — 「마스킹 · 레닥션 레이어」 기각은 그대로이고 이 결정이 기대는 근거의 하나다) · ADR-0175 결정 1(logging 은 base) · ADR-0267(command · messaging 도 base 의존) · `crates/engram-dashboard-base/src/logging/mod.rs`(`mask_secrets`) · `docs/reference/logging-conventions.md`(「보안」) · `docs/tracking-archive.md` T-1(가리기는 sink 에 배선하지 않고 호출자가 명시 호출) · 큰 절 A(로깅 시스템 설계 — 메모 「큰 절」) · step-log S21

## 맥락

`tracing` 을 직접 의존하는 crate 가 base 말고 여섯이다 — agent · daemon · discovery · messaging · net · 셸. 로그 매크로 호출은 약 530곳이다(daemon 193 · agent 129 · 셸 125 · net 38 · messaging 34 · discovery 9 — `tracing::` 경로 포함 대략치, 실측 master `a226f63`). `command` · `protocol` · `transport` 는 0.

지금 중앙에서 쥔 것은 **출력 설정**뿐이다 — 레벨 필터 · 파일 · 형식은 base 가 설치하는 구독자 한 곳에서 정한다. **로그 라이브러리 교체나 로그 규칙(필드 이름 · 형식) 강제**는 여섯 crate 를 다 고치는 일이 된다.

비밀값 가리기는 중앙에서 걸리지 않는다 — 파일 writer 는 받은 바이트를 그대로 쓰고(`crates/engram-dashboard-base/src/logging/mod.rs` 의 `FileSinkWriter::write`), 가리기는 찍는 쪽이 `mask_secrets` 를 골라 부른다. 그 배치는 이미 정해져 있다 — T-1 이 「sink 에 배선하지 않고 호출자가 명시 호출」로 구현했고, ADR-0138 이 「로그용 마스킹 · 레닥션 레이어 추가」를 기각했다(토큰이 이미 같은 폴더에 평문으로 있다 · 대신 「우리가 쓰는 문장에는 자격증명을 넣지 않는다」).

사용자(2026-09-26): 「로그 라이브러리를 왜 직접 쓰냐고. 나중에 컨트롤이 안 되잖아」.

## 결정

1. **로그는 base 를 거쳐서만 찍는다**(사용자 2026-09-26). base 가 로그 입구를 **자기 경로로** 제공한다. 처음엔 `tracing` 을 얇게 감싼다(메인 제안).
2. **입구의 인자는 위험도 · 카테고리 · 메시지 셋이다**(사용자 2026-10-02 — 「일단은 함수화하고 기본적인 인자만 넣도록」). 카테고리 어휘는 큰 절 A 전까지 자유 문자열(검사 없음). 메시지 형식은 표준(Rust 포매팅 관례)을 따른다(사용자).
3. **호출부에서는 함수처럼 보이되 안쪽은 매크로로 둔다**(메인 판단) — 꺼진 위험도의 메시지를 문자열로 만들지 않기 위해서다. 호출 위치(파일:줄)는 사유가 아니다 — 함수도 `#[track_caller]` 로 부른 자리를 얻는다(메인 판단).
4. **비밀값 가리기는 실제로 찍는 곳에 둔다**(사용자 2026-10-02 — 「base는 그걸 모르고 실제 찍는 곳에 걸어야 되는 거 아님?」). base 의 입구 · writer 는 메시지를 파싱하지 않는다. base 의 `mask_secrets` 는 부르는 쪽이 고르는 범용 도구로 남는다 — 그 패턴은 업체별 키 형식 일반(`sk-` · `AKIA` · `ghp_` 등 · Bearer 토큰)이라 도메인 지식이 없다(`logging/mod.rs` 의 `mask_secrets`).
5. **`tracing` 직접 의존은 base 만 허용한다**(사용자 2026-09-26 방향 · 게이트 꼴은 메인 제안) — CI 게이트로 막는다: 해석된 의존 그래프에서 base 밖 crate 의 **일반 의존(`[dependencies]`)** 에 `tracing` = 0. 게이트는 전환 마지막에 한 번 건다.
6. **이 결정이 정하는 것은 「base 를 거친다」와 위 세 인자 틀까지다.** 카테고리 · 위험도의 체계는 큰 절 A(로깅 시스템 설계)가 정하고, 그때 입구 모양을 다시 본다.
7. **전환은 사이드 작업이다**(사용자 2026-10-02 — 「일단 뒤로 하되 기계적으로 할 때 중간에 끼어들기해도 된다 · 모듈 경계가 아니라 아무 때나 해도 되는 사이드 작업」). crate 의존을 바꾸지 않아 어느 단계의 선행 · 후행도 아니고, crate 끼리 파일이 안 겹쳐 crate 단위로 쪼개 넣는다(그동안 옛 · 새 방식 공존). 끼울 때 조건 둘:
   - **단계 사이에만** — 단계를 master 에 머지한 뒤 · 다음 단계 전. 모든 crate 를 건드려 진행 중인 단계와 같은 파일을 만진다.
   - **첫 조각 전에 입구 모양(특히 카테고리 체계)을 못 박는다.** 안 박고 시작하면 설계 확정 때 다시 고친다.

## 거부한 대안

- **각 crate 가 `tracing` 을 직접 쓴다(현행).** 기각 = 사용자 결정(「나중에 컨트롤이 안 되잖아」). 라이브러리 교체 · 규칙 강제가 여섯 crate · 약 530곳을 다 고치는 일이 된다(위 「맥락」 — 정량, 대략치).
- **base writer 단계에서 모든 줄에 가리기를 자동으로 건다(선택 → 기본 — 메모 결정 후보 3 의 옛 메인 제안).** 기각 = 사용자 결정 둘(2026-10-02) — 「base는 그걸 모르고 실제 찍는 곳에 걸어야 되는 거 아님?」(무엇이 비밀인지는 찍는 쪽이 안다) · 「매번 파싱해서 체크할 수는 없잖아 내부에서」(모든 줄에 정규식을 거는 비용 — 재지는 않았다). 그리고 ADR-0138 의 기각 사유가 그대로 선다 — 토큰은 이미 같은 폴더에 평문으로 있어 로그 사본을 가리는 것은 같은 신뢰 경계 안의 중복 방어다(논리).
- **보통 함수로 둔다(매크로 없이).** 기각 = 결정 3 의 사유 하나 — 함수 인자는 부르기 전에 만들어지므로 꺼진 위험도의 메시지도 문자열로 만든다(메인 판단). **기각 근거 자평: 약함**(서술 — 꺼진 위험도의 포매팅 비용을 재지 않았다).
- **전환을 platform crate 이전(작업 순서 1-3)보다 앞에 둔다 — 옮겨질 코드가 처음부터 새 방식을 쓰게.** 기각 = 사용자 결정(2026-10-02 사이드 작업) + 그 근거가 약했다 — 전환이 기계적이라 코드가 어느 crate 에 있든 드는 품이 같다(메인 판단). **기각 근거 자평: 약함**(서술).

- **사용자 결정 2026-09-26 · 2026-10-02** — 위 인용.

- **writer 실측** — 파일 writer 가 받은 바이트를 가공 없이 쓴다(`FileSinkWriter::write`).
- **가리기 배치의 선례** — T-1(`docs/tracking-archive.md` — 「sink 에 배선하지 않고 호출자가 명시 호출」) · ADR-0138 「거부한 대안」 · `docs/reference/logging-conventions.md` 「보안」(「`mask_secrets` 헬퍼는 자동 적용이 아니라 호출자가 명시 호출한다」).
- **스팬 실측(2026-10-02 · `d5ac725`)** — `rg "_span!|#\[instrument|tracing::instrument|\.instrument\(|span!\(" crates src-tauri/src` → 0줄. 스팬을 만드는 곳이 없다 — 메모가 「감쌀 표면이 커질 수 있다」고 남긴 열린 것은 지금 기준으로 닫힌다. `tracing::span` 이 걸리는 자리는 전부 테스트 쪽 로그 관측 구독자 구현이다(아래 영향).

## 영향 / 불변식

- **불변식(전환 완료 뒤): base 밖 crate 의 일반 의존에 `tracing` 이 없다** — 결정 5 의 게이트가 진다. 전환 중에는 옛 · 새 방식이 공존하고 게이트는 아직 없다.
- **열린 것 — 전환 때 정한다: 테스트 쪽 로그 관측.** 테스트가 로그를 잡으려고 `tracing` 구독자를 직접 구현한 곳이 있다 — 데몬 `src/log_capture.rs`(그 머리 주석이 남은 사본 둘 — `command_roster` · `control::mod` — 을 함께 센다) · agent `backend/codex/transport.rs` · `backend/claude/leftover.rs` · 셸 `daemon_client/usage_interest.rs` · `settings/tests.rs`(`impl tracing::subscriber::Subscriber for` · `with_default` — `d5ac725`). 이것들이 `tracing` 을 dev 의존으로 들지 · base 의 `testing` 기능 뒤 관측 도구로 모일지는 그때 본다. 결정 5 의 게이트가 일반 의존만 보는 이유가 이것이다.
- **열린 것 — 큰 절 A 까지:** `키 = 값` 필드를 입구에 들일지(메모 결정 후보 3 의 옛 메인 제안은 호출부 표면 = 레벨 매크로 + 필드였다 · 지금은 결정 2 의 세 인자뿐 — 사용자 「기본적인 인자만」). `docs/reference/logging-conventions.md` 의 예(`tracing::info!(agent = %profile.id, epoch, ?mode, "…")`)와 안티패턴(「식별자 · 수치를 메시지 문자열에 보간 — 필드로 빼라」)이 지금 필드를 쓴다 — 세 인자 틀로 옮길 때 그 규약을 함께 고친다.
- **ADR-0138 은 고치지 않는다** — 동기 writer · 폴더는 호출자가 넘긴다 · `LogKind` 닫힌 집합 · 마스킹 레이어 기각 전부 그대로다.
- **`docs/reference/logging-conventions.md` 의 `tracing::` 예와 규약을 같은 전환에서 고친다.**
- **데몬의 미사용 `tracing-subscriber` 선언(CLAUDE.md 「의존성」)은 이 전환 때 정리한다**(메모 §11).
- **코드 앵커 = `// ADR-0268`** — base 로그 입구 · 게이트.
