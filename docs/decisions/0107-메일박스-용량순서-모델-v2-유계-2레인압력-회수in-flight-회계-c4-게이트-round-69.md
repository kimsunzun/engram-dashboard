# ADR-0107: 메일박스 용량·순서 모델 v2 — 유계 2레인·압력 회수·in-flight 회계 (C4 게이트 round 6~9)

- 상태: 확정 (2026-07-26, 근거: C4 적대 리뷰 4라운드 실적출 + 사용자 결정 2026-07-26)
- 관련: Amends ADR-0103 (notice cap 예외 통로 및 파킹 단일 수신자 전용 조항) · ADR-0104(일괄 flush) · ADR-0105(TTL 24h)

## 맥락

C4(그룹 fan-out) 게이트의 적대 리뷰 라운드 6~9가 메일박스 용량·순서 모델의 결함을 연쇄 적출했다. **라운드 표기 = 적출한 판정 라운드**(수정은 각각 그 다음 라운드가 재검증 — 코드 주석의 round-N 라벨과 동일 규약):

1. **notice cap 예외(ADR-0103)가 무계 통로 + 잔해 기아(round 6 적출)** — 예외 통로라 통지가 무한 누적 가능했고, 방송 잔해(죽은 incarnation 결박분)가 정원을 물어 재스폰 에이전트가 24h 굶는 기아도 실재했다(round 5까지의 2단 정원+면제 설계의 귀결).
2. **cap 우회 성장(round 6 적출)** — flush의 drain↔주입 창에서 동시 발송이 빈 큐로 수용되고, 주입 실패 복원(`restore_ordered`)이 cap을 안 세 사이클마다 큐가 자랐다. "일시 초과 ≤ 한 배치" 논증은 옛 큐 자체가 초과일 수 있어 순환 논리였다.
3. **산 메일 오회수(round 6 적출)** — stale 판정 `bound != current`가 동명 산 에이전트의 결박 메일을 잔해로 오판해 압력 회수가 산 메일을 `skipped`로 은퇴시켰다.
4. **FIFO 합류 사각지대(round 7 적출)** — 합류 판정이 큐만 봐서, 주입 중(in-flight) 배치를 직발송이 앞질렀다(C2부터 있던 기존 결함 — in-flight 회계가 생기며 비로소 관측·수정 가능해짐. 스코프 편입 = 사용자 결정 2026-07-26).
5. **유예 마커 lost wakeup(round 8 적출)** — flush 중첩 유예 마커가 이름당 단일 슬롯(last-writer-wins)이라 죽은 id의 유예가 산 id의 wake를 덮어썼다. round 9 = PASS(종결).

## 결정

1. **용량 = 종류별 독립 2레인, 예외 없음.** message 레인 `MAILBOX_CAP=100`(결박 유무 무관 전량 계수) · notice 레인 `NOTICE_CAP=20`(완전 독립). ADR-0103의 "notice는 cap 예외 통로" 조항을 이 유계 레인이 대체한다(회신 계약의 "통지는 반려되지 않는다"는 보존 — 아래 3).
2. **압력 회수(정원 도달 시).** message 레인 = **stale 결박 잔해만** 오래된 순 은퇴(장부 `skipped`, TTL 경과분은 `expired`), 회수 불가면 `MAILBOX_FULL` 반려(부작용 0). stale 판정 = **동명 생존 incarnation 목록 비소속**(단일 current 비교 아님 — 산 메일 보호), 생존 목록 불명이면 아무것도 회수하지 않는다.
3. **notice 레인은 반려 갈래 없음** — 초과 시 가장 오래된 통지 은퇴 후 신규 수용(통지의 조용한 유실 금지 = ADR-0103 회신 계약 불변식 보존 방식만 교체).
4. **in-flight 회계로 구조적 유계.** flush가 락을 벗어나 주입 중인 배치를 수신자·레인별 계수하고 park 분모 = 큐 + in-flight → "보관+주입중 ≤ cap" 등식. 정산은 배달/복원 두 실출구에서 항목별, RAII 백스톱.
5. **FIFO 합류 = 큐 + in-flight.** 직발송·그룹 즉시배달 게이트가 in-flight도 "앞에 선 것"으로 센다(과차단 = 지연만, 미차단 = 순서 위반 — 비대칭 비용으로 안전측). 동일 수신자 flush 중첩은 유예(마커 = 이름당 **id 집합**, 전원 재타 — 죽은 id는 무해 no-op) + 정산 시 재타 도어벨.
6. **그룹 방송의 busy(또는 앞선 파킹이 있는 — FIFO 합류) 멤버는 파킹한다 — 단 발송 순간 개체 `(id,epoch)` 결박으로 "방송 소급 금지"를 보존.** ADR-0103의 "파킹은 단일 수신자 전용"(방송 파킹 금지) 조항을 이 결박 방식이 대체한다 — 불변식(스냅샷 이후 스폰분에게 배달 금지)은 유지, 강제 수단만 "파킹 안 함"에서 "결박 파킹"으로 교체(busy 멤버가 방송을 통째 놓치는 손실 제거).

## 거부한 대안

- **2단 정원 + 면제(round 5까지의 설계)** — 면제 축이 incarnation 교체마다 분모를 리셋시켜 큐 무계 성장 + 배달 불가 결박분이 정원을 물어 재스폰 기아. 복잡도 대비 결함만 낳아 사용자 결정으로 폐기(2026-07-26, "정원 단순화").
- **priority(중요도) 필드** — 기준 애매 + 기아·TTL 교차버그(AMQP 실무 경고) + LLM 프레임워크 전원 미채택. ADR-0103 거부 대안 재확인 — 성격이 다른 것만 레인 분리(notice)가 우리 방식.
- **visible_to(가시성 필터)를 cap 분모에 재사용** — 순서 축과 용량 축의 결합이 무계 성장의 원인(맥락 2). 순서(누가 앞인가)와 용량(몇 개인가)을 분리.
- **drain 시점 in-flight 등록** — 락 안에서 복원되는 몫까지 계수하면 관측 불가능한 창으로 분모가 부풀어 정상 발송이 억울하게 반려됨. 락을 실제로 벗어나는 배치만 등록(등식 성립).
- **유예 마커를 이름으로 재해석(정산 시 로스터 재조회)** — 이름이 해석 못 하는 힌트 큐 지목 id(rename·동명 다수)가 유실됨 + 정산 경로에 port 호출 추가. 요청된 id를 그대로 보존하는 집합이 더 작고 정확.
- **notice 반려 갈래 추가(+1 일시 초과 제거)** — `deliver_notice`는 park 결과를 버리므로 반려 = 통지의 조용한 유실(회신 계약 반쪽). +1 일시 초과(유계·자기수정)를 수용.

## 근거

- 리뷰 실적출: round 6 FIX 3건(무계 성장·산 메일 오회수·TTL 어휘) → round 7 FIX 1건(FIFO 사각지대) → round 8 FIX 1건(마커 lost wakeup) → round 9 **PASS**. 각 수정은 mutation 검증(수정 되돌리면 해당 회귀 테스트만 실패).
- 게이트: core 285 + daemon 597 pass · fmt clean · blind(cross-family) 종결 판정 PASS.
- 체감 변화(수용): ① flush 주입 창 동안 신규 발송이 빈 큐로 보여도 `MAILBOX_FULL` 가능(가시적 반려 > 조용한 유실 — spec §5 기조) ② 동명 산 쌍둥이 존재 시 가득 찬 보관함은 상대 메일을 잡아먹는 대신 반려 ③ in-flight 창의 발송은 `Delivered` 대신 `Parked/Pending`(직후 flush로 순서대로 배달).

## 영향 / 불변식

- **구조적 유계 등식:** 수신자당 message 레인(보관+주입중) ≤ 100 · notice 레인 ≤ 20(+1 일시 초과 허용, 자기수정). 코드 앵커 `// ADR-0107` 7개 = `mailbox.rs`(정원 상수 2곳 `MAILBOX_CAP`/`NOTICE_CAP` · 압력 회수 `park` · in-flight 회계 `take_in_flight` · FIFO 합류 `has_pending_ahead`)·`service.rs`(유예 마커 `deferred_flush` 필드 · 회수 장부 종점 `park_into`).
- **회수가 산 메일을 잡아먹지 않는다** — stale = 생존 목록 비소속만. 생존 근거 = reachable 로스터(산-비structured 에이전트 결박분은 회수될 수 있음 — 수용 잔여).
- **admitted(`pending`) 메시지의 조용한 유실 금지** — 모든 제거는 장부 종점(`skipped`/`expired`)을 남긴다. **단 장부 전이는 best-effort** — 레코드가 링(4096)에서 이미 밀려났으면 종점 대신 debug 로그로 강등(제거 사실 자체는 로그에 남는다). 재파킹(`restore_ordered`)은 cap 우회(보관 통제 아님·유입 통제)지만 in-flight 회계가 총량을 묶는다.
- **수신자가 보는 순서 = 전역 오래된 순** — 합류 판정이 큐+in-flight를 보고, 유예/재타가 flush 중첩을 직렬화한다. 위반 시 직발송 끼어들기·배치 간 나이 역전이 재발한다.
