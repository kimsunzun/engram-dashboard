# ADR-0144: Left-click on an empty slot only focuses; the menu is right-click only

- 상태: 확정 (2026-08-18, grounds: user decision)
- 관련: Amends ADR-0141 (empty slot left-click menu opening) · Amends ADR-0143 (empty slot left-click menu opening) · ADR-0065(empty slot menu composition) · `src/components/layout/ViewLayoutRenderer.tsx`

## 맥락

ADR-0141 attached a menu to left-click on an empty slot, and ADR-0143 widened its target to the whole slot. As a result an empty slot shows the menu **on every left-click** — even on a click meant only to move focus.

User report (2026-08-18): "좌클릭 누를 때마다 매번 뜨니까 불편하다. `+` 이미지만 있으면 될 것 같다." (gloss: it pops up every time I left-click, so it is inconvenient; the + image alone seems enough.) The target widened for the affordance has reversed into something that gets in the way of everyday operation.

## 결정

1. **Left-click on an empty slot only moves focus.** The menu is returned to right-click only.
2. **The `+` icon stays as it is** — a pure picture, not a click target, size also kept (ADR-0143 decisions 2 and 3 remain valid).
3. **No guidance text is added.** ADR-0141 decision 1 is kept: the visual information of an empty slot is the `+` alone.

## 거부한 대안

- **Keep the current behavior (left-click also gives the menu)** — it is the very subject of the report. There are reasons to click an empty slot besides opening the menu (moving focus), and the current structure cannot tell the two apart.
- **Remove the left-click menu but put guidance text in the empty slot** (for example "우클릭으로 생성" (gloss: create with right-click)) — the user explicitly rejected it (2026-08-18, "`+` 이미지만 있으면 될 것 같다" — gloss: the + image alone seems enough). It is also reviving the centered text that ADR-0141 removed, with only its form changed.
- **Move the left-click to double-click or a modifier-key combination** — what the user asked for is "the menu not popping up," not a different gesture. A new gesture has lower discoverability than right-click and only adds learning cost.

## 근거

- **User decision (2026-08-18)** — the user specified both removing the left-click menu and forbidding guidance text.
- **This is a choice made knowing the cost.** ADR-0143 wrote this very option ("left-click only focuses, the menu is right-click only") as a rejected alternative and left its reason as "the path to fill an empty slot is not visible on screen." That cost is still valid, and the user decided to bear it. **A later session does not revert this decision on the grounds of the affordance** — reverting needs a new user decision.

## 영향 / 불변식

- **The menu opening path shrinks to one** — right-click. The `setContextMenu` state itself stays and only one opener is removed. ADR-0141's invariant of not adding a third path remains valid.
- **Loss of the affordance is the intended cost.** If it ever needs to be revived, a means other than guidance text must be found — adding text was rejected by the user, so it is not to be revived on one's own.
- **ADR-0143 decision 4 (the gap between the anchor and the menu) is kept as it is.** The path that motivated that clause, "the first click of a double-click on an empty slot opens the menu," disappears with the left-click opener, but a double-click on a menu opened by right-click remains. An edit that shrinks or removes the gap is not to be taken as a consequence of this decision.
- **The latent path of the click without coordinates is closed together** (what ADR-0143 decision 5 left as "it only moved and did not disappear"). The path where code calling a click on the slot element opened the menu at the top-left of the viewport becomes unreachable once left-click no longer opens the menu. It is a side benefit, not the purpose of this decision.
- **The left-click behavior of a slot with content does not change** — it was only focus move originally, and with this decision the empty slot joins it.
