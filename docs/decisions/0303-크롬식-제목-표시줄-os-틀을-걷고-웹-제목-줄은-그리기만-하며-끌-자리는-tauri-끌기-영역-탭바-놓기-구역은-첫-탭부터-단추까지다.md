## 맥락

OS 제목 표시줄이 탭바 위에 한 줄을 따로 먹었다 — Chrome · Windows 11 탐색기처럼 탭바가 제목 표시줄 자리에 서게 하기로 했다(사용자 결정 2026-10-17 · PRD §1). 테두리 없는 창으로 가면 OS 제목 표시줄이 주던 것을 우리가 다시 세워야 한다: 창 끌기 · 두 번 누름 · 창 단추 · 크기 조절 · 비활성 모습 · 최소 창 폭 · 창 메뉴(Alt+Space · 오른쪽 클릭) · 스냅 레이아웃 메뉴(ADR-0304).

탭 끌기는 OS(HTML5) 끌기다(ADR-0296 · ADR-0297) — 끌기 영역 위에 HTML5 `dragover` · `drop` 이 닿는지가 슬롯 도킹 4.9 뒤 가장 큰 미검이었고(PRD W2), 어느 끌기 영역 기법을 쓰느냐가 그것을 가른다(Q5 — 사용자가 메인에게 맡겼다 · 2026-10-23).

## 결정

1. **OS 틀은 `WebviewEnv::finish` 한 곳에서 걷는다**(TRD §8-1 · ADR-0283) — platform `window::caption_style()`(메인 결정 M17 — 「단추를 우리가 그리나 · 왼쪽 비울 폭」)이 단추를 그린다고 답할 때만 `decorations(false)` · `shadow(true)` 를 붙인다. main · 팝아웃 · 예열 창 · 복원 팝아웃이 모두 지난다 — **팝아웃도 같은 제목 표시줄이다**(사용자 결정 2026-10-23 — Q2). `tauri.conf.json` 의 main 선언에 `decorations` · `shadow` 를 적지 않는다. 크기 조절 = Tauri 코어의 테두리 없는 창 크기 조절.
2. **제목 줄(웹)은 그리기만 한다** — `TitleRow` = 탭바(탭 · `+`) · 끌 빈 자리 `GrabGap`(최소 42 — 번호 표식과 **따로** · 메인 결정 M10) · 번호 표식(ADR-0300 — 끌 자리 · `pointer-events: none` · `aria-hidden`) · 창 단추 셋(레지스트리 명령을 부른다 — ADR-0302). 탭바만 줄어들어 **탭이 먼저 준다**(R13 — 넘침은 슬롯 도킹 R24 그대로 · 탭 폭 상수는 모양이 안 바뀌어 그대로 · 메인 결정 M18). 대기 모드(예열 창) · 로딩 · 부팅 실패 화면도 제목 줄을 그린다 — 단추를 빼는 것은 대기 모드뿐이다(TRD §7-1). 크기 값(메인 결정 M10 · 정본 = `titleRow/metrics.ts`): 탭바 28 · 보통 상태 위 여백 `TOP_GAP` 6(줄 34) · 최대화 위 여백 0(줄 28 — Chromium `TabStrip::CanExtendDragHandle`) · 창 단추 폭 46 · 번호 표식 최소 28. `TOP_GAP` 은 접힌 끌기(W13) 대응을 겸한다 — 값은 측정(S13)으로 정하고 모양은 사용자가 확인한다(메인 결정 M32 · 사용자 확인 필요(QA)).
3. **창 단추**(R10 · R21) — 셋 다 진짜 단추(Tab 순서 · Enter · Space · 포커스 테두리). 셋째 단추: main = 「모든 창 숨기기」 lucide `EyeOff` · 올림 = 다른 단추와 같은 옅은 바탕(빨강 아님)(사용자 결정 2026-10-24 — T3) · 팝아웃 = 「창 닫기」 `X` · 올림 = 빨강. 단추가 하는 일은 ADR-0302.
4. **끌 자리 = Tauri `data-tauri-drag-region`**(Q5 = ① — 메인 결정 M27 · 사용자 위임 2026-10-23 · 스파이크 S1) — `TitleRow` · 탭 줄 행 · `GrabGap` 에 값 없는 속성(자기 자신만 — 자식 탭 · `+` · 단추는 끌기를 시작하지 않는다). 두 번 누름 = 최대화 ↔ 원래 크기(`drag.js` 의 `internal_toggle_maximize`). 권한 `core:window:allow-start-dragging` 을 main · 팝아웃에 더한다(빠뜨리면 소리 없이 안 된다 — W4). **탭 둘레(탭 줄의 빈 곳 · 보통 상태 위 여백)도 끌 자리다**(사용자 결정 2026-10-23 — R25). 끌기 · 두 번 누름은 OS 제스처 층이라 버스를 지나지 않는다(D7).
5. **창 메뉴(Alt+Space · 끌 자리 오른쪽 클릭) = 네이티브를 그대로 받아들이고 아무것도 짓지 않는다**(Q10 = ① — 메인 결정 M28 · 사용자 위임 2026-10-23 · 2026-10-24 지시) — 결과는 QA 가 적는다(AC23 ①: 안 뜨면 그 회귀를 PRD §2 비목표에 적고 사용자에게 보고). 이 기법으로 잃는 것(받아들임 · 사용자에게 보고): 끌 자리 오른쪽 클릭 창 메뉴(`drag.js` 는 왼쪽 단추만 본다 — W6) · 터치 · 펜 끌기(미검).
6. **탭 놓기의 탭바 구역 = 가로 첫 탭 왼쪽 ~ `+` 오른 끝 × 세로 제목 줄(위 여백 포함)**(사용자 결정 2026-10-26 · T-66 — 「탭이 있는 곳(첫 탭 ~ `+`)만 탭바 구역」 · 메인 결정 M26 의 가로를 뒤집었고 세로는 남는다) — `+` 오른쪽 빈 곳 · 끌 빈 자리 · 번호 표식 · 창 단추 위 놓기 = 새 창(단추는 눌리지 않는다 — HTML5 놓기는 `click` 을 내지 않는다 · 가능성 높음 · AC12 가 잰다). 탭이 없으면 구역 = `+` 만. 그 사각형을 `dock/bands.ts` `stripZone` 이 위아래 `STRIP_ZONE_PX` 로 넓히는 것은 그대로다 — 셸 `strip_zone` · 골든은 바뀌지 않는다.
   - **D-a**(사용자 결정 2026-10-26) — 자기 탭바에서 끄는 탭도 커서가 `+` 오른 끝을 넘으면 구역 밖이다: 순서 이동이 멈추고 자리로 돌아가며 남은 탭이 보이고(슬롯 도킹 R15) 거기서 떼면 새 창으로 떼어진다.
   - **D-b**(사용자 수락 2026-10-26) — 구역 밖이 된 `+` 오른쪽 밑 캔버스 위 끝 0..15 px 는 바깥 위 띠다(놓으면 레이아웃 전체 위로 나눔 · 놓기 전에 미리보기) — 그 위가 더는 탭바가 아니니 아래 띠는 내용의 위 끝으로 군다.
   - 탭 끌기의 나머지 규칙(순서 이동 · 다른 창 도킹 · 떼어 새 창 · 놓기 직전 대상이 닫히면 통째로 취소)은 바뀌지 않는다(R14 · ADR-0296 · ADR-0297).
7. **창 사실은 기존 `window:frame` 길에 칸을 더해 받는다**(메인 결정 M21) — `focused`(`Focused(b)` 로 미는 그 창 자신의 칸 = 사건 값 · 당기기 · 그 밖의 밀기 = platform `is_foreground`) · `caption { buttons, leading_inset, snap_overlay }`. `Focused` 사건에서도 그 창의 창 사실을 민다. 새 사건 · 새 당기기 invoke 는 없다.
8. **비활성 창은 제목 줄이 흐려진다**(R11 — 기본값 메인 제안) — `TitleRow` 의 `data-window-active="false"` 면 탭 글자 · 번호 · 단추 글리프에 테마 토큰 `--chrome-inactive-fg`. **흐림 대비(다크 3.6:1 · 라이트 3.1:1 · e-ink 거의 안 보임)를 그대로 받아들인다 — 토큰을 고치지 않는다**(사용자 결정 2026-10-26).
9. **최소 창 폭**(R20 · 메인 결정 M11) — 웹이 창마다 셈하고 보고한다(`report_window_min_width { width, height, seq, epoch }` — 정책 상수의 정본 = 화면 · ADR-0227 선례). 셸 `chrome::ChromeBook`(순수 판정)이 정하고 어댑터가 OS 최소 크기로 입힌다.
   - **OS 최소 크기는 보통(원래 크기) 상태의 창에만 입히고 최대화 · 최소화 동안은 입히지도 걷지도 않는다 — 보통이 되면(`Resized`) 적어 둔 값을 입힌다**(메인 결정 · U8b 2026-10-26 — TRD 0.3판의 「최대화면 걷는다」를 대신함).
   - 입히는 값 = 보고한 안쪽 크기 + 보이지 않는 테두리(바깥 − 안쪽 · 배율로 논리로 푼 값 — U8b 리뷰 수정).
   - 넓혀 당기기(D14)는 **열 때만**(새 창 · 맡긴 예열 창 · 부팅 복원 · 사본 수락 — 열기 표시 `mark_opening` · 사본 수락의 main 은 자리 앞 걷기 `lift_min`) 하고, 보이는 가장자리 기준으로 작업 영역 안에 당긴다(`fit_min_width` · 작업 영역이 창보다 좁으면 보이는 왼쪽 끝 = 작업 영역 왼쪽 끝). 사람이 창을 옮기는 동안은 OS 최소 크기만 걸린다(PRD R20 · AC34 — 기본값 메인 제안 · 리뷰 codex ⑩).
   - 보고 순번 = `(epoch = 페이지를 읽은 벽시계 ms, seq)` 사전순(메인 결정 · U8a 리뷰 2026-10-25) · 창 번호를 받은 뒤에만 보고한다(메인 결정 · U8b 리뷰 2026-10-26) · 첫 화면 알림보다 먼저 보내되 기다림 상한 300 ms 로 첫 화면을 막지 않는다.
   - 옛 상태 파일의 안쪽 크기는 그대로 쓴다 — 첫 부팅 창이 틀 높이만큼 짧아진다(한 번뿐 · PRD D14 · W5 — 받아들임).
10. **macOS 는 이번에 짓지 않되 막지 않는다**(R16 · D10 — 기본값 메인 제안) — 크롬 모양의 OS 가름은 platform `caption_style()` 한 곳이고 웹은 창 사실의 `caption` 대로 그린다. 지금 코드는 모든 OS 에서 `{ drawn_buttons: true, leading_inset: 0 }` 이다.
11. **슬롯 도킹 실측에서 넘어온 다섯 중 ②(탭 둘레 끌기 = 창 이동)만 한다**(사용자 결정 2026-10-23 — 「어차피 탭 남는부분 끌면되니 … 구지 따로 구현할 필요 없음」) — ① 탭 하나뿐인 팝아웃의 탭을 끌 때 창이 따라오기 · ③ 메인의 하나뿐인 탭 끌기 = 창 이동 · ④ 창 밖 금지 커서 · ⑤ 순서 바꾸기의 끌기 그림은 하지 않는다(R26–R28).

## 거부한 대안

- **끌기 영역 = CSS `app-region: drag`**(Q5 ②) — 그 위에 놓은 탭이 받는 쪽 없이 끝난다: `app-region` 영역의 적중 판정이 최상위 창(HWND)으로 가고, 거기엔 tao 가 파일만 받는 `RegisterDragDrop` 을 걸어 두었다(우리 `webview_env` 의 `no_drop_handler` 는 웹뷰 것만 끈다 · 디버그 세션 실측 2026-10-24 — 확실). 이 갈래가 주던 이점(창 메뉴 · 터치 · 펜을 OS 가 줌)은 이것으로 잃는다. 기각 강도 = 실측(메인 결정 M27 · 사용자 위임).
- **우리가 그린 창 메뉴**(Q10 ② — Alt+Space · 끌 자리 오른쪽 클릭에 웹 메뉴 · 항목이 버스 명령을 부른다) — 키 가로채기 · 메뉴 그리기 · 접근성 몫이 는다. 기각 강도 = 서술(비용)(메인 결정 M28 · 사용자 위임).
- **탭바 구역 가로 = 제목 줄 전체**(메인 결정 M26 — U8a 가 지은 구현 · 빈 곳 · `+` · 끌 빈 자리 · 번호 · 단추 · 위 여백 위 놓기 = 그 탭바 끝 · 메인 추천 사유 = OS 틀이 걷히면 창 맨 위 띠 어디든 그 창에 들어가는 편이 예측 가능 — U8a 핸드오프 2026-10-25) — 사용자가 Chrome 의 탭 위 놓기를 보고 「탭이 있는 곳(첫 탭 ~ `+`)만 탭바 구역」으로 정했다(2026-10-26). ★자기 탭 떼기 경계까지 Chrome 과 같다는 뜻은 아니다★ — 조사 `slot-docking-chrome-desktop-drag-2026-10-18.md` A5 는 Chrome 의 떼기 경계를 탭바 끌기 영역 가로 밖으로 읽는다(TRD §7-9). 기각 = 사용자 결정 2026-10-26.
- **슬롯 도킹의 구역 가로(첫 탭 ~ 잰 `available` 의 끝 = 줄 끝 − `+` 폭 — `+` 오른쪽 빈 곳까지)** — 같은 사용자 결정으로 첫 탭 ~ `+` 오른 끝으로 좁혔다(PRD R14). 기각 = 사용자 결정 2026-10-26.
- **자기 탭은 `dragAreaWidth`(잰 `available`)의 끝 — `+` 오른쪽 빈 곳까지 — 붙여 두기**(D-a 의 거부한 대안) — 거기까지 가야 떼어지면 다루기 어렵다(사용자). 기각 = 사용자 결정 2026-10-26.
- **창 사실을 새 사건 채널 `window:chrome` · 새 당기기 invoke(`window_chrome_state` · `window_chrome`)로 나르기**(TRD 0.1판) — 리뷰 codex ⑧ 이 기존 `WindowFrame` 길(구독 먼저 · 한 번 당기기 · 당기기 뒤 사건이 오면 당기기 답을 버림)에 칸을 더하라고 지적해 걷었다. TRD 에 그 밖의 기각 사유 서술은 없다. 기각 강도 = 약함(리뷰 지적만).
- **번호 표식으로 끌 빈 자리 최소를 갈음하기**(PRD R13 이 TRD 에 맡김) — Chromium `FrameGrabHandle::CalculatePreferredSize` 는 42 를 늘 둔다(「탭줄이 차도 잡을 자리를 남긴다」 — 소스 사본 `horizontal_tab_strip_region_view.cc`)(메인 결정 M10). 기각 강도 = 코드(Chromium 소스).
- **좁은 창에서 단추를 줄이기 · 끌 빈 자리만 보장하고 활성 탭까지 숨기기**(PRD D15 의 다른 갈래) — 앞은 Windows · Chrome 과 어긋나고 뒤는 무엇을 보는지 안 보인다. 기각 강도 = 서술(기본값 메인 제안). ★2026-10-26 — 뒤 갈래는 일부 되살아났다: 최소 폭에서 탭 자리에 어느 탭이 서는지는 탭바 넘침 규칙(사용자 결정 Q22 「Chrome 과 같은 한계를 받아들인다」)이 정해 첫 탭이 아닌 활성 탭은 숨을 수 있다(실측 · 메인 결정 M35 · PRD AC22) — 끌 빈 자리 · 번호 · 단추는 그대로 보장한다★
- **첫 부팅에 제목 줄 높이를 더해 바깥 크기를 지키기**(PRD D14 의 다른 갈래) — 그 높이가 배율 · OS 판마다 달라 고르지 않았다. 기각 강도 = 서술.
- **최대화 동안 OS 최소 크기를 걷기**(TRD 0.3판 §7-7 「최대화면 걷는다」) — tao 0.35.3 의 최소 크기 세터(`set_min_inner_size`)가 지금 크기를 다시 입혀(`set_inner_size`) 최대화 깃발을 내리고 `SW_RESTORE` 로 원래 크기로 되돌리며, 숨은 창이면 보이며 활성화한다(소스 독해 — `platform_impl/windows/window.rs` · `window_state.rs` `apply_diff`). 최대화 사각형 = 작업 영역은 tao 의 테두리 없는 창 `WM_NCCALCSIZE` 가 지킨다(rcWork 로 자른다 — 소스 독해). 기각 강도 = 코드(소스 독해)(메인 결정 · U8b 2026-10-26).
- **보고한 안쪽 크기를 그대로 OS 최소 크기로 넘기기**(U8b 첫 구현) — tao 의 `WM_GETMINMAXINFO` 는 틀 없는 창의 최소 추적 크기에 테두리를 더하지 않고 `WM_NCCALCSIZE` 는 안쪽을 줄여, 안쪽이 보고한 값보다 100 % 에서 폭 약 16 · 높이 약 9 px 좁게 끌려 줄었다(소스 독해 · U8b 리뷰). 기각 강도 = 코드.
- **최소 폭 보고의 페이지 표식 `epoch` 을 난수로**(U8a 리뷰 2026-10-25) — 다시 읽기 전 페이지의 늦은 보고가 새 페이지 값을 덮는다. 기각 강도 = 서술(코드 추론).
- **번호를 받기 전(예열 대기 · 로딩 · 부팅 실패)에도 최소 폭을 보고하기**(U8b 리뷰 · 2026-10-26) — 예열 창은 대기 중 보고와 들인 뒤 보고가 같은 페이지라 순번으로 가를 수 없어, 날아가던 대기 중 보고(폭 120)가 들일 때 적은 열기 표시를 먼저 거두면 들인 창이 넓혀 당겨지지 않는다. 다른 갈래 = 셸이 표시를 적을 때의 `epoch` 보다 새 페이지만 거두기(같은 페이지라 막지 못한다) · 보고에 「대기」 깃발 더하기(wire 를 늘린다). 기각 강도 = 코드.
- **흐림 대비를 올리게 토큰을 고치기** — 사용자가 지금 대비를 그대로 받아들였다(2026-10-26). 고치지 않는 사유는 기록되지 않았다. 기각 = 사용자 결정(사유 기록 없음).
- **팝아웃만 OS 제목 표시줄 + 그 아래 탭바(지금 모양)**(Q2 의 다른 갈래) — 사용자가 「같다」로 정했다(슬롯 도킹 R24 「모든 창의 탭바가 같다」와 맞고, 새 창 자리 셈 `inset_dip` 이 기대는 「팝아웃과 main 의 창 틀이 같다」가 선다 — W5). 기각 = 사용자 결정 2026-10-23.
- **슬롯 도킹 실측 ① · ③ · ④ · ⑤** — ① 탭 하나뿐인 팝아웃 끌기에 창이 따라오기: 창 UI 가 웹이고 창 · 탭 모델이 다른 프로세스인 피어(Vivaldi · Chrome WebUI 탭바)도 같게 군다 — 커서를 따라오는 진짜 창은 한 프로세스 네이티브 구현에만 있다(조사 끌기 피어 A4–A6) · ③ 메인의 하나뿐인 탭 끌기 = 창 이동: 슬롯 도킹 Q35 그대로 · ④ 금지 커서 · ⑤ 끌기 그림: 둘 다 HTML5 끌기의 주인이 WebView2 라서 생기고 바꾸는 길 셋(A `DragStarting` · B 크롬식 직접 창 이동 · C 셸 직접 `DoDragDrop`)이 모두 크다(조사 커서 결론). 창을 바로 옮기려면 탭 남는 곳을 끈다(R25). 기각 = 사용자 결정 2026-10-23.

## 영향 / 불변식

- **제목 줄은 OS 틀이 걷힌 창에서 창을 옮기고 닫는 유일한 마우스 자리다** — 그 위를 덮는 것(알림 띠 · 복원 모달)의 규칙 = ADR-0306.
- **웹은 렌더만 한다** — 단추는 레지스트리 명령을 부르고 Tauri 창 API 를 부르지 않는다(ADR-0302 불변식 3). 끌 자리 속성은 한 곳(`titleRow/dragRegion.ts`)에 둔다.
- 셸 쪽 새 코드(`chrome/` · `commands/window_ctl.rs`)에 OS `cfg` 를 두지 않는다 — OS 가름은 platform(`caption_style` · `is_foreground`)뿐이다(TRD §8-3 — 4f · 4g · 4h 바뀌지 않음).
- 최소 크기 장부 `ChromeBook` 은 잎 락이다 — 쥔 채 OS 호출 · emit · 다른 락이 없다. 크기 상태 읽기 · 장부 적기 · OS 세터는 메인 스레드 일 하나로 돈다(`lift_min` — U8b 리뷰 2).
- ★**열린 것 · 미검(결정 아님)**★: S8 — 작업 영역이 최소 크기보다 좁은 화면의 최대화가 작업 영역을 넘는지(넘치면 ① 받아들임 ② 입히는 최소 크기를 그 모니터 작업 영역으로 줄임 ③ platform `WM_GETMINMAXINFO` 서브클래스 — 사용자에게 올린다) · S13 — 접힌 끌기와 `TOP_GAP`(원인 Win32/Blink 는 모름 · 원인을 가르기 전에 시한 · 문턱을 고치지 않는다) · S14 — 위 가장자리 크기 조절 자식 창 위 놓기 잃음(메인 결정 M33: 측정 뒤 ① 그 자리를 구역에서 빼고 받아들임 ② platform 에 최상위 창 수준 놓기 받는 쪽) · S12 — `Focused` 사건이 OS 활성 바뀜마다 오는지(빠지면 흐림이 늦다) · AC13(tauri#10767 — 창 끌기 직후 탭 누름) · Alt+Space · 오른쪽 클릭 · Win+Z 결과 · S9 · S10 · S11 · 최대화로 되살린 창의 6 px 뜀.
- 앵커 — `webview_env.rs`(틀을 걷는 자리) · `chrome/book.rs` · `chrome/mod.rs`(최소 크기 입히기 · 열기 표시) · platform `window::caption_style` · `is_foreground` · `titleRow/dragRegion.ts` · `tabStrip/measure.ts` 의 구역 셈 · `state::placement::fit_min_width` 에 `// ADR-0303` 을 단다.
