# ADR-0314: Presets and the library are assets owned by the daemon, and the client requests and reads them

- 상태: 제안 (2026-10-31, basis: user decisions memos 53 · 74 · 76 · 99 (2026-10-14) · R7 / G36 · G22-RESOLVED · G32 · G43 (2026-10-31 「engram이 할때는 갱신하고, 바깥은 실행할때 막히거나 새로고침으로 … 라이브러리도 동등한 룰」) + main M25 · M30 · M58 (reported) · research `docs/research/broken-reference-check-timing-practice-2026-10-31.md` · `docs/research/derived-vs-stored-broken-marker-practice-2026-10-31.md`)
- 관련: Supersedes ADR-0061 · ADR-0311 (where the crate lives) · ADR-0312 (one root) · ADR-0313 · ADR-0029 (the daemon is the single owner of user data) · ADR-0264 (old data is discarded) · ADR-0291 (already partially discarded ADR-0061) · ADR-0324 · memo 58 (machine side = daemon · viewing side = client) · TRD `docs/process/S25-preset-library/trd.md` §1-1 · §1-12 · §7 1 · Amends ADR-0070 (the Preset.name preset-name clause) · Amends ADR-0291 (the presets.json store clause)

## 맥락
The old 「프리셋」 was a working-folder bookmark (ADR-0061 — the daemon's `presets.json` · `Preset{id, cwd}` · broadcast to all connections after CRUD / ADR-0070 — the `Preset.name` display name). The S25 preset is an asset that bundles instructions, skills, settings and other presets, so the names collide (memo 43).

## 결정
1. A preset is a YAML file inside the library folder — an asset in the same place as skills and instructions (memos 74 · 76). There is one library folder (ADR-0312).
2. The asset-library inside the daemon process alone reads and writes (location = ADR-0311). The client does not read the disk.
3. Request-based: the client makes a request on its own actions (opening a slot, focus, refresh, changing the folder), and the daemon scans and answers only that client · it checks again before an agent runs. There is no watching (notify), no subscription, no broadcast, and no periodic polling while visible (memo 99).
4. The daemon-side features (commands, CLI) are always on (G22-RESOLVED · ADR-0313).
5. The old `presets.json`, the old preset wire and the preset palette slot are withdrawn — old data is discarded without asking (G32 · M26 · ADR-0264). The profile of the new edition uses a new file name, so the old `agents.json` is neither read nor deleted (M25).
6. **The tree ⛔ follows the same rule as the library list** (G43): changes that go through Engram (file operations, edits, relinks) land immediately in the in-memory `Catalog`, and the screen fetches again at the same triggers as the library list (opening an area, focus) plus when the agent list is refreshed (M58). Outside changes are seen only on refresh (F5 · `library.refresh`) or when blocked at run time. No new broadcast is created — 「감시 · 방송 없음」 as is.
7. **「찾을 수 없음」 (nothing is pointed at) is not stored and is derived from `Catalog` at view time. Parsing and schema errors of a file itself are computed when that file is read and stored together with the entry** (G43).

## 거부한 대안
- **The shell scans the library** — a client disk read is forbidden (PRD invariant constraint), and it does not hold with a remote daemon (later) (TRD §1-1).
- **notify watching + broadcast** — user 「화면 보고 있는 동안 바로 보여줄 필요 없음」 (memo 99 · research `docs/research/library-folder-change-sync-survey-2026-10-14.md`). The request-based form also holds for remote and mobile clients — every trigger is a client action (memo 99). Watching can be added later (TRD §1-12).
- **Presets as an internal list** (the shape of the old `presets.json`) — when handing out to someone else the folder is handed over, so presets must go with it (memos 53 · 74).
- **Only the tree ⛔ reflects even outside changes immediately** (the old 「곧바로 사라진다」 in the PRD acceptance text) — user 「바깥은 실행할때 막히거나 새로고침으로 … 라이브러리도 동등한 룰」 (G43). The text was corrected to match.
- **Storing 「찾을 수 없음」 per entry** (computed when it changes) — this form is not seen where finding it at view time in an in-memory index is enough · storing per entry is seen where the decision costs disk I/O (Nautilus) (research derived-vs-stored — it answers the user's question 「폴더를 이리저리 옮기는데 매번 저 검사를 한다고?」 · G43).

## 근거
- User decisions memos 53 · 74 · 99 (2026-10-14) · the split rule of memo 58 · TRD §1-1 · G43.
- Research broken-reference-check-timing (light · thin evidence): 「새로 고침이나 쓸 때만」 is a common shape in file-based tools (Blender 「Report Missing Files」 = certain · Premiere · Ableton · Lightroom = likely) · a watcher for outside changes was not found in the sample.
- Research derived-vs-stored (light): the split shape is common — the inter-file relation index is stored and fixed incrementally, and the mark next to an entry is computed at view time (Foam = certain — original text of `graph.ts` · `document-decorator.ts` checked). The S25 design (a relation table at the first scan · incremental on Engram changes · look up and mark only what is visible) has the same shape as Foam.

## 영향 / 불변식
- The remaining clauses of ADR-0061 (the daemon's `FilePresetStore` · `PresetRegistry` · the preset wire · the broadcast · `Preset{id, cwd}`) and the `Preset.name` part of ADR-0070 are discarded. This ADR does not address the `AgentProfile.display_name` part of ADR-0070 (§7 1 points only at the preset name part).
- **Needs confirmation**: the `presets.json` clauses of ADR-0291 (R6 cap · R9 corrupt copy · R12 temporary name · R17 read-only mode) become dead letter — decide at `/adr link`.
- No path is built to push library list changes to the client. It is not built for the tree ⛔ either (G43 · TRD §1-11a finding 18 closed).
- For the derived 「찾을 수 없음」 to be correct, `Catalog` must not be empty — every method that reads `Catalog` after a restart passes through the first scan (ADR-0324 Decision 6).
- The new profile file name avoids the `**/data/daemon/state/agents.json*` of `.gitignore`, and the profile holds plain-text `env` — the implementation step that brings in that file adds the new name + the `*` tail line to `.gitignore` (M30 · ADR-0136 Decision 3 · ADR-0264 Decision 7).
