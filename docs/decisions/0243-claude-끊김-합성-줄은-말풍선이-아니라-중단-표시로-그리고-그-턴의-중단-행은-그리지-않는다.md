# ADR-0243: The claude interrupt synthetic line is drawn as an interrupt marker, not a speech bubble, and that turn's interrupt row is not drawn

- 상태: 확정 (2026-09-28, basis: user decision ⑫ (TRD `docs/process/S21-chat-ux/trd.md` §11) + main decisions a–d (delegated by the user) + B2 spike measurement (`docs/research/claude-interrupt-spike-2026-09-28.md` §1 · §10-1) · before implementation · no code changed)
- 관련: TRD `docs/process/S21-chat-ux/trd.md`(§3-4 · §7 B3 · FE-2c · touchpoint table · §8-2 F2 ② · §10 0243 · §11 ⑪ ⑫) · research `docs/research/claude-interrupt-spike-2026-09-28.md`(§1 · §10-1) · ADR-0237(decision 6 U8 — the emphasized 「중단됨」 row) · ADR-0238(decision 4 — an interrupted `result` → `TurnEnd{Interrupted}` · this ADR does not change that classification) · ADR-0241(decision 12 — claude interrupted tool row) · ADR-0004(backend knowledge isolation) · ADR-0127(turn observation · 30-minute fail-open) · step-log S21 · Amends ADR-0237 (decision 6: for claude the marker row carries the emphasis and that turn's interrupt row is omitted) · Amends ADR-0238 (decision 4's frontend-unchanged statement, and the end of decision 7's symptom and impact, the interrupt-row description: for claude it is the interrupt marker row, and the interrupt row remains only as the fallback) · Amends ADR-0241 (decision 12: under the claude interrupted tool row, the context is given by the interrupt marker row)

## 맥락
The B2 spike found one line the TRD did not expect. On every interrupted claude turn (observed 14/14) the CLI emits a synthetic user line `{"type":"user","message":{"role":"user","content":[{"type":"text","text":"[Request interrupted by user]"}]},…}` **before** that turn's `result` — if a tool was running, the text is `[Request interrupted by user for tool use]`. It is also left in the transcript (research §1 · §10-1).

Today the claude translator emits this line as `Structured{kind:"user"}`, and the frontend draws a **user speech bubble** — both live and in reopened history. So TRD §3-4's 「codex 끊김과 같은 모양 · 프론트 무변경」 and the screen of U8 (ADR-0237 decision 6) differ by exactly this one speech bubble.

This line has two known roles. ① It tells the model on the next turn that 「앞 요청이 끊겼다」 — the claude CLI sends it to the model by itself, so it is independent of our display choice (likely — inference: it remains in the transcript as a user turn · the spike did not measure it). ② Claude Code's own UI recognizes this line and shows 「Interrupted · What should Claude do instead?」 instead of a speech bubble. Whether the same line is used in other situations is **unknown** (the spike measured only the two interrupt cases).

The interrupt decision itself does not come from this line — it comes from the `result`'s `terminal_reason ∈ {"aborted_streaming","aborted_tools"}` → `TurnEnd{Interrupted}` (not an error · the mail stop unchanged — ADR-0238 · TRD §3-4).

## 결정
Notation — **[사용자]** = a decision the user answered · **[메인]** = an orchestrator decision (delegated by the user — 「너가 생각하는 방향으로 하고 나중에 보고 개선하면 되지」 · can be reversed).

The user's original words (2026-09-28, after pointing at a screenshot of Claude Code's 「Interrupted · What should Claude do instead?」 screen): 「이게 정석이긴한데」 · 「어쨋든 그냥 표기하는게좋을것같음. 물론 말풍선은 제거하고, 그리고 오히려 응답이 중단되었습니다.를 빼는게 맞는것같은데? Claude에 한해서」.

1. **claude only — the synthetic line is drawn not as a user speech bubble but as an interrupt marker row carrying that line's original text** [사용자] — both live and in reopened history.
2. **claude only — a turn that already has that marker does not draw the 「응답이 중단됐습니다」 end row that comes from the `result`** [사용자]. codex is unchanged (it has no such line · its interrupt row and the U8 emphasis stay as they are).
3. **ADR-0238's turn-end classification stays as is** [사용자] — the marker row is only a marker. The interrupt decision · the stop after an error · turn observation are decided by the `result`.

Implementation and display details [메인]:

- **a. Recognition lives in the claude translator (`backend/claude`)** (CLAUDE.md 「백엔드 확장」). Condition = the `user` line's `message.content` is **an array with exactly one `text` block**, that text starts with `[Request interrupted by user`, and it is **not `isReplay: true`**. A plain-string content is not looked at — today `consume_line` drops `user` lines whose content is not an array (the `content` array match in `backend/claude/mod.rs` — `:973-976`@HEAD) and that shape has never been observed. ★`isReplay: true` is excluded★ — if the user types text that starts with that prefix, an echo (replay) carrying our uuid comes back, and converting it would skip the accumulator's pending-row check · uuid dedup and also lose the progress signal. A genuine synthetic line has no `isReplay` (research §0 · §1). That line is emitted as **`Structured{kind:"interrupted", json:{"text":"<원문>"}}`** instead of `Structured{kind:"user"}` (the `json` field is, as today, a serialized JSON string — `crates/engram-dashboard-agent/src/types.rs:91` — and its content is this object). This is a vendor-string match — if the vendor changes the wording it goes back to today's speech bubble (still visible, nothing is lost).
- **b. In `classify_turn` this event is `None`** (not progress). It is a marker about the end, not progress. If it came after the `result`, the progress would turn 「턴 중」 back on and block mail for 30 minutes (ADR-0127). This line comes only when the turn is already open (measured 14/14 · claude 2.1.280 · likely).
- **c. The frontend accumulator moves this into an `interruptNote` item `{ kind:'interruptNote'; text: string; itemId: number }`.** On `TurnEnd{Interrupted}` it skips the end row **only when the current turn (the items after the last divider) already has an `interruptNote`** (the divider stays). The fallback = if that line never arrives, the interrupt row stands as is. ★Order premise★ — the marker row comes **before** that turn's `result` (measured 14/14 · claude 2.1.280). If it came after that turn's divider, it would sit in the next turn and could erase that turn's fallback interrupt row. ★The frontend decides by the presence of the marker row — not by 「claude 인가」★.
- **d. The marker row has the same shape as the U8 interrupt row** (icon `CircleStop` · bold · `var(--accent)` — ADR-0237 decision 6), and the text is drawn as the original (without markdown).

## 거부한 대안
**Rejected by the user** (the reason is only what the original words above say — look like Claude Code, remove the speech bubble, and for claude drop our row):
- **Hide that line in the translator** (the main agent's earlier recommendation) — no interrupt marker remains in reopened history.
- **Hide it live and show it as an interrupt row only in reopened history.**
- **Leave it as a user speech bubble** (today's shape).

**Rejected by the main agent:**
- **Recognize it by position** (the user text line right before the `result`) — a reopened transcript has no `result`, so in history the marker would never appear.
- **Carry it as a new wire variant (the ADR-0241 `ToolResult` precedent)** — a new `kind` of `Structured` needs no wire type · generated artifacts · `PROTOCOL_VERSION`/edition handling, and an old shell receives it as an escape-hatch item and shows a collapsed `interrupted` box (`GenericItemRow` — `StructuredTextView.tsx:336-360`@HEAD), and when expanded the text appears as JSON (`{"text":…}`) — it is readable.
- **Decide 「claude 한정」 in the frontend by agent type** — backend knowledge leaks into the frontend (ADR-0004) · it loses the fallback for when the line does not arrive (decision c).

## 영향 / 불변식
- **It relies on a vendor string** — if the vendor changes the discriminating prefix `[Request interrupted by user`, it goes back to the speech bubble (a silent regression, but no information is lost). Then a claude turn shows as speech bubble + interrupt row (fallback). ★This does not contradict TRD §11 ⑪ · ADR-0241's refusal to identify a claude interrupted `tool_result` by its body text★ [메인] — the failing-to-recognize side (the vendor changes the wording) just goes back to today's shape in both cases, so it is not the difference. The difference is the **wrongly-recognizing side**: here even a wrongly recognized line shows its original text as is, so it states no false meaning. The rule ⑪ rejected would attach 「중단됨」 to a real failure, and its body 「The user doesn't want to proceed…」 is also the text of a permission denial (likely — the body is 「…The tool use was rejected…」 · never measured).
- **An interrupt marker remains in reopened claude history** — history has no `result` (the comment of `parse_transcript_events` in `backend/claude/mod.rs` — `:1536`@HEAD 「실측 2026-08-17 — 최근 transcript 12개 전부 0건」 · the main agent's 2026-09-28 check — the S1 spike session transcript also has no `result` line. The `result` line in the fixture `claude_transcript.jsonl` is hand-made (placeholder uuid `1111…`) and its comment treats it as 「픽스처·미래 claude 가 result 를 남기는 경우」 — even if a `result` comes in history, decision c skips the end row, so the display is the same) so today there is no end row, but this line remains in the transcript, so the marker row stands.
- **Known limitation — in reopened history the `isReplay` exclusion does not work** — the transcript's `user` lines have no `isReplay` field (main check 2026-09-28 — all 6 `user` lines of the S1 spike session transcript have no such field). So if the user typed text starting with `[Request interrupted by user` themselves, it is a speech bubble live but shows as an interrupt marker row in reopened history. The text is shown as is and turn observation does not take the history path, so nothing is lost — accepted.
- **The interrupt row remains on codex, and as claude's fallback** — the emphasis of ADR-0237 decision 6 stays on that row. On claude, when a marker row exists, the marker row carries the emphasis.
- **Turn observation unchanged** — `Structured{kind:"interrupted"}` is in none of the two turn-observation cleanup points · the stop after an error · the pending-input event (`classify_turn` `None`). Do not change it to progress (decision b).
- **Do not open the turn-open gate (TRD §3-4)** — the gate opens only on a progress signal, so this event does not touch the gate. When the line arrives the gate is already open (measured 14/14 · claude 2.1.280 · likely).
- **Not a new wire variant** — it is a new `kind` string of the existing `Structured`, so the wire type · generated artifacts · `PROTOCOL_VERSION` do not change. An old shell (before FE-2c) receives the unknown `kind` as the accumulator's escape-hatch item (`kind:'structured'` — the push at the end of the `Structured` branch in `consume` in `src/components/slot/structuredAccumulator.ts` · `:252-253`@HEAD 「알 수 없는 종류(kind)도 흘려 유실 방지」) and still draws the interrupt row as is. That item is drawn by `StructuredTextView.tsx` as a `GenericItemRow` (label + json · rail `assistant` — `:463-467`@HEAD) — a collapsed `interrupted` box (`:336-360`@HEAD), and when expanded the text appears as JSON (`{"text":…}`).
- **ADR-0241's reason for rejecting the escape hatch (「같은 두 분류기가 `Structured` 를 통째로 진행으로 센다」) is resolved here by a single `kind` exception inside the claude classifier** — the codex classifier is unchanged. The `QueuedInput` doc in `types.rs` (`:94-95`) and the `classify_turn` doc, which state the same premise, are fixed together by B3 (TRD §7 B3 · §10).
- **It does not take the side effects of the `user` branch** — the accumulator's `kind === 'user'` branch does uuid dedup and `turnDone = false` (start of a new user turn) (`structuredAccumulator.ts:233-251`). The synthetic line is not a new user turn, so the `interruptNote` branch does neither.
