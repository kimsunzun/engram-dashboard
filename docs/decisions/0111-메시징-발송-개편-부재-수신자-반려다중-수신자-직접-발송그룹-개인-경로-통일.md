# ADR-0111: 메시징 발송 개편 — 부재 수신자 반려·다중 수신자 직접 발송·그룹 개인 경로 통일

- 상태: 확정 (2026-07-29, 근거: 사용자 결정 — 메시징 학습 Q&A 세션에서 v1 실물 검토 후 확정, step-log 2026-07-29)
- 관련: Amends ADR-0103 (결정 2 request 단일 한정, 결정 4 그룹 등록 명단과 skip, 결정 5 부재 파킹, 결정 6 group 툴, 방송 소급 금지 불변식) · ADR-0112(같은 개편의 ADR-0104 조항 반영 — 쌍) · ADR-0104(결정 3 idle 게이트·일괄 flush는 불변 유지) · ADR-0110(커널 lib 격리 — 이 개편도 포트 구조 유지) · `docs/process/S18-messaging-v1/spec/messaging-v1-spec.md` §4·§5·§6(갱신 대상)

## 맥락

메시징 v1 완결 후 사용자 학습 Q&A(2026-07-29)에서 v1 발송 semantics를 실물로 검토한 결과, 세 가지 설계 이상이 지목됐다:

1. **"없는 이름도 파킹"의 암묵 혼입** — 스폰 전 선지시 지원이라는 특수 용례가 일반 발송 경로에 섞여, 오타 이름이 반려 없이 조용히 파킹되고(발송 응답 pending+hint뿐) 24h TTL 만료 시 발신자 능동 통지 없이 소멸한다.
2. **다중 수신자 직접 발송 부재** — 실사용의 메인은 "몇 명 찝어 보내기"인데 v1 `to`는 단일 이름 아니면 @그룹뿐이라, 부분집합 발송이 그룹 등록이라는 우회를 강요한다. 그룹 방송의 실수요는 "모두 종료"류 전원 통보 정도.
3. **그룹 전용 배달 semantics의 이중화** — 그룹만 죽은/부재 멤버 skip·발송 순간 스냅샷·epoch 결박(bound_incarnation)이라는 별도 규칙을 갖고 있어, 개인 편지와 배달 규칙이 2벌이다.

## 결정

1. **부재 수신자 = 입구(ControlIngress) 반려.** 발송 순간 로스터(산 에이전트 명단)에 없는 수신자는 `RECIPIENT_NOT_FOUND` 부활로 실패 처리한다. 스폰 전 선지시(예약 발송)는 **미래의 명시 opt-in 옵션**으로 분리하고 지금은 만들지 않는다. 문턱을 넘은 것의 내부 처리(파킹 semantics)는 통일 유지 — busy 파킹·주입 실패 파킹은 그대로다(경계 = 입구 한 곳).
2. **다중 수신자 직접 발송 = 메인 유스케이스.** `to`가 복수 수신자를 받는다. 내부는 개인 발송 로직을 수신자별 1회씩 태우는 fan-out이며(경로 1벌), 수신자 해석은 **로스터 스냅샷 한 장**으로 전원 일괄(해석 도중 명단 변동에 의한 반쪽 판정 방지 — 옛 그룹 스냅샷 원칙에서 이 조각만 존치).
3. **부분 진행.** 다중 수신자 중 일부만 부재·실패면 가능한 수신자에겐 보내고, 응답 `results[]`에 수신자별 실패 행(+사유 힌트)을 싣는다(상태 어휘에 실패 값 추가). 전송 자체의 문제(인자 오류·본문 과대 등)만 전체 반려.
4. **그룹 = 해석 매크로로 강등.** @주소는 명단을 펼쳐 결정 2의 다중 발송에 태우는 주소록 확장일 뿐, 전용 발송 경로·전용 배달 규칙(죽은 멤버 skip·epoch 결박)은 폐지한다. **사용자 정의 그룹(런타임 등록 명단 + group 관리 툴)은 제거**하고 내장 `@all`(발송 순간 살아있는 전원 — 무저장 즉석 계산)만 유지한다. 저장형 그룹이 필요해지는 시점에 재설계한다(그룹을 위한 구조를 미리 두지 않는다). MCP 툴은 send_message·messages 2개로 준다.
5. **request 다중 수신자 허용.** 수신자별 독립 계약 N개 오픈(각자 회신·각자 기한 통지). 회신은 어차피 1:1이라 전체회신 문제가 없어 옛 단일 한정의 근거가 소멸했다.
6. **epoch 결박(소급 금지) 폐지.** busy 파킹분은 개인 편지 규칙대로 같은 이름의 새 화신(epoch)에게도 배달된다. "이 편지는 발송 순간 화신에게만" semantics가 필요해지면 **개인 메일 옵션으로 후일 무파괴 추가**한다(봉투/인자 확장 경로 — spec §8 정신).

## 거부한 대안

- **부재 파킹 유지(현행 — 선지시 암묵 지원)** — 오타·죽은 상대가 조용히 파킹돼 발신자 피드백이 24h 뒤 장부 기록뿐. 선지시라는 저빈도 용례의 대가를 모든 발송이 치르는 구조라 기각. 존재 검사는 동명 모호(RECIPIENT_AMBIGUOUS) 판정이 이미 로스터를 보므로 추가 비용 ~0.
- **다중 수신자 = 발신자가 N회 호출(현행)** — 메인 유스케이스에 N회 왕복·토큰 비용. 내부 fan-out이 같은 결과를 1회 호출로 제공.
- **그룹 전용 fan-out 경로·skip·결박 유지(현행)** — 배달 규칙 2벌의 유지·검증 비용. "방송은 그 순간 사람들에게"라는 스냅샷 의미론은 부재자가 입구 반려로 걸러지는 새 구조에서 해석 스냅샷 한 장으로 충분히 대체된다.
- **일부 부재 시 전체 반려** — 원자성은 얻지만 방송·다중 발송 사용성이 급락(1명 죽었다고 전원 미발송). 수신자별 실패 행이 재시도 판단 재료로 충분.
- **request 단일 수신자 유지** — 계약 남발 방지 외 실근거 없음. 예외 최소화(통보/request가 같은 다중 규칙) 우선.
- **사용자 정의 그룹 레지스트리 유지(해석 전용으로 축소)** — 다중 직접 지목이 메인이 되면 이름 붙인 부분집합의 실수요가 불명확한데 저장소+관리 툴 표면 유지 비용은 그대로. "필요 시점에 재설계"가 사용자 방향(폴더 그룹 아이디어도 그 시점 후보 — ADR-0104 seam 방향은 ADR-0112).

## 근거

- 사용자 결정(2026-07-29 학습 Q&A 세션): 지목·방향 제시 전부 사용자 발화 — "선지시는 예약 기능으로 분리, 일반 발송의 미존재 이름은 반려" · "몇 명 찝어 보내기가 메인, 그룹은 얹혀 가는 부가" · "그룹도 개인 쏘는 것과 동일하게, 내부에서 한 개씩 쏘는 동일 로직" · 갈림길 4문(그룹 제거/다중 request/부분 진행/busy 분리) 명시 선택.
- v1 실물 검토에서 확인된 사실(코드 확인): 부재 파킹의 발신자 피드백은 발송 응답 hint + 24h 후 장부 `expired`뿐(능동 통지 없음, 기한 있는 request 제외) · ingress는 동명 모호 판정을 위해 이미 발송 시점 로스터를 해석 · 응답 shape은 이미 수신자별 `results[]`라 다중·부분 진행을 구조 변경 없이 수용.

## 영향 / 불변식

- **파킹의 의미 축소** — 파킹 = "살아있으나 지금 못 받는 상대"(busy·주입 실패) 전용. 부재 파킹 경로가 사라지므로 mailbox의 부재 관련 회계(배달 불가 잔해 회수 등)와 TTL의 역할이 좁아진다(TTL은 안전망으로 존치).
- **수신자 해석 = 스냅샷 한 장** — 다중 수신자·@all 펼침·존재/모호 판정은 발송 순간 로스터 스냅샷 하나로 전원 처리한다. 수신자별로 로스터를 따로 뜨면 반쪽 판정이 재발한다.
- **경로 1벌** — @all은 명단 펼침 후 다중 발송과 동일 경로. 그룹 전용 배달 분기를 되살리면 이 결정 위반.
- **툴 표면 = send_message·messages 2개**(ADR-0103 "툴 3개 상한" 갱신). group 툴 제거.
- ADR-0104 결정 3(idle 게이트·일괄 flush·delivered=실주입)은 **불변 유지** — 이 개편은 "누구에게 보낼 수 있나"를 바꾸지 "언제 주입하나"를 바꾸지 않는다.
- 구현 계약 상세(응답 실패 행 어휘·에러 코드·다중 to 표기)는 spec §4·§5·§6 갱신이 정본.
