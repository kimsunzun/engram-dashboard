# ADR-0111: Messaging send overhaul — reject absent recipients, direct send to multiple recipients, unify the group and individual paths

- 상태: 확정 (2026-07-29, basis: user decision — confirmed after reviewing the v1 implementation in a messaging learning Q&A session, step-log 2026-07-29) · 부분 폐기 by ADR-0117 (decision 1 the scope of absent recipients) · 부분 폐기 by ADR-0121 (the @all roster source) · 부분 폐기 by ADR-0309 (decision 6 the criterion for a new incarnation)
- 관련: Amends ADR-0103 (decision 2 the request single-recipient limit, decision 4 the registered group roster and skip, decision 5 absent parking, decision 6 the group tool, the no-retroactive-broadcast invariant) · Amends ADR-0107 (decision 6 broadcast-bound parking) · Amends ADR-0109 (decisions 1-5 group management semantics) · ADR-0112(the ADR-0104 clauses reflecting the same overhaul — a pair) · ADR-0104(decision 3 idle gate and batch flush stay unchanged) · ADR-0110(kernel lib isolation — this overhaul also keeps the port structure) · `docs/process/S18-messaging-v1/spec/messaging-v1-spec.md` §4·§5·§6(to be updated) · Amended by ADR-0117 (decision 1 the scope of absent recipients) · Amended by ADR-0121 (the @all roster source) — **the `@all` in decision 4 was renamed `@here`. Excluding the sender is canonical in spec §4, not in this ADR, and applies to both vocabularies** · Amended by ADR-0309 (decision 6 the criterion for a new incarnation)

## 맥락

After v1 messaging was complete, a user learning Q&A (2026-07-29) reviewed the v1 send semantics against the real implementation and pointed out three design anomalies:

1. **The implicit mix-in of "park even a name that does not exist"** — the special use case of supporting instructions before spawn got mixed into the general send path, so a typo name is silently parked with no reject (the send response is only pending+hint) and, when the 24h TTL expires, vanishes with no active notice to the sender.
2. **No direct send to multiple recipients** — the main real use is "send to a few picked people", but the v1 `to` is only a single name or an @group, so a subset send forces the workaround of registering a group. The real demand for a group broadcast is only an all-hands announcement like "everyone shut down".
3. **Two sets of group-only delivery semantics** — only groups have a separate set of rules — skipping dead/absent members, a snapshot at send time, epoch binding (bound_incarnation) — so there are two sets of delivery rules, one for individual letters and one for groups.

## 결정

1. **An absent recipient = rejected at the entry (ControlIngress).** A recipient who is not in the roster (the list of live agents) at the moment of sending fails with a revived `RECIPIENT_NOT_FOUND`. Instructions before spawn (reserved send) are split out as a **future explicit opt-in option** and are not built now. The internal handling of what clears the threshold (parking semantics) stays unified — busy parking and injection-failure parking are unchanged (the boundary = one place, the entry).
2. **Direct send to multiple recipients = the main use case.** `to` accepts multiple recipients. Internally it is a fan-out that runs the individual-send logic once per recipient (one path), and recipient resolution covers everyone at once with **a single roster snapshot** (preventing a half-decision from the roster changing mid-resolution — only this piece of the old group snapshot principle survives).
3. **Partial progress.** If only some of the multiple recipients are absent or fail, send to the ones that can be sent to, and put a per-recipient failure row (+ a reason hint) in the response `results[]` (a failure value is added to the status vocabulary). Only problems with the transmission itself (argument errors, an oversized body, etc.) reject the whole send.
4. **Group = demoted to a resolution macro.** An @address is only an address-book expansion that expands the roster and puts it on the multi-send of decision 2; the dedicated send path and the dedicated delivery rules (skipping dead members, epoch binding) are discarded. **User-defined groups (a runtime-registered roster + the group management tool) are removed**, and only the built-in `@all` (everyone alive at the moment of sending — an unstored, on-the-spot computation) is kept. Redesign it when stored groups become needed (do not lay down a structure for groups in advance). The MCP tools are given as two: send_message and messages.
5. **Allow multiple recipients for request.** Open N independent contracts, one per recipient (each with its own reply and its own deadline notice). A reply is 1:1 anyway, so there is no reply-all problem and the basis of the old single-recipient limit is gone.
6. **Discard the epoch binding (no retroactive delivery).** Busy-parked items are delivered, as under the individual letter rule, to a new incarnation (epoch) of the same name too. If the semantics "this letter goes only to the incarnation at the moment of sending" becomes needed, **add it later non-destructively as an individual mail option** (the envelope/argument extension path — in the spirit of spec §8).

## 거부한 대안

- **Keep absent parking (current — implicit support for instructions before spawn)** — a typo or a dead target is silently parked, and the sender's feedback is only a ledger record 24h later. It makes every send pay the price of the low-frequency use case of instructions before spawn, so it is rejected. The existence check adds about zero cost, since the same-name ambiguity (RECIPIENT_AMBIGUOUS) decision already looks at the roster.
- **Multiple recipients = the sender calls N times (current)** — N round trips and token cost for the main use case. An internal fan-out gives the same result in one call.
- **Keep the group-only fan-out path, skip, and binding (current)** — the upkeep and verification cost of two sets of delivery rules. The snapshot semantics "a broadcast goes to the people at that moment" is sufficiently replaced by a single resolution snapshot in the new structure, where absent people are filtered by the entry reject.
- **Reject the whole send when some are absent** — it gains atomicity, but broadcast and multi-send usability drops sharply (one dead means nobody gets it). Per-recipient failure rows are enough material for the retry decision.
- **Keep request single-recipient** — there is no real basis other than preventing contract spam. Minimizing exceptions (ordinary notifications and requests follow the same multi-recipient rules) comes first.
- **Keep the user-defined group registry (shrunk to resolution only)** — once multi direct addressing becomes the main use, the real demand for a named subset is unclear, while the upkeep cost of the storage + the management tool surface stays the same. "Redesign when needed" is the user's direction (the folder group idea is also a candidate at that point — the ADR-0104 seam direction is in ADR-0112).

## 근거

- User decision (2026-07-29 learning Q&A session): the pointing and the direction are all the user's own words — "선지시는 예약 기능으로 분리, 일반 발송의 미존재 이름은 반려" (split instructions before spawn out as a reservation feature, reject a nonexistent name in a general send) · "몇 명 찝어 보내기가 메인, 그룹은 얹혀 가는 부가" (picking a few people is the main thing, groups are an add-on that rides along) · "그룹도 개인 쏘는 것과 동일하게, 내부에서 한 개씩 쏘는 동일 로직" (a group is the same as shooting at individuals, the same logic firing one at a time inside) · explicit choices on the 4 fork questions (remove groups / multi request / partial progress / busy separation).
- Facts confirmed in the v1 implementation review (code checked): the sender's feedback for absent parking is only the send response hint + the ledger `expired` after 24h (no active notice, except a request with a deadline) · ingress already resolves the roster at send time for the same-name ambiguity decision · the response shape is already per-recipient `results[]`, so multi and partial progress fit without a structural change.

## 영향 / 불변식

- **The meaning of parking narrows** — parking = only for "a counterpart who is alive but cannot receive right now" (busy, injection failure). With the absent-parking path gone, the mailbox's absence-related accounting (reclaiming undeliverable leftovers, etc.) and the role of the TTL narrow (the TTL stays as a safety net).
- **Recipient resolution = a single snapshot** — multiple recipients, the @all expansion, and the existence/ambiguity decision are all handled for everyone with one roster snapshot at the moment of sending. Taking the roster separately per recipient brings the half-decision back.
- **One path** — @all takes the same path as a multi-send after roster expansion. Reviving a group-only delivery branch violates this decision.
- **Tool surface = two: send_message and messages** (updates the ADR-0103 "three-tool cap"). The group tool is removed.
- Decision 3 of ADR-0104 (idle gate · batch flush · delivered = real injection) is **kept unchanged** — this overhaul changes "who can be sent to", not "when to inject".
- The implementation contract details (the response failure row vocabulary · error codes · the multi-to notation) are canonical in the spec §4·§5·§6 update.
