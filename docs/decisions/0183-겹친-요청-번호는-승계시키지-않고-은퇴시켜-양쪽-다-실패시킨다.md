# ADR-0183: A colliding request number is not handed on but retired, and both sides fail

- 상태: 확정 (2026-09-07, basis: the main agent decided and reported it with grounds and costs → no objection from the user 2026-09-06 + `pending.rs` regression net measured 177/177)
- 관련: ADR-0177 (the charter of this crate — request/response correlation moves here from the shell) · ADR-0181 decision 4 (★**a different case of the same principle**★ — that one is reuse *after a deadline expiry*, this one is a collision *while still waiting*) · real artifacts = `crates/engram-dashboard-transport/src/pending.rs:99` (the three `Insert` branches) · `:143` (`Pending` = waiting table + retirement ring, the rustdoc 「알려진 한계」 is its canonical source) · `:157` (`insert`) · `:60` (`RetiredRing`) · `crates/engram-dashboard-transport/src/policy.rs:172` (`retired_tags` · default 256 = `:205`) · regression nets = `pending::tests::a_colliding_tag_wakes_both_sides_and_retires_the_number` (`:294`) · `pending::tests::a_reply_for_a_collided_tag_reaches_nobody` (`:313`) · ★**the regression nets for today's opposite shell behavior**★ = `src-tauri/tests/daemon_client_pending.rs:71` (`duplicate_request_id_supersedes_instead_of_panicking`) · `:160` (`supersede_survives_dropped_waiter`) · `docs/process/S21-transport-crate/trd.md` §4-1 · step-log S21

## 맥락

With the `transport` crate taking over request/response correlation, we had to decide who handles, and how, the case where the same request number (`Wire::Tag`) comes in again **while it is still waiting**.

**Today's shell behavior = succession.** On a collision it wakes the old waiter with an error and the new request takes over that number (`daemon_client_pending.rs:71`). This behavior came in with the fix for the 2026-08-18 GUI-measured defect — but ★**what that defect aimed at was 「패닉과 영구 hang」 (the panic and the permanent hang), not succession itself**★. The colliding number hit the old `debug_assert`, so every command after it was cut off and there was no reconnect, and the fix's requirement was 「죽지 말고 옛 대기자를 깨워라」 (do not die, wake the old waiter). The part where the new request **takes over** that spot was a choice that came along with that requirement.

The first draft of TRD §4-1 copied that behavior as it was (「옛 대기자를 `Superseded` 로 깨우고 **새 것이 승계** — 오늘 동작 보존」 (wake the old waiter as Superseded and **the new one takes over** — preserve today's behavior)). This ADR overturns that wording.

## 결정

**A colliding number is retired on the spot and both sides fail.**

1. **The old waiter** → `RequestError::Superseded` (preserves today's behavior — it wakes).
2. **The new request** → `RequestError::TagRetired`. ★It cannot take over that spot★.
3. **That number is retired** — it goes into a bounded ring and any later reuse is refused too (ring length = `Policy::retired_tags`, default 256).
4. `Insert::Collided { displaced, rejected }` **hands back both slots as they are** — the caller must wake both (swallowing a slot is itself the permanent hang).

## 거부한 대안

- **Keep succession (accept the misdelivery)** — if the new request takes over the number, **the late reply of the request that went out first is delivered as the counterpart of the later request.** The correlation key is that one number alone, and `Wire` has no material to tell two replies apart (`wire.rs:41` — `reply_tag` is a bare `Option<Tag>`). ★**A wrong answer is worse than a failure**★: the consumer knows about a failure but does not know about a misdelivery.
- **Add one field to `Wire` to tell the two apart** (a second correlation material such as a generation or sequence number) — today `Wire` has six methods (`encode` · `decode` · `request_tag` · `reply_tag` · `stream_mark` · `resume_request`), and adding a field **breaks every implementer.** A collision is an exception path that happens only when a consumer picks a number wrongly, yet every consumer would pay that cost all the time.

## 근거

- **That the correlation key is one is not a design choice but the reality of the wire** (`wire.rs:41`). When two requests use the same key, this crate has ★in principle★ no way to know whose the reply is — in that state, the option of 「배달한다」 (deliver it) is **a delivery that may be right or wrong**, not the correct answer.
- **The range that breaks is narrow** — succession is needed only when a consumer **reuses a live number**, and that condition is itself the consumer's fault. The real guarantee is not in this ring but **on the side that generates the numbers** (canonical source = the `pending.rs:60` rustdoc), and the actual consumer in this repository uses uuid v4.
- **The regression net guards that spot** — `a_reply_for_a_collided_tag_reaches_nobody` nails down 「겹친 뒤 그 번호의 답장은 **아무에게도** 가지 않는다」 (after a collision, the reply for that number goes to **nobody**) with `take(&9) == None`.
- Decision maker = the main agent decided and reported it to the user with grounds and costs, and the user had no objection (2026-09-06).

## 영향 / 불변식

- ★**Today's shell behavior is not preserved on this path**★ — a consumer that reuses a live number receives **two failures instead of one success**. At the move (phase 2), `src-tauri/tests/daemon_client_pending.rs:71` and `:160` are **targets for update**. ★The principle of the move phase is 「동작이 안 바뀌어야 한다」 (behavior must not change), but this one point is an **intended exception**★ — if it is missed, those tests turning red will be misdiagnosed as a regression.
- **The retirement ring is bounded, and forgetting is half of what that ring does** — after `retired_tags` more numbers are retired, the oldest number is forgotten and can be used again. ★Do not read this limit as a guarantee★ (canonical source = the `pending.rs:143` rustdoc 「알려진 한계」). If it did not forget, **legitimate** reuse would be blocked forever too, and a memory with no upper bound is impossible in the first place.
- **All three `Insert` branches return the slot** — not just `Placed`; `Collided` and `Retired` also hand back the slot that could not be put in. If the caller throws it away, that request hangs forever, and the 2026-08-18 defect was exactly that shape.
- **The regression-net gap of ADR-0181 decision 4 was filled only inside `transport`** — that ADR wrote 「만료 뒤 재사용 금지는 아직 아무 테스트도 잡지 않는다」 (the ban on reuse after expiry is still caught by no test), and in this crate the retirement ring and the tests above catch it. ★**The shell path is still as it was**★ — until the move, that sentence holds for the shell.
