# ADR-0306: The notification band covers below the title row, and the title row stays blocked while the restore modal is up

- 상태: 확정 (2026-10-26, basis: user decision 2026-10-26 (notification band = below the title row · reviving the title row during the restore modal only if it is a small change → on a second look it was not small, so it was not done) + main-agent decision (the loading · boot-failure screens use the same frame — U8b review fix) + implementation U8b `a78851d3` · review fix `d3955fb1`)
- 관련: Amends ADR-0276 (decision 2's 「TabBar 를 가려도 된다」 and the rationale GUI QA's 「안내가 TabBar 를 덮는다」) · Amends ADR-0277 (decision 2's 「main 과 팝아웃에서는 TabBar 를 가린다」 and the position basis in the consequences and the position fact in the rationale GUI QA) · ADR-0287 (every band notification is a covering layer · layer height = as much as the notification rows — unchanged · only the covered-screen example in decision 2 changes — Amends at the end) · ADR-0180 (band vs popup split) · ADR-0229 (closing main = hide all windows) · ADR-0303 (Chrome-style title bar) · ADR-0302 decision 11 (window buttons for a window outside the model) · TRD `docs/process/S26-window-chrome/trd.md` (version 0.3 — §7-1 · §7-12 · §10-3 「알림 층의 자리」 · §12-2) · storage TRD `docs/process/S21-storage/trd.md` §6 (restore modal) · `src/components/layout/WindowLayout.tsx` (`notices`) · `src/components/layout/NoticeOverlay.tsx` · `src/components/layout/AppLayout.tsx` · `src/pages/PopoutPage.tsx` · `src/components/layout/ConnectionNotice.tsx` · step-log S26 · tracking T-66 · Amends ADR-0287 (the covered-screen example in decision 2, 「TabBar 등」)

## 맥락

Once the OS frame is stripped (ADR-0303), the title row becomes the only spot where the mouse moves and closes the window. Two things covered it (TRD §7-12):

- **The notification band** (`NoticeOverlay` — state-file notices · connection failure) — it was attached at the very top (`top: 0` · z 40) of the wrapper cell in `AppLayout` · `PopoutPage` and covered the tab bar. ADR-0276 decision 2 「TabBar 를 가려도 된다 — ✕ 로 닫는다」 · ADR-0277 decision 2 「main · 팝아웃에서는 TabBar 를 가린다」 · the position basis in ADR-0277 「영향」 (the caller's cell — main's layout cell · the popout's content box) have that shape. At the time of those decisions, there was a separate OS title bar above the tab bar.
- **The restore modal** (`RestoreModal` — main only · after an abnormal exit) — `AppLayout` locks the whole layout (including the title row) with `inert`, and the modal backdrop covers the whole window (`fixed inset-0` · z-50).

While covered, there is no way to move or close the window with the mouse — this was raised to the user as something to decide before U8b (stripping the OS frame) (TRD §12-2 「알림 띠」 — branches = band below the title row · only window buttons and drag spots above the band · leave as is).

## 결정

1. **The notification band covers below the title row** (user decision 2026-10-26 — 「알림띠는 제목줄 밑으로 와야지」) — the callers (`AppLayout` · `PopoutPage`) pass the notification layer to `WindowLayout` as `notices`, and `WindowLayout` attaches it at the very front of the canvas cell (positioned) right below the title row. It does not hide the window buttons · drag spots · tab bar, and there is no need to compute the title row height (normally 34 · maximized 28) separately. The covering shape (out of flow · height = as much as the drawn rows · z 40 · max height 33vh) stays as is, and it now covers the top of the canvas.
2. **The loading · boot-failure screens use the same frame** (main-agent decision · U8b review fix) — title row (drag spot · window buttons · the number marker is absent until the number arrives · the tab-bar spot is filled with a drag spot) → cell (front = notification layer) → screen content. Since there is no OS frame, those screens also need a place to move and close the window (the window buttons reach it even if that window is not in the model — ADR-0302 decision 11), and the notification layer must be at the same spot in the tree on every screen so that React does not re-mount that layer, so the memory of having closed it with ✕ (what ADR-0277 said not to withdraw) survives loading → tab screen · boot failure → revival. The cell of those screens does not report the canvas size (only while tabs are drawn — ADR-0227).
3. **While the restore modal is up, the title row stays blocked as is** (user decision 2026-10-26 — 「작은 변경일 때만 살린다」 · it was not done after measuring the size). Ways to move or hide the window during the question = keyboard (Alt+Space · Win+arrow — QA records the result · AC23) · tray hide · taskbar.
4. **What this decision changes** — of ADR-0276 decision 2 and the GUI QA in its rationale, 「안내가 TabBar 를 덮는다」 · ADR-0277 decision 2's 「main · 팝아웃에서는 TabBar 를 가린다」 · the position basis in ADR-0277 「영향」 (now = the cell below the title row inside `WindowLayout` · the loading · boot-failure screens use the same spot) · the position fact in its rationale's GUI QA (the layer covers the TabBar) · the 「그 아래(TabBar 등)」 that ADR-0287 decision 2 gave as an example of the covered screen below (what is covered now is the top of the canvas — that decision's layer-height rule is unchanged · an amendment link was added in U10 2026-10-26). **The rest of ADR-0276 · ADR-0277 is unchanged** — the band covers without pushing the layout · stacked and scrolls on overflow · the layer invariants (the wrapper `div` takes the position · height is as much as the rows · z 40) · ★the ✕ and the closed-memory are not withdrawn★ (the spot the band covers cannot receive clicks until ✕ — that spot is now the top of the canvas).

## 거부한 대안

- **Leave it — the band covers the title row from the top of the wrapper cell** (the shape of ADR-0276 decision 2 · ADR-0277 decision 2) — in a window whose OS frame is stripped, while the band covers, there is no way to move or close the window with the mouse (TRD §12-2 「알림 띠」). The user did not choose it (2026-10-26). Rejected = user decision + descriptive.
- **Expose only the window buttons · drag spots above the band (the band keeps covering the tab bar)** — a branch raised to the user (TRD §12-2 「알림 띠」), and the user did not choose it (2026-10-26). The reason for not choosing it is not recorded. Rejected = user decision (no reason recorded).
- **Revive the title row (window buttons · drag spots) during the restore modal** — not a small change (TRD §7-12): (1) `inert` has to be lifted from the wrapper cell and applied separately to the canvas cell inside `WindowLayout` and the tab bar (the `TabBar` root — a child of the title row) (`inert` cannot be undone on a descendant), (2) the modal backdrop has to start below the title row (move it into the canvas cell, or count the row height from the window fact's maximized), (3) a separate backdrop is needed for the loading · boot-failure screens, and (4) it has to be decided how a press on a locked tab falls through to the parent title row (drag spot) and becomes a window drag — four components (`AppLayout` · `WindowLayout` · `TabBar` · `RestoreModal`) · about 60–100 lines + tests. It did not meet the user's condition (「작은 변경일 때만」), so it was not done. Rejection strength = code (size estimate) + user decision.

## 영향 / 불변식

- **The notification layer enters only as `WindowLayout`'s `notices`** — if a caller puts the layer directly on top of the wrapper cell, it covers the title row again. If `position:relative` is removed from the cell, the layer attaches to a reference further out and covers a different spot (the same invariant as ADR-0277's — only the position basis changed).
- **The notification layer is at the same spot in the tree on every screen (loading · boot failure · tab screen)** — if it is put at a different spot per screen, the layer is re-mounted and loses the ✕ closed-memory.
- main's notification layer is still locked during the question — during the restore modal the band's ✕ is also blocked (ADR-0277 as is).
- If a human closes the window during the modal (Alt+F4 · tray), main only hides (ADR-0229), and the question stays as `awaiting`, so when it is shown again the modal is unchanged.
- Anchors — put `// ADR-0306` on the `notices` spot in `WindowLayout.tsx` · the head of `NoticeOverlay.tsx`.
