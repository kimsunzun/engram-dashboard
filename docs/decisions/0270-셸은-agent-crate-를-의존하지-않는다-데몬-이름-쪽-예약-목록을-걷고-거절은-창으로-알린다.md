- 상태: 확정 (2026-10-02, basis: user decision 2026-10-02 (`docs/refactoring/architecture-discussion-2026-09-26.md` decision candidate 5 · work units and order) + code cross-check 2026-10-02 (`d5ac725`)) · 부분 폐기 by ADR-0279 (the policy-wall path in decision 3)
- 관련: Amends ADR-0176 (decision 2's COMMAND_SPECS edge and keeping the daemon-name-side reserved filter, the basis of the item "only remove the filter" among 거부한 대안, and in the impact the warning against deleting reserved_names and the lingering shell agent dependency) · Amends ADR-0219 (decision 2's shell gate_backend door and the shell refusal-arm guard in the impact) · Amends ADR-0175 (in the impact, the line where the shell holds agent in the dependency graph, and in the basis the reason the COMMAND_SPECS filter is needed) · ADR-0176 decisions 4 · 5 (owner declaration · preset duplication — below) · ADR-0167 decision 5 (the commands the webview puts on the bus remain two, `tab.next` · `slot.empty` — 2026-08-23) · ADR-0231 · ADR-0237 (the webview's `agent.cancelQueuedInput` · `agent.interrupt` are in-window-only twins) · ADR-0029 (shell = daemon client) · ADR-0155 (registration bounce contract) · ADR-0138 (a native popup is added when it becomes needed) · ADR-0266 (the place for OS branches) · ADR-0269 (`normalize_cwd` → base) · `src-tauri/src/view_commands.rs` (`reserved_names` · `report`) · `src/commands/viewCommandBridge.ts` (`offeredCommands`) · `src-tauri/src/layout/apply.rs` (`gate_backend` · slot spawn) · `src-tauri/src/layout/commands.rs` · `src/commands/agentCommands.ts` · `crates/engram-dashboard-daemon/src/connection_core.rs` (`refuse_names_i_answer`) · `crates/engram-dashboard-agent/src/commands.rs` (`llm_creation_refusal` · `verb_new`) · `src-tauri/tests/layout_apply.rs` · `src-tauri/tests/layout_commands.rs` · step-log S21 · Amended by ADR-0279 (the policy-wall path in decision 3)

## 맥락

The shell uses **only three things** from the agent crate (not hosting, code cross-check 2026-10-02):

- `COMMAND_SPECS` — the reserved names the webview cannot take (`reserved_names` in `src-tauri/src/view_commands.rs`). The reserved list is the sum of two halves — agent's `COMMAND_SPECS` (the names the daemon answers) + the shell's own table `crate::layout::commands::COMMAND_SPECS` (the names the shell answers). What needs agent is only the first half.
- `llm_creation_refusal` — the backend-policy filter before a slot spawn (`gate_backend` in `src-tauri/src/layout/apply.rs`).
- `normalize_cwd` — cwd spelling cleanup (`src-tauri/src/layout/commands.rs`).

The daemon already blocks name collisions — if a client registers a name the daemon answers by itself, it rejects **the whole registration packet** with `CONFLICT` (`refuse_names_i_answer` in `connection_core.rs`). Shell commands and webview commands are registered in one packet, so if it is rejected, this shell's commands become **zero** until the next reconnect (the LLM cannot touch windows · tabs · slots). Today the shell leaves that rejection only as one `warn` log line (`src-tauri/src/daemon_client/connection.rs` — 「셸 명령 등록 거절」).

**The same names in the webview registry — registration and bus advertisement are looked at separately** (code cross-check `d5ac725`):

- **The registry has four names that are the same as the daemon's** — `agent.spawn` · `agent.rename` · `agent.cancelQueuedInput` · `agent.interrupt` (`src/commands/agentCommands.ts` · the daemon declarations = `crates/engram-dashboard-agent/src/commands.rs`). What ADR-0176 counted is the first two (the latter two were added by ADR-0231 · ADR-0237 as in-window-only twins, and the comment at that place fixes 「`help` 를 달지 말 것 — 데몬이 같은 이름을 버스에서 답한다」). There are also names the same as the shell's own table — `tab.create` · `slot.close`.
- ★**But what is advertised on the bus is only commands that carry `help`**★ — the webview reports to the shell only those with `help.summary` (`offeredCommands` in `src/commands/viewCommandBridge.ts` · since 2026-08-23), and the shell also drops those with no `help.effect` or an empty description (`report` in `view_commands.rs`). Today the webview commands carrying `help` are only the two, `tab.next` · `slot.empty` (`rg "^\s*help\s*[:,]" src -g '!*.test.*'`) — the two that ADR-0167 decision 5 left on 2026-08-23, and it was the same at the time of ADR-0176 (2026-08-26) (at the end of master that day, `5780dcc`, the webview commands carrying `help` were also only those two — `git grep -n -E "^\s*help\s*[:,]" 5780dcc -- 'src/**/*.ts'`). Neither is in the daemon vocabulary or the shell table.
- ★**So the number of names the reserved filter filters out today is 0**★ (code reading — not measured by launching the app). What the filter blocks is the accident on the day someone attaches `help` to a command with the same name. The header comment of `view_commands.rs` and the 「그 사고가 오늘 바로 난다」 in `tests/layout_commands.rs::the_registration_packet_never_carries_a_name_the_daemon_answers_itself` are a description that saw only that the name is in the registry and missed the advertisement gate (`help`) — that test builds a hypothetical situation where the webview reports the names wholesale.

The canonical source of backend-policy decisions is agent alone, and the daemon's `agent.new` looks at the same table (ADR-0219). The shell side is a duplicate that filters first. But the only place that calls the policy function is `agent.new` handling (`verb_new` in `agent/src/commands.rs`), and the shell's slot spawn does not go through that command and sends the communication message `SpawnByCwd` directly, and the daemon does not look at policy on that path.

The user (2026-10-02): 「클라는 데몬이랑 아예 별도의 개념이라서 agent 를 모르는 게 좋음」 · 「데몬에 거절만 하면 딱히 복잡하게 할 필요 없을 듯 … 실행해서 안 되면 다시 빌드하면 되니깐」 · 「빵 하고 뜨면서 클라에서 뜨면 유저도 알지」 · 「망가지지 않는 단위로 잘 그룹지어서 작업하라」 · 「임시 땜빵 때우지 말고」.

## 결정

1. **The shell (client) does not depend on the agent crate** (user 2026-10-02).
2. **The wall against daemon names is kept as the daemon's registration refusal alone** (user 2026-10-02 — 「데몬에 거절만 하면」). Remove the half of the reserved list that reads agent's `COMMAND_SPECS`. No CI cross-check script is added. **The half drawn from the shell's own table stays** (main session's judgment 2026-10-02) — it is the shell's own declaration that does not need the agent crate, and the daemon refusal cannot see the shell and webview names that half blocks (the second item of 「거부한 대안」 below — code).
3. **Work order (work order 2-1) — cut at each unit with the app still running, and leave no temporary workaround** (user 2026-10-02 — 「망가지지 않는 단위로 잘 그룹지어서 작업하라」 · 「임시 땜빵 때우지 말고」):
   1. **Switch the slot spawn to the daemon's `agent.new` command path.** The slot spawn goes in the order 「검사 → 데몬 스폰 → 배치」, so even if the daemon refuses, the layout does not change (`layout/apply.rs` — the spawn is outside the lock · the placement is a single critical section after it). The refusal message makes one round trip to the daemon.
   2. **Delete the shell's policy check (`gate_backend`).** Only after 1 is there no policy hole.
   3. **Delete the daemon half of the reserved list (reading agent's `COMMAND_SPECS`).** With this unit, the shell → agent production edge closes (`normalize_cwd` is moved first by decision 5). The four same names in the webview registry have no `help` and so do not go up on the bus (「맥락」 above), so this unit does not break the app — **no unit that removes the same names first is set up** (main session's judgment 2026-10-02 · 「거부한 대안」 below).
4. **The client shows the refusal in an OS message box** (user 2026-10-02). The side that shows it = the shell. The dialog window differs per platform, so the OS branch goes not in the shell but in the place for OS-dependent code (decision candidate 1) or behind Tauri's dialog feature — chosen at implementation time. **No LLM notification is set up** — the cause stays in the log and appears if the agent digs through the log (the user). Today's one `warn` log line stays as it is. After unit 3 of decision 3, if someone attaches `help` to a command with the same name, that box appearing is the shape this wall intended (「실행해서 안 되면 다시 빌드하면 되니깐」).
5. **`normalize_cwd` moves to base** (decision candidate 4 — `path::normalize_spelling` · work order 1-1 comes first).

## 거부한 대안

- **Put a unit that removes the webview's same names (`agent.spawn` · `agent.rename`) first.** The order was like this at first — because it assumed ADR-0176 decision 2's 「필터만 없애면 앱이 깨진다(자평: 강함)」. Rejected = code — those names have no `help` so they do not go up on the bus, and the number of names the filter filters out today is 0 (「맥락」 above), so unit 3 does not break the app. That cleanup is tied up with ADR-0176 decision 5 (preset duplication) and the identifier-change cost (reason ③ of the first item of that ADR's 「거부한 대안」) and drags in scope unrelated to the purpose of 2-1 (the shell → agent edge) (main session's judgment). ★That 「강함」 basis of ADR-0176 did not stand even on that day's code★ (「맥락」 above — the `5780dcc` cross-check). ★The 「`COMMAND_SPECS` 필터가 지금 필요한 이유」 in ADR-0175 「근거」 (if the filter is removed first, registration is bounced at every boot) carried the same premise★ — the advertisement gate `help` had been there since `85aa6ab` (2026-08-23) and ADR-0175 (2026-08-25) is after it, so that basis also did not stand on that day's code (`85aa6ab` is an ancestor of the ADR-0175 commit).
- **Remove the reserved list wholesale (including the shell's own half).** Rejected = code (main session's judgment) — that half does not depend on agent, so it is unrelated to the purpose of decision 1 (code). ★And there is no wall to replace that half★ — shell commands and webview commands are registered in one packet by one owner, and the daemon's registration refusal (`refuse_names_i_answer`) looks only at the names the daemon answers. The registry folds the same name within one packet into one without an error (`register` in `crates/engram-dashboard-command/src/roster.rs` — it puts entries in order into a `BTreeMap` keyed by name and the later overwrites the earlier · test `duplicate_names_in_one_packet_count_once`, `roster.rs:622`). So if someone attaches `help` to the webview's `tab.create` · `slot.close`, it silently overlaps with the same name in the shell table, and decision 4's refusal box does not appear either (code).
- **Just delete the shell policy check (leaving the slot spawn path as it is).** Rejected = code — the only place that looks at policy is `agent.new`, and the slot spawn bypasses that door with `SpawnByCwd`, so deleting it first would open a policy hole in the slot spawn.
- **Have commands declare their own owner and remove the filter · edge all at once (the 「진짜 결함」 of ADR-0176 decision 4).** Not chosen now = it is a separate topic and large in scope (main session's judgment). **Own assessment of the rejection basis: weak** (narrative — the scope was not measured). Since decision 2 removes only the daemon half, 「뺄셈으로 웹뷰 몫을 구한다」 remains in the shell's own half — that defect stays as the next topic.
- **Catch collisions in advance with a CI cross-check script.** Rejected = user decision (「실행해서 안 되면 다시 빌드하면 되니깐」).
- **Notify the LLM of the refusal too.** Rejected = user decision (the cause stays in the log).
- **Leave the refusal only as one `warn` log line (current).** Rejected = user decision (「빵 하고 뜨면서 클라에서 뜨면 유저도 알지」).
