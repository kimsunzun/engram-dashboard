# ADR-0259: The usage popup puts one 「N분 전 ⟳」 at the head of each vendor and shows the reset time with an hourglass — amber when stale, no fetch on open, and the stage is chosen by width alone

## 맥락
The user tried the usage slot in real use and gave feedback (2026-09-30). The screen then looked like this.

- The popup wrote the age (「1분 전」) separately on every window row (`src/components/slot/UsageSlot.tsx:1115-1119`). The popup had no ⟳ — ADR-0258 Decision 1 gathered refresh into one global button on the small display.
- The reset time was the word 「리셋 00:58」 (ADR-0258 Decision 4). Both the small display (`UsageSlot.tsx:723-730`) and the popup (`:1110-1114` — 「리셋 HH:MM (N 뒤)」) did so.
- The only cue that a value was old was the dimmed number on the small display. The popup did not dim; it showed only the age (`UsageSlot.tsx:1108`).
- The width stage dropped to stage 3 when the hidden render height of stage 2 was larger than the slot (TRD §3 #99 · `pickStage` `UsageSlot.tsx:229-237`). Stage 2 is four lines, so in a slot that was narrow vertically it went straight from stage 1 to stage 3 even when the width allowed stage 2.

Two items from the same feedback ended without a decision. The percent direction ended as a misunderstanding — the remaining-amount display (PRD R1) stays. What 「1분 전」 means got only an explanation — it is the time the value was received (handoff record 150000:32-33).

## 결정
1. **Put one 「N분 전 ⟳」 at the head of each vendor in the popup** — 「Claude 플랜: max · 1분 전 ⟳」. The plan is written only when there is one (D8). Do not attach a clock icon to 「몇 분 전」, and drop the age that was written on every window row. User's words: 「아이콘 2개 나와서 난잡 … 1분 전 하고 바로 리프래시 버튼이 있으면 리프레시라는게 인지가 되니깐」. **The head age = the oldest age among the two windows, 5-hour and weekly — per-model windows are not included.** The amber of Decision 4 looks at the same value. If neither the 5-hour nor the weekly window has a value, no age is written. Source = the user looked at the mockup and chose main's recommendation B (「B이긴한데」 … 「ㅇㅇ 그렇게해」 — user answer 2026-09-30 (this session — source text = `.claude/handoff/attachments/usage-slot-user-answers-2026-09-30.md`)). The accepted cost = an old per-model row does not show on screen that it is stale — ⟳ refreshes that row too. Background (code facts): the ages of the 5-hour and weekly windows diverge after an observation that updated only one window (the same when a window is missing from a fetch response — PRD R16 · the book changes only the windows carried) — for picking up, that is when the old claude `rate_limit_event` shape (only one top-level `rateLimitType`) comes in, or when one window of `unifiedWindows` is missing (`crates/engram-dashboard-agent/src/backend/claude/usage.rs:5-8`·`:53-76`). ★Per-model windows are different★ — picking up does not carry per-model windows (`backend/claude/usage.rs:90` · `backend/codex/usage.rs:81` — `model_scoped: None`) and only the fetch fills them (`backend/claude/usage_probe.rs:359`). The book changes the per-model list only when it is carried (`crates/engram-dashboard-daemon/src/usage_service/book.rs:587-589`). Moreover, a pick-up that carries both windows sets `fresh_reset` (`book.rs:591-595`) and pushes the next automatic fetch back (`next_auto` — `book.rs:554-558`). So while a conversation goes on, the 5-hour and weekly windows are always fresh, but the per-model windows can grow hours old.
2. **The popup's ⟳ is one per vendor — it refreshes only that vendor.** The single global ⟳ on the small display (all enabled vendors) stays. This reverses, for the popup only, ADR-0258 Decision 1's 「팝업의 회사별 ⟳ 는 없앤다」. The rest of Decision 1 (the global button on the small display · no usage item in the slot's right-click menu · the command stays on the LLM path) is alive. Press rules (main's proposal — the global ⟳ rules applied by analogy): the two conditions of the global ⟳ apply to that one vendor. If there is a visible rejection, the button is disabled. If that vendor's fetch is in progress, the press is discarded. There is still no time interval (ADR-0258 Decision 3).
3. **The reset label = unified on the lucide `Hourglass` icon (small display and popup)** — the only visible text beside the icon is the time. If the day is not today, it is the date + time, and ADR-0258 Decision 4's date rule applies as is. The tooltip and screen-reader name are 「리셋 11:29」. This reverses ADR-0258 Decision 4's 「글리프 대신 낱말」. User's words: 「그냥 모레시계 통일로 하자」 · the reason for dropping the word = 「리셋이라고 하면 뭔가 지저분함」 (user answer 2026-09-30 (this session — source text = `.claude/handoff/attachments/usage-slot-user-answers-2026-09-30.md`)). ★This decision also overturns the rejection of 「리셋 표기 — 시계 아이콘」 in ADR-0258's 「거부한 대안」★ — that rejection was on the side that chose a word over an icon (the reason was the trade-off at presentation time — no source text), and this time the choice turned back to an icon. The reason for an hourglass rather than a clock type is main's (the lucide candidates item under 「거부한 대안」 below). The remaining-time parentheses in the popup (「(N 뒤)」) are not touched by this decision (PRD R2 — remaining time only in the popup).
4. **When 「N분 전」 passes 30 minutes, turn it amber** — the threshold = automatic interval 15 minutes × 2 = the code's `STALE_AFTER_SECS` (1800 seconds · `src/components/slot/usageFormat.ts:14`). It does not show up normally, only when the automatic fetch has failed or stalled. The small display's rule (an old value dims only the number · no age text — PRD R32) stays as is.
5. **Do not fetch anew when the popup opens (the Orca way)** — this is the convention of tools that have a periodic fetch. The current code already does so — a click on the summary button only opens and closes (`UsageSlot.tsx:386`). The slot-mount pull only pulls the shell cache and is not a daemon fetch (`:182-185` · TRD §3 #82). This decision records that behavior.
6. **The width stage is chosen by width alone — the stage is not changed because of height.** If the height is short, the bottom is cut off and hidden. Remove the height fallback of TRD §3 #99 (stage 2 → stage 3).
7. **Turning on and off stays as is — a reconfirmation, not a new decision.** Keep 「슬롯에 표시」 at the bottom of the popup (ADR-0258 Decision 2). A vendor that is turned off also disappears from the popup — this is the current behavior and matches peer convention (research ④).

## 거부한 대안
★Each item below states the source of its reason — one of user's words · research · the grounds at presentation time (main).★ The grounds at presentation time are what main wrote when raising the options, and there are no user words saying the user rejected it for that reason (the same notation as ADR-0258).
- **A clock icon on 「몇 분 전」** — user's words: 「아이콘 2개 나와서 난잡」 (handoff record 150000:25).
- **Repeating the age on every window row (the popup before the change)** — research ①: no peer puts it on every row. This is limited to the roughly seven checked, and each vendor gets it once, lightly (CodexBar·Orca at the vendor head · Paseo as `footerText` under the card). User decision (the handoff record's summary — not a quotation of the user's words): the age repeated on every row is dropped.
- **Including per-model windows in the head age (the oldest age — main's reading A, written first)** — the user looked at the mockup and chose main's recommendation B (5-hour and weekly only) (「B이긴한데」 … 「ㅇㅇ 그렇게해」). That is the only user's reason in the user's words. By code facts, while a conversation goes on the per-model windows can grow hours old (Decision 1 background), so with A the head would look stale and amber even though the 5-hour and weekly windows are fresh.
- **Merging the age and ⟳ into one element (a 「⟳ 2분 전」 that fetches anew when pressed)** — research ②: no merged example was found. Placing them side by side is the convention (AWS Cloudscape · Smashing 「Data Freshness Indicator」 — likely · few examples). The user chose side by side (quoted in Decision 1).
- **Keeping no ⟳ in the popup (ADR-0258 Decision 1)** — user's words: 「1분 전 하고 바로 리프래시 버튼이 있으면 리프레시라는게 인지가 되니깐」. It means a ⟳ right next to the time reads as refresh.
- **An arrow icon in the reset slot (`History` · `RotateCcw` · `RotateCw` · `Repeat`)** — research ③: it mixes with the global ⟳. Where ↻ is used for reset, either there is no refresh button (t3code mobile) or it is the same arrow and so mixes (Usage4Claude). `History` is `RotateCcw`'s same line plus clock hands.
- **Keeping the word 「리셋 00:58」 (ADR-0258 Decision 4)** — user's words: 「그냥 모레시계 통일로 하자」 · reason (user answer 2026-09-30): 「리셋이라고 하면 뭔가 지저분함」. Research ③ notes that tools that have a refresh button actually use the word — the user chose differently from that convention.
- **Other lucide candidates without another arrow (`AlarmClock` · `CalendarClock` · `ClockArrowUp`)** — research ③ listed them as candidates (they exist in 1.23.0). ★The hourglass is a recommendation of the main session and the user accepted it — the reasons below are main's (source = user answer 2026-09-30)★. `AlarmClock` = reads as 「알람이 맞춰져 있다」. `CalendarClock` = smears at small sizes, and the date is already visible as text. `ClockArrowUp` = the arrow mixes with ⟳ (the same reason as the arrow icon ban above). The hourglass reads as 「이 시각까지」, which fits the popup showing the remaining time 「(N 뒤)」 alongside — so the risk of being read as remaining time (「영향」 · TRD §6 #31) is reduced but not removed.
- **An amber threshold of 15 minutes (Codex CLI `/status` precedent — research ①)** — the grounds at presentation time (main — handoff record 150000:10-11): 30 minutes is automatic interval 15 minutes × 2, so it does not show up normally and shows only when the automatic fetch has failed or stalled. 30 minutes equals the code's `STALE_AFTER_SECS` and also equals CodexBar Linux's `max(10분, 간격×2)`. The user chose 30 minutes.
- **Fetching anew when the popup opens (the Paseo way)** — research (the 「결정」 section): fetching on open is for tools without a periodic fetch (Paseo `components/context-window-meter.tsx:112-125` · the Claude web usage page is inferred). Orca, which has a periodic fetch, does not fetch on open — the open handler only records and focuses (`StatusBar.tsx:2232-2238` · it fetches only when another account is expanded `:770-775` · certain). We are on the periodic-fetch side. There is also an added risk context (main's note — not the user's words, handoff record 153000:50). For Claude, a 429 comes back as `Failed`, so no block is placed during a rejection, and that rejection can last about an hour (TRD §6 #21). If every open action carries a fetch, that risk grows.
- **Changing the stage by height (the stage 2 → stage 3 fallback · TRD §3 #99 · 7b review FIX)** — removed by user decision (handoff record 150000:22). Reason (user answer 2026-09-30 · ★the user's memory is uncertain★): 「아마 높이 때문에 가장 긴거에서 중간거로 안가고 짧은거로 바로해서였나 잘 기억이 안남」. That account matches the code facts — when stage 2 fails on height, it goes straight from stage 1 to stage 3 (`UsageSlot.tsx:233-236`).
- **Leaving a turned-off vendor only in the popup (n/a etc. in the value slot)** — user answer (2026-09-30): 「다른데가 그래서 그랬고, 보여주면 갱신도 해야되잖아. n/a로 표시해도 되긴 한데 어쨋든 표시가 애매하고 다른곳도 그래서」. Research ④ confirms those 「다른데」 — no tool leaves a vendor hidden from the bar only in the popup. In CodexBar, turning it off removes it everywhere and the fetch stops too (likely). In Orca, the bar and the popup have the same list (certain).
- **Moving the on/off outside the popup (settings screen · right-click menu)** — research ④ notes that no peer puts the switch inside the popup (CodexBar·Stats = settings screen · Orca = status bar right-click menu). Putting it inside the popup is not newly decided by this ADR — ADR-0258 Decision 2 already decided it (a vendor that is off is not subscribed, so there is no value · user: 「끄면 사용량도 안보내고 좋네」). This time it was only kept.

## 영향 / 불변식
- **There are two ⟳ — the small display's global ⟳ (all enabled vendors) and the popup's per-vendor ⟳ (that one vendor).** Both follow the same press rules (the per-vendor side is main's proposal — the global ⟳ rules applied by analogy). If there is a visible rejection, the button is disabled (`aria-disabled` — it keeps focus and only blocks the press). If a fetch is in progress, the press is discarded. The daemon joins an in-progress fetch per vendor. The time interval is not revived (ADR-0258 Decision 3). The accepted risk (Claude 429 from repeated pressing — TRD §6 #21) stays as is, and the places to press grow by the number of vendors.
- **Do not add a new global handle to the LLM path** (CLAUDE.md 「LLM-우선 제어」) — refreshing one vendor rides on the existing command surface (implementation details = TRD §3 #106 ②). The daemon bus `usage.refresh --backend` stays as is.
- **Do not use an arrow icon for 「몇 분 전」 or in the reset slot** — it mixes with ⟳. Do not attach a clock icon to 「몇 분 전」 again (Decision 1).
- **Do not attach a fetch to opening the popup** (Decision 5) — if attached, every open action raises the Claude 429 risk (TRD §6 #21).
- **Do not revive the height fallback** (Decision 6) — if revived, stage 1 skips to stage 3 at narrow heights. The cost (main's inference — a consequence of 「아래가 잘려 가려진다」): if the slot height is short, the bottom row is cut off, and that row's `!` badge (PRD R31) is hidden with it. The bottom row is either the second vendor's row or the lower window row of stage 2. So PRD R31's 「모든 폭 단계에서 배지」 becomes a statement for when the height is ample (written in PRD R31).
- **The head age looks only at the 5-hour and weekly windows — do not put the per-model windows back** (Decision 1 · user decision). The cost = an old per-model row does not show its staleness on screen — ⟳ refreshes that row too.
- **The staleness decision is one constant** — the small display's dimming and the popup's amber use the same `STALE_AFTER_SECS`. If the automatic interval (15 minutes — PRD R15) changes, look at this constant again (threshold = interval × 2).
- **Accepted risk — there is no precedent for writing the reset time with an hourglass** (research ③ — Usage4Claude used the hourglass for remaining time · likely). The user was told there is no precedent (handoff record 150000:30). ★It may collide with the reason ADR-0258 rejected 「시각만」★ — that reason was that 「00:58」 reads as remaining time. Whether the hourglass increases that reading is to be seen in real use (main's inference · TRD §6 #31). The hourglass reads as 「이 시각까지」 and fits the popup's remaining time 「(N 뒤)」, so the risk is reduced but not removed (the lucide candidates item under 「거부한 대안」 — main's reason).
- **On e-ink, the amber has no color cue** — the amber background token `--status-blocked` is the body color (`var(--text)`) on e-ink (`src/styles/theme.css:3`). So it only becomes darker than the usual dim text (`--text-muted`). The handling is undecided (TRD §6 #30 — main's observation).
- **A vendor that is off is also absent from the popup** (ADR-0258 Decision 2 as is — it is not subscribed, so there is no value to show). ★There is a way to turn it back on★ — the 「슬롯에 표시」 row at the bottom of the popup carries all vendors, not only the enabled ones (`ShowToggles` iterates all of `USAGE_VENDORS` — `src/components/slot/UsageSlot.tsx:56`·`:1012`). The detail carries only the enabled vendors (`views` — `:195-196`).
