# ADR-0117: Linked to the send-entry decision restructuring — amending the reject scope (proper ADR-0116)

- 상태: 확정 (2026-07-30, basis: user decision — the same ratification Q&A session as ADR-0116, step-log 2026-07-30)
- 관련: Amends ADR-0111 (decision 1 the scope of absent recipients) · **ADR-0116(the entry decision restructuring proper — this ADR is the stamp of what that decision does to ADR-0111 decision 1, read them as a pair)** · ADR-0111(decisions 2-6 all survive)

## 맥락

ADR-0116 (reviving parking for sleeping recipients) conflicts with the scope of absence in ADR-0111 decision 1 ("a recipient not in the roster at the moment of sending = a `RECIPIENT_NOT_FOUND` reject"). So that a session that reads only the old ADR does not read the discarded scope as alive, the clause amendment on the 0111 side is recorded under a separate number (the supersede tool is one new ADR per old ADR — the same precedent as the 0111↔0112 pair. The proper prose is canonical in ADR-0116).

## 결정

1. **Narrow the reject scope of ADR-0111 decision 1:** change "not in the roster = reject" to **"in neither the roster nor the profiles = reject"** — a sleeping (profile exists, restorable) recipient is accepted by parking (`pending`). In addition, since **the structured-output condition leaves the roster predicate** (ADR-0116 decision 7), every live session becomes a delivery target regardless of whether it has a turn signal — what the 3rd round did, excluding that class from the roster and sending it to a reject, is gone. The canonical branching = ADR-0116 decision 1. The **principle** of the entry reject (the existence check is in one place, the entry · wake not triggered) survives, and decisions 2-6 (multi-recipient fan-out · partial progress · group macro · multi request · binding discarded) all survive too.
2. **Also discard the item "the meaning of parking narrows = only for busy and injection failure" in the ADR-0111 impact section.** Sleeping returns as the **third parking reason**, so that sentence dies (meaning the stamp clause "decision 1 the scope of absent recipients" includes this impact item — stated here so that a session that reads only 0111 does not read that item as a living invariant).
3. **The scope of "instructions before spawn unsupported" narrows too** — sending ahead to a sleeping name that has a profile is now formally supported (parking), and what is unsupported is only sending ahead to a **name that has no profile either** (a spec §8 correction).

## 거부한 대안

- **Discard ADR-0111 in full** — decisions 2-6 are entirely valid regardless of this amendment. It would be a wrong discard that kills a living clause, so it is rejected.
- **Bury it in the proper ADR-0116 and skip the stamp on 0111** — the next session that reads only 0111 follows "reject sleeping too" as a valid decision (violating the no one-way link invariant). Rejected.

## 근거

- User decision (2026-07-30): the same session as the ADR-0116 rationale section — reviving sleeping parking confirmed.

## 영향 / 불변식

- **Survives:** decisions 2-6 of ADR-0111 + the invariants "recipient resolution = a single snapshot" (one profile-list lookup is added to the sources, but the principle "one per send" is the same) · "one path" (@all = the same path as a multi-send) · "partial progress" · "tool surface = two: send_message and messages".
- **Discarded (decision 2):** the first item of the ADR-0111 impact section, "parking = only for a counterpart who is alive but cannot receive right now (busy, injection failure) / the absent-parking path disappears" — invalidated by the return of sleeping parking.
- **Scope narrowed (decision 3):** ADR-0111's "instructions before spawn unsupported in v1" → "limited to names with no profile".
- The remaining details (vocabulary · transitions · deletion cleanup) are in ADR-0116 / the contract lifetime joining is in ADR-0118 / the implementation contract is in the spec.
