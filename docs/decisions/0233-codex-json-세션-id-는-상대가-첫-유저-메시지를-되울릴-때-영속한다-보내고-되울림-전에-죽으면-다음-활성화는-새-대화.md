# ADR-0233: codex JSON 세션 id 는 상대가 첫 유저 메시지를 되울릴 때 영속한다 — 보내고 되울림 전에 죽으면 다음 활성화는 새 대화

- 상태: 확정 (2026-09-26, 근거: 사용자 결정 2026-09-26(TRD §10-1 24) + P2 로컬 QA full 실측(격리 release — 첫 되울림에서 영속 확인))
- 관련: Amends ADR-0226 (결정 2 방아쇠와 결정 11 예외 및 영향의 불변식을 codex JSON 에서 첫 유저 메시지 되울림 기준으로) · Amends ADR-0231 (결정 9 끝의 codex 연결 중 거둔 첫 입력 id 영속 입구를 닫음) · Amends ADR-0185 (영향의 Phase 2 요구 첫 턴 전 persist 를 codex JSON 에서 거둠) · TRD `docs/process/S21-codex-backend/trd-mid-turn-input-queue.md`(§5-8 · §10-1 24 · §10-6 첫 행) · `docs/reference/backend-capabilities.md` §1 「codex 에만 있는 위험」 · 관련 ADR-0218(codex 터미널의 락 회수 — 결정 11 의 그 칸은 그대로) · ADR-0071(프로필 저장 락 규율 — commit 이 도는 스레드가 바뀐다) · ADR-0004(첫 턴 포트는 backend 가 꽂을지 정한다) · step-log S21

## 맥락
ADR-0226 은 세션 id 를 화신의 「첫 제출 래치」가 commit 할 때만 영속하게 했다 — 입력 둘(`offer` = id 가 알려졌다 · `note_submission` = 첫 사용자 턴이 나가기 직전)이 다 선 첫 순간이고, 제출은 세션의 입력 동사가 `send_input` **앞에서** 센다(그 ADR 결정 2). 그 전제는 「세션이 통로에 넘긴 글은 곧 상대에게 간다」였다.

턴 도중 입력(ADR-0231)이 codex JSON 을 `TransportOwned` 로 켜면서(P2c) 그 전제가 깨졌다. 통로가 연결 중 · 턴 id 대기 · 도구 구간 등에서 글을 **쥐고**, 쥔 글은 ✕ 로 거둔다(벤더 호출 없음). 그래서 새 codex 에이전트에 연결이 서기 전 친 첫 글이 목록에 서고 → 세션이 그것을 제출로 세고 → 핸드셰이크 응답의 `offer` 와 만나 id 가 영속되고 → 사용자가 그 글을 ✕ 로 거두면 **턴 하나 없는 thread 의 id 가 프로필에 남는다.** `thread/start` 는 rollout 을 만들지 않으므로(`docs/reference/backend-capabilities.md` §1) 다음 활성화의 `thread/resume` 은 ADR-0226 이 없애려던 그 실패(`-32600 no rollout found` → 「이어받을 대화가 없습니다」 — 그 ADR 맥락 P2)로 돌아간다. ADR-0231 결정 9 는 이것을 ADR-0226 「이 결정이 새로 만드는 쓰레기」 부류에 새 입구 하나로 적어 두었다(구현 전 서술).

구현 중(P2c 뒤) 이 입구가 리뷰 전 우려로 올라왔고 사용자가 영속 시점을 정했다.

## 결정
1. ★**codex JSON(app-server · `TransportOwned`)의 thread id 는 상대가 라이브 스트림에서 유저 메시지를 처음 되울릴 때 영속한다 — 세션이 우리 제출을 셀 때가 아니다**★ [사용자]. 사용자: 「세션 id가 저장되는건 우리가 보내는 시점이 아니고 오는 시점이잖아」 → 「제출하는게 아니고 코덱스가 뱉는거 기준으로 저장하라고 최초 뱉을때가 완전한 타이밍인거잖아. 미세하게 중간에 종료되서 저장안되는건 그냥 초기화 하라고하고」 → (첫 되울림 대 `thread/start` 응답을 물음) → 「일단 실제 아이디가 생성된 기준이어야지 당연히. 그게 사용자 글을 에코할때잖아.」
   - **래치는 그대로다** — 상태 기계·비교-교체·「포트는 화신당 많아야 한 번」(ADR-0226 결정 2–4)이 바뀌지 않는다. `offer` 도 오늘 자리(통로 라이터가 핸드셰이크 응답에서 받는 `record_session_id`)다. 바뀌는 것은 이 칸에서 `note_submission` 을 **누가 언제** 부르느냐뿐이다.
   - **부르는 자리 = 통로 리더** — 래치가 첫 턴 포트(`FirstTurnSink` = `SessionIdLatch::first_turn_sink` → 기존 `note_submission`)를 내주고, 조립점이 그것을 `open_spawn` 에 넘기고, codex app-server 갈래가 `TransportOwned` 와 짝으로 통로에 꽂는다. 리더가 화신당 한 번 부른다(`Reader::witness_first_turn`). 꽂을지는 backend 가 정한다 — 나머지 backend·모드는 버린다(ADR-0004).
   - **무엇을 세나** [고름]: 라이브 `item/started`·`item/completed` 의 `userMessage` 면 무엇이든 — `clientId` 가 있든 없든 · 우편 턴 · 버전 하한 미달 턴 · 턴 끝 뒤의 늦은 되울림도(그 글이 벤더 이력에 든 사실은 같다). 다른 thread 라고 **밝힌** 줄만 뺀다. 이력 복원은 이 문을 지나지 않는다.
   - **어느 스레드·어느 락에서** [고름]: 락을 하나도 쥐지 않은 채, 그 줄의 화면 방출 **뒤에** 부른다 — 포트 너머가 프로필 디스크 쓰기라 말풍선을 붙잡지 않게. 그래서 화신당 한 번의 프로필 저장이 codex 리더 스레드에서 돈다(ADR-0071 의 저장 규율이 그 시간을 묶는다).
   - **세션 쪽** — `count_turn_submission` 은 사용자 종료 중 제출 거절(ADR-0226 결정 4)을 그대로 타고, `TransportOwned` 면 세지 않고 돌아온다.
2. ★**그래서 이 칸에는 「첫 턴 전에 영속」이 없다 — 첫 턴 뒤 영속이다**★ [사용자]. 보내고 되울림 전에 에이전트·데몬이 죽으면 아무것도 영속되지 않고 다음 활성화는 새 대화로 연다(id 없음 → Fresh — ADR-0226 결정 1 의 입구 그대로). 그 사이 상대 쪽에는 첫 메시지가 든 대화가 생겼을 수 있고 그 대화는 이어받지 못한다 — 사용자가 받아들인 결말이다(「그냥 초기화」). 이것은 이 화신의 **첫** 턴에만 걸린다: 이어받는 화신은 저장값이 이미 있고, 그 뒤 턴은 영속과 무관하다.
3. **범위 = codex JSON 뿐** [사용자]. claude(두 모드)는 그대로다 — 목록에 오르든 아니든 곧바로 stdin 에 쓰므로 제출이 곧 넘기기이고, 화신의 첫 입력은 도는 턴이 없을 때라 Direct 다(우편이 먼저 턴을 열었으면 그 우편이 첫 제출이다 — TRD §5-8). 그래서 claude 에서 ✕ 로 거둘 목록 항목은 이미 센 앞 턴 뒤에만 선다. codex 터미널도 그대로다(ADR-0226 결정 11 — 제출과 락 회수 중 늦은 쪽).
4. **개정하는 조항**(각 ADR 상태줄·관련줄에 도장):
   - **ADR-0226 결정 2** — 「방아쇠는 입력 경계 하나다(백엔드 중립) · 세션의 입력 두 동사가 `send_input` 앞에서 센다」 → 세는 자리가 둘이다: 세션의 입력 경계(claude 두 모드 · codex 터미널)와 codex JSON 통로 리더의 첫 되울림. 래치는 여전히 화신마다 하나다. ★그 ADR 이 거부한 「codex `writer_loop` 의 `turn/start` 직전」은 여전히 거부다(아래 「거부한 대안」)★ — 그 거부 사유였던 「방아쇠가 둘이 된다」는 이 칸에서 대가로 받아들였다.
   - **ADR-0226 결정 11** — 「첫 턴 전 영속」이 성립하지 않는 칸이 codex 터미널 하나에서 **둘**이 된다: codex 터미널(늦은 쪽) · codex JSON(첫 되울림 — 결정 2).
   - **ADR-0226 「영향 / 불변식」** — ① CLAUDE.md 「핵심 불변식」의 새 줄(「세션 id 영속 = 첫 제출 래치 한 지점」)의 예외 서술에 codex JSON 이 든다. ② 「운영 조립점에서 래치는 필수다」에 짝 규율이 하나 는다 — `TransportOwned` 를 신고하는 backend 가 첫 턴 포트를 통로에 안 꽂으면 어느 화신도 id 를 영속하지 못한다(오류 없이 모든 이어받기가 새 대화 — 정본 문구 = `FirstTurnSink` 타입 doc). ③ 그 ADR 「근거」의 「ADR-0185 의 크래시 창은 codex 터미널을 뺀 세 칸에서 녹아 없어진다」가 두 칸으로 준다 — codex JSON 에서 그 창(보냄 → 되울림)이 다시 열렸다.
   - **ADR-0231 결정 9 끝** — 「codex 연결 중 ✕ 는 ADR-0226 쓰레기 부류(대화 없는 id 영속)에 새 입구 하나를 더한다」 → 그 입구는 닫혔다: 거둔 글은 되울려지지 않으므로 id 를 남기지 않는다. 그 ADR 이 ADR-0226 에 박은 도장 중 「연결 중 거둔 첫 입력의 id 영속을 쓰레기 부류에 더함」도 같은 뜻으로 낡았다.
   - **ADR-0185 「영향」 Phase 2 요구사항** — 「응답으로 받은 sid 는 첫 턴을 허용하기 전에 persist 한다」 → codex JSON 에서 거둔다(결정 2 의 사용자 수용). 그 요구는 상대가 발급한 id(codex)의 말이고 codex 터미널은 ADR-0226 결정 11 이 이미 뺐으므로, 이제 codex 어느 모드에서도 서지 않는다(claude 는 id 를 우리가 뽑아 첫 제출 앞에서 영속한다 — ADR-0226 결정 1).

## 거부한 대안
표기는 ADR-0231 범례를 따른다 — **[사용자]** = 사용자가 답한 결정 · **[위임]** = 사용자가 맡긴 판정·리뷰 판정 · **[고름]** = 구현이 스스로 고른 내부 구현.

- **세션이 받을 때 센다**(ADR-0226 결정 2 그대로 · TRD 8판 §5-8) [사용자] — 연결 중 친 첫 글을 ✕ 로 거두면 0턴 id 가 영속되고, 다음 활성화가 없는 대화를 이어받으려다 실패한다(위 맥락). P2c 가 codex 를 `TransportOwned` 로 켜며 처음 열린 입구다 — 그 전에는 거둘 수 있는 글이 없었다.
- **`thread/start` 응답에서 영속한다**(물음의 B) [사용자] — 한 마디도 안 하고 끄거나 첫 글을 거두는 에이전트마다 0턴 id 가 남는다 — ADR-0226 D1(「저장된 id 가 있다 ⟺ 이어받을 대화가 있다」)을 되돌린다. 사용자: 「일단 실제 아이디가 생성된 기준이어야지 당연히. 그게 사용자 글을 에코할때잖아.」
- **넘기는 때(라이터가 `turn/start`·`turn/steer` 를 쓰기 직전)에 센다** [사용자] — 여전히 「우리가 보내는 시점」이다(「세션 id가 저장되는건 우리가 보내는 시점이 아니고 오는 시점이잖아」). 통로 안에 넘기기 쪽 방아쇠가 하나 더 선다 — ADR-0226 이 거부한 모양 그대로다(그 ADR 「거부한 대안」 · TRD §5-8).

## 근거
- **사용자 결정** — 2026-09-26 구현 중(TRD §10-1 24 · §10-6 첫 행 · 결정 주체 = 사용자). 발화 원문은 위 결정 1. 물음은 둘이었다(A = 첫 되울림 · B = `thread/start` 응답).
- **첫 되울림이 「대화가 생긴 때」인 이유** — codex 새 thread 는 첫 사용자 메시지 전까지 rollout 이 없다(codex 0.154.0 자기 시험 · `thread/start` 가 rollout 을 만들지 않는 것은 우리 실측으로도 재확인 — `docs/reference/backend-capabilities.md` §1). 그래서 되울림 전의 id 에는 이어받을 것이 없고, 되울림은 그 글이 벤더 이력에 들었다는 신호다. ★되울림 순간에 rollout 이 디스크에 이미 써져 있는지는 재지 않았다 — 가능성 높음★.
- **실측** — P2 로컬 QA full(격리 portable release · `3014247`): 세션 id 가 첫 되울림에서 저장됨을 확인. ★재지 않은 것★: 되울림에서 영속한 뒤 그 턴이 끝나기 전에 데몬이 죽은 thread 를 다시 이어받는 경로.
- **리뷰** — 이 결정은 P2 조각 안에서 착지해 P2 리뷰(`/review code deep` · FIX → 수정 → PASS)를 함께 거쳤다.

## 영향 / 불변식
- **착지** — P2 `3014247`(push · CI 녹). 코드 앵커는 이 번호가 서기 전에 달려 `// ADR-0226 · ADR-0231` 을 가리킨다 — 찾는 법 = `rg "first_turn_sink|witness_first_turn|FirstTurnSink" crates/`.
- ★**짝 규율 — `TransportOwned` ⟺ 통로에 첫 턴 포트**★. 한쪽만 두면 조용히 깨진다: 포트 없이 `TransportOwned` 면 세션도 통로도 세지 않아 어느 화신도 id 를 영속하지 못하고(다음 활성화가 전부 새 대화 — 오류 없음), 포트를 꽂고 세션도 세면 연결 중 ✕ 입구가 되살아난다. 지키는 것 = `FirstTurnSink` 타입 doc · codex `open_spawn` 의 ★ 주석 · manager 의 배선 구조 시험(스폰 경로가 `Some(latch.first_turn_sink())` 를 넘기는지 — `rg "first_turn_sink" crates/engram-dashboard-agent/src/manager.rs`).
- **CLAUDE.md 「핵심 불변식」** 의 「세션 id 영속 = 첫 제출 래치 한 지점」 줄에 codex JSON 예외(첫 되울림 뒤 영속 · 되울림 전 죽으면 영속 없음)가 들어야 한다 — 그 문서 쪽 몫이다.
- **받아들인 잔여**(TRD §5-9): 벤더가 `userMessage` 를 되울리지 않게 바뀌면 영속이 **조용히** 멈춘다(래치의 「보류」 info 로그만 남는다) · commit 이 codex 리더 스레드에서 돌아, 그 사이 상대 stdout 을 읽지 않는다(저장 한 번으로 묶인다) · 리더 스레드에서 포트가 패닉하면 펌프 `Failed`(릴리스는 `panic = "abort"`) · kill 과 늦은 commit 의 창(`record_session_id` 의 창과 같다).
- **어기면 깨지는 것**: 세션 쪽 세기를 codex JSON 에 되살리면 0턴 id 입구가 다시 열린다 · 되울림 대신 `thread/start` 응답이나 넘기는 때로 옮기면 사용자 결정을 뒤집는다.
