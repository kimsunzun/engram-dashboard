# ADR-0132: 제어 평면 CLI — 단일 실행파일에 우편과 제어를 담고 우편 격리를 데몬 거절로 옮긴다

- 상태: 확정 (2026-08-11, 근거: 사용자 결정 + 코드 실측 3건 — 아래 근거)
- 관련: Amends ADR-0128 (제어 CLI 우편 동사 금지 제약) · ADR-0086(듀얼 typed 입구 — CLI 입구의 출처 · least-privilege 기본) · ADR-0094(bare-name grant·PATH 주입) · ADR-0099(capability 스위치) · ADR-0126(CLI 우회 교육 폐지) · ADR-0081(UI relay — 미구현) · ADR-0119(에이전트 어휘) · `src-tauri/src/cli.rs`(제거 대상 CLI 모드) · `crates/engram-dashboard-daemon/src/bin/engram.rs`(개명·확장 대상) · `crates/engram-dashboard-core/src/agent/backend/claude.rs`(env·PATH 주입) · step-log S19

## 맥락

ADR-0128이 우편 채널을 capability로 하드 단일화하면서 **제어 평면(스폰 등)의 채널을 미결로 남겼다**. 사용자 잠정 방향은 "웬만하면 CLI"였고, 이번에 그대로 확정됐다 — 제어는 빈도가 낮아 MCP 툴 스키마를 모든 에이전트 컨텍스트에 상주시킬 이유가 없다.

착수 시 세 가지가 드러났다.

- **제어 CLI 표면이 이미 있다.** `src-tauri/src/cli.rs`가 릴리즈 exe를 데몬 제어 CLI로 겸용해 `list`/`send`/`spawn`/`kill` 4동사를 이미 제공한다(daemon.json 읽어 WS 직결). 새로 만들면 같은 일을 하는 입구가 둘이 된다.
- **그 `send`는 우편이 아니다.** 대상 stdin에 텍스트를 주입하는 키 입력이라, 우편 `send`와 이름은 같고 뜻이 다르다.
- **ADR-0128의 격리 수단이 단일 실행파일과 양립하지 않는다.** 지금 격리는 "MCP 가능 스폰엔 `engram-send`를 아예 안 깔기"인데(`claude.rs`의 PATH·env 주입이 비-MCP 스폰 전용), 제어 CLI를 형제 바이너리로 두고 그 부모 디렉토리를 PATH에 붙이면 우편 CLI가 bare 이름으로 되살아난다. PATH는 파일이 아니라 **디렉토리 단위** 권한이다.

## 결정

1. **입구 단일화.** 제어 평면 CLI는 별도 실행파일 하나(`engram`)로 모은다. `src-tauri/src/cli.rs`의 CLI 겸용 모드는 **제거**하고, 그 4동사는 새 실행파일로 옮긴다. 텍스트 주입 동사는 우편 `send`와 충돌하므로 개명한다.
2. **우편과 제어를 한 실행파일에 담는다.** `engram-send`를 `engram`으로 개명·확장해 우편 동사와 제어 동사를 함께 갖는다. 실행파일이 하나뿐이므로 "형제 바이너리 PATH 노출" 문제 자체가 소멸한다.
3. **우편 격리 수단을 데몬 거절로 옮긴다.** MCP 가능 백엔드로 스폰된 에이전트의 자격증명으로 우편 요청이 오면 **데몬이 거절**한다. help에서 우편 동사를 숨기는 것은 그 위에 얹는 편의일 뿐, 강제가 아니다. ADR-0128의 채널 단일화(우편은 capability로만 갈린다, 런타임 스위칭·폴백 없음)는 그대로 유지된다 — 바뀌는 것은 그것을 **어떻게 강제하느냐**뿐이다.
4. **발견은 그룹 help.** 프라이밍에는 "제어가 필요하면 `engram help`" 한 줄만 넣고, 기능 목록을 나열하지 않는다. `engram help`가 계열 목록을, `engram help <계열>`이 그 계열 사용법을 낸다(MCP가 툴 스키마를 스스로 드러내는 것의 CLI 대응).
5. **제어 권한은 전원 개방.** 스폰된 모든 에이전트가 제어 동사를 쓸 수 있다. 선별 부여는 필요해질 때 별도 결정으로 연다.
6. **v1 범위 = 에이전트 제어 전부.** 데몬(`AgentManager`)이 이미 가진 동사 — 띄우기·이름 변경·죽이기·목록·만들기·지우기·계층 이동·재우기 — 를 전부 낸다. 조작 어휘는 에이전트 어휘를 쓴다(ADR-0119: 프로필이라는 단어가 매니저 경계 밖으로 나오지 않는다).
7. **UI 제어와 픽셀 제어는 후속 순서로 분리.** ① 창·탭·슬롯의 **기능** 제어(만들기·쪼개기·빼내기)는 데몬↔클라이언트 릴레이(ADR-0081)를 먼저 깔아야 하므로 2차 ② **위치·크기**(픽셀) 제어는 지금 앱에 개념 자체가 없고 레이아웃 디스크 영속도 없으므로 3차 — 필요해지면 영속과 함께 연다.

## 거부한 대안

- **앱 실행파일의 CLI 겸용 모드를 확장한다** — 신규 실행파일 0개라 싸다. 그러나 에이전트가 치는 이름이 GUI 앱 이름이 되고, "첫 인자가 GUI 인자와 겹치면 창이 안 뜬다"는 제약을 동사가 늘 때마다 영구히 관리해야 한다. 발견용 이름으로 부적합.
- **기존 CLI와 새 제어 CLI를 공존시킨다** — 당장 아무것도 안 깨진다. 그러나 같은 일을 하는 입구가 영구히 둘이 되어 동사 하나 고칠 때마다 두 곳을 고쳐야 하고, 에이전트에게 어느 쪽을 가르칠지가 계속 애매해진다.
- **제어 CLI를 우편 CLI와 별도 실행파일로 두고 디렉토리를 분리한다**(ADR-0128 미결이 적어둔 회피안 ①) — ADR-0128 제약을 안 건드린다. 그러나 배포·패키징이 디렉토리 둘로 늘고 발견(help)도 둘로 갈린다.
- **PATH 주입을 포기하고 절대경로 + 환경변수로만 호출**(회피안 ②) — 가장 안전하나 에이전트 명령줄이 길어지고 bare 이름 발견성이 떨어진다. 단일 실행파일을 택하면 애초에 노출될 형제가 없어 이 대가를 치를 이유가 사라진다.
- **제어도 MCP 툴로 낸다** — 우편과 채널이 통일된다. 그러나 제어는 빈도가 낮은데 툴 스키마는 **모든 에이전트 컨텍스트에 상시 상주**한다. 우편이 MCP인 이유(오가는 양이 많아 속도가 이득)가 제어에는 적용되지 않는다.
- **프라이밍에 제어 명령 목록을 전부 적는다** — 확실히 알게 된다. 그러나 모든 에이전트가 쓰지도 않는 목록의 토큰을 상시 지불하고, 동사가 늘 때마다 프라이밍을 고쳐야 하며, 길어질수록 정작 지켜야 할 문장이 묻힌다.
- **제어 권한을 선별 부여한다** — least-privilege에 맞다. 그러나 부여 축이 하나 더 늘어 v1 범위가 커진다. 개방은 나중에 좁힐 수 있으나(안 가르치거나 안 깔아주면 된다) 지금 좁히면 v1이 커진다.
- **UI 기능 제어를 v1에 함께 넣는다** — 사용자 요청 범위였다. 그러나 실측 결과 릴레이가 미구현이라(아래 근거) "기존 것을 입구만 다는 일"이 아니라 없는 배선을 새로 까는 일이다. CLI가 먼저 서 있어야 거기 동사를 얹으므로 순서상으로도 뒤다.

## 근거

- **UI 릴레이 미구현(실측 2026-08-11).** `RegisterRole`·`UiApp`·`RelayUi`·`UiCommand`·`UiResult` 전부 `.rs` 소스 hit 0. `AuthFrame`에 role 필드 없음, `connection_core.rs` dispatch에 relay arm 없음, `src-tauri/src/daemon_client/`에 인바운드 UI 명령 처리 없음. `docs/reference/architecture-overview.md`도 "아키텍처는 확정, 코드 구현은 대기 중(diff 0)"이라 자인한다.
- **데몬은 레이아웃을 모른다(실측).** `ViewManager`·`LayoutState`는 `src-tauri/src/layout/`에만 있고 `crates/` 전체에 없다. protocol의 `AgentCommand`/`AgentEvent` 어휘에 창·탭·슬롯이 없다.
- **좌표 개념 부재(실측).** `src-tauri/src/commands/layout.rs`·`popout.rs`의 창·탭·슬롯 동사 17종 중 x/y/w/h를 받는 것이 하나도 없다. 픽셀 제어는 입구 추가가 아니라 신규 기능이다. 레이아웃은 디스크 영속도 없다(인메모리 — 클라이언트 재시작 시 초기화).
- **에이전트 제어는 전부 데몬에 있다(실측).** `AgentManager`에 `create_agent`·`delete_agent`·`rename_agent`·`reparent_agent`·`spawn_agent`·`activate_profile`·`kill_agent`·`list_agents` 등이 구현돼 있고 wire 변주도 대응된다. 이름 유일성·자동 접미사도 이미 돈다(ADR-0119/0120/0123). CLI는 순수 입구 추가다.
- **PATH 노출 경로 확인(실측).** `claude.rs`의 `ENGRAM_SEND_EXE` + PATH prepend는 비-MCP(CLI 전용) 스폰에서만 호출된다 — MCP 가능 스폰엔 우편 배선이 아예 안 깔린다(ADR-0128 반영분). 단일 실행파일로 합치면 이 분기가 "무엇을 깔까"가 아니라 "무엇을 허용할까"로 이동한다.
- **클라이언트 측 숨김은 강제가 될 수 없다.** CLI를 부르는 주체가 에이전트 자신이라 명령줄·환경변수를 조작할 수 있다. 그래서 강제는 자격증명을 아는 데몬에 둔다.

## 영향 / 불변식

- **불변식(강화):** 우편 동사의 허용 여부는 **데몬이 자격증명으로 판정**한다. CLI 측 숨김·필터에 의존하는 구현은 위반이다 — 뚫리면 ADR-0128의 채널 단일화가 무너진다.
- **불변식(유지):** 우편 채널은 백엔드 capability로만 갈린다. 런타임 스위칭·폴백 없음(ADR-0128 결정 1은 그대로).
- ADR-0128의 격리 **수단**(MCP 가능 스폰에 우편 배선 미주입)은 이 결정으로 대체된다. 그 조항만 부분 폐기이고 채널 단일화 본체는 유효하다.
- **★결정 3은 아직 구현 전이다 — 옛 수단을 지우지 말 것★:** 데몬 측 자격증명 거절은 **1라운드(에이전트 제어) 안의 우편 거절 게이트 조각**에서 만든다 — 제어 동사 조각 다음, 앱 CLI 모드 철거 앞이다. **결정 7의 「1·2·3라운드」와 혼동하지 말 것**(그 3라운드는 위치·크기 제어이고, 레이아웃 영속이 선행이라 훨씬 뒤다). 두 번호 체계가 겹쳐 "우편 격리가 두 단계 뒤"로 오독된 적이 있다(리뷰 적출 2026-08-11). **그때까지 실제로 우편을 격리하는 것은 여전히 `claude.rs`의 "MCP 가능 스폰엔 CLI 배선을 깔지 않는다" 분기뿐이다.** 이 ADR의 위 문장(“대체된다”)과 ADR-0128의 부분 폐기 도장만 읽고 그 분기를 제거하면 **우편 격리가 0이 된다** — 도장은 *결정*이 바뀌었다는 표시지 *코드*가 바뀌었다는 표시가 아니다. 구현 완료 시 이 항목을 지운다. (deep 리뷰 3인 중 2인이 독립 적출 — 2026-08-11)
- `src-tauri/src/cli.rs` 제거 → `is_cli_verb` 분기와 `main.rs`의 선행 판정도 함께 사라진다. 그 4동사를 쓰던 외부 스크립트가 있으면 깨진다.
- `engram-send` 개명 → grant 문자열(`Bash(engram-send:*)`)·프라이밍 문장·`ENGRAM_SEND_EXE`·CLI 프로세스 테스트가 함께 이동한다. ADR-0094의 bare-name 정렬 불변식(가르치는 이름 = PATH로 해석되는 이름)은 새 이름으로 유지해야 한다.
- **알려진 수용 위험 2 — grant 접두 확장(사용자 결정 2026-08-11: 수용, 지금 좁히지 않는다):** 이름이 짧아져 `Bash(engram:*)`의 **접두 매칭**이 형제 실행파일까지 덮는다 — `engram-dashboard`(옛 CLI 모드에 `spawn`·`kill` 잔존)와 `engram-dashboard-daemon`. 배포 폴더 co-location + PATH prepend로 실제 bare 이름 해석이 된다. 옛 이름 `engram-send`는 길어서 자기 자신만 걸렸다. **지금 무해한 이유:** `--permission-mode bypassPermissions`가 **조건 없이** 주입돼(ADR-0097) grant 자체가 NO-OP다. **좁히지 않은 이유:** 이득이 관측 불가(아무도 안 보는 목록)이고, 계열 단위로 좁히려면 grant 매처가 접두에 공백을 허용하는지 실측이 선행돼야 하며(미확인 — 추측 수정 금지, ADR-0038), 가장 위험한 형제는 결정 1의 `src-tauri/src/cli.rs` 제거로 사라진다. **재검토 트리거 = 그 base 플래그를 걷는 날**(claude.rs가 auto mode를 "임시 체제, 정식 대체는 전 LLM 공용 제약 레이어"로 이미 못 박아 뒀다 — 그 작업이 이 항목을 함께 연다). **미확인 1건:** 프로필 `extra_args`가 `--permission-mode`를 다시 지정하면 어느 쪽이 이기는지 검증 안 됨(현재 그런 프로필 없음).
- **알려진 수용 위험:** 제어 전원 개방으로 prompt-injection된 에이전트 하나가 형제를 kill하거나 무한 스폰할 수 있다. T-11(child별 권한 스코프)이 이미 같은 축의 보류 항목이며, 이 결정은 그 위험 표면을 넓힌다.
- **ADR-0086과의 긴장 — 도장을 박지 않기로 판단(2026-08-11):** 그 ADR의 "워커에겐 send_message만 노출(least-privilege 기본)"은 문구상 **MCP 툴 노출 범위**를 말하고 이번 결정은 **CLI 축**이라 직접 충돌하지 않는다. 게다가 ADR-0086 자신이 "이번 스코프 = send 하나, spawn/창이동 등은 **additive로 후속**"이라 제어 동사의 후속 추가를 이미 예정해 뒀다. 다만 "전원 개방"이 그 ADR의 least-privilege **기조**와 어긋나는 것은 사실이므로 여기 남긴다. 부분 폐기 도장을 안 박은 이유는 셋이다: ① 문구 충돌이 아니라 기조 긴장이라 조항을 특정할 수 없다 ② 결정 근거를 전부 쥔 doc-aware 적대 리뷰어가 이 긴장을 결함으로 적출하지 않았다 ③ ADR-0086은 이미 `Amended by`를 하나 갖고 있어 둘째를 박으면 `adr.mjs index --write`가 인덱스 셀에서 그것을 조용히 지우는 알려진 결함(8회 재발)을 다시 밟는다. **이 판단이 틀렸다면 증상은** — ADR-0086만 읽은 세션이 least-privilege를 근거로 제어 CLI 노출을 되돌리려 드는 것이다. 그때 이 항목을 근거로 정식 도장을 박는다.
- **후속 순서(이 ADR이 고정):** ① 에이전트 제어 CLI(이번) → ② 창·탭·슬롯 기능 제어(ADR-0081 릴레이 구현 선행) → ③ 위치·크기 제어(레이아웃 영속 선행).
