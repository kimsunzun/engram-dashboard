# ADR-0145: JSON 모드 빈 상태 화면 = 복원 완료 신호 기준, 마스코트와 가운데 입력창

- 상태: 확정 (2026-08-18, 근거: 사용자 결정) · 부분 폐기 by ADR-0146 (마스코트 임계 높이 접힘)
- 관련: ADR-0045(구조화 렌더 파이프라인) · ADR-0046(뷰 단위 구독) · ADR-0078(렌더 모드는 생성 시 고정) · `src/components/slot/RichSlot.tsx` · `src/api/protocolClient.ts` · Amended by ADR-0146 (마스코트 임계 높이 접힘)

## 맥락

JSON 모드 슬롯을 새로 만들면 검은 화면에 입력창 한 줄만 뜬다. 사용자 제보(2026-08-18): 무엇이 떠 있는지, 살아 있는지 구분이 안 된다. 터미널 모드는 claude가 자기 배너를 그려 주는데 JSON 모드에는 그런 신호가 없다.

여기에 "대화가 0건이면 안내 화면"을 그대로 얹으면 **복원 세션에서 깜빡인다.** 챗 뷰는 마운트 시 목록을 비우고(`RichSlot.tsx:85`) 구독을 건 뒤, 데몬이 보낸 이력이 도착해야 채워진다. 즉 이력이 있는 세션도 복원이 끝나기 전까지는 0건이라, 안내 화면이 떴다가 대화로 바뀐다.

## 결정

1. **빈 상태 판정 = 복원 완료 신호 + 0건.** `subscribeOutput`의 네 번째 인자(상태 콜백)가 `'live'`를 알릴 때까지는 아무 안내도 그리지 않는다. 지금 챗 뷰는 이 인자를 넘기지 않는다 — 신호는 이미 클라이언트까지 와 있고 소비만 안 하고 있다.
2. **빈 상태 구성** — 위에서 아래로 마스코트, "Claude Code" 문구, 입력창. 슬롯 세로 중앙에 놓는다.
3. **마스코트는 클로드코드 CLI 배너 캐릭터 원본 형태, 색은 빨강 고정.** 테마 강조색을 따라가지 않는다.
4. **마스코트는 픽셀 격자로 그린다** — 도트 배치를 문자열 데이터로 두고 격자 요소로 렌더한다. 이미지 자산을 넣지 않는다.
5. **입력창은 하나를 공유하되 빈 상태에서만 모양이 다르다** — 둥근 모서리에 조금 크게. 첫 전송 이후에는 하단의 기존 고대비 스타일로 돌아가고 하단 입력창은 손대지 않는다.
6. **전환은 스냅** — 애니메이션을 넣지 않는다.
7. **슬롯 높이가 임계 미만이면 마스코트만 숨긴다.** 문구와 입력창은 남는다.
8. **구독이 실패 상태로 끝나면 빈 상태를 그리지 않는다** — 현행처럼 빈 화면이다. 실패 표시 신설은 이 결정의 범위 밖이다.

## 거부한 대안

- **0건이면 무조건 빈 상태(복원 신호 무시)** — 위 맥락의 깜빡임이 생긴다. 복원 도중 구간은 대화 길이에 비례해 늘어나므로 짧다고 가정할 수 없다. (코드 확인 근거 — 화면 실측은 아직 없다.)
- **일정 시간 기다린 뒤 0건이면 표시** — 대기 시간이 근거 없는 상수가 된다. 느린 복원에서는 여전히 깜빡이고 빠른 복원에서는 빈 상태가 늦게 뜬다. 정확한 신호가 이미 있는데 시간으로 대신할 이유가 없다.
- **마스코트를 우리 식으로 재해석한 캐릭터** — 사용자 판단(2026-08-18): "짝퉁이 더 문제일 듯". 이 앱이 실행하는 대상이 클로드코드이므로 그 마스코트를 그대로 쓰는 편이 정직하다고 봤다.
- **마스코트 색을 테마 강조색에 연동** — 사용자가 빨강 고정을 골랐다(2026-08-18). e-ink 테마에서 튀는 문제는 테마 전반을 손볼 때 함께 처리하기로 미뤘다.
- **이미지 자산(PNG)** — 테마 전환을 따라가지 못하고 배율에 따라 흐려진다. 원본이 픽셀 아트라 격자로 그리면 형태 손실이 없다.
- **문자 블록으로 출력** — 모노스페이스 셀이 정사각형이 아니라 캐릭터가 세로로 늘어난다. 줄 간격으로 보정하면 폰트마다 결과가 갈린다.
- **입력창을 항상 둥근 박스로**(claude.ai 형태) — 사용자 취향으로 기각(2026-08-18). 첫 화면만 꾸미고 이후에는 지금의 고대비 터미널 감각을 유지한다.
- **빈 상태에 안내 문구·예시 프롬프트 추가** — 요청은 "무엇이 떠 있는지 구분"이지 사용법 안내가 아니다. 슬롯은 작을 수 있어 문구가 늘면 임계 높이 문제가 커진다.

## 근거

- **사용자 결정(2026-08-18)** — 구성·마스코트·색·전환·입력창 스타일 전부 사용자가 지정했다.
- **복원 완료 신호는 이미 존재한다** — 셸(`src-tauri`)이 데몬 replay 의 끝을 받아 표식 프레임을 만들어 넣고(`encode_marker_frame` — 정의 `src-tauri/src/daemon_client/replay_flight.rs`, 호출부 같은 폴더 `connection.rs`), 클라이언트가 그것으로 버퍼를 비우며 `'live'`로 전환한다(`src/api/protocolClient.ts` `flushToLive`). ★사실 정정 2026-08-26(결정은 불변)★ — 옛 문장은 *"데몬이 …넣고"* + 경로 `crates/engram-dashboard-core/src/replay_flight.rs` 였는데 둘 다 틀렸다: 표식 tag 255 는 **데몬 codec 에 없는 셸↔웹뷰 Channel 내부 계약**이라 데몬은 이 표식을 모르고(ADR-0046 결정 4), 그 경로는 ADR-0175(개명 + 결정 3 이사)로 죽었다. 이력이 0건인 새 에이전트에도 같은 신호가 오므로 "복원 끝 + 0건"이 정확히 갈린다. 프로토콜·백엔드 변경이 필요 없다.
- **터미널 슬롯도 같은 신호를 안 쓰고 있다** — 거기서는 빈 화면이 자연스러워 문제가 드러나지 않았을 뿐이다. 이 결정은 그 미사용 자리를 챗 뷰에서 처음 채운다.

## 영향 / 불변식

- **빈 상태는 표시 판정에만 개입한다.** 구독·누산·전송 경로를 바꾸지 않는다(ADR-0044/0045/0046 데이터 흐름 불변). 상태 콜백은 추가로 받는 신호이지 기존 조각 콜백을 대체하지 않는다.
- **복원 완료 표시는 재구독마다 초기화한다.** 뷰·에이전트·epoch가 바뀌면 목록을 비우는 그 자리에서 함께 내린다. 안 내리면 재spawn 후 이전 세션의 완료 상태를 물려받아 깜빡임이 되살아난다.
- **마스코트는 JSON 모드 전용이다.** 터미널 모드는 claude 자신의 배너가 그 역할을 한다 — 거기에 얹지 않는다.
- **지금은 백엔드가 클로드코드 하나뿐이라 마스코트를 고정한다.** codex 등 다른 백엔드가 붙으면 이 자리는 백엔드별로 갈라야 한다 — 챗 뷰가 특정 백엔드를 아는 상태를 영구화하지 않는다(CLAUDE.md 「백엔드 확장」).
- **팝아웃 창에도 자동 적용된다** — 같은 챗 컴포넌트를 쓴다. 별도 배선이 없다는 뜻이자, 팝아웃에서 깨지면 본창에서도 깨진다는 뜻이다.
