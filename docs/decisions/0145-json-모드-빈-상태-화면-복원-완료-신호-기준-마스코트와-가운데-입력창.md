# ADR-0145: JSON mode empty state screen = based on the restore-complete signal, mascot and a centered input box

- 상태: 확정 (2026-08-18, grounds: user decision) · 부분 폐기 by ADR-0146 (mascot threshold-height collapse) · 부분 폐기 by ADR-0226 (decision 1 empty state decision and the no-protocol-change premise in the grounds)
- 관련: ADR-0045(structured render pipeline) · ADR-0046(per-view subscription) · ADR-0078(render mode is fixed at creation) · `src/components/slot/RichSlot.tsx` · `src/api/protocolClient.ts` · Amended by ADR-0146 (mascot threshold-height collapse) · Amended by ADR-0226 (decision 1 empty state decision and the no-protocol-change premise in the grounds)

## 맥락

When a JSON mode slot is newly created, a black screen with a single line of input box appears. User report (2026-08-18): you cannot tell what is showing or whether it is alive. Terminal mode has claude draw its own banner, but JSON mode has no such signal.

If "show the guidance screen when there are 0 conversations" is simply laid on top of this, **it flickers in a restored session.** The chat view empties the list on mount (`RichSlot.tsx:85`), attaches the subscription, and is filled only when the history the daemon sent arrives. That is, even a session with history has 0 items until the restore finishes, so the guidance screen appears and then changes to the conversation.

## 결정

1. **Empty state decision = restore-complete signal + 0 items.** Nothing is drawn as guidance until the fourth argument of `subscribeOutput` (the status callback) reports `'live'`. The chat view currently does not pass this argument — the signal already reaches the client and is merely not consumed.
2. **Empty state composition** — from top to bottom: the mascot, the "Claude Code" text, the input box. Placed at the vertical center of the slot.
3. **The mascot is the original shape of the Claude Code CLI banner character, with the color fixed to red.** It does not follow the theme accent color.
4. **The mascot is drawn on a pixel grid** — the dot arrangement is kept as string data and rendered as grid elements. No image asset is brought in.
5. **One input box is shared, but its shape differs only in the empty state** — rounded corners and a bit larger. After the first send it returns to the existing high-contrast style at the bottom, and the bottom input box is left untouched.
6. **The transition is a snap** — no animation is added.
7. **If the slot height is below the threshold, only the mascot is hidden.** The text and the input box remain.
8. **If the subscription ends in a failed state, the empty state is not drawn** — it is an empty screen as it is now. Adding a failure display is outside the scope of this decision.

## 거부한 대안

- **Always show the empty state when there are 0 items (ignoring the restore signal)** — the flicker in the context above occurs. The in-restore interval grows in proportion to conversation length, so it cannot be assumed to be short. (Grounds = code check — there is no screen measurement yet.)
- **Wait a fixed time and show it if there are still 0 items** — the wait time becomes a constant with no grounds. With a slow restore it still flickers, and with a fast restore the empty state appears late. An exact signal already exists, so there is no reason to substitute time for it.
- **A character reinterpreted in our own style for the mascot** — user judgment (2026-08-18): "짝퉁이 더 문제일 듯" (gloss: a knockoff seems the bigger problem). Since what this app runs is Claude Code, it was judged more honest to use its mascot as is.
- **Link the mascot color to the theme accent color** — the user chose fixed red (2026-08-18). The problem of it sticking out in the e-ink theme was deferred to be handled together when the theme as a whole is touched.
- **An image asset (PNG)** — it cannot follow theme switches and blurs with scaling. The original is pixel art, so drawing it on a grid loses no shape.
- **Output as text blocks** — monospace cells are not square, so the character stretches vertically. Compensating with line spacing gives results that differ per font.
- **Always a rounded box for the input box** (the claude.ai form) — rejected by user taste (2026-08-18). Only the first screen is decorated, and afterwards the current high-contrast terminal feel is kept.
- **Add guidance text or example prompts to the empty state** — the request is "tell what is showing," not usage guidance. A slot can be small, so more text makes the threshold height problem bigger.

## 근거

- **User decision (2026-08-18)** — the user specified everything: composition · mascot · color · transition · input box style.
- **The restore-complete signal already exists** — the shell (`src-tauri`) receives the end of the daemon replay, builds a marker frame and inserts it (`encode_marker_frame` — defined in `src-tauri/src/daemon_client/replay_flight.rs`, call site in `connection.rs` of the same folder), and the client uses it to clear the buffer and switch to `'live'` (`src/api/protocolClient.ts` `flushToLive`). ★Fact correction 2026-08-26 (decision unchanged)★ — the old sentence was *"데몬이 …넣고"* (gloss: the daemon … inserts) + the path `crates/engram-dashboard-core/src/replay_flight.rs`, and both were wrong: marker tag 255 is a **shell↔webview Channel internal contract that is not in the daemon codec**, so the daemon does not know this marker (ADR-0046 decision 4), and that path died with ADR-0175 (rename + decision 3 move). The same signal arrives for a new agent with 0 history, so "restore finished + 0 items" separates exactly. No protocol or backend change is needed.
- **The terminal slot does not use the same signal either** — an empty screen is natural there, so the problem simply did not show. This decision fills that unused spot in the chat view for the first time.

## 영향 / 불변식

- **The empty state intervenes only in the display decision.** It does not change the subscription · accumulation · send paths (the ADR-0044/0045/0046 data flow is unchanged). The status callback is an additionally received signal and does not replace the existing chunk callback.
- **The restore-complete flag is reset on every resubscription.** When the view · agent · epoch changes, it is lowered at the same spot where the list is emptied. If not lowered, after a re-spawn it inherits the previous session's completed state and the flicker comes back.
- **The mascot is JSON mode only.** In terminal mode claude's own banner plays that role — it is not laid on top of it.
- **The mascot is fixed because the backend is only Claude Code for now.** When other backends such as codex join, this spot must be split per backend — the chat view's knowledge of a specific backend is not made permanent (CLAUDE.md 「백엔드 확장」).
- **It applies automatically to the popout window too** — it uses the same chat component. That means there is no separate wiring, and also that if it breaks in the popout it breaks in the main window too.
