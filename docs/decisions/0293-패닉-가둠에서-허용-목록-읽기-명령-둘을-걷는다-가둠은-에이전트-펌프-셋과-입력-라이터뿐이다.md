# ADR-0293: Drop the two allow-listed read commands from the panic containment — containment is only the three agent pumps and the input writer

- 상태: 확정 (2026-10-12, 근거: user decision 2026-10-12 「그냥 걷으면 되긴할것같은데」 · 「결국 펌프에만 있다는거네」)
- 관련: Amends ADR-0292 (the command-side allow list of decision 2) · ADR-0159 (bus command panic = `INTERNAL`) · TRD `docs/process/S21-panic-policy/trd.md` §4-2 B1

## 맥락

ADR-0292 decision 2 set the contained units as the agent side (the three output pumps · the input writer) plus a command-side **explicit allow list** of two commands, `agent.list` and `agent.listQueuedInputs`. On the command side, the daemon's `call_daemon_command` in `control/commands.rs` wrapped the table call (argument adjustment · building the future) and the body drive in `contain` when the command had one of those names, and folded a caught panic into an `INTERNAL` reply for that one command (U2 `76c8031e`). After the implementation was done (U5 `40b8a08e`), the user asked 「이 위치가 필요하냐」, and we followed the code and re-measured the real benefit.

## 결정

1. **Drop the command-side containment.** Remove the allow-list constant · its `contain` branch by that name · the single function that held the table call and body drive for that branch · the allow-list test. Every bus command follows the same rule — a panic in the execution span = reason log → immediate daemon exit (ADR-0292 decision 1).
2. **The only contained places = the four on the agent side** — the three output pumps (PTY · stdio · codex reader) and the input writer drain. The four marker-off spots inside them (ADR-0292 decision 3) stay as they are.
3. The rest of ADR-0292 (decisions 1 and 3–7) stays live.

## 거부한 대안

- **Keep it — contain broadly as now (argument adjustment + body).** It blocks no real risk (code). ① The two commands do not interpret external input — the argument declaration of `agent.list` is an empty object (`AgentListArgs {}`), and `agent.listQueuedInputs` takes one target id, so the argument adjustment (`command/src/table.rs:130-131`) does nothing, and a format error is bounced **as a value** by the earlier `check_args` and by the body's deserialization. ② The body is only a read lock · a copy · path normalization · serialization, so it has no panic source. ③ A poisoned lock's `.expect` (the profile table · the agent state lock) never reaches these commands: after the pump panic that would poison the lock, the pump's `finish` (outside the marker) takes the same lock first and ends the daemon. What is left is only the value of insurance against a bug that may come in later, and such a bug is better surfaced by immediate exit + reason log like every other command, which matches the ADR-0292 policy.
- **Narrow — contain only the body.** For the same reasons there is no benefit, and for these two commands there is practically no difference from broad (the argument adjustment does nothing).

## 근거

- User decision 2026-10-12 (the status line above).
- Code trace (2026-10-12 · the `40b8a08e` tree): `daemon/src/control/commands.rs` `call_daemon_command` · `call_and_drive` · `PANIC_CONTAINED` · agent `commands.rs` `verb_list` · `AgentManager::roster` · the U4-C body audit of the allow list (neither body changes state — certain).
- Cost: the allow-list constant · the 「본문 효과 없음」 contract (code cannot catch it) · the test that pins that contract · the split-out function · several comments explaining it were a maintenance burden.

## 영향 / 불변식

- **Invariant — the bus command execution span is not contained.** To contain a command again, re-check the `effect == Read` counterexample of ADR-0292 「거부한 대안」 (`usage.get`) and the folding rule 「본문 효과 없음 → `INTERNAL`, 효과 있음 → `OUTCOME_UNKNOWN`」 (`daemon/src/command_delivery.rs` `fold_local`), and make it a new decision.
- The command tool crate's body net (`command` `guard_panic`) is not reached in the production process — a panic outside the marker is ended by the hook first. It lives only in test builds without the hook (it is not dropped · the shell and daemon tests lean on that net).
- The comments that pointed at the allow list — the 「셋째 그물」 comment in `daemon/src/command_delivery.rs` · the hook doc in daemon `lib.rs` · base `sync` contract 3 · the contained-unit list in agent `turn.rs` and so on — are fixed in the same change as this decision (`rg "허용 목록|PANIC_CONTAINED"`).
- TRD `docs/process/S21-panic-policy/trd.md` §4-2 B1 is withdrawn by this decision.
