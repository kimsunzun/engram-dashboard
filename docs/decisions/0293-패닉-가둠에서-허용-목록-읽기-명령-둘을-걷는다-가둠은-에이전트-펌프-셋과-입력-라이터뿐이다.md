# ADR-0293: 패닉 가둠에서 허용 목록 읽기 명령 둘을 걷는다 — 가둠은 에이전트 펌프 셋과 입력 라이터뿐이다

- 상태: 확정 (2026-10-12, 근거: 사용자 결정 2026-10-12 「그냥 걷으면 되긴할것같은데」 · 「결국 펌프에만 있다는거네」)
- 관련: Amends ADR-0292 (결정 2의 명령 쪽 허용 목록) · ADR-0159(버스 명령 패닉 = `INTERNAL`) · TRD `docs/process/S21-panic-policy/trd.md` §4-2 B1

## 맥락

ADR-0292 결정 2 는 가두는 단위를 에이전트 쪽(출력 펌프 셋 · 입력 라이터)과 명령 쪽 **명시 허용 목록** `agent.list` · `agent.listQueuedInputs` 둘로 정했다. 명령 쪽은 데몬 `control/commands.rs` 의 `call_daemon_command` 가 그 이름일 때 표 호출(인자 보정 · future 만들기)과 본문 몰기를 `contain` 으로 감싸고, 잡은 패닉을 그 명령 하나의 `INTERNAL` 답으로 접는다(U2 `76c8031e`). 구현을 다 마친 뒤(U5 `40b8a08e`) 사용자가 「이 위치가 필요하냐」를 물었고, 코드를 따라가 실익을 다시 쟀다.

## 결정

1. **명령 쪽 가둠을 걷는다.** 허용 목록 상수 · 그 이름의 `contain` 분기 · 그 분기를 위한 표 호출 / 본문 몰기 한 몸 함수 · 허용 목록 시험을 없앤다. 모든 버스 명령은 같은 규칙을 따른다 — 실행 구간의 패닉 = 사유 로그 → 데몬 즉시 종료(ADR-0292 결정 1).
2. **가두는 자리 = 에이전트 쪽 넷뿐** — 출력 펌프 셋(PTY · stdio · codex 리더)과 입력 라이터 drain. 그 안의 표시 끔 넷(ADR-0292 결정 3)은 그대로다.
3. ADR-0292 의 나머지(결정 1 · 3~7)는 그대로 산다.

## 거부한 대안

- **유지 — 지금처럼 넓게(인자 보정 + 본문) 가둔다.** 막는 실제 위험이 없다(코드). ① 두 명령은 외부 입력을 해석하지 않는다 — `agent.list` 의 인자 선언은 빈 객체(`AgentListArgs {}`), `agent.listQueuedInputs` 는 대상 id 하나라 인자 보정(`command/src/table.rs:130-131`)이 하는 일이 없고, 형식 오류는 앞선 `check_args` 와 본문의 역직렬화가 **값으로** 반려한다. ② 본문은 읽기 락 · 복사 · 경로 정규화 · 직렬화뿐이라 패닉원이 없다. ③ 오염된 락의 `.expect`(프로필 표 · 에이전트 상태 락)는 그 락을 오염시킬 펌프 패닉 뒤 펌프의 `finish`(표시 밖)가 같은 락을 먼저 잡아 데몬을 끝내므로 이 명령까지 오지 않는다. 남는 값어치는 앞으로 들어올지 모를 버그의 보험뿐이고, 그런 버그는 다른 모든 명령처럼 즉시 종료 + 사유 로그로 드러나는 편이 ADR-0292 의 정책과 맞다.
- **좁게 — 본문만 가둔다.** 위와 같은 이유로 실익이 없고, 두 명령에서 넓게와의 차이도 사실상 없다(인자 보정이 빈 동작).

## 근거

- 사용자 결정 2026-10-12(위 상태줄).
- 코드 추적(2026-10-12 · `40b8a08e` 트리): `daemon/src/control/commands.rs` `call_daemon_command` · `call_and_drive` · `PANIC_CONTAINED` · agent `commands.rs` `verb_list` · `AgentManager::roster` · U4-C 의 허용 목록 본문 감사(두 본문이 상태를 바꾸지 않음 — 확실).
- 비용: 허용 목록 상수 · 「본문 효과 없음」 계약(코드가 못 잡는다) · 그 계약을 못 박는 시험 · 분리 함수 · 그것을 설명하는 주석 여럿이 유지 부담이었다.

## 영향 / 불변식

- **불변식 — 버스 명령 실행 구간은 가두지 않는다.** 명령 하나를 다시 가두려면 ADR-0292 「거부한 대안」의 `effect == Read` 반례(`usage.get`)와 「본문 효과 없음 → `INTERNAL`, 효과 있음 → `OUTCOME_UNKNOWN`」 접기 규칙(`daemon/src/command_delivery.rs` `fold_local`)을 다시 대 보고 새 결정으로 한다.
- 명령 도구 crate 의 본문 그물(`command` `guard_panic`)은 운영 프로세스에서 닿지 않는다 — 표시 밖 패닉은 훅이 먼저 끝낸다. 훅 없는 시험 빌드에서만 산다(걷지 않는다 · 셸 · 데몬 시험이 그 그물에 기댄다).
- `daemon/src/command_delivery.rs` 의 「셋째 그물」 주석 · 데몬 `lib.rs` 훅 doc · base `sync` 계약 3 · agent `turn.rs` 의 가둔 단위 목록 등 허용 목록을 가리키던 주석은 이 결정과 같은 변경에서 고친다(`rg "허용 목록|PANIC_CONTAINED"`).
- TRD `docs/process/S21-panic-policy/trd.md` §4-2 B1 은 이 결정으로 철회된다.
