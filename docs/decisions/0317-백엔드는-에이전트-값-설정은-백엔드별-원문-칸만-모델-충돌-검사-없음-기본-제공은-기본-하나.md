# ADR-0317: The backend is an agent value — settings are only per-backend raw-text fields, no model conflict check, the built-in is one 「기본」

- 상태: 제안 (2026-10-31, basis: user decisions memos 199 · 201 (2026-10-18 「그건 에이전트가 골라야지」 · 「그냥 고정해. 백엔드는.」 · 「어 고정해.」))
- 관련: ADR-0316 · ADR-0337 · PRD R35 · D4 · D5 · TRD §7 11

## 맥락
The old memo 7 (2026-10-10~12) left the agent as an empty shell and let the settings asset choose the backend and model (two of them = error · none = do not run · changing = a new conversation).

## 결정
1. The backend is an agent value fixed at creation — to change it, make a new agent (memo 199). The mode (JSON · terminal) is the same (memo 201 · D5).
2. A settings file = `description` + only per-backend raw-text fields (`claude:` · `codex:`). There are no formal `backend` · `model` fields — the model is also inside the raw text. The raw text is loaded only when it matches the agent backend.
3. There is no model conflict check — Engram does not interpret the raw text.
4. The built-in preset is one 「기본」.

## 거부한 대안
- **Settings decide the backend and model** (memo 7) — user 「그건 에이전트가 골라야지」 · 「설정을 claude codex 둘다 입력되게 해놓은건 특정 모델의 에이전트 설정되면 설정을 스위칭 하라고 해놓은거잖아. 근데 model을 왜 에이전트가 골라」 (memo 199).
- **A built-in backend preset** (yield and swap when unpacked — the old candidate 「사용자 백엔드가 있으면 사용할 수 없음」) — not needed since the backend is an agent value (PRD D4 「백엔드가 에이전트 값이라 백엔드 프리셋이 필요 없다」).
- **Two `model` = conflict** — to check it, a lookup table per CLI would have to be fixed at every update (memo 199 · user 「대조표? 매번 업데이트 받아서 비교된다는거잖아. 그게 아니라 이번에 적용하고 나중에 또 대응해야되면 빼는게 맞고」).

## 근거
User decisions memos 199 · 201 (2026-10-18).

## 영향 / 불변식
- Editing a preset does not change the agent backend — so the edit reply does not carry a list of affected agents (TRD §1-7).
- If two models are in the same backend field, leave it as the CLI does.
