# ADR-0176: Do not add the command name prefix, and keep the shell filter

- 상태: 확정 (2026-08-26, basis: user decision + code measurement) · 부분 폐기 by ADR-0270 (decision 2's COMMAND_SPECS edge and keeping the reserved filter on the daemon-name side, the rationale of the rejected alternative that removes only the filter, and in the consequences the warning not to delete reserved_names and the remaining shell agent dependency)
- 관련: Amends ADR-0175 (decisions 4 and 5 put on hold) · ADR-0155 (registration bounce contract) · ADR-0055 (single control surface) · ADR-0061 (preset = cwd bookmark) · Amended by ADR-0270 (decision 2's COMMAND_SPECS edge and keeping the reserved filter on the daemon-name side, the rationale of the rejected alternative that removes only the filter, and in the consequences the warning not to delete reserved_names and the remaining shell agent dependency)

## 맥락

The goal of ADR-0175 decisions 4 and 5 was **to remove the shell → `agent::commands::COMMAND_SPECS` edge**, and the prefix (`ui.`) was the means. The chain was this — what reads that constant is the **reserved-name filter** (`reserved_names` in `src-tauri/src/view_commands.rs`), and the reason the filter exists is that the daemon **bounces a registration packet whole if even one name it answers itself is in it** (`connection_core.rs:675` `refuse_names_i_answer` — it does not drop only the overlapping ones), and since `agent.spawn` and `agent.rename` really exist in the webview registry, removing the filter first would bounce the registration at every boot, and **the shell's names would not get onto the registry at all.** So the order was 「충돌 제거 → 필터 삭제 → 간선 소멸」 (remove the collision → delete the filter → the edge disappears).

In the measurement before starting, **three premises collapsed.**

1. **A classification channel already exists and is already exposed.** A command declaration has a `category` field (`src/commands/registry.ts:48`) and `list()` returns it as is (`:127-131`). It amounts to stamping **once more into the identifier** the information the prefix was meant to give. (But today's `category` values are on the noun axis (`agent`·`slot`·`tab`), so they do not carry 「누가 답하나」 (who answers) — if that axis is needed, fixing the values or the field is cheaper than a prefix.)
2. **There are only 2 collisions, and they are symptoms of a boundary defect.** The daemon declarations are `agent.list`·`agent.move`·`agent.new`·`agent.rename`·`agent.spawn`, and the frontend registrations are `agent.kill`·`agent.rename`·`agent.spawn`·`agent.spawnInto` — the overlap is **two**, `agent.spawn` and `agent.rename`. What the frontend's `agent.spawn` does is **resolve a preset to a cwd and then call the daemon**, but ★the preset is owned by the daemon★ (`FilePresetStore` in `persistence/presets.rs` of the `agent` crate) — and **the daemon's `agent.new` already takes `preset` directly** (mutually exclusive with `cwd`, exactly one of the two). That is, the frontend is resolving on the daemon's behalf something the daemon already knows.
3. **Even if the edge is closed, the gate number does not change.** The shell keeps declaring `agent` in its manifest and the `daemon` dev-dependency pulls in all of it, so the dependency cap gate reads 7 either way. The real gain is release binary size, which ADR-0175 §남는 무검증 had already declared **unmeasured**.

So the prefix becomes **renaming commands that are about to be deleted**, and what is gained in return is an unmeasured benefit.

## 결정

1. **Do not add the `ui.` prefix** (ADR-0175 decision 5 put on hold). Command names keep their current form.
2. **Leave the `COMMAND_SPECS` edge and the reserved-name filter as they are** (ADR-0175 decision 4 put on hold). The filter does its job today, and deleting it breaks the app.
3. **Treat ADR-0175 as complete with decisions 1·2·3 (rename · create `base` · move `replay_flight`).** The three are finished through implementation, review, and CI green.
4. **Hand the real defect to the next topic — 「명령이 자기 주인을 밝히지 않는다」 (commands do not declare their owner).** Today the owner is found by **subtraction**: `프론트 레지스트리 − 데몬이 답하는 이름 − 셸 표가 답하는 이름 = 웹뷰 몫` (frontend registry − names the daemon answers − names the shell table answers = the webview's share). That subtraction is the reason for reading `COMMAND_SPECS`, and replacing it with a declaration makes the filter, the edge, and the prefix **all** unnecessary at once.
5. **Hand over together — the frontend resolving daemon-owned presets as a copy.** The direction of the fix is already shown by `agent.new` (the daemon takes `preset` directly). Fixing it removes the frontend shell and **the 2 collisions disappear with it.**

★**This is on hold, not rejected**★ — once 4 and 5 above are sorted out, the goal of ADR-0175 decision 4 (the edge disappears) is achieved without a prefix.

## 거부한 대안

- **Force the `ui.` prefix as originally planned** (ADR-0175 decision 5) — rejected. ① The classification value is already carried by the `category` field (measured: exists in the declaration + `list()` exposes it) ② the 2 collisions that were the compelling reason are symptoms of a boundary defect, so even with a prefix, **the moment the boundary is fixed those commands get erased** ③ changing the identifier shakes existing keybindings, docs, and usage habits together. **Basis of rejection = measured (self-assessment: strong).**
- **Put `daemon.` and `shell.` symmetrically too** — rejected. The reason ADR-0175 「거부한 대안」 already gave (stamping location into the name makes it false when moved — if `tab.create` is moved to the daemon, `shell.` is false) still holds as is, and the `ui.` rejection reasons ① and ③ above apply equally. There is no reason to set up three when one prefix does not stand. **Self-assessment: strong** (the rejection of the location axis follows the ADR-0175 precedent, the rest is measured).
- **Remove the daemon's bounce check (`refuse_names_i_answer`)** — rejected (**closer to on hold**). If the daemon accepts overlaps, the filter and the edge become unnecessary and the goal is achieved, but ① it is **covering a collision while knowing it**, which is clearing away a net while something is actually caught in it ② ADR-0155 nailed that contract, so a reversal is needed ③ ★the routing priority of overlapping names was not checked★ — a code comment says *"route looks at the table first"* but it was not measured. **Self-assessment of the basis for rejection: weak** (③ is unconfirmed). It is an option that will be reopened during the boundary cleanup.
- **Remove only the shell's reserved-name filter** — rejected. **The app breaks.** `refuse_names_i_answer` collects all overlapping names and bounces them, and the call site is `refuse_names_i_answer(...).and_then(register)`, so if bounced, registration does not run at all — because of one overlap, the rest of the shell's names also fail to get onto the registry. **Self-assessment: strong** (code measurement).
- **Fix the boundary all at once now** — rejected (user decision). Changing daemon command arguments + deleting frontend commands + sorting out preset ownership are naturally looked at together when working on the agent tree system. This branch's topic is the crate boundary cleanup.

## 근거

- **`category` field measurement** — `category?: string` at `src/commands/registry.ts:48`, and `list()` at `:127-131` returns `id`·`title`·`category`·`keybinding`·`help`. But it has **0 consumers in the frontend** (not used in rendering) — that is, the channel is open and only the display is missing.
- **Collision measurement** — comparing the 5 daemon declarations against the 4 frontend registrations, the overlap was confirmed to be the two, `agent.spawn` and `agent.rename`. (The initial rough figure 「4건」 (4) was a guess made from looking only at the frontend list.)
- **Preset ownership measurement** — `crates/engram-dashboard-agent/src/persistence/presets.rs` (`FilePresetStore`) is the daemon-side file store, and the argument comment of `agent.new` states *"mutually exclusive with `preset`, exactly one of the two"*. The frontend's `store.presets` is a copy of that.
- **Bounce contract measurement** — `crates/engram-dashboard-daemon/src/connection_core.rs:675`~ and the call site `:1279-1280`. The comment even gives the basis for why overlapping names are all collected (reconnection cost).
- **Edge accounting** — after the move, `rg -o "engram_dashboard_agent::[A-Za-z0-9_:]+" src-tauri/ | sort -u` → **exactly 1** (`commands::COMMAND_SPECS`, `src/view_commands.rs:204` · `tests/layout_commands.rs:1489`). The dependency cap is 7 regardless of that (manifest declaration + dev-dependency transitive).
- **Known limit of the filter** — the function comment admits it: **if the daemon crate declares its own name, the shell does not compile it in and cannot see it** (the announced `mail.*`). Then the only line of defense is the daemon's bounce. That is, the filter is already incomplete, and that makes this decision **less regrettable**.

## 영향 / 불변식

- **ADR-0175 decisions 1·2·3 remain valid as is** — rename · create `base` · move `replay_flight`. This ADR puts only decisions 4 and 5 on hold.
- **Do not delete `reserved_names` in `src-tauri/src/view_commands.rs`** — deleting it bounces the registration at every boot (see §근거 above). The condition under which it can be deleted is **the collision disappearing first**, and the path there is decision 5 (correcting preset ownership).
- **The shell's `engram-dashboard-agent` dependency remains** — 1 symbol (`COMMAND_SPECS`). A gate that brings this to 0 is not set up now. Setting it up would be **permanent red until the boundary is fixed**.
- **Where to reconsider when the prefix is brought up again** — if the 「누가 답하나」 axis becomes necessary, express it as a **field** (data). The option of stamping it into the identifier was rejected by this ADR, and the reason is the first two items of 「거부한 대안」 above.
- **Tracking place for the two items handed to the next topic** = `docs/backlog.md`. This ADR holds the *why*, and the backlog holds the *what and when*.
- **Remaining unverified** — the routing priority of overlapping names (whether the daemon table comes first) was not measured. The basis for rejecting the alternative 「데몬 반려 검사 제거」 (remove the daemon bounce check) is weak by that much, and that measurement must come first during the boundary cleanup.
