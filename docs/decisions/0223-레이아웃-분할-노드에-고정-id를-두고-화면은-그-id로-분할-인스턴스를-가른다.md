# ADR-0223: 레이아웃 분할 노드에 고정 id를 두고 화면은 그 id로 분할 인스턴스를 가른다

- 상태: 확정 (2026-09-23, 근거: 결함 재현 + 2라운드 적대 리뷰 실측 — 메인 결정(화면에 안 보이는 내부 구현), 사용자에게 보고 2026-09-23) · 부분 폐기 by ADR-0227 (결정 2 Allotment key와 영향의 승격 재마운트 조항)
- 관련: ADR-0035(레이아웃 권위 = src-tauri) · ADR-0063(결정 2의 분할은 ratio 초기 사이징만 다룬다) · ADR-0148(죽은 에이전트 화면 보존) · ADR-0222(부팅 기본 = 단일 빈 슬롯) · `src-tauri/src/layout/types.rs`(`LayoutNode::Split.id`) · `src-tauri/src/layout/tree.rs`(`split_in_tree`·`close_in_tree`) · `src/components/layout/ViewLayoutRenderer.tsx`(Allotment key) · Amended by ADR-0227 (결정 2 Allotment key와 영향의 승격 재마운트 조항)

## 맥락

사용자 보고(2026-09-23): 에이전트 트리 슬롯을 팝아웃하면 main 뷰가 통째로 빈다. 슬롯을 닫거나 병합하다 보면 레이아웃이 가끔 날아간다.

원인은 백엔드가 아니라 화면이었다(재현 — 백엔드 트리·스냅샷은 온전했다).

- 닫기와 팝아웃은 닫힌 칸의 형제를 부모 자리로 올린다(`close_in_tree`).
- 렌더러는 분할 컴포넌트(allotment 1.20.5)를 트리 위치로 재사용한다.
- 그 라이브러리는 가로/세로 방향을 마운트 때 한 번만 정하고, `preferredSize`도 새로 붙은 칸에만 적용한다.

그래서 방향이 다른 분할이 같은 자리에 오면 칸이 0으로 접혀 빈 화면이 됐다. 방향이 같으면 예전 칸의 픽셀 크기가 남았다.

## 결정

1. **`LayoutNode::Split`에 `id: Uuid`를 둔다.** 분할할 때마다 새로 뽑는다(`split_in_tree`). 노드가 자리를 옮길 때(형제 승격)는 노드째 이동하므로 id가 따라간다. TS 바인딩(`LayoutNode.ts`)에도 실린다.
2. **렌더러는 Allotment를 `${id}:${dir}`로 key한다.** 다른 분할이 그 자리에 오면 새로 마운트하고, 자식만 바뀐 같은 분할은 인스턴스와 칸 크기를 유지한다.
   - `dir`을 key에 남기는 이유: 제자리에서 방향이 바뀌는 경로가 생기면 여전히 다시 마운트해야 한다(라이브러리 제약).
   - `ratio`를 key에서 빼는 이유: 나중에 드래그를 백엔드에 되쓰게 되면 드래그할 때마다 그 분할 아래 터미널이 전부 다시 마운트된다. (현재 코드 사실: 드래그 크기는 백엔드에 안 돌아간다 — Allotment에 변경 콜백이 없다.) 그러니 제자리 ratio 변경은 명령형 resize로 반영해야 한다.

## 거부한 대안

아래 대안의 기각 근거는 전부 실측이다. 리뷰어가 대안별로 프론트 사본을 만들어 같은 테스트 12건을 돌렸다(2026-09-23).

- **key 없음(HEAD)**: 방향이 뒤집힌 자리에서 칸이 접힌다. 결함 그 자체다. 테스트 12건 중 4건 실패.
- **`${dir}:${ratio}` key(1차 수정)**: ADR-0222 이후 실제로 만들어지는 분할은 전부 ratio 0.5라, 이 key는 사실상 `dir`만 가른다. 같은 방향의 분할이 올라오면 예전 드래그 크기가 남는다. 1차 적대 리뷰가 지적했고, "같은 방향·같은 비율·다른 분할" 테스트가 실패한다.
- **자식의 첫 슬롯 id로 만든 key**: 칸 하나를 닫으면 조상의 key가 바뀐다. 그러면 닫기와 무관한 형제 칸까지 다시 마운트되어 터미널이 재구독하고, ADR-0148이 보존하는 죽은 에이전트 화면이 사라진다. "첫 슬롯이 바뀌어도 형제의 슬롯은 그대로다" 테스트가 실패한다.
- **잎 집합으로 분할 정체를 추론(프론트 전용)**: 와이어 변경은 없지만, 정체를 규칙으로 추측하는 방식이라 새 연산이 들어올 때마다 규칙이 맞는지 다시 따져야 한다. 명시 id가 더 단순하다. 기각 근거는 설계 판단이고 실측은 없다(**약함**).

## 근거

- 재현: 백엔드 하네스에서 트리가 온전함을 확인했다. 실제 allotment + 가짜 ResizeObserver 테스트에서, 재사용된 인스턴스가 옛 방향의 `left/width`를 유지함을 확인했다.
- 적대 리뷰 2라운드(두 family). 1라운드는 `${dir}:${ratio}`의 퇴화를 적출했고, 2라운드는 코드 무결함 판정과 위 대안별 실측을 냈다.
- 데이터 경로 확인: 분할을 만드는 곳은 `split_in_tree` 하나다. `LayoutNode`를 입력에서 역직렬화하는 경로가 없다. 스냅샷은 트리 clone이라 같은 분할의 id가 emit마다 안정적이다(2라운드 리뷰 확인).

## 영향 / 불변식

- **분할을 새로 만드는 모든 경로는 새 id를 뽑는다.** 서브트리를 복제하는 경로(프리셋·탭 복제 등)가 생기면 복제본의 분할 id를 다시 뽑아야 한다. 그러지 않으면 복제본이 같은 id가 그려지던 자리에 들어올 때 key가 같아 옛 인스턴스(옛 드래그 크기)가 재사용된다. 규칙을 단순히 두기 위해 분할 id는 전역 고유로 유지한다.
- **형제 승격은 노드를 옮긴다(재생성 금지).** id를 지키는 이유는 승격된 노드 자신이 아니라, 그 자리에 남는 조상 분할과 무관한 형제의 key가 바뀌지 않게 하는 것이다.
- ★**승격된 서브트리는 다시 마운트된다**★ — 자손은 React 트리 깊이가 바뀌어서 어느 key 방식으로도, 승격된 노드 자신은 부모 자리의 인스턴스를 물려받되 key(id)가 달라서다(key가 없던 HEAD에서는 이 인스턴스가 재사용된 것이 결함이었다). 그 안의 터미널은 재구독하고, 드래그한 칸 크기는 ratio로 돌아가며, ADR-0148이 보존 중이던 죽은 에이전트 화면은 사라진다. 이 결정 전에도 같았던 알려진 한계다. 해법은 대화 상태를 슬롯 컴포넌트 밖으로 올리는 별건이다(렌더러 주석 「알려진 한계 ①」과 같은 뿌리).
- **`LayoutNode`를 입력으로 받는 경로가 생기면** `id` 누락을 처리해야 한다(지금은 없어 serde 기본값을 두지 않았다).
- 회귀망: `src/components/layout/ViewLayoutRenderer.allotment.test.tsx`(실제 allotment), `tree.rs`의 분할 id 테스트 셋.
