# ADR-0223: Give layout split nodes a fixed id, and let the screen tell split instances apart by that id

- 상태: 확정 (2026-09-23, basis: defect reproduction + measurement from two rounds of adversarial review — main decision (an internal implementation not visible on screen), reported to the user 2026-09-23) · 부분 폐기 by ADR-0227 (decision 2's Allotment key and the promotion-remount clause in the consequences)
- 관련: ADR-0035 (layout authority = src-tauri) · ADR-0063 (the split of decision 2 deals only with the initial sizing by ratio) · ADR-0148 (preserving the dead-agent screen) · ADR-0222 (boot default = single empty slot) · `src-tauri/src/layout/types.rs`(`LayoutNode::Split.id`) · `src-tauri/src/layout/tree.rs`(`split_in_tree`·`close_in_tree`) · `src/components/layout/ViewLayoutRenderer.tsx`(Allotment key) · Amended by ADR-0227 (decision 2's Allotment key and the promotion-remount clause in the consequences)

## 맥락

User report (2026-09-23): popping out the agent tree slot empties the whole main view. While closing or merging slots, the layout sometimes vanishes.

The cause was not the backend but the screen (reproduced — the backend tree and snapshot were intact).

- Closing and pop-out lift the sibling of the closed cell into the parent's place (`close_in_tree`).
- The renderer reuses the split component (allotment 1.20.5) by tree position.
- That library decides the horizontal/vertical direction only once at mount, and applies `preferredSize` only to newly attached cells.

So when a split of a different direction came into the same place, the cells collapsed to 0 and the screen went empty. When the direction was the same, the old cells' pixel sizes remained.

## 결정

1. **Put `id: Uuid` on `LayoutNode::Split`.** A new one is drawn at every split (`split_in_tree`). When a node moves to another place (sibling promotion), the node moves as a whole, so the id goes with it. It is carried in the TS binding (`LayoutNode.ts`) too.
2. **The renderer keys Allotment by `${id}:${dir}`.** When a different split comes into that place it mounts anew, and the same split with only its children changed keeps its instance and cell sizes.
   - Why `dir` stays in the key: if a path appears in which the direction changes in place, it still has to be remounted (a library constraint).
   - Why `ratio` is left out of the key: if dragging is later written back to the backend, every drag would remount all terminals under that split. (Current code fact: the drag size does not go back to the backend — Allotment has no change callback.) So an in-place ratio change has to be reflected through an imperative resize.

## 거부한 대안

The rejection basis of every alternative below is measurement. The reviewer made a frontend copy per alternative and ran the same 12 tests (2026-09-23).

- **No key (HEAD)**: the cells collapse at a place where the direction flipped. This is the defect itself. 4 of the 12 tests fail.
- **`${dir}:${ratio}` key (first fix)**: after ADR-0222 every split actually created has ratio 0.5, so this key effectively separates only `dir`. When a split of the same direction comes up, the old drag size remains. The first adversarial review pointed this out, and the test "same direction, same ratio, different split" fails.
- **A key made from the child's first slot id**: closing one cell changes the ancestor's key. Then even sibling cells unrelated to the close get remounted, terminals resubscribe, and the dead-agent screen that ADR-0148 preserves disappears. The test "even if the first slot changes, the sibling's slots stay as they are" fails.
- **Infer the split identity from the leaf set (frontend only)**: there is no wire change, but since it guesses identity by a rule, every time a new operation comes in the rule has to be checked again. An explicit id is simpler. The rejection basis is a design judgment with no measurement (**weak**).

## 근거

- Reproduction: in a backend harness we confirmed the tree is intact. In a test with a real allotment + a fake ResizeObserver, we confirmed that the reused instance keeps the old direction's `left/width`.
- Two rounds of adversarial review (two families). Round 1 pulled out the degeneration of `${dir}:${ratio}`, and round 2 produced the verdict that the code is flawless plus the per-alternative measurements above.
- Data path check: there is only one place that creates a split, `split_in_tree`. There is no path that deserializes `LayoutNode` from input. The snapshot is a tree clone, so the id of the same split is stable at each emit (confirmed by the round-2 review).

## 영향 / 불변식

- **Every path that newly creates a split draws a new id.** If a path that copies a subtree appears (presets, tab duplication, etc.), the copy's split ids have to be drawn again. If not, when the copy enters the place where the same id was being drawn, the key is the same and the old instance (the old drag size) is reused. To keep the rule simple, split ids are kept globally unique.
- **Sibling promotion moves the node (no re-creation).** The reason for keeping the id is not the promoted node itself, but so that the keys of the ancestor split that remains in that place and of the unrelated sibling do not change.
- ★**A promoted subtree is remounted**★ — for its descendants, because the React tree depth changes, whichever key scheme is used; for the promoted node itself, because it inherits the parent place's instance but the key (id) differs (in HEAD, which had no key, this instance being reused was the defect). The terminals inside resubscribe, the dragged cell sizes return to the ratio, and the dead-agent screen that ADR-0148 was preserving disappears. This is a known limit that was the same before this decision. The fix is a separate item of lifting the conversation state out of the slot component (the same root as 「알려진 한계 ①」 in the renderer comment).
- **If a path appears that receives `LayoutNode` as input**, a missing `id` has to be handled (there is none now, so no serde default was placed).
- Regression net: `src/components/layout/ViewLayoutRenderer.allotment.test.tsx` (real allotment), the three split-id tests in `tree.rs`.
