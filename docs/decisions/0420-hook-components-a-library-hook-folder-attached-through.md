## 맥락
S25 item 22 (user, 2026-11-23) adds a fifth library asset kind: a hook. User: 「없는것보다는 있는게 좋겠지? 유저가 하드코딩하기 딱 좋은게 훅인데」 · 「기존 인프라에 그대로 끼고 우리쪽은 거치고 클로드 코덱스쪽으로 에러를 넘기는거라서 많이 수정은 안한다고 생각되는데 어쨋든 쭉 진행하면 될듯」.

Before this decision a claude hook could already ride a settings preset's raw text (ADR-0328), while codex raw `-c hooks.*` lines passed through but were skipped silently: codex runs a non-managed hook only when it is trusted by its definition hash (measured). ADR-0216 had removed Engram's own codex hook machinery (the session-id hook), and ADR-0210's per-definition trust had failed before. The two CLIs load hooks differently — claude from settings or a plugin folder with no trust gate; codex from config layers behind a hash-keyed trust gate whose keys are positional — so one library component has to be translated per backend, while asset-library stays backend-blind (ADR-0367, ADR-0334) and Engram checks only what its own assembly breaks (ADR-0359).

What this changes in earlier ADRs: ADR-0216 (codex hooks come back, as user components and merged settings hooks, not as Engram's session-id hook); ADR-0328 and ADR-0316 decision 3 (the merged claude settings gain one layer per hook component); ADR-0353 (more fail-closed cases); ADR-0359 (agent regains `toml`, for codex parsing only); ADR-0341 decision 5 (one notice shown on every launch it occurs); ADR-0386 decision 4 (two more library kinds and a folder-row field).

## 결정
1. **Component and folder precedence (M1).** A hook is a library folder holding `hooks.json` (the marker and the definition, in the shape claude and codex share) plus its scripts, which run in place and are not copied. A `hooks.json` directly in a mount's top makes no hook. Precedence is a folder-level rule: a folder holding both `SKILL.md` and `hooks.json` is a skill, and adding or removing `SKILL.md` flips the kind. Code that treats a marker folder as one item treats `Skill | Hook` alike; ADR-0339's lone-marker mechanism stays skill-only (see 영향).
2. **Section and omission rule (M5).** Presets gain a `hooks:` section after `skills:`, with backend tags; plan order is preset expansion order and a hook reached twice is carried once, at its first position. `preset.save` / `preset.check` take an optional `hooks`: omitted = the file's hooks stay (save) and are judged as they are (check). A missing hook is skipped with a notice (ADR-0374); an unreadable one, or one that fails the shape check, blocks.
3. **Placeholder and path rule (M2).** `${CLAUDE_PLUGIN_ROOT}` and the unbraced `$CLAUDE_PLUGIN_ROOT` in every string value are replaced with the hook folder's absolute path in forward-slash form, for both backends. When the placeholder is used, a hook folder path with a backtick anywhere, or a `$` that is not the last character of a path component (off Windows also `"`, `\` or a control character), is refused (`hook-path-unsafe`). The rule lives in the rewrite function itself — it refuses to rewrite an unsafe path — and asset-library calls the same rule at check. A placeholder written in single quotes or unquoted is the author's risk. `CLAUDE_PLUGIN_DATA` is not supported.
4. **claude route (M3, O2).** Each hook component becomes one more layer of the one merged `--settings` file, after the raw settings in attach order, with the ADR-0328 merge: a settings preset's own `hooks` groups first in each event, the components' after, identical groups once. Both claude modes load hooks.
5. **codex assembly (M4, T3, T4).** One function in `backend/codex` assembles every hook output; the check (`command_line_fits`) and `materialize` both call it, so what the check counted is what goes on the line.
   - **One seam with origins** — it takes the raw `-c` lines with their origins (settings asset, line), the pass-through arguments, the plan's hooks and the mode; every notice and refusal names the hook or the settings asset and line it came from.
   - **Only what codex reads** — codex's 14 events, a group's `matcher` and `hooks`, and the typed handler fields codex normalizes; nothing else is written. Terminal: one line per event after the non-hook lines, then one `hooks.state` line. JSON: one `hooks` object in the thread config on `thread/start` and `thread/resume` (absent when nothing is written, never an empty object).
   - **Raw folding, codex last-wins first** — among all settings hooks lines (attach order, then file order) codex's own rule applies first (the last write to a path wins; a `hooks` table line replaces the whole table); the effective result then merges with the components per event, raw groups first (U4).
   - **State carry with trimmed keys** — trust entries are generated only for the session-flags keys Engram assembled; other-source entries of the effective raw result are carried verbatim; keys are trimmed before classifying, and a raw entry equal to a session-flags key after trimming is dropped with a warning.
   - **Left-off and index rule** — a handler Engram cannot trust (another event, `prompt`, `agent`, `mcp_tool` by scope cut, an unnormalizable field) or a group with a non-string `matcher` is left off with `codex-hooks-left-off`; indexes are positions in the arrays Engram writes, so they match what codex assigns.
   - **Raw hooks lines always consumed** — every raw settings hooks line is folded, carried or left off with a notice and never re-emitted raw, whether or not anything is written. Whether Engram writes hook output is decided on the written result.
6. **Per-run trust (U1, U2, T8).** Engram trusts exactly the hooks it assembles (components and folded settings groups): it computes codex's hash itself and writes each trust entry in the session-flags layer of that run, with `enabled = true` in every entry. Nothing is persisted: `~/.codex/config.toml` is never written; no bypass flag; no review prompt.
7. **Post-open check and run notice (T5).** In JSON mode, after the thread opens and before the link reports ready, the transport asks `hooks/list {threadId}`; any expected key not listed trusted and enabled, or a foreign trusted session-flags hook, raises `codex-hooks-untrusted` as a run notice. A failed `hooks/list` never fails the handshake. Terminal mode has no run-time check (drift shows in the lane).
8. **Shape check as Engram's own format (T7).** At scan asset-library reads `hooks.json` as UTF-8 JSON and checks only the shape it assembles from (a `hooks` object, arrays of groups, each group's `hooks` an array of objects): `hook-shape-invalid`. Event names, matchers, handler fields and script existence are each CLI's rule (ADR-0359).
9. **Terminal budget refusal text (M7, user 2026-11-24).** No proactive warning. Over the codex terminal line budget with hook lines on it, the existing fail-closed refusal reads 「codex terminal command line limit exceeded — reduce hooks or use JSON mode」; one help line names the terminal-mode limit; no preset-editor warning.
10. **codex settings hooks lines are merged (U4).** A codex settings asset's raw hooks lines join the combined list (decision 5) and are trusted like components; the launch notice `codex-raw-hooks-trusted` names each such asset with a digest of its folded groups, so a grown set is named again. No collision refusal.
11. **Pass-through hooks lines are refused with guidance (U5).** When a codex launch has a hook component attached for codex or a settings asset with a hooks line, a pass-through `-c` / `--config` argument (any spelling clap reads, nothing after `--`) whose trimmed key's first segment is `hooks` refuses the launch: `codex-passthrough-hooks`, 「move this hooks line into a hook component or a codex settings asset」. The trigger is on the inputs, not the written result. With neither input, pass-through hooks lines pass as today. This applies ADR-0216 decision 1 (no silent overriding) to hooks: Engram's lines would replace them, an event Engram does not write would stay untrusted, and the JSON thread config wipes them all.
12. **Accepted consequence (F4).** The hash is recomputed from the current `hooks.json` at every launch, so any edit to a hook — a teammate on a shared mount, a sync, an LLM writing files or calling `preset.save` — is trusted at the next launch without review. Trusted = attached by anyone with library and command access, agents included; content changes are not re-reviewed (as with claude, which has no hook trust at all).
13. **Engram's own session-id hook is not revived (U3)** — 「ㅇㅇ 그대로가」; nothing is added to the built-in preset.
14. **The lone-marker rule covers `hooks.json` (main, TRD O4 — ADR-0339 lineage)** — renaming `hooks.json` or moving it out of a referenced hook folder asks for confirmation like a lone `SKILL.md`, with its own code `hook-unconfirmed`; without it the hook would vanish and its references would only be skipped with a notice (ADR-0374).

## 거부한 대안
- **codex's bypass flag (`--dangerously-bypass-hook-trust` / `bypass_hook_trust`)** — it also trusts every other unreviewed hook and prints a warning on every run (measured: `codex exec` printed the warning; source: the TUI startup warning). Evidence: 실측. 사용자 직접 기각 (U1).
- **Persisting trust in `~/.codex/config.toml` (through `config/value/write` / `config/batchWrite`, or codex's own 「Trust all」)** — trust keys are positional (`<source>:<event>:<group>:<handler>`, measured), so a persisted entry is overwritten by the next agent's combination, and it leaves state behind in the user's file. User: 「-c 가 그럼 더 좋다는거아냐? 유동적이고」. Evidence: 실측 (key format). 사용자 직접 기각 (U2).
- **Asking the user per hook (a review prompt)** — attaching a hook to a preset already is the approval; user: 「우리건데?」. Evidence: 약함 (judgement; measure-4 M-C only shows codex's own picker writes the real `~/.codex/config.toml`). 사용자 직접 기각 (U1).
- **claude route through `hooks/hooks.json` in the `--plugin-dir` folder** — measured working, but Engram's `--plugin-dir` is the volatile `engram` folder of junctions (ADR-0316 decision 2), so `CLAUDE_PLUGIN_ROOT` would name that folder rather than the hook folder, and it would be a second mechanism beside the merged `--settings`. Evidence: 실측 + 코드 (measured: `CLAUDE_PLUGIN_ROOT` = the folder passed; a bad handler drops only itself in both routes, so neither route is safer).
- **Refusing settings/component hook collisions with guidance (U4 (a), main's recommendation), or ours-win with a notice (U4 (c))** — user: 「합치기가 맞고」 (chose merge, diverging from the recommendation). Evidence: 약함. 사용자 직접 기각.
- **Folding every pass-through spelling into one override sequence with the settings lines (O6, U5 (B))** — one more input class to the seam and its tests, for users who keep hooks in profile arguments. User: 「A로 해서 코딩 들어가.」 (chose refuse). Evidence: 약함. 사용자 직접 기각.
- **Reviving Engram's own codex session-id hook in the built-in preset** — user: 「ㅇㅇ 그대로가」; ADR-0216's status-line channel stays. Evidence: 약함. 사용자 직접 기각 (U3).
- **A per-codex-version hash probe (L17, T9)** — would catch a terminal-mode hash drift at ≈ 350 ms once per codex binary, but needs a codex-binary identity, a process spawn on the check path and a cache that follows codex's self-update; the codex lane re-runs on every installed codex version change and JSON mode has the run-time check. Evidence: 정량 (≈ 350 ms) + 코드 (the lanes rule).
- **Per-backend definition files in one hook folder (M1)** — the TRD records the rejection without a reason; one `hooks.json` in the shape both CLIs share, with backend tags for a hook that uses one backend's fields (R4), covers it. Evidence: 약함 (not put to the user).

## 영향 / 불변식
- **Own wording for the hook notice codes** — the interim omission codes `claude-hooks-omitted` / `codex-hooks-omitted` (until each backend loads hooks) and the hook notice codes the TRD lists take facts-only wording of their own, joining the ADR-0357 / ADR-0364 list of codes that do not use the generic text.
- **asset-library stays backend-blind** — it sees hooks only as neutral `HookRef`s, neutral agent functions and port answers; every claude/codex hook rule lives in `backend/claude` / `backend/codex` (the ADR-0367 gate re-runs in every unit touching asset-library).
- **One counting seam** — the check and `materialize` call the same codex hook assembly; a second path that builds hook lines would let the check count differ from the line. JSON counts no hook lines.
- **`~/.codex/config.toml` and `~/.claude` are never written** (QA compares the file byte for byte). Every hook on the codex terminal line has its trust entry on the same line, or codex's TUI picker would write the user's file.
- **Fail closed (amends ADR-0353)** — `materialize` refuses before any write on `codex-hook-line-refused`, the budget with hook lines (M7 text), `codex-hooks-unreadable` and `codex-passthrough-hooks`.
- **ADR-0328 / ADR-0316 decision 3** — the merged claude settings now take raw settings then one `hooks` layer per component; `settings_file` is written when there are raw settings or hooks.
- **ADR-0359** — agent regains `toml` (parse only, codex backend only); still no schema check of events, matchers or handler fields.
- **ADR-0341 decision 5** — `codex-hooks-untrusted` is a run notice: shown on every launch it occurs, outside the notice fingerprint; boot restore only logs it (O7 held).
- **ADR-0386 decision 4** — `LibraryKind` gains `Hook` / `HookFile`; `library.list --kinds` matches a hook folder's `hooks.json` row only by `HookFile`; `LibraryFolderRow` (the `library.folders` row) gains `hook`.
- **ADR-0216** — its status-line channel and 「do not revive the session-id hook」 stand; the no-hook tests now read 「a spawn with no hook output written carries no hook」, and a new test asserts a component's line carries only the user's command.
- **Dependencies** — agent gains `sha2` and `toml`, both already locked in the workspace (no new package).
- **Risks accepted** — per-run trust relies on source-honoured, undocumented codex behaviour (R2: JSON run notice, terminal lane and a help line); raw codex hooks lines that were inert start running (R11, named by `codex-raw-hooks-trusted`); a pass-through `--disable hooks` turns off every hook, Engram's included (R13).
- **Not decided here** — boot-restore verdict surfacing (O7), detecting codex's hook review screen in the terminal pump (O8).
