# ADR-0028: The backend owns the event bus — a single push channel (backend → tray/WebView/LLM)

- 상태: 확정 (2026-06-21, dashboard10 session — user decision. The concept was generalized from the tray stuck-gray bug)
- 관련: ADR-0003 (OutputSink/StatusSink core isolation — this ADR generalizes and extends it) · ADR-0024 C2 (WS/lockfile liveness) · ADR-0026 (tray merge) · CLAUDE.md §5 (LLM-first control, hands/brain separation) · `docs/process/step-log.md` dashboard10
- Scope: where and how backend (Rust) state changes flow to reach the tray, WebView, and (future) LLM. It replaces the approach of "attaching an observer/probe separately per feature" with a single event bus.

## 맥락
A bug appeared in daemon mode where the tray icon got stuck gray (the daemon was actually alive, but the tray stayed the gray it painted from one probe at boot). Digging into the cause, it was a structural problem: **the tray (Rust) cannot see daemon life and death directly and has no choice but to probe daemon.json/PID.** This is because in daemon mode the WS connection (the real liveness signal) is held by the frontend (WebView JS), which Rust cannot see.

Trying to fix this, we proposed "the frontend pushes state up to the tray" — but the direction was backwards. **Rust is the upper layer (it owns the process, tray, and lifecycle), and events must flow down from backend to frontend** (§5: backend = brain, frontend = hands and feet, and death detection is also a backend decision). Bespoke per-feature observers and consumer-side probes were all workarounds that arose "because there is no single push channel."

The code already has a **seed** of this channel: `StatusSink` (core trait, the publish side) → `TauriStatusSink` (`app.emit`) → the frontend `eventBus.ts` (`agentClient` subscription). `agent-list-updated`/`status-changed`/`restore-result` come down from Rust to the WebView by this path. We raise this to a formal concept.

## 결정
**The backend (Rust) owns the event bus. It is the single push channel for backend state changes.**

- **The publish side = the backend.** Every backend state change (agent list · status · restore result · **daemon life and death** · future backend logic) is published to this bus as an event. No separate observer/wiring is built per feature — a new signal is the work of adding one bus event.
- **Subscribers = several.** ① the WebView (Tauri `emit` → the frontend `eventBus`) ② the tray (an internal Rust subscription, native `set_icon`) ③ (future) the LLM/control surface. Several subscribe to the same bus.
- **Direction invariant (load-bearing): backend → downward only.** State push is always Rust→{tray, WebView, LLM}. **The frontend does not push state up (to the tray/Rust).** (Frontend→backend is a *command/intent* (command/invoke), not a *state push* — a different layer.)
- **Daemon life and death = the first new event on this bus.** A life-and-death observer owned by Rust publishes the change to the bus → the tray (icon) and the WebView (event) subscribe and reflect it. *How* the observer learns of the change is an impl detail behind the bus: **pre-flip = Rust periodic probe (daemon.json/PID, owned by Rust), post-flip = connect/disconnect events of the connection Rust holds (ADR-0024 C2)**. Both have the same shape "owned by Rust → pushed downward" → at the flip only the observer internals change and the bus and subscribers stay as is (no rebuild).

### Core isolation preserved (an extension of ADR-0003, not a discard)
The bus's publish surface stays as the core's sink trait (currently `StatusSink`) — the core knows nothing of Tauri/transport. Tauri `emit` and the tray are **edge (src-tauri) subscribers/adapters**. That is, 0028 only generalizes ADR-0003 to "the sink = the publish side of the bus, fanned out to multiple subscribers at the edge," and core isolation (core tauri imports 0) stays as is.

## 거부한 대안
- **The frontend pushes state up (frontend → tray/Rust)** — violates §5 (backend = brain, death decision in the backend). It *entrenches* the structure that created the stuck-gray in the first place (the frontend holds the connection so Rust cannot see). Also, "when moving backend logic down to the frontend later" the path is backwards and does not fit. Discarded.
- **Bespoke per-feature observers + dedicated wiring** — every new backend→frontend signal needs a new observer, event, and subscription. They do not compose, and the tray/frontend receive the same signal separately, causing duplication and drift. Absorbed into a single bus.
- **Consumer-side pull/probe (the tray probes daemon.json, the frontend polls)** — no single source, stale, a timing bug (the direct cause of the stuck gray). This is the workaround this ADR removes.
- **Put periodic polling in the frontend** — the polling location is the hands and feet (the frontend), so it is backwards. The observer is owned by Rust (the brain). (Polling itself is only an implementation means of the pre-flip observer — hidden behind the bus and replaced by connection events at the flip.)

## 근거
- It makes explicit the direction that §5 (hands/brain separation), ADR-0003 (sink isolation), and ADR-0024 C2 (WS liveness) were already pointing to. The stuck-gray bug exposed the common root "no single push channel" (pointed out by the user).
- The existing `StatusSink`+`eventBus` is a working seed, so the effort is small — add daemon life and death as an event of the same pattern + attach the tray as a new subscriber.

## 영향 / 불변식
- **The tray icon color is updated only by the bus's daemon-liveness event** (remove the dependence on one boot probe). The Rust observer is the push source.
- **A new backend→frontend signal is added as a bus event** (no dedicated wiring). "Moving backend logic down to the frontend" = publish to the bus.
- The frontend only **subscribes** to the bus (no pushing state up). Frontend→backend is limited to command/invoke (intent).
- Keep core tauri imports at 0 (the bus publish surface = the core sink trait, fan-out is at the edge).
- Pre-flip observer = Rust periodic probe (impl behind the bus), post-flip = connection events. The bus and subscriber contract is unchanged (no rebuild at the flip).
