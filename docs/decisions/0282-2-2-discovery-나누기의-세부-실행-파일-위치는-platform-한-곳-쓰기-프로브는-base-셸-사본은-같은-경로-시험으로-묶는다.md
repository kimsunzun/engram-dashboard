# ADR-0282: Details of the 2-2 discovery split — the executable location lives in one place in platform, the write probe in base, and the shell copy is bound by a same-path test

- 상태: 확정 (2026-10-07, basis: main's decision under the user's delegation 2026-10-07 · 2-2 landing 2026-10-07 (U1 `a0ec7f4` · U2 `3c9bf33` · U3 `b42e139` · U4 `d2f9822`) · canonical design = `docs/process/S21-crate-boundaries/trd-2-2-discovery-split.md` §7) · 부분 폐기 by ADR-0285 (the CLI temporary-edge item of the impact)
- 관련: ADR-0269(the move-in condition of decision 7 — decision 2 below) · Amends ADR-0271 (the place that computes the executable location in decision 2) · ADR-0273(engram CLI → daemon lib temporary edge — 「영향」 below) · Amended by ADR-0285 (the CLI temporary-edge item of the impact)

## 맥락

ADR-0271 split the discovery crate so that the daemon's part goes to the daemon and the shell's part to the shell (decisions 1 ~ 4 · start = work order 2-2 · decision 7), and it left four internal placements as 「열린 것」 — the place of `logs\` · the shape of the executable location 「두 곳 → 한 곳」 · the write-check helpers (`retry_if_vanished` · `probe_write_in`) · the place of `send_stop` between 2-2 and 3-2. The same ADR put the `Gate: discovery has no async-runtime ingress` of `ci.yml` among the gates that disappear, because 「대상 crate 가 사라진다」.

Where the current-state measurement of TRD 2-2 (`6fa966a`) differs from that picture:

- **The executable location computation was in three places, not two** — the daemon's `locate_send_exe` · the first candidate of discovery's `locate_daemon_exe` · the `sibling_send_exe` in the daemon's `src/bin/roundtrip_smoke.rs` (which attached `.exe` by hand with `cfg!(windows)`). ADR-0271 decision 2 sent that computation to the daemon, but the shell cannot depend on the daemon crate (ADR-0271 invariant · the second of 「거부한 대안」) — if it is gathered in the daemon, the shell's daemon lookup cannot call it.
- **After the split the write-probe helper is used in two places, the daemon and the shell** — that is the move-in condition ADR-0269 「입주시키지 않는 것」 wrote for itself. The static counter of the probe name (`probe_path`) has to be one, because the shell race test mixes the daemon version and the shell version in one process.
- **There is still something to guard for the two properties that the async-ingress gate guarded as a bonus** — agent is a synchronous crate without tokio while carrying platform as a production dependency (the platform header holds this gate as the wall against an async runtime), and net `Cargo.toml` wrote that it is this gate that actually catches a quiet ingress through the default feature.
- **Two real-WMI `#[ignore]` tests of discovery looked for the daemon exe as a production candidate and failed with `ExeNotFound` at the crate folder cwd** (memo §11). Once moved to the shell, the cwd is `src-tauri`, so the third candidate points at the repository `target\debug` and it resolves by accident (code reading).

## 결정
(main's decisions under the user's delegation 2026-10-07 · the timing of the crate deletion (2-2 U4) and the completion measurement are written in 「근거」 · 「영향」 below)

1. **The executable location computation is in one place, platform `env::sibling_exe`** — this fixes the place where ADR-0271 decision 2 had put it 「데몬으로」. The daemon's CLI lookup · the shell's daemon lookup · `roundtrip_smoke` all call it (the daemon and the shell cannot share each other's code, and both reach platform).
2. **The write-probe helper is base `writable` — the move-in is pulled forward to 2-2 U1.** The 「사본 둘」 condition of ADR-0269 decision 7 is met in U2 · U3 within the same step. The reasons for pulling it forward = no temporary copy is made · the daemon version and the shell version have to share the probe-name counter (the static of `probe_path`) in one process so that the names do not collide. Zero domain knowledge was kept through the signature — the base version of `retry_if_vanished` returns an `io::Result`, and the two callers fold it into their own error with `map_err` (the daemon's `DataDirUnwritable` · the shell's `DiscoveryError::DataDirUnwritable`) (the decision table — `Ok` · retry once after `NotFound` · other errors — stays as is · TRD §2-3 ①). With the move, the tracing target of that cleanup warning changes from `engram_dashboard_discovery` → `engram_dashboard_base::writable` (text · level unchanged · zero `RUST_LOG` directives in the repository that use that target).
3. **A same-path test binds the shell copy to the daemon canonical version** — the shell does not depend on the daemon crate in production (ADR-0271), so the shell keeps copies of the root lookup · the `daemon.json` place · `logs\`, and runs that test through a shell → (dev) daemon edge. What it measures = the root (three states of the environment variable: unset · empty · path — the variable name is a literal) · `release_data_dir` · `daemon_file` · `logs_dir`. What it cannot measure = the body of the release branch of the root rule (the test is always debug — the one-time release measurement covers it) · a shell copy that misses one walk-up marker (`.git` · `[workspace]`) (this repository root has both — the marker test lives only in the daemon). On the day the shell → (dev) daemon edge is removed or narrowed (after work order 2-4), the place of this test and of the race test is decided again.
4. **One environment lock per crate** — tests that change or read `ENGRAM_DATA_DIR` sit under one lock in the daemon's `data_dir` and one lock in the shell's `discovery` (the two real-WMI `#[ignore]` tests also hold the shell lock). Those two real-WMI tests look for the daemon exe at the test exe location (the candidates of production `locate_daemon_exe` stay as they are).
5. **The 2-2 ~ 3-2 place of `send_stop` = the shell's `daemon_client/stop.rs`, letter for letter** — 3-2 (transport attached to the shell) rewrites it (ADR-0271 decision 5). So the discovery internals opened as `pub(crate)` (`check_acceptable` · `AcceptCheck` · `FileReader` and its `path` · `RealLiveness`) are used outside discovery only by stop.rs. A direct `tungstenite` line enters the shell, but the same version is already in the lock, so zero new packages. The log target of the moved discovery · stop code changes from `engram_dashboard_discovery` → `engram_dashboard_lib::discovery` · `engram_dashboard_lib::daemon_client::stop` (text · level unchanged · zero directives that use that target).
6. **discovery's async-ingress gate is not deleted but replaced with platform gate ⑦** — targets = agent (`-e normal` · the synchronous consumer — covers base · command · platform together) zero lines · net default feature zero lines (the property of net `default = []`) · pair = net `--features server` at least one line (in the ADR-0278 form — if the pattern breaks, the pair goes red). The reason the delete-only proposal was dropped = there is still something to guard on the axis of platform's async prohibition that the gate guarded as a bonus (the synchronous consumer agent remains) and on the net default feature. protocol drops out of that coverage — after 2-2 its consumers (the daemon · the shell · net `server`) are all async. Canonical source = that step in `ci.yml` · gate ⑦ in the header of platform `src/lib.rs`. ★This decision amends two sentences of ADR-0271★ — the 「나눈 뒤 지킬 대상이 없다」 in the first item of 「거부한 대안」 and the 「사라지는 게이트 — `Gate: discovery has no async-runtime ingress`」 in 「영향」 (the partial-discard stamp on that ADR's status line records only the share of decision 2 — the clerk script has no way to add a clause between the same two ADRs).

## 거부한 대안

- **Put the 「한 곳」 of the executable location in the daemon (the letter of ADR-0271 decision 2 — decision 1).** Rejected = the shell does not depend on the daemon crate in production (ADR-0271 invariant), so the shell's daemon lookup cannot call it and it would not be one place. What both the daemon and the shell reach is below, in platform, and `exe_file_name` already lives there (TRD D2 — ADR-0271 「열린 것」 had already pointed to 「현재 exe 옆 규칙 · `.exe` 붙이기는 platform 몫」).
- **Have the daemon and the shell each keep a copy of the write-probe helper, or move it to base after two copies exist (U2 · U3) (decision 2).** Rejected = ADR-0269 decision 7 (base if it is now used in several places) · no intermediate state is created where there are briefly two copies · if each copy has its own static counter, then when the shell race test mixes two versions in one process, probe names with the same pid and same number collide (`create_new` hits `AlreadyExists`, deletes another's probe and recreates it — the seed of a false failure) (TRD §2-3).
- **A shape that takes the probe file prefix as an argument (decision 2).** Not chosen — the prefix `.engram-write-probe-` is a product name, not agent runtime · wire · daemon lifecycle knowledge (it was seen as the same class as the log file name convention of base `logging`, and moved to a base constant with the value as is). The two callers would only pass the same value (TRD §2-3 ② · §8 O4).
- **The shell's `daemon.json` copy borrows net `portfile::DAEMON_FILE` (decision 3).** Rejected = net leaves the shell in 3-3 (TRD §2-4).
- **Move discovery's root test to the daemon together with its lock — two locks (decision 4).** Rejected = in one test binary, two locks trample the same `ENGRAM_DATA_DIR`. The `ENV_LOCK` in the daemon's `lib.rs` was deleted and gathered into the one lock of the `data_dir` test module (TRD §2-4 — main's decision reflecting the review).
- **Fix the candidates of production `locate_daemon_exe` so that the real-WMI tests resolve · rely on the accident that the shell cwd resolves it · use `sibling_exe` (decision 4).** Rejected = production behavior is not changed for test convenience (TRD D6) · that accident is a code reading that relies on cargo running tests at the package root (TRD §1-7 · §9) · the test exe is in `deps\`, so `sibling_exe` does not match (TRD §2-5).
- **Only delete the async-ingress gate (the 「사라지는 게이트」 of ADR-0271 「영향」 — decision 6).** Rejected = the reason of decision 6 (there is still something to guard on the synchronous consumer agent and on the net default feature axis). The two proposals of TRD draft 1 — (a) only fix the text that points to it · (b) move a zero-line gate of the same form to the platform target (draft 1 proposal = (b) for platform · (a) for net) — were also widened in draft 2: a platform-only target cannot see agent bringing in async by another path (one agent covers base · command · platform together), and net is measured directly with the default feature, not only in text (it continues the axis the old step comment wrote). Without the pair, when the pattern breaks the two zero-expected lines pass blind (TRD §8 O1 — main's decision reflecting the review).
- **Set up a separate CI step for the shell's `tests/stop_smoke.rs` (decision 5).** Rejected = all three tests are in the `#[ignore]` · `#![cfg(windows)]` · real-daemon-exe lane, so there is nothing to run in the default CI execution, and the CI workspace regression already covers the compile (TRD §3-4 5 — main's decision). Running is the local real lane.
- **For the temporary place of `send_stop` and the timing of the crate deletion (2-2), there is no other proposal that the TRD weighed** — only the rewrite now was deferred to 3-2 (ADR-0271 decision 5 · the TRD's 「지금 하지 않는 것」).

## 영향 / 불변식

- **The rule 「현재 exe 폴더 + OS 확장자」 exists only in platform `env::sibling_exe`** — it does not check existence (what is done after the existence decision differs by caller — TRD §2-2). A new 「exe 옆 실행 파일」 computation calls this. `find_install_root` (a different rule that walks up from the exe) stays as is in the daemon's `data_dir`.
- **The write probe is the single base `writable`** — seven base residents · `writable` (six copies) in the name list of base gate ③. If the prefix value is changed, the consumer tests' counting of leftovers goes blind (TRD §3-2 risk). The `retry_if_vanished` · `probe_write_in` item of ADR-0269 「입주시키지 않는 것」 is the fulfillment of that condition, not an amendment.
- **Canonical root rule = the daemon's `crates/engram-dashboard-daemon/src/data_dir.rs`** · shell copy = `src-tauri/src/discovery/layout.rs` — the same-path test binds the two (anchor `// ADR-0271`). That test relies on the shell → (dev) daemon edge (decision 3).
- **`send_stop` = `src-tauri/src/daemon_client/stop.rs` (until 3-2)** — if other shell modules start using the discovery internals opened as `pub(crate)`, the rewrite in 3-2 widens (TRD §3-4 risk). 3-2 also removes the shell's direct `tungstenite` line.
- **platform `test-support` in the shell dev dependency** — if the lib and the test targets are built in one cargo call as with `--all-targets`, it can be merged into the shell production binary. The platform test-feature gate cannot see that shape and it is blocked only by a manifest warning (TRD §2-1 · §3-4 risk).
- **The wall against async ingress = `platform gate 7` in `ci.yml`** (the qa binding 「CI와의 분담」 · gate ⑦ in the header of platform `src/lib.rs` · net `Cargo.toml` point to it). protocol is outside that coverage (decision 6).
- **The discovery crate was deleted in 2-2 U4 (`d2f9822`)** (TRD D1 · workspace members 10). The discovery entry leaves the CLAUDE.md 「백엔드 모듈 맵」 and the daemon entry carries `data_dir`.
- **This amends ADR-0271** — the executable-location place of decision 2 (the partial-discard stamp on that ADR's status line) · the two sentences that decision 6 writes (in the body only — the stamp is not reflected, awaiting the user's decision).
- **If an old record points to the discovery crate, read it this way** (old ADR bodies are not edited · how to find them = `git grep -n "engram-dashboard-discovery\|engram_dashboard_discovery" docs/decisions`):
  - `crates/engram-dashboard-discovery/src/lib.rs` → if it is daemon lookup · start · status · stop fallback · pre-start precheck, the shell's `src-tauri/src/discovery/mod.rs`; if it is the root rule · the write check that creates the folder · the install location, the daemon's `crates/engram-dashboard-daemon/src/data_dir.rs` (the shell's root copy is `src-tauri/src/discovery/layout.rs`).
  - the `send_stop` bundle → `src-tauri/src/daemon_client/stop.rs` · the write-probe helper → base `writable` · the raw call of the WMI start already went to platform `spawn` in 1-3.
  - `crates/engram-dashboard-discovery/src/layout.rs` (`DataLayout`) → the daemon's part is the daemon's `data_dir.rs` · the shell's part (and the `daemon.json` · `logs\` copies) is the shell's `src-tauri/src/discovery/layout.rs`.
  - `crates/engram-dashboard-discovery/tests/stop_smoke.rs` → `src-tauri/tests/stop_smoke.rs`.
  - Examples (not exhaustive): `check_acceptable` (ADR-0196 · the discovery 「버전 불일치 시 데몬 거부」 path item in the 「영향」 of ADR-0178) → the shell's `src-tauri/src/discovery/mod.rs` · the `stop_smoke.rs` pointer in ADR-0230 → `src-tauri/tests/stop_smoke.rs` · the CLI edge below.
- **engram CLI → daemon lib temporary edge (U2 ~ 2-3)** — the bin `engram.rs` calls `engram_dashboard_daemon::data_dir::find_install_root`. The 「데몬 lib 를 한 줄도 쓰지 않는다」 in ADR-0273 「맥락」 is false from U2 (`3c9bf33`) until 2-3. 2-3 replaces this edge with a CLI-side copy (ADR-0273 decision 5) — the anchor `// ADR-0273` is on that call line.
