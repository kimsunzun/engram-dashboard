# ADR-0263: 도구 묶음은 도는 동안에도 접고 대기 표시는 입력창 위 고정 줄에 둔다

- 상태: 확정 (2026-10-01, 근거: 사용자 지시 2026-10-01 「클로드 코드 관행 따르면 될것같은데」(결정 1) + 사용자 결정 2026-10-01 「마지막꺼 보여줬다가 접는게 맞아보이는데」(결정 1 — 도는 동안 마지막 호출 한 줄) + 사용자 결정 2026-10-01(결정 2 — 메인이 올린 두 안 중 선택) + 피어 `docs/research/chat-ux-four-features-2026-09-27.md:115` · `:117`)
- 관련: Amends ADR-0239 (결정 4의 도는 동안 마지막 묶음 자동 펼침) · Amends ADR-0244 (구현 세부 b의 채팅 꼬리 Wait 행 자리) · TRD `docs/process/S21-chat-ux/trd.md`(§2-4 · §4-3 · §4-4 · QA F3 ①) · 조사 `docs/research/chat-ux-four-features-2026-09-27.md` · `src/components/slot/chat/WaitRow.tsx` · `src/components/slot/chat/ToolGroupRow.tsx` · `src/components/slot/StructuredTextView.tsx` · `src/components/slot/RichSlot.tsx` · step-log S21

## 맥락
사용자가 챗 화면 브랜치(`v0.3.3/feat/chat-ux`)를 마지막으로 시험하다(2026-10-01) 두 문제를 찾았다.

1. **도구 묶음이 끝에 가서야 접힌다** — 도는 동안에는 호출이 하나하나 따로 보이다가, 다 끝나야 한 묶음으로 접혔다. 도는 마지막 묶음을 자동으로 펼쳤기 때문이다(ADR-0239 결정 4 · TRD §4-3 · §4-4 — 사용자 결정이 아니라 TRD 가 고른 것). 끝나면 그 펼침이 툭 닫혔다.
2. **대기 표시가 나타나고 사라질 때 대화가 들썩인다** — 대기 표시는 스크롤 목록 끝의 흐름 속 행이었고, 스트리밍에 따라 마운트·언마운트됐다. 그래서 켜지고 꺼질 때마다 대화 내용이 위아래로 튀었다.

## 결정
1. **도구 묶음은 도는 동안에도 통째로 펼치지 않는다** [사용자 지시 — 「클로드 코드 관행 따르면 될것같은데」]. 요약의 개수가 그 자리에서 늘어난다. 도는 동안에는 요약 뒤에 「진행 중…」 표시가 붙고, 끝나면 그 표시가 빠진다(지난 것 = 표시 없음). 묶음은 여전히 연속된 도구 ≥2 에서 선다(무변경).
   - **도는 동안에는 머리 밑에 지금 도는 호출(마지막 호출) 한 줄만 보인다. 호출이 늘면 그 줄이 새 마지막 호출로 바뀌고, 끝나면 그 줄도 접혀 머리만 남는다** [사용자 결정 2026-10-01 — 「마지막꺼 보여줬다가 접는게 맞아보이는데」].
   - 사람·LLM 의 토글은 그대로 양방향으로 이긴다 — 펼치면 모든 멤버, 접으면 도는 중에도 머리만이다.
2. **대기 표시는 대화 스크롤 목록 밖, 입력창 바로 위의 자기 줄에 선다** [사용자 결정 — 두 안 중 선택]. 그 줄은 대화 레이아웃에 늘 마운트돼 있고 늘 제 높이를 차지한다 — 켜고 끄는 것은 안의 내용뿐이다. 높이는 값 하나, CSS 변수 `--chat-wait-strip-h`(1.75rem)이고, 챗 스타일 스토어에 `waitStripH` 로 등록해 기존 조정 경로가 닿게 한다. 사용자는 나중에 2–3 줄이 될 수 있다고 적었다.

## 거부한 대안
- **A — 도는 마지막 묶음을 계속 자동으로 펼친다(이전 동작)** — 보고된 결함 그 자체다(따로 보이다 끝에 접힘). 사용자가 따르라고 한 Claude Code 관행과도 어긋난다.
- **B — 대기 표시를 목록 끝에 두되 그 자리를 늘 비워 둔다(visibility 토글)** — 사용자에게 올렸고 고르지 않았다. 한가할 때 마지막 메시지 밑에 약 40px 빈칸이 남는다.
- **C — 도는 동안에도 머리만 보인다(결정 1 의 첫 구현, 같은 날)** — 사용자가 시험한 뒤 바꿨다(「마지막꺼 보여줬다가 접는게 맞아보이는데」).

## 근거
- **사용자 지시 · 결정(2026-10-01)** — 결정 1 은 지시 원문, 결정 2 는 두 안 중 선택.
- **피어** — Claude Code CLI 는 읽기·검색 묶음을 도는 동안에도 접어 두고(현재형) 끝나면 과거형으로 바꾸며, 펼침은 Ctrl+O 다(`docs/research/chat-ux-four-features-2026-09-27.md:115`). 도는 호출을 보이게 두는 가장 가까운 선례는 cline 이다 — 「가벼운」 도구만 묶고 도는 중인 것은 묶음 밖에 둔다(같은 문서 `:117`).
- **리뷰 지적** — 입력 묶음 위에 떠 있던 에이전트 이름 라벨이 좁은 슬롯에서 대기 글을 덮었다(아래 영향).

## 영향 / 불변식
- **도는 동안 묶음의 높이가 바뀐다** — 마지막 호출 줄이 새 호출로 갈리고, 끝나면 사라진다. 바닥에 붙어 따라가는 동안은 대화 내용의 크기 관측(`useScrollFollow` 의 ResizeObserver)이 그대로 따라가고, 이를 위한 스크롤 규칙은 새로 두지 않았다.
- **`StructuredTextView` 는 더 꼬리를 그리지 않는다.** 바닥 숨 쉴 자리는 `h-3` 바닥 여백 하나가 진다(Radix ScrollArea 는 바닥 padding 을 무시한다). 그 여백은 턴 구분선과 1:1 로 맞바뀌어 턴 끝에 목록 높이가 변하지 않는다.
- **ADR-0244 의 「중단하는 중…」은 대기 줄 안의 같은 `WaitRow` 인스턴스가 그린다**(다시 마운트하지 않는다). 대기 타이머는 턴마다 다시 시작한다 — `WaitRow` 가 스트리밍이 켜질 때 마운트되기 때문이다.
- **에이전트 이름 라벨은 입력 묶음 위 떠 있는 겹침에서 대기 줄 오른쪽으로 옮겼다**(리뷰 지적 — 좁은 슬롯에서 대기 글을 덮었다).
- **알려진 한계 — 한 커밋에 몰린 턴 경계** — 한 턴의 끝과 다음 턴의 시작이 한 React 커밋에 몰리면 스트리밍이 꺼지지 않아 타이머가 앞 턴에서 이어 센다(이 변경 전과 같다).
- **알려진 한계 — `JumpToBottom` 의 `bottom-7`** — 옛 떠 있는 라벨에 맞춰 정한 높이다. 그대로 둔다 — 낮추는 것은 사용자에게 보이는 선택이라 사용자 몫으로 남긴다.
