# ADR-0263: Fold the tool group while it runs, and put the wait indicator on a fixed line above the input box

- 상태: 확정 (2026-10-01, basis: user instruction 2026-10-01 「클로드 코드 관행 따르면 될것같은데」 (Decision 1) + user decision 2026-10-01 「마지막꺼 보여줬다가 접는게 맞아보이는데」 (Decision 1 — one line of the last call while running) + user decision 2026-10-01 (Decision 2 — a choice between two options main raised) + peer `docs/research/chat-ux-four-features-2026-09-27.md:115` · `:117`)
- 관련: Amends ADR-0239 (Decision 4's auto-expansion of the last group while running) · Amends ADR-0244 (the chat-tail Wait row place of implementation detail b) · TRD `docs/process/S21-chat-ux/trd.md` (§2-4 · §4-3 · §4-4 · QA F3 ①) · research `docs/research/chat-ux-four-features-2026-09-27.md` · `src/components/slot/chat/WaitRow.tsx` · `src/components/slot/chat/ToolGroupRow.tsx` · `src/components/slot/StructuredTextView.tsx` · `src/components/slot/RichSlot.tsx` · step-log S21

## 맥락
While doing a last test of the chat screen branch (`v0.3.3/feat/chat-ux`) (2026-10-01), the user found two problems.

1. **The tool group folds only at the end** — while running, the calls were shown one by one separately, and only when all were done did they fold into one group. This was because the last running group was auto-expanded (ADR-0239 Decision 4 · TRD §4-3 · §4-4 — chosen by the TRD, not a user decision). When it ended, that expansion suddenly closed.
2. **The conversation jolts when the wait indicator appears and disappears** — the wait indicator was an in-flow row at the end of the scroll list, mounted and unmounted along with streaming. So every time it turned on and off, the conversation content jumped up and down.

## 결정
1. **The tool group is not expanded in full even while running** [user instruction — 「클로드 코드 관행 따르면 될것같은데」]. The count in the summary grows in place. While running, a 「진행 중…」 indicator is attached after the summary, and when it ends, that indicator drops off (past = no indicator). A group still forms at consecutive tools ≥2 (unchanged).
   - **While running, only one line — the call running now (the last call) — shows under the head. When calls increase, that line changes to the new last call, and when it ends, that line also folds, leaving only the head** [user decision 2026-10-01 — 「마지막꺼 보여줬다가 접는게 맞아보이는데」].
   - A human's or LLM's toggle still wins in both directions — expanding shows all members, and collapsing shows only the head even while running.
2. **The wait indicator sits outside the conversation scroll list, on its own line right above the input box** [user decision — a choice between two options]. That line is always mounted in the conversation layout and always takes its own height — only the content inside is turned on and off. The height is one value, the CSS variable `--chat-wait-strip-h` (1.75rem), registered in the chat style store as `waitStripH` so the existing adjustment path reaches it. The user wrote that it may become 2–3 lines later.

## 거부한 대안
- **A — keep auto-expanding the last running group (the previous behavior)** — it is the reported defect itself (shown separately, then folded at the end). It also conflicts with the Claude Code convention the user said to follow.
- **B — keep the wait indicator at the end of the list but leave that place always empty (visibility toggle)** — raised to the user and not chosen. About 40px of blank is left under the last message when idle.
- **C — show only the head even while running (the first implementation of Decision 1, the same day)** — the user changed it after testing (「마지막꺼 보여줬다가 접는게 맞아보이는데」).

## 근거
- **User instruction · decisions (2026-10-01)** — Decision 1 is the instruction's source text, Decision 2 is a choice between two options.
- **Peers** — the Claude Code CLI keeps read and search groups folded even while running (present tense) and changes them to past tense when they end, and expanding is Ctrl+O (`docs/research/chat-ux-four-features-2026-09-27.md:115`). The closest precedent for keeping the running call visible is cline — it groups only 「가벼운」 tools and keeps running ones outside the group (the same document `:117`).
- **Review finding** — the agent name label floating above the input group covered the wait text in a narrow slot (the impact below).

## 영향 / 불변식
- **The group's height changes while running** — the last-call line switches to the new call, and disappears when it ends. While stuck to the bottom and following, the conversation content's size observation (`useScrollFollow`'s ResizeObserver) follows as is, and no new scroll rule was added for this.
- **`StructuredTextView` no longer draws a tail.** One `h-3` bottom margin carries the bottom breathing room (Radix ScrollArea ignores bottom padding). That margin is swapped 1:1 with the turn divider, so the list height does not change at the turn end.
- **ADR-0244's 「중단하는 중…」 is drawn by the same `WaitRow` instance inside the wait line** (it is not remounted). The wait timer restarts every turn — because `WaitRow` is mounted when streaming turns on.
- **The agent name label moved from a floating overlay above the input group to the right of the wait line** (review finding — it covered the wait text in a narrow slot).
- **Known limit — a turn boundary packed into one commit** — if the end of one turn and the start of the next are packed into one React commit, streaming does not turn off and the timer continues counting from the previous turn (the same as before this change).
- **Known limit — `JumpToBottom`'s `bottom-7`** — a height set to fit the old floating label. It is left as is — lowering it is a user-visible choice, so it is left to the user.
