# ADR-0313: 구현은 서버 먼저 — 데몬 라이브러리 기능은 늘 켜져 있고 화면만 끄고 켠다

- 상태: 제안 (2026-10-31, 근거: 사용자 결정 G20(2026-10-29 「일단 서버 먼저가 맞고」) · G22-RESOLVED(2026-10-29 「데몬은 디폴트로 제공하는거고 UI는 그냥 패키지? 형식으로 온오프」) + 메인 M24-1 · M25 · M26(보고))
- 관련: G18 · G18-REVISED(순서가 뒤집힘) · G22 · S25 초안 E(미채번) · CLAUDE.md 「LLM-우선 제어」 · TRD `docs/process/S25-preset-library/trd.md` §1-5 「명령 어휘의 자리와 소유」 · §5 · §7 33

## 맥락
G18(2026-10-21)은 화면만 먼저 짓는 시제품 + 사용성 시험을 백엔드 앞에 뒀고, G18-REVISED 는 데몬 · 셸 없이 실 슬롯에 가짜 데이터로 짓는 꼴을 정했다. G22 는 라이브러리 화면을 켜고 끄는 「플러그인 같은」 기능으로 두되, 끄면 무엇이 꺼지는지(화면만 · 데몬 명령까지)를 열어 뒀다.

## 결정
1. 서버 먼저: asset-library + 데몬 명령 + `engram library.*` CLI 를 짓고 CLI 로 검증한 뒤 클라이언트(G20). 명령 · 답 꼴은 TRD 가 먼저 박는다.
2. 서버 단계가 1판 · 2판의 서버 몫을 다 덮는다 — 1판 · 2판은 출시 단위로 남는다(M24-1).
3. 화면 가짜 시제품은 짓지 않는다 — 클라이언트는 서버 뒤 실 데몬에 붙여 짓는다(M25).
4. 데몬 라이브러리 기능(명령 · CLI)은 늘 켜져 있다. 끄고 켜는 것은 화면 패키지뿐이다 — 화면을 꺼도 LLM 은 그대로 쓴다(G22-RESOLVED).
5. 서버 단계는 빌드를 초록으로 지키는 데 필요한 최소한의 기계적 클라이언트 변경(옛 프리셋 팔레트 쓰임 지우기 · 컴파일 고침)만 한다 — 새 클라이언트 기능은 클라이언트 단계까지 없다(M26).

## 거부한 대안
- **화면만 먼저 짓는 가짜 시제품 + 사용성 시험 뒤 백엔드**(G18 · G18-REVISED) — 사용자가 순서를 뒤집었다(G20 「일단 서버 먼저가 맞고」 · 결정 기록의 덧말 = LLM 길이 바탕).
- **끄면 데몬 명령까지 끄기**(G22 의 열린 갈래) — 사용자 「데몬은 디폴트로 제공하는거고」(G22-RESOLVED).

## 근거
- 사용자 결정 G20 · G22-RESOLVED.
- CLAUDE.md 「LLM-우선 제어」 — LLM 이 메인 조작 주체 · 프론트는 렌더링만 소유한다. 결정 기록 G28 이 같은 읽기(「LLM-first + UI optional (G20/G22)」)로 codex 터미널 알림을 화면이 아니라 데몬 답에 싣는다.

## 영향 / 불변식
- 화면만 아는 동작을 만들지 않는다 — 화면이 하는 조작은 전부 버스 명령이다(M21 — 예외 = 휴지통 비우기(셸 전용) · 로컬 OS 도우미).
- 화면 패키지가 꺼져도 데몬 명령 · CLI · 프라이밍 안내는 그대로 서야 한다.
- 클라이언트 단계 착수 = 화면 이야기부터(§5-4 — §1-9~§1-11 을 다시 확정).
