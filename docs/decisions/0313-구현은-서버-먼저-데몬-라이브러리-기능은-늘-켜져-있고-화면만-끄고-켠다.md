# ADR-0313: Implement the server first — the daemon library feature is always on, and only the screen is toggled

- 상태: 제안 (2026-10-31, basis: user decisions G20 (2026-10-29 「일단 서버 먼저가 맞고」) · G22-RESOLVED (2026-10-29 「데몬은 디폴트로 제공하는거고 UI는 그냥 패키지? 형식으로 온오프」) + main M24-1 · M25 · M26 (reported))
- 관련: G18 · G18-REVISED (the order was reversed) · G22 · S25 draft E (unnumbered) · CLAUDE.md 「LLM-우선 제어」 · TRD `docs/process/S25-preset-library/trd.md` §1-5 「명령 어휘의 자리와 소유」 · §5 · §7 33

## 맥락
G18 (2026-10-21) put a screen-only prototype + usability test ahead of the backend, and G18-REVISED settled on building with fake data in a real slot without the daemon or shell. G22 made the library screen a 「플러그인 같은」 feature that can be turned on and off, but left open what turns off when it is off (only the screen, or the daemon commands too).

## 결정
1. Server first: build asset-library + daemon commands + the `engram library.*` CLI, verify with the CLI, then the client (G20). The TRD fixes the command and reply shapes first.
2. The server stage covers all the server share of edition 1 and edition 2 — edition 1 and edition 2 remain as release units (M24-1).
3. A fake screen prototype is not built — the client is built after the server, attached to the real daemon (M25).
4. The daemon library feature (commands, CLI) is always on. Only the screen package is toggled — even with the screen off, the LLM uses it as before (G22-RESOLVED).
5. The server stage makes only the minimum mechanical client changes needed to keep the build green (removing the old preset palette usage · compile fixes) — new client features do not exist until the client stage (M26).

## 거부한 대안
- **A fake screen-only prototype + backend after a usability test** (G18 · G18-REVISED) — the user reversed the order (G20 「일단 서버 먼저가 맞고」 · the note on the decision record = based on the LLM path).
- **Turning off the daemon commands too when off** (the open branch of G22) — user 「데몬은 디폴트로 제공하는거고」 (G22-RESOLVED).

## 근거
- User decisions G20 · G22-RESOLVED.
- CLAUDE.md 「LLM-우선 제어」 — the LLM is the main operating party · the frontend owns only rendering. Decision record G28 carries the codex terminal notice in the daemon reply rather than on the screen, under the same reading (「LLM-first + UI optional (G20/G22)」).

## 영향 / 불변식
- Do not build behavior that only the screen knows — every operation the screen performs is a bus command (M21 — exceptions = emptying the trash (shell-only) · local OS helpers).
- Even when the screen package is off, the daemon commands, the CLI and the priming guidance must still stand.
- Starting the client stage = begin with the screen story (§5-4 — re-confirm §1-9~§1-11).
