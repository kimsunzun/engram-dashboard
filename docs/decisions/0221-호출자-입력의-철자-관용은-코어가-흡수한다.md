# ADR-0221: The core absorbs spelling tolerance for caller input

- 상태: 확정 (2026-09-23, basis: user decision)
- 관련: ADR-0220 (in the same round the screen dropped its trap wording on the assumption of this tolerance)

## 맥락

When an agent typed a command, it was carrying our side's circumstances for us. `agent.new --backend` demanded `Claude`/`Codex` **down to the exact letter case**, while `agent.spawnInto --backend`, which takes the same concept, is `#[serde(rename_all = "lowercase")]` and so demanded `claude`/`codex` — ★the same word was spelled differently on each surface★. The screen was also teaching that a folder path should be written with slashes and without wrapping quotes, but the form a Windows agent naturally types is `C:\work\thing`.

Those three were left as trap wording on the help screen. To delete that wording, the code has to actually accept that tolerance.

## 결정

1. **An enum value is accepted in any letter case and is sent back in the declared spelling.** The value that goes out is byte-identical to before — the tolerance is applied only on the deserialization side.
2. **The absorption point is the core.** `AgentBackendKind` uses manual deserialization, and the enum fields stamped by the declaration macro are moved to the declared spelling at the command bus's coordination point (`coerce`). That coordination point is the **common entrance of the two surfaces**, the CLI and the bus envelope, so one place covers both.
3. **The frontend control surface gets the same tolerance.** The allowlists in `src/` fold the incoming value to the declared spelling before sending it. An unknown word is still rejected — the tolerance is the letter-case axis alone and does not accept anything.
4. **`cwd` absorbs one layer of wrapping quotes and backslashes.** One normalization function is shared by `agent.new` · `agent.spawn --cwd` · `agent.spawnInto`. ★No existence check is made★ — it fixes the spelling and does not validate the folder.
5. **The trap wording is removed from the screen.** 「대소문자까지 그대로」 (down to the exact letter case) and 「슬래시로 적고 따옴표를 두르지 않는다」 (write with slashes and without wrapping quotes) are no longer true, so they are not written.

## 거부한 대안

- **Normalize only at the CLI entrance** — MCP and the frontend would still be strict, so **behavior would differ per surface**. A state where the same word works at one entrance and not at another is exactly what this decision set out to remove.
- **Attach custom deserialization to the declaration macro** — ★impossible (measured)★. The `@typedef enum` arm of `declare_commands!` stamps the derive list as fixed and has no place to accept declaration-site attributes. `macro_rules!` cannot turn an identifier into a lowercase string, so it cannot produce `serde(alias)` either. Instead of tearing the macro apart, we used the point whose very reason for existing is already 「광고한 스키마와 serde 사이를 조정한다」 (to coordinate between the advertised schema and serde).
- **Narrow the tolerance to the `backend` field** — the coordination point cannot see which field it is handling, so **field names would have to be hard-coded by hand**. That list goes stale every time a field is added, and a stale list creates 「왜 이 칸만 안 되나」 (why does only this field not work). We chose the broad side.
- **Fold `backend` once more in the frontend** — the core already absorbs it, so it would not be rejected. Folding again here makes **two normalization points**, and on the day the two diverge there is no telling which one is true.
- **Absorb underscore and camelCase differences too** — not done. The axis of this tolerance is letter case alone. So `LeftRight` of `slot.split --dir` and `left_right` of the frontend direct path **still remain as different spellings** (「영향」 below).

## 근거

- **The surfaces were actually split** — `AgentBackend` of `agent.new` is PascalCase, and `AgentBackendKind` used by `agent.spawnInto` is `rename_all = "lowercase"`. The two screens were copying that difference as is.
- **The macro constraint is measured** — the worker opened the relevant arm of `declare_commands!` and confirmed there is no place to inject an attribute, so it went around through the coordination point.
- **Tests** — 16 new (Rust) + 10 (frontend). `-p engram-dashboard-protocol` 67 · `-p engram-dashboard-command` 105 · `-p engram-dashboard-agent` 766 · `--test layout_commands` 84 · `npm test` 953, all with 0 failures.
- **Case folding is done with `toLowerCase`** — `toLocaleLowerCase` decides the same word differently on each machine because of the Turkish dotless I.

## 영향 / 불변식

- ★**The value going out is the declared spelling**★ — the tolerance is only on the receiving side, and the serialization spelling that the disk (`agents.json`) and the ts-rs bindings depend on does not change. If this property breaks, old profiles cannot be read.
- ★**The axis of the tolerance is letter case alone**★ — no whitespace trimming, and no underscore or camelCase conversion. An unknown word must still be rejected, and if that rejection disappears as the tolerance widens, typos pass silently.
- ★**This tolerance covers every declared enum field, not just the `backend` field**★ — what actually splits today is `output_format` · `SlotContentKind` · `ThemeOrigin`. That is why we fixed the assertions of the two tests that nailed down 「소문자 철자는 반려된다」 (the lowercase spelling is bounced). The place to revert is one line at the coordination point.
- ★**The split direction still has two spellings per path**★ — `slot.split --dir` going to the CLI is `LeftRight`/`TopBottom`, and the path the frontend calls directly on the shell is `left_right`/`top_bottom`. Underscore and uppercase are not a letter-case difference, and this decision does not fill that. The screen writes the CLI side, so it is right today, but the same concept is left with two spellings.
- **The `cwd` normalization does not strip unmatched quotes, an empty pair, or two layers** — stripping an empty pair would turn a value that was not empty into an empty value, which passes the earlier whitespace check and then makes the folder disappear.
