# ADR-0221: 호출자 입력의 철자 관용은 코어가 흡수한다

- 상태: 확정 (2026-09-23, 근거: 사용자 결정)
- 관련: ADR-0220 (같은 라운드에서 화면이 이 관용을 전제로 함정 문구를 걷었다)

## 맥락

에이전트가 명령을 칠 때 우리 쪽 사정을 대신 지고 있었다. `agent.new --backend` 는 `Claude`/`Codex` 를 **대소문자까지 그대로** 요구했고, 같은 개념을 받는 `agent.spawnInto --backend` 는 `#[serde(rename_all = "lowercase")]` 라 `claude`/`codex` 를 요구했다 — ★같은 낱말이 표면마다 철자가 달랐다★. 폴더 경로도 슬래시로 적고 따옴표를 두르지 말라고 화면이 가르치고 있었는데, Windows 에이전트가 자연스럽게 치는 꼴은 `C:\work\thing` 이다.

그 셋이 help 화면의 함정 문구로 남아 있었다. 문구를 지우려면 코드가 그 관용을 실제로 받아야 한다.

## 결정

1. **enum 값은 어떤 대소문자로 와도 받고, 선언된 철자로 되돌려 보낸다.** 내보내는 값은 전과 바이트 동일하다 — 관용은 역직렬화 쪽에만 건다.
2. **흡수 지점은 코어다.** `AgentBackendKind` 는 수동 역직렬화로, 선언 매크로가 찍는 enum 칸은 명령 버스의 조정 지점(`coerce`)에서 선언 철자로 옮긴다. 그 조정 지점이 CLI 와 버스 봉투 **두 표면의 공통 입구**라, 한 자리가 둘을 덮는다.
3. **프론트 제어 표면도 같은 관용을 갖는다.** `src/` 의 allowlist 들은 들어온 값을 선언 철자로 접은 뒤 보낸다. 모르는 낱말은 여전히 거절한다 — 관용은 대소문자 축 하나뿐이고 아무거나 받는 것이 아니다.
4. **`cwd` 는 감싼 따옴표 한 겹과 역슬래시를 흡수한다.** 정규화 함수 하나를 `agent.new` · `agent.spawn --cwd` · `agent.spawnInto` 가 공유한다. ★실재 확인은 하지 않는다★ — 철자를 고치는 것이지 폴더를 검증하는 것이 아니다.
5. **화면에서 그 함정 문구를 걷는다.** 「대소문자까지 그대로」·「슬래시로 적고 따옴표를 두르지 않는다」는 더 이상 참이 아니므로 적지 않는다.

## 거부한 대안

- **CLI 입구에서만 정규화한다** — MCP 와 프론트가 여전히 엄격해 **표면마다 동작이 갈린다**. 같은 낱말이 한 입구에서는 되고 다른 입구에서는 안 되는 상태가 이 결정이 없애려던 바로 그것이다.
- **선언 매크로에 커스텀 역직렬화를 붙인다** — ★불가능하다(실측)★. `declare_commands!` 의 `@typedef enum` arm 이 derive 목록을 고정으로 찍고 선언부 attribute 를 받는 자리가 없다. `macro_rules!` 는 식별자를 소문자 문자열로 못 바꿔 `serde(alias)` 도 못 만든다. 매크로를 뜯는 대신 이미 「광고한 스키마와 serde 사이를 조정한다」가 존재 이유인 지점을 썼다.
- **관용을 `backend` 칸으로 좁힌다** — 조정 지점이 칸을 가릴 수 없어 **필드 이름을 손으로 박아야** 한다. 그 목록은 칸이 늘 때마다 낡고, 낡은 목록은 「왜 이 칸만 안 되나」를 만든다. 넓게 두는 쪽을 골랐다.
- **프론트에서 `backend` 를 한 번 더 접는다** — 코어가 이미 흡수하므로 거절되지 않는다. 여기서 또 접으면 **정규화 지점이 둘**이 되고, 둘이 갈리는 날 어느 쪽이 참인지 알 수 없다.
- **밑줄과 camelCase 차이까지 흡수한다** — 하지 않았다. 이번 관용의 축은 대소문자 하나뿐이다. 그래서 `slot.split --dir` 의 `LeftRight` 와 프론트 직결 경로의 `left_right` 는 **여전히 다른 철자로 남는다**(아래 「영향」).

## 근거

- **표면이 실제로 갈려 있었다** — `agent.new` 의 `AgentBackend` 는 PascalCase, `agent.spawnInto` 가 쓰는 `AgentBackendKind` 는 `rename_all = "lowercase"`. 두 화면이 그 차이를 그대로 베껴 적고 있었다.
- **매크로 제약은 실측이다** — 워커가 `declare_commands!` 의 해당 arm 을 열어 attribute 주입 자리가 없음을 확인했고, 그래서 조정 지점으로 우회했다.
- **테스트** — 신규 16건(Rust) + 10건(프론트). `-p engram-dashboard-protocol` 67 · `-p engram-dashboard-command` 105 · `-p engram-dashboard-agent` 766 · `--test layout_commands` 84 · `npm test` 953, 전부 0 실패.
- **대소문자 접기는 `toLowerCase` 로 한다** — `toLocaleLowerCase` 는 터키어 점 없는 I 때문에 같은 낱말을 기계마다 다르게 판정한다.

## 영향 / 불변식

- ★**나가는 값은 선언 철자다**★ — 관용은 받는 쪽에만 있고, 디스크(`agents.json`)와 ts-rs 바인딩이 의존하는 직렬화 철자는 바뀌지 않는다. 이 성질이 깨지면 옛 프로필이 안 읽힌다.
- ★**관용의 축은 대소문자 하나뿐이다**★ — 공백 트림도, 밑줄·camelCase 변환도 하지 않는다. 모르는 낱말은 그대로 거절돼야 하고, 그 거절이 관용을 넓히다 사라지면 오타가 조용히 통과한다.
- ★**이 관용은 `backend` 칸만이 아니라 선언된 모든 enum 칸에 걸린다**★ — 오늘 실제로 갈리는 것은 `output_format` · `SlotContentKind` · `ThemeOrigin` 이다. 「소문자 철자는 반려된다」를 못 박던 테스트 둘의 단언을 그래서 고쳤다. 되돌릴 자리는 조정 지점 한 줄이다.
- ★**분할 방향은 아직 경로마다 철자가 둘이다**★ — CLI 로 가는 `slot.split --dir` 는 `LeftRight`/`TopBottom`, 프론트가 셸에 직접 부르는 경로는 `left_right`/`top_bottom`. 밑줄과 대문자는 대소문자 차이가 아니라 이 결정이 안 메운다. 화면은 CLI 쪽을 적고 있어 오늘은 맞지만, 같은 개념에 철자가 둘인 상태로 남아 있다.
- **`cwd` 정규화는 짝이 안 맞는 따옴표·안이 빈 짝·두 겹을 벗기지 않는다** — 빈 짝을 벗기면 비어 있지 않던 값이 빈 값이 되어 앞선 공백 검문을 통과한 뒤 폴더가 사라진다.
