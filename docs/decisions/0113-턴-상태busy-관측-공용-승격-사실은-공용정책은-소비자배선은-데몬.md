# ADR-0113: 턴 상태(busy) 관측 공용 승격 — 사실은 공용·정책은 소비자·배선은 데몬

- 상태: 확정 (2026-07-29, 근거: 사용자 결정 — 메시징 학습 Q&A 세션, 구현 시점 = 발송 개편(ADR-0111/0112) 후 별도 슬라이스) · 부분 폐기 by ADR-0119 (공용 시설 거처)
- 관련: ADR-0111·0112(발송 개편 — 이 승격은 그 다음 슬라이스) · ADR-0104(결정 3 idle 게이트 — 메시징이 이 상태의 1호 소비자) · ADR-0110(커널 lib 격리 — 포트 구조 유지) · CLAUDE.md §5(LLM-우선 제어 — 상태의 제어 표면 노출과 정합) · `crates/engram-dashboard-messaging/src/busy.rs`(현 소유처 — 이관 대상) · Amended by ADR-0119 (공용 시설 거처) — **거처는 코어로 확정됐다. 결정 1의 "코어/데몬측"을 미결 갈림길로 읽지 말 것**

## 맥락

"수신자가 지금 턴 진행 중인가"(busy/idle)는 에이전트의 일반 상태인데, 현재 그 관측 표(BusyTracker)가 메시징 커널 내부에 산다 — 유일 소비자가 우편 배달 게이트(ADR-0104 결정 3)였기 때문. 그러나 같은 상태를 원하는 소비자가 이미 보인다: UI의 "턴 중 채팅 입력 잠금/큐잉", 슬롯 상태 표시, LLM 제어 표면(§5). 메시징 안에 있는 한 이들이 접근할 수 없다(커널은 워크스페이스 무의존 격리 — ADR-0110). 사용자 제안(2026-07-29): "BusyTracker는 순수 에이전트 상태만 서빙하고, 그에 대한 처리는 메시지 내부에서, 이벤트 연결은 데몬에서."

## 결정

**턴 상태 관측을 3분리로 공용 승격한다:**

1. **사실(fact) = 공용** — "(에이전트, epoch)별 턴 진행 관측값" 표를 코어/데몬측 공용 시설로 승격한다. 이 계층은 관측된 사실만 서빙하고 어떤 해석·정책도 갖지 않는다.
2. **정책(policy) = 소비자 내부** — 사실을 어떻게 해석할지는 각 소비자가 정한다. 메시징의 기존 정책(positive-knowledge-only "모르면 idle"·busy 상한 30분 sweep·flush 도어벨)은 메시징 내부에 그대로 남는다. 다른 소비자(입력 잠금 등)는 자기 폴백·상한을 따로 정한다.
3. **배선(wiring) = 데몬** — 출력 스트림 tap 부착·턴 신호(진행/종료) 연결은 데몬(조립실 messaging_host 계열)이 담당한다. 커널 포트(TurnProbe/BusyGate) 구도는 유지하되 신호 공급원이 공용 시설로 바뀐다.

**구현 시점 = 발송 개편(ADR-0111/0112) 구현·검증 완료 후 별도 슬라이스**(사용자 갈림길 선택).

## 거부한 대안

- **현행 유지(메시징 내부 소유)** — UI 입력 게이트 등 후속 소비자가 같은 상태를 못 쓰고, 필요 시 관측 배선을 중복 구축하게 된다(같은 출력 스트림에 도청기 2벌).
- **정책까지 공용화(공용 계층이 busy/idle 판정·폴백·상한을 결정)** — 소비자마다 오판 비용이 다르다: 메시징은 "안 가는 것 > 늦게 가는 것"이라 배달 쪽으로 무너지는 폴백·30분 상한이 맞지만, 입력 잠금은 다른 상한·해제 규칙을 원할 수 있다. 정책을 공용에 넣으면 한 소비자의 가치판단이 전원에게 강제된다.
- **발송 개편과 같은 슬라이스로 동시 수술** — 우편 semantics 수술과 독립적인 구조 리팩터라 리뷰·QA 범위와 회귀 표면이 불필요하게 커진다. 위험 분리(사용자 선택).

## 근거

- 사용자 결정(2026-07-29): 공용 승격 + 3분리 구도 + 후속 소비자("채팅 한꺼번에 입력되지 못하도록 막는 곳") 지목 전부 사용자 발화. 갈림길 선택 = "별도 슬라이스로 분리".
- 이사 비용이 구조적으로 낮음: 커널은 이미 TurnProbe(신호 수신구)/BusyGate(조회 seam) 포트 뒤에서만 turn 상태를 다루고, 실물 배선은 데몬 어댑터 소유(ADR-0110) — 소유처 이동이 파이프라인을 흔들지 않는다.
- 현 busy.rs 헤더가 스스로 명시하는 사실: positive-knowledge-only·30분 상한은 메시징의 가치판단("안 가는 것이 최악")에서 도출된 정책이다 — 사실/정책 분리의 필요 근거.

## 영향 / 불변식

- **공용 계층 = 사실만** — 폴백·상한·도어벨 같은 정책을 공용 계층에 넣으면 이 결정 위반. 소비자 정책은 소비자 코드에.
- **메시징 소비자 정책 불변** — 승격 후에도 메시징의 "모르면 idle"·30분 상한·flush 도어벨 동작은 관측 가능하게 동일해야 한다(승격 = 소유처 이동이지 semantics 변경 아님).
- **콜백 규율 승계** — 턴 신호 콜백은 출력 펌프 스레드에서 돈다: 작은 락 구간 갱신 + 논블록 통지만(busy.rs 현 규율). 공용화하면서 이 규율이 풀리면 전 에이전트 출력이 배달 작업 뒤에서 밀린다.
- **§5 정합** — 공용 상태는 LLM 제어/관측 표면으로 노출 가능해야 한다(UI 전용 은닉 금지).
