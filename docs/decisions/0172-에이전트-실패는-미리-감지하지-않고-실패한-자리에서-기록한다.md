# ADR-0172: Agent failures are not detected in advance but recorded where they fail

- 상태: 확정 (2026-08-19, basis: user decision + code investigation 2026-08-19)
- 관련: ADR-0082 (no automatic fresh fallback on restore failure) · ADR-0008 (sid is controlled · claude files are best-effort) · ADR-0171 (layer 3 of the home criterion) · ADR-0173 (display rules) · ADR-0127 (do not add cleanup points)

## 맥락

If an agent is launched and then exits **without a single exchange**, reopening that entry fails. We issue the conversation identifier first and pass it in, but claude creates the actual conversation for that identifier only **once the first exchange happens** — the identifier exists without the real thing, so resuming fails. Since ADR-0082 forbids automatic fresh fallback, that failure stays on screen as is (intended behavior).

The problem is that **the failure is recorded nowhere**. The exit classification does not distinguish crash, user exit, and restore failure, and converges all of them to the same disposition (turning off only automatic restore), and the field to hold the failure reason is only reserved and not wired up. So neither the screen nor the control LLM can know "why it did not open". **What ADR-0082 required — "leave the cause so the control LLM can read it and raise it to the user" — is effectively not being kept.**

## 결정

1. **No up-front decision.** Do not check "does this entry have history" before activation. Observe the failure at the place it is attempted and record it then.
2. **Attach 「마지막 실패」 (last failure) to the entry (profile).** It is an enum, excluded from disk serialization so it lives **only for the daemon's lifetime** (ADR-0171 layer 3). It is not gathered in a separate container.
3. **Keep it on a separate axis from the current state.** Do not merge it into the existing state enum.
4. **Clear it when activation succeeds.** This is the only clearing point. A stale write is rejected by an incarnation (epoch) check, and a **request that did nothing** (already running or already starting up) neither records nor clears — there is no failure to record and no ground to clear for something that was not done.
5. **Gather, in one table, 「다시 해볼 가치가 있나 · 화면 문구 · 권하는 행동」 (whether it is worth retrying · screen wording · recommended action) for each failure kind.** Screen behavior is derived from that table.
6. **This round covers recording and display only.** Changing click behavior and a 「새 대화로 시작」 button are deferred to a follow-up.

## 거부한 대안

- **Persist our observations and decide in advance** — the profile has no such value, so it would have to be created, and **entries already accumulated have no stamp, so retroactive decision is impossible.** Defaulting to "no history" locks a healthy conversation as not runnable; defaulting to "has history" means the feature does not catch old entries.
- **Read the conversation file claude created and decide in advance** — it is retroactive, but ADR-0008 **forbids building product features on files claude creates** (the format can change without notice, so the grade is fixed at best-effort). Reading it for scrollback revival and locking a feature on it are different grades.
- **Persist the last failure to disk** — taking the daemon down also kills those sessions, so there is little reason to hold on to an old failure. A profile file format change and backward-compatibility handling follow (user decision 2026-08-19).
- **Gather it in a separate container** — state drifts away from its owner and one more cleanup point appears. The same struct **already has a precedent of memory-only fields that are dropped from disk**, so there is no reason to build a side table.
- **Merge it into the existing state enum** — "started again and running but before the first conversation" cannot be expressed. Without that combination, the ground for the screen to apply 「도는 중이 이긴다」 (running wins) also disappears.

## 근거

- **Code investigation (2026-08-19)** — the profile has no stored value that says whether a conversation happened. The runtime turn-observation table is memory-only and disappears on restart. The profile, on the other hand, already has a memory-only field that is dropped from disk serialization, so the same approach is a verified pattern.
- **ADR-0082 §영향** left this decision explicitly open and deferred it, with "the visual display of the corpse is for the user to judge later after seeing the real thing". This ADR and ADR-0173 close that open item.
- **User decision (2026-08-19)** — do not detect every time · do not save to disk · clear it once a transmission goes through · handle by kind flexibly but gather in one place.

## 영향 / 불변식

- **The clearing point is 「활성화 성공」 (activation success) only.** Adding callers splits the causality — the same reason ADR-0127 pinned the turn-observation cleanup points at two.
- ★**Do not revert to 「대화 왕복 성립」 (conversation round trip established)**★ — it was the criterion of the first draft and was discarded during implementation. A round trip is observed **only through the turn-end signal**, but that signal comes only from structured output, while, conversely, failure **classification** comes only from console bytes. The two halves are split by output format and are mutually exclusive, so **a terminal agent's record would never be cleared.** Moreover the turn-end signal has no epoch check and a non-blocking contract, so taking the profile lock from there was itself a contract violation.
- **Why using success as the ground for clearing is honest** — if resume got past the early-exit window, the conversation to resume **really existed**, and if a new one started, one now exists. If it is then closed without a single word, **the next activation fails again and is recorded again** — that is decision 1 (do not detect in advance; record where it fails).
- **It disappears on daemon restart.** It survives an app window restart.
- **Unknown failure kinds are not blocked (fail-open).** If classification falls to "other", treat it as 「다시 해볼 가치 있음」 (worth retrying) — the loss of blocking and then being unable to open a healthy entry is larger than one wasted attempt.
- One field is added to the wire spec to carry this value (per entry).
