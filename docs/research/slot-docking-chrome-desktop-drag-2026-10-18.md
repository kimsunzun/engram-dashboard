### C. Practice on docking area size

| Product | Attach area | Preview | Marker | New window | Confidence |
|---|---|---|---|---|---|
| VS Code editor group | 10% at the edge (30% on one axis for group dragging) · the rest = merge | split 50% · merge 100% — larger than the attach area | none (implicit) | not in this file | likely (read from a summary — the constants need rechecking against the original) |
| dockview | edge `activationSize` default 20% · the rest = center | overlay size `size` is separate | none | floating groups are a separate feature | 20% = likely · `size` default = uncertain |
| FlexLayout | 4 diagonal triangles + center 0.25–0.75 | half | none | popout is a separate feature | likely |
| Lumino / JupyterLab | widget = 3 equal parts · root edge px (12 at the top · 40 for the rest) | half · root 0.618 | none | none | constants = likely |
| Qt ADS | cross icon (40 px or 3× the font) | 1/3 · 1/2 | yes | floats when dropped outside the target (unchecked) | size = likely |
| Visual Studio | only the arrows of the diamond guide | shading only over an arrow | yes | Ctrl drag · outside the target | likely (MS Learn) |

- **「붙는 영역 < 미리보기」 (attach area < preview) is a common practice** — it matches the user demand. Narrow attach area (10–20% or fixed px), preview = half of the pane.
- **No precedent for 「칸 가운데 = 새 창」 (middle of the pane = new window) was found** — in all of them the middle = merge into that pane. Our current rule (`choose_band` in `hit.rs` makes a new window if it is in no band · outer band 32 px · band rectangle = preview rectangle `landing_rect`) is the cause of the 「새 창으로 빼려면 가운데까지」 (to pull out to a new window, go to the middle) inconvenience.
- **With the A6 model this problem resolves naturally** — at the moment of detaching a real window already exists, so dropping over a docking band attaches to that pane (the floated window is closed), and dropping anywhere else leaves the window as it is. A separate 「새 창」 (new window) target is not needed.


### D. The dragged real window covers the guides of the window below (ADR-0295 open item 1 · additional collection 2026-10-18)

1 collector (shallow source clones — Qt ADS `4f4f602` · AvalonDock `10d1cc6` · DockPanelSuite `577d5b8` · KDDockWidgets `88adab0` · IntelliJ master) · no main grounding · no adversarial review (additional collection).

- **Every docking system that moves a real window draws its guides in a separate top-level window** — no border · transparent background · not activated · above the dragged window. AvalonDock is the clearest: each time the target changes it re-stacks the z-order as 「대상 창 → 끌던 창 → 안내 창」 (target window → dragged window → guide window) (`DragService.cs:93-110` · `239-246` · guide window `OverlayWindow.cs:65-68` — `AllowsTransparency` · `WindowStyle=None` · `ShowActivated=false`). Qt ADS · KDDockWidgets = `Qt::Tool | Frameless` + `WA_TranslucentBackground` (ADS `DockOverlay.cpp:442-448` · KDDW `ClassicIndicatorsWindow.cpp:159-185`). — likely.
- **Making the dragged window translucent is rare and optional** — KDDW `setDraggedWindowOpacity` (default 1.0 = opaque) · ADS · AvalonDock do not change it. Only those that move an image (IntelliJ · DockPanelSuite outline 0.5) make the image translucent. — likely.
- **The decision is always on the cursor's screen point · the dragged window is excluded** — own container list geometry (ADS `FloatingDockContainer.cpp:566-588` · AvalonDock `DockingManager.cs:2539-2560`) · walking the z-order below the dragged HWND (KDDW `DragController.cpp:953-985`) · hiding the guide window from `WindowFromPoint` with `HTTRANSPARENT` (DockPanelSuite `DragForm.cs:8-60` — `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` · `TopMost`). Dragged window position = cursor − the offset grabbed at the press. — likely.
- **Implication:** our decision is already made by the shell from a screen point (`hit.rs` · `regions.rs` — only the dragged window needs to be excluded). Drawing the guides and preview in **one transparent · click-through · non-activating topmost window** is peer practice. Whether such a window can be made with Tauri/WebView2 (transparent · `ignore_cursor_events` · always on top) is measured by spike S7.
- **Gaps:** Visual Studio internals (no source — by the docs only the guide diamond and shading) · Godot · GoldenLayout not reached · ADS's Windows z-order was read only.
