## 결론

- **둘을 갈라 봐야 한다 — 「무엇으로 가리키나(메커니즘)」 와 「덮어쓰기 때 붙임을 어떻게 하나(정책)」.** 메커니즘(경로 · OS 신원 · 옆 파일 ID)은 덮어쓰기 정책을 정해 주지 않는다 — Unity 에서도 내용만 갈아 끼우고 목적지 `.meta` 를 두면 참조는 새 내용을 받는다(적대 리뷰 지적 · 반영). 그래서 이번 결정은 정책(아래 A · B · C)이고, 메커니즘은 지금 경로(ADR-0315)로 충분하다.
- **경로로 가리키는 도구가 흔하다 — 대개 앱 안 이동만 고치고 바깥 이동은 「찾을 수 없음」 + 다시 연결**(Obsidian · VS Code · Foam · Lightroom — 가능성 높음 · 대부분 2차 자료). 예외가 있다: Zotero 는 설정한 기준 폴더 아래 연결 파일을 자동으로 다시 잇고, Dendron 은 색인에 앞머리 id 를 쓴다(적대 리뷰 반증 · 반영). 지금 engram 설계가 이 갈래다.
- **덮어쓰기 · 휴지통 동안 참조를 지키는 문서화된 선례가 일부 있다.** DEVONthink 읽기 목록은 휴지통에 간 항목의 참조를 휴지통을 비울 때까지 남긴다(데이터베이스 구조라 경로 바꿔 쓰기와는 다르다) · calibre 는 같은 책(논리 id)에 형식 파일을 갈아 끼운다 · Lightroom 은 가져오기에서 원본을 갈아 끼우며 옛 설정을 남길 수 있다(적대 리뷰가 찾음 — 메인 미대조 · 가능성 높음). engram 의 「이동하며 덮어쓰기」 와 똑같은 선례는 못 찾았다.
- **OS 파일 ID 는 임시 파일에 쓰고 바꿔 넣는 저장에서 바뀔 수 있다** — `ReplaceFile` 결과 파일의 file ID = 바꿔 넣은(replacement) 파일의 것(확실 — 원문 대조). 단 같은 함수가 NTFS **object ID** 는 원래 파일 것을 지킨다(확실 — 원문 대조). 그래서 「모든 쓰기가 신원을 깬다」 는 과장이다 — 깨는 것은 임시+이름 바꾸기로 저장하는 편집기(JetBrains safe write · vim `backupcopy=no` 등 — 가능성 높음)이고, Notepad · Notepad++ · Obsidian · VS Code 기본 저장은 모름.
- **OS 신원을 쓰는 성숙 구현(Windows 바로가기 · OLE 링크)도 신원 · 휴리스틱은 「못 찾았을 때 찾아 주는」 보조다** — object ID 추적(NTFS 3.0+ · 이동식 매체 안 됨) 뒤 마지막 경로 근처를 만든 날짜 · 크기 · 이름으로 훑는다. Microsoft 스스로 「늘 찾지는 못하고 오래 걸릴 수 있다」 고 적는다(확실 — 원문 대조). digiKam 은 부분 해시 + 크기로 바깥에서 옮긴 파일을 다시 찾는다(적대 리뷰가 찾음 · 가능성 높음).
- **Godot 4.4** — 바깥에서 옮기면 의존 장면에 경고가 나고 다시 저장해야 하며, 경로 폴백에 기대지 말라 · 경로가 안 바뀐 채 두 리소스가 뒤바뀔 수 있다(확실 — 원문 대조). 그 글은 바깥 이동 지원을 앞세운다(옛 판의 「앱 안 이동 권장」 요약은 틀렸다 — 적대 리뷰 · 반영).

## engram 에 대한 선택지 — 덮어쓰기 정책

예: 라이브러리에 `리뷰.md` · `코딩.md` · 에이전트 X = `[리뷰, 코딩]` · 에이전트 Y = `[코딩]`. engram 에서 `리뷰.md` 를 `코딩.md` 자리로 옮기며 [덮어쓰기] → 옛 `코딩.md` 는 `.trash` 로, `코딩.md` 자리엔 리뷰 내용.

| | X 결과 | Y 결과 | 되살리기 | 비용 |
|---|---|---|---|---|
| **A. 이름을 따라간다 + 중복 접기** | `[코딩]`(리뷰 내용) | `[코딩]` → 조용히 리뷰 내용을 받음 | 자동 복원 없음 — 옛 코딩을 되살리면 이름이 부딪혀 다른 이름 · 다시 붙여야 함 | 지금 구현 + 접기 몇 줄 |
| **B. 덮어쓴 것은 지운 것** | `[코딩]`(리뷰 내용) | `[]` 떨어짐 | 자동 복원 없음 | 덮어쓰기 계획에 「덮어써질 경로의 붙임 떼기」 단계 |
| **C. 휴지통 보내기도 「이동」 으로** | `[코딩(리뷰 내용), 휴지통의 옛 코딩]` — 둘 다 남음 | `[휴지통의 옛 코딩]` — 「휴지통에 있음」 | engram 안 되살리기면 따라 돌아옴(이름이 부딪히면 정한 새 이름으로) · 바깥에서 꺼내면 안 됨 | 아래 규칙들 |

- **C 가 필요로 하는 규칙**(적대 리뷰 · 반영): ① 한 번의 덮어쓰기 안에서 두 대응(`옛 코딩 → .trash/…` · `리뷰 → 코딩`)이 서로 이어 걸리지 않게 원래 값 기준으로 동시 적용(지금 P3 의 규칙과 같다) ② 되살릴 때 이름 부딪힘 처리와 그 결과 경로로 다시 바꿔 쓰기 ③ 파일 조작은 됐는데 참조 저장이 실패했을 때 되돌리기 · 다시 하기 ④ 휴지통을 비우면 그 붙임을 어떻게 할지(떼기 / 「찾을 수 없음」) ⑤ 실행할 때 휴지통에 있는 붙임을 어떻게 할지(건너뜀 / 막힘).
- **A 와 C 는 Y 만이 아니라 X 에서도 다르다** — C 는 X 가 옛 코딩 붙임을 휴지통 쪽으로 그대로 들고 있다(옛 판의 「Y 에서만 다르다」 는 틀렸다 — 적대 리뷰 · 반영).
- **메커니즘을 바꾸는 길(OS 신원 · 옆 파일 ID · 해시 · 앱 카탈로그 id)은 이번 결정 밖이다** — 셋 다 「바깥 이동 뒤 다시 찾기」 에 값어치가 있고 덮어쓰기 정책은 따로 정해야 한다. 바깥 이동 대응을 키울 때 다시 볼 후보로 남긴다: object ID(NTFS 한정) · 부분 해시 + 크기(digiKam) · 앱 카탈로그의 경로↔id 표.

## grounding (메인 대조)

| 클레임 | 출처 | 판정 |
|---|---|---|
| `ReplaceFile` 결과 파일의 file ID = replacement 의 것 · object ID · 만든 시각 등은 원래 파일 것을 지킴 | https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew (Remarks) | 지지 |
| 경로 참조는 믿을 수 없다 · rename · backup · restore 는 object ID 를 지키고 copy 는 아니다 · NTFS 3.0+ 만 · 이동식 매체 안 됨 · 휴리스틱 훑기는 늘 찾지는 못하고 오래 걸림 | https://learn.microsoft.com/en-us/windows/win32/fileio/distributed-link-tracking-and-object-identifiers | 지지 |
| Godot — 바깥 이동은 `.uid` 를 함께 옮겨야 · 바깥 이동은 의존 장면 경고 + 다시 저장 · 경로 폴백에 기대지 말 것 · 경로가 안 바뀐 채 두 리소스가 뒤바뀔 수 있다 | https://godotengine.org/article/uid-changes-coming-to-godot-4-4/ | 지지 |
| Unity — 바깥에서 옮기면 `.meta` 도 옮겨야 · 아니면 새 에셋 취급 | https://docs.unity.com/en-us/engine/current/manual/assets-and-media/import-assets/asset-metadata | 수집자 인용(메인 미대조) — 가능성 높음 |
| Obsidian — 앱 안 이동만 링크 갱신 · 바깥 이동은 안 고침 | https://forum.obsidian.md/t/auto-update-links-for-files-moved-while-obsidian-is-closed/91670 (사용자 포럼) | 부분지지(공식 문서 아님) |
| Obsidian — 같은 이름 위로 이동은 기본으로 막힘 | 플러그인 문서 · 검색 요약 | 불확실 |
| Lightroom · Zotero 의 찾기/다시 연결 UX | 2차 자료 · Zotero KB | 가능성 높음 |

## 공백 · 한계

- 덮어쓰기(c) 동작은 모든 피어에서 문서 없음 — A · B · C 어느 것도 「관행」 이라 부를 근거가 약하다.
- Notepad · Notepad++ · Obsidian · VS Code 기본 저장의 file ID 유지 여부는 실측 안 함(10 줄 실측으로 확인 가능).
- Obsidian 휴지통 되살리기 때 링크 동작 · Logseq `id::` · Dendron 앞머리 id 는 읽지 못함.
- macOS 행은 2차 자료뿐.

## 적대 리뷰

codex(cross-family) · effort high · 웹 검색 — **FIX**. 반영:

- 메커니즘과 정책을 섞은 선택지 표(옛 A–E) → 정책 A · B · C 로 갈라 다시 씀 · D · E 는 메커니즘으로 내림(high).
- 「A 와 C 는 Y 에서만 다르다」 — X 에서도 다르다(C 는 옛 붙임을 휴지통 쪽으로 남김)(high).
- C 의 「되살리기 = 다시 이동이라 자동」 — 이름 부딪힘 · 동시 대응 · 부분 실패 되돌리기 · 비우기 · 실행 처리 규칙이 더 필요(high).
- 「편집기 · LLM 쓰기마다 file ID 가 바뀐다」 과장 · object ID 는 `ReplaceFile` 에서 지켜짐과 어긋남(high).
- 빠진 피어: digiKam(부분 해시) · DEVONthink(앱 UUID · 휴지통 항목 참조 유지) · calibre · Lightroom 원본 갈아 끼우기 · Zotero 자동 다시 잇기 · Dendron 앞머리 id(medium) — 결론에 넣음. **메인은 이 출처들을 대조하지 않았다**(가능성 높음으로 표기).
- Godot 요약 오귀속(medium) — 고침.
- Obsidian 공식 문서의 URI · CLI 덮어쓰기 · 휴지통 설정 — 덮어쓴 파일의 링크 처리는 여전히 확인 못 함(medium) — 공백에 남김.
