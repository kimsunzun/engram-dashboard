# Reference implementations — OSS peer list

> A sample list of the results of the OSS peer survey of projects that solved the same problem first (2026-09-19) and the clone cleanup (2026-09-23), moved over from `CLAUDE.md` 「참조 구현」 (reference implementations) — it is not exhaustive. Clone locations · the state of the clones on this PC = `.claude/skill-bindings/research.md`.

- ★**The ★ and activity figures below were measured on 2026-09-19 and go stale**★ — when deciding 「죽었나」 (is it dead), do not copy them; look again on the spot with `gh api repos/<경로>`.
- ★**Two points of consensus on this axis — these come before any individual peer**★ (survey 2026-09-19)
  - ★**No project streams scrollback to an attaching client.**★ Mature implementations without exception **redraw only the current screen** (the server runs a VT and hands over the screen state, or rewinds bounded bytes, or catches up only what is missing by sequence number), and scrollback is **a separate path that is pulled explicitly and separately**. ★**One project tried to rewind history and screen as a single stream, and reverted because the screen broke**★ — `coder/boo` #22: the rewind target was the **Claude Code TUI**, and because the formatter trimmed the trailing blank lines, the cursor restoration was off by **exactly 3 lines**. This is the case to read first when the idea of enlarging our replay buffer comes up.
  - ★**On Windows, the daemon must be the process that *created* the PTY.**★ `HPCON` keeps the session alive while the process that created it holds it, and **there is no documented API to hand it to another process** — nothing like POSIX `reptyr` (pulling someone else's process into my terminal) can hold for ConPTY. So **there is no way on Windows to adopt an arbitrary process later**, and the four wrappers that actually try to do it are all immature (archived · 1 star · admitting 「세션 지원 없음」 (no session support)). ★**Confidence = likely**★ — it is the necessary reading of two MS docs pages, and no place states 「못 넘긴다」 (it cannot be handed over) in a sentence.
- **Clones kept**
  - **herdr** (`herdrdev/herdr` · 39.5k★ · Apache-2.0 · active) — a single Rust binary whose **background server owns the terminals**, and agents keep running and **reattach from anywhere (including ssh)**. It also has a socket API for agents. ★The closest peer to our daemon model★, and **another project picks it as its terminal backend** (awslabs CAO). ★**The real-world precedent for recovering the codex session id is here**★ — it installs **only a single `SessionStart` hook**, receives `session_id` from the stdin payload and sends it back (POSIX = socket · **Windows = re-entering its own binary's CLI**). **It does not automate trust** and instead shows the review screen as 「막힘」 (blocked) and **hands it over for a human to approve once**. ★**The old description written as 「신뢰를 안 다루니 id 를 못 받는다」 (it does not handle trust, so it cannot receive the id) was wrong**★ (close reading of the clone 2026-09-19 — that inference was carried in both CLAUDE.md and the survey report). ★**All herdr `파일:줄` pointers in documents before 2026-09-23 are against the old master `624dfd4` (2026-08-20) → open them with `git show 624dfd4:<경로>`**★ (master has moved since — on other commits the lines are off). That commit is still an ancestor of master (`gh api repos/herdrdev/herdr/compare/624dfd4796559042ec13ccf4d4b54374902ab81d...master` → `behind_by=0`, 2026-09-23). ★**A freshly cloned shallow clone does not contain that commit, so this command fails**★ — a full or `--filter=blob:none` clone contains it (the clone itself was not run). A source build of `v0.9.1` needs Zig 0.16.0 — it is not in the README development section but only in `AGENTS.md` (details = `docs/research/oss-peer-hands-on-2026-09-23.md`).
  - **orca** (`stablyai/orca` · 72k★ — the largest in this field · MIT · active) — an orchestrator + GUI that runs several agent backends **side by side per worktree**. It overlaps with 「백엔드 확장」 (backend extension). ★**The disk-replay precedent is here**★ — the daemon periodically checkpoints the ANSI buffer to disk and rewinds it on cold-restore. It **grants hook trust through an app-server RPC** (the same path as ours) and, when provenance verification fails, **drops the resume argument, starts a clean new session, and then notifies** (ADR-0208 refers to it). But the backend is split **one per directory**, so it is not pluggable. ★**Its 「Orchestration」 is not a feature where the app drives things by itself**★ — the running app runtime holds Run · Task · Dispatch state and routing but does not schedule or place workers, and **a coordinator agent drives that runtime via CLI + skills** (the source that document read is the 2026-08-20 snapshot `df7460af` — details including the Windows-side issue status = `docs/research/oss-peer-hands-on-2026-09-23.md`).
  - **zellij** (`zellij-org/zellij` · 35.5k★ · MIT · active) — a multiplexer. It carries session survival + client reattach + the pane/tab structure as server-client.
  - **ttyd** (`tsl0922/ttyd` · 12.4k★ · MIT · active) — a minimal implementation that carries a PTY over websocket and **negotiates the size** (resize message → both ConPTY and POSIX).
  - **paseo** (`getpaseo/paseo` · 17.7k★ · active) — **the daemon owns the agents and desktop · web · mobile · CLI attach to it**. Multi-client reattach overlaps with ours. **There is no PTY on the agent path** (SDK · JSON-RPC per backend, and for codex `codex app-server` + line-delimited JSON-RPC). ★**But 「그래서 전송 계층은 참조가 안 된다」 (so its transport layer is not a reference) was too strong**★ — for its own shell tab it ships node-pty and **records the ConPTY workaround in a comment** (measured 2026-09-19). The agent transport is not a reference, but **the terminal-tab transport is.** Resume is delegated to the backend — one handle (`nativeHandle`) holds the codex thread id · the claude resume token, and on reconnect it re-streams the provider history. ★**The license is Apache-2.0, not AGPL-3.0**★ — it carries the usual notice that included third-party components keep their own licenses, and because of that GitHub's automatic detection fails with `NOASSERTION`. ★Do not read that detection failure as 「라이선스가 어긋났다」 (the license is inconsistent)★ — the LICENSE text carries the full Apache-2.0 text (a misreading caught by the adversarial review, 2026-09-19).
  - **t3code** (`pingdotgg/t3code` · 23k★ · MIT · active) — the server owns the provider · PTY · git · files, and desktop · web · mobile attach **over authenticated RPC (HTTP+WS)**. The backend is an adapter seam (`ProviderAdapter`), and it has an ACP client and a codex app-server client separately. ★**But that combination is not a unique axis — paseo has the same shape**★ (adapter separation + a direct codex implementation + a generic ACP adapter + provider plugins. Caught by the adversarial review, 2026-09-19). **So this is not a 「새 축」 (new axis) but a more active second sample of the same shape**, and its value is ① releases are alive and there is a Windows installer ② **one server owns** both the PTY and the structured path. Because the axes overlap, **if you have already read paseo, there is little new to learn here.**
  - **vibe-kanban** (`BloopAI/vibe-kanban` · Apache-2.0) — a manager that starts one agent per worktree as a CLI subprocess (Rust + TS/React). This repo cites it in places such as these (not exhaustive — **how to find them = `git grep -n -i "vibe.kanban"`**) — ① one sample in a third-party manager comparison (`docs/research/multi-agent-hosting-orchestration-research-2026-06-22.md` §B) ② a comparison of the **tool description size** of inter-agent messaging (97 bytes alone — ADR-0211) ③ a precedent for migrating the codex app-server protocol (`newConversation` → `thread_start`/`thread_fork` — `docs/process/S21-codex-backend/trd-phase2a.md` D5 · the raw source that it uses the official `codex_app_server_protocol` crate = `.claude/handoff/attachments/codex-app-server-survey.md:61`) ④ ★**it backed one design decision**★ — it is a peer precedent cited together with paseo when the codex process model was fixed as 「대화마다 하나」 (one per conversation) (`.claude/handoff/history/20260908-013000-codex-phase1-착지-리뷰-FIX-대기.md:148`). ★**The README announces its sunsetting**★ (`README.md:19`) — look at the design only.
  - **tmux** (`tmux/tmux` · ISC) · **mosh** (`mobile-shell/mosh` · GPL-3.0 + OpenSSL linking exception) · **gotty** (`sorenisanerd/gotty` · MIT) · **cline** (`cline/cline` · Apache-2.0) — references for the initial design (moved over from the old `references\` · licenses checked against the text of each clone's `LICENSE`·`COPYING`, 2026-09-23). **tmux·mosh** = two of the three great daemon references (ADR-0013 — tmux = daemon model · attach/detach · control mode · mosh = remote · reconnection robustness) and backed the prior art for daemon lifetime · console viewer separation (ADR-0015) and the gap analysis (`docs/process/step-log.md:122` — WS keepalive · resize negotiation). **gotty** = a PTY→WebSocket bridge, an auxiliary transport reference (ADR-0013). ★**But because it is 「보조」 (auxiliary), do not read that it can be deleted — live code leans on that pattern**★: the resize that sends the initial size once right after subscription is written down as the gotty pattern (`src/components/slot/TerminalSlot.tsx:331` · `src/lab/terminal/TerminalView.tsx:10,44`). **cline** = a chat-rendering reference — ADR-0050 removed the leaf-component port and its Apache-2.0 attribution (ADR-0048) together, so nothing remains in the codebase (it also appears in ADR-0047's OSS candidate survey).
- **Not yet cloned** (clone when needed — they fill the axes the clones above do not cover. t3code, which used to be here, was cloned, so it was moved above, 2026-09-23)
  - **superset** (`superset-sh/superset` · 14.4k★ · Elastic-2.0 · active) — ★**it re-adopts via a disk manifest**★: the daemon holds the PTY, and after cold restore it reattaches using a pid·port·secret manifest on disk. **It is the only peer on our discovery·portfile axis.** ★Beware the name collision★ — `apache/superset` (74.8k★) is a BI tool and unrelated.
  - **Coder v2** (`coder/coder` · 15.3k★ · AGPL-3.0 · active) — ★**the only external precedent for 「replay 를 밀면서 live 로 넘어가는 그 틈」 (the gap while pushing replay and switching over to live)**★. PR #9094 named and fixed that defect and the reason is written in the commit as is — because a condition-variable wait releases the lock, **output between writing the buffer and being added to the subscriber list was lost**. It is exactly what our 「subscribers lock 보유 중 replay 전송」 (send replay while holding the subscribers lock) invariant (`docs/reference/architecture.md` 「런타임 불변식」 I5) prevents. In addition, **it carries two replay implementations side by side, and its own source calls one of them 「(buggy) buffer replay fallback」** (64 KiB ring buffer · delegation to GNU screen on Linux only).
  - **sshx** (`ekzhang/sshx` · 7.7k★ · MIT · **stagnant since 2025-06**) — ★**it resumes by number**★: the client **itself names where in the stream to resume** with `Subscribe(shell, chunk번호)`, and the server returns chunks from that point. The cap is 2 MiB per shell, and when it overflows the old data is dropped while **the index stays monotonic**, so asking for a trimmed point gives data from the current floor. The closest precedent for our seq dedup axis. Because it is stagnant, **look at the design only**.
  - **qm** (`yc-software/qm` · 15.2k★ · MIT · active) — ★**a third resume model that is neither reattach nor CLI resume**★: it does not use a PTY at all, an append-only record is **the sole source of the model's context**, and an idempotency key recovers the same child. The backend is a harness router + one file per backend. **A counterexample that stops us from assuming that the resume shapes we know are only two.**
  - **ACP** (`agentclientprotocol/agent-client-protocol` · 4.3k★ · Apache-2.0 · active) — not a tool but a **protocol** (JSON-RPC 2.0 over stdio). The client starts the agent as a child and **the agent issues the `sessionId`**. **Resume has two branches** — `session/load` (rewinds the history) · `session/resume` (does not rewind). ★**Do not write 「신뢰 게이트가 없다」 (there is no trust gate) — it has optional agent authentication**★ (`authenticate` · `authMethods` · terminal authentication · `logout`). What we lack is **binding the hook origin to the provenance of the resume token**, and this spec does not standardize that (an exaggeration caught by the adversarial review, 2026-09-19). Adopted by Zed · JetBrains · Kiro. A branch that solves 「백엔드 확장」 through a protocol rather than code.
