구조

웹뷰 슬롯 하나에 Claude·Codex 의 5시간·주간 남은 한도를 작게 띄운다. 슬롯이 묻고, 데몬은 캐시로 답하거나 — 기한이 지났으면 — 짧게 뜨는 CLI 로 조회한 뒤 답한다.

주의출시 전 법무·보안 확인 필요 — A 방식도 검토 범위에 든다. 이 문서는 판단하지 않는다(표지만).

02구조

묻는 길 둘, 채우는 길 둘

묻기 — 웹뷰(wire) · LLM(버스), 같은 서비스로 능동 조회 — 기한 지남 또는 ⟳ 줍기 — 대화 스트림에서 공짜로

데몬 코드에 벤더 이름이 없다 — 회사 목록·쿨타임·시한은 backend 등록부가 준다. 방송이 없으므로 주운 값은 다음 요청(≤ 60초)에 화면에 닿는다.

03요청 흐름

요청 하나에 답 하나 — 판정은 셋

① usage.get · 기한 전

캐시로 즉시 답

  • 대기 맵을 먼저 병합 · 리셋 지난 창에 만료 래치
  • 기한 전 — 조회 안 나감
즉시 캐시 (Cached)
② usage.get · 기한 지남

조회한 뒤 답 — 최대 5초

  • 조회 시작 · 이미 진행 중이면 합류(회사당 조회 1회)
  • 5초 안에 끝남 → 새 값 · 실패면 캐시 + 실패 상태(작은 표시엔 ! 배지)
5초 넘음 → 캐시 + 「갱신 중」. 조회는 계속 돌고 결과는 다음 요청에
③ usage.refresh (⟳)

쿨타임 무시 — 둘만 막는다

  • 거절 중 → 조회 안 나감 · 캐시 + 「거절됨 — N분 뒤」
  • 직전 조회 끝 뒤 30초 안 → 캐시
  • 그 밖 → ②와 같다
조회가 끝나면(성공·실패·시한) 쿨타임을 다시 센다

회사끼리는 서로 안 기다린다. 요청이 5초에 포기해도 조회 스레드의 완료 가드가 「진행 중」을 반드시 푼다.

05기동·연결

새 메시지 없이 전부 선다

#상황동작
1데몬 기동 직후 첫 요청거절 파일을 조립 때 먼저 읽는다 — 첫 요청도 저장된 거절을 못 넘는다
2데몬이 뜨기 전셸이 즉시 NOT_CONNECTED → 이전 값 또는 「없음」 · 연결되는 순간 바로 요청
3빈 캐시에 첫 요청조회 1회, 답 약 1초 · 동시 요청은 회사별로 합류 · 회사끼리 안 기다림
4데몬만 재시작대기 요청은 오류로 깨어나 이전 값 유지 → 재연결 때 재요청 · 캐시는 비고 거절 파일은 남음
5기동 경합조회는 별 프로세스·별 Job — 특별 처리 없음
6조회 중 데몬 종료분리 스레드라 종료가 안 기다림 · Job 이 닫히며 자식 트리가 죽음
7레이아웃 영속(미래)복원된 슬롯이 부팅 즉시 요청해도 1–3 이 그대로 덮음
