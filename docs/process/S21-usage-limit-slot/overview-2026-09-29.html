정상 조회 실패 거절됨 그 밖

← 그림은 옆으로 밀어서 봅니다.

  • 「거절됨」은 지금 확인된 CLI 에선 드문 길이다 — Claude 2.1.280 은 429 를 「조회 실패」로 준다(CLI 코드 정독 · 실측 아님). Codex 오류는 「로그인 필요」나 「조회 실패」로만 간다.

04예시 타임라인

세 가지 장면

화면 줄은 7단계가 붙은 뒤의 모습이다. 시각은 예시이고 간격은 비례가 아니다.

정상 조회 실패 거절됨 / 거절 기한 리셋됨 — 갱신 대기

(a)조회 실패 중 에이전트가 값을 계속 보낸다

(b)429 거절 중 값이 온다 — D22 = C

30분은 예시 — 상류가 대기 시간을 안 주거나 깨진 값을 주면 5분, 길어도 24시간으로 자른다. 14:30 조회는 그 회사가 구독 중일 때만.

(c)리셋 시각이 지난다

에이전트가 없으면 다음 자동 조회가 새 값을 가져올 때 풀린다. 한 번 선 「리셋됨」은 시계가 뒤로 가도 풀리지 않는다.

← 그림은 옆으로 밀어서 봅니다.

05자동 조회 시점

스케줄러는 언제 조회하나

다음 자동 조회 = 늦은 쪽(「마지막 조회」와 「두 창이 다 새로 들어온 때」 중 나중 것 + 15분, 거절 기한) — 기준점이 없으면(켠 뒤 첫 구독) 거절 기한, 그것도 없으면 곧바로.

← 그림은 옆으로 밀어서 봅니다.

  • 한 계정에 조회는 한 번에 하나 — 겹친 요청은 그 조회에 합류한다. 시한 Claude 15초 · Codex 30초.
  • 절전에서 깨면 놓친 간격마다가 아니라 한 번만 조회한다.
  • LLM 의 usage.get 은 구독이 없어도 기한이 지났으면 조회한다.
