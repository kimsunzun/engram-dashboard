00작은 표시 · 반영 완료

작은 표시 — 아이콘·세로 정렬·리셋 시각, ⟳ 는 내용 바로 옆 하나

전에 여기 있던 「수정안 미리보기」는 그대로 구현했고, 그 뒤 ⟳ 자리까지 정해 반영했습니다(2026-09-29·30 사용자 결정). 아래는 지금 화면 캡처입니다 — 왼쪽부터 넓은 순.

1단계 (넓을 때) — 회사마다 한 줄에 5시간·주간. 두 회사 줄의 칸(창 이름·막대·%·리셋)이 세로로 맞습니다. 막대가 남는 폭을 채우므로 ⟳ 는 내용 끝, 곧 슬롯 오른쪽에 붙습니다.

2단계 (중간) — 창마다 한 줄. 회사 아이콘이 그 회사의 두 줄에 걸칩니다. ⟳ 는 역시 내용 바로 옆입니다.

3단계 (좁을 때) — 아이콘 + 남은 % 숫자만(5시간·주간). ⟳ 는 숫자 바로 옆에 붙고 슬롯의 나머지는 비워 둡니다. 숫자 뒤에 약 14px 여유를 남겨 둡니다.

3단계 — 새로 고치는 중 — 아이콘 옆에 도는 표식이 생겨 숫자가 밀리지만, 그 약 14px 여유를 쓰므로 ⟳ 는 움직이지 않습니다(왼쪽 그림과 같은 자리).

  • 리셋 시각은 「리셋 00:58」 꼴 — 오늘이 아닌 날이면 요일 대신 날짜로 「리셋 10/1 01:48」. 남은 시간(「N 뒤」)은 팝업에만 둡니다. 3단계는 %만 보이고 리셋 시각도 팝업에서 봅니다.
  • ⟳ 는 작은 표시에 하나 — 누르면 켠 회사(Claude·Codex)를 함께 새로 고칩니다. 세 단계 모두 내용 바로 옆에 있고, 두 회사를 다 끄면 ⟳ 도 사라집니다.
  • 누르는 간격 제한(30초)은 없앴습니다. 조회가 도는 동안 누른 것은 무시하고(도는 표식이 보이는 동안), 막는 경우는 서비스가 거절한 동안(「거절됨 — N분 뒤」)뿐입니다 — 켠 회사가 전부 거절 중이면 ⟳ 가 흐려지고 눌러도 요청이 나가지 않습니다. 일부만 거절 중이면 나머지만 새로 고칩니다.
  • 새로 고치는 동안에도 폭 단계는 바뀌지 않습니다 — 단계를 고를 때 도는 표식 자리까지 미리 셉니다.
  • ⚠ 는 없앴습니다 — 색(초록 / 주황 / 빨강)이 대신합니다. 퍼센트는 남은 양입니다.
  • 회사 아이콘은 자리표시입니다 — 최종 모양은 아직 정하지 않았습니다.
00팝업

작은 표시를 누르면 여는 상세 — 남은 시간과 켜고 끄기는 여기

작은 표시 아무 곳이나 클릭하면 열립니다. 켠 회사마다 상세를 전부 보이고, 맨 아래 한 줄에서 회사별로 켜고 끕니다. 팝업엔 ⟳ 가 없습니다 — 새로고침은 작은 표시의 ⟳ 하나입니다.

다크 테마 — 오른쪽 위가 누른 작은 표시, 가운데가 팝업입니다. 슬롯 가장자리에서 열어도 잘리지 않게 슬롯 밖으로 뜹니다(여기선 왼쪽으로).

라이트 테마 — 같은 내용, 배경만 밝게.

e-ink 테마 — 색 대신 채움 모양으로 가릅니다(주황 구간 = 빗금).

  • 회사마다 — 아이콘 + 이름 · 플랜(값이 있을 때만, 예 「플랜: max」) · 5시간·주간 막대와 남은 % · 모델별 창이 있으면 그 줄도(그림의 Fable · gpt-reserve) · 「사용량 페이지 ↗」 링크(마우스를 올리면 목적지 설명).
  • 시간은 「리셋 11:29 (4시간 36분 뒤)」 꼴 — 리셋 시각 + 남은 시간. 다른 날이면 「리셋 10/4 11:59 (4일 5시간 뒤)」. 줄 끝엔 그 값의 나이(「1분 전」·「방금」).
  • 새로 고치는 동안 회사 이름 줄 끝에 「갱신 중」이 붙습니다. 팝업을 연 채 작은 표시의 ⟳ 를 눌러도 팝업은 닫히지 않습니다 — 「갱신 중」을 보며 누를 수 있게.
  • 문제가 있으면 맨 위에 그 회사의 상태 한 줄(조회 실패·거절됨·로그인 필요 등)이 뜹니다 — 작은 표시의 ! 배지에 마우스를 올렸을 때와 같은 문장입니다.

맨 아래 「슬롯에 표시: ☑ Claude ☑ Codex」

Codex 를 끈 모습 — 상세엔 켠 Claude 만 남고, 끈 Codex 는 체크 줄에만 있습니다(다시 켤 자리).

둘 다 끈 모습 — 작은 표시엔 「클릭해서 표시할 항목 고르기」 한 줄(⟳ 없음), 누르면 체크 줄만 있는 팝업.

  • 끈 회사는 작은 표시·팝업 상세 어디에도 없고, 조회하지도 않습니다 — 구독에서 빠지므로 그 회사 값은 오가지 않습니다.
  • 슬롯 우클릭 메뉴엔 사용량 항목이 없습니다 — ⟳ 와 표시 체크 둘 다 뺐습니다(2026-09-29 사용자 결정 — 켜고 끄기는 팝업으로, ⟳ 는 작은 표시로). LLM 은 같은 동작을 명령(usageSlot.refresh · usageSlot.toggleClaude · usageSlot.toggleCodex)으로 부릅니다.
  • Codex 끈 모습·둘 다 끈 모습은 2026-09-30 새벽 캡처입니다(⟳ 자리를 옮기기 전) — 팝업 부분만 잘라 실었고, 그 부분은 지금과 같습니다.

03★확인해 주세요★

메인이 대신 정한 것들 — 문구·동작과 이유

기획 문서(PRD·TRD)가 세부까지 정하지 않은 부분은 구현하면서 메인이 하나를 골라야 했습니다. 각 항목의 실제 문구·동작과 그렇게 고른 이유입니다. 설계서 이탈 표시는 PRD·TRD 에 적힌 것과 다르게 구현된 항목입니다.

01
사용량 정보를 못 받을 때 문구
「이 계정의 한도 정보를 받을 수 없음」
이유 — 원인(로그인 문제인지, CLI 가 없는지, 일시 오류인지)을 문구에서 단정하지 않고 중립적으로 표현했습니다.
02
새로고침(⟳) 버튼 위치설계서 이탈해결 · 2026-09-30
팝업(회사별 카드마다 하나)과 우클릭 메뉴 두 곳에만 있습니다. 가장 좁은 3단계 화면에는 없습니다.
이유 — PRD(R12)는 「세 곳」을 요구했지만, 가장 좁은 표시에는 ⟳ 를 넣을 자리가 없어 뺐습니다.
지금 — ⟳ 는 작은 표시의 버튼 하나로 바꿨고(팝업·우클릭 메뉴의 ⟳ 는 없앰, 2026-09-29 사용자 결정 · ADR-0258 — 팝업의 회사별 ⟳ 는 2026-09-30 ADR-0259 로 되살림 · 구현 전), 세 단계 모두에 있습니다. 3단계에서 ⟳ 가 내용과 멀리 떨어지던 문제는 내용 바로 옆에 붙이는 것으로 정해 반영했습니다(2026-09-30 사용자 결정). → 「작은 표시」
03
메뉴에서 회사 표시를 껐다 켤 때바뀜 · 2026-09-30
슬롯 내용을 부분 수정하지 않고 통째로 다시 그립니다(전체 교체).
이유 — TRD 가 고른 방식입니다. 그 순간 LLM 이 같은 슬롯을 다른 용도로 바꾸고 있었다면 그 변경과 겹칠 수 있는데, 드문 경우라 받아들였습니다.
지금 — 켜고 끄기는 팝업 맨 아래 「슬롯에 표시」로 옮겼고, 체크 하나는 자기 회사 칸만 셸에 보냅니다. 셸이 레이아웃 잠금 안에서 그 칸만 바꾸고 나머지는 지금 값을 지킵니다(새 셸 커맨드 set_usage_slot). 전체 교체를 버린 이유 = 두 체크를 빠르게 연달아 누르거나 LLM 이 동시에 쓰면 서로를 덮어서입니다(ADR-0258 · TRD §3 #102 ⑤). 반영 전에 같은 체크를 다시 누르면 두 번째 누름은 사실상 무시됩니다(현행 유지 — 사용자 결정 2026-09-30). → 「팝업」
04
칸 높이가 낮으면 곧바로 가장 좁은 3단계로설계서 이탈바뀜 · 문구 정정
너비가 넉넉해도 세로 공간이 부족하면 1·2단계를 건너뛰고 3단계로 갑니다.
이유 — 설계서는 너비만 기준으로 정했지만, 리뷰에서 「경고 배지는 어떤 크기에서도 보여야 한다」(PRD R31)는 지적이 나와 높이 조건을 추가했습니다.
지금 — 높이는 2단계에서만 봅니다. 1단계가 들어갈 너비면 높이와 상관없이 1단계(두 줄)이고, 1단계가 안 들어가 2단계(네 줄)를 고를 때 칸 높이가 모자라면 3단계로 갑니다. 이유(어느 크기에서도 ! 배지가 잘리지 않게)는 그대로입니다.

연결이 끊겼다 되살아나면 사용량 값을 다시 당겨옵니다설계서 이탈
소켓 재연결 시 웹뷰가 사용량 값을 능동적으로 다시 요청합니다.
이유 — 설계서엔 없던 동작인데, 리뷰에서 「데몬 시작 직후 첫 조회가 실패하면 그 뒤로도 값이 영영 안 온다」는 구멍이 지적돼 추가했습니다.
12
숨김으로 줄어드는 중 같은 관심이면 타이머를 유지
트레이로 숨겼다가 1.5초 안에 다시 같은 회사가 보이면, 대기 타이머를 취소하는 대신 그대로 둡니다.
이유 — 탭을 빠르게 오가거나 트레이가 순간 깜빡이는 정도로 매번 타이머를 리셋하지 않기 위해서입니다.
13
메뉴 항목의 체크·활성 조건 — 새 스키마해당 없음 — 메뉴 항목 제거
메뉴 항목에 체크 표시(checked)와 활성 조건 함수(enabled(ctx))를 더했습니다 — ADR-0252.
이유 — 처음엔 기존 명령 조건식(Command.when)을 넓혀 쓰려 했지만, 그러면 사용자에게 값이 새는 경로가 생긴다는 리뷰 지적을 받아 되돌리고 이 방식으로 바꿨습니다.
지금 — 슬롯 우클릭 메뉴의 사용량 항목이 전부 없어져(ADR-0258) 이 슬롯에서 확인할 것이 없습니다. 두 칸 자체는 공용 메뉴 기반에 쓰는 곳 없이 남아 있고, 걷을지는 뒤로 미뤘습니다(메인 결정 2026-09-29 · TRD §3 #102 ②).
14
새로고침 스피너는 「동작 줄이기」·e-ink 에서도 돕니다
접근성 설정으로 애니메이션을 줄이거나 e-ink 테마를 써도 ⟳ 스피너는 계속 회전합니다.
이유 — 이번에 새로 정한 게 아니라, 2026-08-24 에 이미 내려진 사용자 결정을 그대로 따랐습니다.

그 밖에 아직 사용자 확인이 남은 것

  • 반영 완료위 「수정안 미리보기」 — 아이콘·세로 정렬·⚠ 제거·리셋 시각 표시로 바꾸는 안, 구현 전 확인 필요 → 확인받아 구현했고, 그 절은 지금 모습(「작은 표시」)으로 바꿨습니다.
  • QA 바인딩 문서의 설정 오류 정정 묶음(3건) + 슬롯 레시피 + engram 토큰 레시피
  • CLAUDE.md 에 박힌 테스트 수치(워크스페이스 결과 줄·통과 수 등) 최신화
  • 이 브랜치를 지금 push 해도 되는지

05알려진 한계

고치지 않고 받아들인 것

  • 새 의존성이 들어온 직후 개발 모드 첫 로드가 빈 화면으로 뜰 수 있음 — 새로고침 한 번이면 해결됩니다.
  • 팝업의 경과 시간 표시가 최대 60초까지 늦게 갱신될 수 있습니다.
  • 막대 정렬이 1~2px 미세하게 어긋나는 곳이 있습니다.
  • 사용량 값을 실제로 내보내는 시점을 로그로 남기지 않습니다 — 문제가 생겨도 그 지점만으로는 추적이 어렵습니다.
  • 드물게 동시에 64개 이상의 usage.* 호출이 몰리면(비정상 상황) 다른 버스 명령이 최대 5초까지 밀릴 수 있습니다(설계상 받아들인 위험).
  • RUST_LOG=trace 로 두면 소켓 프레임 내용이 그대로 로그에 찍힙니다 — 이번에 새로 생긴 문제는 아니고 예전부터 있던 동작입니다.
