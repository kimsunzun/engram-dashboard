## 1. 무엇·왜

- 여러 에이전트가 5시간·주간 한도에 걸려 멈춘다. 웹뷰 슬롯에 새 타입을 두어 **Claude·Codex 의 남은 한도를 한 곳에 작게** 보인다.
- 지금 데몬은 대화 중 오는 한도 정보를 버린다 — Claude `rate_limit_event` 는 건너뛰고, Codex `account/rateLimits/updated` 는 받고 버린다(UI §4-1·§4-2). 줍기는 새로 까는 배관이다.
- 분할 레이아웃의 한 칸에 두는 선례는 조사한 제품에서 찾지 못했다 — 최근접 = 사이드바 상시 게이지(TokenTelemetry)(UI §0-6).

## 3. 요구사항

**작은 표시(상시)**
- **R1** 퍼센트 방향 = **남은 양**(Codex 방식 — 쓸수록 막대가 줄어든다). Claude 는 사용률을 주므로 100 에서 뺀다. (결정)
- **R2** 회사별로 두 창(5시간·주간) 모두 · 막대 + % + **남은 시간**. (결정)
  - 남은 시간 요구는 R3 의 1·2단(회사당 한 줄 · 창마다 한 줄)에만 걸린다 — 3단(숫자만)은 % 만 보이고 시간은 팝업으로 간다. (리뷰 반영 기본값 — D16)
- **R3** 슬롯 폭에 따라 회사당 한 줄 → 창마다 한 줄 → 숫자만으로 줄어든다. 판정은 글자 수가 아니라 **실제 그려진 폭** 기준. (결정)
  - 3단 폭보다 더 좁으면 줄바꿈·스크롤 없이 말줄임(…)으로 자른다. (리뷰 반영 기본값 — D16)
- **R4** 두 회사를 다 끄면 "우클릭해서 표시할 항목 고르기" 안내 한 줄. (결정)

**팝업(상세)**
- **R5** 작은 표시를 클릭하면 연다 — 전부 보인다 · **목표 시각**(리셋 시각) · 플랜(값이 있을 때만) · 각 사 사용량 설정 링크 · ⟳. (결정)
- **R6** 링크 이름 = 「사용량 페이지 ↗」 + 마우스를 올리면 목적지 설명. Codex `chatgpt.com/codex/settings/usage` · Claude `claude.ai/settings/usage`. (결정)
- **R7** 보기 전용. 슬롯 밖으로 뜰 수 있다 — 기존 슬롯 우클릭 메뉴와 같은 `position: fixed` 방식. (결정)

**켜고 끄기**
- **R8** 슬롯 우클릭 메뉴에만 둔다 — ⟳ 새로고침 · ☑ Claude 표시 · ☑ Codex 표시. (결정)
- **R9** 켜고 끈 상태는 슬롯 내용 안에 넣어 레이아웃과 같은 수명으로 둔다. 레이아웃 영속이 생기면 따라서 저장된다. (결정)

**색**
- **R10** 남은 양 기준 — 50% 초과 초록 · 50~20% 노랑 · 20% 미만 빨강 + ⚠. (결정)
  - 경계: `x > 50` 초록 · `20 ≤ x ≤ 50` 노랑 · `x < 20` 빨강 + ⚠ (50·20 은 노랑 · 0 은 빨강 · 100 은 초록). 0–100 밖의 값은 막대·숫자 모두 0–100 으로 자른다. "없음"(R21)은 색 없이 중립 회색 "—". **보이는 숫자 = 남은 양을 정수로 내림**(남은 양을 부풀리지 않게 — 19.6 → 19) · **색은 보이는 숫자로 정한다**(숫자와 색이 어긋나지 않게). (리뷰 반영 기본값 — D17)
- **R11** e-ink — 노랑 = 빗금 · 빨강 = 검정 채움 + 굵은 테두리 + ⚠. (결정)

**갱신**
- **R12** 수동 ⟳ = 작은 표시 · 팝업 · 우클릭 메뉴 세 곳. (결정) (→ D11)
- **R13** 줍는 곳 = Claude JSON 모드의 `rate_limit_event` · Codex app-server 알림뿐(이미 읽는 스트림 — 추가 비용 0). 터미널 모드는 두 회사 모두 줍지 않는다. (결정)
- **R14** 두 창이 다 새로 들어오면 쿨타임을 초기화하고, 쿨타임이 지나면 자동 조회한다. (결정) (→ D12)
- **R15** 쿨타임 = 5분. Claude 값은 재론 대상(§5 D1). (결정)
- **R16** 주운 값은 **창 단위로 병합**한다 — 이벤트에 없는 창은 이전 값을 유지한다(통째로 덮어쓰지 않는다). (줍기 결론 1 · UI §2)
  - 줍기(부분 관측)에 빠진 창 = 이전 값 유지 · 능동 조회(전체 응답)에서 null 이거나 빠진 창 = "없음"으로 비운다(출처가 지금 그 창이 없다고 말한 것). (리뷰 반영 기본값 — D18)

**데이터 출처**
- **R17** Claude 능동 조회 = **잠정 B**(Claude Code 토큰 파일을 읽어 비공개 사용량 주소 호출 — 피어 8곳 중 7곳의 방식). A(CLI 에 `get_usage`)는 탐침으로 되는지만 확인한다. (결정 2026-09-27) · **A 탐침 결과: 동작 확인(2026-09-27) — 추천 A**(조회 §7 · → D2).
  - 인증·플랫폼: **A** = 자격증명은 CLI 가 모든 OS 에서 스스로 찾는다(우리 쪽 OS 분기 없음) · **B** = 자격증명 찾기가 OS 마다 다르다(Windows·Linux = 파일 · macOS = Keychain) → OS 분기 함수 하나가 필요하다. 둘 다 로그인 안 됨·인증 오류면 상태 "로그인 필요"(R31).
- **R18** Codex 5시간/주간 분류는 `primary`/`secondary` 자리가 아니라 창 길이 `windowDurationMins`(300 · 10080)로 한다 — `primary` 가 주간인 버킷이 실측됐다. (UI §4-1)
- **R19** Claude 단위를 한 모양으로 맞춘다 — 사용률 0–1(stream)·0–100(`get_usage`·OAuth 주소), 리셋 epoch 초·ISO 8601. (UI §4-2·§4-3 · 줍기 결론 5)
- **R20** `rate_limit_event` 는 두 모양(최상위 `rateLimitType` 한 창 · 비문서 `unifiedWindows`)을 다 느슨하게 받는다 — 버전마다 모양이 다르다. (UI §4-2 · 줍기 결론 5)

**오류·빈 값**
- **R21** null·빠짐은 정상 응답이고 0% 가 아니다 → 0% 로 그리지 않고 "없음"으로 둔다. (조회 §3)
  - "없음" = 그 창에 유효한 값을 들고 있지 않음(절대 0% 로 그리지 않는다). 언제 비우나 = R16 하위 · R32. (리뷰 반영 기본값 — D18)
- **R22** 조회 실패(429 포함)는 마지막 정상값을 덮지 않는다 — 이전 값 유지(단 리셋 시각이 지난 값은 R32). (조회 §1 · 줍기 결론 2)
- **R23** `Retry-After` 가 없거나·깨졌거나·과거거나·`0` 이면 대체 대기를 쓴다(값 = §5 D4). (조회 §1)
- **R24** 거절 중엔 자동·수동(⟳) 모두 즉시 재조회하지 않는다. (조회 §1) (→ D11)
- **R25** 한 계정에 조회는 한 번에 하나만. (조회 §1) (→ D13)
- **R29** 조회 스케줄러는 **회사 계정당 하나** — 모든 슬롯·모든 대시보드 클라이언트가 공유한다(한 번 조회가 전원에게 간다). 수요 = 그 회사를 켠 슬롯이 하나라도 보이는 중. (리뷰 반영 기본값 — D19)
  - ★**자동 조회 규칙은 하나뿐이다**★: 다음 자동 조회 시각 = max(마지막 조회 또는 마지막 쿨타임 초기화 + 쿨타임, 거절 종료 시각). **다른 계기(거절 종료 · 리셋 경과 R32)는 조회를 앞당기지 않는다** — 쿨타임이 이미 찼을 때만 그 시각에 한 번 나간다. 수요가 없으면 나가지 않는다.
  - 줍기의 쿨타임 초기화(D12)는 다음 조회를 미룰 뿐 거절을 줄이지 않는다. 수동 ⟳ 는 D11(쿨타임을 무시하되 거절은 못 넘는다).
  - 쿨타임·거절 대기·값 나이(R32)는 **잠든 시간을 포함한 경과 시간**으로 센다 — 사용자가 시계를 앞뒤로 옮겨도 늘거나 줄지 않는다. 복귀 때 기한이 지났으면 한 번만 조회한다(놓친 간격마다가 아니다). 리셋 시각만 서버가 준 벽시계 값과 비교한다.
  - 데몬 재시작: 값·쿨타임은 메모리뿐이라 사라지고 수요가 생기면 첫 조회가 나간다. **단 거절 종료 시각만은 데몬 데이터 폴더에 적어 두고 재시작 때 읽는다** — 재시작이 거절 중인 주소를 다시 치지 않게.
- **R30** 모든 조회에 타임아웃 — Claude 15초 · Codex 30초(app-server 냉기동 약 10초 관측). 넘기면 프로세스를 죽이고 실패로 세며, 진행 중 자리(R25)를 풀고 다음 자동 시도는 다음 쿨타임. (리뷰 반영 기본값 — D20)
- **R31** 사용자에게 보이는 상태를 가른다 — "설치 안 됨"(CLI 없음) · "로그인 필요"(인증 오류) · "조회 실패 — 다음 시도 HH:MM"(그 밖의 실패) · "거절됨 — N분 뒤"(429 · D11). 실패는 들고 있는 값을 지우지 않는다(R22 · R32 예외). (리뷰 반영 기본값 — D20)
- **R32** 창의 값은 그 창의 리셋 시각까지만 유효하다. 리셋이 지나면 그 창의 %·카운트다운을 숨기고 "리셋됨 — 갱신 대기"를 보인다 — 조회는 R29 의 규칙대로(리셋 경과가 조회를 앞당기지 않는다). **만료는 한 번 관측되면 그 창에 새 값이 올 때까지 유지한다** — 시계가 뒤로 가도 옛 % 가 되살아나지 않는다. 들고 있는 값이 30분보다 오래되면 옛 값으로 보인다(흐리게 + "N분 전") · 팝업은 값마다 나이를 늘 보인다. (→ D10 · 리뷰 반영 기본값 — D21)

**LLM 제어**
- **R26** 사용자 동작마다 LLM 경로를 **기존 명령 표면에** 얹는다 — 슬롯 생성·켜고 끄기 = 기존 `layout.setSlotContent`(R9 — 상태가 슬롯 내용) · 새로고침 · 현재 값 읽기. 새 전역 핸들을 늘리지 않는다. (원칙 「LLM-우선 제어」 · UI §5 ③) (→ D15)
- **R27** 표시 값은 DOM 텍스트로 둔다 — LLM 이 읽는다. (UI §3-5 · §5 ③)

**로컬라이징**
- **R28** 문구는 전부 `t(키)`(ADR-0069) · 날짜·시간은 `Intl` 로케일 포맷. (결정)

**불변 제약 (원칙 — 요구가 아니라 지켜야 할 벽)**
- 벤더 지식(`get_usage`·사용량 주소·app-server 메서드·단위)은 한 곳에 모은다 — 「백엔드 확장」.
- 토큰 위치가 OS 마다 다르다(`~/.claude/.credentials.json` · macOS Keychain · `CLAUDE_CODE_OAUTH_TOKEN` — 조회 §0-1). OS 분기는 그 일을 맡은 한 곳 안에서만 — 「플랫폼 중립」.

## 4. 수용 기준 (화면 실측)

- [ ] `layout.setSlotContent` 로 슬롯을 채우면 두 회사가 창마다 막대 + % + 남은 시간으로 보인다(R2·R26).
- [ ] Claude 사용률 u 가 100−u 로 보이고, 두 회사 막대가 같은 방향으로 준다(R1).
- [ ] 슬롯 폭을 줄이면 회사당 한 줄 → 창마다 한 줄 → 숫자만 순으로 바뀐다(R3).
- [ ] 클릭 → 팝업에 목표 시각 · 플랜(있을 때만) · 「사용량 페이지 ↗」(hover 설명) · ⟳. 슬롯 가장자리에서 열어도 잘리지 않는다(R5–R7).
- [ ] 우클릭 메뉴로 회사별 켜고 끈다 · 둘 다 끄면 안내 한 줄 · 팝업엔 토글이 없다(R4·R7·R8).
- [ ] 세 구간 색 + 20% 미만 ⚠ · e-ink 테마에서 빗금 / 검정 채움 + 굵은 테두리 + ⚠(R10·R11).
- [ ] JSON 모드 에이전트의 턴 뒤 값이 바뀐다 · 터미널 모드 에이전트뿐이면 자동 조회·⟳ 로만 바뀐다(R13·R14).
- [ ] 한 창만 실린 이벤트 뒤 다른 창 값이 지워지지 않는다(R16).
- [ ] 값이 null·빠진 창은 0% 가 아니라 "없음"(R21).
- [ ] 429 뒤 마지막 값이 남고, 거절 중 ⟳ 가 요청을 내보내지 않는다(R22–R24).
- [ ] 명령 표면으로 켜고 끄기·새로고침·값 읽기가 된다 · `rg "\)\.__ENGRAM_|\)\.__engram" src/ -g '!*.test.*'` 결과가 늘지 않는다(R26·R27).
- [ ] 새 문구가 `t()` 경유 · 시각이 로케일 포맷(R28).
- [ ] 남은 양 정확히 50·20 = 노랑 · 0 = 빨강 + ⚠ · 100 = 초록 · 범위 밖 값은 잘려서 그려진다 · "없음" 은 회색 "—"(R10).
- [ ] 경계 양쪽 값: 남은 19.6 → "19%" 빨강 · 20.4 → "20%" 노랑 · 50.9 → "50%" 노랑 · 51.0 → "51%" 초록(R10).
- [ ] 거절 종료·리셋 경과가 쿨타임 전이면 조회가 앞당겨지지 않는다 · 거절 중 데몬을 재시작해도 거절이 끝날 때까지 자동 조회가 나가지 않는다(R29).
- [ ] 리셋이 지나 숨겨진 창은 시스템 시계를 리셋 전으로 되돌려도 옛 % 가 다시 보이지 않는다(R32).
- [ ] 숫자만 단계보다 좁히면 말줄임으로 잘리고 줄바꿈·스크롤이 생기지 않는다 · 남은 시간은 1–2 단계에만 보인다(R2·R3).
- [ ] 사용량 슬롯 둘 · 대시보드 창 둘을 띄워도 조회는 회사당 한 번씩만 나간다 · 슬롯을 모두 닫으면 자동 조회가 멈춘다(R29).
- [ ] 거절 중 대화로 두 창이 들어와도 거절이 짧아지지 않고, 조회는 max(거절 종료, 쿨타임 만료) 시각에 한 번만 나간다(R29).
- [ ] 응답 없는 조회 프로세스는 제한 시간 뒤 정리되고 다음 조회·⟳ 가 막히지 않는다(R30).
- [ ] CLI 미설치 · 로그아웃 · 기타 실패 · 거절이 서로 다른 문구로 보이고, 실패해도 들고 있던 값이 남는다(R31).
- [ ] 리셋 시각이 지나면 그 창의 % 와 남은 시간이 사라지고 "리셋됨 — 갱신 대기" 가 보인다 · 30분 넘은 값은 흐리게 + "N분 전"(R32).

## 5. 미결 결정

### 5-1. 사용자 결정 대상

- **D1** Claude 쿨타임 — 5분(결정) ↔ 15분(피어 하한 Orca·ClaudeBar — 조회 제한 증거). **15분도 안전이 증명된 간격이 아니다**(조용한 기간 뒤 한 번 호출에 1시간 거절 사례). (조회 §0-3·§1)
- **D2** A/B 확정 — **A**(추천: 탐침으로 동작 확인 · 앱이 토큰을 만지지 않음 · 짧게 뜨는 프로세스로 조회당 약 1.2초) ↔ **B**(사용자 잠정 선택). 탐침 = 원시 CLI 2.1.280 에 `get_usage` 직송 → `initialize` 없이·첫 턴 전에 성공, 모델 호출 없음(가능성 높음). 미검 = 부작용 줄이는 인자 없는 우리 인자 그대로 · 떠 있는 에이전트 프로세스에 보내기 · "not supported in this context" 분기(모드 미식별). (조회 §7)
- **D3** ★**출시 전 법무·보안 확인 필요**★ — B 는 「개발자는 Claude.ai 자격증명이나 세션 토큰을 수집·저장·중개할 수 없다」 문장과 모양이 겹치고, A 도 Agent SDK 를 이름으로 든 API 키 문장의 검토 범위에 든다(조회 §0-5). 결정이 아니라 표지다 — 이 문서는 판단하지 않는다.

### 5-2. 기본값 (메인이 정함 — 사용자가 바꿀 수 있다)

- **D4** `Retry-After` 없음·깨짐·과거·0 이면 5분 대기(ClaudeBar 값). (R23 · 조회 §1·§2)
- **D5** B 를 고를 때만: 토큰은 읽기만(갱신은 CLI 몫) · UA 흉내 안 함. A 면 해당 없음. (조회 §0-1·§2)
- **D6** Codex 능동 조회 = 돌고 있는 Codex 에이전트가 없어도 짧게 뜨는 app-server 로 `account/rateLimits/read`(Claude A 와 같은 모양). 냉기동이 느릴 수 있다(관측 약 10초 — TRD 에서 확인). (UI §4-1)
- **D7** `get_usage` 는 돌고 있는 에이전트 프로세스에 보내지 않고 따로 짧게 띄운 프로세스로(턴과 섞이지 않게). (조회 §1)
- **D8** 팝업 「전부」 = 5시간·주간 + 값이 있는 모델별 주간 창 + 플랜 + 리셋 시각. 크레딧·과금 줄은 뺀다. (UI §1-3·§4-1)
- **D9** 속도(pace) 표시 없음 — 비목표 「소진 예측」에 든다. (UI §1-3·§6-5)
- **D10** UI §6-7 기본 후보 채택 — 오래된 값 표시 · 리셋 지난 옛 % 지우기 · 분 단위 카운트다운. (구체값 = R32)
- **D11** ⟳ 는 쿨타임을 무시하고 바로 조회하되, 거절(429) 중에는 막고 "거절됨 — N분 뒤" 를 보인다. 조회가 끝나면 쿨타임을 다시 센다. (R12·R24)
- **D12** 「두 창이 다 새로 들어오면」 = 마지막 조회 뒤로 두 창이 각각 한 번 이상 새로 들어왔으면(한 이벤트에 같이 올 필요 없다 — Claude 이벤트는 창 하나씩 온다). (R14 · UI §4-2·§9)
- **D13** 계정은 회사당 하나(이 PC 의 CLI 기본 로그인). 여러 계정은 범위 밖. (R25 · 조회 §1)
- **D14** 막대에 ARIA `meter` · 팝업은 키보드 포커스로도 연다. (UI §3-5)
- **D15** LLM 경로 = 슬롯 채우기·켜고 끄기(슬롯 내용)·새로고침·현재 값 읽기. 팝업 열고 닫기는 넣지 않는다(보기 전용). (R26 · 원칙 「LLM-우선 제어」)
- **D16** 남은 시간은 폭 1·2단에만 · 3단은 % 만 · 3단보다 좁으면 말줄임. (R2·R3) (리뷰 반영 기본값 — 확인 필요)
- **D17** 색 경계 `>50` / `20–50` / `<20`(양끝 포함은 노랑) · 0–100 클램프 · "없음" = 회색 "—". (R10) (리뷰 반영 기본값 — 확인 필요)
- **D18** 줍기에 빠진 창 = 유지 · 능동 응답의 null·빠짐 = "없음"으로 비움. (R16·R21) (리뷰 반영 기본값 — 확인 필요)
- **D19** 스케줄러 회사 계정당 하나(전 슬롯·전 클라이언트 공유) · 자동 조회 규칙 하나(max(쿨타임, 거절 종료) — 다른 계기는 앞당기지 않음) · 경과 시간 기준 · 거절 종료 시각만 디스크 저장. (R29) (리뷰 반영 기본값 — 확인 필요)
- **D20** 타임아웃 Claude 15초 · Codex 30초 · 상태 네 가지 구분. (R30·R31) (리뷰 반영 기본값 — 확인 필요)
- **D21** 리셋 지난 창 = "리셋됨 — 갱신 대기"(조회는 R29 규칙 — 앞당기지 않음) · 만료는 새 값까지 유지 · 30분 넘은 값 = 흐리게 + 나이. (R32) (리뷰 반영 기본값 — 확인 필요)
