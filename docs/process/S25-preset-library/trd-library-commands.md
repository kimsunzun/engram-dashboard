## 1. Boundaries and ownership

- **agent owns the vocabulary** — names, args, answer row types, all in the one `declare_commands!` block of `commands.rs` (one block per module — `declare_commands!` doc; `CommandTable::new` takes one declared slice). The handlers live in a new module `library_commands.rs` beside it (the port trait, the verb functions, the refusal → `CommandError` mapping); `make_table` gains a third port argument (B2).
- **The port `LibraryCommandHost`** (agent, name from parent §1-5) — one typed method per library / preset / agent-preset command. Its methods take parsed values (an `AgentId`, never a name — the handler resolves `target` with `commands::resolve`, the same resolver as `agent.spawn`) and answer the declared ok types or a port refusal type agent defines (B1). It also has the read-locked judgement `agent.new {presets}` needs (§4.1).
- **Names are the handler's** — the port answers agents by id only. `agent.presets` and the agent-preset edits fill `name` from the `ResolvedAgent.name` the handler already has from `commands::resolve` (an agent-preset edit never renames); `library.read` fills agent names from one `AgentCommandHost::roster` read and drops an id the roster no longer holds (B18). So the views cross the port without `name` (the port's `agent.presets` view and `library.read`'s agent rows carry the id only); the handler builds the declared row by adding it, and no port answer is rebuilt after its change (ADR-0384 「영향」).
- **asset-library implements it** — `impl LibraryCommandHost for LibraryService` in a new module `host.rs`: parses spellings with the crate's own helpers (`edit::lib_path` · `edit::parse_ref` · `AssetRef::parse`), calls the 9a body, converts the crate-local answer into the declared row types and `LibraryRefusal` 1:1 into the port refusal. It never calls a second body to rebuild an answer and never reads a file back (ADR-0384 「영향」).
- **The manager** — gains the `agent.setWorkspace` and `agent.duplicate` bodies (parent §1-5), a holder-aware reservation table and two new registry methods (§4.2 · §4.3 · B22); `AgentCommandHost` gains one method for each body. The working-folder stat goes through the manager's launch-kit port, so production gets asset-library's bounded IO (B12); no library lock is involved.
- **The daemon only wires** — `make_daemon_table` takes `Arc<dyn LibraryCommandHost>`. Production: `run()` builds the table with `wiring.library` (today the accept-loop function destructures it as `library: _`). The test server (`lib.rs`, its `wiring.library` is `None`) and `saturation_pilot` pass `NoLibrary` (B8); `roundtrip_smoke` passes its real service and plugs the profile-edit port (§4.6). Every other caller of `make_daemon_table` gains the argument: the `control/commands.rs` tests, the `connection_core.rs` tests, `tests/control_agent.rs`, `tests/mail_gate.rs`. `control/catalog.rs` and `control/mcp_server.rs` only mention it in comments and do not change.
- **The CLI does not change** — every new name is reached by the general form `engram <name> --flag value` over `/control/call` (the agent family route `engram agent <verb>` has the fixed list `CLI_AGENT_VERBS`, so the help teaches full names, as it already does for `agent.new`). MCP exposes only the mail tools; commands reach an LLM through the CLI.
- **The help screen** — daemon `control/help.rs` gains `HelpTopic::Library` (section `library`, required); `prompts/engram-help.md` gains the root line and the section. The CLI sends the word as is (the daemon owns the word table).
- **No wire change** — no new wire message, `PROTOCOL_VERSION` unchanged (parent §1-8). No shell or frontend change.

## 3. Refusal → command error

One function in `library_commands.rs` maps the port refusal (ADR-0379):

| Refusal | Bus code | Retained id? |
|---|---|---|
| `Conflict` | `CONFLICT` | no |
| `NotFound` | `NOT_FOUND` | no |
| `InvalidArgument` | `INVALID_ARGUMENT` | no |
| `Unavailable` | `CONFLICT` | no (incl. `library-config-write-failed` — ADR-0381) |
| `Internal` (`profile-edit-unavailable`) | `INTERNAL` | yes (ADR-0379 decision 5) |
| `Store(StoreError)` | agent `store_command_error` + `store_error_reason(PROFILES_FILE, …)` | as the agent decides (write IO = `INTERNAL`) |

- **Shape** — `CommandError.args` = `{code, args, line?}` of the `Reason` (the same keys as one `args.reasons` row, agent `launch::put_reason`); the message is one readable English line naming the command and the code (B3). A Store refusal carries no args, as every other registry-writing command.
- **Argument errors the handler raises itself** (blank values, `items` and `folders` both or neither) are `INVALID_ARGUMENT` without args, like `reject_blanks`; target resolution failures are the resolver's (`NOT_FOUND` / `CONFLICT` with candidates).
- **Path spellings are the host's** — a `path` / `folder` / `parent` / `from` / `to` that is not a library path (or, for `preset.get`, not an `AssetRef`) is refused by `host.rs` `InvalidArgument` · `item-path-invalid`, the code the bodies use (`edit::lib_path` · `edit::parse_ref`): this covers `library.read`, `list` and `refresh` `folder`, `preset.get`, `preset.check` and every edit.
- **`library.list`** — the body answers a bare `Reason` (`library-unavailable`, no class); the host gives it class `Unavailable` (→ `CONFLICT`).
- **Codes per command** — exactly the ones the 9a bodies document (no new refusal codes from 10a except B9 and B12):
  - every library read: `library-unavailable`; `read` · `preset.get`: `not-found`; `preset.get`: the reader's code, `wrong-kind`;
  - `setRoot`: `item-path-invalid` (relative) · `library-config-read-only` · `library-root-unusable` · `library-config-write-failed`;
  - every preset edit (`edit.rs` header): `library-unavailable` · `root-generation-stale` · `item-path-invalid` · `wrong-kind` · `path-through-link` · `not-found` · `library-read-failed` · reader/writer codes (`WriteError::to_reason`) · `library-write-failed`; plus `reorder`: `reorder-order-mismatch` · `rev-mismatch`; `save`: `preset-save-refused` · `rev-mismatch`; folder `add`: `preset-folders-refused`; `setBackend`: `backend-tag-unknown`;
  - `previewFolder`: `backend-tag-unknown`; `check`: `library-unavailable`;
  - agent-preset bodies (`agent_edit.rs` header): `profile-edit-unavailable` · `root-generation-stale` · `not-found` `{agent}` · Store; `attach`: `library-unavailable`; `detach`: `item-path-invalid` · `default-preset-detach`; `reorder`: `reorder-order-mismatch` · `rev-mismatch`;
  - `relink`: `item-path-invalid` · `library-unavailable` · `root-generation-stale` · `not-found` · `path-through-link` · `library-read-failed` · `relink-kind-mismatch` · `profile-edit-unavailable` · a stop before any write = its own refusal;
  - `newFolder` · `newFile`: `item-path-invalid` · `library-unavailable` · `root-generation-stale` · `path-through-link` · `library-read-failed` · `name-exists` · `not-found` · `library-write-failed`;
  - `agent.new {presets}`: `library-unavailable` · `root-generation-stale` (both `CONFLICT`, nothing created — §4.1) beside its existing refusals;
  - `agent.setWorkspace`: `workspace-not-found` · `workspace-locked` · `NOT_FOUND` (agent gone) · Store (§4.2); `agent.duplicate`: the `create_error` mapping (`RosterFull` · name space exhausted → `CONFLICT`), the backend policy refusal (`policy_refusal` — `INVALID_ARGUMENT`, §4.3), Store (§4.3).
- **Not refusals** — skips (`skipped[]`), a relink `stopped`, a refresh `errors[]`: answers (ADR-0379 decision 6, ADR-0384 decision 8).
- **Advertised errors** — each declaration lists the codes its refusals can map onto (`errors [NOT_FOUND, CONFLICT]` or a subset); `INVALID_ARGUMENT` · `INTERNAL` come from the table.

## 4. Behaviour

### 4.1 `agent.new {presets}`

- `verb_new` builds the new profile (`new_profile`), then — when `presets` is given — asks the library port to judge it: one read lock over the catalog, the same pure judgement `attach` uses (`agent_edit::attach` over a `CatalogLookup`, the profile outside the registry) → accepted list + skips (G41 partial apply). The profile is created with the accepted list already in `presets` (`create_agent`, one registry write) — no profile-edit-port step after the create (B10; the port doc already says `agent.new` writes a new id outside the port).
- Naming a library preset while no first scan could be applied: refuse the whole call `CONFLICT` `library-unavailable`, nothing created — the attach rule (§12 O3).
- **Root generation** (user 2026-11-19) — `agent.new` takes the optional `root_generation` like `agent.attachPreset`; the judgement compares it inside its read lock, and a stale one refuses the whole call `CONFLICT` `root-generation-stale`, nothing created. So A7 「every agent-preset edit」 holds for `agent.new {presets}` too. Without `presets` there is no judgement and the argument is not read.
- The judgement passes the first-scan entrance, which has no deadline of its own; a cold library can push the call past the ordinary seat (§10 R1).
- No backend policy change; `llm_creation_refusal` and the store refusals stay as they are. The answer adds `skipped`.

### 4.2 `agent.setWorkspace` (manager body — parent §1-5 · ADR-0321)

Order (B12):

1. Normalize the spelling (`normalize_spelling`, as `new_profile`). Stat the folder through the launch-kit port's bounded folder stat, outside every lock — production = asset-library `BoundedIo` on a read budget (`IO_LIMIT` 5 s, ADR-0360 decision 4); the Noop kits (tests, harness) = std `fs`. Missing, not a folder, unreadable or timed out ⇒ `INVALID_ARGUMENT` `workspace-not-found` `{cwd, why}` — a timeout answers this code too, and `why` names the timeout or the unreadable folder.
2. Pre-check without the reservation: the shared decision (`ProfileEditPort::workspace_lock` body, `manager/profile_edit.rs` — reservations → sessions → roster) ⇒ `CONFLICT` `workspace-locked` `{reason: running | preparing | conversed}`. A call that will be refused returns here, so it never holds the reservation and never turns a concurrent start into a refused start.
3. Take the agent's `SpawnReservation` as a working-folder holder. Held by a launch ⇒ `CONFLICT` `workspace-locked` `{reason: running | preparing}` (the shared decision — `running` first); held by another working-folder change ⇒ `CONFLICT` `workspace-locked` `{reason: changing}`.
4. Re-check under the reservation through the shared decision — running ⇒ `{reason: running}` (a launch that finished between 2 and 3), conversed ⇒ `{reason: conversed}`. The decision counts only launch holders as `Preparing`, so the caller's own working-folder reservation is ignored (this closes the `workspace_lock` TODO). It is called before any registry closure: it calls `profiles.get`, and the registry's std `Mutex` is not re-entrant.
5. Take the name-allocation gate; derive the agent's current name outside the registry mutate (the existing derivation, which can canonicalize — `canonical_name_when_live` for an asleep agent).
6. One conditional registry method (`ProfileRegistry::try_set_workspace`, `pub(crate)`, the `try_mutate_if` shape — B22): inside it, re-check `backend_session_id` (the 「has conversed」 lock is judged here too, because the first-submit latch and `observe_session_id` write it without the reservation) ⇒ `CONFLICT` `workspace-locked` `{reason: conversed}`; an agent deleted after resolving ⇒ `NOT_FOUND`; else write `cwd` and set `display_name` to the derived name only if it is still `None`. The closure answers `false` for both refusals, so a refusal writes nothing and saves nothing of its own (`try_mutate_if` only flushes an already pending change, whose failure is not this request's) — a store error cannot mask the refusal. Not `try_update_with`: it goes through `try_mutate` → `commit_if_saved`, which always saves, so a `conversed` refusal would still rewrite the file and a store error could replace the refusal. A store refusal of the write ⇒ `store_command_error`.
7. Release the gate and the reservation (RAII); notify `RosterChanged` (the tree shows `cwd` — B13).

- **No deadlock** — taking a reservation never blocks (`SpawnReservation::reserve` returns `None` at once), and no holder of the name-allocation gate waits on a reservation; launches take reservation → gate in the same order (`ensure_registered` under the reservation).
- **ADR-0120** — deriving and writing the name under the gate means a concurrent rename (also under the gate) cannot take the same name.
- **`agent.presets` while a working-folder change holds the reservation** — `workspace_lock` ignores that holder and shows the lock as it otherwise is (a momentary change, not a reason the folder cannot be changed).
- **Disagreement window** — on a connection-declaring link the reservation lives until the connection outcome while the session is already live, so the two reads can say `running` or `preparing` for the same moment; both are `CONFLICT`.
- **A launch that loses the reservation to a working-folder change** answers one way (B20): a new `PtyError` variant (working folder being changed), listed in `refused_before_spawn`. Today such a loss surfaces at three places — the `activation_in_flight` check in `AgentManager::activate_profile_reporting`, the reserve branch in `spawn_agent_watching_link`, and the Fresh / Resume branches after it — and ends `INTERNAL` on the bus (a `SpawnFailed` text, whose same-id retry is swallowed as `ALREADY_APPLIED`); all three return the new variant when the holder is a working-folder change.
  - **Callers** — the bus maps it in `wake_existing` and every other bus caller to `CONFLICT` with `RetryMode::AfterCondition` (the `LaunchRaced` precedent). The wire launch callers (`Spawn` · `SpawnProfile` — the screen's start) get no bus code: daemon `connection_core.rs` `activation_error` answers `AgentEvent::Error` with the variant's text (`profile_error_text`), as for every other launch failure.
  - **No last failure** (ADR-0172 「a moot request writes nothing」) does not follow from `refused_before_spawn`: both record sites write before or regardless of it. `spawn_fresh_settled` hands every `Err` to `note_spawn_result`, which records `spawn_error_kind(e)`; `resume_no_fallback` records `note_activation_result(.., spawn_error_kind(&e))` before it tests `refused_before_spawn`. Both gain an arm that writes nothing for the new variant (as `note_spawn_result` does for `Moot`), and `spawn_error_kind` names the variant explicitly (`Other`), so a record site that misses it does not fall into the default arm's `SpawnFailed`.
  - **Boot restore** (`restore_one`) answers `RestoreOutcome::Failed` with that reason instead of today's `Started` for a moot Fresh and `Resumed` for a moot Resume. Boot restore is off in production (daemon `lib.rs` step 9 does not call `restore_all`), so this touches a dormant path; it is pinned by manager tests only.
  - A double start by two launches is unchanged: today's answers stay (the in-flight `SpawnFailed` text for a wake, `Moot` in the spawn path).
- **ADR-0321 decision 4's exception** (a create verb that registered before its activation loses to `setWorkspace` → `INTERNAL` + id) is unreachable since ADR-0348: the one creation body (`create_and_activate` → `activate_profile_reporting` → `spawn_agent_watching_link`) reserves before `ensure_registered` adds the profile, so `setWorkspace` either cannot resolve the agent or meets the reservation. No branch or test for it; main records that the exception is out of date with an ADR link at the 10a freeze (like C7).

### 4.3 `agent.duplicate` (manager body — parent §1-5 · B13)

- **Policy** — consults `llm_creation_refusal` with the original's backend word (`launch::backend_word` of its `command`); a backend with no declared LLM policy (shell, gemini) refuses, the same accepted cost as `SpawnByCwd` (ADR-0279) (B21). The refusal is `policy_refusal` as on every door (its doc: 「the same words on every door that asks it」) — `INVALID_ARGUMENT` 「backend '<word>' is a known word, but this surface does not create it now — <reason>」; for a duplicate the word is the original's backend, which the caller did not pass (C11).
- **Name and ceiling** — under the name-allocation gate, on one roster read: `check_roster_capacity` (ADR-0132) and the existing name rule (`assign_new_name` → `pick_suffix`: `bob` → `bob(1)` when no other `bob(n)` exists, else the next number; no space). `RosterFull` and an exhausted name space map through `create_error` (`CONFLICT`).
- **One locked section** — a new `pub(crate)` registry method (`ProfileRegistry::try_insert_copy`, name in B22) reads the original and inserts the copy inside one locked section built the `try_mutate_if` way (private today; `get` + `try_upsert` would be two locked sections), so the copy queues with `rewrite_preset_paths` / `remove_preset_paths` on that lock (a copy cannot slip past a relink). An original deleted meanwhile ⇒ the closure answers `false`, nothing is saved for this request and the answer is `NOT_FOUND` — a store error cannot mask it (`try_mutate` would save through `commit_if_saved` even then).
- **The copy** = `AgentProfile::new(original.name, command, cwd, env, auto_restore = false)` plus `default_preset`, `presets`, the original's `parent_id` (§12 O4) and the pinned name as `display_name`. Carried: `default_preset` · `presets` · `command` (backend, mode, `extra_args`) · `cwd` · `env` · parent. Not carried (constructor values): backend session id and history · `epoch` · last failure · `failed_reason` · `restart_count` · `last_start_at` · `created_at` · `auto_restore` · last-applied instructions hash · notice fingerprint (ADR-0341 decision 5) · `restart_policy` (the constructor default; no production path sets another).
- Store refusal as every registry-writing command; notifies `RosterChanged`. Answer = new id · name · `sleeping`.

## 5. Concurrency

- Library handlers run on the blocking pool (`call_daemon_command` contract). Lock order is the asset-library one (library lock → manager / registry locks, never the reverse — `gate.rs` header, agent `profile_edit.rs`): a handler holds no manager lock when it calls the port.
- `agent.new {presets}`: the judgement's library read lock is released before `create_agent` takes the name-allocation gate and the registry lock — no nesting. A relink between the judgement and the create can leave the new agent on the old path, and that relink's `fixed` does not name it (the agent did not exist when the relink rewrote the profiles) — a rerun of the same relink fixes it. More generally, a `library.setRoot` or a `library.refresh` after an outside delete between the judgement and the create leaves the new agent on a path judged against the old catalog: it shows as missing, like every agent after a root change (§10 R3).
- `agent.setWorkspace`: bounded stat (no lock) → pre-check (the shared decision, no reservation) → reservation (leaf `spawning` mutex, briefly) → re-check → name-allocation gate → name derivation → one conditional registry mutate (conversed re-check inside) → release; no library lock. Deadlock argument in §4.2.
- `agent.duplicate`: name-allocation gate → roster read (capacity + name) → one registry locked section for read-original + insert; queues with the profile-edit port's rewrites on that lock; no reservation.
- Agent-preset edits keep 9a's order (port cell → first-scan entrance → root stat outside every lock → one `change_at` → folder stats after it).

### 8 (b) — main decides

- **B1** The port speaks agent types: `LibraryCommandHost` returns the declared ok types or an agent-defined port refusal (`{class, reason}` | `Store(StoreError)`), asset-library converts `LibraryRefusal` into it 1:1, and agent maps it to `CommandError` (§3). — Follows the `LaunchKitSource` precedent (asset-library answers agent's `LaunchBlocked`; agent picks the bus code) and keeps bus codes out of asset-library (ADR-0379 rejected alternative 「asset-library answers bus codes itself」). Consequence: asset-library's `command` dependency stays test-only; its `Cargo.toml` comment is corrected. Alternative: the impl returns `CommandError` directly from `host.rs` (uses the dependency the comment reserved for 10a).
- **B2** Declarations in the existing `commands.rs` block; handlers, the trait and the mapping in a new `library_commands.rs`. — One block per module (macro rule) and one declared slice per table; a second module keeps `commands.rs` (5,900 lines) from growing by the verbs.
- **B3** `CommandError.args` = `{code, args, line?}`; message = `<command>: <code>` plus the key args in English. — Same keys as an `args.reasons` row, so one reader parses both.
- **B4** Rows are typed declarations (`ReasonRow` · `ProblemRow` · `ListRow` · `FolderRow` · `AgentFolderRow` · `PreviewSetRow`). `ProblemRow.kind` is a `String` so its words equal the launch block's (`missing`, not a macro enum's `Missing`); `LibraryKind` is a macro enum (no earlier JSON to match, and the filter gets case folding and a word list for free). `Json` only for payloads whose keys depend on a code (`args`). The preview set is typed rows (user 2026-11-19 — the screen gets a schema and bindings); its `unsure` row is a word plus `message?` because `UnsureWhy` variants carry payloads. — The pattern of `LaunchNoticeRow` and `StoreStatusRow` (word + optional fields).
- **B5** snake_case field names; the agent argument is `target` (with `presets`, `order`, `base_rev`, `root_generation`); the two `library.status` reasons are `state_why` and `config_why`. — Every existing declaration is snake_case; every existing `agent.*` verb names the agent it acts on `target` (one word per kind — conventions §1-2); the parent's `{agent}` is a placeholder.
- **B6** `preset.add` · `remove` take `items: [string]` or `folders: [string]` (both or neither ⇒ `INVALID_ARGUMENT`); `add` items share one optional `backend`; `preset.save` and `preset.check` lists are `[{path, backend?}]`. — The common LLM call is one backend per call (conventions §1-1 fewest calls); `save` / `check` carry a whole draft.
- **B7** `library.refresh` is `Read`. — It changes only the in-memory catalog and a rerun is harmless; `Write` would make a same-id retry answer `ALREADY_APPLIED` with no report (`command_delivery::retains_the_id`).
- **B8** `NoLibrary` port (daemon `control/commands.rs`, beside `NoUsageLimits`) — answers as §4.4. — `NoUsageLimits` precedent; keeps one table shape in every assembly and keeps 「refresh never refuses」 and the O3 rule true there too.
- **B9** A relink `stopped` carrying a Store error answers `code: "profile-store-refused"`, `args: {why}` (`why` = `store_error_reason`). — `stopped` must carry the refusal itself (ADR-0384 decision 8) and a store error has no reason code; kebab-case beside the code that answers (ADR-0379 decision 6).
- **B10** `agent.new {presets}` judges under one library read lock and writes the accepted list into the new profile; no port step after the create, so no `INTERNAL`-after-create path. — The port doc (`profile_edit.rs` `set_attachments`) already places `agent.new` outside the port; one registry write; the race is harmless (§5). Alternative: create bare, then `attach_preset` through the port (parent §1-7's 「race at the edit-port step」 → `INTERNAL` + id).
- **B11** `library.list` gains `query`, `kinds` (omitted or empty = all) and `builtins` (the one `engram:/default` row) in U1 as a small `list` extension. `query` = a case-insensitive substring match on an item's `name` and `description`, over every item at or below `folder` (recursive); a query answer carries matching rows only (`folders` empty); `kinds` filters rows by `kind` (a broken file by the kind it claims; a skill folder's `SKILL.md` row by the fifth word `SkillFile` only — `Skill` does not match it, and the row is not left out, so a listing of a skill folder shows what the tree shows). — The parent decided the shape (B1 · Δa · G2); declaring them now avoids changing the declaration in a later step. Alternative: declare only `folder?` now and add the three with the screen step (still catalog 9).
- **B12** `agent.setWorkspace` codes `workspace-not-found` `{cwd, why}` (also for a stat timeout — `why` names it) and `workspace-locked` `{reason: running | preparing | conversed | changing}`; the folder stat is a new `LaunchKitSource` method (default std `fs` for the Noop kits; `LibraryService` = `BoundedIo` read budget) — the `working_folder` precedent, where the default is unbounded and the library overrides it with bounded IO; the reservation table becomes holder-aware (launch · working-folder change). — Codes are main's (ADR-0379 B8 precedent); the manager owns no bounded IO, its kits port does; the holder kind is what parent §1-5 and ADR-0321 decision 4 ask for.
- **B13** `agent.setWorkspace` and `agent.duplicate` call `RosterChanged`. — The tree shows `cwd` and composition (parent §1-8 「the changed value flows along today's path for refreshing the agent list」).
- **B14** The unit split of §7. — Each group is green alone; shared files force order.
- **B15** Agent-preset commands are documented in `help library`; `help agent` gets the three agent-only additions, a pointer, and the registry-writing paragraph names them all. — The help is grouped by topic (B12); attaching presets is library work.
- **B16** T-117's root stat stays (every agent-preset edit stats the root outside every lock, ≤ `IO_LIMIT` 5 s on an unresponsive share). — Routing adds no lock around it; moving it needs the in-change order change T-117 describes. Its time cost is in §10 R1.
- **B17** Every new command is `Ordinary`. — Only launches carry `Launch` (ADR-0369); the waits are measured in QA (§10 R1).
- **B18** `library.read` agents are `{id, name}`, names filled by the handler from one roster read, unknown ids dropped. — The LLM calls by name (conventions §4); the id disambiguates duplicates; the port stays id-only (§1).
- **B19** `library.refresh` maps the report as is, including a total failure as one `errors` row with no path; only an unparsable `folder` spelling is refused (host, `item-path-invalid`). — ADR-0384 「map as they are」; the body never refuses.
- **B20** A launch that loses the reservation to a working-folder change: one new `PtyError` variant → `CONFLICT` · `AfterCondition` on the bus (the wire `Spawn` · `SpawnProfile` callers get its `AgentEvent::Error` text), in `refused_before_spawn`, no last failure (both record sites skip it — `note_spawn_result` · `resume_no_fallback` — and `spawn_error_kind` names it); `restore_one` → `Failed` (a dormant path — boot restore is off); launch-vs-launch answers unchanged (§4.2). — Today's `INTERNAL` holds the request id, so the fixed retry would be swallowed as `ALREADY_APPLIED`; `LaunchRaced` is the precedent for a retryable launch refusal.
- **B21** `agent.duplicate` is an LLM creation door and consults `llm_creation_refusal` with the original's backend word. — Every LLM creation door looks at that one table (`commands.rs` `LLM_BACKEND_POLICY`); refusing shell / gemini copies is the cost ADR-0279 already accepts for `SpawnByCwd`.
- **B22** The registry methods are `pub(crate)`: `ProfileRegistry::try_insert_copy(original, build)` — the `try_mutate_if` shape: reads the original and inserts what `build` returns in one closure; when the original is gone the closure answers `false`, nothing is saved for this request and the method answers `None` (→ `NOT_FOUND`); and `ProfileRegistry::try_set_workspace` — the `try_mutate_if` shape: the conversed re-check, the `cwd` write and the `display_name` pin in one closure that answers `false` (nothing saved for this request) when the agent is gone or has conversed, with the outcome carried out of the closure (§4.2 step 6). — `try_mutate` / `try_mutate_if` are private and two public calls would be two locked sections; `try_update_with` always saves (`try_mutate` → `commit_if_saved`), so a refusal through it would rewrite the file and a store error could mask the refusal.

## 10. Risks

- **R1** Time against the ordinary seat (7 s). The first-scan entrance has no deadline of its own, so a command waiting on a cold or large library can outlive the seat and answer `OUTCOME_UNKNOWN` while it keeps running. Some edits spend two fresh 5 s IO budgets — an agent-preset edit stats the root before `change_at` and then `settle_resolution` stats folders after it; a folder `add` takes `folder_verdicts` before and the view's folder stats after — so up to 10 s on dead shares. A library edit is safe to retry (a refusal applied nothing; a success holds the id). `agent.new --presets` and `agent.duplicate` are not: a retry with a new id after `OUTCOME_UNKNOWN` creates `name(1)`, and the LLM has no delete verb — `help library` / `help agent` tell it to check `agent.list` first. Measured in C1.
- **R2** `commands.rs` and the bindings grow by ~23 declarations and ~60 generated files; review cost. Mitigated by B2 and the unit split.
- **R3** `agent.new {presets}` judged against one catalog and created after it (§5): a relink in between can leave the new agent on the path the relink moved away from, outside that relink's `fixed` — a rerun of the relink fixes it; a `library.setRoot`, or a `library.refresh` after an outside delete, in between leaves it on a path judged against the old catalog, and it shows as missing, like every agent after a root change. In 10a no command deletes a library item (delete is 10b).
- **R4** The holder-aware reservation (§4.2) touches every launch's reservation take and three answer places; a wrong branch would change today's double-start answers or record a failure for a moot launch. Pinned by the manager tests, G2 and the full regression.
- **R5** The priming is length- and character-bounded by the codex terminal command line; growing it can block every codex terminal launch. Margin today: 735 characters of 8191 (§4.5).
- **R6** ADR-0374 (T-112, scheduled right after 10a and before step 21) changes what a missing item does at launch (skipped with a notice instead of block ①); texts written now must stay true after it (§4.5), and 10a checks no block ① live (§4.6).
- **R7** Later independent roots (ADR-0312 decision 6 — an added root's paths get a name prefix; an unprefixed path = the current root; step 21 · ADR-0385) are not designed for and no root argument is added, but nothing here blocks them: every path argument and every path field in an answer is a plain string validated by the existing `LibPath` / `AssetRef` rules (a prefix would be a parser extension, not a shape change), omitted `folder` / `parent` means the current root, and root management stays `library.status` + `library.setRoot`. The one single-root-shaped answer is `library.status` (`root?` · `root_generation`) and the one `root_generation` argument: both read as 「the current root」, and per-root values would be added fields, not a change of these. `help library` says 「the library root」 without claiming there can only ever be one.
