## 1. 무엇·왜

- 지침(`.md`) · 스킬(`SKILL.md` 폴더) · 설정(`.yaml`)을 이름 있는 **프리셋**으로 묶고, 에이전트는 프리셋만 붙인다. 백엔드(claude · codex)는 에이전트가 만들 때 고르는 값이고 고정이다 — 설정은 백엔드별 원문 칸만 갖고 에이전트의 백엔드와 같은 칸이 쓰인다(모델도 그 칸 안 — R5 · R44 · 사용자 2026-10-18). 같은 규칙 · 스킬 · 설정을 에이전트마다 손으로 맞추지 않고 한 곳에서 고쳐 여럿에 쓰려는 것이다. (메모 6 · 26 · 2026-10-18)
- **라이브러리** = 폴더 하나(루트 하나 — R7 · G36). 처음 시작 때 배포판 폴더 안 빈 `library\` 를 만들어 라이브러리로 정해 두고, 사용자가 다른 폴더로 바꿀 수 있다(R8 · R9 · G35). 부품도 프리셋도 그 안의 파일(에셋)이고, 남에게 줄 땐 폴더째 넘긴다(필요한 파일만 참조째 내보내기 · 가져오기 = S25 뒤 — §2 · G37). 바깥 내용은 라이브러리 안으로 복사 · 클론해 쓴다(G37). 예외는 Engram 기본 제공 프리셋 「기본」(R43)뿐이다. 백엔드가 에이전트 값이라 라이브러리에 아무것도 없어도 에이전트를 만들어 바로 돌린다. (메모 53 · 74 · 127)
- 옛 「프리셋」(작업 폴더 즐겨찾기 — ADR-0061 · `presets.json` · `src/components/slot/PresetPalette.tsx`)과 그것을 선택하던 피커는 없애고 이름을 새 체계가 쓴다 — 옛 데이터는 그냥 버린다(G32). 에이전트 트리 pane 메뉴 「에이전트 생성 ▸」 자체는 남는다(R44). 대체 ADR(ADR-0061 · ADR-0070)은 TRD 때. (메모 43 · 44 · 122)

- **R54** **지침 · 스킬의 백엔드 표시 — 공통 · claude · codex**(새 기능 · 사용자 2026-10-30 「프리셋에 하는게 맞지 싶은데」 · G29 · 조사 = `docs/research/per-agent-instructions-practice-2026-10-30.md`) — 프리셋 안 지침 · 스킬 줄마다 백엔드 표시를 하나 붙일 수 있다: 없음 = 공통 · `claude` · `codex`. **표시는 프리셋에 산다 — 에셋 파일에 적지 않는다**(받아 둔 파일을 건드리지 않는다 · 같은 파일을 프리셋마다 달리 쓴다 · 앞머리를 떼어 낼 일이 없다 — G29). 설정은 지금처럼 파일 안 `claude:` / `codex:` 칸이다(R5). **실을 때 순서 = 프리셋마다 — 그 프리셋의 공통 줄, 그 뒤 그 프리셋의 그 에이전트 백엔드 줄**(사용자 2026-10-31 「공용 전용이 그렇게 쓰이는게 아니라 공용으로 안되는걸 덧붙이는 느김이라 aa bb 가 맞을듯?」 · G51) — 펼친 순서(R4)대로 프리셋을 하나씩 실으며 각 프리셋 안에서 공통 줄 다음 그 백엔드 줄을 잇는다 · 덮어쓰지 않고 이어 붙인다(M20). 예: 에이전트에 A · B 순으로 붙고 A = {지침 a1 · 지침 a2(claude)} · B = {지침 b1 · 지침 b2(claude)} 이면 claude 에이전트엔 a1 · a2 · b1 · b2 순으로 실린다(옛 「펼친 프리셋 전체에 걸쳐 공통 줄 전부 다음 백엔드 줄 전부 — a1 · b1 · a2 · b2」(메인 2026-10-31 M24)를 뒤집음 · 거부 = 전체에 걸쳐 공통 먼저(M24) · 백엔드 줄 먼저(Roo Code) — 백엔드 줄은 그 프리셋의 공통 줄이 못 덮는 것을 덧붙이는 것이라 바로 뒤에 놓인다 · 사용자 2026-10-31 G51). **표시를 두는 뜻**(사용자 2026-10-31 「프리셋이 메인세션 프리셋인데 로컬모델이 구져서 제대로 안들으면 클로드랑 다르게 덧붙이는 느낌으로 해야되는거 아니면 각각 쓰거나」 · G51) = 그 프리셋을 잘 못 따르는 백엔드를 위한 덧댐이다(예 약한 모델에겐 claude 엔 필요 없는 줄을 더 준다) — 그 프리셋의 공통 줄에 덧붙는다 · 백엔드마다 내용이 크게 다르면 표시 대신 프리셋을 따로 만든다. 충돌 검사(R4)는 그 에이전트에 실제로 실리는 줄만 본다 · 에이전트 프리셋 슬롯은 그 에이전트 백엔드에 안 실리는 줄을 흐리게 보인다(P12 와 같은 흐림 — R31) · codex 터미널은 여전히 지침 · 스킬을 싣지 않고 codex 표시 줄도 알림의 「빠진 것」 에 든다(R37) · 기본 제공 「기본」 도 이 표시로 백엔드별 프라이밍을 싣는다(R32 · R43)(M20). 프리셋 YAML 의 줄 = 맨 경로(공통) 또는 경로 + 백엔드(꼴 = TRD). LLM = 추가 명령의 백엔드 인자(생략 = 공통) + 표시 바꾸기 명령 하나(이름 = TRD — M20 · R39). 편집 칸에서 보이는 꼴(공통 / claude만 / codex만 세 묶음 · 끌기나 우클릭으로 바꾸기)은 클라이언트 단계에서 다시 본다(M20). 관행(조사) = 「공통 기본 + 에이전트별 예외」 는 있는 꼴이다 — rulesync 가 규칙 · 스킬 파일 앞머리 `targets` 로 같은 일을 한다 · 묶음(프리셋) 쪽에 표시를 다는 선례는 못 찾았다 · 합치기는 거의 전부 이어 붙이기이고, 순서를 문서로 적은 Roo Code 는 전용 먼저 → 공통 나중이다(우리와 반대).

- **R8** **첫 시작에 기본 폴더를 만들어 라이브러리로 정한다**(사용자 2026-10-31 「최초 디폴트 등록해둬」 · G35 — 옛 「자동 기본 폴더는 없다 · 처음엔 빈 트리 안 「아직 라이브러리 폴더를 선택하지 않았습니다.」 + [폴더 열기] · [새로 만들기]」 를 기본 경우에 대신함) — 데몬이 처음 켜질 때 라이브러리 폴더가 정해져 있지 않으면 배포판 폴더 안 빈 `library\`(`data\` 옆)를 만들어 라이브러리로 정해 둔다(개발 · 시험 빌드는 데이터 폴더 규칙을 따르고 `ENGRAM_DATA_DIR` 로 격리된다 — 꼴 = TRD) · 내용은 넣지 않는다 · 다른 폴더로 바꾸기 = R9. **만들지 못하면 정해지지 않은 상태로 둔다**(메인 세션 결정 2026-10-31 · M24) — 라이브러리 프리셋이 붙은 에이전트는 「라이브러리 폴더 없음」 으로 막히고(E4 ④) · 폴더는 화면(R9)이나 `engram library.setRoot` 로 정한다. 폴더가 없어지면 슬롯 트리 자리에 「<경로>를 찾을 수 없습니다」 + [폴더 열기] · [새로 만들기]([새로 만들기] = 폴더 선택 창에 배포판 `library\` 경로만 미리 채우고 선택하면 빈 폴더를 만든다) · 설정 값은 둔다. - **R27** 프리셋 줄 한 번 누름 = 그 자리에서 ▸/▾ 펼침. **열 때는 늘 접힌 채(▸)** — 편집 칸 · 에이전트 프리셋 슬롯을 열 때마다 프리셋 줄(예 「공용 규칙」)은 모두 접혀 시작하고 펼침은 기억하지 않는다(사용자 2026-10-20 「그냥 무조건 접혀있게 해 그럼 초반엔」 · R10) · 종류 칸 머리(프리셋 · 지침 · 스킬 · 설정)의 접힘은 R10 의 1~4 공통 기억 그대로 · 문제 목록 누름(R51)은 필요한 줄을 펼친다. 안쪽은 바깥과 같은 레이아웃을 한 단 들여 같은 부품을 재귀로 쓰고(안쪽의 안쪽도 ▸), 흐리게 · 보기만(+ · × · 순서 없음). 고치려면 그 프리셋을 연다 · 바깥에서 그 줄을 빼는 것은 된다. 거부 = 안쪽 것을 바깥 칸에 섞기(상속 도구 관례 — 우리는 여럿을 포함한다) · 그 자리 고치기(공유 파일이라 참조하는 쪽이 전부 말없이 바뀐다). (메모 130 · 132 · 169) **부품 내용 보기(사용자 2026-10-17 · 2026-10-18 · 2026-10-19)** — 편집 칸의 부품 줄(지침 · 스킬 · 설정 — 안에 든 프리셋을 펼친 안쪽 포함 · 10-18 사용자 「ㅇㅇ 달아」 = 모든 부품 줄)을 **누르면 그 항목의 상세 카드(R15 와 같은 카드 · 떠 있는 카드 — 호버 툴팁 아님)가 토글된다**(사용자 2026-10-19 「그냥 카드 토글하고, 왼쪽 구석은 위치 배치하는거고」 — 옛 줄 끝 👁 단추를 걷음: 너무 작고 내용 보기가 잦다 · 거부 = 더 큰 👁 · 👁 + Space) · 누름은 여전히 그 줄을 끼울 자리로 고른다(R46) · 왼쪽 끝 ⋮⋮ = 끌어서 순서 — 자리 = R29(라이브러리 슬롯 = 오른쪽 칸 왼쪽 가장자리 · 목록 위 · 에이전트 슬롯 = 슬롯 바깥 — D11) · 같은 줄 다시 누름 = 닫힘 · 떠 있을 때 다른 줄 누름 = 바로 그 줄로 바뀜 · ×(그 카드) · 카드 바깥 누름 · Esc(쌓인 카드를 나중에 연 것부터 — 관행 2026-10-18) = 닫힘 · 프리셋 줄은 그대로(누름 = 선택 + 펼침 · 카드 없음 — 펼쳐서 본다) · 더블클릭(R28)은 그대로. 거부 = 줄 아래 끼워 펼치기(VS Code Peek 꼴 — 사용자가 싫다) · 편집 칸 아래 미리 보기 칸 · 따로 뜨는 창(그림 후보 비교 2026-10-17 · 조사 = docs/research/editor-referenced-content-peek-survey-2026-10-17.md).
- **R28** 줄 호버의 폴더 돋보기를 누르거나 줄을 더블클릭하면 그 항목 자리로 간다. 라이브러리 슬롯에선 같은 슬롯이 그 자리로 가고 거기서 그 프리셋을 고칠 수 있으며 `←` 로 돌아온다. 에이전트 슬롯에선 라이브러리 슬롯(E11 의 대상)이 그 자리로 가고 에이전트 슬롯은 그대로 남는다 — 돌아오기 = 에이전트 슬롯을 다시 누름. 기본 제공(R43)은 꺼짐. (메모 140 · 169 · 그림 §3 「편집 칸의 줄 누르기」 · 기본값 E11)

**상세 패널**
- **R29** 편집 칸 줄의 상세(라이브러리 상세와 같은 내용 · 같은 블록 순서 — R15)는 부품 줄을 누르면 떠 있는 카드로 토글된다(R27 · 사용자 2026-10-19 · 그 누름은 끼울 자리도 고른다 — R46). 카드 = 모든 부품 줄(지침 · 스킬 · 설정 — 사용자 확인 2026-10-18 「ㅇㅇ 달아」) · 프리셋 줄엔 없음(누름 = 선택 + 펼침). 같은 줄 다시 누름 = 닫힘 · 다른 줄 누름 = 그 항목. **자리 — 어느 경우에도 잘리지 않는다**(D11 · 관행 — 2026-10-18 · ★리뷰 때 확인 — 그림으로★): 라이브러리 1~4 = 오른쪽 칸은 창 안의 칸이라 넘치지 않고, 편집 칸 줄의 카드(줄 누름 — R27)는 오른쪽 칸 **왼쪽** 가장자리에 그 줄 높이로 붙어 가운데 목록 위에 뜬다(창이 좁으면 폴더 트리까지 덮을 수 있다) · 에이전트 슬롯(편집 칸만) = 슬롯 오른쪽 바깥에 붙어 **옆 슬롯 위로 겹친다**(옆 슬롯 크기 · 내용 그대로) → 오른쪽에 자리가 없으면 슬롯 왼쪽 바깥으로 뒤집기(왼쪽 옆 슬롯 위) → 양쪽 다 없으면(예 팝아웃 창을 채운 슬롯) 창 안으로 당긴다(슬롯을 덮음). 관행 = Floating UI `flip()` 다음 `shift()`(확인함) · Radix · MUI · NSPopover 같은 순서 · 기준점을 덮는 것은 마지막 수단. 메모 137 「창에 걸려 잘린 채 · 뒤집기 · 안쪽 대체 없음」 을 뒤집는다. 거부 = 슬롯 안에 칸 끼워 넣기. (메모 137–138 · 그림 §3)

**에이전트 프리셋 슬롯**
- **R30** 에이전트 프리셋 편집 = 슬롯 종류 하나 = **공용 편집 부품(R21)만 올린 슬롯** — 편집 부품 + 데이터 훅만 싣고 트리 · 목록 · 필터 · 트리 부품(react-arborist) · 가상 표는 올리지 않는다(메인 세션 결정 2026-10-19 — 사용자 위임 「알아서 해 이 부분은」 · 옛 「편집 칸만 켠 라이브러리 슬롯(트리 · 목록 숨김) · 통째 재사용이 느리면 로직만」 을 고정 규칙으로 바꿈). 편집 부품은 홀로 서는 부품이고 라이브러리 오른쪽 칸과 에이전트 슬롯이 각자 품는다 · 데몬 훑기는 하나를 함께 쓴다(슬롯은 묻기만). 번호 없음 · 에이전트 트리 우클릭 「프리셋…」 으로 열고 이미 열려 있어도 하나 더 · 팝아웃하면 OS 창. 거부 = 트리 옆 펼침 칸 · 라이브러리 오른쪽 칸에 에이전트 띄우기(그림 §9 「지난 안」). (메모 157–163)
- **R31** 칸 = 맨 위 따로 구분된 「기본」 · 「작업 폴더」 · 「프리셋」. 칸 머리는 라이브러리 편집 칸처럼 ▾/▸ 로 접는다 — 접은 상태는 모든 에이전트 슬롯 공통으로 한 번 기억 · 라이브러리 1~4 의 것(R10)과 따로(사용자 2026-10-18 「머리접기는 그냥 머리접기해 안할 이유가 없음.」 · 기억 범위 = 세션 판단). 에이전트에선 프리셋 칸만 고친다(`+` · `⇐` · 폴더 돋보기 · ×) · 붙은 프리셋은 R27 처럼 펼쳐 보기만 · 안에 깨진 항목(찾을 수 없음 · 오류)이 든 프리셋 줄은 접혀 있어도 빨간 오류 수 배지(R6) · 펼치면 그 항목 줄 ⛔ + 이유(찾을 수 없음 = 「찾을 수 없음 · [다시 연결] ×」 점선 줄 — R19) · 그 줄 더블클릭 · 돋보기(R28)면 라이브러리가 그 항목을 고른다(E4 · 사용자 2026-10-18 — 줄 누름은 상세 카드 · R27 · 2026-10-20 막힘 창도 같은 길) · 머리 아래 문제 목록 = 그 에이전트의 막힘 이유 전부(붙은 프리셋 속 것은 「<프리셋> ›」 길 · 에이전트 단위 것 포함 — R51 · 사용자 2026-10-19). **이 에이전트에 안 실리는 줄은 흐리게**(있던 흐림 상태 — R6 · 새 범주 없음) — 그 에이전트 백엔드 칸이 없는 설정 줄은 흐림 + 작은 덧말 「claude 칸만 있음 — 이 에이전트(codex)에는 안 실림」(사용자 2026-10-21 「손해볼건 없지」 · P12 · 리뷰 #14 · 펼친 안쪽 프리셋의 설정 줄도) · 다른 백엔드 표시가 붙은 지침 · 스킬 줄도 같은 흐림(R54 · M20). 라이브러리 편집 칸은 에이전트를 모르니 그대로다. codex 터미널 에이전트에 지침 · 스킬이 든 프리셋이 붙어 있으면 그 슬롯 맨 위에 실행 알림(R37)과 같은 내용을 흐린 한 줄로 보인다 — 실행 전에도 보이게(P4-FINAL 메인 세션 채움). 머리 = 이름 + 백엔드 · 모드(에이전트 값 · 만들 때 고정 — R44)(예 「리뷰봇 codex · JSON」). **「작업 폴더」 칸**(사용자 2026-10-18 「거기에 항목이 하나 더 있는거지」 · D3) = 경로 표시 · 바꾸기 = 직접 입력 또는 「찾아보기」(OS 폴더 선택 창 · 같은 PC 전용)(「경로는 수동으로 넣을 수도 있고 브라우저 탐색으로 넣을수 있는 2방향」) · 있는 폴더여야 한다. **잠금** = 영속된 백엔드 세션 id 가 있거나(첫 제출 래치 — ADR-0226) 돌고 있으면 읽기 전용 + 짧은 이유 — 돌고 있으면 「실행 중 — 바꾸려면 멈추기」 · 대화했으면 「대화한 에이전트 — 바꾸려면 새 에이전트」(「대화 뒤 잠금은 있어야지」 · 문구 나눔 = 메인 세션 · P2-REVISED · 리뷰 #3 — 옛 한 문구가 대화 안 한 채 도는 에이전트에도 쓰였다) — 대화 전에만 바뀌므로 작업 폴더를 바꿔 새 대화로 넘기는 로직(세션 놓기)은 없다. LLM = `agent.setWorkspace`(R48). (메모 146 · 164–165 · 2026-10-18 · 그림 §9 · 기본값 E15)
- **R32** 「기본」 칸 = 기본 제공 프리셋 「기본」 하나뿐(모든 에이전트에 거는 사용자 공용 층이 아님 · 백엔드마다 다른 프라이밍은 백엔드 표시로 — R54 · M20) + 하는 일 한 줄 「Engram 사용 안내, Engram 메시지 · 제어 통로, claude 자동 업데이트 끄기」(통로는 T10 으로 더해짐 — 2026-10-18) — 버릇처럼 떼지 않게 따로 보인다. 내용 = 프라이밍(Engram 수신 계약) + 기본 설정(claude 원문 `{"env":{"DISABLE_AUTOUPDATER":"1"}}` — 지금 다른 세션이 claude 백엔드에 박는 것을 이리 옮긴다 · 그 옆에 Engram 통로 `allowedMcpServers: [{serverName: "engram"}]` — 숨긴 설정 조각을 두지 않고 보이는 프리셋에 싣는다 · TRD T10 · ADR-0109 결정 9(숨긴 한 키 조각)를 대체 · 사용자 2026-10-18 「사실 감추는 설정이 있으면 안되지」 · Engram MCP 서버 등록 실행 인자 `--mcp-config` 는 범위 밖 — 실행 인자 그대로(실행마다 주소 · 토큰을 싣는 인자라 설정이 아니다 — 사용자 2026-10-18 「셋팅이 아니잖아」)). 만들 때 늘 붙고, 떼면 확인 **모달**(R18 삭제 확인과 같은 꼴 — 창 전체 · 앱 안 · 사용자 2026-10-19 「ㅇㅇ 모달로하면되고」)(「기본 프리셋을 떼면 Engram 사용 안내, Engram 메시지 · 제어 통로, claude 자동 업데이트 끄기가 빠집니다.」 · □ 다시 묻지 않기 · [취소] [떼기]). (메모 77–82 · 164–165 · 2026-10-18)
- **R44** **에이전트 만들기** — 만들기는 에이전트 트리 pane 메뉴 「에이전트 생성 ▸ claude/codex × JSON/터미널」 그대로(안의 옛 작업 폴더 즐겨찾기 선택만 없앤다 — 메모 44). 만들면 기본 프리셋(「기본」 칸)만 붙어 곧바로 실행된다(「프리셋」 칸은 빔) — **지금 흐름 그대로**(메뉴 → OS 폴더 선택 창 → 만들기 → 「기본」 만 붙어 실행) · 러프하게 되기만 하면 된다(사용자 2026-10-20 「이부분 리팩토링할거잖아. 그럼 에이전트 트리쪽은 그냥 러프하게 되게 구현하고 나중에 정리하자고」 · P2-REVISED · 리뷰 #3) — 첫 실행에 사용자 프리셋이 없다는 문제 · 만들 때 설정 · 경로 없이 만들기는 다음 주제(§2) · 있는 에이전트를 본떠 만들기 = 복제(R53). **백엔드 · 모드 = 만들 때 고르는 에이전트 값 · 고정**(사용자 2026-10-18 「그냥 고정해. 백엔드는.」 · 모드도 「어 고정해.」 · D5) — 나중에 바꾸는 길은 없고, 다른 백엔드를 쓰려면 새 에이전트를 만든다. 설정이 백엔드를 바꾸는 일도 없다(R5 — 설정은 에이전트 백엔드와 같은 원문 칸만 쓰인다). 에이전트 슬롯 머리에 백엔드 · 모드가 보인다(R31). **기존 에이전트는 이전하지 않는다**(D4 · 사용자 2026-10-18 「기존거 필요없어」 — 옛 「기존 에이전트 = 기본 프리셋 · 지금 백엔드 · 모드 · 작업 폴더 그대로」 이전을 걷음) — 새 판은 빈 에이전트 목록으로 시작하고 옛 데이터는 그냥 버린다(사용자 2026-10-30 「옛것은 물어보지마 현재 기준으로 그냥 다 날리면됨」 · G32 · 버리는 길 = TRD). (기본값 E7 · D4)
- **R53** **에이전트 복제**(사용자 2026-10-19 — 작은 새 기능) — 에이전트 트리 우클릭 「복제」 · LLM = `agent.duplicate {agent}`(원칙 「LLM-우선 제어」 — 이름은 자리표시). 복사하는 것 = 붙은 프리셋(「기본」 칸 + 「프리셋」 칸) · 백엔드 · 모드 · 작업 폴더 경로 · 추가 인자 · 환경 변수. 복사하지 않는 것 = 세션 id · 대화(새 에이전트는 새 대화로 시작하고 「작업 폴더」 칸은 잠기지 않는다 — R31) · 도는 상태. 이름 = 「<이름>(2)」 · (3) …(띄어쓰기 없음 — 앱에 이미 있는 에이전트 이름 규칙 · ADR-0115 · ADR-0120 · ADR-0123 · M12 — 옛 「<이름> (2)」(R17 파일 이름 규칙을 따른 2026-10-19 메인 세션 결정)를 대신함 · 사용자 「네이밍은 관행대로」).

- **R52** **`description` 쓰기 안내**(사용자 2026-10-19 「일단은 그렇게하자」) — 설정 · 프리셋 파일 형식을 프라이밍(「기본」 의 Engram 사용 안내 — R32)과 `engram help` 에 싣는다 — 예에 `description:` 을 넣고 한 문장 「설정 · 프리셋 파일을 만들거나 고칠 때 한 줄 설명을 적는다」 를 붙인다. `engram help` 맨 위는 부풀리지 않는다 — 묶은 주제(예 `engram help library`) 아래에 두고 맨 위엔 그 주제 한 줄만. 「새로 만들기 ▸ 설정 · 프리셋」 틀에 빈 `description: ` 줄(R17). 설명이 없으면 흐린 「설명 없음」(상세 · 검색 결과 줄 — R15 · R25) · 막지 않는다. 거부 = 설명 필수(없으면 오류) — 에이전트가 파일을 직접 쓸 수 있다. 나중 생각 = 프라이밍 자체를 라이브러리 에셋으로(§2 비목표).

- **R49** **로컬라이제이션 대비(사용자 2026-10-16)** — 새 화면 글자(메뉴 · 확인 창 · 칸 제목 · 상태 이름)는 기존 다국어 장치(`src/i18n` 의 `t()` + `ko.ts`)의 키로만 쓴다(컴포넌트에 직접 박지 않는다). 데몬이 돌려주는 사유 · 상태(충돌 · 찾을 수 없음 · 「N개 더 찾아 연결함」 · 실행 막힘 · 설정 검사 오류 · 막지 않는 알림 — R37 · R48)는 문장이 아니라 **코드 + 인자**로 주고 화면이 번역한다. 기본 제공 프리셋의 표시 이름(「기본」)도 키 — 저장 값은 `engram:/…` 경로. 번역하지 않는 것 = 사용자가 만든 파일 · 폴더 이름 · 파일 안 형식 낱말(`kind` 등) · 명령 이름. 앱 전체 번역은 tracking T-68.
- **R50** **단축키 = 각 OS 파일 관리자의 기본값**(사용자 2026-10-16 「범용적인 걸로」). 라이브러리 슬롯에 포커스가 있을 때만 듣고, 이름 칸 · 검색칸에 치는 중이면 키는 그 칸으로 간다. Windows = 탐색기: F2 이름 바꾸기 · Delete(Shift+Delete 도 — 영구 삭제가 없으니 `.trash` 로 · R18) · Enter 열기(폴더 = 들어감 · 파일 = 더블클릭과 같음) · Backspace · Alt+← 뒤로 · Alt+→ 앞으로 · Alt+↑ 상위 폴더 · Ctrl+Shift+N 새 폴더 · Ctrl+F · Ctrl+E · F3 검색칸 · F5 새로 고침(R19) · Esc 이름 취소 · 검색 지우기 · Ctrl+A · Shift/Ctrl+클릭 · Shift+화살표 · Home/End 선택 · 트리 ← → 접기/펼치기 · Shift+F10 우클릭 메뉴 · 글자 입력 = 그 글자로 시작하는 항목으로 · Ctrl+X 잘라내기 · Ctrl+C 복사 · Ctrl+V 붙여넣기(R17 · P6). **포커스에 따라 뜻이 갈리는 키**(사용자 2026-10-20 「ㅇㅇ 그래」 · P6 · 리뷰 #10 — 같은 편집 부품이라 에이전트 프리셋 슬롯 · 막힘 창의 편집 칸 줄도 같다 · R21):

  | 키 | 라이브러리 목록 · 트리 | 편집 칸 줄 |
  |---|---|---|
  | Delete | `.trash` 로(R18) | 프리셋에서 빼기 — 파일은 그대로(R51) |
  | Alt+↑ | 상위 폴더 | 그 줄을 위로(지침 · 설정 · 프리셋 — 끌기 ⋮⋮ 와 같은 순서 바꾸기) |
  | Alt+↓ | — | 그 줄을 아래로(같음) |

  macOS = Finder 기본값(Enter 이름 바꾸기 · Cmd+↓ 열기 · Cmd+Delete 삭제(`.trash` 로) · Cmd+[ / ] 뒤로/앞으로 · Cmd+↑ 상위 · Cmd+Shift+N · Cmd+F) — 맥 이식 때 확인. 없는 기능의 키(되돌리기 · 속성 · 탭)는 넣지 않는다(복사 · 붙여넣기는 이제 있다 — P6). **LLM 경로를 따로 만들지 않는다** — 화면 조작이고, 키가 하는 일(이동 · 이름 · 복사 · 삭제 · 새로 만들기 · 새로 고침 · 빼기 · 순서)은 이미 데몬 명령으로 닿는다(사용자 2026-10-16 · R39). OS 별 키맵을 통째로 주는 공용 라이브러리는 없다(VS Code · Spacedrive 도 손으로 쓴 표 — 조사 2026-10-16).

**도킹 · 화면 꾸러미**
- **R42** 두 슬롯(라이브러리 · 에이전트 프리셋)은 평범한 슬롯 종류로 만든다 — 슬롯 종류를 가리지 않는 도킹 작업(wt2 `v0.4.1/feat/slot-docking` · `docs/process/S21-slot-docking/` — 이 브랜치엔 없음)이 그대로 붙게. 도킹 자체는 범위 밖. (메모 152 · 161)
- **R55** **화면 = 켜고 끄는 꾸러미**(사용자 2026-10-29 「데몬은 디폴트로 제공하는거고 UI는 그냥 패키지? 형식으로 온오프」 · 「슬롯을 추가하는? 시스템의 첫 사례가 되고 싶은데」 · G22 · G23) — 라이브러리 · 프리셋 화면(라이브러리 1~4 · 에이전트 프리셋 슬롯)은 켜고 끌 수 있는 꾸러미다 — 동적 플러그인이 아니라 함께 빌드되고 등록 · 켬끔 자리가 하나다(G22). **끄면 화면만 꺼진다** — 데몬 기능(명령 · `engram library.*`)은 늘 켜져 있어 LLM 은 화면 없이도 그대로 쓴다(G22). 이 꾸러미가 「슬롯 종류를 더하는 꾸러미」 의 첫 사례다(G23). 꾸러미의 꼴(계약 · 켬끔 자리 · 꺼진 꾸러미의 슬롯이 저장된 레이아웃을 부팅 때 어떻게 보이나 · 슬롯 안 보기 상태를 어디에 두나 · ADR)과 클라이언트 모듈 경계(G19)는 클라이언트 단계에서 정한다 — 화면 이야기는 그때(사용자 「화면은 나중에 다시 얘기하자」).

**불변 제약 (원칙 — 지킬 벽)**
- 데이터(훑기 · 프리셋 · 설정 내용 · 참조 · 다시 연결 · 기본 제공 에셋)는 **데몬 소유**. 클라이언트는 디스크를 읽지 않고 보이기만 하며, 쥐는 것은 보기 상태(폴더 · 선택 · 정렬 · 기록 · 칸 폭)뿐이다(옛 「개인 데이터(컬렉션) — 항목 키에 데몬 신원」 은 컬렉션과 함께 S25 뒤로 — G34). 화면은 꾸러미라 꺼져도 데몬 기능은 그대로다(R55). (메모 58–59 · 71 · 87)
- 클라이언트 · 데몬은 지금 같은 PC. 화면은 OS 대화상자 · 기본 프로그램 열기 · 탐색기 보이기를 직접 부르지 않고 요청 하나를 지난다(지금 = OS 기본 · 원격엔 끈다) — 이 같은 PC 도우미는 화면 전용이고 데몬 명령이 아니다(R39 · M21). (메모 60 · 63)
- 서드파티 라이브러리는 늘 우리 부품 뒤에 감싼다. (메모 93 · 113)
- 백엔드 지식은 「백엔드 확장」 한 곳 · OS 별 동작(기본 프로그램 · 정션)은 「플랫폼 중립」 OS 층 — 삭제는 OS 휴지통을 안 쓰고 라이브러리 안 `.trash` 로 옮긴다(R18 · 2026-10-19) · 사람의 비우기 · 영구 삭제가 OS 휴지통으로 보내는 일은 OS 층 함수 하나(macOS = 휴지통 — 나중 · R18 · 2026-10-20). (원칙)
