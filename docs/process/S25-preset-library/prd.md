## 1. What · why

- Instructions (`.md`) · skills (`SKILL.md` folders) · settings (`.yaml`) are bundled into a named **preset**, and an agent only attaches presets. The backend (claude · codex) is a value picked when the agent is created and is fixed — a settings asset has only per-backend raw fields, and the field that matches the agent's backend is used (the model is also inside that field — R5 · R44 · user 2026-10-18). The aim is to fix the same rules · skills · settings in one place and use them for many agents, instead of aligning them by hand for each agent. (memo 6 · 26 · 2026-10-18)
- **Library** = one folder the user selects. Parts and presets are both files (assets) inside it, and when handing it to someone else the whole folder is passed. The only exception is the Engram built-in preset 「기본」 (R43). Because the backend is an agent value, an agent can be created and run right away even before a library is selected. (memo 53 · 74 · 127)
- The old 「프리셋」 (working-folder favorites — ADR-0061 · `presets.json` · `src/components/slot/PresetPalette.tsx`) and the picker that selected it are removed without migration, and the new system takes over the name. The agent tree pane menu 「에이전트 생성 ▸」 itself stays (R44). The superseding ADRs (ADR-0061 · ADR-0070) come at TRD time. (memo 43 · 44 · 122)

## 3. Requirements

**Assets and composition rules**
- **R1** Asset kinds = instructions (`.md`) · skills (a folder holding `SKILL.md`) · settings (`.yaml`) · presets (`.yaml`). A preset is also a file inside the library (exception = built-in, R43). **Instructions = every `.md` wherever it is** (including inside a skill folder · free content · no format · exception = `SKILL.md` itself — it stands in for that skill, R12 · `.txt` is not an instruction — user 2026-10-17). **Files that are not our kinds do not appear in the list** (images · `.json` · `.txt` · scripts etc. · also inside skill folders · also a `.yaml` that has no `kind` or cannot be read at all — user 2026-10-17). 「오류」 + a reason (e.g. 「오류 · YAML 3줄」) is only for a broken file with `kind: preset` · `kind: settings` and for an unknown `kind` value (likely a typo). YAML is the direction; the TRD confirms. (memo 74 · 76)
  - **Settings check — light · only inside the daemon · the CLI is not run** (user 2026-10-18 「가볍게하는걸로하고 나중에 문제되면 차후에 고려하자」 · 「안되면 그냥 어느정도 미스매칭 각오하고 별도로 라이트하게」 — withdrew the 10-17 pre-run CLI check (`claude --settings … doctor` · `codex debug models` / `codex doctor`) and its pass record · the blocked reason 「설정 실행 직전 검사 실패」 · measured = `docs/research/settings-asset-validation-spike-2026-10-17.md`). ① Syntax (YAML) → ⛔ error 「N째 줄」 ② Schema — claude = SchemaStore `claude-code-settings.json` (a community-maintained copy the official docs point to · later than claude — `docs/research/claude-settings-schema-source-2026-10-18.md`) · codex = the release `config-schema.json` of the installed version. A type · range error on a key the schema knows → **⛔ error — blocks the run** (「막어」 — claude silently discards the whole `--settings` if even one value has the wrong type · measured) · unknown keys = claude shows nothing (SchemaStore misses many new keys) · codex only ⚠ (does not block — unchanged from 10-17). **When to check = every time Engram reads the content** (the VS Code · JetBrains practice for cheap checks) — the first sweep (everything) · refresh (files changed by tag) · edit inside Engram (immediately) · run (the attached settings — already read) · if the schema changes, everything again. Schema download = only when actually needed (the sweep that needs it — not at daemon start · 「가장 늦은 타이밍 … 실 필요할 때」) · if the installed claude · codex version differs from the one at the last download, download again then (session proposal · no objection). There is no 「검사」 · 「모두 검사」 menu and no `library.validate` — refresh (F5 · right-click 「새로 고침」 · `library.refresh`) covers it · there is no 「검사 필요」 state either (checking is nearly free, so it runs on every read) (session proposal · no objection). There is no re-reading on editor focus (「너무 복잡하게 할 필요는 없는것같아」 — an outside edit shows up on refresh · at run time). A run-time error (exit code + stderr) does not put ⛔ on the settings row — only the agent sees it (the raw exit code + stderr · user 2026-10-18 — withdrew the 10-17 「그 설정 줄 ⛔」). The icon shows in the list name field, and the reason goes in the tooltip · detail card (e.g. 「3째 줄 · …」). A schema error · syntax error is the run-blocked reason 「오류」 (E4).
- **R2** Part → preset (a preset can hold a preset · a reference, not a copy) → agent (several presets). Parts are added only in the preset edit area, and an agent attaches only presets. The backend does not come through a preset — it is an agent value (picked at creation · fixed — R44 · user 2026-10-18 「그건 에이전트가 골라야지」). (memo 26 · 39 · figure §1)
- **R3** A reference = one form, a `/` path from the top of the library (e.g. `스킬/리뷰/review`) · no scope limit. Rejected = a path relative to the preset file · a name reference · an ID file — a skill is shared by several presets, the same name is common in a folder browser, and the identity of an item is its place. (memo 101–103 · figure §5)
- **R4** Check after expansion — a cycle = error · if the same preset arrives by two paths it counts once · a conflict = only two or more skills with the same name (different paths) — Engram lays skills down into per-name folders, so they really collide on our side regardless of the CLI. There is no model conflict check (R5 · user 2026-10-18 — withdrew the old 「백엔드 설정 둘 이상」 conflict). Instructions · settings are joined in the order they were added. (memo 9 · 26 · 2026-10-18)
- **R5** A settings asset = only `description` + per-backend raw fields (claude = the settings JSON passed with `--settings` · codex = the `-c` list) — there are no official `backend` · `model` fields (user 2026-10-18 — withdrew the official field of memo 79). Only the field that matches the agent's backend is used, and they are joined in the order added — **the claude field is merged into one settings file in the attached order and passed as a single `--settings` — the later value wins · lists are merged** (objects = merged recursively · lists = joined in the attached order with identical values kept once · any other value = the later preset wins · no per-key rules — user 2026-10-18 「이어붙이기 진행」 · so a later preset cannot remove `engram` from `allowedMcpServers` — accepted) (Engram-first rule · no hidden settings fragment — TRD T10 · user 2026-10-18 「프리셋으로 해줘. 사실 감추는 설정이 있으면 안되지.」 · the Engram link key is left visible in the claude field of 「기본」 — R32) · the codex field joins the `-c` lists. The model · effort also go inside that field (e.g. claude field `model: claude-opus-5-5` · codex field `- model=gpt-5.5` · `- model_reasoning_effort=high`) — the field is kept per backend so the field that fits the agent's backend can be swapped in, and the agent does not pick the model (「근데 model을 왜 에이전트가 골라」). Engram does not interpret the raw text or check it for conflicts (the content is the user's responsibility) — even if two settings put a model in the same backend field there is no conflict check — claude keeps the later value when merging (above) · codex does what the CLI does (「클로드 쪽에서 허용하면 허용인거고 안되면 충돌인거지」 · to check, a lookup table per CLI would have to be fixed at every CLI update). If a model is put in, the CLI starts with that model — the JSON picker does not lock it (R35 · user 2026-10-18). Key names are placeholders. (memo 79 · 81 · 167 · 2026-10-18 · figure §8)
- **R6** Status display = conflict (cannot be used as is) · not found (「찾을 수 없음 · [다시 연결] ×」 — R19) · error (cannot be read · settings schema error — R1) · dimmed (already added · cannot be added). **There is no warning (notify-only) category** (user 2026-10-18 — R22 · R45 · the only exception is the ⚠ for unknown codex keys in the settings check — R1). The old 「다시 연결됨(확인할 때까지 그 줄에 붙는 표시)」 was withdrawn — a row is either not found or fine (D10 · practice — 2026-10-18 · on 2026-10-19 the sweep-candidate suggestion row was also withdrawn — R19). 「찾을 수 없음」 appears only where a spot points at a missing file (a preset row · an agent slot · a collection) — it is not in the folder list. **Inner error roll-up** — a preset row that holds a not-found or an error inside shows a red error-count badge even when collapsed (the VS Code Explorer practice · user 2026-10-18 — R31 · E4) · the same problem also appears one line each in the problem list above the edit area (R51). (memo 86 · figure §12)
- **R43** **Built-in assets** — live in a fixed fake-path namespace outside the library (e.g. `engram:/…` — the form is the TRD's). The actual files sit in one `builtin\` folder of the distribution as files in the same form as the library (preset `.yaml` · instruction `.md` · settings `.yaml`), and the fake path points at those files (main session decision 2026-10-20 — reported). The built-in set = only the default preset 「기본」 (R32) (user 2026-10-18 — the old 「claude 기본」 · 「codex 기본」 backend presets were withdrawn: their content was a single `backend` and the backend is now an agent value — R44). It exists even if no library is selected. **In the library slot tree, built-in = hidden** (user 2026-10-20 — R11) — it shows, as a separate read-only root 「Engram 기본 제공」 under the library tree, only in a number where the 「…」 menu ☐ 「기본 제공 보기」 is turned on (browse · detail only — no edit · move · delete · rename · create new · drop) · and in library search it appears, marked 「기본 제공」, only when that is turned on in that number (main session decision 2026-10-20 — reported · matches 「숨김」). Expand-view only (R27) · the folder magnifier and R28 are off · it cannot be added inside another preset (it attaches only to agents) · `engram` is addressed by its fake path. A person attaches it from the fixed 「기본 제공」 list at the top of the agent slot `+` search (one 「기본」 · always there regardless of whether 「기본 제공 보기」 is on or off) — this and the empty 「기본」 field are the ways to re-attach a detached default preset (D8). (default E7 · E17)
