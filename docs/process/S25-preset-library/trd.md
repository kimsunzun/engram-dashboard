## 0. One-paragraph summary — the flow

The library folder belongs to **the daemon PC** and only the daemon's new `library` module reads and writes it. The screen does not look at the disk; when a slot opens · gets focus · moves between folders it sends a **bus command** (`library.list` etc.) and draws the reply (request style — the daemon answers from its in-memory list and scans the disk only at the first time · `library.refresh` · root change · no watching · no broadcast). The `engram` CLI and the LLM call the same commands. Edits and file operations are commands too, and the daemon applies them to the latest file (hand-written comments are preserved — T2). At launch, `AgentManager` finishes the check through the new port `LaunchKitSource` (concrete implementation = the daemon) **before** deriving the session, receives the preset the daemon expanded as a **backend-neutral launch kit** in a volatile folder, and only `backend` translates it into claude · codex flags. Backend · mode are agent values (fixed at creation), and only that backend's raw-text field of the settings is carried (the model is also inside it — user 2026-10-18) · there is no settings fragment injected in hiding — the Engram link key (`allowedMcpServers`) is also visible in the raw text of the built-in 「기본」, and claude raw texts are merged into one `--settings` in attach order (T10). The working folder is chosen at creation (required — as-is) and changed through the agent slot 「작업 폴더」 field · `agent.setWorkspace`, but it is locked after a conversation (persisted session id) · while running (creation without a path etc. = next topic §8). When a launch is blocked, it is blocked for the same five reasons no matter who issued it (screen · CLI · LLM) — for a launch issued by a person, the screen opens that agent's preset editor area in a separate floating window next to the agent tree row (the blocked window — closes only with × · Esc · fixing happens inside it), and a launch issued by the LLM · CLI receives code + arguments without a window (G13). The daemon checks settings inside the process every time it reads the content (syntax · schema — it does not run the CLI). A file that disappeared outside is left as 「찾을 수 없음」 (launch is blocked · the scan does not suggest candidates), and when the user · LLM picks one with [Relink], the rest with the same old path · the same old folder are fixed together. Delete moves into a hidden `.trash` inside the library root (the OS Recycle Bin is not used for delete), and the person views and restores it at 「🗑 휴지통」 at the very bottom of the left area (`library.restore` — the LLM too) and empties it — emptying · permanent delete sends to the daemon PC's OS Recycle Bin (deleted directly if that fails) and there is no bus · `engram` command for it (an intended exception to 「LLM-우선 제어」) · it never empties by itself. In-app moves · relinks accumulate in the daemon 「이동 기록」 and each client fixes its own collections at its next request. The view state of numbers 1~4 and the collections · target collection are held authoritatively by the **shell** (keyed by the daemon identity), and OS actions pass through `platform` (junction · path comparison · file identity) and the shell's local requests. The implementation ships in two editions (edition 1 = read · edit · attach · launch · edition 2 = file operations · relink · drag-to-move · collections — §5 · the T8 picker is handed over to the next topic — G10).

**Rejected alternatives**
- **The shell scans the library** — reading the client disk is forbidden (PRD invariant constraint) and it does not hold with a remote daemon (later).
- **Per-number view state in the daemon** — it is viewer-side state. With several clients it has no owner (same reason as memo 58 「레이아웃을 데몬에 두지 않는다」).
- **View state · collections in the webview `localStorage`** — it splits per window (webview), so the library slot of a popout window and the editor area of the main window cannot share the ⇐ source, and the LLM cannot reach it through shell commands.
- **The library as a separate crate** — there is one consumer. Extract it when another crate needs it (memo 96).

Settings · presets are told apart by a **marker inside the file** (`kind`) (D7). If we relied on the extension or folder name, a move would change the kind.

**Preset file** (reading = serde-saphyr · Engram's rewriting = an editor that preserves hand-written comments · shape — the only place that knows both = `library::format` · T2)

```yaml
# 손으로 단 주석은 Engram 이 고쳐도 남는다(T2 — 0b 단계 스파이크가 편집기를 고른다)
kind: preset
version: 1
description: PR 리뷰 전용
presets:
  - 공용/기본 규칙.yaml
instructions:
  - 지침/리뷰 규칙.md
skills:
  - 스킬/리뷰/review
settings:
  - 설정/claude opus.yaml
```

The areas = four per-kind lists (R22). The order of `instructions` · `settings` · `presets` is the concatenation order (D2). An entry is a path string (the old `{path, relinked_from}` shape is withdrawn — there is no path that relinks automatically, so there is nothing to display · D10 · 2026-10-18).

**Settings file**

```yaml
kind: settings
version: 1
description: 모델 고정 — claude opus · codex gpt-5.5
claude:                  # claude 원문 — 실행 때 --settings 로 넘길 settings 객체(Engram 은 해석하지 않는다)
  model: claude-opus-5-5 # 모델도 원문 안 — 있으면 CLI 가 그 모델로 시작(R35 · 선택 칸은 잠그지 않는다)
  env:
    SOME_VAR: "1"
codex:                   # codex 원문 — 실행 때 -c 로 하나씩 넘길 목록
  - model=gpt-5.5
  - model_reasoning_effort=high
```

There are no formal fields — only `kind` · `version` · `description` and the per-backend raw-text fields (user 2026-10-18 — withdraws the old formal `backend` · `model` fields). Model · effort are also inside a raw-text field (D6 confirmed · R5). Launch carries **only the field with the same name as the agent's backend**, and the other fields drop out silently. Engram does not interpret the raw text (it only checks it — §1-4 `validate.rs` · it does not read the model out of the raw text either) — even if two settings put a model in the same backend field, it is not checked and the CLI does what it does (T3). The raw-text field name is a backend word (the same spelling as the backend vocabulary of `agent.new` — case-insensitive).

**`description` (settings · preset — B12 · user 2026-10-19 「일단은 그렇게하자」)** — an optional field. If absent, the list · detail show a dim 「설명 없음」 and do not block. The 「새로 만들기 ▸ 설정 · 프리셋」 template (`library.newFile`) contains an empty `description: ` line. How to write it is carried by the priming (the Engram guide of 「기본」) and `engram help library` (§1-7 CLI) — the file format + an example containing `description:` + one sentence 「만들거나 고칠 때 한 줄 설명을 적는다」. Rejected = a required field (error if absent — an agent can write the file directly).

**Reference shape `LibPath`** — a single shape of `/` path from the top of the library (R3). Rules: UTF-8 · the separator is `/` only · no leading or trailing `/` · no empty segment · `.` · `..` · no `\` · `:` · control characters. The representation is our type (`library::path::LibPath`) wrapping the `RelativePathBuf` of the `relative-path` crate, and that one type handles validation · conversion to a disk path (`to_path(root)`) · prefix replacement on a move (`strip_prefix` + `join`). Whether two paths are the same file is compared by OS rule (Windows = case-insensitive) with the path comparison helper of `platform` — display keeps the spelling on disk.

**Built-in namespace `engram:/` (Δ1)** — a fixed fake path outside the library. `LibPath` does not accept `:`, so the two never mix.

| Reference | Display name | Content |
|---|---|---|
| `engram:/default` | 「기본」 | Instruction `engram:/priming` (a `.md` inside the distribution's `builtin\` — the current priming text as it is · G1) + settings `engram:/settings/default` (a `.yaml` inside the distribution's `builtin\` · claude raw text `{"env":{"DISABLE_AUTOUPDATER":"1"},"allowedMcpServers":[{"serverName":"engram"}]}` — turn off auto-update + Engram messages · control link (server name = agent `MCP_SERVER_NAME`) · T10 · user 2026-10-18 「프리셋으로 해줘. 사실 감추는 설정이 있으면 안되지.」 — the old id `engram:/settings/no-autoupdate` was changed because its content grew) |

**The concrete form = one `builtin\` folder in the distribution** (G1 · main session decision 2026-10-20 — reported) — preset `.yaml` · instruction `.md` · settings `.yaml` are placed in the same shape as the library, and `engram:/…` maps to those files (withdraws the old split 「코드 + 배포판 `prompts\agent-priming.md`」). File names · the shape of the mapping are implementation decisions. ### 1-3. Resolution — 「실제로 받는 것」 (`library::resolve`, a pure function)

Input = an agent (backend + whether the default is on + the attached preset list) or one preset + a lookup function that finds items (tested with a fake store). Output = `Resolution`.

1. **Expansion** — for an agent: [the default (if attached)] then [the attached presets in order]. When expanding one preset = first expand the `presets` inside it in order (D1 — the instructions of an inner preset come **before** its own instructions), then its own `instructions` · `settings` · `skills`.
2. **Duplicates** — if the same preset arrives by two routes, it appears once at the first place (R4). Instructions · settings · skills with the same path likewise appear once at the first place (the path is the identity — internal choice §3).
3. **Cycle** — if it appears again on the stack being expanded, that row is a 「순환」 error.
4. **Backend = agent value** (user 2026-10-18 — the place where the old 「기본 제공 백엔드의 물러남(Δ1 · 3차 델타)」 was withdrawn) — the backend of the resolution is read from the `command` variant of the profile (fixed at creation — §1-5) and does not come from the settings. The settings carry only the raw-text field with the same name as that backend in the resolution (concatenated in the order added), and the other fields drop out silently. When one preset is expanded (editor area — no agent), there is no backend, so no raw-text field is chosen.
5. **Conflict** (red — cannot be launched as it is) — two or more skills with the same name (different paths) are **the only one** (Engram lays skills down as per-name folders, so they collide on our side regardless of the CLI — user 2026-10-18 · withdraws the old 「백엔드 정하는 설정 둘 이상」 · 「`model` 칸 둘 이상(T3)」 — no model conflict check). **One conflict = one row** = what kind of conflict + **all** the items involved, with the route each item came by (the chain of presets from the expansion starting point — for an agent, the attached preset — to that item · the screen joins them with `›` = contained in that preset). It is reported as code + arguments (R49 · §3). The red row in the editor area and the launch block reason `Conflict` (8 · E4) are **the same row** (user 2026-10-18).
6. **Warnings — none** (user 2026-10-18 — PRD R6 · R22 · R45). The yellow category is withdrawn. The old warnings (another backend's raw-text field exists but is unused · the codex size limit was raised (R38) · context share ratio · relinked automatically · 「다음 실행은 새 대화」 for an agent whose backend changes — Δ4) are shown neither in the editor area nor at launch. Behaviour is unchanged — the size limit is raised with `-c` at every launch (§1-5) · relink runs only when the user · LLM chooses it (no candidate suggestion during a scan — user 2026-10-19 · the backend change that triggered the old 「다음 실행은 새 대화」 no longer exists — 4). Reason (user) = rules like which edits cause a new conversation can change, so the screen does not compute by following those rules · the old conversation is not lost. The number is left empty because other places point to 7 · 8.
7. **State** — not found (file missing — row = 「찾을 수 없음 · [다시 연결] ×」) · error (cannot be read · settings schema error) · cycle — attached only to the row that points to it (R6). Neither the old 「다시 연결됨(자동 적용 · 확인 전)」 state nor the old 「찾을 수 없음 — 후보 <경로> [연결]」 (waiting for relink confirmation — the shape of D10 on 2026-10-18) exists — a row is either 「찾을 수 없음」 or fine (B11 · user 2026-10-19 「ㅇㅇ 그게 더 자연스러운것같네」).
8. **Block reasons (right before launch) — five, one category** (user 2026-10-18 「막는게 좋을듯」 — practice: a part attached explicitly is required, so launch is blocked if it is missing · `docs/research/launch-missing-component-practice-2026-10-18.md`). **Whoever launches** (double-click · CLI · LLM) is blocked for the same reasons. ① not found (the attached file is missing — relinking only when the user · LLM chooses it · §1-4 flow ②) ② error (YAML syntax · cycle · type · range error of the settings schema — §1-4 `validate.rs`) ③ conflict (skills with the same name — the reason carries the conflict row of 5 as it is · E4) ④ the library folder is unset/missing but a library preset is attached ⑤ codex file pre-check failure (the codex terminal cannot place files in the working folder — R37). Withdrawn = the old ④ 「다시 연결 확인 대기」 (had only candidate suggestions — the candidate suggestion itself was withdrawn · B11 · user 2026-10-19 · the old ⑤ ⑥ moved up to ④ ⑤) · the old 「백엔드 정하는 설정 없음(R33)」 (the backend is always an agent value) · 「codex 파일 대답 없음」 (codex files are always laid down) · 「설정 실행 직전 검사 실패」 (the CLI check was withdrawn) · the branch 「화면이 낸 실행에서만 막힘」 (user 2026-10-18). How it is shown = §1-10 「막힘 창」 (G13). (Blocking on no workspace = next topic §8)

The same function produces the conflict row of the editor area and the launch block reason (the same row), the **problem list** above the editor area, 「에이전트 N개에서 참조 중」, and all three launch kit parts — so that the screen and launch do not diverge by different rules. `Resolution` has no warning field (6).

**Update rule (user decision 2026-10-16 · 2026-10-17)** — the full scan happens only when the data is first needed (「첫 훑기」 below) · when the library folder is changed. Outside changes are brought in by the tree right-click 「새로 고침」 (that folder — including below · root header row = everything) · F5 = based on the focused area — tree = the selected folder (everything if none) · list = the folder currently viewed, both including below (because we do not re-read when entering a folder — user 2026-10-17) or `library.refresh {folder}` (omitted = everything) — agents are advised to call this command after changing files outside Engram (priming · not enforced — PRD R41 · user 2026-10-17) · the reply carries the problems of the re-read files (§1-7). Safety net = if a command points to a path that is not in the list, only that one path is checked and put in · the attached files are re-checked right before launch. No watching · subscription · broadcast · periodic requests. **The first scan = everything once (user 2026-10-17 · S1–S3)** — write the tags of all files, read the settings · preset `.yaml` files, and even do the syntax · schema check (there is no cache, so everything is 「바뀜」 · the schema is downloaded at this time if first needed — `validate.rs`). A list request that arrives before the first scan ends waits for that scan (the rule that simultaneous requests share one scan stays — flow ①), and the frontend shows a brief loading indicator in the meantime and, when it ends, shows the list · icons · reference counts at once (no filling in pieces — S3 · if slow, look again after the §6-2 measurement). The cache is only in memory, so if the daemon is restarted the full scan runs once more (S1). Implementation = flow ① below.

**Flow ① List request and scan (R19 · request style)** — the two are separated. The list does not read the disk, and only the scan reads the disk.
- **List request** — bus `library.list {folder}` (synchronous port · `blocking_handler` thread) → if the first scan has not happened yet, start it or wait for the one in progress (the merging of 「훑기」 below) → read lock → from the in-memory `Catalog` produce the items directly inside that folder + subfolder rows (including skill folders · skill marking · files that are not our kind are left out — §1-2) · reference counts · state. If a command points to a path not in `Catalog`, only that one path is checked on disk and put in (the safety net of the update rule).
- **Scan** — trigger = first need (the 「첫 훑기」 of the update rule) · `library.refresh {folder?}` · `library.setRoot`. On a daemon worker thread, `FsStore::scan(root, under)` (walkdir · `under = None` = the whole root · `library.refresh {folder}` = `Some(그 폴더)` — scan again only below it, and items outside keep the previous scan state) → re-parse only changed files (tag = path · modification time · size · file identity compared for equality + racy rule — the `catalog.rs` row · re-read settings are checked by `validate.rs` · the first scan has no cache so everything) → rebuild `Catalog` (references = preset + agent, direct + indirect — Δ3 · a reference whose target path is not in `Catalog` = 「찾을 수 없음」 — the old step 「→ 다시 연결 후보(②)」 is withdrawn · B11). During the scan · rebuild, file operations · edits wait (so that the scan result and Engram changes do not interleave). Simultaneous requests (list requests waiting for the first scan · overlapping `library.refresh`) are merged by the scan generation number (a later request waits for and uses the result of the scan in progress — `Mutex` + `Condvar`). The reply of `library.refresh` = number of changed items + problems of the re-read files (§1-7).
- **Changes inside Engram** — flow ③ · ④ · relink application (②) do not scan but directly fix `Catalog` (items · reverse reference index) under the write lock.

**Flow ③ Edit (Δ8)** — `preset.add/remove/reorder` apply to the latest content of the file. **Flow ④ File operations (R17 · R18 · Δ3 · edition 2)** — under the write lock: (a) plan — old → new mapping table (delete = old path → path inside the trash — decided at planning time · placement rule §6-5) · preset files to fix · agents to fix · **the pairs to accumulate in the move record and their numbers (reserved at planning time)** (b) write the journal (the whole plan above) (c) disk operation (`rename` · delete = `rename` into the root `.trash` — within the same root, so no OS Recycle Bin · no copy) (d) fix rows and write atomically per preset file (e) fix agent attachments (`ProfileRegistry` saved once) (f) update the move record (g) erase the journal. A journal left at boot **re-runs (c)~(f) with per-step decisions**: (c) if the old path is absent and the new path exists, treat it as finished and skip (if both are absent, leave the journal as 「실패」 and notify · if only the old path exists, try again) · (d)(e) 「옛 경로면 새 경로로」 — if already fixed, leave it · (f) if the pair with the reserved number is already in the record, skip. The root itself cannot be deleted (it cannot even be pointed to by a path — there is no empty `LibPath`). `library.*` does not accept paths under `.trash` (it is a hidden item and not in `Catalog`, and the safety net 「목록에 없는 경로 하나만 확인해 넣는」 also does not put in a segment that starts with `.` — closes the back door of deleting inside the trash over the bus · this refusal is a main session proposal) — exception = the trash view · restore command (`library.restore` — an item inside the trash back to its original path · the LLM too · G11 · §1-7). **There is no bus · `engram` command for emptying · permanent delete — humans only** (an intended exception to 「LLM-우선 제어」 · §7 28) · both send to the OS Recycle Bin and delete directly if that fails (G12 · §6-5 2).

**Flow ⑤ Launch kit** — §1-5.

**Flow ⑥ Move record (Δc)** — in-app moves · renames · applied relinks accumulate pairs (old → new) with numbers (the most recent 1,000 pairs — when it overflows, drop the oldest first and raise the floor number). Every time a client makes a library request (opening a slot · focus · refresh · moving between folders) it also calls `library.moves {since: 커서}` to receive the pairs after the cursor, fixes its own collections, and then moves the cursor. If the cursor is older than the floor, `truncated` is set in the reply, and collection items moved in between remain 「찾을 수 없음」 (an accepted loss — §6). **Every** client, not only the requesting one, catches up at its own next request — without a broadcast.

**Root · default path** — `library.status` gives `{daemon_id, root, state: unset|ok|missing, suggested_new}`. `suggested_new` is produced by a **method of the data folder layout (`DataLayout`)**. `DataLayout` also holds **where the root came from** (`ENGRAM_DATA_DIR` specified · debug default · release default) — release default (root = `<배포판>\data`) = `library` of its parent, otherwise = `library` **inside** the root. It does not guess from the directory name. So a test isolated with `ENGRAM_DATA_DIR` does not touch the real folder. [Create new] only pre-fills this path and puts no content in (Δ1). When the root is changed, agent attachments · collections are left as they are and **the same paths are looked up in the new root** — if absent, 「찾을 수 없음」. The move record starts anew (Δf — there is no relink that crosses roots · `relink` accepts only paths inside the same root). `.trash` is inside each root — the trash of the old root stays in the old folder. The move record carries a `log_id` drawn anew per root, and if the `log_id` of a client cursor differs, the pairs are not applied and only the cursor is moved to the new head.

**Old agents — not migrated** (D4 · user 2026-10-18 「기존거 필요없어」 — withdraws the old migration (Δ1 · Δh)) — when the daemon of the new build first starts, the `agents.json` written by the old version is not erased but set aside as a backup file, and it starts with an empty registry (main session internal choice · §3). **Compatibility · downgrade (honestly)** — the new build uses the `cwd` key as it is now. `libraryView.*` are **shell commands on top of the per-number view state the shell holds** (the 「레이아웃 명령」 side of R40). **CLI** — the general form `engram <이름> --인자 값` reads the daemon's runtime table, so the CLI code does not change. A boolean stands without a value (`--yes`). A screen button is the same command too — after passing a confirmation modal it calls with `yes=true`.

## 3. Internal choices I made (reported)

- **Localization (PRD R49 · 2026-10-16)** — screen strings only through `src/i18n` keys (`t()` · `ko.ts`). Daemon → screen reasons · states are answered in the shape `{code, args}` (e.g. `{code:"conflict.skill_name", args:{name, items:[{path, via:[프리셋 경로…]}]}}` — a conflict row carries **all** items involved together with the route · it is not pinned to two · §1-3 5) and the screen draws with `t(code, args)` — `Resolution` · `LaunchBlocked` · `CONFLICT` replies · relink display apply. The human-facing CLI output stays Korean as now (policy decision in T-68). Built-in preset display name = a screen key, stored value = `engram:/…`.

Where the body has the basis, only the place is pointed to.

- **Command declaration = agent crate block + port** (§1-5) — the `usage.*` precedent. The daemon's own block + table synthesis is rejected.
- **Complete and use the webview → daemon bus round trip** (§1-7) — no separate wire messages are made for the library.
- **Launch preprocessing = after the reservation · before session derivation** (§1-5 (ga)) — it queues per agent, and the registry change is one mutate (compare-and-swap) so it does not overwrite a value that changed in between, and the latch (ADR-0226) and the incarnation marker see only the aligned profile. A block is also cut off **before** the control channel is issued.
- **Launch kit = `check` → `prepare` + backend `materialize`** · **a dedicated RAII guard** (independent of `ProvisionGuard`) · **placement port `LaunchFs`** (tests backend placement without a disk).
- **Pass-through arguments = `command.extra_args` as it is now** — the backend does not change, so there is no reason to split them per backend (a consequence of user 2026-10-18 — the old `backend_args` · 「`command` 는 해석에서 파생」 · `backend::command_for` withdrawn).
- **codex working folder artifacts = a per-agent list + an ownership marker inside the content** — withdrawn only when the marker and the content are as they were, and deferred until after it stops while running (protecting the user's files).
- **Instructions are merged into one file** — so that it is not necessary to ask whether `--append-system-prompt-file` can be repeated.
- **claude `--system-prompt-snapshot off` only for a real kit** — so that resume sees the changed instructions (no cache loss if the text is the same — measured). The argv of `NoopLaunchKits` is byte for byte as it is (regression golden).
- **claude settings merge** (this rule became a user decision — 2026-10-18 「이어붙이기 진행」 · T10 · §6-5 closed) — in attach order (「기본」 first · then the attached presets — §1-3 1), objects = merged recursively · lists = concatenated and the same value kept once · other values = the later one. There is no specially treated key — the old 「`allowedMcpServers` 는 Engram 값이 권위」 is withdrawn (T10 · no hidden fragment). Consequence = a later preset cannot remove `engram` from the `allowedMcpServers` of 「기본」 (in effect the Engram link remains — accepted). It is claude's share — the same key's `-c` row of codex is as the CLI does and was not measured (§6-3).
- **The old `agents.json` = backup file · empty registry** (the executable form of D4 = no migration — main session internal choice 2026-10-18) — it is set aside, not erased. The version marker · backup name are implementation decisions (§1-5 「옛 에이전트」).
- **Override order** — codex follows the ADR-0216 discipline (pass-through → preset raw text (including the model row) → Engram, a warning if overridden) · claude follows ADR-0094 (`--allowedTools` at the very end).
- **The launch origin is decided by the entry point** — wire `Spawn` · activation = `Interactive` · bus `agent.spawn` · control CLI · boot auto-restore = `Unattended` (there is no person to ask). In this edition it does not change the result (a block is the same whoever launches — §1-5 port) — only the skeleton is placed and the next topic uses it (§8).
- **Relink = one apply function (`relink` — all of the same old path + the rest of the same old folder) · no candidate finding at scan time · no index · no delete record** — as a consequence of withdrawing candidate suggestion (B11 · user 2026-10-19), 「찾을 수 없음」 is now decided only by comparison against `Catalog` (the withdrawn row of §1-1 — this consequence judgment is a target for main session confirmation). The reference fixing of apply is the same function as the file operations (flow ④).
- **Ship in two editions** (B17 · main session decision 2026-10-19 — user delegation 「너가 알아서. 급한건 아니니 효율적인 방향으로」) — edition 1 = library read · edit · attach · launch · settings check · block · 「기본」 · duplicate / edition 2 = file operations · relink · drag-to-move · collections · move record (T8 was handed over to the next topic on 2026-10-20 — G10 · §2-2). Reason = keep the review · QA loop small · use 「프리셋을 붙여 에이전트 실행」 first · in the meantime file operations are done by Explorer · the LLM. Boundary = §5.
- **Agent slot = mount only the editor part + data hooks** (B15 · main session decision 2026-10-19 — user delegation 「알아서 해 이 부분은」) — it does not mount the tree · list · filter · react-arborist · virtual table (§1-10).
- **Duplicate name = 「<이름> (2)」 · (3) …** (B13 · main session choice — user 「네이밍은 관행대로」) — the whole app is aligned with the same single numbering rule as the R17 new item name (Explorer's 「- 복사본」 is a file-copy word, so it is not used).
- **Move record = the most recent 1,000 pairs · `log_id` per root** — an overflowed cursor accepts the loss.
- **Excerpt generation = the daemon `library` module** — from the markdown AST remove code · tables · HTML · front matter and keep only the text (strip-markdown style · the Rust-side parser is chosen at implementation — not measured). It goes in the instruction description field of the `library.list` row (the one line of the 「+ 추가」 search result row) — it is not put on the detail card. Rule = PRD R15 · research = docs/research/markdown-plaintext-snippet-survey-2026-10-17.md · docs/research/snippet-vs-rendered-preview-placement-survey-2026-10-17.md.
- **`rev` = 64-bit hash of the file bytes (std)** — compared only inside the daemon process · no new hash crate is added.
- **Lock = one `std::sync::RwLock` per library** — the port is synchronous, so it is not a tokio lock. The only direction is calling `ProfileRegistry` inside the write lock, so there is no cycle edge with other locks.
- **Built-in references = fixed ASCII ids** (`engram:/default` etc.) · only the display name is Korean.
- **Default preset = the `default_preset` boolean** — a separately shown field that does not take part in the ordering. Commands also accept the `engram:/default` path.
- **Old `preset_palette` slot = folded into an empty slot** — preserving unknown content is not a device for keeping a withdrawn feature.
- **One more submenu level in the slot menu (addendum to ADR-0065)** — the shape 「라이브러리 ▸ 1~4」 (Library ▸ 1~4) of R10. The flat 「라이브러리 1~4」 (Library 1~4) is rejected.
- **Per-number view state = the shell is authoritative · `libraryView.*` shell commands** — fired at the window that holds the slot of that number, and the selection summary to every window (⇐ source — it also holds across pop-outs).
- **Local OS actions = shell Rust through the plugin Rust API** — the webview opener permission is not widened.
- **Area width = inside the per-number view state · the existing `Splitter` family** — `react-resizable-panels` is not brought in.
