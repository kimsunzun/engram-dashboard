한 줄 결론

asset-library는 데몬 안에 들어가는 새 크레이트다. 라이브러리 폴더 하나에 프리셋·지침·스킬·설정 파일을 두고, 그 파일들을 읽고 쓰고 검사한다. 에이전트를 띄울 때는 그 에이전트 백엔드 몫만 골라 실행 재료로 넘긴다.

7단계에서 하는 것크레이트만 짓는다. 아직 아무도 부르지 않는다. 모든 실행은 지금처럼 Noop으로 돈다.
8단계에서 하는 것데몬에 꽂는다. AgentManager가 실행 때 이 크레이트를 부르기 시작한다.
화면지금은 바뀌는 것이 없다. 목록·편집 명령은 9a·10a, 화면은 11·13단계.

폴더 확인 시간 규칙

프리셋은 라이브러리 밖의 폴더(예: 공유 드라이브의 규칙 폴더)를 가리킬 수 있다. 그 폴더가 느리거나 꺼져 있어도 실행 응답이 버스의 명령 응답 한도 7초 안에 나가야 해서, 확인 시간을 두 갈래로 나눴다.

무엇을 확인하나시간답이 없으면
필수프리셋의 폴더 항목(있는지·목록·파일 읽기), 라이브러리 프리셋이 붙었을 때 라이브러리 루트, prepare의 원본 다시 읽기실행 하나에 합쳐서 최대 5초. check가 여러 번 돌고 prepare까지 가도 이 5초를 나눠 쓴다. 이미 답을 받은 폴더는 다시 묻지 않는다.폴더 하나만 늦어도 실행 전체를 막는다.
참고작업 폴더의 정식 경로(정션 풀기), 백엔드 기본 스킬 폴더(예: codex의 <CODEX_HOME>/skills), 같은 이름 스킬 비교용 정식 경로실행 하나에 따로 최대 1초. 필수 5초에서 빼 쓰지 않는다.건너뛴다. 대신할 값을 지어내지 않는다. 작업 폴더는 적힌 경로를 그대로 쓰고, 스킬 폴더 비교는 이번 실행에서 뺀다.

폴더 여러 개는 동시에 확인한다. 열 개가 다 죽어 있어도 5초 한 번이면 끝난다. 폴더 목록이 10,000개를 넘으면 앞부분만 보고 알림을 낸다. 실행은 막지 않는다.

동시성 규칙 두 개

메모리 목록은 읽기·쓰기 잠금 하나로 지킨다. 리뷰 3차에서 같은 종류의 버그가 두 번 연달아 나와서, 사례마다 고치는 대신 아래 두 규칙으로 묶었다.

A목록 쓰기는 항목 하나씩

목록에 쓰는 모든 일(훑기 반영, 실행 검사가 새로 읽은 내용, 목록 요청의 안전망, 스키마 재검사)은 쓰기 잠금 안에서 항목 하나씩 적용한다. 같은 항목이면 나중에 읽은 쪽이 이긴다. 목록을 통째로 바꿔 끼우지 않는다.

예외는 루트 변경 하나다. 앞뒤 변경을 모두 기다리게 하고 혼자 돌며, 새 루트를 처음부터 전부 새로 읽은 뒤 한 번에 바꿔 끼운다. 그동안 읽는 쪽은 옛 목록을 본다. 빈 목록을 보는 일은 없다.

왜: 예전 설계는 훑기 결과를 통째로 바꿔 끼워서, 훑는 사이 들어온 다른 쓰기를 계속 잃었다.

B필수 먼저 혼자, 참고는 그 뒤에

실행을 막을지 정하는 확인(필수)을 먼저, 다른 것과 섞지 않고 돌린다. 알림이나 덤 값만 만드는 확인(참고)은 필수가 끝난 뒤 자기 몫 1초 안에서만 돈다. 필수는 참고를 기다리지 않고, 참고는 필수의 시간을 가져가지 않는다.

왜: 예전 설계는 두 확인을 한 묶음에 넣어서, 막을 이유가 없는 참고 확인이 필수 확인의 시간을 잡아먹고 실행을 막을 수 있었다.

아직 모르는 것

  • jsonschema가 실제 claude 스키마를 받아들이는지로컬에는 0.59.0만 있어 0.60.2로 컴파일·통과하는지 확인하지 못했다. P4에서 확인하고, 안 되면 문법 검사만 하고 스키마 없음 알림(settings-schema-unavailable)을 낸다.
  • codex 스키마 경로릴리스 파일 rust-v<ver>/config-schema.json이 맞는지 미확인. 확인 전까지 codex 설정은 문법과 -c 규칙만 보고, 스키마를 확인하지 못했다는 알림을 낸다.
  • 새 패키지의 라이선스 파일granit-parser · annotate-snippets · encoding_rs_io · jsonschema · relative-path · pulldown-cmark. P1·P3에서 라이선스 게이트를 로컬로 돌려 본다.
  • 새 판의 최소 Rust 버전serde-saphyr 2.1.1, jsonschema 0.61.1의 MSRV는 미확인 (툴체인은 1.95.0, serde-saphyr 2.0.0은 1.89).
  • NaN · -0.0을 다시 쓸 때의 출력TRD는 미확인 항목으로 따로 적지 않았고, P3 골든에서 「-0.0이 그대로 남는다」「NaN끼리는 같다」를 확인하기로 했다. NaN의 부호는 버리기로 정했다.

이 페이지는 TRD 초안 8의 요약이다. 세부 규칙·근거·테스트 목록은 docs/process/S25-preset-library/trd-asset-library.md에 있다 (§3-8 폴더 IO, §6 동시성, §9 조각, §10 결정, §11 위험).
