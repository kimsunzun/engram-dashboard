## 1. 무엇·왜

- 지시서(`.md`) · 스킬(`SKILL.md` 폴더) · 설정(`.yaml`)을 이름 있는 **프리셋**으로 묶고, 에이전트는 프리셋만 붙인다. 에이전트는 깡통이고 백엔드 · 모델은 붙은 설정이 정한다. 같은 규칙 · 스킬 · 설정을 에이전트마다 손으로 맞추지 않고 한 곳에서 고쳐 여럿에 쓰려는 것이다. (메모 6 · 7 · 26)
- **라이브러리** = 사용자가 고른 폴더 하나. 부품도 프리셋도 그 안의 파일(에셋)이고, 남에게 줄 땐 폴더째 넘긴다. 예외는 Engram 내장 프리셋 셋(R43)뿐이고, 그 덕에 라이브러리를 고르기 전에도 에이전트를 만들어 바로 돌린다. (메모 53 · 74 · 127)
- 옛 「프리셋」(작업 폴더 즐겨찾기 — ADR-0061 · `presets.json` · `src/components/slot/PresetPalette.tsx`)과 그것을 고르던 피커는 이전 없이 없애고 이름을 새 체계가 쓴다. 에이전트 트리 pane 메뉴 「에이전트 생성 ▸」 자체는 남는다(R44). 대체 ADR(ADR-0061 · ADR-0070)은 TRD 때. (메모 43 · 44 · 122)

## 3. 요구사항

**에셋과 구성 규칙**
- **R1** 에셋 종류 = 지시서(`.md`) · 스킬(`SKILL.md` 를 든 폴더) · 설정(`.yaml`) · 프리셋(`.yaml`). 프리셋도 라이브러리 안의 파일이다(예외 = 내장, R43). 깨진 프리셋 · 설정은 목록에서 「오류」 + 이유(예 「오류 · YAML 3줄」). YAML 은 방향, 확정은 TRD. (메모 74 · 76)
- **R2** 부품 → 프리셋(프리셋 안에 프리셋 가능 · 복사가 아니라 참조) → 에이전트(프리셋 여러 개). 부품은 프리셋 편집 칸에서만 담고 에이전트는 프리셋만 붙인다. 에이전트가 돌 백엔드 설정도 프리셋으로 온다 — 라이브러리가 없을 땐 내장 백엔드 프리셋(R43 · R44). (메모 26 · 39 · 그림 §1)
- **R3** 참조 = 라이브러리 맨 위부터의 `/` 경로 한 꼴(예 `스킬/리뷰/review`) · 범위 제한 없음. 거부 = 프리셋 파일 기준 상대 경로 · 이름 참조 · ID 파일 — 스킬은 여러 프리셋이 나눠 쓰고, 폴더 브라우저에선 같은 이름이 흔하며, 항목의 정체는 자리다. (메모 101–103 · 그림 §5)
- **R4** 펼친 뒤 검사 — 순환 = 오류 · 같은 프리셋이 두 길로 오면 한 번 · 충돌 = 사용자 백엔드 설정 둘 이상(내장 백엔드 프리셋은 충돌하지 않고 양보하거나 서로 바뀐다 — R44) · 같은 이름 스킬 둘. 지시서 · 설정은 담은 순서대로 이어 붙는다. (메모 7 · 9 · 26)
- **R5** 설정 에셋 — 정식 칸은 `backend` · `model` 뿐. 나머지는 백엔드별 원문 칸(claude = `--settings` 로 넘길 settings JSON · codex = `-c` 목록)이고 그 백엔드로 실행할 때만 쓴다. Engram 은 원문을 해석 · 충돌 검사하지 않는다(내용 책임은 사용자). `model` 은 선택이고 넣으면 고정. 키 이름은 자리표시. (메모 79 · 81 · 167 · 그림 §8)
- **R6** 상태 표시 = 충돌(그대로는 못 씀) · 경고(알리기만) · 찾을 수 없음(다시 잇기) · 오류(못 읽음) · 흐림(담김 · 못 담음). 「찾을 수 없음」 은 없는 파일을 가리키는 자리(프리셋 줄 · 에이전트 슬롯 · 묶음)에만 — 폴더 목록엔 없다. (메모 86 · 그림 §12)
- **R43** **내장 에셋** — 라이브러리 밖 고정된 가짜 경로 이름공간(예 `engram:/…` — 꼴은 TRD)에 산다. 내장 = 기본 프리셋(R32) + 「claude 기본」 · 「codex 기본」 프리셋(각각 내장 백엔드 설정 하나 — `backend` 만, `model` 없음). 라이브러리를 고르지 않아도 있다. 펼쳐 보기만(R27) · 폴더 돋보기와 R28 은 꺼짐 · 다른 프리셋 안에 담을 수 없음(에이전트에만 붙는다) · `engram` 은 가짜 경로로 부른다. 사람은 에이전트 슬롯 `+` 검색 맨 위의 고정 「내장」 묶음(기본 프리셋 · claude 기본 · codex 기본)에서 붙인다 — 뗀 것을 다시 붙이는 길도 이것이다. (기본값 E7 · E17)

**라이브러리 폴더**
- **R7** 라이브러리 = 폴더 하나 · 프리셋도 그 안. 거부 = 프리셋 폴더 따로 + 부품 라이브러리 여럿(루트를 넘는 참조 · 순환 문제). (메모 127)
- **R8** 자동 기본 폴더는 없다. 처음엔 평소 모양 슬롯의 빈 트리 안에 「아직 라이브러리 폴더를 고르지 않았습니다.」 + [폴더 열기] + [새로 만들기]. [새로 만들기]는 폴더 고르기 창에 **경로만** 미리 채우고(배포판 폴더 안 `library\` — `data\` 옆), 고르면 빈 폴더를 만든다 — 내용은 넣지 않는다. 폴더가 없어지면 같은 자리에 「<경로>를 찾을 수 없습니다」 + 같은 단추 · 설정 값은 둔다. (메모 105 · 153–155)
- **R9** 바꾸기 = 트리 맨 위 머리(이름 + 경로) → 「라이브러리 폴더 바꾸기…」 → 폴더 고르기(같은 PC 전용). 설정 창에 같은 칸 · LLM 은 `engram` 명령. **바꾼 뒤 규칙은 하나** — 참조는 새 루트에 대해 경로 그대로 풀린다: 같은 경로가 있으면 그냥 쓰이고(내용이 달라도 — 그 루트를 고른 것은 사용자다) · 없으면 「찾을 수 없음 · 다시 잇기」 · 루트를 넘는 다시 잇기 후보 찾기(R19)는 없다. (메모 123 · 기본값 E19)

**라이브러리 슬롯 (1~4)**
- **R10** 번호 1~4 고정(언리얼 콘텐츠 브라우저 1~4). 슬롯 이름 = 「라이브러리 1~4」(뒤에 붙이지 않는다 — 범용: 나중에 커맨드 묶음 · 스크립트 같은 종류도 담는다 · 사용자 결정 2026-10-16) · 슬롯 추가 메뉴 「라이브러리 ▸ 1~4」 · 열린 번호를 고르면 그 슬롯으로(중복 없음) · 닫힌 번호를 다시 열면 그 번호의 보기 상태(칸 폭 · 마지막 폴더 · 뒤로/앞으로 기록)로 돌아온다. 거부 = PC 당 한 벌 · 슬롯 id 마다 · 마지막 만진 슬롯 폭 물려받기. (메모 149)
- **R11** 배치(그림 §2) — 왼쪽 = 머리 붙은 칸 둘(언리얼 Content Browser 꼴 · 사용자 2026-10-16) — 위 「▾ <라이브러리 폴더 이름>」(폴더 트리 · 머리 누름 = 「라이브러리 폴더 바꾸기…」) · 아래 「▾ 즐겨찾기 ＋」(＋ = 새 묶음 — 목록 끝 단추는 없다). 칸마다 따로 스크롤 · ▾ 로 접으면 머리 줄만 남고 다른 칸이 공간을 쓴다 · 펼친 칸 사이 경계를 끌어 높이 조절(번호마다 기억 — R10). 머리 안 검색 단추는 없다(목록 위 검색이 하위까지 찾는다) · 가운데 = 탐색기식 목록 · 오른쪽 = 상세(프리셋이면 편집 칸 — R20). 맨 위 줄 = 슬롯 전체 폭에 `← →` + 누를 수 있는 경로(`라이브러리 › 스킬 › 리뷰`). 목록 칸 위 줄 = `필터 ▾` · 검색 · 오른쪽 끝 `★ = <대상>` 칩. 칸 사이 경계는 전부 표시 없는 선이고 끌어서 폭을 바꾼다(올리면 커서만 바뀜). 추가 · 가져오기 · 저장 단추는 없다. 거부 = `← →` 만 따로 한 줄 · 목록 칸 위에만(Spacedrive). (메모 118 · 135–136)
- **R12** 폴더를 고르면 바로 안의 것만 · 하위 폴더는 맨 위 📁 줄(더블클릭 = 들어감) · 검색은 하위까지 · 스킬 폴더는 항목. 열 = ★ · 종류 · 이름 · 쓰는 곳. 정렬 = 폴더 먼저, 다음 이름 · 머리 누름 = 그 열 · 다시 = 거꾸로 · ★ 열은 정렬 없음. (메모 65 · 73)
- **R13** `필터 ▾` = 종류 체크(지시서 · 스킬 · 설정 · 프리셋) + 「필터 리셋」 뿐. (메모 121)
- **R14** 뒤로/앞으로는 자리가 바뀔 때만 기록 — 폴더 이동 · 쓰는 곳 링크 · 묶음 보기 · 항목 자리로 가기(R28). 같은 폴더 안 클릭 · 편집은 기록 안 함 · 번호마다 따로. (그림 §2 · 메모 149 · 169)
- **R15** 부품 상세 = 설명 · 위치 · 쓰는 곳, 단추 없음. **쓰는 곳 = 그 항목을 쓰는 프리셋과 에이전트, 직접 + 건너서**(건너서 쓰는 것은 「<프리셋> 통해」 로 표시) — 목록의 쓰는 곳 열도 같은 뜻이다. 프리셋 이름 = 링크 — 트리에서 그 자리를 펼쳐 그 프리셋을 고르고 오른쪽이 편집 칸이 된다 · 에이전트 이름 = 그 에이전트의 프리셋 슬롯(R30)을 연다. 부품 더블클릭 = OS 기본 연결 프로그램(스킬은 `SKILL.md`) · 프리셋은 앱 안 편집 칸. (메모 37–40 · 86 · 기본값 E9)
- **R16** 즐겨찾기 — 머리 이름 「즐겨찾기」(「이 PC 에만 저장」 은 머리 툴팁) · 그 아래 첫 줄 = 처음부터 있는 묶음 **「기본」**(지울 수 없음 · ★ 의 기본 대상) · 그 밖은 사용자가 「+ 새 묶음」 으로 만드는 한 단계 묶음 · 한 항목이 여러 묶음에 · 이 PC 에만 저장(클라이언트 소유) — 이름 = 사용자 결정 2026-10-16(조사 `docs/research/default-favorites-list-naming-survey-2026-10-16.md`). 한 번 누름 = 보기 · 더블클릭 = 보기 + ★ 대상 · 우클릭 「★ 대상으로」. ★ = 대상 묶음에 넣고 빼기 · 목록 ★ = 대상 묶음에 들었나. **★ 대상은 PC 마다 하나**(슬롯마다가 아니다 · 기본 = 「기본」). (메모 50 · 64 · 66 · 67 · 71 · 기본값 E9)
- **R17** 파일 조작 = 옮기기 · 이름 바꾸기 · 지우기 · 새로 만들기(폴더 · 마크다운 · 설정 · 프리셋). 우클릭 메뉴 「새로 만들기 ▸ 폴더 · 마크다운 · 설정 · 프리셋 · 이름 바꾸기 · 지우기」 — 마크다운 = 빈 `.md` · 설정 = `kind: settings` 한 줄 틀 · 프리셋 = `kind: preset` 틀(만들면 바로 편집 칸) · 스킬 메뉴는 없다(폴더 + `SKILL.md` 마크다운으로 만들고, 내용은 편집기 · 에이전트 몫 — 사용자 결정 2026-10-16) · 옮기기 = 목록에서 트리로 끌어 놓기. 옮기거나 이름을 바꾸면 데몬이 **같은 조작 안에서** 프리셋 속 경로와 에이전트 붙임을 함께 고친다. 묶음은 클라이언트 것이라, 데몬이 최근 옮기기 짝(옛 → 새 · 순번)을 짧게 기록해 두고 클라이언트마다 다음 요청(열기 · 포커스 · 새로고침) 때 자기가 본 것보다 새 짝을 받아 자기 묶음을 고친다 — 화면 · CLI · LLM 누가 옮겨도 같다. 바깥에서 만든 파일은 새로고침에 보인다. (메모 106–111 · 그림 §4 · 기본값 E9)
- **R18** 지우기는 늘 데몬 PC 의 OS 휴지통으로. 쓰는 곳(R15)이 있으면 먼저 확인 창 — 쓰는 프리셋과 에이전트를 함께 늘어놓는다(예 「프리셋 2개가 씁니다 — 리뷰어 · 야간 점검」 · 「휴지통으로 갑니다」 · [취소] [휴지통으로]). 지운 뒤 그 줄들은 「찾을 수 없음」 이다. 에이전트의 `engram` 명령도 같다(확인 = R48). (메모 112 · 그림 §4 · 기본값 E9)
- **R19** **다시 잇기** — 후보는 가리키던 것이 **바깥 변경**으로 사라졌고 **같은 종류 · 같은 이름 · 정확히 하나**일 때만 생긴다. Engram 으로 지운 뒤(→ 「찾을 수 없음」) · 라이브러리 폴더를 바꾼 뒤(→ R9)엔 후보가 없고, 그 밖엔 「찾을 수 없음 · 다시 잇기」 로 사용자가 고른다. 후보를 저절로 쓸지 확인 한 번 뒤 실행에 쓸지 = **D10**. 이어진(또는 제안된) 줄의 「다시 이어짐 · 원래 <경로>」 는 확인할 때까지 편집 칸 줄 · 라이브러리 목록(상태 표시 · 쓰는 곳) · 에이전트 슬롯 머리에 보이고 그 자체로 실행을 막지 않는다. 이음이 정해지면 데몬이 프리셋 파일(에이전트 붙임도)에 적는다. **목록 갱신(사용자 결정 2026-10-16)** — 전체 훑기는 데몬이 처음 라이브러리를 열 때 · 라이브러리 폴더를 바꿀 때만. 그 밖의 목록 요청(슬롯 열기 · 포커스 · 폴더 이동)은 데몬이 들고 있는 메모리 목록으로 답하고, Engram 안의 변경(옮기기 · 이름 · 지우기 · 새로 만들기 · 편집)은 그 목록에 바로 반영한다. 바깥 변경은 F5(포커스된 라이브러리 슬롯의 현재 폴더 — 하위 포함) 또는 `library.refresh {folder}`(생략 = 전체)로 들인다 — 에이전트는 파일을 만든 뒤 이 명령을 부른다(프라이밍). 안전장치 = 명령이 목록에 없는 경로를 가리키면 그 경로 하나만 확인해 넣는다 · 실행 직전 붙은 파일을 다시 확인한다. 감시 · 구독 · 방송 · 주기 요청 없음. 다시 잇기 후보는 훑을 때 찾는다. 거부 = 데몬 감시 + 바뀜 신호(「화면 보고 있는 동안 바로 보여줄 필요 없음」). (메모 68 · 88 · 99–100 · 기본값 E8)

**프리셋 편집 칸 (공용 부품)**
- **R20** 편집 = 라이브러리 슬롯 오른쪽 칸 하나. 가운데에서 프리셋을 누르면 상세 칸이 그대로 편집 칸이 된다(잠금 없음). 따로 된 편집 슬롯 종류는 없다. (메모 85 · 122)
- **R21** ★같은 편집 부품 하나가 라이브러리 오른쪽 칸과 에이전트 프리셋 슬롯(R30)을 맡는다 — 두 벌을 만들지 않는다(사용자 주의).★ (메모 146 · 161)
- **R22** 종류별 칸 = 프리셋 · 지시서 · 스킬 · 설정(그림 §3 「편집 칸 = 종류별 칸」). 지시서 · 설정은 ⋮⋮ 로 끌어서 순서(= 이어 붙는 순서) · 스킬은 이름순 · × = 빼기 · 저장 단추 없이 바로 저장. 충돌(빨강) · 경고(노랑)는 칸 아래 줄(예 「백엔드 정하는 설정이 둘 — codex high · 공용 규칙 › claude opus」). 거부 = 한 줄로 섞인 목록 · 「담은 것 | 최종 구성」 탭(세션 발상 · 피어 없음). (메모 128 · 130 · 145)
- **R23** 칸 제목 단추, 이 순서 = `+`(그 종류만 검색해 담기 — ▾ 없는 단추 하나) · `⇐`(다른 라이브러리 슬롯에서 고른 것 중 그 종류만) · 폴더 돋보기(그 종류를 둘러보러 **다른** 라이브러리 슬롯을 연다 — 편집 칸은 그대로 · 대상 슬롯 = E11). 편집 칸 머리 = 「← 선택한 것 담기」(주 경로) · 「+ 담기」(전체 검색). 담은 것은 자기 종류 칸의 끼울 자리(R46) 뒤 · 없으면 끝에 들어간다. (메모 85 · 128 · 139–141 · 그림 §7)
- **R24** `⇐` · 「← 선택한 것 담기」 의 원천 = 다른 라이브러리 슬롯 중 마지막으로 만진 곳의 선택 · 없으면 비활성 · 원천 강조 없음. 고른 것 일부를 못 담으면 담을 수 있는 것만 담고 나머지는 건너뛰며 한 줄 결과를 보인다(예 「2개 담음 · 1개 못 담음(순환)」). 에이전트 슬롯은 프리셋만 받고 다른 종류는 같은 문구로 건너뛴다. (메모 85 · 142 · 기본값 E12)
- **R25** 검색 팝오버 — 열면 검색칸에 커서 · 하위까지 찾음 · 체크 = 바로 담김(여러 개) · 담긴 것 = 비활성 + 「담김」 · 순환 · 충돌 = 비활성 + 이유 · 「이미 담김」 칸 · 묶음 칩 없음. (메모 83–84 · 그림 §7)
- **R26** 라이브러리 우클릭 「프리셋에 추가」 는 없다 — 담기는 편집 칸에서만. (메모 143–144)
- **R45** **편집 영향** — 편집 칸 머리에 「에이전트 N개가 씀」(직접 + 건너서 — R15). 편집이 어느 에이전트의 **풀린 백엔드**를 어느 쪽으로든 바꾸면 그 칸 아래 경고 줄 「에이전트 N개가 다음 실행에서 새 대화로 시작합니다」. 돌고 있는 에이전트에는 여전히 아무것도 띄우지 않는다(R36). (기본값 E10)
- **R46** **고름** — 마지막으로 누른 줄이 그 칸의 끼울 자리다. 프리셋 줄 누름 = 고르기 + 펼침 토글(R27) · 부품 줄 누름 = 고르기 + 상세 패널 토글(R29). 고름은 다른 줄을 누르거나 Esc · 빈 곳 누름까지 남는다. (기본값 E13)
- **R47** **동시 · 낡은 편집** — 편집은 전부 조작(담기 · 빼기 · 순서 등)으로 데몬에 보내고 데몬이 **최신 파일**에 적용한다. 데몬은 그 화면이 본 파일 판을 확인한다 — 담기 · 빼기는 낡은 화면에서 와도 적용(항목 기준 멱등) · 순서 바꾸기는 낡은 화면이면 거절하고 그 화면을 새로 불러 「다른 곳에서 바뀌어 새로 불러왔습니다」. 바깥 편집(LLM 이 YAML 을 고침)도 같은 길로 잡힌다. 자세한 것은 TRD. (기본값 E14)

**안에 든 프리셋**
- **R27** 프리셋 줄 한 번 누름 = 그 자리에서 ▸/▾ 펼침. 안쪽은 바깥과 같은 레이아웃을 한 단 들여 같은 부품을 재귀로 쓰고(안쪽의 안쪽도 ▸), 흐리게 · 보기만(+ · × · 순서 없음). 고치려면 그 프리셋을 연다 · 바깥에서 그 줄을 빼는 것은 된다. 거부 = 안쪽 것을 바깥 칸에 섞기(상속 도구 관례 — 우리는 여럿을 포함한다) · 그 자리 고치기(공유 파일이라 쓰는 곳이 전부 말없이 바뀐다). (메모 130 · 132 · 169)
- **R28** 줄 호버의 폴더 돋보기를 누르거나 줄을 더블클릭하면 그 항목 자리로 간다. 라이브러리 슬롯에선 같은 슬롯이 그 자리로 가고 거기서 그 프리셋을 고칠 수 있으며 `←` 로 돌아온다. 에이전트 슬롯에선 라이브러리 슬롯(E11 의 대상)이 그 자리로 가고 에이전트 슬롯은 그대로 남는다 — 돌아오기 = 에이전트 슬롯을 다시 누름. 내장(R43)은 꺼짐. (메모 140 · 169 · 그림 §3 「편집 칸의 줄 누르기」 · 기본값 E11)

**상세 패널**
- **R29** 편집 칸의 지시서 · 스킬 · 설정 줄을 누르면 그 상세(라이브러리 상세와 같은 내용)가 슬롯 가장자리에 붙어 **옆 슬롯 위로 겹쳐** 나온다 — 옆 슬롯 크기 · 내용은 그대로. 같은 줄 다시 = 닫힘 · 다른 줄 = 그 항목. 창 끝 슬롯이면 창에 걸려 잘린 채 둔다(뒤집기 · 안쪽 대체 없음 — 보려면 넓힌다). 패널이 창 밖으로 **통째** 나가는 경우(팝아웃 창 · 창을 채운 오른쪽 끝 슬롯)는 D11. 거부 = 슬롯 안에 칸 끼워 넣기 · 팝업처럼 뒤집기. (메모 137–138 · 그림 §3)

**에이전트 프리셋 슬롯**
- **R30** 에이전트 프리셋 편집 = 슬롯 종류 하나 = **편집 칸만 켠 라이브러리 슬롯**(트리 · 목록 숨김 — 세션 해석). 통째 재사용이 느리면(예: 훑기) 로직(편집 부품 + 데이터 훅)만 재사용. 번호 없음 · 에이전트 트리 우클릭 「프리셋…」 으로 열고 이미 열려 있어도 하나 더 · 팝아웃하면 OS 창. 거부 = 트리 옆 펼침 칸 · 라이브러리 오른쪽 칸에 에이전트 띄우기(그림 §9 「버린 안」). (메모 157–163)
- **R31** 칸 = 맨 위 따로 구분된 「기본」 + 「프리셋」. 에이전트에선 프리셋 칸만 고친다(`+` · `⇐` · 폴더 돋보기 · ×) · 붙은 프리셋은 R27 처럼 펼쳐 보기만 · 머리 = 이름 + 풀린 백엔드 · 모드(예 「리뷰봇 codex · JSON」) + 워크스페이스(D3 추천 기준) · codex 파일 만들기 답(R37) — 둘 다 머리 메뉴에서 보고 바꾼다(CLI · 버스 실행이 정한 값도 — R48). 워크스페이스를 바꾸면 「다음 실행에서 새 대화로 시작합니다」 를 알린다(claude 세션이 작업 폴더에 묶인다 — R34). (메모 146 · 164–165 · 그림 §9 · 기본값 E15)
- **R32** 「기본」 칸 = 내장 기본 프리셋 하나뿐(모든 에이전트에 거는 사용자 공용 층이 아님) + 하는 일 한 줄 「Engram 사용 안내 · claude 자동 업데이트 끄기」 — 버릇처럼 떼지 않게 따로 보인다. 내용 = 프라이밍(Engram 수신 계약) + 기본 설정(claude 원문 `{"env":{"DISABLE_AUTOUPDATER":"1"}}` — 지금 다른 세션이 claude 백엔드에 박는 것을 이리 옮긴다). 만들 때 늘 붙고, 떼면 확인 창(「기본 프리셋을 떼면 Engram 사용 안내와 claude 자동 업데이트 끄기가 빠집니다.」 · □ 다시 묻지 않기 · [취소] [떼기]). (메모 77–82 · 164–165)
- **R44** **에이전트 만들기 · 이전** — 만들기는 에이전트 트리 pane 메뉴 「에이전트 생성 ▸ claude/codex × JSON/터미널」 그대로(안의 옛 작업 폴더 즐겨찾기 고르기만 없앤다 — 메모 44). 만들면 기본 프리셋(「기본」 칸) + 고른 백엔드의 내장 백엔드 프리셋(「프리셋」 칸)이 붙어 곧바로 실행된다. 모드는 만들 때 고르는 에이전트 값(D5). **양보(풀 때 규칙)** — 내장 백엔드 프리셋은 붙은 채 남고, 펼친 구성에 사용자 백엔드 설정이 하나라도 있으면 양보한다: 흐리게 「쉼 — <프리셋> 의 백엔드가 이김」. 그 사용자 백엔드가 나중에 사라지면(편집으로 빠짐 · 떼기) 내장이 다시 깨어난다 — 내장을 떼지 않는 한 이 규칙 때문에 에이전트가 백엔드 없이 남는 일은 없다. 사용자 백엔드 설정 둘은 R4 충돌. **내장 둘** — 내장 백엔드 프리셋은 한 에이전트에 하나만: 「내장」 묶음에서 다른 쪽을 붙이면 앞의 것을 바꾼다(그 줄은 「바꾸기」 로 보이고 R45 의 「새 대화」 알림이 붙는다). **이전** — 기존 에이전트 = 기본 + 맞는 내장 백엔드 프리셋 · 지금 작업 폴더 = 워크스페이스 · 사용자 폴더의 codex 터미널 에이전트는 R37 답 = 「만들지 않음 · 프라이밍만」(지금 동작). (기본값 E7 · E18 · → D4)

**실행 시 적용**
- **R33** 백엔드 정하는 설정이 없으면 실행하지 않는다 · 설정을 다른 백엔드로 바꾸면 새 대화. (메모 7)
- **R34** 워크스페이스가 없으면 — 화면에서 실행하면 「어디서 일할까요?」 — [Engram 폴더 자동 생성] · [찾아보기…](같은 PC 전용) · 고른 폴더는 그 에이전트에 저장해 다음엔 묻지 않는다. CLI · 버스가 실행을 요청하면 묻지 않고 Engram 폴더를 만들어 쓰고, **그 폴더도 그 에이전트의 워크스페이스로 저장**한다(R48 · 머리에 보임 — R31). Engram 폴더 위치는 설정이고 바꾸면 새 에이전트에만(claude 세션이 cwd 에 묶인다). (메모 11 · 27 · 28 · 그림 §10)
- **R35** 모델 · 강도 — 저장 값은 설정 에셋 값 하나(공유 · 고정) · 에이전트별 기억 없음 · 대화 중 바꾼 것(`/model`)은 그 세션뿐. 바꿔 쓰려면 프리셋에 `model` 을 넣지 않는다 — 모델 인자 없이 CLI 기본값. JSON 모드는 **새 대화마다** 첫 메시지 전에 모델 · 강도 칸(claude `initialize` · codex `model/list`)이 뜨고(이어받기엔 없음) 그 선택도 그 세션뿐(세션 해석) · 설정이 `model` 을 고정하면 그 모델이 잠긴 채 「설정이 고정」. **피커는 막지 않는다** — 처음부터 골라진 채(CLI 기본값 또는 잠긴 모델) 뜨고, 첫 메시지가 어디서 오든(화면 · 버스) 그때 골라진 값을 쓴다. 터미널 모드 = CLI 기본값 · 안에서 `/model`. (메모 27 · 166–167 · 그림 §10 · 기본값 E16)
- **R36** 바꾼 프리셋 · 부품은 다음 실행(이어받기 포함)부터 — 돌고 있는 에이전트에 알림 · 배지 · 재시작 단추 없음. (메모 14 · 168)
- **R37** codex 터미널 모드 — Engram 폴더면 파일로 깐다(지시서 = 생성 파일 · 스킬 = 디렉터리 정션 · 실행마다 결정적으로 다시 만듦). 사용자 폴더면 파일(`AGENTS.override.md` + `.agents/skills/engram-*` 링크)을 만들지의 답을 에이전트마다 기억하고, 기억된 답이 없으면 화면 실행은 묻고 CLI · 버스 실행은 묻지 않고 「만들지 않음 · 프라이밍만」 — **이 값도 그 에이전트의 답으로 기억**한다(R48 · R31). 막는 경우(이미 있는 `AGENTS.override.md` · 같은 폴더의 다른 프리셋 codex 터미널 에이전트)를 먼저 검사한다. git 숨기기는 사용자 몫. 안 만들면 프라이밍만 `-c developer_instructions` 로(메모 15 · 30 결합 — TRD 확인). (메모 12 · 15 · 30)
- **R38** codex 크기 한도(`project_doc_max_bytes` 32 KiB · 스킬 문맥 한도)는 실행마다 재서 `-c` 로 올리고(저장 안 함) 크기가 바뀌었을 때만 알린다 · 문맥 차지 비율 경고. (메모 13)

**LLM 제어 경로** (원칙 「LLM-우선 제어」)
- **R39** 프리셋 · 라이브러리 조작은 전부 **데몬 명령**이고 화면 단추와 LLM(`engram` CLI · 버스)이 같은 명령을 부른다 — 라이브러리 폴더 읽기 · 바꾸기 · 목록 · 항목 읽기 · 파일 조작 다섯 · 담기 · 빼기 · 순서 · 다시 잇기(표시 확인 포함) · 펼친 구성과 충돌 · 경고 읽기 · 에이전트 만들기 · 프리셋 붙이기 · 떼기(기본 · 내장 포함). 이름은 자리표시(그림 §11). 원격(나중) 편집도 이 명령으로. (메모 70 · 72)
- **R40** 개인 데이터(묶음 · ★ 대상)와 슬롯 보기(번호 슬롯 열기 · 폴더 이동 · 항목 고르기)는 클라이언트의 기존 표면(`window.__engramCmd` · 레이아웃 명령)에 얹는다 — 새 전역 핸들 없음. (메모 71)
- **R41** 에이전트는 파일 내용을 직접 고치고 옮기기 · 이름 바꾸기 · 지우기는 `engram` 명령으로 한다(참조가 같이 고쳐지게) — 이 규칙을 프라이밍에 넣는다. `engram` 은 부품 경로를 돌려준다. (메모 38 · 110)
- **R48** **사람용 확인이 낀 조작의 CLI · 버스 경로** — 쓰이는 항목 지우기(R18) · 기본 프리셋 떼기(R32)는 `--yes` 가 없으면 쓰는 곳 · 이유를 돌려주며 거절. 실행 대화상자는 **누가 만들었나가 아니라 누가 실행을 요청했나**로 가른다 — CLI · 버스가 요청한 실행엔 대화상자가 없다: 워크스페이스 없음 → Engram 폴더 자동(R34) · codex 터미널 + 사용자 폴더 + 기억된 답 없음 → 「만들지 않음 · 프라이밍만」(명시 플래그로만 만듦 · R37) · 모델 피커는 막지 않으니 골라진 값 그대로(R35). 이렇게 정해진 워크스페이스 · R37 답은 화면에서 고른 것과 똑같이 에이전트에 저장되고 머리 메뉴에서 보고 바꾼다(R31). (기본값 E15)

- **R49** **로컬라이제이션 대비(사용자 2026-10-16)** — 새 화면 글자(메뉴 · 확인 창 · 칸 제목 · 상태 이름)는 기존 다국어 장치(`src/i18n` 의 `t()` + `ko.ts`)의 키로만 쓴다(컴포넌트에 직접 박지 않는다). 데몬이 돌려주는 사유 · 상태(충돌 · 경고 · 찾을 수 없음 · 실행 막힘 · 다시 이어짐)는 문장이 아니라 **코드 + 인자**로 주고 화면이 번역한다. 내장 프리셋의 표시 이름(「기본」 · 「claude 기본」)도 키 — 저장 값은 `engram:/…` 경로. 번역하지 않는 것 = 사용자가 만든 파일 · 폴더 이름 · 파일 안 형식 낱말(`kind` 등) · 명령 이름. 앱 전체 번역은 tracking T-64.

**도킹**
- **R42** 두 슬롯(라이브러리 · 에이전트 프리셋)은 평범한 슬롯 종류로 만든다 — 슬롯 종류를 가리지 않는 도킹 작업(wt2 `v0.4.1/feat/slot-docking` · `docs/process/S21-slot-docking/` — 이 브랜치엔 없음)이 그대로 붙게. 도킹 자체는 범위 밖. (메모 152 · 161)

**불변 제약 (원칙 — 지킬 벽)**
- 데이터(훑기 · 프리셋 · 설정 내용 · 쓰는 곳 · 다시 잇기 · 내장 에셋)는 **데몬 소유**. 클라이언트는 디스크를 읽지 않고 보이기만 하며, 쥐는 것은 보기 상태(폴더 · 선택 · 정렬 · 기록 · 칸 폭)와 개인 데이터뿐 — 개인 데이터 항목 키에 데몬 신원이 든다. (메모 58–59 · 71 · 87)
- 클라이언트 · 데몬은 지금 같은 PC. 화면은 OS 대화상자 · 기본 프로그램 열기 · 탐색기 보이기를 직접 부르지 않고 요청 하나를 지난다(지금 = OS 기본 · 원격엔 끈다). (메모 60 · 63)
- 서드파티 라이브러리는 늘 우리 부품 뒤에 감싼다. (메모 93 · 113)
- 백엔드 지식은 「백엔드 확장」 한 곳 · OS 별 동작(휴지통 · 기본 프로그램 · 정션)은 「플랫폼 중립」 OS 층. (원칙)

## 5. 미결 결정

- **D1 안에 든 프리셋의 지시서 순서** — 자기 지시서 앞 ↔ 뒤(메모 128 「앞으로 그렸고 미정」). **추천 = 앞** — 공용 규칙 위에 자기 규칙을 얹는 모양이고 그림 §3 이 그렇다.
