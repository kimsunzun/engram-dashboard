## 1. 무엇·왜

- 지침(`.md`) · 스킬(`SKILL.md` 폴더) · 설정(`.yaml`)을 이름 있는 **프리셋**으로 묶고, 에이전트는 프리셋만 붙인다. 백엔드(claude · codex)는 에이전트가 만들 때 고르는 값이고 고정이다 — 설정은 백엔드별 원문 칸만 갖고 에이전트의 백엔드와 같은 칸이 쓰인다(모델도 그 칸 안 — R5 · R44 · 사용자 2026-10-18). 같은 규칙 · 스킬 · 설정을 에이전트마다 손으로 맞추지 않고 한 곳에서 고쳐 여럿에 쓰려는 것이다. (메모 6 · 26 · 2026-10-18)
- **라이브러리** = 사용자가 선택한 폴더 하나. 부품도 프리셋도 그 안의 파일(에셋)이고, 남에게 줄 땐 폴더째 넘긴다. 예외는 Engram 기본 제공 프리셋 「기본」(R43)뿐이다. 백엔드가 에이전트 값이라 라이브러리를 선택하기 전에도 에이전트를 만들어 바로 돌린다. (메모 53 · 74 · 127)
- 옛 「프리셋」(작업 폴더 즐겨찾기 — ADR-0061 · `presets.json` · `src/components/slot/PresetPalette.tsx`)과 그것을 선택하던 피커는 이전 없이 없애고 이름을 새 체계가 쓴다. 에이전트 트리 pane 메뉴 「에이전트 생성 ▸」 자체는 남는다(R44). 대체 ADR(ADR-0061 · ADR-0070)은 TRD 때. (메모 43 · 44 · 122)

## 3. 요구사항

**에셋과 구성 규칙**
- **R1** 에셋 종류 = 지침(`.md`) · 스킬(`SKILL.md` 를 든 폴더) · 설정(`.yaml`) · 프리셋(`.yaml`). 프리셋도 라이브러리 안의 파일이다(예외 = 기본 제공, R43). **지침 = 어디에 있든 모든 `.md`**(스킬 폴더 안 것도 · 내용 자유 · 형식 없음 · 예외 = `SKILL.md` 자신 — 그 스킬을 대신한다, R12 · `.txt` 는 지침 아님 — 사용자 2026-10-17). **우리 종류가 아닌 파일은 목록에 안 보인다**(그림 · `.json` · `.txt` · 스크립트 등 · 스킬 폴더 안도 · `kind` 가 없거나 아예 못 읽는 `.yaml` 도 — 사용자 2026-10-17). 「오류」 + 이유(예 「오류 · YAML 3줄」)는 `kind: preset` · `kind: settings` 인데 깨진 파일과 모르는 `kind` 값(오타일 것)뿐. YAML 은 방향, 확정은 TRD. (메모 74 · 76)
  - **설정 검사 — 가볍게 · 데몬 안에서만 · CLI 를 돌리지 않는다**(사용자 2026-10-18 「가볍게하는걸로하고 나중에 문제되면 차후에 고려하자」 · 「안되면 그냥 어느정도 미스매칭 각오하고 별도로 라이트하게」 — 10-17 의 실행 직전 CLI 검사(`claude --settings … doctor` · `codex debug models` / `codex doctor`)와 그 통과 기록 · 막힘 이유 「설정 실행 직전 검사 실패」 를 걷음 · 실측 = `docs/research/settings-asset-validation-spike-2026-10-17.md`). ① 문법(YAML) → ⛔ 오류 「N째 줄」 ② 스키마 — claude = SchemaStore `claude-code-settings.json`(공식 문서가 가리키는 커뮤니티 관리본 · claude 보다 늦다 — `docs/research/claude-settings-schema-source-2026-10-18.md`) · codex = 설치된 판의 릴리스 `config-schema.json`. 스키마가 아는 키의 타입 · 범위 오류 → **⛔ 오류 — 실행을 막는다**(「막어」 — claude 는 값 하나의 타입만 틀려도 `--settings` 전체를 말없이 버린다 · 실측) · 모르는 키 = claude 는 표시 안 함(SchemaStore 가 새 키를 많이 놓친다) · codex 는 ⚠ 만(막지 않음 — 10-17 그대로). **검사 때 = Engram 이 내용을 읽을 때마다**(값싼 검사의 VS Code · JetBrains 관행) — 첫 훑기(전부) · 새로 고침(꼬리표로 바뀐 파일) · Engram 안 편집(바로) · 실행(붙은 설정 — 이미 읽음) · 스키마가 바뀌면 전부 다시. 스키마 내려받기 = 실제로 필요할 때(그것이 필요한 훑기 — 데몬 시작 때 아님 · 「가장 늦은 타이밍 … 실 필요할 때」) · 설치된 claude · codex 판이 지난번 내려받을 때와 다르면 그때 다시 받는다(세션 제안 · 이의 없음). 「검사」 · 「모두 검사」 메뉴와 `library.validate` 는 없다 — 새로 고침(F5 · 우클릭 「새로 고침」 · `library.refresh`)이 맡는다 · 「검사 필요」 상태도 없다(검사가 거의 공짜라 읽을 때마다 돈다)(세션 제안 · 이의 없음). 편집기 포커스 때 다시 읽기는 없다(「너무 복잡하게 할 필요는 없는것같아」 — 바깥 편집은 새로 고침 · 실행 때 보인다). 실행 중 오류(종료 코드 + stderr)는 설정 줄에 ⛔ 를 붙이지 않는다 — 에이전트에만 보인다(종료 코드 + stderr 원문 · 사용자 2026-10-18 — 10-17 의 「그 설정 줄 ⛔」 를 걷음). 아이콘은 목록 이름 칸에 보이고 툴팁 · 상세 카드에 이유(예 「3째 줄 · …」). 스키마 오류 · 문법 오류는 실행 막힘 이유 「오류」(E4).
- **R2** 부품 → 프리셋(프리셋 안에 프리셋 가능 · 복사가 아니라 참조) → 에이전트(프리셋 여러 개). 부품은 프리셋 편집 칸에서만 추가하고 에이전트는 프리셋만 붙인다. 백엔드는 프리셋으로 오지 않는다 — 에이전트 값(만들 때 고름 · 고정 — R44 · 사용자 2026-10-18 「그건 에이전트가 골라야지」). (메모 26 · 39 · 그림 §1)
- **R3** 참조 = 라이브러리 맨 위부터의 `/` 경로 한 꼴(예 `스킬/리뷰/review`) · 범위 제한 없음. 거부 = 프리셋 파일 기준 상대 경로 · 이름 참조 · ID 파일 — 스킬은 여러 프리셋이 나눠 쓰고, 폴더 브라우저에선 같은 이름이 흔하며, 항목의 정체는 자리다. (메모 101–103 · 그림 §5)
- **R4** 펼친 뒤 검사 — 순환 = 오류 · 같은 프리셋이 두 길로 오면 한 번 · 충돌 = 같은 이름 스킬 둘 이상(경로 다름) 하나뿐이다 — Engram 이 스킬을 이름별 폴더로 까니 CLI 와 무관하게 우리 쪽에서 실제로 부딪힌다. 모델 충돌 검사는 없다(R5 · 사용자 2026-10-18 — 옛 「백엔드 설정 둘 이상」 충돌 걷음). 지침 · 설정은 추가한 순서대로 이어 붙는다. (메모 9 · 26 · 2026-10-18)
- **R5** 설정 에셋 = `description` + 백엔드별 원문 칸뿐(claude = `--settings` 로 넘길 settings JSON · codex = `-c` 목록) — 정식 `backend` · `model` 칸은 없다(사용자 2026-10-18 — 메모 79 의 정식 칸을 걷음). 에이전트의 백엔드와 같은 칸만 쓰고 추가한 순서로 잇는다 — **claude 칸은 붙인 순서로 settings 파일 하나에 합쳐 `--settings` 하나로 넘긴다 — 값은 나중 것 · 목록은 합침**(객체 = 재귀로 합침 · 목록 = 붙인 순서로 이어 붙이고 같은 값은 하나로 · 그 밖의 값 = 뒤 프리셋이 이긴다 · 키마다 다른 규칙 없음 — 사용자 2026-10-18 「이어붙이기 진행」 · 그래서 뒤 프리셋은 `allowedMcpServers` 에서 `engram` 을 뺄 수 없다 — 받아들임)(Engram 우선 규칙 · 숨긴 설정 조각 없음 — TRD T10 · 사용자 2026-10-18 「프리셋으로 해줘. 사실 감추는 설정이 있으면 안되지.」 · Engram 통로 키는 「기본」 의 claude 칸에 보이게 둔다 — R32) · codex 칸은 `-c` 목록을 이어 붙인다. 모델 · 강도도 그 칸 안에 둔다(예 claude 칸 `model: claude-opus-5-5` · codex 칸 `- model=gpt-5.5` · `- model_reasoning_effort=high`) — 칸을 백엔드마다 둔 것이 에이전트 백엔드에 맞는 칸으로 갈아 끼우려는 것이고 모델은 에이전트가 고르지 않는다(「근데 model을 왜 에이전트가 골라」). Engram 은 원문을 해석 · 충돌 검사하지 않는다(내용 책임은 사용자) — 두 설정이 같은 백엔드 칸에 모델을 넣어도 충돌 검사는 없다 — claude 는 합칠 때 뒤 값이 남고(위) · codex 는 CLI 가 하는 대로다(「클로드 쪽에서 허용하면 허용인거고 안되면 충돌인거지」 · 검사하려면 CLI 마다 대조표를 CLI 갱신 때마다 고쳐야 한다). 모델을 넣으면 CLI 가 그 모델로 시작한다 — JSON 피커는 잠그지 않는다(R35 · 사용자 2026-10-18). 키 이름은 자리표시. (메모 79 · 81 · 167 · 2026-10-18 · 그림 §8)
- **R6** 상태 표시 = 충돌(그대로는 못 씀) · 찾을 수 없음(「찾을 수 없음 · [다시 연결] ×」 — R19) · 오류(못 읽음 · 설정 스키마 오류 — R1) · 흐림(이미 추가됨 · 추가할 수 없음). **경고(알리기만) 범주는 없다**(사용자 2026-10-18 — R22 · R45 · 설정 검사의 codex 모르는 키 ⚠ 만 예외 — R1). 옛 「다시 연결됨(확인할 때까지 그 줄에 붙는 표시)」 은 걷었다 — 줄은 찾을 수 없음이거나 멀쩡하다(D10 · 관행 — 2026-10-18 · 2026-10-19 에 훑기 후보 제안 줄도 걷음 — R19). 「찾을 수 없음」 은 없는 파일을 가리키는 자리(프리셋 줄 · 에이전트 슬롯 · 컬렉션)에만 — 폴더 목록엔 없다. **안쪽 오류 끌어올림** — 안에 찾을 수 없음 · 오류가 든 프리셋 줄은 접혀 있어도 빨간 오류 수 배지(VS Code 탐색기 관행 · 사용자 2026-10-18 — R31 · E4) · 같은 문제는 편집 칸 위 문제 목록에도 한 줄씩(R51). (메모 86 · 그림 §12)
- **R43** **기본 제공 에셋** — 라이브러리 밖 고정된 가짜 경로 이름공간(예 `engram:/…` — 꼴은 TRD)에 산다. 기본 제공 = 기본 프리셋 「기본」(R32) 하나뿐(사용자 2026-10-18 — 옛 「claude 기본」 · 「codex 기본」 백엔드 프리셋은 걷었다: 내용이 `backend` 하나였고 백엔드는 이제 에이전트 값이다 — R44). 라이브러리를 선택하지 않아도 있다. 펼쳐 보기만(R27) · 폴더 돋보기와 R28 은 꺼짐 · 다른 프리셋 안에 추가할 수 없음(에이전트에만 붙는다) · `engram` 은 가짜 경로로 부른다. 사람은 에이전트 슬롯 `+` 검색 맨 위의 고정 「기본 제공」 목록(「기본」 하나)에서 붙인다 — 뗀 기본 프리셋을 다시 붙이는 길이 이것과 빈 「기본」 칸이다(D8). (기본값 E7 · E17)

**라이브러리 폴더**
- **R7** 라이브러리 = 폴더 하나 · 프리셋도 그 안. 거부 = 프리셋 폴더 따로 + 부품 라이브러리 여럿(루트를 넘는 참조 · 순환 문제). (메모 127)
- **R8** 자동 기본 폴더는 없다. 처음엔 평소 모양 슬롯의 빈 트리 안에 「아직 라이브러리 폴더를 선택하지 않았습니다.」 + [폴더 열기] + [새로 만들기]. [새로 만들기]는 폴더 선택 창에 **경로만** 미리 채우고(배포판 폴더 안 `library\` — `data\` 옆), 선택하면 빈 폴더를 만든다 — 내용은 넣지 않는다. 폴더가 없어지면 같은 자리에 「<경로>를 찾을 수 없습니다」 + 같은 단추 · 설정 값은 둔다. (메모 105 · 153–155)
- **R9** 바꾸기 = 위 칸 머리의 경로 옆 「…」 → 바로 폴더 선택 창(같은 PC 전용 · 메뉴 없음 — 2026-10-16 · 문구 사용자 확인 2026-10-18). 설정 창의 같은 칸은 설정 창이 생길 때(첫 판엔 설정 창 없음 — TRD T5) · LLM 은 `engram library.setRoot`. **바꾼 뒤 규칙은 하나** — 참조는 새 루트에 대해 경로 그대로 풀린다: 같은 경로가 있으면 그냥 쓰이고(내용이 달라도 — 그 루트를 선택한 것은 사용자다) · 없으면 「찾을 수 없음 · 다시 연결」 · 루트를 넘는 다시 연결(R19)은 없다. (메모 123 · 기본값 E19)

- **R11** 배치(그림 §2) — 왼쪽 = 머리 붙은 칸 둘(언리얼 Content Browser 꼴 · 사용자 2026-10-16) — 위 「▾ <라이브러리 폴더 이름>」(폴더 트리 · 머리 줄 누름 = 접기 · 펼치기 · 경로 옆 「…」 = 바로 Windows 폴더 선택 창으로 라이브러리 폴더 바꾸기 — 메뉴 없음 · 사용자 2026-10-16) · 아래 「▾ 즐겨찾기 ＋」(＋ = 새 컬렉션 — 목록 끝 단추는 없다). 칸마다 따로 스크롤 · ▾ 로 접으면 머리 줄만 남고 다른 칸이 공간을 쓴다 · 펼친 칸 사이 경계를 끌어 높이 조절(번호마다 기억 — R10). 머리 안 검색 단추는 없다(목록 위 검색이 하위까지 찾는다) · 가운데 = 탐색기식 목록 · 오른쪽 = 상세(프리셋이면 편집 칸 — R20). 맨 위 줄 = 슬롯 전체 폭에 `← →` + 누를 수 있는 경로(`라이브러리 › 스킬 › 리뷰`). 목록 칸 위 줄 = `필터 ▾` · 검색 · 오른쪽 끝 `★ = <대상>` 칩. 칸 사이 경계는 전부 표시 없는 선이고 끌어서 폭을 바꾼다(올리면 커서만 바뀜). 추가 · 가져오기 · 저장 단추는 없다. 거부 = `← →` 만 따로 한 줄 · 목록 칸 위에만(Spacedrive). - **R22** 종류별 칸 = 프리셋 · 지침 · 스킬 · 설정(그림 §3 「편집 칸 = 종류별 칸」). 지침 · 설정은 ⋮⋮ 로 끌어서 순서(= 이어 붙는 순서) · 스킬은 이름순 · × = 빼기 · 저장 단추 없이 바로 저장. **칸 아래 줄은 충돌(빨강)뿐이다 — 경고 줄은 없다**(사용자 2026-10-18). 충돌 하나 = 한 줄 = 무슨 충돌 — 걸린 항목 **전부**와 각자 온 길(`›` = 그 프리셋 안에 든)(예 「같은 이름 스킬 review 가 둘 — review · 공용 규칙 › 팀/review」). 충돌은 하나뿐 = 같은 이름 스킬 둘 이상(경로 다름 — R4)(사용자 2026-10-18 — 옛 「백엔드 정하는 설정 둘 이상」 · 「`model` 칸 둘 이상」 걷음 · 모델 충돌 검사 없음 — R5). 실행이 막힐 때도 같은 줄을 이유로 보인다(E4). 거부 = 한 줄로 섞인 목록 · 「추가한 것 | 최종 구성」 탭(세션 발상 · 피어 없음). (메모 128 · 130 · 145)
- **R23** 칸 제목 단추, 이 순서 = `+`(그 종류만 검색해 추가 — ▾ 없는 단추 하나) · `⇐`(다른 라이브러리 슬롯에서 선택한 것 중 그 종류만) · 폴더 돋보기(그 종류를 둘러보러 **다른** 라이브러리 슬롯을 연다 — 편집 칸은 그대로 · 대상 슬롯 = E11). 편집 칸 머리 = 「← 선택 항목 추가」(주 경로) · 「+ 추가」(전체 검색) — 머리 「+ 추가」 와 칸 제목 `+` 는 둘 다 둔다(선례 = 언리얼 My Blueprint 「Add New」 + 칸별 `+` · 조사 = `docs/research/global-vs-section-add-button-2026-10-19.md`). 머리 아래 = 문제 목록(R51). 추가한 것은 자기 종류 칸의 끼울 자리(R46) 뒤 · 없으면 끝에 들어간다. (메모 85 · 128 · 139–141 · 그림 §7)
- **R24** `⇐` · 「← 선택 항목 추가」 의 원천 = 다른 라이브러리 슬롯 중 마지막으로 만진 곳의 선택 · 없으면 비활성 · 원천 강조 없음. 선택한 것 일부를 추가할 수 없으면 추가할 수 있는 것만 추가하고 나머지는 건너뛰며 한 줄 결과를 보인다(예 「2개 추가됨 · 1개는 추가할 수 없음(순환)」). 에이전트 슬롯은 프리셋만 받고 다른 종류는 같은 문구로 건너뛴다. (메모 85 · 142 · 기본값 E12)
- **R25** 검색 팝오버 — 열면 검색칸에 커서 · 하위까지 찾음 · 체크 = 바로 추가됨(여러 개) · 이미 추가된 것 = 비활성 + 「이미 추가됨」 · 순환 · 충돌 = 비활성 + 이유 · 「이미 추가됨」 칸 · 컬렉션 칩 없음 · 결과 줄 = 이름 + 한 줄(스킬 = 설명 · 지침 = 발췌 · 설정 · 프리셋 = description — 없으면 흐린 「설명 없음」 · R52). (메모 83–84 · 그림 §7)
- **R26** 라이브러리 우클릭 「프리셋에 추가」 는 없다 — 추가는 편집 칸에서만. (메모 143–144)
- **R45** **편집 영향** — 편집 칸 머리에 「에이전트 N개에서 참조 중」(직접 + 건너서 — R15). **경고 줄은 없다**(사용자 2026-10-18 — 옛 「에이전트 N개가 다음 실행에서 새 대화로 시작합니다」 경고 줄을 걷음). 이유(사용자) = 어떤 편집이 새 대화를 부르는지 같은 규칙은 나중에 바뀔 수 있어 편집 칸이 그 규칙을 따라 계산하지 않는다 · 옛 대화는 잃지 않는다(옛 목록). 편집은 에이전트의 백엔드를 바꾸지 못한다(백엔드 = 에이전트 값 · 고정 — R44 · 사용자 2026-10-18 — 옛 「풀린 백엔드가 바뀌면 다음 실행은 새 대화」 걷음). 돌고 있는 에이전트에는 여전히 아무것도 띄우지 않는다(R36). (기본값 E10)
- **R46** **선택** — 마지막으로 누른 줄이 그 칸의 끼울 자리다. 프리셋 줄 누름 = 선택 + 펼침 토글(R27) · 부품 줄 누름 = 선택 + 상세 카드 토글(R27 · R29 · 사용자 2026-10-19). 선택은 다른 줄을 누르거나 Esc · 빈 곳 누름까지 남는다. (기본값 E13)
- **R47** **동시 · 낡은 편집** — 편집은 전부 조작(추가 · 빼기 · 순서 등)으로 데몬에 보내고 데몬이 **최신 파일**에 적용한다. 데몬은 그 화면이 본 파일 판을 확인한다 — 추가 · 빼기는 낡은 화면에서 와도 적용(항목 기준 멱등) · 순서 바꾸기는 낡은 화면이면 거절하고 그 화면을 새로 불러 「다른 곳에서 바뀌어 새로 불러왔습니다」. 바깥 편집(LLM 이 YAML 을 고침)도 같은 길로 잡힌다. **Engram 이 프리셋 YAML 을 고칠 때 손으로 쓴 주석을 지킨다**(관행 — 2026-10-18 · 사용자 「그런 라이브러리를 찾고 없으면 관행대로 처리해」 · Home Assistant · openHAB 불만 · ruamel.yaml · TRD T2 추천 「사라짐을 받아들임」 을 뒤집음 · 조사 `docs/research/yaml-comment-preserving-edit-2026-10-18.md`) — 첫 구현 단계 = 실제 프리셋 파일로 스파이크(후보 `yaml-edit` 0.3.2 · `yamlpatch` 비교) · 둘 다 안 되면 「주석 잃음을 받아들이고 메모는 `description`」 으로 물러서고 사용자에게 보고. 자세한 것은 TRD. (기본값 E14)
- **R51** **편집 칸 위 문제 목록**(사용자 2026-10-19 「위에 쭉 나열해 유저가 한눈에 볼 수 있도록」 · 조사 = `docs/research/editor-problem-summary-practice-2026-10-18.md` — GOV.UK 오류 요약 · NN/g) — 편집 칸 머리 아래에 문제마다 한 줄(찾을 수 없음 · 오류 · 충돌) · 붙은 · 안에 든 프리셋 속 문제도 길 「<프리셋> › …」 과 함께 · 문구 = 그 줄 표시와 같게 · 누르면 그 줄로 간다(접힌 칸 · 안에 든 프리셋을 펼쳐) · 줄 표시(⛔ · 오류 수 배지 · 칸 아래 충돌 줄)는 그대로 둔다 · 문제가 없으면 안 보인다 · 접는 기준 수 없음. 같은 부품(R21)이라 에이전트 프리셋 슬롯에도 있고, 거기선 에이전트 단위 막힘(라이브러리 폴더 없음 · codex 파일 사전 검사 실패)도 한 줄씩 든다 — 실행 막힘 이유(E4)를 그 자리에서 다 본다. (R6 · R22 · R31 · E4)

**안에 든 프리셋**
- **R27** 프리셋 줄 한 번 누름 = 그 자리에서 ▸/▾ 펼침. 안쪽은 바깥과 같은 레이아웃을 한 단 들여 같은 부품을 재귀로 쓰고(안쪽의 안쪽도 ▸), 흐리게 · 보기만(+ · × · 순서 없음). 고치려면 그 프리셋을 연다 · 바깥에서 그 줄을 빼는 것은 된다. 거부 = 안쪽 것을 바깥 칸에 섞기(상속 도구 관례 — 우리는 여럿을 포함한다) · 그 자리 고치기(공유 파일이라 참조하는 쪽이 전부 말없이 바뀐다). (메모 130 · 132 · 169) **부품 내용 보기(사용자 2026-10-17 · 2026-10-18 · 2026-10-19)** — 편집 칸의 부품 줄(지침 · 스킬 · 설정 — 안에 든 프리셋을 펼친 안쪽 포함 · 10-18 사용자 「ㅇㅇ 달아」 = 모든 부품 줄)을 **누르면 그 항목의 상세 카드(R15 와 같은 카드 · 떠 있는 카드 — 호버 툴팁 아님)가 토글된다**(사용자 2026-10-19 「그냥 카드 토글하고, 왼쪽 구석은 위치 배치하는거고」 — 옛 줄 끝 👁 단추를 걷음: 너무 작고 내용 보기가 잦다 · 거부 = 더 큰 👁 · 👁 + Space) · 누름은 여전히 그 줄을 끼울 자리로 고른다(R46) · 왼쪽 끝 ⋮⋮ = 끌어서 순서 — 자리 = R29(라이브러리 슬롯 = 오른쪽 칸 왼쪽 가장자리 · 목록 위 · 에이전트 슬롯 = 슬롯 바깥 — D11) · 같은 줄 다시 누름 = 닫힘 · 떠 있을 때 다른 줄 누름 = 바로 그 줄로 바뀜 · ×(그 카드) · 카드 바깥 누름 · Esc(쌓인 카드를 나중에 연 것부터 — 관행 2026-10-18) = 닫힘 · 프리셋 줄은 그대로(누름 = 선택 + 펼침 · 카드 없음 — 펼쳐서 본다) · 더블클릭(R28)은 그대로. 거부 = 줄 아래 끼워 펼치기(VS Code Peek 꼴 — 사용자가 싫다) · 편집 칸 아래 미리 보기 칸 · 따로 뜨는 창(그림 후보 비교 2026-10-17 · 조사 = docs/research/editor-referenced-content-peek-survey-2026-10-17.md).
- **R28** 줄 호버의 폴더 돋보기를 누르거나 줄을 더블클릭하면 그 항목 자리로 간다. 라이브러리 슬롯에선 같은 슬롯이 그 자리로 가고 거기서 그 프리셋을 고칠 수 있으며 `←` 로 돌아온다. 에이전트 슬롯에선 라이브러리 슬롯(E11 의 대상)이 그 자리로 가고 에이전트 슬롯은 그대로 남는다 — 돌아오기 = 에이전트 슬롯을 다시 누름. 기본 제공(R43)은 꺼짐. (메모 140 · 169 · 그림 §3 「편집 칸의 줄 누르기」 · 기본값 E11)

**상세 패널**
- **R29** 편집 칸 줄의 상세(라이브러리 상세와 같은 내용 · 같은 블록 순서 — R15)는 부품 줄을 누르면 떠 있는 카드로 토글된다(R27 · 사용자 2026-10-19 · 그 누름은 끼울 자리도 고른다 — R46). 카드 = 모든 부품 줄(지침 · 스킬 · 설정 — 사용자 확인 2026-10-18 「ㅇㅇ 달아」) · 프리셋 줄엔 없음(누름 = 선택 + 펼침). 같은 줄 다시 누름 = 닫힘 · 다른 줄 누름 = 그 항목. **자리 — 어느 경우에도 잘리지 않는다**(D11 · 관행 — 2026-10-18 · ★리뷰 때 확인 — 그림으로★): 라이브러리 1~4 = 오른쪽 칸은 창 안의 칸이라 넘치지 않고, 편집 칸 줄의 카드(줄 누름 — R27)는 오른쪽 칸 **왼쪽** 가장자리에 그 줄 높이로 붙어 가운데 목록 위에 뜬다(창이 좁으면 폴더 트리까지 덮을 수 있다) · 에이전트 슬롯(편집 칸만) = 슬롯 오른쪽 바깥에 붙어 **옆 슬롯 위로 겹친다**(옆 슬롯 크기 · 내용 그대로) → 오른쪽에 자리가 없으면 슬롯 왼쪽 바깥으로 뒤집기(왼쪽 옆 슬롯 위) → 양쪽 다 없으면(예 팝아웃 창을 채운 슬롯) 창 안으로 당긴다(슬롯을 덮음). 관행 = Floating UI `flip()` 다음 `shift()`(확인함) · Radix · MUI · NSPopover 같은 순서 · 기준점을 덮는 것은 마지막 수단. 메모 137 「창에 걸려 잘린 채 · 뒤집기 · 안쪽 대체 없음」 을 뒤집는다. 거부 = 슬롯 안에 칸 끼워 넣기. (메모 137–138 · 그림 §3)

**에이전트 프리셋 슬롯**
- **R30** 에이전트 프리셋 편집 = 슬롯 종류 하나 = **공용 편집 부품(R21)만 올린 슬롯** — 편집 부품 + 데이터 훅만 싣고 트리 · 목록 · 필터 · 트리 부품(react-arborist) · 가상 표는 올리지 않는다(메인 세션 결정 2026-10-19 — 사용자 위임 「알아서 해 이 부분은」 · 옛 「편집 칸만 켠 라이브러리 슬롯(트리 · 목록 숨김) · 통째 재사용이 느리면 로직만」 을 고정 규칙으로 바꿈). 편집 부품은 홀로 서는 부품이고 라이브러리 오른쪽 칸과 에이전트 슬롯이 각자 품는다 · 데몬 훑기는 하나를 함께 쓴다(슬롯은 묻기만). 번호 없음 · 에이전트 트리 우클릭 「프리셋…」 으로 열고 이미 열려 있어도 하나 더 · 팝아웃하면 OS 창. 거부 = 트리 옆 펼침 칸 · 라이브러리 오른쪽 칸에 에이전트 띄우기(그림 §9 「지난 안」). - **R48** **사람용 확인이 낀 조작의 CLI · 버스 경로** — 참조가 있는 항목 삭제(R18 — `.trash` 로) · 기본 프리셋 떼기(R32)는 `--yes` 가 없으면 참조 · 이유를 돌려주며 거절. `.trash` 비우기는 CLI · 버스 경로가 아예 없다(사람만 — R18 · 사용자 2026-10-19). 실행 대화상자는 **누가 만들었나가 아니라 누가 실행을 요청했나**로 가른다 — CLI · 버스가 요청한 실행엔 대화상자가 없다: 모델 피커는 막지 않으니 선택된 값 그대로(R35). **작업 폴더**(사용자 2026-10-18 「llm은 그냥 한방에 실행할수 있게 기존처럼 인자 두는게 맞고」) — `agent.new` 의 `cwd` 는 필수 그대로 · 바꾸기 = `agent.setWorkspace {agent, cwd}` — 잠겨 있으면(R31) CONFLICT(코드 + 인자 — R49) · 경로는 있는 폴더여야 한다. 실행이 막히면 화면과 같은 이유를 실행 명령의 답으로 돌려준다(E4). 옛 「워크스페이스 없음 → Engram 폴더 자동」 = 다음 주제(R34) · 옛 codex 파일 답 자동값 「만들지 않음 · 프라이밍만」 = 걷음(R37). (기본값 E15)
- **R52** **`description` 쓰기 안내**(사용자 2026-10-19 「일단은 그렇게하자」) — 설정 · 프리셋 파일 형식을 프라이밍(「기본」 의 Engram 사용 안내 — R32)과 `engram help` 에 싣는다 — 예에 `description:` 을 넣고 한 문장 「설정 · 프리셋 파일을 만들거나 고칠 때 한 줄 설명을 적는다」 를 붙인다. `engram help` 맨 위는 부풀리지 않는다 — 묶은 주제(예 `engram help library`) 아래에 두고 맨 위엔 그 주제 한 줄만. 「새로 만들기 ▸ 설정 · 프리셋」 틀에 빈 `description: ` 줄(R17). 설명이 없으면 흐린 「설명 없음」(상세 · 검색 결과 줄 — R15 · R25) · 막지 않는다. 거부 = 설명 필수(없으면 오류) — 에이전트가 파일을 직접 쓸 수 있다. 나중 생각 = 프라이밍 자체를 라이브러리 에셋으로(§2 비목표).

- **R49** **로컬라이제이션 대비(사용자 2026-10-16)** — 새 화면 글자(메뉴 · 확인 창 · 칸 제목 · 상태 이름)는 기존 다국어 장치(`src/i18n` 의 `t()` + `ko.ts`)의 키로만 쓴다(컴포넌트에 직접 박지 않는다). 데몬이 돌려주는 사유 · 상태(충돌 · 찾을 수 없음 · 「N개 더 찾아 연결함」 · 실행 막힘 · 설정 검사 오류)는 문장이 아니라 **코드 + 인자**로 주고 화면이 번역한다. 기본 제공 프리셋의 표시 이름(「기본」)도 키 — 저장 값은 `engram:/…` 경로. 번역하지 않는 것 = 사용자가 만든 파일 · 폴더 이름 · 파일 안 형식 낱말(`kind` 등) · 명령 이름. 앱 전체 번역은 tracking T-64.
- **R50** **단축키 = 각 OS 파일 관리자의 기본값**(사용자 2026-10-16 「범용적인 걸로」). 라이브러리 슬롯에 포커스가 있을 때만 듣고, 이름 칸 · 검색칸에 치는 중이면 키는 그 칸으로 간다. Windows = 탐색기: F2 이름 바꾸기 · Delete(Shift+Delete 도 — 영구 삭제가 없으니 `.trash` 로 · R18) · Enter 열기(폴더 = 들어감 · 파일 = 더블클릭과 같음) · Backspace · Alt+← 뒤로 · Alt+→ 앞으로 · Alt+↑ 상위 폴더 · Ctrl+Shift+N 새 폴더 · Ctrl+F · Ctrl+E · F3 검색칸 · F5 새로 고침(R19) · Esc 이름 취소 · 검색 지우기 · Ctrl+A · Shift/Ctrl+클릭 · Shift+화살표 · Home/End 선택 · 트리 ← → 접기/펼치기 · Shift+F10 우클릭 메뉴 · 글자 입력 = 그 글자로 시작하는 항목으로. macOS = Finder 기본값(Enter 이름 바꾸기 · Cmd+↓ 열기 · Cmd+Delete 삭제(`.trash` 로) · Cmd+[ / ] 뒤로/앞으로 · Cmd+↑ 상위 · Cmd+Shift+N · Cmd+F) — 맥 이식 때 확인. 없는 기능의 키(복사 · 붙여넣기 · 되돌리기 · 속성 · 탭)는 넣지 않는다. **LLM 경로를 따로 만들지 않는다** — 화면 조작이고, 키가 하는 일(이동 · 이름 · 삭제 · 새로 만들기 · 새로 고침)은 이미 `library.*` 명령으로 닿는다(사용자 2026-10-16). OS 별 키맵을 통째로 주는 공용 라이브러리는 없다(VS Code · Spacedrive 도 손으로 쓴 표 — 조사 2026-10-16).

**도킹**
- **R42** 두 슬롯(라이브러리 · 에이전트 프리셋)은 평범한 슬롯 종류로 만든다 — 슬롯 종류를 가리지 않는 도킹 작업(wt2 `v0.4.1/feat/slot-docking` · `docs/process/S21-slot-docking/` — 이 브랜치엔 없음)이 그대로 붙게. 도킹 자체는 범위 밖. (메모 152 · 161)

**불변 제약 (원칙 — 지킬 벽)**
- 데이터(훑기 · 프리셋 · 설정 내용 · 참조 · 다시 연결 · 기본 제공 에셋)는 **데몬 소유**. 클라이언트는 디스크를 읽지 않고 보이기만 하며, 쥐는 것은 보기 상태(폴더 · 선택 · 정렬 · 기록 · 칸 폭)와 개인 데이터뿐 — 개인 데이터 항목 키에 데몬 신원이 든다. (메모 58–59 · 71 · 87)
- 클라이언트 · 데몬은 지금 같은 PC. 화면은 OS 대화상자 · 기본 프로그램 열기 · 탐색기 보이기를 직접 부르지 않고 요청 하나를 지난다(지금 = OS 기본 · 원격엔 끈다). (메모 60 · 63)
- 서드파티 라이브러리는 늘 우리 부품 뒤에 감싼다. (메모 93 · 113)
- 백엔드 지식은 「백엔드 확장」 한 곳 · OS 별 동작(기본 프로그램 · 정션)은 「플랫폼 중립」 OS 층 — 삭제는 OS 휴지통을 안 쓰고 라이브러리 안 `.trash` 로 옮긴다(R18 · 2026-10-19). (원칙)
