## 0. 한 문단 요약 — 흐름

라이브러리 폴더는 **데몬 PC 의 것**이고 데몬의 새 모듈 `library` 만 읽고 쓴다. 화면은 디스크를 보지 않고 슬롯 열기 · 포커스 · 폴더 이동 때 **버스 명령**(`library.list` 등)을 보내 답을 그린다(요청형 — 데몬은 메모리 목록으로 답하고 디스크는 처음 · `library.refresh` · 루트 바꾸기 때만 훑는다 · 감시 · 방송 없음). `engram` CLI 와 LLM 도 같은 명령을 부른다. 편집 · 파일 조작도 명령이고 데몬이 최신 파일에 적용한다(손으로 단 주석은 지킨다 — T2). 실행 때 `AgentManager` 는 세션을 파생하기 **전에** 새 포트 `LaunchKitSource`(실물 = 데몬)로 점검을 끝내고, 데몬이 펼친 프리셋을 휘발 폴더의 **백엔드 중립 실행 재료**로 받아 `backend` 만이 claude · codex 플래그로 옮긴다. 백엔드 · 모드는 에이전트 값(만들 때 고정)이고, 설정은 그 백엔드의 원문 칸만 실린다(모델도 그 안 — 사용자 2026-10-18) · 숨겨 주입하는 설정은 없다 — Engram 통로 키(`allowedMcpServers`)도 기본 제공 「기본」 의 원문에 보이고, claude 원문은 붙인 순서로 `--settings` 하나에 합친다(T10). 작업 폴더는 만들 때 선택하고(필수 — 지금 그대로) 에이전트 슬롯 「작업 폴더」 칸 · `agent.setWorkspace` 로 바꾸되, 대화한 뒤(영속된 세션 id) · 떠 있는 동안은 잠긴다(경로 없는 생성 등 = 다음 주제 §8). 실행이 막히면 누가 냈든(화면 · CLI · LLM) 같은 다섯 사유로 막는다 — 화면은 에이전트 옆 비모달 팝업(항목 링크 → 라이브러리에서 그 항목 선택), LLM · CLI 는 코드 + 인자로 받는다. 설정은 데몬이 내용을 읽을 때마다 프로세스 안에서 검사한다(문법 · 스키마 — CLI 를 돌리지 않는다). 바깥에서 없어진 파일은 「찾을 수 없음」 으로 두고(실행은 막힘 · 훑기는 후보를 제안하지 않는다) 사용자 · LLM 이 [다시 연결] 로 하나를 고르면 같은 옛 경로 · 같은 옛 폴더의 나머지를 함께 고친다. 삭제는 라이브러리 루트 안 숨은 `.trash` 로 옮기고(OS 휴지통은 안 쓴다) 비우기는 사람만 한다 — 버스 · `engram` 명령이 없다(「LLM-우선 제어」 의 의도된 예외). 앱 안 이동 · 다시 연결은 데몬 「이동 기록」에 쌓여 각 클라이언트가 다음 요청 때 자기 컬렉션을 고친다. 번호 1~4 보기 상태와 컬렉션 · 대상 컬렉션은 **셸**이 권위로 갖고(키에 데몬 신원), OS 동작은 `platform`(정션 · 경로 비교 · 파일 신원)과 셸의 로컬 요청을 지난다. 구현은 두 판으로 낸다(1판 = 읽기 · 편집 · 붙이기 · 실행 · 2판 = 파일 조작 · 다시 연결 · 끌어 옮기기 · 컬렉션 · T8 — §5).

**거부한 대안**
- **셸이 라이브러리를 훑는다** — 클라이언트 디스크 읽기 금지(PRD 불변 제약)이고, 원격 데몬(나중)에서 성립하지 않는다.
- **번호별 보기 상태를 데몬에** — 보는 쪽 상태다. 클라이언트가 여럿이면 주인이 없다(메모 58 「레이아웃을 데몬에 두지 않는다」와 같은 이유).
- **보기 상태 · 컬렉션을 웹뷰 `localStorage` 에** — 창(웹뷰)마다 갈려 팝아웃 창의 라이브러리 슬롯과 메인 창 편집 칸이 ⇐ 원천을 나누지 못하고, LLM 이 셸 명령으로 닿지 못한다.
- **라이브러리를 별 crate 로** — 소비자가 하나다. 다른 crate 가 필요해지면 뺀다(메모 96).

설정 · 프리셋을 **파일 안 표식**(`kind`)으로 가른다(D7). 확장자나 폴더 이름에 기대면 이동이 종류를 바꾼다.

**프리셋 파일**(읽기 = serde-saphyr · Engram 이 고쳐 쓰기 = 손 주석 · 모양을 지키는 편집기 — 둘을 아는 유일한 곳 = `library::format` · T2)

```yaml
# 손으로 단 주석은 Engram 이 고쳐도 남는다(T2 — 0b 단계 스파이크가 편집기를 고른다)
kind: preset
version: 1
description: PR 리뷰 전용
presets:
  - 공용/기본 규칙.yaml
instructions:
  - 지침/리뷰 규칙.md
skills:
  - 스킬/리뷰/review
settings:
  - 설정/claude opus.yaml
```

칸 = 종류별 목록 넷(R22). `instructions` · `settings` · `presets` 의 순서가 이어 붙는 순서다(D2). 항목은 경로 문자열이다(옛 `{path, relinked_from}` 꼴은 걷었다 — 저절로 다시 연결하는 길이 없어 표시할 것이 없다 · D10 · 2026-10-18).

**설정 파일**

```yaml
kind: settings
version: 1
description: 모델 고정 — claude opus · codex gpt-5.5
claude:                  # claude 원문 — 실행 때 --settings 로 넘길 settings 객체(Engram 은 해석하지 않는다)
  model: claude-opus-5-5 # 모델도 원문 안 — 있으면 CLI 가 그 모델로 시작(R35 · 선택 칸은 잠그지 않는다)
  env:
    SOME_VAR: "1"
codex:                   # codex 원문 — 실행 때 -c 로 하나씩 넘길 목록
  - model=gpt-5.5
  - model_reasoning_effort=high
```

정식 칸은 없다 — `kind` · `version` · `description` 과 백엔드별 원문 칸뿐이다(사용자 2026-10-18 — 옛 정식 `backend` · `model` 칸을 걷음). 모델 · 강도도 원문 칸 안이다(D6 확정 · R5). 실행에는 **에이전트의 백엔드와 같은 이름의 칸만** 실리고 다른 칸은 말없이 빠진다. Engram 은 원문을 해석하지 않는다(검사만 한다 — §1-4 `validate.rs` · 원문에서 모델을 읽지도 않는다) — 두 설정이 같은 백엔드 칸에 모델을 넣어도 검사하지 않고 CLI 가 하는 대로다(T3). 원문 칸 이름은 백엔드 낱말(`agent.new` 의 백엔드 어휘와 같은 철자 — 대소문자 무시)이다.

**`description`(설정 · 프리셋 — B12 · 사용자 2026-10-19 「일단은 그렇게하자」)** — 선택 칸이다. 없으면 목록 · 상세가 흐린 「설명 없음」 을 보이고 막지 않는다. 「새로 만들기 ▸ 설정 · 프리셋」 틀(`library.newFile`)에는 빈 `description: ` 줄이 든다. 쓰는 법은 프라이밍(「기본」 의 Engram 안내)과 `engram help library`(§1-7 CLI)가 싣는다 — 파일 형식 + `description:` 이 든 예 + 「만들거나 고칠 때 한 줄 설명을 적는다」 한 문장. 거부 = 필수 칸(없으면 오류 — 에이전트가 파일을 직접 쓸 수 있다).

**참조 꼴 `LibPath`** — 라이브러리 맨 위부터의 `/` 경로 한 꼴(R3). 규칙: UTF-8 · 구분자는 `/` 만 · 앞뒤 `/` 없음 · 빈 칸 · `.` · `..` 없음 · `\` · `:` · 제어 문자 없음. 표현은 `relative-path` crate 의 `RelativePathBuf` 를 감싼 우리 타입(`library::path::LibPath`)이고, 검증 · 디스크 경로로 바꾸기(`to_path(root)`) · 이동 때 접두 바꾸기(`strip_prefix` + `join`)를 그 타입 하나가 맡는다. 같은 파일인지 비교는 OS 규칙(Windows = 대소문자 무시)을 `platform` 의 경로 비교 도우미로 한다 — 표시는 디스크의 철자 그대로.

**기본 제공 네임스페이스 `engram:/`(Δ1)** — 라이브러리 밖의 고정 가짜 경로. `LibPath` 는 `:` 를 받지 않으므로 둘이 섞이지 않는다.

| 참조 | 표시 이름 | 내용 |
|---|---|---|
| `engram:/default` | 기본 | 지침 `engram:/priming`(배포판 `prompts\agent-priming.md` — 지금 프라이밍 그대로) + 설정 `engram:/settings/default`(claude 원문 `{"env":{"DISABLE_AUTOUPDATER":"1"},"allowedMcpServers":[{"serverName":"engram"}]}` — 자동 업데이트 끄기 + Engram 메시지 · 제어 통로(서버 이름 = agent `MCP_SERVER_NAME`) · T10 · 사용자 2026-10-18 「프리셋으로 해줘. 사실 감추는 설정이 있으면 안되지.」 — 옛 id `engram:/settings/no-autoupdate` 는 내용이 늘어 바꿨다) |

기본 제공 프리셋은 「기본」 하나다 — 옛 `engram:/backend/claude` · `engram:/backend/codex`(「claude 기본」 · 「codex 기본」 — 내용 = `backend` 칸 하나)는 걷었다(사용자 2026-10-18 — 백엔드 = 에이전트 값). 기본 제공 프리셋은 읽기 전용이고 라이브러리 프리셋에 추가할 수 없다 — 라이브러리 프리셋 파일이 `engram:/…` 를 가리키면 그 줄이 「오류 · 기본 제공 프리셋은 추가할 수 없다」(Δ1). 에이전트에는 붙는다.

### 1-3. 해석 — 「실제로 받는 것」 (`library::resolve`, 순수 함수)

입력 = 에이전트(백엔드 + 기본 여부 + 붙은 프리셋 목록) 또는 프리셋 하나 + 항목을 찾는 조회 함수(가짜 저장소로 시험). 출력 = `Resolution`.

1. **펼치기** — 에이전트면 [기본(붙어 있으면)] 다음 [붙은 프리셋 순서대로]. 프리셋 하나를 펼칠 때 = 그 안의 `presets` 를 순서대로 먼저 펼치고(D1 — 안에 든 프리셋의 지침이 자기 지침 **앞**), 다음 자기 `instructions` · `settings` · `skills`.
2. **중복** — 같은 프리셋이 두 길로 오면 처음 자리에서 한 번(R4). 지침 · 설정 · 스킬도 같은 경로는 처음 자리 한 번(경로가 정체 — 내부 선택 §3).
3. **순환** — 펼치는 중인 스택에 다시 나오면 그 줄이 「순환」 오류.
4. **백엔드 = 에이전트 값**(사용자 2026-10-18 — 옛 「기본 제공 백엔드의 물러남(Δ1 · 3차 델타)」 을 걷은 자리) — 해석의 백엔드는 프로필의 `command` 변형(만들 때 고정 — §1-5)에서 읽고 설정에서 오지 않는다. 설정은 그 백엔드와 같은 이름의 원문 칸만 해석에 들고(추가한 순서대로 이어 붙음) 다른 칸은 말없이 빠진다. 프리셋 하나를 펼칠 때(편집 칸 — 에이전트 없음)는 백엔드가 없으니 원문 칸을 고르지 않는다.
5. **충돌**(빨강 — 그대로는 실행 못 함) — 같은 이름 스킬 둘 이상(다른 경로) **하나뿐**이다(Engram 이 스킬을 이름별 폴더로 까니 CLI 와 무관하게 우리 쪽에서 부딪힌다 — 사용자 2026-10-18 · 옛 「백엔드 정하는 설정 둘 이상」 · 「`model` 칸 둘 이상(T3)」 걷음 — 모델 충돌 검사 없음). **충돌 하나 = 줄 하나** = 무슨 충돌 + 걸린 항목 **전부**, 항목마다 온 길(펼친 시작점 — 에이전트면 붙은 프리셋 — 부터 그 항목까지의 프리셋 사슬 · 화면은 `›` 로 잇는다 = 그 프리셋 안에 든). 코드 + 인자로 낸다(R49 · §3). 편집 칸의 빨간 줄과 실행 막힘 사유 `Conflict`(8 · E4)가 **같은 줄**이다(사용자 2026-10-18).
6. **경고 — 없다**(사용자 2026-10-18 — PRD R6 · R22 · R45). 노랑 범주를 걷었다. 옛 경고(다른 백엔드 원문 칸이 있으나 안 쓰임 · codex 크기 한도를 올렸음(R38) · 문맥 차지 비율 · 자동으로 다시 연결됨 · 백엔드가 바뀌는 에이전트의 「다음 실행은 새 대화」 — Δ4)는 편집 칸에도 실행 때에도 알리지 않는다. 동작은 그대로다 — 크기 한도는 실행마다 `-c` 로 올리고(§1-5) · 다시 연결은 사용자 · LLM 이 고를 때만 돈다(훑기 때 후보 제안 없음 — 사용자 2026-10-19 · 옛 「다음 실행은 새 대화」 의 계기였던 백엔드 바뀜은 이제 없다 — 4). 이유(사용자) = 어떤 편집이 새 대화를 부르는지 같은 규칙은 바뀔 수 있어 화면이 그 규칙을 따라 계산하지 않는다 · 옛 대화는 잃지 않는다. 번호는 다른 자리가 7 · 8 을 가리키므로 비워 둔다.
7. **상태** — 찾을 수 없음(파일 없음 — 줄 = 「찾을 수 없음 · [다시 연결] ×」) · 오류(못 읽음 · 설정 스키마 오류) · 순환 — 가리키는 줄에만 붙는다(R6). 옛 「다시 연결됨(자동 적용 · 확인 전)」 상태도, 옛 「찾을 수 없음 — 후보 <경로> [연결]」(다시 연결 확인 대기 — 2026-10-18 D10 의 꼴)도 없다 — 줄은 「찾을 수 없음」 이거나 멀쩡하다(B11 · 사용자 2026-10-19 「ㅇㅇ 그게 더 자연스러운것같네」).
8. **막힘 사유(실행 직전) — 다섯, 한 범주**(사용자 2026-10-18 「막는게 좋을듯」 — 관행: 명시로 붙인 부품은 필수라 없으면 막는다 · `docs/research/launch-missing-component-practice-2026-10-18.md`). **누가 실행하든**(더블클릭 · CLI · LLM) 같은 사유로 막는다. ① 찾을 수 없음(붙은 파일이 없음 — 다시 연결은 사용자 · LLM 이 고를 때만 · §1-4 흐름 ②) ② 오류(YAML 문법 · 순환 · 설정 스키마의 타입 · 범위 오류 — §1-4 `validate.rs`) ③ 충돌(같은 이름 스킬 — 사유에 5 의 충돌 줄을 그대로 싣는다 · E4) ④ 라이브러리 폴더 미설정/없음인데 라이브러리 프리셋이 붙음 ⑤ codex 파일 사전 검사 실패(codex 터미널이 작업 폴더에 파일을 놓을 수 없음 — R37). 걷은 것 = 옛 ④ 「다시 연결 확인 대기」(후보 제안만 있음 — 후보 제안 자체를 걷었다 · B11 · 사용자 2026-10-19 · 옛 ⑤ ⑥ 이 ④ ⑤ 로 당겨졌다) · 옛 「백엔드 정하는 설정 없음(R33)」(백엔드는 늘 에이전트 값) · 「codex 파일 대답 없음」(codex 파일은 늘 깐다) · 「설정 실행 직전 검사 실패」(CLI 검사를 걷음) · 「화면이 낸 실행에서만 막힘」 갈래(사용자 2026-10-18). 보이는 법 = §1-10 「막힘 팝업」. (워크스페이스 없음 막힘 = 다음 주제 §8)

같은 함수가 편집 칸의 충돌 줄과 실행 막힘 사유(같은 줄), 편집 칸 위 **문제 목록**, 「에이전트 N개에서 참조 중」, 실행 재료 셋 모두를 만든다 — 화면과 실행이 다른 규칙으로 갈리지 않게. `Resolution` 에 경고 칸은 없다(6).

**문제 목록(B3 · 사용자 2026-10-19 「위에 쭉 나열해 유저가 한눈에 볼 수 있도록」)** — `Resolution` 이 펼친 결과의 문제를 한 줄씩 낸다: 찾을 수 없음 · 오류(순환 포함) · 충돌 — **안에 든 프리셋(붙은 프리셋 · 그 안의 프리셋) 속 것까지**, 줄마다 그 줄까지의 온 길(「<프리셋> › …」 — 5 의 온 길과 같은 사슬)과 그 줄을 가리키는 자리(칸 · 펼친 사슬 — 화면이 눌러 그 줄로 뛰는 재료). 에이전트 슬롯에서는 실행 점검(`LaunchKitSource::check` — §1-5)이 에이전트 단위 막힘(④ 라이브러리 폴더 없음 · ⑤ codex 파일 사전 검사 실패 — 펼침이 아니라 디스크 · 설정을 보는 것)을 같은 목록에 더한다 — 그래서 에이전트의 문제 목록 = 막힘 사유 다섯과 같은 줄이다. 문구는 줄 표시와 같은 코드 + 인자(§3)다. 조사 = `docs/research/editor-problem-summary-practice-2026-10-18.md`.

**갱신 규칙(사용자 결정 2026-10-16 · 2026-10-17)** — 전체 훑기는 데이터가 처음 필요할 때(아래 「첫 훑기」) · 라이브러리 폴더를 바꿀 때만. 그 밖의 목록 요청(슬롯 열기 · 포커스 · 폴더 이동)은 데몬이 들고 있는 메모리 목록으로 답하고, Engram 안의 변경(이동 · 이름 · 삭제 · 새로 만들기 · 편집)은 그 목록에 바로 반영한다. 바깥 변경은 트리 우클릭 「새로 고침」(그 폴더 — 하위 포함 · 루트 머리 줄 = 전체) · F5 = 포커스한 칸 기준 — 트리 = 선택한 폴더(없으면 전체) · 목록 = 지금 보는 폴더, 둘 다 하위 포함(우리는 폴더에 들어갈 때 다시 읽지 않으므로 — 사용자 2026-10-17) 또는 `library.refresh {folder}`(생략 = 전체)로 들인다 — 에이전트에겐 Engram 밖에서 파일을 바꾼 뒤 이 명령을 부르라고 권한다(프라이밍 · 강제 아님 — PRD R41 · 사용자 2026-10-17) · 답에 다시 읽은 파일의 문제가 실린다(§1-7). 안전장치 = 명령이 목록에 없는 경로를 가리키면 그 경로 하나만 확인해 넣는다 · 실행 직전 붙은 파일을 다시 확인한다. 감시 · 구독 · 방송 · 주기 요청 없음. **첫 훑기 = 전부 한 번(사용자 2026-10-17 · S1–S3)** — 모든 파일의 꼬리표를 적고 설정 · 프리셋 `.yaml` 을 읽어 문법 · 스키마 검사까지 한다(캐시가 없으니 전부 「바뀜」 · 스키마는 이때 처음 필요하면 내려받는다 — `validate.rs`). 시작 = 데이터가 처음 필요할 때 — 라이브러리 슬롯을 처음 열 때 · `library.*` 명령이 처음 올 때 중 먼저 오는 쪽(옛 셋째 계기 「실행 중 다시 연결 후보가 필요할 때」 는 후보 제안을 걷어 없다 — 2026-10-19 · 데몬이 켜질 때 미리 훑지 않는다 — 사용자 2026-10-17 「데이터가 필요할때 훓어야지」) · 실행은 전체 훑기를 기다리지 않고 자기 프리셋과 그것이 가리키는 파일만 바로 읽는다(문법 확인 포함). 데몬 작업 스레드에서 돈다 — 데몬도 화면도 멈추지 않는다. 첫 훑기가 끝나기 전에 온 목록 요청은 그 훑기를 기다리고(동시 요청이 훑기 하나를 나눠 쓰는 규칙 그대로 — 흐름 ①), 프론트는 그동안 잠깐 로딩 표시를 띄웠다가 끝나면 목록 · 아이콘 · 참조 수를 한 번에 보인다(나눠 채우기 없음 — S3 · 느리면 §6-2 실측 뒤 다시 본다). 캐시는 메모리에만 있어 데몬을 다시 켜면 전체 훑기가 한 번 더 돈다(S1). 구현 = 아래 흐름 ①.

**흐름 ① 목록 요청과 훑기(R19 · 요청형)** — 둘을 가른다. 목록은 디스크를 읽지 않고, 디스크는 훑기만 읽는다.
- **목록 요청** — 버스 `library.list {folder}`(동기 포트 · `blocking_handler` 스레드) → 첫 훑기가 아직이면 그 훑기를 시작하거나 진행 중인 것을 기다린다(아래 「훑기」 의 합치기) → 읽기 잠금 → 메모리 `Catalog` 에서 그 폴더의 바로 안 항목 + 하위 폴더 줄(스킬 폴더 포함 · 스킬 표시 · 우리 종류 아닌 파일은 빠짐 — §1-2) · 참조 수 · 상태를 낸다. 명령이 `Catalog` 에 없는 경로를 가리키면 그 경로 하나만 디스크에서 확인해 넣는다(갱신 규칙의 안전장치).
- **훑기** — 계기 = 첫 필요(갱신 규칙의 「첫 훑기」) · `library.refresh {folder?}` · `library.setRoot`. 데몬 작업 스레드에서 `FsStore::scan(root, under)`(walkdir · `under = None` = 루트 전체 · `library.refresh {folder}` = `Some(그 폴더)` — 그 하위만 다시 훑고 밖의 항목은 직전 훑기 상태 그대로) → 바뀐 파일만 다시 파싱(꼬리표 = 경로 · 수정 시각 · 크기 · 파일 신원 같음 비교 + racy 규칙 — `catalog.rs` 행 · 다시 읽은 설정은 `validate.rs` 검사 · 첫 훑기는 캐시가 없어 전부) → `Catalog` 재구성(참조 = 프리셋 + 에이전트, 직접 + 건너서 — Δ3 · 가리키는 경로가 `Catalog` 에 없는 참조 = 「찾을 수 없음」 — 옛 「→ 다시 연결 후보(②)」 단계는 걷었다 · B11). 훑기 · 재구성 동안 파일 조작 · 편집은 기다린다(훑기 결과와 Engram 변경이 엇갈리지 않게). 동시 요청(첫 훑기를 기다리는 목록 요청 · 겹친 `library.refresh`)은 훑기 세대 번호로 합친다(뒤에 온 요청이 진행 중 훑기의 결과를 기다려 쓴다 — `Mutex` + `Condvar`). `library.refresh` 의 답 = 바뀐 항목 수 + 다시 읽은 파일의 문제(§1-7).
- **Engram 안의 변경** — 흐름 ③ · ④ · 다시 연결 적용(②)은 훑지 않고 쓰기 잠금 아래 `Catalog`(항목 · 참조 역색인)을 바로 고친다.
- 방송 · 구독 · 감시 없음.

**흐름 ② 다시 연결(Δ2 · D10 — B11 · 사용자 2026-10-19 「ㅇㅇ 그게 더 자연스러운것같네」 · 2판)** — **사용자 · LLM 이 하나를 고른 뒤에만** 돈다. 이름만 보고 저절로 적용하는 길도, 훑기 때 후보를 제안하는 길도 없다(관행 — 피어는 사용자가 첫 하나를 손으로 찾게 하고 나머지만 이름으로 잇는다 · 누르기만 하면 이름으로 잇는 피어가 없다 · `docs/research/relink-and-error-popup-practice-2026-10-18.md` · ★메모 68 「저절로」 를 뒤집는다★ · 옛 2026-10-18 D10 의 「훑기 때 후보 하나면 제안 + 막힘 ④ 다시 연결 확인 대기」 를 걷었다).
- **찾을 수 없음** — 참조 경로가 지금 `Catalog` 에 없으면 그 줄은 「찾을 수 없음 · [다시 연결] ×」(R19 · 막힘 사유 ①). 직전 훑기와 견주지 않으므로 색인 · 삭제 기록이 없다(§1-1 걷음 행). 참조는 고를 때까지 **옛 경로 그대로**다.
- **고르기** — 화면 [다시 연결] = 「+ 추가」 검색 팝오버를 **그 종류만** 걸러(종류 = 그 줄이 든 칸) **옛 이름을 미리 채워** 연다(채움은 우리 편의 — 피어 근거 없음). 고르기 전엔 아무것도 잇지 않는다. 1판엔 [다시 연결] 이 없다 — 없는 줄 = 「찾을 수 없음 · ×」(× 로 빼고 다시 추가 · LLM 은 파일을 고친다 · §5).
- **적용 — `library.relink {from, to}` 하나**(「다시 연결」 팝오버에서 고른 파일 · LLM 공용 — 코드 + 인자). 쓰기 잠금 아래, 하나씩 묻지 않고 이름으로: (a) 그 옛 경로를 가리키는 **모든** 참조(프리셋 파일 줄 · 에이전트 붙임 — 어느 프리셋 · 에이전트든)를 새 경로로 고친다 (b) 옛 폴더가 같았던 **다른** 「찾을 수 없음」 항목도, 새 파일의 폴더에 같은 이름 파일이 있으면 같이 고친다. 참조 고침은 흐름 ④ 의 참조 고침과 같은 함수다. 답 = 고친 쌍 + 「N개 더 찾아 연결함」(관행 — Premiere Link Media · After Effects 「X additional missing items have been found」 · Resolve · Blender). 고친 뒤 그 줄은 평범한 줄이다(옛 「다시 연결됨 · 이전 경로」 표시 · `relinked_from` · 확인 단추 · `library.ackRelink` 는 걷었다). 앱 안 이동 · 이름 바꾸기는 지금처럼 정확히 따라간다(흐름 ④ — 이 흐름은 바깥 변경 몫).
- 적용된 쌍은 이동 기록에 쌓인다(흐름 ⑥).

**흐름 ③ 편집(Δ8)** — `preset.add/remove/reorder` 는 파일의 최신 내용에 적용된다. 읽기 답마다 `rev`(파일 바이트 해시)가 실리고, `add` · `remove` 는 낡은 판이어도 멱등 적용, `reorder` 는 `base_rev` 가 다르면 `CONFLICT` → 화면이 다시 받고 「다른 곳에서 바뀌어 새로 불러왔습니다」 한 줄. 바깥 편집기의 수정도 같은 길로 반영된다. 답 = 그 프리셋의 새 상태(종류별 칸 · 줄 상태 · 충돌 줄 · `rev` · 「에이전트 N개에서 참조 중」). 옛 판의 「적용 뒤 참조하는 에이전트를 다시 해석해 **백엔드가 바뀌는 에이전트**를 답에 싣는다(Δ4)」는 걷었다 — 그것을 쓰던 경고 줄이 없다(§1-3 6 · 사용자 2026-10-18). 여러 개 추가는 부분 적용 `{added, skipped[{path, reason}]}`(Δ7).

**흐름 ④ 파일 조작(R17 · R18 · Δ3 · 2판)** — 쓰기 잠금 아래: (a) 계획 — 옛 → 새 대응표(삭제 = 옛 경로 → 휴지통 안 경로 — 계획 때 정한다 · 자리 규칙 §6-5) · 고칠 프리셋 파일 · 고칠 에이전트 · **이동 기록에 쌓을 쌍과 그 번호(계획 때 예약)** (b) 일지 쓰기(위 계획 전부) (c) 디스크 조작(`rename` · 삭제 = 루트 `.trash` 로 `rename` — 같은 루트 안이라 OS 휴지통 · 복사 없음) (d) 프리셋 파일마다 줄 고쳐 원자적 쓰기 (e) 에이전트 붙임 고치기(`ProfileRegistry` 한 번 저장) (f) 이동 기록 갱신 (g) 일지 지움. 부팅 때 남은 일지는 (c)~(f) 를 **단계별 판정으로 다시 돈다**: (c) 옛 경로가 없고 새 경로가 있으면 끝난 것으로 건너뜀(둘 다 없으면 일지를 「실패」로 남기고 알림 · 옛 경로만 있으면 다시 시도) · (d)(e) 「옛 경로면 새 경로로」 — 이미 고쳐졌으면 그대로 · (f) 예약한 번호의 쌍이 이미 기록에 있으면 건너뜀. 진짜 원자성이 아니라 **멱등 롤포워드**다. 답 = 대응표 + 고친 수. 옛 「삭제 기록에 더할 경로」 · 「삭제 기록 · 색인 갱신」 은 걷었다(후보 제안을 걷어 쓰임이 없다 — §1-1 걷음 행).
- **여러 개(B7)** — `library.move` · `library.delete` 는 경로 여럿을 한 조작으로 받는다(Ctrl · Shift · 상자 선택 · 끌어 놓기 모두 이 한 길). 삭제는 고른 것 중 **하나라도** 참조(프리셋 + 에이전트)가 있으면 `yes` 없이 `CONFLICT` 한 번(Δ9) — 걸린 항목 전부와 그 참조를 싣는다(화면은 모달 하나 — §1-10).
- **삭제 = `.trash`(B8)** — 삭제는 늘 루트 `.trash` 로 옮긴다(LLM · CLI 도 같다 — 되살릴 수 있게). 루트 자체는 지울 수 없다(경로로 가리킬 수도 없다 — 빈 `LibPath` 없음). `library.*` 는 `.trash` 아래 경로를 받지 않는다(숨은 항목이라 `Catalog` 에 없고, 「목록에 없는 경로 하나만 확인해 넣는」 안전장치도 `.` 으로 시작하는 마디는 넣지 않는다 — 버스로 휴지통 안을 지우거나 꺼내는 뒷문을 막는다 · 이 거절은 메인 세션 제안 — 꺼내기를 LLM 에 열지는 §6-5). **비우기(영구 삭제)는 버스 · `engram` 명령이 없다 — 사람만**(「LLM-우선 제어」 의 의도된 예외 · §7 28).

**흐름 ⑤ 실행 재료** — §1-5.

**흐름 ⑥ 이동 기록(Δc)** — 앱 안 이동 · 이름 바꾸기 · 적용된 다시 연결이 쌍(옛 → 새)을 번호 붙여 쌓는다(최근 1,000 쌍 — 넘치면 오래된 것부터 버리고 바닥 번호를 올린다). 클라이언트는 라이브러리 요청을 낼 때마다(슬롯 열기 · 포커스 · 새로고침 · 폴더 이동) `library.moves {since: 커서}` 를 함께 불러 커서 뒤의 쌍을 받고, 자기 컬렉션을 고친 뒤 커서를 옮긴다. 커서가 바닥보다 오래됐으면 답에 `truncated` 가 서고, 그 사이 이동된 컬렉션 항목은 「찾을 수 없음」으로 남는다(받아들인 손실 — §6). 요청한 클라이언트만이 아니라 **모든** 클라이언트가 자기 다음 요청에 따라잡는다 — 방송 없이.

**루트 · 기본 경로** — `library.status` 가 `{daemon_id, root, state: unset|ok|missing, suggested_new}` 를 준다. `suggested_new` 는 **데이터 폴더 배치(`DataLayout`)의 메서드**로 낸다. `DataLayout` 은 루트가 **어디서 왔나**(`ENGRAM_DATA_DIR` 지정 · 디버그 기본 · 릴리즈 기본)를 함께 든다 — 릴리즈 기본(루트 = `<배포판>\data`) = 그 부모의 `library`, 그 밖 = 루트 **안**의 `library`. 디렉터리 이름으로 짐작하지 않는다. 그래서 `ENGRAM_DATA_DIR` 로 격리한 시험은 실제 폴더를 건드리지 않는다. [새로 만들기]는 이 경로를 미리 채울 뿐이고 내용은 넣지 않는다(Δ1). 루트를 바꾸면 에이전트 붙임 · 컬렉션은 그대로 두고 **같은 경로를 새 루트에서** 찾는다 — 없으면 「찾을 수 없음」. 이동 기록은 새로 시작한다(Δf — 루트를 넘는 다시 연결은 없다 · `relink` 는 같은 루트 안의 경로만 받는다). `.trash` 는 루트마다 그 루트 안에 있다 — 옛 루트의 휴지통은 옛 폴더에 남는다. 이동 기록에는 루트마다 새로 뽑는 `log_id` 가 붙고, 클라이언트 커서의 `log_id` 가 다르면 쌍을 적용하지 않고 커서만 새 머리로 옮긴다.

| `generated_paths: Vec<PathBuf>` | Engram 이 작업 폴더에 만든 파일 · 정션(codex 터미널 — 늘 깐다 · 사용자 2026-10-18 · 옛 「파일 만들기 대답」 칸 `codex_files` 는 걷었다). 걷는 조건은 아래 「생성물 소유」 |

**작업 폴더 `cwd`** — 칸은 지금 그대로다(필수 · 만들 때 선택 · 디스크 키 · wire 모양 불변 — 빈 값 · 경로 없는 생성 = 다음 주제 §8). 더하는 것은 **바꾸는 길과 잠금**이다(사용자 2026-10-18 「에이전트 프리셋 셋팅하고 하는부분 있잖아. 거기에 항목이 하나 더 있는거지」 · 「대화 뒤 잠금은 있어야지」).
- **잠금** — 그 에이전트에 영속된 backend 세션 id 가 있거나(첫 제출 래치가 적은 것 — ADR-0226 · 사용자 「ssi 박히잖아. 그게 있으면 못바꾸게」) **떠 있으면** 바꿀 수 없다. 화면은 읽기 전용 + 짧은 이유 「대화한 에이전트 — 바꾸려면 새 에이전트」. 대화 전에만 바뀌므로 놓을 세션이 없다 — 작업 폴더 바뀜에 새 대화 · 세션 놓기 로직을 두지 않는다(§8 에 옮겨 둔 옛 설계의 `launched_workspace` · `release_session_id` 길을 이 잠금이 대신한다).
- **`agent.setWorkspace {agent, cwd}`**(본문 = manager — 라이브러리가 필요 없다) — 경로는 있고 폴더여야 한다(아니면 오류 코드 + 인자) · 잠겼으면 `CONFLICT`(코드 + 인자 = 잠긴 까닭 — 대화함 · 떠 있음 · R49). 잠금 판정과 저장은 그 에이전트의 실행 예약과 같은 줄에서 `ProfileRegistry` mutate 한 번으로 한다 — 실행 준비 중인 에이전트와 엇갈리지 않게(그 사이엔 떠 있음으로 `CONFLICT`). 화면 「작업 폴더」 칸의 입력 · 「찾아보기」 도 이 명령을 부른다(LLM 과 같은 길 — CLAUDE.md 「LLM-우선 제어」).

**그 밖의 프로필 규칙**
- **`command`(Claude/Codex/Shell + `extra_args` + `output_format`)** 는 지금 그대로 **에이전트 값**이다 — 변형 = 백엔드 · `output_format` = 모드(D5) · 둘 다 만들 때 정하고 바꾸는 길이 없다(사용자 2026-10-18 「그냥 고정해. 백엔드는.」). 해석(§1-3 4)은 백엔드를 이 변형에서 읽는다 — 변형 → 백엔드 낱말 대응은 지금 있는 것(`agent.new` 의 백엔드 어휘)을 쓴다. 패스스루 인자도 지금 그대로 `command.extra_args` 하나다. 옛 판의 「`command` 는 해석 결과에서 파생」 · `backend::command_for` · 백엔드별 인자 `backend_args` 는 백엔드가 설정으로 바뀌는 경우를 위한 것이라 걷었다(그 경우가 없다). Shell 에이전트는 프리셋을 받지 않는다(해석 대상 아님).
- **`display_name` 고정** — 만들 때 `None` 이면 그때의 표시 이름을 박는다. 이름이 `cwd` basename 에서 파생되던 길은 작업 폴더가 바뀌면 우편 주소 · 트리 이름을 말없이 바꾼다 — 이번 판에 작업 폴더를 바꾸는 길(`agent.setWorkspace` · 「작업 폴더」 칸)이 생기므로 이 단계에서 고정한다.
- **새 프로필 생성자 하나** — `AgentProfile::new`(지금 `SpawnByCwd` · 스모크 bin · `CreateProfile` 이 이미 지나는 그 생성자)가 기본값을 단다: `default_preset = true` · `presets = []`(`command` 는 받은 그대로 — 기본 제공 백엔드 프리셋을 붙이던 dispatch `backend::builtin_backend_preset` 는 걷었다 · 사용자 2026-10-18). `agent.new` · wire `CreateProfile` · `SpawnByCwd` · 스모크 bin 이 모두 이 한 길로 같은 기본값을 얻는다.
- **`merge_preserving_live` 보존 칸에 더한다**(「런타임이 저자인 칸」) — `presets` · `default_preset` · `generated_paths` · `cwd`(만든 뒤의 저자 = `agent.setWorkspace` 하나 — 지금은 만든 뒤 `cwd` 를 쓰는 길이 없다 · 확인함). 이 칸들의 저자는 프리셋 명령 · 실행 전처리이지 spawn 이 뜬 옛 사본이 아니다.
- **복제 `agent.duplicate {agent}`(B13 · 사용자 2026-10-19 · 1판)** — 에이전트 트리 우클릭 「복제」 와 같은 명령. 새 id 의 프로필을 만들어 **옮기는 것** = 붙은 프리셋(`default_preset` + `presets`) · 백엔드 · 모드 · 패스스루 인자(`command` 전체 — `extra_args` 포함) · 작업 폴더(`cwd`) · 환경 변수. **옮기지 않는 것** = backend 세션 id · 대화(새 대화로 시작 — 그래서 「작업 폴더」 칸이 잠기지 않는다) · 실행 상태 · `generated_paths`(원래 에이전트 id 의 소유 표식이 붙은 생성물이라 — 이 줄은 「실행 상태」 의 해석). 이름 = 「<이름> (2)」 · (3) …(R17 새 항목 이름과 같은 번호 규칙 — 메인 세션 선택 「네이밍은 관행대로」) · `display_name` 으로 고정한다. 본문 = manager(라이브러리 불요 — `agent.setWorkspace` 와 같은 자리 · 메인 세션 선택). 답 = 새 에이전트 id · 이름.

**옛 에이전트 — 이전하지 않는다**(D4 · 사용자 2026-10-18 「기존거 필요없어」 — 옛 이주(Δ1 · Δh)를 걷음) — 새 빌드의 데몬이 처음 켜질 때 옛 판이 쓴 `agents.json` 은 지우지 않고 백업 파일로 비켜 두고 빈 명부로 시작한다(메인 세션 내부 선택 · §3). 옛 판 파일인지 가르는 판 표식 · 백업 파일 이름은 구현 판단이다 — 새 판이 쓴 파일(빈 명부 포함)을 다시 비켜 두지 않게 한다. 옛 에이전트의 세션 · 작업 폴더 · 백엔드는 새 판에 이어지지 않는다 — 쓰려면 새로 만든다.

**호환 · 내림(정직하게)** — 새 빌드는 `cwd` 키를 지금 그대로 쓴다. 옛 빌드는 모르는 칸을 무시하므로(`deny_unknown_fields` 없음 — 확인함) 새 `agents.json` 을 **읽는다**. 그러나 옛 빌드가 다시 저장하면 새 칸(판 표식 포함)이 전부 사라지고, 다시 새 빌드로 올리면 그 파일이 옛 판 파일로 보여 다시 백업으로 비켜지고 **에이전트 목록이 비워진다**(위 「옛 에이전트」). 내림을 지원하지 않는다는 것은 이 손실을 받아들인다는 뜻이다.

**포트(`launch.rs` 신설)** — 데몬이 꽂는다. 기본 구현 `NoopLaunchKits` 는 「지금과 같은 결과」(백엔드 = 명령 변형, 지침 = 프라이밍 파일 그대로)를 내고 **argv 가 바이트 단위로 같다**(`--system-prompt-snapshot off` 도 안 붙는다 — 아래 번역 표).

- `trait LaunchKitSource { fn check(&self, profile, origin: LaunchOrigin) -> Result<LaunchPlan, LaunchBlocked>; fn prepare(&self, plan, id, epoch, priming: Option<&Path>) -> Result<LaunchKit, String>; fn release(&self, id, epoch); }` — `check` 는 프로필을 고치지 않고, 무인 실행의 기본값을 `LaunchPlan.profile_changes` 로 돌려준다(포트가 프로필 저장소를 직접 만지지 않는다). ★이번 판엔 `origin` 이 결과를 바꾸지 않고 `profile_changes` 도 늘 빈다★ — 막힘 사유는 누가 실행하든 같고(§1-3 8), 채우던 무인 기본값(codex 파일 대답)은 걷었다(사용자 2026-10-18). 틀은 다음 주제(경로 없는 에이전트를 실행 때 묻기 — §8)가 쓴다.
- `LaunchPlan` = 에이전트 백엔드 낱말 · 지침 원천 목록 · 스킬(이름 · 절대 폴더) · 그 백엔드 원문 목록(모델 · 강도도 이 안 — 따로 된 모델 칸 없음) · 프라이밍 포함 여부 · 프로필 변경 · `real: bool`(Noop = false). 경고 칸은 없다(§1-3 6 · 사용자 2026-10-18).
- `LaunchKit` = `LaunchPlan` + 휘발 폴더 · 합친 지침 파일 경로 · 스킬 목록(절대 경로).
- `LaunchBlocked { reasons: Vec<BlockReason> }` — 종류가 있는 사유 다섯(§1-3 8 의 순서 — `Missing` · `Broken` · `Conflict` · `LibraryUnavailable` · `CodexFilesBlocked` · 옛 `NeedsCodexFilesAnswer` 와 `RelinkUnconfirmed`(다시 연결 확인 대기 — B11 · 2026-10-19)는 걷었다). 사유마다 걸린 항목(라이브러리 경로 · 그 항목을 참조하는 프리셋)과 이유(코드 + 인자 · 줄)를 싣는다 — 막힘 팝업 · LLM 답의 재료(§1-10 · R49). `Conflict` 는 §1-3 5 의 충돌 줄을 하나씩 싣는다(무슨 충돌 · 걸린 항목 전부 · 온 길) — 실행 때 화면이 보이는 것은 이 충돌 내용(과 다른 막힘 사유)뿐이다(사용자 2026-10-18).

**manager 실행 흐름** — 두 덩이로 가른다.

*(가) 실행 전처리(`prelaunch`) — `SpawnReservation` 예약과 「이미 떠 있음」 확인 **바로 뒤**.* 둘은 `profile.id` 만 읽으므로 그 뒤에 두면 전처리가 **에이전트마다 하나씩 줄 선다**(같은 에이전트의 두 실행이 함께 돌지 않는다). `epoch_for_spawn` · 작업 폴더 canonicalize · 세션 id 파생보다는 **앞**이다. `activate_profile` 의 「활성화 진행 중」 조기 반환도 그대로 앞에 남는다.

0. **명부에 없는 id 를 먼저 넣는다** — wire `SpawnByCwd`(`connection_core.rs:1530-1543`) · 스모크 bin(예 `bin/priming_smoke.rs:168-179`)은 명부에 없는 프로필로 `spawn_agent` 를 부른다. 그래서 `register_for_spawn` 의 **「없을 때 넣는」 부분**(용량 검사 · 이름 배정(`display_name` 고정) · upsert)을 `ensure_registered` 로 떼어 전처리 **앞**으로 옮긴다. 「있을 때 갱신하는」 부분과 나머지 일은 지금 자리에 남는다. 그래서 전처리는 늘 **명부에 있는 항목**을 고친다.

1. `kits.check(명부에서 읽은 프로필, origin)` — 호출자가 넘긴 사본이 아니라 **예약 뒤 명부에서 다시 읽은 값**으로 점검한다. `origin` = **누가 실행을 냈나**(Δg): `Interactive`(화면 — wire `Spawn` · 활성화) 또는 `Unattended`(버스 `agent.spawn` · 제어 CLI · 부팅 자동 복원) — 이번 판엔 결과를 바꾸지 않는다(위 포트 항목). 막히면 `PtyError::SpawnFailed(사유)`로 끊고 `failed_reason` 에 남긴다(지금 실패 표시 길 — 에이전트 트리의 그 줄 ⛔). 화면은 실행 전에 `agent.launchCheck` 로 같은 사유를 구조로 받아 막힘 팝업을 띄우고(§1-10), 버스 · CLI 는 `agent.spawn` 의 거절 답으로 같은 사유를 코드 + 인자로 받는다(§1-7).
   - **설정 검사는 실행이 붙은 설정을 읽을 때 함께 돈다**(§1-4 `validate.rs` — 프로세스 안 · CLI 를 돌리지 않는다) — 타입 · 범위 오류면 막힘 ②. 옛 실행 직전 CLI 검사(`claude --settings … doctor` · `codex debug models`)와 그 통과 기록 · 캐시는 걷었다(사용자 2026-10-18 — 문제가 생기면 그때 다시 본다). 실행 중 오류(종료 코드 + stderr)는 설정 행에 표시하지 않는다 — 에이전트에만 남는다(지금 실패 표시 길 · 종료 코드 + stderr 원문 · 사용자 2026-10-18 — 2026-10-17 의 「그 설정 행 ⛔」 를 걷음).
2. **맞추기 — 명부 변경 한 번(비교-교체)** — 1 에서 읽은 뒤 `presets` · `default_preset` 이 **바뀌지 않았을 때만** 적용한다. 바뀌었으면 다시 읽어 1 부터 **한 번** 더 하고, 또 바뀌었으면 「실행 준비 중 프리셋이 계속 바뀌었다 — 다시 시도하라」로 끊는다. 바뀔 칸(무인 기본값)을 **`ProfileRegistry` 의 mutate 한 번**으로 **지금 명부 값에 대해** 적용한다(그 사이 사람이 정한 값은 덮지 않는다). ★이번 판엔 바뀔 칸이 없다★(`profile_changes` 가 늘 빈다 — 옛 예 `codex_files` 를 걷음) — 비교(그 사이 바뀌었으면 1 부터 다시)는 그대로 하고 쓰는 칸만 없다. 옛 판의 「해석된 백엔드로 변형 맞추기 · 백엔드가 저장된 변형과 다르면 `release_session_id`(옛 R33)」 는 걷었다 — 백엔드는 에이전트 값이라 바뀌지 않는다(사용자 2026-10-18). (작업 폴더 맞추기 · Engram 폴더 만들기 = §8)
3. **명부에서 다시 읽기** — 그 mutate 가 돌려준 프로필(= 명부의 지금 값)에서 이후 모든 단계(등록 · 화신 표식 · canonicalize · 세션 id · 모드)를 파생한다. 이번 판엔 전처리가 세션을 놓는 계기가 없다(옛 백엔드 바뀜을 걷음 · 작업 폴더는 대화한 뒤 잠겨 바뀜이 세션을 놓지 않는다 — 위 「작업 폴더 `cwd`」). 그 계기가 서면 세션을 놓은 실행은 호출자가 `Resume` 을 청했어도 `Fresh` 로 간다(결말은 `Started` — 지금 `resume_no_fallback` 의 같은 결말 길) — 첫 제출 래치(ADR-0226)가 맞춰진 프로필과 어긋나지 않는 id 만 보게.

*(나) 기동 — 지금 순서 그대로에 셋을 끼운다.*

4. 제어 채널 `provision`(지금 그대로 — 프라이밍 경로가 여기서 나온다).
5. `kits.prepare(plan, id, epoch, endpoint.priming_file)` — 데몬이 휘발 폴더에 합친 지침(기본이 붙었으면 프라이밍 + 프리셋 지침 순서대로)를 쓰고 스킬 목록을 낸다. **실행 재료 전용 RAII 가드(`LaunchKitGuard`)** 가 바로 무장된다 — `ProvisionGuard` 와 독립이고, 스폰이 끝나기 전 어디서 실패하든 `kits.release(id, epoch)` 를 부른다.
6. `backend::materialize(command, kit, cwd, fs)`(새 dispatch) — 백엔드만 아는 디스크 배치(claude 플러그인 폴더 정션 · codex 작업 폴더 파일). 쓰기는 **배치 포트 `LaunchFs`**(`write_file` · `link_dir` · `unlink_dir` · `remove` · `exists`)로만 한다 — 운영 = std + `platform::fs`, 시험 = 메모리 가짜(디스크 없이 backend 배치를 잰다). 작업 폴더에 만든 것은 `generated_paths` 로 돌려줘 프로필에 남고, 스폰이 실패하면 가드가 이번에 만든 것을 걷는다. 결과 = `LaunchArtifacts`(그 백엔드가 쓸 경로 · 인자 조각).
7. `build_command_spec(…, control, &artifacts)` · `open_spawn(…, &artifacts)` — 두 함수가 실행 재료 descriptor 를 하나 더 받는다(`ControlEndpoint` 와 같은 방식).
8. 회수(reaper · kill)에서 `kits.release(id, epoch)` — 휘발 폴더를 지운다. 데몬 부팅 때 남은 `launch\` 를 쓸어 낸다.

**생성물 소유(codex 터미널)** — 만드는 것마다 **확인 가능한 소유 표식**을 단다: `AGENTS.override.md` 첫 줄 `<!-- engram:generated agent=<agent-id> sha=<내용 해시> -->` · 정션 이름 `engram-<agent-id 앞 8자>-<스킬>`. 걷기는 표식이 있고 **내용이 Engram 이 만든 그대로일 때만**(파일 = 해시 일치 · 정션 = 대상이 그 스킬 폴더) 하고, 아니면 남기고 경고한다(사용자가 손댄 것을 지우지 않는다). 전처리는 **기존 파일 검사(R37 막힘)보다 먼저** 지난 실행의 남은 생성물을 이 규칙으로 정리한다(스폰 도중 죽은 경우 포함). 에이전트가 떠 있는 동안의 떼기는 걷기를 **멈출 때 · 다음 실행 전처리로 미룬다**(돌고 있는 codex 가 읽는 파일을 빼지 않는다).

**JSON 모드 모델 · 강도 선택 칸(T8 — 마지막 단계 · 2판 · 범위 안)** — 목록은 **그 에이전트 백엔드의 모델만**이다(백엔드는 에이전트마다 고정 — claude 에이전트 = claude 목록 · codex 에이전트 = codex 목록 · 두 백엔드를 한 목록에 섞지 않는다 · B16). 막지 않고 **잠그지도 않는다**(3차 델타 · 사용자 2026-10-18 「모델선택칸 잠금은 하지마. 그냥 유저가 알아서 하라고 그러지.」 — 옛 「설정이 모델을 고정하면 잠김 · 설정이 고정」 을 걷음): CLI 가 시작한 값(원문 칸에 모델이 있으면 CLI 가 그것으로 시작한다 · 없으면 CLI 기본값 — Engram 은 원문 칸에서 모델을 읽지 않고 CLI 가 알려 준 값을 쓴다)이 미리 선택되어 있고, 선택 칸은 그 세션에서 그것을 바꾼다(원문 칸과 맞추는 것은 사용자 몫). 첫 메시지가 어디서 오든(화면 · 우편 · 버스) 그때 선택한 값으로 나간다. 선택한 값은 그 세션 것이고 저장하지 않는다(R35). **모델과 강도 둘 다 첫 사용자 메시지 전에 backend 요청으로 세션에 닿는다** — 길은 backend 가 정한다.
- claude: stream-json 의 control request 로 모델 · 강도를 바꾼다(SDK 의 바꾸기와 같은 요청 꼴). 목록은 `initialize` 응답(메모 27 실측).
- codex: 첫 `turn/start` 의 모델 · 강도 덮어쓰기 칸. 목록은 `model/list`.
- **수용 관문(14 단계)**: JSON 백엔드 **각각**(claude · codex)에서 모델 · 강도 둘 다 첫 메시지 전에 바뀌는지 실 CLI 로 확인한다(다음 턴 표기). 미리 선택할 「CLI 가 시작한 값」 을 CLI 가 알려 주는지(원문 칸에 모델을 넣은 경우 포함)도 함께 본다(미측).
- **멈춤 조건**: 어느 백엔드에서든 그 요청이 안 되면 그 부분의 구현을 **멈추고 사용자에게 돌아간다**(R35 를 고치거나 지원되는 다른 길을 찾는다). 칸을 조용히 끄는 것은 허용되는 대체가 아니다. 대기 입력 명부 · 첫 제출 래치의 소유는 건드리지 않는다.

`DISABLE_AUTOUPDATER` 와 `allowedMcpServers:[{serverName:"engram"}]` 는 기본 제공 프리셋 「기본」의 claude 원문(settings `env` · 최상위 키)으로 실린다 — `DISABLE_AUTOUPDATER` 는 이 브랜치 · HEAD 의 claude 백엔드에 박힌 값이 없다(grep 0건 · 다른 세션이 박았다면 그 머지 때 이 길로 옮긴다 — R32). `allowedMcpServers` 는 지금 제어 채널이 스폰마다 쓰는 조각 파일(`control/mcp_config.rs` · ADR-0109 결정 9)에서 이리 옮긴다(T10). 그래서 「기본」 을 떼면 Engram 메시지 · 제어 통로도 빠질 수 있다(사용자 전역 설정이 `allowedMcpServers: []` 로 막을 때) — 떼기 확인 문구에 「Engram 메시지 · 제어 통로」 가 더해진다(`DetachDefaultConfirm` · R32).

**명령 어휘의 자리와 소유(ADR-0155 결정 1 · ADR-0251 선례)** — `library.*` · `preset.*` · 에이전트 프리셋 명령은 **agent crate 의 `declare_commands!` 블록에 선언한다**(catalog 6 → 7). 어휘(이름 · 인자 · 답 행 타입)의 주인은 agent crate 이고, 데몬은 그 어휘를 **구현**만 한다 — 포트 `LibraryCommandHost`(실물 = 데몬 `LibraryService`) + `blocking_handler`. `agent.*` 프리셋 명령도 같은 포트로 간다(붙임 검증에 라이브러리가 필요하다). 거부 = 데몬 자기 블록 + 표 합성(ADR-0251 이 `usage.*` 에서 같은 이유로 거부) · 라이브러리 전용 crate(소비자 하나).

### 1-6. platform — OS 층 동작 셋

| 함수(자리표시) | Windows | 그 밖 | 바탕 |
|---|---|---|---|
| `fs::link_dir(target, link)` · `fs::unlink_dir(link)` | 디렉터리 정션(관리자 권한 불요) · `unlink_dir` 는 정션이 아니면 거절 | 심볼릭 링크(std) | `junction` 2.1.0 — `windows-sys` `>=0.59, <=0.61` 을 쓰는데 그 판들(0.59.0 · 0.60.2 · 0.61.2)이 이미 `Cargo.lock` 에 있어 새 사본이 늘지 않는다(가능성 높음 — 해석기가 고르는 판은 2 단계에서 `cargo tree` 로 확인) |
| `fs::same_path(a, b)` | 대소문자 무시 비교 | 그대로 비교 | std |
| `fs::file_identity(path)` | 볼륨 일련번호 + 파일 인덱스(`GetFileInformationByHandle`) — 훑기 꼬리표의 파일 신원(§1-4 `catalog.rs`) | (장치 번호, inode)(std `MetadataExt`) | `windows` 0.58(합집합 한 의존) · std |

- **게이트** — OS crate 의존 게이트(`/qa` 4g · CI `platform gate 5`)의 손 목록에 `junction` 을 더한다. 새 OS 별 코드 · 시험은 platform 안에 두며, platform **밖**의 시험 파일이 OS `cfg` 를 써야 하면 OS cfg 파일 명단 게이트(`/qa` 4f · CI `platform gate 4`)의 명단도 같은 커밋에서 고친다(되도록 platform 도우미를 불러 `cfg` 없이 쓴다).
- **(걷음 2026-10-19) OS 휴지통 `fs::move_to_trash`** — 옛 첫 줄(전용 STA 작업 스레드의 `IFileOperation` · `FOFX_RECYCLEONDELETE` · `FOF_ALLOWUNDO` · `FOF_NO_UI` · `windows` 0.58 에 `Win32_UI_Shell` feature 추가)을 걷었다. 삭제는 라이브러리 루트 안 `.trash` 로 옮기는 같은 루트 안 rename 이라 OS 층 동작이 필요 없다(B8 · 사용자 2026-10-19 「ㅇㅇ 우리 trash 폴더로해」 · 거부 이유 = §7 20). 그래서 `windows` feature 도 더하지 않는다. 옛 「`trash` crate 를 쓰지 않는 이유」(셋째 `windows` 사본 · 호출 스레드 `CoInitialize` 실패 시 패닉 — 리뷰 지적 · 미측)도 OS 휴지통 자체를 안 쓰므로 따질 일이 없어졌다.

### 1-7. 명령 표면 — 화면 단추와 LLM 이 같은 것을 부른다

**웹뷰 → 데몬 왕복(선행 작업)** — 웹뷰는 이미 `forward_daemon_command` 로 wire 명령을 보내고 답을 request_id 로 맞춘다. 버스 봉투(`Command{envelope}`)의 답 `CommandReply` 는 상관 키가 봉투 안이라 웹뷰 `handleEvent` 가 아직 못 맞춘다(셸 `daemon_client/inbound.rs` 헤더의 그 틈). 그 갈래를 더하고 `agentClient.callCommand(name, args)` 를 연다. 데몬은 자기 표의 이름을 그 자리에서 답한다(`command_delivery::deliver` 의 `locals.claim`).

**CLI** — 일반형 `engram <이름> --인자 값` 이 데몬의 런타임 표를 읽으므로 CLI 코드는 안 바뀐다. 불리언은 값 없이 선다(`--yes`). 화면 단추도 같은 명령이다 — 확인 모달을 거친 뒤 `yes=true` 로 부른다.

**도움말 — 주제로 묶는다(B12 · 사용자 2026-10-19 — 맨 위 help 를 부풀리지 않는다)** — `engram help` 맨 위엔 주제 줄 하나(예 `library`)만 더하고, `engram help library` 가 설정 · 프리셋 파일 형식 + `description:` 이 든 예 + 「설정 · 프리셋 파일을 만들거나 고칠 때 한 줄 설명을 적는다」 한 문장을 싣는다. 프라이밍(「기본」 의 Engram 안내)도 같은 내용을 싣는다. 화면(help)은 데몬이 낸다(`/control/help`) — 지금 help 계약이 주제를 받는지는 확인하지 않았다(§6-2).

**사람만 하는 것(의도된 예외)** — 라이브러리 휴지통 **비우기**는 버스 · `engram` 표에 없다(§7 28 — 에이전트가 잘못 지워도 되살릴 수 있게). 삭제(→ `.trash`)는 LLM · CLI 도 한다. 화면 길은 §6-5.

**데이터(요청형)** — `api/libraryClient.ts` 가 `agentClient.callCommand` 위의 타입 있는 얇은 층(인자 타입 = agent crate 생성 바인딩). `api/libraryQueries.ts` 가 TanStack Query 를 import 하는 **유일한 파일**이다(T1) — 키 = `[daemonId, 종류, 인자]`. 슬롯 열기 · 포커스(슬롯 포커스 이벤트) · 새로고침 · 폴더 이동 때 그 슬롯의 쿼리를 무효화해 다시 받고, 같은 계기에 `library.moves {since}` → 새 쌍이 있으면 `collection.applyMoves` 를 부른다(Δc). 창 포커스 자동 재요청 · 주기 재요청은 끈다(R19). 편집 답은 그 자리의 쿼리 데이터를 바로 바꾼다. 다른 슬롯은 자기 포커스 때 맞춰진다.

**표시** — 없는 항목은 편집 칸 · 에이전트 슬롯에 점선 줄 「찾을 수 없음 · [다시 연결] ×」 로 보이고(후보 제안 줄은 없다 — B11 · 1판엔 [다시 연결] 없이 「찾을 수 없음 · ×」), 그 줄을 품은 프리셋 줄이 빨간 오류 수 배지를 달고 머리 밑 문제 목록에도 한 줄 든다(`PresetEditor` 행 · B3). 옛 「다시 연결됨 · 이전 경로」 · 「다시 연결할까요? · [확인]」 표시(Δd)는 걷었다. 에이전트 슬롯 머리 = 이름 + 백엔드 · 모드(에이전트 값 · 만들 때 고정 · R31 — 작업 폴더는 머리가 아니라 「작업 폴더」 칸에서 보고 바꾼다) — 옛 「기본 제공 백엔드의 흐린 「사용할 수 없음」 줄」 과 codex 파일 대답은 걷었다(사용자 2026-10-18).

**막힘 팝업**(사용자 2026-10-18 「프리셋 툴팁 뜨잖아. 거기서 셋팅이 에러났다는게 한눈에 보여서 그걸 누를 수 있게 유도해야됨」 · 관행 = 모달은 심각 · 앱 전체 오류에만 · 원천 곁에 · 눌러 따라가기 — NN/g · Microsoft · Unreal Compiler Results — `docs/research/blocked-launch-error-display-practice-2026-10-18.md`)
1. 실행이 막히면(더블클릭 · 활성화 — `agent.launchCheck` 가 사유를 내면) 에이전트 곁에 `LaunchBlockedPopup` 이 뜬다 — 막힌 항목마다 이유 한 줄 · 항목 이름 = 링크.
2. 링크를 누르면 라이브러리가 그 항목을 고른다 — 셸 명령 `libraryView.reveal {path}`(번호 생략 = Δ6 규칙: 열린 라이브러리 1~4 가 있으면 마지막 만진 것 · 없으면 「라이브러리 1」 을 연다 — 위 메뉴와 같은 길(떠 있는 창)로 열되 그 길은 도킹 작업(R42 · wt2)의 것이라 이 브랜치엔 없고, 그 전엔 `slot.openUnique` 의 열 자리 고르기 규칙). 첫 훑기가 아직이면 잠깐 로딩 뒤 고른다(흐름 ①). 오른쪽 상세 칸이 이유 · 줄 · 위치를 보인다(R15 오류 상세). 없는 파일은 고를 수 없으니 그 항목을 **참조하는 프리셋**을 고른다.
3. 에이전트 프리셋 슬롯 — 머리 밑 문제 목록(막힘 사유 다섯과 같은 줄 · 누르면 그 줄로 뛴다 — B3) · 막힘 항목이 든 프리셋 줄에 빨간 오류 수 배지(접힌 채 · 안에서 올라온 것까지 — `PresetEditor` 행) · 펼치면 그 줄 ⛔ + 이유 · 누르면 2 와 같다. 이 슬롯 표시와 에이전트 트리의 ⛔(지금 실패 표시 길)가 팝업이 닫힌 뒤에도 남는 기록이다.
4. LLM · CLI — 같은 내용을 `agent.spawn` · `agent.launchCheck` 답의 코드 + 인자로 받는다(R49).
- 새 전역 핸들 · 웹뷰 레지스트리 명령은 없다 — 기존 셸 명령(`libraryView.reveal` · `slot.openUnique`) 위에 선다(CLAUDE.md 「LLM-우선 제어」).

**보기 상태** — 권위는 셸(§1-9). `store/libraryViewStore.ts`(zustand)는 셸이 쏜 `library-view:updated` 를 받아 둔 **그리기용 사본**이고, 몸짓은 `libraryView.*` 를 invoke 한다. 끄는 중의 칸 폭 같은 순간 값만 웹뷰에 머물고 끝난 값을 `libraryView.setLayout` 으로 보낸다.

### 2-2. TRD 단계 결정 (각각 추천 + 이유 한 줄)

- **T1 슬롯 데이터 받기 = TanStack Query** — **확정 2026-10-18(추천 그대로)** · `libraryQueries.ts` 한 파일에 가둔다. 이유: 요청형 · 포커스 무효화 · 편집 답 반영 · 중복 요청 합치기를 그대로 준다(메모가 예정한 `/research` 는 돌리지 않았다 — 구현 때 확인해도 된다).
- **T2 프리셋 파일의 손 주석** — **확정 2026-10-18 = 지킨다**(관행 — 사용자 「그런 라이브러리를 찾고 없으면 관행대로 처리해」 · 옛 추천 「사라짐을 받아들이고 머리 주석 · 메모는 `description`」 을 뒤집음). 근거 = 사용자 파일을 고치는 도구가 주석을 날리면 불만이 나온다(Home Assistant · openHAB) · Python 쪽 사실상 표준 ruamel.yaml 이 왕복 보존이 존재 이유(`docs/research/yaml-comment-preserving-edit-2026-10-18.md`). 후보 `yaml-edit` 0.3.2(rowan 무손실 — 맵 set/remove/rename · 목록 push/set 은 문서 확인 · 목록 넣기/빼기/순서 · 뺀 항목 주석은 미확인) → **첫 구현 단계 = 실제 프리셋 파일로 스파이크 · `yamlpatch` 와 견줌**(§5 0b). 둘 다 안 되면 옛 추천(잃음 받아들임 + 메모는 `description`)으로 물러나 사용자에게 보고한다. 읽기는 serde-saphyr 그대로 — 편집 쓰기 길만 바뀐다.
- **T3 `model` 칸 둘 이상** — **확정 2026-10-18 = 검사 없음**(사용자 「클로드 쪽에서 허용하면 허용인거고 안되면 충돌인거지」 · 「대조표? 매번 업데이트 받아서 비교된다는거잖아. 그게 아니라 이번에 적용하고 나중에 또 대응해야되면 빼는게 맞고」). 정식 `model` 칸이 없어져 모델은 원문 칸 안이고 Engram 은 원문을 해석하지 않는다 — 두 설정이 같은 칸에 모델을 넣으면 CLI 가 하는 대로다. 옛 추천(충돌)은 검사하려면 CLI 마다 대조표를 CLI 갱신 때마다 고쳐야 해서 걷었다. 받아들인 것 = 어느 모델로 뜰지 화면에 안 보인다(§6-3).
- **T4 Engram 폴더 기본 위치** — 미룸(다음 주제 — 에이전트 트리 · §8 에 추천 그대로 옮겼다 · 사용자 2026-10-18 에도 미룸 유지).
- **T5 설정 창이 코드에 없다**(R9 · E3) — **확정 2026-10-18(추천 그대로 · 문구 사용자 확인 2026-10-18)**: 첫 판은 트리 머리(경로 옆 「…」 → 바로 폴더 선택 창 — R9) · 명령(`library.setRoot` · `settings.set`)만 · 설정 창은 별 작업. 이유: 설정 창은 이 기능보다 넓은 화면 설계다.
- **T6 codex JSON 이어받기에서 바뀐 지침** — **확정 2026-10-18(추천 그대로)**: 지침 해시가 바뀐 때만 첫 턴 실험 API `additionalContext` 로 「바뀌었다」 + 새 글(backend/codex 안). 이유: R36 을 codex 에서 지키는 유일한 실측 길(공식 `developerInstructions` 는 이어받기에서 말없이 버려짐). 대안 = 새 대화까지 미반영 + 경고.
- **T7 claude 스킬 싣는 길** — **확정 2026-10-18(추천 그대로)**: `--plugin-dir`(이름 `engram:<스킬>` — 예 `engram:review`). 대안 = `--add-dir`(접두 없음 · 네이티브 스킬과 이름이 겹치면 승자를 모른다). 이유: 사용자 `~/.claude/skills` 와 안 섞이고 적재가 실측됐다.
- **T8 JSON 모드 모델 · 강도 선택 칸** — 코드에 없다(R35 는 있는 듯 적혀 있다). **확정 2026-10-18(추천 그대로)**: 이 기능의 **마지막 단계**(§5 14 · 2판 — 범위 안이다 · B16 · 「다음 주제」 는 작업 폴더 몫뿐). 목록 = 그 에이전트 백엔드의 모델만(백엔드는 에이전트마다 고정 — 두 백엔드를 한 목록에 섞지 않는다 · B16). 막지도 잠그지도 않고(CLI 가 시작한 값이 미리 선택됨 · 어느 출처 첫 메시지든 그 값 — §1-5), 모델 · 강도 둘 다 첫 메시지 전에 backend 요청으로 세션에 닿게 한다. **claude · codex 각각의 실측 확인이 그 단계의 수용 관문**이고, 안 되면 구현을 멈추고 사용자에게 돌아간다(R35 개정 또는 다른 길) — 칸을 조용히 끄거나 재기동하지 않는다. 이유: 프리셋 없이도 서는 독립 부분이다.
- **T9 codex 압축 뒤 지시 재주입** — **후속으로 뺌 2026-10-18**(사용자 「codex 압축은 나중에 고려하자. 모든 유저 고려하면 넣는게 맞겠지만 후속으로 빼자.」) — 첫 판 제외(지금 프라이밍도 같은 틈 — 압축이 developer 메시지를 버린다 · 실측). 이유: 압축 감지 + `inject_items`(실험 API)라는 별 경로가 필요하다. 덧붙인 실측 항목 = codex `AGENTS.md`(터미널의 `AGENTS.override.md`) · 스킬이 압축 뒤 살아남나(버린다고 잰 것은 developer 메시지뿐 — §6-2).
- **T10 프리셋 claude 원문을 `--settings` 파일 하나에 합치기 = ADR-0109 결정 9(「조각은 `allowedMcpServers` 단일 키」) 대체** — **확정 2026-10-18 = 숨은 설정 없음**(사용자 「프리셋으로 해줘. 사실 감추는 설정이 있으면 안되지.」 — 옛 추천 「`allowedMcpServers` 는 Engram 값이 권위 · 프리셋의 그 키는 버리고 경고」 를 걷음). Engram 조각 `allowedMcpServers:[{serverName:"engram"}]` 은 기본 제공 「기본」 의 claude 원문으로 옮기고(자동 업데이트 끄기 옆 · §1-2), 붙은 프리셋 claude 원문 전부를 붙인 순서로 한 파일에 합쳐 `--settings` 하나로 넘긴다 — 값은 나중 것 · 목록은 합침(보이는 동작 · Engram 우선 규칙 없음 · 합침 규칙 = §3 · 사용자 2026-10-18 「이어붙이기 진행」). 「기본」 을 떼면 Engram 통로도 빠질 수 있어 떼기 확인 문구에 「Engram 메시지 · 제어 통로」 가 더해진다. 두 번째 `--settings` 는 동작이 문서에 없어 거부 그대로(미측). `--mcp-config`(Engram MCP 서버 등록)는 범위 밖 — 실행 인자 그대로다(실행마다 주소 · 토큰을 싣는 인자라 설정이 아니다 — 사용자 확인 2026-10-18).

## 3. 내가 정한 내부 선택 (보고)

- **로컬라이제이션(PRD R49 · 2026-10-16)** — 화면 문자열은 `src/i18n` 키(`t()` · `ko.ts`)로만. 데몬 → 화면 사유 · 상태는 `{code, args}` 꼴(예 `{code:"conflict.skill_name", args:{name, items:[{path, via:[프리셋 경로…]}]}}` — 충돌 줄은 걸린 항목 **전부**를 온 길과 함께 싣는다 · 둘로 못 박지 않는다 · §1-3 5)로 답하고 화면이 `t(code, args)` 로 그린다 — `Resolution` · `LaunchBlocked` · `CONFLICT` 답 · 다시 연결 표시가 해당. CLI 사람용 출력은 지금처럼 한국어(T-64 에서 정책 결정). 기본 제공 프리셋 표시 이름 = 화면 키, 저장 값 = `engram:/…`.

본문에 근거가 있는 것은 자리만 가리킨다.

- **명령 선언 = agent crate 블록 + 포트**(§1-5) — `usage.*` 선례. 데몬 자기 블록 + 표 합성은 거부.
- **웹뷰 → 데몬 버스 왕복을 완성해 쓴다**(§1-7) — 라이브러리용 wire 메시지를 따로 만들지 않는다.
- **실행 전처리 = 예약 뒤 · 세션 파생 앞**(§1-5 (가)) — 에이전트마다 줄 서고, 명부 변경은 mutate 한 번(비교-교체)이라 사이에 바뀐 값을 덮지 않으며, 래치(ADR-0226)와 화신 표식은 맞춰진 프로필만 본다. 막힘도 제어 채널 발급 **앞**에서 끊는다.
- **실행 재료 = `check` → `prepare` + backend `materialize`** · **전용 RAII 가드**(`ProvisionGuard` 와 독립) · **배치 포트 `LaunchFs`**(디스크 없이 backend 배치를 시험).
- **패스스루 인자 = 지금 그대로 `command.extra_args`** — 백엔드가 바뀌지 않으므로 백엔드별로 나눠 둘 까닭이 없다(사용자 2026-10-18 의 귀결 — 옛 `backend_args` · 「`command` 는 해석에서 파생」 · `backend::command_for` 걷음).
- **codex 작업 폴더 생성물 = 에이전트별 목록 + 내용 속 소유 표식** — 표식과 내용이 그대로일 때만 걷고, 떠 있는 동안은 멈춘 뒤로 미룬다(사용자 파일 보호).
- **지침은 파일 하나로 합친다** — `--append-system-prompt-file` 반복 가능 여부를 묻지 않아도 되게.
- **claude `--system-prompt-snapshot off` 는 실 재료에만** — 이어받기가 바뀐 지침을 보게(같은 글이면 캐시 손해 없음 — 실측). `NoopLaunchKits` 의 argv 는 바이트 그대로(회귀 골든).
- **claude settings 합침**(이 규칙은 사용자 결정이 됐다 — 2026-10-18 「이어붙이기 진행」 · T10 · §6-5 닫힘) — 붙인 순서(「기본」 먼저 · 그다음 붙은 프리셋 — §1-3 1)로 객체 = 재귀로 합침 · 목록 = 이어 붙이고 같은 값 하나로 · 그 밖의 값 = 나중 것. 특별 취급하는 키는 없다 — 옛 「`allowedMcpServers` 는 Engram 값이 권위」 는 걷었다(T10 · 숨은 조각 없음). 귀결 = 뒤 프리셋은 「기본」 의 `allowedMcpServers` 에서 `engram` 을 뺄 수 없다(사실상 Engram 통로가 남는다 — 받아들임). claude 몫이다 — codex 의 같은 키 `-c` 줄은 CLI 가 하는 대로이고 재지 않았다(§6-3).
- **옛 `agents.json` = 백업 파일 · 빈 명부**(D4 = 이전 없음의 실행 꼴 — 메인 세션 내부 선택 2026-10-18) — 지우지 않고 비켜 둔다. 판 표식 · 백업 이름은 구현 판단(§1-5 「옛 에이전트」).
- **덮어쓰기 순서** — codex 는 ADR-0216 규율(패스스루 → 프리셋 원문(모델 줄 포함) → Engram, 덮으면 경고) · claude 는 ADR-0094(`--allowedTools` 맨 끝).
- **실행 출처는 진입점이 정한다** — wire `Spawn` · 활성화 = `Interactive` · 버스 `agent.spawn` · 제어 CLI · 부팅 자동 복원 = `Unattended`(물을 사람이 없다). 이번 판엔 결과를 바꾸지 않는다(막힘은 누가 실행하든 같다 — §1-5 포트) — 틀만 두고 다음 주제가 쓴다(§8).
- **다시 연결 = 적용 함수 하나(`relink` — 같은 옛 경로 전부 + 같은 옛 폴더의 나머지) · 훑기 때 후보 찾기 · 색인 · 삭제 기록 없음** — 후보 제안을 걷은 귀결(B11 · 사용자 2026-10-19)로 「찾을 수 없음」 은 지금 `Catalog` 대조로만 판정한다(§1-1 걷음 행 — 이 귀결 판단은 메인 세션 확인 대상). 적용의 참조 고침은 파일 조작(흐름 ④)과 같은 함수.
- **두 판으로 낸다**(B17 · 메인 세션 결정 2026-10-19 — 사용자 위임 「너가 알아서. 급한건 아니니 효율적인 방향으로」) — 1판 = 라이브러리 읽기 · 편집 · 붙이기 · 실행 · 설정 검사 · 막힘 · 「기본」 · 복제 / 2판 = 파일 조작 · 다시 연결 · 끌어 옮기기 · 컬렉션 · 이동 기록 · T8. 이유 = 리뷰 · QA 고리를 작게 · 「프리셋을 붙여 에이전트 실행」 을 먼저 쓴다 · 그동안 파일 조작은 탐색기 · LLM 이 한다. 경계 = §5.
- **에이전트 슬롯 = 편집 부품 + 데이터 훅만 마운트**(B15 · 메인 세션 결정 2026-10-19 — 사용자 위임 「알아서 해 이 부분은」) — 트리 · 목록 · 필터 · react-arborist · 가상 표를 마운트하지 않는다(§1-10).
- **복제 이름 = 「<이름> (2)」 · (3) …**(B13 · 메인 세션 선택 — 사용자 「네이밍은 관행대로」) — R17 새 항목 이름과 같은 번호 규칙 하나로 앱 전체를 맞춘다(탐색기의 「- 복사본」 은 파일 복사 낱말이라 쓰지 않는다).
- **이동 기록 = 최근 1,000 쌍 · 루트마다 `log_id`** — 넘친 커서는 손실을 받아들인다.
- **발췌 만들기 = 데몬 `library` 모듈** — 마크다운 AST 에서 코드 · 표 · HTML · 앞머리를 지우고 글자만(strip-markdown 꼴 · Rust 쪽 파서는 구현 때 고름 — 미측정). `library.list` 행의 지침 설명 칸(「+ 추가」 검색 결과 줄의 한 줄)에 싣는다 — 상세 카드엔 싣지 않는다. 규칙 = PRD R15 · 조사 = docs/research/markdown-plaintext-snippet-survey-2026-10-17.md · docs/research/snippet-vs-rendered-preview-placement-survey-2026-10-17.md.
- **`rev` = 파일 바이트 64비트 해시(std)** — 데몬 프로세스 안에서만 비교 · 해시 crate 를 늘리지 않는다.
- **잠금 = 라이브러리당 `std::sync::RwLock` 하나** — 포트가 동기라 tokio 락이 아니다. 쓰기 잠금 안에서 `ProfileRegistry` 를 부르는 한 방향뿐이라 다른 락과 순환 간선이 없다.
- **기본 제공 참조 = ASCII 고정 id**(`engram:/default` 등) · 표시 이름만 한국어.
- **기본 프리셋 = `default_preset` 불리언** — 따로 보이는 칸이고 순서에 안 낀다. 명령은 `engram:/default` 경로도 받는다.
- **옛 `preset_palette` 슬롯 = 빈 슬롯으로 접기** — 모르는 내용 보존은 걷은 기능을 지키는 장치가 아니다.
- **슬롯 메뉴 서브메뉴 한 단 더(ADR-0065 덧붙임)** — R10 의 「라이브러리 ▸ 1~4」 모양. 평평한 「라이브러리 1~4」는 거부.
- **번호별 보기 상태 = 셸이 권위 · `libraryView.*` 셸 명령** — 그 번호의 슬롯을 가진 창에 쏘고, 선택 요약은 모든 창에(⇐ 원천 — 팝아웃 사이에서도 선다).
- **로컬 OS 동작 = 셸 Rust 가 플러그인 Rust API 로** — 웹뷰 opener 권한을 넓히지 않는다.
- **칸 폭 = 번호별 보기 상태 안 · 기존 `Splitter` 계열** — `react-resizable-panels` 는 들이지 않는다.

## 5. 이행 순서 (커밋마다 빌드 · 시험 초록 — 어디서 멈춰도 선다)

각 단계는 「자료구조를 먼저 갈아엎고 호출부를 나중에」가 아니라 **새 것을 옆에 세우고 → 잇고 → 옛 것을 걷는** 순서다.

**두 판으로 낸다**(B17 · 메인 세션 결정 2026-10-19 — 이유 §3). **1판** = 라이브러리 읽기(트리 · 목록 · 상세 · 필터 · 검색 · 새로 고침 · 번호별 보기 상태 저장) · 새로 만들기(폴더 · 마크다운 · 설정 · 프리셋) · 프리셋 편집 칸(세 길로 추가 · 빼기 · 순서 · 위 문제 목록 · 부품 줄 누름 카드) · 에이전트에 프리셋 붙이기 + 「작업 폴더」 칸 · `agent.setWorkspace` · 실행 때 적용(claude · codex) · 설정 검사 · 막힘 사유 다섯 · 기본 제공 「기본」 · 에이전트 복제. **2판** = 파일 조작(이동 · 이름 바꾸기 · 삭제 → `.trash` · 사람만 하는 비우기) · 다시 연결 · 끌어 옮기기 어디서나 · 컬렉션 · 즐겨찾기 · 이동 기록 · T8 선택 칸. 단축키 · LLM 명령(`library.*` 등)은 그것이 속한 기능의 판을 따른다. 아래 번호는 옛 번호를 지키고(다른 자리가 가리킨다) 판 경계에서 a · b 로 가른다. **1판 끝에서도 빌드 · 시험이 초록이고 1판만으로 쓸 수 있다** — 없는 줄 = 「찾을 수 없음 · ×」(× 로 빼고 다시 추가) · 파일 조작은 탐색기 · LLM 이 한다.

### 6-5. 미결 (사용자 확인 필요)

남은 사용자 미결 없음(2026-10-18). **2026-10-19 결정이 남긴 TRD 몫** — 1~3 은 **메인 세션 제안**(사용자 확인 전 · 이번 반영분과 함께 `/review trd` 가 다시 본다 · 셋 다 2판)이고 4 는 확인 항목이다.

1. **`.trash` 안 자리 · 이름 충돌(B8)** — 제안 = `library.delete` 한 번(한 조작)마다 새 묶음 폴더 `.trash\<UTC 시각>-<짧은 id>\` 를 만들고 그 안에 **원래 라이브러리 경로 그대로** 둔다(예 `.trash\20261019T031500Z-a1b2\지침\리뷰 규칙.md`). 이유 = 묶음이 조작마다 새로라 같은 이름을 두 번 지워도 부딪히지 않고 · 원래 자리가 경로에 남아 되살리기가 「묶음 안 경로 → 같은 경로」 한 번이며 · 따로 된 기록 파일이 없다. 견준 것 = 평평하게 넣고 부딪히면 「(2)」(원래 자리를 잃는다).
2. **사람의 비우기 · 되살리기 화면(B8)** — 제안 = 트리 루트 머리 우클릭 「휴지통 비우기…」(창 전체 모달 — B9 와 같은 꼴 · 지울 묶음 수) + 「휴지통 열기」(셸 `os_reveal` 로 `.trash` 를 OS 탐색기에서 연다 — 되살리기는 사람이 탐색기에서 옮긴 뒤 새로 고침 · 같은 PC 일 때만 — 셸 로컬 요청 규칙). 앱 안 휴지통 보기 · 되살리기 단추는 두지 않는다. 비우기의 전송 = **버스 · `engram` 표에 없는 길** — 셸 → 데몬 wire 메시지 하나(이름 구현 판단)로 §1-8 「라이브러리용 새 wire 메시지는 없다」 의 유일한 예외가 된다. 확인할 것 = 에이전트가 그 wire 에 닿지 못하는가(에이전트는 제어 라우트 CLI 만 쥔다고 본다 — 가능성 높음 · 확인 안 함 · 닿으면 다른 길을 찾는다).
3. **LLM 의 되살리기** — 제안 = 첫 판엔 버스로 열지 않는다(`library.*` 는 `.trash` 아래 경로를 받지 않는다 — 흐름 ④). 에이전트는 데몬 PC 파일 시스템에서 직접 옮기고 `library.refresh` 할 수 있다. 견준 것 = `library.restore {trashPath}` 를 더함(되살리기는 해가 없다는 메인 세션 짐작 — 결정 기록 2026-10-19) — 사용자가 원하면 연다.
4. **다른 창(팝아웃) 사이 끌기가 되는가(B6 · 확인 항목)** — 슬롯이 다른 웹뷰(창)라 한 끌기 체계가 창을 넘지 못할 수 있다(포인터 이벤트로 끄는 dnd-kit 은 창 안 전용일 것 — 가능성 높음 · OS 끌기를 쓰는 react-dnd HTML5 백엔드가 창을 넘는지는 불확실 · 둘 다 재지 않았다). 0a 조사 + 실측으로 가린다. 안 되면 **같은 창 안 슬롯 사이만** 되고 그 사실을 PRD · 화면 문서에 적는다(사용자 확인 2026-10-19).

- (닫힘 2026-10-18) 옛 「§1-3 8 단계 막힘 사유 둘의 갈래가 비어 있다」 — 막힘 사유(그때 여섯 · 2026-10-19 에 다섯)는 한 범주이고 누가 실행하든 막힌다(사용자 2026-10-18 · §1-3 8).
- (닫힘 2026-10-18) **claude settings 합침의 목록 규칙 = 이어 붙인다**(사용자 「이어붙이기 진행」) — 키마다 다른 규칙 없이 하나: 객체 = 재귀로 합침 · 목록 = 붙인 순서로 이어 붙이고 같은 값은 하나로 · 그 밖의 값 = 나중 것. T10 문구는 「값은 나중 것 · 목록은 합침」 이 됐다(§2-2 · §3). 귀결 = 뒤 프리셋이 `allowedMcpServers: []` 를 적어도 「기본」 의 `engram` 이 남는다(사실상 Engram 통로가 남음 — 받아들임). 거부 = 목록을 갈아 끼우기(뒤 프리셋이 목록을 통째로 바꿈). claude 몫이고 codex 의 같은 키 `-c` 동작은 재지 않았다(§6-3).

## 7. ADR 제안 (번호는 `/adr` 가 준다)

1. **프리셋 · 라이브러리 = 데몬 소유 에셋, 클라이언트 요청형** — 라이브러리 폴더 하나 · 프리셋도 그 안의 YAML 파일 · 데몬 `library` 모듈 단독 읽기/쓰기 · 감시 없음. 거부: 셸 훑기 · notify 감시 + 방송 · 프리셋 내부 목록. **ADR-0061 · ADR-0070(프리셋 이름 부분) 폐기.**
2. **참조 = 라이브러리 루트 `/` 경로 + 기본 제공 `engram:/` 네임스페이스** — 거부: 프리셋 파일 기준 상대 · 이름 참조 · ID 파일 · URI 꼴.
3. **실행 재료 포트(`LaunchKitSource`) + backend `materialize`** — 해석은 데몬, 플래그 번역은 backend. 거부: manager 가 프리셋을 해석 · backend 가 라이브러리를 읽음 · `ControlEndpoint` 에 칸 덧붙이기.
4. **claude 실행 재료 = 합친 지침 파일 + `--system-prompt-snapshot off` + `--plugin-dir` 정션 + 합친 `--settings` 하나** — 거부: `--add-dir` 스킬 · 여러 `--settings`.
5. **codex 실행 재료** — JSON = developerInstructions · extraRoots · 이어받기 `additionalContext`(실험) · 터미널 = **늘** 작업 폴더 `AGENTS.override.md` + `.agents\skills\engram-*` 정션(묻지 않는다 · 사용자 2026-10-18). 거부: `CODEX_HOME` 바꾸기 · 로컬 플러그인 설치 · 사용자 폴더면 만들지 묻고 기억(옛 R37 대답 — 2026-10-18 사용자 결정으로 걷음).
6. **편집 = 데몬이 최신 파일에 적용하는 연산 + 판 확인(순서만)** — 거부: 클라이언트 초안 + 저장 단추 · 전부 판 확인.
7. **파일 조작 = 참조 고침 + 일지 롤포워드 · 삭제 = 라이브러리 루트 안 `.trash`(20)** — 거부: 바깥 정리 + 이름 다시 연결만 · 영구 삭제.
8. **다시 연결 = 사용자 · LLM 이 [다시 연결](같은 종류만 · 옛 이름 채움)로 하나를 고른 뒤 나머지 자동(같은 옛 경로 전부 · 같은 옛 폴더의 같은 이름 · 「N개 더 찾아 연결함」) · 훑기 때 후보 제안 없음 · 고르기 전엔 아무것도 잇지 않음**(2026-10-18 관행 · 2026-10-19 개정 B11) — 거부: 이름만 보고 저절로 적용(메모 68 — 사용자가 찾기를 시작하기 전에 이름으로 다시 연결하는 피어가 없다) · 훑기 때 같은 이름 후보 하나를 제안하고 확인 전까지 막힘 「다시 연결 확인 대기」(2026-10-18 D10 의 꼴 — 사용자 2026-10-19 「ㅇㅇ 그게 더 자연스러운것같네」 · 피어는 첫 하나를 손으로 찾게 한다) · 항목마다 하나씩 고르기(관행 = 「N개 더 찾음」) · 리다이렉터 파일 · 루트를 넘는 다시 연결.
9. **이동 기록(번호 붙은 쌍) + 클라이언트 커서 따라잡기** — 클라이언트 소유 컬렉션을 방송 없이 고친다. 거부: 요청한 클라이언트에게만 대응표(다른 클라이언트가 못 따라잡는다) · 데몬이 컬렉션을 소유.
10. (이번 판엔 걷음 — 2026-10-18 사용자 결정의 귀결) 옛 후보 「실행 출처(`Interactive` / `Unattended`)가 대화상자 여부를 정한다 — 버스 · CLI 실행은 기본값을 채워 저장」 — 묻는 대화상자(codex 파일 대답)가 없어지고 막힘은 누가 실행하든 같다(§1-3 8). 다음 주제(경로 없는 에이전트를 실행 때 묻기)가 다시 연다(§8). 번호는 비워 둔다.
11. **백엔드 = 에이전트 값(만들 때 고정 · 바꾸려면 새 에이전트) · 설정 = 백엔드별 원문 칸만(정식 `backend` · `model` 칸 없음 · 모델도 원문 안) · 모델 충돌 검사 없음 · 기본 제공 = 「기본」 하나**(사용자 2026-10-18 — 옛 후보 「기본 제공 백엔드 프리셋은 사용자 백엔드가 있으면 사용할 수 없음 상태가 된다」 를 대체) — 거부: 설정이 백엔드 · 모델을 정함(메모 7 — 둘이면 오류 · 없으면 실행 안 함 · 바꾸면 새 대화) · 기본 제공 백엔드 프리셋(풀 때 양보 · 바꾸기) · `model` 둘 = 충돌(검사하려면 CLI 마다 대조표를 갱신 때마다 고쳐야 한다).
12. **보는 쪽 상태(번호별 보기 · 컬렉션 · 대상 컬렉션)는 셸, 키에 데몬 신원** — 거부: 데몬 · 웹뷰 `localStorage`.
13. **웹뷰 → 데몬 버스 왕복 완성 — 화면과 LLM 이 같은 명령** — 거부: 기능마다 타입 있는 wire 메시지.
14. **서드파티 감싸기 = 목적 포트 · 부품 경계**(walkdir · serde-saphyr → 라이브러리 저장소 · 형식 / 트리 · 목록 · 끌기 · 쿼리 → 우리 부품 한 곳씩) — 거부: 라이브러리마다 1:1 래퍼.
15. **슬롯 메뉴 서브메뉴 두 단(ADR-0065 덧붙임 개정)** — 거부: 평평한 「라이브러리 1~4」.
16. **슬롯 데이터 받기 = TanStack Query 한 파일**(T1 확정 시) — 거부: 손으로 짠 zustand 캐시.
17. **실행 전처리(점검 · 무인 기본값)는 예약 · 떠 있음 확인 뒤, 세션 파생 앞 · 명부 변경은 mutate 한 번(비교-교체)** — 거부: 기동 중간에 맞추기(래치 · 화신 표식이 옛 사본을 본다) · 예약 앞(같은 에이전트 두 실행이 겹친다). (작업 폴더 맞추기 · Engram 폴더 몫 = §8)
18. (걷음 — 2026-10-18 사용자 결정의 귀결) 옛 후보 「패스스루 인자 = 백엔드별 저장(`backend_args`) · `command` 는 해석에서 파생」 — 백엔드가 바뀌지 않아 `command.extra_args` 그대로다(11). 번호는 비워 둔다.
19. **ADR-0109 결정 9 대체 — 숨은 settings 조각 없음 · `allowedMcpServers` 는 기본 제공 「기본」 의 claude 원문 · 붙은 프리셋 claude 원문을 붙인 순서로 `--settings` 파일 하나에 합침(값은 나중 것 · 목록은 합침 — 객체 재귀 · 목록 이어 붙이고 같은 값 하나 · 키마다 다른 규칙 없음 · Engram 우선 규칙 없음)**(T10 · 사용자 2026-10-18) — 거부: 숨겨 주입하는 조각(사용자 「사실 감추는 설정이 있으면 안되지」) · `allowedMcpServers` 는 Engram 값이 권위(옛 추천) · 목록 갈아 끼우기(사용자 「이어붙이기 진행」 — 귀결: 뒤 프리셋이 `engram` 을 못 뺌, 받아들임) · 두 번째 `--settings`(동작 미문서 · 미측) · 원문을 안 싣기. `--mcp-config` 는 범위 밖(실행 인자 그대로).
20. **삭제 = 라이브러리 루트 안 우리 숨은 `.trash` 로 옮김(같은 루트 안 rename · 트리 · 목록 · 검색에서 숨김 · 루트 자체는 못 지움 · LLM · CLI 삭제도 같은 곳)**(B8 · 사용자 2026-10-19 「ㅇㅇ 우리 trash 폴더로해」 · 조사 = `docs/research/trash-unavailable-delete-practice-2026-10-19.md` — 앱 전용 `.trash` 선례 = Obsidian) — 거부: OS 휴지통(platform 의 전용 STA 작업 스레드가 부르는 `IFileOperation` — 2026-10-18 까지의 후보) — 휴지통 대신 말없이 영구 삭제할 수 있고(Microsoft 문서의 `FOF_WANTNUKEWARNING` 「재활용 대신 파괴될 때 경고」 — UI 없이 부르면 그 경고가 묻힌다 · 네트워크 드라이브 · 휴지통 없는 볼륨 · 용량 초과) 비우기를 사람만으로 묶을 수 없다(탐색기 · 다른 도구가 비운다) · `trash` crate(같은 OS 휴지통 길 + 셋째 `windows` 사본 · `CoInitialize` 실패 패닉) · OS 휴지통을 못 쓰면 거절 · 영구 삭제 + 센 확인(VS Code 꼴 — 에이전트 호출엔 답할 사람이 없다).

## 8. 다음 주제(에이전트 트리) — 작업 폴더의 나머지 (사용자 결정 2026-10-16 · 2026-10-18)

**이번 판이 하는 것은 본문에 있다** — 만들 때 폴더 선택(`cwd` 필수 · 지금 그대로) · 에이전트 슬롯 「작업 폴더」 칸(입력 · 찾아보기) · 대화 뒤 · 떠 있는 동안 잠금 · `agent.setWorkspace {agent, cwd}`(§1-5 「작업 폴더 `cwd`」 · §1-7 · §1-10 `WorkspaceField` · D3 확정). **다음 주제 = 에이전트 트리 설계**(사용자 2026-10-18 「에이전트 트리는 다음 주재로 설계할거야. 묶는 폴더도 있어야되고 아까처럼 경로없이 생성이나 뭐 그런것들 다듬어야됨. 지금은 프리셋 실행을 위한 기본 기능만」) — 경로 없이 에이전트 만들기 · 비었으면 실행 때 묻기 · 자동 경로(Engram 폴더 · T4) · codex 파일 전용 폴더 · 묶는 폴더(메모 2026-10-16 의 「폴더를 담은 프리셋(하위 포함)」 도 여기서 다시 본다). 아래는 `/review trd` 3회차까지 본문에 있던 작업 폴더 설계를 옮겨 둔 것이다(조금 줄임) — 다음 주제의 출발점이고 그때 사용자 결정으로 다시 연다(짝 = PRD R34 · R48 · E15 의 워크스페이스 부분). ★「만들 때 폴더를 묻지 않음」 은 TRD 해석이었고 사용자 결정이 아니다★. ★아래 「워크스페이스가 바뀌면 새 대화(`launched_workspace` · `release_session_id`)」 는 이번 판의 「대화 뒤 잠금」 이 대신했다★ — 다음 주제가 대화 뒤에도 바꾸는 길을 열 때만 다시 꺼낸다.

**소유 · 영속(§1-1 · §1-4 에서 뺀 몫)** — Engram 폴더(자동 워크스페이스) 위치 = 데몬 · `daemon\state\library.json`(라이브러리 루트와 같은 파일) · `config.rs` 가 맡는다 · `library.status` 가 그 위치도 싣는다.

**프로필 칸(§1-5 에서 뺀 몫)**
- `workspace: Option<PathBuf>` — 작업 폴더. `None` = 실행 때 정한다(R34 · D3). 디스크에는 옛 키 `cwd` 를 그대로 쓴다(`None` 이면 빈 문자열).
- `launched_workspace: Option<PathBuf>` — 지금 저장된 세션을 만든 실행의 워크스페이스 — 다르면 새 대화(아래 전처리).
- 둘 다 `merge_preserving_live` 보존 칸에 든다.
- 이주 — `workspace = Some(옛 cwd)` · `launched_workspace = Some(옛 cwd)`(지금 세션을 이어받을 수 있게).
- `display_name` 고정의 원래 이유 — 이름이 `cwd` basename 에서 파생되던 길이 워크스페이스(비어 있거나 나중에 Engram 폴더로 채워짐)를 따라 바뀌면 우편 주소 · 트리 이름이 말없이 바뀐다(고정 자체는 이번 판 3 단계에서 한다 — `agent.setWorkspace` 가 생겨서).
- 호환 위험 — 빈 `cwd` 인 에이전트를 옛 빌드가 띄우면 어떻게 되는지는 재지 않았다(아마 실패).

**wire · 화면(§1-7 · §1-8 · §1-10 에서 뺀 몫)**
- `CreateProfile.cwd` 는 선택이 된다(만들 때 폴더를 안 묻는다). wire `AgentProfile.cwd` · `AgentInfo.cwd` · 버스 `AgentRow.cwd` 는 문자열 그대로 두고 **빈 문자열 = 아직 작업 폴더 없음**으로 정한다(칸 모양을 안 바꿔 생성물 · 옛 소비자가 그대로 읽는다). 화면은 빈 값을 「작업 폴더 없음 · 실행 때 정함」으로 그리고, 이름은 고정된 `display_name` 을 쓴다(빈 basename 으로 파생하지 않는다).
- `agent.new` 의 `cwd?` — 없으면 Engram 폴더(R34).
- 트리 판 메뉴 「에이전트 생성 ▸」 — 만들 때 폴더를 묻지 않고, 활성화 전 `agent.launchCheck` → `NeedsWorkspace` 면 「어디서 일할까요?」(확인 창 `WorkspaceAsk`).
- 에이전트 슬롯 「작업 폴더」 칸(이번 판에 있다)에 「작업 폴더 없음 · 실행 때 정함」 과 버스 · CLI 실행이 Engram 폴더를 채웠다는 사실을 더한다(R31).
- 전제(옛 §6-4) — R34 「워크스페이스가 없으면」 은 프로필이 지금 작업 폴더를 필수로 갖는 것(`AgentProfile.cwd` 필수 — 확인함)과 어긋나 위 칸 변경이 먼저다.

**막힘 사유(§1-3 · §1-5 에서 뺀 몫)** — 「워크스페이스 없음(R34)」 = `BlockReason::NeedsWorkspace` — **화면이 낸 실행에서만** 묻고, 버스 · CLI 가 낸 실행은 Engram 폴더로 채워 에이전트에 저장한다(Δg). ★이번 판엔 「화면이 낸 실행에서만」 갈래가 없다★(막힘 사유 다섯은 누가 실행하든 막는다 · codex 파일 대답은 걷었다 — 사용자 2026-10-18) — 이것을 세울 때 그 갈래와 실행 출처(`LaunchOrigin` — 지금은 결과를 안 바꾸는 틀)를 함께 다시 연다(옛 §7 후보 10).

**실행 전처리(§1-5 (가) 에 더해지던 것)**
- 1 점검 — `Unattended` 에서 워크스페이스가 없으면 Engram 폴더를 채운다(3차 델타 — 저장되고 에이전트 슬롯 머리에 보인다).
- 2 맞추기 — 비교-교체 대상에 `workspace` 가 든다(또 바뀌면 「실행 준비 중 프리셋 · 워크스페이스가 계속 바뀌었다 — 다시 시도하라」). mutate 한 번에 `launched_workspace` 도 든다 · `workspace` 는 아직 `None` 일 때만 채운다(그 사이 사람이 정했으면 그 값을 쓴다) · **워크스페이스가 `launched_workspace` 와 다르면** 같은 mutate 안에서 `release_session_id` 와 같은 일을 하고 `launched_workspace` 를 새 값으로 적는다(claude 세션은 작업 폴더에 묶인다). Engram 폴더는 **에이전트 id 로만** 정하고(`<workspaces>\<agent-id>` — 바뀌는 이름을 쓰지 않는다) 있으면 그대로 쓴다(멱등 생성).
- 3 다시 읽기 — 첫 제출 래치(ADR-0226)는 맞춰진 워크스페이스와도 어긋나지 않는 id 만 본다.

**워크스페이스 바꾸기** — 이번 판의 `agent.setWorkspace {agent, cwd}` 는 본문에 있다(대화 뒤 · 떠 있는 동안 `CONFLICT` — §1-5). 다음 주제가 더할 것 = Engram 폴더 만들기 인자(옛 설계 `{agent, path?, engramFolder?}` · R34). 옛 설계의 「바뀐 값은 다음 실행 전처리 2 가 새 대화로 맞춘다」 는 대화 뒤 잠금이 대신했다(위 머리말).

**Engram 폴더 위치(옛 T4 — 추천 그대로)** — 릴리즈 `<배포판>\workspaces\<agent-id>` · 디버그 · `ENGRAM_DATA_DIR` = 데이터 루트 안 `workspaces\<agent-id>`(`DataLayout` 이 낸다 — 라이브러리 `suggested_new` 와 같은 루트 출처 규칙: 릴리즈 기본 = 데이터 루트의 부모 아래 · 그 밖 = 루트 안) · 화면에는 고정된 이름을 보인다. 이유: 이름은 바뀌므로 id 로만 정해야 멱등 생성(있으면 재사용)이 서고, 프로그램 데이터와 작업물을 가르며 시험 격리가 폴더 하나로 된다. 명령 = `workspace.getRoot` · `workspace.setRoot {path}`(새 에이전트에만 — R34). 설정 창이 없으니 첫 판은 명령만이었다(T5 · PRD R34 「Engram 폴더 위치는 설정」 과 어긋남).

**codex 터미널(R37)** — Engram 폴더도 작업 폴더에 `AGENTS.override.md` + `.agents\skills\engram-*` 정션을 깐다(이번 판과 같다 — 이번 판은 늘 깔고 묻지 않는다 · 사용자 2026-10-18).

**시험(§4 에서 뺀 몫)** — 이주 골든 `cwd` → `workspace` · 비교-교체가 그 사이 정해진 `workspace` 를 덮지 않음 · Engram 폴더 = id 로 멱등 · 워크스페이스 바뀜 = `release_session_id` 후 Fresh.

**이행 순서에 끼던 것(§5)** — 3 단계: `cwd` → `workspace`(디스크 키 `cwd` 유지 · 빈 문자열 = 없음) · wire `cwd` 빈 문자열 뜻 · 화면의 빈 작업 폴더 표시 · `None` 이면 지금처럼 스폰 실패(사유 문장). 4 단계: Engram 폴더 id 멱등. 13 ④: 실행 전 대화상자의 워크스페이스.

**ADR 후보(§7 17 에서 뺀 몫)** — 실행 전처리가 워크스페이스도 맞추고 Engram 폴더는 id 로 멱등. 거부: 이름으로 폴더 정하기.
