프리셋 라이브러리 설계

지시서 · 스킬 · 설정을 프리셋으로 묶어 에이전트에 붙이는 기능의 PRD → TRD 요약. TRD 대신 읽도록 흐름과 모듈 · 타입 수준까지만 적었다.

지금 고를 것 — 5절의 D1–D11 · T1–T10. 그중 다툼이 있는 D10, 이전 결정을 바꾸는 D11 · T10 은 메인이 정하지 않았다.

한눈에

지시서(.md) · 스킬(SKILL.md 를 든 폴더) · 설정(.yaml)을 프리셋(.yaml)으로 묶고, 에이전트는 프리셋만 붙인다. 백엔드와 모델은 붙은 설정이 정한다. 부품과 프리셋은 사용자가 고른 라이브러리 폴더 하나에 파일로 산다. 예외는 라이브러리 없이도 에이전트가 돌게 하는 내장 프리셋 셋이다.

데몬권위 · 디스크를 읽고 쓰는 유일한 쪽

  • 라이브러리 루트 · 훑기 · 쓰는 곳 · 다시 잇기 · 파일 조작 · 편집 — 새 library 모듈 하나
  • 에이전트에 붙은 프리셋 · 워크스페이스(agents.json)
  • 실행 재료(휘발 폴더) · 내장 프리셋 셋

셸보는 쪽 상태 · 이 PC 의 것

  • 번호 슬롯 1~4 의 보기 상태 — 권위(state.json)
  • 즐겨찾기 묶음 · ★ 대상 · 옮김 기록 커서 — 데몬 신원별(collections.json)
  • 폴더 고르기 · 기본 프로그램 열기 · 탐색기 보이기 요청

웹뷰그리기만

  • 디스크를 읽지 않는다 — 명령의 답을 그린다
  • 펼침 · 팝오버 · 끄는 중인 칸 폭 같은 휘발 상태만 쥔다
  • engram CLI · LLM 과 같은 명령을 부른다

요청형이다. 데몬은 감시 · 방송을 하지 않는다. 화면은 슬롯 열기 · 포커스 · F5 · 폴더 이동 때 묻고, 그 사이 다른 슬롯이 낡아 보이는 것은 받아들였다.

프리셋 파일 모양 
# Engram 이 고쳐 쓰는 파일입니다 — 손으로 단 주석은 사라집니다.
kind: preset
version: 1
description: PR 리뷰 전용
presets:
  - 공용/기본 규칙.yaml
instructions:
  - 지시서/리뷰 규칙.md
skills:
  - 스킬/리뷰/review
settings:
  - 설정/claude opus.yaml

참조 = 라이브러리 맨 위부터의 / 경로. 설정 · 프리셋은 파일 안 kind 로 가른다(D7). 설정의 정식 칸은 backend · model 뿐, 나머지는 해석하지 않는 백엔드별 원문 칸이다.

내장 프리셋 셋 — 라이브러리 밖 engram:/
engram:/default
「기본」 — Engram 사용 안내(프라이밍) + claude 자동 업데이트 끄기. 만들 때 늘 붙고, 떼면 확인 창이 뜬다.
engram:/backend/claude
「claude 기본」 — backend: claude 하나뿐.
engram:/backend/codex
「codex 기본」 — backend: codex 하나뿐.

읽기 전용 · 에이전트에만 붙는다. 사용자 백엔드 설정이 있으면 내장 백엔드는 「쉼」, 사라지면 다시 깬다. 만드는 길(메뉴 · agent.new · wire · SpawnByCwd · 이주)은 전부 생성자 AgentProfile::new 하나를 지나 기본 + 맞는 내장 백엔드를 얻고 곧바로 돈다.

A라이브러리 슬롯 열기 → 훑기 → 답

  1. 셸「새 콘텐츠 ▸ 라이브러리 ▸ 1」(LLM 은 libraryView.open) → slot.openUnique. 같은 번호 슬롯이 어느 창에든 있으면 거기에 포커스, 없으면 채운다.
  2. 셸그 번호의 보기 상태(폴더 · 기록 · 칸 폭 · 정렬 · 선택)를 library_view 에서 꺼내 그 창에 쏜다. 웹뷰는 그리기용 사본만 쥔다.
  3. 웹뷰libraryQueries → agentClient.callCommand 로 library.status · library.folders · library.list {folder}. 셸은 봉투를 중계만 한다.
  4. 데몬읽기 잠금 → FsStore::scan(루트 전체) → 바뀐 파일만 다시 파싱 → Catalog::build(항목 표 + 쓰는 곳 역색인) → 다시 잇기 후보 찾기(흐름 D) → 그 폴더 바로 안 항목으로 답. 동시 요청은 진행 중인 훑기 하나를 함께 쓴다.
  5. 웹뷰 → 셸같은 계기에 library.moves {since: 커서} → 새 옮김 쌍이 있으면 collection.applyMoves 로 묶음을 고치고 커서를 옮긴다(흐름 C).

루트가 없으면 unset → 빈 트리 안에 [폴더 열기](셸 os_pick_folder → library.setRoot) · [새로 만들기](제안 경로 library\ 를 채운 고르기 → library.setRoot {create:true}). 폴더가 사라졌으면 missing → 「…를 찾을 수 없습니다」.

B프리셋 편집 — 조작을 보내면 데몬이 최신 파일에 적용

  1. 웹뷰프리셋을 누르면 오른쪽 칸이 PresetEditor 가 된다 → preset.get 이 종류별 칸 · 줄 상태 · 충돌/경고 · rev(파일 해시) · 「에이전트 N개가 씀」을 준다.
  2. 웹뷰담기(+ · ⇐ · 「← 선택한 것 담기」) · 빼기 · 순서는 전부 조작 명령 — preset.add · preset.remove · preset.reorder {baseRev}. 저장 단추 · 클라이언트 초안은 없다.
  3. 데몬쓰기 잠금 → 최신 파일 읽기 → 연산 → 원자적 쓰기. add · remove 는 낡은 화면에서 와도 멱등 적용, reorder 만 baseRev 가 다르면 CONFLICT. LLM 이 YAML 을 직접 고친 것도 이 읽기에서 잡힌다.
  4. 데몬이 프리셋을 직접 · 건너서 쓰는 에이전트를 다시 풀어 백엔드가 바뀌는 에이전트를 답에 싣는다. 여러 개 담기는 부분 적용 {added, skipped}.
  5. 웹뷰답으로 쿼리 데이터를 바로 바꾼다. CONFLICT 면 다시 받고 「다른 곳에서 바뀌어 새로 불러왔습니다」 · 백엔드가 바뀌면 「에이전트 N개가 다음 실행에서 새 대화로 시작합니다」.
해석은 한 함수다. 편집 칸의 충돌 · 경고, 「에이전트 N개가 씀」, 실행 재료를 모두 순수 함수 library::resolve 가 만든다. 규칙: [기본] → 붙은 프리셋 순서로 펼치고 안에 든 프리셋을 먼저(D1) · 같은 것은 한 번 · 순환은 오류 · 사용자 백엔드가 있으면 내장 백엔드는 쉼 · 충돌 = 사용자 백엔드 둘, 같은 이름 스킬 둘, model 둘(T3).

C옮기기 · 이름 바꾸기 · 지우기 — 참조까지 같은 조작 안에서

  1. 웹뷰목록에서 트리로 끌어 놓기 또는 우클릭 「이름 바꾸기」 → library.move · library.rename. CLI · LLM 도 같은 명령이다.
  2. 데몬library::ops 가 쓰기 잠금 아래 계획(옛 → 새 대응표 · 고칠 프리셋 파일 · 고칠 에이전트 · 옮김 기록 번호)을 세워 일지 파일에 먼저 쓴다.
  3. 데몬디스크 이름 바꾸기 → 프리셋 파일마다 경로 줄 고쳐 원자적 쓰기 → 에이전트 붙임 고치기 → 색인 · 옮김 기록 갱신 → 일지 지움.
  4. 데몬중간에 죽으면 다음 부팅의 OpJournal 이 단계별로 판정해 이어서 돈다. 진짜 원자성이 아니라 멱등 롤포워드다.
  5. 클라이언트묶음은 셸 것이라 데몬이 고치지 않는다. 각 클라이언트가 다음 요청 때 library.moves → collection.applyMoves(멱등). 방송 없이 누가 옮겨도 따라간다.

지우기는 library.delete → OS 휴지통. 쓰는 곳이 있으면 yes 없이 CONFLICT 로 그 목록을 돌려주고 화면은 확인 창을 띄운다. 지운 경로는 기록해 흐름 D 의 자동 다시 잇기를 막는다. 옮김 기록은 최근 1,000 쌍 — 그보다 오래 못 따라잡은 클라이언트의 묶음 항목은 「찾을 수 없음」으로 남는다(받아들인 손실).

D바깥 변경 · 다시 잇기 — D10 이 걸린 곳

  1. 데몬훑기마다 직전 색인과 비교해 「바깥에서 없어진 것」(직전엔 있었고 · Engram 이 지우지 않았고 · 지금 없음)을 찾는다.
  2. 데몬새로 나타난 항목 중 같은 종류 + 같은 이름이 정확히 하나일 때만 후보 RelinkCandidate 가 생긴다. 둘 이상이거나 없으면 「찾을 수 없음 · 다시 잇기」로 사람이 고른다. 라이브러리 루트를 바꾼 뒤에는 후보가 없다.
  3. 데몬적용은 상수 RelinkMode 하나로 갈린다. Auto = 프리셋 줄 · 에이전트 붙임을 바로 새 경로로 고치고 「다시 이어짐 · 원래 <경로>」 표시(실행 안 막음). Confirm = 참조는 옛 경로 그대로, 실행은 「다시 잇기 확인 대기」로 막히고 화면 「다시 이어짐? · [확인]」 → library.relink.
  4. 데몬적용된 쌍은 옮김 기록에 쌓여 흐름 C 의 5 처럼 묶음까지 따라간다.

E에이전트 실행 — 세션을 만들기 전에 점검 · 맞추기

  1. 진입점실행 출처가 정해진다 — wire Spawn · 활성화 = Interactive · 버스 agent.spawn · 제어 CLI · 자동 복원 = Unattended. 화면은 먼저 agent.launchCheck 로 사유를 받아 「어디서 일할까요?」 · codex 파일 질문을 띄운다.
  2. agentAgentManager 가 SpawnReservation 예약과 「이미 떠 있음」 확인을 먼저 한다(id 만 읽는다) — 그래서 전처리가 에이전트마다 줄 선다.
  3. agent전처리 0 = ensure_registered — 명부에 없는 id(wire SpawnByCwd · 스모크 bin)를 먼저 넣는다(용량 검사 · 이름 배정). 그래서 전처리는 늘 명부에 있는 항목을 고친다.
  4. agentkits.check(명부에서 읽은 프로필, origin) → LaunchPlan 또는 LaunchBlocked. 호출자가 넘긴 사본이 아니라 명부 값을 본다. 막히면 제어 채널을 열기 전에 끊는다.
  5. agent맞추기 = 명부 mutate 한 번(비교-교체). 읽은 뒤 프리셋 · 기본 · 워크스페이스가 안 바뀌었을 때만 적용하고, 바뀌었으면 한 번 다시, 또 바뀌면 「다시 시도하라」로 끊는다. 그 안에서 맞춰진 명령 변형(backend::command_for) · Unattended 기본값(Engram 폴더 · 「안 만듦 · 프라이밍만」) · launched_workspace 를 적고, 백엔드나 워크스페이스가 바뀌었으면 세션을 놓아 새 대화로 간다. Engram 폴더 = <workspaces>\<agent-id>, 있으면 재사용.
  6. agentmutate 가 돌려준 명부 값에서 화신 표식 · 세션 id · 모드를 파생한다 — 첫 제출 래치가 맞춰진 프로필만 보게.
  7. 데몬제어 채널 발급 뒤 kits.prepare — 휘발 폴더 daemon\run\launch\<id>-<epoch>\ 에 합친 지시서(프라이밍 + 프리셋 순서) · 스킬 링크 · 합친 claude settings. LaunchKitGuard 가 어디서 실패하든 걷는다.
  8. backendbackend::materialize — 백엔드만 아는 디스크 배치(포트 LaunchFs 로만 씀) → LaunchArtifacts → 명령 조립이 아래 표의 플래그로 옮긴다.
  9. 데몬회수(reaper · kill) 때 kits.release 가 휘발 폴더를 지운다. 부팅 때 남은 것도 쓸어 낸다.

JSON 모델 · 강도 고르기(T8 · 마지막 단계) — 둘 다 첫 메시지 전에 backend 요청으로 세션에 닿게 한다(claude = control request · codex = 첫 turn/start 덮어쓰기). claude · codex 각각의 실측이 그 단계의 수용 관문이고, 하나라도 안 되면 멈추고 사용자에게 돌아간다 — 칸을 끄거나 재기동으로 대신하지 않는다.

NoopLaunchKits(기본)는 오늘과 바이트 같은 argv — 8 단계 전까지의 회귀 골든이고, SpawnByCwd · 스모크 bin 길도 골든에 넣는다. 라이브러리 잠금이 동기라 tokio 워커에서 spawn 을 부르던 wire SpawnByCwd 는 spawn_blocking 으로 옮긴다.

FLLM 제어 — 화면 단추와 같은 명령

  1. agent어휘(library.* · preset.* · agent.attachPreset 등)는 agent crate 의 declare_commands! 블록에 선언하고, 본문은 데몬 LibraryService 가 포트 LibraryCommandHost 뒤에서 구현한다(usage.* 선례).
  2. CLILLM 은 engram <이름> --인자 값 으로 부른다. CLI 는 데몬의 런타임 명령 표를 읽어 코드가 바뀌지 않는다.
  3. 데몬사람 확인이 낀 조작(쓰이는 항목 지우기 · 기본 프리셋 떼기)은 --yes 없이 쓰는 곳 · 이유를 돌려주며 CONFLICT. 화면 단추는 확인 창 뒤 yes=true 로 같은 명령을 부른다.
  4. 셸보기 상태 · 묶음은 셸 명령 — libraryView.* · collection.* · slot.openUnique · agentPresets.open. 셸이 데몬에 붙어 있을 때 버스로 닿는다. 새 전역 핸들은 없다.
  5. 프라이밍에이전트 규칙 — 파일 내용은 직접 고치고, 옮기기 · 이름 바꾸기 · 지우기는 engram 명령으로(참조가 함께 고쳐지게). library.read 가 절대 경로를 준다.

결정 대기

추천 = 그대로 두면 가는 값. D 쪽은 바뀌어도 대부분 고칠 자리가 한 곳이다.

PRD — D1–D11

D1안에 든 프리셋의 지시서는 자기 지시서의 앞인가 뒤인가추천앞 — 공용 규칙 위에 자기 규칙을 얹는 모양이다.
D2프리셋 칸도 끌어서 순서를 바꾸나추천허용 — 프리셋 순서가 그 안 지시서 · 설정의 이어 붙는 순서를 정한다.
D3워크스페이스의 자리추천에이전트 값으로만. 에이전트 슬롯 머리에서 보고 바꾼다 — 라이브러리 종류를 늘리지 않는다.
D4라이브러리 전에 도는 첫 에이전트(E7 확인)이전 결정에 닿음추천내장 프리셋 셋 · 생성 메뉴 유지 · 만들 때 기본 + 내장 백엔드 부착 · 기존 에이전트 이전. 대안 = 이름 없는 부품을 에이전트에 직접.
D5JSON / 터미널 모드를 어디서 정하나추천지금처럼 만들 때 고르는 에이전트 값.
D6강도(effort)의 자리추천백엔드 원문 칸 — 정식 칸을 backend · model 로 묶은 결정을 지킨다.
D7설정과 프리셋 .yaml 을 무엇으로 가르나 · 칸 제목 폴더 돋보기의 대상추천파일 안 kind 표식 · 돋보기는 다른 라이브러리 슬롯의 필터를 그 종류로 — 폴더 이름에 기대면 옮기기가 종류를 바꾼다.
D8뗀 내장 프리셋을 다시 붙이는 길추천+ 검색 맨 위 「내장」 묶음에 더해, 기본 프리셋은 빈 「기본」 칸에서도 다시 붙인다.
D9세션 해석 넷 — 에이전트 슬롯 = 트리 · 목록 숨긴 편집 칸 · 기본은 붙고 뗄 수 있음 · JSON 첫 선택은 그 세션뿐 · 「한 개 폴더」 = 라이브러리 하나추천넷 다 그대로.
D10이름만 맞는 다시 잇기 후보를 저절로 쓸까, 확인 한 번 뒤에 쓸까다툼추천 없음이전 사용자 결정(메모 68) = 저절로 + 표시. 리뷰어(codex) = 확인 한 번 — 잘못 이은 것이 누가 보기 전에 실행될 수 있다. 확인 쪽 대가 = 바깥 정리 때마다 누름이 는다. TRD 는 두 길을 상수 RelinkMode 하나로 다 설계했다.
D11상세 패널이 창 밖으로 통째 나갈 때(팝아웃 창 · 창을 채운 오른쪽 끝 슬롯)사용자 결정 일부 바꿈추천통째 밖일 때만 슬롯 안쪽으로 겹친다(일부 잘림은 결정대로). 메모 137 「안쪽 대체 없음」을 이 한 경우만 바꾼다. 대안 = 그대로.

TRD — T1–T10

T1슬롯 데이터 받기추천TanStack Query 를 한 파일에 가둔다. 예정한 /research 는 아직 안 돌렸다.
T2프리셋 파일의 손 주석추천고칠 때 사라짐을 받아들이고 머리 주석으로 알린다. 메모는 description 칸에.
T3model 칸이 둘 이상이면추천충돌 — 나중 것이 이기면 어느 모델인지 화면에 안 보인다.
T4Engram 폴더(자동 워크스페이스) 기본 위치추천릴리즈 <배포판>\workspaces\<agent-id> · 디버그와 ENGRAM_DATA_DIR = 데이터 루트 안 workspaces\<agent-id>. 이름은 바뀌므로 id 로만 정해야 있으면 재사용(멱등)이 선다. 화면엔 고정된 이름을 보인다.
T5설정 창이 코드에 없다추천첫 판은 트리 머리 메뉴와 명령만. 설정 창은 별 작업.
T6codex JSON 이어받기에서 바뀐 지시서추천지시서 해시가 바뀐 때만 첫 턴 additionalContext(실험 API). 대안 = 새 대화까지 미반영 + 경고.
T7claude 스킬 싣는 길추천--plugin-dir(이름 engram:review). --add-dir 은 이름이 겹치면 승자를 모른다.
T8JSON 모드 모델 · 강도 고르는 칸(코드에 없음)멈춤 조건추천마지막 단계(14) · 막지 않고 미리 골라진 채. 모델 · 강도 둘 다 첫 메시지 전에 backend 요청으로. claude · codex 각각의 실측이 수용 관문이고, 안 되면 멈추고 사용자에게 돌아온다(R35 개정 또는 다른 길) — 칸 끄기 · 재기동은 없다.
T9codex 압축 뒤 지시 재주입추천첫 판 제외 — 지금 프라이밍도 같은 틈이 있다.
T10프리셋 claude 원문을 --settings 파일 하나에 합친다ADR-0109 결정 9 대체추천합치되 allowedMcpServers 는 Engram 값이 권위(프리셋 값은 버리고 경고). 두 번째 --settings 는 동작이 문서에 없어 거부.

PRD 기본값 E1–E19 는 메인이 정했고 바꿀 수 있다. 그중 이전 사용자 결정에 닿는 것 = E7 · E8 · E9 · E10 · E11 · E15 · E18(PRD §5-2).
