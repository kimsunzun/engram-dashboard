1프리셋 안의 경로 = 라이브러리 폴더 맨 위부터 / 로 (한 가지 꼴 · 범위 제한 없음) · 칸 = 종류별 목록 넷 · 설정과 프리셋은 파일 안 kind 로 가름(결정 대기 D7) 2스킬은 여러 프리셋이 나눠 씀 → 프리셋 옆이 아니라 라이브러리 어디든 3자동으로 만들지 않는다 — 처음에 [폴더 열기]로 고르거나 [새로 만들기]. 새로 만들기는 고르기 창에 경로만 미리 채움 = 배포판 폴더 안 library\ (data\ 옆) · 고르면 빈 폴더를 만듦 — 안의 폴더는 사용자가 만든 예(정해진 종류 폴더 없음) 4zip 을 덮어 풀어도 남음 (같은 이름 파일만 덮임)

확정내장 프리셋은 라이브러리 밖 — engram:/default · engram:/backend/claude · engram:/backend/codex · 라이브러리 프리셋 파일에 적으면 그 줄이 「오류」

확정처음 = 슬롯의 빈 트리 안에 「아직 라이브러리 폴더를 고르지 않았습니다.」 + [폴더 열기] [새로 만들기] · 고른 폴더가 없어지면 같은 자리에 「<경로>를 찾을 수 없습니다」 + 같은 단추(설정 값은 둠)

확정폴더 바꾸기 = 트리 맨 위 머리(이름 + 경로) → 「라이브러리 폴더 바꾸기…」 → 폴더 고르기(같은 PC) · LLM = library.setRoot · 바꾼 뒤 참조는 새 루트에서 경로 그대로 풀림 — 같은 경로가 있으면 그대로 쓰고(내용이 달라도) 없으면 「찾을 수 없음 · 다시 잇기」 · 루트를 넘는 다시 잇기 후보 없음

결정 대기 T5설정 창이 코드에 없음 — 첫 판은 트리 머리 메뉴 · 명령(library.setRoot · workspace.setRoot · settings.set)만이 추천

범위 밖배포판에 라이브러리 내용을 싣지 않음 — 실을 계획이 생기면 그때 「사용자가 고친 같은 이름 파일이 덮이는」 문제를 다시 연다

프리셋 편집 — 조작을 보내면 데몬이 최신 파일에 적용
