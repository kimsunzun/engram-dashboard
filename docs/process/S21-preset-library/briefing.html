LLM 이 YAML 을 직접 고친 것도 ② 에서 잡힌다. 순서 바꾸기가 낡은 화면에서 오면 거절 → 그 화면이 새로 받고 「다른 곳에서 바뀌어 새로 불러왔습니다」. ⑤ 의 새 상태엔 충돌 줄(걸린 항목 전부 · 온 길)과 「에이전트 N개에서 참조 중」 만 실린다 — 경고는 없다(2026-10-18 · 참조하는 에이전트를 다시 풀던 단계도 걷었다). 편집은 에이전트의 백엔드를 바꾸지 않는다 — 백엔드는 에이전트 값(만들 때 고정 · 2026-10-18). ④ 의 쓰기는 손 주석을 지킨다(T2 — yaml-edit 스파이크가 첫 구현 단계 · 안 되면 「잃음 받아들임」 으로 돌아가 보고).

18

이동 · 이름 바꾸기 — 참조까지 한 조작 안에서

중간에 죽으면 다음 부팅에 일지를 보고 이어서 마친다. 삭제는 OS 휴지통 — 참조가 있으면 확인 창(CLI = --yes 없으면 거절) · 삭제한 경로는 기록해 두어 같은 이름 후보로도 내지 않는다 · 바깥에서 옮긴 것은 저절로 잇지 않고 「찾을 수 없음 — 후보 [연결]」 로 제안만 한다(D10 · §4 · 2026-10-18).
