### 2-2. Pure core — `followCore.ts` (DOM 0)

```ts
export const FOLLOW_THRESHOLD_PX = 48 // [고름] 피어 범위 40–64 의 가운데(t3code 40 · paseo 64)
export interface Metrics { top: number; height: number; client: number } // scrollTop · scrollHeight · clientHeight
export interface FollowState {
  pinned: boolean
  frozen: boolean            // client === 0 (display:none 탭) — 재는 값이 무효
  lastTop: number            // 마지막으로 본 scrollTop
  expectTop: number | null   // 우리가 쓰고 아직 이벤트로 못 본 값
  savedTop: number | null    // 얼 때 적은 scrollTop — 풀릴 때 되살린다. 처음·풀린 뒤 = null
  unseenGrowth: boolean      // 떨어진 동안 내용이 자랐다(U3 대안용)
}
export type FollowInput =
  | { type: 'attach'; m: Metrics }   // 뷰포트 노드가 (다시) 붙었다
  | { type: 'scroll'; m: Metrics }   // scroll 이벤트
  | { type: 'resize'; m: Metrics }   // 내용·뷰포트 ResizeObserver
  | { type: 'intentUp'; m: Metrics } // 위로 가는 사용자 입력(§2-3)
  | { type: 'pin' }                  // 비우기 · 버튼 · 보냄 · LLM
  | { type: 'unpin' }                // F3 묶음 펼침(§4-5)
export function step(s: FollowState, i: FollowInput): { state: FollowState; scrollTo: number | null }
```

Rules (this table is the test table):

1. **Freeze**: when `m.client === 0` arrives in a state that is not frozen (on any of the four inputs that carry measured values), `frozen = true` · **`savedTop = expectTop ?? lastTop`** (the `m.top` of that moment may already be invalid, so we record the last validly seen value) · `scrollTo = null`. While frozen, `scroll`·`resize`·`attach`·`intentUp` change no field (except the thaw in rule 2). `pin`·`unpin` change only pinning even while frozen (applied on thaw · the `unseenGrowth` that `pin` also lowers is rule 10).
2. **Thaw** (`resize`·`attach` when `frozen` and `m.client > 0`): `frozen = false` · `lastTop = m.top` · `expectTop = null` (the events of writes before hiding were discarded while frozen and the position was re-measured). If pinned, write the bottom. If not pinned, write `savedTop` only when `savedTop !== null` and `m.top` differs from `savedTop` (the 0.5 px width of rule 7) (if `null`, do not write) — we do not know whether `scrollTop` is preserved across `display:none` (research §1-1), so restoring is always attempted (if preserved, it is a no-op). At the end `savedTop = null`.
3. **Our own writes never unpin**: if the `m.top` of a `scroll` is within 1px of `expectTop`, only move `lastTop` and set `expectTop = null`.
4. **User scroll**: any other `scroll` — distance from the bottom `d = height − top − client`. At the end always `lastTop = top` · `expectTop = null` (the browser merges one frame's position changes into one event — if the user moved after our write, that write's event does not arrive separately).
   - While pinned: if `d > 문턱` and `top < lastTop` (moved up) → `pinned = false`. Otherwise → unchanged (an upward move within the threshold may be a clamp from content shrinking — do not unpin).
   - **While not pinned = upward-intent latch**: re-pinning happens **only** on a `scroll` that **moved down (`top > lastTop`) and entered the threshold** — `pinned = true` · `unseenGrowth = false`. Up · in place · down but outside the threshold all stay unpinned. ★This latch exists so that after a small upward wheel within the threshold is unpinned by rule 5, the `scroll` that wheel produces (up · within the threshold) does not immediately re-pin★. The only other ways to release the latch are an explicit `pin` (button · send U4 · clear · command).
5. **Upward input** (`intentUp`): if `height > client` (there is something to scroll), `pinned = false`. Even a small wheel within the threshold unpins immediately — otherwise growth would drag it down (re-pinning is blocked by the latch in rule 4).
6. **Growth** (`resize`): ★do not re-measure pinning★ (research §1-3 — if re-measured, streaming growth would be read as 「위로 올렸다」). If pinned, `scrollTo = max(0, height − client)`. If not pinned, `unseenGrowth = true`.
7. **Write notice**: a write is emitted only when `|m.top − 목표| > 0.5` — then `expectTop = scrollTo` · **`lastTop = scrollTo`**. Within 0.5 px it is already there, so `scrollTo = null` (neither a write nor a notice) — no event arrives, so leaving the notice would misread a later user scroll as ours. `lastTop` is moved to where the write will land because of the case where the user drags up before the write's event arrives: the two arrive merged as one event, and with the old position as the reference, 「위로」 would not be read, so it would stay pinned and the next growth would drag it back down. The write's own event is recognized separately by `expectTop` (rule 3).
8. Initial state = `pinned: true` · `frozen: false` · `lastTop: 0` · `expectTop: null` · `savedTop: null` · `unseenGrowth: false`.
9. **New node** (`attach` · not frozen and `m.client > 0`): `lastTop = m.top` · `expectTop = null` (the event of a position written to the old node does not arrive at the new node). If pinned, write the bottom; if not pinned, do not write.
10. **`pin` · `unpin`**: `pin` = `pinned = true` · `unseenGrowth = false` (even while frozen — invariant `pinned ⇒ !unseenGrowth`). `unpin` = only `pinned = false`. Neither carries measured values, so `scrollTo = null` — the bottom write is emitted by the hook feeding one `resize` (the current measured values) after `pin`, via rule 6 (if frozen, rule 1 blocks it and rule 2 writes on thaw).

### 3-4. claude JSON interrupt (U1) — design

**Control line**: `{"type":"control_request","request_id":"interrupt:<uuid v4>","request":{"subtype":"interrupt"}}\n` — the shape is from the official Agent SDK (research §2-1). It is serialized with a typed struct like `cancel_line` (`claude/mod.rs:698-724`). ★An optional capability like `cancel_queued` is not carried★ — the meaning we want is the same as codex: **only the running turn stops, and the waiting input already received goes to the next turn** (ADR-0235 decision 4 — `Interrupted` does not set a stop · decision 5 — the remaining text goes in the next single turn). Whether that is the meaning of the CLI response's `still_queued` (the list of waiting messages that will still run after the interrupt) is confirmed by the spike (§3-5 S3).

**How the line reaches the path** — ① (main session accepted): the instruction was 「`cancel_async_message` 가 닿는 길을 따라 하라」. That way is `MidTurnPolicy::SessionClassified { cancel_line }` (`types.rs:215`), where the session does `send_input` inside the input lock (`session.rs:563-580`). Interrupt does not fit that way: ① the capability `control.interrupt` comes from the **path's caps** (`session.rs:656-657` → `stdio.rs:425-455`) ② interrupt is not tied to an input id, so there is no order for the input lock to guard. So we use **the same shape as the `structured` injection** (`stdio.rs:52-56` — the backend injects 「구조화냐」):

```rust
// transport/stdio.rs — 통로는 이 바이트의 뜻을 모른다(바보 파이프 유지)
/// `None` = 「지금은 끊을 턴이 없다」(backend 가 판정) — 통로는 그대로 `Unsupported` 로 옮긴다.
pub type InterruptLine = Arc<dyn Fn() -> Option<Vec<u8>> + Send + Sync>;
impl StdioTransport {
    /// 「지금 턴을 멈춰 달라」는 줄을 만드는 backend 함수를 꽂는다. 없으면 오늘처럼 `Unsupported`.
    pub fn with_interrupt(mut self, line: InterruptLine) -> Self { self.interrupt = Some(line); self }
}
// interrupt(): Some(f) => match f() { Some(b) => self.input.push(b) · None => Unsupported("끊을 턴이 없다") }
//              · None => 오늘의 Unsupported(`:371-376`)
// capabilities(): control.interrupt = self.interrupt.is_some()(`:441`) — 능력은 「끊을 수 있는 통로」이지 「지금 턴이 있다」가 아니다
```

- [고름] `open` is not given more arguments and a builder is used instead — there are 9 `StdioTransport::open(` call sites including tests (`rg "StdioTransport::open\(" crates`). The existing assertions (`stdio.rs:507` · `session.rs:1249` — a path without injection is `Unsupported`·`false`) remain true.
- The line goes into the input queue (`stdio.rs:46-47` — one writer thread) and is serialized **as a whole** with user lines (no line mixing). It does not take the input lock (`input_order`) — there is no new edge in the lock-order invariant (ADR-0006).
- `backend/claude/mod.rs` `open_spawn` (`:424-433`): `open` returns a tuple `(StdioTransport, Option<u32>)` (`stdio.rs:72-76`) — unpack it, then plug in: `let (t, pid) = StdioTransport::open(spec, true, Some(decoder))?; let t = t.with_interrupt(interrupt_line(Arc::clone(&turn_gate)));`. Claude knowledge (line shape · turn-open decision) lives only in `backend/claude` (「백엔드 확장」).
- The response `control_response` (`request_id` prefix `interrupt:`) is **not translated** — `cancel_response_event` (`:1215-1235`) looks only at the `cancel:` prefix, so it is already `None`. A response arriving does not mean the turn stopped (§3-5 S4).

**Turn-open gate** — codex refuses an interrupt when there is no turn (`backend/codex/transport.rs:4045-4061` — `Unsupported("… 중단할 턴이 없다")`). claude follows the same bus contract (§3-3 mapping = CONFLICT):

- **The setting side = the live decoder**: if one live line emits even one turn-progress signal event (`classify_turn` `:538-545` → `Progress` — the user echo `Structured{user}` · an `assistant` block · a streamed `TextDelta` · the `Delivered` of `command_lifecycle` `started`), `open = true`. **`open = false` at `result`** (after today's translation). - **The reading side = the interrupt-line function**: if `open`, `Some(줄)` (also `interrupt_sent = true` in the ④ fallback), otherwise `None` → path `Unsupported` → bus CONFLICT · WS `Interrupt` is an error response (`connection_core.rs:1222-1230`). ③ is resolved by this (main-session decision) — an Esc before the turn opens is honestly refused as a no-op, and no deferring queue is kept. ★But if S4 shows 「되울림이 `system/init` 보다 먼저 오고 그 틈의 끊기는 무시된다」, the point where the gate opens is delayed to **the first progress line after that turn's `system/init`**★ (same value · same refusal — only the opening line changes).
- ★**Residual race — narrowed, not closed**★: if that turn's `result` comes out between reading the gate and putting the line in the queue, or before the line reaches the CLI, and **the CLI opens the next turn by itself** (B was waiting · a turn carried by mail), that line interrupts the **next turn**. **Classification of the interrupted turn's `result`** — the current translator (`:944-970`) emits `Error(RESULT_FAILURE_DETAIL…)` if `is_error || subtype.starts_with("error")`. ### 5-2. Translator state · rules

One field in `ClaudeStreamDecoder` (`:768-794`) — [고름] with the same lifetime as the line buffer (one incarnation):

```rust
/// 라이브 부분 메시지 추적 — `stream_event` 가 채우고 완결 `assistant` 줄이 읽는다.
#[derive(Debug, Default)]
struct PartialMessage {
    /// 지금 메시지의 id(`message_start`). `None` = 추적 중인 메시지가 없다.
    id: Option<String>,
    /// 시작했고 아직 멈추지 않은 블록 번호(`content_block_start` ~ `content_block_stop`).

    /// 글 델타를 하나라도 흘린 블록 번호들.
    streamed: BTreeSet<u64>,

```

`consume_line` (`:882-1005`) takes one more argument: `partial: Option<&mut PartialMessage>` — live (`decode` `:836-840` · `flush` `:865`) passes `Some(&mut self.partial)`, resume (`parse_transcript_events` `:1351`) passes `None`.

| Line | Rule |
|---|---|
| `stream_event` + `parent_tool_use_id` is not null | **discard wholesale** (including `message_start` — so a sub-agent's flow does not overwrite the parent's state · research §4-2) |
| `message_start` | `*partial = { id: message.id, open: None, streamed: {} }` — a new message opened by input folded in mid-turn also starts fresh here |
| `content_block_start{index}` | `open = Some(index)` |
| `content_block_delta{index, delta:{type:"text_delta", text}}` | if `id` exists and `text` is not empty, `TextDelta{text, turn_id: None, message_id: id.clone()}` · `streamed.insert(index)` · if there is no `id` (a late delta that came without `message_start`) **discard** |
| other deltas (`thinking_delta` · `input_json_delta` · `signature_delta`) | discard — thinking · tools come from the completed line as today |
| `content_block_stop{index}` | if `open == Some(index)`, `open = None` |
| `message_delta` · `message_stop` · unknown `event.type` | emit nothing — ★`MessageDone`/`TurnEnd`/`Structured` forbidden★ (§5-3) |
| completed `assistant` line | if `message.id == partial.id` and `open = Some(k)` and `streamed ∋ k`, then **only the `text` block** of that line does not emit `TextDelta`. | `result` | after today's translation, `*partial = PartialMessage::default()` |

- **Why 「(메시지 id, 블록 번호)」 is taken as the open block** [고름]: a completed line has no block number. The contract is 「비지 않은 블록마다 완결 메시지 하나, 그 블록의 `content_block_stop` 보다 먼저」 (research §4-2 — measured + official docs = certain). So the block open at the moment a completed line arrives is that line's block. An empty block (stops with no completed line) takes no slot. If the vendor changes the order (completed after stop), `open` is empty and **it emits the full text as today — it overlaps rather than loses** (it errs toward visible).
- **By default, no merging** (the same as codex — research §4-4). But if the numeric threshold of §9 ring pressure is exceeded, merge inside B1 (§9).
- Doc update: fix `:762-767` (「decoder 자신의 상태 = 줄 재조립뿐」) for this field.

### 5-3. Invariants

- **The turn end stays the single `result` line** (research §4-4 trap) — if `message_stop` were moved to the end, the turn would end at every tool call.
- **Do not emit stream-attached lines as `Structured`** — the claude turn classifier counts every `Structured` as progress except the interruption marker (`kind:"interrupted"` — ADR-0243) (`classify_turn`). ## 9. Risks · known limits

- **F1 content node = Radix's first child**: if Radix changes the wrapper structure, growth is not seen (the viewport RO keeps running). Symptom = streaming does not stick to the bottom → the hook test leaves a warning for the absence of the first child. The alternative (passing a content ref down) needs changes to both slots.
- **F4 ring pressure**: with token-level `TextDelta`, the ring (`REPLAY_MAX_EVENTS = 4096` — `output_core.rs:1291`) fills faster → the early history of a long conversation is pushed out of replay sooner. ★Numeric exit threshold★: if the number of streamed deltas in one long-answer turn (≥ 2,000 characters) of the B1 capture (§5-4 ring pressure record) **exceeds 10 % of `REPLAY_MAX_EVENTS` (≈ 410)**, build merging inside B1 — join adjacent `TextDelta`s with the same `message_id` inside the event list that one `decode()` call returns (backend only · seq is assigned at emit so no holes appear · test 14). If not exceeded, merging stays as a follow-up (research §4-4). The decision number is put in B1's return.
- **F4 render cost**: `setItems` per delta (`RichSlot.tsx:215`) + F1 RO. codex already takes the same path today.
- **F4 late completed line = two copies** (B1 review): if a completed `assistant` line comes after that block's `content_block_stop` (a vendor contract violation — §5-2), the text comes out twice. It is intended behavior (「잃기보다 겹친다」 — a completed line has no block number, and tail comparison was rejected by ADR-0240). The test `a_text_block_that_was_not_streamed_falls_back_to_the_completed_text` (the complete-after-stop branch) pins it.
- **F4 streamed text cannot be taken back** (B1 review): if the CLI retries a failed stream or falls back to a non-streaming request, the front part streamed by the failed attempt stays on screen. Vendor behavior unconfirmed.
- **F4 compact not captured** (B1 review): `/compact` · automatic compact were not captured with the flag on — if compact emits a top-level `stream_event`, the summary could flow into the chat. Unconfirmed — confirmed in GUI QA (§8-2).
- **F2 interrupt before the turn opens** (③ · S4): an Esc before the turn opens (right after sending · until before `init` depending on the S4 result) is a no-op refused with CONFLICT — just press again.
- **F2 residual race** (§3-4 · S7): a late Esc · bus call right after the turn end can interrupt the next turn that the CLI opened by itself. It cannot be closed because the vendor line has no turn id.
- **F2 an interrupt that was accepted but not heard (받아들여졌으나 듣지 않은 끊기)** (7th edition · ADR-0244 · code review): `requested` means 「줄에 실었다」. If an accepted interrupt is actually not heard (e.g. codex queues `turn/interrupt` and returns `Ok` without an answer from the other side), that window's Esc and window command are no-ops until the turn ends by itself — no timeout is set (intended). The way out = close that view (it clears when the last view unmounts) · call the bus directly (`engram agent.interrupt …`).
- **F2 early clearing in a newly attached view** (7th edition · ADR-0244 · accepted): if the first catch-up of a newly attached view ends at the end of the previous turn (another view just sent and there is no frame of the new turn yet), it clears early as 「열린 턴 없음」 — it just returns to today's behavior (Esc can send again). The window is short, so it is accepted.
- **F2 a direct bus interrupt has no 「끊는 중」** (7th edition · ADR-0244): an interrupt sent directly over the daemon bus (`engram agent.interrupt …`) does not go through the window command, so it has neither the display nor the Esc ignore · a window command called from a window with no chat view of that agent also does not set the state — on those paths the risk of a second interrupt while stopping (uncertain · unchecked — §11 ⑬) stays as it is. The residual race of one press (just above) is also unchanged in the 7th edition.
- **F2 terminal mode has no interrupt command** (7th edition · ADR-0245): for a PTY agent, the bus `agent.interrupt` answers CONFLICT and WS `Interrupt` answers an error — an LLM · CLI cannot interrupt a terminal-mode agent with this command. A person types Esc · Ctrl-C directly in the terminal pane. ★LLM gap (accepted by user decision ⑭)★: the bus has no raw input command either, so there is no way for an LLM to interrupt a terminal-mode agent — a gap of CLAUDE.md 「LLM-우선 제어」 (CLAUDE.md was not fixed · ADR-0245 impact). Do not revive it — user decision ⑭ (「터미널모드는 지가 알아서 하잖아」) removed it, and a raw Ctrl-C goes out whether or not a turn is running and a TUI ends on the second Ctrl-C within a short window (codex = source reading — research `docs/research/interrupt-feedback-peers-2026-09-28.md` codex TUI row · likely · claude = known behavior · unmeasured here · likely).
- **F2 codex interrupt (`turn/interrupt`) does not stop a command that is already running** (vendor behavior · 5th edition · tag reading · likely — §4-7 fact 「끊긴 명령은 계속 돌다 늦게 끝난다」): Esc interrupts the turn but a command process already running via unified-exec stays alive and runs to the end, and its end can come in the middle of the next turn. The way to end it is on the vendor side — the experimental API `thread/backgroundTerminals/terminate` · `clean` · `list` (`app-server-protocol/src/protocol/common.rs:745-762@v0.156.1` — `#[experimental]` · re-opened and checked in the 5th-edition light re-check edit · argument details were not read). It is out of scope for this round — user decision ⓐ (§11 ⑩) rejected ⓒ (end it when interrupting) and it stays only as a follow-up candidate (no tracking item yet). The 5th edition's 「우리 쪽 끊기 경로로는 고칠 수 없다」 was too much — it just cannot be stopped with `turn/interrupt`.
- **Contrast — Claude Code kills the running Bash tool on Esc** (measured 2026-09-27 · certain): a command printing a line for 90 seconds stopped writing the moment Esc was pressed at the 10-second mark and afterwards that process was gone · the screen went to 「Interrupted」 right away. ★Scope = the Bash tool of the interactive Claude Code CLI — whether our stream-json `control_request` interrupt kills a running Bash tool is unchecked★ (recorded by B2 spike S1 — §3-5).
- **F2 capability display**: if `control.interrupt` of claude JSON becomes true, the tree's `canInterrupt` (`mergeTreeNodes.ts:94`) also becomes true — there is no consumer today.
- **F3 expansion state is in memory** (reset on reload).
- **F3 version skew** (U2 · §4-7 ⑤): new daemon + old shell = a 「표시할 수 없는 신호」 line for every codex failure·refusal call · old daemon + new shell = no codex error display. There is no value to tell shells apart within one version so it cannot be filtered — the same acceptance as `TurnEnd`.
- **F3 codex decision = the vendor `status`**: what the vendor writes for a non-zero exit is unchecked (confirmed by B5 capture — it stops if it comes as `completed`) · a search command that reports 「못 찾음」 with exit 1 shows as 「오류」 if the vendor writes `failed`.
- **F3 late end**: if the end of an interrupted call comes after the next turn (measured `steer_m6`), the badge attaches to the previous turn's row (today's design). 5th-edition tag reading (likely): an interrupted command closes with the real `exitCode`, so with a non-zero exit its end is `failed` — a red 「오류」 stands in the interrupted turn's group and is left as is (user decision ⓐ 2026-09-27 · the 「중단됨」 row right below gives the context · §11 ⑩ · §4-7 ⑨ capture two). Even if that frame falls in the window 「보낸 직후 · 첫 응답 전」, the waiting display does not go off — the `ToolResult` branch returns `false` from `feed`, so `RichSlot.tsx:222` does not release waiting (§4-7 ⑧ · it closes the gap that the 3rd-edition review Designer FIX had accepted). ★The same class remains for `Usage`★ — it is not this scope and belongs to the Wait redesign (`docs/tracking.md` T-12).
- **F3 refusal attribution rests on the upstream mapping** (U2-a · §4-7 ②-2): 「우리 거절 → 같은 item id 의 끝이 곧바로(명령 = `failed` · 파일 변경 = `declined`)」 is an upstream source reading (main `41f9084` · 5th-edition tag `rust-v0.156.1` — source of the same edition as the installed build but not an execution check · likely).
