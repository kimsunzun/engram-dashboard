S37 멀티 데몬 큰 그림

PRD·TRD 초안 기준 (리뷰 전) — prd.md · trd.md draft 1 (2026-11-15). TRD는 PRD D1–D7의 ★ 기본값을 가정하고 쓰였다.

1한 줄

내 PC끼리 데몬이 iroh로 이어지고, 에이전트 우편이 PC를 넘는다. 앱은 보여 주기만 하고, 연결·우편은 전부 데몬이 한다.

데몬 = 시스템·LLM 실행, 앱(클라이언트) = 보여 주기. v1은 우편만 — 앱이 다른 PC의 데몬을 직접 보는 것은 다음 단계이고, 같은 링크 위에 구조 변경 없이 얹는다.

4우편 한 통

전달됨받는 에이전트에 들어감
보관됨상대가 잠듦·바쁨 — 깨면 전달
거절한도 초과 등, 이유가 같이 옴
받는 이 없음그 PC에 그 이름이 없음
PC 꺼짐링크 없음 — 바로 실패
미확인8초 안에 판정 없음 — 갔을 수도 있으니 무작정 재전송 금지

v1은 자동 재전송이 없다.

5연결이 맺어지는 순간

6데몬에 생기는 파일 2개

자리: 데몬 state 폴더 <data root>\daemon\state\

peer-key — 신원 키

이 PC의 비밀 키. 공개 절반이 곧 PC ID다. 처음 필요할 때 한 번 만들고 다시 쓰지 않으며, 소유자만 읽을 수 있게 쓴다.

peers.json — 믿는 PC 목록 + 네트워크 설정

믿는 PC(ID · 이름 · 선택 주소)와 포트 · relay · 주소 조회 · mDNS 설정. 앱 없이도 데몬이 혼자 연결해야 해서 데몬이 가진다.
