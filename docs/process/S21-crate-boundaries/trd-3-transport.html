transport 를 셸 · 데몬에 붙이고
net 을 걷는다

셸과 데몬 사이의 연결을 지금은 손으로 짠 코드 세 벌(셸 connection.rs · 셸 stop.rs · net 의 ws.rs)이 나눠 맡는다. 3단계는 이미 혼자 검증을 끝낸 transport crate 한 벌로 그 일을 옮기고 net 을 지운다. 2판은 그 앞에 transport 를 먼저 고치는 단계(3-0)를 둔다 — 받는 줄이 손실형이라 그대로 붙이면 셸 · 데몬 양쪽이 깨지기 때문이다. 데몬 여럿 · 데몬끼리는 자리만 세우고, 원격 · 페어링 · TLS 는 빈칸으로 남긴다.

읽기 전에. 이 문서는 TRD 2판(2026-10-12)을 그림으로 옮긴 것이다. 2판은 적대 리뷰(deep · 3인 · 전원 FIX)를 반영했고 재리뷰 전이다. 사용자 결정(D1~D22)은 하나도 내려지지 않았다 — 결정 전 구현 진입 금지. 그림 속 모양은 전부 「권고안을 고르면 이렇게 된다」는 뜻이다(TRD §8-3 은 권고안을 첫째로 둔다 — 대개 ①, D6 만 ②'). 코드는 한 줄도 바뀌지 않았고 빌드 · 시험도 돌리지 않았다.

01한눈에

세 벌이 한 벌로, net 은 사라진다

가져갈 것: 핸드셰이크 · 재연결 · 짝 맞추기를 하던 세 벌이 transport 한 벌로 모이고, 셸과 데몬에는 자기 쪽 끝자락(link/)만 남는다. protocol 은 아무것도 의존하지 않는 잎이 된다. 2판은 붙이기 전에 transport 를 먼저 고친다(3-0 — 다음 절). 그림은 연결에 관한 간선만 그렸다 — 셸 · 데몬의 base · platform · command 직접 의존은 생략.

지우는 것 (TRD §2-3)
net crate 전체 — 6 파일 3,601줄 셸 tungstenite = "0.26" 셸 connection.rs 의 핸드셰이크 · 재연결 · pending protocol → command 간선 net gate 1~5 와 그 사본

셸 tokio-tungstenite 는 지우지 않고 dev 의존으로 내린다 — 시험의 가짜 서버가 쓴다.

왜 (TRD §1-1)
  • 같은 일이 세 벌이다 — 핸드셰이크 · keepalive · 재연결 · 짝 맞추기.
  • net 이 셋을 섞는다 — 데몬 전용 서버 행 · 클라도 쓰는 인증 프레임 · 데몬 살림. 셸이 데몬 쪽 crate 를 아는 것을 기능 플래그로 겨우 막는다.
  • protocol 이 command 구조체 넷을 품는다 — ADR-0272 가 걷기로 했고 착수를 이 단계로 미뤘다.
02왜 3-0 이 먼저인가

붙이기 전에 transport 를 고친다 — 유실 · 순서가 crate 안에서 이미 정해진다

1판은 transport 표면을 거의 그대로 쓴다고 봤다. 리뷰가 짚은 다섯을 TRD 가 코드에서 확인했고(정적 판독), 어느 것도 어댑터로 메울 수 없다. 소비자가 0 인 지금 고치면 깨지는 쪽이 없고, 「지금 확정」 표면을 한 번만 다시 연다(D19 ① 권고 · TRD §3-0).

D11 선택지 (TRD §3-0 첫째 항 — 2판에서 다시 썼다)
  1. ①
    상대별 유계 줄 + 배압 + 포화 분류 훅 추천net on_inbound_saturated 계약을 crate seam 으로 옮긴다 · 데몬은 지금 의미(Refused 답 · 취소 우선)를 그대로 구현한다.
  2. ②
    상대별 줄 + 배압만 (훅 없음)줄이 찬 동안 뒤에 온 취소가 앞을 못 지른다 — net 의 bypass 소실.
  3. ③
    공유 줄을 await무손실이지만 한 상대가 막으면 전부 선다(ADR-0180 결정 8).
  4. ④
    1판 — 손실형 그대로 + 어댑터 대처위 그림의 넷이 남는다. 1판 추천(어댑터가 공유 줄을 즉시 비움)은 소비자 태스크가 밀리는 순간 유실로 돌아간다.
D19 — 이 보강을 어디에 두나 (TRD §3-0 「자리」)
  1. ①
    새 단계 3-0 에 전부 추천소비자 0 인 지금 고치면 깨지는 쪽이 없다 · 「지금 확정」 표면을 한 번만 다시 연다 · 3-1 과 파일이 안 겹쳐 나란히 간다 · 1판 3-2 U1 · 3-3 U3 를 흡수.
  2. ②
    3-0 = 셸이 쓰는 것(①~⑤)만받는 쪽 seam · ws 수락 강화는 1판대로 3-3 U3 — 그 설계를 쓰는 데몬 어댑터 바로 앞에서. 표면을 두 번 연다.
  3. ③
    1판대로 각 단계 안3-2 가 손실형 줄 위에서 시작한다 — 기각 사유 = 위 ① 그림.

03목표 토폴로지

셸 하나 → 데몬 N, 데몬 ↔ 데몬 — 3단계는 자리까지

3단계가 실제로 내보내는 동작은 셸 하나 + 로컬 데몬 하나뿐이다. 데몬 여럿과 데몬끼리는 transport 인메모리 하네스와 한 PC 여러 데몬으로만 잰다. 원격(다른 PC)은 나중 트랙이다.

D2 — 관계를 어떻게 가르나 (결정 전 · 세 안)

이미 있는 사실 하나 — 셸↔데몬 링크는 지금도 양방향 요청이다. 데몬→셸 CommandRequest 에 셸이 CommandOutcome 으로 답하고, 그 짝은 데몬 command_delivery 가 진다(transport pending 이 아니다).

DaemonWire 모양 — 원문 통과 (§3-3 · 메인 판단 · D 목록 밖)
  • 1판 = In 이 AgentCommand 라 Wire 가 해독했다. 위층 계약(on_text(&str) · Frame::Text(String) …)과 「위층 무변경」이 모순이고, 기본 해독 실패 정책(DropFrame)이 지금 동작 셋(깨진 명령에 Error + 유지 · 두 번째 Auth · binary 에 Error + 닫기)을 조용히 버리며, 어휘가 link/ 로 샌다.
  • 2판 제안 = In = RawIn{Text(String) | Binary(Vec<u8>)} — 해독 실패 0 · 바이트 길이를 같이 실어 CONN_RX_MAX_BYTES 회계를 잇는다. 해독은 지금처럼 agent_conn, link/ 는 어휘를 공장 콜백으로만 받는다.
  • DaemonWire::request_tag · reply_tag 는 모든 입력에 None — 하나라도 Some 이면 셸의 CommandOutcome 이 대기 표에서 못 찾고 UnmatchedReply 로 삼켜진다.
셸 쪽 순서가 바뀐다 (B2 · R10)
  • ShellWire::reply_tag 가 Some 인 답장은 받는 줄을 건너 대기자를 바로 깨운다.
  • 지금 셸 읽기 루프는 프레임 순서대로 사건을 내고 답장을 푼다 — 붙인 뒤엔 답장 직전에 온 사건(예: 목록 갱신)이 답장보다 늦게 위층에 보일 수 있다.
  • 3-2 U2 에 그 순서를 재는 시험을 둔다. 그 순서에 기대는 호출자는 아직 안 찾았다(미확인).
데몬끼리 — 신뢰 · 거는 방향 (§3-3 · D5)
  • PeerDaemon(DaemonId) 는 주장된 · 검증 안 된 id — 신뢰 수준은 LocalClient 와 같다. 자격 = 받는 데몬의 daemon.json 토큰.
  • DaemonId 를 키로 한 영속 신뢰(허용 목록 등)를 만들지 않는다 — 페어링으로 키에 묶기 전까지.
  • 각 Listener 는 다른 관계의 인증 프레임(셸 Auth ↔ PeerAuth)을 거절한다.
  • 양쪽이 동시에 걸면 DaemonId 가 작은 쪽이 건 연결을 남긴다(가안 — D5 ② 일 때만 실물 시험).
04층 지도

보안은 한 덩어리가 아니라 층이다 — 3단계는 위 두 층만 만진다

보안 조사의 첫 결론: 보안을 통째로 해 주는 라이브러리는 없다. 층마다 빌릴 것과 우리가 할 것이 다르다. 그래서 3단계는 우리 몫 층만 채우고, 빌려 끼울 층에는 끼울 자리만 남긴다.

층 이름에 대한 주. 조사 §1 은 층을 ①로컬 브라우저발 · ②인증 · ③암호화·원격 · ④DoS·자원 · (페어링)으로 나누고 NAT 를 ③ 안에 함께 둔다. 여기서는 빌리는 부품이 달라(rustls 는 도달성이 없고 iroh 는 있다) 도달성을 따로 그렸고, 연결 관리는 조사의 층이 아니라 transport 를 가리키려고 더한 줄이다. 조사가 확실로 둔 사실 하나: 로컬호스트 WS 에 Origin 검사가 없는 것은 이 부류에서 실제 CVE 가 반복된 실패이고, Origin 을 기본으로 켜 주는 라이브러리는 없었다.

05연결 타임라인

연결 하나가 붙고 살고 끊기기까지 — 양쪽에서

위에서 아래로 시간이 흐른다. 가운데 화살표가 오가는 것, 양옆이 각자 하는 일이다. 그림은 권고안을 모두 고른 경우의 모양이다(D6 ②' · D11 ① · D20 ① · D21 ① 포함).

새 3단계 새 동작이식 net 에서 옮김D 번호 = 그 자리에 걸린 결정 · U 번호 = 단위거절 · 끊김
출력 프레임과 seq — 누가 지키나 (TRD §2-5)
  • 링 · seq 찍기 = 데몬 OutputCore — 그대로.
  • replay→live 순서 = 같은 lock 안 FrameSink::try_send → Peer::notify(await 없음) → 감독 단일 writer FIFO. 지금과 같은 성질.
  • 화신 표식 · gen 펜스 · seq 연속 = 셸 frame_relay · replay_flight · 프론트 — 그대로.
  • transport 스트림 층 = 안 쓴다(D10 ①).
  • 받는 줄 포화 = 유실을 없앤다(3-0 U1 · D11 ①). 셸 줄이 차면 그 상대의 소켓 읽기만 서고, 데몬 나가는 큐가 차면 D13 규칙(끊고 전량 replay)으로 푼다 — seq 를 건너뛰는 길이 없다. 1판의 「Dropped{Inbound} → reconnect_now」는 걷었다.
스트림 층을 켜면 깨지는 셋 (TRD 확실 — 코드 판독)
  • 셸은 창마다 같은 에이전트의 replay 를 전량 다시 받는다 — transport 의 「seq ≤ last 면 버림」이 새 창의 replay 를 통째로 버린다.
  • 구멍을 보면 transport 가 Subscribe 를 스스로 낸다 — gen 펜스 붕괴.
  • transport 는 재요청 뒤 2초가 지나면 잘림을 신고하지만 프론트는 구멍 뒤를 시한 없이 붙든다.
06단계별 변화

23 단위, 어느 칸에서 멈춰도 초록

갈 곳을 먼저 세우고 옛 자리를 지운다. 2판은 붙이기 전에 transport 를 고치는 3-0 을 앞에 두고(D19 ①), 3-0 과 3-1 은 파일이 안 겹쳐 나란히 간다. 새 구동은 옆에 세우되 그 시험은 따로 세우고(옛 시험을 두 구동에 돌리지 않는다), 운영 전환은 생성자 한 줄이다.

끊는 규칙 (TRD §6 머리)

  • 갈 곳을 먼저 세우고 옛 자리를 지운다.
  • 타입을 바꾸면 그 호출부를 같은 커밋에서 다 맞춘다.
  • 게이트 사본(CI · qa · CLAUDE.md · testing-strategy · crate 헤더)은 게이트를 바꾸는 그 커밋에서 함께 고치고 /review doc 을 거친다 — CLAUDE.md 는 load-bearing 문서다.
  • 단위 앞뒤로 결과 줄 · 통과 · 무시를 견준다 — 줄이 줄면 초록이어도 멈춘다. 예외는 net 의 결과 줄 둘(lib · doc-tests — 의도적 소실 · 정확한 셈 미확인).
