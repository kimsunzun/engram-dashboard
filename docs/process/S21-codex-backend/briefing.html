codex 가 뜬다

트리에서 폴더를 고르면 codex TUI 가 슬롯에 뜨고 타이핑된다. 실제 앱에서 확인했다. 새 파이프를 짓지 않았다 — 파이프는 이미 중립이었고, claude 지식이 샌 자리를 제자리로 돌렸을 뿐이다.

무엇이 바뀌었나

새는 곳 셋을 제자리로 돌렸다

  • 백엔드마다 폴더 하나가 됐다. 그 전엔 파일 하나여서 「여기 전부 넣어야 한다」가 안 보였고, 실제로 샜다 — 갈림길 파일이 claude 함수를 직접 넷 부르고 있었다. 계약으로 올렸다.
  • claude 세션 파일을 읽던 488 줄이 claude 폴더 안으로 들어갔다. 규약을 실제로 어기던 유일한 자리였다. codex 는 세션 id 를 못 정해서 두 번째 구현이 영영 안 생긴다 — 안전하게 옮길 수 있었다.
  • 범용 개념에 붙어 있던 벤더 이름을 걷었다 — 세션 id 칸(16 파일 50 건)과 「claude 인가」를 묻던 판정. 그 판정 하나가 입력·출력·전송 셋을 동시에 고르고 있었다.
  • 안 걷은 것도 있다 — 백엔드를 고르는 칸에 백엔드 이름이 든 것은 누수가 아니라 식별자 그 자체다. 지우면 무엇을 띄울지 못 고른다.
지금이 가장 쌌다 — 출시 전이라 이행 비용이 0 인 창이 열려 있었다.
릴리스가 한 번 나가면 그 창이 닫힌다.
실측

codex는 얼굴이 둘이다

대화형 화면

codex --cd <폴더>

사람이 보는 진짜 codex 화면. PTY가 없으면 아예 안 뜬다. 번역기가 필요 없다 — 바이트를 그대로 흘린다.

대신 세션 id를 알 길이 없다 → 복원 불가.

상주 JSON 서버

codex app-server

claude의 JSON 모드에 대응하는 물건. 대화를 만들면 id를 그 자리에서 돌려준다. 복원·중단·중간 개입까지 있다.

대신 실험 딱지가 붙어 있고 버전마다 흔들린다.

claude와 다른 점: claude는 한 프로세스가 두 모드를 다 한다. codex는 얼굴마다 다른 프로세스이고 능력도 다르다.

꾸밈

예쁜 상자마다 고정 칸이 하나씩

  • 안 꾸민 것은 이미 백엔드 무관하게 돈다. 고정 칸이 있어서다.
  • 꾸민 것이 claude에 묶여 있다. 도구 결과 상자·생각 블록 접기. 칸 없이 원본에서 바로 읽는다.
  • 지금 codex를 붙이면 그 꾸밈만 안 걸린다. 안 죽고 내용도 다 보인다 — JSON 덩어리로 떨어질 뿐이다.
  • 새 타입의 통과 시험 = 양쪽 번역기가 다 낼 수 있나. 한쪽만 내면 중립 타입이 아니다.
꾸밈이 죄가 아니다. 칸 없이 꾸민 것이 죄다.
단 번역기를 고르는 갈림길은 백엔드 계약 밖에 있다 — 백엔드에 구현을 얹는 형태가 아니라, “claude인가”를 묻는 판정 하나가 입력·출력·전송을 동시에 고른다. codex 번역기를 붙이려면 그 판정 자체를 고쳐야 한다. 2단계 청구서다.
저장

우리는 대화를 저장하지 않는다

  • 우리 것 = 메모리 링 버퍼 하나. 화면 다시 붙었을 때 되뿌리는 용도. 앱 끄면 없어진다. 여기 들어가는 건 번역본이다.
  • 원본 = CLI가 자기 폴더에 남긴다. claude도 codex도 각자. 우리가 안 건드린다.
  • 번역 못 한 것은 원본 JSON 그대로 미해석 칸에 실려 온다.
링 버퍼에 실제로 쌓이는 것 — 번호 + 이벤트 + 크기(퇴출 예산용) 글 { 텍스트, 턴id?, 메시지id? } 도구 호출 { 이름, 인자는 원본 그대로, 호출id?, 턴id?, 메시지id? } 사용량 { 입력토큰, 출력토큰, 턴id? } 턴 종료 { 턴id?, 메시지id? } 오류 { 문구 } 미해석 { 종류 태그, 원본 JSON 통째로 } 터미널 { 원본 바이트 } ← 터미널 모드는 이것뿐이다

버퍼는 건수와 바이트 양쪽으로 상한이 걸려 있다 — 큰 도구 인자나 미해석 덩어리가 상한을 우회하지 못하게 크기를 근사해 예산에 넣는다.

화면이 보는 건 번역본뿐이다 → 번역에서 떨어뜨린 정보는 화면에서 영영 안 보인다. 그래서 애매하면 버리지 말고 미해석으로 통과시킨다.

대화마다 하나

가장 성숙한 독립 피어 둘이 이 형태다 — 그중 하나는 28k 스타에 우리와 같은 Rust 스택.

지금 우리 구조가 그대로 산다.

작업공간마다 하나

OpenAI 자기 플러그인이 이 형태. 우리는 에이전트가 대개 자기 폴더에서 돌아 실제로는 거의 같은 그림이 된다.

전역 하나

codex 문서가 의도한 모양. 하지만 메모리가 부풀어 강제 종료된 보고가 여럿이고, 그러면 안의 대화가 전부 같이 죽는다.

계획

세 단계로 나눈다

0단계 터전 + 실측. 배선보다 먼저. cargo test로 도는 백엔드 계약 시험대를 세우고, 거기서 codex를 실제로 띄워 우리가 도움말로만 아는 것들을 잰다. 백엔드가 늘 때마다 질문표에 열이 하나 는다.
1단계 대화형 화면으로 띄우기. 번역기 0줄. 스폰·명부·wire 칸·화면 붙기만 증명한다. 어느 얼굴로 가든 이 넷은 똑같이 필요하다.
2단계 상주 서버 + 번역기. 여기서 세션 복원·우편·구조화 화면이 함께 열린다. 고정 칸을 몇 개 늘릴지가 실제 작업이다.
3단계 프론트에 샌 해석 회수. claude 쪽 정리라 codex와 독립이다. 끝나면 두 백엔드를 같은 코드가 그린다.
0단계에는 게이트가 달려 있다.
실측이 다섯 관측 중 하나라도 내면 배선을 시작하지 않고 설계를 다시 연다.
1단계의 대부분은 저쪽 transport 작업과 파일이 하나도 안 겹친다. 접합부(wire 칸·데몬 스폰·프론트 스폰)만 겹친다.
2 인 적대 리뷰

리뷰가 내 보고 셋을 반증했다

두 렌즈(불변식 · 다른 모델 신선 렌즈) 모두 FIX. 적출 12 건 중 10 반영, 2 는 사유와 함께 보류. ★그중 셋은 내가 「됐다」고 보고한 것을 정면으로 뒤집었다★ — 그게 이 리뷰의 값어치다.

  • 「문이 둘이다」 → 셋이었다. 트리 메뉴 항목이 사람 메뉴이자 LLM 표면을 겸직한다. 백엔드 낱말로는 못 닫아서(사람 길까지 닫힌다) 호출자 축으로 갈랐다.
  • 「버전 안 올려도 된다」 → 근거가 거짓이었다. 칸을 더한 게 아니라 종류를 더한 거라 모르는 쪽은 파싱이 통째로 실패한다. 그리고 데몬은 셸 재빌드보다 오래 산다 — 「출시 전」이 이 실패를 안 막는다. 4 로 올렸다.
  • 「drift 시험이 갈림을 잡는다」 → 지워도 초록이었다. 한쪽 문은 어휘만 비교하고 있었다. 이제 각 검사를 지우면 실제로 빨개진다 — 지워 보고 확인했다.
  • 「argv 가 실측됐다」 → 반만 맞았다. 실 argv 는 화면 실측이 OS 에서 읽어 맞았지만, 시험대는 그걸 안 쟀다 — 같은 파일 상수를 자기와 비교하는 동어반복이었다.
안 고친 것 둘 — 폴더 이름에 %VAR% 가 실제로 들어 있으면 셸이 확장한다(유일 해법이 claude 공용 코드를 건드려 틀리면 모든 스폰이 죽는다) · codex 프로필이 디스크에 박혀 옛 빌드로 되돌리면 명부를 잃는다(수용하기로 한 것). 둘 다 그 자리 주석과 추적 항목에 남겼다.
주의

아무것도 안 하면 이렇게 된다

  • 우편이 켜진다. 기본값이 “받는다”이고, 턴 신호를 선언 안 하면 막지 않고 항상 즉시 꽂는다 — 생각 중인 codex에 우편이 들어간다. 그래서 1단계는 끄고 간다.
  • 디스크 하위호환이 진짜 일이다. 종류 칸이 늘면 구버전이 프로필 파일 전체를 못 읽고 명부가 빈다.
  • 옛 데몬이 codex 지정을 조용히 무시한다. 버전을 안 올리기로 했으므로 모르는 칸은 버려지고 claude가 대신 뜬다.
검증 상태

무엇으로 확인했나

  • 화면 실측 PASS — 트리 메뉴 → 폴더 → 활성화 → 슬롯에 codex TUI. 실 argv 를 OS 에서 직접 읽어 명세와 대조했고, 신뢰 확인 창을 엔터로 지나 입력 프롬프트까지 진행했다.
  • 워크스페이스 회귀 2116 통과 · 0 실패 — 두 갈래 작업을 합친 상태에서 다시 돌린 값이다.
  • 시험대 11/11 — 백엔드마다 같은 질문표. 셋째 백엔드는 파일이 아니라 열 하나가 는다.
  • 2 인 적대 리뷰 — 두 렌즈 모두 FIX, 반영 후 push 완료.
안 재는 것을 안 잰다고 적어 뒀다 — 쓰기 권한 아래의 모델 동작 · 우리가 안 쓰는 인자 · %VAR% 한계. 「전부 실측」이라 적던 옛 문장이 거짓이었고, 리뷰가 잡아 고쳤다. 정본은 그 파일 헤더다.
