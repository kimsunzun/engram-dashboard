codex 가 뜬다

트리에서 폴더를 고르면 codex TUI 가 슬롯에 뜨고 타이핑된다. 실제 앱에서 확인했다. 새 파이프를 짓지 않았다 — 파이프는 이미 중립이었고, claude 지식이 샌 자리를 제자리로 돌렸을 뿐이다. 그리고 다음 얼굴로 가는 통로가 실측 위에서 정해졌다.

무엇이 바뀌었나

새는 곳 셋을 제자리로 돌렸다

  • 백엔드마다 폴더 하나가 됐다. 그 전엔 파일 하나여서 「여기 전부 넣어야 한다」가 안 보였고, 실제로 샜다 — 갈림길 파일이 claude 함수를 직접 넷 부르고 있었다. 계약으로 올렸다.
  • claude 세션 파일을 읽던 488 줄이 claude 폴더 안으로 들어갔다. 규약을 실제로 어기던 유일한 자리였다. codex 는 세션 id 를 못 정해서 두 번째 구현이 영영 안 생긴다 — 안전하게 옮길 수 있었다.
  • 범용 개념에 붙어 있던 벤더 이름을 걷었다 — 세션 id 칸(16 파일 50 건)과 「claude 인가」를 묻던 판정. 그 판정 하나가 입력·출력·전송 셋을 동시에 고르고 있었다.
  • 안 걷은 것도 있다 — 백엔드를 고르는 칸에 백엔드 이름이 든 것은 누수가 아니라 식별자 그 자체다. 지우면 무엇을 띄울지 못 고른다.
지금이 가장 쌌다 — 출시 전이라 이행 비용이 0 인 창이 열려 있었다.
릴리스가 한 번 나가면 그 창이 닫힌다.

꾸밈

예쁜 상자마다 고정 칸이 하나씩

  • 안 꾸민 것은 이미 백엔드 무관하게 돈다. 고정 칸이 있어서다.
  • 꾸민 것이 claude에 묶여 있다. 도구 결과 상자·생각 블록 접기. 칸 없이 원본에서 바로 읽는다.
  • 지금 codex를 붙이면 그 꾸밈만 안 걸린다. 안 죽고 내용도 다 보인다 — JSON 덩어리로 떨어질 뿐이다.
  • 새 타입의 통과 시험 = 양쪽 번역기가 다 낼 수 있나. 한쪽만 내면 중립 타입이 아니다.
꾸밈이 죄가 아니다. 칸 없이 꾸민 것이 죄다.
갈림길은 이제 백엔드 계약 위에 있다 — 「claude 인가」를 묻던 판정 하나가 입력·출력·전송을 동시에 고르던 시절은 Phase 1 에서 끝났다. codex 번역기는 codex 폴더에 자기 것을 얹으면 붙는다. 남은 청구서는 꾸밈 쪽이다 — 칸 없이 claude 원본에서 바로 읽는 상자들(3단계).
저장

우리는 대화를 저장하지 않는다

  • 우리 것 = 메모리 링 버퍼 하나. 화면 다시 붙었을 때 되뿌리는 용도. 앱 끄면 없어진다. 여기 들어가는 건 번역본이다.
  • 원본 = CLI가 자기 폴더에 남긴다. claude도 codex도 각자. 우리가 안 건드린다.
  • 번역 못 한 것은 원본 JSON 그대로 미해석 칸에 실려 온다.
링 버퍼에 실제로 쌓이는 것 — 번호 + 이벤트 + 크기(퇴출 예산용) 글 { 텍스트, 턴id?, 메시지id? } 도구 호출 { 이름, 인자는 원본 그대로, 호출id?, 턴id?, 메시지id? } 사용량 { 입력토큰, 출력토큰, 턴id? } 턴 종료 { 턴id?, 메시지id? } 오류 { 문구 } 미해석 { 종류 태그, 원본 JSON 통째로 } 터미널 { 원본 바이트 } ← 터미널 모드는 이것뿐이다

버퍼는 건수와 바이트 양쪽으로 상한이 걸려 있다 — 큰 도구 인자나 미해석 덩어리가 상한을 우회하지 못하게 크기를 근사해 예산에 넣는다.

화면이 보는 건 번역본뿐이다 → 번역에서 떨어뜨린 정보는 화면에서 영영 안 보인다. 그래서 애매하면 버리지 말고 미해석으로 통과시킨다.

계획

세 단계로 나눈다

0단계 · 끝 터전 + 실측. 배선보다 먼저. cargo test로 도는 백엔드 계약 시험대를 세우고, 거기서 codex를 실제로 띄워 도움말로만 알던 것들을 쟀다. 백엔드가 늘 때마다 질문표에 열이 하나 는다. 여기 달려 있던 게이트는 1단계로 넘어가는 문이었고 이미 지난 문이다.
1단계 · 끝 대화형 화면으로 띄우기. 번역기 0줄. 스폰·명부·wire 칸·화면 붙기를 증명했다. 어느 얼굴로 가든 이 넷은 똑같이 필요했다.
2단계 · 지금 상주 서버 + 번역기. 굵은 것 넷이 정해졌다 — 통로(상주 JSON 서버) · 자리(codex 폴더 안의 통로 구현체) · 권한을 백엔드 중립 축으로 · JSON 모드 입력은 큐로. 설계 문서는 그 넷 위에서 다시 쓰는 중이다.
3단계 프론트에 샌 해석 회수. claude 쪽 정리라 codex와 독립이다. 끝나면 두 백엔드를 같은 코드가 그린다.
2단계가 한꺼번에 여는 것 — 세션 복원 · 우편 · 구조화 챗 · 턴 중단의 절반.
넷이 같은 통로에 매달려 있어서 통로를 고르는 것이 먼저였다. ★절반인 이유 — 신고 값이 정직해져도 사람이 누를 표면은 그래도 남는다.★
★아직 안 정한 것 셋★ — 권한 축의 값 설계(축 몇 개, 값 이름 무엇) · 입력 큐의 상한(길이·대기 시간) · 대기 중임을 화면에 알리는 수단. 비워 둔 채로 확정했다 — 재 보고 정한다.
2 인 적대 리뷰 · Phase 1 코드

리뷰가 셋을 반증했고, 한 번은 판정이 뒤집혔다

두 렌즈(불변식 · 다른 모델 신선 렌즈) 모두 FIX. 적출 12 건 중 10 반영, 2 는 사유와 함께 보류. ★그중 셋은 내가 「됐다」고 보고한 것을 정면으로 뒤집었다★ — 그게 이 리뷰의 값어치다.

  • 「문이 둘이다」 → 셋이었다. 트리 메뉴 항목이 사람 메뉴이자 LLM 표면을 겸직한다. 백엔드 낱말로는 못 닫아서(사람 길까지 닫힌다) 호출자 축으로 갈랐다.
  • 「버전 안 올려도 된다」 → 근거가 거짓이었다. 칸을 더한 게 아니라 종류를 더한 거라 모르는 쪽은 파싱이 통째로 실패한다. 그리고 데몬은 셸 재빌드보다 오래 산다 — 「출시 전」이 이 실패를 안 막는다. 4 로 올렸다.
  • 「drift 시험이 갈림을 잡는다」 → 지워도 초록이었다. 한쪽 문은 어휘만 비교하고 있었다. 이제 각 검사를 지우면 실제로 빨개진다 — 지워 보고 확인했다.
  • 「argv 가 실측됐다」 → 반만 맞았다. 실 argv 는 화면 실측이 OS 에서 읽어 맞았지만, 시험대는 그걸 안 쟀다 — 같은 파일 상수를 자기와 비교하는 동어반복이었다.

그쪽은 두 판 다 BLOCK 이었다 — 부품이 앉을 자리를 층 이름 위에서 추측했고, 막힌 것이 맞았다.
★그 지적들 중 한 건이 뒤집혔다★ — 통로 배치를 막은 근거 주석의 주어가 범용 파이프 구현체였음이 원문 재독으로 드러났다. 뒤집은 주체는 사용자 판정이다 — 메인이 임의로 확정하지 않았다. 나머지 지적은 살아서 3판으로 넘어갔다.
안 고친 것 둘 — 폴더 이름에 %VAR% 가 실제로 들어 있으면 셸이 확장한다(유일 해법이 claude 공용 코드를 건드려 틀리면 모든 스폰이 죽는다) · codex 프로필이 디스크에 박혀 옛 빌드로 되돌리면 명부를 잃는다(수용하기로 한 것). 둘 다 그 자리 주석과 추적 항목에 남겼다.
이번 결정의 파장

codex 를 붙이는데 claude 가 바뀐다

  • ★claude 의 권한 값이 코드 고정에서 값 유래로 바뀐다.★ 지금은 「승인 끄기」를 맨 앞 두 인자로 무조건 넣는다. 그 값이 앞으로는 우리 어휘에서 나온다 — 그렇게 두기로 한 옛 결정 자체는 살아 있고, 바뀌는 건 코드에 박혀 있던 것뿐이다.
  • ★claude JSON 모드에서 턴 중 입력이 즉시 안 나간다.★ 큐에 담겼다가 보낼 수 있을 때 흘러간다. 버리지는 않는다 — 상한을 넘거나 준비가 끝내 실패하면 그때 오류로 돌린다. 이래서 이 결정이 codex 전용이 아니다.
  • 대기 자리가 둘이 된다. 우편은 이미 바쁜 수신자 앞에서 편지를 파킹한다. 큐가 생기면 편지가 두 번 기다릴 수 있다 — 지금은 둘을 따로 두기로 했고, 우편 쪽을 고칠 때 합칠지 판단한다.
  • 권한 축의 값 이름은 아직 못 정한다. claude 여섯 값이 실제로 무엇을 하는지 claude 도움말이 한 줄도 안 적는다(실측). 이름부터 짓고 코드를 나중에 대 보는 실패를 어휘 층에서 반복하지 않는다.
축이 둘인데 하나로 뭉치지 말 것 — 지난번 wire 버전 4 는 종류를 더한 변경이라 옛 쪽이 명부 응답을 통째로 못 읽는 비관용 축이었다. 권한을 capability 에 넣는 것은 칸을 더하는 쪽이라 ★그 판정을 자동으로 물려받지 않는다★ — 「탈 수 있다」로 열어 둔 것이지 정해진 게 아니고, 어느 축이 되는지는 값 설계 때 갈린다.
검증 상태

무엇으로 확인했나

  • codex 실측 3 종 — 세 모드 비교 · 캔슬 비교 · 권한 값 목록. 기각 둘이 서술이 아니라 실측에 걸려 있다. 대상 = codex-cli 0.153.4, 2026-09-09.
  • 소유권 추적 + 8 문항 검증 — 새 부품이 앉을 자리가 공용 계약 변경을 강제하지 않음을 확인했다. 막혀 있던 셋(쓰기 경로·실패 표현·취소)이 그 자리에서 전부 풀린다.
  • 적대 리뷰 두 판 — 둘 다 BLOCK 이었다. 그 지적이 3판과 이번 결정들로 흘러갔다. ★결정 넷이 선 자리는 리뷰가 아니다★ — 실측 · 소유권 추적 · 주석 원문 재독 · 사용자 결정이다. 기록은 ADR-0187·0188·0189·0190, 정합성 검사 통과.
