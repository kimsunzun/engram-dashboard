## 1. 무엇 / 왜

**무엇.** 구조화 채팅(JSON) 슬롯에서 에이전트가 턴을 도는 도중에 보낸 글을, **에이전트가 실제로 받을 때까지 입력창 위 목록에 따로** 보이고, 받는 순간 **대화 끝에 평범한 말풍선**으로 옮긴다. 글은 받자마자 에이전트에게 넘겨 **지금 도는 도구 호출이 끝나는 지점**에서 읽히게 하고, 그 턴에 못 들어가면 다음 턴으로 간다. claude 항목은 받기 전까지 ✕ 로 거둘 수 있다.

**오늘의 증상(사용자 체감).**
- **claude(JSON)** — 보낸 글은 곧바로 에이전트에게 가고 에이전트도 도구 호출이 끝나는 지점에서 읽는데, 화면은 **보낸 자리**에 정식 말풍선을 박는다. 그래서 앞 답의 나머지가 그 말풍선 **아래로** 이어져, 대화 순서가 에이전트가 실제로 읽은 순서와 어긋나 보인다. 보낸 뒤 거둘 방법이 없다.
- **codex(JSON)** — 턴 도중 보낸 글은 **턴이 끝날 때까지 모델에게도 화면에도 가지 않는다.** 글이 먹혔는지 알 수 없고, 도는 에이전트를 도중에 바로잡을 수 없다(긴 빌드 중 교정 지시가 턴 끝에야 닿는다). 한가할 때 보낸 글도 에이전트가 되울려 줄 때에야 뜬다 — 사용자가 처음 짚은 「보낸 글이 늦게 뜬다」가 이것이다. 거둘 방법도 없다.
- **공통** — 「보냈지만 에이전트가 아직 안 받은 글」이라는 상태가 화면 어디에도 없다.

**왜 이 모양인가(조사 결론).**
- 턴 도중 보내기를 막지 않는 것이 현재 에이전트 도구의 관행이다(Claude Code · Codex · t3code · paseo · Cursor 등). — 가능성 높음
- 대기분은 대화 밖에 따로 보이고, 정식 말풍선의 자리는 **보낸 시점이 아니라 전달 시점**이다(Codex TUI · t3code 소스로 선다). 보낸 자리에 정식으로 고정하는 곳은 Orca 하나다. — 가능성 높음
- 대화 밖 표시 위치는 두 갈래(대화 맨 아래 대기 행 / 입력창 위 목록)이고, 사용자는 터미널 CLI(Claude Code · Codex TUI)와 같은 **입력창 위 목록**을 골랐다.
- 두 백엔드 모두 이 모양을 받칠 수단이 있다 — 턴 도중 입력을 도구 경계에서 받아들이고, 받은 항목을 하나씩 알려 준다. — 가능성 높음(벤더 원문·소스) · **우리 스폰 모드에서는 미실측**(§8 R1)

## 2. 범위 (사용자 결정)

- **들어간다:** JSON(구조화 채팅) 모드의 **사용자 입력** — claude stream-json · codex app-server.
- **빠진다 — 터미널(PTY) 모드.** 사용자: 「터미널 모드는 그런거 필요없잖아」. 거기서는 에이전트 자신의 TUI 가 턴 중 입력을 이미 줄 세워 보인다. 터미널 슬롯의 동작과 입력 바이트는 하나도 안 바뀐다.
- **빠진다 — 에이전트 간 우편.** 오늘 경로 그대로 간다. 목록에 오르지 않는다.
- **사실 — 오늘 채팅 뷰에는 턴 끊기 조작이 없다.** 화면에도 명령 표면에도 없다(연결 수준의 끊기 요청은 있으나 부르는 곳이 없다 — 2026-09-25 코드 확인). claude JSON 은 끊기 자체가 아직 지원되지 않는다(TRD §3-1). 그래서 **codex 항목은 사실상 거둘 수 없다.** 끊기 조작을 이번 범위에 넣을지는 §9 Q5. 오늘 턴을 실제로 멈추는 것은 오류로 끝나는 턴뿐이다(§9 Q8).

## 3. 동작 명세 (사용자 결정 — 다시 열지 않는다)

1. **받자마자 넘긴다 — 두 백엔드 공통.** 턴 도중 보낸 글을 붙들지 않고 곧바로 에이전트에게 넘긴다(claude = 오늘처럼 즉시 · codex = 진행 중 턴에 끼워 넣기, 도는 턴이 없으면 새 턴). 에이전트는 그 글을 **지금 돌고 있는 도구 호출이 끝나는 지점**에서 읽는다.
   - 사용자: 「당연히 도구호출 끝나면 바로 푸쉬」 · 「클로드든 코덱스든 우리가 받고 바로 전달하자. 일단 공용화하고 나중에 세분화」.
   - 받아들인 근거: 도구가 끝나는 것을 보고서야 넘기면 그 경계를 놓쳐 **다음** 도구가 끝날 때에야 읽힌다(사용자 확인: 「도구가 끝날 때 넘기면 다음 도구가 끝나야 전달되지 않나」 — 그렇다). 즉시 넘기면 글이 처음부터 에이전트 쪽 대기함에 있어 지금 도는 도구의 끝에서 읽힌다.
   - **턴 끝 경계:** 도는 턴에 끝내 못 들어간 항목(도구 없이 답만 쓰다 턴이 끝났거나, 경계를 놓쳤거나)은 턴이 끝난 뒤 **다음 턴으로, 친 순서대로** 들어간다 — 사용자 결정 「도구 경계 없이 턴이 끝나면 남은 항목은 친 순서대로 자동 전송」(2026-09-25 · TRD 본문 D5). 이것은 §3-7 이 막는 재전송이 아니다 — 아직 어느 턴에도 안 들어간 글을 처음 들여보내는 것이다. 남은 항목 여럿을 한 턴에 들일지 항목마다 턴을 줄지는 §9 Q9.
   - ★**요구: 보낸 글은 §3-7 로 버려지지 않는 한 전부 에이전트가 답하는 턴에 들어간다**★ — 대화에 말풍선만 있고 답이 없는 글이 남으면 안 된다.
   - **이미 들어갔는데 답을 못 받은 항목도 같다:** 받음이 와 말풍선이 됐는데 그 턴이 그 글에 답하지 않고 끝나면(codex — 턴이 끝나는 찰나에 들어간 글), 그 글도 답하는 턴을 받아야 한다. **단 같은 글을 에이전트에게 두 번 넘기거나 말풍선을 두 번 그리지 않는다.** 방법 = TRD(M6).
   - 예외 둘은 답이 날 때까지 이 요구에서 뺀다 — **오류로 끝난 턴에 걸린 글**: 목록에 남은 것과 그 턴에서 이미 말풍선이 된 것(한가할 때 보낸 글 포함)(§9 Q8) · 한가할 때 보낸 글이 말풍선이 그려진 뒤 거절된 경우(§9 Q1 ④). 이 PRD 는 오류 뒤에 후속 턴을 여는 것을 요구하지 않는다 — 그 여부가 Q8 이다.
2. **받기 전까지는 입력창 위 목록에 둔다**(터미널식 — Claude Code · Codex TUI).
   - 항목마다 회색 한 줄, 넘치면 「…」.
   - 오래된 것이 위.
   - 3개를 넘으면 「외 N개」로 접는다(접었을 때 무엇이 보이나는 §9 Q3).
   - 머리줄: 도구가 도는 턴 도중 = 「도구 호출이 끝나면 전달」 · codex 가 연결·이력 복원 중 = 「준비되면 전달」(도구가 안 도는 턴 도중의 문구는 §9 Q4).
   - 대화 안(보낸 자리든 대화 맨 아래든)에는 아무것도 그리지 않는다.
3. **목록은 하나다 — 모든 창과 LLM 이 같은 목록을 본다.** 같은 에이전트를 여러 창(메인·팝아웃)에서 봐도 목록이 같다. 창을 닫았다 다시 열어도, 대시보드 앱을 재시작해도(데몬·에이전트가 살아 있는 한) 목록이 그대로다. LLM 도 명령 표면으로 같은 목록을 읽는다(`CLAUDE.md 「LLM-우선 제어」` — 화면은 그리기만 하고 목록을 소유하지 않는다). 목록을 어디에 두는지는 TRD 몫이다.
4. **항목은 「받음」이 올 때만, 하나씩 빠진다.**
   - **받음 = 에이전트 자신이 「그 항목을 대화에 넣었다」고 항목별로 알려 오는 것**(항목별 되울림). 우리가 글을 에이전트에게 써 넣은 것, 에이전트가 요청을 접수했다고 답한 것은 **받음이 아니다** — 그때까지 항목은 목록에 남는다.
   - 빠지는 순간 **그 순간의 대화 끝**에 평범한 사용자 말풍선으로 나타난다(보낸 자리가 아니다).
   - 「도구가 끝났다」를 이유로 목록을 한꺼번에 비우지 않는다.
   - 받음이 끝내 오지 않으면 항목은 **에이전트가 끝날 때까지** 목록에 남고, 그때 §3-7 대로 버린다.
5. **한가한 에이전트에 보내면 곧바로 대화에 들어간다** — 목록을 거쳐 깜빡이지 않는다. codex 도 마찬가지다(ADR-0198 의 즉시 표시).
   - **한가 = 도는 턴이 없고 목록도 비어 있음.** 목록에 항목이 남아 있으면 — 예: 앞 턴에서 넘어온 A·B 가 다음 턴을 기다리는 틈 — 새로 보낸 C 는 곧바로 대화에 들어가지 않고 **목록 맨 뒤**에 선다. 「친 순서대로」(§3-1)를 지키려면 C 가 A·B 를 앞지르면 안 되기 때문이다.
6. **✕ 취소는 claude 항목에만 있다.**
   - codex 항목에는 ✕ 가 없다 — 넘긴 글 하나만 거두는 수단이 벤더에 없고, 있는 것은 턴을 끊어 대기분을 전부 버리는 것뿐이다(가능성 높음 — 소스). 그 끊기 조작도 오늘 채팅 뷰엔 없다(§2).
   - 취소는 **등록된 명령**이다 — LLM 도 같은 명령으로 취소한다. ✕ 는 그 명령을 부르는 사용자 동작이지, 슬롯 안 에이전트의 행동이 아니다.
   - Esc 키 바인딩은 지금 두지 않는다(§7).
   - **✕ 는 요청이다 — 결말이 날 때까지 항목은 목록에 남고, 결말은 정확히 셋 중 하나다:** (가) **사라진다** — 취소가 확정됐다, 글은 버린다(§3-7) · (나) **대화 끝 말풍선이 된다** — 에이전트가 먼저 가져갔다 · (다) **버려진다** — 결말 전에 에이전트가 끝났거나, 에이전트가 살아 있어도 백엔드가 그 항목을 거절했다(§3-7). (가)·(나)는 에이전트의 알림으로만 정한다(§8 R2).
   - **「취소 대기」도 하나뿐인 목록의 상태다**(§3-3 에서 따라 나온다) — 모든 창과 LLM 이 같은 취소 대기를 보고, 앱을 재시작해도 남는다. 그 모양은 §9 Q7.
7. **거둔 글·못 보낸 글은 버린다.**
   - ✕ 로 취소한 글은 버린다 — 입력창으로 되돌리지 않는다. 사용자: 「일단 그냥 다 버리고 나중에 생각하자」.
   - 끊기·에이전트 종료·백엔드 거절로 끝내 전달될 수 없게 된 항목도 버린다(사용자 확인 2026-09-25 밤).
   - **끊기 = 도는 턴이 (어떤 조작으로든) 중단되는 것.** 창이 데몬과의 연결을 잃는 것은 끊기가 **아니다** — 목록은 그대로 남고, 창은 다시 붙을 때 목록을 다시 맞춘다(§3-3 에서 따라 나온다). 오류로 끝난 턴이 끊기에 드는지는 §9 Q8.
   - 자동 재전송은 없다 — 이미 넘긴 글을 다시 보내면 에이전트가 같은 글을 두 번 받을 수 있다(조사 §2-4 · TRD §3-1).
   - 버릴 때 알림을 남길지는 §9 Q1.
8. **메시지는 따로 남는다.** 여러 개를 보내도 이어 붙이지 않는다 — 각자 한 줄, 각자 말풍선이다.

## 4. 시나리오 / 엣지

- **한가할 때 보냄:** 곧바로 대화 끝 말풍선. 목록은 나타나지 않는다.
- **긴 도구(빌드) 도중 교정 지시:** 입력창 위에 회색 한 줄 → 에이전트가 받으면 목록에서 빠지고 그 순간의 대화 끝 말풍선 → 에이전트의 다음 행동이 그 지시를 반영한다. 보통은 그 빌드가 끝나는 지점에서 받고, 빌드가 끝나는 찰나에 보냈다면 다음 경계나 다음 턴에서 받는다 — 어느 쪽이든 에이전트가 답한다(§3-1).
- **도구 없이 긴 답을 쓰는 도중 보냄:** 그 답이 끝난 뒤 에이전트가 그 글을 받아 답한다 → 말풍선은 앞 답 **아래**에 선다.
- **턴이 끝날 때 목록에 남은 항목:** 다음 턴으로, 친 순서대로 들어간다. 사용자가 다시 보낼 필요가 없다(한 턴에 묶을지 항목마다 턴을 줄지는 §9 Q9).
- **남은 A·B 가 다음 턴을 기다리는 틈에 C 를 보냄:** 턴이 안 돌아도 한가가 아니다 — C 는 목록 맨 뒤에 서고, 말풍선은 A·B·C 순서로 선다.
- **codex — 글이 턴에 들어가(말풍선이 뜬) 직후 그 턴이 답 없이 끝남:** 그 글에 답하는 턴이 이어진다. 같은 말풍선이 두 번 생기지 않고, 같은 글이 에이전트에게 두 번 가지 않는다(방법 = TRD, M6).
- **턴이 오류로 끝남(요청 한도 · 과부하 · 맥락 초과) — 목록에 항목이 남아 있음:** 처리 = §9 Q8.
- **여러 개 연달아:** 오래된 것이 위, 4개째부터 「외 N개」. 에이전트가 받는 대로 하나씩 빠져 각자 따로 말풍선이 된다.
- **claude 항목 ✕:** 결말이 날 때까지 목록에 남는다 → (가) 취소 확정이면 사라지고 모델에 가지 않는다(다음 응답이 그 글을 모른다), 글은 버려진다 · (나) 에이전트가 먼저 가져갔으면 사라지지 않고 대화 끝 말풍선이 된다.
- **claude ✕ 결말 전에 에이전트가 끝나거나 거절:** 항목은 버려진다(§3-7).
- **✕ 를 누른 창과 다른 창·LLM:** 모두 같은 「취소 대기」를 보고, 결말도 모두에게 같게 반영된다.
- **codex 턴 도중 보냄:** ✕ 가 없다. 거둘 길이 없다 — 턴을 끊는 조작도 오늘 채팅 뷰엔 없다(§2 · §9 Q5).
- **codex 이어받기(연결·이력 복원 중) 입력:** 목록 머리줄 「준비되면 전달」 → 준비되면 넘긴다 → 받음이 오면 말풍선이 복원된 이력 **아래**에 선다. 이어받기 자체가 실패하면 에이전트가 종점으로 끝나므로(ADR-0082 — 새 대화로 자동 전환하지 않는다) 대기분은 버려진다(§3-7). 그 밖의 복원 실패 갈래는 §9 Q6.
- **받음이 끝내 안 옴:** 항목은 에이전트가 끝날 때까지 목록에 남고, 그때 버려진다.
- **끊기 / 에이전트 종료 / 거절:** 남은 항목은 목록에서 사라지고 버려진다. 입력창으로 돌아오지 않고 재전송되지도 않는다(알림 여부는 §9 Q1).
- **창이 데몬과의 연결을 잃었다 다시 붙음:** 끊기가 아니다 — 연결이 끊겼다는 이유로 사라지는 항목은 없다. 다시 붙은 창은 목록과 말풍선을 실제 상태대로 보인다: 그 사이 에이전트가 받은 항목은 말풍선으로, 그 사이 버려진 항목은 없는 채로.
- **창 두 개(메인 + 팝아웃):** 두 창의 목록이 같고, 한쪽의 ✕ 가 양쪽에 반영된다.
- **창을 닫았다 다시 열기:** 목록이 그대로다.
- **대시보드 앱 재시작 — 데몬과 에이전트는 살아 있음:** 다시 뜬 창에 목록(취소 대기 포함)이 그대로 나타난다.
- **데몬 재기동:** 에이전트와 함께 목록도 사라진다(§7 — 오늘 입력 큐와 같은 등급).
- **LLM 이 목록 조회 · claude 항목 취소:** 화면의 목록이 같게 바뀐다.
- **턴이 끝나는 찰나에 보냄(claude):** 목록에 한순간 비쳤다 곧바로 말풍선이 될 수 있다 — 표시만의 흔들림이다.
- **턴 도중 슬래시 명령(「/compact」 등)을 보냄:** 특별 취급 없이 다른 글처럼 넘긴다. 에이전트가 그것을 어떻게 다루는지는 미측정이다(§8 R7).
- **터미널 슬롯에서 턴 중 타이핑:** 변화 없음 — 에이전트 TUI 자신의 대기 표시만 보인다.
- **에이전트 간 우편 도착:** 목록에 오르지 않는다. 오늘과 같다.

## 5. 수용 기준 (보이는 동작)

1. 두 백엔드 모두 **한가할 때**(도는 턴 없음 + 목록 빔) 보낸 글은 목록을 거치지 않고 곧바로 대화 끝 말풍선으로 뜬다 — 목록 깜빡임 없음.
2. 목록에 항목이 남아 있는 동안 보낸 글은 턴이 안 돌더라도 목록 맨 뒤에 서고, 앞 항목을 앞지르지 않는다 — 말풍선 순서가 친 순서와 같다.
3. **claude JSON:** 긴 도구 도중 보낸 글이 즉시 입력창 위 목록(회색 한 줄)에 뜨고, 보통은 그 도구가 끝나는 시점에 목록에서 빠져 **그 순간의 대화 끝** 말풍선이 되며, 에이전트의 다음 응답이 그 글에 반응한다(도구가 끝나는 찰나에 보낸 글은 다음 경계나 다음 턴 — 5). 앞 답의 중간(보낸 자리)에는 말풍선이 없다.
4. **codex JSON:** 긴 도구 도중 보낸 글이 턴 끝까지 기다리지 않고 그 도구가 끝난 뒤 모델에 닿는다(도구가 끝나는 찰나에 보낸 글은 다음 경계나 다음 턴 — 5). 목록 → 말풍선 전환은 3과 같다.
5. **보낸 글은 §3-7 로 버려지지 않는 한 전부 에이전트가 답하는 턴에 들어간다.** 도는 턴에 못 들어간 항목은 턴이 끝난 뒤 다음 턴으로 친 순서대로 들어가고, 사용자가 다시 보낼 필요가 없다. 대화에 답 없는 말풍선이 남지 않는다. **예외(답 전까지):** 오류로 끝난 턴에 걸린 글 — 목록에 남은 것과 그 턴에서 이미 말풍선이 된 것(한가할 때 보낸 글 포함)(§9 Q8) · 한가할 때 보낸 글이 말풍선이 그려진 뒤 거절된 경우(§9 Q1 ④). 오류 뒤 후속 턴을 여는지는 이 기준이 요구하지 않는다(Q8).
6. **이미 턴에 들어갔는데 그 턴이 답하지 않고 끝난 항목(codex)도 답하는 턴을 받는다** — 같은 글의 말풍선이 두 번 생기지 않고, 같은 글이 에이전트에게 두 번 넘어가지 않는다.
7. 여러 개를 보내면 각자 한 줄(넘치면 「…」), 오래된 것이 위, 4개 이상이면 「외 N개」로 접힌다. 전달되면 각자 따로 말풍선이 되고 이어 붙지 않는다.
8. 목록 머리줄이 도구가 도는 턴 도중엔 「도구 호출이 끝나면 전달」, 도구가 안 도는 턴 도중엔 §9 Q4 에 따라, codex 연결·이력 복원 중엔 「준비되면 전달」이다. 복원 중 친 글의 말풍선은 복원된 이력 아래에 선다.
9. 항목은 에이전트가 그 항목을 받았다고 알려 올 때만 하나씩 빠진다 — 글을 써 넣은 것만으로 빠지지 않고, 도구가 끝났다고 목록이 한꺼번에 비지 않는다. 받음이 끝내 안 오면 에이전트가 끝날 때까지 목록에 남는다.
10. ✕ 는 claude 항목에만 있고 codex 항목엔 없다.
11. **claude ✕ — (가) 취소가 이긴 경우:** 누른 뒤 결말이 날 때까지 항목이 목록에 남고, 결말이 오면 사라진다. 모델의 다음 응답이 그 글을 모르고, 글은 입력창에 돌아오지 않는다.
12. **claude ✕ — (나) 에이전트가 먼저 가져간 경우:** 항목이 사라지는 대신 대화 끝 말풍선이 되고, 에이전트가 그 글에 답한다.
13. **claude ✕ — (다) 결말 전에 에이전트가 끝났거나, 에이전트가 살아 있어도 백엔드가 그 항목을 거절한 경우:** 항목은 목록에서 사라지고 버려진다(입력창에 돌아오지 않는다). **한 번의 ✕ 는 11·12·13 셋 중 정확히 하나로 끝난다** — 사라졌는데 모델에 가거나, 말풍선이 됐는데 모델이 모르는 일은 없다.
14. 끊기·에이전트 종료·거절로 못 보낸 항목은 목록에서 사라지고, 입력창에 돌아오지 않으며, 자동으로 다시 보내지지 않는다.
15. 메인 창과 팝아웃 창이 같은 에이전트를 보면 목록(취소 대기 포함)이 같고, 한쪽의 ✕ 가 양쪽에 반영된다. 창을 닫았다 다시 열어도 목록이 그대로다.
16. 창이 데몬과의 연결을 잃었다 다시 붙어도 **연결이 끊겼다는 이유로** 사라지는 항목은 없다. 다시 붙은 창은 목록과 말풍선을 실제 상태대로 보인다 — 그 사이 받힌 항목은 말풍선으로, 그 사이 버려진 항목은 없는 채로 — 그리고 다른 창과 같다.
17. 데몬과 에이전트가 살아 있는 채로 대시보드 앱을 재시작하면 목록(취소 대기 포함)이 그대로 다시 나타난다.
18. LLM 이 명령 표면으로 같은 목록을 읽고 claude 항목을 취소할 수 있다 — 화면 ✕ 와 같은 명령이다. Esc 키 바인딩은 없다.
19. 목록의 회색 글이 세 테마(dark · light · e-ink) 모두에서 읽힌다.
20. 목록이 입력창 위의 에이전트 이름표를 가리지 않는다.
21. **터미널(PTY) 모드는 그대로다:** 턴 중 타이핑에 대시보드 목록이 뜨지 않고 에이전트 TUI 자신의 대기 표시만 보이며, 입력 바이트가 오늘과 같다(기존 터미널 회귀가 초록).
22. 에이전트 간 우편은 목록에 오르지 않고 오늘과 같은 시점·모양으로 전달된다.
23. 완료 판정은 GUI 실측(`/qa full`)으로 한다 — 테스트·타입체크 통과만으로는 완료가 아니다.

## 6. 거부한 대안 (사용자 사유 — 새 ADR 「거부한 대안」으로 옮긴다)

괄호 안 기호는 조사 보고서·TRD 가 쓴 이름이다. 이 문서만 읽어도 뜻이 통하게 풀어 적는다.

- **보낸 자리에 정식 말풍선을 고정한다**(오늘 claude 동작 · ADR-0198 원안 · 조사의 B) — 턴 도중이면 앞 답의 나머지가 그 아래로 이어져 순서가 섞인다.
- **대화 맨 아래(흐르는 답 아래)에 회색 대기 행을 둔다**(조사 보고서의 추천안이었던 A) — 사용자: 「터미널이 가장 자연스럽다」.
- **턴이 끝날 때까지 우리가 붙든다**(오늘 codex 동작) — 사용자: 「당연히 도구 호출 끝나면 바로 푸쉬」.
- **우리가 붙들고 있다가 도구가 끝난 것을 보고 넘긴다**(TRD 의 S1) — 한 걸음 늦다. 에이전트는 도구가 끝나자마자 자기 대기함을 확인하므로, 그 뒤에 넘긴 글은 그 경계를 놓치고 다음 도구가 끝나야 읽힌다(사용자 확인). ★**codex 는 Phase 0 실측이 이 사유를 뒤집었다**★ — 도구 끝 뒤에 넘겨도 10 번 중 10 번 같은 경계에 맞았다(창 6–64 ms · 우리 데몬 반응 시간 미측정 · TRD §10-2). 결정은 그대로이고 사용자 재확인 대기다. claude 는 사유대로다(0/10).
- **에이전트 훅이 도구가 끝날 때마다 우리 대기분을 당겨가게 한다**(TRD 의 S4) — 사용자: 「훅마다 매번 뭔가 실행하면 안 된다」.
- **지금 백엔드별로 가른다 — codex 는 우리가 붙들었다가 도구가 *시작될 때* 넘겨, 그 전까지 ✕ 를 살린다**(TRD 의 S5 · TRD 본문의 옛 권고) — 공통 동작을 먼저, 세분화는 나중이다(→ §7).
- **대기분을 이어 붙여 한 번에 보낸다** — 백엔드마다 편법이 필요하고, 받자마자 넘기면 모아 둘 대기분이 애초에 없어 의미가 없어진다. (조사 보고서 §5 는 「항목별 id 가 하나로 뭉개져 합치기가 깨진다」를 덧붙인다.)
- **참고 — 조사 단계의 거부 후보**(사용자 결정이 아니라 조사 보고서 §5 의 판단): 턴 중 보내기 막기(현재 에이전트 도구 관행과 반대이고 claude 경로는 이미 허용 중이라 퇴행) · 글 내용을 비교해 화면 말풍선과 에이전트 쪽 사본을 짝짓기(ADR-0198 이 이미 기각 — 두 백엔드 모두 항목 id 가 있다).

## 7. 미룬 것 (지금은 비목표 — 나중 후보)

- **취소·못 보낸 글을 입력창으로 되돌리기** — 그리고 여러 개일 때 입력창에 붙이는 규칙(덮어쓰기 · 이어 붙이기).
- **codex 항목별 취소** — 참고: Codex TUI 는 Enter = 진행 중 턴에 끼워 넣기 / Tab = 턴 끝까지 기다리기로 갈라 둔다.
- **Esc 키 바인딩** — 취소가 이미 등록된 명령이라 묶기만 하면 된다.
- **넘기는 시점의 백엔드별 세분화** — 예: codex 는 우리가 붙들었다가 도구가 시작될 때 넘기기.
- **「지금 보내기(Send now)」 — 도는 턴을 끊고 이 글을 즉시 보낸다.** 선례: Claude Code Ctrl+Enter = 끊고 지금 보냄(2.1.275↑) · Esc = 끊고 대기분을 다음에 보냄 · Up = 대기분을 입력창으로 되가져오기 · Cursor 도 Ctrl+Enter 끊기와 Send now 를 둔다(불확실 — changelog)(조사 보고서 §2-1 · §2-2). 이 기능에는 끊고 보내는 길이 없다. 사용자가 2026-09-25 밤에 질문으로만 올렸고 결정은 없다(끊기 조작 자체는 §9 Q5 와 묶인다).
- **데몬 재기동 뒤 목록 보존** — 대기분은 에이전트와 함께 사라진다(오늘 입력 큐와 같은 등급).

## 8. 위험 · 모르는 것

- **R1. ★claude 쪽은 벤더 내부용 표면에 기대고, 우리 스폰 모드에서 아직 안 쟀다★.** 항목별 받음 알림과 취소 요청 둘 다 그렇다 — 안 되면 §3 의 claude 동작(목록 · ✕)이 바뀐다. 측정 결과가 사용자 체감을 바꾸면 사용자 결정으로 다시 올린다. — 가능성 높음 · 미실측. 상세 = TRD §3-1 · §3-3(M1–M4).
- **R2. ✕ 에 claude 가 「못 뺐다」고 답해도 「전달됐다」는 뜻이 아니다**(취소를 예약해 두고 나중에 확정하기도 한다) — 그래서 ✕ 의 결말은 뒤이은 알림으로만 정한다(§3-6). — 가능성 높음 · 미실측(M3). 상세 = TRD §3-1.
- **R3. codex 항목은 사실상 거둘 수 없다** — 벤더에 항목 하나를 빼는 수단이 없고, 전부 버리는 턴 끊기도 오늘 채팅 뷰엔 없다(§2). 오타도 그대로 모델에 간다. 두 백엔드의 체감이 여기서 갈리고, ADR-0192 「못 맞추면 보고」의 대상이다. — 가능성 높음(소스) · 끊기 조작 부재는 확실(코드). 끊기를 들일지는 §9 Q5.
- **R4. 답 없는 글은 생기면 안 된다(§3-1 요구)** — codex 는 턴이 끝나는 찰나에 들어간 글을 답 없이 기록만 하는 벤더 동작이 있어, 설계가 이를 두 번 넘기지 않고 막을 수 있는지는 TRD 위험(M6)이다. 측정 결과가 사용자 체감을 바꾸면 사용자 결정으로 다시 올린다.
- **R5. 이어받기 복원에서 claude 의 턴 중 입력이 빠질 수 있다** — 이어받은 뒤 그 말풍선이 복원 이력에 없을 수 있고, 이 기능이 그 경우를 흔하게 만든다. 측정 결과가 사용자 체감을 바꾸면 사용자 결정으로 다시 올린다. — 불확실(M5). 상세 = TRD §3-1.
- **R6.** 벤더 전제(claude 받음 알림 · codex 항목 id 되울림 — codex 0.140.0 이상)가 없는 버전에서의 폴백은 **TRD 가 선택지를 내고 사용자가 고른다.**
- **R7. 턴 도중 보낸 슬래시 명령(「/compact」 등)은 특별 취급하지 않는다** — 다른 글처럼 넘기며, 에이전트가 그것을 명령으로 실행하는지·턴 끝까지 미루는지·받음 알림을 내는지는 미측정이다(Claude Code 문서는 명령·셸 입력을 턴 끝까지 보류한다고 적는다 — 우리 모드에서 같은지는 모른다). **나쁜 경우:** 벤더가 명령을 턴 끝까지 보류하거나 항목별 받음 알림을 내지 않으면, 그 항목은 받음이 안 와 에이전트가 끝날 때까지 회색으로 목록에 남는다(§3-4). 그 동안 목록이 비지 않으므로 에이전트는 §3-5 의 한가가 아니고, 이후 보낸 글도 전부 목록을 거친다(AC1 상실). 「도는 턴 없음 + 목록 안 빔」 상태의 머리줄 문구는 TRD·§9 Q4 몫이다. 측정 결과가 사용자 체감을 바꾸면 사용자 결정으로 다시 올린다.

## 9. 열린 질문 (새로 드러난 것만 — §2·§3 의 결정은 다시 묻지 않는다)

각 항목 = 질문 · 선택지 · 추천(있으면) · 왜 중요한가.

- **Q1. 이 창의 사용자가 직접 하지 않은 제거·실패를 알리나.** 해당 경우: ① 못 보내 버려짐(끊기 · 에이전트 종료 · 거절 · Q8 에 따라 오류 턴) ② ✕ 가 경합에서 짐(이미 전달됨) ③ 다른 창이나 LLM 이 취소함 ④ 한가할 때 보낸 글이 말풍선이 그려진 뒤 백엔드에 거절됨(1차 리뷰 지적 — 오늘은 말풍선이 그대로 남는다고 한다 · 미확인).
  - **알릴지:** (a) 알림 없이 사라진다 · (b) 경우마다 한 줄 알림(예: 「전달 안 됨」) · (c) 글이 모델에 **안 간** 경우(①·④)만 「전달 안 됨」 한 줄, ②는 말풍선이 뜨는 것 자체가 알림이라 따로 없음, ③은 조용히. **추천 (c)** — 사용자가 모르는 새 글이 모델에 안 갔다는 사실만은 다른 수단으로 알 길이 없다.
  - **④ 의 말풍선을 어떻게 하나:** (a) 말풍선을 지운다 · (b) 말풍선을 남기고 「전달 안 됨」 표시를 단다 · (c) 오늘처럼 그대로 둔다. **추천 (b)** — 지우면 무엇이 안 갔는지 모르고, 그대로 두면 모델이 받은 글처럼 보인다. 이 답 전까지 ④는 §5-5 에서 뺀다.
  - **알림의 자리:** (a) 대화 안 한 줄 · (b) 목록 자리 · (c) 토스트. **추천 (a)** — 모든 창과 LLM 이 같은 것을 보고 흘러가 버리지 않는다.
  - **알림의 공유·유지:** 모든 창이 같은 알림을 보고 앱 재시작에도 남나 — (a) 예 **추천**(목록과 같은 원칙 — §3-3) · (b) 알림은 그 창에서만 한 번.
  - **버린 글을 알림에 보이나:** (a) 알림 문구만 · (c′) 버린 글 전문을 함께 보여 사용자가 복사할 수 있게. **추천 (c′)** — 입력창에 넣지 않으므로 §3-7 「버린다」와 충돌하지 않고, §7 에 미룬 「입력창 되돌리기」 없이도 글을 잃지 않는다.
  - 왜: 알림이 없으면 「보냈다」고 믿고 답을 기다린다. **묶임:** Q5 가 「끊기 조작을 넣는다」로, Q8 이 「버린다」로 가면 ①이 자주 생겨 이 답의 무게가 커진다.
- **Q2. codex 연결·이력 복원 중 항목에도 ✕ 를 안 붙이나.** 그 동안은 아직 우리가 쥐고 있어 기술적으로 거둘 수 있다 — codex 에서 ✕ 를 뺀 사유(넘긴 글 하나를 거두는 수단이 없다)가 이 구간엔 해당하지 않는다.
  - 선택지: (a) 그 구간에만 ✕ 를 준다 · (b) codex 항목은 늘 ✕ 없음(결정 문구 그대로).
  - **추천 (b)** — (a)는 연결이 끝나는 순간 같은 항목의 ✕ 가 사라지는 흔들림을 만들고, 「codex 는 거둘 수 없다」 한 규칙이 단순하다.
  - 왜: 이어받기 직후 오타를 친 사용자가 거둘 수 있느냐가 갈린다. **묶임:** (a)면 Q7 ③의 codex 안내 문구가 「연결 뒤엔 거둘 수 없다」로 바뀐다.
- **Q3. 접힌 목록.** 세 갈래가 묶여 있다.
  - ① 「외 N개」를 펼칠 수 있나 — (a) 누르면 펼침 **추천** · (b) 접힌 채. (TRD 초안은 (a)를 내부 선택으로 적었으나 체감 동작이다.)
  - ② 접혔을 때 보이는 3개 — (a) 가장 오래된 3개(「오래된 것이 위」와 같은 방향 — 곧 전달될 것이 보인다) **추천**(①-(a)와 함께일 때) · (b) 가장 최근 3개(방금 친 글과 그 ✕ 가 보인다).
  - ③ 잘린 항목의 전문 보기 — (a) 마우스를 올리면 전문(툴팁) **추천** · (b) 없음.
  - 왜: ①-(b)와 ②-(a)가 만나면 방금 친 claude 항목의 ✕ 에 화면에서 닿을 길이 없다. 잘린 한 줄만으로는 무엇을 취소하는지 모를 수 있다.
- **Q4. 도구가 안 도는 턴 도중(모델이 쓰거나 생각하는 중)의 머리줄.**
  - 선택지: (a) 늘 「도구 호출이 끝나면 전달」(결정 문구 그대로) · (b) 그때는 둘째 문구(예: 「응답이 끝나면 전달」)로 바꾼다.
  - **추천 (b)** — 도구가 안 도는 동안 첫 문구는 사실과 다르다.
  - 왜: 문구가 사실과 다르면 「도구가 없는데 왜 안 가지」로 헷갈린다.
- **Q5. 채팅 뷰에 턴 끊기 조작을 이번 범위에 넣나.**
  - 선택지: (a) 넣는다 · (b) 넣지 않는다 — 별건.
  - **묶임 — (a)면 이어서 정할 것:** 끊을 때 claude 대기분을 (i) 버린다(§3-7 그대로) · (ii) 다음 턴으로 보낸다(Claude Code 의 Esc 식 — ★§3-7 의 「끊기로 못 보낸 것은 버린다」를 claude 에 한해 바꾸는 것이다★). codex 대기분은 어느 쪽이든 벤더가 버린다. claude JSON 은 끊기 자체가 아직 지원되지 않아(§2) (a)는 그 작업을 함께 안는다. §7 「지금 보내기」도 이 답 위에 선다.
  - **추천 (b)** — 끊기는 이 기능 없이도 필요한 별개 조작이고, claude 쪽은 끊기 지원부터 새로 들여야 해 범위가 커진다. 대가는 R3(codex 항목은 사실상 못 거둔다)이 그대로 남는 것이다.
  - 왜: codex 항목을 거둘 유일한 수단이 이것이다.
- **Q6. 이어받기 복원 갈래에서 대기분.** ★전제 정정: 이어받기가 실패하면 에이전트는 종점으로 끝나고 새 대화로 자동 전환하지 않는다(ADR-0082)★ — 그 경우 대기분은 §3-7(에이전트 종료)대로 버려지므로 「실패 뒤 새 대화로 보낸다」 갈래는 생기지 않는다. 남는 두 경우만 묻는다.
  - ① codex 대화는 이어받았는데 **화면 이력 복원만** 실패·중단됐을 때 「준비되면 전달」 항목 — (a) 그대로 전달한다 **추천**(대화 자체는 이어졌다) · (b) 붙든 채 알림을 띄워 사용자가 고르게 한다.
  - ② claude 가 이어받은 대화를 **불러오는 중에** 보낸 글 — (a) codex 와 같이 목록 + 「준비되면 전달」 · (b) 한가할 때처럼 곧바로 대화에 들인다. 추천 없음 — claude 쪽 로딩 중 입력이 벤더에서 어떻게 처리되는지 미측정이다.
  - 왜: 복원 중 친 글이 어디에 서고 언제 가는지가 이어받기 직후 첫 경험이다.
- **Q7. 세부 화면 기본값 — 각각 따로 예/아니오.**
  - ① ✕ 를 누른 뒤 결말 대기 중인 항목 = 흐리게 + ✕ 비활성.
  - ② ✕ 는 Tab 으로 닿고, 툴팁 「취소 — 글은 버려짐」.
  - ③ codex 목록엔 「codex 는 보낸 글을 거둘 수 없습니다」 한 줄 안내.
  - 왜: 하나하나는 작지만 모두 사용자가 보는 모양이다. **묶임:** ③의 문구는 Q2(연결 중 ✕)와 Q5(끊기 조작 — 넣으면 「턴을 끊으면 전부 버려집니다」 같은 덧붙임이 생긴다)의 답에 따라 바뀐다. ②의 ✕ 도달 경로는 Q3 의 답과 엮인다.
- **Q8. 오류로 끝난 턴(요청 한도 · 과부하 · 맥락 초과)에 걸린 글.** 오늘 채팅 뷰엔 끊기 조작이 없으니(§2) 실제로 턴을 멈추는 것은 이것뿐이다. 두 갈래를 따로 묻는다.
  - ① **목록에 남은 항목** — (a) 버린다(끊기와 같게 — §3-7) · (b) 다음 턴으로 넘긴다(§3-1 의 턴 끝 규칙과 같게 — 위험: 또 실패하는 턴을 연다).
  - ② **그 턴에서 이미 말풍선이 됐는데 답을 못 받은 글(한가할 때 보낸 글 포함)** — (a) 그대로 둔다(말풍선만 남고 후속 턴을 열지 않는다) · (b) 그 글에 답하는 후속 턴을 연다(같은 글을 두 번 그리거나 넘기지 않고 — §3-1) · (c) 말풍선에 「답 못 받음」 표시만 단다(Q1 과 묶임).
  - 추천 없음 — 오류 종류마다 결과가 다르다(맥락 초과는 다음 턴도 실패하기 쉽고, 일시적 과부하는 다음 턴에 성공할 수 있다). claude 는 벤더가 실패한 턴의 대기분을 스스로 취소할 수 있어(TRD §3-1) 선택이 벤더 동작에 묶일 수 있다 — 미측정.
  - 왜: 이 답 전까지 이 경우는 §5-5 의 「전부 답을 받는다」에서 빠져 있다. **묶임:** (a)면 Q1 ①의 알림이 이 경우에도 걸린다.
- **Q9. 턴이 끝날 때 남은 항목 여럿을 다음 턴에 어떻게 들이나.**
  - 선택지: (a) **한** 다음 턴에 따로따로(각자 말풍선) 함께 들인다 · (b) 항목마다 턴을 하나씩 준다.
  - **추천 (a)** — 뒤 글이 앞 글을 고치는 경우(A 다음 B 「아니 그거 말고」)에 (b)는 B 를 보기 전에 A 대로 한 턴을 돈다. (a)도 이어 붙이지 않고 메시지를 따로 두므로 §3-8 과 충돌하지 않는다.
  - 왜: 교정 지시가 이 기능의 대표 사례라 순서대로 한 턴씩이면 교정이 한 턴 늦는다. **주의:** claude 는 이 묶음을 벤더가 정하고(미측정) codex 는 우리가 정한다 — 고르는 것은 codex 쪽만 보장하고 두 백엔드가 어긋나지 않는다는 보장은 못 된다. claude 는 고른 쪽과 측정 결과가 다르면 다시 올린다(ADR-0192 — 못 맞추면 보고).

## 10. TRD · QA · ADR 로 넘기는 것

- **「어떻게」는 전부 TRD:** 목록을 어느 층이 쥐나 · 받음 판정과 창·LLM 이 같은 목록으로 수렴하는 규칙 · 명령 이름·인자 · 창이 다시 붙을 때 목록 맞추기 · 답 못 받은 항목을 두 번 넘기지 않고 답받게 하는 법(M6) · 벤더 버전 탐지와 폴백 선택지 · 측정 M1–M8 · 시험 계획.
- **TRD·QA 로 넘기는 게이트:** 새 전역 핸들을 늘리지 않는다(`CLAUDE.md 「LLM-우선 제어」` — 기존 명령 표면에 얹는다) · 터미널 모드 입력 바이트 동일 회귀.
- **TRD 는 2판(2026-09-25)에서 이 결정들로 개정됐다** — codex 「도구 시작에 넘기기」 권고(S5)·모든 항목의 ✕·「못 보낸 글은 입력창으로 돌아온다」가 본문에서 걷혔다.
- **ADR:** 새 ADR 하나(미채번) — 결정 = §2·§3, 거부한 대안 = §6. 개정 도장 후보 = ADR-0044 · 0045 · 0193 · 0198 · 0226(구체 조항은 TRD §8).
- **순서:** §9 사용자 답 → TRD `/review trd` · 사용자 확정 → ADR → 구현(TRD §9).
