05실제로 실행되는 것

argv 는 네 인자뿐이고, 실행 파일은 이름으로 부른다

cmd.exe /c codex --cd <고른 폴더> -s workspace-write -a on-request [extra_args…]
  • Windows 는 cmd.exe /c 를 한 겹 씌운다 — PATH 의 codex 가 .cmd → node → 실 바이너리로 이어지는 shim 사슬이라서다.
  • 실 경로로 부르지 않고 이름으로 부른다 — 벤더 바이너리가 버전에 묶인 경로에 있고 codex 가 스스로 업데이트해 그 경로를 옮긴다.
  • extra_args 는 항상 마지막에 붙는다 — 호출자가 우리 인자를 덮을 수 있게. 이 순서는 단위 테스트가 고정한다.
  • 우리가 발급한 sid 를 넘기지 않는다 — 「argv 에 절대 안 실린다」가 아니다. extra_args 는 그대로 통과하므로 호출자가 넣으면 실린다. 전용 테스트가 단언하는 것은 빈 extras 기준으로 sid·--session-id·--resume·--session 이 조립되지 않는다는 것이다.
안 고친 한계: cmd.exe 는 따옴표 안에서도 %NAME% 을 확장한다. 폴더 이름에 % 로 감싼 낱말이 실제로 들어 있으면 codex 는 다른 폴더를 받는다. 고치려면 claude 와 공용인 조립 지점을 건드려야 하고 틀리면 모든 스폰이 죽는다 — 사유는 코드 주석이 정본이다.

06렌더 분기

프론트에 codex 코드가 한 줄도 없는 이유

렌더러는 백엔드 이름을 보지 않는다. capability 한 칸만 본다 — 그 칸은 transport 가 소유하고, PTY 는 false 를 보고한다.

  • 이 그림은 축 하나를 생략했다 — 첫째 축은 renderModeOverride 이고, override 가 없을 때 비로소 위 칸이 갈린다. 위 그림은 override 없는 기본 경로다.
  • 실행 중인 codex 는 claude 터미널과 화면상 구별되지 않는다. wire 의 AgentInfo 에 backend 칸이 아예 없고, 프론트 프로덕션 코드는 프로필의 command 를 읽지 않는다. 배지·아이콘·툴팁 어느 것도 없다.
  • 이 구별을 붙이는 것이 Phase 2 의 「배너」 항목이다 — 지금은 없는 게 아니라 안 만든 것이고, 타입 주석이 「화면 분기에 백엔드 이름을 쓰지 말 것」으로 못 박아 뒀다.

08닫힌 문

사람은 통과하고 LLM 은 반려된다 — 문이 셋이었다

사유 — codex 는 처음 보는 폴더에서 자기 신뢰 확인 모달을 띄우는데 사람이 아닌 호출자는 그 모달을 못 지난다(키를 넣어도 안 먹는다 — 실측). 지금 창구를 열면 “만들 수는 있는데 쓸 수는 없는 에이전트”가 생긴다. 여는 시점 — Phase 2, codex 신뢰 확인 모달 처리가 정해질 때. ★사유와 여는 시점은 항상 함께 적는다★ — 코드가 그렇게 못 박아 뒀다(LlmBackendPolicy.refusal 의 doc). 그래서 정책 표 한 곳이 세 문에 동시에 읽힌다.

  • 문 3 은 오늘 발화하지 않는다 — 선언 어휘가 Claude 하나뿐이어서 역직렬화가 먼저 거절한다. 구조적 사각이고, 어휘가 늘면 그때 이 팔이 살아난다.
  • 표에 없는 낱말은 반려가 기본값이다(fail-closed). 셋째 백엔드가 정책을 안 적으면 조용히 열리는 게 아니라 막힌다.

09wire 계약

프로토콜을 4 로 올린 이유는 “출시 전”과 무관하다

왜 경성 파손인가

스폰 명령은 kind 태그로 갈리는 열거형이다. Codex 추가는 변형 추가이고, 모르는 변형은 무시되지 않고 역직렬화 실패가 된다.

왜 로컬에서 터지나

데몬이 셸 재빌드보다 오래 사는 것은 설계다. 그래서 “릴리스 상대가 없다”가 이 실패를 막아 주지 않는다 — 개발 중에 온다. 다만 그 만남은 조용하지 않다 — 아래 표가 그 결말이다.

조합증상
새 데몬 + 옛 셸discovery 가 먼저 거부한다 — daemon.json 의 protocol_version 이 갈리면 check_acceptable 이 살아있는 데몬을 spawn 으로 덮지 않고 DiscoveryError::VersionMismatch 로 실패한다
옛 데몬 + 새 셸같은 거부다 — 그 판정이 보는 것은 같은지 다른지뿐이라 어느 쪽이 새것인지를 묻지 않는다
  • ★버전 4 인상의 값어치는 「조용한 오작동」이 아니라 「분명한 거부」다★ — 안 올렸으면 두 빌드가 악수를 지나 서로 다른 낱말을 같은 것으로 읽었을 자리에서, 지금은 연결 자체가 사유와 함께 실패한다. 파싱 실패 서술은 악수를 지난 경우의 이야기이고, 그 축의 실물은 아래 디스크 항목이다 — 모르는 kind 가 한 건이라도 있으면 파싱 전체가 실패하고 명부가 통째로 사라진다.
  • backend 칸은 필수다 — 형식상 기본값이 있지만 핸들러가 빈 칸을 거부한다. 「안 적으면 claude」 같은 조용한 기본값을 두지 않았다.
  • claude_session_id → backend_session_id 는 shim 없는 하드 rename이다(디스크·wire·API 동시). 이름이 더 이상 “누가 id 를 발급하나”를 말하지 않게 하려는 것이다 — claude 는 우리 것을 받고, codex 는 자기가 만들어 알려 준다.
  • 디스크 하위호환은 수용했다 — codex 프로필이 kind:"Codex" 로 박히므로 옛 빌드로 되돌리면 명부를 잃는다. 재도입 트리거는 「그 빌드가 릴리스로 나가는 순간」으로 추적표에 걸려 있고, 미지 kind 회귀 테스트는 여전히 0 건이다.
