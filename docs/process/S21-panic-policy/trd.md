## 0. 결론

```
① 가둘 수 있는 단위(기준 넷 — §4-1)만 입구에서 가둔다 → 그 요청 · 그 에이전트만 실패한다.
② 그 밖의 패닉 = 사유를 로그하고 곧바로 프로세스를 끝낸다 — 오늘 배포판 abort 와 같은 결과.
   정상 종료 꼬리 · 감시 스레드 · 깨우기 같은 장치는 없다.
③ 둘을 가르는 것은 스레드 지역 「표시」 하나다. 훅은 되감기 전에 돌므로, 표시 없이는 가둘 패닉까지 끝낸다.
④ 순서 = 표시 원시 → 입구 → 훅 → 오염 · 여러 걸음 구간 → abort 전제 감사 → 프로필 한 줄(§5).
   앞 단위들은 abort 아래 아무 일도 하지 않는다 — 어디서 멈춰도 배포판은 오늘과 같고, 문제가 나면 마지막 한 줄만 되돌린다.
```

## 2. 현황 (실측)

- **프로필:** `Cargo.toml:39-44` `[profile.release]` — `panic = "abort"`(`:40`). 워크스페이스 유일이라 데몬 · 셸 · CLI 가 함께 바뀐다. debug · 시험 빌드는 이미 unwind 다.
- **훅:** 데몬에만 있다 — `daemon/src/lib.rs:129-151`(로그 + 이전 훅) · 설치 `:458`(로깅 초기화 `:453` 뒤) · 부르는 곳은 운영 `daemon/src/main.rs:13` 하나라 시험 서버에는 훅이 없다. 셸 · CLI 에는 없다. std 의 훅은 **패닉한 스레드에서, 되감기 전에** 돈다.
- **로그 자기교착(알려진 미수정):** 로그 파일 Mutex 를 쥔 채 패닉하면 훅의 로그가 자기를 기다린다 — `base/src/logging/mod.rs:110-115`.
- **이미 있는 `catch_unwind`:** 펌프 셋 · 라이터 · codex 첫 턴 기록 · claude 잔여물 정리 · reaper · sweep · 버스 `guard_panic`(`command/src/route.rs:23`) 등(자리는 §4-4). 배포판은 abort 라 지금 하나도 잡지 않는다.
- **락 오염:** agent 운영 코드에 base `sync` 의 말없는 되찾기 ≈76 · `.expect("…poisoned")` ≈55(10판 어림). `sync` 헤더 계약 3(`base/src/sync.rs:10-11`)은 「운영 빌드는 오염에 닿지 않는다(abort)」를 전제한다.
- **abort 전제 기록:** 코드 57줄 · 30파일 + ADR 일곱 + TRD 여럿 — 목록과 정규식은 10판 §2-8.
- **셸:** 운영 `catch_unwind` 0 · 락 오염은 `.lock().map_err(…)` 로 오류 값이 된다(28곳 — 10판 실측). 데몬이 보낸 버스 명령도 `command::route` 를 탄다.
- **CLI:** 단일 스레드(`cli/src` 에 스레드 · tokio 없음).
- **종료 코드:** 운영 코드에 프로세스 종료 코드를 판정하는 곳이 없다(셸은 소켓 · portfile 로 데몬을 본다).

### (가) 락 오염 — 「가둔 패닉이 쥐고 있던 락을 다음에 누가 만나면」

가둔 패닉이 락을 쥔 채 나면 그 락은 오염된 채 남는다. 지금 코드에서 그다음은 자리마다 갈린다 — `sync` 자리는 반쯤 바뀐 데이터로 말없이 계속, `.expect` 자리는 다시 패닉한다(표시 안이면 그 요청도 실패 · 밖이면 즉시 종료).

| 안 | 규칙 | 사용자가 겪는 것 | 비용 |
|---|---|---|---|
| A 그대로 | 손대지 않는다 | 같은 버그가 다음에 어느 코드가 그 락을 만나느냐에 따라 조용히 계속되거나 데몬이 꺼진다. 명부(`agent/src/reaper.rs:54`) · 프로필 저장소(`agent/src/persistence/mod.rs`)는 말없이 계속 — ADR-0290 이 거부한 「조용히 살리기」 | 0 |
| **B 공유 락만 종료(권고)** | 공유 락(명부 · 프로필 · 제어 레지스트리 · 메시징 표 · 사용량 · 추적기 · 이름 할당 — 목록은 구현 때 확정)을 여는 자리에서 오염을 만나면 즉시 종료. 단위 자기 락(세션 · 출력 코어 · 통로 · codex 상태 · 입력 큐 · 연결 구독)은 그대로 | 공유 상태가 반쯤 바뀐 채 도는 일은 없다. 단위 락의 오염은 그 단위와 함께 버려지거나, 표시 밖 코드가 그 락의 `.expect` 를 만나면 즉시 종료(안전한 쪽 — 예: 펌프가 출력을 내보내다 패닉하면 `finish` 의 `.expect`(`agent/src/output_core.rs:692`)가 표시 밖에서 다시 패닉) | 작음~중간 — 공유 락 자리 수십 곳 · 대부분 기계 치환(수는 불확실) |
| C 넓게 | B + 단위 락의 `.expect` 를 되찾기로 | 한 에이전트 버그가 데몬 종료로 번지는 일이 B 보다 적다. 대가 — 그 에이전트가 반쯤 바뀐 자기 상태로 계속 돈다(끄고 켜면 낫는다) | 중간 — B + ≈100곳(`output_core.rs` 27 · `pty.rs` 6 …) |
| D 전부 종료 | 어떤 락이든 오염 = 즉시 종료 | 규칙이 가장 단순하다. 대가 — codex 통로는 상태를 거의 늘 락 안에서 다루고 되감기 중 그 락을 다시 잡아(`agent/src/backend/codex/transport.rs:2901` → `:2918`) codex 에이전트 패닉 대부분이 데몬 종료 | 작음 |

- 권고 B — ADR-0288 의 가름(에이전트 하나 대 공유 상태)을 락 단위로 옮긴 것이고, 가장 작은 손으로 「공유 상태는 조용히 살리지 않는다」를 지킨다. C 는 B 뒤 로그에 단위 락 연쇄 종료가 실제로 보일 때(트리거).

### (마) 가둔 패닉의 고지 모양

| 층 | 권고 | 대안 |
|---|---|---|
| 요청 — WS 명령 · 제어 HTTP · MCP 도구 | **N1a 오류 답 · 연결 유지** — WS = 그 `request_id` 의 `Error`(「internal error: <패닉 문장>」 — 영어 사유 · 가안) · HTTP = 500 + 같은 문장 · MCP = 도구 오류 결과 | N1b 연결을 닫는다(답 없음 · 같은 연결의 다른 진행 중 명령도 잃는다) |
| 요청 — 버스 명령 | (정해져 있다 — ADR-0159) `INTERNAL` · 전달 중이면 `OUTCOME_UNKNOWN` | — |
| 에이전트 | **N2a 지금 표면** — 펌프 = 그 에이전트 `Failed`(「pump panicked: …」) · 라이터 = 입력 거절 사유 | N2b 띠 알림 더함(새 고지 장치 — ADR-0288 이 미룬 무리) |

- 권고 N1a · N2a — 새 화면 장치가 없다. 버스 명령이 이미 하는 일(값으로 답한다)을 나머지 요청에 맞춘다. 즉시 종료는 지금의 「데몬 꺼짐」과 같게 보인다(사유 안내 없음 — 미룬 장치).
- `request_id` 를 읽기 전에 난 패닉은 답할 곳이 없다 — 그 프레임만 버려진다(사유는 훅이 로그).

### (사) 끝내기 수단

| 안 | 결과 | 비용 |
|---|---|---|
| **abort — `std::process::abort`(권고)** | 오늘 배포판과 같은 끝(Windows 종료 코드 `0xC0000409` — `command/src/testing.rs:25-27` 의 실측 주석) | 새 코드 0 · std 뿐이라 base · 메시징 커널 · command 어디서나 부른다 · 전환 전후 겉모습이 같다 |
| 자기 `TerminateProcess`(코드 101) | DLL 분리 알림 없이 끝 · 종료 코드를 고를 수 있다 | platform 도우미 하나(OS 코드 — ADR-0266) · 의존 0 crate(메시징 커널 · command)는 부를 수 없어 조립부가 주입 · U3 부터 배포판 종료 코드가 101 로 바뀐다 |
| `process::exit(101)`(권고 안 함) | — | `ExitProcess` 가 다른 스레드를 먼저 끝낸 뒤 DLL 분리 알림을 돌아 거기서 멎을 수 있다(MS 문서 순서 · 가능성 높음 · 실측 아님) |

- 묶임 — (가)=B · C · D 면 메시징 커널(의존 0)도 오염을 만나 끝내야 한다. abort 면 그대로 부르고, `TerminateProcess` 면 주입 seam 이 하나 는다.
- 두 안에 대한 Windows 오류 보고(WER)의 반응이 다른지는 모른다(불확실) — abort 쪽은 오늘과 같다.

## 4. 설계

### 4-1. 가둠 기준

넷이 모두 설 때만 가둔다. 하나라도 빠지면 가두지 않는다 → 즉시 종료.

1. 그 일 단위의 **가장 바깥 입구**다.
2. **실패를 알릴 길**이 있다(오류 답 · `Failed` 상태 — (마)).
3. 그 단위가 **자기 상태만** 만진다. 공유 상태는 락 하나 안의 한 걸음까지 — 그 락의 오염은 (가)가, 락 밖 여러 걸음 변경은 (나)가 표시를 꺼서 맞춘다.
4. 그 단위를 버린 뒤 **나머지가 멀쩡**하다(매달리는 스레드 · 차오르는 파이프가 남지 않는다).

### 4-2. 표시 — base 새 입주자 `panic`(가안)

- 스레드 지역 깊이 하나(const `Cell` · `try_with` — 스레드 해체 중에도 읽힌다 · 못 읽으면 「표시 없음」).
- 원시(이름 가안): 동기 입구 `contain(f) -> Result<T, Caught>` · 비동기 입구 `Contained<F>`(poll 마다 깊이를 올린다 — 태스크는 스레드를 옮겨 다닌다 · 패닉한 future 는 다시 poll 하지 않고 표시 안에서 drop) · 표시를 끄는 구간 `escalating(f)`(깊이 0 · 잡지 않는다 — (나)) · 페이로드 → 문장(지금 사본 일곱 — 10판 §2-2).
- **표시는 스레드를 따라가지 않는다** — 가둔 단위가 띄운 스레드 · 태스크 · blocking 은 표시 밖이다(= 즉시 종료 · 안전한 쪽). 거기도 가두려면 그 입구에 따로 건다(§4-4 의 blocking 행들).
- **왜 표시가 있어야 하나** — 훅이 `catch_unwind` 보다 먼저 돈다(§2). 표시 없이 「잡히지 않은 패닉 = 종료」 훅을 걸면 입구가 잡으려던 패닉까지 끝낸다.
- 입주 조건(ADR-0269): 소비자 agent · 데몬 · 셸 + 페이로드 사본 · 도메인 지식 0 · 다른 입주자 무참조 — 게이트 ③ 정규식(CLAUDE.md 「빌드·검증 명령」 · `ci.yml` 사본)에 `panic` 을 더한다. command · 메시징 커널 · net 은 base 를 의존하지 않으므로 그 코드는 부르는 쪽(데몬)이 표시 안에서 부른다.

### 4-3. 훅 — 데몬 · 셸이 같은 것을 설치

```
패닉 → 훅(패닉한 스레드 · 되감기 전)
  ① 사유 줄을 로그한다(스레드 · 문장 · 자리 — 지금 데몬 훅의 줄) · 이전 훅(std 기본 — debug 의 stderr)을 부른다
  ② 표시가 섰으면 돌아간다 → 되감기가 입구까지 가서 실패로 접힌다((마))
  ③ 표시가 없으면 끝낸다((사))
```

- 훅 몸통은 base `panic`(가안)에 두고 끝내기를 인자로 받는다 — 시험이 프로세스를 죽이지 않게 · (사)=`TerminateProcess` 면 조립부가 platform 도우미를 넘긴다. 설치 = 데몬 지금 자리(`daemon/src/lib.rs:458`) · 셸 `run()` 머리(`src-tauri/src/lib.rs:28` · `Builder` 앞 — 셸 로깅 초기화가 그 뒤 `src-tauri/src/state/boot_plugin.rs:89` 라 그 앞 패닉은 사유 줄 없이 끝난다).
- **훅은 표시와 무관하게 로그한다** — 표시 밖 갈래가 어차피 로그하므로 자기교착(§2)은 로그 쪽에서 닫아야 하고, 닫고 나면 표시 안에서 조용히 할 까닭이 없다. 패닉 자리(파일 · 줄)는 훅에서만 보이므로, 안쪽에서 잡고 로그하지 않는 자리(버스 `guard_panic`)의 기록도 이렇게 남는다. 입구는 패닉을 다시 로그하지 않고 실패 표면만 낸다.
- **자기교착은 로그 쪽에서 닫는다** — base `logging` 파일 싱크에 스레드 지역 「이 스레드가 파일에 쓰는 중」 표지를 두고, 섰으면 그 줄을 버린다. 닫는 것은 같은 스레드 재진입뿐이다(나머지는 §7).

### 4-5. 셸 · CLI · 이어질 단계

- 셸 = (라)의 답. S1 이면 셸 코드는 표시를 하나도 세우지 않는다 — 훅 설치뿐.
- CLI = 훅 없음. 단일 스레드라 unwind 면 main 패닉이 곧 프로세스 끝(종료 코드 101 · 기본 훅 stderr) — 오늘 abort 와 겉으로 같다(가능성 높음).
- 다음 단계가 transport crate(`crates/engram-dashboard-transport`)를 셸 연결 층에 붙이며 새 연결 · 펌프 태스크를 들인다 — 그 태스크는 들어올 때 §4-1 기준과 §4-4 표를 따른다.

### 4-6. abort 전제 감사

- 표시 밖 코드는 「패닉 = 프로세스 끝」이 그대로 참이다(훅이 끝낸다). 전제가 무너지는 것은 **표시 안에서 도는 코드뿐**이라 감사 범위가 10판 §2-8 의 57줄보다 좁다 — §4-4 「표시」 행의 몸통 · base `sync` 계약 3(`base/src/sync.rs:10-11`) · 메시징 커널의 되돌림 Drop(`messaging/src/service.rs:2718` · `:3505` — 표시된 보내기 요청 R5 · R7 이 그 안에서 패닉하면 이것이 공유 표를 되돌린다 · 오염이면 말없이 건너뛴다 → (가) 답과 맞춘다) · ADR-0262 K7 의 막이 표시된 코드(R3 활성화 등)에서 도는지.
- 무엇을 보나: 「여기서 패닉하면 프로세스가 죽으니 정리는 필요 없다」에 기대 되감기 때 상태를 반쯤 남기는 자리 · 되감기 중 `Drop` 이 `.expect` 로 다시 패닉하는 자리(소멸자를 벗어나면 abort — ADR-0288 결정 4 로 간다).
- 「release=abort」를 글자 그대로 적은 주석 · 로그 문장(예: `messaging_host.rs:769`)은 「표시 밖 패닉 = 즉시 종료」로 고친다. 표시하지 않기로 한 자리의 기존 `catch_unwind`(reaper · sweep · leftover 등)는 운영에서 죽은 코드가 되지만 시험 빌드에는 훅이 없어 살아 있으므로 걷지 않고 주석만 고친다.

### 4-7. 프로필 전환

`Cargo.toml:40` `panic = "abort"` 한 줄을 지운다(기본 unwind). 앞 단위가 전부 abort 아래 무동작이라 되돌림 = 이 한 줄. 그래서 「abort 면 빌드를 멈추는」 컴파일 가드는 두지 않는다. 실행 파일 크기 변화를 이 단위에서 잰다(ADR-0288 「영향」이 재지 않았다고 적었다).

## 6. 시험 전략

- **훅은 프로세스 전역이고, 표시 밖 갈래는 프로세스를 끝낸다** — 그래서 둘로 나눈다.
  - **프로세스 안:** 훅 몸통을 끝내기 주입으로 부른다(U1). 전역 훅을 실제로 갈아 끼우는 시험은 한 자물쇠로 줄 세운다 — `command/src/testing.rs:8-30` `with_quiet_panic_hook` 꼴(되돌리기는 `Drop` 이 아니라 잡은 뒤).
  - **자식 프로세스:** 시험 바이너리가 자기 자신을 환경 변수 하나와 `--exact <시험 이름>` 으로 다시 띄운다. 자식은 실제 훅을 설치하고 (a) 표시 밖 패닉 → 부모가 「성공 아님으로 끝남 + 로그 파일의 사유 줄」 (b) 표시 안 패닉 → 「계속 돎」을 본다. 저장소에 이 꼴의 선례는 없다(새 꼴). 데몬 crate 에 둔다 — 그 crate 시험 줄은 이미 `--test-threads=4` 를 붙인다(CLAUDE.md 「병렬은 테스트 바이너리마다」).
- 입구 시험은 debug 에서 돈다 — 시험 빌드는 이미 unwind 라 U2 부터 바로 잰다.
- **배포판의 패닉 길 자체는 cargo 시험으로 못 잰다** — 시험 · 벤치 타깃은 프로필의 `panic` 설정을 무시한다(가능성 높음 — Cargo 문서). unwind 로 바뀐 뒤엔 debug 와 같은 코드라 debug 자식 프로세스 시험으로 갈음하고, U6 은 release 정상 동작 실측만 한다.

## 7. 남는 것 · 범위 밖

**받는 잔여(★ = 사용자 서명 필요):**

- ★**못 찾은 여러 걸음 공유 변경** — 표시 안에서 락 밖으로 공유 상태를 반쯤 바꾼 채 가둬지는 구간. (나)는 찾은 구간만 끈다.
- ★**유령 대기 입력** — `send_input` 이 `Queued` 를 낸 뒤 통로 쓰기에서 가둔 패닉이 나면 `Dropped` 가 안 나가(`agent/src/session.rs:303-311`) 대기 목록 표가 그 에이전트를 「바쁨」으로 세운다 → 그 에이전트로 가는 우편이 재시작까지 멈춘다(그 칸엔 30분 상한이 없다 — 사용자 결정 N8 · N11). 관측되면 그 구간을 (나)로.
- **팬아웃 seq 구멍** — 가둔 패닉이 `fan_out`(`agent/src/output_core.rs:351`) 가운데서 나면 남은 구독자는 그 seq 를 못 받는다 → 기존 replay 회복 길로 돈다.
- **훅의 로그가 멎는 경우** — 패닉한 스레드가 tracing 내부 락(reload · `EnvFilter`)을 쥔 채 나면 훅이 멎는다(오늘 훅과 같다) · 다른 스레드가 로그 락을 쥔 채 멎으면 훅도 기다린다(모든 로그 호출과 같다).
- **Rust abort 갈래** — 이중 패닉 · 소멸자를 벗어난 패닉 · FFI 건넘 · 셸 WebView2 COM 콜백(미검) = ADR-0288 결정 4.
- **표시 누락** — 새 spawn 이 표시 없이 들어오면 그 패닉은 즉시 종료(안전한 쪽).
- **부팅 중 결정적 패닉의 재기동 고리 · 셸 즉시 종료 뒤 트레이 아이콘이 마우스를 올릴 때까지 남음(추론)** — 오늘 abort 와 같다.

**지금 표시하지 않는 것** — PTY 감시 · stderr 배수 · codex 라이터 · claude 잔여물 정리 · 메시징 수신자 배달. 넣을 조건은 §4-4 각 행. 트리거 = 로그의 사유 줄에 그 자리가 실제로 나올 때.

**범위 밖:**

- 정상 종료(StopDaemon · 트레이 「데몬 끄기」)의 오염 내성 · 종료 시간 제한 · T-52 — 패닉이 그 길을 타지 않는다. 가둔 패닉이 오염시킨 락을 StopDaemon 이 만나면 그 끄기가 즉시 종료로 끝날 뿐이다(결과 = 데몬 꺼짐).
- ADR-0288 이 미룬 장치 — 셸 사유 고지 · 다음 부팅의 패닉 표시 · 셸 자동 재기동 · 에이전트 PTY 를 데몬 밖 프로세스로(거부됨).
