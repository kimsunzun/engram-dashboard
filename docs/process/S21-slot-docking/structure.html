구조

탭을 끌어 다른 창 슬롯의 상하좌우 · 탭바 · 새 창으로 옮긴다. 설계는 세 층이다 — ① 레이아웃 연산(셸 layout · OS 무관 · 모델 변경은 전부 여기) ② 끌기 세션(셸 신설 dock · 끌기 스레드 하나가 전경과 포인터를 읽어 판정 · 딱지 이동 · 가이드 지시 · 놓기를 한다) ③ OS 층(crate platform · 「이 점의 맨 위 창이 어느 것인가」 「포인터와 주 버튼」 같은 목적 단위 함수). 웹뷰는 시작과 떼기 힌트를 알리고 셸이 준 사각형을 그릴 뿐이다. 끌린 탭의 배치는 놓을 때 한 번만 바뀌고(끄는 동안 바뀌는 것은 탭 머리 위에 머물러 한 탭 전환 하나), 마우스 놓기와 LLM 명령 tab.dock 이 같은 적용 함수 하나를 지난다.

02구조

웹뷰는 그리고, 셸이 몰고, platform 이 OS 를 읽는다

invoke · 버스 — 셸로 들어오는 요청 emit — 셸이 그릴 것을 보냄 모델 변경 — 적용 서비스 하나로 OS 읽기 · 창 사건

dock 을 layout 밑에 두지 않는 이유 — 끌기 세션은 레이아웃 권위가 아니라 그 권위를 부르는 손님이다. 놓기도 적용 서비스를 부를 뿐이다. 도킹 결과는 기존 알림으로만 흐르고, 도킹 전용 결과 알림은 없다. ★ = 사용자 확인 대상(09 절 #3). 네이티브 이동 루프 · 창 서브클래스는 쓰지 않는다 — 끌기가 웹뷰에서 시작하므로 필요 없다.

04끌기 한 번

누르기부터 끝까지 — 모델은 한 번만 바뀐다

  1. 1 시작 — 실패할 수 있는 것을 먼저, 부수 효과는 나중 탭을 누르고 4px 넘게 끌면 웹뷰가 dock_drag_begin. 셸은 ① 값싼 거절(그 창이 주인이 아님 · 이미 끄는 중 · 메인의 마지막 탭) → ② 준비(딱지 창 확보 · 창 핸들과 기하 · 끌기 스레드) → ③ 락 한 번에 표식 세우기 + 출처 배치 복제 → ④ 그 뒤에야 부수 효과(탭 하나뿐인 팝아웃은 창째 안 보이게, 그 밖은 떼어진 표시 · dock:session Started · 딱지 보이기). ③ 이후의 실패는 되감기 가드가 정상 끝과 같은 순서로 거둔다.
  2. 2 틱 — 전경 → 포인터 → 판정 → 그리기 목표 8ms 마다(실제 주기는 OS 타이머에 묶일 수 있다 — 스파이크가 잰다). 전경이 확실히 다른 앱이면 곧바로 비정상 끝. 전경이 불명(창을 숨기거나 딱지를 보이는 순간의 빈 전경 · 잠금 화면)이거나 포인터를 못 읽으면 한 시계로 500ms 까지 기다린다 — 그동안의 「버튼 0」은 떼기로 치지 않는다. 버튼이 떼어졌으면 놓기. 아니면 딱지 이동 → 맨 위 창 → 짧은 락으로 판정 재료만 복사 → session.step → 바뀐 오버레이만 보낸다. 다른 탭 머리 위에 500ms 머물면 그 탭으로 바꾼다 — 끄는 동안 모델을 바꾸는 유일한 동작이다. 그 창의 활성 탭만 바뀌고(사람 탭 클릭과 같은 쓰기) 저장에도 실리며, 끌기가 무변경으로 끝나도 되돌리지 않는다. 끌린 탭의 배치는 그대로다.
  3. 3 놓기 판정 — 가이드 없는 자리는 새 창, 이음새 · 탭바는 보인 것과 같을 때만 떼는 순간 새로 뜬 스냅숏으로 그 점을 한 번 판정한다. 가이드가 없는 자리면 PRD 그대로 새 창이고, 이음새 · 탭바면 마지막으로 보낸 가이드와 같을 때만 적용한다 — 사용자가 못 본 이음새 · 탭바에 놓이는 일이 없다.
    떼는 점의 판정마지막으로 보낸 가이드결과
    (가장 먼저 본다) 끄는 중 출처 배치가 바뀜 — 딱지에 「안 됨」—무변경
    가이드 없음 — 슬롯 가운데 · 칠하지 않은 띠 · 우리 창 밖 · 다른 앱 위 · 바탕화면무엇이든 — 아직 하나도 안 보냈어도새 창 — 딱지 왼쪽 위 자리에
    이음새 · 탭바 자리 X같은 X적용 — 기대 배치 대조 · 놓은 창 앞으로 + 첫 슬롯 포커스
    이음새 · 탭바 자리 X다른 것 · 아직 안 보냄무변경
    떼는 점 = 버튼이 떼어진 것을 본 틱의 포인터. 웹뷰의 놓기 신호가 그 틱보다 먼저 오면 그때 포인터를 새로 읽어 그 자리로 판정한다(마지막 틱 위치는 최대 한 틱 늦다) — 새로 읽은 값을 믿을 수 없으면 판정 없이 비정상 끝. 무변경 = 모델이 끌기 전 그대로라 떼어진 표시만 거두면 탭이 출처 탭바에 다시 보인다. 가이드를 보낸 뒤 대상 배치가 바뀌었으면 적용 단계에서 모델이 무변경으로 거절한다. 문턱을 막 넘기고 캔버스 쪽에서 바로 떼면 새 창이 뜬다 — PRD 그대로이고, 거슬리면 QA 에서 문턱 값만 조정한다.
  4. 4 적용 — 적용 서비스 하나, 모드 셋
    이음새 · Seam

    슬롯 옆 · 바깥 변에 끼움

    • 대상 탭의 슬롯(또는 레이아웃 전체)을 새 분할로 감싼다
    • 새것 1/3 · 기존 2/3 — 감싼 쪽 안 비율은 그대로
    • 슬롯 id · 분할 id 는 그대로 옮기고 출처 탭은 지워진다
    락 한 번 · 변경 번호 한 번
    탭바 · TabBar

    그 창의 탭으로 넣음

    • 탭 통째로 대상 창 탭 목록의 그 자리에
    • 같은 창이면 순서만 바뀐다 · 넘친 자리는 맨 뒤
    • 탭 id · 내용 그대로
    락 한 번 · 변경 번호 한 번
    새 창 · NewWindow

    그 탭만 든 새 창

    • 계획(락) — 출처가 탭 하나뿐인 팝아웃이면 그 창을 옮기고 끝
    • 창 열기(락 밖) — 크기 = 출처 창 · 메인에서 떼었으면 팝아웃 기본
    • 다시 판정 + 적용(락) — 그새 닫혔으면 연 창을 닫고 무변경
    OS 창을 먼저 열고 모델은 마지막에 한 번
    공통 — 출처 팝아웃이 비면 모델에서 지운 뒤 락 밖에서 OS 창을 닫는다. 출력 경로는 같은 락 안에서 다시 계산해 에이전트 출력이 끊기지 않는다(데몬 구독은 그대로). 저장은 기존 기록기가 락 안 스냅숏으로 하므로 탭이 두 곳이거나 어디에도 없는 판은 생기지 않는다.
  5. 5 끝 — Ended → 되보이기 → 딱지 숨김 → 자리 기록 재개 → 표식 해제 Ended 는 적용 알림 뒤에 나가므로 출처 창은 탭이 빠진 목록을 먼저 받는다 — 탭이 한 번 다시 비쳤다 사라지지 않는다. 웹뷰는 Ended 를 받으면 무조건 오버레이를 지운다. 끝마다 info 한 줄(결말 · 사유 · 틱 수 · 최대 틱 ms).
비정상 끝 · 중단

모델은 끌기 전 그대로

  • 전경이 확실히 다른 앱으로 감 — 곧바로
  • 전경 불명 · 포인터 못 읽음이 합쳐 500ms(UAC · 잠금 화면은 여기로)
  • 웹뷰 놓기 신호 때 새로 읽은 포인터를 믿을 수 없음
  • Windows 밖에서 웹뷰가 놓기 신호를 잃음
  • 출처 창이 닫힘 · 출처 탭이 사라짐 → 그 자리에서 중단
떼어진 표시를 거두고 숨긴 창을 되보이면 PRD 의 「출처 탭바로」가 된다. 닫힌 출처의 탭은 그 닫기와 함께 사라진 것이다 — 도킹이 되살리지 않는다.
놓기 신호

먼저 온 것 하나

  • 셸이 직접 읽은 포인터의 떼기 — 주 신호
  • 웹뷰 pointerup → Released — 둘째 신호 · 먼저 오면 그때 포인터를 새로 읽어 판정
  • 웹뷰 pointercancel · blur → Lost — 힌트일 뿐(Windows 밖에서만 끝)

06안전 규칙

어긋남을 막는 규칙 다섯

1
닫히는 창으로는 붙지 않는다. 팝아웃 닫기 요청을 받는 순간 레이아웃 락 안에서 그 창을 모델에서 먼저 지우고 label 에 묘비를 단다. 그 뒤의 도킹 · 새 창 확정은 무변경으로 끝난다. 근거 = 팝아웃 닫기 요청은 되돌려지지 않는다(우리 처리기 · 프론트 · 런타임 소스로 확인 — 확실). 같은 틈을 가진 slot.popout 도 함께 닫힌다. 누가 팝아웃 닫기를 막을 수 있게 만들면 이 규칙을 다시 써야 한다 — 처리기에 주석으로 박고, 3단계부터 매 /qa 가 검색 두 줄로 「막는 코드가 없다」를 확인한다. 4단계(적용 서비스)는 이 규칙에만 기대어 닫히는 창을 막으므로 3단계가 4단계의 필수 선행이다. 확인 #2
2
시작은 되감긴다. 실패할 수 있는 준비를 먼저 하고, 표식 · 창 숨기기 같은 부수 효과는 그 뒤에 한다. 부수 효과가 생긴 뒤의 실패는 가드가 정상 끝과 같은 순서로 거둔다 — 끝 방송 → 숨긴 창 되보이기 → 딱지 숨김 → 자리 기록 재개 → 표식 해제 → 스레드 중단. 아직 하지 않은 부수 효과는 건너뛴다.
3
한 번에 끌기 하나. 표식은 모델 안에 있어 명령의 판정과 같은 락에서 본다 — 두 번째 시작은 거절, 끄는 탭을 옮기는 명령은 「끄는 중」으로 실패, 지난 끌기의 늦은 놓기는 번호가 달라 무변경.
4
늦은 신호는 버린다. 세션 번호가 다른 놓기 신호, 끝맺기에 들어간 뒤 온 창 사건(성공한 놓기가 닫은 출처의 소멸 포함), 웹뷰에서 세션 안 순번이 오래된 표시 사건은 버린다. 어떤 창이 오버레이 지움 한 장을 놓쳐도 끝 방송 한 장이 지운다.
5
끌린 탭은 놓을 때까지 저장되지 않는다. 표식 · 묘비는 메모리, 떼어진 표시는 웹뷰에만 있다. 숨긴 출처 창의 자리 기록도 멈춘다 — 화면 밖 자리가 저장되면 끄다 앱이 죽었을 때 창이 엉뚱한 자리로 복원된다. 끄다 앱이 꺼지면 다음 부팅에 끌린 탭은 끌기 전 자리에 있다. 예외 하나 — 탭 머리 위에 머물러 한 탭 전환은 그 창의 활성 탭을 바꾸고 저장에도 실린다(확인 #5).

다섯 — 불합격이면 멈추고 PRD 로 올린다

버리는 스파이크 브랜치에서 앱을 런처로 띄워 잰다 — 코드는 머지하지 않고 결과만 TRD 개정으로 남긴다. 아래 「못 넘으면」은 요구를 바꾸지 않는 조정뿐이다. 그것으로도 안 되면 구현을 멈추고 PRD 개정(사용자 결정)으로 올린다.
