탭을 끌어, 원하는 창의 원하는 자리에 붙인다

팝아웃 창의 탭을 끌어 다른 창(메인 · 다른 팝아웃 · 같은 창의 다른 탭)의 슬롯 옆, 탭바, 또는 빈 곳에 놓는 기능입니다. 지금은 슬롯을 옮기는 길이 팝아웃 하나뿐이고, 그것도 대상 창의 새 탭으로만 들어갑니다.

먼저 알아 두실 것 — 2026-10-16 에 방향을 바꿨습니다. 끌기는 브라우저 내장 HTML5 끌어 놓기(VS Code 와 같은 방식)로 하고, LLM 명령은 바로 다음 작업으로 뺐습니다. 이 페이지의 이름 · 단계 · 결정 목록은 TRD 5판 · PRD 4.3판(커밋됨 · 재리뷰 전)과 같습니다. 정해 주실 것은 8건이고(7절), 급한 것은 #2(4단계 착수 전)입니다.

01한눈에

탭 하나를 떼어 들고, 이음새에 넣는다

끄는 동안에는 화면만 바뀌고 실제 배치는 놓는 순간 한 번 바뀝니다. 커서 · 끌기 그림 · 버튼 · Esc 는 브라우저 엔진이 맡고, 셸은 창마다 놓을 수 있는 영역을 미리 계산해 주고 놓은 점을 다시 판정해 붙입니다.

어디까지 왔나 — TRD 5판 §10 단계

1 · 2 · 5단계(트리 연산 · 도킹 모델 · 판정 규칙)는 커밋됐고 새 방식에서도 그대로 씁니다. 3단계는 수정 5건을 반영해 재리뷰 · 화면 실측을 기다립니다. 새로 남은 것은 4 · 6a · 6b · 6c · 실측 · 7 · 8이고, 7단계가 끝나면 마우스 도킹이 처음으로 끝까지 됩니다. 커밋은 전부 로컬이며 push 한 것은 없습니다.

02사용자가 보는 동작

떼고, 들고, 셋 중 한 곳에 놓는다

탭을 끌면 그 탭은 곧바로 창에서 떼어져 보이고, Windows 기본 끌기 그림이 커서를 따라갑니다. 떼어진 모습은 화면 표시일 뿐이라, 이 순간에는 저장된 배치가 바뀌지 않습니다.

놓는 곳은 셋뿐입니다 — 이음새(슬롯 옆 · 창 바깥 변), 탭바, 그 밖(새 창). 슬롯 가운데는 이음새가 아니라서 거기 놓으면 새 창이 뜹니다. 결과에서 면적이 0 이 되는 슬롯이 생기는 띠는 아예 칠하지 않습니다.

Esc는 손을 뗀 것과 같고, 포커스를 잃거나 떼기 신호를 놓치면 마지막 점에 놓습니다. 메인의 마지막 탭도 끌 수 있고, 그러면 메인에 빈 탭이 자동으로 생깁니다.

자세히 — 띠 규칙 · 고를 수 있는 곳 · 새 창 크기 · 비목표
  • 띠가 겹치면 창 바깥 띠가 슬롯 띠보다 이기고, 슬롯 모서리에서는 커서에서 가장 가까운 변(띠 두께로 나눈 거리)이 이깁니다. 경계선 위는 늘 같은 답이 나옵니다 — 이미 src-tauri/src/dock/hit.rs 에 있습니다.
  • 바깥 띠 두께 = 32 CSS px — 탭바 높이(28px)보다 조금 두꺼워 노리기 쉽고, 배율과 무관하게 같은 눈 크기입니다.
  • 고를 수 있는 곳 = 커서 밑 맨 위가 우리 창일 때, 그 창의 지금 보이는 탭과 탭바. 다른 앱 창에 가려진 자리 · 최소화된 창은 대상이 아니고 거기 놓으면 새 창입니다. 같은 창의 다른 탭에 붙이려면 그 탭 머리 위에 0.5초 머물러 띄운 뒤 놓습니다.
  • 새 창 크기 = 떼어 온 창의 크기, 메인에서 뗐으면 팝아웃 기본 크기(720×500). 자리 = 커서에서 끌기 그림 안 커서 자리를 뺀 곳 — 그림이 있던 자리에 창이 뜹니다. 탭이 하나뿐인 팝아웃이면 새 창을 만들지 않고 숨겨 둔 그 창을 놓은 자리로 옮깁니다.
  • 메인의 마지막 탭을 끄는 동안 메인은 빈 탭바 · 빈 화면이고, 다른 창에 놓으면 같은 연산 안에서 빈 탭이 생깁니다.
  • 파일 끌어 놓기(탐색기 파일 등)는 모든 창에서 늘 막습니다 — 드롭 처리기를 끄면 웹뷰가 그 파일로 이동할 수 있어서입니다.
  • 놓은 뒤 대상 창이 앞으로 오고 붙은 첫 슬롯에 포커스가 갑니다.
  • 에이전트 출력은 끊기지 않습니다 — 배치를 바꾸는 같은 잠금 안에서 출력 경로를 다시 계산합니다(팝아웃과 같은 길). 끄는 동안에도 셸 메인 스레드가 비어 있어 출력이 계속 흐릅니다(3절).
  • 비목표: 슬롯 하나 직접 끌기 · 슬롯 가운데 칸 · Ctrl 끌기 · 직전 도킹 되돌리기 · 크기 기억 · 웹뷰 안 화면 상태(입력 초안 · 스크롤) 옮기기.
03구조와 코드

끌기는 브라우저 엔진이 돌리고, 셸은 영역 · 판정 · 적용만 쥔다

  • 셸이 여전히 권위다웹뷰는 셸이 보낸 영역으로 가이드를 그릴 뿐입니다. 놓으면 셸이 같은 규칙으로 다시 고르고, 보인 것과 같을 때만 적용 서비스 한 곳에서 바꿉니다.
  • OS 코드가 없다끌기 루프 · 커서 · 그림을 웹 표준이 맡아 platform 에 새 함수가 0 입니다. macOS 는 WKWebView 의 창 사이 동작만 이식 때 따로 잽니다.
  • 앱 없이 시험한다판정 규칙 · 장부 · 영역은 순수 함수라 가짜 시각 · 커서 · 스냅숏으로 단독 시험하고, 웹뷰의 판정 거울은 Rust 와 같은 골든 파일을 먹습니다.
다음 작업 — LLM 레이아웃 명령 이번 도킹에서는 LLM 명령(tab.dock · layout.get)도 프론트 레지스트리 명령도 만들지 않고, 도킹이 끝나면 바로 다음 작업으로 합니다. 첫 단계는 외부 조사 — LLM 도구 설계 관례(흔한 요청을 1–2 호출로). CLAUDE.md 「LLM-우선 제어」의 의식적 예외이고 사용자 결정입니다(TRD §3 · ADR-D). 적용 서비스 apply::dock_tab 은 4단계에 만들어지므로, 다음 작업은 4단계만 있으면 시작할 수 있습니다.

04왜 바꿨나

셸이 끌기를 몰던 설계에서, 브라우저에 맡기는 설계로

끌기를 셸이 직접 몰려면 커서 폴링 · 맨 위 창 판정 · 딱지 창 · OS 함수를 모두 우리가 짜야 했습니다. 브라우저 내장 끌어 놓기는 그 일을 엔진이 하고, 셸 메인 스레드도 막지 않는다는 것을 스파이크로 확인해 바꿨습니다(사용자 결정 2026-10-16).

  • 사라지는 것
    • 셸의 8ms 커서 폴링 루프
    • 커서 밑 맨 위 창 판정
    • 딱지 창(별도 창)
    • OS 함수 대부분 → macOS 이식 때 다시 짤 것이 준다
  • 받아들인 것
    • 끌기 그림은 Windows 기본 모양 — 불투명하게 못 만들고, 가장자리가 흐려진다
    • 다른 앱 창 위에서는 끌기 그림이 사라진다
  • 버린 대안 — crabnebula 끌기 플러그인
    • 끌기 루프를 셸 메인 스레드에서 돌려, 끄는 동안 위치 사건이 막혔다가 놓은 뒤 몰려온다 → 실시간 가이드 불가
    • Esc = 취소로 고정 · 끄는 동안 위치 없음
    • 실은 것이 실제 임시 파일(탐색기에 놓으면 복사됨)
    • 끝나지 않아 앱이 멈추는 열린 버그
자세히 — 피어 · 스파이크 수치
  • VS Code(Electron)가 편집기 탭을 다른 창 · 새 창으로 떼는 방식이 HTML5 끌어 놓기입니다. 창 밖에 놓았는지는 「어느 창도 마지막에 dragover 를 보지 못했다」로 가르고, 호스트에 커서 위치를 물어 새 창을 엽니다(소스 확인).
  • dockview 의 Tauri 데모도 같은 방식이고 모든 창에서 Tauri 드롭 핸들러를 끕니다(리눅스에서만 실측된 데모).
  • 스파이크(tauri 2.11.3 · WebView2 Edg/155 · RDP 세션 · 배율 1.25 · 끌기 22회): 메인 스레드 지연 p99 1.2 · 최대 4.1ms(평소 최대 1.4) · 셸 → 웹뷰 이벤트 도착 p99 11 · 최대 33ms · invoke 왕복 p50 2.2 · 최대 약 50ms · 대상 dragover 움직일 때 60/s · 멈춤 약 15/s · 좌표 오차 1px 이하 · 커스텀 데이터 12/12 · dragend 는 모든 경우에 옴 · 끄는 중 원본 창을 숨겨도 계속(2회).
  • 어느 웹뷰도 아닌 자리(창 사이 틈 · 바탕화면)에서는 JS 사건이 없습니다. 그 자리는 끝 신호 때 셸이 커서(Tauri cursor_position)를 읽어 판정합니다 — 메인 스레드가 비어 있어서 가능하고, OS 별 코드는 없습니다.
  • 또 버린 대안 — 움직일 때마다 셸에 판정을 묻기: invoke 왕복 p99 약 16ms · 최대 약 50ms(실측)라 60Hz 가이드가 눈에 띄게 늦습니다. 그래서 셸이 영역을 미리 보내고 웹뷰가 거울 규칙으로 고릅니다(TRD ADR-C ⑥).
  • 근거 문서: docs/research/slot-docking-drag-mechanism-2026-10-16.md (적대 리뷰 대신 실측으로 판정 — 확신도 라벨은 그 문서에).
05끌기 한 번의 흐름

끝 신호는 셋 — drop · dragend · 끝 뒤 pointermove

끄는 동안 셸은 끼어들지 않습니다 — 대상 웹뷰가 미리 받은 영역으로 스스로 가이드를 그리고, 보인 것이 바뀔 때만 셸에 알립니다. 끝은 세 길입니다: 우리 창 위에서 떼면 drop, 창 밖 · Esc · 시스템 취소면 dragend(none), 신호를 잃으면 끝 뒤의 pointermove. 어느 길이든 셸이 같은 판정으로 붙이거나, 새 창을 열거나, 아무것도 바꾸지 않습니다.

자세히 — 끝나는 경우 전부 · Esc 를 따로 가르지 않는 이유
상황들어오는 사건결과
우리 창 위에서 손을 뗌drop (대상) → dragend move (출처)셸이 다시 고름 → 보인 것과 같으면 붙임 · 다르면 무변경 · 가이드 없음 = 새 창
dragend move 가 drop 보다 먼저 옴dragend move500ms 동안 drop 을 기다림 → 지나면 마지막 점에 놓기
창 밖 · 바탕화면 · 다른 앱 위에서 뗌dragend none마지막 점에 놓기 → 보통 그 자리에 새 창
Esc (어디서든)대상 dragleave → 출처 dragend none마지막 점에 놓기 — 우리 창 안이면 그 창에서 보인 가이드로
끝 신호 유실끝 뒤 첫 pointermove · pointerdown300ms 뒤 마지막 보고로 판정 · 보고가 없으면 지금 커서에 새 창
끄는 중 출처 배치가 바뀜—받지 않음(커서 「안 됨」) · 어느 끝이든 무변경
출처 창이 부서짐 · 출처 탭이 사라짐Destroyed · 스냅숏그냥 끝 (변경 없음 · 되보이기 없음)
  • Esc 와 떼기를 키 상태로 가르지 않습니다. 우리 창 위에서 버튼으로 떼면 그 창의 drop 이 처리하므로, none 끝이 우리 창 위를 가리키면 그것은 Esc(또는 시스템 취소)입니다. Esc 와 떼기는 같은 「그 자리에 놓기」라 가를 것이 없고, 남는 질문 「지금 커서가 어느 우리 창의 보인 가이드 위인가」를 마지막 보고 + 셸 커서의 창 사각형 검사가 답합니다. Esc 가 낸 떠남 보고가 끝보다 먼저 닿을 수 있어 100ms 유예를 둡니다.
  • 끄는 동안 웹뷰에는 포인터 사건이 오지 않습니다(끌기가 대신함). 그래서 세션 중 어느 창이든 pointermove 를 보면 끌기는 이미 끝난 것이고, 이것이 유실 대비 신호입니다.
  • 끄는 탭은 커스텀 형식 application/x-engram-tab 하나만 싣습니다 — 다른 앱이 받지 않아 그 앱에 아무것도 들어가지 않습니다.
  • Esc 키가 웹뷰에 닿으면 터미널 · 입력창에 들어가지 않게 세션 동안 + 200ms 삼킵니다(보험 — OS 가 넘기는지는 실측 S1).
06안전장치

어긋남을 막는 네 장치

끌기 · 창 닫기 · 출력이 동시에 일어날 수 있는 경로입니다. 아래 넷이 「탭이 두 곳에 있거나 어디에도 없는」 상태, 「사용자가 못 본 결과」, 「끝나지 않는 끌기」를 막습니다.

자세히 — 각 장치의 근거와 한계
  • 한 세션에 적용은 많아야 한 번 — 판정과 「적용 중」 표시가 장부 잠금 한 번 안이라, 그 뒤 오는 놓기 · 끝 신호는 늦은 신호로 버립니다. 모르는 세션 id 의 신호도 버립니다.
  • 표식(lease_tab)은 끌기 시작 때 서고, 놓기는 그 표식을 싣고 갑니다. 지난 끌기의 늦은 놓기는 StaleLease 로 무변경입니다.
  • 닫히는 창 장치의 전제 = 「팝아웃 닫기는 막을 수 없다」. 누가 프론트에 닫기 요청 리스너를 달면 이 전제가 무너지므로, 점검 명령 두 줄을 QA 게이트로 매번 돌립니다(rg -i "close.?requested" src/ → 0줄 · rg "prevent[_]close" src-tauri/src/ → 1줄).
  • 드롭 처리기 점검(6단계부터) — rg "disable_drag_drop_handler" src-tauri/src/ → 1줄(webview_env.rs) · 끈 처리기의 사건을 기대하는 코드 0줄.
  • 저장: 기록기는 같은 잠금 안에서 배치를 통째로 복사해 쓰므로 저장 파일에는 도킹 전 아니면 도킹 뒤만 실립니다 — 다시 켜도 탭은 정확히 한 곳에 있습니다. 끄는 동안 저장되는 것은 0.5초 머물러 바꾼 탭 전환 하나뿐입니다.
07남은 결정

정해 주실 것 8건 — TRD 5판 §11-1, 지금은 전부 기본값으로 진행 중

이미 정해져 이 목록에서 빠진 것 — Esc = 그 자리에 놓기 · 비정상 끝 = 마지막 점에 놓기(출처 탭이 사라진 경우만 그냥 끝) · 끌기 그림 모양 = Windows 기본 · 메인 마지막 탭도 끌기(떠나면 빈 탭) · LLM 명령 = 다음 작업 · platform 창 핸들 의존(옛 목록 #3 — 5판에서 OS 함수와 함께 빠짐).
#2 — 4단계 착수 전 #4 · #7 — 7단계(프론트) 전 #8 — 결정 Q8 과 맞춰 볼 것 #1 · #3 · #5 · #6 — 이미 기본값으로 구현됨

카드마다 청록 실선 = 지금 기본값, 회색 점선 = 대안입니다. 「이미 구현됨」 항목도 답에 따라 그 자리를 고칩니다. 번호는 TRD 5판 §11-1 그대로입니다.

#1

같은 창 안 도킹 — 보던 탭이 빠지면 무엇이 보이나

2단계(커밋됨)에 기본값으로 들어감 src-tauri/src/layout/manager.rs · ViewManager::dock

탭 [A · 보는 중][B][C] 에서 A 를 끌어 같은 창 C 의 슬롯 옆에 붙이면

지금 기본값
붙은 대상이 보인다(이음새 = 대상 탭 · 탭바 = 옮긴 그 탭) — 보던 내용이 그 탭에 들어가 화면에 남는다.
대안
탭 닫기와 같은 승계(오른쪽, 없으면 왼쪽 이웃)로 다른 탭이 보인다.
달라지는 것
놓은 직후 화면에 무엇이 남는가. 「대상 창의 보이는 탭은 안 바뀐다」는 원래 규칙이 보던 탭이 사라지는 이 경우엔 성립하지 않아 둘 중 하나를 골라야 한다.
#2

닫히는 창 — 닫기 요청 순간 모델에서 먼저 지우나 (M2)

4단계 착수 전에 필요 · 3단계에 이미 구현 · 확인 대기 src-tauri/src/commands/popout.rs · close_requested_popup_window

사용자가 팝아웃 X 를 누른 직후 몇 ms 안에 그 창으로의 도킹이 확정되면

지금 기본값
팝아웃 닫기 요청을 받는 순간 모델에서 그 창을 지우고 묘비를 단다. 기존 slot.popout 의 같은 틈도 함께 닫힌다.
대안
도킹 직전 「창이 열려 있나」만 확인하고 남는 위험을 기록한다.
달라지는 것
기본값은 팝아웃 모델 정리의 계기를 「창 소멸」에서 「닫기 요청」으로 옮긴다(ADR-E · 불변식은 그대로). 대안을 고르면 4단계 전에 옛 2판의 검사 둘을 되살린다.
#3

최대화된 창에서 뗀 탭의 새 창 크기

2단계(커밋됨)에 기본값으로 들어감 src-tauri/src/layout/manager.rs · plan_new_window

최대화된 팝아웃에서 탭을 떼어 빈 곳에 놓아 새 창이 될 때

지금 기본값
그 창의 보통(최대화 전) 크기로 연다.
대안
최대화 상태 그대로 연다.
달라지는 것
기본값은 「화면만 한데 최대화는 아닌 창」이 생기지 않게 한다. 대안은 떼어 온 창의 모양을 그대로 잇는다.
#4

끄는 중 바꾼 탭을 되돌리나

7단계(프론트) 전 대상 웹뷰의 머묾 500ms → 기존 탭 전환(switch_tab) — dockDrag.ts (7 신설)

끄는 동안 「B」 머리 위에 0.5초 머물러 B 로 바뀌었는데, 끌기가 아무 변화 없이 끝나면

지금 기본값
되돌리지 않는다 — 탭 전환은 사람 탭 클릭과 같은 쓰기라 저장에도 실린다.
대안
끌기가 무변경으로 끝나면 끌기 시작 때의 탭으로 되돌린다.
달라지는 것
끄는 중 모델을 바꾸는 유일한 동작을 「남김」으로 둘지 「취소 가능」으로 둘지. 대안은 끝 정리에 되돌리기 쓰기가 하나 더 생긴다.
#5

칠하지 않은 바깥 띠 위에 놓으면

5단계(커밋됨)에 기본값 · PRD R8 괄호와 다름 src-tauri/src/dock/hit.rs · choose_seam

창 바깥 띠가 「면적 0」이라 칠해지지 않았는데, 그 밑 슬롯의 띠는 칠해져 있는 자리에 놓으면

지금 기본값
그 밑 슬롯의 띠로 넘어간다(그 칸 띠에 들면 그 이음새, 안 들면 새 창).
대안
PRD R8 괄호 그대로 — 칠하지 않은 바깥 띠에 놓으면 새 창.
달라지는 것
기본값을 고르면 PRD 문구를 고친다. 대안이면 PRD 는 그대로지만 그 자리에서는 밑 슬롯 띠를 고를 수 없다.
#6

안 보이던 탭을 제자리 탭바에 도로 놓으면

2단계(커밋됨)에 잠정 · 리뷰어 둘 의견이 갈림 src-tauri/src/layout/manager.rs · ViewManager::dock (탭바 갈래)

탭 [A · 보는 중][B][C] 에서 안 보이던 C 를 끌어 같은 창 탭바의 원래 자리에 놓으면

지금 기본값
그 탭을 보이게 한다(목록은 그대로 · 변경 번호 +1). 마우스로 놓으면 「옮긴 것을 보인다」는 규칙을 이 경우에도 지킨다.
대안
아무것도 바꾸지 않는다 — 제자리에 놓았으니 진짜 무변경.
달라지는 것
탭을 집었다 놓는 손동작이 「그 탭 보기」로 읽히는가. 이미 보이는 탭은 어느 안이든 무변경이다.
#7

끌기 그림에 무엇을 담나

7단계 전 · 실측 S2 와 함께 src/components/layout/dragImage.ts (7 신설)

끌기 그림은 Windows 기본 모양으로 정해졌고, 「내용은 되는 만큼」의 범위가 남았다

지금 기본값
보이던 탭이면 터미널 칸 = 그 화면의 축소 그림, 그 밖 칸(챗 · 목록 · 사용량 · 빈 칸) = 칸 이름 자리채움. 안 보이던 탭 = 제목만.
대안
누르는 순간 그 탭으로 전환해 화면을 띄운 뒤 그린다.
달라지는 것
DOM 칸은 끌기 시작 순간 그림으로 옮길 수 없어 자리채움이 된다. 대안은 탭 클릭이 「누를 때 전환」으로 바뀌어 끌지 않은 누름도 탭을 바꾼다. 터미널 그림이 비어 보일 수 있는지는 실측 S2 가 잰다.
#8

「보인 것과 다름」으로 끝나면 — 무변경이냐 새 창이냐

결정 Q8(원래 창 되돌리기 없음)과 맞춰 볼 것 src-tauri/src/dock/book.rs · 놓기 판정 (6b 신설)

보인 가이드와 다시 고른 결과가 다르거나(그 사이 손이 움직임), 끄는 중 출처 · 대상 배치가 바뀌었을 때

지금 기본값
무변경 — 못 본 결과를 만들지 않는 안전장치. 결과로 탭은 원래 창에 다시 보인다.
대안
이 경우에도 그 자리에 새 창(R22) — 못 본 이음새에 붙지는 않으면서 「되돌림」이 사라진다.
달라지는 것
TRD 는 결정 Q8 의 「원래 창 되돌리기 없음」을 비정상 끝에 대한 것으로 읽었다. 이 경우까지 넓히면 대안이 맞다.
08위험과 남은 일

남은 실측 여섯 — 화면에서는 아직 한 번도 돌려 보지 않았다

전제 — 실측이 합격선을 못 넘으면 요구를 바꾸지 않는 조정만 시도하고, 그것으로도 안 되면 조용히 물러나지 않고 구현을 멈춘 뒤 PRD 개정(사용자 결정)으로 올립니다(TRD §8-2).
미측정 · 미실행 설계상 남는 위험 모름 · 나중에 잼 받아들임

남은 실측 (TRD §8-2) — S5 를 뺀 다섯은 7단계 앞

  • S1 — 끝 신호미측정

    Esc 를 우리 창 위 · 틈 · 바탕화면 · 덮은 다른 앱 위에서 각 20회 — 대상 떠남과 출처 끝이 셸에 닿는 순서 · 간격(떠남 유예 100ms 가 맞나) · 끝 뒤 pointermove · 머리를 접어도 dragend 가 오나 · 팝아웃 hide() · Esc 가 터미널에 들어가나. 안 되면 시한 조정 → 그래도면 platform 함수 하나(「주 버튼이 지금 눌려 있나」 · 사용자 보고).

  • S2 — 끌기 그림 내용미측정

    터미널(WebGL) 캔버스를 옮긴 그림이 비지 않나 · dragstart 안 합성 p95 ≤ 8ms · 화면 밖 상자 그림이 쓰이나. 실패하면 자리채움 → 제목만 → 엔진 기본 그림 순으로 물러납니다(결정 #7 범위).

  • S3 — 바탕화면 · 다른 앱 · 파일미측정

    탐색기 바탕화면 · 탐색기 창 · 메모장 · Edge 위 떼기 각 10회(새 창 · 그 앱에 아무것도 안 들어감) · OS 파일을 창에 놓아도 웹뷰가 그 파일로 탐색하지 않나. 탐색이 남으면 멈춤(회귀).

  • S4 — 배율이 다른 모니터 · 다중 모니터미측정

    100% · 150% 모니터에서 그린 띠와 판정이 ±1 CSS px 안 · 다른 모니터 빈 곳에 놓은 새 창 크기 · 걸친 창 위 Esc. 안 되면 마지막 보고 점을 화면 좌표로 옮겨 대조 → 그래도면 멈춤.

  • S5 — 원격(RDP)이 아닌 콘솔 세션 · 다른 PC미측정 · 8단계

    2026-10-16 실측(RDP 세션 · 배율 1.25)의 핵심 수치를 로컬 콘솔에서 다시. 결론이 다르면 멈춤 — 수단 재검토(사용자).

  • S6 — Tauri 창 끌기 포커스 이슈(#10767)미측정

    팝아웃 제목줄을 메인 위로 옮긴 직후 탭 끌기 10회가 정상인가. 걸리면 끌기 전 웹뷰 포커스를 다시 잡는다 → 그래도면 멈춤.

설계상 남는 위험 (TRD §11-2 에서 추림)

  • 「마지막 점에 놓기」의 오판가능성 낮음

    우리 창을 덮은 다른 앱 창 위로 나가 100ms 안에 떼면 그 밑 우리 창의 마지막 가이드로 붙습니다(사용자는 그 가이드를 직전에 봤음). S1 이 간격 분포를 재고, 끝 로그의 leave_gap_ms 로 현장에서도 봅니다.

  • 끝 신호를 잃고 마우스가 우리 창에 안 오면가능성 낮음

    장부 · 표식이 남아 그 탭의 떼어진 표시가 남고 다음 끌기가 거절됩니다. 마우스가 우리 창에 오는 순간 dock_pointer_seen 이 끝냅니다.

  • 문턱 직후 캔버스에서 떼면 새 창확실 · PRD R22 그대로

    끌기 문턱이 엔진 것이라 값을 고칠 수 없습니다. 거슬리면 QA 에서 「출처 창 안 · 시작 직후의 가이드 없음 놓기 = 무변경」을 올립니다.

  • macOS (WKWebView) 의 창 사이 끌기모름 · 이식 때 S1 · S2 · S4

    방식은 웹 표준이지만 WKWebView 가 창 사이 · 끄는 중 포인터 사건 · 끌기 그림을 어떻게 다루는지는 확인하지 않았습니다.

  • 끌기 그림 모양 · LLM 표면 없음받아들임 · 사용자 결정

    끌기 그림은 반투명이고 다른 앱 위에서는 사라집니다. LLM 은 이번에 도킹 · 레이아웃 조회를 못 합니다 — 다음 작업이 닫고, 그 사이 CLAUDE.md 「LLM-우선 제어」 남은 갭에 적습니다(8단계).
