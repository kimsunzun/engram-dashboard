## 1. 무엇·왜

- **계속 커지는 내부 번호가 사람에게 보인다.** 팝아웃 창 제목 = 「Engram — slot-popup-11」(`src-tauri/src/commands/popout.rs:231`) · 새 창 팝아웃의 탭 이름 = 「Popup 6」(같은 파일 `tab_name` :61). 창 label 은 단조 카운터라 창을 닫아도 번호가 돌아오지 않는다. (코드)
- **창 제목이 내용을 말하지 않고, 창 이름은 못 바꾼다.** 메인 제목은 「Engram Dashboard」 고정(`src-tauri/tauri.conf.json`). 탭은 이름을 바꿀 수 있지만(화면 · `tab.rename`) 처음 이름은 대개 「View N」이다(Q6). (코드)
- **OS 제목 표시줄이 탭바 위에 한 줄을 따로 먹는다.** Chrome · Windows 11 탐색기처럼 탭바가 제목 표시줄 자리에 선다. (결정 · 2026-10-17)
- **LLM 이 창을 보이거나 앞으로 낼 길이 없다.** 보이기 · 숨기기는 트레이와 그 Tauri invoke 명령(`show_main_ui` · `hide_main_ui` — `src-tauri/src/commands/tray.rs`)뿐이고 버스 명령이 아니다 · 창 하나를 앞으로 내는 명령은 없다. 단추를 우리가 그리면 이 갭이 사람 · LLM 사이에 그대로 드러난다(R17). (코드)
- 시점 = 슬롯 도킹 9c 직후, 같은 브랜치에서 최종 머지에 포함. 탭바 넘침(슬롯 도킹 R24 — Chrome 규칙)과 같은 줄을 나눠 쓰므로 함께 간다. (결정 · 2026-10-17)

## 3. 요구사항

**창 번호 · 이름**
- **R1** 각 창은 사람에게 보이는 **창 번호**를 갖는다 = 그 창이 생길 때 **살아 있는 창들이 쓰지 않는 가장 작은 번호**. 1 · 2 · 3 에서 2 를 닫으면 다음 새 창 = 2. (결정 · 2026-10-17) 새로 만드는 길 전부(팝아웃 · `window.create` · 슬롯 도킹으로 떼어 만든 새 창(슬롯 도킹 R22))가 이 규칙을 탄다 · 부팅 복원 · 크래시 사본 수락은 D3(Q8). 「살아 있는 창」 = 모델에 있는 창(`window.list` 에 보이는 창 — 숨은 · 최소화한 창 포함) **+ 모델에서 빠졌지만 OS 창이 아직 없어지지 않은 닫히는 창**. 번호는 창을 모델에 넣는 같은 락 안에서 잡아 동시에 만든 둘이 같은 번호를 받지 않고, **OS 창이 실제로 없어질 때(`Destroyed` — `src-tauri/src/lib.rs:337`) 풀린다** — 모델에서 빼는 길(`window.close` · 팝아웃 닫기 요청(셸이 그때 모델을 먼저 지운다 — 같은 파일 :305–330) · 마지막 탭 닫기 · 0탭 자가닫힘)은 그때까지 번호를 닫히는 창 몫으로 잡아 둔다. 만들기 실패 되돌림(`src-tauri/src/layout/apply.rs` `create_window`)은 OS 창이 서지 않았으므로 되돌림에서 곧바로 푼다. (기본값 — 메인 제안 · 거부한 갈래 = D13)
- **R2** 내부 창 label(`slot-popup-N`)은 지금처럼 **단조**다 — 번호는 label 과 따로 매긴다. capability glob(`slot-popup-*`) · 닫힘 정리 판정은 그대로다. (결정 · 2026-10-17) D12 가 label 에 실행 표식을 더해도 실행 안 단조 · glob 은 그대로다(기본값 — 메인 제안).
- **R3** **창 제목**(작업 표시줄 · Alt+Tab · 작업 보기에 보이는 OS 제목) = 「<활성 탭 이름> - Engram」 + Q3 의 번호. 탭 전환 · 활성 탭 이름 바뀜(사람 · `tab.rename` · Q6 ④ 의 자동 이름) · 활성 탭 닫기 · 다른 창으로 옮기기 직후 새 활성 탭을 따른다. 활성 탭이 아직 없으면(창을 막 만들어 모델을 받기 전) 「Engram」. 긴 · 유니코드 이름은 OS 제목에 자르지 않고 싣고(작업 표시줄이 자르는 것은 OS 몫), 탭 머리는 말줄임 + 툴팁 전체 이름. 같은 이름 탭이 여러 창에 있어도 그대로 — 창은 번호가 가른다. 우리 제목 표시줄 안에는 제목 글자를 그리지 않는다(Chrome 과 같다). (기본값 — 메인 제안 · 조사 이름 §2 ③ · §4)
- **R4** **새 탭의 처음 이름** = Q6. 어느 갈래든 「Popup N」 · 「Tab」은 없어지고, 에이전트 없는 슬롯은 내용 종류로 짓는다 — 빈 슬롯 = 「새 탭」 · 에이전트 목록 · 프리셋 팔레트 · 사용량은 그 이름(`SlotContent` — `src-tauri/src/layout/types.rs`). 보이는 글자는 i18n 을 따른다. (기본값 — 메인 제안 · 조사 이름 §4)
- **R5** **창 이름 바꾸기** — Q4(기본값 = 이번엔 안 함).
- **R6** **LLM 이 영속 id · 번호 · label 을 함께 본다** — `window.list` 가 창마다 영속 id · 번호 · label · 상태(R18)를 돌려주고, 창을 만들거나 고르는 명령(`window.create` · `slot.popout` — 프론트 레지스트리의 같은 이름 명령 포함 · 슬롯 도킹의 새 창)도 셋을 함께 돌려준다. **명령의 창 인자 = 영속 id**(재시작 · 사본 수락을 넘어 같은 창) · label 은 같은 실행 안의 별칭으로만 맞는다(D12) · 번호를 받나 = Q9. 도움말에 적는다 — 번호는 재사용된다 · label 은 그 실행 안에서만 맞는다. (기본값 — 메인 제안 · 조사 이름 §2 ① tmux · §4)

**제목 표시줄 (Windows)**
- **R7** OS 제목 표시줄을 없애고 **탭바가 창 맨 위**에 선다 — 한 줄에 탭바 · 빈 곳(끌 자리) · 창 단추 셋. (결정 · 2026-10-17) Q3 ① 이면 왼쪽 끝에 번호 표식이 더 선다. 팝아웃도 같은가 = Q2(기본값 = 같다).
- **R8** 그 줄의 **빈 곳을 끌면 창이 움직인다**(OS 이동 루프 — 화면 위 끝으로 끌면 최대화 · 옆 끝 스냅 그대로 · 상태 사이 옮김 = R22). 슬롯 도킹 R1 의 「제목줄」이 이제 이 빈 곳이다 — 끌어도 도킹 가이드가 뜨지 않는다. (결정 · 2026-10-17)
- **R9** 빈 곳 **두 번 누름 = 최대화 ↔ 원래 크기**. 탭 머리 두 번 누름은 지금처럼 이름 편집이다. (기본값 — 메인 제안 · Windows 관행)
- **R10** **창 단추 셋**(최소화 · 최대화/원래 크기 · 닫기)을 우리가 그린다. 모양 = Windows 11(올리면 옅은 바탕 · 닫기는 빨강) · 각 창 테마(ADR-0265). **닫기 = 지금 OS 닫기(X · Alt+F4)와 같다 — 메인 = 모든 UI 창(메인 · 팝아웃)을 트레이로 숨기기**(`hide_main_ui` · ADR-0026 · ADR-0229) · **팝아웃 = 그 창과 그 탭 배치를 지우기**. 둘이 다르므로 메인의 닫기 단추는 모양으로 구별되고(TRD) 툴팁 · 접근성 이름이 하는 일 이름이다 — 메인 「모든 창 숨기기」 · 팝아웃 「창 닫기」(어느 쪽도 맨 「닫기」가 아니다). 메인만 숨길지 = Q7. (직접 그린다 = 결정 · 2026-10-17 · 나머지 = 기본값 — 메인 제안)
- **R11** **비활성 창**은 탭바 · 표식 · 단추가 흐려진다(Windows 11 · Chrome 관행 — 피어 Cap 이 포커스로 가른다). Engram 창끼리도 앞 창 하나만 또렷하다. (기본값 — 메인 제안 · 조사 제목 §3)
- **R12** **가장자리 · 모서리를 끌어 크기를 바꾼다** — 최대화가 아닐 때 위 가장자리 포함. 창 그림자 · Windows 11 둥근 모서리를 유지한다. (기본값 — 메인 제안 · 조사 제목 §2 — Tauri 코어 크기 조절 · `shadow`)
- **R13** **탭바 넘침 = 슬롯 도킹 R24 그대로**(Chrome 규칙) — 단 탭이 쓰는 폭은 표식 · 창 단추 · 끌 빈 자리를 뺀 나머지다. 탭이 가득 차도 **창을 끌 빈 자리가 남는다**. 탭 스타일이 바뀌므로 탭 폭 상수(표준 · 활성 최소 `A` · 비활성 최소)를 새 스타일에서 다시 끌어낸다(슬롯 도킹 TRD §7 #73). (넘침 규칙 = 결정 · 2026-10-17 · 끌 빈 자리 · 상수 값 = 기본값 — 메인 제안 · TRD 가 Chromium 규칙을 확인)
- **R14** **탭 끌기는 하나도 바뀌지 않는다** — 순서 이동 · 다른 창 도킹 · 떼어 새 창(슬롯 도킹 R2 · R21–R23). 다른 창의 탭을 이 줄의 빈 곳 · 표식 · 창 단추 위에 놓으면 그 탭바 끝에 새 탭으로 들어가고 그 단추는 눌리지 않는다. 놓기 직전 대상 창이 닫히면 놓기는 통째로 취소되고 출처 탭은 그대로다(슬롯 도킹의 「닫히는 창」 규칙). (기본값 — 메인 제안)
- **R15** **Windows 11 스냅 레이아웃 메뉴**(최대화 단추에 올리면 뜨는 배치 고르기) — Q1. 어느 쪽이든 Win+Z · 화면 끝으로 끌기 스냅은 된다(조사 제목 §4).
- **R16** **macOS 는 이번에 짓지 않는다 — 다만 막지 않는다.** 그쪽은 OS 신호등 단추를 두고(Overlay) 탭바 왼쪽을 비운다(조사 제목 §2). 「단추를 우리가 그리나 · 왼쪽을 얼마나 비우나」는 셸이 한 곳에서 알려 주고 웹은 그대로 그린다 — OS 가름은 `platform` crate 한 곳(원칙 · ADR-0266). (기본값 — 메인 제안)

**LLM 길 (원칙 「LLM-우선 제어」)**
- **R17** 사람이 닿는 창 상태 바꾸기는 전부 **버스 명령**이고, 사람의 단추는 그 명령을 부른다 — 최소화 · 최대화 · 원래 크기 · 닫기 · 모든 창 숨기기(R10) · **보이기 · 앞으로 내기**. 「되살리기」를 셋으로 가른다 — 최대화 → 원래 크기(그 창만) · 최소화 → 되살려 맨 앞으로(그 창만) · 숨김 → 보이기(숨기기가 모든 창 단위라 보이기도 모든 창 — 트레이 보이기와 같은 길 · ADR-0229). 창 하나 앞으로 내기는 숨어 있으면 모든 창을 보인 뒤 그 창을 되살려 맨 앞에 둔다. 지금 `window.close` 는 메인을 거부하고 보이기 · 숨기기는 버스에 없다. 웹이 Tauri 창 API 를 직접 부르지 않고 새 전역 핸들을 늘리지 않는다. 명령 이름 · 모양은 TRD. (원칙 · 기본값 — 메인 제안)
  - 알려진 갭(이번에 안 닫는다): 옮기기 · 크기 · 스냅의 버스 명령(§2). 팝아웃 0탭 자가닫힘(W9)은 이번에 버스 닫기로 옮겨 웹의 Tauri 창 닫기 호출이 남지 않는다.
- **R18** LLM 이 창 상태를 `window.list` 칸으로 조회한다 — 최대화 · 최소화 · 숨김 · 앞 창(`focused` = OS 앞 창이 그 창 — 많아야 한 창만 참 · 다른 앱이 앞이면 전부 거짓). 지금 답 모양(`windows` = label 목록)을 깨지 않고 더한다(TRD). 스냅 여부는 싣지 않는다(§2 갭). (기본값 — 메인 제안)
- 빈 곳 끌기 · 두 번 누름(R8 · R9)은 OS 제스처라 버스를 지나지 않는다 — 지금 OS 제목 표시줄과 같은 층이고, LLM 은 R17 의 최대화 명령으로 같은 결과를 낸다(D7).

**경계 규칙**
- **R19** **누름 우선순위** = 창 단추 > 탭 머리 · `+` · 번호 표식 > 끌 빈 자리. 끌 빈 자리는 줄에서 그 밖의 곳뿐이다. (기본값 — 메인 제안)
- **R20** **최소 창 폭** — 창은 그보다 좁아지지 않는다(OS 크기 조절이 막는다). 최소 폭 = 번호 표식 + 활성 탭 하나(활성 최소 `A`) + `+` + 끌 빈 자리 최소 + 단추 셋 — 그 폭에서 다 보이고 눌린다. 값 · 누름 자리 크기(DIP)는 TRD 가 정하고 AC 가 그 값을 잰다(D8). 저장된 크기가 최소 폭보다 좁으면 **최소 폭이 이긴다** — 최소 폭으로 넓혀 열고, 넓힌 창이 작업 영역을 넘으면 작업 영역 안으로 당긴다(D14). 다른 갈래 = D15. (기본값 — 메인 제안)

- **R22** **창 상태 옮김** — 보통 · 스냅 · 최대화 · 최소화 사이를 줄 끌기 · 두 번 누름 · 단추 · Win+화살표가 **지금(OS 제목 표시줄) 빌드와 같게** 옮기고(최대화 · 스냅한 창은 끌면 원래 크기로 돌아와 커서를 따라온다), 원래 크기로 돌아올 때 최대화 · 스냅 전 크기 · 자리를 되찾는다. 움직임 없는 한 번 누름은 창을 옮기지 않고, 두 번 누름의 둘째 누름은 끌기를 시작하지 않는다. 판정 = §4 끝 「창 상태 옮김 표」. (기본값 — 메인 제안)
- **R23** **닫는 길은 한 결과로 모인다** — 단추 · Alt+F4 · 버스 명령(R17) · 팝아웃 마지막 탭 닫기 · 0탭 자가닫힘(W9 — 버스 닫기를 부른다): 메인 = 모든 창 숨기기 · 팝아웃 = 그 창 지우기 + 번호 풀기(OS 창이 없어질 때 — R1). 메인이 숨은 동안 마지막 팝아웃을 닫아 보이는 창이 0 개가 돼도 앱 · 트레이는 살아 있고 트레이 보이기가 메인을 되살린다. 팝아웃 닫기가 앱을 끝내지 않는다. (기본값 — 메인 제안)

## 4. 수용 기준 (화면 실측 · 명령)

> 열린 Q 는 권장 갈래로 잰다 — Q2 도 권장(모든 창이 같은 제목 표시줄)이 AC 기준이고, 다른 갈래를 고르면 그때 범위를 다시 적는다. 제목 표시줄 AC 는 **메인 · 팝아웃 하나 · 팝아웃 셋**에서 모두 잰다. 「기준 빌드와 같다」 = 바꾸기 전 빌드에서 같은 조작으로 떠 둔 결과와 견준다. 크기 값(줄 높이 · 누름 자리 · 최소 폭 — D8 · 아래 표의 오차)은 TRD 단계에서 정하고 AC 는 그 값을 잰다.

- **AC1** 같은 실행 안에서 메인(1) · 팝아웃 2 · 3 을 띄우고 2 를 닫은 뒤 새 창을 만들면 그 창 = 2 · 3 은 3 그대로 · 새 label 은 앞서 쓴 어느 label 과도 다르다. 창 안 표식 · OS 제목 · `window.list` 셋이 같은 번호를 보인다(Q3 ①).
- **AC2** 슬롯 도킹으로 떼어 만든 새 창 · `window.create` · 새 창 `slot.popout` 이 AC1 규칙으로 번호를 받고, 명령으로 만들면 답에 영속 id · label · 번호가 함께 온다.
- **AC3** 작업 표시줄 · Alt+Tab 의 창 제목 = R3 · Q3 규칙. 탭 전환 · 사람 이름 바꾸기 · `tab.rename` · 활성 탭 닫기 · 활성 탭을 다른 창으로 옮기기 직후 제목이 새 활성 탭을 따른다. 「slot-popup-」 · 「Popup N」 · 「Tab」이 사람 눈에 보이는 곳에 없다.
- **AC4** 새 탭 이름(Q6 ④): 새 창 · 기존 창 팝아웃 · `+` · `window.create` 모두 — 에이전트 슬롯 = 그 에이전트 이름 · 빈 슬롯 = 「새 탭」 · 에이전트 목록 · 프리셋 팔레트 · 사용량 = 그 내용 이름. 에이전트 이름이 바뀌거나 탭 안 포커스가 옮기면 이름을 정하지 않은 탭만 따라가고, 사람 · `tab.rename` 이 정한 이름은 그대로다. 옛 상태 파일(D16) — 「View 3」 · 「Tab」 · 「Popup 7」 탭은 자동 이름으로 바뀌고 「빌드 로그」 탭은 그대로다.
- **AC5** 맨 위 줄이 (창이 둘 이상이면 번호 표식 ·) 탭바 · 빈 곳 · 창 단추 셋이고 OS 제목 표시줄이 없다. 창이 하나뿐이면 표식 · 제목 번호가 없다(Q3 ①).
- **AC6** 빈 곳을 끌면 창이 움직이고 도킹 가이드가 뜨지 않는다. 화면 위 끝 = 최대화 · 옆 끝 = 반쪽 스냅 · 최대화한 창을 끌면 원래 크기로 돌아와 커서를 따라온다(표 「빈 곳 끌기」 열). 움직임 없는 한 번 누름은 창을 옮기지 않는다.
- **AC7** 빈 곳 두 번 누름 = 표 「빈 곳 두 번 누름」 열 · 둘째 누름에 창이 움직이지 않는다. 탭 머리 두 번 누름 = 이름 편집(창 크기 그대로).
- **AC8** 단추 — 최소화 → 작업 표시줄로 · 최대화 ↔ 원래 크기(단추 그림 · 접근성 이름이 바뀐다) · 닫기 → 메인은 모든 창이 트레이로 숨고 앱은 산다 · 팝아웃은 그 창만 닫히고 `window.list` 에서 사라진다. 메인 닫기 단추는 팝아웃 것과 모양이 다르고 툴팁이 R10 대로다. Alt+F4 는 같은 창의 닫기 단추와 같은 결과다.
- **AC9** AC8 의 동작 · 모든 창 숨기기 · 보이기 · 앞으로 내기(숨은 창 · 최소화한 창 포함)를 LLM 이 버스 명령으로 하고 사람 단추와 같은 결과를 낸다 — 결과는 `window.list` 상태 칸과 화면으로 확인한다(소스 grep 으로 갈음하지 않는다). 다른 앱이 앞일 때 OS 가 앞으로 내기를 막으면 명령 답 · `focused` 가 그 사실 그대로다(W10).
- **AC10** 구조 확인(AC9 를 대신하지 않는다) — CLAUDE.md 「LLM-우선 제어」의 찾는 법(`rg "\)\.__ENGRAM_|\)\.__engram" src/ -g '!*.test.*'`) 결과가 이 작업 앞과 같고, 웹 코드 어디도(0탭 자가닫힘 포함 — W9) Tauri 창 API 의 최소화 · 최대화 · 닫기 · 보이기 · 앞으로 내기를 부르지 않는다.
- **AC11** 슬롯 도킹의 수용 기준(순서 이동 · 다른 창 도킹 · 떼어 새 창 · Esc · 넘침)이 새 제목 표시줄에서 그대로 통과한다(화면 QA 다시 잼).
- **AC12** 다른 창의 탭을 빈 곳 · 표식 · 창 단추 위에 놓으면 탭바 끝에 새 탭으로 들어가고 그 단추는 눌리지 않는다. 끌기 도중 대상 창을 `window.close` 로 닫으면 놓기는 통째로 취소되고 출처 탭은 그대로다(미검 · W2).
- **AC13** 빈 곳으로 창을 옮긴 직후 탭 누름 · 탭 끌기 · 단추가 곧바로 정상이다 — 누름이 먹히지 않거나 끌기가 저절로 시작되지 않는다(tauri#10767 · W1).
- **AC14** 네 변 · 네 모서리로 크기를 바꾼다(최대화 아닐 때 위 변 포함). 최대화 때는 탭바가 화면 맨 위에 붙고 위 · 옆이 잘리지 않으며 작업 표시줄을 덮지 않는다.
- **AC15** 다른 앱을 앞으로 내면 우리 창의 탭바 · 표식 · 단추가 흐려지고 돌아오면 원래대로다. Engram 창 둘 사이를 오가면 앞 창만 또렷하고 `window.list` 의 `focused` 는 그 창 하나만 참 · 다른 앱이 앞이면 전부 거짓이다.
- **AC16** Win+↑ · ↓ · ← · → · 최대화/복원 단추 · 작업 표시줄 단추 누름(최소화 ↔ 복원) · (Windows 11) Win+Z 가 표대로 옮기고(표에 없는 조합 = 기준 빌드와 같다), 원래 크기로 돌아오면 최대화 · 스냅 전 크기와 자리를 되찾는다.
- **AC17** 탭이 넘칠 만큼 많아도 `+` · 끌 빈 자리 · 단추 셋이 보이고, 보이는 활성 탭의 닫기 버튼이 잘리지 않는다(새 스타일에서 다시 끌어낸 `A`).
- **AC18** dark · light · e-ink 창 테마에서 단추 · 탭바 · 표식이 그 테마로 칠해진다. 배율 100 · 150 · 200% 모니터 사이를 보통 · 스냅 · 최대화 상태로 옮겨도 단추 · 끌 자리 · 크기 조절 가장자리가 어긋나지 않고 누름 자리가 TRD 값(DIP) 그대로다. 보통 상태에서 창 그림자 · (Windows 11) 둥근 모서리가 보인다.
- **AC19** (Q1 에서 ② 를 고를 때만) Windows 11 에서 최대화 단추에 올리면 스냅 레이아웃 메뉴가 뜨고, 고른 자리로 창이 간다.
- **AC20** 번호 수명(D13) — ① 팝아웃 2 · 3 을 거의 동시에 닫으면(Alt+F4 두 번 · `window.close` 두 번) 둘이 없어진 뒤 다음 두 새 창 = 2 · 3 ② 닫기 명령과 새 창 명령을 겹쳐 보내는 동안(되풀이 · 하네스로 `Destroyed` 를 늦춰서도) 표본 시각마다 `window.list` 에도, 화면(창 안 표식 · OS 제목 — 아직 닫히는 창 포함)에도 같은 번호가 둘 없다 — 닫히는 창이 없어지기 전에 만든 새 창은 다른 번호를 받는다 ③ 창 만들기가 실패하면(하네스로 꾸며) 그 번호는 곧바로 다시 쓰인다 ④ 모든 창이 숨은 동안 메인은 1 을 쥐고 `window.create` 는 1 을 받지 않는다.
- **AC21** 제목 경계 — 창을 막 만들어 탭을 받기 전 제목 = 「Engram」(+ 번호 규칙). 200 자 · 이모지 · 한글 섞인 탭 이름이 OS 제목에는 전부, 탭 머리에는 말줄임 + 툴팁으로 보이고 줄이 넘치지 않는다. 같은 이름 탭이 두 창에 있어도 번호로 가른다.
- **AC22** 창을 최소 폭까지 좁히면 그 아래로는 안 줄고, 그 폭에서 번호 표식 · 활성 탭(닫기 버튼 포함) · `+` · 끌 빈 자리(TRD 최소 폭 이상) · 단추 셋이 다 보이고 눌린다 — 배율 100 · 150 · 200% 에서.
- **AC23** Tab 으로 창 단추에 닿고 Enter · Space 로 눌리며 포커스 테두리가 보인다. 내레이터가 세 단추를 이름 · 상태로 읽는다 — 셋째 = 메인 「모든 창 숨기기」 · 팝아웃 「창 닫기」. Alt+Space — 결과(창 메뉴 뜸 · 안 뜸)를 QA 보고에 적고 Q10 에서 고른 갈래와 맞을 때만 통과: ① = 네이티브 메뉴가 뜨거나, 안 뜨면 그 회귀가 §2 비목표에 적히고 사용자에게 보고돼 있다 · ② = 우리 메뉴가 뜨고 항목이 버스 명령을 부른다. 결과를 적지 않은 통과는 없다.
- **AC24** 메인이 숨은 동안(트레이 숨기기 · `--hidden` 부팅) LLM 이 `window.create` 로 연 창을 닫기 단추 · Alt+F4 · 마지막 탭 닫기 · 0탭 자가닫힘(하네스로 그 창에 `tabs:[]` 를 보내 — W9)으로 각각 닫으면 네 길 모두 그 창이 모델 · `window.list` 에서 빠지고 없어진 뒤 번호가 풀리며, 보이는 창이 0 개여도 앱 · 트레이가 살아 있고 트레이 보이기가 메인을 되살린다.
- **AC25** 복원(Q8 ① · D3) — 메인 · 2 · 3 인 채 끄고 켜기를 세 번 하면 매번 같은 창(영속 id)이 같은 번호다(label 은 매번 새로 받는다 — `window.list`). 1 · 3 인 채 다시 켜도 1 · 3 이고 다음 새 창 = 2. 번호 칸이 없는 옛 상태 파일은 메인부터 저장 순서대로 1 · 2 · 3. 꾸민 상태 파일 — 두 팝아웃이 모두 3 → 앞 창 3 · 뒤 창 2 · 팝아웃의 1 · 0 · -1 · 「x」 → 비어 있는 가장 작은 번호 · 메인의 5 → 1 · 어느 경우에도 같은 번호 둘이 없다. 크래시 사본 수락(`restore.answer`) 뒤 사본의 창이 사본에 적힌 번호를 받고, 수락 동안 화면에 같은 번호의 창이 둘 보이지 않는다.
- **AC26** (Q9 ①) 창 인자에 번호 「2」를 주면 INVALID_ARGUMENT 로 거부하고 도움말이 `window.list` 로 영속 id 를 찾으라고 알린다. 2 를 닫고 새 2 를 만든 뒤 옛 2 의 영속 id · label 로 보낸 `window.close` 는 CONFLICT 이고 새 2 는 그대로다.
- **AC27** 이 판으로 처음 켤 때 저장된 창이 저장된 자리에 뜨고 내용 영역 크기가 같으며 화면 밖으로 나가지 않는다(D14). 최소 창 폭보다 좁게 저장된 팝아웃(작업 영역 오른쪽 끝에 붙은 것 포함)은 배율 100 · 150 · 200% 모니터 각각에서 최소 폭으로 넓혀 열리고 작업 영역 안에 다 들어온다.
- **AC28** 재시작 경계(D12) — 팝아웃 X 의 영속 id 와 label 을 읽어 두고 셸을 끄고 켠 뒤 늦게 보낸 `window.close(<영속 id>)` 는 복원된 X 를 닫거나 X 가 없으면 CONFLICT 이고, 앞 실행의 label 로 보낸 `window.close` 는 지금 실행에 팝아웃이 여럿 떠 있어도 CONFLICT 다 — 어느 쪽도 다른 창을 닫지 않는다. 크래시 사본 수락 앞에 읽어 둔 옛 팝아웃 label 로 보낸 명령도 CONFLICT 다.

**창 상태 옮김 표**(R22 · AC6 · AC7 · AC16 의 판정 · 기본값 — 메인 제안) — 「앞 사각형」 = 그 상태로 들기 전 보통 상태의 자리 · 크기 · 「작업 영역」 = 그 모니터에서 작업 표시줄을 뺀 곳 · 사각형 비교 = 보이는 가장자리 기준 물리 px ±2(보이지 않는 크기 조절 테두리는 빼고 · 오차 값은 TRD 가 기준 빌드 실측으로 확정) · 「기준」 = 기준 빌드에서 같은 조작으로 떠 둔 상태 · 사각형(OS 가 정하는 칸 — 미리 적지 않는다).

| 시작 \ 조작 | 빈 곳 두 번 누름 | 빈 곳 끌기 | Win+↑ · ↓ · ←/→ | 최대화 단추 | 복원 단추 |
|---|---|---|---|---|---|

- **Q1 스냅 레이아웃 메뉴를 지금 넣나** — 권장 = ① 로 시작하고, 원하면 ② 를 둘째 조각으로(조사 제목 §4 추천). Q5 와 묶였다 — 표의 「잃음」 전체가 Q1 · Q5 의 답으로 정해진다.
  - ① 넣지 않는다 — 위 표의 스냅 메뉴 줄을 **회귀로 받아들인다**(§2 비목표). 작다. 큰 Tauri 앱들(Yaak · Cap · GitButler 등)이 이 꼴이다(조사 제목 §3).
  - ② 넣는다 — 최대화 단추 위에 투명 Win32 자식 창을 덮어 OS 가 메뉴를 띄우게 한다(`platform` 에 직접 짓기 · 참고 플러그인의 MIT 귀속 유지 · Win32 코어 160–360 줄 규모). 중간 — 단추 자리를 웹이 재서 넘기는 길 · 올림/누름 중계 · DPI · 전체 화면 · 팝아웃마다 하나. 플러그인 셋은 돌려 보지 않았다(조사 제목 §3 · §5). Windows 10 은 ① 과 같다.
  - ② 를 고르면 그 조각을 이번 최종 머지에 넣을지 뒤로 미룰지도 정한다 — 트래킹 T-66 은 「따로 본다」, 조사는 「같은 단계의 둘째 조각」으로 적어 둘이 어긋난다.
- **Q5 끌기 영역 기법** — 권장 = ① Tauri `data-tauri-drag-region`(조사 제목 §2 · §4). Q1 과 묶였다.
  - ① Tauri 끌기 영역 — 그 요소 자신을 누를 때만 끌기 · 두 번 누름 최대화 · 탭 머리 · 단추 누름은 건드리지 않는다(확실 — Tauri `drag.js`). 권한 하나(`core:window:allow-start-dragging`)를 더해야 한다. 표의 오른쪽 클릭 창 메뉴를 잃고 터치 끌기는 미검. tauri#10767(W1).
  - ② CSS `app-region: drag` — 창 메뉴 · 터치/펜까지 OS 가 준다. 그 영역은 웹에 포인터 사건이 오지 않고, **그 위로 탭을 놓으면 닿는지 아무도 확인하지 않았다** → 고르면 스파이크 먼저.
- **Q6 새 탭 이름 — 제목이 내용을 말하게** — 권장 = ④. 지금 처음 이름은 갈래마다 다르다 — 새 창 팝아웃 「Popup N」 · 기존 창 팝아웃 「Tab」(`src-tauri/src/layout/apply.rs:746`) · `+` 「View N」 · `window.create` · 부팅 기본 「View 1」(`src-tauri/src/layout/manager.rs` `create_tab` · `create_window`). 제목이 활성 탭 이름을 따르므로(R3) ①–③ 이면 제목은 대개 「View N - Engram」이다.
  - ① 새 창 팝아웃만 에이전트 이름(메인 제안 문자 그대로) — 옮기는 순간의 이름으로 굳는다(뒤에 에이전트 이름이 바뀌어도 안 따라간다).
  - ② ① + 기존 창 팝아웃 — 같은 동작의 이름이 갈래마다 다르지 않게.
  - ③ ② + `+` · `window.create` 도 「새 탭」 — Chrome 과 같다. 「새 탭」이 여럿 겹친다.
  - ④ **자동 이름** — 사람(· `tab.rename`)이 이름을 정하기 전까지 탭 이름 = 그 탭 포커스 슬롯의 에이전트 이름(에이전트 없으면 R4 의 내용 이름) · 에이전트 이름이 바뀌거나 포커스가 옮기면 따라간다 · 이름을 정하면 굳는다(Chrome 의 탭 = 페이지 제목과 같은 꼴). 대가 = 슬롯이 여럿인 탭은 포커스 따라 이름이 바뀐다 · 탭마다 「정한 이름인가」를 저장한다 · 자동으로 되돌리는 길(TRD). 그 칸이 없는 옛 파일의 탭 = D16.
  - ⑤ 탭 이름은 ①–③ 대로 두고 창 제목만 활성 탭 포커스 슬롯의 에이전트 이름 — 탭바와 제목이 다른 말을 한다.
- **Q3 창 번호를 사람에게 어디에 보이나** — 권장 = ①. 옛 메인 제안(「탭이 없으면 「Engram N」」)으로는 **번호가 사실상 안 보인다** — 메인은 빈 탭을 늘 하나 남기고 팝아웃은 탭이 0 이 되면 닫힌다(코드 — `src/components/layout/WindowLayout.tsx` 0탭 자가닫힘 주석). OS 제목 표시줄을 걷으면 창 안에 창을 가를 것이 없어지고, Windows 11 작업 표시줄은 기본으로 단추 글자를 숨긴다.
  - ① 창 안 표식 + OS 제목 — 살아 있는 창이 둘 이상이면 모든 창(메인 = 1 포함)이 탭바 왼쪽 끝 작은 번호와 제목 끝 「- Engram N」을 보이고, 하나뿐이면 둘 다 없다. 대가 = 창 수가 1 ↔ 2 로 바뀔 때 탭이 쓸 폭이 표식만큼 바뀐다.
  - ② 표식을 늘 — 폭이 흔들리지 않지만 창이 하나여도 「1」이 보인다.
  - ③ OS 제목에만(메인 = 번호 없음 · 0.1판 권장) — 창 안에서는 안 보인다.
  - ④ 안 보임 — `window.list` 만. 사람이 「2번 창」이라 말할 근거가 없다.
- **Q8 번호를 저장해 재시작을 넘기나** — 권장 = ①(D3).
  - ① 번호를 창의 영속 id(D12)와 함께 저장하고 부팅 · 크래시 사본 수락 때 되살린다 · 비어 있는 가장 작은 번호는 새 창에만 — 「살아 있는 창 번호는 안 바뀐다」(D2)가 재시작에도 선다. 대가 = 상태 파일 칸 하나 · 옛 파일 규칙(D3).
  - ② 저장하지 않고 부팅마다 메인부터 저장 순서대로 다시 매긴다(0.1판 D3) — 1 · 3 으로 끄면 1 · 2 로 켜져 「3번 창」이 2 가 된다.
- **Q2 팝아웃도 같은 제목 표시줄인가** — 권장 = 같다. 슬롯 도킹 R24 「모든 창의 탭바가 같다」와 맞고, 팝아웃은 탭이 하나인 때가 많아 끌 빈 자리가 넉넉하다. 대가 = 팝아웃 쪽 끌기 · 놓기 실측이 는다(§4 머리 — AC 는 이 갈래로 잰다). 다르게 두면 팝아웃만 OS 제목 표시줄 + 그 아래 탭바(지금 모양)다.
- **Q9 명령이 창 번호를 인자로 받나** — 권장 = ①.
  - ① 받지 않는다 — 창 인자는 영속 id(· 같은 실행 안 label 별칭 — D12), 번호는 `window.list` 에서 id 를 찾는 데만. 영속 id 는 재사용되지 않고 앞 실행의 label 은 맞지 않아 늦은 명령이 다른 창에 닿지 않는다. 대가 = LLM 이 한 번 더 읽는다.
  - ② 받되 `window.list` 가 준 창 목록 판을 함께 줘야 받고, 판이 바뀌었으면 CONFLICT — 편하지만 칸이 늘고 LLM 이 판을 들고 다닌다.
  - ③ 그냥 받는다(0.1판 D11) — 2 를 닫고 새 2 가 생긴 뒤 늦게 도착한 `window.close("2")` 가 새 창을 닫는다.
- **Q7 메인 닫기 단추가 무엇을 숨기나** — 권장 = ①.
  - ① 지금 그대로 모든 창 — 모양 · 툴팁으로 구별한다(R10). 대가 = 같은 자리 단추가 창마다 다른 일을 한다.
  - ② 메인만 — 팝아웃은 남는다. 대가 = ADR-0229 「숨기기 경로는 하나다」 번복(새 ADR) · 메인 없이 팝아웃만 보이는 상태가 생긴다.
- **Q10 키보드 창 메뉴(Alt+Space)** — 권장 = ①.
  - ① 네이티브 — 테두리 없는 창에서 뜨는지 스파이크로 보고, 안 뜨면 회귀로 받아들인다(Win+화살표 · Alt+F4 · 단추로 대신).
  - ② 우리가 그린 창 메뉴(Alt+Space · 빈 곳 오른쪽 클릭) — 항목이 버스 명령을 부른다. 대가 = 키 가로채기 · 메뉴 그리기 · 접근성.
- **Q4 창 이름 바꾸기를 넣나** — 권장 = 이번엔 안 함(비목표). 창 제목이 활성 탭 이름을 따르고 번호가 창을 가른다. 넣으면 사람 입구(빈 곳 오른쪽 클릭 메뉴 등 — 지금 없음) · `window.rename` · 제목 규칙(「<활성 탭> - <창 이름>」 — Chrome 「창 이름 지정」 · 조사 이름 §2 ④) · 저장이 함께 는다.

### 5-3. 기본값 (메인 제안 — 사용자가 바꿀 수 있다)

- **D1** 메인 = 늘 1번. 메인은 닫히지 않고(숨기기뿐 — ADR-0026) 늘 살아 있다. 숨은 창도 살아 있는 창이라 번호를 쥔다.
- **D2** 살아 있는 창의 번호는 바뀌지 않는다 — 앞 번호 창이 닫혀도 당겨 매기지 않는다(tmux 의 기본 · 결정의 예 「새 창 = 2」와 맞는 쪽). 재시작을 넘어서도 = Q8 ①.
- **D3** (Q8 ①) 번호를 영속 id 와 함께 화면 상태에 저장하고 부팅 · 크래시 사본 수락 때 되살린다. 저장값 고치기 — 메인 = 늘 1(저장값을 보지 않는다) · 양의 정수가 아니면(0 · 음수 · 숫자 아님 · 칸 없음 = 옛 파일) 없음 · 팝아웃이 적은 1 = 없음 · 같은 번호를 둘 이상이 적었으면 저장 순서에서 앞 창만 갖고 나머지는 없음. 바른 번호를 먼저 다 세운 뒤 없음인 창이 저장 순서대로 비어 있는 가장 작은 번호를 받는다. 사본 수락(`ViewManager::adopt_restored` — 살아 있던 팝아웃을 걷고 사본의 창을 세운다)은 갈아끼우기라 옛 팝아웃(닫히는 중 포함)의 번호를 다 풀고 사본 번호를 세우되, 사본 창은 옛 팝아웃이 모두 없어진(`Destroyed`) 뒤 보인다 — 지금은 사본 창을 보인 뒤 옛 창을 걷는다(`src-tauri/src/state/restore.rs` `after_commit` · 순서 = TRD).
- **D4** 제목의 앱 이름 = 「Engram」(지금 메인 「Engram Dashboard」 · 팝아웃 「Engram — …」을 모두 바꾼다) · 구분자 = 「 - 」(Chrome 과 같다 · 조사 이름 §2 ③).
- **D5** (Q6 ①–③ 일 때만) 팝아웃 탭 이름은 옮기는 순간의 이름이다 — 바꾸려면 탭 이름 바꾸기. ④ 면 이 D 는 없다.
- **D6** 사람의 창 단추 = 버스 명령 호출(R17). 메인 닫기 단추 = 모든 창 숨기기 — 지금 OS 닫기(X)와 같다(ADR-0026 · ADR-0229).
- **D7** 빈 곳 끌기 · 두 번 누름은 Tauri 끌기 스크립트가 OS 를 직접 부른다 — 지금 OS 제목 표시줄과 같은 층이라 버스를 지나지 않는다. 결과 상태는 R18 로 LLM 에게 같이 보인다.
- **D8** 줄 높이 · 최대화 아닐 때 탭바 위 여백 · 끌 빈 자리 최소 폭 · 단추 누름 자리 · 최소 창 폭 = Windows 11 · Chrome 관행을 따르고 값(DIP)은 TRD 단계(사용자 결정 뒤 · 탭바 넘침과 같은 「Chrome 규칙」 기조 — Chromium 소스를 읽어 확인). AC18 · AC22 · AC27 이 그 값을 잰다.
- **D9** 끌기 동안 이 줄의 빈 곳 · 표식 · 창 단추는 「탭바」로 본다(R14) — 끼울 자리 막대는 보이는 마지막 탭 뒤(슬롯 도킹 D25).
- **D10** 창 크롬 모양(단추를 우리가 그리나 · 왼쪽을 비울 폭)은 셸이 창마다 알려 주고 웹은 그대로 그린다 — OS 가름은 `platform` 한 곳(R16).
- **D11** 창 인자 = 영속 id(· 같은 실행 안 label — D12) — 번호를 받을지는 Q9(0.1판 「둘 다 받는다」는 Q9 ③ 으로 옮겼다).
- **D12** **명령의 창 인자 = 영속 id**(메인 = `main` · 팝아웃 = 처음 생길 때 뽑은 UUID — `src-tauri/src/state/schema.rs:46` `WindowEntry`) — 재시작 · 사본 수락을 넘어 같은 창을 가리키는 유일한 손잡이다. label 은 같은 실행 안의 별칭으로만 맞는다: 팝아웃 label 은 실행마다 1 부터 다시 세므로(`src-tauri/src/layout/manager.rs:240–242`) label 에 실행 표식을 실어(꼴 = TRD · glob `slot-popup-*` 안) 앞 실행의 label 이 지금 실행의 어느 창에도 맞지 않게 한다 → CONFLICT. 별칭을 남기는 까닭 = 지금 label 을 넘기는 프론트 레지스트리 · 셸 안 호출을 그대로 둔다. 다른 갈래 = ① 영속 id 만(label 거부) — 가장 단순하지만 창 인자를 쓰는 명령(`tab.*` · `window.close` · `window.getTheme`/`setTheme` · `slot.popout` 등)의 모든 호출이 바뀐다 ② label 카운터를 상태 파일에 저장해 실행을 넘어 단조 — 꼴은 그대로지만 저장이 늦거나 실패한 채 꺼지면 앞 실행이 나눠 준 label 보다 작은 값부터 다시 센다 ③ 지금처럼 label 만 — 재시작 뒤 늦은 명령이 다른 창에 닿는다(2차 리뷰 BLOCK).
- **D13** 번호는 OS 창이 실제로 없어질 때(`Destroyed`) 풀린다(R1) — 모델에서 빠진 뒤 그때까지 닫히는 창 몫으로 잡혀 새 창이 받지 않는다. 그래서 `window.list`(새 창)와 화면(닫히는 창의 표식 · 제목) 어디에도 같은 번호 둘이 함께 보이지 않는다. 대가 = 그 잠깐 `window.list` 에 없는 번호가 비어 있지 않다(1 · 2 · 3 에서 닫히는 2 가 아직 있으면 새 창 = 4 — 도움말에 적는다) · `Destroyed` 가 끝내 안 오면 그 번호는 실행 끝까지 잡힌다(W7). 거부한 갈래 = 모델에서 빠질 때 풀고 닫히는 창을 먼저 숨긴다 — 숨기기 호출이 돌아온 것은 화면에서 사라졌다는 OS 확정이 아니어서 실패 · 늦음을 따로 다뤄야 하고, 닫는 길(닫기 요청 · `window.close` 의 직접 파괴 · 사본 수락의 거두기)마다 숨기기를 끼워야 한다. 0.2판의 「모델에서 빠질 때」(숨기기 없이)는 같은 번호 둘이 보였다(2차 리뷰 BLOCK).
- **D14** 저장된 창 크기 — 옛 상태 파일의 안쪽 크기를 그대로 쓴다: 내용 크기는 같고 창 바깥만 OS 제목 줄만큼 짧아진다(한 번뿐 · W5). 단 최소 창 폭(R20)이 이긴다 — 저장된 폭이 그보다 좁으면 최소 폭으로 넓혀 열고, 넓힌 창이 작업 영역을 넘으면 크기는 두고 자리를 작업 영역 안으로 당긴다. 다른 갈래 = 첫 부팅에 제목 줄 높이를 더해 바깥 크기를 지킨다 — 그 높이가 배율 · OS 판마다 달라 고르지 않았다.
- **D15** 좁은 창 = 최소 창 폭(R20). 다른 갈래 = 좁으면 단추를 줄인다(Windows · Chrome 과 어긋난다) · 끌 빈 자리만 보장하고 활성 탭까지 숨긴다(무엇을 보는지 안 보인다).
- **D16** (Q6 ④) 옛 상태 파일의 탭(「정한 이름인가」 칸 없음) — 이름이 지금 코드가 짓는 기본 꼴 그대로(「View N」 · 「Tab」 · 「Popup N」 — `src-tauri/src/layout/manager.rs` `create_tab` · `apply.rs:746` · `commands/popout.rs:61`)면 자동 이름, 그 밖은 정한 이름. 대가 = 사람이 일부러 「View 2」로 지은 탭도 자동이 된다. 다른 갈래 = 옛 탭 전부 정한 이름(옛 창 제목이 「View N - Engram」으로 남는다) · 전부 자동(사람이 지은 이름을 잃는다).

## 6. 위험

- **W1 tauri#10767 × 슬롯 도킹 끌기 상태** — 끌기 영역을 누른 뒤 `mouseup` 이 웹에 안 오고 포커스가 깜빡이는 열린 이슈. 탭바의 마지막 누름 자리 · 끌기 시작 판정과 엮이는지 미조사(슬롯 도킹 W5 와 같은 것) → AC13.
- **W2 끌기 영역 위 놓기** — Tauri 끌기 영역은 사건을 막지 않는 평범한 요소라 막을 이유는 보이지 않지만 돌려 보지 않았다(조사 제목 결론 4) → AC12. Q5 ② 는 더 모른다.
- **W3 탭 폭 상수** — 지금 `A` = 42 는 실측상 엄밀히 44 이고 「T-66 에서 다시 끌어낸다」로 미뤄 둔 값이다(슬롯 도킹 TRD §1-3 · §7 #73). 탭 스타일 · 줄 높이가 바뀌면 표준 · 비활성 최소도 다시 잰다. 탭이 쓸 폭이 표식 · 단추 · 끌 자리만큼 줄어 지금보다 일찍 숨는다.
- **W4 권한 빠뜨림** — `core:window:allow-start-dragging` 이 `src-tauri/capabilities/default.json`(main) · `popup.json`(`slot-popup-*`) 어디에도 없다. 빠뜨리면 빈 곳 끌기가 소리 없이 안 된다(웹 콘솔 오류만).
- **W5 저장된 창 크기** — 화면 상태는 바깥 위치 + **안쪽 크기**를 저장한다(`src-tauri/src/state/placement.rs` 머리). OS 제목 표시줄이 없어지면 첫 부팅의 창이 그 줄 높이만큼 짧아진다(미검 · 한 번뿐) → D14 · AC27.
- **W6 창 메뉴** — Tauri 끌기 영역은 빈 곳 오른쪽 클릭에 창 메뉴를 띄우지 않는다(`drag.js` — 왼쪽 단추만 본다). Alt+Space 가 테두리 없는 창에서 뜨는지 미검 → Q10.
- **W7 팝아웃 닫기 전제** — 셸은 「팝아웃 닫기 요청은 되돌려지지 않는다 · 프론트에 닫기 요청 리스너가 없다」를 전제로 모델을 먼저 지운다(`src-tauri/src/lib.rs:305–330` CloseRequested 갈래). 닫기 단추가 닫기 요청 리스너나 닫기 취소를 들이면 그 전제가 깨진다 — 버스 명령으로 닫는다(R17). 번호는 `Destroyed` 에서 풀리므로(D13) 닫기가 취소된 창 · `Destroyed` 가 안 온 창은 모델에 없이 번호만 쥐고, 그 번호는 실행 끝까지 비지 않는다.
- **W8 스냅 오버레이(Q1 ②)** — 플러그인 셋을 빌드 · 실행해 보지 않았다 · 최소 창 폭 조건(330–500 px 보고 — R20 의 최소 폭과 맞춰 봐야 한다) · 배율 변화 · 전체 화면 · 팝아웃마다 하나(조사 제목 §5).
- **W9 0탭 자가닫힘** — 팝아웃에 `tabs:[]` 가 닿으면 웹이 Tauri 창 닫기를 직접 부른다(`src/components/layout/WindowLayout.tsx:229–245` · 주석상 정상 흐름에선 죽은 방어 경로). 이번에 그 호출을 버스 닫기(자기 영속 id — R17)로 바꿔 X 단추와 같은 셸 닫기 길(모델 · 번호 · 트레이 정리)을 타게 한다. 정상 흐름에선 안 타므로 하네스로 잰다(AC24).
- **W10 앞 창 잠금** — LLM 이 부르는 앞으로 내기는 셸이 앞 프로세스가 아닐 때 Windows 의 앞 창 바꾸기 제한에 막혀 작업 표시줄 깜빡임으로 끝날 수 있다(트레이는 누름이 그 권한을 준다 — `src-tauri/src/tray/actions.rs` 의 show → unminimize → set_focus 순서 주석). 미검 → AC9.
- **W11 상태 파일 칸 더하기** — 화면 상태에 번호 칸(Q8 ①) · 탭의 「정한 이름인가」 칸(Q6 ④)이 는다. 옛 파일 읽기(D3 · D16) · 새 판을 옛 앱이 읽을 때의 처리는 저장 규약(`docs/process/S21-storage/trd.md`)을 따른다 — TRD.

## 7. 사용자에게 물을 것 (영향 큰 순)

1. **Q1 스냅 레이아웃 메뉴** — 권장 = 지금은 없음(①), 원하면 둘째 조각(②). 대가: ① 은 작고 관행이지만 메뉴 회귀를 받아들인다 · ② 는 진짜 메뉴지만 Win32 자식 창 · 중계 · DPI 를 우리가 진다.
2. **Q5 끌기 영역 기법**(Q1 과 묶임) — 권장 = Tauri 끌기 영역. 대가: 탭 놓기가 안전한 쪽이지만 오른쪽 클릭 창 메뉴를 잃고 터치 끌기는 미검.
3. **Q6 새 탭 이름** — 권장 = 자동 이름(에이전트 이름을 따르다 사람이 정하면 굳음). 대가: 제목 · 탭이 내용을 말하지만 슬롯 여럿인 탭은 포커스 따라 이름이 바뀌고 저장 칸이 는다.
4. **Q3 창 번호 보이는 곳** — 권장 = 창이 둘 이상일 때 창 안 표식 + OS 제목. 대가: 창 안 · 작업 표시줄 어디서나 「2번 창」이 보이지만 창 수가 1 ↔ 2 로 바뀔 때 탭 폭이 바뀐다.
5. **Q8 번호 저장** — 권장 = 영속 id 와 함께 저장해 재시작에도 같은 번호. 대가: 「3번 창」이 계속 3 이지만 상태 파일 칸 · 옛 파일 규칙이 는다.
6. **Q2 팝아웃도 같은 제목 표시줄** — 권장 = 같다. 대가: 모든 창이 한 모양이지만 실측 범위가 는다.
7. **Q9 명령이 번호를 받나** — 권장 = 받지 않음(영속 id · 같은 실행 안 label). 대가: 엉뚱한 창에 닿을 일이 없지만 LLM 이 `window.list` 를 한 번 더 읽는다.
8. **Q7 메인 닫기가 숨기는 것** — 권장 = 지금처럼 모든 창(모양 · 툴팁으로 구별). 대가: 동작은 그대로지만 같은 자리 단추가 창마다 다른 일을 한다.
9. **Q10 Alt+Space** — 권장 = 네이티브 확인 후 안 되면 회귀 받아들임. 대가: 짓는 것이 없지만 키보드 창 메뉴를 잃을 수 있다.
10. **Q4 창 이름 바꾸기** — 권장 = 이번엔 안 함. 대가: 범위가 작지만 창에 사람이 정한 이름을 못 붙인다.
