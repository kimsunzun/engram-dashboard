## 1. Answers to the 「먼저 결정할 둘」 of T-29

- **① Sending to an agent that does not exist yet** — even now it is not parked. A name that exists nowhere is `RECIPIENT_NOT_FOUND` (`service.rs:3090` `absent_disposition` · ADR-0116 decision 1). Parking happens only for a sleeping agent that has a profile, and that has an id. No separate mechanism is needed (certain).
- **② An agent restarting with a new id** — the same profile comes back up with the same id (`agent/manager.rs:1641` `spawn_session(profile.id, …)` · session id = profile id). A new id is a different profile and, per ADR-0309 decision 5, does not receive. No migration mechanism is needed (certain). When a live session without a profile (the deletion gap of ADR-0122) dies, it is not sleeping but absent, so the parked items addressed to it become `expired` by TTL (until now the next agent with the same name received them — the same direction as decision 5).

## 3. What gets removed

- **The hint mechanism (decision 7):** `ParkedMessage.hinted_id` · `Mailbox::queues_with_hint` (`mailbox.rs:623`) · the per-item target resolution in `drain_queue` (hint → unique reach by name, `service.rs:1520`) · the name queue + hint queue scan in `flush_for_agent` (`:1855`) · the extra `by_name` doorbell in `deliver_notice` (`:2005`) · `unique_reachable_in` (`:3888`) · the `live_agents()` call in `sweep` (`:1941` — it used only `by_name`).
- **The contract name fallback (decision 7 · ADR-0120 list 3):** the name branch of `match_contract_for_replier` (`ledger.rs:1010`) · `replier_name` of `close_on_reply` · `fail_on_undeliverable_reply` · the `allow_name_fallback` argument · the namesake count of `handle_send` (`service.rs:701`) · the two fields of `ReplyClosing` · `rebind_request_recipient` (`ledger.rs:897` — the recipient id exists from the start and the queue = that id, so the landing id is always the same) · `matches_contract_party` (`service.rs:2427`).
- **The name-axis guard of deletion cleanup (decision 6 · list 5):** the `live_id_for_name` branch of `handle_profile_deleted` (`:1204`) and that port method.
- **The `canonical_name` port:** if `flush_for_agent` first filters by 「큐가 비었나」, there is no user.
- **The loser key · A8/M3 (ADR-0120 list 4 · 6):** `loser_key` (`:3009`) · `dup_of` · the resolution swap in `push_recipient` · the failure row 「다른 실체가 같은 이름 키」. If the key is an id, different entities cannot contend for a key, so this is structurally never reached (U3).
- **What stays (ADR-0309 impact — TRD decision):** list 1 (same-name blocking in the dormant layer) · 2 (the live layer beats the dormant layer) **stay**. These are resolution rules when calling by name, and same-name still arises in operation — deleting a renamed live profile leaves the session alive, its name falls back to the basename and overlaps with another agent (the known gap of ADR-0122 decision 6 — likely). Dormant twins arise only from an old `agents.json` · the test seam.
- **What does not die but loses its use (not removed — Q2):** the ADR-0142 target axis (`in_flight_targets` · `deferred_by_target` · `FlightSettle.targets`) — the only trigger that ADR names (two name queues converging on one session) cannot arise with id keys. The id set of `deferred_flush` is also always a single queue id. It does no harm to correctness, so it stays this time.

## 7. Risks · open questions

- **Q1 (needs a user decision — outside the ADR):** do we accept X0~X4. Default = accept (same-name is unsupported — a consequence of ADR-0116 decision 5 · ADR-0120 · decision 3's second line). If we reject, U3 must keep group expansion as a round trip through names, and that conflicts with decision 3's second line.
- **Q2 (main session):** do we remove the ADR-0142 target axis. The trigger disappears, so the tests that covered that axis (convergence · hint) vanish in U2a, and the remaining path (from the last settlement of the same queue to target release) is hard to make a test for — code without tests is left. Default = keep it this time and do it separately as U6 (an ADR-0142 amendment).
- **Risk — deterministic `live(name)`:** a test that used the same name for two entities may silently become one entity and pass vacuously. Mitigation = before the substitution, extract the twin tests with grep and change them to `live_distinct` first.
- **Risk — U2a size:** the test module is ~7300 lines. If the mechanical substitution is not done in one go, the calls overflow. Mitigation = a bulk regex in §6-1 + separating the §6-2 list.
- **Risk — removing the contract `recipient_id` from Option (U1):** the only path that opens a contract is `handle_send`, and a failure row drops out before the contract is opened, so the id is always there (likely — the `Failed` → `continue` in `service.rs` is before `open_request`). If another entry point appears, revisit this assumption.
- **Remaining residue (unchanged):** a reply goes by name at the edge (decision 2). If the requester renames, a reply to the old name is `RECIPIENT_NOT_FOUND` → the contract `reply_failed`, and if another agent took the old name, it is delivered to that agent — the same as now.
- **Not confirmed:** whether a profile copy feature exists (ADR-0309 impact) · whether CI has clippy.
