# Command surface — owners are not declared (what ADR-0176 handed over)

> **Status:** Waiting for trigger · **Canonical index:** [`../todo.md`](../todo.md)

> The two are **one lump.** Fixing ① below makes the conflict in ② disappear as a by-product. Look at them together when working on the agent-tree system (user decision 2026-08-26). The canonical source for *why* = ADR-0176.

- **① Commands do not name their own owner, so it is obtained by subtraction** — Today the webview's part is computed as `프론트 레지스트리 − 데몬이 답하는 이름 − 셸 표가 답하는 이름` (`reserved_names` in `src-tauri/src/view_commands.rs`). This is because the frontend registry **also contains entries it does not answer itself** (`tab.create` is answered by the shell table, and `agent.spawn` is ultimately answered by the daemon), so declarations cannot tell them apart. That subtraction is the only reason `engram_dashboard_agent::commands::COMMAND_SPECS` is read, and it is the **last agent symbol** left in the shell. Switching to declarations makes the filter, the edge and the prefix unnecessary all at once. **Why not now:** see ADR-0176 — closing the edge does not change the dependency-cap gate figure (7 either way, through the manifest declaration + the `daemon` dev-dependency transitive), and the real gain, release binary size, has not been measured.
  - ★**Do not delete `reserved_names` first — the app breaks**★. The daemon **collects all overlapping names and bounces the whole packet** (`crates/engram-dashboard-daemon/src/connection_core.rs:675` + call site `:1279-1280`), and when it is bounced, registration does not run at all — because of one overlap, the rest of the shell's names also cannot get into the registry.
  - **If a classification axis is needed, solve it with a field.** `category` is already in the declaration (`src/commands/registry.ts:48`) and `list()` exposes it (`:127-131`) — but today's values are on the noun axis (`agent` · `slot`), so it does not carry 「누가 답하나」 (who answers). ★The option of solving it with an identifier prefix was rejected by ADR-0176★.
  - **One measurement first** — the routing priority of overlapping names (does the daemon table come first?). The comment says *"route looks at the table first"*, but it was not verified. The rejection rationale for the 「데몬 반려 검사를 없앤다」 (eliminate the daemon bounce check) option is that much weaker (ADR-0176 §거부한 대안 (Rejected alternatives)).
- **② The frontend resolves by duplicating a daemon-owned preset** — the frontend `agent.spawn` takes `preset` (id), finds the cwd in `store.presets`, and then calls the daemon (`src/commands/agentCommands.ts:41`). But ★the preset is owned by the daemon★ (`crates/engram-dashboard-agent/src/persistence/presets.rs` `FilePresetStore`). **The same file already shows the direction of the fix — the daemon `agent.new` takes `preset` directly** (mutually exclusive with `cwd`, exactly one of the two). If `agent.spawn` did the same, the frontend wrapper would disappear and **the 2 conflicts (`agent.spawn` · `agent.rename`) would disappear with it.** **Why not now:** it is a daemon command argument change + frontend command deletion + ownership cleanup, so it naturally ties in with the agent-tree work (user decision).
  - **Side observation — the same name behaves differently depending on the surface that calls it.** Because the filter pulls the frontend's `agent.spawn` out of the registration packet, only the daemon's entry goes into the registry, and the frontend's is reachable only through `window.__engramCmd`. Daemon path = cwd only, frontend path = preset too. ★What creates this mismatch is the filter itself.★
  - **Whether `agent.rename` has the same structure was not checked.** Check it together when starting ②.

## Command-surface owner declaration — ★not a target to start now★

- **What:** Commands do not declare their own owner, so the webview's part is obtained by subtraction. That subtraction is the last reason an agent symbol remains in the shell.
- **Why not now:** It is already set as 「에이전트 트리 시스템을 손볼 때 함께 본다」 (i.e. look at it together when working on the agent-tree system) (user decision 2026-08-26). Do not open it until the tree work is picked up.
- **Canonical:** *why* = ADR-0176 · *what* = the section above in this document. ★Be sure to read the warning 「`reserved_names` 를 먼저 지우지 말 것」 (do not delete the reserved-names list first) in this document before starting★ — deleting it breaks the app.
