# Observed only (judgment deferred)

> **Status:** Observed only · **Canonical index:** [`../todo.md`](../todo.md)

- **`TERM` is not set** — the core has no such assignment, so claude uses an inherited value or its own guess. One axis of terminal capability negotiation is left to chance. There has been no problem so far.
- **Circumstances of the app vanishing by itself** — right after deleting a profile assigned to a live slot, the process disappeared with no exit log (at the end of the 2026-08-20 GUI measurement). Causation unconfirmed, not tried to reproduce.
- **Two lines of `main_loop` are uncovered** — the replay event apply call and the dispatch of its return command. Deleting them leaves every gate green.
- **There is no test for the ordering where incarnation registration happens before the first signal** — only an argument exists. If the call site is later moved, the gate stays green and silently breaks.
- **~~`src-tauri/bindings/` is outside the CI sync gate~~ → ★closed on 2026-08-24★.** Old description: the generated-output directories the gate looks at are only protocol and core, but three are committed, so what should be regenerated silently drifts (that is why `SlotContent.ts` was fixed by hand on 2026-08-21 — at that time the lib test target of that package died with `0xc0000139`, so regeneration itself was impossible and the export test was inside it). **The two halves closed in turn:** ① with `--test lib_unit` in place, the `.ts` files of that directory are automatically regenerated each time that suite runs (ADR-0174) ② CI set up a step that runs that suite and widened the existing sync gate to **three directories**. ★**That step now runs the whole suite**★ — the name filter that picked only the export test to avoid the red ones was removed (those failures were all fixed), and the workspace regression also dropped its exclusion of this package and generates the same `.ts` once more. ★**The order dependency that used to be 「게이트를 넓히려면 알려진 실패 수정이 먼저다」 (the known failures must be fixed before the gate can be widened) no longer remains**★ (canonical status = `ci.yml` · qa binding 「모듈별 명령」).
- **2 types that are serialized but have no shape gate** — `PtyEvent` (`crates/engram-dashboard-agent/src/types.rs` — the one whose own comment says "if this value is dropped, the output disappears entirely at the frontend guard") · `InjectionRecord` (`crates/engram-dashboard-daemon/src/experiment/record.rs`). Both derive serialization yet have no test asserting the shape, so a field rename or deletion passes every gate.
- **~~`decide_epoch` runs on every frame in production but has no CI gate~~ → ★closed on 2026-08-24★** — the definition is in `src-tauri/src/daemon_client/protocol_state.rs`, the call is in the WS frame loop of `connection.rs`, and it is also reachable from a registered Tauri command handler (it is not dead code). The test that measures it is inside `#[cfg(test)]`, and the target that holds it (`lib_unit`) is now **carried into CI whole**, and the workspace regression also runs this package. The reason died twice: the old `0xc0000139` instant death went away with ADR-0174, and the 「알려진 실패 때문에 전체 등재를 미뤄 뒀다」 (full registration was deferred because of known failures) that remained after that disappeared when those failures were all fixed (canonical status = `ci.yml` · qa binding 「모듈별 명령」). ★**The observation itself that none of the 4 shell integration suites calls this function remains true — but it no longer means coverage 0.**★
- **Replayed output may answer terminal queries again — in a light reproduction no query answer leaked, but a focus report goes out again** — the concern is that rewinding raw output into xterm makes xterm answer the queries inside it (cursor position report `CSI 6n` · background color `OSC 11;?` and so on) again, and those answers can leak into the PTY as input. The input guard of `TerminalSlot.tsx` (`onData`, `:386-387`) blocks only when there is no agent. Precedent = CARB/IDE ADR-014(https://docs.carbidecore.online/design/decisions/adr-014-terminal-renderer-model/ · its #87).
  - **Reproduction attempt (2026-09-25 · light only, at the user's request · 3 runs · claude v2.1.280 · agent idle at the prompt)** — during replay no answer to any query reached stdin. The queries contained in claude's real output were only XTVERSION `CSI > 0 q` (2 times) and the kitty keyboard query `CSI ? u` (1 time), and in the range seen through the parser hook (startup and rewind in the idle state) there were no DSR · DA · DECRQM · OSC color queries. xterm answers neither of those two.
  - ★**New observation — on every replay a focus report goes out again to the stdin of the live agent**★ — the observed value was `ESC[O` (bytes 27,91,79), 3 times per replay. This window was driven by CDP and it was not checked whether the xterm element held DOM focus. At startup it also went out 3 times live (observed), and no residue was visible on the claude input line (observed). xterm sends `ESC[O` if the element has no focus and `ESC[I` if it does (source reading — `CoreBrowserTerminal.ts` `_reportFocus` in `@xterm/xterm`). So **whether `ESC[I` goes out for an area that actually holds focus is untested**. Guess (**untested**): the rewound output turns focus reporting mode (`ESC[?1004h`) on again and each time xterm reports the current focus state.
  - **Limits** — other claude states (tool execution · `/` menu · resize redraw) were not exercised. The replay buffer has a cap.
  - **Why not now:** the direction of the fix is not decided — the only thing confirmed to leak is the focus report, and no visible harm has been observed yet.
- **Every layout snapshot redraws all area bodies** — the memo of `SlotBody` compares `node` by reference, but the snapshot creates new node objects. It is not a remount. **Why not now:** there is no cost measurement. The fix = `node.id` + `content` value comparison, or structural sharing.
- **Other name forms the gate regex cannot see** — the `replay_flight` purity gate and `transport gate 3` (the pure layer) look only for the `<이름>::` form, and let aliases (`use tokio as rt;` · `extern crate tokio as rt;`) · tail-segment import (`use std::net;`) · multi-item groups (`use std::{net::TcpStream, time::Instant};`) pass. The limits are written in the replay_flight gate comment (`ci.yml`) and in transport header gate ③ (the same kind — the base header's grouping limit · the platform gate 6 header's alias · grouping limit). **Why not now:** unlike the whitespace form (S31), it also appears in normal code that passes rustfmt and has several forms, so it is not closed by this whitespace-form extension and the check method must be decided separately (among forbidding the entire `use <이름>` form · expanding groups · a compiler check).
