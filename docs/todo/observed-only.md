- **재생 출력이 터미널 질의에 다시 답할 수 있다 — 가벼운 재현에선 질의 답은 안 샜고, 대신 포커스 보고가 다시 나간다** — 원시 출력을 xterm 에 되감으면 그 안의 질의(커서 위치 보고 `CSI 6n` · 배경색 `OSC 11;?` 등)에 xterm 이 다시 답하고, 그 답이 입력으로 PTY 에 샐 수 있다는 우려다. `TerminalSlot.tsx` 의 입력 가드(`onData`, `:386-387`)는 에이전트가 없을 때만 막는다. 선례 = CARB/IDE ADR-014(https://docs.carbidecore.online/design/decisions/adr-014-terminal-renderer-model/ · 그쪽 #87).
  - **재현 시도(2026-09-25 · 사용자 요청으로 가볍게만 · 3 회 · claude v2.1.280 · 프롬프트에서 쉬는 에이전트)** — 재생 중 어떤 질의의 답도 stdin 에 닿지 않았다. claude 의 실제 출력에 든 질의는 XTVERSION `CSI > 0 q`(2 회)와 kitty 키보드 질의 `CSI ? u`(1 회)뿐이었고, 파서 훅으로 본 범위(쉬는 상태의 기동·되감기)에서는 DSR·DA·DECRQM·OSC 색 질의가 없었다. xterm 은 그 둘 어느 것에도 답하지 않는다.
  - ★**새 관측 — 재생할 때마다 포커스 보고가 산 에이전트의 stdin 으로 다시 나간다**★ — 관측값은 `ESC[O`(바이트 27,91,79)가 재생마다 3 회였다. 이 창은 CDP 로 몰았고 xterm 요소가 DOM 포커스를 쥐고 있었는지는 확인하지 않았다. 기동 때 live 로도 3 회 나갔고(관측), claude 입력줄에 보이는 찌꺼기는 없었다(관측). xterm 은 요소에 포커스가 없으면 `ESC[O`, 있으면 `ESC[I` 를 보낸다(소스 판독 — `@xterm/xterm` 의 `CoreBrowserTerminal.ts` `_reportFocus`). 그러니 **실제로 포커스를 쥔 칸이면 `ESC[I` 가 나가는지는 미검**이다. 추정(**미검**): 되감은 출력이 포커스 보고 모드(`ESC[?1004h`)를 다시 켜고 그때마다 xterm 이 현재 포커스 상태를 보고한다.
