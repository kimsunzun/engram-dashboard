# 터미널 한글 조합 표시

> **상태:** 소유됨(브랜치 `v0.3.2/fix/terminal-cursor-ime-resize`) — 사용자 실 입력기 확인 대기 · **정본 색인:** [`../todo.md`](../todo.md)

평평한 분할 렌더러 머지 뒤 사용자 GUI 확인(2026-09-25)에서 갈라낸 것. 같은 브랜치가 함께 맡았던 치수 가드·커서 기본값은 `fa1690d` 로 닫혀 이 파일에서 지웠다 — 기록 = `../process/step-log.md` 의 「숨은 칸은 구독 직후 치수를 보내지 않고」 항목.

- **한글 조합 표시가 깨진다 — 사용자 실 입력기 확인 대기** — 증상 = 조합 중 커서가 사라지고 조합 글자 위에 작은 파란 선이 보인다. CDP `Input.imeSetComposition` 흉내로 재 봤다(★실 Windows 입력기가 아니다★ · 2026-09-25):
  - 커서 변경(막대) 뒤 흉내 조합에서 **파란 선이 보이지 않았다.** ★변경 전을 같은 방법으로 재현한 적은 없어 커서 변경이 고쳤는지는 미확인이다★.
  - 조합 상자(`.composition-view`, 배경 `#000` — 터미널 배경은 `#0a0a0a`)가 커서 칸 위에 정확히 얹혀 조합 동안 막대를 덮는다(xterm 기본 동작) — **조합 중 커서가 안 보이는 것은 그대로다.**
  - 조합을 확정한 「한」은 stdin 에 제대로 닿았다.
  - **사용자가 볼 것** = 실 입력기로 한글을 칠 때 ① 파란 선이 보이나 ② 조합 중 커서가 가려지는 것을 문제로 볼지 ③ 확정한 글자가 제대로 들어가나.

**연관:** 이 브랜치의 치수 가드가 드러낸 남은 치수 결손 = [`terminal-sizing.md`](./terminal-sizing.md) · 커서를 사용자 설정으로 여는 일 = [`display-policy.md`](./display-policy.md)(트리거 대기).
