# Terminal dimension propagation

> **Status:** Waiting for trigger · **Canonical index:** [`../todo.md`](../todo.md)

- **Propagation points are scattered across four places** — window resize detection (RO) · visibility transition (`attachWebgl`) · reattach (onReset) · initial mount (right after subscription). These four are the four places that emit `resizePty`. Each has its own condition, so a new path can omit one again (in fact it was omitted on reattach and the screen broke). Hooking it into one place, xterm's grid-change event, structurally guarantees that "if the grid changes, the PTY always changes too." **Why not now:** a separate task that folds the existing four effects. ★That the hidden guard was missing only on the initial mount path was closed by `fa1690d`★ — that path now goes through the shared decision (`src/components/slot/TerminalSlot.tsx:257` `sendSizeIfMeasurable`). **Of the four places, only that one uses the helper, and the other three keep their own decisions** (the items below). The re-propagation after reconnect (ADR-0195) also uses the same helper but is an additional trigger outside the four (it shares the helper's send site).
  - **Hidden-state facts to use as premises when folding (2026-09-25 · CDP · this PC)** — the container of a display:none area has `offsetParent` null, its computed width and height are literally `"100%"`, and the rectangles are all 0 (measured). The `fit()` of an area **mounted while hidden** = **11×6** — FitAddon reads `"100%"` as 100px (measured · it is neither of the two branches the research document wrote, 「`auto` 면 NaN 이라 no-op · 0 이면 2×1」 (auto gives NaN, so a no-op · 0 gives 2×1) — grounding section of `../research/hidden-tab-terminal-subscription-survey-2026-09-25.md`). The grid of an area that was visible and then hidden stayed at the last real dimensions (84×50) (measured) — ★because nobody calls `fit()` while it is hidden, not because `fit()` of a hidden area yields a sane value★: the computed value `"100%"` is independent of history, so calling `fit()` on a hidden area produces a garbage grid for any area (inference — FitAddon source). Cell size (cell metrics) exists even while hidden — because xterm 6.0.0 measures the cell size with OffscreenCanvas TextMetrics (source reading — `CharSizeService.ts` of `@xterm/xterm`).
- **When making font settings data, it must go through the path above** — when the font changes, cell size → grid → PTY dimensions cascade. If it does not, the dimension mismatch breaks the TUI (the same symptom as the actual occurrence on 2026-08-20).
- **A restore spawn does not inherit the last dimensions** — the stretch before a client attaches uses the default 80×24. The root fix is to put the dimensions in profile storage. **Why not now:** it touches the storage format again (old-build compatibility was just closed).
- **On the hidden→visible transition, the visibility path's dimension propagation is tied inside the WebGL attach** — if the WebGL attach fails and it falls back to the DOM renderer, the `fit()`+`resizePty` tied inside the attach is skipped. ★The old statement 「그 전이의 치수 전파가 통째로 건너뛰어진다」 (the dimension propagation of that transition is skipped entirely) was an overstatement for the display:none transition★ — the collapsed box grows to its real size and RO sends the dimensions (regression net = `src/components/slot/slotInitialResize.test.tsx:271`). What is lost is only the one propagation inside the attach. **Why not now:** this device does not walk that path, and even if it did, RO sends the dimensions instead. An item to be absorbed into the "into one place" work above.
- **The decisions in the RO callback and onReset are looser than the shared decision** — RO (`TerminalSlot.tsx:105-107`) skips only when `offsetParent` is null or **both axes** are 0, and onReset (`:315`) looks only at `offsetParent`. So if the box collapses on only one axis, those two places can send the floor grid (2×N · N×1). The code comment of the shared decision (`:257` — skip if either axis is 0) points to this item and writes 「그쪽에 맞춰 느슨하게 되돌리지 말 것」 (do not loosen it back to match theirs). The reach is narrow — areas of the flat renderer stop at `MIN_PANE_PX` (`src/components/layout/splitPreview.ts:9`). **Why not now:** it is pre-existing, and it will be matched when folding the four send points (first item).
- **The WebGL attach path has no box decision at all** — `attachWebgl` (`TerminalSlot.tsx:176-228`) emits `fit()`+`resizePty` (`:217-219`) when IO says it is visible, but does not look at the box size. Because IO reports a zero-width target as intersecting, a displayed but 0×0 container can send 2×1 through this path, and a box collapsed on only one axis passes as is. Areas stop at `MIN_PANE_PX` above, so what applies is only the case where the window root collapses. **Why not now:** it is pre-existing and the reach is narrow — adjust it together in the first item.
- **Design consideration (use it in the folding work of the first item): attaching an agent to an area of a hidden tab leaves the PTY dimensions as they are until that tab is shown** — it is the price the shared decision chose, not a to-do. When an agent is attached or moved to a hidden-tab area, the PTY keeps its current dimensions (for a new agent, the spawn default 80×24 — the same stretch as the 「복원 spawn」 (restore spawn) item above). The old right-after-subscription path called `fit()` just before sending, so for a hidden area it pushed a garbage grid (e.g. 11×6) **regardless of history** (inference — the hidden-state facts above). When the tab is shown, the visibility path and RO send the real dimensions. It is within the scope of the industry rule the user chose (「잴 수 없는 치수는 보내지 않는다」 (do not send a dimension that cannot be measured) — the research document above). When folding, look at how to handle this stretch together.
- **A very small but non-zero box passes the shared decision** — for example a 1px box passes the decision and yields the minimum grid. orca sets a pixel floor (48×24 px) (the table in the research document above). **It is only a candidate.** **Why not now:** the review left it as an out-of-scope candidate — whether to set a floor and at what value is not decided.
- **On the first subscription of a visible area, the first Resize is about 6% narrow** — pre-existing (not created by the shared decision). Measured (2026-09-25 · CDP): the columns of the first Resize go out about 6% fewer, like 163 → 173 · 79 → 84, and are corrected 20~35ms later → the PTY is resized twice. That claude redraws each time is an inference (not observed). Cause guess (**untested**): the `fit()` at subscription time runs before the WebGL attach and measures with the DOM renderer's cell width (7.619px), whereas WebGL measures 7.2px. **Why not now:** it is corrected right away — confirming the cause comes first.
