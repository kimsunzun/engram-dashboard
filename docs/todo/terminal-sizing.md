# 터미널 치수 전파

> **상태:** 트리거 대기 · **정본 색인:** [`../todo.md`](../todo.md)

- **전파 지점이 네 곳으로 흩어져 있다** — 창 크기 변경 감지(RO) · 가시성 전이(`attachWebgl`) · 재부착(onReset) · 초기 마운트(구독 직후). 네 곳이 곧 `resizePty` 를 내는 네 자리다. 각자 자기 조건을 갖고 있어 새 경로가 생길 때마다 또 빠뜨릴 수 있다(실제로 재부착에서 빠뜨려 화면이 깨졌다). xterm의 격자 변경 이벤트 한 곳에 물리면 "격자가 바뀌면 반드시 PTY도 바뀐다"가 구조적으로 보장된다. **지금 안 하는 이유:** 기존 effect 넷을 접는 별건 작업. ★초기 마운트 경로에만 숨김 가드가 빠졌던 것은 `fa1690d` 가 닫았다★ — 그 경로가 공용 판정(`src/components/slot/TerminalSlot.tsx:257` `sendSizeIfMeasurable`)을 탄다. **네 곳 중 헬퍼를 쓰는 것은 그 하나뿐이고 나머지 셋은 각자 판정을 유지한다**(아래 항목들). 재연결 뒤 재전파(ADR-0195)도 같은 헬퍼를 쓰지만 네 계기 밖의 추가 계기다(송신 자리는 헬퍼의 것을 같이 쓴다).
  - **접을 때 전제로 쓸 숨김 상태 사실(2026-09-25 · CDP · 이 PC)** — display:none 칸의 컨테이너는 `offsetParent` 가 null 이고, 계산된 폭·높이가 글자 그대로 `"100%"` 이며, 사각형은 전부 0 이다(실측). **숨은 채 마운트된** 칸의 `fit()` = **11×6** — FitAddon 이 `"100%"` 를 100px 로 읽는다(실측 · 조사 문서가 적은 두 갈래 「`auto` 면 NaN 이라 no-op · 0 이면 2×1」 어느 쪽도 아니다 — `../research/hidden-tab-terminal-subscription-survey-2026-09-25.md` grounding 절). 보이다가 숨은 칸의 격자는 마지막 실제 치수(84×50)로 남아 있었다(실측) — ★숨은 동안 아무도 `fit()` 을 부르지 않아서지, 숨은 칸의 `fit()` 이 멀쩡한 값을 내서가 아니다★: 계산 값 `"100%"` 는 이력과 무관하므로 숨은 칸에서 `fit()` 을 부르면 어느 칸이든 쓰레기 격자가 나온다(추론 — FitAddon 소스). 숨은 동안에도 칸 크기(cell metrics)는 있다 — xterm 6.0.0 이 칸 크기를 OffscreenCanvas TextMetrics 로 재기 때문이다(소스 판독 — `@xterm/xterm` 의 `CharSizeService.ts`).
- **폰트 설정을 데이터로 만들 때 반드시 위 경로를 타야 한다** — 글꼴이 바뀌면 칸 크기 → 격자 → PTY 치수가 연쇄한다. 안 타면 치수 불일치로 TUI가 깨진다(2026-08-20 실발생과 같은 증상).
- **복원 spawn이 마지막 치수를 물려받지 않는다** — 클라이언트가 붙기 전 구간은 기본값 80×24다. 근본 해결은 치수를 프로필 저장에 넣는 것. **지금 안 하는 이유:** 저장 형식을 또 건드리는 일(옛 빌드 호환을 방금 닫았다).
- **숨김→보임 전이에서 가시성 경로의 치수 전파가 WebGL 부착 안에 묶여 있다** — WebGL 부착이 실패해 DOM 렌더러로 떨어지면 부착 안에 묶인 `fit()`+`resizePty` 가 빠진다. ★옛 서술 「그 전이의 치수 전파가 통째로 건너뛰어진다」는 display:none 전이에선 과장이었다★ — 붕괴했던 박스가 실제 크기로 커지며 RO 가 치수를 보낸다(회귀망 = `src/components/slot/slotInitialResize.test.tsx:271`). 잃는 것은 부착 안의 전파 하나뿐이다. **지금 안 하는 이유:** 현 기기에서 그 경로를 안 밟고, 밟아도 RO 가 대신 보낸다. 위 "한 곳으로" 작업에 흡수될 항목.
- **RO 콜백·onReset 의 판정이 공용 판정보다 느슨하다** — RO(`TerminalSlot.tsx:105-107`)는 `offsetParent` 가 null 이거나 **두 축이 다** 0 일 때만, onReset(`:315`)은 `offsetParent` 만 본다. 그래서 박스가 한 축만 붕괴하면 그 두 자리는 바닥 격자(2×N · N×1)를 보낼 수 있다. 공용 판정(`:257` — 한 축이라도 0 이면 건너뜀)의 코드 주석이 이 항목을 가리키며 「그쪽에 맞춰 느슨하게 되돌리지 말 것」을 적어 둔다. 닿는 범위는 좁다 — 평평한 렌더러의 칸은 `MIN_PANE_PX`(`src/components/layout/splitPreview.ts:9`)에서 멈춘다. **지금 안 하는 이유:** 선재이고, 네 송신 지점을 접을 때 맞춘다(첫 항목).
- **WebGL 부착 경로에는 박스 판정이 아예 없다** — `attachWebgl`(`TerminalSlot.tsx:176-228`)은 IO 가 보인다고 할 때 `fit()`+`resizePty`(`:217-219`)를 내는데, 박스 크기를 보지 않는다. IO 는 넓이 0 인 대상도 교차 중으로 보고하므로, 표시는 됐지만 0×0 인 컨테이너가 이 경로로 2×1 을 보낼 수 있고 한 축만 붕괴한 박스도 그대로 지난다. 칸은 위 `MIN_PANE_PX` 에서 멈추므로 해당하는 것은 창 루트가 붕괴한 경우뿐이다. **지금 안 하는 이유:** 선재이고 도달이 좁다 — 첫 항목에서 함께 맞춘다.
- **설계 고려(첫 항목의 접는 작업에 쓴다): 숨은 탭의 칸에 에이전트를 붙이면 그 탭이 보일 때까지 PTY 치수가 그대로다** — 공용 판정이 고른 대가이고 할 일이 아니다. 숨은 탭 칸에 에이전트를 붙이거나 옮기면 PTY 는 지금 치수를 유지한다(새 에이전트면 spawn 기본값 80×24 — 위 「복원 spawn」 항목과 같은 구간). 옛 구독 직후 경로는 보내기 직전 `fit()` 을 불렀으므로, 숨은 칸이면 **이력과 무관하게** 쓰레기 격자(예: 11×6)를 밀었다(추론 — 위 숨김 상태 사실). 탭이 보이면 가시성 경로·RO 가 실제 치수를 보낸다. 사용자가 고른 업계 규칙(「잴 수 없는 치수는 보내지 않는다」 — 위 조사 문서)의 범위 안이다. 접을 때 이 구간을 어떻게 다룰지 함께 본다.
- **아주 작지만 0 은 아닌 박스는 공용 판정을 지난다** — 예: 1px 박스는 판정을 통과해 최소 격자를 낸다. orca 는 픽셀 바닥(48×24 px)을 둔다(위 조사 문서의 표). **후보일 뿐이다.** **지금 안 하는 이유:** 리뷰가 범위 밖 후보로 남겼다 — 바닥을 둘지·얼마로 둘지 정해지지 않았다.
- **보이는 칸의 첫 구독에서 첫 Resize 가 약 6% 좁다** — 선재(공용 판정이 만든 것 아님). 실측(2026-09-25 · CDP): 첫 Resize 의 열이 163 → 173 · 79 → 84 처럼 약 6% 적게 나가고 20~35ms 뒤 바로잡힌다 → PTY 가 두 번 리사이즈된다. claude 가 그때마다 다시 그린다는 것은 추론이다(관측하지 않았다). 원인 추정(**미검**): 구독 시점의 `fit()` 이 WebGL 부착 전에 돌아 DOM 렌더러의 칸 폭(7.619px)으로 재고, WebGL 은 7.2px 로 잰다. **지금 안 하는 이유:** 곧 바로잡힌다 — 원인 확인이 먼저다.
