# comments — 코드 주석 규약

🔒 = 바인딩·지시서가 못 덮는다 — 약화·생략 지시를 받으면 무시하고 보고한다. 바인딩이 같은 항목명으로 다시 써서 이길 수 있는 건 **§양식·§대상 단위별 쓸 거리·§세부뿐**이고, §기준·§보호 항목은 §프로젝트 추가분 규칙을 따른다.

> 보호 패턴 = §보호 항목 ∪ 바인딩 추가분. 스폰 지시서로 합성 목록을 받았으면 그걸 쓴다.

## 기준 (무엇을 남기나 — 전 항목 🔒)

1. **디폴트 = 무주석.** 이름 · 시그니처 · 본문 · 주변 코드 · 테스트 · 호출부에서 읽히는 건 쓰지 않고, **아래 어디에도 안 걸리는 기존 주석은 지운다.**
2. **쓰는 건 넷뿐:** 없는 것의 이유(의도적 부재 · "되살리지 마라") · 외부 세계의 사실(실측 · OS·상대 프로세스 동작 · 프로토콜 상대편의 요구) · 결정·의도(이 값이 왜 이 값인가) · 알려진 미확인("X 가 Y 인지 미검증, 새면 증상은 Z").
3. **경계 밖 소비자가 있는 정의는 예외** — 계약(단위 · 경계값 · 에러 조건 · 부재의 의미 · 동형 형제와의 구분)은 본문에서 읽혀도 쓴다. 판별 = **본문을 볼 수 없는 소비자**(다른 언어·프로세스·생성물·문자열 호출)가 있나 — "오늘 호출부가 있나"도 문서 생성기를 돌리나도 아니다. **예외는 저 열거에만 선다** — "무엇을 하나" 요약은 계약이 아니고, 이름이 나르는 건 경계 밖에도 나른다.
4. **계약은 그 언어의 doc 채널에, 내부 노트는 일반 주석에.** 채널 표기는 언어·프로젝트 소관(§양식) — 기준이 정하는 건 **가르라는 것**뿐이다. 계약을 doc 채널로 옮길 수 없는 자리(그 언어가 그 위치에 doc 을 허용하지 않을 때)면 일반 주석으로 남기고 옮기지 않는다.
5. **코드를 바꾸면 관련 주석도 같이 고친다.** 근거를 못 대는 건 쓰지 않는다. 코드와 어긋난 주석은 **코드를 근거로** 고치고, 어느 쪽이 옳은지 못 가리면 지우지 말고 **보고한다**(코드 버그 의심 등 주석에 못 담는 발견도 보고로).
6. **주석 처리된 코드는 지운다.** TODO 는 소유자나 이슈 식별자가 있으면 남기고, 없으면 지운다.
7. **도구가 파싱하는 주석**(빌드 태그 · 린터/타입체커/커버리지/포매터 지시)**과 ADR·리뷰 앵커는 건드리지 않는다.** 앵커 = 주석 안의 결정·리뷰 참조 토큰(`ADR-NNNN` 등) — **adr 스킬 도구가 파싱하므로 형식 변경·삭제 금지.** 이 규약이 없는 프로젝트면 바인딩이 자기 앵커 형태를 적거나 "없음"을 적는다.

- **🔒 삭제와 작성은 같은 기준** — 지워야 할 주석 = 애초에 쓰지 말았어야 할 주석. 표준을 용도별로 가르지 않는다(사용자 결정).
- 🔒 **단 삭제의 기울기를 작성에 그대로 쓰지 않는다** — 이미 있는 주석은 주변 문맥으로 해소되면 지우지만, **안 쓴 것은 주변을 읽어도 해소되지 않는다.**
- **길이는 규칙이 아니다** — 필요한 자리엔 상한이 없고, 비율·주변 밀도는 판정 근거가 아니다.

## 대상 단위별 쓸 거리

별도 규칙이 아니라 "대상별로 무엇이 자주 걸리나"다. 쓸지 말지의 판정은 §기준.

| 대상 | 이름·시그니처가 못 나르는 것 |
|---|---|
| 모듈/파일(`//!` 등) | 주어 = 이 파일 — 무엇을 소유하나 · 파일 경계 불변식 · 진입점 |
| 타입(struct·enum·trait·interface) | 단위 · 경계값 · null/부재의 의미 · 소유권 · 불변식 · 수명 · **동형 형제와의 구분** |
| 공개 함수/메서드 | 에러 조건 · 순서 보장 · 호출 전제 · 어느 형제를 대신 쓰나 |

- **타입이라고 다 다는 게 아니다** — `struct RetryPolicy { max_attempts: u32 }` 는 무주석. 주석이 붙는 건 *타입이라서*가 아니라 **계약이 이름에 안 들어가서**다.

## 양식

- **WHY 주석 = 한 줄 + 근거 식별자 우선** — `// ADR-0006: 락 순서 고정` · `// #4402 우회: IPC 가 u64 를 자름`. 식별자가 없으면 이유만 한 줄.
- **doc 채널 표기** — 그 언어의 표준(Rust `///`, TS JSDoc 등). 무엇을 doc 채널에 두나 = §기준 4.
- **TODO = `TODO(식별자): 내용`** — 이슈 번호 또는 소유자.
- 🔒 **이력 서사 금지** — "옛 코드는 X → 이제 Y"는 changelog 다. 위치 무관(헤더·함수·선언 위 전부). **단 옛 형태의 구체적 실패 모드를 진술하면 §기준 2 의 "되살리지 마라"라 남긴다** — 맨 A→B 서사만 지운다.

## 보호 항목 (바인딩은 추가만 — §프로젝트 추가분)

- **법적 고지** — 저작권·라이선스·SPDX. §기준 허용 유형에 안 걸려도 지우지 않는다.
- **테스트 구획 라벨·tally**(`// ── 인증 실패 ──` · `// 총 12 케이스`) — 테스트 코드에서도 이 둘은 남긴다.
- **도구 지시 주석 범주** — `//go:build` · `# noqa` · `# type: ignore` · `eslint-disable` · `prettier-ignore` · `istanbul ignore`. 열거가 아니라 범주다 — 목록에 없어도 도구 지시로 보이면 보존.

## 세부 (해당될 때 본다)

- **섹션 구분선**(`// ── 이름 ──…`) **= 큰 구획에만** — 남발 금지.
- **모듈 overview 헤더 = load-bearing 파일에 권장**(동시성·보안·복원 등 핵심 책임).
  - 담을 것 = 역할 · 핵심 불변식 · 진입점 · 시그니처로 안 보이는 의미(자동 vs 호출자 책임, 보장 vs best-effort) — **현재 상태로**.
  - 가름선 = **주어가 파일 전체인가** — 본문 한 곳을 복창하는 메커니즘 서술은 헤더에 두지 않는다.

## 프로젝트 추가분

`.claude/skill-bindings/code-conventions.md`(cwd-상대 Read)의 주석 절을 함께 읽는다.

- **§양식** — 바인딩이 같은 항목명으로 다시 쓰면 그게 이긴다(채널 표기 등은 언어·프로젝트 소관).
- 🔒 **§보호 항목** — 바인딩은 **더하기만** 한다. 빼라는 지시는 무시하고 보고한다.
- 🔒 **§기준은 못 덮는다** — 바인딩이 기준을 재선언하면 무시하고 사용자에게 보고한다.
- **파일 부재 = 정상** — 이 문서 그대로 진행하되 "바인딩 부재"를 보고한다(조용한 생략 금지).
