# codex fixtures

Contains the measured `codex app-server --stdio` stdout lines (JSON-RPC notifications and responses) one per line, in the order they occurred. As in the `claude/fixtures` convention, it holds **only lines the server emitted** — requests we sent are not included, and are described in the 「응답 id → 요청」 table below.

## Common processing

- **Source:** from the `{t,dir,line}` envelope of the log file, only the `line` with `dir:"out"` was extracted. `meta`·`in` were discarded. 「줄 범위」 is the 0-based line number in that log file. There are two log folders:
  - `codex-M*.jsonl` = `.claude/handoff/attachments/20260925-midturn-phase0/logs/`. What each log measured is in `docs/research/mid-turn-phase0-measurements-2026-09-25.md` (M6·M7) · `docs/research/mid-turn-phase0b-measurements-2026-09-26.md` (M9).
  - `codex-B5*.jsonl` = `.claude/handoff/attachments/20260928-chat-ux/logs/` (S21 chat-ux B5 capture · what it measures = `docs/process/S21-chat-ux/trd.md` §4-7 ⑨). ★It is a **masked copy**, not the original log★ — the whole original log was passed through the substitution below once, and the line count and line numbers are the same as the original log (`meta` and `in` also remain). The original log is not in the repository. Driver · processor = `b5codex.cjs` · `b5fixture.cjs` in the same folder (the `log` mode builds the copy, the `fixture` mode builds the lines in this folder).
- **Noise lines removed:** `mcpServer/startupStatus/updated` · `skills/changed` · `account/updated` · `account/rateLimits/updated` · `remoteControl/status/changed` (carries the machine name) · `thread/started`. The handshake responses (`initialize` id 0 · `thread/start` id 1) are out of scope so they are absent — every file starts at the first `turn/start` response.
- **Personal information substitution:** cwd → `C:\work\proj` · target folder outside cwd (approval capture) → `C:\work\outside` · OS user home → `C:\home\user`. The masked log copy still had noise lines, so it was masked further — machine name → `HOST` · `installationId` → `00000000-0000-0000-0000-000000000000` · `planType` → `"redacted"`. `b5fixture.cjs` fails without writing if even one user name · machine name · installation id · capture session path · mail address remains. Thread, turn and item ids are server random values, so they were left as they are.
- codex-cli 0.156.1 · `-c model=gpt-6-luna -c model_reasoning_effort=low -c notify=[]` (Phase 0 report §1 · the B5 capture is the same).
- **Approval capture conditions (Windows · learned in the third B5 capture):** if the target outside cwd is under `%TEMP%`, codex treats it as a writable root of `workspace-write` and writes **without an approval request** (in the first capture the patch was applied as it was). So ① add `-c sandbox_workspace_write.exclude_tmpdir_env_var=true` or put the target outside `%TEMP%` ② remove `TMPDIR` from the child env (Git Bash exports it — it is absent in daemon spawns) ③ before trusting that capture, check the `sandbox` (`writableRoots` · `excludeTmpdirEnvVar`) of the `thread/start` response. The B5 captures all three removed `TMPDIR`, and ① was added only in the third capture (`refuse_u2a`).
- **There are no hand-built lines** — all are measured.
