# codex fixtures

Measured `codex app-server --stdio` stdout lines (JSON-RPC notifications and responses), one per line, in the order they happened. Like the `claude/fixtures` convention, it carries **only the lines the server emitted** — the requests we sent are not carried; they are written in the 「response id → request」 table below.

## Common processing

- **Source:** from the `{t,dir,line}` envelopes of the log file, only the `line` with `dir:"out"` was taken. `meta` and `in` were dropped. 「Line range」 is the 0-based line number in that log file. There are two log folders:
  - `codex-M*.jsonl` = `.claude/handoff/attachments/20260925-midturn-phase0/logs/`. What each log measured: `docs/research/mid-turn-phase0-measurements-2026-09-25.md` (M6 · M7) · `docs/research/mid-turn-phase0b-measurements-2026-09-26.md` (M9).
  - `codex-B5*.jsonl` = `.claude/handoff/attachments/20260928-chat-ux/logs/` (S21 chat-ux B5 capture · what it measures = `docs/process/S21-chat-ux/trd.md` §4-7 ⑨). ★It is not the original log but **a masked copy**★ — the whole original log was passed once through the substitution below, and the line count and line numbers are the same as the original log (`meta` and `in` remain too). The original log is not in the repository. Driver · processor = `b5codex.cjs` · `b5fixture.cjs` in the same folder (the `log` mode builds the copy, the `fixture` mode builds the lines of this folder).
- **Noise lines removed:** `mcpServer/startupStatus/updated` · `skills/changed` · `account/updated` · `account/rateLimits/updated` · `remoteControl/status/changed` (it carries the machine name) · `thread/started`. The handshake responses (`initialize` id 0 · `thread/start` id 1) are out of range, so they are absent — every file starts at the first `turn/start` response.
- **Personal data substitution:** cwd → `C:\work\proj` · target folder outside cwd (approval capture) → `C:\work\outside` · OS user home → `C:\home\user`. The masked log copy keeps the noise lines, so more was masked — machine name → `HOST` · `installationId` → `00000000-0000-0000-0000-000000000000` · `planType` → `"redacted"`. `b5fixture.cjs` fails without writing if even one of user name · machine name · installation id · capture session path · mail address remains. Thread, turn and item ids are server random values, so they were left as is.
- codex-cli 0.156.1 · `-c model=gpt-6-luna -c model_reasoning_effort=low -c notify=[]` (Phase 0 report §1 · the B5 capture is the same).
- **Approval capture conditions (Windows · learned in the third B5 capture):** if the target outside cwd is under `%TEMP%`, codex takes it as a writable root of `workspace-write` and writes **without an approval request** (in the first capture the patch was applied as is). So ① add `-c sandbox_workspace_write.exclude_tmpdir_env_var=true` or put the target outside `%TEMP%` ② remove `TMPDIR` from the child env (Git Bash exports it — the daemon spawn does not have it) ③ before trusting that capture, look at the `sandbox` (`writableRoots` · `excludeTmpdirEnvVar`) of the `thread/start` response. All three B5 captures removed `TMPDIR`, and ① was added only to the third capture (`refuse_u2a`).
- **There are no hand-made lines** — all are measured.
